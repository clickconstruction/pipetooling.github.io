Same result, but every row carries its own house picker, date and link — more typing per house, and the quote links are almost never in hand when the requests go out. It earns its keep only if the requests really do go out on different days.

What it does not touch. The app-sent path (Send price requests on Pricing) already picks several houses and emails each one — this plus is for requests you sent by hand and want on record. It writes the same bid_rfqs rows + Add a request writes (sent_via = 'outside', status = 'sent', no link), so the desk, the summary line, Nudge and the Robots all see them with no schema change.

Decision for you: Option 1 (checklist, one date) or Option 2 (stacked rows)? And should a house that already has an open request on this bid be unchecked with a warning (mock) or hidden from the list?
