Tap a chip's "how" to flip it: app emails Dan ↔ I'll send it. A house with no rep on file defaults to I'll send it (or you type an address, and it's remembered — same as the compose modal today).

Why this is the better version. The plus-with-checklist gets the rows in faster and then leaves the estimator doing four separate things in four places. This puts the whole loop on the row the robot already reads, and the one number that matters — quotes in — sits next to the button that uses them.

What it costs. Steps 1 and 3 reuse what exists (the compose modal's send-rfq-email path + remembered reps; Submittals' drop-a-PDF storage). Step 2's Call is a tel: link to the rep. The new pieces are the "usual houses" pick (a kernel over the estimator's last bids in the trade), the drop-zone on the row, and moving Price with robot's button up here. All client + one storage bucket path — no new table; bid_rfqs already has every column.

Plan — four PRs, each usable on its own

PR 1 · + Ask houses (hand-sent only)

  • Kernel usualHousesForBid: the estimator's houses on their last 10 bids in this trade, ranked by how often; pre-picked chips; "+ another house" = the existing picker.
  • One insert of N outside rows with a shared needed-by; toast. This alone is the plus you asked for, with the pick made for you.

PR 2 · the chip's "how" — app emails it

  • Scope = the bid's count rows (the price-matrix snapshot); per-house send through send-rfq-email exactly as the compose modal does; the desk's compose stays for scoped sends from the Supply house list.

PR 3 · quote lands on the row

  • Status column (waiting / late / quote in); drop-zone on waiting rows → upload to the bid's price-requests path, set quote_url, status quoted; paste still works. Call (tel:) on hand-sent rows, Nudge stays on app-sent.

PR 4 · Price with robot on the strip

  • The header button appears at ≥1 quote in and opens the existing modal; a Needs You card for "needed-by passed, no quote" on live bids.
