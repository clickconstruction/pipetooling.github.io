    6 Under the frame: the seal

    One small module runs first on every page load. Without the lens's name it returns at once, so the app is untouched for everyone else.

    The lens names the frame<iframe name="pipetooling-lens:{as: estimator, state: full, theme: dark}" src="/dashboard">

    The name survives the frame's reloads and its own links.

    →
    seal.ts runs firstIt is the first import in main.tsx and imports nothing heavy. It swaps the browser's pieces before any other module starts, then loads the world on the first request.
    →
    What a named frame swaps
    StorageMemory, seeded with the role's invented session and the frame's theme. The dev's own is never read or written.
    NetworkRequests to the Supabase address go to the world. Map tiles and fonts go out as normal.
    RealtimeA quiet socket.
    IndexedDB, cachesHidden, so the Pipeline board's remembered copy and a hard reload stay the dev's own.
    SensorsLocation, notifications and the online flag answer from the state.
    New tabsCarry the name, so they stay sealed.
    Without the name the seal returns at once. A signed-in person's app never loads the world, and a sealed frame never holds a real token, so nothing it sends could be authorized.

    7 What it does not do yet

    • Numbers the database computes are the world's answers, not the database's. A copy of the database in the browser could run the real ones later, behind the same seam.
    • The nine touch-only CSS rules do not apply in a desktop browser's frame. The CI report runs with touch on.
    • A window that needs a click to open is clicked in the live frame. Scripted openings come with the CI report.
    • A page's print layout is not drawn. The papers come from What customers see.
