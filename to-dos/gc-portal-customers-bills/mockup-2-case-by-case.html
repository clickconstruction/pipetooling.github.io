The revision, in the owner's words. "Looking at this holistically, I think that maybe we should be able to set it on a case-by-case basis … what could that look like in the job bill modal?"

This is the same shape "Bills go to" and "Bills also go to" already use: a customer-level default, a job-level memory, the bill's own stamp. The bill's stamp is the only thing the portal reads.

a typed "someone else" recipientthe tick is still offered (the other party can see it); payer stays nobody

The v2.3346 strip "On your jobs, billed to someone else" goes away in both directions. Every existing bill starts with NULL, so on day one no portal shows anything it did not show before v2.3346. A one-off script can stamp gc on the open owner-paid bills under GCs whose card is ticked, if the owner wants the Done Right repairs visible without re-sending.

  1. The stamp and the leak.

    Migration: jobs_ledger_invoices.shown_to_party, jobs_ledger.show_bills_to_other_party. Kernel billVisibility.ts (shared with the edge functions like billToParty.ts): shownToPartyFor, statementRoleFor(job, inv, viewer) → owed · shared · hidden. customer-portal filters before the payload, drops billedTo, emits sharedBills.   2. The doors and the card.

    Bill tab eye chip + menu; Edit tab fact row; the shared card on the portal in both wordings; the office globe mirror; guides share a customer their portal, choose who gets the bill, send a bill to more than one person; glossary.

  3. The GC's card default.

    customers.sees_customer_bills, "Sees their customers' bills by default" on Edit customer, shouldDefaultShowOtherParty judged once per GC pick the way shouldDefaultBillsToGc is. Plus the one-off stamp script for Done Right's open repairs (dry run, owner commits).

  4. Optional, later: Ask the office from the shared card (bill this to us · remind the owner) as inbox requests.

Is this the best we can do?

What the revision fixes

Consent is explicit and per bill, in the modal the office is already in, beside the copy tick that means almost the same thing. Nothing leaks by default. The capability is symmetric while the defaults carry the owner's original intent, so the rare "show the homeowner this one" case needs no exception path. Every layer copies a shape the office already knows from Bills go to.

What it costs

One more tick in a busy modal. Bill Customer's Send to block grows to four lines on a two-party job. Mitigation: the tick only renders when there is an other party, exactly like Copy, so single-party jobs never see it.

Copy and Show can disagree. A GC copied on the email but not shown the bill on their statement has the amount in their inbox anyway. That is allowed on purpose (the email is a one-time act, the statement is standing), but the guide should say it plainly. The alternative, folding Show into Copy, was rejected: it would make "email the AP clerk" and "keep it on their portal" one decision, and it would retroactively expose every bill ever copied.

The office has to remember. Without PR 3, Done Right's ~200 jobs a year each need the tick. PR 3 is small and is the difference between a feature and a chore; recommend shipping it with PR 2, not after.

Versus revision 1. The automatic rule was one function and no schema; this is two columns, a tick, a chip and a fact row. What it buys is the ability to say no on one bill without touching anyone's data model, and a portal that never shows a number the office did not choose to show. For customer-facing money, that trade is right.

Open decisions

  • Wording of the tick. "Show it on Done Right Foundation's statement" (recommended) vs "Done Right can see this bill". The first names the surface they know.
  • Should the tick write the job memory back? Recommend yes, mirroring Bill to ▾; a per-bill exception should not have to be repeated on the next bill unless it was meant as the new normal. Alternative: memory only from the Edit tab.
  • Stamp Done Right's existing open repairs with the script, or let them roll forward as new bills are sent?
  • PR 3 in the first train (recommended) or held?
