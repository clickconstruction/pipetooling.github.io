Is this the best we can do?

What could still be wrong with the after, window by window.

  • A short list can hide the row that matters. Each list shows its biggest rows first, by dollars. The count is always on the heading, and Show all is one press.
  • "Do this week" must not become a sixth list of things to do. The first screen already has the week's call. These rows are the same moves, for this one step, with their doors. Where a move is on the week's call, the row should say so.
  • Market and Sales change their numbers, not only their looks. They would read wins by the rules set on 2026-11-11. That is the larger part of the work, and it should ship before the layout.
  • Build and Bill share the no-price jobs. After, Build owns the list and Bill shows one row with a count. If that is wrong, both keep it.
  • Collect's guess stays a guess. What if half of it lands moves behind a press. It is the only place the page forecasts a change, so it should not lead.
  • How this is counted is rewritten in plain words, with no column names, and closed until pressed. A developer can still find the columns in the code.
