The rule What "ZZ test job" means to the code

One kernelisZzTestJob(job) in src/lib/jobs/: the job name or the customer name starts with ZZ (case-insensitive, after trimming). The glossary's ZZ convention already binds twins and live passes to this prefix; no new column, no backfill, no migration.
Applied at the loadThe Pipeline's job fetch and fetchStagesHeaderStats drop the rows before anything counts them, unless the viewer is a dev with the switch off. Sections, the stage pills, "Ready to ask for", the map's pins and the section totals all read the same filtered list.
Not touched in this PRHeader search (a dev still needs to find J1053), the Dashboard cards, the Lien desk ("3 need an owner" includes ZZ TEST Owner On Notice), AR, the Customers list, Bids. Each is a follow-up using the same kernel.

Open calls Three decisions before building

  1. Name prefix or a column? Prefix (recommended): it is the existing contract and covers every row already on the board. A jobs_ledger.is_test flag would be cleaner but needs a migration, a backfill and every creator (twins, live passes, New Job) to set it.
  2. Who gets the switch? Dev only (recommended). Assistants and the controller never need the rows; giving them a checkbox is one more thing to explain.
  3. Stop the pile-up too? Separate follow-up: a dev tool that reassigns ZZ rows older than a week into J1032, the permanent test job — then the board stays clean without anyone hiding anything.
