1 · What the office mailed by hand, what the app prints today, what it would print

The packet the office used to assemble (the 273 · Dudley (Lennox) sample) was four sheets: the cover letter, the § 53.056 notice, a page of QR codes, one per unpaid bill, and the owner-of-record copy. The app builds the first two and encloses the invoices themselves (v2.3437). The QR page is the piece it never learned. Proposed: the pay page goes where the office always put it, right behind the notice, in front of the invoices.

2 · The pay page, as the packet prints it

The same paper as the rest of the packet (Georgia, the letterhead, the reference strip). The heading is the office's own sentence. One row per unpaid bill: the code, the bill's number and date, its description as the invoice reads it, the amount still owed. The page ends with the total, which is the claim amount on the form behind it. On the owner's copy one shaded line repeats the cover letter's rule, so the page never contradicts the letter it follows.

3 · Where the office sees it before it goes: the Lien desk and the GC run

Both previews already stack the pages as the packet prints them. The pay page joins the stack with its own label, and the page count moves from 2 to 3. The desk pane today reads the job's unpaid invoice follows it in the packet under the notice; that line becomes the pay codes and the invoice follow it in the packet.

4 · View bill: a fourth payment link, the code itself

The Payment Links row in View bill (Jobs → Pipeline → Billed) has Copy · Text · Email. A fourth icon opens the code large enough to scan off a screen — for a customer standing at the counter, a phone held up in the field, or a sheet to print and leave with a bill. The code carries the same /pay/… address as the mailed page, so a printout stays good after Stripe's link rolls.

5 · What a scan opens

The address is the app's, not Stripe's, so the phone lands on one small page that knows the bill: it names it, shows what is left, and forwards to Stripe's payment page a second later, with a button in case it does not. A bill that is already paid says so and stops — the same code on a letter someone finds a year on does not ask for money twice.

Behind the page: one public function, modelled on the customer portal. pay-link takes the bill's id, checks it is a billed Stripe invoice, renews Stripe's link when it is past the stale margin (the same refreshStripeInvoiceLinks the portal and the nightly sweep use), and answers with the link, the number, the job's name and the amount still owed. The id is a UUID: unguessable, and nothing more than Stripe's own page already shows to whoever holds the link.

6 · The code itself: the mark in the middle costs nothing

The library the app already ships for the portal QR (qrcode.react) draws an image in the centre and carves the modules out under it. At the highest error-correction level a code survives losing 30% of its modules; the mark takes about 5%. So the mark is free, and the trade is only density: a denser code means smaller squares on the same inch of paper.

Plain · level M37 × 37 modules for /pay/…. What the portal card does today. Smallest squares needed: none of this is hard for a phone.
With the mark · level H49 × 49 modules for the same address. The hand-and-wrench sits in a carved-out square. This is the proposal.
Stripe's own address · level H69 × 69 modules. What encoding Stripe's link directly costs, before it expires. The stable address is a third sparser and never dies.
The mark is the plumbing hand-and-wrench, cropped square from public/brand/click-plum.png into a new public/brand/click-mark.png (the electrical logo has its own hand-and-bulb; the same crop gives click-mark-elec.png if a bill ever carries that brand). At print size (1.1 in per code) the mark is a quarter inch — recognisable, not readable, which is the right size for a mark.

7 · Decisions

QuestionProposedWhy, and the alternative
1 · What address does the code carry?clicktooling.com/pay/<bill id>, an app page that fetches Stripe's current link at scan time.Stripe's link expires 30 days after the due date (the nightly sweep keeps the stored copy fresh, not the paper). A lien notice is exactly the letter that gets paid late. Encoding Stripe's link directly is what the office did by hand and is a third denser. A short code (/pay/ab12cd34) would be sparser still but needs a column and a migration; it can come later without changing the page.
2 · Which envelopes get the pay page?Owner's copy: yes, with the shaded rule. GC's copy: the owner's call; the build gates it on one line, default off until counsel nods.The cover letter tells the owner not to pay us without the GC's written okay; the shaded line keeps the page honest to that. Counsel wrote that the GC's envelope is "the form and invoices only" — a pay page is neither a letter nor a smear, but it is an addition, so it is a question for counsel, not a default.
3 · Where in the packet?After the notice, before the enclosed invoices — page 3 of the owner's copy.Where the office always put it. Under the notice the reader has just seen the claim amount; the page shows how it splits and how to pay it. The invoices behind it are the detail.
4 · The heading and the words"Once these bills are paid, there will be no lien filed." — the office's sentence, unchanged.It is true, it is plain, and it is what the owner has read before. The rows say Still owed rather than Total because a partly paid bill should show what is left.
5 · The mark in the middleYes, at level Q, the hand-and-wrench cropped square.Free with the library already shipped; the only cost is 41 modules instead of 37 (level H would be 49), still coarse at 1.1 in. Level Q survives losing a quarter of the code; the mark takes a twentieth, so a coffee ring on the letter does not kill it.
6 · View bill: what does its code carry?The same /pay/… address as the mailed page.One code per bill everywhere, so a printout from the modal and the page in the packet scan to the same place. Copy · Text · Email keep handing out Stripe's link as they do today: those are sent now and read now.
7 · A bill outside StripePrints its row without a code: pay by check to the address above. No icon in View bill, as it has no links today.Faking a code for a bill that has no payment page is worse than no code.
8 · Later, not nowThe code on the invoice sheet itself (top right of every printed and emailed invoice); a short code column.Both make the pay page and the modal better without changing them. The sheet's code would also settle decision 2 for the GC's envelope, since the invoices already go there. Kept out so the first train ships small.
