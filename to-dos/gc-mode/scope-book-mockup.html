2. Is this the best we can do? No. Here is why.

One line at a time is slow.A sitework scope is 8 to 15 lines. Pressing + Add fifteen times is worse than the paste it replaces. The book should hold sets, like "Sitework · retail pad", taken in one press and then trimmed.
The real value is what we missed.A list of words saves typing. A book that remembers the lines we added late on past jobs (by a later set, a change order or a gap between trades) saves money. "Detention pond came in with Bulletin 1 on Boerne Retail Shell" should come to you, not wait to be found.
A third column crowds the step.Step 4 already has the trade list, the lines and Not in this trade. The book belongs in the place you type a line: Add a line should search the book as you type, the way the new pickers do.
A line is more than words.A book line should carry its spec section and its usual "leaves out, done by" partner, so pulling "Roof curbs" into HVAC also asks Roofing to leave them out. And it should know how often we used it and when it was last used, so the good lines rise.
It has to fill itself.Nobody will type a book from nothing. It starts from every scope on our past jobs, and every line you type new offers to join it. Duplicates ("Clearing & grading", "Clearing and grading") get merged on the book's own page.
Search across trades, honestly labeled."Fire caulking at penetrations" lives under Electrical, Plumbing and HVAC. Search shows which trade each hit comes from, so pulling it into another trade is a choice you see.

4. The plan

  1. New ProjectThe book in the model (gcScopeBook.ts, tested). A book line has the trade, the words, a spec section, an optional "leaves out, done by", the jobs it was used on, and the jobs where it came in late: added by a later set, a change order or a gap between trades. A set is a named list of lines for one trade. The book is seeded from every scope on our made-up jobs and the trade templates, so it is never empty. Readers: search (this trade first, then most used, a missed line flagged), sets for a trade, often missed for a trade (late lines not in this scope yet), duplicates.
  2. New ProjectStep 4: Start from the book. A set picker and Use these lines, which merges and keeps lines already there. Book lines carry a small "book" mark.
  3. New ProjectStep 4: Often missed. The amber callout under the set, with + Add on each. Hidden when there is nothing to warn about.
  4. New ProjectStep 4: Add a line searches the book, on the same searchable picker as the rest of the window. It shows this trade's lines first, then other trades labeled "from Concrete", and "+ Add as a new line" last. A new line offers Save to the book. A book line brings its spec section and its "leaves out, done by" with it.
  5. New ProjectThe book's page (Open the scope book): lines and sets by trade, edit, save this project's scope as a set, and merge duplicates. The same search is in A new set of plans came in, where a later set adds lines.
  6. BoardWhere it lives outside the window: a door to the book from Trade partners, a "Walk me through this job" or New here? stop, and the README row. Golden steps for the new moves, at the end of the walk.
  7. The real buildA gc_scope_book_lines and gc_scope_book_sets pair of tables, company-wide. Late-line history comes from change orders and plan sets as they happen. Estimators edit; anyone writing a scope can pull from it.
