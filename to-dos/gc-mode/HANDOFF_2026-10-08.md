## Rules that bit today

The repo's `CLAUDE.md` holds the hard rules. These are the ones that cost time in the last two days, in the order they come up.

1. **Migrations.** Only `supabase db push` from a clean checkout at main's tip, after a dry run, and only after the file merged. Every file starts with `SET lock_timeout = '3s'`. One that touches the clock tables (billing-only did) goes after 6 pm Central. After the push: the migration doc's verify steps, then a types PR (`src/types/database.ts` plus the dev-mcp catalog) on a `claude/types-...` branch, auto-merged. Prod is checked with `npm run check:migration-drift`.
2. **Compare the SQL to the mock-up byte for byte** before a migration PR merges. Each approved mock-up in `mockups/` holds the SQL as built; a diff that is not the version number or a comment is a question for the lane.
3. **Verify-SQL recipe.** Through the management API: `BEGIN;` then `set_config('request.jwt.claims', ...)` for the role's user BEFORE `SET LOCAL ROLE authenticated`, the check, then `ROLLBACK;`. `gc_projects`' key is `project_id`, not `id`. The endpoint reports a bad column at "LINE 1" of the whole batch; read the CONTEXT line instead.
4. **Lifts.** A kernel moving from `src/lib/gcMode/` (the spike) to `src/lib/gc/` (main) moves word for word. The lifting lane writes a spike follow-up branch (`spike/<lane>-follow`: delete what moved, re-export from main, a pinned config); the lead merges it and runs `node to-dos/gc-mode/scripts/lift-same.cjs --all`, which must be green. Generated files are regenerated, never hand-merged.
5. **Pushes.** Fetch and compare before every push to any `claude/gc-*` or `spike/*` branch; push with `--force-with-lease` only; never rebuild a branch with `reset --hard` over someone else's identical head.
6. **The merge queue.** `gh pr merge N --auto` arms it; a queued PR reads `autoMergeRequest` null, which is normal. Two PRs touching the same docs paragraph go DIRTY on each other; the second rebases after the first lands. A PR whose CI died after a tooling fix is rebased and re-armed, not re-run. A SQL bed that dies in 20 seconds with "toomanyrequests" is Docker Hub, not the SQL; re-run the one job.
7. **Versions and docs.** `npm run claim` reserves `v2.NNNN`; every feature PR carries one release note and one `docs/recent-features/` fragment; every migration a `docs/migrations/` page; a changed surface updates `PROJECT_DOCUMENTATION.md`, `GLOSSARY.md`, `ACCESS_CONTROL.md`; a new page updates `docs/twins/APP_DIRECTORY.md`.
8. **Email.** Every send starts off until the three test emails are read. Test sends go to bids@clickplumbing.com only. No session presses a send or writes a prod row for a check without Grace's own yes in that session's chat; a lead's word does not stand in for hers.
9. **Watching.** Monitor scripts under zsh list PR numbers literally and use `${br}:` not `$br:`; node needs `--input-type=module` for top-level await. Monitors expire at 30 minutes and must be re-armed.
10. **Testers' notes.** Grace's notes arrive in the lead's chat; each goes into `USER_TESTING.md` with the date, lane and state, then to the lane. Her first note, the ring's check at 100%, is built on the spike and rides to main when the ring lifts with the Board lane.
