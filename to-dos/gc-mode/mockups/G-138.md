## The kernel: additions to `gcNotReady.ts`

The kernel reads G-77's own `insuranceGap`, on the day itself. For a bar already under way, *before
it starts* no longer applies, so the gap is *none on file* or *ran out*.

```ts
/** A bar under way, of a trade whose insurance ran out or was never on file (G-138): the work goes on uncovered. */
export interface UninsuredBar { lineId: string; pkg: TradePackage; partner: Partner; gap: StartGap }

/** On a job being built: a hired trade's bars with work reported or a real start, not done. */
export function uninsuredBars(state: GcState, project: GcProject): UninsuredBar[]

/** By bar: the red note beside it and the hover card's line. */
export function uninsuredNotes(state: GcState, project: GcProject): Map<string, { note: string; words: string }>

/** The opened bar's block for a bar under way: G-77's shape, its paper's Ask for it, and the draws' lock. */
export function uninsuredBlock(state: GcState, project: GcProject, lineId: string): NotReadyBlock | null
```

*Under way* is the complement of G-77's *not started*. G-77 takes a bar with nothing reported and no
real start, and G-138 takes a bar with work reported or a real start that is not done. So a bar is
never both. `notReadyBlock` stays as it is, and the block reads `notReadyBlock(…) ?? uninsuredBlock(…)`.

**No new action, no fixture change, no hold.** The Held count stays 6, and the golden test does not move.
