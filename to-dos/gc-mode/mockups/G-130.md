# G-130: one schedule kernel

## What it is, and what it is not

- **Not a screen.** Nothing a person sees changes. The chart, the list, the paper, the walk, the
  morning list, the customer's copy and the portal show the same days, the same spare days and the
  same pushes.
- **What it is:** the schedule's day math in one pure file on main,
  `src/lib/gc/schedule/network.ts`. The chart and the measures both read it. Today it is split:
  - The calendar is in `gantt.ts`: `holidaysOf`, `holidayOn`, `isWeekend`, `isWorkingDay`,
    `workingDays` and `holidaysIn`.
  - The spare days and the pushes are in `schedule.ts`: `scheduleFloat`, `lagOf`, `wouldLoop`,
    `waitOrder`, `pushAfter` and `pushedAfterWords`.
- **Why it matters:** the two files count a stretch of days two ways. `gantt.ts` counts
  `workingDays(start, finish)`. `scheduleFloat` counts `daysBetween(start, finish) + 1` through its own
  `dayNumber`. They agree only because every day is a working day (the owner, 2026-10-05: "anyone
  can work 365 days a year"). A rule that changes that would have to be made twice, once for the
  bars and once for the spare days.

## The kernel: `src/lib/gc/schedule/network.ts`

Pure, no database, no screen. Everything below moves **word for word**. Only the imports change,
plus `export` on five helpers that are private today, so `schedule.ts` and `gantt.ts` can still
read them.

- **Days:** `dayNumber` (exported now), `isoOf` (exported now), `daysBetween`.
- **The calendar, from `gantt.ts`:** `iso` and `nthWeekday` (private, as now), `weekdayOf` (exported
  now, since the chart's axis reads it), `holidaysOf`, `holidayOn`, `isWeekend`, `isWorkingDay`, `workingDays`, `holidaysIn`.
- **The links:** `lagOf`, `wouldLoop`, `waitOrder` (exported now, so a later caller does not write a
  second one).
- **Spare days:** `scheduleFloat`.
- **Pushes:** `PushedAfter`, `pushAfter`, `pushedAfterWords`, with `activityLabel`, `activityDone`
  and `lineOf`. `schedule.ts` uses `lineOf` in four more places, so it is exported and `schedule.ts`
  imports it.

**Its imports:** `../building` (`addDays`), `../types`, `./types` and `../words`. It never imports
`./schedule` or `./gantt`, so there is no loop. Both of those import from it.

**Nobody's imports change.** `schedule.ts` and `gantt.ts` re-export every public name that moved
(`export { … } from './network'`). That covers the 18 files that read `daysBetween` from
`./schedule`, `moves.ts`, the tests and the spike.

## The one change on the way (its own commit)

This is the point of G-130. `scheduleFloat` counts an activity's length with the calendar, not
beside it:

```ts
// before
const duration = (a: ScheduleActivity) => daysBetween(a.start, a.finish) + 1
// after
const duration = (a: ScheduleActivity) => workingDays(a.start, a.finish)
```

For every activity whose finish is on or after its start, the two are equal, so no number moves.
They differ only for an activity that finishes before it starts. Today that counts as zero or
fewer days. After the change it counts as zero, which is what `workingDays` says for the bar. The PR
first checks that no fixture or prod-shaped test activity finishes before it starts. If one does,
the commit is dropped and the row stays Part, with the reason here.

`pushAfter` keeps moving by calendar days (`addDays`). With every day worked that is the calendar's
count. The day a day can be off, the shift goes through the calendar in this same file, and only
here.

## What I am leaving out, and why

- **`ganttLinks`, `ganttNeighbors`, `spareTail`, `TIGHT_SPARE_DAYS` stay in `gantt.ts`.** They read
  the chart's bars, not the activities. They are how the links are drawn, not what they are.
- **`lateNotices.ts` (line 246) and `portalSchedule.ts` (line 43) walk `after` themselves** for one
  step: "what waits right after this". Folding that into the kernel is a change, not a move
  (option 2 below).
- **`draft.ts` and `templates.ts` place a first draft from a template's offsets** with their own
  forward pass. That is a different rule (an offset after the last wait), and it stays.
- **Days off** (weekends off for a trade, rain days, our crew's calendar for G-51) are not asked
  for. This only makes them one edit when they are.

## Is this the best we can do?

Thought through for the chart's three jobs: See, Tell, Chase.

1. **The calendar inside the spare days** (commit 2 above). *Picked.* Without it, the calendar and
   the spare days only share a file. With it, See shows the same length on the bar and in the spare
   days whatever the calendar becomes. It changes no number today.
2. **One way to ask "what waits on this".** A `waitersOf(activities, id)` in the kernel, read by
   `pushAfter`, `scheduleFloat`, the late notices and the portal's "who comes after you". *Not
   picked now:* it changes three files that work. It is worth its own PR the day one of them
   changes, and Chase (the late notices) is the likeliest.
3. **The links as drawn, from activities.** `ganttLinks` and `ganttNeighbors` rewritten on
   activities and moved into the kernel, so the paper and the export read the same links without
   bars. *Not picked:* both already read the bars every view builds, and the move would re-pin the
   paper's tests for no change on the page.
