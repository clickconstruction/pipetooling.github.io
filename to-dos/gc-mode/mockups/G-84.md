**The job, as the lead put it.** A strip under the rows in Chart view, with its own toggle like *Show
spare days*, and nothing on the customer's copies. Planned people per week come from the bars, with
each trade's count taken in this order:

1. the trade's reported crew where it exists;
2. else the log's last count for the trade;
3. else a plain assumption, named on the strip.

The other side is the daily log's actual count per week. Helper 4's G-142 record,
`crewCountsNow(project)` in `gcCrewCounts.ts` (packageId, partnerId, weekOf, count, on), gets a slot

## The rules

- **Planned uses the plan's dates.** A bar counts on the days from its start to its finish as drawn
  now. G-60's *running late* rule is not used here. A late bar not yet done would otherwise count
  on every day ahead and fill every future week. The log already shows a late bar's crew while it
  is still there, so the gap between plan and log is the news.
- **One trade, one crew per day.** Two bars of the same trade on one day count its crew once, as the
  log does. Our own crew counts like any trade. Inspections and added activities have no crew, so
  they never count.
- **The busiest day**, not an average, because headcount is about the gate, parking and toilets on
  the day it peaks. The log's side is the busiest logged day of the week. A week's missing days are
  not guessed.
- **The count per trade and week** follows this order:
  1. G-142's newest count for that trade and that week, in the slot until it merges.
  2. The daily log's last count for the trade, up to today.
  3. `ASSUMED_CREW` = 3, the plain assumption.

  The hover names which one each trade's number came from.

## The kernel: `src/lib/gcMode/gcPeopleOnSite.ts`

Pure, out of the barrel, with `gcPeopleOnSite.test.ts`.

```ts
/** A trade with no count from itself or the log is counted as this many people, named on the strip. */
export const ASSUMED_CREW = 3

/** G-142's record, by shape: read from `crewCountsNow(project)` once it merges. Until then, none. */
export interface TradeCount { packageId: string; partnerId: string | null; weekOf: string; count: number; on: string }

export interface PeopleWeek {
  /** Monday. */
  weekOf: string
  /** The plan's busiest day: its date and headcount, and who made it up, each with where its number came from. */
  planned: { on: string | null; count: number; by: { company: string; count: number; from: 'told' | 'log' | 'assumed' }[] }
  /** The daily log's busiest day that week. Null: no log that week. */
  logged: { on: string; count: number; days: number } | null
  /** The log's busiest day had SHORT_BY (3) or more fewer people than the plan's busiest day. */
  short: boolean
  /** The hover card's lines. */
  words: string[]
}

/** Every week from `from` to `to` (Mondays), the plan's and the log's busiest day. */
export function peopleOnSite(state: GcState, project: GcProject, from: string, to: string, told?: TradeCount[]): PeopleWeek[]
```

`short` is *3 or more people fewer*, as `SHORT_BY`, the one threshold, which is A.

## Left out, and why

- **The customer's copies.** `GcGantt` is drawn only on the office's Schedule tab, and the customer's
  and the architect's schedules are their own views, so the strip cannot reach them. The print does
  not carry it, which is B below.
- **G-142's counts before it merges.** The slot is the `told` argument, empty until then, and the
  card never says *its own count* without one.
- **A day-by-day strip.** At Days zoom a week is still one cell. Per-day headcount is the daily log's
  own page.
- **Who was missing in a short week.** G-60's card names the trade not on site. The hover could repeat
  it, but one fact has one home.

## Is this the best we can do?

**A. See: a short week in amber.** A strip of numbers makes the eye do the subtraction. Turning the
log's number amber when the busiest logged day fell 3 or more short of the plan puts the week to ask
about in front of the person. **I pick this.** It is one threshold in the kernel and one color on
the strip, and the hover says why.

**B. Tell: the office's printed chart carries it.** With the toggle on, our team's copy could print the
strip under the rows, as it prints the spare-day tails. The customer's copy never would. **Not now.**
The print is its own kernel, `gcGanttPrint.ts`, with its own rows and pages. A strip row there is a
change to G-21's layout, best as its own small row after this one.

**C. Chase: ask the trades for their counts.** A week planned on an assumed 3 could offer to ask the
trade how many it sends. **Not now.** That is G-142's own job: the trade tells its count from its
portal. Once G-142 merges, the assumed 3 shrinks by itself.

So the build is the plan above with A, and the G-142 slot read after it merges.
