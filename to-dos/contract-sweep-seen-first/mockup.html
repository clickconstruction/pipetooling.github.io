Contract sweep, seen before it's sent

Today the sweep is a mailing list with a Send button on every line. The first answer was a better sweep: the queue on the left, the actual agreement on the right, filing in one drop. The better answer is to make the sweep small before making it good: file what is already signed from Drive, give GC jobs their own door, set a floor, and put the contract question on the job form so the pile stops refilling.

"I do not love this page. I think it should be easy for the user to upload a contract or to view what is about to be sent." — owner, 2026-09-13

What the page does today, read from the code

The sweep (v2.2685) lists every non-paid job whose coverage is none or draft, one row each, and each Send mints a draft from the job's own facts and calls the send function. Nothing on the page shows what that draft says. Seven things follow from that.

Is a better sweep the best we can do? No.

A two-pane sweep makes sending safer. But the sweep is built on a premise that is wrong for most of the pile: that every one of the 104 jobs needs us to send our agreement. Four things the code already knows say otherwise, and each one shrinks the pile before anyone opens a sweep.

1 · Half the rows want the other door.TF Harper, Summit GC, RMC, Michael Palmer are builders. On a GC job the paper that matters is the builder's subcontract, which they send to us and which is already signed somewhere. "Send our service agreement" to a GC's estimating inbox is the wrong action. The job carries gc_customer_id, so the row can say so: GC job · file their subcontract, filing primary, sending secondary.
2 · Most of these are signed already.You told us in September that signed contracts live in Google Docs. The pile is mostly a filing gap, not a signing gap. The drive-intake service account already reads the jobs Shared Drive, where folders are named after the project. One pass lists every contract-looking PDF or Doc per job folder, matches it to the job, and files the confident ones in one click. Nobody gets an email.
3 · Not every job needs a chase.The nudge has no floor: Mike Holub's $450 repair counts the same as Mission Hills' $123,600. A dollar floor you set, plus a Not needed answer per job that the count respects, turns 104 into the list that is actually worth chasing.
4 · Stop the pile growing.Jobs born from a won bid or an accepted estimate are already covered. The pile grows from hand-made jobs and imports, and the job form has no contract door at all. One question on a new job — Send the agreement · File the GC's subcontract · Not needed — ends the backlog as a recurring event. The sweep becomes a one-time cleanup, then a rare tool.

The order matters. Shrink first (floor, Not needed), file what is already signed (the Drive pass), then send what remains from a sweep that knows which door each row wants. Done in that order the sweep is a short list sorted by dollars, and the two-pane design below is what it looks like for that short list.

Then, for what remains: the sweep in three rules

Nothing sends unseen.The selected job's agreement renders on the right exactly as the customer will get it, from the same fields the send will mint. Scope and amount are editable in place. Changing the terms redraws it.
Filing is one drop.Drop a PDF, photo or Google Doc link on the row or into the pane. Signed by and signed on are prefilled. One button, the row turns green and leaves the queue.
Bulk is rare.Send & next is the fast path: one look, one click, the next job loads. Send all moves under ⋯, takes only rows the app calls ready, and says how many customers it will email.

Nothing in the sweep itself needs a migration or a new edge function (the floor, Not needed and the Drive pass above do). The coverage kernel, the quick-send kernel, the document renderer and the filing write path all exist; this is a new shell around them plus one small kernel for row readiness.

Phone width

The shell already stacks. The list is the screen; a tap opens the pane as a sheet with the document and the same footer; Send & next slides to the next row without going back to the list. Dropping a file has no phone equivalent, so the sheet's File it door opens the camera or files picker directly.

Build plan · shrink, file, then sweep

  • PR 0 The floor and Not needed. One migration: jobs_ledger.contract_not_needed_at (+ who, + a short reason) and an app setting for the floor; the nudge kernel, the Pipeline card and the coverage chip respect both. The 104 becomes the true count before anything else is built.
  • PR 0b The Drive pass. drive-intake gains a list mode over the jobs Shared Drive; a matching kernel (folder name ↔ job address or number, filename ↔ contract words) with tests; the Found in Drive review list files confident rows through the existing paper-record write. Dev-run first.
  • PR 0c The door on the job form. A new hand-made job asks once: Send the agreement · File the GC's subcontract · Not needed. Nothing else in the form changes.
  • PR 1 The readiness kernel and the list. contractSweepRowState.ts (+tests), the header count line, the To send · Needs a look · All switch, row chips, Send all moved under ⋯ and restricted to Ready. The pane is not yet built; a row's Send still sends. Smallest visible win: the thin rows stop being "ready".
  • PR 2 The pane. Selected job → the document rendered from buildJobContractDocumentHtml in an iframe (the record modal already does this), the To and Terms fields above it, Send · Send & next · Skip in the footer with the sentence. The quick-send kernel gains the accepted-estimate lookup so the sweep's document equals the modal's.
  • PR 3 Editing in place. Click the scope or the amount in the document to edit; autosave to the shared draft through the same write the Contract modal uses; Open the full editor hands off to the modal with the draft intact.
  • PR 4 Filing. The pane sheet (the v2.2744 sheet extracted into a shared JobContractFileSheet the modal also mounts), row drop targets with the 5-second undo, the green filed row, the header's N filed.

Stays as it is

  • send-job-contract, the signing page, reminders, the PDF.
  • The Contract modal for careful edits; the sweep hands off to it.
  • The Pipeline card, the Needs You item, the ?contractSweep=1 door.

Ships with it

  • Help guide get a job contract signed → "Clear the backlog" rewritten; a recording of Send & next.
  • One release note and one docs fragment per PR.
  • Render smoke on the sweep: a thin row is not Ready; Send & next selects the next row.

Decisions for the owner

  1. Is a no-amount agreement sendable in bulk? Proposed no: it sends one at a time after a look, and Send all skips it. The alternative is to treat time-and-materials as normal and let Send all take it.
  2. Where is the line for "scope is just the name"? Proposed: no fixtures and no accepted-estimate lines. Some job names are real scope ("Gonzalez · water heater"); the row can still be sent with Send anyway.
  3. One customer, two jobs. Proposed for now: one email per job, with the + J798 chip and the footer sentence so the office knows. One email carrying two agreements is a later change to the send function; worth it only if the pairs are common after the first sweep.
  4. Row drop with no questions. Proposed: signer = the job's customer, date = today, undo for 5 seconds. If a wrong date on a filed contract is a real risk, the drop can open the sheet prefilled instead of filing outright.
  5. The floor, and Not needed. What dollar amount is too small to chase? Is Not needed an answer the office may give per job (one column, a reason, shows on the chip), or should every live job stay in the count until it has paper?
  6. GC jobs. Is the builder's subcontract the agreement on a GC job, so the sweep's primary on those rows is file theirs and Send all skips them? Or do you want our service agreement countersigned by builders too?
  7. The Drive pass. May a dev run the first pass and file the confident matches, with the review list for the rest? It reads the jobs Shared Drive the intake account already has; nothing is written to Drive.

When you pick a direction I can file this as a to-do folder (to-dos/contract-sweep-seen-first/) with this page beside the README and start PR 1.
