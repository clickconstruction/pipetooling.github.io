Report by line: how far along each line is, not the job

A tech is halfway through the rough-in and the report asks how complete the job is. They type 50. The job reads half done everywhere money is counted. The question should be the size of the work: each line of the job, no amounts, the job's number worked out behind it.

The tech's seat

Marco files from Job Mode before he drives off. He has a number for the rough-in, not for the job. Fewest taps, honest answer. The same on the My Schedule stepper.

The job behind the ask

The question is wrong-sized. The job's percent feeds the Pipeline bar, the AR and Not Billed Out cards, Burn, the Bridge, capable-to-bill and the Ready-to-bill prompt. A fifty for the rough-in makes the job look half unbilled.

The whole office

The office already names the lines on the Bill tab, the Pipeline cell already draws one segment per line, the GC portal shows the shared stages. Every one gets truer when the number per line is the tech's own.

7Is this the best we can do? What the second pass changed

  1. Chips on every row made a six-line job a wall on a phone. Now one row is open at a time; done rows are one line with a check.
  2. The share on each row read as value. It moved behind how? on the job line, percentages only, folded until tapped.
  3. A separate stepper design was two idioms for one answer. The stepper opens the same list; its ± chips stay only where there is nothing to list.
  4. "Which line did you work on?" then a slider reports one line per report. The list lets a tech move two rows in three taps and is faster for one, since the likely row is already open.
  5. Gating on the Order flag was the whole gap. The list keys on two or more priced lines, what the Pipeline bar already keys on, so the report and the bar agree on what a job's pieces are.
  6. One text field per row cluttered the report card. One Stage progress field, one sentence per moved line, keeps today's readers working.

8Decisions for the owner

D1 · the shareDefault: behind how?, percentages only.
Or print 35% of the job on each row as v2.3192 does.
D2 · which rows listDefault: every priced line that is not a discount, in plan order.
Or only lines the office marks as work, which needs a third choice on the Bill tab's chooser.
D3 · the escape hatchDefault: Set the whole-job % instead stays, no note required.
Or require a note on a multi-line job.
D4 · the stepper doorDefault: PR 3 in the same train.
Or leave it whole-job and watch whether the fifties stop with PR 2 alone.
D5 · the office's windowsDefault: the Additional report gets the list; Edit report edits the stored text only.
Or leave both as they are.

The plan, the kernels and the PR train are in to-dos/report-by-line/README.md. PR 1 is the write RPC and the kernel; PR 2 the field on the report; PR 3 the stepper; PR 4 the Pipeline cell; PR 5 retires the one-stage field.
