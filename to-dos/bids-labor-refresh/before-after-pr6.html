The three conflicts are one pattern: the human book put the same total in different stages. Whichever is picked, the totals agree; the report exists so the pick is a person's, not the script's. Default and Bill are archived (not deleted) until the first bid prices on the folded book without a complaint; a rollback is one flag.

Where it plugs in. labor_book_entries gains origin (robot · human), robot_hrs (the robot's own three numbers, kept when a human overrides so Reset works), set_by / set_at. labor_book_versions gains archived_at. The migration is the fold plus a RAISE NOTICE report; the picks are three UPDATEs in the same file once the owner says which. Every bid's selected_labor_book_version_id re-points to its trade's robot book. Idempotent; SET lock_timeout.

Set writes the multiplier onto the book as an override of every robot entry it touches — the same column, the same chip (calibrated · 4 jobs · Sep 18) — so Reset to robot undoes a calibration one entry at a time, and the evidence chip says which jobs argued for it.

What the estimator notices. The picker is gone, the pills are gone, and every number has a provenance. The queue (PR 1) and the sanity strip are unchanged. BP83 opens on the Electrical book with Bill's three rows already in it.

What the robot notices. Its write fence keys on the robot-flagged book; that flag stays. It writes robot rows only; the migration teaches it the robot_hrs column so a re-seed refreshes what it may.

RejectedKeeping human books as separate "override books" layered over the robot's — two lookups per row, and the same fork PR 6 exists to close.

RLS: labor_book_entries update stays open to the tab's roles (dev, master, assistant-like, estimator) for the hour and alias columns; robot_hrs is written only by the robot role and the migration; the calibration RPC checks is_master_or_dev() and, for an estimator, records a proposal row instead. The RPC the twins use (get_man_hours_by_job) already refuses estimators, which is why their tile reads no linked jobs today — proposing needs only the multiplier, so the tile shows the proposal without the hours.

Why not "everyone who can open the tab may Set". Set rewrites every robot entry the multiplier touches — 17 rows — from one button. An override is one row with a name on it and a reset; a calibration is the whole book. The plan's own words: dev · master tech · estimators for their own overrides.

Owner callDoes an estimator's Set go live at once, or wait for a leader? Drawn as propose; one flag either way.

The Takeoffs precedent. v2.3588 retired Old there with a two-way pill and a stored-pick rule (a device that had picked Old lands on the default, never asked again). Labor is simpler: one view remains, so the pill component goes entirely.

Kept on purposeNothing — unlike Takeoffs' By Stage editor, Old Labor has no reader the New view lacks. If a week on the folded book turns one up, the retirement PR is the one to hold.
