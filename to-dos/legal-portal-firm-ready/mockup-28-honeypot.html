The honeypot: wired or dropped

The portal's forms draw a hidden website box. The page never sends it. The function answers { ok: true } and writes nothing when it is filled. Who reaches each path, today and after.

Before — the trap guards nothing and can eat a real act
Who postsWhat happens
The firm, through the pageThe page builds the body from React state and leaves website out. Saved. The hidden input is dead markup.
A bot with the link, posting to the functionIt sends no website (it does not draw the form). Saved. The trap never fires.
A page change that wires the input (the obvious "fix")A password manager that fills every text box fills website. The function answers { ok: true }, the page says Saved. The fee, the step or the payment is gone and nobody knows.

A body that still carries website (an old tab)Ignored. The act is saved like any other.

Is this the best we can do?

  • Wire it instead? No. A honeypot earns its keep on a public form anyone can find. This page is behind a private link. A bot that has the link can skip the box, and a person with an autofilling password manager would lose real acts behind Saved.
  • Keep it but answer honestly ("Could not save")? Still no. Then the autofill case shows an error the firm cannot fix, because the box is invisible.
  • Is the rate limit enough on its own? For matter acts, yes: 30 an hour per firm. The people acts are capped at twelve people. A confirmation resend has no cap; that is noted for item 18 (acts a firm can trust), not added here.
