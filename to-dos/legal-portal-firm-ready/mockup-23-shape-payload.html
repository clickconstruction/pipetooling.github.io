How it is held

One file, _shared/legalMatterShape.ts, the item 2 pattern: a column list per table, the select strings (the list plus the PDF storage paths only the function reads), and shapeMatterForCounsel, which cuts every row of a built matter to its list before it is sent. A select widened later cannot leak by itself. The test sends whole rows carrying fifteen kinds of secret through the shaper: none come out, each row has exactly its list, and the shaped matter builds the same packet as the whole one.

Is this the best we can do?

  • Why shape twice? A select is a promise only until someone adds a column or writes select('*') again. The kernel is the contract and the test holds it.
  • Why keep the contact person's note? It is the only thing that says who the person is ("Project manager"), and the printed packet prints it. The table has no role column. (The firm print on #4601 reads role, which nobody sends: it should read note.)
  • Why keep the filed copy's link? The Paper tab's Copy column draws it. What documents travel is item 12's call.
  • Found on the way, left alone: coverage reads bid_id, contract_not_needed_at and contract_not_needed_reason on jobs, which the function never sent; adding them would change what the firm sees, so it waits for its own item. The GC's name is looked up only among the matters' payers, so a job whose GC is not the payer reads "GC".
