One firm, said in the schema

The decision of 2026-10-05: one collections law firm. The guide already says "One firm at a time", the portal and the Lien grid serve that firm, and Settings edits the one active row. The table did not say it: two active rows were possible, and every reader picks "the first active firm" in its own way.

What a second active firm does

Before
legal_firms
  id   name                    active
  f1   Sample & Partner, PLLC  true
  f2   Second Firm LLP         true   ← allowed

Settings shows f1 (oldest active). The desk's firm list orders by active, then age. The Lien desk's "copy the firm's link" reads the oldest active. A matter can be released to either, and each firm's portal shows only its own. Nothing says which one is "the firm".

After
CREATE UNIQUE INDEX legal_firms_one_active
  ON public.legal_firms ((true)) WHERE active;

insert … active = true
→ ERROR: duplicate key value violates unique
  constraint "legal_firms_one_active"

Settings, when a race in another tab saves a firm first:

One firm at a time: another firm is already active. Reload Settings to edit it.

Changing firms still works

Set the old firm's active to false, then add the new one. Inactive rows are unlimited, and their matters, links and recipients stay where they are.

Is this the best we can do?

  • Index or trigger? The index. A trigger is code that can be dropped, disabled or written wrong; a partial unique index on a constant is one line that Postgres enforces on every write, including a hand edit in the SQL editor.
  • What if prod already has two active firms? The migration checks first and stops with a sentence that says how many and what to do. Nothing changes until someone picks the one firm.
  • Should the copy change too? The guide already says "One firm at a time" and needed nothing. docs/ACCESS_CONTROL.md now says one active firm, and the table's comment names the index.
  • What does it lock? Building a unique index takes a SHARE lock on legal_firms (a handful of rows) for an instant; the file starts with SET lock_timeout = '3s'.
