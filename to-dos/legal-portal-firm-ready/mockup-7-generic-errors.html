What the firm reads when something breaks

Both portal functions answered an unexpected failure with the thrown error's own words, and the page printed them as they came. A Postgres error names tables and columns. On a law firm's screen that reads as a system nobody looks after.

What stays as written

The messages the functions write for the firm do not change. They tell the firm what to do.

StatusSentenceWhy it stays
404This link is no longer active. Please contact the office for a new one.the link was rotated or turned off
403That matter is not with your firm.the office pulled the matter back
429Too many changes in the last hour. Please try again later.the hourly limit
400Enter an amount. · Say what the amount is for. · Type your question. …the form's own checks
500Could not record the step. · Could not save that. · Could not save the rule.written by the function; say what failed, not how
500anything else → the generic sentence and a referencethe real error goes to the function's log with the same reference

Is this the best we can do?

  • Is a generic sentence enough for the firm to act? Not quite. The first draft said only "try again or contact the office", and the office would then have nothing to look up. Refined: every unexpected failure carries a short random reference, printed on the page and written beside the real error in the function's log. The firm reads it out; the office finds the line.
  • Does the reference leak anything? No. It is eight random letters and digits, minted per failure. The page prints only a reference of that shape, so a body that carried anything else is dropped.
  • What if the old function is still deployed tomorrow? The page applies the same rule itself: on a 5xx it prints the body's words only when they are one of the three sentences the functions write. So the demo is safe the moment the page ships, before anyone redeploys.
  • Why not filter the 4xx too? Every 4xx sentence is a literal in the code, written for the firm. None passes a database message through; the one place that reads a database error (adding a person twice) turns it into "That address is already on the list."
  • What about the email links? legal-notify-dispatch answers the confirm and stop pages with a kind only (confirmed, stopped, expired), and its POST is the cron tick behind a secret. Neither reaches a firm with an error's words, so it is left alone.
