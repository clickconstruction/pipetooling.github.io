read first What the code says that the audit did not

Nothing computes a job's "one line" today. "set % done", "no bid value", "no contract", "bill T+1", "quiet 6 days", "NEXT Thu 1–4 · Abraham" each come from a different chip on the card. PR 2 adds one kernel that picks the first that applies, in a fixed order (table below). The row shows that line and that chip; Needs me is "the kernel picked something red or amber".
The confirmations stay. Working → Ready to bill already asks two questions (parts reported · customer knows the work is done); Ready to bill → Bill opens the Bill Customer window; Billed → Paid opens Mark paid. Swipe-right does not replace any of them — it opens the same one, with one new line that states the consequence.
The window has no bid value and no "next bill" kernel. The tiles are Job total · Billed · Paid (all three already loaded). The bar's primary verb is the same next-line kernel, read from inside the window: Bill it, Send bill…, Set % done, Mark paid, Ready to bill. The tappable status stepper lives on the Edit tab; the bar's Status ▾ lists the stepper's allowed moves with the stepper's own guards.
A bug the phone card carries since v2.1241. On bill rows the big button reads the send-back label ("Delete draft bill", "Send back") but taps the forward action (Bill Customer, Mark paid). PR 2 retires the button on phones, and fixes the label on the ⋯ sheet where it also crosses.

Your five calls
  1. The swipe keeps the two-box confirmation (parts reported · customer knows). Recommended: yes — it is the office's rule, and the sheet is the confirmation with the consequence written on top. The alternative is a plain "Move it / Not yet".
  2. Needs me = a red or amber pick from the kernel, in the order above. Recommended: yes. Say if "no contract" should rank above "quiet N days", or if quiet should not count at all.
  3. The Overview folds closed by default on phones, remembered per device (the map already remembers Hide). Recommended: yes. The alternative keeps the map open and folds only the tiles and opportunities.
  4. Two PRs, 2a then 2b. Recommended: yes — the kernel ships with the list, the window reads it a PR later; one PR would touch eleven files across two surfaces.
  5. Arrived / Leaving only for people on the crew. Recommended: yes, with one caveat: if the office ever stamps Arrived on a tech's behalf, say so and the buttons stay for assistants behind the ⋯ sheet instead.
