Email reports, one modal — before and after

Jobs → Reports (toolbar) → Email reports modal

What changes

The two toolbar buttons on Jobs → Reports — Recurring Email Reports and Report email recipients — become one Email reports button that opens one modal. Inside, a one-sentence intro names the two kinds of report email, and two tabs (Digests · Every report) hold today's two bodies unchanged: the digest schedules list comes first with the preview/test toolbar folded under a 'Preview or send a test' disclosure, and the Every report tab keeps today's recipient cards. Not drawn here: the Dashboard's Recent Reports mail button now opens this same modal on the Every report tab, the phone links row shrinks to one Email reports link, and two Settings strings now read 'Jobs → Reports → Email reports'.

Assumptions the drawing made

  • The modals are shown stacked below the toolbar on a dimmed strip (page ground under the app's rgba(0,0,0,0.4) overlay = #909193), each with a small white caption naming which button opens it; in the app each modal covers the page on its own, and the Before's two modals never show at once.
  • The After modal is 720px wide as the approved Option A artboard drew it; today's Recurring Email Reports dialog is max-width 900px and the README does not name a width for the new shell.
  • The After's schedule lines read 'On · Mon · 3:00 AM' / 'On · Tue–Sat · 3:00 AM' as the approved mockup wrote them; today's code prints 'On · 03:00 · 1 · America/Chicago' (raw day numbers, 24h time, timezone) and the README calls the panel extraction a pure move, so a builder following the code literally would keep today's format.
  • The Before's preview toolbar shows Org = Robert and Recipient = Robert: the code labels scope leaders by name only (not name + email as the mockup drew) and the signed-in dev account is Robert; the real Org choice list depends on who is a master technician.
  • The two schedules (Last week recap, Yesterday recap) and the one recipient card (Malachi, all reports, auto-send and enabled) are the real rows the README names; both schedules show '1 recipient(s)' as the mockup did.
  • The Every report tab is shown only as its inactive tab; its body is today's recipient cards unchanged (the README and mockup both say so), so it is not redrawn.
  • Native controls (selects, radios, checkboxes, the collapsed disclosure) are drawn as static spans with inline SVG chevrons/checks in Chrome's light-theme look (#767676 control borders, #2563eb checked state); the app's SearchableSelect trigger keeps its own text chevron because that is literally what it renders.
  • Only the toolbar and the view chips row (Newest · By job · By person) are drawn from the Reports page; the report list below is unchanged and omitted.
  • Measured in Chrome with the system font: the Before toolbar's five items (basis 180px for the search box) exceed the 860px Reports column, so Templates wraps to a second line exactly as the app's flex-wrap rule does at that width; the After's four items fit on one line. Rendered heights: Before 1177px, After 712px, plus 5% slack.
