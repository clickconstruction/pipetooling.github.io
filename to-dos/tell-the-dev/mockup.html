Punch list #380 · the plan's sketch, revised after asking "is this the best we can do?" · every name is invented

The wrench: a note to the dev from any page

The owner's idea: a small wrench on every page. Press it, finish a sentence, and the note goes to the dev with the page it was written on. The first sketch answered where the wrench sits. This one answers a harder question: what would make people use it, and what would make each note worth reading.

The asker's seat

The dev wants more notes, sooner, from the people using each page, without waiting for someone to relay them.

The job behind the ask

The app already has this box. It sits at the bottom of each Help guide, and it has taken no notes since July. The pipe works. The door is in the wrong place.

The whole office

On a crew's phone both bottom corners are taken by Job Mode, and toasts use the top right. A floating wrench fits a desk. A phone needs doors that cover nothing.

★What the first sketch got wrong, and what changed

Six faults, each with its fix, and two things the owner added. The letters match the marks on the frames below.

A
A wrench alone says nothing. In a plumbing app it reads as a tool. Fix: it carries the words Tell the dev until the person has opened it once.
B
A sentence is a lot to ask of a tech on a phone. Fix: the page and its state do the talking. Confusing and Went wrong can be sent with no words at all.
C
The best moment was missed. People want to tell someone the second an error shows. Fix: every error line carries a Tell the dev press, with the error already attached.
D
On a phone, the header is out of reach inside a window. Most confusion happens in a window. Fix: the shared window's title row gets the wrench too.
E
The answer waited to be found. Fix: the wrench shows a dot when an answer is waiting, so the answer finds the sender.
G
The owner: a lost signal is not a fault to report. The phone already keeps the press and sends it when the signal is back. Rule: an error line that only says the signal dropped carries no Tell the dev press.
H
The owner: Fix mode. A row in the gear menu, beside Job Mode. On, the wrench shows. Off, it is gone from that person's screens. It starts on, so the test can be seen.
F
The dev's side was a list to read, not work ready to start. Fix: Copy as a brief hands a note to a coding session, and the usage ledger counts opens against sends.

4Looked at and left out

Each of these is better on paper. None belongs in a two-week test.

✕
A picture of the screen. It can hold a customer's address, a pay rate or an HR note, and it is slow on a phone. Open that page, viewed as the sender, shows the dev the same screen.
✕
Guessing confusion from presses. The usage ledger already counts presses and errors. It says where people struggle. Only words say why.
✕
Notes with no name. An answer has to reach someone, and a company this size has no real anonymity.
✕
Customers and public pages. A write box with no sign-in invites spam. A customer already has the text thread.
