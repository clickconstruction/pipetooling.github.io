**People → HR** keeps a private file on each person — employees, helpers, subs, and office alike. Only devs can see this tab, and nothing in it is ever visible to any other role.

Each person's file has three layers:

- **Summary** — the one-page read: trajectory, reliability, pay, watch items. Maintained by the agent.
- **Narrative** — the chronological story of their time with the company. Also maintained by the agent.
- **Raw entries** — the dated facts everything else is built from. This is the only layer you write here.

## Add what happened

1. Open **People → HR** and pick the person. The dot next to each name tells you the file's state: {{chip:green|●}} summary current, {{chip:yellow|●}} entries newer than the summary, {{chip:gray|●}} no file yet.
2. Go to **Raw entries**, set the date it **happened** (not today's date, unless it happened today), pick a source — Conversation, Payroll event, Incident, Review, Milestone, Job event — and write the fact.
3. Tap {{button:blue|Add entry}}.

:::example Good entry
"Sit-down about a fall raise and the path to Master hours — agreed to revisit both at the November review." Dated the day of the conversation, source **Review**.
:::

Stick to facts with dates. If it's an impression, say whose: "my read after the call was…".

## Entries can't be edited or deleted

That's deliberate — the raw log is trustworthy because nothing in it can be quietly rewritten. Made a mistake? Add a new entry: "Correction to the Aug 19 entry: …".

## Keeping the summary fresh

When you add entries, the summary falls behind — the person's dot turns amber and the Summary view shows how many entries it hasn't covered. Ask the agent to bring the file current; it rewrites the summary and extends the narrative from the raw entries.
