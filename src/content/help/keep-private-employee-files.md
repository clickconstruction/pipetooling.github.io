People → HR keeps a private file on each person. Only devs can see this tab.

The files cover employees, helpers, subs, and office alike. Nothing in **People → HR** is ever visible to any other role.

Each person's file has three layers:

- **Summary** is the one-page read: trajectory, reliability, pay, watch items. The agent maintains it.
- **Narrative** is the chronological story of their time with the company. The agent maintains it too.
- **Raw entries** are the dated facts everything else is built from. This is the only layer you write here.

## Add what happened

1. You open **People → HR** and pick the person. The dot next to each name tells you the file's state. {{chip:green|●}} means the summary is current. {{chip:yellow|●}} means entries are newer than the summary. {{chip:gray|●}} means no file yet.
2. You go to **Raw entries** and set the date it **happened**. That is not today's date, unless it happened today. You pick a source: Conversation, Payroll event, Incident, Review, Milestone, or Job event. Then you write the fact.
3. You tap {{button:blue|Add entry}}.

:::example Good entry
"Sit-down about a fall raise and the path to Leader hours — agreed to revisit both at the November review." Dated the day of the conversation, source **Review**.
:::

Stick to facts with dates. If it is an impression, say whose: "my read after the call was…".

## Entries can't be edited or deleted

That is deliberate. The raw log is trustworthy because nothing in it can be quietly rewritten. Made a mistake? You add a new entry: "Correction to the Aug 19 entry: …".

## Keeping the summary fresh

When you add entries, the summary falls behind. The person's dot turns amber. The Summary view shows how many entries it has not covered. You ask the agent to bring the file current. It rewrites the summary and extends the narrative from the raw entries.
