## What this surface is

[`src/pages/Checklist.tsx`](../src/pages/Checklist.tsx) (**~3,500 lines** at 2026-08-23; the Review tab grew the Goals strip + ledger and the roadmap task-context modal in the 2026-08-20→23 train) is the task-checklist page, tab-switched on a single `activeTab` state (`type ChecklistTab = 'today' | 'history' | 'roadmap' | 'review' | 'manage'`). Unusually for this repo's God components, the page is **already internally seamed**: each tab is a separate in-file function component (`ChecklistTodayTab`, `ChecklistHistoryTab`, `ChecklistOutstandingTab` = the Review tab, `ChecklistManageTab`) with a small explicit prop surface, and the Roadmap tab is **already extracted** to [`src/components/checklist/ChecklistTechTreeTab.tsx`](../src/components/checklist/ChecklistTechTreeTab.tsx) (**~1,840 lines** after the v2.2156 sub-decomposition; it peaked at 2,825 during the 2026-08-20→23 Plan/Timeline/Next-up train) — its internal structure is mapped here too.

Consequence: most Stage-B moves on this page are near-mechanical **file moves of already-isolated components**, not the cut-a-tab-out-of-a-monolith surgery Bids/Materials needed. The real work is Stage A (pure kernels + tests) and the tech-tree sub-decomposition.

This map is coupling/refactor-oriented; for feature behavior see `PROJECT_DOCUMENTATION.md` and `GLOSSARY.md` (checklists, tech tree / roadmap).

### The parent shell (`Checklist()` — lines ~57–247)

- **Owns:** `role` (from `users.role`), `activeTab`, `loading`, `error`/`setError`, `editItemId`/`setEditItemId` (the one cross-tab selection pointer), `onRoadmapUrlParamChange` (writes `?tab=roadmap&roadmap=<uuid>`).
- **Role gates:** `canManageChecklists` = dev / master_technician / [`isAssistantLike`](../src/lib/subcontractorLikeRole.ts) (shows Review + Manage tabs); `canEditTechTree` = the same **plus `primary`** (mirrors `is_dev_or_master_or_assistant()` in DB per the in-code comment) — passed to the tech tree.
- **URL router:** `?tab=` read/write on every tab button; when no `?tab` and role is known, the **default tab is role-dependent** — `review` for staff (`canManageChecklists` roles), `today` for everyone else — written with `replace: true`. `?roadmap=<uuid>` is read here and passed to `ChecklistTechTreeTab` as `roadmapIdFromUrl`.
- **Shared modal:** [`ChecklistItemEditModal`](../src/components/ChecklistItemEditModal.tsx) (619 lines, extracted) renders at page level behind `editItemId`, opened from **both** Review and Manage. On save it dispatches `window` event `checklist-item-saved`.
- **Layout quirk:** the page container switches padding and becomes a flex column only when `activeTab === 'roadmap'` (the canvas needs `flex: 1; minHeight: 0`).

## The shared substrate (or lack of one)

**There is no shared data engine and no shared record pointer on this page.** Nothing like Bids' `setSharedBid` + `useBidPricingEngine` exists:

1. **Every tab self-loads its own data** (`loadToday`/`loadUpcoming`, `loadHistory`, `loadOutstanding`, `loadItems`, and the tech tree's `useTechTreeData`). No caches are shared between tabs; switching tabs remounts and refetches.
2. The only cross-tab **UI pointer** is `editItemId` → the shared `ChecklistItemEditModal` (opened from Review and Manage). It stays in the parent (playbook rule: modal opened from 2+ tabs is page-level).
3. Cross-tab **freshness** is event-based, not state-based: [`ChecklistAddModal`](../src/components/ChecklistAddModal.tsx) (a **global** modal mounted in [`Layout.tsx`](../src/components/Layout.tsx), opened via [`ChecklistAddModalContext`](../src/contexts/ChecklistAddModalContext.tsx)) and `ChecklistItemEditModal` both dispatch the `checklist-item-saved` window event; Review and Manage each register a listener that calls their own loader via a `loadXRef` pattern. This event contract must survive extraction unchanged.
4. The tech tree is a **separate data universe** (its own five `checklist_tech_tree_*` tables) sharing nothing with the other four tabs except `authUserId`, `setError`, and the URL params.

**What this means for extraction:** no seam hook is needed before moving tabs — each tab's prop surface is already its full contract. The absence of shared caches is why this page is low-risk. The one thing that must NOT move into a child is the `?tab`/`?roadmap` router + `editItemId` + the edit modal.

## Per-tab dossiers

Line numbers are as of 2026-07-29 (v2.1088 era) and rot — search the symbol.

### `today` — Today (`ChecklistTodayTab`, ~249–868)

- **Render location:** `activeTab === 'today'` → `<ChecklistTodayTab authUserId isDev={role === 'dev'} setError />`.
- **Owned local state (moves with it):** `todayInstances`, `upcomingInstances`, `upcomingExpanded`, `loading`, `toggleCompleteInFlightRef` (per-instance re-entry guard Set), `notesByInstance` (draft notes keyed by instance id), the Forward-modal cluster (`fwdInstance`, `fwdTitle`, `fwdAssigneeId`, `fwdSaving` + derived `fwdMissingFields`/`fwdCanSubmit`), `users` (dev-only assignee list), `muteModalItemId`, `muteModalTitle`.
- **Cross-tab/shared state:** none. Props only.
- **Derived:** `fwdMissingFields`/`fwdCanSubmit` (computed in render body, not memos).
- **Handlers/loaders:**
  - `loadToday()` — three-step: (1) today's instances via `checklist_instances` with `checklist_items(...)` + `checklist_instance_assignees!inner(user_id)` filtered to the signed-in user; (2) overdue instances of items flagged `show_until_completed` (`completed_at IS NULL`, `scheduled_date < today`); (3) fetches `checklist_item_assignees.display_order` for the merged item set and sorts overdue-first-merged rows by `display_order` (999999 fallback) then `scheduled_date`. Seeds `notesByInstance` from persisted notes.
  - `loadUpcoming()` — next 30 future instances.
  - `toggleComplete(inst)` — optimistic update with `toggleCompleteInFlightRef` guard; un-completing nulls `notes` and drops the draft; revert-on-error restores both; on complete fires `sendCompletionNotifications` and `maybeCreateNextInstance` (fire-and-forget `void`).
  - `sendCompletionNotifications(inst)` — re-reads the item's `notify_on_complete_user_id` / `notify_creator_on_complete` / `created_by_user_id` and invokes edge function **`send-checklist-notification`** per recipient (tag `checklist-<instanceId>`); errors swallowed.
  - `maybeCreateNextInstance(inst)` — the `days_after_completion` repeat engine: reads `repeat_type`/`repeat_days_after`/`repeat_end_date` + item assignees, computes next date from `inst.scheduled_date` (module helper `toLocalDateString`), skips if past `repeat_end_date` or an instance already exists, inserts `checklist_instances` + `checklist_instance_assignees`.
  - `saveNotes(inst)` (onBlur autosave), `isNotificationRecipient(inst)` (gates the 🔕 mute button), `openMuteModal`, `openFwd`, `saveFwd`.
  - `saveFwd()` — the **Forward** flow: clones the source item's notify/reminder fields into a brand-new `checklist_items` row (`repeat_type: 'once'`, `start_date` = the instance's date), inserts a `checklist_item_assignees` row using [`getNextDisplayOrders`](../src/utils/checklistOrder.ts), creates the new instance + instance-assignee, then **deletes the original instance**.
- **Supabase tables / functions:** `checklist_instances` (SELECT/UPDATE/INSERT/DELETE), `checklist_items` (SELECT/INSERT), `checklist_item_assignees` (SELECT/INSERT), `checklist_instance_assignees` (INSERT), `users` (dev-only list); edge fn `send-checklist-notification`.
- **Sub-components:** [`ChecklistTitleWithLinks`](../src/components/ChecklistTitleWithLinks.tsx) (extracted), [`ChecklistItemMuteModal`](../src/components/ChecklistItemMuteModal.tsx) (extracted, this tab's own instance), inline Forward modal (full JSX, ~86 lines — **duplicated in Review**, see below).
- **External coupling:** none beyond the edge fn. Note the same completion engine (notifications + days-after-completion rescheduling) was already duplicated into [`DashboardMyInboxCard`](../src/components/dashboard/DashboardMyInboxCard.tsx) during the Dashboard decomposition — three copies exist in the app.
- **Extraction status + risk + approach:** In-file. **Low-med risk** — self-contained; the only subtlety is preserving optimistic/revert semantics and the fire-and-forget ordering in `toggleComplete`. Stage A first (see inventory): `maybeCreateNextInstance` date math and the notification-recipient derivation are the shared kernels. Then move the whole function component + the Forward modal to `src/components/checklist/ChecklistTodayTab.tsx` verbatim. Preserve quirk: the Forward select has **no placeholder option** — `fwdAssigneeId` starts `''` so the select *displays* the first user while the state stays empty and the "Required: Assignee" hint shows until the user actively picks (Review's copy instead pre-fills `rowUserId`).

### `history` — History (`ChecklistHistoryTab`, ~870–1125)

- **Render location:** `activeTab === 'history'` → `<ChecklistHistoryTab authUserId canViewOthers={canManageChecklists} canEditHistory={role === 'dev'} setError />`.
- **Owned local state:** `instances`, `loading`, `monthsBack` (3/6/12, default 6), `users` (loaded when `canViewOthers`), `selectedUserId` (defaults to self; staff can view others), `editMode` (dev-only checkbox), `cyclingCell` (in-flight cell key), `deletedCells` (Set of optimistically-whitened cells).
- **Cross-tab/shared state:** none.
- **Derived (computed inline in the render body — not memos):** `byItem` map (`itemId → {title, links, dates: {date → 'completed' | 'completed_by_other' | 'incomplete'}}`; `completed_by_other` when `completed_by_user_id` differs from `selectedUserId`), `sortedDates` (only the **last 60** render: `sortedDates.slice(-60)` in both header and rows), `instanceByKey` (`` `${itemId}-${date}` `` → instance).
- **Handlers/loaders:** `loadHistory()` (range = today − `monthsBack` months → today, joined titles + `checklist_instance_assignees!inner` on `selectedUserId`); `handleCycleStatus(itemId, date)` — dev edit-mode cell cycle: **incomplete → delete** the instance (optimistic white via `deletedCells`, then a `setTimeout(2000)` reload + cell un-mark); **completed → delete + reinsert** as incomplete (with `checklist_instance_assignees` row for `selectedUserId`); **not-due → insert** a completed instance. Guarded by `cyclingCell`.
- **Supabase tables:** `checklist_instances` (SELECT/DELETE/INSERT), `checklist_instance_assignees` (INSERT), `users`.
- **Sub-components:** `ChecklistTitleWithLinks` only. Grid cells are raw divs (green `#22c55e` / yellow `#eab308` / red `#ef4444` / near-white `#f9fafb` — literal status colors, per convention).
- **External coupling:** none.
- **Extraction status + risk + approach:** In-file. **Lowest risk on the page — extract first** (the momentum-builder, like `po-generator` was for Materials). Props are already the full contract. Stage A: lift the `byItem`/`sortedDates`/`instanceByKey` derivation into a pure `buildChecklistHistoryMatrix(instances, selectedUserId)` in `src/lib/checklist/` + tests (status precedence, completed-by-other, last-60 slicing left in the component or parameterized). Preserve quirks: the 2-second optimistic `deletedCells` window, and that `loadHistory` errors are silently dropped (only `setLoading(false)`).

### `review` — Review (`ChecklistOutstandingTab`, ~1382–2068, plus module components ~1134–1380)

- **Render location:** `activeTab === 'review' && canManageChecklists` → `<ChecklistOutstandingTab authUserId isDev={role === 'dev'} canManageChecklists setError setEditItemId />`.
- **Owned local state:** `loading`, `byUser` (`Array<{userId, name, count, instances}>`), `expandedUserId`, `dateRange` (`'next_day' | 'next_week' | 'non_repeating' | 'missed'`, default `'non_repeating'`), `remindingUserId`, the second Forward cluster (`fwdInstance`, `fwdTitle`, `fwdAssigneeId`, `fwdSaving`), `users` (dev-only), `deletingInstanceId`, `completingInstanceId`, `reorderingUserId`, `outstandingDeletePending` (delete-confirm modal).
- **Cross-tab/shared state (stays in parent):** `setEditItemId` (opens the page-level `ChecklistItemEditModal` from the row pencil). Uses the app-global `useChecklistAddModal()` context ("Add task" button on the expanded person row, pre-assigned via `openAddModal(userId)`). Listens for the **`checklist-item-saved`** window event (via `loadOutstandingRef`) to refresh after the global add modal or the shared edit modal saves.
- **Derived:** `fwdMissingFields`/`fwdCanSubmit` (same pattern as Today).
- **Handlers/loaders:**
  - `loadOutstanding()` — incomplete instances with `checklist_items(title, links, repeat_type, reminder_scope)` + `checklist_instance_assignees(user_id, users(name, email))`; date-range filters: `missed` = `scheduled_date <` yesterday **and** (client-side) `reminder_scope !== 'today_and_overdue'` (those items already nag daily via the reminder cron); `non_repeating` = (client-side) `repeat_type === 'once'` with no date bound; `next_day` = tomorrow only; `next_week` = tomorrow → +7d. Groups per assignee, fetches `checklist_item_assignees.display_order` for (user × item), sorts each person's list by display_order then date, sorts people by count desc.
  - `markComplete(inst)` — dev row action; `.select('id')` after UPDATE and errors if `updatedRows` is empty (RLS/visibility guard); then **inline near-duplicates** of Today's `sendCompletionNotifications` (body prefix `"Dev completed:"`) and `maybeCreateNextInstance` logic (same `days_after_completion` math, sequential assignee inserts).
  - `saveFwd()` — near-duplicate of Today's `saveFwd` (same clone-as-`once` + delete-original flow; differs only in the follow-up reload).
  - `sendReminder(userId, instances)` — edge fn `send-checklist-notification` with a truncating body builder (1 title / ≤3 joined / "and N more"), tag `task-reminder`.
  - `persistOutstandingOrderForUser(userId, ordered)` — sequential `checklist_item_assignees.display_order = i+1` UPDATEs wrapped in [`withSupabaseRetry`](../src/utils/errorHandling.ts); `onOutstandingDragEnd(userId, instances)` (curried) uses dnd-kit `arrayMove`.
  - `openOutstandingDeleteModal` / `performDeleteOutstandingInstance`, `openFwd(inst, rowUserId)` (pre-fills assignee with the row's user).
- **Supabase tables / functions:** `checklist_instances` (SELECT/UPDATE/DELETE/INSERT), `checklist_items` (SELECT/INSERT), `checklist_item_assignees` (SELECT/UPDATE/INSERT), `checklist_instance_assignees` (INSERT), `users`; edge fn `send-checklist-notification`.
- **Sub-components:** module-level `OutstandingByPersonSortableRow` (~1134–1311; dnd-kit `useSortable` row with dev action buttons: complete ✓, edit → `setEditItemId`, delete, FWD) and `OutstandingByPersonSortableList` (~1313–1380; `DndContext` + `SortableContext`, plain `<ul>` fallback when `!canManageChecklists`) — both **move with this tab**. [`ChecklistReviewInboxes`](../src/components/checklist/ChecklistReviewInboxes.tsx) (**extracted**, 134 lines) renders below the table and is fully self-contained (owns [`useDispatchInbox`](../src/hooks/useDispatchInbox.ts) + [`useEstimatorInbox`](../src/hooks/useEstimatorInbox.ts) + `HelpFeedbackInboxSection` + the dismissed-archive modal; hides itself for assistant-like roles). Inline: delete-confirm modal, Forward modal (the **second copy** of Today's JSX).
- **External coupling:** `ChecklistAddModalContext` (global), `checklist-item-saved` window event, edge fn. `useEstimatorInbox`'s realtime channels are named `checklist-estimator-*` and are also mounted by Dashboard/DispatchMode via the same hook (routes never coexist — noted in RECENT_FEATURES v2.9xx Dashboard extraction #4).
- **Extraction status + risk + approach:** In-file. **Medium risk** — largest tab, but its shared touchpoints are all already props/contexts. Move `OutstandingByPersonSortableRow` + `OutstandingByPersonSortableList` + the tab into `src/components/checklist/ChecklistOutstandingTab.tsx` in one Stage B; `setEditItemId` stays a prop; the `checklist-item-saved` listener moves with the tab (it's tab-local). Stage A first: the `loadOutstanding` grouping/sort and the reminder-body builder (see inventory). Do **not** merge the duplicated Forward/completion logic with Today's during the move (behavior-preserving rule) — record it as the follow-on dedupe below.

## Preserve-quirks list (odd but load-bearing — do not "fix" during the move)

1. **Role-dependent default tab** (`review` for staff, `today` otherwise) written with `replace: true` only when `?tab` is absent and `role` has resolved.
2. **Today = overdue-first merge**: overdue instances are only pulled for items with `show_until_completed`, prepended before today's rows, then the whole list is re-sorted by per-user `display_order`.
3. **Un-completing clears notes** (`notes: null`) and drops the local draft; the revert path restores the previous notes only when non-empty.
4. **Forward deletes the original instance** and mints a new single-shot `checklist_items` row (copying notify/reminder fields) — history for the original item loses that date. Today's copy starts with `fwdAssigneeId=''` (placeholder-less select quirk); Review's pre-fills the row's user.
5. **`checklist-item-saved` window event** is the only cross-surface refresh: dispatched by `ChecklistAddModal` (global, in Layout) and `ChecklistItemEditModal`; consumed by Review + Manage via `loadXRef` listeners. Extracted tabs must keep registering it.
6. **History cell cycle** (dev edit mode): incomplete→delete uses a 2 s optimistic `deletedCells` window before reload; completed→delete-then-reinsert (new row id); only the **last 60** distinct dates render.
7. **`missed` filter double-gate**: server `scheduled_date < yesterday` AND client `reminder_scope !== 'today_and_overdue'` (those items self-nag via the reminder cron, so the Review list hides them).
8. **`markComplete` verifies `updatedRows.length`** after UPDATE (`.select('id')`) and errors on 0 rows — an RLS/staleness guard; keep it.
9. **Reorder persists sequentially** (`display_order = i+1`, one UPDATE per row via `withSupabaseRetry`), keyed on (`checklist_item_id`, `user_id`) — instance order is per-person, not per-instance.
10. **Manage completion is derived from ALL instances** of the loaded items in one unbounded `.in()` query; a one-off item is "Complete" only when `total > 0 && !hasIncomplete`.
11. **Tech tree loads all edges unscoped** then filters to the roadmap's groups client-side; `blockingLoadOverlayRef` keeps refetches from unmounting the canvas.
12. **Layout cache keyed on `structuralKey`** (group ids + edges + collapsed set): task add/toggle must NOT re-run dagre; `fitView` refits happen only on `organizeVersion` bumps (Organize / Collapse all / Show all / bootstrap), never on node-count change.
13. **Collapse-all bootstrap** runs once per (auth, roadmap); the group-reconciliation effect auto-collapses newly added groups and prunes removed ids; a group created by dragging a connection into empty canvas keeps its drop position via `newGroupManualPositionFromConnectRef`.
14. **Fullscreen**: DOM Fullscreen API with a CSS `position: fixed` fallback (iPhone Safari), Esc + body-scroll lock in CSS mode, double-rAF `window.dispatchEvent(new Event('resize'))` to make React Flow re-measure, and **all eight tech-tree modals portal into the canvas shell while fullscreen** (`roadmapModalPortalHost`; the seventh is the v2.1941 `ChecklistTechTreeOrderStagesModal`, the eighth the v2.1901/1949 task card — drag-reorder of `checklist_tech_tree_groups.sort_index`, which drives the v2.1940 stage-number badges on Map and Plan).
15. **Task permissions**: `canEditStructure = canEditTechTree || roadmap member role 'editor'`; non-staff can toggle a task only when its group is unlocked AND they are an assignee; **unassigned tasks are staff-only** (`canActOnTask`).
16. **`handleCreateRoadmap` uses `window.prompt`** and inserts the creator as an `editor` member row before navigating.
17. Edge-fn notification failures are swallowed everywhere (`try {} catch { /* ignore */ }`) — completion must never fail because a push failed.
