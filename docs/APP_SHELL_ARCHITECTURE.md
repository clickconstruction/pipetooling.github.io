## What this surface is

The shell is everything around a page. `App.tsx` decides which of **69 `<Route>` elements** renders and wraps the signed-in tree in **23 providers**. `Layout.tsx` draws the chrome every signed-in user sees: the top nav (different per role), the header toolbar (search, task buttons, Job Mode "Contact:" row), the ⚙ gear menu (mode toggles, secondary pages, sign out, reloads), the phone hamburger or the assistant's phone dock, the Dispatch/Job Mode footers, the Pin Mode footer, the twin/read-only/customer-waiting banners, the impersonation Exit button, and the route `<Outlet>` inside a chunk-error boundary. It also mounts 12 app-wide modal and deep-link components.

### Key structural facts

1. **Two gates, two sources of truth.** *Route access* is the kernel [`isPathAllowedForRole`](../src/lib/layoutRouteAccess.ts), enforced by Layout's guard effect (399–404). *Nav visibility* is inline JSX: `renderNavLinks` branches, `canShowMaterialsNav`/`canShowChecklistNav`/`canShowMapNav` (496–528), and the icon-cluster and gear gates. No test checks that a link a role sees passes the guard. That gap is where the drift items below come from.
2. **Cold load has `role === null` for ~0.5 s.** The guard skips null (400). `renderNavLinks` renders the **primary** branch for null (712). `canShowMaterialsNav`/`canShowChecklistNav` and the Documents gear gate admit null. `navContentKey` (249) re-measures nav fit when the role lands. The search provider **always** wraps the body (2308–2312), because a conditional wrapper remounted the whole app when `role` flipped.
3. **Mode precedence:** Farm > Dispatch > Job. `farmModeActive` (152) turns off `dispatchModeActive` (164) and `jobModeFooterActive` (178–179). Dispatch turns off Job. `phoneDockActive` (270) = Dispatch Mode ∧ `isMobile` ∧ an assistant-like dock (`resolveDockSlots`). While the dock is up, the hamburger (891), the gear (1286) and the Customers/People icons (1246) hide, and the More sheet carries them.
4. **`isMobile` is not a breakpoint alone.** It is `viewportNarrow` (≤640 px, 238) **or** `navOverflowCollapsed` (`useNavFitCollapse(navRef, …)` 250). Nothing that feeds `navContentKey` may depend on `isMobile` (comment 245–248).
5. **Two modal-mount patterns.** 8 providers render their own modal: BillCustomer → `SendRecordInvoiceModal`, TestReport, JobForm, BidPreview, JobDetail → `DetailJobModal`/`JobWindowModal`, CustomerProfile, JobHoursStory, ActiveAccounts. The rest hold state only, and **Layout** renders the UI (2292–2303): ChecklistAdd, DispatchTask, EstimatorTask, UserReview (+ deep-link handler), PersonDesk drawer (+ deep-link handler) + QuickSheet, NewCustomer, NewProject, EditProject, EditCustomer.

## Per-region dossiers

### A. Boot + app-wide providers (App.tsx)

- **Render:** `App` 369–383. Outside the router's routes sit `ThemeProvider`, `ToastProvider`, `ConfirmDialogProvider`, `LedgerDisplayPrefixProvider` (via bridge 355–358) and `DispatchNoteRequirementsProvider` (via bridge 360–367), and they are mounted for **public pages too**. The `/` element (249–302) nests 23 providers in this order: `RealtimeLifecycle` → `ForceReload` → `ChecklistAddModal` → `DispatchTaskModal` → `EstimatorTaskModal` → `NewCustomerModal` → `NewProjectModal` → `EditCustomerModal` → `EditProjectModal` → `BillCustomerModal` → `TestReportModal` → `JobDetailOpenerBridge` → `JobFormModal` → `BidPreviewModal` → `DailyGoalsGate` → `JobsListCache` (569-line data cache) → `UpdateFocusOpenerBridge` → `JobDetailModal` → `CustomerProfileModal` → `JobHoursStoryModal` → `UserReviewModal` → `ActiveAccountsModal` → `PersonDesk` → `Layout`.
- **Owned state:** `slow` (`AuthGateLoadingScreen` 101). **Effects:** 5 s slow timer (102–105), `session-expiring` window event → warning toast (194–205), magic-link hash (153–181).
- **Data:** `supabase.auth.setSession` (165). Realtime: `ForceReloadProvider` holds the `force-reload` broadcast channel. `RealtimeLifecycleProvider` drops **all** channels after 5 min hidden and bumps `useRealtimeEpoch`.
- **Coupling:** provider **order is load-bearing**. `JobDetailOpenerBridge` sits above `JobFormModal` so the form singleton can open Job Detail, which is owned lower down. `UpdateFocusOpenerBridge` mirrors it. `UpdatePrompt` (auto-reload at a quiet moment) mounts beside `<Routes>`.
- **Tests:** `useAuth.render.test.tsx` (2), `UpdatePrompt.render.test.tsx` (9), `chunkLoadRecovery.test.ts` (12, main.tsx's preload handler), `RouteLoadingFallback.render.test.tsx` (4). **No test renders `App`**. `AuthHandler`, `AuthGateLoadingScreen`, `ForceReloadContext` and `RealtimeLifecycleContext` are untested.
- **Approach:** optional Stage B. Move the pyramid to `AuthedShellProviders` verbatim (same order). Leave the `<Route>` literals in `App.tsx` (see B).
