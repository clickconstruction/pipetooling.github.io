## Shared substrate

- **Cover Letter + Submittals share the parent's pricing pointer.** `selectedBidForPricing` (Bids.tsx; `setSharedBid` writes 8 selections, these two tabs have none of their own) is passed as a controlled prop; `selectBidAndSyncUrl(bid, tab)` writes `?tab=&bidId=` and the router restores both tabs from its workflow `bidTabs` list (~1971). Neither child may own selection.
- **Cover Letter's data engine is split.** The parent owns the pricing engine (`bidVersions`, `priceBookVersions`, `pricingCountRows`, `coverLetterPricingRows`, active version / pricing ids) and the 8 content maps; the tab runs a **second, private engine** (CL-5 bundle pricing, CL-6 version GC map + sends, CL-9 schedule / materials, CL-3 defaults) through 6 of its 8 effects (292, 322, 378, 510, 529, 546; the other two, 243 and 266, are CL-11's alt-text hydrate and quick-add reset). Hook seam before any Stage B: `useCoverLetterBundle` (CL-5 + CL-6) and `usePaymentSchedule` (CL-9). The derived letter (CL-4) is the substrate every card reads — after Stage A it is one call whose result is passed down.
- **Submittals has its own engine** (SU-3): one bid's revisions, items, room, people, events, messages, tasks, picks. Every panel reads and reloads it → `useBidSubmittal(bidId)` first.
- **Builder Review has no selection pointer.** It is customer-keyed; its substrate is parent caches (`peopleBids`, `gcPacketsByBid`, customers, contacts, contact persons, `lastContactFromEntries`) plus the parent-owned deep-link highlight, and a private prefs store (`customer_followup_prefs`, BR-4).
- The three tabs share **no state with each other**. Shared kits: the bid-picker trio + search predicate (Cover Letter, Submittals), `BidWorkflowTabTitleWithPreview` + `bidPreview` (Cover Letter, Submittals), `CustomerNotesTable`, `BidLostQuickPopover`, the stale kernels and `localStorage['bids_followup_stale_days']` (Builder Review with the Followup "By status" lens).

## Hazards

**Money paths (Cover Letter).**
- Mark sent writes `bids.bid_date_sent`, `bids.bid_value` and `bid_version_sends.value`; the value is `headlineAmount` (CL-4) — custom amount, else (version bundle active) `boardValueForRule` (org rule from `app_settings`) falling back to the letter total, else (no bundle) active pricing. `markSentToday` stamps `bid_value` only for the bid's own GC (`isOwnGc`), only sections with a version and revenue > 0 get send rows, and the roll-up date is the first send (the `sync_bid_date_sent_from_sends` trigger enforces the same rule).
- **Display ≠ stamp:** on an all-alternates same-page packet the studio shows `displayHeadlineAmount` (the leading alternate) while Mark sent passes `headlineAmount` (the base sum — 0 there under the default `base_sum` rule → no `bid_value` write; under `active_star` it is the active pricing's revenue). Keep the split.
- `totalsResolved` (J13-F3) gates Print, Copy & open in Google Docs and the header Print only; Mark sent has its own `> 0` guards.
- `effectiveRevenue` is duplicated in `lib/bidDocuments/approvalPdf.ts` 530–533, and the parent's `downloadApprovalPdf` (1669–1687) falls back to `DEFAULT_EXCLUSIONS` / `DEFAULT_TERMS_AND_WARRANTY`, **ignoring the org defaults** the letter uses. The 8 content maps are session-only (lost on reload). Out of scope for a move.
- Schedule-of-Values row writes (insert / update / delete / reorder / stage shares) and version / pricing writes (`toggleVersionInclude`, `setScenarioOffered`, `setVersionAlternate`, `reorderVersion`) check **no error and no refused-row count**; only `bids` updates use `bidUpdateRefused`. `togglePaymentScheduleEnabled` seeds default rows when the closure's `paymentScheduleRows` is empty — toggling before the hydrate read (322) lands can seed on top of existing rows.
