## What this surface is

[`src/components/jobs/SendRecordInvoiceModal.tsx`](../src/components/jobs/SendRecordInvoiceModal.tsx) (3,907 lines; the component `SendRecordInvoiceModal` is L408–3907 = 3,500 lines) is the **Bill Customer** modal — the single surface where a ready-to-bill invoice becomes a customer-facing bill through one of three channels: **Stripe bill** (hosted Stripe invoice via edge functions), **Physical invoice** (client-built jsPDF emailed via Resend), or **HouseCall Pro** (record-only client UPDATE — no external side effects; tucked behind a ▾ caret since v2.1531). It is a modal, not a page — same method as [`JOB_FORM_MODAL_ARCHITECTURE.md`](./JOB_FORM_MODAL_ARCHITECTURE.md).

Census at `f423bd6e5` (fact sheet): **66 `useState`**, **14 effects** (13 `useEffect` + 1 `useLayoutEffect`), **12 `useMemo`**, **8 `useCallback`**, **6 `useRef`**, 2 context hooks (`useAuth`, `useToastContext`), 14 handlers/inner functions (3 async submit paths), 2 module components (`SendRecordInvoiceModal`, `BillCustomerMemoPresetRow`), 6 module functions, 57 local imports, **14 extracted child components** composed (`StripeBillPreSubmitPreview`, `StripeBillingModeToggle`, `HostedStripeBillPanel`, `StripeInvoiceSharePanel`, `StripeInvoiceSendFromStripeButton`, `StripeInvoicePreviewMeta`, `StripeInvoiceLinesSummary`, `PhysicalInvoicePreview`, `BillCustomerPreviewLineEditModal`, `BillCustomerDiscountStrip`, `BillCustomerOwnerLine`, `BillCustomerReturnedChecksLine`, `BillCustomerLienReleaseStrip`, `JobContractStrip`).

The modal is **lib-heavy**: calculation / formatting / document building lives in tested `src/lib/*` kernels — `billing/proposedPrimaryRtbAmount` (the plan), `billing/localStripeBillPreview`, `jobs/billToParty` + `jobs/billVisibility` (both re-export the Deno `supabase/functions/_shared/*` rule so UI and edge fns can't disagree), `jobs/billCopyRecipients`, `jobs/invoiceBillTo`, `jobs/discountLine`, `hazmatRollIn`, `invoiceScopedFixtures`, `physicalInvoiceDocument`, `physicalInvoicePdf`, `stripeInvoicePreview`, `stripeInvoiceFooter`, `physicalInvoiceFooter`, `billCustomerMemoPresets`, `billingStripeModePref`, plus `supabase/functions/_shared/paidJobBillGuard` imported straight from the Deno shared dir. What remains inline is orchestration: the billing-target plan + commit-time ensure, the recipient/payer resolution effect, hazmat detection, the discount apply path, the three submit paths, **three hand-mirrored fee compositions**, and ~1,570 lines of render JSX (L2334–3906).

It is switched on a single local `tab` state (`const [tab, setTab] = useState<BillCustomerMainTab>('stripe')`, L444):

```
'stripe' | 'housecallpro' | 'physical'
```

The master open-reset (L881–936) **always** lands on `'stripe'` and re-hides HCP (`setHcpTabRevealed(false)`) — v2.1531; a no-email job no longer defaults to HCP, the missing-email banner fixes it inline. Tab bar: **Stripe bill · Physical invoice · ▾** (the caret sets `hcpTabRevealed`; HCP shows when `hcpTabRevealed || tab === 'housecallpro'`). Domain behavior: [`BILLING_FLOWS.md`](./BILLING_FLOWS.md) §"The three billing channels (Bill Customer)".

### Key structural facts

1. **Selection lives OUTSIDE the modal.** The "selected record" is the `payload: SendRecordInvoicePayload | null` prop (`kind:'job' | 'invoice'`, [`SendRecordInvoiceModal.types.ts`](../src/components/jobs/SendRecordInvoiceModal.types.ts)), owned by [`BillCustomerModalContext`](../src/contexts/BillCustomerModalContext.tsx) — the only production render site (lazy-loaded, `BILL_CUSTOMER_OVERLAY_Z_INDEX = 1020`; the prop default `overlayZIndex = 760`, v2.4431). Importers: the context and `SendRecordInvoiceModal.render.test.tsx` only. Openers call `openBillCustomer({payload, onSuccess, onAfterEnsureSuccess, onAfterOobUnwindSuccess, onDiscountApplied})` from `Dashboard.tsx`, `useJobFormInvoiceActions.ts` (the Edit Job form's hook), `JobFormInvoiceList.tsx`, `JobsStagesTab.tsx` (Jobs.tsx passes the context handle down) and `JobsSubsWorkView.tsx`. Props (L408–433): `payload`, `onClose`, `onSuccess`, `onAfterEnsureSuccess?`, `onSentWantWaiver?` (v2.4275 — the context passes it itself; it is not an `openBillCustomer` option), `onAfterOobUnwindSuccess?`, `onDiscountApplied?` (v2.3268), `jobUpdating`, `invoiceUpdating`, `overlayZIndex?`; the three opener callbacks are held in refs (L434–439), `onSentWantWaiver` is called straight from the prop.
2. **The shared substrate is data, not a UI pointer** — see [Shared substrate](#shared-substrate-the-billing-target-and-recipient-engine): which invoice row, what amount, **who pays and who gets copies**, which hazmat fees ride along. The composition chain is now **three overlays** (L595–597): `jobRaw` → `jobWithPayer` (GC payer, `applyPayerToJobBillingContext`, v2.3345) → `jobWithBillTo` (`applyBillToToJobBillingContext`, v2.1086) → `job` (`emailOverride`, v2.936).
3. **Several "stripe"-named states are cross-channel.** `stripeLineDescription` is also the Physical "line on bill" (`physicalLineOnBillRaw`); `stripeDueDate` is also the Physical due date; `sentDate` is the HCP date AND the Physical service date; `externalNote` is the HCP memo AND the Physical memo (`applyMemoPresetToBoth` writes it together with `stripeMemo`); and `physicalAdditionalEmails()` is the copy list for **both** email channels (Physical `additional_emails`, Stripe `copy_emails`, v2.3359). Renaming during extraction is a redesign — don't.
4. **No amount input exists.** `billAmountStr` is written programmatically only: the plan effect (L632–635, kind:'job'), the master reset (`invoice.amount`, kind:'invoice'), the commit-time ensure when the remainder moved, and `applyBillDiscount` (kind:'invoice' → `plan.newBillAmount`). Preserve.
5. **The three submit paths are the money-risk core.** Each runs `ensurePrimaryRowForCommit` (ensure RPC + share stamp) before its write — except HCP kind:'invoice' — then `maybePromoteJobToBilledAfterCustomerInvoice`, then `recordBillCustomerCommitted(channel)` telemetry, then `onSuccess()` and — while `waiverAfterSend` is on — `onSentWantWaiver(job.id, invoiceId)` (v2.4275, quirk 29). The Stripe fee math (folded fees inside the amount vs roll-ins on top vs a line override swallowing the folded fees while roll-ins still ride on top; v2.1033 → v2.1035 double-count history) is now **hand-mirrored in three places plus one render total** (`localStripePreview` L1226–1234, the preview effect L1324–1327, `submitStripeInvoice` L1688–1697, the roll-in checkbox total ~L3745).
6. **Paid-job guard (v2.2846, J3-1).** `jobIsPaid` / `paidJobBlocked` (L2095–2097, from `_shared/paidJobBillGuard`) turn off every submit via `outsideReady`, unmount the Stripe pre-submit preview, and hide the discount strip; the "Bill this job again anyway" tick (`allowRebill`) rides as `allow_rebill: true` on both edge fns. HCP has no server stop, so `confirmOutsideBill` checks it client-side (L1571).

### Shared substrate: the billing-target and recipient engine

The modal's equivalent of Bids' `useBidPricingEngine` — **no shared selection pointer inside the file**; the substrate is data every tab and all three submits consume. It now has three separable parts.

**A. Billing target (plan + commit-time ensure).**
- **Plan (v2.2885, decision 17 — no write on open):** `primaryPlan = planPrimaryRtbForBillCustomer(billCustomerJobDetails, invoices, payments)` (L605–615; v2.3775 added `payments` so each open line nets to its unpaid part via `openLineAllocation`, mirroring the ensure RPC). Derived `ensureLoading = open && kind === 'job' && !billCustomerJobDetailsLoaded` (L616), `ensureError` ("Could not load this job" / plan-blocked message, L617–624), `ensuredInvoice` (L625–630: `committedPrimary` wins, else `{jobId, id: plan.invoiceId (null = RPC would INSERT), amount}`). Plan effect L632–635 keeps `billAmountStr` = plan amount.
- **Commit-time ensure:** `ensurePrimaryRowForCommit(amountShown)` (L1153–1159) = `ensurePrimaryRowForCommitRaw` (L1161–1210) + `stampShareOnInvoice` on success. Raw: kind:'invoice' returns `invoice.id` with no RPC; kind:'job' runs RPC `ensure_single_ready_to_bill_invoice_for_job` (`withSupabaseRetry` + 15 s timeout), maps `error` / `fully_allocated` ("Nothing left to bill…", refreshes details) / malformed → `{ok:false}`, stores `committedPrimary`, fires `onAfterEnsureSuccessRef`, and refuses with "The amount left to bill changed to $X…" when `|amt − amountShown| > 0.005` (resets `billAmountStr`, refreshes details).
- **Job details:** effect L1102–1127 → `fetchJobWithDetailsById(job.id)` → `billCustomerJobDetails` + `stripeFixtureMultiLineAvailable = jobHasBillableStripeSpecificWorkFixtures(fixturesForInvoiceBill(fresh.fixtures, kind==='invoice' ? invoice.id : null))`; `refreshBillCustomerJobDetails` (L1938–1947) is the same fetch, called by the line-edit modal's save callbacks, the ensure path and `applyBillDiscount`.
- **Telemetry:** `recordBillCustomerCommitted(channel)` (L1213–1215) → `recordNavClick(…, 'bill_customer_committed', '#<kind>:<channel>')` (`ui_nav_clicks`).

**B. Recipients (payer / bill-to / share / copies / email fix).**
- **Composition chain (core invariant, L595–597):** `jobWithPayer = payerParty === 'gc' ? applyPayerToJobBillingContext(jobRaw, payerRecipient) : jobRaw` → `jobWithBillTo = applyBillToToJobBillingContext(jobWithPayer, billToOverride)` → `job = emailOverride ? {...jobWithBillTo, customer_email: emailOverride} : jobWithBillTo`. ## Preserve-quirks list (odd but load-bearing — do not "fix" during the move)

1. **Timeout semantics (v2.1063 class):** all three submits (and the commit-time ensure) wrap in `withOperationTimeout` (15 s DB / 30 s Stripe / 60 s email); requests are NOT cancelled — every timeout message says "may or may not". Busy flags reset in `finally`.
2. **`billAmountStr` has no input** — programmatic only: the client-side plan (kind:'job'), `invoice.amount` (kind:'invoice'), the commit-time ensure when the remainder moved, `applyBillDiscount` (kind:'invoice'). BILLING_FLOWS documents this as intentional.
3. **Overlay order:** `emailOverride` over `billToOverride` over the GC payer — a just-typed email fix wins for the session.
4. **`emailHazmatNoticeWithStripe` defaults unchecked** (v2.1039) and `attachHazmatNotice` defaults checked; the success screen's "Email the notice now" is the catch-up path.
5. **Roll-in fold order:** repoint incident → THEN delete the rider row. Fold failures only `console.error` — the Stripe invoice is already created.
6. **Line override folds the in-amount fees** (v2.1036): non-empty `stripeLineDescription` → no folded-fee `extra_line_items` on Stripe AND no fee rows on the physical PDF; roll-ins (quirk 7) still ride on top as their own Stripe lines; folded incidents still repoint on success.
7. **Folded fees are inside the amount; roll-ins add on top** (v2.1035 vs v2.1033) — `hazmatFeeLinesWithinAmount` keeps work lines ≥ 1 cent.
8. **`is_primary_rtb_bundle` self-fetch:** the hazmat detection re-reads the flag when the opener's payload omits it.
9. **Stale-while-revalidate preview:** `stripePreviewExistsRef` (maintained by the `useLayoutEffect` L873–879) keeps the old preview during refetch; `stripePreviewReqId` discards out-of-order responses; 450 ms debounce.
10. **Disclosure state carries across tabs:** `lineOnBillSectionOpen`/`memoSectionOpen` are single instances rendered by multiple tabs. Splitting tabs must keep the carry-over.
11. **Contact persons are withheld under a bill-to override** (v2.1086) — only the one-off rides; the Copy-other-party and Share ticks hide too; `eligibleHazmatRollIns` skips overridden invoices.
12. **`stripeLineDescription` seeds from the stored memo only for `is_primary_rtb_bundle === false`** rows; otherwise empty so billable Specific Work produces multi-line Stripe items.
13. **Mode gate:** `stripeModeForBilling = authRole === 'dev' ? stripeModePref : 'live'`; the toggle renders only in the header, dev, Stripe tab, pre-submit.
14. **PDF size caps:** 5,500,000 base64 chars for the invoice alone; 8,500,000 with notice attachments. `openPhysicalInvoicePdfInNewTab` opens the window BEFORE building (popup blocker) and revokes after 60 s.
15. **`busy` is global across tabs** — plus the opener-supplied `jobUpdating`/`invoiceUpdating` (the context passes `false`/`false`).
16. **Stripe success keeps the modal open** (`onSuccess` without `onClose`); HCP and Physical close on success. The waiver hand-off (quirk 29) fires after `onSuccess` on all three, so on Stripe the Release of Lien window opens over the still-open success screen.
17. **`physicalDocPreview` is rebuilt every render** on the physical tab — memoizing is a later pass, not part of the move.
18. **Promote failure surfaces on the succeeding tab** — the bill IS recorded, but the tab shows `promote.error` and does not close (HCP/Physical). Stripe returns there too (L1749–1753), before telemetry, the roll-in fold loop (rider rows stay undeleted) and the success screen; Physical skips its folded-fee repoint loop the same way.
19. **Paid-job guard (v2.2846):** client + server for Stripe/Physical (`allow_rebill: true` only when ticked); HCP is client-only (`confirmOutsideBill` L1571); `allowRebill` resets on every open (effect L636–642); the Stripe pre-submit preview unmounts and the discount strip hides while blocked.
20. **The master reset keys on the composed `job?.customer_email`** (L936): a bill-to / GC-payer overlay landing, or an inline email save, re-runs the whole reset (tab → stripe, memo / line / footers / dates to defaults, `committedPrimary` cleared). A hook extraction must keep the composed `job` in that dep list, or change it deliberately with a behavior note.
21. **HCP kind:'invoice' skips the commit-time ensure and therefore the share stamp** — Stripe and Physical always call `ensurePrimaryRowForCommit` (which returns the payload's id for kind:'invoice' and stamps). Preserve the asymmetry.
22. **GC-payer email fix writes `customers.billing_email` on the GC row** and patches `payerRecipient` in place — no `emailOverride`, no `jobs_ledger` write.
23. **Copies:** contacts are the payer's (the GC's people when the GC pays); `gets_bill_copies` contacts start ticked; the Copy-other-party tick hides when that address equals the billing address; Stripe copies are fixed on the row at create (`copy_emails`) and sent later by `send-stripe-invoice`.
24. **The owner-of-record line renders outside the email-gated Send-to block** (v2.3455) — `sendToBlock` returns it even with no email and no contacts. Beside it since v2.4333: `BillCustomerReturnedChecksLine` (2 smokes), the payer's returned-check count (`list_ar_returned_check_payers` → `arReturnsByPayer`); never a gate, nothing on a refused read.
25. **`outsideReadyForPreview` (L1278–1281) omits `paidJobBlocked`** while `outsideReady` (L2139–2143) includes it — the paid case is handled by unmounting the preview. Don't unify blindly.
26. **Discount apply:** `p_draft_amounts` only for a kind:'invoice' `ready_to_bill` row; `billAmountStr` follows only for kind:'invoice'; `discountPreviewNonce` forces the Stripe preview because the edge fn reads the rows itself.
27. **Two previews:** `StripeBillPreSubmitPreview` gets `localPreview` and `stripePreview`; Stripe's replaces the local one whenever it can run; `stripePreviewIdleHint` names the first blocker in gate order.
28. **Commit-time ensure refusals:** `fully_allocated` → "Nothing left to bill…" + details refresh; amount drift > 0.005 → "The amount left to bill changed to $X…" + `billAmountStr` reset — the bill is not sent at the new number.
29. **The waiver hand-off follows `waiverAfterSend`, not the tick's visibility (v2.4275).** The state is seeded true for any job with a `gc_customer_id` (effect L463–465) and is not in the master reset — it re-seeds because the reset nulls `billCustomerJobDetails`. The strip draws the tick only when it gets an `invoiceId`, which the parent passes for kind:'invoice' alone (L2503). On a kind:'job' open of a GC job the state is therefore true with no tick to untick, and all three sends still call `onSentWantWaiver`. A promote failure returns before the hand-off. **Closed v2.4603:** the hand-off is `waiverHandoff` = `waiverAfterSend` and a non-null `lienWaiverTickForBill`, so no tick, no hand-off; the seed is unchanged.
