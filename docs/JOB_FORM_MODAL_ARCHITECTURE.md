### Key structural differences from the page maps

1. **Regions, not tabs.** Standalone, one scrolling card (max-width 560, `maxHeight: min(90vh, 100%)`) renders everything. Embedded, `embeddedRegion: 'edit' | 'bill' | 'costs'` display-toggles three contiguous region wrappers (2658 / 2936 / 3240) — **everything stays mounted**, so tab switches never lose typed state (pinned by `JobWindowModal.render.test.tsx`). The window's ✕ routes through `closeForm` via `registerRequestClose`; `onRequestRegion` lets Stage Plan / the job-account note jump tabs.
2. **Almost all state is the form.** Controlled fields feed four autosave slices (edit) or `createJob` (new). Seams are props-heavy controlled children plus a few self-contained data loaders — not per-region hooks.
3. **Two modes fork the UI, not just the save.** `mode` plus `editing: JobWithDetails | null` (set only in edit mode) gate nearly everything. Since v2.1681, **edit mode renders people / customer / GC / bill-to / property / links / development as fact rows (`JobFormEditFactRows`)**; the classic `JobFormCustomerSection` / `JobFormLinksSection` / `JobFormAccountManSection` + `JobFormPeoplePicker` render **only in new mode**. Billing regions (segments, invoices, status stepper, stages) render only when `editing` is set.
4. **Remount-by-key lifecycle.** The context bumps `jobFormModalInstanceSeed` as the React `key` on every open, so the init effect is deliberately mount-only (file-top `eslint-disable react-hooks/exhaustive-deps -- mount-only init; parent remounts via key`). Any extraction must preserve this.
5. **The modal is itself the parent.** Regions extract to `src/components/jobs/JobForm*` pieces; the shell keeps lifecycle, shared form state, the save engine, and modals opened from 2+ regions.

### How to read a dossier

Each region lists: **anchor** (symbol + line range as of this re-draw), **status** (extracted / inline / shell-owned), **props in** (shell state passed down — stays in the parent), **what stays shell-side**, **data**, **tests**, and **next action**. Coupling counts ("reads 34 · writes 23") are the fact sheet's per-block state reads/writes (a setter passed as a prop counts as a write).

### How to maintain this doc

- When a region extracts or its state/handlers change, flip its row and dossier and point at the new file; re-run `npm run map` and move `mapped_at`.
- Search the symbol (state name, component tag, label text) — never trust a line number past `mapped_at`.

## Modal lifecycle

### Open / close / remount

- **Openers:** `openEditJob(jobId, {initialJob?, onSaved?, billingCustomerHighlight?, fixturesSectionHighlight?, paymentsReceivedHighlight?, jobPicturesLinkHighlight?, alsoOpenCreateCustomerModal?, initialTab?, propertyRecordFocus?, focusRow?})` first tries the Job window bridge; only when no window is registered does the context mount the standalone form. `openNewJob({onSaved?, onCreatedJobId?, projectId?, prefillBidId?, prefillDraft?, prefillDraftFrom?, prefillCustomer?})` always mounts standalone (`prefillCustomer`, v2.5711: a lead's name, number, email and words from Messages, `NewJobCustomerPrefill`, passed as `newJobPrefillCustomer`). Every open bumps `jobFormModalInstanceSeed` → fresh mount, clean state.
- **Init** (layout effect 1765–1906, keyed on `authUser?.id`): parallel loads of `customers` (incl. `billing_email`, `gc_pays_by_default`, `sees_customer_bills`, `date_met_source`), `projects`, `bids` (latest 800, `partitionBidsByScope` with `fetchTwinUserIds` to drop twin-seat bids), `service_types`, the caller's `users` row (per-role `*_service_type_ids`), `developments`; role-filtered people via `fetchActiveUsers` (dev also loads dev users). Then:
  - **new:** `resetNewForm(newJobProjectId)`; RPC `next_job_number_suggestion` with `clickNumberSuggesting` (C# shows "finding…"; the late value fills only an empty box); default trade via `pickDefaultServiceTypeId`, recorded in `initialNewJobServiceTypeIdRef`; a `newJobProjectId` prefill pulls the project's customer.
  - **edit:** `fetchJobWithDetailsById(editJobId)` (fallback `initialJob`; not found → toast + `onClose()`); `applyEditJob(job, billingGate, fixturesGate, picturesGate)` hydrates 41 states (incl. `breakOffPrefillAmountStringFromJob`, `hideHcpEntryField`, `hydratedPaymentIdsRef`, discount snapshot); `setPaymentsReceivedHighlight`; `alsoOpenCreateCustomerModal` + a customer name opens the create-customer modal.
  - Both end `setInitDone(true)`; until then a bare "Loading…" (embedded: inline text; standalone: overlay).
- **Bid prefill timing** (1920–1929): once `initDone && mode==='new'`, runs `applyPrefillFromBid(newJobPrefillBidId, undefined, { closeOnCancel: true })` once (`newJobPrefillBidAppliedRef` Strict-Mode guard + `bidId === pid` short-circuit). **Customer prefill** (v2.5711, beside it): once `initDone && mode==='new'`, fills `customerName`, `customerPhone`, `customerEmail` and `jobName` (the lead's words as the note) from `newJobPrefillCustomer`, each only when empty (`newJobPrefillCustomerAppliedRef`), never over what the person typed.
- **Close** (`closeForm` 1536–1573): bail while a flush is saving → **New Job discard guard** (`confirmDiscardNewJobIfDirty`) → cancel every slice debounce → fast path when nothing needs flushing and `editCloseSideEffectsNeeded()` is false → else flush billing → identity → materials → team (`flushForClose`, first failure stops) then `runEditCloseSideEffects` (`customers.date_met` backfill stamped `date_met_source: 'manual'` + the paid→billed demote via `update_job_status`), all under one 15 s `withOperationTimeout`. Failure or timeout keeps the form open with the §15a banner (Retry and close / Keep editing / Close without saving). Callers that navigate after closing (trade pill → Stages, Job Detail bridge) await the boolean. Delete and both migrate paths use `closeFormWithoutSaving()` (clears slice baselines — a flush would reinsert children of a dead job). `visibilitychange → hidden` flushes all slices (1578–1584). An invalid identity slice (required field blank) never persists — the footer reads "Waiting on required fields".
- **Escape** (1282–1291, after the payment/delete state since v2.3839): window listener → `closeFormRef.current()` unless `escCloseBlocked` (25 terms: `externalEscBlocked`, the three link/import flags, create-customer, segment generator, `bannerOverlayOpen`, Stripe preview, `billViewInvoice`, `agreedWriteDownInvoice`, `billToEditorInvoice`; and since v2.3839 `invoiceListOverlayOpen` / `peoplePickerOverlayOpen` (reported by `JobFormInvoiceList` / `JobFormPeoplePicker` through `onOverlayOpenChange`), the two inline payment confirms, record-payment / undo-part / apply-to-Stripe / check-didn't-clear / move-payment, delete + migrate, `winningGcPick`, terms, the Stages drawer) or `isTopmostModal()` is false (`useModalStackEntry(!embedded)`, Tier-2 #42). A new stacked layer adds its flag here (quirk #29).
- **onSaved / onCreatedJobId** ride refs (353–356); `onSaved` fires after every slice persist, every immediate write, invoice/payment actions, status moves, create, delete and migrate.

### Dirty tracking — two New Job gates + edit-mode undo

- **Import gate** — `newJobImportBlockedByContent` (1118–1162) over `newJobFormHasBlockingContent` (19 inputs: 14 fields + the auto-picked trade + 4 row arrays). `JobFormHeaderRow` still renders Import but greys it with a hint toast via `newJobImportButtonState` (never `disabled`, v2.2909); effect 1163–1167 force-closes an open Import modal once content appears.
- **Discard guard** — `newJobInitialSnapshotRef` is armed at init (1418–1420) and captured on the next render (1421–1425); `applyPrefillFromBid` re-arms after an import so imported rows are baseline. `confirmDiscardNewJobIfDirty` compares via `newJobDraftIsDirty` and asks "Discard this job?" once at a time; `newJobSkipDiscardGuardRef` is set before `createJob`'s own close.
- **Edit mode** has no discard prompt — it autosaves. `performUndo` restores the snapshot taken on hydrate (re-based when the invoice set changes, `invoiceSetKey`), and the autosave persists the revert.

### Prefill appliers — in `useJobFormImport` since v2.3949

- **`applyPrefillFromBid(bidRowId, forcedGc?, opts?)`**: fetches the bid (+ `agreed_value`, embedded customer); first pass checks `jobs_ledger` for jobs already on this `bid_id` and asks through `confirmDialog` (`secondConversionMessage`) — Cancel → `cancelBidImport`; builds GC packets from `bid_versions` + `bid_version_sends` + `bid_gc_recipients` (+ `customers` names) → `resolveWinningPacket` (silent single winner, else `PickWinningGcModal` via `winningGcPick`, carrying `closeOnCancel`); asks "Start the job at $X?" for the bid's `agreed_value` when set, else the sent value (forced/picked packet → auto winner → lone packet) — Yes replaces the line items with one "Bid price" line and back-fills `bids.agreed_value` only when null (`.is('agreed_value', null)`), No writes nothing; sets bid link, name, address, `linkedBidSummary`, `linkedBidGc`, the bid's GC through `pickGcCustomerId`; applies the trade only if the role-filtered list allows it; fills drive/plans links only when blank. `handleWinningGcPick` records the win through `setGcPacketOutcome` then re-enters with `forcedGc`.
- **`applyPrefillFromEstimate(estimateId)`**: refuses an estimate already on a job; clears the bid link; line items via `normalizeEstimateLineItemsFromJson` + `fixturesPayloadForCreateJobFromEstimate`; applies the customer (fetching an uncached/archived row).
- **`createJob` tail** (2358–2398, after the child rows at 2339–2344): `onCreatedJobIdRef`, `recordNavClick('job_created', jobCreatedTelemetryTarget(...))`, `JOB_CREATED_FROM_BID_EVENT`, the hours baseline (since v2.6646, punch list #234 PR 1a: on a project `award_job_baseline` with the block's pick or what Not now writes (since v2.6737 through `awardJobBaseline` in `lib/jobs/awardBaselineIo.ts`, the one write the Costs strip's late award and the deck share, which first saves the company's Line budgets rate on a picked bid that has hours and no rate of its own), else `snapshot_job_budget_from_bid` when `carryBidBudget`; best-effort toast either way), `closeOpenJobFromBidRequests`, and the bid-outcome toast.

## The save engine — MONEY-PATH

Edit mode has **no Save button** (v2.1080): four `useJobFormAutosaveSlice` instances persist — registered, with their mirror refs and writers, in [`useJobFormAutosaveEngine`](../src/hooks/useJobFormAutosaveEngine.ts) since v2.3973 — `createJob` is the New Job button only, and the close guard runs the paid→billed demote and `date_met` backfill. Flagged in [BILLING_FLOWS](./BILLING_FLOWS.md) as payment-write path **E** and candidates **#9/#10** (both struck through there — fixed by B5 and B3/B4; only #10's B6 hard write-guard is still open). **The map documents; it does not fix.** Since v2.3966 the write sequences below are [`lib/jobs/jobFormSliceWrites.ts`](../src/lib/jobs/jobFormSliceWrites.ts) (`writeBillingSlice`, `writeMaterialsSlice`, `writeTeamSlice`, `writeNewJobChildRows`), each taking `supabase` and tested over a client that records the order; the shell's `persist*Slice` functions read their refs, call the writer, and toast a failure. The identity slice's writer stays inline (one update between two bid reads and the dispatch auto-closes).

| Slice | Writer (lines) | Debounce / gate | Write sequence | Errors |
|---|---|---|---|---|
| billing | `persistBillingSlice` (the engine's) | 1,200 ms | a read of the job's line ids first (v2.7746, `lineIdsNeverHeld` over the engine's `heldLineIdsRef`): a line the form never held means nothing is written, the lines are re-read through `rehydrateFixturesFromDb` and the form says so → `UPDATE jobs_ledger SET revenue` (fixtures + rider fees, a returned check's fee among them since v2.5091; `payments_made` is trigger-derived since B3/B4) → payments **diffed** (`diffPaymentRows` over `hydratedPaymentIdsRef`: delete owned-and-gone ids, upsert the rest; a Sent or Received date caught half typed is left out of its row, in an upsert of its own — `paymentUpsertStatements`) → fixtures **upserted in place** in one call under their own ids, then the job's lines not among them deleted (v2.6420, `diffFixtureRows` over `fixtureInsertRows`, which carries `id` and `invoice_id`; was delete + reinsert one row at a time, which minted new line ids and took every stage checklist row and stage window on the job with them) → discount events via `log_job_discount_event` (fire-and-forget) | every call checked → toast, slice `error`; a refused save (lines changed elsewhere) is a toast of its own and slice `error` |
| identity | `persistIdentitySlice` (the engine's) | 1,200 ms; `enabled: identitySliceReadyToSave` | one `UPDATE jobs_ledger` from `buildEditJobIdentityUpdatePayload` (master via `resolveEditJobMasterUserId`, customer / GC / development re-resolved) → bid-outcome toast when `bid_id` changed → `autoCloseJobDispatchRequests` for blank→set pictures link / phone | checked; dispatch close only `console.warn`s |

GC, bill-to, `show_bills_to_other_party`, `customer_address_id`, development, AM, title-cased address) → sequential inserts of payments / materials / fixtures / team → tail (above) → `date_met` backfill → `closeForm()` → `onSaved` | the `jobs_ledger` insert throws; since v2.4031 each child insert is read — a refused row does not stop the rest, and what did not land is said in one toast (`newJobChildRowFailureWords`) as the form closes |

**Contracts any seam must keep:** `FixtureRow.invoice_id` rides both fixture write paths and the slice JSON (v2.1068–69); `hydratedPaymentIdsRef` is re-captured by `applyEditJob`, `refreshEditingJobAndHydratePayments` 503–515, each billing persist (in the engine), the undo-part / record-payment / check-didn't-clear / apply-to-Stripe successes (the windows at 3121–3215) and — since v2.4029, through the engine's `paymentsRereadFromDb`, which also re-baselines the billing slice when it had nothing waiting — the remove-payment, Mercury-unlink and payment-Move refetches; it is **not** reset by Undo; `rehydrateFixturesFromDb` (the engine's) re-baselines the billing slice through `rebaselineBillingNonce` after Bill Customer writes a discount row; invoice creators call `flushBillingAutosave()` first so `sequence_order` positions match the DB.

**The seam, as built (v2.3966 + v2.3973):** the write sequences are `jobFormSliceWrites`; the four slices, their mirror refs, their records of what was last saved and their writers are `useJobFormAutosaveEngine`, called once every field it carries is declared (after `teamMemberIds`). **Same order, same checked/unchecked errors, same non-transactionality**; the transactional `TODO(billing)` sits at the head of `jobFormSliceWrites`. The slices register in the order they had (billing → its re-baseline effect → identity → materials → team), so they keep their order among themselves; they now all run after three shell effects they used to be interleaved with (the GC-pays default, the property-candidates read, the Account Man un-team), none of which reads or writes a slice's refs. **Left in the shell, by decision:** the close guard (`closeForm`, `closeFormWithoutSaving`, `runEditCloseSideEffects`, the visibility flush) — it ends in `finishClose`, which resets a dozen pieces of the form's own state — and `createJob`. `createJob`'s child inserts were left unchecked by the decomposition and are checked since v2.4031. **Changed since (v2.4027):** after `rehydrateFixturesFromDb` the re-baseline (`markSavedNow`) drops the debounce the new rows started, so the slice no longer writes the same rows back 1.2 s later; when the slice had an edit waiting or a save in flight, the re-read is not taken as saved and that save still runs (`billingRereadFromDb`). **And (v2.4084, in `useJobFormAutosaveSlice`, so Edit Bid and the Estimates draft too):** an edit made while a save is in flight that puts a field back to its value from before that save now saves on the clock after the save ends; it used to start no clock and wait for the close or tab-hidden flush. **And (v2.7746, the billing slice alone):** the form's lines were the whole truth of the job's lines, so a window left open while a line was added somewhere else (`apply_job_discount` from another screen, `apply_estimate_to_job`) deleted that line at its next save and wrote the total without it. `writeBillingSlice` now reads the job's line ids before it writes, and when the database holds one the form's rows never carried (`heldLineIdsRef`, gathered from the form's rows on every render — `editing` alone does not count, since a re-read that set only the job has not put its lines in the form) it writes nothing; `persistBillingSlice` re-reads the lines, says so for 15 s and fails the save. It refuses, it does not merge: the person's last change to the lines is gone, and a payment typed with it is saved by the save the re-read's render starts. A save queued behind the refused one runs before that render and is refused again without a second read or telling (`rereadForLinesRef`). The read and the delete are two calls, so the gap is one save long where it was as long as the window stayed open; a line deleted elsewhere is still written back, as before.

## Quirks (preserve, don't fix)

1. **Child-row write shapes differ per table:** fixtures (v2.6420) and materials (v2.6111) upsert by the row's own id, then delete the job's rows not named, so the form's rows are the whole truth of the job's lines (a discount's basis positions key on `sequence_order` across them); payments are **diffed** against the ids the form owns (B5, `diffPaymentRows`; rows born mid-edit — Stripe webhook payments — survive); team is diffed.
2. **Error handling differs per path:** every edit-mode slice write is checked (toast → slice error → close-guard banner); `createJob` throws on the `jobs_ledger` insert alone — since v2.4031 each child insert is read, a refused row does not stop the rest, and what did not land is said in one toast as the form closes.
3. **`payments_made` is trigger-derived** (B3/B4, v2.1119–v2.1120); no client writes it (B6 hard write-guard still pending — BILLING_FLOWS #10).
4. **Scope-only fixture rows are dropped on save** (`fixtureInsertRows` filters on the normalized name) yet count as blocking content for the Import gate.
5. **Paid→billed demote tolerance** is `revenue > payments + 0.01` (`shouldDemotePaidJobToBilled`), judged at close from the form's refs, not the DB.
6. ~~**Revenue and paid sum are recomputed in 4 and 5 places**~~ — one kernel since v2.3922 (`jobFormMoneyTotals`); the sum with the rider fees is still not rounded again after the line items round to cents.
7. **Mount-only init** under the file-top `eslint-disable`; correctness depends on remount-by-key.
8. **`editing` doubles as the mode flag** (65 reading units); edit mode refetches by id and falls back to `initialJob`.
9. **Stripe memo/footer backfill** invokes the edge function serially per invoice (dev gate now applied — the old "raw pref" quirk is fixed, here and in `AgreedWriteDownModal`).
10. **`BilledBillViewModal.onClose` retry loop** — up to 3 refetches, 280 ms apart.
11. **Z-index collision:** migrate, the `BILL_VIEW` constant (bill view + agreed write-down) and the Stages drawer all resolve to 1012.
12. **C# suggestion** fills asynchronously after init, only into an empty box.
13. **Master is provenance, not a wall** (v2.2972): new customers carry the job's master (edit) or the company owner (new); the local `CustomerRow` still needs `master_user_id` so the identity slice's re-resolve keeps the pick.
14. **Both New Job gates ignore GC, development, Account Man, bill-to and property** — `newJobFormHasBlockingContent` (19 inputs) and `NewJobDraftSnapshot` (18 keys) predate those fields.
15. **Discard vs autosave:** New Job asks before Cancel / Esc / backdrop discard; edit mode never asks (autosave), and "Close without saving" appears only after a failed flush.
16. ~~**Redundant nested `editing` check** in the invoices block~~ — gone v2.4307 with `JobFormBreakOffSection`; the block's children sit under one `editing &&` (2996–3097).
17. **Last-row semantics differ:** materials clear the last row in place; fixtures refuse to remove it; payments replace an emptied list with one fresh row. Pinned since v2.7729 (`materialRowsAfterRemove`, `fixtureRowsAfterRemove`; payments were `paymentRowsAfterRemove` already). The two adds each replace a lone blank placeholder, by two different tests: a discount reads the name and the price, the generator reads `fixtureRowHasUserContent`, so a lone line with a count of 3 is kept by the generator and replaced by a discount.

35. **Landing on Bill the N picked looks every 100 ms, up to 50 times** (`landOnBillPicked` over `lib/landWhenDrawn.ts`, v2.8185): a new landing stops the one before and the window's unmount stops the last, so no look runs after the window or a test's page is gone.
