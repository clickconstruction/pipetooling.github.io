# 20261030010000_supply_bill_read.sql (2026-10-29, v2.6088)

Supply-house bill capture, the fill behind a switch (punch list #179 PR 2). The Add invoice window stays the one way a bill is recorded; what is new is that the bill's PDF can fill its fields, and the row keeps what was read.

- **`supply_house_invoices.bill_read jsonb`** — the read as the row keeps it (`BillRowRead` in `src/lib/materials/bills/billRead.ts`): the file, the model and when, each field's value with its source *read · guessed · typed* and the why, the lines as the paper printed them, the checks as they stood at Save. Null on a bill typed with no PDF. The words read, guessed and typed live here and nowhere on a screen.
- **`supply_house_invoices.bill_attachment_id uuid → message_attachments`** (ON DELETE SET NULL, a partial index) — the thread file the bill was recorded from, so the house's count of bills to record and the form's picker (PR 3) know a file is on a row.
- **`app_settings` `bill_read_on_v1`** — the switch, `'false'` as it ships, with the master-or-dev key-scoped UPDATE policy the other switches have. `bill-read` refuses every caller but a dev while it is off.
- **`supply_bill_reads`** (new) — one row per fill the function makes: who asked, when, the file's path and name, the house, the model, the tokens and cents, whether it came back whole, the answer, the reason when not. The function counts the last day's rows for its cap (`BILL_READ_DAILY_CAP`, 150). RLS: `is_office_staff()` reads; the service role writes; the three fence appliers at the end.

**Order**: the client of v2.6088 writes neither column and reads no new table, so it may deploy before the push. Push, then `bash scripts/deploy-functions.sh bill-read` and redeploy `dev-mcp` (its catalog names the function). PR 3's client writes the two columns only when a bill was filled from a PDF, so it waits on this push. Regenerate the types after the push (`npm run gen-types:linked`, a `chore(types)` PR).
