# 20260824170000_person_reports.sql — field reports queue for HR files (v2.2235)

`person_reports`: open-response reports masters/devs write about a person from
the Dashboard's HR Report card. `subject_person_id` → people (CASCADE),
`author_user_id` → users (SET NULL) + `author_name` denormalized so the byline
survives account deletion, `occurred_date` (when it happened — becomes the HR
entry date) distinct from `created_at` (when written), `content` CHECK not
blank, `status` pending/filed/dismissed, `filed_entry_id` → person_file_entries
(SET NULL), `resolution_note`/`resolved_at`/`resolved_by`. Partial index on
pending.

RLS: INSERT masters+devs as themselves (`author_user_id = auth.uid()`);
SELECT devs all, authors their own; UPDATE devs; **no DELETE policy** —
dismissal keeps the report + a required reason.

RPCs (SECURITY DEFINER, `is_dev() OR current_user = 'hr_agent'`, idempotent):
- `file_person_report(p_report_id, p_content default null, p_source default
  'report')` — appends the append-only `person_file_entries` row ("Reported by
  <author>" + content, entry_date = occurred_date) and marks the report filed.
- `dismiss_person_report(p_report_id, p_reason)` — marks dismissed with the
  reason.

Also: `hr_agent` GRANT SELECT,UPDATE on the table + EXECUTE on both RPCs
(role-exists guard), and a DO block redefining the **live** `hr_agent_write`
to include `'report'` in its `allowed_sources` (the deployed body was verified
by md5 before patching). Ends with both `apply_read_only_*` guards.
