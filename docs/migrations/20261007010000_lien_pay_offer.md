# 20261007010000_lien_pay_offer.sql (2026-10-07, v2.4708)

The pay offer: a discount on each bill behind a § 53.056 notice if it is paid in full by a day, offered on the owner's pay page. Two tables gain columns; the desk item guard is regenerated from its newest definition (`20260915140258`).

- `job_lien_desk_items.offer_pct smallint NOT NULL DEFAULT 0` (0–50, check), `offer_by date` (required when `offer_pct > 0`, check), `offer_set_by uuid → users`, `offer_set_at timestamptz`. The leader's choice on the notice being approved.
- `jobs_ledger_invoices.lien_offer_pct`, `lien_offer_by`, `lien_offer_set_by`, `lien_offer_filing_id → job_lien_filings`, `lien_offer_credit_note_id text`, `lien_offer_credit_cents integer`, `lien_offer_applied_at`, `lien_offer_taken_at`, `lien_offer_ended_at`. The money side, written by the `lien-pay-offer` function (apply, expire) and the Stripe webhook (taken). Partial index `jobs_ledger_invoices_lien_offer_live_idx` on `lien_offer_by` for the nightly sweep.
- `job_lien_desk_items_guard()`: an offer set or changed (`offer_pct` / `offer_by`) needs a master or dev (42501 otherwise; the service role passes), and the row is stamped `offer_set_by` / `offer_set_at`; clearing the offer clears all three. Everything else as before.

Additive and idempotent. Deploy the client first: an old client never writes the new columns, and their defaults keep every reader whole. The function and the cron that use the invoice columns ship in the next PR (v2.4701).
