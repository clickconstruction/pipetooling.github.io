# 20261107070000_case_search.sql (2026-11-07, v2.6620)

One full-text search across a person's case for dev-mcp's `search_case`, punch list #278 PR 2 ([v2.6620](../recent-features/v2.6620.md)).

- **`hr_doc_sections(md text)`** (`IMMUTABLE`): a document split at its headings — the preamble (heading null) when words come before the first heading, then one row a section with the heading, its number as `hr_doc_heading_index` reads it, its line and its body (heading line included). Over `hr_doc_headings` (`20261107013000`).
- **Five GIN indexes** over `to_tsvector('english', …)`: `person_file_entries.content`, `person_file_evidence.title || ' ' || memo`, `person_documents.content`, `person_files.content`, `legal_matter_entries.COALESCE(body, '')`. Each is `CREATE INDEX IF NOT EXISTS`; the tables are small (hundreds of rows), so the build takes its lock briefly under the 3-second timeout.
- **`dev_case_search(p_person_id, p_q, p_in default null, p_limit default 40)`**: `SECURITY DEFINER`, `search_path = public`, raises `42501` unless `auth.uid()` is set **and** `public.is_dev()`. `p_q` through `websearch_to_tsquery('english', …)` (words, `"a phrase"`, `-not`); a query of stop words alone is refused. `p_in` is one of `entries`, `evidence`, `documents`, `summary`, `narrative`, `matter`. Seven sources, unioned: the entries; the evidence (title and memo); the named documents (unarchived) by section; the summary and the narrative by section; the matter standing on the person (open first, else newest) — its narrative by section, its unvoided entries, its unvoided documents' titles and what-it-shows lines. Each hit: `source`, `id`, `title`, `section_n`, `section`, `day`, `counsel_only`, `rank` (`ts_rank_cd`), `snippet` (`ts_headline`, `«` `»` around the match, one fragment). Ranked, then `day` newest, capped at `p_limit` (1 to 100). Returns `{ q, query, in, person_id, matter_id, count, shown, hits }`.
- EXECUTE on both functions revoked from `PUBLIC` and `anon`, granted to `authenticated` (the gate is inside).

No table, so no fence appliers; a matter document's file is not searched (its title and what it shows are) — the body joins when the write keeps a text column, a follow-up on the card. Idempotent.
