Charges by crew (punch list #254, PR 1): a person's standing when a crew is priced, a job's rule for how its labor is charged, and the rate card's rows in `app_settings`.

- **`users.charge_standing text`** — master · tech · helper · none; null reads as none. A NOT VALID check holds the four words. A plain profile field: `users_guard_privileged_columns` does not name it, so the roles the users update policy admits (dev, master, assistant, controller) may set it.
- **`jobs_ledger.charge_rule text`** (crew · shape · flat; null reads as crew), **`charge_shape text`** (the six shapes), **`materials_markup_pct numeric`** (≥ 0; null means the company's) — NOT VALID checks on each; the flat rate is the existing `hourly_charge_rate`.
- **Seeded settings rows**, `ON CONFLICT DO NOTHING`: `hourly_charge_rate_v1` 285 (the v2.6431 row, repeated so either migration order leaves one row), `charge_rate_two_techs_v1` 285, `charge_rate_tech_alone_v1` 185, `charge_rate_helper_alone_v1` 75. Nothing is seeded for a master alone, two helpers, each person beyond two, or the markup: those are the owner's.
- **No table, no policy, no fence calls** — two existing tables gain nullable columns; `app_settings` has its policies.

**Apply order**: the client reads every new column through a cast and treats a missing row as not set, so the client may deploy first with nothing lost; the Settings cards read blank rows until the push seeds them. Push, then regenerate the types.
