# 20260906180000_revoke_anon_rpc_exposure.sql (2026-09-06, v2.2954)

Security hardening from the RLS / exposure audit (Plan B, audit 1). Live-proved the same day with only the public anon key and no session: `get_jobs_ledger_by_status('paid')` returned 714 jobs with name, address, revenue, payments made and Drive / plans links; `search_jobs_ledger('')`, `search_bids_for_clock('')`, `search_jobs_for_reports('')` and `search_jobs_for_tally_mercury_assign('')` each returned ~50 rows; `list_customer_review_job_hours()` 98 customer rows; `get_archived_user_names()` and `get_location_enabled_user_ids()` the roster. Every table probed anonymously returned zero rows — RLS is sound; the hole was the RPC layer.

Why: Supabase grants EXECUTE to PUBLIC (so `anon`) on every function, the baseline dump re-granted it explicitly, and a SECURITY DEFINER body that never checks the caller runs as the owner for whoever holds the anon key — which is everyone, since it ships in the client bundle.

- **`REVOKE EXECUTE … FROM PUBLIC, anon`** on 24 signatures (23 functions — both `get_parts_ordered_by_price_count` overloads): the jobs-ledger readers (`get_jobs_ledger_by_status / _office / _by_ids / _by_hcp_numbers` and the `_paid_only` pair), the three search RPCs plus the Tally one, `get_bids_by_ids`, `get_projects_by_ids`, `get_job_display_for_report`, `get_archived_user_names`, `get_location_enabled_user_ids`, `list_customer_review_job_hours`, `next_job_number_suggestion`, `next_work_order_record_id`, `get_supply_house_stats_by_service_type`, both `get_parts_ordered_by_price_count` overloads, the two nudge counters, and `create_po_from_job_tally`. `authenticated` and `service_role` keep their explicit grants, so nothing changes for a signed-in user.
- **`… FROM PUBLIC, anon, authenticated`** on five with no caller anywhere in `src/` or `supabase/functions/`: `create_project_with_template`, `duplicate_purchase_order`, `copy_workflow_step`, `create_takeoff_entry_with_items` (SECURITY DEFINER writers a logged-in low-privilege role could otherwise call to bypass RLS) and `debug_cost_estimate_policies`. `service_role` keeps them.
- Precedent: `20260730160048_revoke_stripe_webhook_rpc_public_grants.sql`. Idempotent; a signature that does not exist on prod aborts the push on purpose.

Apply order: any time — client unchanged. Verify after the push: `POST /rest/v1/rpc/search_jobs_ledger` with the anon key alone returns 401 `42501`; the Clock In picker and header search still work signed in.

Left alone, deliberately: `report_edit_window_days()` / `report_sub_visibility_months()` (config constants, possibly evaluated inside policies), `get_hazmat_notice_by_token` and `list_my_contract_dashboard_prompts` (the two RPCs the public pages need). The general rule the audit surfaces — every new SECURITY DEFINER RPC gates on the caller in its body, and never with a deny-list alone — is recorded in `ACCESS_CONTROL.md`.
