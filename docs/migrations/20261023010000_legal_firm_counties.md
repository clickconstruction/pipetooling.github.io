# 20261023010000_legal_firm_counties.sql (2026-10-23, v2.5756)

Legal firms by county, PR 1 of 4 (punch list #144, `to-dos/legal-firms-by-county/`). The owner is engaging a second collections law firm, one for San Antonio and one for Austin, and territories are counties because venue for a collections suit is the county. One transaction, one new table.

- **`legal_firm_counties`** (`id`, `firm_id → legal_firms` on delete cascade, `county text`, `since`, `until null`, `set_by → users`): which firm covers which Texas county. One live row per county, held by the partial unique index `legal_firm_counties_live_county_uidx` on `county WHERE until IS NULL`; a county that changes hands gets its old row closed (`until = now()`) and a new row, so the history stays. `county` is the Census county name as `public/geo/tx-counties.json` spells it (*Bexar*, *Travis*, *DeWitt*), the same spelling as `customer_addresses.county`. No row means no firm covers the county: no default firm. RLS: the office roles read (`legal_office_can_read()`), a dev inserts and updates (`is_dev()`), nobody deletes. The three house calls fence it for read-only users and twins.
- **`legal_firms_one_active` is dropped.** The index from punch list #85 (item 27, `20261006070144`) held the office to one active firm while the desk could release to only one; with territories the second active firm is the feature. `legal_replace_firm` (`20261006234500`) keeps working: it retires one firm and adds its successor in one step. The table comment on `legal_firms` says so.

Additive for readers: the old client never reads the new table, and with the index gone it still edits the oldest active firm (`useLegalMatters` takes the first `active` row until PR 2). Push after `20261023003000_shadow_reclaim_idle_reasons`, from a main checkout, after the client deploys. PR 2 (the desk picks the firm by venue) reads the table; nothing reads it before then except Settings → Jobs & billing → **Collections law firms**, whose map writes it.
