## `price_row_file`

`p` carries `supply_house_id`, `part_id`, `unit_price` as printed, `pricing_unit`, an optional `unit_factor`, `dated_on`, `house_code`, `mfr_number`, `description`, `came_by`, `bid_id`, `number`, `matched_how`, and either nothing more (a one-off, which makes its own one-row paper) or `line_id` (a row of a sheet already read).

In order:

1. The gates a definer passes: signed in, `may_edit_parts_book()`, not read-only, not a digital twin, not archived.
2. The house and the part exist; the price is above zero and comes to at least a cent each.
3. The house's number, when given, is free or already this part's. Otherwise the call raises, naming the part, before anything is written.
4. **The newest dated paper wins**: a price on file dated after `dated_on` is kept and the call returns `filed: false, why: newer_on_file`, unless `allow_older`.
5. **A move past a quarter waits**: returns `filed: false, why: moved`, unless `allow_big_move`.
6. The price is written with its source; the row remembers what it replaced; the house's number is kept on the part with the unit factor.

## `price_row_take_back`

The price is put back only while it is still this row's (`source_line_id`). A price somebody changed since returns `restored: false, why: changed_since` and is left alone. With no price before the row, the price row is deleted. The number the row taught is removed. A one-off's paper is deleted with its row; a sheet's row is only cleared.

## Access

`EXECUTE` on both RPCs to `authenticated` and the service role, revoked from `anon`. No table is new, so no fence applier runs; both functions state the read-only, twin and archived gates themselves.

## Additive and idempotent

`ADD COLUMN IF NOT EXISTS`, the check constraint behind a `pg_constraint` test, `CREATE OR REPLACE`, `DROP … IF EXISTS` before each policy and trigger. The bed applies it twice.
