# 20260915032447_bid_submittals.sql (2026-09-14, v2.3465)

Submittals stage 2a (`to-dos/submittals/README.md` → PR 2a): the package as rows, plus its bucket. Schema only — the tab (2b) and the package PDF (2c) follow.

- **`bid_submittals`** (new) — one revision per (bid, `rev_number`): `job_ledger_id` (set when the job is opened from the bid, stage 4), `title`, `status` (`draft · shared · reviewed · superseded`), `note`, `package_path` (the rendered PDF, 2c), `source_files` jsonb (the vendor PDFs dropped on the revision: `path · house_id · house_name · name · pages · trimmed_at`), `shared_at/by`, `created_by`, timestamps.
- **`bid_submittal_items`** (new) — one row per fixture tag on a revision: specified (`manufacturer · model · description`), submitted (`manufacturer · model · label`), `supply_house_id`, `source_quote_line_id`, `status` (`as_specified · superseded · equal · alternate · design_change · missing · accessory`), `reason_kind` / `reason_note`, `lead_time_days` (0–730), the sheet (`sheet_file` index into `source_files` + `sheet_pages int[]`, `sheet_source` `estimator · robot · house`), `carried_from_item_id`, and stage 4's `review_decision` (`approved · revise · rejected`), `review_note`, `reviewed_by_name/email/at`.
- **Helpers** — `is_pricing_sharer()` (the five pricing-side roles: dev · master · assistant · controller · estimator) and `can_access_submittal(id)` (the item's revision's bid passes `can_access_bid_for_pricing`), both SECURITY DEFINER, `authenticated` only (`REVOKE … FROM PUBLIC, anon`).
- **RLS** — both tables: pricing sharers read and write on bids they can price. All three fence appliers (read-only ×2 + twin).
- **Bucket `bid-submittals`** (private) — paths `<bid_id>/<submittal_id>/<file>.pdf`; four `storage.objects` policies (select · insert · update · delete) for pricing sharers on bids they can price, keyed on the first folder being the bid id (the `job-test-reports` bucket's shape, v2.3331). Outsiders never touch the bucket: stage 4's review page and stage 5's portal mint short-lived signed links server-side.

Idempotent (`IF NOT EXISTS`, `CREATE OR REPLACE`, `DROP POLICY IF EXISTS`, `ON CONFLICT DO NOTHING`). Apply order: push after the client merge — the old client never selects these tables; the 2b tab treats an RLS or missing-table error as "no revisions yet".
