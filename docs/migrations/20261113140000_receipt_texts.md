# 20261113140000_receipt_texts

**Punch list #299, PR 2 (v2.7142).** What the text about a card charge needs in the database. It sends nothing: the switch ships off, and the cron it schedules calls nothing while the switch is off.

## What it does

1. **`receipt_requests.text_tries`** (integer, 0 by default, never below 0) and **`text_fail_why`** (at most 300 characters): a first text Quo turned away is tried again on a later sweep, three times in all, and the Team queue's line then says the text did not go. **`receipt_requests_remind_idx`**, a partial index on `texted_at` for the reminder's read.
2. **`app_settings` `receipt_texts_v1`**, JSON in `value_text`, inserted as `{"on":false}` when the row is missing. Switched on it reads `{"on":true,"since":"<ISO instant>","only":["<user id>", …]}`. `since` is the floor under the backlog: a charge that posted before it is never texted. `only` is a trial; empty means everyone with a card. The policy **`master_or_dev_update_receipt_texts`** lets `is_master_or_dev()` update this one row, the rule Send texts follows (`20261014160000`).
3. **`receipt_texts_stamp()`**, a `BEFORE INSERT OR UPDATE` trigger on `app_settings` that runs for this key alone (`WHEN (NEW.key = 'receipt_texts_v1')`). It rewrites the value so the row always reads: `since` is the database's clock at the write that switched it on, whatever the write said; a write that leaves it on for the same people keeps the day it went on; a change of `only` while on starts from now; `only` is lower-cased and de-duplicated; anything that does not read as on (not JSON, `on` not the boolean `true`, an `only` that is not a list of user ids) lands as `{"on":false}`.
4. **`receipt_texts_due()`** → boolean, `STABLE`, `SECURITY DEFINER`, executable by the service role alone. False while Send texts (`messages_texts_on_v1`) is not `'true'`, while this switch is off, or while its value does not read. Else true when any of these holds, over the later of `since` and 48 hours ago:
   - a card purchase posted since the floor with no request and no live ticket (not pending, not money back, not a duplicate, not failed, cancelled or reversed);
   - a request on such a charge waits for its first text or its reason (`texted_at`, `no_text_why`, `answered_at`, `closed_at` all null, `text_tries < 3`, no live ticket on the charge), in a trial only when its holder is one of `only`;
   - it is six to nine in the evening in `America/Chicago` and a request was texted at least twelve hours ago with no reminder, no answer and no reason, its link still open, in a trial only for its people;
   - an open request sits on a charge the bank failed, cancelled or reversed (the sweep closes it).
5. **The cron `receipt-request`**, `*/5 * * * *`: `net.http_post` to `/functions/v1/receipt-request` with `X-Cron-Secret`, `WHERE public.receipt_texts_due()`. Unscheduled first, so a second run leaves one row.

## Who may do what

- The switch: read by every signed-in user (the table's own SELECT policy), changed by the owner or a dev. Settings → Phone and texts draws its card for those two roles.
- The guard: the service role (the cron's own session is `postgres`).
- No table is made, so no fence is added. `receipt_requests` keeps PR 1's policies: the office and the holder read, nobody writes from the app.

## Lock and safety

`SET lock_timeout = '3s'` first. `ALTER TABLE receipt_requests ADD COLUMN` with a constant default rewrites nothing; its `ACCESS EXCLUSIVE` is for the catalog write. `DROP POLICY` and `CREATE POLICY` on `app_settings` each take a brief `ACCESS EXCLUSIVE`, as every switch's migration has; `CREATE OR REPLACE TRIGGER` takes `SHARE ROW EXCLUSIVE`, which does not hold readers. Idempotent: `ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `ON CONFLICT DO NOTHING` (a second run never switches a live switch off), `DROP POLICY IF EXISTS`, `CREATE OR REPLACE`.

## Undo
