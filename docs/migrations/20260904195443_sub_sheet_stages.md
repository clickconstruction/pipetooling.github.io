# 20260904195443_sub_sheet_stages

**Sub sheet stages (v2.2767)** — a Sub Labor sheet walks `working → walkthrough → customer_pay`; paid is derived.

## What it does

- `people_labor_jobs` gains `stage` (text, NOT NULL default `working`, CHECK working | walkthrough | customer_pay), `stage_changed_at`, `stage_changed_by` (→ users, SET NULL), `stage_source` (office | portal | auto), `stage_note`. Additive; the column default is metadata-only.
- One-time carry: rows with the old `portal_status = 'complete'` start at `walkthrough`. `portal_status` is left in place, commented **DEPRECATED** — the deployed `sub-portal` function selects it until redeployed.
- `sub_sheet_stage_label(text)` (IMMUTABLE) — the office chip wording, so the Activity line matches the UI.
- `set_sub_sheet_stage(p_labor_job_id, p_stage, p_note DEFAULT NULL)` — SECURITY DEFINER, office writers (dev / assistant-like / master_technician), moves either direction, stamps `stage_changed_at/by`, `stage_source = 'office'`, replaces the note; returns `{ok, stage}` / `{ok, stage, unchanged}` / `{error}`.
- Trigger `people_labor_jobs_stage_to_activity_upd` (AFTER UPDATE, `OLD.stage IS DISTINCT FROM NEW.stage`): resolves the job via `lower(btrim(jobs_ledger.hcp_number)) = lower(btrim(job_number))` (newest first) and inserts a `job_activity_events` row of type `sub_stage_change` (actor = `stage_changed_by`, or `auth.uid()` for office moves, NULL for portal/auto; `financial = false`; `detail.source_id` = the sheet id). No job match → no row, no error.

## Order

Deploy the client first (its parser defaults a missing stage), push this, then redeploy `sub-portal` and `submit-sub-portal` — the function's new select and the `mark_work_done` kind both need the columns.
