# 20261108200000_file_index_reach.sql (2026-11-08, v2.6714)

The file index reaches the files a person's HR file and a legal matter hold, punch list #285 PR 1 ([v2.6714](../recent-features/v2.6714.md)). One table, as the card decided: `file_index` (#240, [`20261102040500`](./20261102040500_file_index.md)) gains the reach, and two queue functions feed it.

- **Five columns on `file_index`**: `source text NOT NULL DEFAULT 'drive'` (`drive` for every row before; `hr_attachment` for a `person_file_attachments` row; `matter_document` for a `legal_matter_documents` row), `source_id uuid` (the row it stands for), `person_id uuid` (→ `people`, cascade), `matter_id uuid` (→ `legal_matters`, cascade), `counsel_only boolean NOT NULL DEFAULT false` (carried from the evidence record). Two checks: `source` is one of the three; `(source = 'drive') = (source_id IS NULL)`. A unique partial index over `(source, source_id)`, partial indexes on `person_id` and `matter_id`. **The key keeps its name**: a record's file carries its own row id in `drive_file_id` (a uuid passes the key's shape check), never a Drive id, so a staged file later filed into Drive by `hr-evidence-drive` keeps one row.
- **Who reads**: `file_index_select` becomes `is_office_or_estimator() AND NOT is_digital_twin() AND (source = 'drive' OR is_dev())` — the office reads the Drive rows as before, a record's row is a dev's alone. `file_index_counsel_only_seat`, a restrictive policy: `NOT (counsel_only AND request_is_dev_seat())`, the seat as deployed refused a counsel-only row as it is refused the record (`20261106020000`). `hr_agent` has no grant on the table and reads none.
- **Find a file answers Drive rows alone**: `search_file_index` and `search_file_index_meaning` are replaced with `source = 'drive'` on their `file_index` reads (the bodies otherwise as `20261102040500` and `20261102051500` left them, the same signatures and return shapes) — `drive-link` runs them as the service role, which sees past the policy. `file_index_embed_due` ([`20261104160000`](./20261104160000_file_index_embed_due.md)) gains the same filter: the case search is words-only, so a record's text never goes to Gemini.
- **`file_index_records_due(max_rows DEFAULT 40, p_person_id DEFAULT NULL, p_matter_id DEFAULT NULL, retry_after DEFAULT '1 hour')`** (`STABLE`, `SECURITY INVOKER`, service role only): every `person_file_attachments` row (joined to its person, its evidence record and its entry: `record_kind` evidence / entry / file, `record_id`, `record_title`, `record_day`, `counsel_only`, the path *People › the person › the day · title* or *Files from before records*, the bucket `hr-files`, `storage_path`, `drive_file_id`) and every unvoided `legal_matter_documents` row (the matter's `person_id`, `record_kind` matter_document, the path *Matter › the payer › Evidence*, the bucket `legal-matter-documents`), that has no `file_index` row or a held one (`slow`, `error`, `reading`) checked over `retry_after` ago, newest first, at most `max_rows` (500). `p_person_id` narrows to a person's files and their matter's documents; `p_matter_id` to a matter's documents.
- **`file_index_records_drop_gone()`** (plpgsql, service role only): deletes the `hr_attachment` rows whose attachment is gone and the `matter_document` rows whose document is voided or gone; returns how many went.
- **`dev_file_index_status()`** replaced with `by_reach` (rows by `source`), `records_with_rows` and `records_without_rows` (attachments and unvoided documents with no row); `rows_under_no_home` now counts Drive rows alone.

No table is created, so no fence appliers are owed. Idempotent: `ADD COLUMN IF NOT EXISTS`, constraints behind `pg_constraint` checks, `CREATE OR REPLACE`, `DROP POLICY IF EXISTS`.
