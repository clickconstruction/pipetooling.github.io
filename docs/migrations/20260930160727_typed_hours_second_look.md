# 20260930160727_typed_hours_second_look.sql (2026-09-30, v2.4242)

Hours typed by hand get a ledger, a hold and a second look. Until now a clock session someone typed for a worker looked the same as the worker's own punch, and the person who typed it could approve it.

- **`clock_typed_entries`** (new): one row each time a signed-in person makes time exist on a day that the clock had not recorded (`added`) or makes punched time stop existing (`trimmed`) — `user_id`, `work_date`, `typed_range` (a `tstzmultirange`), `typed_seconds`, the day's total before and after, `typed_by` + name, and `confirmed_by` / `confirmed_at` for the second look. SELECT for whoever may read the person's clock sessions; no write policy.
- **Two triggers on `clock_sessions`** write it. `clock_sessions_typed_snapshot` (BEFORE INSERT / DELETE / UPDATE of the time columns) remembers, once per person and day per transaction, what was on the day; `clock_sessions_typed_record` (a deferred constraint trigger) compares it with the day at commit and records the net change. It is day-level on purpose: the split and replace RPCs delete a day's rows and insert new ones, so a row-level rule would call every job split "typed". An open session counts to now + 10 minutes as what existed and to now − 10 minutes as what was added, so a real punch adds nothing. Writes with no signed-in person, salary-schedule sessions and quick adds are never the added time. Both functions swallow their own errors — the ledger never stops a punch.
- **The hold**: `clock_session_approval_hold(session)` returns `own` (the caller's own hours), `typed` (the caller typed hours onto it and nobody else has looked) or NULL. Trigger `clock_sessions_guard_approval` (BEFORE INSERT OR UPDATE OF `approved_at`) refuses the write — and a session a signed-in person inserts already approved; on an approval by anyone else it marks the typed entries under the session confirmed.
- **`approve_clock_sessions`** rewritten from its live body (read 2026-09-30): a held session is skipped, not approved — nothing else changed. **`approve_clock_sessions_v2`** returns the same result plus `held_own` and `held_typed`.
- **`confirm_clock_typed_entry(entry)`**: "Looks right" on hours typed onto a session that was already approved (an in-place time change keeps its approval). Refused for the typist and for the person whose hours they are.
- **`clock_typed_stamps(ids)`** and **`list_typed_hours_waiting()`**: what the screens read — the stamp and the caller's hold per session, and the added hours nobody else has looked at.
- **`app_settings.typed_hours_second_look_v1`** seeded `test`: the hold applies to sample accounts and ZZ-named people only, so the screens can be walked on prod before anyone real is held. A dev sets it to `on`. The ledger and the second-look record run in every mode.

Proof: `npm run test:pg:typed-hours` (18 scenarios on a throwaway Postgres — a real punch, the office typing a missed day, a job split, time added to approved hours, a trim, a worker's own late entry, the three switch settings, a ledger failure that does not block the write), and the whole file run on prod inside `BEGIN … ROLLBACK`.

Apply order: this migration first; it changes nothing a screen shows. The client that reads it follows, then the switch.
