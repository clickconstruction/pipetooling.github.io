# 20261104190000_users_login_attached_at.sql (2026-11-04, v2.6511)

PR 1 of punch list #260: a row in `public.users` no longer has to be a login. Until now `users_id_fkey` (`users.id → auth.users.id ON DELETE CASCADE`) refused a users row with no auth account behind it, so a worker with no login was a People record with `account_user_id` NULL who could hold no clock session and no Charged as (#254's first pricing, 2026-11-04). The spike found the auth server takes a chosen id on create (GoTrue ≥ v2.155.0; prod v2.197.0), so a login attaches to an existing `users.id` later and nothing that points at the row moves.

Body otherwise `20260714213000`'s.
