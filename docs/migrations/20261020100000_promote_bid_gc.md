# 20261020100000_promote_bid_gc.sql (2026-10-20, v2.5682)

New RPC `promote_bid_gc(p_bid_id uuid, p_new_gc_id uuid, p_old_gc_stays boolean)` — the atomic
GC handoff behind Edit Bid's × on the ★ card, "make bid's GC" on alternate cards, and the
rerouted change ▸ (punch list #134, Wendi's report).

SECURITY INVOKER, so RLS and the read-only/twin write fences apply: the `bids` UPDATE runs
first and raises on zero rows, rolling the whole call back. The swap, in order:

1. Own-GC (`customer_id IS NULL`) `bid_versions` **with at least one `bid_version_sends` row**
   re-key to the departing GC — sent letters stay with the GC they went to; unsent drafts are
   the project's estimate and stay with the bid.
2. The stepping-up GC's explicit versions become the bid's own (`customer_id NULL`).
3. `bid_gcs`: the NULL row re-keys to the departing GC (wholesale merge into an existing
   explicit row — the NULL row is the live primary state and wins); the stepping-up GC's row
   becomes the NULL row. A fully-departed GC's row is deleted so its due stops steering
   `recompute_bid_due`. A legacy builder primary (`customer_id` already NULL on the bid) has no
   key to move to: its NULL row is dropped.
4. `bid_proposal_rooms`: closed own-GC rooms re-key to the departing GC; the open own-GC room
   follows only while that GC's open slot is free (partial unique indexes), else it closes —
   the new GC never inherits a room minted for the old one. The stepping-up GC's rooms become
   the bid's own.
5. `bid_gc_recipients`: the stepping-up GC's row deletes (this was the duplicate-card bug);
   the departing GC gets a row (`'version'` when its packet keeps it on the bid's pages, else
   `'manual'`) when it stays, or its row deletes.
6. A **method-less whole-bid note** in `bids_submission_entries` records the handoff — it does
   not move `bids.last_contact` (only method entries count).
7. `recompute_bid_due(p_bid_id)` runs last.

Grants: EXECUTE to `authenticated` + `service_role` only. No new table, so no RLS-fence calls.

**Apply order:** push this migration before merging/deploying the client (the client calls the
RPC; the RPC is invisible to old clients). Smoke-tested on a throwaway Postgres 15: idempotent
re-run, the sent-packet handoff scenario and the unsent full take-off scenario both asserted.
