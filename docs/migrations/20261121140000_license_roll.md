# 20261121140000_license_roll.sql (2026-11-21, v2.8159)

State roll, the ground (punch list #411, step one; `to-dos/state-roll/`). Five tables and one gate function, for the kept roll of state licenses. They ship alone, ahead of the pull that fills them and every line of client code that names them, so the merge holds no deploy.

## What it does

- **`user_can_read_license_roll()`**: true for the people who hold the Hiring switch (`user_has_team_prospects_access()`). The one gate on every table here. Closed to `anon` by name.
- **`license_roll`**: one row a license, as the state's file has it today.
  - `source` is `tsbpe` (the plumbing board) or `tdlr`. `trade` is `plumbing`, `electrical` or `hvac`.
  - `license_class` is the rank, in the words `license_targets` uses, with `responsible_master` apart from `master`.
  - `license_number` is as the state writes it. It is unique within a source and a class (`license_roll_number_once`), not across them: the board numbers each rank on its own.
  - `status` is `current` or `expired`, the only two the state's files give. `licensed_on` is the day this rank was licensed, which TDLR does not give. `expires_on` is the expiry.
  - `last_name`, `first_name`, `middle_name`, `suffix`, `zip` and `county` are the state's. The county is upper case.
  - `name_key` is the last name, first name, middle initial and five-digit ZIP in lower case, joined with `|`. It joins one person's rows across ranks. Two people can share one, so a join on it is a match to check.
  - `endorsements` is a list: `medical_gas`, `fire_sprinkler`, `water_supply`, `drain_cleaner`, `drain_cleaner_restricted` and `utilities_installer` for plumbing.
  - `company` and `insurance_ends_on` are filled on a responsible master plumber's row.
  - `ours` marks a number that is one of our own people's or subs'. Such a row is kept whatever the county.
  - `first_seen_on`, `last_seen_on` and `gone_on` are the pull's: when it first saw the row, last saw it, and first found it missing.
- **`license_roll_changes`**: what a pull saw change on one row.
  - `kind` is `first_seen`, `renewed`, `lapsed`, `current_again`, `moved`, `endorsement`, `named`, `gone` or `back`.
  - `was` and `now_is` hold the fields that changed, before and after. `seen_on` is the day of the pull, and `pull_id` names it.
  - `roll_id` cascades with its row. It only grows.
- **`license_roll_pulls`**: the ledger. One row a file read, with `rows_seen`, `rows_kept`, `added`, `changed`, `gone`, the `error` when it failed, and who pressed Pull now.
- **`license_roll_counties`**: the counties whose rows are kept. Seeded with Bexar, Travis, Hays, Comal and Guadalupe, the five the permits cover.
- **`license_roll_left_off`**: a person who asked not to be listed, kept by license number and by `name_key`. The pull keeps no row that matches one.
- **Row security.**
  - Every table is read through `user_can_read_license_roll()`, the rule inside a scalar subquery.
  - Nobody signed in writes a roll row, a change or a pull. The pull writes with the service key.
  - A person who reads the roll adds a county under their own name, or removes one.
  - `license_roll_left_off` has no insert policy yet. The Leave off press ships with the person's sheet, as a function that also deletes the person's rows.
- Closed to `anon`. The four fences close the file.

## What is not kept

- **No phone, street address or email for a person.** The state does not give them (Tex. Gov't Code § 552.11765).
- **A responsible master plumber's business address and phone**, which the board does publish, are not kept either.
- **No apprentice row**, unless the number is one of our own people's. The state's apprentice file gives no age.

## Why a history table from the first day

The state keeps no history: a file says what is true today. What changed is known only by comparing one pull with the next, so the first pull is the first day anything can be said. A history table added later would have lost every week before it.

## Why Leave off is by name too

The board gives a person a new number at each rank. A journeyman left off by number alone would come back as a master. So a left-off person is kept by `name_key` as well.
