Push me, each person's own days and hours for pushes (punch list #141 PR 2, `to-dos/quiet-hours/README.md` → The plan → PR 2, decision 2 D). The client reads the table fail-soft (no row, or no table yet, reads as any time), so it may deploy first; push after the feature PR merges and regenerate the types. No function reads the table until PR 3.

## What it does

1. **`user_push_hours`**: one row a person (`user_id` PK → `users`, cascade), `days integer[]` (0 Sunday to 6 Saturday, at least one, every element known), `opens` and `closes` (`"HH:MM"` Chicago, zero-padded, so `opens < closes` as text is to after from), `updated_at`. No row is *Push me any time*.
2. **RLS**: the row's owner for every verb (`user_push_hours_own`); the owner of the company and a dev read every row (`user_push_hours_master_or_dev_read`, `is_master_or_dev()`), for the Office hours card's coverage line in PR 4; `authenticated` holds SELECT, INSERT, UPDATE and DELETE (*Any time* deletes the row); `anon` nothing; the service role everything, for the senders in PR 3 and PR 5. The three fence appliers run at the end.

## Why the shape

- A table of its own, not a column on `users`: `users` is read by every role's rosters and guarded against self-edits by the role trigger, so a self-written column there is a policy change on a hot table. A row of its own is `tell_customer_prefs`'s shape (`20261016060000`), already shipped and fail-soft.
- Not an `app_settings` row: those are the company's. These hours are one person's.
- The Office hours row's own fields and words, so `hasRule.ts`'s `officeOpen` and `nextOpening`, already on the edge, do the check with nothing new mirrored for the read.

## Verify
