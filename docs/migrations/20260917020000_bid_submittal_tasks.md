# 20260917020000 — bid_submittal_tasks (v2.3544, Submittals stage 6b)

The submittal robot's queue, shaped like `bid_price_matrix_requests`: `bid_id`, `submittal_id` (nullable — a schedule read is on the bid), `kind` CHECK read_schedule · file_cut_sheets · read_redlines, `input` jsonb (`{}` / `{ file_index, path, name, pages }` / `{ reviewer_index, path, name, person_id, person_name }`), `result` jsonb (the robot's rows / guesses / annotations), `status` CHECK queued · working · ready · blocked · cancelled · done, `requested_by/_at`, `claimed_by/_at`, `heartbeat_at`, `finished_at`, `reviewed_at/_by` (the office confirmed or discarded), `summary`. Indexes on `(bid_id, requested_at DESC)` and the live queue `(status, requested_at) WHERE status IN (queued, working)`.

RLS: pricing sharers (`is_pricing_sharer()` + `can_access_bid_for_pricing(bid_id)`) select, insert and update; the twin never touches it through RLS — `twin-mcp` writes with the service role. Ends with `apply_read_only_write_blocks()`, `apply_read_only_stmt_blocks()` and `apply_digital_twin_write_blocks()` (a new table gets the training-mode blocks and the twin fence). Idempotent. Apply with `bash scripts/db-push.sh` once on `main`; deploy `twin-mcp` after.
