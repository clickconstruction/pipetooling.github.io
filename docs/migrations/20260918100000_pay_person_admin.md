# 20260918100000_pay_person_admin — person admin through functions, with a reason and an audit row (v2.3584)

**What**:

- `pay_admin_events` — one row per admin action: `person_name`, `action` (`void_report` · `set_hours` · `set_pay_config` · `set_alias`), `payload` (before/after and, for a voided report, its payment rows), `reason`, `actor`, `created_at`. RLS: payroll access to read and insert. The three house-rule block calls close the migration.
- `void_pay_report(p_stub, p_reason)` — deletes the report; its payments, days, deductions and additional lines cascade, and the deleted-records archive keeps every row. Refuses a report whose payment carries a `source_id` (a real send), so money tied to a bank row is never dropped silently. Returns the snapshot it recorded.
- `set_person_hours(p_person, p_from, p_to, p_hours, p_reason)` — `0` clears the manual `people_hours` rows in the range; `> 0` sets every date in the range to that figure (upsert on person + date). Before/after in the payload. Refuses hours outside 0–24.
- `set_pay_config(p_person, p_changes, p_reason)` — only the keys given change: `hourly_wage`, `is_salary`, `record_hours_but_salary`, `show_in_hours`, `office_hourly_wage`; unknown keys refused; a missing row is created.
- `set_cashapp_alias(p_counterparty, p_person, p_not_staff, p_reason)` — upserts the reconcile alias (key = lowercased, whitespace-collapsed name); `not_staff` clears the person and any note rule.

Every function requires a non-blank reason and payroll access (or the service role); SECURITY INVOKER.

**Why**: v2.3584 — the owner, 2026-09-18, on Mike Z: *"he was still listed as hourly but not working … How can I adjust his hours? And how can I make it easy for an agent to manage the app to do so in the future?"* Until now every one of these was a UI-only write. See `docs/recent-features/v2.3584.md`.

**Verified**: `supabase/tests/pay_sources/30_person_admin.sql` (run by `npm run test:pg:pay-sources`): reason required; clear and set hours with before/after; void with cascade and the audit snapshot; refusal of a sourced payment and of an unknown report; config partial update, unknown key refused, row created; alias not-staff and person with key normalisation; seven audit rows.

**Idempotent**: `CREATE TABLE IF NOT EXISTS`, `DROP POLICY IF EXISTS` + create, `CREATE OR REPLACE FUNCTION`. Additive; no data touched.
