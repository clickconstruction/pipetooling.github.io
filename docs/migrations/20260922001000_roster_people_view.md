# 20260922001000_roster_people_view.sql (2026-09-21, v2.3698)

People spine, PR 1 ([`docs/recent-features/v2.3698.md`](../recent-features/v2.3698.md)).

- **`CREATE OR REPLACE VIEW public.roster_people`** — one row per human: `users` FULL OUTER JOIN `people` ON `people.account_user_id = users.id`, filtered to rows with a name and to signed-in viewers (`(SELECT auth.uid()) IS NOT NULL`). Columns: `user_id`, `person_id` (both CASE-wrapped so PostgREST does not relate every FK through the view — v2.2995), `row_key` (`u:<id>` / `p:<id>`, the Person-desk param), `pay_name` (trimmed account name, else roster name — the pay tables' key), `account_name`, `roster_name`, `role`, `kind` (roster kind, else the role mapped `helpers → helper`, `subcontractor → sub`), `account_kind` (`twin` | `sample` | `external` | `person`), `is_digital_twin`, `is_sample`, `is_dev`, `read_only`, `needs_supervision`, `user_archived_at`, `person_archived_at`, `is_archived`, `is_pay_roster`, `is_active_roster`, `has_login`, `has_roster_row`, `start_date`, `end_date`, `master_user_id`. No email, phone, notes or sign-in times. Owner rights (not `security_invoker`): every viewer gets the same roster. `REVOKE ALL … FROM PUBLIC, anon; GRANT SELECT … TO authenticated, service_role`.
- **`salary_sync_one_user_clock_sessions(uuid, date, timestamptz)`** — rewritten from its newest definition (baseline) with one guard after `BEGIN`: an archived account (`users.archived_at IS NOT NULL`) gets the day's unapproved `salary_schedule` sessions deleted and the function returns.
- **`sync_salary_clock_sessions_for_day(date)`** — the template loop joins `users` and skips `archived_at IS NOT NULL`.
- **`auto_approve_salary_clock_sessions()`** — rewritten from `20260903010000`; the session query adds `AND u.archived_at IS NULL`.

Idempotent (CREATE OR REPLACE throughout); no CREATE TABLE, so no read-only block re-apply.
