# 20261101163412_job_folders_tidy.sql (2026-11-01, one Drive folder per job under its customer, v2.6284)

The ground under the folder tree (the owner's rule of 2026-11-01: a folder for every job, under its customer, uniform, and a quick link from the app to each): the stamps the folder sweep leaves on a job, and the sweep's cron. The rule itself lives in `supabase/functions/_shared/jobFolders.ts` (`FolderTree.placeJob`, under `job-drive-folders`' press and `sweep` verbs and the photo sweep's first photo on a job with no folder); the words in `_shared/whereFilesGo.ts`.

- **`jobs_ledger.drive_folder_tidied_at`** (`timestamptz`) — when the sweep or the press last placed this job's folder in the tree; null = never looked at. A partial index on the live jobs (`status` null or not `paid`), nulls first, serves the sweep's pick.
- **`jobs_ledger.drive_folder_hold`** (`text`) — why the folder could not be placed, in the office's words (outside the Shared Drive, not a folder, not shared with the app, the customer's folder held); null once it sits where it should. The Where files go tab and the job window read it; nobody has to run anything to see it.
- **The cron** `job-drive-folders-sweep`, every 10 minutes: `POST /functions/v1/job-drive-folders` with `{"sweep":{}}` and the cron secret (Vault `PROJECT_URL` and `CRON_SECRET`, as `photo-save`'s cron), only while some live job was never placed or was placed more than seven days ago, so a tidy tree makes no call. Unscheduled first, so a second run leaves one row.
- **No table is made**, so the three fence calls are not needed. Additive: `ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`.

Apply order: the migration first is harmless (two nullable columns nobody reads yet); the function reads them, so push before `job-drive-folders` and `photo-save` are deployed from the merge (`npm run check:calls-ahead` holds the deploy until the push).
