# 20261110220345_bid_site_permits.sql (2026-11-10, v2.6866)

Bids and permits: what the city holds on a bid's address (punch list #307, PR 2 and 3; `to-dos/bid-permits/`). One read and one index, no table.

## What it does

- **`bid_site_permits(p_city text, p_numbers text[])`**: every permit in a city whose street starts with one of the house numbers asked for (`split_part(address_key, ' ', 1)`), newest first, at most 5,000 rows. It returns the permit's number, type, kind, stage, work, project name, street, days, declared value, area, the contact the city lists and the builder key. Invoker rights: it reads `permits` under the caller's own row security, so it shows the office and every estimator what Prospects → Permits already shows them, and nobody else anything.
- **`permits_city_house_number_idx`** on `(city, split_part(address_key, ' ', 1))`, partial on a non-null key: the read's lookup.

The join to a bid is not made in SQL. A bid's address is one typed line and the feed's street is not tidy (a street type spelled out or left off, Loop 1604 as `n 1604 w`), so `src/lib/research/bidSite.ts` reads both into one shape and decides which permits sit on the bid's site.

The function is closed to `PUBLIC` and `anon` by name and granted to `authenticated`. No table is made, so no fence calls.
