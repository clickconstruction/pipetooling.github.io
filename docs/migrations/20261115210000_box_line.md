# 20261115210000_box_line.sql (2026-11-15, v2.7348)

Materials on site, punch list #351 PR 2: what is in a box, on a line of its own. Nothing said what was in a box but its part lines, so people typed it into the name. PR 1 (`20261114100000`) held the name to letters and a number and parked the words on the where line. This file gives them a column.

## What it makes

No table, so no fence call is owed. No policy, trigger or function changes.

- **`job_containers.description text`**, nullable, with `job_containers_description_check`: null, or 1 to 80 characters that are not all spaces. It holds a person's own words and nothing else. While it is null the screens write the line from the box's parts (`src/lib/materials/boxLine.ts`, shared with `box-read` through `supabase/functions/_shared/boxLine.ts`), so the app's line is never stored and never stale. Clearing a person's words writes null, which hands the line back to the app. An empty string is refused, so nothing said has one spelling.

## Who may write it

Whoever may update the box: `job_containers_update` (`on_site_can_touch_job`) is unchanged, so the people who may rename a box may say what is in it. An account in training and a digital twin are held by the table's existing restrictive policies. `on_site_carry_job` moves a box by its `job_id`, so a combine or a whole-job move carries the words with the box.

## Locks

One `ADD COLUMN IF NOT EXISTS` carrying its CHECK. The column is nullable with no default, so no row is rewritten and the exclusive lock is a moment. `SET lock_timeout = '3s'` makes a busy moment fail fast. A second run adds nothing.

## Order of deploy

The client's box reads name the column (`CONTAINER_COLS`), so **push right after the merge, before the Pages deploy finishes**: until the push, a build that carries this PR is refused its read of a job's boxes with the column's name. A build from before the PR never names the column and reads as it did. `box-read` selects the column too and is redeployed after the push; the function deployed before answers as it did, and the page then writes the app's line from the lines that answer carries.
