# 20261023003000_shadow_reclaim_idle_reasons.sql (2026-10-23, v2.5753)

Robot rounds, one rule (punch list #142 follow-up). Seen live 2026-10-23 00:08–00:14 UTC: the Console's queue read *Ready · 4* while the Mac Mini's rounds reported *found nothing to do*. Two changes, one transaction; no table is created.

- **`twin_shadow_runs`**: the `UNIQUE (reference_bid_id)` constraint from `20260831210000` is dropped and replaced by the partial unique index `twin_shadow_runs_live_reference_uidx` on `reference_bid_id WHERE status <> 'void'` — one *live* run per reference. Before this a voided shell (a *Leave this one to me* order, a category error, a reference sent before the lock) blocked every later claim of that bid for good, even after the person let the robot back in (b510 on 2026-10-23: its shell b522 voided at 00:03, its opt-out cleared at 00:12, the queue listing it Ready while the dispatcher could never insert a second run). twin-mcp's `next_shadow`, `open_shadow` and `heartbeat` read the live run only (`_shared/shadowEligibility.ts`).
- **`robot_run_signals(p_bid_id)`** (`CREATE OR REPLACE`, same signature): the run it reads is the live one first, then the newest, so *Read the run* on a re-claimed bid opens the current shell, not the voided one.
- **`robot_agents()`**: dropped and recreated (the return table grows). Two new columns, `idle_at` and `idle_progress` — the key's latest idle check-in and its shape, which since v2.5753 twin-mcp fills with `ready` (how many live bids the one rule would let the round claim at that moment) and `held` (the bids it passes over, each with the reason in plain words). `idle_rounds_today` now sums a stretch's `progress.nothing` (the rounds in it that saw no bid to claim) when the row carries it, falling back to `rounds` and then 1 as before, so a round that checked in and then worked a bid is no longer counted as one that found nothing. The join to the heartbeat shell's run takes the live run first.

Additive for readers: the old client ignores the two new columns and `holds_open_shell` keeps its meaning. Push after `20261022060151_robot_agents`. Deploy `twin-mcp` after the push: before the function is deployed the idle rows carry no `ready`/`held` and the card draws as before.
