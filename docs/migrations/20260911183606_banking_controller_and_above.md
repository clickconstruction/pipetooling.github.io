# 20260911183606_banking_controller_and_above.sql (2026-09-11, v2.3305)

Banking is controller and above (fragment `docs/recent-features/v2.3305.md`). Idempotent (`CREATE OR REPLACE`, `DROP POLICY IF EXISTS` + `CREATE POLICY`); no CREATE TABLE, so no read-only-block calls.

- **`is_banking_staff()`** → `is_master_or_dev() OR is_controller()` (was `OR is_assistant()`, which admitted plain assistants). Every policy already gating on it narrows with it: `mercury_accounting_label_rules`, `mercury_accounting_label_suggestions`, `mercury_transaction_org_notes`, `mercury_transaction_duplicate_dismissals`, `mercury_reconcile_runs`, `mercury_debit_card_user_links`.
- **Shared tables re-pointed to `is_office_staff()`** (the identical set they gated on before — no behavior change for any role): `mercury_drag_sort_labels`, `mercury_transaction_drag_sort_assignments`, `mercury_transaction_attributions`, `mercury_transaction_job_allocations` (all four verbs each), `mercury_transaction_supply_house_invoice_links` (`mtshil staff select`), `mercury_transaction_ar_returned` (four verbs, `OR primary` kept). These feed Job Parts Tally, the Jobs board, Job Summary and AR, which assistants keep.
- **Nicknames**: the baseline `assistant` policies (`is_assistant()`) are dropped. `mercury_account_nicknames office select` and `mercury_debit_card_nicknames office select` read `is_office_staff()` (card names on the Tally allocations modal and the Jobs bank-payments modal); `mercury_debit_card_nicknames banking staff insert / update / delete` read `is_banking_staff()`. Side effect: `master_technician`, which the matrix always listed but which had no nickname policy, now reads and edits them.
- **`can_manage_mercury_category_tags()`** → `is_banking_staff()` (was a four-role literal with assistant).
- **Banking-only RPC bodies** (live-definition string replacement, the reverse of the v2.2920 sweep; loud on a missing function, NOTICE + skip on a body with no four-role literal): `bulk_insert_accounting_label_suggestions`, `bulk_approve_accounting_label_suggestions`, `count_pending_accounting_label_suggestions`, `auto_approve_pending_accounting_label_suggestions`, `list_people_with_kind_for_banking_attribution`, `list_people_for_banking_attribution`, `backfill_mercury_auto_attributions_for_debit_card`, `upsert_mercury_org_transaction_note`.
- **Deliberately untouched**: the `mercury_transactions assistant select` policy (the Jobs board's bank-deposit matching and job card-charge costs read the table directly), `replace_mercury_transaction_splits`, `list_users_for_banking_attribution`, `list_user_mercury_review_window`, and the `*_as_staff` / `*_for_tally_*` helpers — all shared with pages assistants keep.

Apply order: merge (client deploys first — the assistant shell hides Banking either way), then `supabase db push`, then `supabase functions deploy mercury-reconcile` and `supabase functions deploy get-mercury-account-balances`.
