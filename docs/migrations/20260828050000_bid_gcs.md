# 20260828050000 — bid_gcs: per-GC due / submitted-to / ITB (v2.2416)

Per-GC bids Phase 4 (`docs/PER_GC_BID_PLAN.md`).

- **New table `bid_gcs`**: one row per (bid, GC); `customer_id` NULL = the bid's own GC
  (unique via `COALESCE(customer_id, zero-uuid)` expression index). Columns:
  `due_date date`, `due_time time`, `submitted_to_name/phone/email text`,
  `itb_links jsonb default '[]'`, timestamps, `created_by`. Rows created lazily on first
  per-GC edit — the migration ships the table empty, no backfill.
- RLS: `can_access_bid_for_pricing(bid_id)` on all four verbs (same gate as
  `bid_version_sends`); grants to `authenticated`; BOTH
  `apply_read_only_write_blocks()` + `apply_read_only_stmt_blocks()` applied.
- **`recompute_bid_due(p_bid_id)`** (INVOKER, `search_path=public`): sets
  `bids.bid_due_date`/`bid_due_time` to the earliest due among GCs whose packet has NO
  send ("still open"), falling back to the earliest per-GC due overall; RETURNs without
  touching bids that have no per-GC dues (hand-set dates keep working). Ties on date break
  by earliest time, NULLs last.
- Trigger fn `sync_bid_due_from_bid_gcs()` fires it AFTER INSERT/UPDATE/DELETE on
  **`bid_gcs`** and on **`bid_version_sends`** (a send changes which dues are open; this is
  a second trigger on that table beside `bid_version_sends_sync_bid_date_sent`).

Deploy order: client merged first (the `BidGcDetailsEditor` hides while the table 404s),
`supabase db push` right after.
