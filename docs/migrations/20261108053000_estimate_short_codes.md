# 20261108053000_estimate_short_codes.sql (2026-11-08, v2.6677)

The estimate text's link: a ten-character code, and the guard on guessing it (punch list #281, PR 2 of three; `to-dos/short-estimate-link/README.md`). PR 1 (v2.6657) put the share link (`share_estimate_link`, #127) in the text the Tell the customer sheet sends: 32 base64url characters of token, 75 characters of link. The owner's call 2 of 2026-11-07: the code is 10 characters, from an alphabet that reads aloud without a mistake.

## What it does

1. **`share_estimate_link(p_estimate_id uuid) → text`** is re-stated with the same refusals (signed out, a training account, a twin, anyone off the office team, an estimate not there or not sent) and a new token: ten letters from `23456789abcdefghjkmnpqrstuvwxyz`, 31 letters with no 0, O, 1, l or I. Each byte of `gen_random_bytes` is used only when it is under 248 (8 × 31), so no letter is likelier than another; a code the table already holds (one chance in 10¹⁴) is minted again. `token_hash` keeps the code's SHA-256 as before, so `estimate_share_links_token_hash_shape`, the unique, the 14 days and `_shared/estimateTokenLookup.ts` are unchanged, and a 32-character link made before the push keeps opening until its day. 31¹⁰ is about 8 × 10¹⁴ codes, about 49.5 bits; against a thousand live codes a guesser at a thousand tries a second expects one hit in about 25,000 years.
2. **`estimate_link_misses`**: the hour (`date_trunc('hour', now())`), the SHA-256 of a caller's address (never the address; `estimate_link_misses_source_hash_shape`) and the count of links from it that opened nothing. RLS on with no permissive policy and every grant revoked: the service role alone, which bypasses RLS, touches it. The four fence appliers run at the end.
3. **`estimate_link_miss(p_source_hash text) → integer`**: one more miss for the source in the current hour, answering the hour's count (an upsert on the primary key). `SECURITY DEFINER`; EXECUTE to `service_role` only. The three functions that open an estimate from a link (`get-estimate-for-customer`, `accept-estimate`, `log-estimate-option-view`) call it through `_shared/estimateLinkMisses.ts` on a lookup that finds no hash, log the count, and answer **429** once it passes 20 in the hour (`docs/EDGE_FUNCTIONS.md`). The lock is on misses only: a customer with a working link behind the same address is never turned away.
4. **`purge-estimate-link-misses`**, a `pg_cron` line at 09:40 UTC daily, drops hours older than a day; a warning instead when `pg_cron` is not installed (the SQL bed).

## Release order

Merge the PR, `supabase db push`, then deploy the three functions (`supabase functions deploy get-estimate-for-customer accept-estimate log-estimate-option-view`). Either order works on its own: a function deployed first finds no `estimate_link_miss` and answers its 404 as before (fail open); a migration pushed first mints ten-letter codes that the deployed functions already open, since the lookup hashes whatever it is given. The client needs no change (`estimateAcceptUrl` takes the code the RPC returns); `src/types/database.ts` picks up the new table and function in the next `chore(types)` PR.
