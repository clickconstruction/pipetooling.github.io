# 20260928190000_estimates_field_write_up.sql (2026-09-28, v2.4071)

Adds `estimates.field_write_up jsonb` (nullable, commented). The Quick Estimate wizard creates an ordinary `estimates` draft on its first job/customer pick and autosaves into it, and nothing told that draft apart from a change order the same person drafted in the office editor — so the wizard could not offer to pick a half-done write-up back up (the v2.2293 deferral). The wizard alone writes the column: `started_at`, the `job` it was opened on (`{ id, hcp, name, address, customer_id }` — the row's own `job_ledger_id` stays reserved for the created-from link), `phone`, `free_customer`, and `dismissed_at` once the person chooses *Leave it for the office*. Office screens never read it. Additive, `IF NOT EXISTS`, `lock_timeout = 3s`; no RLS, grant, index or trigger change (the table's policies cover the column). Pushed before the v2.4071 client deploys — the client's insert names the column.
