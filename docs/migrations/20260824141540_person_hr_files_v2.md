# 20260824141540_person_hr_files_v2.sql — HR files v2: revisions, coverage marker, provenance, agent RPC + role (v2.2232)

Additive/idempotent upgrade of the v2.2220 HR files system (`docs/HR_FILES.md`):

1. **`person_file_revisions`** — new table; a `BEFORE UPDATE` definer trigger on
   `person_files` archives the prior version whenever `content` or
   `covered_through` changes. Dev `SELECT` only; **no write policies by design**
   (rows come only from the trigger). The curated docs were the one HR layer
   that lost history on rewrite; now nothing does.
2. **`person_files.covered_through timestamptz`** — writer-set "this doc folds
   in entries created through T". The freshness kernel prefers it over
   `updated_at` inference (UI lands separately as v2.2229).
3. **`author_label text`** on `person_files` and `person_file_entries` —
   provenance for non-user writers (the agent has no `auth.uid()`).
4. **`hr_agent_write(jsonb)`** — SECURITY DEFINER RPC: atomically append
   validated entries (source whitelist, person existence) and/or rewrite the
   summary and/or rewrite-or-append the narrative, stamping `author_label` +
   `covered_through`. EXECUTE revoked from `PUBLIC`/`anon`/`authenticated`;
   granted to `hr_agent`.
5. **`hr_agent` role** — least-privilege LOGIN role for the agent. Table grants
   + role-scoped RLS policies give it: read on `people` and all three HR
   tables, INSERT on entries (**no UPDATE/DELETE policy → append-only holds for
   the agent by policy**, not convention), INSERT/UPDATE on `person_files`,
   EXECUTE on the RPC. Created with **no password**; set out-of-band after
   `db push` (never in git):

   ```sql
   ALTER ROLE hr_agent WITH LOGIN PASSWORD '<generated>';
   ```

   then store it as `HR_AGENT_DB_PASSWORD` in `.env.local` and stop using the
   `postgres` password for agent HR work.

Safety notes: `lock_timeout` set; ends with both `apply_read_only_write_blocks()`
and `apply_read_only_stmt_blocks()` (new table gets both read-only guards). The
read-only restrictive policies and statement trigger no-op for `hr_agent`
(`is_read_only()` is false when `auth.uid()` is NULL).
