# 20261111060000_price_sheets — a supply house's price sheet kept as rows under its fixtures (v2.6908, punch list #308 PR 4)

**File**: `supabase/migrations/20261111060000_price_sheets.sql`
**Card**: `to-dos/price-sheet-reader/README.md`

## What it adds

| Object | What it holds |
| --- | --- |
| `supply_paper_groups` | One row per fixture heading on a quote: `group_no`, `tag` and `label` as printed, `each_price` (the printed Subtotal EACH), `held_why`, and where the fixture landed on the bid, filled by PR 6: `count_row_id`, `template_id`, `placed_line_id`, `placed_at`, `placed_by`. Unique on (`paper_id`, `group_no`), and it goes with its paper. |
| `supply_paper_lines.group_no`, `page_no` | The fixture a row sits under on the same paper, and the page it is printed on. |
| `price_sheet_gate(act)` | The gates every function below passes, said once: signed in, `may_edit_parts_book()`, not read-only, not a digital twin, not archived. |
| `price_sheet_save(paper, groups, lines)` | Keeps a sheet that was just read: a `supply_papers` row of kind `quote`, `came_by = 'sheet'`, with its house when known, its bid, number, day, good-until day and the file's hash; its fixtures; its rows in the order read (800 at most). Files nothing. Returns the paper id. |
| `price_sheet_set(paper_id, p)` | Settles the house, number, day, good-until day or bid. The house cannot change while a row of the sheet is filed. |
| `price_sheet_line_hold(line_id, why)` | Leaves an unfiled row out (`left_out`), or brings it back (empty). |
| `price_sheet_line_part(line_id, part_id)` | Keeps a person's pick of the part for an unfiled row, or undoes it with null. |
| `price_sheet_discard(paper_id)` | Removes a sheet with nothing filed and nothing placed. |

## Access

`supply_paper_groups`: read for `may_edit_parts_book()` on papers of kind `quote` or `bid`; written only by the functions. `EXECUTE` on each function to `authenticated` and the service role, revoked from `anon`. One table is new, so the migration ends with the four fence appliers.

## Additive and idempotent

`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE`, `DROP POLICY IF EXISTS` before the policy. The bed applies it twice.
