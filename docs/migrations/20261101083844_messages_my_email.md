# 20261101083844_messages_my_email.sql (2026-11-01, v2.6266)

Messages → My email (punch list #230 PR 1, `to-dos/messages-my-email/README.md`): the ground for a tab that reads a person's own Inbox and Sent live and tags a Gmail conversation onto a job. Everything here but the person's own switch is written by the edge function `gmail-mine` (PR 2) as the service role; nothing reads or writes it until that function deploys.

- **`email_tag_threads`** — one row per Gmail conversation a person tagged: `user_id` (whose box; deleting the person deletes their tags), `gmail_thread_id` (never blank), the job in exactly one of `bid_id`, `project_id` (a GC project by `gc_projects.project_id`, as `messages` and `contact_jobs` key one) and `jobs_ledger_id` (`email_tag_threads_one_job`; each cascades, so a tag goes with its job), `tagged_by`, `tagged_at`, and the follow's place and health for PR 4 (`last_read_at`, `last_error`). Unique on `(user_id, gmail_thread_id)`; an index on `(user_id, last_read_at)`. RLS: SELECT for the office team, `(SELECT gc_office_team())`; no INSERT, UPDATE or DELETE policy, and every privilege the project's defaults hand a new table revoked first, so `authenticated` holds SELECT alone and the service role writes.
- **`my_mail_set(p_on boolean, p_hidden_labels text[] DEFAULT NULL)`** — SECURITY DEFINER, `search_path = public`: the caller's own `users.my_mail_on` and, when the list is given, `users.my_mail_hidden_labels` (trimmed, the empty ones dropped, once each whatever their case, in the order given; twenty at most, each 225 characters at most; null leaves them). Refuses anyone not signed in, and a null switch, in words. Training mode is still refused by the `read_only_block_stmt` trigger on `users`, which fires inside a definer. Answers `(is_on, hidden_labels)` as saved. Closed to `PUBLIC` and `anon`; `authenticated` and `service_role` execute it. The two columns carry no UPDATE grant (prod grants `users`' UPDATE column by column), so this is their one door.
- **`messages.mailbox`** takes `mine` on an email alone: `messages_mailbox_known` is dropped and added again `NOT VALID`, then validated, inside a `pg_constraint` check so a rerun is a no-op. **`messages.mail_user_id`** (`users`, `ON DELETE SET NULL`) names whose box a tagged line came from, with a partial index on `(mail_user_id, gmail_thread_id)` where it is set, for the untag and the follow.
- **`email_write_line`** is recreated from its newest definition (`20261031050000_messages_invitation.sql`) carrying `mail_user_id` from `p_row`, so `gmail-mine` writes a tagged line through the same one write, with its files and the same Message-ID fence the boxes use. The bids@ reader sends none, so its lines stay null and nothing about it changes; the grants are kept.
- **`users.my_mail_on`** (`boolean NOT NULL DEFAULT true`: on for every office member, the owner's word of 2026-11-01) and **`users.my_mail_hidden_labels`** (`text[] NOT NULL DEFAULT '{}'`). They read as the rest of a `users` row reads.
- The hot tables are altered last, `messages` and then `users`, so their locks are held for the shortest stretch before the commit; the three fence calls close the file.

Tried before the PR on a throwaway local Postgres 15 with stubs for the five tables, `auth.uid()`, the office-team helper and the fence helpers (the read-only pair as their migrations define them): the migration applied twice in a row, then a rolled-back scenario held every rule above (the old team text still valid, `mine` on an email and never on a text, a tagged line written with its person and file and the same mail from a box answered with that line, a reader's line left null, one job and one row per conversation, the estimator reading the tags and a helper none, nobody signed in writing one, `anon` shut out, `my_mail_set`'s cleaning, refusals and training-mode refusal, the column shut to a direct UPDATE, a deleted person's tags gone and lines kept, the three fences on the table).
