# 20261013110000_drive_links.sql (2026-10-12, v2.5372)

Messages, cut 7a (GC Reviews helper 9, directed by the lead session GC Review). The data behind files going out: our own link to one file in a job's Drive folder, how each file on a line we sent went, and the opens. The `drive-link` function (cut 7b) is the only writer of a link, and the screens come with 7d to 7f. The mock-up is `to-dos/gc-mode/messages/files-out-mockups.html` on spike/gc-mode. Nothing makes a link until 7b is deployed, so nothing changes for anyone until then.

## What it does

1. **`drive_links`**: one row per file's own link, `clicktooling.com/f/<link>`.
   - It keeps the link's SHA-256 in `token_hash`, never the link. The link itself lives on the line it went on.
   - It names the job whose folder holds the file, as the spine ties a line: one of `bid_id`, `project_id` and `jobs_ledger_id`, each on delete cascade.
   - It names the Drive file and its half. A Plans file opens in Drive's own viewer, since that half is open to anyone with its link. A Team only file comes through the function, so Team only is never opened up.
   - It keeps the file's name, type and size, the line it went on, who made it and when, and when it ends: 30 days after it is made, the lead's call. When and by whom it was cut off, if it was.
   - The office team reads it. Only the service role writes it. Its checks hold the hash's shape, one job, a half it knows, and an end after its start.
2. **`message_attachments`** (cut 6) gains three columns, each with its check:
   - `sent_as`: how a file on a line we sent went. `file` keeps its bytes in `message-attachments` under `out/`, so the office's one page opens every file on a line. `link` keeps our link, or their portal's, in `url`. `picture` is a photo on an email. Null on a line that came in. A link went as a link, and a file as the file or the picture.
   - `drive_link_id`: our link's row, on a file that went as a file's own link. A link to their portal has none, since the portal's link opens it. Only a link we sent carries one.
   - `drive_file_id`: the Drive file this is. That is where Save to Drive put a file that came in, or the Drive file a line we sent carried. The job's one list shows it once, where it lives.
3. **`public_page_views`** takes the surface `drive_link`: each open of our link, `entity_id` the `drive_links` row. The list is main's newest with `drive_link` added.
4. **`cut_drive_link(link)`**: the office team cuts a link off, and its open page reads the turned-off words from then on. A link cut off already answers its first cut and keeps the first name. It refuses anyone outside the office (*Only the office cuts a link off.*), a training account (*A training account cannot cut a link off.*), a twin (*A digital twin cannot cut a link off.*) and a link not there (*That link is not there.*).
5. **`drive_link_views(links)`**: the office's read-back of the opens, the way `customer_portal_views` reads a page's. Per link it gives how many opens, the first and the last, and each open's time newest first, the newest 50. It never says who: a link cannot know, so a forwarded link reads the same as the first person's open. Outside opens only. The office team only; anyone else gets no rows.

A new table, so the three house calls end it.

## Verify after the push

```sql
-- 1. The table and the three columns, read only.
SELECT table_name, column_name FROM information_schema.columns
WHERE (table_name = 'drive_links' AND column_name IN ('token_hash', 'half', 'ends_at', 'cut_at'))
   OR (table_name = 'message_attachments' AND column_name IN ('sent_as', 'drive_link_id', 'drive_file_id'))
ORDER BY 1, 2;
-- expect: seven rows

-- 2. The two functions, the signed in only.
SELECT p.proname, has_function_privilege('authenticated', p.oid, 'EXECUTE') AS authenticated, has_function_privilege('anon', p.oid, 'EXECUTE') AS anon
FROM pg_proc p WHERE p.pronamespace = 'public'::regnamespace AND p.proname IN ('cut_drive_link', 'drive_link_views') ORDER BY 1;
-- expect: both authenticated true, anon false

-- 3. The surface, and no link yet.
SELECT pg_get_constraintdef(oid) LIKE '%drive_link%' AS surface FROM pg_constraint WHERE conname = 'public_page_views_surface_check';
SELECT count(*) FROM public.drive_links;
-- expect: true; 0
```
