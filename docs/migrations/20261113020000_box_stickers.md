# 20261113020000_box_stickers.sql (2026-11-12, v2.7072)

Stickers before boxes, the ground (punch list #329, PR 1 of 6). A label's code is cut from its box's own row (`job_containers.code`), so a label cannot exist before its box. This makes a sticker its own row: a printed code and a short number that point at one box, or at nothing yet. `job_containers.code` is not touched.

## What it makes

1. **`sticker_runs`**: a run of stickers printed at once. `job_id` (where a new box made from one of its stickers lands; set null when that job is deleted, and the stickers stay good), `sticker_count` (1 to 500), `first_number` and `last_number`, `copies` (1 to 6), `printed_by`, `printed_by_name`, `printed_at`. A check holds the block whole: both numbers or neither, and as long as the run.
2. **`box_stickers`**: one sticker. `run_id`, `number` (unique, from `box_sticker_number_seq`, one company-wide count), `code` (unique, generated: the id's first eight hex characters in capitals, by `job_containers.code`'s rule), `container_id` (null while blank, set null when its box's row is deleted), `placed_by`, `placed_by_name`, `placed_at`, `lost_at`.
3. **`box_sticker_events`**, insert only: `kind` of `placed`, `moved`, `taken_off`, `lost`, with `from_container_id`, `to_container_id`, `by_user_id`, `by_name`, `at`.
4. **`job_container_names`**, insert only: `container_id`, `old_label`, `new_label`, `by_user_id`, `by_name`, `at`.

## The triggers

- **`sticker_runs_stamp`** (BEFORE INSERT, definer): refuses in words anyone who may not print a run, checks the count and the copies, and fills who and when from the session. It runs before a number is taken, so a refused run takes none.
- **`sticker_runs_mint`** (AFTER INSERT, definer): takes the run's block from the sequence under an advisory lock, so two runs printed at once get two unbroken blocks, and makes the stickers. A new id is cut for any code a box or a sticker already carries, twenty tries a sticker.
- **`job_containers_code_free`** (BEFORE INSERT on `job_containers`, definer): refuses a new box whose code a sticker already holds, so a scanned code names one thing. The app makes the box again under a new id.
- **`box_sticker_events_judge`** (BEFORE INSERT, definer): locks the sticker, refuses an act that does not fit where it is (SQLSTATE `P0STK`: placed on one that is on a box, moved or taken off or lost on a blank one, anything on a lost one), refuses Unsorted and a retired box, and fills the box the sticker left, who and when. It runs before the INSERT policy, so the policy judges the boxes the database filled in.
- **`box_sticker_events_apply`** (AFTER INSERT, definer): moves the sticker to match the row that was just allowed.
- **`box_stickers_keep_whole`** (BEFORE UPDATE OF `container_id`): a sticker with no box has no placer. It fires on the foreign key's own SET NULL too.
- **`job_containers_keep_names`** (AFTER UPDATE OF `label` on `job_containers`, when the label changed, definer): one `job_container_names` row.

## The functions

| Function | Security | What it does |
|---|---|---|
| `mint_sticker_run(p_job_id, p_count, p_copies default 1)` | invoker | Inserts the run as the caller and answers `{ run, stickers: [{ id, number, code }] }` in number order. The rules are the table's own; it adds the reach refusal in words. |
| `sticker_by_code(p_code)` | definer | The sticker a code names, or null: its id, number, `blank` / `on_box` / `lost`, the box with its name, kind and job, who put it there and when, and the job its run was printed for. The dash and the case of a typed code do not matter. |
| `box_sticker_facts(p_sticker_id)` | definer | The same by id. `place_sticker` reads it for its verdict. |
| `place_sticker(p_sticker_id, p_container_id, p_job_id, p_label, p_kind, p_where_note, p_place_id)` | invoker | With `p_job_id`, makes a new box there (id `p_container_id` when the client made one, name `p_label` or the sticker's number) and places the sticker in the same transaction. Without it, places the sticker on the known box `p_container_id`. Only a blank sticker is taken: otherwise `{ ok: false, sticker }` says where it is, and a new box made a moment before is undone. The same placing sent twice answers `{ ok: true, already: true }`. |
| `sticker_can_mint()`, `box_sticker_caller_name()`, `box_sticker_number_words(n)` | definer, definer, immutable | The three printing roles; the caller's own name; `0147`. |

The two writes are `SECURITY INVOKER` on purpose. `on_site_can_touch_job` reads `jobs_ledger` under the caller's own RLS, and inside a definer it would say yes to every job. The two reads are definers on purpose: the caller's RLS hides a sticker on a box of a job they are not on, which is exactly when a scan must still say *Marcus put 0147 on R76*.

## Who may do what

| Table | Read | Write |
|---|---|---|
| `sticker_runs` | whoever may touch the run's job; an orphaned run, the office | insert: the office, a primary or a superintendent on a job they can reach, in their own name. update: the same roles, `job_id` alone (a column grant), from a job they reach to a job they reach |
| `box_stickers` | on a box: whoever may touch the box's job. blank: whoever may touch its run's job | none. The mint trigger makes it and the events trigger moves it |
| `box_sticker_events` | whoever may touch a box the row names | insert in the caller's own name, by whoever may touch every box the row names |
| `job_container_names` | whoever may touch the box's job | none. The trigger writes it |

`sticker_by_code` and `box_sticker_facts` are granted to `authenticated` and `service_role`, never `anon`: signed out, `box-read` answers less. The four fences close the migration, so a training account, a digital twin and an archived account are held on all four tables.

## Locks

Four new tables and one sequence. The foreign keys take a brief lock on `jobs_ledger`, `users` and `job_containers`, and the two triggers on `job_containers` one more on that table. No row of an existing table is read or changed. `SET lock_timeout = '3s'` makes a busy moment fail fast.

## Checked before the push

Applied three times to a throwaway local Postgres 15 with stub tables, and walked through 117 checks and two races between two real sessions (`docs/recent-features/v2.7072.md`, *Checked on a database*). The stub is not the app's schema and 15 is not 17, so the dry run at the push still matters.

## Release order

The client calls `sticker_by_code`, so push right after the merge: `supabase db push` from `main` after a dry run, then `supabase functions deploy box-read`. A label opens its box in between, since the resolver never lets the sticker read stand in a label's way.

## Verify

Read-only on prod after the push:

- `select count(*) from information_schema.tables where table_name in ('sticker_runs','box_stickers','box_sticker_events','job_container_names')` reads `4`.
- `select count(*) from box_stickers` reads `0`, and `select last_value, is_called from box_sticker_number_seq` reads `1, false`.
- `select tgname from pg_trigger where tgrelid = 'public.job_containers'::regclass and tgname in ('job_containers_code_free','job_containers_keep_names')` lists two.
- `select count(*) from pg_policy where polrelid = 'public.box_stickers'::regclass` reads `8`: the one select policy and the seven the fences add.
- A label printed before this still opens its box at `/b/<code>`, signed in and signed out.
