# 20260908030946_esign_consents.sql (2026-09-08, v2.3118)

The electronic-signature consent ledger ([`docs/recent-features/v2.3118.md`](../recent-features/v2.3118.md)).

- **`public.esign_consents`** — one row per signature made on a public signing page: `record_type` (`estimate` · `job_contract` · `person_contract_document` · `step_commitment` · `bid_proposal_room`) + `record_id`, `consent_version` (≥ 1), `lang` (`en` / `es`), `audience` (`customer` / `sub` / `gc`), `document_noun`, `clause_text` (the consent line, the two "How electronic signing works" paragraphs, the disclosure link and the checkbox label, verbatim as rendered; ≤ 4000 chars), `printed_name`, `method` (`type` / `draw` / `in_person`), `consented_at`, `ip`, `user_agent`. Index on `(record_type, record_id, consented_at DESC)`.
- **RLS**: SELECT for `is_master_or_dev() OR is_office_or_estimator()`. No client write policy — the signing Edge Functions insert with the service role (`_shared/esignConsent.ts`). Ends with both read-only fence appliers.
- Statutes the row evidences: 15 U.S.C. § 7001 (ESIGN); Tex. Bus. & Com. Code ch. 322 (Texas UETA).

Apply order: **push first, then deploy the five signing functions** (`accept-estimate`, `accept-contract`, `sign-job-contract`, `sign-bid-room`, `submit-sub-portal`) — their insert is best-effort and logs on a missing table, so nothing breaks either way, but rows only accrue once both are live. The client can go out in any order (a function without the field ignores it). Then `npm run gen-types:linked`.
