# 20261002050000_ar_close_out_books_label.sql (2026-10-02, v2.4363)

Close out books it: a deposit closed out in Accounts Receivable leaves with its Banking label settled in the same press.

- **`mercury_transaction_ar_close_labels`** (new, RLS on, SELECT for the AR roles — office staff + primary; no client writes) — one row per deposit whose label a close-out set: `label_id`, `previous_label_id` (what it replaced), `source` (`rule` = the close-out approved the rule's own waiting match; `close_out` = the label the person chose), `suggestion_id`, `labelled_at`, `labelled_by`. Ends with `apply_read_only_write_blocks()` + `apply_read_only_stmt_blocks()`.
- **`ar_deposit_booking(p_mercury_transaction_id)`** (SECURITY DEFINER, STABLE, AR roles) — jsonb: `label` + `label_by` (`rule` when an approved suggestion's final label is the rule's own and still on the deposit; `close_out`; `ar_income`; else `person`) + `label_at` + `rule_name`; `pending` (the newest pending suggestion of an enabled rule); `usual` (the label most of the payee's own payments carry — same `lower(btrim(counterparty_name))`, money out, not failed, not a duplicate); `last_close_out` (the payee's last other deposit that was closed out); `labels` (the label list for the picker — primary cannot read Banking's tables).
- **`close_out_ar_deposit(p_mercury_transaction_id, p_reason, p_note, p_label_id)`** (SECURITY DEFINER, AR roles via the call it makes) — closes through `set_mercury_transaction_ar_closed` (every check stays there), then books: `kept` when the label is already on it; `approved` when nothing labels it and the label is the waiting rule match's (assignment, the rule's person attribution with hand-set-wins, suggestion `approved` with `resolved_by` = the closer — what Approve writes); `set` otherwise (assignment upsert; a waiting match is resolved `approved` with the chosen `final_label_id`). A missing label raises, so the close-out rolls back with it. Returns the close-out's jsonb plus `booked` and `label_name`.
- **`set_mercury_transaction_ar_closed`** — same signature and checks; the Reopen branch calls the internal **`_ar_close_label_undo`** first: a `close_out` label still on the deposit goes back to `previous_label_id` (or off), and a match it answered with another label waits again; a `rule` source, or a label changed since, stays. Returns `label_undone` (`restored` · `removed` · `left` · null).

Rehearsed on prod in `BEGIN … ROLLBACK` (the paths are listed in `docs/recent-features/v2.4363.md`).

Apply order: merge → `supabase db push`. Before the push the client's read fails and the strip closes out the old way, Banking untouched.
