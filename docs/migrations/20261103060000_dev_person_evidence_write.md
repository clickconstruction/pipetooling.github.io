# 20261103060000 — dev_person_evidence_write (the dev seat keeps a piece of evidence)

The dev MCP's dry-run wrapper for a piece of evidence on a person's HR file: `plan_person_evidence` → `apply_person_evidence` in `dev-mcp`. One `SECURITY DEFINER` function, `dev_person_evidence_write(p jsonb, p_dry_run boolean DEFAULT true, p_files jsonb DEFAULT NULL)`, gated `auth.uid()` + `is_dev()`, closed to `anon`, modeled on `dev_legal_document_write` (`20261028010000`) and the HR door `dev_hr_entry_write` (`20260922102017`).

- `p` carries the record's words and the files' facts: `person_id` (a `people.id`), `dated_on` (the day it is about, never ahead of `app_today()`), `title` (under 160), `memo` (what it shows, under 4,000), `entry_id?` (an entry on the same person's file, which the record then proves) and `files` (one to twenty, each `name`, `mime`, `size_bytes` from 1 byte to 10 MB, `sha256` — the plan hash commits to the digests). The same rules as the panel's `evidenceDraftProblem` (`_shared/personEvidence.ts`), refused in words.
- The dry run returns the person, `author_label` (the dev's name, whatever the payload says), the record as it would be written (`after`, with its files), the count and bytes, `where` it lands in Drive (*People › the person › the day · the title*), how many records the person holds (`evidence_on_person`, so one kept since the plan changes the hash), whether the People folder is set, and `then`.
- The write needs `p_files = { evidence_id, files: [{ id, storage_path }] }` aligned with `p.files`: the edge function stores each file in the `hr-files` bucket first under `<person>/evidence/<evidence_id>/<id>-<name>` (`evidenceStoragePath`), and the function refuses the rows unless every object is there under the record's folder. It then inserts the `person_file_evidence` row with that id and one `person_file_attachments` row per file, both as the caller with `author_label` the dev's name — the rows `personEvidenceIo.ts`'s `savePersonEvidence` writes. No update or delete: a correction is a new record.
- Drive is the function's leg after the rows (`hr-evidence-drive`, fail-soft); the wrapper never reaches Drive.
- No table is created, so no read-only fence is owed; training mode is blocked by the HR tables' statement triggers.
