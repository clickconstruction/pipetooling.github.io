# 20261004145511_job_pay_applications.sql (2026-10-04, v2.4490)

`job_pay_applications` — pay applications the job remembers: one row per `(job_id, application_number)` (unique, number 1–9999) holding the AIA G702-G703 window's form as it was typed (`fields`, a jsonb object keyed by the window's field keys) and the sheet's totals over it (`contract_sum_to_date`, `total_completed_and_stored`, `retainage_pct` 0–100, `retainage_held`, `total_earned_less_retainage`, `current_payment_due`), with `period_to` / `application_date` when the form's text reads as a date. The next application starts from the last: its work becomes *from previous application*, its `total_earned_less_retainage` becomes *less previous certificates*. `source` (`window` | `file`) and `files` (a jsonb array, empty) are there for the files step: adding an application already sent, from its file. `created_by` / `created_at` / `updated_by` / `updated_at` are set by a BEFORE INSERT OR UPDATE trigger (`job_pay_applications_stamp`, `search_path = ''`, EXECUTE revoked from PUBLIC, anon and authenticated) from `auth.uid()` / `now()`; an update keeps the first author.

Nothing locks (the owner, 2026-10-04: "no lock"): the office updates and deletes a saved application.

RLS: select / insert / update / delete for the office set that bills jobs — `is_dev() OR is_assistant() OR role = 'master_technician'`, the rule `job_supply_house_words` uses. Ends with `apply_read_only_write_blocks()`, `apply_read_only_stmt_blocks()` and `apply_digital_twin_write_blocks()`.

Apply order: **client first**. `loadPayApplications` treats a failed read as no applications, so the window opens as it did until the push; a Save before the push fails with a toast and Generate still downloads. Push once the v2.4490 deploy is live, then regenerate `src/types/database.ts` (`aiaPayApplicationsIo.ts` casts `'job_pay_applications' as never` until then).

Test: `npm run test:pg:pay-applications` builds a throwaway copy of the whole schema and runs `supabase/tests/pay_applications/20_scenario.sql` through RLS — the office saves, the stamp ignores what the client sent, a number is used once per job, a bad number / form / percent is refused, the master changes a saved one and the first author stays, the controller reads, a subcontractor and anon read nothing, a read-only account is refused, the office deletes, a deleted job takes its applications.
