# 20261112060000_first_looks.sql (2026-11-11, v2.6981)

The ground under the First look spike (punch list #319, `to-dos/show-us-the-problem/README.md`): a caller is sent a link and adds photos and a short video of the problem on a page with no sign-in. Two tables and one private bucket. No function, no trigger, no cron.

## What it does

1. **`first_looks`**: one row an ask. `contact_id` (a Messages contact, or null for a test), `label`, `asked_by` and `asked_by_name`, **`code_hash`** (the SHA-256 of the link's ten-letter code, unique, shape-checked; the code itself is handed out once and never kept, as an estimate's share link is), `made_at`, `expires_at`, and the stamps the owner will later count from: `opened_at`, `sent_at` with `sent_count`, `looked_at` with `looked_by`, `closed_at` with `closed_by`. `place` and `words` are the page's two optional fields.
2. **`first_look_files`**: one row a file the page was handed an upload address for. `kind` (photo or video), `mime`, `name`, `storage_path` (unique), `declared_bytes`, and what the spike measures: `bytes` as the bucket has them, `seconds` for a video, `road` (pieces or whole), `resumed`, `took_ms`, `client` (the phone and browser in two words). `signed_at`, `finished_at`, `removed_at`. Rows go with their look (`ON DELETE CASCADE`).
3. **The bucket `first-look-files`**: private, 52,428,800 bytes a file (the live project's own limit, read 2026-11-11), pictures and video only (`image/jpeg`, `image/png`, `image/webp`, `image/heic`, `image/heif`, `video/mp4`, `video/quicktime`, `video/webm`, `video/3gpp`). Objects are `<look id>/<file id>.<ext>`.

## Who may do what

- **Read**: the office team (`gc_office_team()`), on both tables. They are the people who read a customer's thread, and PR 1 of the card draws a look there.
- **Write**: nobody from the app. There is no INSERT, UPDATE or DELETE policy on either table for any of the nine roles, and `authenticated` is granted SELECT alone. Every write is the `first-look` function's, as the service role, after it has checked the link's code or that the caller is the owner or a developer.
- **Signed out**: no grant on either table.
- **The bucket**: no policy on `storage.objects` names it, so nobody reads or writes it directly. The function signs a one-file upload address for the page and a one-hour link for the desk.
- The four fence appliers run at the end, as for every CREATE TABLE.

## Release order

Merge, `bash scripts/db-push.sh`, then `supabase functions deploy first-look`. The client calls only the function. A function ahead of the push answers its 500 words on every ask; a push ahead of the function leaves two empty tables.

## Verify

Read-only on prod after the push: both tables exist with RLS on (`select relrowsecurity from pg_class where relname in ('first_looks','first_look_files')` reads true twice); `select file_size_limit, public from storage.buckets where id = 'first-look-files'` reads 52428800 and false; `select has_table_privilege('anon', 'public.first_looks', 'select')` reads false.
