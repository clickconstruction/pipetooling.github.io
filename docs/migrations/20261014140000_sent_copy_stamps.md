## What it does

**`sent_copy_stamps(p_ids uuid[])`** answers one row for each copy among `p_ids`: `id`, `from_email`, `opened_at`,
`paid_on`, `paid_how`.

- `from_email` is `email_send_log.from_email`, joined by the copy's `resend_email_id`, which is unique on the log.
- `opened_at` is the log's `last_event_at` while `last_event` is `opened` or `clicked`. Resend's webhook keeps only the
  last event, so a later event overwrites the open. Null means not known, never unopened, and the small print then says
  nothing.
- `paid_on` and `paid_how` come only for a copy of a `jobs_ledger_invoices` row whose `status` is `paid`. They are the
  newest payment's day and its `payment_type` as the row has it. A payment with no `paid_on` counts on the day it was
  entered, in Chicago. Wording the payment type ("card", "check") is the client's.
- A copy with none of the three still comes back with nulls, so the client never wonders whether it asked.
- Only a reader of `sent_documents` gets rows: `is_office_staff()`, the table's SELECT policy (the dev, the owner, the
  assistants and the controller). Anyone else, an estimator included, reads no rows.
- It is `SECURITY DEFINER` with `SET search_path = public`, since the log is a dev's read under its own policies (plus
  the office's RFQ and GC statement rows). The office could not read an estimate's or a bill's open before this.
- `REVOKE ALL … FROM PUBLIC, anon` and `GRANT EXECUTE … TO authenticated, service_role`.

No table, so no house calls. No `CREATE TABLE`, so no fences. It starts `SET lock_timeout = '3s'`.

## Checked before the push

The SQL bed `sent-copy-stamps` (`npm run test:pg:sent-copy-stamps`) runs every migration on Supabase Postgres 17, then
this one a second time, which must change nothing, then the scenario. Docker does not run on the office Mac, so it runs
in the SQL beds workflow once the PR is ready.

- The office reads a paid bill's copy as opened at 23:12 UTC, from office@, paid Oct 11 by card. That's the newest of
  its two payments, not the first.
- An estimate's copy only delivered reads its from, with no open and no paid.
- An unpaid bill's copy that was clicked reads as opened, and says nothing of paying.
- A printed page with no email and no log still comes back, all nulls.
- A paid bill whose payment has no paid day reads the Chicago day it was entered (03:30 UTC on Oct 12 is Oct 11).
- Only the copies asked for come back, none for an id no copy has, and nothing for an empty ask.
- An estimator reads no rows.
- Anon cannot run it, the office can, and it reads as its definer.
