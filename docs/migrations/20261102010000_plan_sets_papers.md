Papers on a part, the ground (punch list #239, the papers train, PR A). The owner, 2026-11-01, on the documents that travel with a set of plans: *I feel like each one needs either an action item or an event description. They all seem important to save to a job.* The spike's answer, walked on the dev server the same evening: a paper is a document on a part, kept in the same register as the sets (`plan_sets`, v2.6297), beside the set it goes with; it carries the question it raised and an *owed* state for a paper that has not come; keeping one writes the History line.

## What it does

- **Kinds**: `plan_sets_kind_known` widens to the paper kinds `spec`, `submittal`, `schedule`, `scope`, `change_order`, `meeting_notes`, `task_list`, `report`, `sheet`, `other` beside the eight drawing kinds. `plan_set_is_drawing(kind)` says which group a kind is in.
- **Sources**: `engineer` and `supplier` join `gc`, `architect`, `ours`.
- **Goes with**: `marks_up_set_id` is the set a paper travels with, as it is the set an as-built marks up; its comment says so. No new column.
- **The ask**: `ask_lane` (`estimators` · `dispatch`) and `ask_request_id` (the question's id in its lane's table; no FK, since there are two tables), both set or both null (`plan_sets_ask_pair`). The row reads the answer back from the question.
- **Owed**: `owed boolean`, true for a paper we are waiting on; the ask says who owes it.
- **Only a drawing builds**: the trigger `plan_parts_current_is_drawing` refuses a part's `current_set_id` that points at a paper.
- **The History line**: `plan_sets_paper_history`, `AFTER INSERT`, writes one `development_history_entries` row for a paper (never a drawing) on the part's development, or the job's development when the part is the job's own; `happened_at` is the day it came, the author is who kept it, `link_url` the file when there is one, `job_id` the job it was kept on. `plan_set_paper_words` builds the line: *Kept task list Nate's task list, the owner, on Bunker addendum 1: doors already bought…* or *Owed: Soil report from the owner · …*. A part owned by a job outside any development has no site to write on, so no line; the job's own Plans section still shows the paper. `SECURITY DEFINER`, since the entries table lets only the office keep lines through the app.
- **RLS**: a crew member on the job may keep a paper on the job's own part, as they may an as-built; the office writes as before.
