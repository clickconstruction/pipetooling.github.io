# 20261001230000_ar_returned_check_cases.sql (2026-10-01, v2.4320)

A check that came back is a case, and it opens itself (punch list #76 PR 2). Before this, the office heard about a returned check only from `mercury-webhook`, and only while a recorded payment still carried it — `mercury_bank_return_notices` held zero rows on 2026-10-01.

- **`mercury_bank_return_reason(status, posted_at, amount, kind, reason)`** — IMMUTABLE; the bank's reason (`''` when none) for a deposit that came back, else NULL: money in that posted and then failed, or a `checkDeposit` that failed before posting with a bank's return reason (eleven phrases — *insufficient funds*, *stop payment*, *refer to maker*, …; Mercury's own *There was an issue with this transaction* is not one). Twin of `mercuryBankReturn()` in `_shared/bankReturnedDeposits.ts`; `bankReturnedDeposits.test.ts` reads this file to keep the phrase lists equal. Helpers `_ar_try_timestamptz` (never raises) and `_ar_payer_key` (first five letters).
- **`mercury_transaction_ar_returned`** — `ADD COLUMN IF NOT EXISTS` `source` (bank · hand · rejected), `bank_reason`, `opened_at` (default now), `closed_at`, `closed_by`, `closed_reason` (replaced · settled_other_way · not_coming), `closed_note`, `replaced_by_mercury_transaction_id`; three CHECKs (closed_at and closed_reason together). Existing rows get a source and an opened date.
- **Trigger `mercury_transactions_open_return_case`** — `AFTER INSERT OR UPDATE OF status, posted_at, raw` on `mercury_transactions`: a bank return upserts its case (returned, source bank, the reason, opened at Mercury's `failedAt`). Any writer counts: the webhook, the Banking page's Sync, a backfill. Wrapped so it can never fail a bank sync.
- **Backfill** — every return Mercury already holds becomes a case. A past return with no job still carrying it and a later deposit from the same payer for the same amount within 60 days closes as *replaced* (rehearsal: Dudley, M&M Roofing, Poolcorp twice). Cases older than two days get a notice-ledger row, so the first run tells the office only about today's (Loberg).
- **`open_ar_rejected_check_cases()`** — service role only; returns `{opened, replaced}`. Opens a *rejected* case for a check deposit that failed without posting and without a bank reason, refused 5–90 days ago, when an unlinked payment for the same amount was recorded between 3 days before and 10 days after, and no same-payer deposit for the amount followed within 30 days. Closes a rejected case once that deposit arrives.
- **`list_ar_return_cases(p_include_closed default false)`** — the cases with the deposit, the reason, source and close, `notified_at`, `live_payments` (the payments still carrying it, with the bill's number, status, amount and Stripe flags and each job's status, revenue and paid), `last_job` (the newest removal in `deleted_records_archive`) `recorded_payment` (a hand-recorded payment it matches when no job ever carried it — Peter Garza's $2,700 on #120) and `promise` (the newest unvoided *They said…* on any job it touched, made after it came back). AR roles and the service role; revoked from `anon`.
- **`set_mercury_transaction_ar_returned`** — a hand mark writes `source` hand (bank when Mercury says so) and `opened_at`; unticking a bank return raises *The bank returned this check, so it stays returned* (it used to delete the row).
- **pg_cron `ar-returned-checks-hourly`** (`17 * * * *`) → `functions/v1/ar-returned-checks` with `X-Cron-Secret`, vault `PROJECT_URL` / `CRON_SECRET` (the `stripe-invoice-links-nightly` pattern).
