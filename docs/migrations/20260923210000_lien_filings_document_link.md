# 20260923210000_lien_filings_document_link.sql (2026-09-23, v2.3763)

Punch list #35, PR 1: five additive columns on `job_lien_filings`, all with defaults — `document_url` and `document_note` (a link to the saved copy of the paper and a line beside it, plain text, on every filing kind), and the three the rest of the stream reads: `packet_id` (the filings one paper covered share it — a by-hand record across jobs at one property, or a combined notice the run printed), `by_hand` (recorded after the fact, outside the run) and `printed_claim` (the paper's total when it differs from the job's amount). A partial index on `packet_id`. No new table, so the read-only sweeps are not re-run; no RLS change (the office policies are row-level). The client sends the new keys only when they carry a value, so a client deployed before this push still records; a link typed in that window fails to save until the push lands. Push with `supabase db push` after merge, then regenerate `src/types/database.ts` and the dev-mcp catalog.
