# 20260919014218_fold_labor_books_into_robot.sql (2026-09-18, v2.3596)

Labor refresh PR 6a — one book ([`docs/recent-features/v2.3596.md`](../recent-features/v2.3596.md)).

- **`labor_book_versions`** gains `archived_at` (a folded human book — hidden from pickers, kept for a rollback) and `proposed_multiplier · proposed_by · proposed_at · proposed_note` (an estimator's calibration proposal, applied or cleared by a leader in PR 6b).
- **`labor_book_entries`** gains `origin` (`robot` · `human`, CHECK), `robot_rough_in_hrs / robot_top_out_hrs / robot_trim_set_hrs` (the robot's own numbers, kept under a human override), `set_by` (FK users, SET NULL), `set_at`, `set_note`. Existing robot-book entries are stamped `origin = 'robot'` with `robot_* = hrs`.
- **The fold** (a `DO` block, idempotent — a second run finds nothing): every non-robot book with entries folds into the oldest robot book of its trade. Same fixture, same hours → the human aliases merge onto the robot entry; same fixture, different hours → the robot's numbers stand (the owner's pick, 2026-09-18), the aliases merge, `set_note` records the human split; a fixture the robot book lacks → inserted as `origin = 'human'`, `set_note = 'from <book>'`. Bids on the human book re-point to the robot book; the human book is archived. Empty human books with no bid on them are deleted. A `RAISE NOTICE` per conflict and one report line (`fold report: 2 book(s) folded · 3 same · 3 conflict · 12 added · 2 empty book(s) deleted` on prod).
- **Trigger `labor_book_entries_provenance`** (BEFORE INSERT OR UPDATE, SECURITY DEFINER): a twin's insert is `origin = 'robot'` with `robot_* = hrs`; a twin's update refreshes `robot_*` and, when a person has set the hours (`set_by` not null), leaves the visible hours alone; a person's hour change stamps `set_by = auth.uid()` / `set_at = now()` unless it restores the robot's numbers exactly, which clears the stamp (Reset to robot). The fold runs before the trigger exists, so its rows carry only the `set_note` / `set_at` it wrote.
- `apply_digital_twin_write_blocks()` re-run (no change in what twins may write; the trigger now decides what of it shows).

No new tables. Additive and idempotent. Apply order: merge → `supabase db push` → `npm run gen-types:linked` (the 6b client reads the new columns). The 6a client is unchanged: the picker still lists the archived books until 6b removes the picker.
