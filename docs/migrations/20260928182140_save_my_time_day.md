# 20260928182140_save_my_time_day.sql (2026-09-28, v2.4063)

One function, `public.save_my_time_day(p_subject_user_id uuid, p_work_date date, p_leader boolean, p_writes jsonb) RETURNS void` — the My Time day editor's Save as one transaction (punch list **#46** row 10; the MY_TIME_DAY_EDITOR_MODAL map, quirk 26). Additive: nothing calls it until the client that follows.

## Why

The editor's save (`src/lib/myTimeDayPersist.ts`) works out every write for a day and sent them one request at a time — direct `INSERT`s and `UPDATE`s on `clock_sessions` and the six `own_*` / `leader_*` split / replace RPCs. A refusal part-way left the rows before it rewritten and the rest unsent. This function takes the whole list; PostgREST runs the call in one transaction, so any error rolls every write back.

## What it does

`p_writes` is a JSON array, applied in order:

| `op` | Fields | Does |
|---|---|---|
| `insert` | `clocked_in_at`, `clocked_out_at`, `notes`, `job_ledger_id`, `bid_id` | `INSERT` with `user_id = p_subject_user_id`, `work_date = p_work_date` |
| `update_notes` | `id`, `notes` | `UPDATE … SET notes` |
| `update_times` | `id`, `clocked_in_at`, `clocked_out_at`, `notes`; optional `work_date`, `job_ledger_id`, `bid_id` | `UPDATE` times and notes; the optional columns only when the key is present |
| `split_segments` | `id`, `segments` | `split_own_clock_session_segments` or `leader_…` |
| `split_cluster` | `ids`, `segments` | `split_own_clock_session_cluster` or `leader_…` |
| `replace_mixed` | `ids`, `segments` | `replace_own_clock_session_cluster_mixed` or `leader_…` |

`p_leader` picks the `leader_*` family (true) or `own_*` (false), as the client's `myTimeDayPersistRpcs` does. An RPC answering with an `error_message` is raised, so it undoes everything before it. An update whose row is missing, belongs to another person, or is hidden by RLS (0 rows changed) is raised too. After an in-place `update_times` of an approved row, `recompute_people_hours_after_session_edit` runs once for the day (v2.4061's rule).

## Permissions — unchanged on purpose

`SECURITY INVOKER`: the direct writes run under the caller's own RLS on `clock_sessions`, exactly as the browser's requests did, and the RPCs keep their own checks and week fences. Granted to `authenticated`; revoked from `anon` and `PUBLIC`.

**No week fence was added to the direct writes**, although the design proposed one. The proposed current-week fence on one's own day would break prior-week edits the editor supports after its acknowledgment step; a this-or-last-week fence could refuse Draft Payroll day edits by roles `pay_access_clock_week_fence_bypass()` does not cover. Both need an owner call; this function keeps today's rules.

## Tried before the push

`supabase/tests/my_time_day_save/` — a stand-in schema (`clock_sessions` with its production RLS policies verbatim, `people_hours`, the role helpers as settings, the real `recompute_people_hours_after_session_edit`, and recording stand-ins for the six RPCs) and one scenario, run against a throwaway Postgres 15:

```bash
psql -v ON_ERROR_STOP=1 -f supabase/tests/my_time_day_save/00_schema.sql
psql -v ON_ERROR_STOP=1 -d bed -f supabase/migrations/20260928182140_save_my_time_day.sql
psql -v ON_ERROR_STOP=1 -d bed -f supabase/tests/my_time_day_save/20_scenario.sql
```

The migration ran twice (idempotent). The scenario ends `save_my_time_day PASSED`: notes only leave approval and payroll hours alone; an approved row's times resync the day to 1 + 2 h; a pending row's do not; insert with its job, and `update_times` writing the optional columns only when sent; a missing row undoes the write before it; an RPC's `error_message` undoes a times update and the RPC's own write; the own and leader families called in order with their ids and segments; one's own save cannot reach another person's row, nor can naming that person (RLS hides it), nor insert for them; a lead updates a member's row but — as today — cannot insert one; pay access inserts; two approved rows moved resync once to 2.5 + 1.5 h; an unknown write, a non-array, a missing family, no signed-in user and `anon` are refused.

The first run failed in the scenario, not the function: `rpc_log.n` is a sequence, and the rolled-back call in step 6 spent a number. The scenario reads by order.

The real split / replace RPCs are not in the bed — they are stood in by recorders. What the bed proves is the wrapper: order, family, arguments, rollback and the resync.
