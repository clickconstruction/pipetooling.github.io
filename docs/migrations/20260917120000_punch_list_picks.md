# 20260917120000_punch_list_picks.sql (2026-09-17, v2.3559)

`punch_list_picks` — the shared Do / Later / Drop pick and note per to-do slug on the app's `/punch-list` board (v2.3558 moved the board into the app; this moves the picks off the device). One row per slug (`slug` PK; the to-do's file name, as `src/content/punchList.generated.ts` carries it), `pick IN ('', 'do', 'later', 'drop')`, `note`, and `updated_by` / `updated_at` set by a BEFORE trigger (`punch_list_picks_stamp`) from `auth.uid()` / `now()` whatever the client sends. A cleared pick is `''`, never a delete, so the note and the name stay with the row.

RLS: select / insert / update for `is_master_or_dev()` — the same pair `canOpenPunchList` admits to the page. No delete policy. Ends with `apply_read_only_write_blocks()`, `apply_read_only_stmt_blocks()` and `apply_digital_twin_write_blocks()`.

Apply order: **client first**. The page (`usePunchListPicks`) selects the table on mount; a 42P01 / PGRST205 leaves the picks device-local and the page says "until the database catches up with this deploy". Push once the v2.3559 deploy is live, then regenerate `src/types/database.ts` (the hook casts `'punch_list_picks' as never` until then).
