Burn against the bid, PR 1 (`to-dos/burn-against-the-bid/`). Additive, idempotent.

- **`job_budgets`** — one row per job (`job_id` PK → `jobs_ledger`): `kind` `bid` | `typed`; `bid_id`, `bid_version_id`; `labor_hours`, `labor_rate`, `labor_usd`, `materials_usd`, `subs_usd`, `other_usd` (equipment + permits + waste + other + driving + travel), `total_direct_usd`; `completeness` jsonb (`rows_total`, `rows_with_hours`, `rate_set`, `materials_source` po | takeoff | typed | none, `usable`); `taken_at`, `taken_by`, `note`. RLS: reads mirror the job (a subquery on `jobs_ledger` under the caller's RLS); writes = `can_write_job_budget(job_id)` (dev · assistant-like · master technician, on a job they can read). Both read-only training-mode blocks re-applied.
- **`bid_estimate_breakdown(p_bid_id)`** → jsonb — the single-bid form of `bid_pricing_history`'s math with the v2.3291 row rules (task · sub · per 100 ft) and the v2.3294 total (estimator time and team labor are not cost): hours by stage, labor at `labor_rate`, materials (stage POs, else the base takeoff's rough lines × counts), the five direct-cost tables, driving, travel, and the completeness report. SECURITY INVOKER.
- **`snapshot_job_budget_from_bid(p_job_id, p_bid_id)`** → jsonb — sets `jobs_ledger.bid_id` when unset (a different existing link raises), then upserts the breakdown as `kind = 'bid'` stamped `taken_at` / `taken_by`; the same call refreshes. SECURITY INVOKER, so the caller's `jobs_ledger` UPDATE policy decides who may link; the existing `jobs_ledger_bid_outcome_from_job` trigger marks the bid `started_or_complete`.

- **`suggest_bids_for_job(p_job_id)`** → up to three candidates: rank 1 a bid value / agreed value equal to the job's price (± $1) · 2 same GC customer and won · 3 same address prefix; with `has_estimate`, `estimate_hours`, `linked_jobs`. Nothing auto-links.
