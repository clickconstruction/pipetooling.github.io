# 20261030210000_dev_bid_write.sql (2026-10-30, v2.6183)

The dev seat's bid verbs, PR 1 of the "set a bid up for the robots from a dev's agent" train (the owner, 2026-10-30, after the Gun Dog intake). Before it, no verb made a bid row: an agent with a dev key could read every bid and write none, and the New Bid form was the only door.

## What it does

**`dev_bid_write(p jsonb, p_dry_run boolean, p_link jsonb)`**: `SECURITY DEFINER`, devs only (`is_dev()`), the dry-run wrapper the dev seat's `plan_bid` / `apply_bid` POST — and, in PR 2, `plan_file_plans` / `apply_file_plans`. `p.action` picks the write:

- **`create`** — the row the New Bid form makes: `project_name` (required, under 120 characters: it is the plans folder's name too), `customer_id` (must exist), `service_type_id` (must exist; its name gives the division — *plumb* → plumbing, *electric* → electrical, *hvac / heat / air* → HVAC — or none), `address?`, `development_id?` (must exist), `distance_from_office?` (the text column as the form holds it), `bid_due_date?` / `bid_due_time?`, `estimator_id?` (an active user; the caller when left out), `notes?`, `robot_opt_out?` (false). Live bids already wearing the name (unsent, undecided, not archived off the working board, case-insensitive) are listed, and the plan is refused unless `allow_duplicate_name`. The dry run replies `after` — the bid as it will read, its division, its `plans_folder_name`, and `readiness` (what the line still needs) — and writes nothing. The real run inserts as the caller (`created_by`, `estimator_id` defaulting to the caller) and the existing trigger `set_bid_number_if_empty` numbers it; the reply carries `bid_id` and `bid_number`.
- **`file_plans`** — PR 2's half, shipped in the same function so one push serves the train: `bid_id` (a live bid in a division with a folder), `file_name` (a `.pdf`, under 140 characters), `size_bytes` (1 to 50 MB, CountTooling's cap), `sha256`, `replace?` (a bid that already has a plans link is refused unless true), `set_name?`, `memo?`. The dry run replies with the bid, its division, its folder name, the plans link before and how many sets it holds. The real run needs `p_link = { folder_link, file_link, pages }` (the Drive leg the function does first): it sets `bids.plans_link` to the folder link and inserts a `bid_plan_sets` row named for the set, with the file's name and size, one file, checked now.

Both replies hash into the plan the agent must quote; apply re-runs the dry run first (`devMcpWrites.ts`).
