# 20261019030000_customer_sends_to_activity.sql (2026-10-19, v2.5636)

Four customer sends become lines in the job's trail. Before it, `job_activity_events` had no line for a contract reminder (`remind-job-contracts` logs `reminded` in `job_contract_events`, and the `job_contracts` bridge of 20261008080000 logs sends, views, signing and voids only), a demand letter (`job_demand_letters`), a lien or retainage notice (`job_lien_filings`), or a paper bill emailed again (`send-physical-invoice-email`'s resend writes nothing on the bill; its one record is its sent copy, `sent_documents` kind `bill_resent`).

The migration adds two helpers (`job_activity_send_at(text, timestamptz)`: a recorded send day as a time, the saved time when it is that day in Chicago, else noon that day, a day that is not a date reading as the saved time; `job_activity_send_words(text)`: certified mail, courier, email, hand), one line function per source (`job_activity_line_contract_reminder`, `_demand_letter`, `_lien_notice`, `_bill_resent`, each taking the source row and inserting one event guarded by `(event_type, detail.source_id)`), and four AFTER INSERT triggers that call them: `job_contract_events_to_activity_ins` (WHEN `event_type = 'reminded'`; a `dry_run` row writes none), `job_demand_letters_to_activity_ins`, `job_lien_filings_to_activity_ins` (WHEN `kind` is `notice_53_056` or `retainage_53_057`) and `sent_documents_to_activity_ins` (WHEN `kind = 'bill_resent'`; a copy whose bill is gone writes none). Event types `contract_reminded`, `demand_letter_sent`, `lien_notice_sent` and `invoice_resent`, all financial; actors are the cron's (none), the recorder (`created_by`) and the sender (`sent_by`). Each trigger catches its function's error as a warning, so the record is kept when its line cannot be written. All ten functions are revoked from `PUBLIC`, `anon` and `authenticated`.

The backfill at the end runs the same functions over every recorded send, voided letters and notices excepted; a second run changes nothing. No table, so no RLS fences; `SET lock_timeout = '3s'`, and each `CREATE TRIGGER` takes a brief share-row-exclusive lock on its table. Apply with `supabase db push` after the merge, client first (an old client hides an unknown type). Proven by the bed `scripts/pgtest-customer-sends-trail.sh`.
