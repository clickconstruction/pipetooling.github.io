# 20261031190000 — dev_legal_statement_write (v2.6244)

The dev MCP's dry-run wrapper for a sworn statement or an unsworn declaration on a legal matter: `plan_matter_statement` → `apply_matter_statement` in `dev-mcp`, punch list #220's robot path. One `SECURITY DEFINER` function, `dev_legal_statement_write(p jsonb, p_dry_run boolean DEFAULT true)`, gated `auth.uid()` + `is_dev()`, closed to `anon`, modeled on `dev_legal_plan_write` (`20261023195135`), over the desk's own `legal_statement_add` / `legal_statement_update` (`20261031040000`, v2.6209). A robot drafts; the office prints, signs and files — the wrapper never reaches `legal_statement_print` or `legal_statement_sign`.

- `p` is `{ action: add | update (add when left out), … }`. **add**: `matter_id` (a `legal_matters.id`), `on` (YYYY-MM-DD, the day it is about), `title` (under 200 characters), `body` (the paragraphs, under 20,000), `affiant` (`{ kind: team | witness, user_id?, name, role }` — `user_id` must be a `users.id` when given, and only for one of our team), `form?` (`notary` | `declaration`; `notary` when left out), `incident_to?` (the span's last day), `venue_county?` (under 60; blank leaves the county to the office's setting at print time). **update**: `entry_id` (a `legal_matter_entries.id` of kind `statement`), then any of `on`, `title`, `body`, `affiant` (replaced whole), `form`, `incident_to` (JSON `null` clears the span) and `venue_county` (JSON `null` clears it); refused on a dropped statement and once the signed copy is filed (the sworn text is sworn). A printed draft may still be changed; the plan says so, and the office prints it again.
- The office RPCs' own checks run in the wrapper first (the affiant's shape through `legal_statement_affiant_problem`, the caps, the day never ahead of `app_today()`, the span in order and not past today), so the plan refuses in words instead of apply.
- The dry run returns the matter (`id`, `payer_name`, `stage`), the statement on record (`before`, on update: its day, title, body, affiant, form, span, county, state, print count, source and last edit) and the row as it would be written (`after`: the cleaned affiant, the form, the span, `state` with the Said lane's `state_words` — *Draft · not signed.* for a new one — and `source: mcp`), `statements_on_matter` (the matter's live statements, so one added or dropped since the plan changes the hash), a `then` line on what the office does next, and `firm_reads_it`. No timestamp or id is in `after`, so the hash is the payload and the world.
- The write goes through `legal_statement_add` (or `legal_statement_update` with the clear flags set from the resolved span and county) as the caller with `p_source = 'mcp'`; the Timeline's chip reads *<name> · team · dev MCP* for the office. The reply is `{ ok, action, matter_id, entry_id, state }`.
- No table is created, so no read-only fence is owed; training mode is blocked by the table's statement trigger.
