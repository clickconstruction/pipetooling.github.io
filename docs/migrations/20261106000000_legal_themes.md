# 20261106000000_legal_themes.sql (2026-11-05, v2.6545)

PR T1 of punch list #269. The catalog of **themes on the record** and the **marks** that hang a theme on something that already exists, so a pattern across a large record (what counsel calls a claim: *Dishonesty*, *Disrespectful conduct*, *Interference with the business*) can be named once in plain words and found again.

- `legal_themes`: `name` (one standing theme a name, whatever the case, `legal_themes_name_standing_key`; a retired name may be used again), `what_counts` (400), `counsel_words` (200), `created_by`, `retired_at` / `retired_by` (retired, never deleted, so old marks keep their meaning), `proposed_by_agent` and `kept_at` (the agent's proposal stands dashed until a dev keeps it).
- `legal_theme_marks`: `theme_id` (`ON DELETE RESTRICT`), `target_kind` (`hr_entry` · `hr_evidence` · `matter_document` · `matter_entry`) and `target_id`, `person_id` and `matter_id` (at least one), `why` (200), `proves_by` (`document` · `own_words` · `firsthand` · `relayed`), `marked_by` / `marked_at` / `author_label`, `proposed` with `kept_at` / `kept_by`, and `removed_at` / `removed_by` / `removed_why`. One live mark a theme a thing (`legal_theme_marks_live_key`). The trigger `legal_theme_marks_guard` holds a mark to what it was when made: only the kept and removed stamps change, and a removed mark stays removed.
- RLS: both tables are a dev's on read, insert and update (`is_dev()`), with no delete policy. `hr_agent` reads both and may insert a proposed row only (`proposed_by_agent` / `proposed` true, nothing kept or retired).
- The three fence calls, since both tables are new.
