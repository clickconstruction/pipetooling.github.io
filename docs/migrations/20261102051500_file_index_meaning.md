# 20261102051500_file_index_meaning.sql (2026-11-02, v2.6338)

Search every file deeply (punch list #240, PR 4): search by meaning.

- **`CREATE EXTENSION IF NOT EXISTS vector WITH SCHEMA extensions`** — pgvector (0.8.0 on prod, not installed before this).
- **`public.file_index_chunks`** — one row per chunk of an indexed file's text: `drive_file_id` (cascades from `file_index`), `chunk_no`, `text` (at most 8,000 characters), `embedding extensions.vector(768)`, `embedded_at`; primary key `(drive_file_id, chunk_no)`; an HNSW index with `vector_cosine_ops`. RLS: `file_index_chunks_select` for `authenticated` under `is_office_or_estimator()`; no write policy, since the index pass writes as the service role; `anon` revoked; the three fence calls close the file.
- **`file_index`** gains `embedded_at`, `embed_tried_at`, `embed_note` (the provider's reason, at most 1,000) and the partial index `file_index_embed_due_idx` on `(embed_tried_at NULLS FIRST) WHERE text IS NOT NULL AND (embedded_at IS NULL OR embedded_at < indexed_at)`, the embedding pass's queue.
- **`public.search_file_index_meaning(query_embedding extensions.vector(768), words text, max_hits integer DEFAULT 30, max_distance real DEFAULT 0.45)`** — SECURITY INVOKER, STABLE, `search_path = public, extensions`, `hnsw.ef_search = 200` (an HNSW scan answers at most that many rows, 40 by default, so the nearest two hundred need the knob raised on the function): the words' top sixty (`websearch_to_tsquery` + `ts_rank_cd`, as `search_file_index`), the nearest 200 chunks by cosine distance through the HNSW index cut to one per file within `max_distance` and ranked to sixty, fused by reciprocal rank (k = 60), the top `max_hits` (capped at 100) in a materialized CTE; each row carries `by` (`words`, `meaning`, `both`), the words' `ts_headline` when the words matched, the nearest chunk's `chunk_text` and its `distance`, and the job's and bid's numbers and names. Execute for `authenticated` and `service_role`.

The dimension (768) and the model (`gemini-embedding-001`) are fixed here: a change of provider or dimension is a new table. `max_distance` is the tunable: set it from live reads once the key is in (the first days' hits by meaning say where the noise starts).
