# 20261114100000_box_name_rule.sql (2026-11-14, v2.7276)

Materials on site, punch list #351 PR 1: a box's name is one to three letters and a number from 1 to 999, one letter after the number allowed (`R7`, `AB12`, `G24B`), one of a kind across the site (every job of the development, or the one job when the job is on no development). The owner's calls of 2026-11-14 are on the card, `to-dos/box-names-and-what-is-inside/README.md`. Numbered after `20261114070000` (PR #8123), whose `on_site_carry_job` body this file restates: merge that PR first.

## What it makes

No table, so no fence call is owed. Four new functions, one trigger, three functions restated whole.

- **`box_name_words(label)`** — null when the name holds to the rule, else why not in the words every screen says (*R76 TOILETS is not a name. A name is one to three letters and a number from 1 to 999, like R76.*). The same regex as `src/lib/materials/boxName.ts`.
- **`on_site_site_job_ids(job)`** — the site's jobs: every job of the job's development, or the job alone. Runs as the caller.
- **`on_site_next_box_name(jobs[], letters)`** — the next free name across those jobs: the letters most live boxes carry (a tie to the newest box) unless letters are given, one past the highest number any box, live or retired, carries under them; null with no named box and no letters, or past 999. A letter after a number counts the number as taken, so `G24B` makes `G25` the next and `G24` is never offered. `boxName.ts`'s `nextFreeName`, in SQL.
- **`job_containers_name_rule()`**, the trigger **`job_containers_name_rule`** `BEFORE INSERT OR UPDATE OF label` on `job_containers`, `SECURITY DEFINER` so it reads the whole site. For every kind but `unsorted`, a name that changes must hold to the rule and be free across the site's live boxes; it is saved in capitals, trimmed. A label that does not change passes, so a row with an old name (`G76 TOILETS`) is still moved, pinned, retired and brought back, and a kind or where-line edit never judges it. Refuses with `23514` and the screens' own words (*R12 is already on this site, on job JQ802. Pick another name.*), never `23505`, which the phone's outbox reads as a press that landed before.
- **`on_site_carry_job`** restated from `20261114070000` with one change: a live cage or box whose name the target's site already holds takes the site's next free name in place of `A1 (2)`, which the trigger would now refuse. The clash is read across the target's site, the source's own boxes counted too, so two clashing boxes take two names; a site with no named box starts at `A1`. The combine and the dev seat's move both run it.
- **`dev_on_site_write`** restated from `20261103143000`: `add_container` holds the label to the rule and to the site in words, in the plan as in the apply, and names the next free name in a refusal.
- **`dev_on_site_rename`** restated from `20261114050000`: `edit_container`'s label branch holds a changed name to the rule and to the site in words; a box's old name is never judged.

## Order and proof

The client checks the same rule before a press, so either may land first; push right after the merge. Proved on a scratch Postgres 15 with stub tables (the words, the next free name, the trigger on every path, the carry's two clashes, the seat's two writes) and by CI's `on-site-move`, `on-site-guards` and `combine-rows` beds, whose fixtures with old names (`G7 TOILETS`, `A1 (2)`, `Cage A`) are now inserted with the trigger off, as prod's old rows were, and whose clash assertions read the next free name (`A1 → A2`, `Cage B → A1`).

## Not changed

`dev_on_site_move_job`'s note still says a clashing box *took a numbered label*; the name it reports is the one the carry gave. `job_containers_live_label_key` (one live name a job) stays, under the trigger's site-wide check.
