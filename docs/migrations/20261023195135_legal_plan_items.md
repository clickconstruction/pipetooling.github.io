# 20261023195135_legal_plan_items.sql (2026-10-23, v2.5800)

The Legal desk's Timeline tab: planned steps on a legal matter, as one more kind of `legal_matter_entries` row.

- **`legal_matter_entries.kind` CHECK** gains `'plan'` (`legal_matter_entries_kind_check_v2`, the inline constraint from `20260911195745` dropped by definition, added `NOT VALID` then validated). A planned step: `occurred_on` = the day it is planned for, `body` = what, `meta` = `{ notes, done_at, done_by, source: 'office' | 'firm' | 'mcp' }`; held from counsel under `legal_matters.held_overrides` key `plan:<id>`.
- **`legal_plan_add(p_matter_id uuid, p_on date, p_body text, p_notes text DEFAULT '', p_source text DEFAULT 'office')`**, **`legal_plan_update(p_entry_id uuid, p_on date, p_body text, p_notes text, p_source text)`** (NULL leaves a field as it is; the firm's own planned steps may be changed too) and **`legal_plan_mark_done(p_entry_id uuid, p_done_on date DEFAULT app_today(), p_note text, p_source text)`** (stamps `meta.done_at`, `done_by`, `done_note`; the row keeps its planned day; refused ahead of today, when already done or undone) — `SECURITY DEFINER`, gated `legal_office_can_read()` like `legal_add_entry`; `p_source` is `office` unless the MCP wrapper says `mcp`. Body ≤ 500 characters, notes ≤ 4,000.
- **`legal_void_entry`** re-created with `'plan'` among the kinds the office may undo (the firm undoes its own through `submit-legal-portal` kind `void`).
- **`dev_legal_plan_write(p jsonb, p_dry_run boolean DEFAULT true)`** — the dev MCP's dry-run wrapper (`plan_matter_plan_item` / `apply_matter_plan_item`), devs only (`is_dev()`), modeled on `dev_legal_narrative_write`: `p = { action: add | update | mark_done, matter_id | entry_id, on?, body?, notes?, done_on?, note? }`; the dry run returns the matter, the action, the item before and after and `firm_reads_it`; apply calls the three RPCs above with source `mcp`.

No table is created, so no read-only fence is owed. Additive and idempotent. **Apply order**: push first, then deploy `legal-portal`, `submit-legal-portal` and `dev-mcp` (the client reads the new kind whatever the order; before the push the desk's Plan a step answers *function does not exist*).
