# 20260930210418_assistant_hours_window_fence.sql (2026-09-30, v2.4271)

The assistant hours window (`app_settings.assistant_hours_window_weeks_v1`, v2.1592) was a client-only clamp on what an assistant could *see*. Nothing on the server knew it, so the Add / Edit clock session doors — and the leader split RPCs, which bypass their this-or-last-week fence for assistants — could put hours on any day. The database now holds the same floor.

- **`assistant_hours_window_floor_for(p_today date, p_weeks integer)`** (IMMUTABLE): the pure math — the Sunday `(weeks − 1)` weeks before `p_today`'s week's Sunday; NULL for `weeks <= 0`. The same function as `assistantHoursWindowFloorYmd` in `src/lib/people/assistantHoursWindow.ts`, and the PG test bed pins both on the same fixtures.
- **`assistant_hours_window_floor()`** (STABLE, SECURITY DEFINER): the caller's floor. NULL for no signed-in person, for anyone whose `users.role` is not exactly `assistant` (controllers, devs and pay-approved masters are never limited — the client reads it the same way), and for the setting `0`. The setting is read as `parseAssistantHoursWindowWeeks` reads it: missing or negative = 3, else whole weeks, at least 1. Today is `now()` in America/Chicago. Granted to `authenticated`.
- **Trigger `clock_sessions_window_fence`** — BEFORE INSERT, and BEFORE UPDATE OF `clocked_in_at`, `clocked_out_at`, `work_date` only. When the caller has a floor and the row's day (the lesser of `work_date` and the clock-in's Chicago date; on an update also the old `work_date`) is before it, the write is refused: *Sun Sep 13 is the earliest day in your hours window. Ask the owner for earlier days.* (`P0001`, the message the modal shows as it is). Approving, rejecting, revoking, linking a job and editing notes are not time columns and pass, so an assistant's approvals queue is untouched. A worker's own punch is never fenced; neither are salary-schedule rows, quick adds or edge-function writes (no `auth.uid()`).

Proof: `npm run test:pg:typed-hours` now also runs `supabase/tests/typed_hours/30_window_scenarios.sql` — the math fixtures, who has a floor, the floor day itself, the day before, a clock-in before the floor with a `work_date` inside it, moving a session out, changing the times of an older one, notes and approval on an older one going through, the setting at 0 / 1 / 2.9 / −4, a controller and a dev unfenced.
