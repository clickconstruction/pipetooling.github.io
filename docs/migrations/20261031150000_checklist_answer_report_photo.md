# 20261031150000_checklist_answer_report_photo.sql (2026-10-31, a photo answers a checklist question, punch list #189 PR 6)

On the camera-first field report (v2.6083) a checklist question that asks for a photo is a chip under a new tile, and Save makes the shot the question's answer (v2.6219, `to-dos/phone-first/` item b.3). The answer row of `20261029210000_stage_checklists.sql` could not name a report photo: its photo columns are bound to the `stage-checklist-photos` bucket, which the checklist sweep reads by `photo_storage_path`. Additive and idempotent; no table is created, so no fence call.

- **`stage_checklist_answers.report_photo_id`** — the `report_photos` row that is the answer's photo, `ON DELETE SET NULL`, with a partial index. The client writes it at Save with `photo_file_name`, `photo_taken_at` and `photo_bytes`, as the sheet writes a photo of its own; `photo_storage_path` stays `NULL`, so the checklist sweep leaves the row alone and the report sweep files the one copy in Drive.
- **`stage_checklist_answers_reads_report_photo`** (BEFORE INSERT OR UPDATE OF `report_photo_id`, `photo_storage_path`) — an answer that takes a report photo reads the photo's Drive id, filed time and reason as they stand, so a shot the sweep already filed reads filed at once; a photo taken on the sheet itself (`photo_storage_path` set) takes the question back from the report photo.
- **`report_photos_mirror_checklist_answers`** (AFTER UPDATE OF `drive_file_id`, `filed_at`, `fail_why`) and **`…_delete`** (BEFORE DELETE) — when the `photo-save` sweep files the report photo, or writes why it could not, every answer that names it reads the same; a report photo deleted by hand leaves its question unanswered again. The sweep itself is unchanged, so no edge deploy.

Apply order: the client first is harmless. Until the push the answer write fails with the column's name in a warning toast and the report still saves with its photos; push right after the merge. Then `npm run gen-types:linked` as its own `chore(types)` PR.
