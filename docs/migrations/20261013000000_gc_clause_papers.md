# 20261013000000_gc_clause_papers.sql (2026-10-12, v2.5309)

Messages, cut 4c's next piece (GC Reviews helper 9, directed by the lead session GC Review). A statement of work and our contract can now be papers built from clauses, the way a person's or a company's paper is since v2.5294. Each copy gets the Contract library document it is built from. Its sign path freezes the clauses only at the revision the signer's page showed. The pages that show those clauses come next, and no screen sets a paper before its page shows it, so every signing reads as today until then.

## What it does

1. **`gc_sows.paper_id`** and **`gc_owner_contract_sends.paper_id`**, both pointing at `contract_template_documents(id)`, on delete set null, nullable, with a partial index each. Null is today's paper: the statement of work's lines, or our uploaded contract.
2. **`contract_clause_freeze(paper, trades, lang, title, between)`**: what a signed copy keeps. It is `contract_paper_clauses()` with the heading and the between line, or null when the document has no live clause or nothing published. It is a definer function for the office team or the service role. Anyone else signed in is refused (*Only the office reads a paper's clauses.*), and anon cannot run it. `contract_clause_between(name, lang)` gives the GC frame's line: *Click Construction and …*, or *y …* in Spanish.
3. **The setters**, each a definer function refusing in words, so the screens to come have one writer:
   - **`gc_set_sow_paper(sow, paper)`**: a dev, the board-write team until award's door (*Only a dev picks the paper for a statement of work while GC mode is built.*).
   - **`gc_set_owner_contract_paper(send, paper)`**: the money team (*Only the money team picks the paper for our contract.*).
   - Both refuse a twin, a paper not in the library, a fillable form (*A fillable form is not a paper built from clauses.*) and a copy already signed (*That statement of work is signed already.* / *That contract is signed already.*). Null clears the paper.
4. **`gc_trade_sign_sow`** and **`gc_customer_sign_owner_contract`** gain `p_paper_revision integer DEFAULT NULL` and `p_paper_lang text DEFAULT 'en'`. Each is dropped and created again in this one transaction, so only one signature exists, and its comment and its service-role-only grant are restored. The callers pass named arguments and resolve unchanged: `_shared/gcTradeSubmit.ts`'s `sign_sow`, and `submit-portal-request`. The rule:
   - With no `paper_id`, or a document with no live clause, it signs exactly as before.
   - A copy built from clauses signs only when `p_paper_revision` is today's revision. Otherwise it raises the key `paperChanged`, with the DETAIL *The paper changed since you opened it. Reload to read the new version.* A caller that passes nothing, as today's pages do, is refused the same way.
   - The signature's own update writes `paper_revision` and `clause_versions`, which the v2.5269 trigger keeps as signed.
   - A statement of work keeps the job's clauses and its package's one trade's exhibit, between us and the company. Our contract keeps the clauses for everyone, between us and the customer.
5. **`gc_sign_owner_contract`**, the office's *Mark it signed*: on the first sign, after `gc_owner_contract_keep`, `gc_owner_contract_freeze_newest(project)` freezes the newest send built from clauses, with no revision check, since the office attests what was signed. It runs only once the project is signed, so calling it on its own freezes nothing early. A send already frozen stays as it is.

No new table, so no house calls.

## Verify after the push

```sql
-- 1. The columns, read only.
SELECT table_name, column_name FROM information_schema.columns
WHERE column_name = 'paper_id' AND table_name IN ('gc_sows', 'gc_owner_contract_sends') ORDER BY 1;
-- expect: both

-- 2. One signature per sign verb, the service role's alone; the setters and helpers for the signed in, never anon.
SELECT p.proname, p.pronargs,
  has_function_privilege('service_role', p.oid, 'EXECUTE') AS service_role,
  has_function_privilege('authenticated', p.oid, 'EXECUTE') AS authenticated,
  has_function_privilege('anon', p.oid, 'EXECUTE') AS anon
FROM pg_proc p WHERE p.pronamespace = 'public'::regnamespace
  AND p.proname IN ('gc_trade_sign_sow', 'gc_customer_sign_owner_contract', 'gc_set_sow_paper', 'gc_set_owner_contract_paper', 'contract_clause_freeze', 'gc_owner_contract_freeze_newest', 'gc_sign_owner_contract')
ORDER BY 1;
-- expect: gc_trade_sign_sow and gc_customer_sign_owner_contract once each with 8 arguments, service_role true, authenticated false;
-- the setters, contract_clause_freeze and gc_owner_contract_freeze_newest authenticated true, anon false

-- 3. No copy has a paper yet.
SELECT (SELECT count(*) FROM public.gc_sows WHERE paper_id IS NOT NULL) AS sows, (SELECT count(*) FROM public.gc_owner_contract_sends WHERE paper_id IS NOT NULL) AS sends;
-- expect: 0, 0
```

## Rollback

```sql
-- The sign verbs as they were (20261010043000, 20261010090000): drop the eight-argument ones and re-run those two
-- functions' blocks, then:
DROP FUNCTION IF EXISTS public.gc_owner_contract_freeze_newest(uuid);
DROP FUNCTION IF EXISTS public.gc_set_sow_paper(uuid, uuid);
DROP FUNCTION IF EXISTS public.gc_set_owner_contract_paper(uuid, uuid);
DROP FUNCTION IF EXISTS public.contract_clause_freeze(uuid, text[], text, text, text);
DROP FUNCTION IF EXISTS public.contract_clause_between(text, text);
ALTER TABLE public.gc_sows DROP COLUMN IF EXISTS paper_id;
ALTER TABLE public.gc_owner_contract_sends DROP COLUMN IF EXISTS paper_id;
```

`gc_sign_owner_contract` keeps working without the freeze once `gc_owner_contract_freeze_newest` is restored or its one `PERFORM` line removed. Nothing sets a paper until the pages that show clauses land.
