# 20261001001500_bid_marks.sql (2026-10-01, v2.4287)

One table, no function, no trigger: a person's own marks on bids — "hold a row to mark it" on the nine bid workflow tabs and the Bid Board.

- **`bid_marks`**: `user_id` → `users` (cascade), `bid_id` → `bids` (cascade), `marked_at` (default `now()`), primary key `(user_id, bid_id)`; index on `bid_id`. Says nothing about the bid: no column on `bids`, no count changes, invisible to everyone but the person.
- **RLS**: SELECT, INSERT and DELETE each `user_id = auth.uid()`; no UPDATE policy (a mark is made or cleared, never edited); `anon` has nothing; `authenticated` holds SELECT / INSERT / DELETE, `service_role` all.
- **House rules**: `apply_read_only_write_blocks()` + `apply_read_only_stmt_blocks()` at the end, so a read-only (training) account cannot mark.

Client: `src/lib/bids/bidMarksStore.ts` loads the person's marks once per sign-in and writes optimistically (upsert on mark, delete on clear). The types for `bid_marks` were hand-added to `src/types/database.ts` in the same PR; regenerate (`npm run gen-types:linked`) after the push.

Apply order: any — until the table exists the client reads "no marks" and keeps marks in memory for the session; the table harms nothing without the client.
