# 20261013040000_quo_seats.sql (2026-10-12, v2.5335)

Messages, cut 5 (b), the Quo link's seats in Settings → Phone and texts. A seat is one of Quo's workspace users, by Quo's id (`US…`), and the user of ours who answers on it. `quo-send` texts as the sender's own seat when they have one, and `quo-webhook` names a call or a text by whose seat it rang. Until now the map was the `QUO_SEATS` function secret (#5452). This migration gives it a home the Settings card can write.

## What it does

1. **Seeds `app_settings` `messages_quo_seats_v1`** as `{}`, a JSON object of `"US…": "<users.id>"`. `ON CONFLICT (key) DO NOTHING`, so a second run leaves what the card wrote.
2. **`master_or_dev_update_messages_quo_seats`**, an `UPDATE` policy for `authenticated` keyed to that row alone, with `is_master_or_dev()` in both `USING` and `WITH CHECK`. It is the shape of cut 2's `master_or_dev_update_messages_assign_rule` (`20261012160000_messages_follow_up.sql`), so the two cards in the group write the same way: a plain update returning the key, where no row back means refused.

## Who reaches it

- **Reads**: every signed-in user, as `app_settings` already allows. The team sees which seat is whose, and Quo's user ids are not secrets.
- **Writes**: the owner or a dev, this row only. Training mode's write blocks on `app_settings` stand.
- **The edge functions** read it as the service role, past RLS. While the row is empty they fall back to the `QUO_SEATS` secret, so the row and #5452 can land in either order.

## Safety

- `SET lock_timeout = '3s'` first. The policy takes a short lock on `app_settings`, and a busy table makes the push fail fast.
- No table is created, so no fences are added. `app_settings` keeps its own.
- Idempotent: the seed does nothing when the row exists, and the policy is dropped and made again.

## Verify on prod (read only)

```sql
SELECT key, value_text FROM public.app_settings WHERE key = 'messages_quo_seats_v1';
SELECT polname, polcmd FROM pg_policy WHERE polrelid = 'public.app_settings'::regclass AND polname = 'master_or_dev_update_messages_quo_seats';
```
