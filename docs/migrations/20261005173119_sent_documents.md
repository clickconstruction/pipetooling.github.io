# 20261005173119_sent_documents.sql (2026-10-05, v2.4554)

`sent_documents` — one row each time the company sends someone something, with the copy as it went out. The owner's rule (2026-10-05): every send keeps a record, a print counts as a send, the email itself is kept, and the office finds it in Documents. The plan and the list of what is wired: [`docs/SENT_COPIES.md`](../SENT_COPIES.md).

Columns: `kind` (what it is, as the code names it — text with a shape check, not an enum, so a new kind of paper needs no migration), `title` (as a person reads it), `how` (`print · email · hand · mail · link · download`), who it went to (`recipient_name`, `recipient_emails`, an email's `subject`), where the office finds it (`job_ids uuid[]` under a GIN index, `customer_id`, `bid_id`, `person_id`), the record it was drawn from (`source_table`, `source_id`, no foreign key), the copy (`copy_path` in the bucket, `copy_type`, `copy_hash` — a SHA-256, so a second print of the same page points at the first file — and `copy_bytes`; a null path means the copy could not be kept), an email's `attachments` (`[{ name, path, type, bytes }]`), `resend_email_id`, and `sent_at` / `sent_by` / `sent_by_name`.

Append-only: there is **no UPDATE policy**. RLS: **select** `is_office_staff()` (dev · master · assistant · controller); **insert** `is_office_or_estimator() OR is_primary() OR is_superintendent()` — whoever on staff sends it files it; **delete** `is_dev()`. `sent_documents_stamp` (BEFORE INSERT, SECURITY DEFINER) sets `sent_by`, `sent_at` and `sent_by_name` from the signed-in sender whatever the client says; a service-role insert (an email function) names the sender itself and only has the name filled in.

The bucket **`sent-documents`** is created here, private, with two policies on `storage.objects`: **select** for `is_office_staff()`, **insert** for the same staff set as the table under a `<uuid>/…` path, never a training-mode (`is_read_only()`) user or a twin — the table's fences do not reach storage. No UPDATE and no DELETE policy: a copy is never replaced.

Ends with `apply_read_only_write_blocks()`, `apply_read_only_stmt_blocks()` and `apply_digital_twin_write_blocks()`.

Apply order: **client first**. `fileSentCopy` is best effort and `loadSentCopiesForJob` answers no rows on a failed read, so before the push a print still prints, nothing is filed, and *Sent from this job* says no copy is on file. Additive and idempotent (`IF NOT EXISTS`, `DROP POLICY IF EXISTS`, `CREATE OR REPLACE`, `ON CONFLICT DO NOTHING`).

Not rehearsed on a throwaway schema (docker was not running on the authoring machine). The table follows `20261005155515_lien_owner_record_requests.sql`; the bucket and its policies follow `20260911213000` (`job-test-reports`) and `20260915032447` (`bid-submittals`).
