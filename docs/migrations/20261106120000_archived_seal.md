# 20261106120000_archived_seal.sql (2026-11-06, the seal behind the Away note, punch list #256 PR 7, v2.6572)

A teammate who left may, in PR 8, sign in to one screen the office leaves for them (`to-dos/bring-back-a-teammate/`, the Away note). The app hiding every other screen locks nothing: a signed-in person holds a token that reaches the database, realtime, file storage and the edge functions directly. This migration is three of the seal's four locks on an archived caller (`public.users.archived_at` set); the fourth is the edge guard `supabase/functions/_shared/refuseArchivedCaller.ts`.

- **`caller_is_archived()`**: `SECURITY DEFINER`, `STABLE`, `search_path` pinned; one primary-key lookup on `users` for `auth.uid()`, the shape of `is_read_only()`. Executable by `anon`, `authenticated`, `service_role` and `hr_agent` where that role exists, since the policies run it as the calling role.
- **`archived_pre_request()`**, set as `pgrst.db_pre_request` on the `authenticator` role: PostgREST runs it before every request. No `sub` (anon, the service role, a cron) passes; `/rpc/my_away_note` passes; an archived caller is refused with sqlstate `PT403`, which PostgREST answers as HTTP 403 with *This account is archived. The Away note is the one page it may read.* It covers tables, views, every RPC including the `SECURITY DEFINER` ones, GraphQL, and edge functions that query as the caller. The `ALTER ROLE` runs in a `DO` block that warns instead of failing the push where the migration's role may not alter `authenticator`; the `NOTIFY pgrst, 'reload config'` follows.
- **`apply_archived_read_blocks()`**: one restrictive policy, `archived_fence`, on every RLS-enabled public table that lacks it, `FOR ALL TO authenticated USING ((SELECT NOT public.caller_is_archived())) WITH CHECK (the same)`, so an archived caller reads nothing and writes nothing however the table's own policies read; the `(SELECT …)` wrapper runs the predicate once per statement. It is what realtime obeys, and the lock behind the gate. Creates only what is missing, so a rerun after `CREATE TABLE` locks exactly the new table; the first push locks every RLS table for the length of its transaction, so push it in a quiet moment. Closed to the API like the other three sweep helpers. It is now the fourth call every `CREATE TABLE` migration ends with (`CLAUDE.md`; `scripts/check-migrations.sh` rule 6 fails a later migration that creates a table and skips one of the four).
- **`storage.objects`**: the same `archived_fence`, so a signed-in archived account downloads and uploads nothing.
- Idempotent: `CREATE OR REPLACE` throughout, the fences created only where missing, the `DO` blocks guarded. No table is created; the migration ends with `SELECT public.apply_archived_read_blocks();` so every table gets its fence now.

Apply order: any time after the merge; nothing in the client reads a new name.
