# 20261124093000_lien_run_left_out.sql (2026-11-24, v2.8474)

A place to remember a lien paper left out of the run, and one function that writes it. Punch list #362, step 5: the run's first step, **Get it right**, lists each paper that cannot print as it stands, and each line carries **Leave out**, so one stuck paper never holds the rest. The card asked where a left-out paper is remembered before it was built. The answer is this table, so every office seat sees the same list and the list can say who and when.

## The table, `lien_run_left_out`

| Column | Type | What it holds |
|---|---|---|
| `id` | `uuid`, primary key | |
| `job_id` | `uuid` → `jobs_ledger(id)`, `ON DELETE CASCADE` | The job. |
| `paper` | `text`, `'notice'` or `'affidavit'` | Which of the job's papers. A paper may have no desk item yet, so the row names the paper and not `job_lien_desk_items`. |
| `run_day` | `date` | The day the run counted to when the paper was left out: the day of the Board's first tile. |
| `reason` | `text`, one of `fact_not_in_time`, `leader_not_in_time`, `customer_paying`, `ask_attorney`, `other` | The reason the person picked. |
| `note` | `text`, default `''` | The person's words. Required when the reason is `other` (`lien_run_left_out_other_has_words`). |
| `left_out_by`, `left_out_at` | `uuid` → `users(id)`, `timestamptz` | Who and when, set by the function. |
| `put_back_by`, `put_back_at` | `uuid` → `users(id)`, `timestamptz`, both or neither (`lien_run_left_out_put_back_pair`) | Who put the paper back and when. NULL while the leave-out stands. |

`lien_run_left_out_live_key` is a unique index on `(job_id, paper, run_day)` over the rows not put back: one standing leave-out a paper and run.

## The rule the rows serve

The client's kernel reads the rows (`src/lib/jobs/lienLeftOut.ts`):

- A row that stands for this run's day, or a later one, leaves the paper out of this run.
- A row that stands for an earlier run's day makes the next run ask about the paper again, first on its list, with the old reason. The paper is neither taken into that run nor left out of it until a person answers.

So a paper is never carried into a run nobody looked at, and never stays out of every run with nobody asked. Leaving a paper out changes nothing on the paper: no notice, affidavit, filing or desk item is touched, and no rule about when a paper may go reads this table.

## Who reads and who writes

- **Read:** `lien_run_left_out_select_office`, for dev, assistant-like (a controller too) and a master. The same set that reads `job_lien_desk_items`.
- **Write:** no insert, update or delete policy, and `authenticated` is granted `SELECT` alone. The function below is the only way in.
- The four fences are applied at the end: training mode writes nothing, a twin writes nothing here, an archived caller reads nothing.

## The function

`set_lien_run_left_out(p_job_id uuid, p_paper text, p_run_day date, p_left_out boolean, p_reason text DEFAULT NULL, p_note text DEFAULT NULL) RETURNS jsonb`

- **Who.** The lien office: `dev`, `master_technician`, `assistant`, `controller`. Anyone else gets `{ "error": "Not authorized to leave a lien paper out of the run" }`.
- **Leave out** (`p_left_out` true) needs the run's day and a reason from the list; `other` needs words. It writes one row with who and when. The same press twice for the same run writes one row and answers `changed: false`, whoever presses.
- **Put back** (`p_left_out` false) stamps every standing leave-out of that paper, whatever run it was for, so no older row asks again. Putting back a paper nobody left out answers ok and changes nothing.
- **Returns** `{ ok, left_out, changed }`, or `{ error }` with nothing written.
- `SECURITY DEFINER`, `search_path = public`, EXECUTE for `authenticated` and `service_role`, revoked from `anon`.
