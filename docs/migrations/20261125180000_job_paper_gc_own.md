The office marks a form a job requires as the GC's own form, and the GC's page reads it (punch list #389 step 7, `to-dos/sub-nda-builder/README.md`). No clause wording is written.

## What it makes

Every statement is safe to run twice. No table and no policy, so it ends with no fence call.

- **`job_required_papers.gc_own`**, `boolean NOT NULL DEFAULT false`. Every row there is reads false.
- **`gc_own_set_by`** and **`gc_own_set_at`**: who last set it and when. Null on a row nobody set.
- **The check `job_required_papers_gc_own_is_a_form`**: a row carries the mark only with a `form_template_id` and no `settings`.
- **`job_paper_set_gc_own(p_required_paper_id, p_own)`**, new, for the office. It answers the mark as it now stands.
- **`job_papers_gc_page(p_job_ids)` replaced**, with the same grants. It started from the function as `20261125023655` left it.

## What the setter is held to

`job_paper_set_gc_own` raises in words, in this order:

| Refusal | When |
|---|---|
| *Sign in to set a job's papers.* | Nobody is signed in |
| *This account is archived.* | An archived caller |
| *A digital twin cannot set a job's papers.* | A twin |
| *Only the office sets the papers a job requires.* | Any other role |
| *Training mode is read-only. Nothing was changed.* | A training account |
| *Say whether this is the GC's own form.* | No yes or no |
| *This job no longer requires that paper.* | The row is gone or taken off |
| *(name) is not a form. Only a form can be the GC's own form.* | A paper in prose, or one built from settings |

The same mark twice changes nothing and keeps who first set it. The mark changes no form: no trigger of the settings lock reads these columns, so it is set and taken off whoever has signed, and nobody signs again.

## What the GC's page reads now

- A job is answered when it requires a paper built from settings **or** a form with the mark. Before, only the first.
- Each job's answer keeps `papers` as it was and gains `own_forms`. Both are always arrays, and either can be empty.
- One own form is `{id, paper_name, signed, total, businesses: [{name, people, signed, signed_on}]}`, counted over the office's own roster as a paper's are. It has no level, no plain words, no picks and no proposal.
- A form taken off the job is not read. A form with no mark is not read.

## Why `own_forms` is a list of its own

The `customer-portal` function live between this push and its own deploy reads `papers` and leaves any key it does not know, and it drops a job whose `papers` is empty. So for a job on the GC's own form it draws what it drew before the push: nothing. Had a form been one more entry in `papers`, it would have been drawn as a paper built from settings.

## Locks

Three `ALTER TABLE … ADD COLUMN` on `job_required_papers`, each a change of the catalog alone, and one check that reads the table once. The key from `gc_own_set_by` to `users` takes a short lock on that table too. The table is small. `SET lock_timeout = '3s'` opens the file, so a push that cannot take the lock fails fast.
