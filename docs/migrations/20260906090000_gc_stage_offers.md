# 20260906090000_gc_stage_offers.sql (2026-09-06, v2.2933)

The GC sees the stages you offer (PR 7 of the three-party scheduling plan, artifact 3a540149).

- **`jobs_ledger.gc_shares_stage_dates`** (boolean, default false) — the job-level switch under the GC/Builder picker. Off means the GC portal shows bills and payments only, exactly as before.
- **`jobs_ledger.gc_auto_offer_next`** (boolean, default false) — when a stage passes inspection, offer the next one to the GC without asking.
- **`job_stage_windows.offered_to_gc`** (boolean, default false), **`offered_to_gc_at`**, **`bundle_id`** (uuid) — per-stage offer state; stages offered together share a bundle id (one card, one window, withdrawn as one). Partial index on offered windows.

No RLS change (the columns ride on their tables' policies; the office writes them from Jobs → Subs → Work and Edit Job; the customer-portal function reads them with the service role).

Apply order: **client first, then push**, then `supabase functions deploy customer-portal`. Until the push, the GC column reads "off for this job" everywhere and the portal shows no Stages block.
