How fast a change ships: the cron that keeps Settings → How fast a change ships current.

- **Cron `ship-pace`** — `9,24,39,54 * * * *`, a minute slot no five-minute, ten-minute or quarter-hour cron already uses: `net.http_post` to `/functions/v1/ship-pace` with `{}` and the Vault `CRON_SECRET` (the `PROJECT_URL` and `CRON_SECRET` rows, as `file-index-sweep` is scheduled), unscheduled first so a second run leaves one row. - **No table, no policy, no fence calls** — the row lives in `app_settings`, which already has them.

**Apply order**: the client reads a row that may not exist yet and draws its empty state, so the client may deploy first with nothing lost. Deploy `ship-pace` and set `GITHUB_PACE_TOKEN` before the push, so no tick finds the function missing or answering 503; a tick that does is harmless (nothing is written) and the next one reads.
