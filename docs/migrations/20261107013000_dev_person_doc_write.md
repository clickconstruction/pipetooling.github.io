# 20261107013000_dev_person_doc_write.sql (2026-11-07, v2.6608)

Two functions for dev-mcp's `plan_person_doc` / `apply_person_doc` and the People → HR editor's Save ([v2.6608](../recent-features/v2.6608.md)). A person's summary and narrative (`person_files`, `docs/HR_FILES.md`) could be written only whole, by `hr_agent_write` from psql or inside a `dev_hr_entry_write` call, with no preview, no edit of one section, and nothing that told a second writer the text had moved.

- `hr_doc_headings(md text)`: `IMMUTABLE`, returns `(line_no, level, heading)` for every ATX heading of a document, backticks and bold markers stripped, lines inside ``` or ~~~ fences skipped — the same reading as `src/lib/people/hrDocMarkdown.ts`'s `extractHrDocHeadings`, which builds the jump list.
- `dev_person_doc_write(p jsonb, p_dry_run boolean default true)`: `SECURITY DEFINER`, `search_path = public`, raises `42501` unless `auth.uid()` is set **and** `public.is_dev()`. `p` names `person_id` (a `people.id`), `kind` (`summary` | `narrative`) and one of `markdown` (the whole text) or `ops` (at most 20): `replace_section` (the lines under a heading up to the next heading of the same or a higher level; the heading line stays; `''` empties the body), `insert_after` (new lines after that section's last line) and `append` (at the end). A heading is matched by its text, case-folded; a missing heading is refused with the document's headings, a heading that appears twice with the count. `expect_updated_at` refuses the call when the row's `updated_at` is not that instant (within a millisecond); a text that would not change is refused; more than 400,000 characters is refused.
- With `p_dry_run = true` it writes nothing and returns `{ dry_run, person { id, name }, kind, before { exists, chars, lines, updated_at, author_label, covered_through }, after { chars, lines }, changes [ per op: what moved, the words removed and added capped at 6,000 characters each ], sections [ the headings after, with line numbers ], author_label }`. The plan hash covers `before.updated_at`, so a save by anyone since the plan makes the apply refuse.
- With `p_dry_run = false` it upserts the `person_files` row — `content`, `author_label` = the dev's name, `covered_through` (`now()` unless given), `updated_at = now()`, `updated_by = auth.uid()` — and returns `{ ok, person_id, kind, chars, lines, updated_at, revision_archived }`. The `BEFORE UPDATE` trigger `person_files_archive_revision` (`20260824141540`) keeps the prior version.
- EXECUTE revoked from `PUBLIC` and `anon` on both, granted to `authenticated` (the gate is inside).

No `CREATE TABLE`, so no fence appliers; training mode still blocks the write, because the statement blocks on `person_files` fire inside the definer. Idempotent (`CREATE OR REPLACE`), no locks beyond the catalog.
