# 20260830180000_robot_books.sql — Robot books + fence v2 (v2.2513, 2026-08-30)

Owner decision after the first M5 run: robots get their own default takeoff book,
labor book, and price book — plus robot-owned assemblies — that they can add to.
Same pattern as the Robot Board: identical machinery, robot scope.

- `is_robot boolean NOT NULL DEFAULT false` on `takeoff_book_versions`,
  `labor_book_versions`, `price_book_versions`, `material_templates`.
- `apply_digital_twin_write_blocks()` v2 (CREATE OR REPLACE + rerun):
  - twins may INSERT robot versions (`is_robot = true`) and edit only robot versions;
    `price_book_versions` also keeps the bid-scoped frozen-copy allowance;
  - book ENTRY tables (`takeoff_book_entries`, `takeoff_book_entry_items`,
    `labor_book_entries`) writable when the parent version is a robot book;
    `price_book_entries` = bid-scoped (unchanged) OR robot version;
  - `material_templates` INSERT with `is_robot = true`, edits only robot rows;
    `material_template_items`/`material_template_prices` follow the parent template;
  - `fixture_types`: INSERT allowed (additive catalog), no update/delete;
  - **M5 fence-gap fix**: the generic bid-child branch now also admits tables that
    link through `cost_estimate_id` (labor rows + direct-cost rows) — the table that
    hard-blocked M5 stage 3 (`cost_estimate_labor_rows`) has no `bid_id` column.
- Seeds one `🤖 Robot Default` version of each book kind per service type
  (idempotent by name).

No new tables → no read-only-block calls needed. All statements idempotent.
