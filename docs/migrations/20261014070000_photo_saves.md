# 20261014070000_photo_saves.sql (2026-10-13, v2.5457)

Messages, cut 10's last item (GC Mode helper 2, directed by the lead session GC MODE): photos saved on arrival to the
job's photos, with the file agent copying and naming. This is the data behind it. The design is
`quo-messages-mockup.html` drafts 8 and 9 on branch spike/gc-mode. The kernels are v2.5456 (`src/lib/photos/`,
`src/lib/quo/mediaKeep.ts`). The `photo-save` sweep that reads the ticks comes next, with its `cron.schedule` in a
migration of its own after the deploy. Until then nothing reads a tick, and nothing changes for anyone.

## What it does

1. **`photo_saves`**: one row per job whose office ticked *Save every photo on this job to Drive as it comes in*.
   - A job is one of `bid_id`, `project_id` and `jobs_ledger_id`, as the spine ties a line, each on delete cascade. A
     partial unique index on each keeps one row a job.
   - The tick starts off on every job (the lead, 2026-10-13): no row is off.
   - `on_since` is when it went on, null once it went off again. The sweep copies only a photo that came in on a line
     tied to the job after `on_since`.
   - `set_by` and `set_at` stamp the last press.
   - The office team reads it (`gc_office_team()`, one policy). Nobody signed in writes it by hand. The service role
     reads it for the sweep.
2. **`set_photo_save(bid, project, pipeline job, on)`**: the office's press, a definer function, returning `on_since`.
   - On keeps the time it first went on. Off clears it and keeps the row, stamped.
   - The same press twice changes nothing. Turning off a job never ticked writes nothing.
   - It refuses, in words: anyone signed out (*Sign in to change a job's photos.*), anyone outside the office (*Only the
     office changes where a job's photos go.*), a training account, a twin, a press naming no job or two (*Name one job:
     a bid, a GC project or a Pipeline job.*), and a press with no on or off (*Say on or off.*).
3. **`message_attachments.left_in_gmail`** takes a third mark, `quo_not_copied`.
   - It marks a picture or a file on a text that the quo-webhook could not copy. Quo's own history still holds it.
   - `not_copied` stays an email's, because the line's files read it as still in Gmail.
   - The CHECK is dropped and made again with the three values, then validated. Every row already holds one of the first
     two. The column's comment says all three.

A new table, so the three house calls end it.

## Checked before the push

The SQL bed `photo-saves` (`npm run test:pg:photo-saves`) runs every migration on Supabase Postgres 17. Then it runs this
one a second time, which must change nothing, then the scenario. Docker does not run on the office Mac, so it runs in
the SQL beds workflow once the PR is ready.

- **Presses:**
  - Rosa ticks Helotes Dental Office on, stamped with her. On again keeps the first time.
  - A dev turns it off, stamped with him. Off again changes nothing. On again starts a later time.
  - Turning off a Pipeline job never ticked writes no row. A Pipeline job and a bid tick on the same way.
- **Refusals:**
  - A press naming two jobs, naming none, or saying neither on nor off is refused.
  - The office writes no tick by hand.
  - A superintendent, training mode, a twin and anyone signed out are each refused, and the tick stays on after them.
  - A superintendent reads no tick, and anyone signed out reads none.
- **The table's checks:** a row naming two jobs and a second row for one job are each refused.
- **The fences:** training mode's restrictive policies, the twins' `digital_twin_write_fence_insert` and the
  `read_only_block_stmt` trigger are on the table.
- **The new mark:** a text's picture is kept at `quo/MS-1/1.jpg` or marked `quo_not_copied`. The CHECK holds all three
  marks and is validated, and a mark it does not know is refused.

## Rolling back

Nothing reads a tick until `photo-save` is deployed and scheduled. To undo it, drop the function and the table, and
make the CHECK again with its two marks. Do that only once no row carries `quo_not_copied`:

```sql
DROP FUNCTION IF EXISTS public.set_photo_save(uuid, uuid, uuid, boolean);
DROP TABLE IF EXISTS public.photo_saves;
ALTER TABLE public.message_attachments
  DROP CONSTRAINT IF EXISTS message_attachments_left_known,
  ADD CONSTRAINT message_attachments_left_known CHECK (left_in_gmail IN ('too_big', 'not_copied'));
```
