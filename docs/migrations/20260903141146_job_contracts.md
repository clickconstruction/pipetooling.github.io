# 20260903141146_job_contracts.sql (2026-09-03, v2.2679)

**Contract Desk, PR 1 of the job-contract signing loop** (owner-approved "Contract Desk" proposal; PR 2 office modal + `send-job-contract`, PR 3 public signing page + `get-job-contract` / `sign-job-contract`, PR 4 Needs You + backlog sweep, PR 5 reminders + portal card).

## What it does

- **`job_contracts`** — one row per customer-facing job agreement: lifecycle `status` (`draft` → `sent` → `signed`; `voided` terminal, `superseded_by` links the redo), `revision`, the Contract Book source (`template_document_id`, `template_name`, `template_version_date`), the document `fields` jsonb (scope lines, exclusions, amount, payment terms, dates), the terms `body_html`/`body_format` snapshot, recipient block + `cc_emails`, the durable link (`public_token_hash`, `public_token_expires_at`), send/view/reminder counters, `minted_pdf_path`, the e-signature audit block (`signed_at`, `signer_printed_name`, `signer_mode` type|draw|in_person|paper, `signer_consented_at`, `signer_ip`, `signer_user_agent`, `signer_signature_storage_path`, `signed_pdf_path`), the paper-upload door (`paper_upload_path`, `paper_signed_on`, `recorded_by`), void stamps. Partial unique index: one live (`draft`|`sent`) row per job. `updated_at` touch trigger.
- **`job_contract_events`** — room-style telemetry (`sent` / `viewed` / `reminded` / `signed` / `voided` / `recorded`) with ip/ua; the customer side writes through service-role functions.
- **`contract_template_documents.audience`** (`staff` default | `customer`) — customer contract templates share the Contract Book library without mixing into staff packets.
- **`job_contracts_to_activity()`** trigger (AFTER INSERT OR UPDATE) writes four `job_activity_events` types, all `financial = true`, idempotency-guarded per type: `contract_sent` (each send keys `source_id` by `last_sent_at`), `contract_viewed` (first view only), `contract_signed` (online or paper), `contract_voided`. Client registry entries ship in the same PR.
- RLS mirrors `job_lien_releases`: select/insert/update for dev, assistant-like, the job's master; delete dev-only. Both read-only appliers + the digital-twin write fence.

## Out-of-band storage setup (run once, alongside `db push`)

The private `job-contract-documents` bucket holds signature PNGs, the mint/signed PDFs, and uploaded paper copies. Buckets and `storage.objects` policies are not tracked by this ledger (hr-files / lien-release-documents convention):

```sql
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('job-contract-documents', 'job-contract-documents', false, 10485760, array['image/png', 'image/jpeg', 'application/pdf'])
on conflict (id) do nothing;

create policy job_contract_docs_office_select on storage.objects for select to authenticated
  using (bucket_id = 'job-contract-documents' and (public.is_dev() or public.is_assistant() or exists (
    select 1 from public.job_contracts c join public.jobs_ledger jl on jl.id = c.job_id
    where (storage.foldername(name))[1] = c.id::text and jl.master_user_id = auth.uid())));
create policy job_contract_docs_office_insert on storage.objects for insert to authenticated
  with check (bucket_id = 'job-contract-documents' and (public.is_dev() or public.is_assistant() or exists (
    select 1 from public.job_contracts c join public.jobs_ledger jl on jl.id = c.job_id
    where (storage.foldername(name))[1] = c.id::text and jl.master_user_id = auth.uid())));
create policy job_contract_docs_dev_delete on storage.objects for delete to authenticated
  using (bucket_id = 'job-contract-documents' and public.is_dev());
```

Object paths: `<contract_id>/<uuid>.png` (signature), `<contract_id>/minted-rN.pdf`, `<contract_id>/signed.pdf`, `<contract_id>/paper.<ext>`.
