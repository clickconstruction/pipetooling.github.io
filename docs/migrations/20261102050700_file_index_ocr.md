# 20261102050700_file_index_ocr.sql (2026-11-02, v2.6336)

Search every file deeply (punch list #240, PR 3): three columns on `file_index` for our own OCR of scans. `ocr_tried_at` (when OCR last tried the row; a scan refused by the provider is tried again a day later, never sooner, so a refusal costs a day and not a loop), `ocr_pages` (how many pages Document AI read, the cost; null when the text did not come from OCR), `ocr_note` (the provider's own reason the last time it refused, at most 1,000 characters, for the report; null once it read). A partial index `file_index_ocr_due_idx` on `(ocr_tried_at NULLS FIRST) WHERE text_why = 'scan'` is the OCR pass's queue. Additive, idempotent, no table, no fence calls.

**Apply order**: push before `drive-link`, `file-index-sweep` and `dev-mcp` are redeployed with v2.6336: the pass writes the three columns on every row it upserts, so the old table refuses the new function's write.
