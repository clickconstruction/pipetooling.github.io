# 20260905233000_authorship_events.sql (2026-09-05, v2.2904)

Journey-map Phase 4, Tier-3 batch **B20 — Authorship & events** (cluster C43: "no creation / conversion event; writes with no author"). Four additive, idempotent changes; no new table, so the read-only write-block helpers are not re-applied.

1. **`jobs_ledger` birth event.** New `jobs_ledger_birth_to_activity()` (SECURITY DEFINER) + trigger `jobs_ledger_birth_to_activity_ins` (`AFTER INSERT`) writes one `job_activity_events` row per created job: `event_type = 'job_created'`, summary *Job opened* / *Job opened from bid B398* (looks up `bids.bid_number` when `bid_id` is set) / *Job opened under a project*, `detail = {source_id: job id, source, bid_id, bid_number, project_id, status}`, `financial = false`, actor `auth.uid()`. Returns early when `auth.uid()` is null — service-role creators (`auto_create_job_from_signed_estimate`) already write `job_auto_created_from_estimate`. The insert is wrapped in an exception block so telemetry can never fail a create. A `job_separated` new-job row will now also carry a birth row (different tag, honest, accepted).
   **Backfill:** one `INSERT … SELECT` over `jobs_ledger` (`created_at` not null, no existing `job_created` / `job_auto_created_from_estimate` row for the job) at `created_at`, actor null, `detail.backfilled = true`. Re-runnable.
2. **`bid_pricing_assignments`, `bid_count_row_custom_prices`** each gain `updated_by uuid REFERENCES users(id) ON DELETE SET NULL` and `updated_at timestamptz NOT NULL DEFAULT now()` (`ADD COLUMN IF NOT EXISTS`). New reusable `stamp_updated_by()` (`BEFORE INSERT OR UPDATE`) sets `updated_at = now()`, `updated_by = coalesce(auth.uid(), new.updated_by)`. Existing rows get `updated_at = created_at` **before** the triggers are attached (the stamp would otherwise reset it to now()). Model: `bid_count_row_custom_costs.applied_by/applied_at` (`20260902181208`).
3. **`bid_rfqs.created_by`, `bids_submission_entries.created_by`** get `DEFAULT auth.uid()` and the new `stamp_created_by_if_missing()` (`BEFORE INSERT`, fills only a NULL). Edge functions that pass an explicit `sender.id` (`send-rfq-email`) are untouched; a client passing `created_by: null` (the copy lane before v2.2851) now gets the session user.
4. **`bids` seeds a last-contact entry.** New `bids_seed_last_contact_entry()` (SECURITY DEFINER) + trigger `bids_seed_last_contact_entry_ins` (`AFTER INSERT`): when the new bid has `last_contact` and no `bids_submission_entries` rows, inserts one entry (`contact_method = 'Other'`, explanatory note, `occurred_at = last_contact`, `created_by = auth.uid()`). `sync_last_contact_from_entries` (`20260828040000`) then sees the same max and leaves `bids.last_contact` alone. Duplicate / adopt RPCs don't copy `last_contact`, so they never trip it.

**Apply order:** free. The client (v2.2904) only *reads* the new `job_created` rows; nothing writes the new columns from the client, and an older client keeps working. Push promptly so the Activity feed shows births — until then, new jobs simply have no birth row yet (the backfill catches them on push).

**Lock footprint:** two `ALTER TABLE … ADD COLUMN` (fast default) + six `CREATE TRIGGER` under `SET lock_timeout = '3s'`; one bulk `INSERT … SELECT` and two bulk `UPDATE`s (DML, no DDL lock).

**Rollback:** `DROP TRIGGER IF EXISTS` the six triggers; `ALTER TABLE bid_rfqs / bids_submission_entries ALTER COLUMN created_by DROP DEFAULT`. Columns and event rows can stay (inert; the client ignores unknown event types if the render entry is reverted).
