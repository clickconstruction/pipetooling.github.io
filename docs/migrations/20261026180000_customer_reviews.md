# 20261026180000_customer_reviews.sql (2026-10-26, v2.5896)

Adds `public.customer_reviews`, the review a homeowner leaves us directly from the link the **Review asked** step texts after a job is paid (punch list #185, [`to-dos/customer-reviews/`](../../to-dos/customer-reviews/README.md)). One row per job (`job_id` unique, `ON DELETE CASCADE`): `customer_id`, `token_hash` (the link's SHA-256 as 64 hex, unique; the token itself is never kept, the estimate's pattern), `token_expires_at` (60 days from the ask), `lang` (`en` · `es`, from the customer's language), `asked_at` / `asked_by` / `ask_count` (each ask replaces the hash and the expiry, so an older link dies), `opened_at`, `answered_at`, `stars` (1 to 5), `words` (≤ 1,000), `better` (what we could have done better, ≤ 1,000), `google_pressed_at` (they pressed Post it on Google; whether they posted is never known), and the office's follow-up `called_at` / `called_by` / `call_note`. A check holds `answered_at` and `stars` together. Indexes on `customer_id` and `answered_at`; the house `update_updated_at_column()` trigger.

RLS: the office team (`gc_office_team()`) selects, updates and deletes; `authenticated` holds those three grants, `anon` nothing; there is no insert policy, since the row is made by the function below and answered by the `customer-review` edge function as the service role. The three house calls close it (read-only training mode, the statement trigger, the twin fence).

`customer_review_ask(p_job_id uuid) RETURNS text` (SECURITY DEFINER, EXECUTE to `authenticated`, revoked from `PUBLIC` and `anon`): the office makes or remakes the job's review link and gets the 32-character token back once (`extensions.gen_random_bytes`, `extensions.digest`, as `share_estimate_link`). Refused in words: signed out, a training account, a twin, anyone off the office team, a job not there, a job with no customer, a job already answered.

Apply order: this migration ships in its own PR with the page and the function; the page reads nothing until the function is deployed, and the office's ask (the strip's **Ask for a review**) calls the function above, so `supabase db push` after the merge from a main checkout, then `supabase functions deploy customer-review`, then the types PR (`src/types/database.ts` regen + `node scripts/build-dev-mcp-catalog.mjs`). The hand-written `customer_reviews` block in `database.ts` is replaced by the regen.
