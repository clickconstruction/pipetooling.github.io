# 20261010008000_fleet_truck_rate.sql (2026-10-09, v2.5039)

What the company's trucks cost per field hour, for the Bids crew-rate card. Wheels PR 3, the owner's call of 2026-10-09, sent by Punchlist.

Estimators price bids but cannot read the fleet tables (`vehicles` and its insurance, service and replacement-value rows are pay access only, plus a holder's own vehicle). The card needs one number from them, so this function returns that number and its totals and never a vehicle's own figures. The card shows it beside the company rate and never adds it: the burden factor and the driving line already carry the truck.

## What it does

**`fleet_truck_rate_per_field_hour(p_today date) RETURNS jsonb`**, `STABLE SECURITY DEFINER`, `search_path = ''`.

- Refuses anyone outside `is_office_or_estimator()` (dev, master technician, assistant, controller, estimator) with *Only the office and estimators read the trucks' rate.*, and a null day with *Which day is today?*
- Over the 90 days ending `p_today`, per vehicle (every row in `vehicles`, parked and unassigned ones included), rounded to cents each:
  - **insurance** = `weekly_insurance_cost` × 90/7 while an insurance period covers today, else 0;
  - **registration** = `weekly_registration_cost` × 90/7;
  - **service** = the costed service events in the window, floored at 0;
  - **wear** = the latest replacement value on or before today ÷ (5 × 365) × 90. A latest reading of $0 ends the wear; no reading adds none.
- **Field hours** = every approved, clocked-out session in the window on a job and not a bid, neither rejected nor revoked, `clocked_out_at > clocked_in_at`. The same sessions `fieldHoursByUser` counts.
- Returns `{rate, fixed_usd, field_hours, trucks, days}`. `rate` = `round(fixed ÷ hours, 2)`, null with no field hours.

The arithmetic is `fleetTruckRate` in `src/lib/people/wheels.ts`, which People → Vehicles → Wheels shows the office from the same rows. `src/lib/people/fleetTruckRateSql.test.ts` pins this body's window, wear life, session filter and rules to the kernel's constants. Fuel is never read: it stays on the jobs.

`SET lock_timeout = '3s'` comes first. A new function only: no table is created or altered, so no lock is taken and the read-only and twin blocks are untouched. `CREATE OR REPLACE`, so the file is idempotent. Grants: `authenticated`; revoked from `public, anon`.

## Checked before the PR

On a private local Postgres 15 (its own data directory confirmed before the first statement), with stand-in tables and the fixture in `wheelsData.test.ts` (four vehicles: on and off a plan, a plan starting tomorrow, service before, inside and after the window, a negative credit, values before, on and after today, a latest $0; eleven sessions covering every filter):

1. The office read gives `{"days": 90, "rate": 180.29, "trucks": 4, "fixed_usd": 3245.30, "field_hours": 18.0}`, the same as the loader's `fleet` over the same rows.
2. A day a year earlier, with no sessions in its window: `rate` null, `fixed_usd` 109.29 (registration only).
3. A caller outside the gate is refused; a null day is refused.
4. `anon` cannot execute, `authenticated` can; `prosecdef` true; `search_path=""`.
5. On prod, the body's arithmetic run as a plain read for 2026-10-09 gave $4,754.85 over 13 vehicles ÷ 3,905.2 field h = $1.22. The dev server's People → Vehicles → Wheels showed the same line that day.
