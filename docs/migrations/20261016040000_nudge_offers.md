# 20261016040000_nudge_offers.sql (2026-10-16, v2.5595)

Today's sends (punch list #115 PR 4, `to-dos/tell-the-customer/README.md`): the app's own texts become offers the office presses. The client reads the new table fail-soft (an empty Today's sends before the push), so it may deploy first; push after the feature PR merges, redeploy `messages-nudge-dispatch` (it writes and sends the offers) and regenerate the types.

## What it does

1. **`nudge_offers`**: one row per prepared text — the person (`contact_id`), the step, the job (`bid_id` / `project_id` / `jobs_ledger_id`, as `nudge_sent` keeps it), `how` (text), the `body` as composed, the `channel_id` it goes to, who prepared it (`prepared_by` app or office, `by_user_id`), `send_on` (an office-made offer: the morning the run sends it; null waits for a press), `held_why`, and how it ended (`sent_at` / `sent_by_user_id` / `message_id`, or `dismissed_at` / `dismissed_by_user_id` / `dismissed_why`: not this one, held, stopped, sent elsewhere). One SELECT policy for the office team (`gc_office_team()`); `authenticated` holds SELECT alone and `anon` nothing, both revoked explicitly; the service role (the morning run) and the three functions write. A partial index on the open rows. The three fence appliers run at the end.
2. **`nudge_offer_make(p_contact, p_step, p_job_kind, p_job_id, p_body, p_channel, p_send_on)`**: the office prepares a text for a morning (the Tell the customer sheet's Send in the morning). Refused through `quick_reply_caller('prepare a text')` (signed out, a training account, a twin, off the office team), for an empty text, no morning, a job that is not there (`contact_job_check`), a person not there, or a number that is not theirs. Returns the row's id.
3. **`nudge_offer_sent(p_offer, p_message)`**: the office pressed Send and `quo-send` wrote the line; the offer is stamped sent and `nudge_sent` gets its row through `nudge_record_sent` (which also releases a hold on the step), so the run never doubles the reminder and the person's panel reads it as sent by a person. Refused for a text that already went or was put away.
4. **`nudge_offer_dismiss(p_offer, p_why)`**: not this one, held (after `nudge_hold_until`), stopped (after `flow_skip_step`) or sent elsewhere. Refused for a text that already went.

All three functions are SECURITY DEFINER with EXECUTE to `authenticated`, revoked from `PUBLIC` and `anon`.

## Why the shape

- A table of its own, not a flag on `nudge_sent`: an offer is a text that has not gone, with words the office may change and a reason it is held; `nudge_sent` stays the record of what went.
- The office presses through the reply box's own path, so the opt-out line, STOP, the pause and the texts switch hold as they do from the thread; the function only stamps what the client already sent.
- `send_on` lets the office hand a text to the morning without the run deciding anything: it sends what a person prepared, on the morning they named.

## Verify

Read-only on prod after the push: `select count(*) from nudge_offers where sent_at is null and dismissed_at is null` reads 0 until a step is set to Offers in Flows and the run fires, or the office presses Send in the morning. The messages flows bed (`npm run test:pg:messages-flows`, CI) gains the offers' section: a make, a sent with its `nudge_sent` row, each dismiss, and each refusal.
