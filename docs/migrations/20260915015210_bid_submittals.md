# 20260915015210_bid_submittals.sql (2026-09-15, v2.3461)

Submittals stage 2 (`to-dos/submittals/README.md`): the package as rows, plus its bucket.

- **`bid_submittals`** (new) — one revision per (bid, `rev_number`): `job_ledger_id` (set when the job is opened from the bid), `title`, `status` (`draft · shared · reviewed · superseded`), `note`, `package_path` (the rendered PDF), `source_files` jsonb (the vendor PDFs dropped on the revision: path, house, name, pages, trimmed_at), `shared_at/by`, `created_by`, timestamps.
- **`bid_submittal_items`** (new) — one row per fixture tag on a revision: specified (`manufacturer · model · description`), submitted (`manufacturer · model · label`), `supply_house_id`, `source_quote_line_id`, `status` (`as_specified · superseded · equal · alternate · design_change · missing · accessory`), `reason_kind` / `reason_note`, `lead_time_days`, the sheet (`sheet_file` index into `source_files` + `sheet_pages int[]`, `sheet_source` `estimator · robot · house`), `carried_from_item_id`, and stage 4's `review_decision` (`approved · revise · rejected`), `review_note`, `reviewed_by_name/email/at`.
- **Helpers** — `is_pricing_sharer()` (the five pricing-side roles) and `can_access_submittal(id)` (the item's revision's bid passes `can_access_bid_for_pricing`), both SECURITY DEFINER, `authenticated` only.
- **RLS** — both tables: pricing sharers read and write on bids they can price. All three fence appliers.
- **Bucket `bid-submittals`** (private) — paths `<bid_id>/<submittal_id>/<file>.pdf`; four `storage.objects` policies (select · insert · update · delete) for pricing sharers on bids they can price, keyed on the first folder being the bid id (the test-report bucket's shape). Outsiders never touch the bucket: stage 4's review page and stage 5's portal mint short-lived signed links server-side.

Idempotent. Apply order: push after the client merge — the old client never selects these tables; the new tab treats an RLS or missing-table error as "no revisions yet".
