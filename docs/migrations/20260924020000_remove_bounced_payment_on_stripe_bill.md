# 20260924020000_remove_bounced_payment_on_stripe_bill.sql (2026-09-23, v2.3784)

`remove_jobs_ledger_payment_and_reconcile(p_payment_id)` — the RPC behind Edit Job's **Unlink and remove** — refuses a payment on a Stripe-hosted bill only while Stripe holds a record of it: the row carries a `stripe_credit_note_id` (Undo part payment voids it) or the bill's `stripe_invoice_status = 'paid'` (Unwind reverses the out-of-band close). Any other row deletes as on a physical bill, with the reconcile unchanged. Two additions in the same call: a `removed` event into `jobs_ledger_payment_events` (its kind check now allows `'moved'` and `'removed'`; the snapshot columns already existed) with a reason (`bank_failed: <reason>` / `unlinked_stripe_bill_unrecorded` / `unlinked`), and — when the Mercury deposit behind the row has `status = 'failed'` — an upsert into `mercury_transaction_ar_returned` so the deposit leaves To match as returned. The reply gains `bank_failed`, `bank_reason`, `marked_returned`.

Shipped with v2.3784 (PR for Take 5 – Seguin's bounced $13,680 check). Apply with `supabase db push` after merge. Either order with the client is safe: the old client hides the button on every Stripe bill (and its pre-check toast refuses), so it never reaches the new rule; the new client with the old RPC shows the button and surfaces the old RPC's refusal as a toast. No new table, so no read-only block calls.
