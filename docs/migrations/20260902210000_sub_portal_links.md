# 20260902210000_sub_portal_links

**Sub-portal train, PR 1 — the link spine.** The customer portal's capability-link model, person-keyed for subcontractors.

## What it does

- `sub_portal_links` (person_id → people CASCADE, raw `token` + `token_hash`, `created_by`, `revoked_at`; one active link per person via partial unique; unique token index). Mirrors `customer_portal_links` minus audiences — a sub has exactly one view.
- `sub_portal_slugs` (person_id PK, slug UNIQUE 3-60 chars, `locked_at` on first share) + append-only `sub_portal_slug_events` (`created`/`changed`/`locked`) for the globe modal's History row.
- RLS: office SELECT (dev / assistant-like / master_technician) on all three; every write goes through the SECURITY DEFINER RPCs or the service-role edge fn.
- RPCs: `mint_sub_portal_link(p_person_id, p_rotate)` (returns the existing active raw token; rotate revokes + re-mints), `revoke_sub_portal_link` (the "Turn off portal" kill switch), `set_sub_portal_slug` (friendly errors; **uniqueness checked across `customer_portal_slugs` too**), `mark_sub_portal_slug_shared`.
- **Shared printed namespace**: `set_customer_portal_slug` is re-created (body copied from its defining migration `20260821234000`, unchanged since — never rebuilt from the baseline) with one addition: a uniqueness check against `sub_portal_slugs`. One `my.clickplumbing.com` namespace; `/p/<slug>` dual-resolves client-side (customer first, sub fallback), so the Cloudflare shell worker needs no change.
- `public_page_views.surface` CHECK widened with `'sub_portal'`.

## Order

Apply before deploying the `sub-portal` / `submit-sub-portal` edge functions and before the client PR that mounts the Subs-tab globe goes live (the globe degrades to a friendly "Could not load the portal link" error until then).
