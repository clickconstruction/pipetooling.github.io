# 20260914180000_lien_desk.sql (2026-09-14, v2.3405)

The Lien desk's storage and the count the Dashboard runs on. Shipped with v2.3405 (the desk, PR 1 of the train in `to-dos/lien-desk/`).

- **`job_lien_desk_items`** — one row per (job, kind) from `drafted` on: the months a § 53.056 notice names (`months text[]`, the earliest sets the deadline), `status` drafted · awaiting_approval · approved · held · sent · missed, the draft (`fields jsonb` — the notice form + the GC email), `cover_note`, who drafted / submitted / approved and when, `approval_mode` leader · word · rule with `word_note` + `word_channel` for the spoken-word send, `hold_reason` (promised · call_first · rule) + `hold_until`, `sent_filing_id → job_lien_filings`, `pulled_back_by/at`, `voided_at`. Unique live row per (job, kind). RLS: the office set (dev, assistant-like, master) reads / inserts / updates; dev deletes. "Due" items are derived, never stored.
- **Trigger `job_lien_desk_items_guard`** — a leader's approval (`approval_mode = 'leader'`) needs a master or dev; the spoken word (`'word'`) needs a non-empty note and a channel; a standing rule (`'rule'`) is the office's to apply. Stamps `approved_at/by`, `held_at/by`, `sent_at`, `updated_at`.
- **`customers.lien_notice_policy`** (`ask` default · `send` · `hold`) + note / set_by / set_at — the leader's standing rule per GC; written only through **`set_customer_lien_notice_policy(customer_id, policy, note)`** (master / dev).
- **`lien_notice_deadline(month, property_kind)`** — the § 53.056 date in SQL (15th of the 3rd month after; 2nd residential; weekends rolled), the same rule as `src/lib/jobs/lienDeadlines.ts`.
- **`list_lien_notice_months(p_within_days = 30)`** — every (sub job with money open, approved work month) whose deadline is within the window (a week behind, so a missed month is seen), with whether a live notice names the month, whether an owner of record with a mailing address is on file (job override or property record), and the live desk item. Office-gated; empty otherwise.

Apply order: additive; the client reads the RPC and the table only from the Lien desk and the Dashboard cards, which fail quiet (empty queue) until the migration is applied — push right after the client deploys. Ends with both read-only appliers.
