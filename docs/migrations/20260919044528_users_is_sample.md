# 20260919044528_users_is_sample.sql (2026-09-18, v2.3606)

View as, PR 1 — sample accounts ([`docs/recent-features/v2.3606.md`](../recent-features/v2.3606.md)).

- **`users.is_sample boolean NOT NULL DEFAULT false`** — one real account per imitable role (`sample-<role>@samples.pipetooling.local`), hidden from rosters, pickers and notification fan-outs the way `is_digital_twin` rows are; visible under Settings → Active accounts → *Sample accounts*. A dev imitates one to see a page as that role. Ordinary rows otherwise: no RLS change, writes stamped with their own name.
- **`users_guard_privileged_columns()`** gains a fourth rule — only a dev may change `is_sample` — and the trigger fires on `is_sample` updates too (`BEFORE UPDATE OF role, read_only, archived_at, is_sample`). Service-role writes (the `create-user` function sets the flag at creation) pass through as before.

Additive and idempotent. Apply order: push while the PR is open (the client reads the column in `activeUsersQuery`), then `npm run gen-types:linked`.
