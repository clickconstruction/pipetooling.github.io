# 20261012190000_quick_replies.sql (2026-10-12, v2.5282)

Messages, cut 3's SQL: quick replies, the lines the office types every day (`to-dos/gc-mode/messages/BUILD_PLAN.md` on
branch `spike/gc-mode`, *Cut 3 · Replying*). The kernel is `src/lib/quickReplies/kernel.ts`, and these columns hold its
types. It needs the spine's `contacts` and `contacts_fold` (`20261012010000_messages_spine.sql`, v2.5258), so it lands
after that file.

## What it does

1. **`users.title`**, nullable, 80 characters at most: the title under a person's name in an email's signature
   (`signatureLines` in `src/lib/messages/compose.ts`). Each person sets their own under the users table's own-profile
   policy, as a dev sets anyone's. The privileged-columns guard does not cover it.
2. **`quick_replies`**: a line's words (`text`, 1,000 characters at most), who it is for (`for_kind`: trade, customer,
   arch or any), its flow step (`step_key`), the team's or one person's own (`scope`: team or mine), `added_by`,
   `added_at` and `removed_at`.
   - `step_key` is the step's id in its kind's flow, in `flow_steps.step_key`'s shape, with no foreign key. The flows
     are a sibling cut's, a step the flow no longer has reads as no step, and a line for anyone has none (a CHECK).
   - A removed line stays, for its history and the Removed tab.
3. **`quick_reply_versions`**: every change, with who (`by_user_id`) and when (`at`). The kinds are `added` (the words
   and tags it started with), `words` (`from_text`, `to_text`), `tags` (`from_for_kind`, `from_step_key`,
   `to_for_kind`, `to_step_key`), `removed` and `restored`. A CHECK holds each kind to its own columns. The id is an
   identity, so the words and the tags saved together read back in the order they were written.
4. **`quick_reply_uses`**: each press, by `user_id`, in a contact's thread (`contact_id`) or none, `at`. A press fills
   the box; nothing sends.
5. **The office team's**, one SELECT policy a table on `gc_office_team()`. A line marked mine, with its versions and
   presses, is its owner's alone. The three tables are read only for `authenticated`, and `anon` holds nothing.
6. **The functions** make every change and write its version, so the history holds every change. They are `SECURITY
   DEFINER`, since the tables are read only, and each starts with `quick_reply_caller`'s refusals in words: signed out,
   a training account, a digital twin, anyone off the office team.
   - `add_quick_reply(p_text, p_for, p_step, p_mine)` adds a line for the team or for the caller, with its `added`
     version, and returns its id. It refuses a blank line ("Write the line first."), a kind it does not know, a step
     id of the wrong shape and a line past 1,000 characters. A line for anyone drops its step, as `tidyTags` does.
   - `edit_quick_reply(p_id, p_text, p_for, p_step)` writes a `words` version and a `tags` version, each only when it
     changed, the words first, and returns how many. It refuses "Nothing changed.", a blank save ("Write something, or
     Cancel."), a removed line, and another person's own line ("That line is not there.").
   - `remove_quick_reply(p_id)` and `restore_quick_reply(p_id)` set and clear `removed_at` with their version. Each
     refuses a line already as asked.
   - `press_quick_reply(p_id, p_contact_id)` counts a press by the caller. It refuses a removed line and a contact that
     is not there.
7. **`contacts_fold_quick_replies(p_from, p_into)`** follows the spine's rule: `contacts_fold` runs every
   `contacts_fold_<something>` before the folded contact goes, so the presses in its thread move to the contact it
   folds into. It is a definer, since the presses are read only. Outside a trigger, a call from someone signed in off
   the office team, or a twin, moves nothing, as the fold's own statements move nothing for them.
8. **`quick_replies_seed(p_mine_for)`** adds the Messages prototype's nineteen lines (v1.178), in its order.
   - Sixteen are the team's, added as the app's (`added_by` and the version's `by_user_id` null).
   - Three are the ones the prototype's viewer keeps as their own, added only when a person is named, as theirs.
   - A line whose words a line already has, or started with, is skipped. A second run adds nothing, and a line the
     team removed or reworded stays as they left it.
   - It is the database's own, with EXECUTE revoked from `anon` and `authenticated`. The migration runs it once, with
     no one named, after the fences.

`SET lock_timeout = '3s'`. Adding `users.title` takes the users table's lock for a moment and checks its rows against
the new CHECK, all null. The three fences close the file, then the seed. Every statement is idempotent, and a second
run changes nothing, which the bed checks.

## The bed

`scripts/pgtest-quick-replies.sh` plays `supabase/tests/quick_replies/20_scenario.sql` after every migration, and
again after this file a second time. It checks:
- The seed's sixteen team lines are there once, as the app's, each with its `added` version, in the prototype's tags.
  A third run adds none. Named, it adds the three as Rosa's own, and nothing after.
- Rosa reads nineteen lines, Maria sixteen, and the superintendent none.
- Rosa adds a line for the team and one of Rosa's own. A blank line, an unknown kind, a bad step id and a line past
  1,000 characters are refused in words.
- Rosa changes its words, then Maria its tags: two versions, each with who and what it was before. A save of both
  writes two, the words first. Nothing changed, a blank save and Rosa's own line by Maria are refused.
- Rosa presses it in Priya's thread and outside one, and Maria reads both presses. Nobody else reads the presses on
  Rosa's own line.
- Removed, it keeps its history and is neither changed nor pressed. Maria brings it back.
- A superintendent, a training account, a twin and someone signed out are refused in words. Nobody writes the tables
  by hand, and `anon` reaches nothing.
- Rosa sets a title, and one past 80 characters is refused.
- Rosa folds Priya into the customer's other Priya, and the presses follow. A call outside a fold moves nothing.

It runs on GitHub's runners through `scripts/sql-beds.txt`. The office Mac has no Docker.

## Verify after the push

1. **The column, the tables and the seed.**

   ```sql
   SELECT count(*) FROM information_schema.columns WHERE table_schema = 'public' AND table_name = 'users' AND column_name = 'title';
   SELECT scope, count(*), count(*) FILTER (WHERE added_by IS NULL) FROM public.quick_replies GROUP BY scope;
   SELECT kind, count(*) FROM public.quick_reply_versions GROUP BY kind;
   ```

   Expect `1`, then `team | 16 | 16`, then `added | 16`.
2. **The grants.**

   ```sql
   SELECT table_name, grantee, string_agg(privilege_type, ',' ORDER BY privilege_type)
   FROM information_schema.role_table_grants
   WHERE table_schema = 'public' AND table_name IN ('quick_replies', 'quick_reply_versions', 'quick_reply_uses')
     AND grantee IN ('anon', 'authenticated')
   GROUP BY 1, 2 ORDER BY 1, 2;
   SELECT proname, prosecdef FROM pg_proc WHERE proname LIKE '%quick_repl%' ORDER BY proname;
   ```

   Expect `authenticated | SELECT` on each table and no `anon` row. Expect `true` for the five changes and
   `contacts_fold_quick_replies`, and `false` for `quick_reply_caller`, `quick_reply_step` and `quick_replies_seed`.
3. `npm run check:migration-drift` is clean.

```sql
DROP FUNCTION IF EXISTS public.quick_replies_seed(uuid);
DROP FUNCTION IF EXISTS public.contacts_fold_quick_replies(uuid, uuid);
DROP FUNCTION IF EXISTS public.press_quick_reply(uuid, uuid);
DROP FUNCTION IF EXISTS public.restore_quick_reply(uuid);
DROP FUNCTION IF EXISTS public.remove_quick_reply(uuid);
DROP FUNCTION IF EXISTS public.edit_quick_reply(uuid, text, text, text);
DROP FUNCTION IF EXISTS public.add_quick_reply(text, text, text, boolean);
DROP FUNCTION IF EXISTS public.quick_reply_step(text, text);
DROP FUNCTION IF EXISTS public.quick_reply_caller(text);
DROP TABLE IF EXISTS public.quick_reply_uses;
DROP TABLE IF EXISTS public.quick_reply_versions;

```
