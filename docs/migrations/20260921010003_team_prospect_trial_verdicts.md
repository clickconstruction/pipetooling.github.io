# 20260921010003_team_prospect_trial_verdicts.sql (2026-09-20, v2.3650)

The helper try-out loop, PR 2 (`to-dos/helper-tryout-loop`): the leader's verdict on a trial helper.

- **`trial_helper_supervisors(p_helper_user_id, p_work_date)`** → `(leader_user_id, job_ledger_id)` — the Supervision rule (`src/lib/people/supervision.ts`, the SQL shape of `supervised_days_with`, v2.3614) from the helper's side: everyone who could run a job the helper was listed (`job_schedule_blocks`) or clocked (`clock_sessions`, not rejected / revoked) on that day — a master, or a helper / sub with `needs_supervision` off, not archived, never the helper. `SECURITY DEFINER`; EXECUTE **revoked from `authenticated`**, granted to `service_role` only (the clock webhook calls it). Nothing reads the Team leads tables.
- **`team_prospect_trial_verdicts`** — `prospect_id` → `team_prospects` (cascade), `leader_user_id` → `users` (cascade), `job_ledger_id` → `jobs_ledger` (set null), `work_date`, `verdict IN ('yes','no','unsure','skipped')`, `note`, timestamps (an `updated_at` touch trigger); **unique `(prospect_id, leader_user_id, work_date)`**. `skipped` is stored so a dismissed card is not dealt again.
- **`can_give_trial_verdict(p_prospect_id, p_work_date)`** — the write gate: the card is `status = 'trial'`, the day is `app_today()` or the day before, and the caller is in `trial_helper_supervisors` for it.
- **RLS**: SELECT — `user_has_team_prospects_access()`, `is_dev()`, or the leader's own rows; INSERT / UPDATE — own rows only, and only while `can_give_trial_verdict` holds; **no DELETE policy**. Ends with `apply_read_only_write_blocks()`, `apply_read_only_stmt_blocks()` and `apply_digital_twin_write_blocks()`.
- **`trial_helpers_i_led_today(p_include_open boolean default false)`** → `jsonb` — the card's feed: trial helpers the caller could run a job with today and yesterday, with the job's label fields, the helper's trial-day count and the caller's own verdict. `false` (the Dashboard) waits until the helper has no open session; `true` (the leader's own clock-out) does not. Yesterday's row leaves once it has any verdict; today's stays so the answer can be changed. `SECURITY DEFINER` — the one narrow window onto a Hiring card for a leader who does not hold the board.

Run before merge on a throwaway Postgres 15 with stub tables: applied twice (idempotent); a listed master and a cleared sub who clocked the same job were the only people asked; a sub who still needs supervision, a master on another job, a write in someone else's name, a three-day-old day and any write after Hire were all refused by RLS; a board holder read every verdict by name and a leader only their own; a client call to `trial_helper_supervisors` was denied.

Apply order: **either** — until it is pushed the Dashboard card's RPC is missing and the card simply does not render (the hook swallows the error). After the push: `supabase functions deploy notify-team-lead-clock`, then `npm run gen-types:linked` (+ the dev-mcp catalog) as the usual `chore(types)` PR, which lets the `as never` casts in `TrialVerdictCards.tsx` / `useTrialVerdictFeed.ts` go.
