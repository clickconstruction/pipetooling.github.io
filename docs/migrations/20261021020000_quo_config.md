# 20261021020000_quo_config.sql (2026-10-21, v2.5718)

The Quo connection in Settings (the owner's ask of 2026-10-21: no terminal in setup). Quo's API key moves into Vault, written from Settings → Phone and texts → **Quo connection** by the owner or a dev through the `quo-config` function and read by `quo-send`, `quo-webhook` and `quo-config` at call time, so the key is set and rotated without a terminal. The `QUO_API_KEY` function secret stays the fallback while Vault holds no key. Three functions, idempotent (`CREATE OR REPLACE`), the service role's only, in the shape of the Docsmit connection's (`20261013160000_mail_config.sql`):

- `quo_secret_set(p_value text, p_saved_by text)` → boolean: makes or replaces the one Vault secret named `quo_api_key`, keeping who saved it (at most 120 characters) as the secret's description; a blank value deletes the secret and answers false.
- `quo_secret_get()` → text: the decrypted key, or null.
- `quo_secret_status()` → jsonb `{ set, saved_at, saved_by }`: whether it is set, the secret's `updated_at` and its description. Never the key.

`EXECUTE` revoked from `PUBLIC`, `anon` and `authenticated`, granted to `service_role`. No table is created, so the three `apply_*` fence calls are not needed; no policy reaches Vault.
