# 20261102040500_file_index.sql (2026-11-02, v2.6319)

Search every file deeply (punch list #240, PR 1): our own text index over every file in the jobs Shared Drive, read by Find a file before Drive's own search.

- **`public.file_index`** — one row per Drive file (`drive_file_id`, Drive's own id, the primary key): the home it was walked up to (`jobs_ledger_id`, `bid_id`, each `ON DELETE SET NULL`, and the job's `customer_id`), which of the job's folders holds it (`folder_kind`: top, plans, pictures, photos, sent, other), the folders between (`path`), `name`, `mime`, `bytes`, `modified_at`, the extracted `text` (at most 200,000 characters) with `text_source` (export, pdf_layer, plain, ocr) or `text_why` (scan, kind, big, slow, error, reading), a PDF's `pages`, `indexed_at`, `checked_at` (the sweep's last look at whether the file is still there), and `search`, a stored tsvector weighted name A, path B, text C. Indexes: GIN on `search`; `jobs_ledger_id`, `bid_id` (partial), `modified_at DESC`, `text_why` (partial, the OCR pass's queue), `checked_at` (the sweep's recheck order).
- **Indexes** — `file_index_search_idx` (GIN over `search`), the partial job, bid and customer keys, `modified_at`, `text_why`, `checked_at`.
- **The sweep's stamp** — `app_settings` `file_index_sweep_last_at` seeded at `now()` (ISO), so the sweep keeps the index current from its first run and the history is the backfill's; set it to `1970-01-01T00:00:00.000Z` to walk the whole drive once. A value ending in `#cursor` is a file's modified time (listed from inclusively, no overlap); a bare one is a wall clock (listed from two minutes back).
- **RLS** — `file_index_select` for `authenticated` under `is_office_or_estimator()` (the roles drive-link's door takes; a digital twin is an estimator, so it read here too until `20261102215000` closed that); no INSERT, UPDATE or DELETE policy for `authenticated` on purpose, since the three writers (`drive-link`'s `index` and `index_job`, the `file-index-sweep` cron, the dev seat's backfill) run as the service role. `anon` is revoked; the three fence calls close the file.
- **`public.search_file_index(words text, max_hits integer DEFAULT 30)`** — SECURITY INVOKER, STABLE: `websearch_to_tsquery('english', words)` against `search`, ranked by `ts_rank_cd`, the top `max_hits` (capped at 100) in a materialized CTE, then `ts_headline` (`MaxWords=35, MinWords=20, StartSel=<mark>, StopSel=</mark>, MaxFragments=1`) over each row's text and the job's `hcp_number`, `click_number`, `job_name` and the bid's `bid_number`, `project_name` joined in. An empty or stopword-only query (`numnode = 0`) answers no rows, so the box falls back to Drive. Execute for `authenticated` and `service_role`.
- **Cron `file-index-sweep`** — `3,13,23,33,43,53 * * * *`, three minutes past the folder sweep's slot: `net.http_post` to `/functions/v1/file-index-sweep` with `{"sweep":{}}` and the Vault `CRON_SECRET`, unscheduled first so a second run leaves one row.

**Apply order**: the client reads the RPC first and falls back to Drive when it is refused, so the client may deploy before the push with nothing lost but the index; push right after the merge all the same (`check:calls-ahead` labels the PR), then deploy `drive-link`, `file-index-sweep` and `dev-mcp` (its catalog).
