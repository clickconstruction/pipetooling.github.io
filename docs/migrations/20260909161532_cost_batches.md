# 20260909161532_cost_batches.sql (2026-09-09, v2.3196)

Cost batches — an audited, reversible entrypoint for moving job cost around, the HR-files pattern (v2.2232) applied to cost. Additive and idempotent; nothing in the client calls it yet. Full contract: `docs/COST_BATCHES.md`.

- **Tables**: `cost_batches` (one row per applied batch: label, reason, source_ref, author_label, author_user_id → users, applied_at, reverted_at, revert_reason, op_count, summary) and `cost_batch_ops` (batch_id, seq, op_type ∈ allocate / supply_repoint / clock_repoint / other_charge / thread_note, target, before_image, after_image, reverted_at; unique (batch_id, seq)). RLS on; dev SELECT policies; **no INSERT/UPDATE/DELETE policies by design** — rows are written only by the definer functions. Both read-only appliers run at the end.
- **`cost_batch_apply(p jsonb, p_dry_run boolean DEFAULT true) → jsonb`** (SECURITY DEFINER): validates and applies a batch in one transaction. `allocate` upserts `mercury_transaction_job_allocations` (optionally deleting the `from_job_id` allocation first, recorded in the before-image) and refuses when the transaction's allocations would exceed the transaction; `supply_repoint` updates `supply_house_invoice_job_allocations.job_id` (refuses a target that already holds the invoice); `clock_repoint` updates `clock_sessions.job_ledger_id` (never onto bid time); `other_charge` inserts `jobs_ledger_materials` with a description that must start with `ESTIMATE`; `thread_note` inserts `jobs_ledger_thread_notes` as the batch's author. Dry run performs the writes, builds the summary, then unwinds them via a private SQLSTATE (`P0DRY`) caught inside the function — the same code path as the real apply. Gate: signed-in callers must be devs; database-role callers pass.
- **`cost_batch_revert(p_batch_id uuid, p_reason text DEFAULT NULL) → jsonb`** (SECURITY DEFINER): restores before-images in reverse seq order, marks ops and batch reverted, leaves one thread note per touched job when the batch has an author. Reverts exactly once.
- **Grants**: EXECUTE on both to `authenticated` (gate inside) and to the new **`cost_agent`** role; revoked from `anon` / PUBLIC.
- **`cost_agent` role**: `LOGIN NOINHERIT`, created without a password (set out-of-band: `ALTER ROLE cost_agent WITH LOGIN PASSWORD '…'`; keep it in `.env.local` as `COST_AGENT_DB_PASSWORD`). USAGE on `public`; SELECT (+ a `cost_agent reads <table>` policy each) on the planning/audit tables: `cost_batches`, `cost_batch_ops`, `mercury_transactions`, `mercury_transaction_job_allocations`, `jobs_ledger`, `jobs_ledger_payments`, `jobs_ledger_invoices`, `jobs_ledger_materials`, `jobs_ledger_thread_notes`, `supply_houses`, `supply_house_invoices`, `supply_house_invoice_job_allocations`, `clock_sessions`, `users`, `people`, `customers`. No direct write on any table.
- **Apply**: `supabase db push` after the v2.3196 merge; either order vs the client is safe (no client caller). Then `npm run gen-types:linked` so the tables/RPCs land in `src/types/database.ts` for the eventual dev screen. Then set the role password.
