# 20261115170000_invoice_due_days.sql (2026-11-15, v2.7341)

A bill's own due day (punch list #341, PR 4): one bill due on a named date. A retainage release, a dated draw once it is billed, a final payment. The contract names a date for that one bill, and neither the job's Pay calendar nor its payer's says it. The day sits at the top of the ladder a bill reads: the bill's own day, the job's calendar, the payer's calendar, the pace guess.

- **`invoice_due_days`** (new table): `invoice_id` (primary key, a `jobs_ledger_invoices` row, cascades on delete), `due_on` (date), `clause` (at most 40 characters), `words` (at most 240), `marked_by`, `marked_at`. One row a bill. No row means the bill reads its calendar, or the pace guess, as before.
- **RLS**: one SELECT policy, `can_read_payment_promises()`. No write policy and no write grant to `authenticated`.
- **`set_invoice_due_day(p_invoice_id uuid, p_due_on date, p_clause text DEFAULT '', p_words text DEFAULT '')`**: SECURITY DEFINER, gated on `can_write_payment_promises()`. Upserts the day with its clause and words, trimmed and cut to the columns' lengths, and stamps the caller; a NULL day deletes the row. Refuses an unknown bill in words.
- Ends with the four fence calls.

Starts with `SET lock_timeout = '3s'`. Idempotent: `CREATE TABLE IF NOT EXISTS`, `DROP POLICY IF EXISTS` before the policy, `CREATE OR REPLACE` for the function. The foreign key takes a brief lock on `jobs_ledger_invoices` while the table is created; with the timeout a busy moment fails the push and it is retried.

Proven on a throwaway copy of the whole schema by section 9 of `npm run test:pg:pay-calendar` (`supabase/tests/pay_calendar/20_scenario.sql`), which also applies it a second time; never on prod.

Apply order: after `20261112190000_invoice_payer_acceptances.sql`, though it needs neither that nor the calendars. The client in the same PR reads the table with the calendars and calls the function. Before the push the read answers none, and a Save is refused as a missing function, so nothing breaks; **push right after the merge**, then `npm run gen-types:linked` as its own `chore(types)` PR.
