# v2.2763 — What customers see: the sample pages need no sign-in (2026-09-04)

Follow-up to v2.2758 / v2.2760. On the deployed site the sample frames inside Settings → What customers see came up "Sign in to the app to view the sample": the public pages run in iframes and the office-JWT gate on the five sample branches depended on the iframe fetch carrying the signed-in session, which it did not reliably do. The owner's call: a hard-coded sample customer is invented data, so it should never have needed a login.

- The sample branches in `get-estimate-for-customer`, `get-bid-proposal-room`, `customer-portal`, `sub-portal` and `get-contract-for-signer` now answer the sample tokens for anyone with the link, over the anon key like every other public request. `_shared/sampleViewer.ts` and `SAMPLE_VIEWER_ROLES` are gone.
- `src/lib/customerSampleMode.ts` no longer imports the Supabase client — the public pages stay client-free as they were before v2.2758; `publicFunctionHeaders` is kept so the call sites read the same.
- `/estimate/accept?t=sample`, `/bid-room?t=sample`, `/portal?t=sample`, `/sub?t=sample`, `/contract/accept?t=sample` (and the `-done` / `-gc` variants) are therefore stable demo links you can hand to anyone. They carry the orange Sample banner and save nothing.
- All five functions redeployed.
