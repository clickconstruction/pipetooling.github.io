# v2.2859 — "Open the job" on every Won moment — the bid shows its job, Copy Bid goes back to copying (2026-09-05)

Journey map Phase 4, **Tier-1 #8** (`JOURNEY_MAP.md` → "Winning a bid never opens the job"; findings J1-F1 / J15-F1–F4, F6, F7; N1). Lands after #9 (the auto-create guard, PR #2579 / v2.2838) per sequencing constraint 4.

**Why.** The only bid-side door to a job was a **Job** section at the bottom of a popover titled **Copy Bid**, behind the unlabelled trade pill in Edit Bid — `prefillBidId` had exactly one caller. Prod adoption: **0 of 815 jobs ever carried `bid_id`**; ≥10 of 24 recent wins were visibly re-typed into New Job by hand (same name, same cents, same day). The bid could never show its job, marking Won anywhere offered no follow-through, and cancelling the multi-GC picker stranded a blank New Job form with no notice.

## What changed

- **One door, everywhere a win is recorded** — [`BidWonJobActions`](../../src/components/bids/BidWonJobActions.tsx):
  - **Edit Bid → Win/Loss row** gains a **Job** block (full variant) — primary **Open the job** (green when the bid reads Won / Started), and once a job exists the chip **"J1007 opened from this bid"** + **Open the job** (opens the Job window via `openEditJob`) + quiet **Create another job**.
  - **Bid Board GC lines** ([`BidBoardGcRows.tsx`](../../src/components/bids/BidBoardGcRows.tsx)) and **Followup → Full bid details → Sent to — by GC** ([`BidPackageSendsDetails.tsx`](../../src/components/bids/BidPackageSendsDetails.tsx)): a pill that reads **won** grows a compact **open the job →** link beside it (row click is stopped). The board variant reuses the v2.2741 `jobsByBidId` index (`jobLink` prop) so it never queries per row; the panel looks the link up.
  - **Waiting to hear** ([`BidsWaitingToHearLens.tsx`](../../src/components/bids/BidsWaitingToHearLens.tsx)): the one-tap **Won** removes the bid from the queue as before, and a green **"You won it — B398 · Project with GC"** strip with **Open the job** stays at the top of the right column until dismissed or used (cleared if the write fails).
  - All four call the existing `openNewJob({ prefillBidId })` — the same `applyPrefillFromBid` the Import door runs. The **Copy Bid** popover lost its Job section and is about copying bids only.
- **Who sees what** — pure kernel [`wonMomentActions.ts`](../../src/lib/bids/wonMomentActions.ts) (`wonMomentActions({ hasJob, role, canCreateJobs? })`, `canCreateJobFromBid`, `bidJobLinkLabel`, `secondConversionMessage`, `jobCreatedTelemetryTarget`, `JOB_CREATED_FROM_BID_EVENT`), tested in `wonMomentActions.test.ts`. Create: dev, master, assistant, controller, **estimator** (the job-form provider is app-level, so the estimator gets it without `/jobs`). Open-existing: the v2.2741 `canSeeBidBoardJobLinks` set. Superintendent (read-only board), subs, helpers: nothing. **Not coupled to `bid_versions.outcome`** (NULL on 41/41 versions ever — J15-N1): every surface passes what it already knows.
- **Bid ↔ job link** — read side is `jobs_ledger.bid_id` (FK `jobs_ledger_bid_id_fkey`, the column the v2.2741 J#### chip and `auto_create_job_from_signed_estimate` already use; the client `createJob` insert has always written it). New hook [`useJobsOpenedFromBid`](../../src/hooks/useJobsOpenedFromBid.ts) (newest first, fail-soft, refetches on `JOB_CREATED_FROM_BID_EVENT`); `Bids.tsx` bumps its `jobsByBidId` index on the same event so the board chip appears without a reload.
- **Second conversion warns** — [`JobFormModal.applyPrefillFromBid`](../../src/components/jobs/JobFormModal.tsx) checks `jobs_ledger` for the bid on the first pass (not on the picker's `forcedGc` re-entry) and asks through the house confirm dialog: *"A job already exists from this bid — J1007 was already opened from B398 · Project. Open it from the bid's Job block, or create another job here."* → **Create another job** / **Cancel**. Cancel is a clean cancel-import (below). Fail-soft for roles whose RLS cannot read jobs.
- **Cancel-import closes cleanly (J15-F4)** — `winningGcPick.closeOnCancel` is set when the form was opened *for* the import (the `prefillBidId` effect passes `{ closeOnCancel: true }`); **Cancel import** on `PickWinningGcModal` (and Cancel on the second-conversion confirm) toasts *"Import cancelled — nothing was filled in, and the bid is unchanged."* and, in that case, closes the form through the guarded `closeFormRef`. From the Import modal on an already-open form the toast shows and the form stays.
- **Birth row — ledger gap noted, telemetry instead.** `job_activity_events` has **no client INSERT policy** (rows come only from SECURITY DEFINER triggers/RPCs) and `jobs_ledger` has **no `AFTER INSERT` trigger** (every activity trigger is `AFTER UPDATE`; only `job_auto_created_from_estimate` writes a birth, and only on the signed-proposal path), so a client-side "Opened from bid B398" row would need a migration — deliberately **not** added in this PR. Instead `createJob` records `ui_nav_clicks` `control = 'job_created'`, `target = 'source:bid:<bid_id>' | 'source:project' | 'source:blank'` via `recordNavClick` (fire-and-forget), which gives the journey map its "jobs from bids" ratio today. **Follow-up (separate PR + `db push`):** an `AFTER INSERT ON jobs_ledger` trigger writing a `job_created` event (`detail.source`, `detail.bid_id`) and the matching `JobActivityEventType`.
