# v2.5985 — Attach the notarized PDF to a lien waiver (2026-10-27)

Phase 0 of the online-notary feasibility study (claude.ai/artifact/K2XJ44HWqQtKEAM9KLsSVg: no-go
on becoming a notary platform, go on one in-house online notary on BlueNotary or Proof), which the
owner took up on 2026-10-27. An online session ends with a sealed, tamper-evident PDF; Print for a
notary (v2.5925, #6251) filed the signed copy only as a Google Drive link. Now the file itself lands
on the release.

## What changed

- **Migration `20261027180000_lien_release_notary_copy_file.sql`**: `job_lien_releases.notary_copy_path`
  (additive) and `job_lien_releases_notary_copy_path_check` — a PDF directly in the release's own
  folder, on a row signed in mode `notary_paper` only. No storage change: the bucket's documented
  policies already admit the office under `<release_id>/`. **Push after merge.**
- **Kernel** ([`lienReleaseNotaryCopy.ts`](../../src/lib/jobs/lienReleaseNotaryCopy.ts), new):
  `lienReleaseNotaryCopy` (the file wins over the link, notary rows only), `notaryCopyFileProblem`
  (a PDF of 1 byte to 4 MB; 4 MB in base64 fits the send's 5.5M-character cap),
  `notaryCopyPdfFilename` and `resumesNotaryHold`; `lienReleaseNotaryCopyPdfPath` in
  [`lienReleaseDocuments.ts`](../../src/lib/jobs/lienReleaseDocuments.ts) names
  `<release_id>/notary-copy-<ms>.pdf`, a new object each time (the bucket has no update policy).
  The audit sentence drops *in ink* when the copy is a stored PDF: an online notary may have sealed
  it electronically.
- **[`LienReleaseModal`](../../src/components/jobs/LienReleaseModal.tsx):** the Out for notary hold
  gains **📎 Attach the notarized PDF** above the Drive link box and the sentence *An online notary
  can also notarize the printed page over video* (SB 1780, effective 2024-01-01). The file is
  checked, stored, then the row is stamped `signed` in mode `notary_paper` with the same stamp the
  link writes (now one `notarySignedStamp`). A store that fails changes nothing. Step 6's Attached
  line reads *The notarized PDF you attached*; a waiver just signed by link offers the attach there
  too, writing only the path.
- **The hold reopens:** the window resumed only drafts and signature requests, so a waiver out for
  a notary fell into *Already on this job* with View and Void once the window closed, and its copy
  could never be filed. It now resumes when the window opens on the held waiver's bill and form, or
  on none (`resumesNotaryHold`); a window opened for another bill or the unconditional follow-up
  makes that waiver instead.
- **[`sendLienReleaseEmail.ts`](../../src/lib/sendLienReleaseEmail.ts):** a notary row with a stored
  PDF attaches that file as `…-notarized.pdf`, says *The attached PDF is the signed, notarized copy*,
  and drops the link line; a failed read sends nothing. **Download PDF** (and the signature inbox,
  through `lienReleaseSignedPdfBlob`) hands over the same file.
- **Guide** *send a GC our lien waiver*: **Print it for a notary** attaches the PDF, says the window
  opens on the held waiver again, the 4 MB rule with the Drive link for bigger scans, and the online
  notary paragraph.

## Tests

`lienReleaseNotary.test.ts` (+8: which copy a row holds, the file rules and the email-cap fit, the
path against the CHECK's pattern, the file name, the inkless audit sentence, the attaching email,
the resume rule), `sendLienReleaseEmail.test.ts` (+2: the notarized file goes and the link line
does not; an unreadable file sends nothing), `lienReleaseInk.test.ts` (+1: Download hands over the
notarized file), and the new `LienReleaseModal.notary.render.test.tsx` (6: the window reopens on the
hold, the attach stores and signs, a photo, an empty file or a 6.2 MB PDF is refused, a failed store
changes nothing, a link-signed waiver takes the file, another bill's window leaves the hold in the
list). The `lien-release-sign` SQL bed's `26_notary_file.sql` files the path through the office's
own policies on a held and a link-signed waiver, refuses a field user and every path the CHECK holds
out, and plays the upload against the bucket's documented policies.

## Not in this change

The GC's account page still serves only `signed_pdf_path`, so a waiver signed before a notary shows
there without a PDF link (as since v2.5925); serving `notary_copy_path` is a `customer-portal`
change with its own deploy. The bucket's documented insert policy admits a master only on his own
job's releases, while the table admits all office staff; such a master pastes the link instead.
