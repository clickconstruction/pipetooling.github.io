## The line (`RobotReadinessLine.tsx`, kernel `robotReadinessLine.ts`)

Under Job Plans / CountTooling Plans in the New Bid and Edit Bid modals. Five tones from one pure kernel: `idle` (no link yet — "Add the plans link and the robots will shadow this bid"), `checking`, `ready` ("Robots will shadow this bid within the hour" + the facts: folder shared · 3 PDFs / plans readable, division, miles, due date, and the sealed-number promise), `blocked` ("Robots can't open these plans yet" / "Robots don't bid this division"), `off` (opted out). Gaps are typed: `plans-unreadable` (with `copyIntake` when the probe wording says unshared — the button copies `drive-intake@pipetooling-drive.iam.gserviceaccount.com`), `discipline` (non-plumbing service type), `distance` (blank, has address → "fills itself when you save"), `address` (no address → the robot will ask before pricing travel). A `blocked` line offers ↻ Check again.

The check is the dispatcher's own probe run against the typed link before the bid exists: plan-fetch gains `probe_url` (query or POST body; **staff JWT only**, a twin is refused; nothing recorded). The component debounces 700 ms, reports non-Drive links without a call, and ignores stale answers by sequence.
