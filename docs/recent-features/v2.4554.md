# v2.4554 — Documents: a copy is kept of what we send (2026-10-05)

The owner, 2026-10-05: *"Every time we send someone something we should keep a record of it in Documents."* Then, on the plan: *"Printing counts as sending · keep the email · office can find it in documents when they need it."* Until now about thirty kinds of paper kept a "sent" date and were drawn again from live data when reopened, so a paper opened later could show other numbers than the one the person received. This is step 1 of the train in [`docs/SENT_COPIES.md`](../SENT_COPIES.md): the foundation and the first paper. One migration (a table and a bucket); no edge function.

## The foundation

- **`sent_documents`** and the private **`sent-documents`** bucket (`supabase/migrations/20261005173119_sent_documents.sql`, doc in `docs/migrations/`): one row per send — kind, title, how, to whom, the jobs / customer / bid / person it is about, the record it was drawn from, the copy's path, type, SHA-256 and size, an email's attachments. Append-only. The office reads; staff who send file; dev deletes.
- [`sentCopies.ts`](../../src/lib/sent/sentCopies.ts) (pure): the row a filing writes (`sentDocumentInsert` — ids that are not ids are dropped, never sent), where a copy lives (`sentCopyPath`), a stored row read back (`parseSentCopy`), the list's lines (`sentCopyLines`: the same copy sent the same way to the same person folds into one line), its words (`sentCopyWords`), how a copy opens (`sentCopyDoor`), the window a kept page opens in (`sentCopyFrameHtml`: the page rides in a sandboxed frame with scripts, forms and navigation off), and who reads (`canReadSentCopies`).
- [`sentCopiesIo.ts`](../../src/lib/sent/sentCopiesIo.ts): `fileSentCopy(filing, body)` — hash the copy, point at the file already kept for that same page or upload a new one, write the row; best effort, never throws, and still writes the row when the copy could not be stored. `printAndFile(html, filing)` — `openHtmlPrintWindow`, then file with `how: 'print'`. `loadSentCopiesForJob`, `openSentCopy`, `openSentFile` (a five-minute signed link).
- **Sent from this job** — [`JobDocumentsSent.tsx`](../../src/components/jobs/JobDocumentsSent.tsx) on the Job window's Documents tab, after the lien paper, for the office (`canReadSentCopies`): newest first, the name opening the copy, *Printed 3 times, last …* for a repeat, an email's attachments as links, *The copy was not kept* when it was not, the newest eight with **Show all N**.
- **The ratchet** — [`sentCopiesCoverage.test.ts`](../../src/lib/sent/sentCopiesCoverage.test.ts) reads the source for every file that prints. Each files a copy, is on `PRINTS_OWED` (23 files today), or is on `NOT_A_SEND` with its reason (our own sheets and reports, a page the other party prints from their portal, pay stubs). A new print fails CI until it has an answer; the owed list only shrinks.

## The first paper

`LienOwnerRecordsModal`: **Print the packet** and **Print the acknowledgment** go through `printAndFile` (`owner_records_packet`, `owner_records_acknowledgment`); **Record it as sent** builds the packet before the save and files it after, with how it went (`hand · email · mail`) and the request's row as its source. The toast reads *Recorded as sent. A copy is in Documents.* `save` now answers the request's row id. The recorded time of a payment carries its year (`formatDenverCalendarDayWithYear`): a payment paid in 2025 and recorded in July 2026 read *recorded Jul 3*.

## Apply order

Client first. Before the push a print still prints, nothing is filed, and the section says no copy is on file. `sent_documents` is reached through casts until `database.ts` is regenerated.
