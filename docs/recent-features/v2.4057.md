# v2.4057 — Write up a change from the Job window and from Job Mode (2026-09-28)

Client only; no migration, no edge function. The follow-up v2.4047 owed: the same door where a field person actually is — the job's own window, and the Job Mode card.

## What changed

- **`useQuickEstimateDoor(userId, role)`** (`src/hooks/`, 3-case hook test) — the one read behind every door: `isQuickEstimateRole` plus the `user_dashboard_buttons` row for key `quick_estimate`. `Dashboard.tsx` drops its own copy of the effect for the hook.
- **Job window** (`DetailJobModal`) — a seventh icon in the header's icon row, before ⚙, on every tab: `WriteUpChangeGlyph` at 20 px in the link colour, aria-label *Write up a change*. It mounts `QuickEstimateWizard` with `initialJobId={jobId}` and `zIndex={1100}` (the window sits at 1004, its stacked windows at 1100) and joins `detailEscBlocked`, so Escape closes the wizard's sheet before it ever reaches the window. Render test: icon opens the dialog; no icon when the door is off.
- **Job Mode card** (`DashboardJobModeCard`) — a quiet link under the action row (the clock-out link's style, in the link colour, with the glyph) on the clocked-in job, or the one ready to start when off the clock. Mounts the wizard itself, since Job Mode's focused view never mounts the Dashboard's copy.
- **Wizard** — `zIndex` prop for the overlay (default unchanged).
- Guides: *job-window-tabs* (the icon row), *job-mode-clocking* (a section), *write-up-a-change-order-from-the-field* (where it is, step 3). PROJECT_DOCUMENTATION's Quick Estimate line names all four doors.
