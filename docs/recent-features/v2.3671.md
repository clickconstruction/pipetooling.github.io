# v2.3671 — Materials by stage, PR 1: the rules, the storage and the factor (2026-09-21)

Migration `20260921163920_bid_takeoff_stage_splits.sql` (push after merge; `docs/migrations/`), client (kernel + IO + one Settings field), no edge function. Proposal + mockups: the Claude artifact *Materials by Stage*. PR 1 of 4; PR 2 the Sheet and the rail, PR 3 the paper, PR 4 the book and the assembly remembering.

## Why

Wendi (estimator), 2026-09-21: *"wanting to add a schedule of values with material breakdown, originating from the takeoffs information. should add a box where you can assign each 'fixture or tie in' to either 1, 2, 3, or a combination which would divide the cost between those stages. once all fixture/tie ins are assigned it should generate numbers for material costs for all 3 stages, with the raw numbers × 1.5."* Today she prints the Rough Takeoff and writes *2, 2, 3, ½* in the margin, then halves on a calculator. The owner's correction on the first draft: *"in an assembly, some parts will be used at various stages so in an assembly you should be able to set the stage for the whole assembly or the individual components."*

The app has stages by name everywhere (Rough In / Top Out / Trim Set), and the exact "By Stage" materials model stages assemblies — but 112 of 113 bids use the Combined sheet, where part lines carry no stage. The existing Cover Letter "Schedule of Values" is a payment schedule (percents by timing); this is a different thing and stays a separate section.

## What shipped

- **Storage** — `bid_takeoff_stage_splits`: one split per scope — the fixture, a part line (or a whole bundle line), or a part inside a bundle line — with three relative weights and a `source`. Missing = inherit from the scope above (part → line → fixture → unassigned). `bids.include_materials_by_stage` (the letter pill, PR 3), `bids.sov_material_factor` (per-bid override), `app_settings` `bid_sov_material_factor_v1` seeded at 1.5.
- **Kernel** — [`materialsByStage.ts`](../../src/lib/bids/materialsByStage.ts) (16 tests): weights ↔ shares, `toggleStage` (click adds / drops a stage and re-evens; Shift makes it the only one; the last one off = unassigned), `parseSharesText` ("70 / 30" over the lit stages), `describeWeights` ("½ · ½", "70 · 30"), the scope walk, `bundleComponentShares` (a bundle whose parts disagree splits its price by catalog value; a part with no catalog price counts as an average priced part so it never carries $0), `computeMaterialsByStage` (per-line dollars × count, each fixture's order-rounding share following its staged dollars, raw → × factor → shares, incomplete fixtures, own-split counts), `scaleToContract`, `defaultSplitForFixture` + `planRuleFill` + `describeRulePlan` (the rules keep hand-set splits and refresh rule ones), `parseSovMaterialFactor` (1–5, else 1.5). The tests pin Wendi's SpaceX page: nine rows, her marks `2, 2, 3, 2, 2, 2, 2, ½, ½`, her halves.
- **IO** — [`materialsByStageIo.ts`](../../src/lib/bids/materialsByStageIo.ts): `loadStageSplitsForBid`, `saveStageSplit` (select then insert / update / delete — the unique index coalesces NULLs, so PostgREST cannot upsert on it), `loadSovMaterialFactorDefault`, `loadBundlePartsForSplits` (only bundles with a part-level split load their parts), and `loadMaterialsByStageForBid` — the one door the paper will use so every document says what the rail says.
- **Settings** — Templates & testing → Bid Cover Letter Defaults: the factor field (1–5; saving 1.5 is the seeded default).
- Types hand-added to `src/types/database.ts` (regenerate after the push).

## Decisions taken as drawn

Boxes read 1 · 2 · 3 with the stage name in the tooltip; the factor is a company number with a per-bid override; the paper stays internal-first (the letter pill is off by default). Rules: waste ½ Rough In · ½ Top Out; water / gas / vent → Top Out; drains, cleanouts, floor sinks, interceptors, sample wells → Rough In; valves, arrestors, TMVs → Top Out; set fixtures → Trim Set; allowances (travel, rentals, permits) → no stage.
