# v2.4393 — Takeoffs: a new version shows its stage boxes right away (2026-10-02)

Found by the live test of v2.4388 (punch list #78) on BP398 *ZZ Test*, the night it merged. The owner had asked for the work to be tested when it was live, so that no estimator would meet a problem the next morning.

## What was wrong
v2.4388 made `create_bid_version` copy a Combined takeoff's stage boxes onto the new version, and it does: its migration was on prod and the rows were there. But Takeoffs read `bid_takeoff_stage_splits` once, when the bid opened (`BidsTakeoffTab`'s load effect ran on the bid id and the bid's factor only). The picker switches to a version the moment it is made, so the new version drew with the list read before it existed: no box lit, and the Stages panel said *none staged yet*. Opening the bid again showed them. A box set on one version in another window had the same wait.

## What changed
- The load effect in [`BidsTakeoffTab.tsx`](../../src/components/bids/BidsTakeoffTab.tsx) also runs when `selectedBidVersionId` changes. One small read per version switch.
- [`BidsTakeoffTab.render.test.tsx`](../../src/components/bids/BidsTakeoffTab.render.test.tsx): a version change reads the boxes again. It fails without the change.

## Walked live
Headless Playwright on the worktree dev server against prod, as dev, on BP398 only. A box set on *Toilets* in *To Plans* (Rough In, $3,244.90 → $4,867.35 at the company factor), then **+ version** from *To Plans*.
- **Before this change:** the new version showed 0 boxes lit. After a reload it showed the same box and the same $4,867.35, which is what proved the copy itself was right.
- **With this change:** the new version shows the box and the same Stages panel with no reload.
- The test version was deleted and the box taken off again. *To Plans* reads exactly as it did before the test.

No migration, no edge function.
