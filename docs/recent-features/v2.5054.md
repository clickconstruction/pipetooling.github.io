# v2.5054 — Division 22 rules: the groundwork for the rules manager (2026-10-09)

This is PR 1 of the Division 22 rules manager train (`to-dos/division-22-rules-manager.md`; the owner picked the full manager on 2026-10-09, and Punchlist approved the train). It is a kernel only: no UI, no database change.

## What changed

**`src/lib/specSectionRules.ts`** (new) is the manager's pure kernel. It uses the same rule order and the same pattern test as `classifySpecSection`, so it can never disagree with how a name is classified.
- `ruleStandings(rules, names)`: each rule against the audit's names, with spellings folded as the audit folds them.
  - `deciding`: the names it decides, with their bids and a most-bids sample.
  - `shadowed`: names it catches but an earlier rule decides, with which rule.
  - `idle`: catches nothing.
- `previewRuleChange(rules, names, change)`: what a draft add, edit or delete would do before it is saved.
  - Every name whose outcome or section changes, most bids first.
  - Counted as newly coded, newly uncoded and recoded.
  - Coverage before and after. A deliberate no-code counts as covered, as the audit counts it.
- `validateRuleDraft(draft, rules, sections, editingId?)`:
  - It refuses an empty pattern, a section that does not exist, an order that is not a whole number of 1 or more, and a second rule looking for the same words the same way, in any case.
  - It warns on a two-letter `contains` or `starts with` pattern (the "CO" catches COPPER case).
- `priorityBand(priority)`: the ledger's bands, a hint only (seeded names under 60, pinned names 60–99, patterns 100–699, catch-alls 700 and up).
- `groupRulesBySection(rules, sections)`: every section in code order with its rules in deciding order, the no-code rules last, and a rule naming an unknown section still listed.
- `applyRuleChange` and `orderRules`: the helpers the preview uses.

**`to-dos/division-22-rules-manager.md`** now holds the approved five-PR train.
