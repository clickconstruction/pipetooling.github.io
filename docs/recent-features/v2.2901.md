# v2.2901 — A bid visit reads as a bid visit everywhere: one title helper, tinted cards, bids in the commitment matrix (2026-09-05)

Journey-map Tier-2 #22 (J18-F4 / F5 / F6 / F7, cluster C36 "bid visits are second-class on the schedule"). Bid-anchored `job_schedule_blocks` (v2.1613/1624) reached the data model, the picker, and — since v2.2861 — the "open it" gesture, but not the identity line: the Day tab drew a scheduled bid as "— · Job" while the Clocked line under it read "BP375 · SPACEX BA-02N Architectural"; click-number-only jobs printed "— · name" on the Day tab and "J983 · name" on the People grid; bid and job cards were pixel-identical; the Jobs matrix skipped bid blocks. Two roots: `jobTitleById` was built from jobs only and `bidTitleById` only from clock-session bid ids, and eight sites called the 2-arg `formatScheduleDispatchHubJobTitle(hcp, name)` that drops `click_number`.

**Client only — no migration, no edge function, no telemetry.**

- [`lib/scheduleBlockTitle.ts`](../../src/lib/scheduleBlockTitle.ts) (new, pure, tested — 19 cases):
  - `scheduleBlockTitle({ kind: 'job', hcpNumber, jobTitle, clickNumber } | { kind: 'bid', bidTitle })` — `J<hcp or click number> · <name>` (`— · Job` only when both numbers are missing); `Bid visit · <title>` for bids, bare `Bid visit` when the bid could not be named (RLS-hidden). `formatScheduleDispatchHubJobTitle` is now a positional wrapper over the job branch, so there is one implementation.
  - `collectScheduledBidIds(blocks, sessions)` — the bids a loader must name: block anchors ∪ clock-session bids (before: sessions only).
  - `buildBidTitleById(rows, prefixMap | null)` — per-trade prefix (`BP375 · …`) with a map, the hub's plain `B375 · …` without.
  - `addBidAnchorTitles(jobTitleById, bidTitleById)` — adds `bid:<uuid>` → `Bid visit · <title>` so every anchor-keyed lookup (`blocksToSegments`, search, add-block timeline, block modal title, reorder modal) resolves for bids.
  - `blocksToBidWeekMatrixRows(blocks, titleForAnchorId)` — Jobs-matrix rows for bids with a block this week (total + per-day counts, sorted most blocks first).
- [`lib/scheduleDispatchHub.ts`](../../src/lib/scheduleDispatchHub.ts): `fetchBidTitlesForScheduleBlocks(bidIds, prefixMap, operationName)` — one RLS-limited `bids` SELECT replacing the four copy-pasted "bids for clock sessions" blocks in the loaders below.
- **The eight 2-arg sites now pass `click_number`** via the kernel: [`QuickfillScheduleSection.tsx`](../../src/components/quickfill/QuickfillScheduleSection.tsx) (picker search, picker `displayTitle`, `jobTitleById` build), [`usePersonDayScheduleData.ts`](../../src/hooks/usePersonDayScheduleData.ts), [`usePersonWeekScheduleData.ts`](../../src/hooks/usePersonWeekScheduleData.ts), [`usePersonMonthScheduleData.ts`](../../src/hooks/usePersonMonthScheduleData.ts), [`UserDayScheduleSection.tsx`](../../src/components/userReview/UserDayScheduleSection.tsx) (picker search + `displayTitle`). The same four loaders now fetch titles for **scheduled** bids (block anchors) as well as clocked ones and merge `bid:` anchor entries into `jobTitleById`; the Clocked line's `bidTitleById` (keyed by bid uuid) is unchanged.
- [`ScheduleDispatchHubPage.tsx`](../../src/components/schedule/ScheduleDispatchHubPage.tsx): `hubJobTitleById`'s `bid:` entries go through `scheduleBlockTitle` ("Bid visit · B408 · Project"); new `hubScheduledBidTitleById` — Phase C fetches titles for bids that have a block this week but fell out of the schedulable list (marked lost / archived after scheduling), which previously rendered "— · Job"; `hubBidMatrixRows` → new `bidRows` prop.
- [`ScheduleDispatchHub.tsx`](../../src/components/schedule/ScheduleDispatchHub.tsx):
  - `HubPeopleBlockCard` bid branch (`block.job_id == null`): card `--bg-violet-100` / `--border-violet` / `--text-violet-800`, grip strip and time line in the violet ramp, a `bid` chip (`--bg-violet-200`) before the title; the title button opens the bid via `onOpenJob(anchor)` → `scheduleBlockTarget` (there is no Job Detail for a bid), the time-range button already did. A linked-group accent still wins the background/border; the chip stays.
  - `HubJobsPanel` gains `bidRows` (shell prop, default `[]`): rendered after the job rows with a violet sticky title cell, the same day-column cells, and an `Open` button (violet) → `onOpenJob('bid:<uuid>')` → Edit Bid. Search matches the bid title; the "Only jobs with blocks this week" checkbox is moot for bid rows (they exist only because they have blocks); the empty-state copy considers both lists.

**Matrix decision.** The by-design skip in `blocksToJobWeekSummaries` / `fetchJobScheduleBlockWeekSummaries` is kept as-is: job rows come from the jobs ledger (every job, blocks or not) and are aggregated by job id; bids get a sibling kernel and a separate prop rather than being folded into `hubMergedRows`, because that array also feeds the assign picker (`hubAssignJobPickerRows`) and the `?placeJob=` lookup — merging bids there would duplicate the picker's own bid rows. Full bid rows ("Bid visit · B408 · Project", per-day counts, Open) rather than a "+N bid visits" line: the matrix is the "what are we committed to" audit and a bid meeting is a commitment.

**Superintendent / Dispatch Mode.** Bid reads stay RLS-limited: `fetchBidTitlesForScheduleBlocks` returns no entry for a hidden bid, so the block renders as a bare "Bid visit" instead of leaking a title; `job_schedule_blocks` visibility is untouched. The Dispatch Mode agenda (`QuickfillScheduleSection` with `agendaVariant`) inherits the new labels through `blocksToSegments`; nothing else changed there.

**Docs.** SCHEDULE_DISPATCH_ARCHITECTURE (anchors note, Jobs panel dossier, block card), QUICKFILL_ARCHITECTURE (day data engine loader), help guide `schedule-dispatch` ("Scheduling bid work").
