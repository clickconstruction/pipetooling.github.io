# v2.7973 — Papers: a link in a job's email can be kept as a paper (2026-11-19)

Punch list #368, a follow-up to v2.7954 and v2.7969. Client only: no migration and no function.

## The wrinkle

Two screens drew **Keep this mail as a paper** by two rules. My email's reader drew it on every mail tagged to a job. The mail's window in Messages drew it only on a mail that carried a file. Neither rule fit how papers arrive.

A read of prod on 2026-11-19: of the 47 emails on Pipeline jobs, 10 carry a real file, 12 carry a link to a file and no real file, and 25 carry neither. Almost every paper the app holds is a Drive link and no file. So My email offered the press on 25 mails with nothing a paper could hold, and Messages withheld it from the 12 whose link was the paper.

## The rule

One rule for both screens, in one kernel, `src/lib/papers/mailPaperLinks.ts`: a job's email earns the press when it carries a real file or a link to a file on a file host (`mailHasPaper`). A real file is one `isInlinePicture` does not catch (v2.7954). A file host is one `fileLinks.ts` knows: Google Drive, Dropbox, Box, WeTransfer, OneDrive, SharePoint.

- **Messages**: `viewerPresses` reads a new fact, `links`, beside `files`. Only the job's paper reads it. The bid's **Keep its files on the bid…** still needs a file, since it files bytes into a set.
- **My email**: the reader draws the door once the mail is read, and only when the rule holds. It finds the links in the mail's own words (`fileLinksInWords`, the same two reads `gmailMessage.ts` makes), since the opened mail carries no list of them.
- **The form**: the first link fills the **Link** box, with a line that says so and **Open it** to check it. A mail with more than one link adds a **Mail's links** pick (*1. Google Doc*, *2. Drive folder*, `mailLinkChoices`). A link typed over them is kept as typed.

## One link stored twice

On real mail a pasted Drive link is on the line twice: once as the HTML's link, and once from the text with U+FFFC on its end, the mark an email program leaves where the link's preview picture sat. `mailPaperLinks` cleans what clings to a link's end and counts each link once, so such a mail offers one link and no pick.

The stored rows are untouched: the clean-up is in the client's read. The reader that stores the link twice is `readGmailMessage`, a kernel the functions copy, and it is left for its own change.

## What a person sees

- The five job emails of v2.7954, a Drive link and Gmail's picture of it, have the press again. It is there for the link now. The picture still counts as no file and stays out of the paper's folder (v2.7969).
- A job's email with only words, or only a signature's logo, has no press in My email any more.
