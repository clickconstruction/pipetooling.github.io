# v2.5987 — A waiver signed by code shows his signature on the page, and says how he signed (2026-10-27)

The waiver signing train's live walk on prod (2026-10-27, the owner's word: Sample assistant, Sample estimator and
Sample leader's code on ZZ rows, cleaned up after) passed all three flows (#6248 code signing, #6251 print for a
notary, #6296 the Bids tab's code door) and found three small things. This fixes them.

## What changed

- **The sign window reads the code's status once** ([`LienReleaseSignModal`](../../src/components/jobs/LienReleaseSignModal.tsx)):
  its status effect keyed on the whole `presentSigner` object, and the Bids tab passed a fresh object each render, so
  `lien_sign_code_status` fired on every render of the tab, about three times a second on prod while the window sat
  open. The effect now keys on the signer's id, and
  [`BidLienReleaseTab`](../../src/components/bids/BidLienReleaseTab.tsx) passes its stable leader object.
- **Step 5 says how he signed** (`lienReleaseSignedHow` in
  [`lienReleaseLifecycle.ts`](../../src/lib/jobs/lienReleaseLifecycle.ts)): *by Sample leader · with his code on
  Sample assistant's screen* (code), *drawn on …'s screen* (draw), *typed on …'s screen* (type), *in ink before a
  notary* (notary paper), nothing more from his own desk. It said *drawn* for every signature made on another's screen.
- **The page writes a typed or code signature** (`lienReleaseTypedName`;
  [`LienWaiverFootPreview`](../../src/components/jobs/LienWaiverFootPreview.tsx) gains `typedName`, drawn in the cursive
  face above the rule): the Release of Lien window's page and the Bids tab's page
  ([`TradeWaiverPaperView`](../../src/components/gc/GcTradeWaiverPaper.tsx) passes it through) showed only the name and
  the date under a bare line, while the print, the PDF and the email carried the cursive name. A drawn signature still
  shows its stored ink; notary paper shows none (its signature is on the paper).
