## What shipped

- **`src/lib/companyOwner.ts`** (new; +4 tests): `chooseCompanyOwnerUserId` — the `company_owner_user_id` settings row, else the legacy `job_owner_override_default`, else the single live master, else the signed-in user (mirrors the SQL helper); `resolveCompanyOwnerUserId` (one round-trip a minute, never throws); `invalidateCompanyOwnerCache`.
- **Every owner resolver reads it**: `chooseJobOwnerFromOverrideRows` / `resolveEffectiveJobMasterUserId` (company row first, project owner still wins for project-linked jobs; +1 test), `resolveEstimateMasterUserId` (estimates, the Bids → Estimates CO bridge, the Quick Estimate wizard), Prospects `getEffectiveMasterId`, the job form's create-customer path.
- **Pickers removed**: the "Customer Master" select and its adoption lookup in `NewCustomerForm`, `EditCustomerForm` (with the Advanced block and the merge row) and `CustomerForm`; edit never rewrites `master_user_id`.
- **Cross-master filters retired** in the job form kernels — `resolveCustomerIdForJobPayload` / `resolveGcCustomerIdForJobPayload` keep an explicit pick and resolve by name across every account, `computeSimilarCustomersForCreate` offers every match, `customerListImpliesLinkedRow` is name-only (tests rewritten).

- **Backups**: the People and Full exports no longer include `master_assistants` / `master_shares`.
- Guides: `set-the-company-owner-account` (new, dev), `add-a-customer`, `put-clocked-hours-on-the-right-job`. Docs: `ACCESS_CONTROL.md`, `GLOSSARY.md`, the plan doc's progress.
