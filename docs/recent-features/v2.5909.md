# v2.5909 — A batch button says its count (2026-10-26)

Punch list #184, sweep A, PR 1 of the plan in `to-dos/consistency-sweeps/README.md` → *Sweep A*. The rule (`CLAUDE.md` → *Do what is ready, never all or nothing*): a button that acts on many rows says how many it will act on and how many it holds, acts on the ready ones, lists the held ones with the reason and a door, and is dead only when nothing is ready. The Lien desk's run set the shape (v2.5533, `runRecordWords`); this PR makes it a shared kernel, puts the count on the sites whose array was already in scope, and adds the check that keeps the next *Approve all* from merging.

## The kernel

`src/lib/batchWords.ts`, pure, with `batchWords.test.ts`:

- `batchWords({ verb, ready, held, heldWhy?, noun? })` → `{ button, foot, dead }` in the Lien run's shape. `ready 4, held 0` → *Send 4* (*Send 4 requests* with the noun), no foot. `ready 3, held 1, heldWhy 'has no email'` → *Send 3 · 1 has no email ▸* with the foot *1 is held. It stays here with the reason. The 3 ready ones send now.* (*2 are held. They stay…*; *The 1 ready one sends now.*). `ready 0, held 2` → *Send ▸*, dead, foot *Nothing is ready to send. Fix what is marked in red, then send.* `ready 0, held 0` → *Send*, dead, no foot. `heldWhy` takes one phrase or `{ one, many }` (*1 typed waits* / *2 typed wait*). Every foot sentence passes `plainWordsFailures`.
- `countedLabel(verb, n, noun?)` for a button with no holds: *Mark 5 opened*, *Move 1 session*, *Pin for 4 users*; at zero the bare verb and its noun (*Pin for users*) for a dead button. A noun is one word that takes `s`/`es` (*punch* → *punches*) or a tuple when it does not change (`['opened', 'opened']`).

## The check

`scripts/codemods/batch-label-sweep.mjs --check`, `npm run check:batch-words`, a step in `ci.yml` and `deploy.yml` (*A batch button says its count*). Parsed with the TypeScript compiler over `src/**/*.tsx` minus tests. A label is static when it is spelled only by string literals: the JSX text in a `<button>`, a `{busy ? '…' : '…'}` child made of literals, or a `label=` / `children=` prop that is a literal; one live expression in the children (`{n}`) makes it dynamic and it is left alone. The rule as planned (any *all* / *selected* / *shown* / *remaining* with no digit) matched 80 labels, most of them filter chips (*All*, *‹ All people*) and view verbs (*Fit all*, *Fold all*), so it was narrowed by shape rather than by a growing phrase list: the key word must be the label's second word (*Approve all*, *Delete all shown*, *Generate remaining*), or follow one preposition (*Send to all*), or end it (*Rerun Google for selected*); a label whose first word is the key word is a chip, and one with the word deeper in a sentence (*Needed after all*) is prose. View verbs (*show*, *hide*, *fold*, *fit*, *select*, *read*, *pause*…) and one-act verbs (*print*, *export*, *share*, *refresh*: one file, one email) are allowed by the verb; a label naming a filter is a view; `ALLOW` holds three bare resets (*Clear selection*, *Clear all*, *Clear all checks*). `SKIP` names one file with the reason: Settings → Dashboard's four *Unpin All* need the pinned users' count, which lives in `useSettingsFinancialPins` and is edited away by the ticks before the press — the hand PR adds it and drops the entry. The check prints `file:line: <label>` and *a batch button says its count: `batchWords` in src/lib/batchWords.ts*.

## Is this the best we can do?

The kernel's foot is one shape for every desk, so a surface that needs its own words (the Lien run's *stays in the pile*) keeps its own kernel and the check does not care, since its label is dynamic. The check judges shape, not meaning: *Send to everyone* would pass it. That is the trade for a rule a reviewer can read in one sentence and that found no false hit on today's tree; a verb list that grows is still a list, and the next word that fools it is a line in the fragment that adds it. The seven extra fixes went in because the count was one identifier away; where it was not (Unpin All) the label waits rather than guessing.
