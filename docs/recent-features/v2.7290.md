# v2.7290 — SendPurpose off quo/send.ts: the dev seat stops uploading the Quo send kernel (punch list #359, PR 3) (2026-11-14)

Infra only: no screen and no running code changes. The third cut on the #359 card.

## Why

`lib/quo/textsSwitch.ts` imported `type SendPurpose` from `lib/quo/send.ts`, the Quo send kernel, which imports the events (32 KB), the text's composer, the boxes and the thread's types. dev-mcp reads the switch through `_shared/devMcpBill.ts` (the Billed text waits on it) and sends no text, so it uploaded 84 KB of send kernel for five string literals. quo-send, quo-webhook, messages-nudge-dispatch, receipt-request and walk use the kernel's code and keep it.

## What changed

- **`src/lib/quo/sendPurpose.ts`**, new: `SendPurpose`, moved with its comment. The file imports nothing.
- **`src/lib/quo/send.ts`** imports the type from it and re-exports it, so every reader of the send kernel imports as before.
- **`src/lib/quo/textsSwitch.ts`** imports the type from `sendPurpose`.
- **The copy**: the generator's rule for a file of types that imports nothing points the copy at the file in src with its `.ts` (`../../../../../../src/lib/quo/sendPurpose.ts`, as it does the schedule's types), so `textsSwitch.ts` and `send.ts` in the copy name that file and the deploy uploads it, 1 KB. It is not an entry: `edgeKernels.test.ts` holds that every entry is reached by a running bundle, and a type reaches no bundle.
- **`edgeUploadGraph.test.ts`** holds it: dev-mcp uploads neither `quo/send.ts` nor `quo/events.ts`, and reaches `sendPurpose.ts` through the switch; quo-send keeps the kernel.

## Is this the best we can do?

- The switch could take `purpose: string` and lose the type; the type is what keeps a new purpose from slipping past `switchGates`, so it stays.
- `devMcpBill.ts` reads the switch for `TEXTS_SWITCH_KEY` and `textsAreOn`, two lines; the switch's own file is 3 KB, nothing more to cut there.
- The next sliver chain in dev-mcp is `overheadPartsAccountingBuckets.ts` → `overheadOfficePartsReads.ts` for `type OverheadPartsDetailLine` (74 KB), PR 4 on the card.
