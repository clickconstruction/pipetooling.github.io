# v2.2558 — Job Mode day rail, unvisited-aware Next Job, reachable Clock Out (2026-08-31)

Field reports: Job Mode had **no clock-out anywhere** (the real `ClockInOutButton` is mounted visually hidden in the Job Mode early return, only to power the card's bridge calls), and working jobs out of order trapped techs — the picker only looked forward in time order, so a skipped job was never offered again and the day dead-ended on a disabled gray "Last job of the day". Design review + interactive mockup preceded the build (Day Rail concept).

- **`src/lib/jobModePickCurrentNext.ts`**: `pickCurrentAndNextScheduleBlock` gains optional `visitedJobIds` (jobs with a closed session today). "Next" now means next *unvisited* different job — roll forward in time order first, then wrap back to the earliest skipped job; `on-scheduled-job-last` only when nothing unvisited remains. No-session / on-bid / off-schedule entry points aim at the first unvisited block (right restart after a mid-day clock-out). 7 new/updated tests.
- **`src/lib/jobModeDayRail.ts`** (new, +7 tests): collapses today's `job_schedule_blocks` to one row per job with status `done` / `current` / `still-open` (unvisited but the tech is already past it) / `upcoming`, plus done/total counts.
- **`DashboardJobModeCard`**: renders the day rail ("Today · N of M done") between header and buttons — done ✓ rows muted, current row green-ringed with NOW, skipped rows amber "STILL OPEN"; open rows are tappable and open the advance sheet preselected on that job (start-first intent when not clocked in). New third query in `reload()` for today's closed sessions (`visitedJobIds`); realtime on `clock_sessions` keeps it fresh. New prop `canClockOut` (Dashboard passes `!dashboardSelfIsSalary`).
- **Clock Out in Job Mode**: `UpdateFocusOpenerBridgeContext` gains `registerClockOutOpener`/`requestClockOut`; `ClockInOutButton` registers its guarded `handleClockOutClick` (tally gate → review modal → report nudge) unless `salaryUiActive`. The card uses it three ways: the `on-scheduled-job-last` state becomes a red **Wrap Up Day** button (salaried users keep the informational disabled label), a quiet underlined **Clock out** link sits under the button row while clocked in, and the advance sheet offers **Done for the day**.
- **`JobModeAdvanceNotesModal`** → "Where to next?" sheet: keeps the notes input, adds a destination radio list (today's still-open jobs, suggested next tagged, preselected from the caller) and an optional dashed "Done for the day" row that hands off to the clock-out flow (confirm turns red "Clock Out").
- Help guide `src/content/help/job-mode-clocking.md` updated: day rail section, wrap-up/clock-out flows documented (clocking *out* was previously undocumented).

Kernel behavior change to note: with `visitedJobIds` omitted, wrap-back still applies (all jobs count as unvisited) — the old "forward-only" reading of a 2-job day where the tech starts on the later job now offers the earlier one instead of declaring the day over.
