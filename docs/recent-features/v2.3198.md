# v2.3198 — Pipeline row: the stage bar (mock-up A′, "one bar, two channels") (2026-09-09)

Client only — no migration. Owner-approved mock-up *Stages on the Pipeline Row*, variant A′, with the long-name rules agreed afterwards ("what if the text of the line items is too long?").

## What changed

On a job split into **Order** stages, the Pipeline row's **Progress & payment** cell replaces its paid/billed/unbilled money bar (and the yellow % dot) with the stages themselves:

- **Chips** — `① Rough → ② Top Out 60% → ③ Trim`. Green disc with a ✓ for a done stage, blue for the live one (with its percent when known), outlined numbers for what comes later. The full name always rides the tooltip.
- **One bar** — segments are the stages, sized by their share of the job's stage money (a $500 stage beside a $30k one is floored at 10 % so it still reads; equal shares when no stage carries a price). The **fill** is work: the crew's stage report, else the job's own % spread by weight (done stages full, the remainder on the live stage). The **3 px bottom edge** is that stage's draw: green paid · blue billed · amber ready to bill · gray nothing yet. Fill is never money and the edge is never work, so a full fill over an amber edge reads "passed, draw not sent" and a 40 % fill over a blue edge reads "billed ahead of the work". Each segment's tooltip is the plan's own line ("Stage 2 · on site · 60% · draw 2 after it passes").
- **Caption** — `Stage 2 of 3 · Top Out 60% · draw 1 paid`; amber when a draw is owed, green for `All 3 stages done · paid in full`.
- **Money rows** shrink to **Paid / Billed / Left on Job** — the bar now says which stage, so Unbilled goes. The `% done` box and `$X bid` stay on top. Jobs without an Order stage keep the classic cell untouched.

## Fitting long names

`stageShortLabel` shortens by rule: the plumbing vocabulary by dictionary (Rough In → Rough, Trim Set → Trim, Underground → Ground, Water heater → Heater …), then a leading "Stage 2 —" / "Phase 1:" prefix is dropped and the first word kept when it is ten characters or fewer, else nine characters and an ellipsis. `fitStageChips` measures the strip (ResizeObserver) and collapses in tiers — later stages to numbers first, then done ones, then the live name clipped, then numbers only — so the live stage keeps its name longest. On the desktop table (cell ≈ 190 px) J892 lands on tier 1 (`① Rough → ② → ③`); the phone card shows every name.
