# v2.7645 — Signed contracts: each one is now filed in its job's Drive folder, and Find a file finds it (2026-11-17)

Punch list #377, PR 4 of six: the sweep switched on, and the Contract window's Drive line. This is the step where papers start to file by themselves.

## What changed

- **Migration `20261117233000_job_contract_drive_sweep_cron.sql`.** One cron row, `job-contract-drive-sweep`, every ten minutes. It calls only while a paper is due, by the same rule the function uses. Its first run is the backfill.
- **A Drive line on the Contract window's signed rail** (`ContractDriveBlock.tsx`, its own file), between Keep and Later. It reads from the rules' `contractDriveLine`:
  - *In the job's Drive folder · Team only › Contracts · filed Nov 14*, with **Open in Drive**;
  - *In Drive, where the office put it*, with the file's place read from the file index when the index has it;
  - *Not in Drive yet. The app files it within ten minutes*, with **File it in Drive now**;
  - a hold in amber, with its reason, its door and **Try again**;
  - *Voided. The Drive copy is renamed VOIDED and kept.*
- **The doors.** *Open Where files go*, *Open the job's Edit tab*, *Open the job's folder*, and **Add the scan**, which opens a file picker on a signed record that has no file. The scan goes to the record's own paper path in the contract bucket, the row keeps it, and the paper is filed at once. A file past 25 MB is refused before it uploads, with what to do.
- **The press** (`src/lib/jobs/jobContractDriveIo.ts`). It reads the function's answer, updates the line from the row's own Drive columns as the function returns them, and says what happened. A call that fails names its reason through `formatErrorMessage` and leaves the line as it was. A filing clears the Contract sweep's kept Drive scan in the tab.
- **The office's own writes ask at once** (`jobContractDriveQuiet.ts`): a signed paper filed, a GC's own paper saved, a job added to a paper over several jobs, a paper voided or taken off a job. The ask is never awaited and never throws, so it cannot hold up or fail the write that made it. The sweep is the net.
- **A paper over several jobs asks once its rows are whole.** `fileSignedJobContract` takes `driveLater`, so the group write sets the group and each row's own copy of the scan first. Otherwise the first ask would file a row that does not yet name the jobs the paper covers.
- **Guides.** *Get a job contract signed* gains *The signed copy in Google Drive*. *Find a file when you do not know where it is* says a signed contract is in the search.
- **`docs/ACCESS_CONTROL.md`** says an estimator reads a filed contract through the index, Find a file and the jobs drive, and that the owner settled it.

## A limit worth knowing

A copy's name is made when it is filed. When a job is later added to a paper, the copies already filed keep the name they had, and only the new job's copy says *covers 251, 825 and 843*. Renaming the earlier copies is not built.
