# v2.2522 — pipetooling.com sw.js tombstone: un-brick returning visitors (2026-08-30)

Post-cutover (v2.2440) bug report: `pipetooling.com/sign-in` showed Chrome's
`ERR_FAILED` "site can't be reached" page for returning visitors, despite the
Cloudflare 301 to clicktooling.com working perfectly for fresh visitors (curl
confirmed). Root cause: the old PWA service worker registered on the
pipetooling.com origin intercepts navigations, and a service worker cannot
satisfy a navigation with a cross-origin-redirected response — so once its
precache is gone, every page load dies at `net::ERR_FAILED` before the redirect
is ever seen. It also can never fix itself: the browser's `/sw.js` update check
hits the same zone-wide 301, and a cross-origin redirect counts as a failed
script fetch (only a 404/410 auto-unregisters a registration).

- **New `scripts/cloudflare/sw-tombstone.worker.js`** — reference copy (same
  convention as `portal-link-shell.worker.js`) of the `sw-tombstone` Worker on
  the pipetooling.com zone, routed at `*pipetooling.com/sw.js`. It serves a
  self-destructing service worker (200, `application/javascript`, no-store):
  `skipWaiting` on install; on activate it deletes all caches, claims clients,
  re-navigates open tabs (which then follow the 301 to clicktooling.com), and
  unregisters the registration. Each affected device heals on its next visit's
  update check — one reload at most.
- **Cloudflare zone redirect rule edited** to exclude `/sw.js` (custom
  expression: hostname match AND `URI Path ne "/sw.js"`) — Single Redirects
  execute before Workers, so without the carve-out the Worker route is
  unreachable. Rule + Worker are kept forever, like the redirect itself.
- **`docs/DOMAIN_CUTOVER.md`** — new "After cutover" bullet documenting the
  mechanism, the verify command (`curl -i https://pipetooling.com/sw.js` →
  expect 200 JS, not 301), and the warning that the old clicktooling.com app
  will need the same tombstone on its zone when it moves to plumbingtooling.com;
  corrected the "Announce to the crew" bullet that claimed old installs "land on
  the redirect" (they didn't — that assumption was this bug).

No app-code changes; client `src/sw.ts` untouched.
