# v2.2682 — Review person panel: Jobs Worked per job, recurring tasks collapsed (2026-09-03)

Second slice of the People → Review refresh (variant C). The per-person panel below the ranked list / table gets the two changes the mock-up promised: Jobs Worked reads one line per job with the day rows underneath, and Tasks outstanding stops drowning in recurring instances. Allocation math unchanged — the rollup sums the rows the panel already computes.

## Client only — no migration

- **Kernel** [`lib/people/reviewJobsRollup.ts`](../../src/lib/people/reviewJobsRollup.ts) (+3 tests): `buildReviewJobsRollup(rows)` groups the panel's sub-labor and crew day rows by job (ledger id, else the raw sheet number), sums the person's hours / labor / allocated revenue / allocated profit, carries the whole-job figures (lifetime labor, value created, net before overhead) from the first row, computes the person's share of the job's lifetime labor and per-hour rates, counts zero-hour rows, flags `noBill` / `assumedPct`, orders day rows by date (undated last) and jobs by allocated profit desc. Input is a neutral `ReviewRollupRowInput` — the tab maps its two local row types into it and keeps a rowKey → row map.
- **Kernel** [`lib/people/reviewTasksRollup.ts`](../../src/lib/people/reviewTasksRollup.ts) (+4 tests): `buildReviewTasksRollup(tasks, todayYmd, minInstances = 3)` groups open instances by `checklist_item_id` (title fallback), collapses groups of ≥3 dated instances into one recurring line with cadence (median scheduled-date gap → daily / weekly / every two weeks / monthly / every N days), `missed` (before today) / `upcoming` (today or later), first/last missed, next due; one-offs pass through; lines sort by the earliest date they are about.
- **Tab** ([`PeopleReviewTab.tsx`](../../src/components/people/PeopleReviewTab.tsx)):
  - Jobs Worked heading reads "Jobs Worked (18) · 34 day rows · 4 with 0 h". The `<tbody>` now renders one header row per job (caret, number label, day count, name + amber `no bill` / `% assumed` chips, address, labor + share of lifetime labor, profit + whole-job net, revenue + value created, per-hour) with the same six columns as the day rows; clicking it opens that job's day rows (`reviewJobGroupsOpen`). The two existing day-row `.map` callbacks became `renderLaborRow` / `renderCrewRow` inside the same IIFE — byte-identical bodies, so the per-day detail grid (region F) and its `reviewJobExpandedKey` keep working. The totals `<tfoot>` is untouched.
  - `ReviewTask` gains `checklist_item_id` (already selected by the outstanding query, previously dropped in the map). Tasks outstanding renders `reviewTasksRollup.lines`: recurring lines on a subtle background with ↻, cadence, open count, red missed count + "since", upcoming count, and "next <date>" in the Scheduled column; the heading adds "· N lines, recurring items collapsed" when anything folded.
