# v2.4891 — Downloaded files are named for today, even in the evening (2026-10-07)

Client only. Found on punch list #92's walk: an AIA workbook generated at 7:16 PM Central on Oct 7 was named `AIA-G702-G703-1071-app-1-2026-10-08.xlsx`. Its stamp was `new Date().toISOString().slice(0, 10)`, the UTC date, which is tomorrow every evening after 7 PM Central (6 PM in winter). `check:timezone` let it through on purpose: it skipped any line that looked like a filename.

## The stamps fixed

Each now reads `todayYmdInAppTz()` (`docs/TIME_AND_ZONES.md`).

| File | The download |
|---|---|
| `src/lib/aiaG702G703Template.ts` → `aiaDownloadFilename` | the AIA G702-G703 workbook (takes `now`, so the test can pin it) |
| `src/components/jobs/JobSummaryCostCellDrilldownModal.tsx` | the Job Summary cost cell drill-down export |
| `src/components/settings/UncollectibleListSettingsBlock.tsx` | the accountant's Uncollectible CSV |
| `src/components/bids/BidsCountsTab.tsx` | the bid's Counts CSV |
| `src/lib/bidDocuments/pricingPage.ts` | the bid's Pricing CSV |
| `src/hooks/useSettingsBackupExports.ts` | the ten Settings backups (projects, materials, bids, people, jobs, checklist, reports, prospects, settings, full) |

Looked at and left: `procurementLogFileName(…, toIsoDate(new Date()))` and `expectedBidBasisFilename` read the device's own day, not UTC. The bid-basis name also matches what CountTooling names the file. The other `…Filename(` builders carry no date or take the day they are given.

## The check

`scripts/check-app-calendar-tz.mjs` no longer skips filename lines (`FILENAME_RE` is gone), so a new UTC filename stamp fails CI. A deliberate one takes `// tz-ok: <why>`; none remain. `docs/TIME_AND_ZONES.md`'s rule sentence says so.

## Tests

`aiaG702G703Template.test.ts` +1: `2026-10-08T00:16:00Z` names `…-2026-10-07.xlsx`; mid-day is the same day; `05:30Z` (12:30 AM Central) is the 8th. `npm run check:timezone` passes with the skip removed.
