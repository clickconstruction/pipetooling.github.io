# v2.3700 — People spine, PR 2: Leave — End employment finishes everything on the desk (2026-09-21)

PR 2 of the People spine train ([`to-dos/people-spine/README.md`](../../to-dos/people-spine/README.md); PR 1 = v2.3698). The train's second write moment: when a person leaves, one dialog does all of it. Client only; no migration, no edge function change.

## What was wrong

End employment (v2.2706) was a checklist that finished three things — the end date, an HR line, and optionally `archive-user` — and pointed elsewhere for the rest. The final pay report was a link to Payroll (`generatePayStub` was a closure inside `People.tsx`, so nothing headless could call it). A salaried person's workday template survived their departure: nothing in the flow cleared it or flipped `is_salary`, so the template kept minting schedule sessions and the cron kept approving them into paid hours (the guard in PR 1 stops that for an *archived* account, but the flow archives only when asked). Customers on the account's name were never counted or moved — the desk's Status → Archive… sent a dev to the Active Accounts modal for that. And the roster row was never archived, so the person stayed on the Users tab, the Employment tab and every `people` picker after their account was gone (the Training Helper's roster row on 2026-09-21 was exactly that).

## The change

- **[`src/lib/pay/generatePayStub.ts`](../../src/lib/pay/generatePayStub.ts)** — the money and the two inserts lifted out of `People.tsx`: `buildPayStubDayRows` (pure: hourly / salaried credit / dual-rate split, one row per day — four tests), `payStubTotals`, `payStubDaysInRange`, and `generatePayStubRecord` (reads the period's hours, sessions and salary window; inserts `pay_stubs` + `pay_stub_days`; returns rows, totals, the rate-split summary and warnings). The page's `generatePayStub` now calls it and keeps only the preview (crew rows, vehicles, offsets, the printable HTML). Same math, line for line.
- **[`src/lib/people/leaveWrites.ts`](../../src/lib/people/leaveWrites.ts)** — the headless writes, one function each: `closeOpenClockSessions`, `clearSalaryForPerson` (`removeSalaryScheduleForUser` by user id + `people_pay_config` to hourly), `countCustomersOwned`, `archiveAccount` (`archive-user` with the same `archiveRequestBody` the Active Accounts dialog sends, customers to the company owner via `resolveCompanyOwnerUserId` when asked), `archiveRosterRow`, `setEmploymentEndDate`. No new permission: the sections' gates and the edge function's own.
- **[`lifecycleChecklist.ts`](../../src/lib/people/lifecycleChecklist.ts)** — `EndEmploymentFacts` gains `isSalary` / `hourlyWage`; the *Final pay report* row's action is `generate_pay_report` (skipped, not open, when the pay row has no wage and is not salaried — nothing to pay); a new *Salary* row (`clear_salary`, never leave-open) that is `blockedBy` the report row until it is done — the report needs the salaried credit for the days it covers; `checklistItemBlocker` and `finalPayReportPeriod` (the day after the last report, or the end week's Sunday, through the end date). Four new tests.
- **[`PersonDeskLifecycleModal`](../../src/components/personDesk/PersonDeskLifecycleModal.tsx)** — runs the two new actions through the kernels (each behind a confirm that names the period or the consequence); a blocked action's button is disabled with the reason in its title; the footer counts customers on the account's name and offers *company owner* (default) / *keep on their name*; **Archive after** now archives the account **and** the roster row (`archiveRosterRow`), and the confirm sentence lists exactly what will happen.
- **[`PersonDeskAccessSection`](../../src/components/personDesk/sections/PersonDeskAccessSection.tsx)** — Status → **Archive…** opens End employment (`onOpenFlow('end')`, plumbed from `PersonDeskBody` for pay viewers) for every role that may archive; the dev-only hop to the Active Accounts modal is gone from the desk. The Active Accounts dialog itself is unchanged (PR 6 turns it into a pointer).
- Guides: *open a person's desk* (the Access & account line and the End employment section) and *archive and restore user accounts* (the desk is the other door).
