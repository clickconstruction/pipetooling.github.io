# v2.3829 — Documents: searching "unpaid" finds only the unpaid supply bills (2026-09-25)

Quirk 3 of [`DOCUMENTS_PAGE_ARCHITECTURE.md`](../DOCUMENTS_PAGE_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Client only, no migration.

## The bug

`documentsSupplyInvoiceRowMatchesSearch` in [`Documents.tsx`](../../src/pages/Documents.tsx) tested the paid-state words as substrings, paid first: `t.includes('paid') && r.is_paid`. "unpaid" contains "paid", so a search for *unpaid* matched every paid invoice on that line and every unpaid one on the next — the whole ledger. Workflow's invoice picker (`Workflow.tsx`, `q === 'paid'`) was never affected.

## The change

- New kernel [`lib/supplyInvoicePaidSearch.ts`](../../src/lib/supplyInvoicePaidSearch.ts) — `supplyInvoicePaidWordMatches(query, isPaid)`: *paid* matches paid bills, *unpaid* / *open* unpaid ones, as whole words in any case anywhere in the query (so *unpaid ferguson* still reads the word; *prepaid* and *reopen* no longer do). The page's two lines become one call.

## Verified

- `supplyInvoicePaidSearch.test.ts` — *unpaid* excludes paid bills (the bug), *paid* and *open* each one side, whole words in a longer query, no paid-state word → no match.
- Typecheck, lint.
