# v2.8127 — Trips: a joined trip cannot come back from an old page (2026-11-20)

## Why

The loose ends of punch list #379, run down on 2026-11-20, took the note on the join's migration page: a stale screen can still offer Put back on a joined trip, and the database does not refuse it. It was wider than written. Put back, Change then Save, and the Undo of a delete all send the trip's own save under its own id, and `trip_save` makes any id that is not there. On a Development page older than a join, each made the trip that went again. Its days then stood on two trips, it read as on no bill while the joined trip held its line, nothing said it had been joined, and Put on a bill could bill its days a second time. The owner said yes to closing it in the database.

## What changed

- **Migration `20261120130000_trip_joined_stays_gone.sql`**: a `BEFORE INSERT` trigger on `trips` (`trips_refuse_joined_back`) refuses a trip whose newest delete that nothing has put back carries `joined_into`. The words name both trips and Split in two. It covers the three presses, the dev seat's `apply_trip` and the dev's `restore_deleted_records`. A trip somebody deleted is untouched. The page is `docs/migrations/20261120130000_trip_joined_stays_gone.md`.
- **`useSiteTrips`**: a save the database refuses reads the site's trips and deleted trips again, so the refused trip redraws under Deleted trips as joined, with no Put back. A save lost to the signal reads nothing again.
- **The guide** `keep-a-trip-to-a-far-site` says a page left open from before a join cannot bring the next trip back.
- **Docs**: Access Control's Trips section, the Glossary's Trip entry and the join's migration page say the save now refuses a joined trip.

## Tests

- `supabase/tests/trips/95_joined_back.sql`, 29 checks, run by `scripts/pgtest-trips.sh`. The whole trips bed passed on a local Postgres 15 with the trips migrations applied twice: 392 checks. With the guard made a no-op, the new file failed at the first stale save.
- `useSiteTrips.render.test.tsx`: a refused save reads again and the trip shows as joined, and a save lost to the signal reads nothing again.
- `DevelopmentTripsCard.render.test.tsx`: a refused Put back's toast carries the database's words.

## Deploy

Push the migration with `supabase db push` after the merge. No edge function changes. The page works before and after the push.
