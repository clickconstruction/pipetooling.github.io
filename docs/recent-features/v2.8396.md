# v2.8396 — Supply house bills: the app can read a bill's PDF itself (2026-11-23)

Punch list #431, the door under PR 2. The bill viewer draws a supply house bill's PDF on the app's own canvas, so it needs the file's bytes. The bills sit in one folder of an office login's My Drive, shared with the app's service account as a viewer (punch list #298, step 0), so a browser reads one only through a Google sign-in. This PR gives `drive-link` one new ask, `read_bill`, and changes no screen. It ships ahead of the viewer so the function is deployed before any screen calls it. No migration.

## What changed

- **`drive-link` → `{ action: 'read_bill', invoiceId }`** answers the bytes of the PDF a bill's row links, as an octet stream, up to 30 MB, the way `read` answers a file in a job's folder.
- **Two fences**, pure in `supabase/functions/_shared/billFile.ts`:
  - **The bill's row is read as the caller**, under the caller's own policy on `supply_house_invoices`. A row they may not read is no row, so the door answers 403 (`not_yours`) to an estimator, who passes the door's role check, and to anyone the policy keeps out. A training account is served, since this is a read. A digital twin is refused before any ask is read, in the words *A digital twin cannot read Drive.*
  - **The file must sit inside the bills folder**, up to six folders up. A bill's link is a field the office types, and the service account can read files the office cannot: a person's HR file, a matter's papers. Without this fence a pasted link would make the door a way to read any of them. The folder is known by its id when the secret `BILLS_DRIVE_FOLDER_ID` is set. With no secret it is known by its name, `_Bills`, outside any Shared Drive. Nobody can put a file they cannot already open under a folder of that name, so the name is a fence and not a hint. A file elsewhere answers 403 (`not_a_bill_file`), and a dev alone is also told the folders it sits under (`seen`), so a renamed folder can be told from a stray file.
- **The other answers**, each with its words, `why` and `retry`: 404 `no_file` (the row links no Drive file), 404 `gone` (Drive will not show the file to the app), 409 `trashed`, 415 `no_bytes` (a Google document or a folder), 413 `too_big`, 502 `unanswered`, 500 `unread` (the row did not read).
- **A door of its own**, as the trash is: the ask is read before the shared ask parser, which other functions hold, so that parser is as it was.
