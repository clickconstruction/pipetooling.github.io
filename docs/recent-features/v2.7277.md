# v2.7277 — Lien desk: the title bar’s presses move up when the line has room (2026-11-14)

The owner's screenshot of 2026-11-14, the desk in a window of about 1,290 px: the title line ended at the run pill with 500 px empty to its right, and the second line held *An owner asked for records ›* and the four presses, right-aligned. "I think we can move these three buttons up so the button left of it can slide over underneath it." Client only: no migration, no edge function.

## Before

Since v2.7213 the five tools — the owner-records door, § Rules, ☎, ? and Share — ended the title line in a window of 1,540 px or more and sat together on the second line in a narrower one. 1,540 was the longest title line the desk can draw (a three-figure To do count, the run as *Send the run · 24 · 12 sealed · 8 ready · 4 wait on Grace*), a viewport rule so no view moved the tools. The same arithmetic for the four presses alone gives 1,320 px, which is above the owner's window: a second viewport threshold would have left his screen as it was.

## What changed

- **[`src/lib/jobs/lienDeskTitleBar.ts`](../../src/lib/jobs/lienDeskTitleBar.ts)**: `lienDeskTitleLineFit(width, parts)` says which tools a title line of `width` px holds at its end — `all`, `presses` (the four, with the door to slide under them) or `none` — from the parts as drawn (`LienDeskTitleLineParts`; a part that is not there is 0, and a line with no door is `all` or `none`). `readLienDeskTitleLine(bar)` reads the bar's content width and its parts off the DOM (the way back, the title, the views, the run pill, the door, the `data-lien-desk-presses` span; the column gap from the style sheet), null while the bar has no width. `lienDeskTitleBarLayout` takes `fit` and `recordsDoor` in place of `wide` and answers `door: 'with_tools' | 'second_line'` beside `tools`, `breakLine` and `rightSpan`: with the presses alone up, the break is always there and the right span holds the door. `LIEN_DESK_ONE_LINE_MIN_WIDTH` and its media query are gone; `LIEN_DESK_TITLE_LINE_PARTS` keeps the longest line's widths, with the door (199) and the presses (231) measured 2026-11-14. Tests at 2,000, 1,300 and 1,100 px, the reader against a built bar, and the layout's three tiers.
- **`LienDesk.tsx`**: the bar carries `titleBarRef`; a layout effect reads the line on mount and on a `ResizeObserver` over the bar, the views and the run pill, and sets `titleLineFit`. Affidavits hides the run pill without taking the run away, so the line keeps the pill's last width there and no view moves the door. The tools span draws the door only when `door` is `with_tools`; the second line's right span draws it when the tools or the door are there. `headerTools`' span is `data-lien-desk-presses`.
- **`LienDesk.render.test.tsx`**: the wide-window smoke stubs `getBoundingClientRect` for the bar and its parts instead of `matchMedia`: at 2,000 px the five tools end the title line (By date, To do, By paper, the leader's three); at 1,300 the four presses end it and the door is alone, right-aligned, in the second line's span and still its press, on By paper's Lien affidavits too; at 1,048 the two steady lines of v2.6569.
- [`docs/LIEN_DESK_ARCHITECTURE.md`](../LIEN_DESK_ARCHITECTURE.md): the dated note under *What this surface is*, and the v2.7213 sentences amended.

## Not changed

- A window with room for all five tools keeps the one line of v2.7213; one with room for none keeps the two lines of v2.6569. A phone's header and its More sheet (v2.7200) are untouched.
- No CSS changed: the right span already pushed right, so the door ends under Share.
