## Why a hook and a strip, not one self-contained component

The map planned a component that owned its state and read on mount. The page returns `Loading...` until its steps have loaded, so a strip inside it mounts late: its reads would start only then, and the line would paint "None" before its chips on every visit. Today the reads start as soon as the project and the viewer's role are known, alongside the page's own load. Keeping the hook call in the page keeps that. The map's "What must STAY in the parent" now says so, for this strip and for the Jobs strip after it.
