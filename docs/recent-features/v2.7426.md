# v2.7426 — Tagged job notes: the name shows as a chip the moment you post (2026-11-15)

Punch list #363, a fix from the first walk on prod. Client only.

## What was wrong

The walk of v2.7407 on a ZZ Test job posted a note that tagged the Sample superintendent. The note landed with its tag and the section listed it under You asked, but the row drew the note as plain words. The chip and *waiting on Sample* appeared only after the page was read again.

`useJobNoteTags` read a job's tags again when its feed grew. The reader's own post grows the feed by the optimistic row, before the tag exists, and swapping that row for the real one does not change the length. So the read ran too early and never again.

## What changed

- **`src/hooks/useJobNoteTags.ts`** also follows `noteTagsChanged`, the signal a typed post, an answer, a No reply needed press and a seen mark already send. The feed's length stays as the cue for a note someone else posts.
- **`JobsStagesActivityBox.tags.render.test.tsx`**: one more test, a feed that already holds the note and a tags read that answers only after the signal.

## Also seen on that walk, as built

- The list opens above the row's strip, inside the box, and is not clipped.
- The ZZ Walk tester is not offered, because that account is in training mode. A dev is offered the sample accounts.
