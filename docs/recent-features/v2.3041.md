# v2.3041 — Test-gap audit, pass 51: the Person Desk lifecycle facts get their first tests (2026-09-07)

Follow-up to v2.3040. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`people/personDeskFacts.ts` (129 lines) is the set of reads behind the Person Desk's end-employment and start-employment flows: pay config, pending and open sessions, the last pay report, sub sheet balances, the portal link, vehicles and housing held, leaders, work-order commitments and compliance documents, each folded into a fact the checklist reads. The queue, balance and compliance kernels were tested; the reads were not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Pay config reads by pay name: no name → unknown, no row → "not configured", a read error → unknown rather than a false all-clear.
- End-employment facts ask only the tables that apply: login-keyed reads (open session, vehicles, housing, leaders, pending sessions) only with a login, sub-keyed reads (sheets, portal, documents) only for a sub with a roster row; the balance sums readable sheets and rounds to cents; a vehicle without a joined row reads "Vehicle", housing without an address "Housing", a leader without a name "Leader"; missing compliance labels come from the badge kernel.
- Unreadable side tables degrade: a failed pending-sessions fetch counts none, a null portal read means portal off, a sub with no readable sheets has a zero balance.
- Start-employment facts use head-count requests; pay counts as configured only with a salary flag or a positive wage; paperwork counts as assigned when either assignments or documents exist; a missing roster row or login skips those reads and null counts read as zero.

## What shipped

Covers pay config's four outcomes, the employee and sub end-employment shapes with their reads, the degrade cases, and the two start-employment shapes.
