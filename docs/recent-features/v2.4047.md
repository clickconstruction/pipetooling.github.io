# v2.4047 — Write up a change lives on the job, not in the Dashboard header (2026-09-28)

Client only; no migration, no edge function. The owner's read of the Dashboard on 2026-09-28: the purple Estimate/Change Order pill under the clock row was the loudest thing on the page for the action used least, its name was two nouns and a slash, and the wizard's second screen asked for a job the page was already showing. Option 1 of the mock-up (the door on the My Schedule block, F1 paper-and-pencil icon) was picked.

## What changed

- **`DashboardMyScheduleSection`** — new optional prop `onWriteUpChange(jobId | null)`. Each job block's action row (Leave Report · Update % done) gains a 44 px paper-and-pencil square (`WriteUpChangeGlyph`, `dashboardJobRowShared.tsx`; aria-label *Write up a change*) that opens the wizard on that job. Under the days, a quiet link — *Write up a change on another job, or new work* — opens it with no job. Both render only when the prop is passed.
- **`Dashboard.tsx`** — the pill in `afterJobReportRow` is gone. `openWriteUpChange` is passed when `quickEstimateEnabled` (the same role + `user_dashboard_buttons.quick_estimate` gate) and the page is not Job Mode's focused view (which never mounts the wizard). `quickEstimateJobId` state carries the block's job to the wizard.
- **`QuickEstimateWizard`** — new prop `initialJobId`. When the sheet opens with one, it reads the job (`jobs_ledger` id, HCP, name, address, customer) and runs the same `goWorkFromJob` a tap on the "Which job is it on?" list runs: change-order branch, draft created, straight to *What's the change?*. The kind screen shows *Opening the job…* meanwhile. Back still steps to the job list. The seed runs once per open (`seededJobRef`) and never over an existing draft.
- **Settings → Dashboard & alerts** — the toggle reads *Write up a change from the field* and says where the door now is.
- **Guide** `write-up-a-change-order-from-the-field` rewritten around the square and the link; GLOSSARY, PROJECT_DOCUMENTATION and the Dashboard map amended.

## Not in this PR

- The same door in the Job window and the Job Mode day rail — its own PR.
- The deferred wizard follow-ups from v2.2293 (resume a half-done write-up, already-sent-today warning, auto-close of the dispatch request).
