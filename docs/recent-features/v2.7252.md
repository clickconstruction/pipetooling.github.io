# v2.7252 — Materials on site: four small things on the phone (2026-11-14)

Punch list #344, PR 9, the last of the train, on the owner's word to build the rest. From the review of Materials → On site: *small things on the phone*.

## 1. A Can't find at none is in the count walk

`countWalkKeys` (`countWalk.ts`) took the lines with parts on hand. A line pressed Can't find down to none is drawn in the box with its mark (`linesOf`) and was left out of the walk, so no count on the phone could clear the mark, only the office's **Correct…**. A box whose only line was such a one had no **Count this box**. The walk now takes a line with parts on hand or a Can't find on it, the press shows when the walk has a line, and the walk's card says *3 marked can't find. Your count clears the mark.* A `counted` row resets the mark as it always did.

## 2. The number field can be cleared

The number sheet's field (`Stepper`, `TallyOnSiteTab.tsx`) wrote every keystroke to the number, floored at 1. Clearing it to type 25 put the 1 back at once, and the next key made 12 or 15. The field now keeps what is typed (`stepperInput.ts`): empty stays empty and moves no number, a number is held to 1 and the most the box has, and the field shows the number again on a press of − or +, a quick number or leaving it. The save press still names the number it will use.

## 3. A code that opens no box says what the page knows

Signed in, a box label's code that reads no row said *is not a box on any job* and *the label may be from a box that was retired* (`BoxCode.tsx`). The page cannot know either: a box on a job the reader is not on comes back as no row under their own RLS, the same as a retired box and a code nobody printed. It now says *did not open a box*, and that the box may be on a job they are not on or may be retired (`noBoxTitle`, `NO_BOX_DETAIL` in `stickers.ts`). A sticker's own states are unchanged, since `sticker_by_code` tells them apart.

## 4. The photo sweep takes what has not failed first

`photo-save`'s box source read the waiting rows oldest first, twenty a run, with no regard to `fail_why`. Once twenty rows carried a reason, every run took the same twenty and no newer photo was filed. The read now orders by `fail_why` with nulls first, then `taken_at`. A failed photo is still tried again with the room a run has left.

**An edge function change: it does nothing until `photo-save` is deployed**, which waits on the owner's yes. `npm run check:edge-drift` names it until then.

## Tests

`countWalk.test.ts` and `stepperInput.test.ts` for the two kernels. `TallyOnSiteTab.render.test.tsx`: a box whose only line is a Can't find at none has **Count this box**, the walk says the mark, and *0 is right* writes the count; the field stays empty when cleared, takes a typed 5, shows 8 for a typed 50 in a box of 8, and shows the number again when left empty. `BoxCode.render.test.tsx`: the new words. `boxPhotoRefile.test.ts` reads the function's text for the order.
