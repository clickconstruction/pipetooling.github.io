# v2.7694 — Legal desk: turn an old text file into words you can read and copy (2026-11-17)

## Why

v2.7683 put copy presses over a text document's words on the Legal desk's Evidence tab. **Read**, and so the copy presses, show only on a row with `text_document_id`, which a `.md` or `.txt` gets when it is added since v2.6716. A text file put on a matter before that is a stored file alone: it opens in a new tab and cannot be read or copied on the desk. v2.7683's own note left those rows to "filing again, or a backfill". This is the backfill, as a press the office makes itself: no SQL on prod, no migration, each row changed by a signed-in office role under the policies already there.

## What changed

- **`src/lib/legal/keepAsText.ts`** (pure, tested): which rows qualify (`legalDocumentCanKeepAsText`: a text mime per `legalDocumentIsText`, and no `text_document_id`; a PDF, a picture or an `.eml` never does), and the words. The menu line is **Keep its words as text**. The counted press reads *Keep 3 as text* through `countedLabel` and shows when more than one row waits. `keepAsTextOutcome` words the toast and the head over the rows that did not take through `batchOutcomeWords`. `keepAsTextProblem` refuses a file with no words, or more than a text document keeps.
- **`keepLegalMatterDocumentAsText`** in `legalMatterDocumentsIo.ts`: downloads the stored file from the private `legal-matter-documents` bucket by the row's `storage_path`, reads it as text, inserts the `documents` row exactly as `addLegalMatterDocument` does for a fresh text file (`matter_id`, `title`, `content`, `counsel_only`), then sets `text_document_id` on the Evidence row. The row write carries `text_document_id IS NULL`, so two hands pressing at once cannot leave two copies pointed at. A row write that fails, or finds the row already has its words, archives the `documents` row it just made (`archived_at`; the table has no delete policy, as `addLegalMatterDocument`'s own undo does), so nothing is orphaned. The stored file is never touched.
- **`LegalMatterDocumentsPanel.tsx`**: a qualifying row's ⋯ menu carries **Keep its words as text**, and the menu's record says the paper is kept as a file only. With more than one qualifying row on the matter, a counted press sits beside the filters. It takes the rows one by one in the list's order, keeps going past a row that fails, toasts what took and what did not, and lists each row that did not take with its reason; a listed row drops off once it has its words. Both presses show only to a hand that can edit (`canEdit`). Reasons come through `formatErrorMessage`.

## Access

No new permission and no policy. The writes are the ones the same four roles already make: `documents` insert under *Office adds matter documents* and update under *Office changes matter documents* (`20261108210000`), `legal_matter_documents` update under `legal_matter_documents_office_update`, and the bucket read under `legal_matter_documents_office_rw` (`20261007230000`), all through `legal_office_can_read()`. A matter on a person stays a dev's alone (`documents_person_matter_dev_only`). A read-only (training) account is refused by the house fences, and the row is listed with that reason.

## What follows from a kept row

The row is a text document like any other from then on: **Read** and the copy presses on the desk, **Read here** on the firm's portal for a row the firm may see, a counsel-only row's words counsel-only too, and the words searched by section.
