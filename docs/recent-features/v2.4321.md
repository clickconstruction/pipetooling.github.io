# v2.4321 — Lien desk: the Calendar loads its jobs on a phone (2026-10-01)

Client only: no migration, no edge function. Found 2026-10-01 while walking v2.4308 at 375 px on the dev server against production data. On the phone board, the ⏱ Lien desk's **Calendar** read *every billed job on the statute's calendar · 0 jobs · $0 open* and *Nothing billed is on a lien clock.*, while the desktop Calendar read 64 jobs. Tapping the board's **Billed** chip and reopening the desk filled it in. v2.4308 listed it under *Not done*.

## Cause

The Calendar's rows are the Pipeline's loaded jobs (v2.4101: `lienCalendarRows` in `JobsStagesTab` takes every `status === 'billed'` job through `lienRunwayFor`). The phone board (punch list #30 PR 2a) loads one stage's scope at a time, so with Working or Ready picked the `billed_all` scope was never fetched. `useBilledLienClocks([])` answered `{}`, the rows came out `[]`, and the tab printed the empty count and sentence: it only said *Reading the board…* while the desk's own data loaded (`loading && !rows`), and the desk's data is not the Calendar's.

The desktop had its 64 jobs by accident: the job map card asks for every section's scope when it mounts (v2.3398). On main, a desktop at 1024 px with the map hidden and Billed + Collections folded read *0 jobs* too. The ⋯ menu's Lien desk door hid the bug as well, because an open tools menu loads every non-paid scope (`stagesNeedsAllScopesForModal`).

A shorter gap sat behind it: when the billed jobs did arrive, `useBilledLienClocks` kept the empty list's `{}` until the new reads landed, so for that second the rows were `[]` again.

## What changed

- **The open desk fetches the billed scope** ([`JobsStagesTab`](../../src/components/jobs/JobsStagesTab.tsx)): while `lienDesk` is set, `cacheFetchScopeIfNeeded(scopeForStagesSection('billed'))`, in the Legal desk's retry-until-merged shape (it re-runs as `mergedScopes` / `scopeLoading` move, because the call no-ops while the board's first load is in flight). On any kind, not only Calendar: a row's door opens the desk on Notices, and the Calendar is one tab away. Where the scope is already merged (a desktop with its map) the call returns at once.
- **`lienCalendarRows` is null until the board holds that scope**: `!cacheMergedScopes.has('billed_all') || !billedLienClocks` → null.
- **`useBilledLienClocks` keeps the list key with its record** ([`billedLienClocksFor`](../../src/hooks/useBilledLienClocks.ts)): a record read for an earlier list stays up while the new list reads, so a refresh (the Calendar pen's `refreshKey` bump, a job moving into Billed) never blanks the Pipeline's runways. An empty record does not: an empty list's `{}`, or a failed read's, answers null for any other list until that list's reads land. `lienRunwayFor` reads null and a missing entry the same way, so the Pipeline's rows draw exactly what they drew.
- **[`LienDeskCalendarTab`](../../src/components/jobs/LienDeskCalendarTab.tsx)** says *Reading the board…* whenever `rows` is null and the empty sentence whenever a read list is empty. Its `loading` prop (the desk's own data, which the Calendar never reads) is gone, and `LienDeskModal` stops passing it.
- Tests: `billedLienClocksFor`'s four answers, and the hook with its reads held (a list after an empty answer, a changed list, a refresh, a list after a failed read); the tab's loading and empty words on both layouts; and a Pipeline smoke in which opening the desk asks for `billed_all`, reads *Reading the board…*, then counts the billed job once the scope lands. Against main's code the smoke, the tab's two loading cases and the hook's two loading cases fail; the changed-list and refresh cases pass on both, as they must.
