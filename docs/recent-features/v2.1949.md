# v2.1949 — Roadmap task card redesign: bottom sheet + per-tap saves (2026-08-21)

`ChecklistTechTreeTaskCardModal` rebuilt to the approved mockups (user
request: "these modals don't look great and are not super great to
navigate… mobile friendly").

- **Interaction model**: every edit commits itself — assignee taps and
  inline title saves call `onSave` immediately — so the fold, the checkbox
  list, and the Close/Save footer are gone. ✕ / backdrop dismisses.
- **People zone**: assignee chips with ✕ under the title; "＋ Assign" opens
  a chip picker (search + "On this roadmap" tier from a new optional
  `suggestedUserIds` prop, computed in the tab from current task assignees).
- **Layout**: CSS classes in `index.css` (`.roadmap-task-overlay/-card/
  -grabber/-composer`) — centered 560px card ≥640px, full-width bottom sheet
  with grabber + safe-area padding below. Activity scrolls; composer pinned.
  Comments render as message bubbles, status events as one-liners; thread
  auto-scrolls to newest. New optional `stageNumber` prop puts the stage
  badge in the crumb.
- **`updateTaskInGroup` now skips untouched halves** (title PATCH only when
  changed, assignee rewrite only when changed): per-tap saves shouldn't
  rewrite everything — and the title UPDATE currently trips a **pre-existing
  prod RLS recursion** (42P17: `checklist_tech_tree_group_tasks` UPDATE
  policy ↔ `checklist_tech_tree_task_assignees` SELECT policy — same class
  as the v2.1225 `people_labor_jobs` bug), which also broke the old modal's
  Save. Assign/unassign works today because the assignees tables don't
  recurse; the rename path needs the follow-up migration fix.
- Render tests rewritten for the new model (8 tests); help guide
  `staff-and-discuss-roadmap-tasks` added.
