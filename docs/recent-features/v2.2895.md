# v2.2895 — Aging: the stalest item sinks no more — oldest first, amber and red age states, and a stopwatch that turns into days (2026-09-05)

Journey-map Tier-2 #40 (cluster C60 — "age is displayed, never escalated"; J19-F3 · J30-3 · J32-F7 · J33-F2 · J31-5 · J3-4). Five waiting lists rendered age as gray text, sorted newest-first, with no late state: open dispatch requests at 46 d looked like 4 d and sat under this morning's; one-offs at 128 d had only 🔔 Remind; HR pending reports (11 d) listed newest first; workflow expected dates months past rendered calm blue with no date compare; the field-approval queue read "Waiting 282:59:39". The only escalation anywhere was `HOURS_APPROVALS_MIN_AGE_DAYS = 3` (v2.2671). This PR generalises that precedent into one convention and applies it across the five surfaces. No migration.

## One age convention — [`src/lib/ageState.ts`](../../src/lib/ageState.ts)

- `AgeState = 'fresh' | 'amber' | 'red'`; `ageDays(createdAt, now)` (whole days, floored, ≥ 0, null when unstamped) → `ageStateForDays(days, thresholds)` with **inclusive** boundaries; `ageState()`, `describeAge()` (days + state + label), `ageLabel(days, noun)` → `today` · `1 day waiting` · `3 days waiting`; `ymdAgeDays()` for calendar-date surfaces; `compareOldestFirst()` (ISO strings ascending, missing stamps last).
- **Per-surface thresholds as named constants** (amber / red, days): `DISPATCH_REQUEST_AGE` 3 / 7 · `HR_PENDING_REPORT_AGE` 3 / 7 · `ONE_OFF_TASK_AGE` 7 / 31 (the v2.2012 week/month scale, unchanged) · `FIELD_APPROVAL_WAIT_AGE` 1 / 3. Needs-You min ages in the v2.2671 shape: `DISPATCH_REQUESTS_MIN_AGE_DAYS = 3`, `HR_REPORTS_MIN_AGE_DAYS = 3`.
- `dueState(endYmd, todayYmd, { startYmd, started })` for planned windows: past end → red `N days late`; end today → amber `due today`; pending step whose start slipped → amber `start N days past`; else fresh/silent.
- `ageChipStyle(state)` — one chip palette (tokens for neutrals, literal `#d97706` / `#dc2626` borders per the theme rule); the Checklist's `ageSeverity()` (`checklistTeamBoard.ts`) now reads off `ONE_OFF_TASK_AGE` and maps warn/late, so the one-off chips and the new chips share one table.
- Telemetry: `AGING_ITEM_OPENED_CONTROL = 'aging_item_opened'`, target `agingItemOpenedTarget(surface, days, state)` → `#surface=dispatch-request&age_days=12&state=red`; `shouldRecordAgingOpen()` records amber/red only. Recorded via `recordNavClick` when an aging dispatch row is expanded, an aging HR report's **Open their file** is clicked, or an aging one-off is expanded in Checklist → Manage.

## Surfaces

- **Dispatch inbox** ([`useDispatchInbox.ts`](../../src/hooks/useDispatchInbox.ts) → kernel [`dispatchInboxAging.ts`](../../src/lib/dispatchInboxAging.ts) `sortDispatchInboxRows`): open rows **oldest first**, closed rows stay newest-closed-first. [`DispatchInboxSection.tsx`](../../src/components/DispatchInboxSection.tsx) renders an age chip on open rows (closed rows keep the `(61d)` text). Job Mode **My requests** ([`myDispatchRequests.ts`](../../src/lib/myDispatchRequests.ts)): open rows oldest first; the view carries `age`, and the row rail turns red at `DISPATCH_REQUEST_AGE.redDays`. The v2.2880 `dispatchBadgeCount` kernel is untouched.
- **HR pending reports** ([`HrPendingReportsSection.tsx`](../../src/components/people/HrPendingReportsSection.tsx), kernel additions in [`hrPendingReports.ts`](../../src/lib/people/hrPendingReports.ts) — `sortPendingReportsOldestFirst`, `summarizePendingReportAging`): oldest first, age chip per row, amber/red card border, header adds "oldest N days".
- **One-offs** (Checklist → Manage → One-offs, [`Checklist.tsx`](../../src/pages/Checklist.tsx)): the open list sorts **oldest open instance first** (fallback: created date); the section label says "oldest first". Scheduled / Repeating / Completed keep their orders.
- **Workflow expected dates** ([`Workflow.tsx`](../../src/pages/Workflow.tsx) `expectedDueState`): for pending / in-progress steps the collapsed `Exp:` pill and the expanded Row 2b append `· 43 days late` in red (or `due today` / `start N days past` in amber). Finished steps never age.
- **Stopwatch** ([`formatElapsedCountUp.ts`](../../src/lib/formatElapsedCountUp.ts)): humanizes at `HUMANIZE_ELAPSED_AFTER_MS` (48 h) → `2 days` … `12 days`; `{ liveCountUp: true }` keeps `h:mm:ss` forever. `DashboardFieldCollectPaymentQueue` takes the default and tints the label amber/red via `FIELD_APPROVAL_WAIT_AGE`; `CollectPaymentModal` (the tech watching the clock) passes `liveCountUp`.

## Needs You — two min-age keys

[`dashboardNeedsYou.ts`](../../src/lib/dashboardNeedsYou.ts): `dispatch-requests-aged` (rank 40; amber, red once the oldest passes `DISPATCH_REQUEST_AGE.redDays`; inputs `dispatchAgedEnabled` / `dispatchAged` / `dispatchMinAgeDays` / `dispatchRedDays`) and `hr-reports-pending` (rank 50; same shape; dev-only because People → HR is dev-only). Dashboard passes `dispatchAged` into `DashboardPinnedQuickRow` from the `useDispatchInbox` rows it already holds (`summarizeOpenDispatchAging`, gated on eligibility + first load); the action scrolls to the Teams Inbox card (`#dash-teams-inbox`) or falls back to `/dispatch-mode/inbox`. HR uses the new [`usePendingHrReportsNudge`](../../src/hooks/usePendingHrReportsNudge.ts) (focus-refetch, null under the min age) and navigates to `/people?tab=hr`. Quickfill's twin (`QuickfillNeedsYouSection`) takes `dispatchAged` + `onOpenDispatchInbox` from `Quickfill.tsx` (expands and scrolls to its Dispatch inbox station) and renders the same keys.
