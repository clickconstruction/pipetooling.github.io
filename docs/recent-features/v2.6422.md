# v2.6422 — The dev seat reads a person's HR file whole, as People → HR draws it (2026-11-02)

The People → Paperwork spike's MCP read (the owner, 2026-11-02: a person needs a timeline and a narrative reachable from MCP, like the Legal desk's matters and a development's History), left open by v2.6392. `dev-mcp` 0.17.0; no migration; the function is redeployed after the merge. Builds on v2.6418's lift.

- **`get_person_file(person, lane?, source?, since?, docs?)`** answers the file as the tab draws it: `person` (the roster row), the fact strip (`facts`, `chips`), `counts` by lane and source, `held` (a source that could not be read, with its reason), `ahead` (the lines past today, soonest first), `months` (the record by month newest first, each line as the kernel's `PersonTimelineLine`: the day it is about, its lane, source, kind words, what, notes, who, state, the record it points at and its door), `evidence` (the records newest first with their files and `evidenceDriveWords`), `files_before_records`, and `docs` (the summary and narrative with `covered_through`). `get_history`'s shape: one verb, one reply, the source line named.
- **The kernel `_shared/devMcpPersonFile.ts`** runs the tab's own `buildPersonTimeline` / `personFileFacts` / `personFileFactChips` over the same sources and keys as `src/lib/people/personTimelineIo.ts` — the HR tables by `people.id`, contracts by id and by name, licenses by name, write-ups and attendance by the login's `users.id`, the template and user names after — through the injected `Reader`, every read as the caller under RLS and fail-soft: a failure is named in `held` and takes only itself out; a person with no login has write-ups and attendance held as *needs a login*; the HR sources are not read for a non-dev (`held` says *dev only*, as the panel does), so `view_as` of the office sees the papers and nothing more. `person` is a `people.id`, a login's `users.id` (`find_person`'s key, through `people.account_user_id`) or a name matching exactly one; several matches come back as ids. The lane and source filters are checked against the kernel's lists and refused in words; `since` keeps lines on or after a day; `docs: false` leaves the summary and narrative out of a long file. A source that answers the door's 200 rows is named in `at_cap`.
- **The server** (`dev-mcp/index.ts`, 0.17.0): the tool beside `get_history`, the case beside its case, the instructions name it; the log row carries the person's id and the lines shown. A read verb, so `view_as` runs it.
- **The fake reader** the composite tests run against is its own file now, `src/lib/devMcp/catalogReader.ts` (`catalogReader`, `plainColumns`, `noErrors`), so a second composite test enforces the catalog without copying it; `devMcpComposites.test.ts` keeps its copy untouched this PR (a sibling PR edits that file).
- **Docs**: `dev-mcp/README.md` (the row), `EDGE_FUNCTIONS.md` → dev-mcp, `HR_FILES.md` → The tab, the MCP card's verb table.
