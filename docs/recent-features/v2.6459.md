# v2.6459 — A new flow step never stops the morning reminders (2026-11-03)

A migration that adds a fact or a step to a seeded flow (`flow_steps`) reaches the database before the bundle and the edge functions that know it. On 2026-11-03 the residential Warranty step (v2.6397, fact `warranty_signed`) was pushed while `messages-nudge-dispatch` still ran older kernels: `flowFromRows` kept the unknown fact, `factRead` threw `flows: unknown fact warranty_signed`, and the whole morning run would have failed until the function was redeployed from `main`. This makes the read tolerant, so the next such migration is safe in any order.

## What changed

- **`flows/state.ts`'s read leaves out a fact it does not know.** `preRead` reads only the facts `stepFactById` knows (the seeded list and library papers' `doc:<uuid>:<kind>` facts), for the step, its rounds and its fresh round. A step that gained a newer fact reads by the facts it knows, so it reads as it did before the migration. `factRead` still throws on an unknown id; it is the read's job never to ask.
- **A step with no fact the code knows reads *later*** (`readLane`, right after the skip): it holds nobody, is never *next*, and an aside one never shows, even with a round open. The chain passes it to the step after, and the *since* search walks past it to the step before (`!b.fresh.length`). This is also the rule for a step with no facts at all, which before could be *next* after the head and, as a loop, held the chain; no stored step has no facts (checked on prod 2026-11-03: 54 rows, every fact known).
- **The morning run goes on past one person** (`nudgeRunInputs.ts`'s `nudgeRunReads`): a person whose rows or flow throw is left out and counted in `unread`, which the run's summary already says (*N people could not be read, so the run left them out.*), instead of failing everyone.
- `flowFromRows` (`editor.ts`) still keeps every fact and paper as stored, so Settings → Flows on an older bundle never drops a newer fact on save. Unknown paper ids were already safe: every reader looks a paper up through a fact it knows or with a fallback, and the portal pages read the seed, never the stored rows.
- Docs: `MESSAGES_ARCHITECTURE.md`'s flows section says it once, beside the one list of facts.

## Deploy

After the merge: `supabase functions deploy messages-nudge-dispatch` (it copies the kernels through `_shared/gcKernels/`), then `npm run check:edge-drift` for any other function behind on the copies. No migration.

## Test

`npx vitest run src/lib/flows` — `state.read.test.ts`'s *a fact this code does not know* (every demo person reads exactly as before when every step gains a newer fact, and when a newer step and a newer loop are added second on every lane; Priya's change order with only a newer fact reads *later*), *a step with no facts yet holds nobody and is never next*, `nudgeRunInputs.test.ts`'s incident case (a stored trade flow with a newer fact and a newer step: Tom is read and gets the same text), and `nudgeRunInputs.guard.test.ts` (Greg's flow throws; Tom after him is read). Each fails on the code before this change.
