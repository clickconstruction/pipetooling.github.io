# v2.6123 — Dev MCP keys: the setup command writes Claude Code's settings too (2026-10-30)

Found while closing the signed hours statement exploration (punch list #212): two days of sessions in the Claude desktop app took the dev MCP key for revoked. `.mcp.json` sends `${PT_DEV_MCP_TOKEN}` as the `X-Dev-Token` header, the card's setup command (v2.3686) put the key only in `~/.zshrc`, and an app opened from the Dock never reads a shell profile, so the app's Code sessions started without the variable. The server answers *Missing X-Dev-Token* for no header and *Unknown or revoked dev key* for the unfilled placeholder, which is what every session got, while `/mcp` read the server as connected (the transport, not the key). The same key sent from the Bash tool, whose shell does read the profile, was accepted as a dev. twin-mcp fails the same way for `TWIN_ESTIMATOR_1_TOKEN`.

## What changed

- **`devMcpSetupCommand`** (`src/lib/devMcp/devMcpKeys.ts`) keeps its three parts — drop any old line, append the shell line to `~/.zshrc`, say what to do next — and gains a fourth between them, **`devMcpSettingsWrite`**: `mkdir -p "$HOME/.claude"`, then a node one-liner that reads `~/.claude/settings.json` if it exists, merges `env.PT_DEV_MCP_TOKEN` into it with every other setting kept, and writes it back; python3 runs the same merge when node is not on the path. The key is an argument to both scripts, never text inside them, so there is nothing to escape (`ptd_` + hex). The write runs before the *Saved* echo, so a settings file that is not JSON prints no *Saved*. One line still: one paste, one Return. Tests in `devMcpKeys.test.ts`.
- **The guide** `connect-a-coding-agent` says what the command wrote (two files, which one each tool reads) and that the bare shell line alone does not reach the app; **`docs/dev-mcp/README.md`** → Connect carries the fact.
- The card's words and buttons are unchanged.

## Decisions

- **Claude Code's settings `env`, not `launchctl setenv`.** `launchctl setenv` reaches Dock-opened apps but lasts until the Mac restarts; the settings file is read by every Claude Code session on the machine and survives a restart. Both are outside the repo.
- **Merge, never overwrite.** The settings file holds the person's other choices (a model switch, permissions); the one-liner keeps them and touches `env.PT_DEV_MCP_TOKEN` alone.
- **Not fixed here:** the twin-mcp token has no setup command at all; whoever wires one copies this shape.
