# v2.2317 — Roadmap assignments follow user archiving (2026-08-26)

Owner request: archiving a user should drop them from their roadmap tasks;
restoring should put them back on any task that didn't get a new person.

- **Migration `20260826034043`**: parked-assignments table
  `checklist_tech_tree_task_assignees_parked` + trigger
  `roadmap_assignees_follow_user_archive` on `users` (AFTER UPDATE OF
  `archived_at`, SECURITY DEFINER). Archive parks + deletes the user's
  `checklist_tech_tree_task_assignees` rows on open tasks; restore
  re-inserts parked rows only where the task is still open with zero
  current assignees, then clears the user's parked rows. Completed tasks
  are never touched. Details: `docs/migrations/20260826034043_*.md`.
- **Zero client changes by design**: hard-deleting the rows means the Plan
  lanes, the Dashboard "needs a person" nudge, task-visibility RLS, and the
  roadmap→checklist bridge (which prunes materialized Today items whose
  assignment vanished) all follow automatically.
- Trigger-on-`users` (not edge-function logic) so every archive path is
  covered atomically — `archive-user`, `restore-user`, `merge-users`,
  manual SQL. The People-page roster archive (`people.archived_at`) is a
  different flow and is unaffected.
- Help guide *archive and restore user accounts* documents the behavior.
