# v2.3562 — Sub sheet payments: move or remove one, with a trace (2026-09-17)

Taunya, 2026-09-17: *"I want to be able to delete a payment that was applied to the wrong job."* On Jobs → Subs → Pay the only door was the grey **Edit** button on a payment row, with delete hiding inside that dialog as **Remove**, and nothing could carry a payment to the sheet it belonged on. Mock-up on the design canvas (*Delete or move a payment*). PR 1 of three: this is the office sheet; PR 2 puts the trace on the sub portal; PR 3 brings **Move to job…** to Edit Job → Payments received.

## The row

Every payment and backcharge row in the sheet's Payments table ([`JobsSubLaborFormModal.tsx`](../../src/components/jobs/JobsSubLaborFormModal.tsx)) carries **Edit · Move… · Remove**; below 640px (`useIsMobile`) it is Edit and a **⋯** menu with 44px items. The Edit dialog's own Remove now hands the row to the reason dialog (`SubLaborPaymentModals` → `onRequestRemove`).

## The two dialogs — [`SubLaborPaymentMoveRemoveModals.tsx`](../../src/components/jobs/SubLaborPaymentMoveRemoveModals.tsx)

- **Move this payment**: the same sub's other sheets first (shared assignee, else the sheet's name), a search that opens every sheet; a **What changes** panel reads both sheets before and after (paid, owed, *paid in full*); a reason field seeded *wrong job*. One RPC, `move_labor_job_payment`, re-points the live row — same id, amount, memo, date and `hidden_from_sub`, last slot on the destination — and writes one `moved` event.
- **Remove this payment?**: reason chips *Duplicate entry · Wrong amount · Something else* and **Wrong job → Move it instead** (the door to Move), an optional note. `remove_labor_job_payment` snapshots the row into a `removed` event and deletes it — so every reader of `people_labor_job_payments` (the ledger, the portal, Crew P&L, the Day book) stays correct with no filter — and `restore_labor_job_payment` puts it back within 30 days.

## The trace

Migration [`20260917140000_people_labor_job_payment_events.sql`](../migrations/20260917140000_people_labor_job_payment_events.md): `kind` moved · removed · restored, `from_job_id` / `to_job_id`, the snapshot, `reason`, the actor, `restored_event_id`; `is_office_staff()` policies; the three functions are `SECURITY INVOKER`. [`useSubLaborLedger`](../../src/hooks/useSubLaborLedger.ts) loads the events for every sheet in one fail-soft query (nothing breaks before the push) and exposes `moveLaborJobPayment` / `removeLaborJobPayment` / `restoreLaborJobPayment`. Both the sheet form and the ledger's expanded row draw grey lines from [`subPaymentTraceLines`](../../src/lib/jobs/subPaymentMoveRemove.ts) — *Moved → 922 Michael Palmer · Taunya · wrong job*, *Moved here from 880 Reliant Health-HVAC*, *Removed · Taunya · Duplicate entry* with **Undo** while `canUndoSubPaymentRemoval` says so.

Kernel `subPaymentMoveRemove.ts` (+11 tests): `sheetMoney` (the modal's arithmetic), `sheetLabel`, `planSubPaymentMove`, `rankSubPaymentMoveDestinations`, the reason chips and `subPaymentRemoveReasonText`, `canUndoSubPaymentRemoval`, `subPaymentTraceLines`.
