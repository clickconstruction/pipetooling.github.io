# v2.4644 — Legal portal: a matter carries only what the firm's page shows (2026-10-05)

One edge function (`legal-portal`, deploy after merge); no migration. Item 23 of punch list #85 ([`to-dos/legal-portal-firm-ready/`](../../to-dos/legal-portal-firm-ready/README.md)). Mockup: `mockup-23-shape-payload.html` beside the card — every table's columns before and after.

## The defect

The matter path of `legal-portal` read whole rows and sent more than the page draws: `customer_addresses *` (the office's note), `job_demand_letters *` (the whole draft in `fields`, the debtor's address and email, the exhibit storage list), `job_lien_filings *` (the office's note on the copy, the draft fields, every address and email in `sends`), the customer's whole `contact_info` JSON and terms note, the job's Drive and photo links, and up to 500 job-note bodies with their authors.

## What the page reads

Traced through `buildMatterPacket` → `buildLegalPacket` (coverage, promises, chase touches, the lien paper and timelines) and `LegalFirmMatterView`, the office print and the firm print on #4601. Each table's list is in [`_shared/legalMatterShape.ts`](../../supabase/functions/_shared/legalMatterShape.ts), one comment per list saying what it holds and what it never sends.

## What changed

- `legalMatterShape.ts` (`src/lib/legal/legalMatterShape.ts` re-exports it): `MATTER_JOB_COLUMNS`, `…INVOICE…`, `…PAYMENT…`, `…CUSTOMER…` (+ `MATTER_CONTACT_INFO_KEYS`), `…CONTACT_PERSON…`, `…ADDRESS…` and `…PROPERTY_OWNER…` (item 2's lists), `…CONTRACT…`, `…ESTIMATE…`, `…DEMAND…`, `…FILING…`, `…ENTRY…`; `MATTER_COUNSEL_SELECT` (each list plus the PDF storage paths only the function reads); `shapeMatterForCounsel(matter)`, which cuts every row of a built matter to its list, demand `fields` to the fee clock and the enclosures, filing `sends` to recipient, method, tracking and day, and job notes to `{ jobId, createdAt }`.
- `legal-portal`: every matter-path select uses `MATTER_COUNSEL_SELECT`, the `legal_matters` row and item 6's `jobAddresses` / `jobOwners` reads included (no `select('*')` left on the matter path; the recipients read is the Notifications page's, not the matter's); job notes read `job_id, created_at` only, up to 2000 rows so the per-job count is right; authors of notes no longer feed the name lookup; each built matter is returned through `shapeMatterForCounsel`.
- In that are new: `acknowledged_at` on entries (the page reads it: a withdrawn office ask showed as open and a seen act as *waiting on the office*), and `customer_address_id` on jobs for item 6. `MATTER_PROPERTY_OWNER_COLUMNS` (no `owner_email`) is ready for item 6's owner read.
- `docs/EDGE_FUNCTIONS.md` (legal-portal) lists what goes out and what does not.

- **Integration pass (review fixes).** Item 6's keys are shaped too: `jobAddresses` with the address list and `jobOwners` with the owner list (no owner email); the unused `propertyOwners` key is gone. `MATTER_INVOICE_COLUMNS` keeps `sequence_order` (the payment rule orders bills by it, item 5) and adds `created_at` (the promise rule's `COALESCE(billed_at, created_at)`, item 9). `MATTER_JOB_COLUMNS` carries `contract_not_needed_at` / `_reason` (item 4). `MATTER_ENTRY_COLUMNS` lists item 18 PR 2's `voided_at`, `voided_via_portal`, `void_reason`, so a voided entry never travels as live; the select leaves them out (`MATTER_ENTRY_PENDING_COLUMNS`) until #4637's migration exists, and #4637 empties that list. The `legal_matters` row is read by name (`MATTER_ROW_COLUMNS`). The payer's `payment_terms` and note no longer travel (item 4 took *Terms* off the firm's page).

## Is this the best we can do?

- **Why shape twice?** A select list is a promise only until someone widens it. The kernel and its test are the contract.
- **Why keep the contact person's `note`?** It is the only field saying who the person is, and the printed packet prints it. The table has no role column; the firm print on #4601 reads `role`, which nobody sends, and should read `note`.
- **Why keep a filing's `document_url`?** The Paper tab's Copy column draws it. Which documents travel is item 12.
- **Found, left alone:** coverage reads `bid_id`, `contract_not_needed_at` and `contract_not_needed_reason` on jobs, which were never sent; sending them changes what the firm sees, so it waits for its own item. The GC's name is looked up only among the matters' payers, so a job whose GC is not the payer reads *GC*.
