# v2.3327 — Cash App reconciliation, PR 3: decisions on the review list, proxy rules on the names step (2026-09-11)

Client only (tables v2.3321; import v2.3323). The review list in the Cash App reconcile modal (People → Pay → Payroll → Pay run → **Cash App…**) becomes actionable.

## What shipped

- **Kernel [`cashAppDecisions.ts`](../../src/lib/cashapp/cashAppDecisions.ts)** (+6 tests): `cashAppPaymentMemo` (`Cash App #D-… "Week"` — rule (a) of the matcher reads the id back), `suggestReportForSend` (open reports for the person with something left to pay; prefers the latest whose period ended on or before the send date, else the earliest; amount clamped to what that report can take), `clampRecordAmount`, `advanceOffsetInsert` (a pending `person_offsets` row of type `advance`, dated the send day, description = the memo).
- **Review row decisions** in [`CashAppReconcileModal`](../../src/components/people/CashAppReconcileModal.tsx):
  - **Record** opens an inline editor (report select showing `period · $left`, amount prefilled) and on Save inserts `pay_stub_payments` (`paid_at` = local noon of the send day, memo = the Cash App memo, `created_by`), then files the row `recorded` / `match_rule = manual` / `pay_stub_payment_id`, and calls the tab's `loadPayStubs` so Paid to date and Balance update behind the modal. The existing DB trigger still refuses a payment past Net Pay.
  - **Advance** inserts the pending offset and files the row `advance` with `person_offset_id`. The Less modal already lists every pending offset for a person regardless of type, so the advance is offered as a Less line on the next report with no further change.
  - **Already recorded** → `recorded` with `match_rule = manual` and no payment link — for a send whose money already sits on a report under a different amount or date (Paige, Darren and Abraham have every report paid, yet dozens of sends with no exact match; recording them again would double-pay). **Not pay** → `expense`; **Skip** → `ignored`. All stamp `decided_at` / `decided_by`.
  - Rows whose name is not tied to a person can only be skipped or marked not pay; the buttons say so.
- **Proxy rule editor** on the names step: a **proxy** tick reveals "when the note contains ___ it's for ___", saved as `note_contains` / `note_person_name` on the alias (the rule the owner needed for Taunya → Tristen, set by hand in PR 2).
- The tab now passes `openReports` (every report with `remaining` = net − paid, from the same helpers the rows use) and `onRecorded`.
- Help: `reconcile-cash-app-payments.md` gains "Decide each send"; `GLOSSARY.md` gains **Cash App reconcile**.

## Not changed

The matcher and lanes. No new tables. Recording still goes through the same `pay_stub_payments` row the Record payment modal writes.
