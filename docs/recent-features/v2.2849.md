# v2.2849 — twin-mcp: `paste_counts` (STG-5 as a verb) + zero-row unseal gate (2026-09-05)

Born from the 2026-09-05 backfill of the seven "draft $0" audit cards (b422, b424–b429 — estimates that lived only in lock notes): STG-5 had no API, so the backfill needed a hand-rolled REST script, and nothing stopped a robot from scoring a bid whose audit card would read $0. Edge only (`twin-mcp` v1.3.4 — deploy after merge; `briefs.ts` unchanged, FEEDBACK_LOOP.md isn't bundled).

- **`paste_counts(bid, rows, expected_total?, replace?)`** — writes `bids_count_rows` + `bid_pricing_assignments` together, inside the twin fence. Each row names the 🤖 Robot Default `book_entry` to assign (matched against the global robot `price_book_versions` row for the bid's service type; unmatched names refuse the call — extend the book first) and may carry `unit_price_override` for lump/LOCK-stated prices. **The FEEDBACK_LOOP step-0 invariant (tab total = lock) is enforced server-side**: with `expected_total` passed, a mismatch beyond $1/0.1% refuses the paste. `replace: true` rewrites existing rows (clears assignments/custom-prices/hides first); unit vocabulary ea/ft/px/sqft, null infers from the name. Stamps `[pipeline STG-5]` on the ledger.
- **`score_backtest` refuses zero-row bids** — after the LOCK-note check, a bid with no PipeTooling count rows gets "run STG-5 first" instead of an unseal, so an unpriceable audit can never reach Wendi's queue again.
- Docs: FEEDBACK_LOOP.md step 0 names the verb; EDGE_FUNCTIONS.md → twin-mcp carries the contract.
