# v2.3702 — People spine, PR 5: Users lenses — one roster, three column sets (2026-09-21)

PR 5 of the People spine train ([`to-dos/people-spine/README.md`](../../to-dos/people-spine/README.md); PR 1 = v2.3698, PR 2 = v2.3700, PR 3 = v2.3701; the planned PR 4 — `person_id` on the pay tables — turned out to be already in place since Phase B/B2 in July, `20260722268000` / `20260722270000` / `20260730164728`, so it ships nothing). Client only.

## What was wrong

The same person was edited from three tables: Settings → Active Accounts (role, training, supervision, sign-in, archive), Pay → **People pay config** (a modal: wage, office rate, salary, record hours, vehicle deal) and People → Users (contact, grouping). The modal built its own grouping of the roster (`payConfigRosterSections`, 60 lines in `People.tsx`) that mirrored the Users tab's, and `usePayConfig`'s salaried-template indicator read that grouping through a ref.

## The change

- **[`usersTabLens.ts`](../../src/lib/people/usersTabLens.ts)** — `UsersTabLens = contact | account | pay`; `parseUsersTabLens`, `usersTabLensesFor` (pay needs pay access; a phone shows contact only), `resolveUsersTabLens` (a lens the viewer may not use falls back to contact — never a blank roster), `lensForcesNoLoginOpen` (the pay lens keeps the no-login fold open so every pay-config person shows), `USERS_TAB_PAY_LENS_PATH`. Four tests.
- **[`PeopleUsersTab`](../../src/components/people/PeopleUsersTab.tsx)** — `?lens=` from the URL (`useSearchParams`, replace), a segmented switch beside the search on wide screens, the lens header in place of the needs-rail header, and `lensCellsFor` per row. New props: `payLens` (the `usePayConfig` cluster), `setTrainingMode`, `canEditWorkdayOverrides`. **[`UsersTabRow`](../../src/components/people/UsersTabRow.tsx)** gains `cells` — when set, the lens cells replace the contact span, the note and the needs rail; name, chips and the ⋯ menu stay.
- **[`UsersTabLensCells`](../../src/components/people/UsersTabLensCells.tsx)** — `UsersTabAccountCells` (role, last sign-in via `describeLastSeen`, training checkbox → the desk's own `users.read_only` write under the same guard, supervision checkbox → the existing `setNeedsSupervision`, a *Desk* door to Access & account for password / name / merge / archive), `UsersTabPayCells` (the pay inputs + *Workday…* for salaried rows with a login), `WorkdayScheduleModal` (the desk's own `SalaryWorkScheduleSettings` host). **[`PayConfigCells`](../../src/components/people/PayConfigCells.tsx)** — the modal's `PayConfigRowTr` lifted as flex cells with shared widths; `PeoplePayConfigModal.tsx` deleted.
- **`usePeopleRoster`** — the users select carries `read_only` and `last_sign_in_at` (`UserRow`). **`usePayConfig`** — `loadPayConfigSalaryTemplateIndicators` reads the pay-config names, not a roster grouping; `payConfigRosterSectionsRef` gone from its deps. `People.tsx`: the modal, its state, the 60-line grouping memo and its ref are gone; the indicator loads while the Users tab is up.
- **Payroll tab** — the *People pay config* button is a link to `/people?tab=users&lens=pay`.
- Docs: `PEOPLE_TABS_ARCHITECTURE.md` (Users and Payroll dossiers), `twins/APP_DIRECTORY.md` (`/people`), `GLOSSARY.md` (*Users lenses*); guide *see everyone's pay setup*.
