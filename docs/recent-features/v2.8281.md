# v2.8281 — The Bridge: a dev who shows ZZ tests keeps them when the list leaves something out (2026-11-21)

The last of the faults punch list #334 wrote down under *Found while building, not built*. No migration. Nothing changes on the Monday email.

## What was wrong

Every job-keyed read on the Bridge takes one set of job ids, `zzTestJobIds`, and reads it two ways at once. A row leaves when its job is in the set. And any set at all means *this viewer hides ZZ tests*, so a row whose names say ZZ leaves too, and so does every ZZ bid.

`withLeftOutJobIds` made that set from two things: the ZZ jobs of a viewer who hides them, and the jobs the left-out list names. For a dev who shows ZZ tests the first is nothing. With an empty list the reads got null and every ZZ job stayed. Once the list named one job the reads got a set, and every ZZ job and ZZ bid left the pipe, the step windows and the people tables.

Confirmed on `main`, in the code and on the page at `localhost` on live data. The live list names two things. With the dev's switch set to show ZZ tests, the pipe's Sales step read **$13.4k sold a week**, the same as with the switch off. With this fix it reads **$20.5k**: a ZZ test bid marked won counts again. The switch is a line in this browser's own storage for `localhost`, set for the look and taken off after.

## What changed

The card's plan was to give each read two things in place of one, the switch and the ids, which touches every loader the page has. This does the same with one value and no loader changed.

- **`jobIdsAlone(ids)`** (`src/lib/jobs/zzTestJobVisibility.ts`): a set of job ids that leaves out those jobs and reads no name. To a read that only asks `has` it is a set like any other. **`leavesOutByIdAlone(ids)`** tells it from a plain set and from none.
- **`withLeftOutJobIds`** (`src/lib/bridge/leftOut.ts`): for a reader who keeps ZZ tests, the list's jobs come back as ids alone. For a reader who hides them it is the plain set it always was.
- **Four kernels read the difference**, the four that read a name: `withoutZzTestJobRows` and `withoutZzTestJobMoney` (the jobs' own names), `bridgeZzJobIds` (the ZZ jobs a read's rows name) and `withoutZzBridgeBids` (the ZZ bids). Under ids alone each drops the list's jobs and nothing else. Every other kernel was keyed by id already.
- **`useDashboardFinancials`** made its own copy of the join for the page's money read. It now calls `withLeftOutJobIds`, so the money follows the same rule.

## The totals that move

Only for a dev who shows ZZ tests, and only while the left-out list names something. Every job-keyed figure on the page can move, by the ZZ jobs and ZZ bids the list does not name: the pipe's five steps, the money owed both ways and the accrual balance, the people's hours, the step windows, the bids due. They move back to what that dev read before the list existed, less the jobs the list names.

On the live page today one figure moved for that dev: Sales, from $13.4k to $20.5k sold a week. Market, Build, Bill, Collect, the cash balance, the accrual balance and *Made this week* read the same with the switch on and off.

**The list still wins over the switch.** A ZZ job on a development, a customer or an address the list names is left out for this dev too. The live list names a ZZ test development, so its jobs stay off the page whatever the switch says.

## What does not move, and the tests that hold it

- **A viewer who hides ZZ tests.** Their set is a plain set, and `leavesOutByIdAlone` is false for a plain set, so every read runs the lines it ran before. No test that was there changed but one, which held the old identity of the set: the 686 others in `src/lib/bridge` and the visibility kernel pass as they were. On the page, with the switch off, each figure the walk read was the same before and after.
- **A dev who shows ZZ tests with an empty list.** The reads get null, as before.
- **The rule, viewer by viewer.** `zzTestsShownWithAList.test.ts` (new, 14) names the three viewers by the ids the page hands a read: null, the list as ids alone, and a plain set. Each kernel of `zzTestJobs.ts` is held under all three, with counts and dollars as literal numbers for Ready to Bill and Collections. Five loaders are read under all three over one made-up database: the asks and the bids, the build pace, the Market window, the Sales window and the Bill window. In each, the read under the list equals the read with no list less the list's job, and the read of a viewer who hides ZZ tests is the one there was.
- **The shared kernel.** `zzTestJobVisibility.test.ts` (6 more): rows and money under ids alone and under the same ids as a plain set.
- **The join.** `leftOut.test.ts` (2, one rewritten): ids alone for a reader who keeps ZZ tests, a plain set for one who hides them.

Twelve of the new tests fail with the Bridge's side of the fix taken off.

## Edge functions

`leftOut.ts`, `zzTestJobs.ts` and `zzTestJobVisibility.ts` are copied to the edge functions; `npm run gen:edge-kernels` ran. The Monday email always hides ZZ tests, so it reads a plain set and counts as it did. `npm run check:edge-drift` will name the functions that hold the copies as behind until each is next deployed. Nothing is owed for behaviour.
