# v2.2502 — Edit Bid saves prune to dirty fields (stale-form clobber fix) (2026-08-30)

Bug observed live on prod bid b403 (2026-08-30): the Edit Bid modal seeds its form from
the board's cached bid row (`openEditBid` → `bidForm.loadFromBid`), and both save paths
(`saveBid`, `saveBidAndOpenCounts` in `src/pages/Bids.tsx`) wrote **every** payload column
back on update. Any column written server-side after the board row was fetched got
clobbered by an untouched Save: drive-intake (v2.2499) stamped `plans_link`, the user
opened Edit Bid (form seeded with the pre-stamp empty value), hit Save without touching
anything, and the stamp was silently nulled.

Fix — dirty-tracking, generalized to the whole update payload:

- `useBidEditForm` now snapshots the loaded values (`initialValues`; the row→values
  mapping is extracted as pure `bidRowToFormValues`). `reset` clears the snapshot.
- New kernel `src/lib/bids/bidUpdatePrune.ts` (`pruneUnchangedBidUpdateFields`): drops
  payload keys whose driving form fields equal the snapshot. Coupled columns travel as
  groups (`outcome`+`loss_reason`+`loss_category`; `bid_due_date`+`bid_due_time`;
  `customer_id`+`gc_builder_id`), parent-owned `bid_date_sent` compares via
  `normalizeBidDateInput` against `savedBidDateSentRef`, and **unmapped keys are always
  kept** (attestation columns, future additions fail safe toward the old behavior).
- Both edit-save paths prune before `update()`; an empty diff skips the DB write.
- Inserts (new bids) still send the full payload.

Why dirty-tracking over refetch-on-open: a refetch only narrows the staleness window and
races the user's typing; the prune closes the entire open→save window deterministically,
and covers cross-user concurrent edits of *any* field, not just the link fields.

Bonus fix the audit surfaced: the payload always wrote `gc_builder_id: null`, so editing a
legacy builder-linked bid (no `customer_id`) and saving untouched erased the builder link.
With pruning, an untouched GC picker drops both keys and the legacy link survives.

Tests: `src/lib/bids/bidUpdatePrune.test.ts` (11 cases, incl. the b403 repro shape).
