# v2.7416 — Painted maps: a shared map opens only for a reader who gave a name (2026-11-15)

Punch list #345, the link that asks who is looking, step E, the last. Until now the name step was the page's: someone who knew the function's address and a link's code could still read the map the old way.

## What changed

- **The plain `GET` no longer answers the map.** It answers 403 with *This page is out of date. Reload it to open the map.* The map opens by `way.open` alone, which keeps a visit beside a name.
- **A photo needs a device that gave a name.** The photo's address carries the device's id since v2.7414, and the function now answers only a device with a visit on that link. Anything else reads as a link that is gone.
- A wrong code, an ended link and an expired one read as before.
- **A re-open no longer wipes the screen, the language and the time zone.** The live call of v2.7413 showed it: a second `way.open` that left them out wrote them empty. Each is now written only when the page says it.

## Who this touches

- **A reader who gave a name:** nothing changes.
- **A page left open from before v2.7414,** or one a phone's cache still serves: it says it is out of date. A reload brings the page that asks for a name.

## Is this the best we can do

- **The gate is a name and a device id the page made up.** Someone who writes their own call can send any name and any id. What the gate buys is that nobody reads a map without leaving a row, and that row has the address the call came from. Proving who a person is needs a sign-in, which is what the link exists to avoid.
- **An old page is told to reload, not reloaded for them.** It cannot be reached to do more.
