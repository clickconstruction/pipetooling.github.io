# v2.4710 — AIA G702-G703: the job's pay applications read as a history (2026-10-06)

The owner, 2026-10-06: *"In the tool, are we able to see the history of what was created in the tool for the job previously?"* The window listed the saved applications as chips (number, period, payment due) and the kept workbooks sat lower on the Documents tab in the mixed *Sent from this job* list; nothing said when an application went out, who saved it, or that a later save changed it. A mock-up (https://claude.ai/artifact/7x1hxdFQbgdoh9RRhhLHeB) drew a six-column ledger first, critiqued it (too wide for the form column; "changed since" as a timestamp guess; the blank new application as the first frame; deleted rows gone) and settled on a history strip that opens first. This is the first of three PRs; the owner: *"build C"*. Client only: no migration, no edge function.

## The change

- **Kernel** [`aiaPayApplicationHistory.ts`](../../src/lib/aiaPayApplicationHistory.ts) (new): `payApplicationHistory(apps, sent)` — one line per saved application in number order with the pay-application sent copies filed on it (`source_id`), newest first; copies with no source under `unsaved`; `payApplicationSummary` from the latest application (contract to date, completed and stored, fraction, held, certified to date, work left); the words (`payApplicationSummaryWords`, `payApplicationSavedWords` with *saved again* when the two stamps differ, `payApplicationWentOutWords`, `payApplicationFileName`).
- **The saved application carries its stamps**: `SavedPayApplication.createdAt / createdByName / updatedByName` (the table always stamped `created_by`/`updated_by`; the IO now reads them with the users' names through the two foreign keys, falling back to the old column set on `PGRST200`).
- **Window** [`AiaG702G703Modal.tsx`](../../src/components/jobs/AiaG702G703Modal.tsx): a `view` of `history` or `form`. On a job with saved applications and no application asked for, the window opens on [`AiaG702G703History.tsx`](../../src/components/jobs/AiaG702G703History.tsx) across its whole width: the summary line and four numbers with a bar, a line per application (number, name, period, payment due, Open; under it the saved words, each workbook that went out with a file door through `openSentFile`, the carry-mismatch flag), the workbooks downloaded with no number, and **New application · N**. The chips are gone from the form: its top names the application (*Application 2 · August* / *New application 3*), says who saved it, and carries **← Pay applications** back (asking about typed work; on Leave the form resets). Generate reads the sent copies again once the workbook is filed. Delete lands on the history while applications remain. `startOn="new"` (the Documents tab's *New application* button) skips the history.
- **Documents tab** [`JobWindowDocumentsTab.tsx`](../../src/components/jobs/JobWindowDocumentsTab.tsx): reads the job's sent copies once; the Pay applications table gains **Went out** (each workbook as a file door with its time, then the pasted link) and **Saved** columns and a line for the unsaved workbooks; `JobDocumentsSent` takes `rows` and lists everything but the pay application copies.

## Not built (the next two PRs)

- *Changed after it went out*: Generate filing the carried amounts with the workbook, so a later save is named with the figure that moved rather than guessed from timestamps (a column on `sent_documents`).
- A deleted application staying in the history (soft delete on `job_pay_applications`).
- A paid line tied to the bill the application became.
