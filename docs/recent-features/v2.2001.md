# v2.2001 — Portal modal: live preview, gear advanced menu, red off-globe, link history (2026-08-21)

Upgrades the portal globe modal (`CustomerPortalGlobeButton`):

- **Live preview**: an `<iframe>` of the real `/portal?t=…` page, scaled to 0.62
  inside a fixed-height frame, sits below the action row. Switching the
  As customer / As GC toggle re-resolves that audience's link and the preview
  follows. No duplicate rendering — it is literally the customer's page.
- **Gear → Advanced**: Rotate and Turn off moved out of the main action row
  into a gear-toggled section (same gear SVG as the header settings menu),
  alongside a **Link history** list.
- **Link history**: rows of `customer_portal_links` for the audience, newest
  first — "Created <date> by <name> — active now / rotated <date> / turned off
  <date>". Rotation vs turn-off is inferred by a successor link created within
  a minute of the revocation (`buildPortalLinkHistory` kernel).
- **Red globe + sticky off state**: `usePortalOffStates` keeps a module-level,
  one-query-per-session cache of (customer, audience) pairs whose links are all
  revoked ("turned off"); globes for those customers render red. Opening the
  modal for a turned-off pair now shows an explicit off panel with **Turn
  portal back on** instead of silently re-minting (the old behavior would have
  revived a deliberately killed portal).

No migration: everything reads the existing office-readable
`customer_portal_links` table (RLS SELECT policy from 20260821213000; raw
tokens client-readable since the 20260821223000 v2 model).

Kernel: `src/lib/portal/portalLinkState.ts` (`computePortalOffKeys`,
`buildPortalLinkHistory`) with unit tests; render smokes updated for the gear
flow and the no-silent-remint rule.
