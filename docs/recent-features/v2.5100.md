# v2.5100 — GC mode: only Award changes a trade's award (2026-10-09)

The Board lane: migration `20261010025000_gc_award_guard`, pushed after merge. No client change, no edge function. The plan is `to-dos/gc-mode/mockups/board-b6.md` → *The award guard* on branch `spike/gc-mode`; the doc is `docs/migrations/20261010025000_gc_award_guard.md`.

## Why

B6-a (v2.4934) put the award on `gc_trade_packages` (`awarded_invite_id`, `awarded_by`, `awarded_on`) and wrote it in `gc_award` only, behind a dev-only gate, the vetting check in SQL and the statement of work's draft. The table carries door 1's team policy for every verb, so the whole office team (dev, master, assistant, controller, estimator) could set or clear an award with a plain UPDATE through REST. Found after the 10-09 stop in a docs audit; nothing on prod was written that way.

## What changed

- **`gc_trade_packages_award_guard`**, a BEFORE INSERT OR UPDATE row trigger: a signed-in person's write that sets or changes any of the three columns is refused (*A trade's award changes only through Award and draft the statement of work in Compare quotes.*), a dev's too. It passes `gc_award`'s own write (the transaction's `gc.award_write` flag), a key letting go inside its own trigger (an ask's or a user's `ON DELETE SET NULL`), and server code with no person (the service role, migrations, the beds' fixtures).
- **`gc_award`** restated as B6-a made it, with the flag turned on just before its UPDATE and off just after. Award's door (call W) will change only its gate.
- **Proof:** the `gc_award` SQL bed gains the guard's eight refusals, the flag off after `gc_award`, an estimator's ordinary edit of an awarded trade, the award's day CHECK still refusing under the flag, and a user's delete clearing who awarded. Its runner re-applies B6-a's migration and then this one. `awardSql.test.ts` holds the new refusals to the plain-words rules.

## Not done

Deleting an awarded trade, which the team policy allows and which takes its statement of work by cascade, is its own Board piece (a DELETE guard after call W).
