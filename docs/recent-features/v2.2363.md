# v2.2363 — Multi-add GCs on Edit Bid's "Also sent to" row (2026-08-26)

Estimator request (Wendi): "ability to add multiple GCs on this page" — said on Edit Bid. The
row could already add more GCs, but the picker closed itself after every single pick and wiped
the search, so adding four GCs meant four open→search→click cycles and most people concluded
only one was possible.

- `BidGcRecipientsRow` picker is now a stay-open multi-select: checkbox rows, search preserved
  between ticks, a footer with a running tally ("3 ticked") and one commit button whose label
  counts ("Add 3 GCs"). Cancel or Esc closes without adding. Commit does a single bulk insert
  into `bid_gc_recipients` (source `'manual'`), then appends all chips at once.
- New footnote under the row states the model in one line — GCs added here get the **same
  letter** as the bid's GC (named, e.g. "Loberg Contracting", not "the GC above") — and routes
  to ＋ Add GC on the bid's pages / "track separately" on the Send to strip for a builder that
  needs its own prices. Shown only when the row is editable on a saved bid.
- Pickable-filter + label logic extracted to a pure kernel `src/lib/bids/gcRecipientPicker.ts`
  (`filterPickableGcs`, `addGcsButtonLabel`, `tickedSummary`) with unit tests.
- No schema change: same `bid_gc_recipients` one-row-per-GC model; the own-packet ＋ Add GC flow
  on the bid's pages is untouched. The New Bid form still requires saving first (possible
  follow-up: queue GCs pre-save).
- Help guide `bid-one-project-to-multiple-gcs.md` ("Also sent to" section) updated for the
  multi-select and the footnote.
