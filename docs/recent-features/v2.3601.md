# v2.3601 — Prospects → Hiring: candidate cards that read the same way every time (2026-09-18)

Todd, 2026-09-18, looking at the live board: *"do you see some of the visual issues with this?"* — a screenshot where "TJ Thompson" was six lines of two letters beside the *also in: Plumber* and *call next* badges, "Sergio Padilla" split in two, an Indeed relay address broke as `indeedemail.co / m`, phone and email sat on one line for one card and two for the next, the red **Passed** button orphaned on its own line under Talked today / Advance, and every never-rated card carried three grey "—" bars. Client only, one component.

## The change

All in `SortableCandidateCard` / `CandidateRatingBars` ([`TeamProspectsTab.tsx`](../../src/components/prospects/TeamProspectsTab.tsx)):

- **Line 1 is handle · rank · name · gear.** The header row was one non-wrapping flex line where every badge was `white-space: nowrap` and the name was the only shrinkable item (`min-width: 0; overflow-wrap: anywhere`), so the badges won and the name broke at every character. Now the name is `flex: 1 1 auto` and the only thing on the line that grows, the handle, rank and gear are `flex-shrink: 0` and top-aligned (`align-items: flex-start`, matched line-heights) so they stay on the first line of a wrapped name.
- **Line 2 is the badges** — duplicate / also in / call next / trade — in their own wrapping row, rendered only when there is one.
- **The contact block is a column**, one fact per line: phone, email, source, last contact. It was a wrapping row, which is why cards disagreed about where the email went. The email renders through `EmailText`, which puts a `<wbr>` before the `@` so a too-long address breaks there first; `overflow-wrap: anywhere` stays as the last resort for an address whose domain alone will not fit.
- **The action row fits.** Talked today · Advance · Passed measured 245px in a 239px row, which is why Passed always wrapped. The two primary buttons lose 0.1rem of side padding each, and Passed becomes a quiet text button (no fill, no border, no shadow, `margin-left: auto`) at 0.4rem — 230px, on one line.
- **No bars until someone rates.** `CandidateRatingBars` returns nothing when all three dimensions are null. The help guide's sentence about the bars now says so.

## Verified

`npm run typecheck`, eslint on the file, `theme-tokenize --check`, the suite. On the dev server against prod data: Kevin (call next, no ratings) shows the name on one line, the badge below, no bars; Sergio Padilla's Indeed address wraps before the `@`; every card's three buttons sit on one line.

## Not in this

The column width (300px) and the board's horizontal scroll are unchanged. The Interview / Hire / Review cards were not touched — they lay out their own rows.
