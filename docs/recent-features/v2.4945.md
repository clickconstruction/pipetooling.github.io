# v2.4945 — People: the Hours tab's duplicates banner is its own piece (2026-10-08)

Punch list #46 ([`to-dos/decomposition-queue.md`](../../to-dos/decomposition-queue.md)), row 6: the first of the smaller cuts that [`PEOPLE_TABS_ARCHITECTURE.md`](../PEOPLE_TABS_ARCHITECTURE.md)'s step 8 names for `People.tsx`'s Hours shell. A verbatim move. Client only.

## The change

- **[`usePeopleMergeDuplicates`](../../src/hooks/usePeopleMergeDuplicates.ts)** holds what the page held for the banner: the duplicate list, the name being merged, the effect that looks for person/user duplicates, and Merge.
  - Merge finds the account by email, else by name, then calls `mergePersonIntoUser`. It reloads pay config, drops the row, and calls the page's `afterMerge`, which reloads the Hours grid when it is showing.
  - It returns `dropMergeDuplicate`, so the Users residue's `inviteAsUser` still drops the duplicate it merged on invite.
- **[`PeopleMergeDuplicatesBanner`](../../src/components/people/PeopleMergeDuplicatesBanner.tsx)** is the banner's markup, moved verbatim. It draws nothing when there are no duplicates. The page still gates it on `canAccessPay`.
- **[`People.tsx`](../../src/pages/People.tsx)** loses 2 `useState`, an effect and the handler: 62 lines out, 18 in.

One difference in timing: the look-up effect now runs when `canAccessPay` resolves, as well as on its old triggers. Before, it read `canAccessPay` without listing it. The result is the same, because the pay config it needs loads after access resolves.
