# v2.2162 — Per-GC outcome; Bid Board rows by GC (Bids by GC, G3) (2026-08-23)

G3 of the owner's "Bids by GC" model (proposal claude.ai/code/artifact/a2878573-eb4d-47d9-abaf-e4cbd942a811). "Won with SPC, lost with BURD" becomes recordable.

- **Migration `20260823145006_bid_versions_outcome.sql`** — `bid_versions.outcome text`, `outcome_at date`, `outcome_note text` (additive, idempotent). `bids.outcome` stays the roll-up.
- **Kernel [`gcPackets.ts`](../../src/lib/bids/gcPackets.ts)** (+3 tests): `groupVersionsByGc(versions, { bidGcName, gcNames, latestSends, bidDateSent })` → packets (bid GC first) with `sentOn` (latest per-version send; pre-v2.2124 bids fall back to `bid_date_sent` for versions that existed then), `sentValue`, `outcome`; `rollUpOutcome` (won if any won; lost only when every sent packet lost). Now the single grouping used by the picker, the board and Followup.
- [`gcPacketOutcome.ts`](../../src/lib/bids/gcPacketOutcome.ts) `setGcPacketOutcome` writes the packet's versions (`outcome`, `outcome_at` today) and rolls the bid up conservatively: a GC win sets `bids.outcome='won'` unless already won/started; all-lost sets 'lost' only when the bid isn't already decided.
- **Hook [`useBidGcPackets`](../../src/hooks/useBidGcPackets.ts)**: versions + sends + customer names for a list of bids, recomputed on `bid-version-sends-changed` / `bid-version-picker-reload` / `bid-gc-outcome-changed`.
- **Bid Board** (`BidsBidBoardTab.tsx` → [`BidBoardGcRows`](../../src/components/bids/BidBoardGcRows.tsx)): under a row whose bid has >1 packet or any GC override, one line per GC — name · sent m/d · ★ $value · outcome select (waiting… / won / lost). Phone-width cards show the same lines (`BidBoardGcLines`).
- **Followup → Full bid details** (`BidPackageSendsDetails`): "Sent to — by GC" with the same outcome select; versions listed under each GC.
- Picker refactored onto the shared kernel (no visible change).

Not yet: Why-we-lost / hit-rate lenses per GC (they still read `bids.outcome`), mobile card rows. Verified live on BP364 after `db push` (see PR).
