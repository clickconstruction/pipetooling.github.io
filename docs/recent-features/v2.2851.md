# v2.2851 — Nothing is saved until you commit: contract quick-send, RFQ copy link and the change-order bridge write after confirm (2026-09-05)

Journey-map Phase 4, Tier-1 #14(a) "Opening or picking mints a record" — three of the seven sites: J32-F2/N3/N4/adj-1 (contract quick-send), J12-N1/N3 (RFQ copy lane), J16-2 (Bids → Estimates change-order bridge). Owner decision 17 (2026-09-05): **the house rule is write after an explicit user commit** — a pick, an open, or a copy attempt is intent, not a record. Where a row must exist for the next step, the row is created inside the commit action itself.

## The rule, applied

Each surface keeps its UI; only the *moment of the write* moves. The decision that used to be made-and-executed on open is now made on open (pure kernel, tested) and executed on commit.

### 1. People → Contracts quick-send (`PeopleContractsTab.tsx`, `src/lib/contractsQuickSend.ts`)

**Before**: `openQuickSendForPerson` ran three branches on pick — reuse an existing content-bearing row (no write) · content-fill `UPDATE` of an empty placeholder · `INSERT status:'unsent'` — then opened the Send modal on the row id. Cancel reset modal state only; the guide's "What canceling does" documented the leftover as intended. The assistant, who owns the compliance half, could mint but not delete (`canDeletePeopleContracts` = dev|master), and every abandoned pick fed "Needs attention · N" and the Person rail's "N documents unsent" (J32-adj-1).

**After**: the pick computes a `QuickSendPlan` — `quickSendPlan({ existing, source })` → `reuse | fill | insert | no-content` (extracted, `contractsQuickSend.test.ts`) — and opens the Send modal carrying `{ personName, documentName, plan }` in `contractSendQuickSend` state. `reuse` still targets the existing row id; `fill`/`insert` leave `contractSendDocId` null. The modal's preview, portal lookup and default subject read a `contractSendTarget` derived from either the row or the pending pick. **`sendContractForSignature` materializes the row** (`materializeQuickSendRow`: the same UPDATE/INSERT payloads, moved) right before the `send-contract-for-signature` POST, pins the new id into `contractSendDocId` and flips the plan to `reuse` so a failed send retries against the same row instead of minting twice. Cancel resets state — nothing to undo. The `ContractQuickSendPicker` `busy` guard is passed `false` (a pick no longer writes, so double-taps have nothing to double-create). The office-section queue that landed with Contract Forms does not use this helper (it goes through `officeQueue`/`officeSectionPending` and writes on submit) — unaffected. Add document → Save/Send now is untouched: that path saves on purpose.

### 2. Bids → Supply house list → Copy with quote link (`PrepareFixtureCopyModal.tsx`, `src/lib/rfq/rfqCopyLane.ts`)

**Before**: `copyWithQuoteLink` inserted the `bid_rfqs` row (`status:'sent'`, **no `created_by`**) and then called `navigator.clipboard.writeText`. Live-proved on BP398: a clipboard failure ("Document is not focused"/denied) threw after the insert → error toast, modal open, no chip, no `onRfqMinted`, but the row existed; a retry minted a second open link for the same house.

**After**: a tiny state machine — `idle → prepared → copied → minted`, with `prepared → copy_failed → (confirm_copied) → copied` and `cancel → idle` — and `rfqCopyLaneMayInsert(state)` true **only in `copied`**. The component generates the token, builds the paste (`buildQuoteLinkPaste`), writes the clipboard, and only on success inserts (now stamping `created_by = auth user id`, closing J12-N3). On clipboard failure a fallback panel shows the URL in a read-only field with **"Link is ready — I copied it"** (→ insert) and **"Cancel — don't create a request"** (→ nothing written). A failed insert keeps the lane in `copied` with the same token so the retry saves the link already on the clipboard (button reads "Save quote link"). `onRfqMinted` fires exactly when the row exists.

### 3. Bids → Change Order → Send for signature (`BidChangeOrderTab.tsx`, `src/lib/bidDocuments/changeOrderBridge.ts`)

**Before**: one click → `estimates.insert({ doc_kind:'change_order', total_cents: 0, line_items_snapshot: [], internal_notes: 'Cost impact (from the Bids form — enter it as line items): …' })` → navigate. No confirm; the only number that matters rode the least-visible channel.

**After**: the button opens a confirm sheet listing the parsed fields (description, reason, schedule impact, response-by, cost text) with a **Net change to contract ($)** input, prefilled by `parseCostImpact(text)` when the free text has one unambiguous amount or a "net"/"total" line (credits, minus signs and parentheses go negative; several amounts with no net line → blank, the sheet asks). `buildBridgedChangeOrderDraft` writes `total_cents = net` and, when non-zero, one real line (`Net change to contract (from Bids change-order form)`, the typed breakdown as its description); $0 stays line-less (schedule-only COs are real). The internal note still carries the context, but it is no longer the money's only home. Cancel closes the sheet and inserts nothing.

## Telemetry

The map's counter `record_minted_on_open{surface}` is what these PRs drive to zero, so the commits are instrumented instead, via `recordNavClick` → `ui_nav_clicks`: `contract_quick_send_committed` (target `#reuse|#fill|#insert`), `rfq_link_minted` (target `lane:copy`), `change_order_bridged` (target `/estimates/<n>`).
