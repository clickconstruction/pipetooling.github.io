# v2.2115 — Count rows carry an explicit unit (2026-08-22)

Stage 2b of the counts-vs-line-feet split (stage 1 v2.2113 strip; stage 2a v2.2114 column). The client now **writes and edits** `bids_count_rows.unit`; every total still reads through `effectiveCountUnit(row)` (explicit wins, NULL → name convention), so rows written by older bundles or copied without a unit keep totalling correctly.

- **Importer** — [`parseCountsImportText.ts`](../../src/lib/bids/parseCountsImportText.ts) returns `unit` per row (`classifyCountRowUnit(fixture)`: `ft of` → ft, `px of` → px, else ea; +1 test) and `insertCountRows` writes it, so a CountTooling paste lands with explicit units.
- **Count Sheet** ([`BidsCountsTab.tsx`](../../src/components/bids/BidsCountsTab.tsx)) — the `ft`/`px` tag beside the count becomes a quiet `<select>` (ea · ft · sq ft · px; faint for ea until hover) → `sheetSaveRowEdit(row, 'unit', …)` pins the row (the tooltip says whether the unit is set on the row or read from the name). Quick add gets an **ea / ft** toggle that follows the typed name until clicked, inserts the explicit unit, and resets per row.
- **Old view** — `NewCountRow` (select under the count; follows the name until pinned) and `CountRow` (select in edit mode, `ft`/`px` label in display mode) write `unit`.
- **CSV** — `buildCountsCsv` gains a **Unit** column (effective unit; tests updated).
- Types regenerated after the 2a push (`unit: string | null` on `bids_count_rows`).

Not touched: fixture names keep their `ft of ` prefix (labor/price/takeoff books match by name). Per-foot **labels** on the labor/pricing surfaces are the natural stage 3 — the arithmetic there already works per unit because count × rate is unit-agnostic.
