# v2.3460 — Submittals stage 1: the fixture schedule on the bid, and the compare's Specified column (2026-09-15)

Client + one migration (`20260915014425_bid_specified_products.sql`, [`docs/migrations/`](../migrations/20260915014425_bid_specified_products.md)); no edge function. Stage 1 of [`to-dos/submittals/README.md`](../../to-dos/submittals/README.md): the leverage point — the substitutions that became SpaceX's "why alternates?" email were all decided on the quote compare, and nothing on that screen said so.

## What shipped

- **Schema**: `bid_specified_products` (one row per bid + tag: the schedule's make, model, description, the count-row name it maps to, source, confirmed by/at) and four columns on `bid_quote_lines` for the next PR (the pick's `alternate_reason_kind` / `_note`, `lead_time_days`, `availability`). Types hand-added; the regen chore follows the push.
- **Kernels** (`src/lib/submittals/`): [`parseFixtureSchedule.ts`](../../src/lib/submittals/parseFixtureSchedule.ts) — pasted schedule text → tag · manufacturer (a known-brand list) · model · description per line, wrapped lines folded, "WC-1, WC-2" expanded, count-row matches scored through a tag-prefix synonym table; [`productStatus.ts`](../../src/lib/submittals/productStatus.ts) — `deriveProductStatus` (as specified · superseded · equal · alternate · design change · missing · accessory; `near` for a suffix-only difference like B74-CH vs B74C), `statusCounts`, `statusSummaryLine`, `needsReason`. Tests on both.
- **Plug in the fixture schedule** ([`PlugInScheduleModal`](../../src/components/bids/PlugInScheduleModal.tsx)): from the Supply house prices (RFQ) ▾ menu (cost-side roles, under Plug in a quote) and from the compare's header. Paste → Match to tags → one editable row per tag (make, model, description, count row, a ✓ / ? confidence) → Save upserts on (bid, tag); rows already on the bid load first and a pasted tag replaces its row; + Add a tag by hand.
- **The compare** ([`QuoteCompareModal`](../../src/components/bids/QuoteCompareModal.tsx)): a **Specified** column (tag · make model) and a status chip per row derived from the picked house's line label against the specified model (the kernel gained `label` on `CompareRowCell`); a line above the grid — *Against the schedule: 6 as specified · 8 alternates · …* — plus how many quoted rows carry no tag. Nothing shows until a schedule is on the bid; a bid without one reads a one-line invitation.

## Not in this PR

The reason chips and lead time at the pick (stage 1, PR 1c — the columns exist); the estimator's overrides (superseded / equal / design change) are derived-only here and become tappable in 1c.
