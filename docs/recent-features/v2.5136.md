# v2.5136 — SQL beds keep each run's errors in a file of their own (2026-10-09)

A mechanical sweep across the 14 whole-schema SQL beds that wrote psql's stderr to a fixed `/tmp/$NAME.err`. No migration, no edge function, no client change.

- **The fault**: on the shared office Mac, `/tmp/pgtest-gc-building.err` (and five others) already existed, owned by another macOS user. The redirect failed with "Permission denied", so the bed reported `FAILED applying supabase/migrations/20250101000000_baseline.sql` before running anything. GitHub's runners start clean and never saw it.
- **The fix**: each bed makes its own file with `ERR="$(mktemp "${TMPDIR:-/tmp}/$NAME.XXXXXX")"` and the EXIT trap removes it. The trap still removes the container unless `PGTEST_KEEP` is set, and it now always removes the error file. Every `"/tmp/$NAME.err"` became `"$ERR"`.
- **Why `$NAME.XXXXXX` and not `$NAME.XXXXXX.err`**: macOS `mktemp` fills in only trailing X's, so the `.err` form makes one literal `…XXXXXX.err` file and the clash comes back.
- **The beds**: bid-changes, bid-copies, bid-next-followup, combined-copies, gc-award, gc-back-charges, gc-building, gc-owner-billing, gc-papers, gc-schedule, gc-trade-sign-sow, materials-model-flip, pay-applications, supply-house-words. The other beds already work in a `mktemp -d` folder of their own.
