# v2.2817 — Job Summary: Compare to + Target (2026-09-05)

PR 1 of the Job Summary analysis plan (owner-approved mock-up, artifact 9c02d29a). The two toolbar controls come first so every later view (Cut by, Months, Cycle…) is born with a delta line and a target line.

## Client only — no migration

- [`jobSummaryLedgerView.ts`](../../src/lib/jobs/jobSummaryLedgerView.ts): prefs `compareTo: 'none' | 'prior' | 'lastYear'` and `targetTrueMarginPct` (0 / 30 / 35 / 40; validated on read) with `JOB_SUMMARY_COMPARE_OPTIONS` / `JOB_SUMMARY_TARGET_OPTIONS`. `jobSummaryCompareWindow(start, end, compareTo, window, addDays)` — prior = same length ending the day before the window; last year = same dates a year back (Feb 29 → Feb 28); `window === 'all'` → null. `compareJobSummaryTotals(now, prior)` → `JobSummaryComparison` of `{ now, prior, delta }` per measure (jobs, revenue, gross, margin pts, hours, overhead, true profit, true margin pts, per field hour; null when either side is unknown). `jobSummaryRowUnderTarget` / `countJobSummaryUnderTarget`. Three new tests.
- [`useJobSummaryView.ts`](../../src/hooks/useJobSummaryView.ts): the ledger loader is now an internal `useJobDayLedgerWindow(enabled, userId, start, end, reloadTick)` (same sessionStorage cache) and runs twice — the main window and, only while Compare to is on, the compare window. `compare: { startYmd, endYmd, totals, comparison, ledgerLoading, ledgerError } | null` on the bundle: the same rows enriched with the compare ledger, filtered with the same prefs against the compare dates, summarized, compared. Note the window rule is unchanged — a job worked in both windows counts in both, with its whole cost, exactly as "Worked in" already does.
- [`JobSummaryLedgerToolbar.tsx`](../../src/components/jobs/JobSummaryLedgerToolbar.tsx): **Compare to** and **Target** segmented controls after Overhead (Jobs view only; Target money-gated like Overhead); a "vs Mar 8 → Jun 5" caption; `DeltaLine` under every tile (▲ green / ▼ red by whether higher is good — overhead inverts; "comparing…" while the second ledger loads; "— vs prior period" when a side is unknown); margin tiles append "(+2.3 pts)"; True profit tile turns red when under target; an under-target chip (red when > 0, muted "every job clears…" otherwise).
- [`JobsJobSummaryTab.tsx`](../../src/components/jobs/JobsJobSummaryTab.tsx): True % cell red + bold + ▾ with a title when under target. Nothing else in the tab moved.
- Help guide "read true profit on Job Summary": new **Compare to and Target** section.

## Deferred to later PRs in the train

Delta lines on Days and Timeline tiles arrive with the Months view (PR 3), which builds the per-window kernels those tiles need.
