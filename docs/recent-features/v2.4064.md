## What shipped

- **`src/hooks/useWorkflowStepsEngine.ts`** — `useWorkflowStepsEngine({ projectId, authUserId, userRole, currentUserName })`. Moved verbatim from the page:
  - ten state values (`project`, `workflow`, `steps`, `loading`, `error`, `lineItems`, `stepActions`, `userSubscriptions`, the two sub work order maps) and the two refs (the per-project find-or-create lock, the loaded-workflow marker);

- **`src/pages/Workflow.tsx`** — one hook call, right after `useWorkflowRoster`, destructured so every name the page uses is unchanged. The page's writes (lifecycle, structure, notes, dates, assignment) stay there for the next PR and use the setters the hook returns. 2,985 → 2,572 lines; 36 → 26 `useState`, 6 → 4 effects.

## One ordering change

The hook is called before `useWorkflowProjections`, `useProjectSuperintendents` and `useProjectJobs` (they take its `ensureWorkflow` and `setError`), so the master load effect is now declared ahead of theirs and starts its reads a moment earlier on mount. Each read is independent of the others; the page render smoke and the hook's tests pass unchanged.
