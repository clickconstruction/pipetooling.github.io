# v2.8274 — Sub papers: the dev seat cuts a statement since the last one as the papers window does (2026-11-21)

Punch list #350. The owner's call of 2026-11-21 on how a period is cut (v2.8269) covered the dev seat too. The audit of 2026-11-20 noted that the seat and the window differed after a statement made today, and v2.8269 left them differing on a line typed late. One shared file changes, `supabase/functions/_shared/subStatementMake.ts`, which `sub-statement` bundles. No migration, and `dev-mcp` itself is not changed: its two verbs call `sub-statement`.

## What changed

- **A statement made today is set apart.** `statementsOf(register, today)` answers the last statement that ended before today and the newest one that ended today, by the office's own rule (`subPaperRegister`, v2.8106). `since_last` now runs from the statement before today. It used to refuse with *has no day in it yet* once any statement had been made that day. A first statement made today still leaves nothing to start after, and the refusal names it.
- **A line typed late is carried.** The range for `since_last` carries `lateAfter`, when that last statement was made, so a payment or a back-charge dated inside it and typed after it counts in the new one. `planStatement` hands the builder each sheet's `created_at`, so a sheet typed late is new work, as in the window.
- **The reply says so.** A carried payment in `last_payments` has `recorded_after_the_last_statement: true`, `carried` holds the paper's own sentence, and `register.made_today` names a statement made today.

`lastStatementOf` stays, now with `madeAt` and an optional `today`.

The other periods (`to_date`, `this_month`, `this_year`, dates) are cut by the date alone, as before.

## Deploy

Redeploy `sub-statement` after the merge. Until then the seat keeps the old rule.
