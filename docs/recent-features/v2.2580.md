# v2.2580 — Division 22 ledger: schema, seed, and classification kernel (2026-09-01)

Phase 1 of the owner's ask ("add Division 22 to the supply-house share tool…
backfilling or a ledger of all the Division 22 codes for better matching") —
design settled on a **read-time rules ledger over any row backfill**: fixture
naming is conventional, so pattern rules classify every historical and future
count row with zero bid-data edits. Mockups: design canvas "Division 22 Ledger"
(2026-09-01 session).

- **Migration `20260901181000_division22_spec_sections.sql`** — see its
  `docs/migrations/` fragment: `spec_sections` (14 seeded MasterFormat
  sections) + `spec_section_match_rules` (16 seeded starter rules; priority
  order, NULL section = deliberately no code).
- **New pure kernel `src/lib/classifySpecSection.ts`** (+ tests): first match
  by priority wins; three outcomes — `matched`, `no-code` (rule hit with NULL
  section, e.g. DEMO), `unmatched` (real ledger gap). Case-insensitive.
  Tests pin the seeded ruleset's behavior: exact `CO` never grabs COPPER,
  `contains FD-` catches "4IN FD-1", `EDF-1` does NOT hit `FD-`, STORM beats
  the WATER catch-all, gas/GPR/RH stay unmatched pending the owner's call.
- **No UI yet.** Phase 2 (after `db push` + gen-types) wires the codes into
  the Pricing tab's "Copy fixtures for text" (grouped-by-section format) and
  adds the unmatched-names audit.
