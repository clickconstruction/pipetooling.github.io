# v2.8626 — Activity and tasks: the developer can delete a test job's note and a test task's comment (2026-11-26)

Punch list #443, row 13: one of the eight take-backs that need a migration, on the owner's answer of 2026-11-25 (*All eight*), each push on its own yes.

## The press nothing took back

**Post note** on a job's Activity writes one `jobs_ledger_thread_notes` row, and **Post** under a note a person was tagged in on a task writes one `checklist_instance_events` row of kind `comment`, with the tag rows and a push to each person tagged. A posted note has no edit and no delete, and neither table had a delete policy. The walk of #363 left four notes on the ZZ Test walk job.

## What changed

- **Migration `20261126030238_test_note_delete_dev.sql`**: a `DELETE` policy for a developer on each table and the grant, with the rule in the policy: a ZZ test job's note, or a comment on a task whose title starts with ZZ, that no tag names as its answer (`answer_note_id` and `answer_event_id` are `ON DELETE SET NULL` and would forget the answer without a word). The note's own tags cascade. The notes table already carries the Deleted records trigger, so a deleted note is kept there; a comment is not. Page: `docs/migrations/20261126030238_test_note_delete_dev.md`.
- `src/lib/notes/testNoteDelete.ts`, the rule, pure: a dev alone; a ZZ test job (`isZzTestJob`) or a ZZ task title (`isZzTestName`); a comment and never the app's own line; the answer count's words; the two confirms, whose buttons read **Delete the note** and **Delete the comment**.
- `src/lib/notes/testNoteDeleteIo.ts`: `deleteTestJobNote` reads the job again, counts the tags that name the note as their answer, then deletes the one row; `deleteTestTaskComment` reads the comment with its task's title, counts, then deletes. A delete that reaches no row is said as a refusal.
- `src/components/JobThreadNotesPanel.tsx`: with `noteDeleteJob` and `onNoteDeleted` from the host, a dev reads **Delete…** beside each note, live on a ZZ test job and dead with its reason on any other. `DetailJobModal.tsx`, the job window, hands both over and reads its notes again after a delete.
- `src/components/checklist/ChecklistItemActivity.tsx`: a dev reads **Delete…** beside each comment, live on a task whose title starts with ZZ and dead with its reason on any other; a deleted comment leaves the list.
- `docs/ACCESS_CONTROL.md` and the glossary say who may delete one.
