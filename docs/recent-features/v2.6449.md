# v2.6449 — Job photos: the window loads when you open it, so the app's first load is lighter (2026-11-03)

Punch list #244's follow-up, found while measuring the main chunk after every deploy build began failing on the 7 MiB precache cap (#6935): v2.6368 (#6834) grew the main chunk by about 35 kB (7,348 kB at 61f7540fe to 7,383 kB at 623cd7390, with only v2.6368 and a scripts change between), because its two doors, the Job Mode card's Photos line and the job window's Documents door, imported the Job photos window statically and both live in the app's first load.

## What changed

- **`components/photos/JobPhotosWindowLazy.tsx`** (new): the window through `React.lazy`, its own chunk (16.5 kB), with *Opening the job's photos…* as the Suspense fallback so the press always answers. The service worker precaches every chunk, so a phone with no signal still opens it.
- **`JobModePhotosLine.tsx`** and **`JobDocumentsPhotos.tsx`** open the window through it; `JobDocumentsPhotos` keeps only a type import from the window file. The Pipeline's three tables still import the window directly, since the Jobs page is already its own chunk.
- Measured with `vite build` on 623cd7390: the main chunk goes from 7,395,643 to 7,372,355 bytes (23 kB less), and Vite reports no static import of the window left in the first load.

## Tests

`JobPhotosWindowLazy.render.test.tsx` (new: the fallback answers, then the window). `JobModePhotosLine.render.test.tsx` and `JobDocumentsPhotos.render.test.tsx` already open the window and now meet it through the lazy door.
