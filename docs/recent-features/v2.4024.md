# v2.4024 — A test-mode bill no longer emails the people copied on it (2026-09-28)

`sendBillCopies` in `send-stripe-invoice` never looked at the Stripe mode. A test-mode bill kept the payer's own email away from the customer (v2.4020: it goes to whoever pressed Send, marked `[Test]`; before that Stripe delivered nothing in test mode), but the copies still went to every address in `jobs_ledger_invoices.copy_emails` — the customer's contact persons, the GC, a one-off address — each with a *Pay or view the bill* button on a test invoice's hosted page.

## The decision — `_shared/billCopyPlan.ts`

`planBillCopies({ stripeMode, invoiceLivemode, copyEmails, callerEmail })`, pure:

| Case | Plan |
|---|---|
| nobody on the copy list | `none` |
| live | `live`, one email per address |
| test, the caller has an address | `test`, ONE email to the caller; `heldBack` is the copy list |
| test, no caller address | `skip`, `test_without_sender`; `heldBack` is the copy list |

- **A bill is a test when either source says so**: the send's `stripeMode` (the row's, `effectiveRowStripeMode`) is `test`, or Stripe's invoice has `livemode: false`. A row with no recorded mode falls back to the requested or default mode; the invoice's own word covers it.
- **`heldBack` leaves out the caller's own address** when it is on the list — the test copy reaches it.
- `copyEmailsFromRow` moved here from the function, unchanged (≤10, lowercase, unique, plausible).

One copy to the sender was chosen over skipping the copies: it matches what `planBillEmail` does with the payer's email, and a test then shows the office what a copy reads like.

## The function — `send-stripe-invoice`

`sendBillCopies` takes `stripeMode` and follows the plan.

- **Test**: `buildStripeBillCopyEmail({ …, portalUrl: null, testHeldBack })` to the caller, Reply-To the caller, logged as `stripe_bill_copy`. The portal lookups (`loadPortalReturnUrl`, the payer's contact persons, the other party) are skipped — one copy stands in for the whole list, so it carries nobody's statement.
- **Response on a test bill**: `copies_sent: []`, `copies_held_back: string[]`, and `copies_test_to` when the copy went out. A test copy Resend refused is the caller's address in `copies_failed`. `copies_skipped` gains `test_without_sender`. A live bill's response is unchanged.
- **The send log** (`jobs_ledger_invoice_stripe_email_sends.copy_emails`) is `null` for a test send: it records the copy-list addresses a copy reached, which is what the confirm's history reads back.

## The copy — `_shared/stripeBillCopyEmail.ts`

`testHeldBack` (`null` on a live bill) prefixes the subject with `[Test]` and puts one banner line first: *Test bill. This copy came to you instead of a, b; nothing was sent to the copy list.* — or, with nobody held back, *…came to you; nobody else is on the copy list.* `stripeBillCopyTestLine` is the sentence. A live copy is byte for byte what it was.

## The app

- `src/lib/billing/billEmailOutcome.ts` — `parseBillCopiesOutcome`, `billCopiesSentHint`, `billCopiesFailedMessage` replace the three inline lines in the button. A test bill's toast reads *The copy came to you too; nothing went to a, b.* and never *Copies went to…*; a failed test copy reads *The test copy could not be sent to you. Nothing went to the copy list.* An answer with no `copies_held_back` / `copies_test_to` reads as a live bill, so the client works against the function before and after it is redeployed.
- `StripeInvoiceSendFromStripeButton` — in test mode the confirm reads *One copy comes to you too; nothing goes to a, b.* where it listed the copies as going out.
- Help: *send a bill to more than one person*, *turn a bill into a Stripe bill*. `EMAIL_CATALOG`'s `stripe_bill_copy` gains the test variant.

## Not changed

No migration. `send-physical-invoice-email` (PDF invoices) has no Stripe mode and is untouched. The payer's own email still decides test from `stripeMode` alone (`planBillEmail`).
