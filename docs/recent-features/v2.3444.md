# v2.3444 — Job accounts: two fixes from the end-to-end live test (2026-09-14)

Client only; no migration. Found while running the full loop on the demo job after the five-PR train (v2.3423–v2.3440) merged: the field's ask from the job window → the Dispatch inbox card → Mark opened.

## What was wrong

- **Mark opened from the inbox card returned a 400.** The card built the sheet's rep list from the errand payload, which carried only the rep's name and phone, and handed the sheet a synthetic id (`payload-<house>`); the sheet wrote it as `rep_contact_id`, which is a uuid foreign key. The ask sheet itself, the requested row and the card all worked.
- **React's style warning on the strip's chips**: `chipStyle` mixed the `border` and `font` shorthands with `borderColor` / `borderStyle` / `fontWeight`, which React flags when the values change between renders (a chip going from *none yet* to *requested*).

## What changed

- `RequestedJobAccountHouse` gains `repContactId` (built from the strip entry's rep, parsed tolerantly — older payloads read null). The ask sheet and the New Job prompt pass it; the inbox card passes the sheet a rep only when it has a real id.
- `MarkJobAccountOpenedModal` writes `rep_contact_id` only for a uuid-shaped id.
- `JobAccountsStrip` chips use `borderWidth` / `borderStyle` / `borderColor` and `fontFamily` instead of the shorthands; the modal's and the PO line's buttons likewise.

## Verified

After the fix, the same loop on the demo job: ask filed from the job window (*Ferguson · requested*), the card read *At the counter now* with the note and the rep, Mark opened saved, the request closed with *Ferguson job account open · ref TEST-E2E*, the job window read *Ferguson ✓*. Test rows deleted afterwards.
