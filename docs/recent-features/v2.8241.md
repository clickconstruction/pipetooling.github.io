# v2.8241 — View as: Exit never leaves you signed in as the person (2026-11-21)

Found while building v2.8176 and raised with Taunya as a question, who asked for the fix. Exit from View as puts the dev's own stashed session back with `auth.setSession`. A refusal from that call comes back as `{ error }`, not as a throw, and the two Exit handlers read only the throw. So a refused swap took the flag off and loaded the page the dev had left, still signed in as the person: no banner, the saves held while View as is on running again, and every press saved under the person's name. The throw path was no better: it moved to the sign-in page without signing out. A stash with no tokens skipped the swap and did the same. No migration and no function change.

## What changed

- **One kernel for both doors.** `leaveViewAs` in `src/lib/impersonationExit.ts` replaces the two near-copies of `handleBackToMyAccount` in `Layout.tsx` (the header's Exit and the phone's strip) and `Settings.tsx` (*Back to my account*). `leaveViewAsHere` binds it to the Supabase client, this device's storage and a full load.
- **The answer is read.** The swap counts only when `setSession` answers with no error. Then the stash is cleared and the page the dev left loads, as before.
- **Anything else signs this browser out.** A refusal, a throw, a stash with no tokens and a stash that cannot be read all take one path: `auth.signOut({ scope: 'local' })`, the stored `sb-` keys dropped whatever the server answered, the stash cleared, and a full load of the sign-in page. Local scope, so the person's own devices stay signed in.
- **The flag still comes off last.** On every path the stash is cleared only once the session is no longer the person's, so what v2.8176 holds stays held until then.

## What it does not do

- It does not say why on the sign-in page. A full load carries no toast, and the page a dev lands on is the plain sign-in.
- It does not retry the swap. A lost signal at the press signs the browser out too, and the dev signs in again.

## Tests

- `impersonationExit.test.ts`: the swap that answers clean, the flag held while the swap is open, a refusal, a throw, a stash with no tokens, a stash that cannot be read, and a sign-out that itself fails.
- `Layout.viewAsExit.render.test.tsx`: a press on Exit with a refused swap signs out with local scope while the flag is still on, drops the stored sign-in, clears the stash and never loads the page left. The older cases now carry a stash with tokens, as `loginAsUser` writes it.
