# v2.6769 — The bill text’s link ends in ten letters (2026-11-08)

Punch list #290 (`to-dos/short-bill-link.md`), PR 2 of two. PR 1 (v2.6768) put the bill's pay page in the text: `my.clickplumbing.com/pay/<bill id>`, 69 characters, a page that asks Stripe for the bill's current payment link each time it is opened. This PR gives the bill a ten-letter code from the estimate link's alphabet, so the link reads `my.clickplumbing.com/pay/<code>`, 43 characters.

## What changed

- **Migration `20261109033000_bill_pay_codes.sql`** (`docs/migrations/20261109033000_bill_pay_codes.md`): `jobs_ledger_invoices.pay_code`, one code per bill, in plain (the bill's id is already the capability for `/pay/<id>` and sits in plain beside it), never expiring (a bill is owed until paid, and the paid page stops asking); a shape check and a unique index. `mint_pay_code()` mints ten letters from `23456789abcdefghjkmnpqrstuvwxyz`, unbiased, as `share_estimate_link` does. **`bill_pay_code(p_invoice_id)`** answers the row's code or mints one on the first ask and keeps it; SECURITY INVOKER, so the table's RLS and the read-only, twin and archived fences refuse as they do on any update, and a caller who may read the bill but not change it is refused in words.
- **`pay-link`** takes `?code=<ten letters>` beside `?id=<uuid>` (`payLinkRef` in `_shared/payLink.ts`), reads the row by `pay_code` and runs the same flow; a code that opens nothing counts a miss against its source through the estimate link's guard (`estimate_link_miss`) and past 20 in the hour answers **429** `locked`. **`create-stripe-invoice`** asks `bill_pay_code` after it writes a new bill, best effort. `docs/EDGE_FUNCTIONS.md` for both.
- **The page** `/pay/:id` (`src/pages/PayLink.tsx`) takes either shape and asks the function by the right name; something that is neither is *not found* without a call.
- **The client**: `billPayCode` (`src/lib/billing/billPayCodeIo.ts`, with its tests) asks the RPC once per bill per page load and never throws; the share row asks when it draws with a bill id and `billTextLink` puts the code first, the id's link until it answers or when it is refused, and Stripe's link only with no id at all; Collect payment's Copy payment link asks on the press. A training account, a twin or a client ahead of the push gets PR 1's link.
- The SQL bed `scripts/pgtest-bill-pay-codes.sh` (`supabase/tests/bill_pay_codes/20_scenario.sql`): the shape, the same code on a second ask, a different code per bill, the refusals (a bill not there, a subcontractor, a training account, a twin, anon), and the unique index.
- Words: the guide *turn a bill into a Stripe bill* (ten letters).

## Not in this PR

- The QR code (`BillQrModal`) and the bill email's Pay now still carry `/pay/<bill id>`; the portal's Pay button carries Stripe's link, refreshed on read. A later PR could put the code in the QR for a smaller code.
- The Messages thread's text door does not recognise a `/pay/` link as the bill's.

Release order: merge, `supabase db push`, then `supabase functions deploy pay-link create-stripe-invoice`; `src/types/database.ts` picks up the column and the function in the next `chore(types)`. Either order is safe on its own: a client ahead of the push is refused the RPC and keeps PR 1's link; a function ahead of the push finds no `pay_code` column on a code lookup and answers its 500 words, which no text carries until the client mints.
