# v2.7550 — Checklist: mark a round of daily tasks done in one press (2026-11-16)

Punch list #369, step D2 of the Task Mode train, the second of the three small ones, stacked on D1 (v2.7549). No migration, no new call.

## What changed

- **Mark N done**, a quiet outlined press under today's open tasks, with its count: *Mark 3 done* (`roundPressLabel` over `countedLabel`). It shows once the round holds two tasks (`ROUND_MIN`).
- **The round is narrow on purpose** (`roundTaskIds`): today's open tasks that repeat and have a plain tick. Left out are a one-time or roadmap task, which has a percent; a task with Done when… lines, which its lines finish; a task that asks for a photo, which holds for the photo; and a stuck task. A line under the press says how many: *1 more task has its own steps. Finish it from its card.*
- **A window asks once** (`useConfirmDialog`): *Mark these 3 tasks done? Each finishes as if you had ticked it.* Its button is the press's own words, never OK.
- **Each task takes the tick's own path**, one at a time: the save, the push to whoever hears, the next day row of a task that repeats after it is done.
- **It keeps going past a task that does not mark** and says what took: *Marked 2 tasks done. 1 did not mark.* (`roundOutcome` over `batchOutcomeWords`). The page's own line names the reason, as it does for a single tick.

## The risk the mock-up named

A round ticked without being done. Three things answer it without getting in the way of a real round: the press is not the page's solid blue, a window asks before anything is marked, and anything that wants proof, lines or a photo, is never in a round.

## How it is built

- `src/lib/tasks/markRound.ts`, pure, 6 tests.
- `toggleComplete` now resolves true or false, so a batch can count. Its other callers ignore the answer, as before. The pass's Done answer reads it too, where it could only see a thrown error before.
