# v2.5881 — The Monday sheet is one kernel, with the Friday ask on it (2026-10-26)

PR 3 of the Bridge train (v2.5879 the landing, v2.5880 the loaders take the client): the sheet the page shows and the sheet the weekly send will mail are one function from one set of reads, and the copy of the kernels on the edge holds everything it needs.

- **The kernel** (`src/lib/bridge/sheetBuild.ts`, `buildSheetFromReads`): the page’s memo chain in the page’s order — the course model, cash on hand from the bank or the typed figure, the net position history, the Collect desk’s pile, the receipts and the doubtful, the bills, the forecast, the build pace, the bill pile, the demand, this week’s call, the headline from the eight-week grid, the field’s pace by hours, the stage flow and the lit link, the dial’s readings, the scorecard, the truth check, the two lights, the five moves, the people lines and the link lines — from `MondaySheetReads` (everything the Bridge loads; a failed read is null and named in `gaps`) to the `MondaySheet` that `mondaySheetHtml` / `mondaySheetText` / `mondaySheetSubject` render. The page passes its state (`SheetBuildOptions`: the stepped pay week, the pressed stage, a moved dial) and the weekly send passes none. `buildCollectDeskFrom`, `buildReceipts` and `buildBills` are exported and the page uses them for its own memos too, so those reads have one home.
- **The reads** (`sheetReads.ts`, `loadMondaySheetReads(db, { bank, zzTestJobIds, canReadTouches })`): the page’s loaders in the page’s shape with a client passed in. The Bridge data must come back; every other read that fails leaves its slot null and its plain name in `gaps`, so one failed read never holds the mail. The bank is the caller’s: the page through `loadMercuryCash`, the function through Mercury’s API.
- **The Friday ask rides the sheet** (to-do #107’s suggestion): when the call that stands this week is unanswered and the week is at its fifth day or past (`fridayAsks`), the link tile adds *Friday asks: did Collect move? Answer it on the Bridge.* after last week’s verdict. **What was not read** is on the sheet (`gaps`): *Not read when this sheet was built: the bank, the people. Those tiles read without it.*, red in the mail, before the footer; the page passes its own error lines so the sheet it shows says the same.
- **The copy of the kernels** (`scripts/edge-kernels.mjs`): five entries — `bridge/sheetReads.ts`, `bridge/sheetBuild.ts`, `bridge/mondaySheet.ts`, `bridge/mercuryCash.ts` (`parseMercuryCash`) and `jobs/zzTestJobReads.ts` — pull every loader and kernel under the sheet into `_shared/gcKernels/` (the overhead scan, the Dashboard’s financials, the collect kernels, the pay-week anchor…). A type-only import of `@supabase/supabase-js` is written as `npm:@supabase/supabase-js@2` (`PACKAGE_TYPES`), so `deno check` resolves the client’s type; at run time it is erased. Four type-only imports of files with code of their own were pointed at type files or smaller modules so the generator takes them. No function imports the new entries yet; the weekly send’s does in the next PR.
- **Tests**: `sheetBuild.test.ts` (the empty reads, the Friday ask and its absence after an answer, the stepped week, the gaps in text and html, the bank against the typed figure); `edgeKernels.test.ts` regenerates the larger copy and plants the package-type rewrite. Guide *read the Bridge* says what the sheet now asks and names. No migration, no edge function.

## Verify

Open `/bridge?view=monday`: the sheet reads as before, the link tile ending with the Friday question when last week’s call is unanswered. Press **Email me this sheet**: the mail carries the same lines. Turn off the network for one read (block the bank function): the sheet’s last line names the bank, in red in the mail.
