# v2.5208 — GC mode: Compare quotes marks a quote priced on plans that changed since (2026-10-10)

The Board's B2b-vi-b, the second of B2b-vi's three cuts (`to-dos/gc-mode/mockups/board-b2b-vi.md` on branch `spike/gc-mode`, call T, co-signed by gc 2). No migration, no new screen.

- **What was wrong (found by the B2b-vi plan):** the board mapped every set of plans with no trades (`touches: []` in `boardRows.ts`). So `bidIsStale` was never true on the board. Compare quotes never marked a quote priced on older plans, and its words never said "They priced an older set of plans, so ask them to confirm." The ring's *Confirm quotes after plan changes* would always have read done.
- **Which trades a set touches now** (`setTouches.ts`, new, pure, call T):
  - **A set the office sent:** the office's word at the send, `gc_plan_set_sends.touched`. A trade is touched when a company asked on it got the set with `touched`. A company asked on two trades marks both. That is how the trade portal reads it (`tradePortalState.ts`'s `setsOf`), so the board and a trade's portal agree on every set that went out.
  - **A set not sent yet:** the New plans window's own guess from the set's rows. That means the trades its changed sheets and sections point at (`packagesForSheets`, `packagesForSpecs`), and the trades it added lines to.
  - **That guess is a guess.** It stands until New project saves the office's touched trades on `gc_plan_sets`. Compare quotes and the ring's Confirm quotes lean on it for an unsent set. The comment where `boardRows.ts` maps `touches` says so too.
- **The read:** `loadGcBoardRows` reads `gc_plan_set_sends` (the set, the company, `touched`) in its first round, paged and by the board's set ids. It is the office team's table (`doors.ts`). `BoardRows.planSetSends` is missing when nothing read it, as on the trade portal's edge read, and then no set touches a trade, as before.
- **What else the board's project now carries,** for what changed under a quote (`stale.ts`, B2b-vi-a):
  - each scope line's `sheets` and `specs` as the office said them, leaving out a line that says none, so the guess stands;
  - each set's `changedSpecs` and `addedLines`;
  - `index`, the plans' index and manual as they stand after the newest set.
- **The edge copy** (`_shared/gcKernels/`, the schedule's PR 14b): `boardRows.ts` now imports `setTouches.ts`, which imports `lineReach.ts`, so `npm run gen:edge-kernels` copies both. After P5d-ii-1 the copy goes from 41 files to 43, and 12,107 lines, by the generator's index and `wc`; `EDGE_FUNCTIONS.md`'s copy sentence says so. `gc-trade-portal` is redeployed after the merge. Its read passes no `planSetSends`, so no set touches a trade there, as before.
- **What a person sees:** Compare quotes' **Plans they priced** row turns a quote's set yellow and says *Newer plans changed this trade* when a newer set changed its trade. The guide "compare quotes and carry one" says so.
