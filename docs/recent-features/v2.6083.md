## Decisions

- **The camera opens on a phone only.** The brief gates it on the field roles; a dev at a desk pressing Leave report would get the file picker in their face, so the gate is the role and a phone width. At a desk the same input is an Add a photo tile.
- **The bytes go up as soon as the shot is shrunk, the row with them, and Save only ties them to the report.** So the upload runs while the tech fills the form, and a closed form discards what it sent (the delete policy allows a taker's own unsaved row and object). A row left with no `report_id` (the app closed mid-form) is never filed; a sweep of such rows is left for later.
- **Save waits for a shot still on its way** rather than saving without it: the mock-up says Save never waits, and that is #163's queue (PR 7), where the report and its photos wait together. Until then a shot on no signal fails with Retry, and a failed shot never rides.
- **No Drive folder: the bucket keeps the shot, the card says so.** Decision 8's second half, *the Needs you line that already asks the office for a folder link counts it*, found no such line in the code (the lines in `src/lib/needsYou/` and `needsYouSources.ts` name no folder link; the nearest is Quickfill's *Field photos → Drive* station for the change wizard's photos). The sweep writes *That job has no Drive folder yet.* on the row and the card reads it; the office's press **Make the job's Drive folders** on the job window (v2.6054) is the fix, and the next run files the photo. A Needs you line for it is listed on the card as left.
- **The setting's key lives in `lib/photos/shrink.ts`, not `appSettingsKeys.ts`**, since that file is copied into fourteen edge bundles (`gen:edge-kernels`) and a client-only key would send every one of them out for a redeploy.
- **HEIC never reaches us**: the camera input hands iOS photos over as JPEG; the bucket still lists PNG and WebP for a browser's own picker.

## Push and deploy

From the main checkout after the merge: `supabase db push` (the migration above, a `CREATE TABLE`, a bucket, a setting row, a cron), then `npm run gen-types:linked` as its own `chore(types)` PR, then `supabase functions deploy photo-save` (`npm run check:edge-drift` before and after). Until the push, a shot's send fails with the bucket's refusal in words and the report still saves without it.
