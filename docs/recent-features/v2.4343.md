# v2.4343 — A person's desk holds every account control (2026-10-01)

PR B of the *Account on the desk* train (Grace, 2026-10-01: *"When I go to modify a user and click on Manage account… it brings me to this modal where I then have to research for the user"*; canvas `UC4ZYvy8qDy3XLsz41TCM3`, boards *After 1–5*). PR A is [v2.4336](v2.4336.md). Client only, no migration, no edge function.

## What was wrong

One person's account lived in three places, none of them whole. The desk's Access & account section had role, sign-in, training and status, then a *Manage account…* button that opened the Active Accounts window on **every** account with an empty search. Name, trades, the Hiring board and Prospects switches, the password and the CountTooling seat were only in that window, behind a row's *Edit* mode. Supervision was on the window and the Users lens but missing from the desk, though `ACCESS_CONTROL.md` said the desk had it. For a dev on a desk without the End employment flow, Archive… opened the window too.

## The change

- **[`lib/people/accountWrites.ts`](../../src/lib/people/accountWrites.ts)** (12 tests): the writes the window made, one function each, so the desk makes the same write to the same column through the same guard. `renameAccount` refuses an empty name or one another account or roster row has (read by name, never a whole-table read; the account's own roster row does not count), writes `users.name`, then moves every name the account went by through `cascadePersonNameInPayTables`. `setAccountTrades` writes the role's own column (`tradesColumnForRole`; empty means all). `setAccountExtraAccess` (`extraAccessForRole`: the Hiring board for dev, master, assistant and estimator; Prospects for estimators). `setCanRunAJob` (stored as `needs_supervision`). `passwordProblem` + `setAccountPassword` (`set-user-password`). `createCountToolingSeat` (`ct-bridge` create, then `counttooling_user_id`). A write RLS filters to nothing throws *That change did not apply…*.
- **[`PersonDeskAccessSection`](../../src/components/personDesk/sections/PersonDeskAccessSection.tsx)**, rows in order: **Name** (Edit → the box, Enter saves, Escape cancels, *Their pay and hours rows follow the new name.*), **Email** (*They sign in with this address.*; changing it is PR C), **Role** + **Trades…** (an inline checklist in the app's trade order, with what the trades limit for that role), **Supervision** for helpers and subs (*Can run a job on their own*), **Extra access**, **Training mode**, **Sign-in** (Send sign-in email, **Set password…** in a small window that checks the two boxes before calling the function), **CountTooling** (dev, shown for estimators and anyone with a seat), **Status**. *Manage account…* is gone; Archive… never opens the window. Rows the viewer cannot change keep their value and a tag.
- **[`personDeskGates.canSetSupervision`](../../src/lib/people/personDeskGates.ts)** mirrors `users_guard_privileged_columns`: dev, master or assistant, not in training mode; the desk adds "never your own row" unless dev.
- **`usePersonDesk`** reads `needs_supervision`, `team_prospects_access`, `estimator_prospects_access`, `counttooling_user_id`; `PersonDeskBody` loads the trades in `sequence_order`.
- **Phone**: under 640 px the section's rows stack (label line, then value and buttons) — `src/index.css`, scoped to `[data-desk-section="access"]`.
- The Account lens's *Desk* link hint no longer promises merge. Merge stays in Settings → People & teams → Manage accounts… until that window retires (PR D); the Active Accounts window is unchanged in this PR.
- Guides: *open a person's desk*, *put someone in read-only training mode* (step 2 described the old Last login column), *say who can run a job* (the lens column and the desk row), and the desk doors removed from *archive and restore user accounts*, *link an external person to an account* and *merge user accounts*. *team-prospects* still names Settings → Active accounts for the Hiring switch; it is on the plain-words legacy list and stays true until PR D.
