# v2.3559 — Punch list picks are shared: `punch_list_picks`, stamped with who (2026-09-17)

Client + migration. PR 2 of the board's move into the app (PR 1: v2.3558). Migration `20260917120000_punch_list_picks.sql` — **push after this deploy is live**; the page falls back to device picks until then.

## What shipped

**`punch_list_picks`** — one row per to-do slug: `pick` (`''` / `do` / `later` / `drop`), `note`, `updated_by`, `updated_at`; the last two set by a BEFORE trigger from `auth.uid()` / `now()` so the client never claims a name. RLS select / insert / update for `is_master_or_dev()` — the page's own door — no delete (a cleared pick is `''`, the note and the name stay). Read-only and twin write blocks applied. Doc: `docs/migrations/20260917120000_punch_list_picks.md`.

**`usePunchListPicks`** (`src/hooks/usePunchListPicks.ts`) — one select with `users:updated_by(name)` joined on mount and on every tab focus (the board is looked at, not watched); an upsert per change that returns the stamped row. A 42P01 / PGRST205 flips `shared` off: picks read and write `localStorage` under the old board's key, and the page says "Picks stay on this device until the database catches up with this deploy" with a grey dot; live, a green dot and "Picks are shared — everyone who opens this board sees the same Do / Later / Drop, with the name beside it."

**The row** — under the note, *Robert · Sep 17* (`byLine` in `punchListView.ts`): the person from the joined name, "Someone" when the id has no name, "this device" for a local pick. The note input is keyed on its value so a row that comes back from the server re-renders its note.

**Kernel** — `PickRecord.byName`, `PunchPickRow`, `picksFromRows`, `byLine` (+4 tests).
