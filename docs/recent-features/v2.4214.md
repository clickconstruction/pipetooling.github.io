# v2.4214 — The app updates itself when you switch tabs, too (2026-09-29)

The owner, 2026-09-29: "when I switch pages and there is an update available it reloads, but not when I switch tabs." The route-change quiet moment (v2.3740) keyed its effect on `pathname` alone, and every page's tabs live in `?tab=` — so People → Hours → Review, Settings tab to tab, or Bids → Pricing → Labor never fired it, and the pill sat until the next page change or the idle moment.

- **[`autoReload.ts`](../../src/lib/autoReload.ts)** (+3 tests) — `routeMoveKey(pathname, search)`: the path plus the `tab` query param. A change of page or of tab is a move; a picked bid (`bidId`), a lens or a filter alone is not — those change under a person mid-task, and a reload there would read as the app jumping.
- **[`UpdatePrompt.tsx`](../../src/components/UpdatePrompt.tsx)** (+2 render tests) — the route-change effect depends on that key instead of `pathname`, so the reload try and the v2.1007 pill resurface both run on a tab switch. `decideAutoReload` and every guard in it (dialog open, field focused, unsaved hold, write in flight, *Not now* grace, loop guard) are unchanged.
- Help guide *update the app when a new version is ready* and `TROUBLESHOOTING.md` amended: "when you move to another page or tab".

No migration, no edge function. Not verified live — the dev server has no service worker; the render test drives a `?tab=` navigation through the mocked `registerSW`.
