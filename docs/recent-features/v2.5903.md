# v2.5903 — Every error line a person sees is counted (2026-10-26)

Punch list #187's PR 2 (`to-dos/help-at-the-point/`). Part 3 of the plan asked which error lines people see most, and the answer was that nobody knew: `errorClassTelemetry.ts` wrote one console line per (kind, code, operation) per page load and named its own follow-up, *a real `error_shown{class, operation}` event into whatever sink the app adopts*. The sink is the one the app already has, `ui_nav_clicks`, as `rls_refused` (v2.3058) and `role_gate_redirect` use it.

- **`errorClassTelemetry.ts`** gains `setErrorClassSink`: the reporter calls the sink once per triple, after the console line, inside its own guard, so a sink that fails stays quiet. The file stays import-free, since the edge functions' kernel copy mirrors it.
- **`lib/errorShownSink.ts`** is the app's half: control `error_shown`, target `/<kind>?code=<code>&op=<operation>&status=<status>` with a dash where a part is unknown, `from_path` the surface, and `installErrorShownSink`, which `useAuth` calls beside the refused-write identity and clears at sign-out. `parseErrorShownTarget` is the readout's inverse.
- **Settings → Usage**: under *How people get around*, **Errors shown**, the families people meet most, each with its code, what was being done and who met it on hover (`usageDashboard.ts` `errorsShown`). The guide *read the Usage dashboard* names it.
- **Tests**: `errorShownSink.test.ts` (the target and its parse, one row per triple as the person, none after sign-out, a throwing sink), `usageDashboard.test.ts` (the grouping and the limit).

No migration, no edge function change in behaviour. What the rows say decides PR 6's doors, the guide behind each family.
