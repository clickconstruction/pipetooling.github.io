# v2.3202 — The Bid Board robot icon: two states, a key beside Bid #, grades on sent rows (2026-09-09)

Owner-approved mock-up *Robots on Every Bid* (the ask: "all bids should be bid by a robot — the only two things I should show are the robot that if clicked shows the twin bid, and the I need more information"). Since auto-shadowing (v2.2936; weekday batches since 2026-09-06; owner rule v2.3142 "shadowing is the default, the exception is an opt-out") the yellow "request a robot" click of v2.2542 was a leftover from before the dispatcher existed.

## What changed

**The icon** in the bid-number cluster (table and phone card) now has one kernel behind it, [`robotRowState.ts`](../../src/lib/bids/robotRowState.ts) (+16 tests): one bid in, one state out, precedence decided → opt-out / division → scored → sealed → needs → sent-without-robot (grade) → working → queued.

- **Robot is on it** (blue): *queued* (outline glyph — eligible, no shadow run yet), *working* (solid + breathing dot — run open, or a twin pairing exists), *sealed* (🔒 badge — run locked), *scored* (green ✓ badge — run scored; the tooltip carries the signed delta). Click → `RobotStatusSheet` (new): a five-step timeline (picked up · counted · sealed · you send · scored) built by `robotStatusTimeline`, blind-safe before send (the sealed total is never read — `list_shadow_runs()` returns it NULL anyway), with doors *Open robot bid b###* (Robot Board deep link), *Its questions (n)* (→ Audits → Standing rulings) and **Front of the line next batch** — the old request, as a button: it stamps the same `robot_requested_at` the dispatcher honors (v2.2543) and the toast now reads "Moved to the front of the next robot batch." A scored row's click opens today's comparison modal directly.
- **Robot needs something** (amber, `?` badge — or the count of open questions): a required gap (no plans link; `plans_robot_readable = false` from the probe) or an open estimator-audience `twin_questions` row about this bid. Click → `RobotNeedsSheet` (new, replaces `RobotBidReadinessModal`): the gaps with their fix, *Copy intake address* when the probe says the file isn't shared, the soft warnings (GC, distance, due date) marked "Not blocking", and the robot's questions with an inline answer box — the same `twin_questions` update the Audits tab writes (status → answered, answered_by/at). A sealed robot beats an open question (it already finished).
- **Not this bid** (muted, no click): `robot_opt_out`, or a service type that isn't plumbing (the division rule of the v2.3142 form line, now on the board too). Unknown service-type name → no division verdict.
- **Grade** on decided rows as before (v2.2547), and now on **sent-undecided** rows without a robot, matching the Counts tab chip (v2.2943); a sent row waits for the presence read (`kind: 'none'`) rather than flash a wrong letter.

**The key**: a small **?** beside the **Bid #** column header (the Due Date header's color-key pattern) opens `RobotIconKeyModal` — the four live states, "not this bid", and A–X with the grade modal's meanings. Phones have no table header, so the same ? sits in the pinned pill row beside the scope chip (`narrowViewport && robotReadiness`).

**Retired**: the yellow request click and green withdraw; `RobotBidReadinessModal.tsx` (the kickoff prompt already lives on the dev Queue lens, v2.2542). `bids.robot_requested_at/_by` stay — the sheet button writes them and the Queue lens / `next_shadow` still read them.
