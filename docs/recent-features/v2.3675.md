# v2.3675 — Materials by stage, PR 4: the book and the assembly remember (2026-09-21)

Migration `20260921171921_takeoff_stage_split_defaults.sql` (push after merge; `docs/migrations/`) + client, on top of [v2.3673](./v2.3673.md). Closes the four-PR train Wendi asked for on 2026-09-21.

## Why

Three scopes on a bid (fixture / line / part inside a bundle) answer the ask, but every bid would start blank. The answer for a fixture belongs to the book (which already remembers its assemblies), and the answer for a part inside an assembly belongs to the assembly itself — set once, right on every bid that uses it.

## What shipped

- **Kernel** ([`materialsByStage.ts`](../../src/lib/bids/materialsByStage.ts), 21 tests): `parseStageSplitJson` / `stageSplitJson`; `effectiveSplit` takes the assembly's default for a part — the walk is now part (bid) → line (bid) → **assembly memory** → fixture → none, so a line split set on the bid overrules the catalog for that job; `computeMaterialsByStage` takes `assemblyPartDefaults` and splits a bundle by catalog value when the assembly stages any of its parts; `planRuleFill` takes `bookSplitFor` (book first, `source: 'book'`) and `describeRulePlan` says *N from the book · M by rule*; `paymentRowsFromStageShares` for the Cover Letter.
- **IO** ([`materialsByStageIo.ts`](../../src/lib/bids/materialsByStageIo.ts)): `loadAssemblyPartStageSplits`, `saveAssemblyPartStageSplit`, `saveBookEntryStageSplit`; `loadMaterialsByStageForBid` loads the assemblies' memory for every bundle line so the paper agrees with the rail.
- **The sheet**: a bundle part's boxes read the assembly's memory dashed (*what the assembly remembers* in the tooltip); a part staged by hand shows **remember for ‹assembly›**, and *the assembly remembers this* once it does. The tab loads `assemblyPartDefaults` per bundle template and `bookStageSplitByRow` from `matchBookEntries` + `takeoff_book_entries.stage_split`; **Remember** on a fixture writes its split to the entry (`, with its stage` in the toast); the panel's button reads **Fill from rules & book**.
- **Cover Letter**: **Use stage shares** in the Schedule of values editor (shown once the takeoff has staged material) rewrites the *before Rough In / Top Out / Trim Set* rows from the stages' shares, scaled into what the other rows (retainage, deposit) leave, whole percents summing to 100. The rows load whenever the payment schedule or the Materials by stage pill is on.

## Not done, on purpose

"Scale to contract" as a choice on the tab (the builder supports it; the Takeoffs tab does not hold the priced total); a Won hand-off that seeds the job's stage billing from the schedule (the natural fifth PR once Wendi has used this on a few bids).
