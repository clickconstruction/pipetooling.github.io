# v2.5287 — Messages: a link that opens a person’s thread on GC projects, behind the scenes (2026-10-12)

The Messages build's cut 1, the thread window's contract, landed ahead of the screens so the cuts that draw inside it
can build against it (the lead's ask). No screen yet: `ThreadWindow` comes with cut 1's screens.

- **`src/components/gc/messages/useThreadWindow.ts`**: the URL holds an open thread, `?thread=<contact id>&at=<message
  id>` on /gc, over whatever view is open, so a link opens it and Back closes it. `useThreadWindow()` returns the open
  thread and `openThread(contactId, at?)` / `closeThread()`, which keep every other param (the view, a focus).
  `threadFromSearch`, `withThread` and `withoutThread` are the pure halves.
- **`src/components/gc/messages/threadSlots.tsx`**: `ThreadSlots`, what later cuts draw inside the window, each a
  function of the person or the line: `headerRight` and `statusRow` (cut 2's who-has-it and back pills, cut 8's portal
  pill), `menuRows` (`ThreadMenuRow`, after the window's own Show all text and Open their record), `aboveBox` (cut 2's
  owed strip, settling note and back day), `box` (cut 3's reply box), `underLine` and `lineBody` (cut 2's offer and
  highlighted body), `messageWindowFirst` (cut 2's highlight slot) and `side` (cut 4's flow panel). `useThreadSlots()`
  returns them; each cut adds its own lines there, and the page never changes for a slot.

Tests: `useThreadWindow.render.test.tsx` (5): the URL read and written, a press opening over Follow up and closing back
to it, a link opening a thread, and no slot drawn until a cut fills one.
