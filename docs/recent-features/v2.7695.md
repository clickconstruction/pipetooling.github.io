# v2.7695 — Lien run: four numbered steps on each notice, with a receipt for every envelope (2026-11-17)

The third of three changes from the owner's yes to the mail proof mock-ups of 2026-11-17 (v2.7688 the receipt press, v2.7691 what went out). He asked for the presses to be responsive and easy to follow. Client only: no migration, no edge function.

## What was there

- A run row had three ticks, Printed, Signed and Mailed. **Add what was mailed** sat on a line of its own between the row's name and the ticks, and on a phone it was 20 px tall.
- The run took no receipt. A notice's receipt could be added in one place, the Lien window's **Save & record sends…**, which a notice mailed from the run never passes through.

## What changed

- **Four numbered steps** in the order they are done (`LIEN_RUN_STEP_WORDS`): *1 · Printed*, *2 · Signed*, *3 · In the envelope*, *4 · Mailed*. The file press of `LienRunMailedCopies` moved into step 3, which turns green once a file is on it. A row not printed yet says *print first* there.
- **A Next line** under the row's name (`lienRunRowNext`, pure): the signature, the print, the file that goes in the envelope, then each envelope's number and receipt, then *Ready to record.* A held row and a paid one show none, since their own line says why. A receipt is asked for, never required: the record press reads the numbers alone, as before.
- **A receipt beside each number.** Each envelope's box in step 4 has the receipt press of v2.7688 under it. A photo's barcode fills a number box nobody has typed in. The link rides with the envelope (`RunRecipient.receiptUrl`, set through `setEnvelope`), so every notice inside a shared envelope takes it, and `recordLienDeskRun` writes it with the send as `receipt_url`. An emailed copy takes none.
- **The row's shape.** The name, the amount and the two parties sit on one line at the top and the four steps run the row's width under it (`index.css`: one column, the steps `1fr 1fr 1.5fr 2.4fr`). On a phone Printed and Signed sit side by side and the two wide steps stack under them.
- **A thumb's height on a phone** for the file press, each file's name, **Take off**, **Printed ▸** and **Signed ▸**, and in **Filed liens: copies to mail** for **Close**, × and **Open the Lien window**.

## Known limit

A receipt added in the run is held with its envelope until the mailing is recorded, as the typed number is. A run closed before the record keeps neither. The file is still in the job's Drive folder, and **What went out** on the sent notice (v2.7691) takes the receipt afterwards.

## Verified

`lienRunChecklist.test.ts` (the Next line, the receipt on the cell), `lienDeskRunIo.test.ts` (the receipt on the send), `LienRunChecklist.steps.render.test.tsx` (4) and the run's other render tests. The row, the block and the filed liens window were drawn from the real components with the app's stylesheet at 860 px and 390 px and measured: nothing runs past the edge, and every press this change touched is 44 px or taller on the phone. Not pressed on a real phone.
