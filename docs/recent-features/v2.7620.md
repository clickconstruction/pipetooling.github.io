# v2.7620 — Documents: Search finds agreements too (2026-11-17)

Punch list #376, PR 4 of five: search. Client only. The Documents Search tab mounts the Agreements list as a fifth section, under Jobs, for the roles that see the Agreements tab.

## What is new

- **Documents → Search → Agreements**: `DocumentsUnifiedSearchTab` mounts `DocumentsAgreementsTab` with `embedSearch`, behind `canSeeAgreements`. The box's hint names agreements for those roles.
- **Embedded, the list draws no box and no chips.** It stays quiet until two letters, then asks for the typed words across every kind and every state.
- **`StateAsk`** in `agreementsLedger.ts`: a state chip's pick, or `any`. `statesOfPick('any')` answers null and `readAgreements` then adds no state filter.
- **The typing rests in both modes.** The tab waits 300 ms on the words it is handed as it does on its own box, so a key in the Search box is not a read.

## Choices worth knowing

- **Every state under Search.** The tab opens on *Sent and signed* and keeps voided papers behind a chip. A search has no chips, and the person who types a customer's name wants the voided contract found as well, so it asks for all three states. Each line still wears its state chip.
- **No count is read under Search.** The *Waiting on a signature* count belongs to a chip the section does not draw.
- **The four ledgers are as they were.** They still load on mount and filter in the browser. This section reads only once there are two letters, a page of a hundred, with Show more.
- **The Jobs section's search still does not match a job's contract lines.** The Agreements section under it now does that job.
