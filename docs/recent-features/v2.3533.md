# v2.3533 — Stages tab decomposition, PR 3: the command bar is its own component (2026-09-16)

Client only, behavior-preserving. PR 3 of the train in `to-dos/engineering-hygiene.md` — the rest of region 2 of [`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md) after the ⋯ menu left in v2.3532. With this, the whole toolbar is out of `JobsStagesTab.tsx`.

## What moved

[`src/components/jobs/JobsStagesCommandBar.tsx`](../../src/components/jobs/JobsStagesCommandBar.tsx) — New Job, Follow-ups with its badge, Forecast, the search box with its two busy hints and screen-reader description, the Session notes chip, the # jump chip, and the applied-filter chips (sort, contract, GC, development, Account Man, hidden groups), cut verbatim. The ⋯ menu is handed in as `toolsMenu`, so its props stay at the tab and the bar knows nothing about it. The chip style moved with the chips.

Three things changed shape, none of them behavior:

- **The search box's focus ring** (`stagesSearchBarFocused`) was the only tab state nothing else read; it is now the bar's own `useState`, per the playbook's "tab-local state moves with the tab".
- **The # jump's inline body** (loaded board first, then the lean lookup across every job) became `jumpToTypedNumber` in the tab, passed as `onJumpToNumber` — the same two lines, named.
- **`JobsFollowupModal`** was rendered inside the toolbar's flex row. It is a fixed-position dialog, so it now sits right after the bar in the tab instead of inside it; nothing about how or when it opens changed, and the tab keeps the six values it is wired to.

The part meant to last: **one `filters` object**, built once in the tab (`stagesToolsFilters`), now feeds both the bar's chips and the menu's selects. Before, the two read the same nine values through separate inline expressions; a filter added to one and forgotten in the other would have shown in the menu with no chip to clear it. Now the type (`StagesToolsFilters`, exported by the menu) is the contract for both.

Numbers: `JobsStagesTab.tsx` 5,906 → 5,557 lines; the bar is 442 including its props type and header. Six imports the tab no longer needed went with it.

## New coverage

[`JobsStagesCommandBar.render.test.tsx`](../../src/components/jobs/JobsStagesCommandBar.render.test.tsx), five tests: the buttons and the menu slot render and fire for an office user; Forecast and Session notes hide when not allowed and New Job shortens on request; the search placeholder follows the schedule-time toggle, typing reports, both busy hints show, and the description link comes and goes with the toggle; only the applied filter chips render, each clearing on tap while the hidden-groups chip opens the manage modal; the default filters draw no chips.
