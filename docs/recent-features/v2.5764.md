I would like to make it very, very easy for an assistant to get this information presented to them in QuickFill and be able to update the percentage complete. ## Is this the best we can do?

1. **The Pipeline's own facts, not a second reading**: the card's stage bar, paid share and ticks are the row's models, so what the assistant fixes here is exactly what the Pipeline shows. No new RPC, no new read.
2. **One sentence per card**: the kind chip says the shape, the sentence says the numbers, the box already holds the answer. The assistant reads, presses Save, moves on.
3. **A deposit is not work**: the one rule that keeps the list honest. Without it every job with a deposit paid would sit here at 0% done every week.
4. **The write is the Pipeline's**: the same note, the same column, the same activity trail. An assistant's Quickfill fix reads in Job activity like an office edit from the row.
5. **Shared dismissals**: one table, one kind per station, any later worked list reuses it. Nothing per device.
6. **Cut**: a note box on the card (the sentence is the note), a per-job snooze length (a week is the owner's word), and a "mark the stage done" door (the stage is already ticked; the percent is what lags). Considered and left: flagging a % ahead of the ticks — a bill reminder, which the Pipeline already is.
