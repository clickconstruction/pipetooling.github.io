# v2.3788 — Pipeline: find the Working jobs with no date (2026-09-23)

PR 3 of the two-week strip (v2.3752 the strip, v2.3785 the worked ticks): the Working header gets the schedule pills and a next-first sort, drawn as option D on the mock-up page. Nothing new is fetched. Client only, no migration.

## The change

- **[`stagesWhenPills.ts`](../../src/lib/jobs/stagesWhenPills.ts)** (new, tested) — `stagesWhenForJobs(jobs, upcomingByJobId, todayYmd)` runs the strip's own `deriveStagesWhen` once per Working job and classifies it: `thisWeek` (a block from today through this week's Sunday, `stripWeekEndYmd`), `later`, `unscheduled` (nothing booked, under 100 %), `done`. `countStagesWhenPills` (All counts everyone; Not scheduled never counts a finished job), `filterJobsByStagesWhenPill`, and the next-first order as one string key per job (`stagesNextFirstKey`: `0 <ymd> <start>` booked · `1 <last worked>` unbooked, never-worked first · `2 …` finished) with `makeStagesNextFirstComparator(upcomingByJobId, tieBreak)`.
- **[`jobsStagesSortMode.ts`](../../src/lib/jobsStagesSortMode.ts)** — a fourth mode, `next` ("Next scheduled first"; chip *next first*), persisted per device like `added`; `toggleStagesNextFirstSort`. The ⋯ menu's Sort group lists it automatically.
- **[`jobsStagesBoard.ts`](../../src/lib/jobsStagesBoard.ts)** — `buildJobsStagesBoardLists` takes an optional `nextFirst` comparator, used when the mode is `next`; the classic comparator `sortStagesJobsByEffectiveNumberDesc` is exported as its tie-break.
- **[`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx)** — the board memo hands the comparator in (and depends on `stagesUpcomingByJobId`); `stagesWhenPill` state (session-only, default All), `workingWhen` / `workingWhenCounts` / `workingShown`; the Working header renders the four pills (amber when Not scheduled is non-zero, dark when picked) and the `⇅ Next first` toggle; the Working list takes `workingShown`; with Not scheduled on and finished-unbooked jobs present, a muted line under the list says how many were left out and why.
- **[`index.css`](../../src/index.css)** — `.stagesWhenPills` / `.stagesWhenPill` (`isOn`, `isWarn`, `isSort`) / `.stagesWhenDoneNote`.
- **Guide** *see what days a job is on people's calendars* — a *Find the ones with no date* section; `JOBS_STAGES_TAB_ARCHITECTURE.md` region 4.

## Decisions

- The pills filter **Working only** — that is where Taunya's question lives and where "not scheduled" is a gap; on Waiting it is the stage's meaning. The sort, like every sort mode, orders the rows inside every section.
- The pill pick is not remembered: a filter left on overnight hides rows. The sort is remembered, like *time added*.
