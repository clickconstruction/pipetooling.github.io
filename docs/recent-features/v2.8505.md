# v2.8505 — The type check runs src as three programs that each fit (punch list #434, PR 1) (2026-11-24)

Infra, no screen. No migration, no edge function. One `tsc` over all of `src` needed 12.3 GB of heap on 2026-11-24 and grew about 190 MB a day, and a GitHub runner can give about 13.3 GB (v2.8482). `npm run typecheck` now checks the same files as three programs, one after the other, and the largest needs 8.6 GB.

## The change

- **Three programs** (`scripts/lib/typecheckParts.mjs`), each a config that extends `tsconfig.json` with its own build-info file under `.cache/typecheck/`:
  - `tsconfig.app.json`: `src` without `*.test.ts` and `*.test.tsx`.
  - `tsconfig.tests-lib.json`: the tests under `src/lib`, and what they import.
  - `tsconfig.tests-rest.json`: the tests elsewhere, and what they import.
- **No project references.** A program is its `include` list and everything that list imports. App code that tests import is checked again in the test programs, which costs time and not correctness.
- **`npm run typecheck`** (`scripts/typecheck-queued.mjs`) runs the three under the one machine-wide lock, each through `scripts/lib/runTsc.mjs` with the machine-sized heap and the NO VERDICT line of v2.8482. A part with errors or a heap death does not stop the next, so every part's errors print. A Ctrl-C does stop it. The last line says where it stands, for example `typecheck: all 3 parts are clean.` or `typecheck: 2 of 3 parts clean; with errors: tests-lib.` The exit code is the worst part's.
- **The build's `tsc -b`** (`scripts/tsc-build.mjs`) checks the app program alone. The tests do not ship, and the merge queue's `checks` job has checked them on the same content.
- **`tsconfig.json` stays the whole program**, for editors. The check no longer runs it.
- **CI checks the files it checked before.** `ci.yml` and `warm-caches.yml` still run `npm run typecheck` and cache `.cache` whole; their cache key now also hashes the three configs, so a changed `include` list starts a fresh cache. The first runs after this merges are cold for that reason.
- **The warm-up job's limit is 30 minutes, up from 15.** A cold warm-up is the install, twelve minutes of typecheck and a cold lint, and a warm-up killed at its limit saves no cache, so every run after it would have been cold too.

## One fault the split found

`src/lib/lens/seal.ts` declared `window.__lens` with a `declare global` inside the module. One program over `src` always loaded that module, so the name was known everywhere. The tests-elsewhere program did not load it, and printed three errors where `src/lib/hardReload.ts` and `SettingsWhatEveryoneSeesTab.tsx` read `window.__lens` without importing the seal.

- The declaration moved to `src/lib/lens/lensWindow.d.ts`.
- Each test program's `include` takes every `.d.ts` under `src`, so an ambient name is known in every part.
- `src/lib/typecheckParts.test.ts` refuses a `declare global` or an ambient `declare module` inside a module from now on.

What this says:

- **The largest part needs 8.6 GB against 12.3 GB whole.** A runner's 13,312 MB cap leaves it about 4.7 GB, where the whole program had about 1 GB. If that part grows in step with the whole, that is four to five weeks, not one.
- **The deploy's check is about half as long**: 5:05 for the app part against about 10 minutes for the whole program, and 8.8 GB resident against 12.5.
- **A cold check is dearer**: 11:42 on a runner against 10:04 at the same cap, and on a Mac with memory to spare about 13 minutes against 5. A cold check is the first one in a fresh worktree, or a pull request that changes the lockfile or a tsconfig.
- **A warm check is 15 seconds dearer** on a runner (0:38 against 0:23), and holds 3.9 GB against 5.3. That is what almost every pull request runs.

## Is this the best we can do?

It is the cut that fits today with no change to how the code is written. Two things are left on punch list #434:

- **The peak on every CI run** (PR 2), so the next wall shows weeks ahead.
- **The app program itself** (PR 3): 8.1 GB and growing with the app. Either find the few type shapes that cost the most, or project references.

One variant was measured and not taken: the app and the tests outside `src/lib` as one program, beside the `src/lib` tests. It is two minutes quicker cold (7:50 and 1:52) but its larger program needs 9.4 GB, 0.8 GB more than the largest of three.
