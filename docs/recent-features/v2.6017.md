# v2.6017 — Retainage held: the release (2026-10-28)

Punch list #165, PR 3 of 4 (release C of the owner's picks): the kernel (v2.6010) and AR's band (v2.6015) showed the money; this PR releases it. On a job with pay applications the final application at zero retainage releases it, and the bill tied to it carries the release. On a job with none, a release bill for the held amount is drafted — from AR's line, or from the lien details once our contract on the job has ended — and marked so every reader finds it.

## What changed

- **Migration** [`20261028160000_retainage_release_bill.sql`](../migrations/20261028160000_retainage_release_bill.md): `jobs_ledger_invoices.retainage_release boolean NOT NULL DEFAULT false`, the mark on the release bill. Catalog-only. **Push after merge** (`supabase db push`); the client deploys first and refuses to draft until the column is there.
- **The final application** (`lib/aiaPayApplications.ts`): `retainageReleaseOffer(form)` — the form holds retainage and the work is all in (`AIA_FINAL_APPLICATION_AT`, 99.9% of the scheduled value) → what 0% releases and how much more is due; it takes the drop offer's place. `finalApplicationOffer(apps)` — the latest live application still holds → the history's press. In the window (`AiaG702G703Modal.tsx`): the green *Release it · 0%* strip at the retainage field (`aia-retainage-release`); `newFinalFromHistory` starts the next application as New does and sets retainage to 0. In the history (`AiaG702G703History.tsx`): *Final application · N · release $X* under *New application*, with the words *Retainage goes to 0 on it, and the bill you tie to it carries the release.* The tie (v2.5032) is unchanged: the AR line reads the tied bill's state.
- **The release bill** (`lib/ar/retainageHeld.ts`): `retainageReleaseDraft(line)` — a line read from the lien details, still owed, nothing released → the whole figure once, with the memo `RETAINAGE_RELEASE_MEMO` (*Retainage release*). `lib/ar/retainageHeldIo.ts`: `draftRetainageReleaseBill` writes the `ready_to_bill` draft through `writeDraftInvoice` (the job form's own draft door: the next sequence, the remainder re-sync on a Ready to Bill job) and marks it in `afterInsert`; a database without the column answers `RetainageReleaseNotReady` and the draft is taken back through `delete_ready_to_bill_invoice`, so no unmarked bill is left behind. `readBills` selects `retainage_release` and `sequence_order`, re-reading without the mark on `42703`; `loadRetainageHeldRowsForJob` is the one-job read. `retainageHeldRows.ts`: `releaseBillId` is the job's newest marked bill; `facts.billCount` is the draft's place.
- **AR's band** (`ArRetainageHeld.tsx`): a line with no pay application and nothing released carries *Draft the release bill…* (blue) beside *Open the job*; *Drafting…* while the write runs. `BankPaymentsModal.tsx`: the handler confirms (*Draft the release bill?* … *Draft the bill*), drafts, toasts *Release bill drafted for $X on <job>. Send it from the job's Bill tab.*, rebuilds the band and refetches the jobs; only roles that can apply bank payments see the press.
- **The lien details** (`JobFormLienContractRow.tsx`): `hooks/useJobRetainage.ts` reads the job's line; once the contract state is Complete / Terminated / Abandoned, a job with retainage held and no pay application shows *Our contract has ended and <GC> still holds $X. A release bill asks for it.* with the same press and confirm; once a release exists the row reads *Retainage release: release billed · awaiting payment.* under the retainage box.
- **Tests**: `aiaPayApplications.test.ts` (+6: the release offer at 100%, none while work remains or at 0%, the rounding hair; the history's offer), `retainageHeld.test.ts` (+2: the draft once, none in any release state or on an application job), `retainageHeldRows.test.ts` (+1: the newest marked bill, none without the column, `billCount`), `ArRetainageHeld.render.test.tsx` (+1: the press on the lien-details line only, busy while drafting, none without a handler), `AiaG702G703Modal.render.test.tsx` (+2: the history's final press opens application 2 at 0%; the strip at 100% in the drop offer's place, *Release it · 0%* and the payment due at 0%), `JobFormLienContractRow.render.test.tsx` (+2: the offer on an ended contract drafts after the confirm with the job's facts; none while open; the state line once a release exists). The eleven `BankPaymentsModal*` render tests still pass with the confirm hook in the window.
