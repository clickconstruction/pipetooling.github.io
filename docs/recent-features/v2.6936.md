# v2.6936 — Lien affidavit: a second company address in Settings, printed on the short form (2026-11-11)

Punch list #305, item 5 of *The build*. § 53.054(a)(7) asks for the claimant's name, mailing address and, if different, physical address, as the app reads it; counsel has not answered. Settings held one address (`app_settings` key `physical_invoice_issuer_v1`, field `addressText`), which the short form prints as the mailing address. The short form has printed *Its physical address is …* since v2.6855 when handed one that differs; nothing filled it.

## What changed

- **`physicalAddressText`**, one optional field in the same JSON (`PhysicalInvoiceIssuer` in `src/lib/physicalInvoiceIssuer.ts`). No migration. A setting saved before the field existed parses to a blank.
- **Physical address, if different**, one multiline input under the address in the company block (`PhysicalInvoiceIssuerDevSettingsBlock`, Settings → Jobs, bills and liens), with a line that says what reads it. `?focus=issuer.physicalAddressText` lands on it and rings it, as the other fields' doors do.
- **`buildLienAffidavitFieldsForJob`** (`src/lib/jobs/lienNoticeDraft.ts`) passes it to the short form as `claimantPhysicalAddress`, line breaks as commas, read line by line so a box holding only blank lines is no address. The field is left off when Settings hold none, and on the earlier ten-paragraph form, so a stored copy reads as before. The desk and the Lien window share the fill, so both draw the same paper.
- The paper's own rule is unchanged (`buildShortLienAffidavitBlocks`): the second sentence prints only when the physical address differs from the mailing address.

## What it touches

Only the lien affidavit's short form. Invoices, estimates, contracts, the § 53.056 notice and the edge functions that read the setting parse their own fields and ignore this one.

An affidavit is drawn from the job and from Settings each time, so a short-form paper already drafted or approved prints the second address from the moment Settings hold it, as it would a changed mailing address. A filed paper keeps its own stored fields.

## Prod, read through the dev seat on 2026-11-11

The setting holds one address and no `physicalAddressText`, so no paper changes until the second is typed.
