# v2.3323 — Cash App reconciliation, PR 2: import, the names step, and the lane summary (2026-09-11)

Client only (tables from v2.3321). The first user-facing piece of the owner-approved tool (artifact 44ea272a): upload the Cash App activity export on People → Pay → Payroll → **Pay run**, tie unknown Cash App names to people, and see every send to staff filed into a lane. Decision buttons (Record on a report / Advance / Skip) are PR 3.

## What shipped

- **[`CashAppReconcileModal`](../../src/components/people/CashAppReconcileModal.tsx)** — opened by the new **Cash App…** button in Pay run's right toolbar cluster. Three steps:
  1. **Upload** — `parseCashAppCsv`; shows rows / new (by Cash App id against `cashapp_transactions`) / new sends to staff; skips straight to the summary when an import already exists.
  2. **Names** — `unresolvedCounterparties` over the new sends plus already-imported review rows with no person; a datalist of person names (`personNameOptions`: pay config ∪ reports ∪ users, test accounts dropped) or a **not staff** tick; saved as `cashapp_aliases` upserts on `counterparty_key`.
  3. **Import + match** — every new row is inserted (`upsert … ignoreDuplicates` in 200-row chunks; non-staff rows land in `ignored`, not-staff names in `not_staff`, the rest in `review` with the resolved person). Then `matchCashAppTransactions` runs over **every row still in `review`** against recorded payments not already linked (`recordedPaymentsForMatch`, `firstReportStarts` for the before-records floor); `laneForMatchResult` files each: matched → `recorded` (+ `match_rule`, `pay_stub_payment_id`), before the person's first report → `before_records`, expense note → `expense`, else stays `review`. Rows already decided are never touched.
  4. **Summary** — lane chips with counts and money, the to-review table (date · person · sent · note · kind · Cash App ID, grouped by person), a nag to tie any names still unknown, **Import another export**, and **Copy summary** (`buildAgentSummary`: lanes, unknown names, the review list with IDs) — the text an agent reads instead of a screenshot.
- **Kernel [`cashAppReconcileInputs.ts`](../../src/lib/cashapp/cashAppReconcileInputs.ts)** (+5 tests): the glue named above plus `countLanes`.
- Help: `reconcile-cash-app-payments.md` (new).

## Decisions

- **Proxy matching tries both people.** A send from Taunya's account without "Tristen" in the note is matched against Taunya first, then Tristen; with the note, the reverse. Malachi's alias on Jessica Whites is a plain redirect.
- **Owner's note (2026-09-11): "some of these payments may have gone out before we started counting."** Hence the `before_records` lane: a send dated before that person's first pay report (or, for a person with no reports, before the company's first report) is filed there and never nags.
- The whole export is stored, not only staff sends (`ignored` lane for deposits, Bitcoin, failed rows), so the table is the record of what was uploaded.
