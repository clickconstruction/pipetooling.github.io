# v2.2431 — twin-mcp: the MCP server for twin seats (2026-08-28)

Owner ask: let external agent providers (Grok/xAI etc.) plug into the twin program via
MCP. `supabase/functions/twin-mcp` is a dependency-free Model Context Protocol server
over **streamable HTTP** (stateless JSON-RPC POST; GET → 405, no SSE — spec-permitted):

- **Tools**: `mint_session` (pass-through to `twin-login` with the caller's token, so the
  four account guards, 6/min rate limit, and `twin_runs` mint log stay single-sourced),
  `get_brief`, `get_directory`, `get_harness_guide`, `get_mission` (verbatim mission text
  only — scorer sections never bundled), `submit_report` (→ `twin_runs`,
  `mission = report:<id>`, attributed to the twin).
- **Auth**: every `tools/call` requires the per-twin token (`X-Twin-Token` or
  `Authorization: Bearer`) resolved against `twin_credentials` (v2.2429);
  `initialize`/`tools/list` are open metadata. No business-data tools in v1 — the work
  happens in the app via the minted browser session (browser-first stays the doctrine).
- **Bundled docs are generated**: `briefs.ts` via `node scripts/build-twin-mcp-briefs.mjs`
  from `docs/twins/*` — regenerate + redeploy after brief/mission edits (documented in
  EDGE_FUNCTIONS.md).
- `config.toml` entry (`verify_jwt = false`) + EDGE_FUNCTIONS.md section/TOC.
- Deploy after merge: regenerate briefs (post-#2136 so the harness guide bundles), then
  `supabase functions deploy twin-mcp`. Depends at runtime on twin-login v2 (#2136).
