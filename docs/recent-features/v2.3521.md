# v2.3521 — The firm's confirm / unsubscribe pages, served by the app (2026-09-16)

Bug found by v2.3518's Confirmed-page card on Settings → What customers see. Client + two edge functions (`legal-notify-dispatch`, `submit-legal-portal`); no migration. **Deploy both after merge.**

## Why

`legal-notify-dispatch` answered `GET ?confirm=<token>` and `?unsubscribe=<token>` with a page and `Content-Type: text/html`, but the platform relays that response as `content-type: text/plain; x-content-type-options: nosniff` (a JSON function's `application/json` passes through — verified with curl on prod). Every firm recipient who clicked *Yes, email me* since the legal train (v2.3405) saw the page source. The confirmation itself still recorded, so the emails flowed; only the page was unreadable.

## What shipped

- **A public route `/legal/confirm`** ([`LegalConfirm.tsx`](../../src/pages/LegalConfirm.tsx)): `?t=<token>` confirms, `&stop=1` pauses. The page asks the function for JSON (`&json=1`) and renders the same words from the same builder (`legalConfirmedPageBody` / `legalUnsubscribedPageBody` in `_shared/legalEmails.ts`), in the plain frame the function used to draw. The sample token renders Ann Sample's pages without a call; the tab's *Confirmed page* step now opens this route.
- **`legal-notify-dispatch` GET**: with `json=1` it does the same work and answers `{ kind: 'confirmed' | 'unsubscribed' | 'expired', … }`; without it, the old link shape **302-redirects** to the app page with the same token, so emails already in inboxes land somewhere readable. Its `unsubscribeLink` now builds the app URL.
- **`submit-legal-portal`**: the confirm email's link is the app URL.
- Registry: `/legal/confirm` is placed on the firm's *Confirmed page* step. The `html` render kind from v2.3518 is gone again — the page is a real page now.

## Verified

Typecheck, lint, build; journeys, registry and sample-email tests. Live: `/legal/confirm?t=sample` reads *You're confirmed, Ann Sample.*; `&stop=1` reads *Done, Ann Sample.*; after the deploy, the function's old link shape returns 302 to the app page and `&json=1` answers JSON.
