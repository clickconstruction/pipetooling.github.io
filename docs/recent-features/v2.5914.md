# v2.5914 — Legal desk: documents and the sub-job check read through the generated types (2026-10-26)

The follow-up to the Legal desk train's types regeneration (#6215). The train's columns (`legal_matter_documents` dated_on, state, sent_on, sent_how, sent_to, proof_document_id, received_on from v2.5846; `jobs_ledger.owner_contract_confirmed_at / _by` from v2.5840) are now in `src/types/database.ts`, and both migrations are on prod. The code that worked around their absence goes:

- **The documents client** (`src/lib/legal/legalMatterDocumentsIo.ts`): takes `SupabaseClient<Database>`. The list, the insert and every update go through the generated types, with no `as unknown as` casts. `LegalMatterDocumentRow` is a `Pick` of the generated row, and the v2.5846 fields are no longer optional. The list is one read of the full column list. The second read with the v2.4810 columns, for a table from before migration 20261025150000, is gone.
- **Its callers**: `LegalMatterDocumentsPanel.tsx` passes the typed client, and its untyped `db` alias is gone. `useLegalMatters.ts` passes `supabase` to the list, but its own untyped reads of the other legal tables stay as they were.
- **The packet's job read** (`useLegalPacketData.ts`): `owner_contract_confirmed_at` is a plain column of the row type. The `.catch` that read `jobs_ledger` again without it is gone, so a failed read now counts as a failed source like every other read in the hook.
- **Ours with the owner** (`src/lib/legal/subJobIo.ts`): the `jobs_ledger` update type-checks without `as Record<string, unknown>`.

No behavior change on prod, where both migrations are applied. The panel's render test builds its rows with the v2.5846 fields at their database defaults, which the kernel reads the same as absent.

## Verify

`npm run typecheck` is clean. `npx vitest run src/lib/legal src/components/jobs/legal` passes. On the Legal desk's Evidence tab, documents list, add, mark sent and received, and retire as before.
