# v2.8176 — View as no longer marks the person as seen or syncs their clock (2026-11-21)

Found on 2026-11-20 during a design spike of a crew lead's phone Dashboard, and posted by Taunya as a note to be done. A dev used View as on a teammate to show the page live. The dev's browser is signed in as that teammate while View as is on, so two saves the app makes with no press landed on the teammate: the pane's load set their last seen time and may have added minutes to their app time for the day. Their clock was not changed. No migration and no function change.

## What changed

- **The app activity heartbeat is held while View as is on.** `bumpActivity` in `useAppActivityHeartbeat.ts` is the one place every path of the hook sends through: the seen bump on mount and on a tab shown again, the minute tick, and the part of a minute flushed on a page change, a hidden tab, a closed page and an unmount. It now returns before the call when `isImpersonationSessionActive()` is true. So `user_app_activity_daily` (last seen, active seconds) and `user_app_activity_page_daily` keep only the person's own use.
- **The clock button's salary sync is held too.** `ClockInOutButton` synced a salaried person's clock rows on mount and every 90 seconds through `sync_salary_clock_sessions_for_user_day`. It now calls `syncSalaryClockSessionsUnasked` (`salaryScheduleSync.ts`), which makes no call while View as is on and says `held`. The read of the clock that follows still runs, so the strip stays current. Nothing is lost: the `sync-salary-sessions` function fills every salaried day on the server's own schedule.
- **The flag is read at each send, never once at mount.** A minute or a 90 second tick scheduled before an imitation began is held when it fires, and both start again when the imitation is over.
- **Exit takes the flag off last.** `handleBackToMyAccount` in `Layout.tsx` and in `Settings.tsx` removed the stash before the session swap, a network call. For that moment the page was still signed in as the person with the flag already off. The stash is now removed after `auth.setSession` answers, and on the failure path before the move to the sign-in page.

A sync a person presses for is untouched: a saved workday, time off, a pay change and the People strips still call `syncSalaryClockSessionsForUserDay`, in View as too. A press in View as saves as that person, as it always has.

## Why in the client

The session View as opens carries the person's own sign-in, so both database functions see the person and nobody else. They could tell: the token says it was opened by a magic link and when, and `user_imitations` (v2.6290) holds every imitation, which is how `gmail-mine` refuses such a session. Teaching `bump_user_app_activity` and the salary sync the same rule is a migration and is left as a question.

## What it does not do

- It repairs no row. An activity row is a day's totals with no session on it, so a dev's minutes inside it cannot be taken back out exactly.
- It holds only these two. The PR lists the other saves a page makes with no press and which of them still run in View as.

## Tests

- `useAppActivityHeartbeat.render.test.tsx`: as yourself the bumps go out. While View as is on none does, on mount, on the minute, on a page change, a hidden tab, a closed page or an unmount. A minute scheduled before the imitation is held, and the sends start again after it.
- `salaryScheduleSync.test.ts`: the unasked sync is held while View as is on, reads the flag at each call, and hands back a failure's reason. The pressed sync is not held.
- `ClockInOutButton.viewAsHoldsSalarySync.render.test.tsx`: a salaried person's button syncs on mount and on the 90 second tick as themself, and never in View as while the clock is still read.
- `Layout.viewAsExit.render.test.tsx`: Exit keeps the flag on until the session swap answers.
