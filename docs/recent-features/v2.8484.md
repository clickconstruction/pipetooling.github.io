# v2.8484 — Maps: an unplaced address is now really remembered (2026-11-24)

Punch list #408, a mend to step 2 (v2.8477), found by that step's own live check. The card is [`to-dos/remember-unplaced-addresses.md`](../../to-dos/remember-unplaced-addresses.md).

## What the live check found

After v2.8477 was on the live site and both functions were deployed, a ZZ test job was given a made-up address and the Pipeline was opened three times, at 14:02Z to 14:06Z on 2026-11-24.

- Each open sent the address to `geocode-address-batch`. Each call answered `not_found`.
- No miss was kept. The screen's read of `address_geocode_misses` came back empty every time.
- The database log held no refused write for the table, and the function's log held no warning. So the function never tried to keep the miss.
- The answer's words were *No match from OpenStreetMap or Google; no match from US Census*. Google and the Census had each said *not found*.
- That leaves one cause. OpenStreetMap gave the function something other than a plain *not found*, and v2.8477 kept a miss only when all three said it.

The function did not say which answer OpenStreetMap gave. Its words for a Google *not found* named OpenStreetMap as a miss whatever OpenStreetMap had done. That is mended here too, so the next check reads the real answer.

## What changed

- **The rule**: `isSettledGeocodeMiss` in [`supabase/functions/_shared/geocodeMissMemory.ts`](../../supabase/functions/_shared/geocodeMissMemory.ts) is true when Google and the Census each answered and neither found the address.
  - OpenStreetMap is still asked first. It is no longer part of the rule.
  - Google down, refusing the key, over its limit or with no key set still keeps nothing. So does the Census down.
- **A kept miss says so.** A fresh failure whose miss was just kept carries `checked_at`, without `remembered`. A caller can tell a miss that was kept from one that was not.
- **The words are true.** When OpenStreetMap gives no plain answer, the failure's `detail` leads with it, for example *OpenStreetMap (Nominatim) HTTP 403; no match from Google; no match from US Census*.
- **The log says it once a call.** `geocode-address-batch: OpenStreetMap gave no plain answer: …`, and the same from `geocode-one`.

## A call for the owner

The card's plan kept a miss only when all three services said *not found*, so that an outage could not mark a good address for weeks. This keeps that guard for Google and the Census and drops it for OpenStreetMap.

- **What is given up**: an address that only OpenStreetMap can place, asked while OpenStreetMap is not answering, is remembered as a miss for 30 days. **Try again** asks past the memory at any time.
- **Why it reads as small**: Google is asked for the same address and is the stronger service for a street address, and the address was off the map at that moment either way. That is this session's judgment, not a measured count.
- **To flip it**: put `said.nominatim === 'not_found'` back in `isSettledGeocodeMiss`. With OpenStreetMap as it answers today, nothing would be remembered.

## Left open

Why OpenStreetMap does not answer the function is not known. It may turn away the server's address, or the app's repeated asks for the same few addresses. The log line added here will say which status it sends.
