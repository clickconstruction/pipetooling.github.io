# v2.4877 — People: only a dev is offered Invite as user (2026-10-07)

Found by the help-guides freshness pass (punch list #91) and listed in [v2.4860](v2.4860.md)'s *Left*. Punchlist sent it back as its own small client PR. `docs/ACCESS_CONTROL.md` → *User Management* says **Create users** is dev only, and `invite-user` refuses anyone else with *Forbidden - Only devs can invite users* (`supabase/functions/invite-user/index.ts`). Yet the People → Users row's ⋯ menu offered **Invite as user** to every role that sees the menu: a leader, an assistant or a controller. The press reached the confirm, then failed at the function.

## What shipped

- **The Users row's ⋯ menu** (`PeopleUsersTab.tsx`, `menuFor`) offers *Invite as user* only when `isDev`. Edit, Link account, Combine and Archive are unchanged.
- **The person desk's *No login* gap** (`describePersonGap` in `src/lib/people/personKey.ts` gains `opts.canInvite`) reads *Ask a dev to invite*, with *Only a dev can send the invite.*, for anyone but a dev. Its toast says the same (`PersonDeskHeader.tsx`). A dev keeps *Invite as user* and the old toast.
- **The desk's Access section** points at the header's *No login* note instead of naming the dev's button (`PersonDeskAccessSection.tsx`).
- **Help**: *add someone to the roster* lists the ⋯ menu without *Invite as user*, and says a dev also sees it on a row with no login.

## Tests

- `PeopleUsersTab.render.test.tsx`: a roster-only row's ⋯ menu, per role. A dev is offered *Invite as user*, and a leader, an assistant and a controller are not. All three non-dev cases fail with the gate removed.
- `personKey.test.ts`: the *No login* gap's two wordings.
- The person desk render tests, the plain-words guide test, the release-notes test, lint and typecheck.

## Left

*add someone to the roster* still describes **+ Add to roster** with an *Also invite them to sign in* box. Since v2.4348 the toolbar's door is **+ Hire**. That is a guide fact for the freshness pass's People rows, not this PR.
