# v2.5434 — Messages: every file a job has, read into one list, behind the scenes (2026-10-13)

Messages, cut 7c (GC Mode helper 8, directed by the lead session GC MODE): the reads behind the one list of a job's files. `BUILD_PLAN.md` → *Cut 7* and the mock-up `files-out-mockups.html` (its cut list, 7c) on branch `spike/gc-mode`. No screen, no migration, no edge function: it reads cut 7b's `drive-link` office door, which must be deployed first.

- **`src/lib/documents/jobFilesIo.ts`**: `loadJobFileSources(job)` reads a job's six sources side by side and `loadJobFiles(job)` hands them to `jobFiles`. A job is the spine's `JobRef` (a bid, a GC project or a Pipeline job).
  - The papers the app makes, a GC project's alone: our contract as last sent (`gc_owner_contract_sends`), each pay application (`gc_owner_pay_apps`), each change order sent (`gc_change_orders.sent_on`), each trade's statement of work once awarded (`gc_trade_packages`, never our own trade), and the schedule once it has work on it (`gc_schedule_activities`). Their sizes are not known, since only our contract is stored. A bid and a Pipeline job have none here yet: a Pipeline job's own papers (its estimates and contract) come with 7e and 7f.
  - The plan sets (`gc_plan_sets`) and the trades' uploads (`gc_trade_files`), a GC project's alone.
  - The Drive folder in its two halves, from `drive-link`'s `list`. When Drive does not answer, the rest comes back and `driveFailed` says so; `driveCapped` says the folder holds more than one list reads.
  - The files on the copies of what we sent (`sent_documents.attachments`): a bid's by `bid_id`, a Pipeline job's by `job_ids`, a GC project's by its billing job. A file named on a copy but not kept is left out.
  - The files that came in on the job's messages (`message_attachments` through `messages`): kept copies only, never a link, never one left in Gmail, never one we sent (`sent_as`, cut 7a).
- **`src/lib/documents/jobFiles.ts`**: `JobPaperRow` is renamed `AppPaperRow`, since `flows/jobPapers.ts` exports another `JobPaperRow`. `ArrivedFileRow` takes `mime` from the table in place of `kind`, which the kernel read as a type before `message_attachments` was written; its `drive_file_id` is cut 7a's column.
- Tests: `jobFilesIo.test.ts` (10) over the mapping of each table's rows and the reads against a stand-in client: all six of a GC project's sources, Drive failing, a bid, a Pipeline job, a project with no billing job, a refused read. `jobFiles.test.ts` takes `mime`.
