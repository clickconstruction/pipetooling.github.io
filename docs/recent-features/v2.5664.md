# v2.5664 — Report by line: the My Schedule stepper opens the same list (2026-10-20)

Punch list #130, PR 3 of 5, on PR 2 (v2.5663). The stepper is the fast door — a sub or helper moves the job's percent from their My Schedule card, ±20 at a time, and since v2.2078 that files a Status Report — and it was the other place the whole-job fifties came from. No migration; no edge function.

- **The stepper** ([`FieldPctUpdateModal`](../../src/components/dashboard/FieldPctUpdateModal.tsx)): on a job with two or more priced lines (`useJobLineProgress`), the window mounts [`ReportLinesProgressField`](../../src/components/ReportLinesProgressField.tsx) in place of the big number, the bar and the ± chips — the same list Leave Report shows since v2.5663, the job's recorded number as the Job line's *was*. The number a save writes is what the lines say once something moved, else the base (a note-only save keeps today's number, as before); the button reads *Save · job 38%*. **Set the whole-job % instead** brings the ± chips back, **Mark each line instead** the list. A one-line job, a refused read or any error is the stepper as it was.
- **The report** ([`submitStatusReportFromStepper`](../../src/lib/reports/submitStatusReportFromStepper.ts)): takes `extraFields` and writes them beside the percent and the note — the moved lines under *Stage progress*, the v2.3192 label — and returns the report's id, so the stepper stamps each moved line through `stampMovedLines` after the insert, best-effort, before the shared pipeline (`propagateReportPctToJob`, the Ready-to-bill prompt at 100 on a Working job) runs unchanged.
- **Tests**: `FieldPctUpdateModal.render.test.tsx` gains the lines path (the list in place of the chips, Save held until a line moves, *Save · job 38%* after a pick, the escape bringing the chips back); the five chip cases unchanged; `stepperReportFieldValues.test.ts` unchanged.
- **Docs**: the guide *update how done a job is from my dashboard* gains *On a job with more than one line*; this fragment.
