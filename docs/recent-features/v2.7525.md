# v2.7525 — Lien desk: add what was mailed on a retainage notice, and take a wrong file off (2026-11-16)

The owner, 2026-11-16, asked for two things v2.7461 left for later: "A retainage notice's row in the run has no upload press" and "A file cannot be taken off the list from the run." Client only: no migration, no edge function. The column `job_lien_desk_items.mailed_copies` is the one v2.7460 added.

## What a person sees

- **A retainage notice's row.** A § 53.057 retainage notice rides in the run beside the monthly notices. Once its paper has printed, its row carries **Add what was mailed**, the same press with the same rules. Its file goes to the job's Drive folder as *Retainage notice as mailed · 650 · 2026-11-16.pdf*, so the folder says which paper it is.
- **Take off.** Each file a row lists has **Take off** beside its name. The row asks first, under the files: *Take … off this notice? The file stays in the job's Drive folder.* **Take it off** drops the file from the notice's list. **Keep it** closes the ask.
- After a take-off the words say what changed and what did not: *Took … off this notice. The file is still in the job's Drive folder.*
- A file still listed on a row whose print was taken back can come off too. Nothing can be added there until the paper prints again.
- A take-off that fails says its reason, and the file stays listed.

## What taking a file off does not do

It does not delete the file. `drive-link` has no verb that removes a file from Drive, and a scan of what was mailed is evidence worth keeping. The office can remove the file in Drive itself. A mailing already recorded keeps the link it took as its saved copy: the run no longer shows a recorded notice, so its list is not edited from here.
