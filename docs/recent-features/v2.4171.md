The owner, on the strip under the rows: "I don't love how the documents are presented, I think they could each be on one separate one line instead of two." Before this each file was a boxed card — name and buttons on one line, a rule, the count and *Remove this file* on a second — six lines and two boxes for B375's two files. The drawing (before / after / the other states / two gaps) is `to-dos/submittals/vendor-file-list-before-after.html`.

## The list — [`SubmittalSheetStrip.tsx`](../../src/components/bids/SubmittalSheetStrip.tsx)

- One bordered list, one row per file: an **arrow** (`aria-label` *Show the pages* / *Hide the pages*; opens the fold and asks the host for thumbnails it does not have; a file whose thumbnails are already drawn starts open), the **name** · pages · house, the **standing** (`fileStanding`: a 72 px bar and the words), and the **actions** in weight order — Confirm (when the robot's result waits), **Assign pages…** (blue), *Done with this file* (text, only when something is on rows and the file is not trimmed, held while a page sits on two rows), *Remove* (quiet red, last; not on a trimmed file).
- The **fold** keeps stage 3a as it was: *Drawing the pages…*, the thumbnails with their chips (the robot's dashed guesses, the green tag chips with ×, *2 rows* in red), the row chooser, the conflicts card, and a footer line — `describeFooter` plus *tap a page, then the row it belongs to*, or for a trimmed file *N pages let go · drop the file again if you need one* — with the RobotOffer beside it.

## The standing — `fileStanding` in [`sheetStripModel.ts`](../../src/lib/submittals/sheetStripModel.ts) (3 tests)

## The reader's verdict on the file record

- `SourceFile` gains `namesRows: number | null` and `sectioned: boolean | null` (`names_rows` / `sectioned` in `bid_submittals.source_files`; null until read — no migration, the column is jsonb).
- [`BidsSubmittalsTab.tsx`](../../src/components/bids/BidsSubmittalsTab.tsx) `readFileAgainstRows(bytes)`: `openPdf` → every page's text → `readPages` against `walkRowsFrom(items)` → how many pages name a row, and whether `fileSectionTags` found any. **Drop** runs it before the record is written (the toast then says either *Assign pages… walks it, or open the arrow…* or *no page names a row on this revision; is it the vendor's submittal?*); the **walk** (`SubmittalAssignPagesModal` prop `onReads`, fired once every page is read) reports the same and `noteFileReads` stores it when it changed — so a file dropped before this release gets its verdict the first time it is walked.
