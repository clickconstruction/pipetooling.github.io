# v2.8687 — Dev seat: a box is due a count only when it holds a line to count (2026-11-26)

Found by a docs pass on 2026-11-26 and put to the person as *The dev seat counts an empty Materials box as due a count, when the app does not*; the answer was *"Yes, build them"*. Dev seat 0.137.0. No migration, no new verb, no new file in the functions.

**Read.** Since v2.8612 (punch list #398, migration `20261126014752_box_due_a_count.sql`) one rule says when a box is due a count, the kernel's `boxCountDue` in `src/lib/materials/onSite.ts`: the box is not Unsorted, it holds a line to count (something on hand, or a Can't find since the last count, `lineIsCountable`), and it has no count by hand inside 14 days (`countIsDue` over `lastCountedAt`, which leaves out an added part's own count). Every screen asks it, and `on_site_door_facts` and `on_site_job_summary` copy it. The seat's `read_on_site` did not: `getOnSite` in `supabase/functions/_shared/devMcpComposites.ts` worked `count_due` out as `countIsDue(last, now)` and never asked what the box held. So `count_due` and the summary's `due_a_count` named an empty box never counted, or one past 14 days, that the phone's Count chip, the office's chip, the map's pin and the Job Mode card's line leave out. The page of `on_site_door_facts` tells a reader to verify the function against that very list.

**The mend.**

- `getOnSite` calls `boxCountDue({ kind, last, lines }, now)` with the box's kind, `lastCountedAt(movements, id)` and `linesOf(lines, id)`, the three arguments every screen passes. The rule comes from the kernel copy, `supabase/functions/_shared/gcKernels/lib/materials/onSite.ts`, which `dev-mcp` has bundled since v2.6367 and which has held `boxCountDue` since v2.8612 regenerated it. Nothing is added to the copy, so no other function drifts.
- No new read. The composite already reads the job's whole ledger and works every box's lines out of it. A retired box is not among the live boxes (`groupByPlace`), and a press taken back is closed to the seat by the ledger's own RLS (`job_material_movements_not_taken_back`), as it is to every screen's sum.
- The reply's shape is unchanged: `count_due` on each box, `due_a_count` and `count_due_after_days` in the summary. `read_on_site`'s description says the rule where it said *14 days*.
- `dev-mcp` is 0.137.0: `SERVER_VERSION`, every test that pins it, `docs/dev-mcp/README.md`, `docs/dev-mcp/SERVER_NOTES.md` and `docs/EDGE_FUNCTIONS.md`. `docs/migrations/20261120070000_on_site_door_facts.md`'s verify step and `docs/MATERIALS_ON_SITE_ARCHITECTURE.md`'s row for the verb say which rule the seat asks.

**What the seat answers now, for the same facts as the screens.**

| The box | Due a count |
|---|---|
| Empty, never counted | no |
| Empty, its last count older than 14 days | no |
| Its only lines used or counted down to none | no |
| Holds a line, never counted | yes |
| Holds a line, last counted by hand 14 days ago or more | yes |
| Holds a line, counted by hand inside 14 days | no |
| None on hand, a Can't find since its last count, that count 14 days old or more | yes |
| Holds a line, an old count by hand, a part added since | yes: the add counts its own line |
| Unsorted, whatever it holds | no |
| Retired | not listed among the boxes at all |

**Tests.** `src/lib/devMcp/devMcpComposites.test.ts`: one job of nine boxes, a case each from the table, with Unsorted holding a line and a retired box holding one; `due_a_count` is the five due boxes by stencil; and each box's `count_due` is held against the client's own `boxCountDue` over the same ledger, so the seat and the screens cannot part without a red test. `src/lib/gc/edgeKernels.test.ts` holds the copy to the kernel as before.

**Help guides and the twins' directory.** None names the seat's count rule, so none changed. The two Materials guides already say the app's rule since v2.8612.

**Deploy.** `dev-mcp` is the one function whose bundle holds a changed file. It deploys bundled from `main` by `bash scripts/deploy-functions.sh dev-mcp`, then `npm run check:edge-drift`. The deploy is asked for by name and waits on its own yes; until it lands the live seat asks the old rule.
