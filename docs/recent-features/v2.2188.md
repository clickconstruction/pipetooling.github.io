# v2.2188 — Dialog-role sweep: 120 modal panels gain role="dialog" + aria-modal (2026-08-23)

PR 2 of the modal scroll-lock plan (PR 1 = v2.2186, the sentinel). Mechanical, script-driven, merges alone: [`scripts/codemods/dialog-role-sweep.mjs`](../../scripts/codemods/dialog-role-sweep.mjs) (re-run it on a rebase conflict; never hand-resolve).

- **What it does**: for every file with a fixed `inset: 0` dark backdrop and no `role="dialog"`, tags the **panel** (the first plain element inside the backdrop) with `role="dialog" aria-modal="true"`. 64 files, 120 panels; zero fallbacks onto the backdrop itself.
- **Left alone on purpose** (SKIP list in the script): invisible click-catchers and non-dialog fixed surfaces — `JobReportsModal`'s catcher, `DispatchAddBlockTimeRange`, `ScheduleDispatchHub`/`Grid`, `SwipeToConfirm`, `JobsStagesThreadPanel`, `ScheduleDayTimeline`, the roadmap tab's fullscreen shell, and `Toast` (already `role="alertdialog"`). Elements that already carry a role (the confirm/prompt `alertdialog`s) are skipped by the element-level check — the first dry run duplicated `role` on `ConfirmDialog`; fixed before applying.
- **Why**: (1) the v2.2186 sentinel now detects these modals by the explicit `role`/`aria-modal` signal instead of leaning on the `[style*="position: fixed"]` heuristic; (2) assistive tech announces them as modal dialogs, and the v2.2186 `[role="dialog"] { overscroll-behavior: contain }` rule now reaches them.
- No behavior change otherwise; typecheck/lint clean; full suite green (render tests unaffected).
