# v2.5900 — One index of every door the app has, with its words and its gate (2026-10-26)

Punch list #181, PR 1 of 4 (`to-dos/go-anywhere/README.md`). The owner's lens of 2026-10-26: a go-anywhere box, the same search or ⌘K, that also opens a page, a Settings card, a guide or a window by name. The box comes in PR 2; this PR is the index it reads, shipped first because the Dev doors card (v2.5882) and the box must read one list, not two.

## What shipped

- **`src/lib/search/doors.ts`**: a pure kernel. `Door` is `{ id, kind, label, where, words, to, gate }`, the kinds `page`, `window`, `settings`, `guide` and `todo`. `allDoors(sources)` builds about 230 doors before the guides and to-dos: the signed-in routes and their tabs by hand (Jobs' ten gated as `Jobs.tsx`'s router gates them, Bids' through `bidsTabOpenFor`, Messages' kinds from `KIND_PILLS`, the GC views, Prospects' kinds), the windows the app opens from a query (the Legal desk and its Timeline, GC Review, the Follow-ups deck's Idle lens, Weekly money movement, the scope book, the call script, the New job / bid / estimate forms), the 22 Settings groups from `getZonedSettingsGroups` and the rail's `SETTINGS_SEARCH_INDEX`, and every `DEV_DOORS` row. The guides and the punch list live in Vite-only modules, so the caller hands them in through `DoorSources`. `doorsFor(viewer)` filters by gate; `searchDoors(query, doors)` ranks by word starts (label prefix, then a label word, then a keyword, then the where line), AND over the words, three a group with the rest counted, `>` `?` `#` as prefixes, a leading *how do I* stripped, and a number alone finding no door. `isDevOnly(door)` is computed from the gate for every role, never declared.
- **The gates read the helpers the app already trusts**: `isPathAllowedForRole`, `getZonedSettingsGroups`' filter, `guideIsRelevantForRole`, `canOpenPunchList`, `canOpenBids` + `bidsTabOpenFor`, `canOpenGcProjects`, `canOpenMessages`, `canSeeGcMoney`, `canAccessBanking`, `canOpenRoadmap`, `canOpenMoneyfill`, `canOpenDayBook`, `canWorkRobotAudits`, and the Dev doors card's `who`. A Phone and texts card the office reads and the owner sets opens for whoever sees the tab (`OFFICE_READS_THE_CARD`); every other dev-doors row opens for its `who`.
- **`doors.test.ts`** holds the index to the app: every page, window and Settings door's path is a route `src/App.tsx` serves; every signed-in route has a door (`/my-statement` excepted, a per-person flag); every Settings group and every anchor `settingsDeepLink.ts` knows has a door; every window door names the file that reads its query key and the file still reads it; for every role, with and without the Prospects flag and Farm Mode, no door the gate opens is a path the route guard bounces; every `DEV_DOORS` row is in; and the four searches of the mock-up land where it drew them.
- **`settingsSearch.ts`**: the reverse check found three anchors with no entry. *Bid cover letter defaults* gains its anchor; *Estimate defaults* and *Estimate terms editor* are new entries on Bids & materials.
- `/duplicates` is gated to a dev: the route guard admits a dev alone, though Settings → Bids & materials links an estimator there too (unchanged here, noted for the dev-gates audit).
