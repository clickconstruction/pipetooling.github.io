# v2.8076 — Maps: a key Google refused once is remembered for the page (2026-11-20)

Found by the audit of punch list [#387](../../to-dos/painted-maps-on-google.md) on 2026-11-20, on Google's own script. Client only: no migration and no function.

## What was wrong

**A map made after the refusal waited eight seconds on an empty frame.** Google says a key is refused once for a page, through `window.gm_authFailure`, and not once for each map. v2.7981 made every Google map *on the screen* hear it. A map that came up later heard nothing: Google gave it a frame that never painted, and only the paint clock (`paintClock.ts`, eight seconds) brought the other map up. A painted map kept its own failure for the page (`paintedGooglePage.ts`, v2.7990), but only a failure under a painted map.

Walked on the local server with a made-up key that Google refuses, at a desk:

| Step | Seen before | Seen after |
|---|---|---|
| The Jobs page, with its own map | Google refused the key and the page's map fell back, as built | the same |
| A painted map opened on that page, no reload | Google's canvas at 0.7 s, an empty frame, the Leaflet map at 8.3 s with *the Maps API loaded but never painted a map* | the Leaflet map at 0.7 s, the first look at which the window had a map at all, and Google's canvas never mounted |

**One Google map still put its own function on the global.** `PermitSkimGoogleStill` (v2.6877) set `window.gm_authFailure` to its own function and put back whatever it had found when it left. That is the pattern v2.7981 took out of the pins canvas. A still that came up first found nothing, so when it left it put nothing back, and the shared listener was off the global until the next map asked to be told.

## What changed

- `src/lib/map/googleAuthFailure.ts` remembers the refusal until the page is loaded again. `onGoogleAuthFailure` tells a listener that asks after it at once, and `googleKeyRefusedOnPage()` answers the fact. A refusal nobody was listening for is remembered too.
- `useGoogleCanvasDoors` needed no change: its canvases ask through `onGoogleAuthFailure`, so the pins canvas and a painted map's canvas both fall back the moment they come up.
- `PinsMapFrame` and `PaintedMapCanvas` read the fact for their first answer, so Google's canvas is not mounted at all on a page where the key is already refused.
- `PermitSkimGoogleStill` asks through `onGoogleAuthFailure` like every other Google map.

Nothing changes while Google accepts the key: the fact is only ever set by Google's own word.

## Tests

- `googleAuthFailure.test.ts`, 10 (3 new): a listener that asks after the refusal is told at once and is not kept, the fact is remembered, and a refusal nobody heard is remembered.
- `PinsMapGoogleCanvas.render.test.tsx`: a canvas mounted after the refusal falls back at once.
- `PinsMapFrame.render.test.tsx` and `PaintedMapCanvas.google.render.test.tsx`: with the key already refused, each opens on the Leaflet map and Google's canvas is never mounted.
- The three files that fire Google's word now forget it after each test.

## Not changed

- The load timeout (ten seconds) and the paint clock (eight) are as they were. They are the doors for a script that never comes and a frame that says nothing.
- A failure that is not Google's word (a timeout, a file that did not arrive) is still kept by each map for itself, and by a painted map for the page.
