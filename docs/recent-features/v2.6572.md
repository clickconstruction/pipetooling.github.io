# v2.6572 — The seal behind the Away note: three locks in the database, the fourth in the functions, and the probe that proves them (punch list #256, PR 7) (2026-11-06)

Punch list #256's seventh PR, the second of the Away note's four. PR 6 (v2.6566) is the screen's kernel. The owner's call 5 of 2026-11-03 lets a teammate who left sign in to one screen; the card's second pass found that the app hiding every other screen locks nothing, since a signed-in person holds a token that reaches the database, realtime, file storage and the edge functions directly. So the seal is four locks on an archived caller, and it ships and proves itself before PR 8 lets any archived account sign in. Nothing is visible, and nothing changes for anyone: archived accounts are banned at sign-in until PR 8 skips the ban for a person with a note on.

## What changed

- **Migration `20261106120000_archived_seal.sql`** (`docs/migrations/20261106120000_archived_seal.md`): `caller_is_archived()`, one primary-key lookup in the shape of `is_read_only()`; `archived_pre_request()` set as `pgrst.db_pre_request` on `authenticator`, refusing every request from an archived caller with `PT403` except `/rpc/my_away_note` (PR 8's RPC, named now) and passing a request with no caller; `apply_archived_read_blocks()`, one restrictive `archived_fence` policy for every command on every RLS-enabled public table that lacks it, closed to the API like the other sweep helpers, and the same fence on `storage.objects`. The `ALTER ROLE` warns instead of failing the push where the role may not alter `authenticator`; the doc names the one-line check for after the push.
- **The fourth fence call.** `CLAUDE.md`'s rule now names four calls after `CREATE TABLE`, and `scripts/check-migrations.sh` rule 6 fails a migration after this one that creates a table and skips any of them. Until now the three were a rule without a check.
- **The edge guard** `supabase/functions/_shared/refuseArchivedCaller.ts`: `isArchivedCaller(admin, userId)` and `refuseArchivedCaller(admin, userId, headers)`, the 403 in the gate's own words; a read that fails reads as archived. `scripts/check-edge-archived-guard.mjs` (`npm run check:edge-archived-guard`) lists every function that reads the caller and switches to the service role without the call: 104 of 179 today.
- **The probe** `npm run test:pg:archived-seal` (`scripts/pgtest-archived-seal.sh`, `supabase/tests/archived_seal/20_scenario.sql`), in `scripts/sql-beds.txt` so the SQL beds workflow runs it on every PR that touches a migration: the structure (every RLS table and `storage.objects` fenced, the gate set, the helper closed), an active dev reading and updating where the archived one reads no row of any table and updates nothing, the gate on a table, a view, GraphQL and every RPC `authenticated` may call, the one pass to the note, the pass for no caller, and the predicate's cost printed.

## Decisions

- **The guard sweep is its own PR.** Adding the call to 104 functions is a script-driven change across many files, which `CLAUDE.md` has merge alone, and every one of them must then be deployed. PR 7b does that and wires the check into `ci.yml`; until then the check runs by hand, and the ban keeps every archived account out regardless.
- **The fence is on every command, not reads alone.** The card asked for a read fence, since reads are what realtime obeys; a write fence costs the same policy and closes the second door too.
- **The pre-request's exception for `authenticator`.** On the local bed `postgres` alters the role; on prod the migration's role may not. A hard failure there would block every later push, so the block warns and the doc names the check Micah runs after the push.
- **Measured.** `caller_is_archived()` averaged 5 microseconds a call over 2,000 calls on the stub bed, one indexed lookup; the CI bed prints its own figure in its log.
