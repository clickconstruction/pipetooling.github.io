# v2.4695 — Updates reach the app again (2026-10-06)

Client only; no migration, no edge function. Found while checking that punch list #85 was live.

## The defect

Every `deploy.yml` run on `main` from 06:47Z failed at **Build** (or was cancelled by the next push), so GitHub Pages stayed on `0eb0f0cfc` (06:26Z) while about six hours of merges, their migrations and their edge functions went live around it. The build's PWA step refused the main chunk:

```
Assets exceeding the limit:
- assets/index-DARBWxU-.js is 7.02 MB, and won't be precached.
```

The cap is `injectManifest.maximumFileSizeToCacheInBytes` in `vite.config.ts` (5 MiB). The first failed build was v2.4661; the window from the last good build held seven commits, and the jump came from v2.4655 (#4646, *§ Rules opens the rules in a window you can search*). `LienRulesModal` imports `HELP_GUIDES` from `helpGuideRegistry`, whose `import.meta.glob(..., { eager: true })` carries every help guide (318 files, 1.74 MB). That module was meant to ride only in the lazy `/help` chunk (its own header says so); imported by `LienRulesDoor` → `LienDeskModal` / `LienInstrumentsModal`, it landed in `index`.

PR CI (`ci.yml`) does not run `npm run build`, so the merge queue never saw the failure.

## The fix

- `LienRulesDoor.tsx` loads `LienRulesModal` with `React.lazy` inside a `Suspense` (fallback `null`; the door already turns blue and sets `aria-expanded` on press). The registry, `marked` and the sanitizer now ride in the lazy chunk the `/help` page shares. The window still mounts only while open.
- `vite.config.ts`: the cap goes from 5 to 6 MiB, with a comment saying why. After the fix the main chunk is 4.92 MiB, which left 80 KiB under the old cap — the next ordinary merge would have broken deploys again. 6 MiB still trips on a regression the size of this one.
- `LienRulesDoor.render.test.tsx` waits for the lazy window (`findByTestId`) before the fake timers start.

## Checked

`npm run build` passes locally; the largest chunks are `index` 4.92 MiB, `Settings` 2.80, `Bids` 2.56, `Jobs` 2.20, `helpGuideHtml` 1.78 (the guides, lazy). The door's two render tests pass.

## Left

- PR CI should run the production build so a deploy-breaking change cannot merge; today only `deploy.yml` builds.
- Every public page is imported eagerly in `App.tsx`; lazy public routes would cut the main chunk well below the cap.
