# v2.2280 — Fix: touch scroll canceled the lifted Outstanding card (2026-08-25)

v2.2270's hold-to-lift on Review → Outstanding by person used dnd-kit's
`PointerSensor` (delay 280 / tolerance 8) with `touch-action: pan-y` rows.
Pointer events cannot prevent browser scrolling — after the hold activated,
the first finger movement let the browser claim the vertical pan, which fired
`pointercancel` and dropped the card while the page scrolled (owner report).

Fix (`src/pages/Checklist.tsx`): the drag sensors are now
`MouseSensor` + `TouchSensor`, each with the same 280/8 activation
constraint. `TouchSensor` attaches a non-passive `touchmove` listener and
preventDefaults it **only while a drag is active** — scroll locks from lift
to drop and works normally otherwise (rows keep `touch-action: pan-y`, so a
finger that moves before the delay scrolls and never lifts). Desktop feel is
unchanged (same delay on the mouse path).

The Map's hold-to-lift (v2.2273) does not have this bug — its rows use
`touch-action: none` and the canvas pans via React Flow, not browser scroll.

Verified live on the dev build (mobile viewport, synthetic TouchEvents
against prod data): pre-activation `touchmove` not defaultPrevented (scroll
allowed), post-activation moves defaultPrevented (scroll locked), full drag
down then back up reordered Jessica's three cards and persisted through
reload; original order restored after.
