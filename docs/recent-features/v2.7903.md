# v2.7903 — Robots: a redeemed kickoff names the twin its key belongs to (2026-11-19)

`twin-setup`'s `redeem` now fills the kickoff for the twin the key was minted for. Found on the first live run of the dev seat's whole path, 2026-11-19: `plan_twin` → `apply_twin` made Twin Estimator 4, `mint_twin_setup_code` and `redeem_setup_code.py` put its key on a Mac, and the kickoff saved beside the key opened with "You are **twin-estimator-1**".

## Why

The kickoffs in `docs/twins/kickoffs/` are written for each kind's first seat. `redeem` filled the connector's address and nothing else, so every key got the first seat's name whatever twin it belonged to. That was right while the fleet had one bid robot. The session's key decides who it is on the server, so nothing was written under the wrong name. The session itself was told the wrong one, and its report to the person said it.

## What changed

- `supabase/functions/_shared/twinKickoffFill.ts` (new, pure): `fillTwinKickoff(doc, { connectorUrl, kind, twinEmail })` fills the connector's address and swaps the first seat's bold name for the twin's own, read off its fleet address by `twinSeatHandle`. The first seat keeps the doc's words. An address that is not a fleet seat keeps them too.
- `supabase/functions/twin-setup/index.ts`: `kickoffFor` takes the redeemed twin's address and calls the kernel. The code kickoff, the rounds kickoff and the pricing kickoff all go through it.
- The docs are not rewritten and take no new placeholder. The Console's Copy buttons hold no key, so they hand out the doc as written.

## Held by a test

`src/lib/bids/twinKickoffFill.test.ts` holds each bundled kickoff to naming its first seat once, in bold, and no other seat. A doc reworded to drop the name would otherwise stop the swap with no error. It also reads `twin-setup` for the call.

## Files

- `supabase/functions/_shared/twinKickoffFill.ts`, `supabase/functions/twin-setup/index.ts`.
- `src/lib/bids/twinKickoffFill.test.ts`.
- `docs/EDGE_FUNCTIONS.md` (the redeem sentence and the generated-input sentence, amended).
- No migration and no change to `twinKickoffs.ts` or the kickoff docs.

## Deploy

`supabase functions deploy twin-setup` after the merge (`verify_jwt = false` stays in `config.toml`). Until then a redeem hands back the doc as written. A kickoff already saved on a Mac is not rewritten: the one beside Twin Estimator 4's key still says twin-estimator-1 until that Mac redeems a new code.
