# v2.3858 — Lien windows: the signer is the job's master, in every window — Stages Stage-A sweep II, PR 2 (2026-09-26)

Client only; no migration, no edge function. Punch list **#46** row 2, the Stages tab's Stage-A sweep II, one kernel per PR (`docs/JOBS_STAGES_TAB_ARCHITECTURE.md` → Stage-A candidates); PR 1 was [v2.3857](v2.3857.md). One user-visible fix rides with it (below).

## Why

`JobsStagesTab.tsx` held two memos, `lienToolingSenderFallback` and `lienReleaseSignerFallback`, that restated `lienSignerNameFor` (`lib/jobs/lienSigner.ts`, the kernel counsel's answer 7 is written into: the master signs, his title line or his name, else the session) line for line — while the same tab already had `lienDeskSignerFor`, a callback over that kernel, for the Lien desk. The map flagged one more thing: `LienInstrumentsModal` was handed `lienReleaseSignerFallback`, which reads the *release* modal's job, so with the release window closed the instruments window fell back to the session name — and asked that it be decided before the swap.

## What shipped

- The two memos are gone. The three windows read `lienDeskSignerFor(<their own job>.master_user_id)` at their props: `LienToolingPrefillModal` (`senderNameFallback`), `LienReleaseModal` and `LienInstrumentsModal` (`signerNameFallback`). No new kernel; `lienSigner.ts` (2 tests) is the one rule.
- **The fix, decided here:** the instruments window (the § 53.056 notice and the affidavit on a job) signs as its own job's master. Before, it signed as the person at the keyboard whenever the release window was not open for the same job. The tooling prefill and the release windows read exactly what they read before.
- The map strikes the row and records the decision.
