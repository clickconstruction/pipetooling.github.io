# v2.1913 — Roadmap Plan view + the empty-stage lock-trap fix (2026-08-20)

Owner-approved from a live-play review of the Default roadmap (24 stages, 89 tasks, 1 completed in 116 days, 84 open tasks unstaffed): the canvas is a good map that wasn't generating work. Two changes:

**Milestone completion (the lock-trap fix).** Task-less "goal" stages (Full Use of Land, Foundry to Build Things, …) could never complete — completion required ≥1 task all done — so stages behind them ("Build and test Products") were permanently locked. New rule: a stage with no tasks is a milestone that counts complete once every predecessor is complete (vacuously true for empty roots; chains cascade via fixpoint). Implemented twice, kept in sync: `computeCompleteGroupIdsWithMilestones` in `src/lib/checklistTechTreeGraph.ts` (canvas, Plan view, Review Goals strip via `goalsStripRows`) and migration `20260821001500_roadmap_milestone_unlock.sql` (CREATE OR REPLACE `sync_roadmap_to_checklist` with a plpgsql fixpoint loop). Until the migration is pushed, the client may show a stage unlocked that the RPC won't materialize yet — benign, self-heals on push.

**Plan view.** A Map/Plan segmented toggle (persisted per device, `roadmap_view_v1`) swaps the canvas for a flat work surface (`ChecklistRoadmapPlanView`, kernels + tests in `src/lib/roadmapPlanView.ts`):
- Header truth: done/total progress bar, assigned vs **unstaffed** count (red when > 0).
- **Now** — unlocked, incomplete, task-bearing stages sorted by momentum, each naming what it feeds; task rows open the v2.1901 task card.
- **Tap-tap staffing** (structure editors): "Staff this stage" → pick a name chip once → tap tasks to hand them out; each tap inserts one `checklist_tech_tree_task_assignees` row and reloads, and the load's sync RPC puts the task on that person's Today list immediately.
- **Up next** — locked task-bearing stages with their blockers named (`lockedStageHint`).
- **Goals** — task-less stages as milestone cards measured by their transitive feeder tasks (e.g. "1 of 14 feeder tasks · 5 stages").

Verified live from a worktree dev server against prod: Plan renders (17 Now stages, 13 goal cards, header "1 of 89 · 84 unstaffed"), full staffing loop exercised on a real task (assign → header flipped to 5 assigned → task materialized onto Today via the sync) then reverted; Map mode unaffected, toggle persists. Suite green (5053 incl. 10 new kernel tests).
