## What shipped

- **Kernel** [`src/lib/orgDefaults.ts`](../../src/lib/orgDefaults.ts) (+6 tests): the key registry (`jobs.stages.mobile_cards`, `tally.payroll_auto_apply`, `billing.stripe_mode` — label, hint, kind, fallback), the two role groups (field: subcontractor · helpers · superintendent; office: the rest), and `resolveOrgDefault(key, role, rows, deviceRaw)` → **device → role → everyone (`'*'`) → fallback** with its `source`. `orgDefaultBool` keeps `'auto'` for "hand the decision back" (Mobile cards' width gate).
- **Store + hook**: `orgDefaultsStore.ts` (one `org_defaults` read per session, subscribers, `saveOrgDefault` per group or `'*'`, delete on `''`), `useOrgDefault(key, role, deviceRaw)`.
- **Consumers**: `JobsStagesTab` (Mobile cards) and `JobTally` (payroll auto-apply) seed their state from the org default once loaded **only when the device has nothing stored**; `getBillingStripeModePref(role?)` falls through to the org default when the device has no value. Every device toggle keeps writing its own localStorage key, so a device that chose is never overridden.
- **Dismissals follow the person**: `user_dismissals(user_id, key, state)` (own rows only). The three dismissal kernels stay pure and call `pushDismissal` (`dismissalStore.ts`, a no-op until Layout registers the pusher); `dismissalSync.ts` registers it at sign-in and seeds localStorage from the server where the device has nothing.
- **Settings → Company → Defaults for everyone** (`SettingsOrgDefaultsSection`, dev + master; Settings search entry): one row per key, selects for Everyone / Field roles / Office roles ("Mixed — set to unify" when a group's roles disagree).
- **Migration**: `org_defaults` (SELECT any signed-in user, ALL `is_master_or_dev()`) + `user_dismissals` (own rows), both read-only appliers. Both read soft (missing table = no rows) so the client keeps today's behaviour until the push.
- Guide `set-defaults-for-everyone` (new). `database.ts` carries both table types by hand until the next gen-types run.

Deliberately not moved: Job Mode (#26's hard-coded role default stays the shipped instance), the Stripe invoice-footer presets and other true per-device UI prefs.
