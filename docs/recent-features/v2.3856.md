# v2.3856 — Bids → Pricing: the scenario loader has a home of its own — `loadScenarioInputs` to `lib/bids` (2026-09-26)

Client only; no migration, no edge function, no screen change. Punch list **#46** (`to-dos/decomposition-queue.md`), row 1's second PR — the second half of Stage A in `docs/BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md` (the first half, the `scenarioPricingRows` kernel, was [v2.3853](v2.3853.md)).

## Why

`BidsPricingTab` still owned the read that feeds the kernel: `loadScenarioInputs`, the four overlay reads (price book entries, assignments, custom prices, submission hides) plus the scenario's own count rows when it lives on another bid version — the decision that, taken wrong, priced every Share row at \$0 (v2.3685). A closure over the tab's `priceBookVersions` and `selectedBidVersionId`, untested, and the map's named second half of Stage A.

## What shipped

- **[`src/lib/bids/loadScenarioInputs.ts`](../../src/lib/bids/loadScenarioInputs.ts)** — `loadScenarioInputs(supabase, { bidId, pricingId, scenarioBidVersionId, selectedBidVersionId })`, taking the client the way `loadBidAssignedCosts` does; the `ScenarioInputs` type moves with it. Two pure pieces carry the decision: `scenarioNeedsOwnRows(scenarioBidVersionId, selectedBidVersionId)` (own rows unless the scenario's version is the one on screen; a legacy unversioned scenario on an unversioned bid is the on-screen one) and `scenarioBidVersionIdOf(scenarios, pricingId)`. Own rows read by version, or with `is('bid_version_id', null)` for a legacy scenario, in `sequence_order`; empty reads are `[]`, and own rows that come back empty are `[]`, never null (null means "the rows on screen").
- **The tab** keeps a one-line `loadScenarioInputsFor(bidId, pricingId)` that passes its scenarios and on-screen version; both callers (Share / print / CSV of the ★, the alternates' revenue) are unchanged.
- **Tests** — `loadScenarioInputs.test.ts` (8, on a proxy client that records each query's steps): the own-rows decision's four cases; the version lookup; the four overlay reads carry the bid and scenario keys and the on-screen version never awaits the count-rows builder; another version's rows read by version in sequence order; the legacy scenario reads the unversioned rows; empty reads; rows handed back as read.
- **Docs** — the map's candidate table and move 1 say done; the queue's row 1 and its `next` (the dead-code PR is the Pricing map's next move; rows 2 and 3 of the queue are next for the queue).

## Left in the tab, on purpose

The workbench-cards effect's batch `.in()` read (every version's overlays in one pass, v2.3841) is a different shape and stays; the map lists it beside this loader.
