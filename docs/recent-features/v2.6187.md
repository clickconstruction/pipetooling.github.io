# v2.6187 — A dev's agent can set its own Mac up with a twin key, without the key passing through a chat (2026-10-30)

PR 3 of 3 for the owner's ask after the Gun Dog intake (*"a verb to pull the twin key so anyone with dev access can direct an agent to set up a bid for estimating"*). Not a verb that returns the key: a tool result is transcript, so the key must never come back through one. The Settings page already solves this with a one-time setup code that a Terminal command redeems (`twin-setup`, v2.3277); this PR puts the mint on the dev seat and the redeem in the twin toolkit. No migration. **Deploy `dev-mcp`** after the merge.

- **dev-mcp 0.12.0 — `mint_twin_setup_code({ label, twin?, rounds? })`**: POSTs `twin-setup` `action: mint` as the dev (the function enforces dev-for-any-twin and ten codes per ten minutes; `twin_setup_codes` keeps who minted it); `twin` is a users.id or a twin email, the first estimator twin when left out. The reply is the code, when it expires, the twin, the label and the redeem command — never a token. Refused through `view_as`; outside the plan→apply grammar, which the server's instructions now say.
- **`scripts/twin/redeem_setup_code.py <code> [--rounds]`** (stdlib only): POSTs `twin-setup` `action: redeem` with the Mac's hostname, writes the returned key to `$TWIN_TOKEN_FILE` (default `~/pt-twin-digest/twin.token`, directory 700, file 600), saves the kickoff beside it, prints the twin, the label, the connector and the check call — never the key. A refused code says so and nothing more. After it `python3 scripts/twin/twin.py get_brief` answers, `/bid bNNN` runs, and `bash scripts/twin-session.sh` starts a Code session with the connector live.
- **The rule changes** (`docs/twins/TWIN_HARNESS.md`, `scripts/twin/README.md`, the `/bid` skill): an agent never printed or read a twin key and never issued one; now it may mint a setup code through the dev seat and redeem it into a file it never reads. The audit trail is unchanged: `twin_setup_codes.created_by` and `redeemed_from`, the `setup` line in `twin_runs`, the key's label on the fleet.
- Docs: `EDGE_FUNCTIONS.md` → dev-mcp, `to-dos/mcp-servers.md`. With v2.6183 and v2.6185 the recipe is five calls and one curl: `plan_bid` → `apply_bid` → `plan_file_plans` + the PUT → `apply_file_plans` → `mint_twin_setup_code` + the redeem → `/bid`.
