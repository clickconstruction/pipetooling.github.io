# v2.6342 — A bid pins the set it was priced on, and the hand-off to the job (punch list #239, PR 4) (2026-11-02)

The card's fourth PR, after the papers train (v2.6312, v2.6313). The design's third rule, *a bid pins; a job follows*, had no column and no hand-off: a bid carried set rows and the link the robot reads, but nothing said which set the price stood on, and a job opened from the bid started with an empty Plans subfolder stamped on it by the folder maker.

## Change

- **Migration `20261102060000_bid_priced_on_set.sql`** (`docs/migrations/20261102060000_bid_priced_on_set.md`): `bids.priced_on_set_id` (a `bid_plan_sets` row; null means the set the robot reads, so no backfill); `plan_set_link_key(text)`, the client's `samePlanLink` in SQL; `list_bid_jobs_plan_state(uuid[])`, `SECURITY DEFINER` for the office and estimators who may price the bid, since an estimator reads no job row; and the trigger `jobs_ledger_seed_part_from_bid` (`AFTER INSERT ON jobs_ledger`): a job with a `bid_id` and no part joins the development part already building from the bid's set, else gets a part named after itself seeded with that set (`issued`, from the GC, dated the row's date, memo *From B398, the set it was priced on*), names it, and the existing mirror writes `job_plans_link`. Best effort inside `BEGIN … EXCEPTION`, so no job insert fails on it. A trigger, not a client call, so every door that makes a job carries the set and the job form stays untouched (another card edits it this week).
- **Kernel `src/lib/bids/bidPricedOn.ts`** (pure, `bidPricedOn.test.ts`): `pricedOnItem` (the pin, else the robot's set), `pricedOnIsPinned`, `pricedOnLine`, `partMovedOnNotes` (one note per part whose current set is not the priced one, by link, naming every job on it).
- **Io `bidPricedOnIo.ts`**: `loadBidJobsPlanState` (fail-soft) and `setBidPricedOnSet` (throws its reason).
- **`BidPlanSetsField.tsx`** (`BidPlanSetsField.render.test.tsx`): **Priced on this set** on every row but the priced one; the green *Priced on* chip; the line under the list; the amber notes with **Open the set ↗** and *Open JP972 ›* (the job window's Documents tab through `useJobFormModal`). `BidFormModal` passes the bid's pin in.
- **Types**: `bids.priced_on_set_id` and `list_bid_jobs_plan_state` hand-carried in `src/types/database.ts`; the dev-mcp catalog regenerated.
- **Docs**: guides *keep more than one set of plans on a bid* (the pin) and *keep the plans on a job* (a job opened from a bid); `GLOSSARY.md` → *Plan sets (Bids)*; the card's front matter.
