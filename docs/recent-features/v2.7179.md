# v2.7179 — Materials on site: change a box's name, its kind and where it stands (2026-11-13)

The owner's ask of 2026-11-13, after a read-only look at a development's hundred boxes. Some names carried what the model has a field for (a name ending in *NO CONTAINER*, names with the contents typed in), and every box on the site was saved as a cage, pallets and piles included, because Cage is the Add sheet's first choice. Nothing could fix either: a box's name, kind and where line were typed once in **Add a container** and never again. A wrong name meant retire the box and make another, which changes its code and so its printed label.

## What changed

- **The rules and the words** (`src/lib/materials/editBox.ts`, pure, 11 tests): `editBoxVerdict` cleans the draft as Add a container saves it (trimmed, one space, capitals), holds the database's own limits (24 characters a name, 120 a where line), refuses a name a live box of the job already carries by the index's own key (`lower(trim(label))`), never touches Unsorted or a retired box, and answers a patch of only what changed. `editBoxPressLabel` names the act: *Rename to G70* when the name changes, *Save G70* otherwise. `renameLabelNote` and `editedBoxWords` say what a rename does to a label already stuck on.
- **The write** (`editContainer` in `onSiteStore.ts`): one `job_containers` update through the store's `commit`, so it is drawn at once and, with no signal, kept in the outbox and sent later (v2.7173). `applyOnSiteWrites` learned the three columns, each only when the press sent it, and never blanks a name.
- **One form, two hosts** (`src/components/materials/EditBoxForm.tsx`): the name, **How it sits** (Cage · Box · Loose pile, with the line *A pallet, or a thing too big for a box, is a loose pile.*), **Where exactly**, the refusal in words, and the press. The phone's box screen opens it from **Edit** beside the box's name, in the tab's own sheet. Jobs → Materials opens it from **Edit** beside **Label** on each box, in `EditBoxWindow`.
- **The guide**: *Change a box's name or kind* in the on-site guide.

## What a rename does and does not touch

- **The code and the printed label stay.** `job_containers.code` is cut from the row's id. The QR on a label printed before the rename opens the same box. Only the large words on the tape are old until it is printed again.
- **The history is kept by the database.** `job_containers_keep_names` (v2.7072's trigger) writes the old name, the new one, who and when to `job_container_names` on every changed `label`. No screen reads that table yet: the *Renamed from …* line is #329 PR 4's.
- **The ledger, the counts and the place are not touched.**
- **A photo already filed in Drive keeps the file name it was given**, which starts with the old name.

## No migration, no function

`job_containers_update` has allowed the gate's people to update a box since v2.6039, and the name history's trigger has been live since v2.7072. A training account and a digital twin are held by the fences as before.

## Left

- **Pallet is not a kind.** The check on `job_containers.kind` is cage, box, loose and unsorted. A pallet is saved as a loose pile, and the form says so. A fourth kind is one small migration and its word in four screens.
- **The dev seat cannot edit a box.** `dev_on_site_write` has no such action, so `plan_container` still adds, moves, retires and brings back.
- **The Add sheet still opens on Cage.**
- **#329's PR 4** keeps the rest of *change it afterwards*: the history line, the sticker's own presses, and *Empty it and start over*.
