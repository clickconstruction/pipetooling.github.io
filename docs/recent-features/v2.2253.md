# v2.2253 — Roadmap Map: canvas menus, edge routing, review mode, amber add-icon (2026-08-24)

Four Map upgrades from the 2026-08-24 design spike, all in
`ChecklistTechTreeTab.tsx` + new sibling components.

## Canvas pointer menus (`ChecklistTechTreeCanvasMenu.tsx`)

- **Click (or right-click) a prerequisite line** → menu at the pointer with a
  two-line header naming both stages and a red **Remove link** (calls the
  existing `removeEdge`; the menu header is the confirm step). Editors only.
- **Right-click empty canvas** → amber **＋ Add stage here** → the usual
  Add-group dialog; on save the stage is created at the pointer via a new
  `{ kind: 'pane', flowPosition }` `AddGroupModalState` and the existing
  `newGroupManualPositionFromConnectRef` mechanism.
- One menu at a time; Esc/click-away dismisses; portals into the canvas shell
  in fullscreen. The Links modal remains for auditing all links at once.

## Edge routing (dagre waypoints; no new deps)

`layoutTechTreeFlow` now keeps dagre's per-edge `points` (it computed and
discarded them) and sets `edgesep: 28`; new `ChecklistTechTreeRoutedEdge`
renders the polyline (real handle endpoints + dagre interior waypoints,
rounded bends via `buildRoutedEdgePath`, tests added). Verified geometrically
on the live Farm 1 graph: 0 of 59 edges intersect any stage box; 0 overlapping
parallel runs (99 lane runs sampled). Edges touching a manually-moved stage
fall back to plain smoothstep until Organize re-routes (waypoints are only
valid at dagre's positions). Layout-cache semantics (`structuralKey`,
Organize-only refits) untouched — waypoints ride in the same cached pass.

## Review mode (`ChecklistTechTreeReviewHud.tsx`)

**Review stages** button (Map header; named to avoid colliding with the page's
Review tab) walks stages one at a time in priority (`sort_index`) order: the
current card expands and centers (two-shot `fitView` — re-layout must re-measure
before fitting), everything else collapses and dims to 35%. The floating bar:
◀ ▶ / arrow keys step, amber **▲ #n ▼** swaps `sort_index` with the neighbor
via the existing `saveStageOrder` (a flash names who traded places; you stay on
your card), ✕ / Esc exits and restores the collapse snapshot. Same ranking the
Order-stages modal / stage badges / Plan / ⚡ Next up read — no second priority
system. Viewers without edit rights get the tour without ▲▼.

## Toolbar

The *Add a roadmap group* icon is amber (`#d97706`, matching the cost-chip
accent) so the create affordance stands out from the muted icon row.

Help guides updated: *add a stage and its tasks to a roadmap* (right-click way,
remove a line), *number and order roadmap stages* (review mode).
