# v2.4759 — Pipeline on a phone: a link to a stage lands on that stage (2026-10-07)

Client only. Punch list #93 D (the Collections look of 2026-10-06).

## What was wrong

The phone board shows one stage: the first open section in strip order (`phoneActiveStage = PHONE_STAGE_ORDER.find(open)`). A door that only opened a section — `focusStagesSection`, which `?stagesSection=<key>` and the Dashboard's drill-downs reach through the handle's `focusSection` — left every earlier open section open, so the board landed on that earlier stage and the strip's own chip had to be tapped.

## What changed

- `JobsStagesTab.tsx` `focusStagesSection`: on the phone board it calls `pickPhoneStage(key)` (one stage open, the rest closed — the strip's own rule); on a computer it opens the section as before. The scroll to the section is unchanged.

## Tests

- `JobsStagesTab.render.test.tsx` +1: a phone board (matchMedia stubbed, mobile cards on) with Ready to Bill open; `focusSection('collections')` selects the Coll. chip and deselects Ready. On the old code the assertion fails.
