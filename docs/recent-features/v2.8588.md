# v2.8588 — Accounts Receivable: the office can reopen a case it closed (2026-11-25)

Punch list #443, row 5, on the owner's answer of 2026-11-25: asked whether the press built for a developer on a test row should be wider, *"Wider, as fixing picked"*. The pick read: **Reopen** a closed case for the office. Client only. No migration, no edge function.

**Before.** v2.8566 drew *Closed test cases · N* for a dev alone, and **Reopen…** only on a case whose every job is a ZZ test job. A case on a real job closed by mistake stood closed for good.

**The database already let the office in.** `reopen_ar_return_case`, `reopen_ar_stripe_case` and `reopen_ar_unbanked_check_case` each let a dev, a master, an assistant and a controller in (`20261119104000_primary_money_desks.sql`), and Accounts Receivable is open to those four.

**Now.**

- `arCaseReopenDrawn` is true for those four roles (`AR_CASE_REOPEN_ROLES`) and for nobody else.
- `arCaseReopenProblem` no longer refuses a case on a real job, or one that names no job. It still refuses an open case, a case that is gone, and a case closed for any reason but *settled another way* or *not coming*. The fresh read before the call runs the same rule.
- The folded line reads *Closed cases · N*. `arClosedCases` lists only the cases a reopen undoes, newest closed first. A case closed as replaced, or by Stripe's answer, is counted under the list and not drawn: *N closed cases are not listed. A case closed by a new payment or by Stripe's answer stays closed.*
- The list grows for good, so it draws the cases closed in the last 90 days (`AR_CLOSED_CASES_RECENT_DAYS`, counted from today in the app's time zone) and folds the rest behind one press, **Show N older cases** (`arClosedCasesShown`, `arClosedOlderLabel`). When every case is an older one they are all drawn, since a fold with nothing above it would hide the list.
- The confirm says what a reopen leaves: *The case goes back under Came back, for everyone who opens Accounts Receivable. It stands open there until someone closes it again. Its closing reason and note are cleared.* Its button still reads **Reopen the case**.
- The line *Only a developer sees this list.* is gone.

**Renamed.** `ArClosedTestCases` is `ArClosedCases`, `arClosedTestCases` is `arClosedCases`, `reopenArTestCase` is `reopenArCase`, and the test ids drop *test*. `arCaseIsOnTestJobs` is gone with its one use.

**One thing the client alone holds.** `reopen_ar_return_case` reopens any closed returned-check case and clears its replacement. The two Stripe and unbanked functions hold themselves to the two reasons. So for a returned check, the rule in `arCaseReopenProblem` is what keeps a *replaced* case closed, as it was in v2.8566. Holding it in the function too is a migration and is not in this PR.

**Tests.** The kernel for the four roles and for an estimator, a case on a real job, the 90-day edge (day 90 is drawn, day 91 is folded) and the fold. A render smoke of the list as an assistant, a controller and a master. The window's smoke as an assistant reopening a real job's case. The fresh read's test.
