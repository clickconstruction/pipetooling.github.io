# v2.6893 — Permits: the reads made index-driven, and the read back turned on again (punch list #307) (2026-11-10)

The read back (v2.6873) was held the night it shipped, before its first run (`docs/recent-features/v2.6886.md`): the Permits reads took 1 to 3 seconds each on ten weeks of rows, and their cost grew with the product of building permits and plumbing permits in a city. This makes them index-driven and lifts the hold.

## What changed

- **Migration `20261111003750_permit_reads_indexed.sql`** (`docs/migrations/20261111003750_permit_reads_indexed.md`): `research_permits`, `research_permits_v2` and `research_builders` replaced in place. The pairing of a building permit with its plumbing permits, by number or by address, is two indexed joins in place of one `OR`; Builders' bids with a name likewise. Same shape, same rows, 20 to 60 times faster.
- **The hold lifted**: `HISTORY_CITIES` is San Antonio again, so Builders draws **Read back to …**; `permit-pull` no longer refuses a read back (`HISTORY_HELD` is gone). `historyAsk` keeps the list it can be handed, so its steps are tested whatever cities are open.
- **`scripts/pgtest-permit-skim.sh`**: the bed re-applied the skim's migration last, which put the first bodies of the reads back, so later rewrites were never probed. It runs `*_permit_history.sql` and this migration again after it.
- Guide `research-permits-for-work-to-bid` names the press again; card #307.
- **`nameAnswers.ts`**: a sentence that ends on a customer's name ends once. Seen on the first live walk, where a name ending in *Assoc.* drew two full stops in the name question.

## How it was proven

Read only, on prod: each rewritten body beside the live function with the same arguments, `EXCEPT` both ways, in all five cities and three windows. One row differed on the first pass, a plumber picked between two plumbing permits filed the same day; that pick was already left to chance, so it has a tiebreak now and the comparison is clean. Timings are in the migration's doc.

## Tests

`nameAnswers.test.ts` (a name ending in a full stop), `permitReach.test.ts` (San Antonio asks with no list handed in, another city does not), `ProspectsResearchTab.render.test.tsx` (the press reads one step back, then the start and the list again), `npm run test:pg:permit-skim` on the rewritten reads.

## Release order

Merge, `supabase db push`, `supabase functions deploy permit-pull`. Between the merge and the deploy the press shows and the pull still refuses it with its reason. Then the press, a step at a time, back to January 2025, with the reads timed after each step.
