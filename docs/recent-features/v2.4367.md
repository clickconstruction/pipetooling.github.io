## What changed

- **Kernel** `listPayer(job, inv)` in [`billToParty.ts`](../../src/lib/jobs/billToParty.ts): the bill's payer (`paySpeedPayer`, v2.4365), else the job's customer for a bill typed to someone else, so nothing leaves the lists.
- **Call mode** ([`paymentChase.ts`](../../src/lib/jobs/paymentChase.ts)): one card per payer, named by the payer and judged late on the payer's pace. A card also counts the touches logged on any of its jobs under another id (the homeowner, before this), so the quiet and snooze rules still hold. A dispute is named by its bill's card. The card's phone and email already load by the card's customer id, so a builder's card dials the builder.
- **Money waiting**, **Pay speeds breakdown** ([`moneyWaiting.ts`](../../src/lib/jobs/moneyWaiting.ts), [`paySpeedsBreakdown.ts`](../../src/lib/jobs/paySpeedsBreakdown.ts)), **Billed by customer** ([`billedByCustomerBreakdown.ts`](../../src/lib/jobs/billedByCustomerBreakdown.ts); each bill's `customerId` is the payer, so its Resend touch files under them), **Dashboard AR** ([`dashboardFinancials.ts`](../../src/lib/dashboardFinancials.ts) items; [`useDashboardFinancials`](../../src/hooks/useDashboardFinancials.ts) now loads `gc_customer_id`, `bill_to_party`, the GC's name and the invoices' `bill_to_party` / `bill_to_email`). The Bridge's cash forecast reads the same AR items.
- **Lean rows** (`LEAN_STATS_JOB_COLUMNS` / `LEAN_STATS_INVOICE_COLUMNS`): the who-pays columns, so the overview card's Call mode count groups like the window.
- **Edge**: [`_shared/moneyWaitingCore.ts`](../../supabase/functions/_shared/moneyWaitingCore.ts) `moneyWaitingRowPayer` (the payload's `payer_id` / `payer_name`, else the job customer).
- Guides *chase late payments with call mode* and *drill into the dashboard money cards*.
