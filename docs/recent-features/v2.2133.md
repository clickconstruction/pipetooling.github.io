# v2.2133 — GC statement footer: office number from Settings; preview blurb removed (2026-08-22)

Owner requests (same review as v2.2131): the footer "Questions about a bill? Reply to this email or call the office." should name the office number from Settings, and the dialog's "Statement preview — 1 job, $1,500.00 · job addresses… Sent from team@noreply…" paragraph was useless.

- **Footer** — new [`gcStatementFooterLine(officePhone)`](../../src/lib/jobsDocuments/gcStatementEmail.ts): "…call the office at <phone>." when a number is configured, else the unchanged bare line. The number is the invoice issuer's `phone` (`app_settings.physical_invoice_issuer_v1`, Settings → Company → invoice issuer) — the one customer-facing office number the app already has. Every builder takes `officePhone` via the new `GcStatementEmailOpts` (per-GC HTML/text, Share-all HTML/text, Preview). Call sites: [`JobsGcReviewModal`](../../src/components/jobs/JobsGcReviewModal.tsx) (Send now, Preview ×2, Share all) and [`JobsStagesTab`](../../src/components/jobs/JobsStagesTab.tsx) (Copy for email) read `getPhysicalInvoiceIssuerForDocument().phone` synchronously at click time; GC Review hydrates the issuer session cache on open (`fetchPhysicalInvoiceIssuerFromAppSettings`).
- **Dispatcher mirror** — [`gc-statement-email-dispatch`](../../supabase/functions/gc-statement-email-dispatch/index.ts) reads the issuer row once per run and passes `officePhone` into the four `render.ts` builders (same `gcStatementFooterLine`). **Needs `supabase functions deploy gc-statement-email-dispatch --no-verify-jwt`** (together with the v2.2131 subject change).
- **Dialog** — the "Statement preview — …" box under the When controls is removed; Preview (v2.2061) already shows the exact email.
- Tests: `gcStatementEmail.test.ts` (footer with/without number, HTML + text). Help: `track-a-general-contractor-on-a-job.md`; `docs/EDGE_FUNCTIONS.md` section.

Client + edge function; no migration.
