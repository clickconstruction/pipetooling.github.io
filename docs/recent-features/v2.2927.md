# v2.2927 — Jobs → Subs: Work Orders and Sub Labor fold into one tab; stages get a window (2026-09-06)

PR 1 of the three-party scheduling train (prototype: artifact 3a540149 — GC windows, sub self-scheduling, percent complete, dispatch lanes, watchers, the dispatch inbox). The owner's decision that shaped this PR: the stage table does not belong on the Bill tab (the Edit Job line-item grid is a form that saves on close; windows and offers are actions with side effects), so it lives on a **Subs** tab that folds Work Orders and Sub Labor together — the same sub sheets seen two ways.

## The Subs tab (`src/components/jobs/JobsSubsTab.tsx`)

`Jobs.tsx` has one tab `subs` where `work_orders` and `sub_sheet_ledger` were. A Work / Pay segmented control (`?view=pay`) chooses between:

- **Work** — [`JobsSubsWorkView.tsx`](../../src/components/jobs/JobsSubsWorkView.tsx) (git-moved from `JobsWorkOrdersTab.tsx`; every action — nudge, withdraw, signed on paper, print, discard, link to a job — is unchanged).
- **Pay** — `JobsSubLaborTab` mounted as it was (the v2.2922 pay run).

`subsViewFromParam(param, canSeeWork)`: superintendents see Pay only and no control (they saw Sub Labor but never Work Orders). `SUBS_TAB_ALIASES` in `Jobs.tsx` rewrites `?tab=work_orders` → `subs`, `?tab=sub_sheet_ledger` / `?tab=labor` → `subs&view=pay` with `replace: true`, so dashboard pins (their stored identity is still `sub_sheet_ledger`), Needs You, the person desk, the step panel, Quickfill cleanup and the Edit Job labor panel all land. `jobsListLoadGate` lists `subs`. `JobsSubLaborFormModal.setActiveTab` takes `'subs'`.

## Stages and windows

- Migration [`20260906040000_job_stage_windows.sql`](../migrations/20260906040000_job_stage_windows.md): `job_stage_windows` (job × line item, `window_start/end`, `window_by`) + `step_commitments.stage_window_id`.
- Kernel [`src/lib/subs/stageWindow.ts`](../../src/lib/subs/stageWindow.ts) (+test): `stageWindowProblem`, `stageWindowWeekdays`, `dayInStageWindow`, `stageWindowLabel` ("Sep 8 – Sep 19"), `stageWindowByLabel`, `stageWindowPhase` (past / open / ahead), `nextWeekdayOnOrAfter`, `endAfterWeekdays`, `defaultStageWindow` (next weekday, ten weekdays wide).
- Kernel [`src/lib/subs/subsTabRows.ts`](../../src/lib/subs/subsTabRows.ts) (+test): `buildSubsTabGroups({ board, windows, windowIdByCommitmentId, fixtures, jobs })` regroups the Work Orders board rows **by job**, adds a **stage row** for every window no order has claimed, rides a claimed window on its order's sheet row (`stage`, `window`, `span`), orders stage rows above sheet rows (then by rail position), lists each job's `freeFixtures` (line items not yet read as stages), sorts groups by attention then newest job number with unlinked orders last, and counts `stagesOpen / sheetsWithoutWindow / offersOut / signed`. `subsGroupMatches` searches job, sub, stage and WO number. `fixtureAmount` = count × unit price.
- UI: job group headers with **+ Add a stage…**; the inline [`StageWindowEditor`](../../src/components/jobs/StageWindowEditor.tsx) (line-item select unless the row already names one, two date inputs, `stageWindowProblem` inline); a **Window** column (green chip, "set by the office", **Change**; grey "· passed" once the window is behind); **Set a window…** on sheet rows (upserts on `job_id,fixture_id`, stamps the row's order with `stage_window_id`, and copies the span onto `proposed_start/end` when the order had no dates); **Draft a work order…** on stage rows opens the assembler with `stageWindowId`, `proposedStart/End` and the line-item amount; **Remove** clears the window. Tiles: On a handshake · **Stages waiting** (new) · Offers out · Signed this month. Filter chips keep the rail groups; stage rows show under All. The `job_stage_windows` fetch is non-fatal so the board paints before the migration is applied.
- Assembler ([`WorkOrderAssemblerModal.tsx`](../../src/components/jobs/WorkOrderAssemblerModal.tsx)): `WorkOrderAssemblerInitial` gains `stageWindowId`, `proposedStart`, `proposedEnd`; a **Stage** select (the job's windows, loaded when the job is known) prefills the dates and, when the price is blank, the amount; `persist` writes `stage_window_id`.
