# v2.3645 — MCP servers, PR 4b-2a: the job parts-cost math lifts into `_shared` (2026-09-20)

First half of PR 4b-2 of [`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md). `dev-mcp`'s `get_job` must report the profit the Job window shows. Revenue minus parts minus sub labor is already a shared kernel (`jobProfitSummary`, v2.3638); the **parts** side was not — `fetchJobMaterialsCostSnapshot.ts` interleaved four Supabase reads with the arithmetic that turns their rows into lines. This PR separates the two. No behaviour change.

## The change

- **`_shared/jobMaterialsCostLines.ts`** (new): the line types and totals lifted verbatim from the fetcher (`JobSupplyInvoiceLine`, `JobMercuryAllocLine`, `JobTallyPartLine`, `JobMaterialsCostSnapshot`, `jobAccountSplitFromLines`, `mercuryCardTotalFromLines`, `tallyPartsTotalFromLines`), plus the four mappers that were inline loops: `supplyInvoiceTotalFromRows`, `supplyLinesFromRows` (pct allocation, array-embed unwrap, orphan allocation skipped), `mercuryLinesFromRows` (card id out of the bank transaction's raw JSON), `tallyLinesFromRows` (this job only; a part at price-at-time, a bare fixture at its cost). +4 tests.
- **`fetchJobMaterialsCostSnapshot.ts`**: the same four reads, each handed to its mapper; re-exports the types and totals, so its 12 importers do not change. Its existing test passes with one edit — the `mercuryRawDebitCard` stub now targets the shared module, because that is the module the code imports.
- **`cardChargeAllocationFilter.ts`** and **`mercuryRawDebitCard.ts`** move to `_shared` with `export *` stubs at the old paths (18 and 29 importers untouched), as PR 4a did. `mercuryDebitCardIdFromRaw` takes `unknown` instead of the generated `Json` type — a shared kernel cannot import from `src/types`, and every `Json` is an `unknown`.

Nothing imports these from an edge function yet, so nothing deploys.
