# v2.6014 — Job Mode names the job's number when the number is a Click number (2026-10-28)

Punch list #197. The live press run of #189 on 2026-10-27 filed a Turnaway from the Job Mode card on the ZZ test job, a job numbered in `click_number`; the dispatch request reached the inbox titled *Turnaway: — <job name> — Site not ready*, and the Leave report window's heading showed the same dash, while the card's header above them read the number. The card built its target with `hcp_number` alone.

## What changed

- **The card's target** ([`DashboardJobModeCard.tsx`](../../src/components/jobMode/DashboardJobModeCard.tsx) → `leaveReportTarget`): `hcpNumber` is `effectiveJobLedgerNumber(hcp_number, click_number) || '—'` in both places it is built, the current block and an off-schedule job. That is the choice the card's header (`jobNumberLabel`) and `search_jobs_for_reports` (`COALESCE(hcp_number, click_number)`) already make. Leave report, Turnaway and the % done stepper's saved toast read the number with no change of their own, and `buildTurnawayDispatchTitle` puts it at the head of the dispatch title.
- **Read and left**: `DashboardSupervisorSection`'s Leave report takes its row's number from `buildSupervisedView` (`supervisedDays.ts`), which already falls back to `click_number`.
- **Test** ([`DashboardJobModeCard.pressBar.render.test.tsx`](../../src/components/jobMode/DashboardJobModeCard.pressBar.render.test.tsx), +1): clocked in on a Click-numbered block, Leave report and Turnaway hand the Dashboard's windows that number; clocked in on a block with neither number, the target reads a dash. The test fails on the old card.

The client deploys with the merge. Nothing else.
