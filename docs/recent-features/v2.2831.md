# v2.2831 — Job Summary: Rework view (2026-09-05)

PR 9 of the Job Summary analysis plan (artifact 9c02d29a), stacked on v2.2830 (Ahead). Read-only for now — the "not rework" mark (the plan's one migration) is the follow-up.

## Client only — no migration

- [`jobSummaryRework.ts`](../../src/lib/jobs/jobSummaryRework.ts) (new kernel): `reworkAddressKey(job)` (`customer_address_id`, else normalized street text with suite/unit words dropped; null when too short to trust); `findReworkPairs(rows, ledger, windowDays)` — jobs grouped by address key, each later job pairs with the nearest earlier one whose done date (first invoice `billed_at`, else paid, else last field day) precedes its start (ledger first field day, else `created_at`) by ≤ N days; the pair carries `returnCostUsd` (labor + subs + parts + overhead share of the return) and `returnRevenueUsd`. `reworkRateBy(pairs, rows, tech | trade | gc, ctx)` credits each return to the FIRST job's group ÷ that group's finished jobs. `summarizeRework`. Each pair carries `kind: 'callback' | 'repeat'` (the return billed nothing vs has its own revenue) and `filterReworkPairs(pairs, 'callbacks' | 'all')` — the view counts callbacks by default (on real data "all" reads 43% because commercial sites repeat). `REWORK_WINDOW_OPTIONS` (30 / 90 / 180), `REWORK_RATE_BY_OPTIONS`, `REWORK_COUNT_OPTIONS`. Three tests.
- [`jobSummaryLedgerView.ts`](../../src/lib/jobs/jobSummaryLedgerView.ts): `JobSummaryLedgerRowInput.job` grows optional `customer_address_id` / `job_address`; view mode `'rework'`.
- [`JobSummaryReworkView.tsx`](../../src/components/jobs/JobSummaryReworkView.tsx) (new): Rate by + Window chips (local state); tiles (rate, cost of going back, worst group, can't-place count); ranked rate bars with the company dashed line (groups with ≥ 2 finished jobs); the pairs table (first → return, days after, cost or address) with each job a door to the Jobs view. Runs on `allRows` — the first job may predate the window.
