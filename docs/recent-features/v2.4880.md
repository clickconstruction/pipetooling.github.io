# v2.4880 — Bill Customer: saving a missing email no longer wipes the bill (2026-10-07)

Client only. Found on punch list #94's close-out walk (2026-10-07): Bill Customer on a job with no customer email → type one in the yellow *No customer email on this job* box → **Save** → **Create Stripe invoice** answered *Enter a valid bill amount greater than 0*. Live since f5aeaed23 (April).

## Why

`SendRecordInvoiceModal`'s open-time reset effect was keyed on `job?.customer_email`, and `job` is the payload with the banner's saved email laid over it (`emailOverride`, v2.936). The save changed that key, so the reset ran: it cleared `emailOverride` (the banner came back) and set `billAmountStr` to `''`. The effect that fills the amount from the plan is keyed on the plan, which had not changed, so nothing refilled it. The same reset also threw away the memo, the footer and the tab.

## Fix

The reset is keyed on `open`, `job?.id` and `invoice?.id` only. The Stripe preview effect keeps the email in its own keys, so the preview still follows a new address.

## Tests

- `SendRecordInvoiceModal.render.test.tsx` +1: opened on a job with no email, the banner's Save writes `jobs_ledger`, the banner stays gone, and Create Stripe invoice gets past the amount and email checks (the stub's missing session is the first stop). Fails on the old keys.
- Walked live on ZZ TEST J1072 (a $1 Stripe test bill): saved the email, Create Stripe invoice went out on the first press; the bill was then marked paid.
