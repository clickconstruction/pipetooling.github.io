# v2.7492 — Print future stickers: the Which job? window says what a run would add to (2026-11-16)

Punch list #304 and #329. The fifth of the owner's calls on the mock-up [`to-dos/materials-one-story/print-labels-which-job.html`](../../to-dos/materials-one-story/print-labels-which-job.html): the *Which job?* window of **Print future stickers** is a twin of Print labels' and takes the same cards (v2.7482). His word the same day, *Yes, after rename*: built on top of the rename to **Print future stickers** (v2.7484, v2.7486, v2.7487), whose words and kernels it reads. Client only: no migration, no edge function.

## What changed

- **The band.** Stickers print on tape alone, so it says the tape and its width, the P-touch's own line where the browser already has leave to use it (the same quiet connect as Print labels), the preview's sentence (*Each sticker gets its own link when it prints. XXXX-XXXX stands in for it here.*) and one sticker at its printed size through the preview's own `previewStrip`: the name the first job's next run opens on, or a sticker with no name until that is read. A browser with no USB reach gets the amber note here.
- **A job is a card** (`stickerJobFacts` in [`reserveStickersJobs.ts`](../../src/lib/materials/reserveStickersJobs.ts)): the number and the name apart, the site and the street, its boxes as a count or *no box yet*, the kinds and the names when it has any.
- **The runs so far** (`runsSoFar`, `runsSoFarWords`): *2 runs so far · 223 stickers · 114 on boxes · 3 lost*, or *A run here would be this job's first.*
- **What is reserved**, in v2.7487's own words (`reservedOfJob`, `notYetOnBoxWords`, `reservedByWords`): *109 stickers reserved and not on a box yet, G92 to G200. Printed Nov 16 by Dana.* A job with stickers waiting comes first and has a second door, **Open the job's boxes**, to the job's page on the On site tab, where **These are on boxes** and the Runs fold are.
- **The name a new run opens on** (`nextNameToReserve` over the site's boxes and reserved names): *A new run opens on G201.* Left out when the site has no name to go by.
- **A job that did not load** says so on its card with **Read again**. It was listed as *no box yet*.
- **The foot**: *Boxes that are already in the app?* with **Print labels**, **Scan a label** and the guide.
- **Shared pieces.** The card's head, the looks of the presses, the strip at its printed size, the no-USB note and the quiet printer link moved out of `PrintLabelsWindow.tsx` into [`WhichJobParts.tsx`](../../src/components/materials/WhichJobParts.tsx); both windows draw from it.

## The reads

When the question opens, each under the viewer's own RLS and each optional ([`reserveStickersIo.ts`](../../src/lib/materials/reserveStickersIo.ts)): every listed job's runs with their stickers in two reads (`fetchStickerRunsOfJobs`), and each job's site with the site's boxes and reserved names, read once a site through `fetchSiteStickerNames` (`fetchSitesOfJobs`). A read that fails leaves its lines off the cards; the stickers window a card opens reads the same things again for its one job, and its own hold on a second run over reserved names stands.

## Not built

- The phone's On site tab has no press for this window.
