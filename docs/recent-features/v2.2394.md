# v2.2394 — Body scroll-lock watchdog: leaked locks self-heal (2026-08-27)

Wendi hit "can not scroll down" twice (Bids page, Followup page), fixed only by
refresh. That is the app-wide body scroll lock (v2.2186,
`BodyScrollLockSentinel`) left held after its blocking overlay was gone — the
same failure family as the v2.2357 hidden-tab rAF leak: the release depends on
a MutationObserver-triggered recompute, and any path where the overlay leaves
without a mutation the observer sees (or without a frame firing) strands the
lock until reload.

`BodyScrollLockSentinel.tsx` — two self-healing layers, both active only while
the lock is held:

- **Watchdog interval** (`SCROLL_LOCK_WATCHDOG_MS` = 3s): while locked,
  re-run the overlay check every few seconds regardless of mutations. A
  stranded lock now clears within seconds instead of never.
- **Scroll-intent heal**: `wheel` / `touchmove` / `keydown` listeners (passive)
  schedule a recompute when the lock is held — the exact gesture that hits the
  freeze verifies the overlay and releases immediately if it's gone.

Genuinely-open modals are unaffected: the recompute finds the overlay and the
lock stands. The recompute is the existing cheap rect-check; listeners no-op
when unlocked. Root cause of the specific leak on those two pages remains
unidentified — this makes the whole class self-healing.
