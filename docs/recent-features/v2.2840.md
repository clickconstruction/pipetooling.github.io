# v2.2840 — A paid progress bill no longer marks a job 100% done (2026-09-05)

Journey-map Tier-1 #5(a) (J6 finding #2, drift **WORSE** in `_DRIFT-2` row #5). The Job Summary "%" fallback chain put **paid invoices → 100** ahead of the crew report and the office %, with no check that the invoiced total had anything to do with the contract. On commercial progress billing that is a lie: **J523** (Working, crew active) has one invoice $81,916.60 `paid` = 66 % of a $123,600 contract, latest crew report 77, office `pct_complete` 63 — the row read **100 %**. Census at verification: **17 live jobs** with every invoice paid but invoiced < revenue, **12 of them active**. Since v2.2692 the same override also decides `finished` in `jobSummaryLedgerView.ts`, which picks the default **Finished (100%)** filter and switches Revenue from earned (contract × %) to the **full contract** — so the false 100 flowed into Months (v2.2821), Scatter (v2.2826), Cycle (v2.2823), Ahead, Cut-by subtotals (v2.2820), Compare deltas + target flags (v2.2817) and the `jobs-stale-open` Dashboard card (v2.2825).

## The chain

| | before | after (v2.2840) |
|---|---|---|
| 1 | every invoice `paid` ∧ Σ paid > 0 → **100** | every invoice `paid` ∧ Σ paid > 0 **∧ Σ invoices ≥ revenue − tol** → **100** (`source: 'paid-invoices'`) |
| 2 | latest report % (0–100) | latest report % (`'crew-report'`) |
| 3 | `jobs_ledger.pct_complete` (0–100) | `pct_complete` (`'office'`) |
| 4 | null → "—" | null (`'none'`) |

Tolerance `tol = max($1, 0.5 % × revenue)` (`PAID_INVOICES_COVERAGE_TOLERANCE_USD` / `_PCT`) — cents of line rounding and small retainage / discount write-downs on a fully billed job still count as covered. **Revenue null / $0 → covered** (nothing to compare against): a job with no Total Bill and a paid invoice keeps reading 100, which is exactly the shape the Quickfill "Complete, no Total Bill" section lists so the office sets the Job Total. Single-invoice service jobs where invoiced == revenue still read 100.
