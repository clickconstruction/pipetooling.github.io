# v2.4497 — Submittals: a step pill keeps its grey outline when it goes back to grey (2026-10-04)

Noted in the tab review's under-the-hood paragraph ([`to-dos/submittals/tab-review-before-after.html`](../../to-dos/submittals/tab-review-before-after.html)) as a React console warning on the journey strip. The owner, 2026-10-04: "Do the pill border and the review page now". Client only.

## What was wrong

[`SubmittalJourneyStrip`](../../src/components/bids/SubmittalJourneyStrip.tsx) set each pill's outline with the `border` shorthand and a lit pill's colour with `borderColor`. When a pill went from lit back to grey (a different revision selected, a bid with no revision yet), React removed `borderColor` and left the shorthand in place, which clears the colour the shorthand had set: the outline fell back to the text colour. React said so in the console (*Removing a style property during rerender (borderColor) when a conflicting property is set (border)*). The number badge inside the pill and the strip's buttons mixed the two the same way.

The new test showed it was more than a warning: after a lit-to-grey rerender the pill's `border-color` read blank.

## What changed

`pillBase`, `numBase` and `btn` set `borderWidth`, `borderStyle` and `borderColor` separately, so a lit state overrides one longhand and going back to grey restores it. The same rule the repo already notes for `border` + `borderLeft`.

## Tests

`SubmittalJourneyStrip.render.test.tsx` (+1): a strip with pill 3 lit, rerendered for a bid with no revision — pill 3 reads `later`, its border colour is the grey token, and no *conflicting property* warning is logged. It failed before the change (`border-color` blank).

## Walked live

Worktree dev server against prod, read only, BP398: four switches between Rev 4, Rev 3 and Rev 2 logged no such warning, and every grey pill computed the grey outline.
