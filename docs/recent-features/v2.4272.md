# v2.4272 — The bid list on the workflow tabs is grouped the way the Bid Board is (2026-09-30)

Grace, 2026-09-30, with a screenshot of the Cover Letter tab's flat list of bids: "On the bid board bids are separated by stages … when a user looks at the list like the image I shared I would like it to show up separated by Unsent / Working Bids (15), Not yet won or lost (93), Won (15), Started or Complete (25), Lost (126)." The picker had rendered one flat list in the user's sort order since the standard-row sweep (v2.4034), so a Lost bid from August sat between two bids due next week. Client only; no migration, no edge function. Mock-up: https://claude.ai/artifact/H545taLjmBzxSQ8upLiuDM (the grouped list with a live fold and search, and the "is this the best we can do" pass under it).

## What shipped

- **One kernel, the board's rule** — `src/lib/bidPickerGroups.ts`: `bidPickerGroupKey(bid)` is `getSubmissionSectionKey` (the Bid Board's bucketing, `bidSentCounts.ts` rule 3) plus the one thing the board does in its render: an unsent bid with `working_board_archived_at` leaves Unsent / Working for a trailing `archived` group, named as the board's Archived window names it (*Archived (Unsent/Working)*). `groupBidsForPicker(bids, view)` returns the groups in board order, empty ones dropped, rows sorted by the picker sort view inside each (`compareBidsForPicker`), so the headings never move. `BID_PICKER_GROUPS` carries the labels; `isBidPickerGroupFolded` / `normalizeBidPickerFolds` hold the fold rule (Lost and Archived folded until a choice is stored). Twelve kernel tests.
- **The shared list draws the groups** — `BidPickerStandardList.tsx` (the one component all nine tabs render through) now maps `groupBidsForPicker` to a `<section>` per group: a heading button (`aria-expanded`, `aria-controls`, the count in tabular figures, a ▶/▼ mark) over the rows. The folds are a module store synced to `localStorage` `bidPickerFolds` — the same shape as the sort view's store in `BidPickerSortToggle.tsx` — so one press on Counts folds Lost on every tab and survives a reload. The row itself, the Counts tab's tally column and `onSelectBid` are unchanged.
- **Searching opens everything** — a new `searching` prop (the nine tabs pass `query.trim() !== ''`): every group is open, the fold marks and the heading's press are off, and the host's own filter has already dropped the empty groups, so a match is never behind a fold. Clearing the box restores the stored folds.
- Six render cases in `BidPickerStandardList.render.test.tsx`; the guide *find a bid on the workflow tabs* gains a "Grouped by stage" section.

## The "is this the best we can do" pass — what changed from the first draft

- The first draft folded Lost and left it folded while searching; a search for a lost bid would have shown its heading with a count and no rows. Searching now opens every group.
- Archived bids had been going to fall into Unsent / Working (the picker showed them there before this change, mixed in). The board hides them from that pile, so the picker gives them their own folded group under the board's own name instead of hiding them — the tabs are where an archived bid is still opened and priced.
- Jump pills like the board's (Unsent · Pending · Won · …) were considered and left out: the headings scan in one glance at this list's size, and a second row of buttons would crowd the search row.

## Walked live (dev, 2026-09-30, Plumbing pill)

Cover Letter with *Only my bids* off read Unsent / Working Bids (68) · Not yet won or lost (93) · Won (15) · Started or Complete (25) · Lost (126) · Archived (Unsent/Working) (28). Every count but the first matches the Bid Board of the same minute; Unsent reads 68 against the board's 15 because the picker's rows are the tab's own (it has always listed the 53 robot shadow bids, *ZZ Shadow …*, beside the 15 human ones — the board draws those as robot overlays instead). Pressing Lost opened its 126 rows and wrote `{"lost":false}` to storage; a search for "patagonia" on Counts showed one open group of two rows with their tallies (15 and 10) and no fold marks.
