# v2.2874 — GC statements: no statement for $0; every statement says how to pay; preview matches what is sent (2026-09-05)

Journey-map **Tier-2 #46** (dossier J20 "GC gets a statement", findings F4 · F8 · F9 + the preview-parity note), shipped as one PR because the statement has three hand-mirrored builders that must move together.

## What was wrong

- **F4 — the $0 send trap.** A certified $0.00 GC group's **Draft Message** opened with the GC's real address prefilled, the subject filled, and **Send statement enabled** — the only disables were `emailSending` and the To-field regex. One click emailed a real GC "Total owed $0.00" under the company's name. The nothing-outstanding skip lived only in the scheduled dispatcher (`skipped: nothing outstanding`).
- **F9 — the statement never said how to pay.** The portal card read "This statement stays current at …"; the office-side Share tooltip promised "their live statement with Pay online", but that promise never reached the GC's copy. AP clerks replied asking how to pay, or filed it.
- **Preview ≠ paste.** The round overlay's **Preview statement** omitted the portal card that **Copy for email** (and the Draft Message send) included.
- **F8 — duplicate name.** A job with no address printed its name twice ("Water Heater / Water Heater"): the main line fell back to the job name and the sub-line repeated it.
- v2.2660 made only the scheduled lane's subject + intro editable (Settings → Email templates → GC statement); Draft Message ignored the template, so the two app-sent lanes could drift in wording.

## What changed

**Send guard kernel** — `src/lib/gcStatementSendGuard.ts` (`gcStatementSendGuard({ totalOwedCents, emailSending, hasAddress, scheduled })` → `{ canSend, blockedBy, message }`). Order: in-flight → nothing owed → no address. The Draft Message dialog computes it once (`emailSendGuard`) and uses it for the button's `disabled`/`title`/dimming and a `role="status"` line above the buttons: **"Nothing owed — no statement goes out."** `scheduled: true` exempts the $0 rule — the dispatcher rebuilds fresh at send time and skips empties itself, so a weekly chain may still be set up for a GC at $0 today. `dollarsToCents` bridges the rollup's dollar `subtotal`.

**Pay line, one copy in every lane** — the portal card's second line is now `Pay online any time at <a href="<portal>?src=gc-statement">my.clickplumbing.com/<slug></a> — this statement stays current there.`; plain text: `Pay online any time at <portal>?src=gc-statement — this statement stays current there.` Client `gcStatementPortalCardHtml` / `gcStatementPayLineText` (renamed from `gcStatementPortalLineText`) and the dispatcher's `portalCardHtml` / `payLineText` are mirrors. No portal → no pay line; the footer's reply-or-call sentence stands.

**Telemetry** — the app has no click-redirect pattern for email links, so the pay link carries `?src=gc-statement` (`GC_STATEMENT_PAY_LINK_SRC`, `gcStatementPayUrl` / `payUrl` — appends with `&` when the URL already has a query, e.g. token links). The portal ignores unknown query keys; #37's view counter can attribute a statement click from it. No migration.

**Editable wording now covers Draft Message** — `openEmailDialogForGroup` resolves `resolveEmailWording('gc_statement_scheduled', { date, default_subject }, …)`; when a template row exists its subject prefills (only while the person hasn't edited the field) and its body becomes `emailIntroText`, passed as `introText` into the HTML/text builders for Preview and Send. The builders (client + dispatcher) now take `introText` and render it *inside* the statement `<div>` as a styled `<p>` (escaped, `\n` → `<br>`); the dispatcher previously prepended the raw intro outside the styled block. `emailCatalog` row `gc_statement_manual` → editable via the same template; Settings label reads "GC statement (Draft Message + scheduled)".

**Preview parity** — the round overlay's Preview passes `portalUrl: portalLinkFor(group)?.url` (and `groupBy: 'gc'`), matching Copy for email. The Draft Message dialog's Preview and Send both pass the intro.

**Duplicate-name fix** — `gcStatementRowLabel(address, name, number)` (client) / `rowLabel(row)` (dispatcher): the lead is address → name → "—"; the sub-line shows `Job <n>` and the name only when the name isn't already the lead; a number of `—`/blank drops `Job —`. Used by every row renderer (per-GC HTML/text, Share-all HTML/text) in both files.
