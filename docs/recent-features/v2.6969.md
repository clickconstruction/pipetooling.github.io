# v2.6969 — Corrections as links: `person_file_amendments`, the database half (2026-11-11)

Punch list #315, upgrade 1, PR 1. The owner's go for the whole train, 2026-11-11: *"Build it all and let me know when it is live. Asking yourself along the way is this the best we can do."*

## What was wrong

A correcting entry named the entry it corrected only in its words. The older entry never read as corrected, a search hit on it gave no sign, and a document that cited it was not flagged.

## What changed

- **`person_file_amendments`** (migration `20261112050000`): one row says a thing on a person's file, an HR entry or a piece of evidence, corrects or completes an older one. Insert-only; a wrong link is withdrawn with a reason. Its guard holds both ends to the one person and refuses a link from what was written first, back along a live one, or twice. Dev-only, the four fences; the dev seat is refused a link that touches a counsel-only record. Page: [`docs/migrations/20261112050000_person_file_amendments.md`](../migrations/20261112050000_person_file_amendments.md).
- **Is this the best we can do?** The card planned a nullable reference on `person_file_entries`. A table does more and touches less: no existing row or table changes, one correction can name several things, evidence records are covered, and the corrections already written in prose can be linked by adding rows instead of stamping entries. The card is amended.
- **`hr_agent_write`** learns `entries[].corrects`, `entries[].completes`, `amendments[]` and `withdraw_amendments[]`; a payload with none answers as before. **`dev_hr_entry_write`** names each link by its two ends in words that are the same on every run, so the seat's plan and apply hash alike. `plan_hr_entry` hands its payload over whole, so the seat writes a link once the migration is pushed, with no deploy.
- **Kernel** `supabase/functions/_shared/personAmendments.ts` (door `src/lib/people/personAmendments.ts`, 16 tests): the live links, both ends indexed, where a thing stands (corrected before completed), the latest word along a chain of corrections, the words either line wears, the payload keys and the tab's rows.
- **Docs**: `HR_FILES.md` (the layer, the convention, the RPC's keys), `ACCESS_CONTROL.md`, `GLOSSARY.md`, `dev-mcp/README.md`, the card.
