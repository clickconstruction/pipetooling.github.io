# v2.7251 — Two receipt tests no longer fail just after midnight (2026-11-14)

Test only. `src/components/tickets/ReceiptStateTables.render.test.tsx` and `src/components/tally/TallyTeamQueue.render.test.tsx` failed on every run whose test step fell between 00:00 and 01:00 Central. Nothing in the app changed.

## What broke

Each test stamps a receipt text one hour before now (`hoursAgo(1)`, and `Date.now() - 60 * 60 * 1000`) and expected the chip to read `Texted 11:03 PM`, a time with no day. Inside the first hour after midnight that text is from the day before, so the chip rightly reads `Texted Fri 11:03 PM`, and both tests failed:

> expected 'Texted Fri 11:03 PM' to match /^Texted \d{1,2}:\d{2} [AP]M$/

On 2026-11-14 this failed the merge queue's builds between 06:00 and 07:00 UTC: #8076's own build, and the builds of #8085 and #8086 behind it. The queue took them out for failed checks, though none of them touches receipts.

## The change

Both assertions accept the weekday the chip draws for an earlier day: `/^Texted (?:[A-Z][a-z]{2} )?\d{1,2}:\d{2} [AP]M$/`, with a line saying why. The rest of each test is unchanged, and the chip's own words are not touched.

## Verified

- Both files failed on main at 00:32 Central with the same error as the queue's builds.
- With the change, both pass (20 tests) at 00:32 Central and again with `TZ=UTC`.
