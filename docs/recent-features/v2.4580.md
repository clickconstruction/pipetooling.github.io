# v2.4580 — Accounts Receivable: a new check closes the returned one only when it pays the same job (2026-10-05)

Client only; no migration, no edge function. A hazard found re-reading the Accounts Receivable map (PR #4556).

## The defect

`fillReplacementLines` in [`BankPaymentsModal.tsx`](../../src/components/jobs/BankPaymentsModal.tsx) set `replacingRef` on every press of **Use it as the new check** / **Fill in the bills it paid**, even when no allocation line filled (the bills the returned check paid were no longer open). The flag was cleared only when another deposit was selected. `submitApply` then called `close_ar_return_case` with `replaced` on the next successful apply for that deposit, whatever bills the lines named by then. A deposit applied to an unrelated job closed the case and was recorded as its replacement.

## The rule

- **Kernel** [`arReturnCase.ts`](../../src/lib/jobs/arReturnCase.ts): `arApplyClosesReplacedCase(billsItPaid, appliedJobIds)`. A case with bills on record closes only when the apply pays a job one of those bills was on. A case with no bills on record has nothing to compare, so the press alone decides (the button reads *Use it as the new check* there).
- **The flag** is set only when lines filled, or the case has no bills on record. When the case has bills and none is open, nothing fills, the flag is cleared and a toast says *The bills it paid are not open now. Pick the bill yourself.*
- **At apply** `submitApply` collects the job of every line it sends (billed lines and recorded payments) and asks the kernel. Lines edited away from the case's jobs leave the case open in Came back; the apply itself is unchanged.

The match is by job, not by bill: a new check that pays a different bill of the same job still replaces the old one.

## Tests

- `arReturnCase.test.ts`: the three branches of the kernel.
- `BankPaymentsModal.replacedCase.render.test.tsx`: the bills are not open, nothing fills, an apply to another job sends no `close_ar_return_case`. It fails against the old code.
- `BankPaymentsModal.returnCases.render.test.tsx` still holds the path where the bill fills and the case closes.
