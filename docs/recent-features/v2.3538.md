# v2.3538 — Stages tab decomposition, PR 8: the six section tables share one props object (2026-09-16)

Client only, behavior-preserving. PR 8 of the train in `to-dos/engineering-hygiene.md` — the **prop-bundle seam** from region 4 of [`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md), the wide mechanical diff the map said to land alone.

## What changed

The six section call sites in `JobsStagesTab.tsx` (Waiting, Working, Ready to Bill, Billed Awaiting Payment, Collections, Paid in Full) each repeated the same fifty-odd pass-through props — the mutation engine's ids and callbacks, the thread-notes cluster, the man-hours maps, the openers, the role gates — about 650 lines of the file that said nothing per section. The follow-ups deck (v2.1740) had already solved this for its own five row renders with a `shared` object it spread into each. That object, and its `unifiedShared` extension for the job-plus-invoice tables, are now built once at tab scope as **`stagesTableShared`** and **`stagesUnifiedTableShared`**, and every section site reads `{...stagesTableShared}` (or the unified one) followed by only what is genuinely its own: the rows, the action labels and handlers, the section flags, the send-back wiring, the report pill.

The script that did it checked each dropped line against the shared object's entry for that name and dropped it only when the expression was identical; **zero site-specific overrides were found**, which is the fact that makes this a pure move. Two entries that looked different were the same thing: `openJobCalendar={setCalendarJob}` (the object already maps it that way) and the section IIFE's `toggleStagesJobThreadExpanded` function, whose body is the same one-liner the shared object carries, so the function is gone.

**The tables are untouched.** `JobsStagesTable`, `JobsStagesUnifiedTable` and the two card lists keep their props types and render tests exactly as they were; the spread satisfies the same contract the fifty explicit props did. Folding the shared set into a single typed prop on the table side (the map's "superset of `StagesRowRenderContext`" idea) is a table-side change and belongs with the row dedupe in PRs 9–10.

Numbers: `JobsStagesTab.tsx` 5,217 → 4861 lines. The whole train so far: **6,598 → 4861**.
