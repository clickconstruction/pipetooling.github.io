# v2.3497 — The to-dos get one source and two generated views (2026-09-16)

Tooling + docs. One new kernel, one new script, one new CI step in both workflows, front matter added to all 35 to-dos, and both views regenerated. No migration, no edge function, no user-facing surface.

## Why

The owner asked whether hand-off work should be saved to the punch list instead of the to-dos, and then, after the trade-offs, asked for the third option: **one place to write, with the views following automatically.**

The drift that prompted it, measured against `main` at v2.3487 on 2026-09-16:

| Surface | Drift found |
|---|---|
| `to-dos/punch-list.html` | **three to-dos had no row at all** — `frozen-bid-prices`, `bid-board-job-accounts`, `texas-lien-rules-in-the-app`, all written in the previous two days |
| `to-dos/README.md` | four status cells described work that had already shipped |
| a to-do vs the index | `gc-on-notice` read **built** in its folder and **not started** in the index |
| a board row's `ver` | cited **v2.3478** for the GC cover letter, which shipped as v2.3482 |

The cause was structural, not carelessness: **the same fact had three homes** — a to-do's `Status:` line, the index's Status cell, and the board's row — and all three were kept by hand. A drift check over three copies is a band-aid. This removes two of them.

## Why not "move the to-dos into the board"

Recorded because it was seriously considered. The to-do folders hold **824 KB**; the board holds **37 KB**. The other 96% is fourteen mock-up pages, a forensic drift report, and long plans with tables and links — none of which fits in a JavaScript string. And `to-dos/` took **139 commits in 14 days** from parallel sessions; one shared HTML file rebuilds exactly the conflict that the release-notes aggregator and the `RECENT_FEATURES.md` changelog were split up to solve.

## The rule

Stated once, in the kernel header and in `to-dos/README.md` → *One source, two views*:

- **each to-do owns its triage fields in front matter** (`name`, `group`, `status`, `summary`, `next`, `size`, `blocker`, `ver`, optional `pointer`);
- **`to-dos/README.md`'s index block is rendered from it**, between `<!-- BEGIN GENERATED INDEX -->` markers;
- **`to-dos/punch-list.html`'s `ITEMS` array and stamp are rendered from it.**

Everything else stays prose in the file: the ask in the owner's words, the decision, the mock-up, where it plugs in, the PR train, the verify recipe, and a `## Where it stands` section where the state needs more than a line. Only the triage fields are structured.

## What shipped

**Kernel — `src/lib/todos/todoBoard.ts`** (39 tests). Pure string and data work; file IO stays in the script, following the `sessionClaims.ts` precedent for a tested kernel that only scripts import.

- `parseFrontMatter` is a small reader rather than a YAML dependency: the fields are flat strings and `>` blocks. `readTodoDoc` validates and names every missing field at once.
- `renderIndexBlock` renders a table per group with counts; `spliceIndex` replaces only the marked region. `renderBoardItems` renders the `ITEMS` array; `spliceBoardItems` replaces only the array.
- `renderViews` renders both from the same docs, so they cannot disagree, and is idempotent — a pinned test re-renders its own output and expects no change.
- `findDrift` is now simply "disk does not match what the sources render", plus front-matter errors, unknown version citations and duplicate slugs. **No prose heuristics survive**, because there is only one copy of the prose.

**Script — `scripts/check-todo-drift.ts`**, as `npm run check:todo-drift`, with `-- --fix` to render. Same shape as `theme-tokenize.mjs`. Two deliberate behaviours: `--fix` refuses to render when a to-do's front matter is broken, rather than baking the breakage into both views; and the checking mode compares against the stamp already on disk, so a stamp that merely trails `main` never reddens an unrelated PR.

**CI** — added to the `checks` job of **both** `ci.yml` and `deploy.yml` (`check-workflow-parity.mjs` enforces the pair, now 9 identical commands).

**Migration** — all 35 to-dos gained front matter, built from the already-curated index and board rows so no wording was invented. Where a `Status:` line carried real detail (over 500 characters — 8 files, `submittals` at 3,223) it moved to a `## Where it stands` section; the other 27 are fully expressed by the front matter.

## Two bugs found while building

- **`g:` matched inside `slug:`.** The first field reader used `` `${key}:` `` with no leading delimiter, so every row's group came back as its slug. Five tests caught it. The reader now requires `{`, `,` or whitespace before the key.
- **The board's last row ends `}`, not `},`.** An unbounded `while` looking for `},` ran past the end of the array and hung. Found by a migration run that never terminated; both loops are now bounded and accept either terminator.

## Verified

- 39 kernel tests; typecheck, lint (0 errors), workflow parity and the theme check clean; the full suite was run before merge.
- `npm run check:todo-drift`: *35 to-do(s) render both views. 33 open item(s): 10 ready to build, 6 close out, 12 needs an owner decision, 4 waiting on time or usage, 3 residuals.*
- The generated `ITEMS` array was evaluated as JavaScript: 35 rows, every `file` exists, 2 pointer rows, no row missing a field.
- The board renders in a browser with the right counts, stamp and no console errors, and the markdown that the index needs is stripped for the HTML view (`toPlainText`) so `**bold**` no longer shows as asterisks.
