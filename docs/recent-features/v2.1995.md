# v2.1995 — Recipients feed the followup queues (2026-08-21)

Bid-recipients train PR 2 (schema + capture: v2.1994). The `bid_gc_recipients` rows become call-queue entries, closing the estimator ask: "I want to know everyone I sent it to so I can get bid tabs from them all."

- New shared lib [`bidGcRecipients.ts`](../../src/lib/bids/bidGcRecipients.ts): `fetchBidGcRecipientsMap()` (one query with `customers(id, name, contact_info)` join → `bid_id → {customerId, name, phone}[]`; degrades to `{}` when the table isn't deployed or the read fails) and the pure `expandLensBidByRecipients()` (primary entry + one copy per recipient, recipient-as-builder, primary never duplicated — 4 unit tests). [`Bids.tsx`](../../src/pages/Bids.tsx) loads the map in `loadBids` and threads it to both lenses + the board tab.
- **Why we lost** ([`BidsWhyWeLostLens`](../../src/components/bids/BidsWhyWeLostLens.tsx)): the builder queue and street pills use the per-GC expansion; the **rollup and header counts stay per-bid** so dollars are never double-counted. Recipient entries dial the **recipient's** phone; the bid card shows "also sent to: … (one reason clears it for every GC)". Pending counts on queue rows also count bids received as a recipient.
- **Waiting to hear** ([`BidsWaitingToHearLens`](../../src/components/bids/BidsWaitingToHearLens.tsx)): same expansion — a bid sent to three GCs is three chase entries; contact stamps are per-bid so a touch under any GC freshens every copy (the card says so). Rollup stays per-bid.
- **Bid Board** ([`BidsBidBoardTab`](../../src/components/bids/BidsBidBoardTab.tsx)): the GC/Builder cell gains a **+N GCs** chip whose title lists the full send list.
- Pre-migration the map is empty and every surface renders exactly as before (verified live). Client-only — no migration (pairs with v2.1994's `20260821230000_bid_gc_recipients.sql`).
