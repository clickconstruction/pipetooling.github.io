# v2.4115 — My Time day editor: Save is all or nothing — `planMyTimeDaySave` + `save_my_time_day` (2026-09-28)

Client only; uses the function added in [v2.4063](v2.4063.md) (migration `20260928182140`, pushed). PR 2 of the all-or-nothing save (punch list **#46** row 10; the map's quirk 26) — the planned PR 3 (removing the old one-request-at-a-time path) folded in here. Stacked on [v2.4114](v2.4114.md).

## What changed

- **[`lib/myTimeDayPersist.ts`](../../src/lib/myTimeDayPersist.ts)** is split in two:
  - **`planMyTimeDaySave(input)`** — the ladder, unchanged in its branches and messages, now pure: it returns the day's writes (`MyTimeDayWrite`: `insert`, `update_notes`, `update_times`, `split_segments`, `split_cluster`, `replace_mixed`) and `salarySyncMayAdjust`, and throws every refusal before anything is sent.
  - **`persistMyTimeDayDirtyClusters(input)`** — plans, then sends the list to `save_my_time_day` in one call with the person, the day and the RPC family. One transaction: a refusal from the database — a row-level-security refusal, a split RPC's `error_message` — undoes every write. No writes, no call.
- **`myTimeDaySaveUsesLeaderRpcs(editingSelf, fenceOverridden)`** replaces `myTimeDayPersistRpcs`: the database now calls the RPCs, so the browser only names the family. The `MyTimeDayPersistRpcs` type and the `leader_*` / `own_*` imports leave this file.
- **The payroll-hours resync** (v2.4114) moves into the database call; the browser no longer calls `recompute_people_hours_after_session_edit` from the save.
- **The editor** passes `leader:` instead of `rpcs:`. Nothing on screen changes except the outcome of a refused save.

## Behaviour that changes

- A refusal anywhere in the day — the planner's or the database's — now leaves the whole day as it was. Before, a refused second cluster left the first written; a refused insert in a block left the saved row's note written.
- A save with writes but no person is refused with *Missing subject user for this day.* (before, note and time updates did not need one).

## Not changed

- The assign flow's twin (`persistMyTimeClusterAndGetSegmentIds`) still sends one request per write: it needs the new session ids back, which `save_my_time_day` does not return.
- `withSupabaseRetry` retries the call on network, timeout or deadlock errors, as it retried each write before. A retry after a connection drop that followed a commit could apply the day twice; that risk was there per write before.

## Verified

- `myTimeDayPersist.test.ts` (84): every branch now pins the list of writes it plans; the one call's arguments; a lead's family; a refusal in the second cluster sends nothing; a database refusal writes nothing; a split RPC's error writes none of the block; no writes, no call; no person refused; the planner alone makes no call.
- The 327 tests of the day editor's libs and components; eslint; typecheck; `npm test` in full.
- `save_my_time_day` itself: `supabase/tests/my_time_day_save/` on a throwaway Postgres 15 (v2.4063). Not run against the live database or in the app.
