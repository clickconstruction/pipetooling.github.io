# v2.7328 — The Lien desk’s run is a checklist: Printed, Signed, Mailed (2026-11-15)

Client only: no migration, no edge function. The owner said on 2026-11-15 that printing the month's batch and getting it all right is an ordeal, and asked for marks — printed, then signed, then the mail code — as a checklist. The three facts already lived on the desk item (`printed_at` / `printed_by`, the signature columns, the sends on the filing); the run now reads them as ticks and nothing new is recorded.

## What changed

- `src/lib/jobs/lienRunChecklist.ts` (+ test): `lienRunChecklistRows` builds one row per `RunNotice` — `printed` (the stamp, or the print in this sitting, with who), `signed` (`typed` for a name, drawing or code; `pen` with who wrote it; `not_needed` when the builder said nothing), `mailed` (every paper envelope numbered; by hand or email counts), `waitsOn` in the owner's order (print → sign → mail), the pile row's `line` (`lienRunRowLine`: *printed · not signed*, *signed · not mailed*, *mailed · ready to record*), and the run's own `held` apart from the ticks. `lienRunBatchPlans` gives each batch press its ready rows and held rows with reasons, in `batchWords` shape (*Mark 1 printed · 1 held ▸*, *Mark 1 signed · 2 wait ▸*, *Record 1 mailing · 4 wait ▸*; the dead button keeps its noun). `lienRunPill` reads *The run · 3 of 7 mailed* with a meter; `lienRunMailLink` is the sheet's code address; `lienRunSheetHtml` draws the sheet.
- `RunNotice.printedBy` (`lienDeskRun.ts`): `printed_by` through the run's name lookup.
- `src/components/jobs/LienRunChecklist.tsx`: the rows and ticks. Printed ▸ (`run-check-mark-printed-<id>`), Signed ▸ (`run-check-sign-<id>`, the pen pane under the row), one tracking box per paper envelope (`<label> — owner tracking` / `— GC tracking`, keyed to the envelope so a shared one takes it for every notice inside), `data-run-mail-box` for the scanned code's landing. `.lienRunCheck*` in index.css; the rows stack under 700 px.
- `LienDeskRunModal.tsx`: the checklist replaces the Run-5 live checklist (its local ticks are gone — the ticks are facts now); the envelope cards sit under an *Envelopes and copies* fold (open on a computer, folded on a phone); the foot carries the kernel's status line and the batch presses *Mark N printed* (`run-mark-printed`), *Mark N signed ▸* (`run-mark-signed`, one pen pane over the first leader's printed unsigned notices) and *Record N mailings ▸* (`run-record`), the held rows listed under it (`run-held-list`); **Print the sheet** under More (`run-print-sheet`, `openHtmlPrintWindow`, never filed). A reprint re-stamps the item (`onPrinted` again) so the tick re-marks with now; a Docsmit send stamps the tick the moment it goes. **Record takes only a row that is printed with every paper envelope numbered** — the old *record everything with no number* path is gone, as the owner asked.
- The desk: the printed pile reads **In the run** (`LIEN_DESK_PILES`), its rows carry `lienRunRowLine`, the To do's single printed row reads *In the run · printed · not signed*; the title-bar pill reads `lienRunPill` (mailed = this run's notices recorded sent in the last 7 days, still carrying their print stamp), meter mailed green · printed blue; `?run=<item id>&mail=1` (`lienDeskRoute.ts`, consumed once by `LienDeskPage` like `?records=`) opens the run on that notice's Mailed box (`openRun` → `focusMailItemId`).
- Guide *send lien notices from the Lien desk*: the run section rewritten around the checklist, the presses, the sheet and the phone. Glossary's pile line amended.
