# v2.6432 — Materials on site: the manifest and the box labels print at full size (2026-11-03)

Punch list #209. Measuring the live manifest PDF (v2.6366) on 2026-11-03 showed the whole printout at about two thirds size. At 96 dpi, where one image pixel is one CSS pixel, from Playwright Letter PDFs of the Lift stations job:

| | Printed before | Designed | Printed now |
|---|---|---|---|
| Manifest QR, dark modules | 68 px | about 102 px | 101 px |
| Manifest ruled-line pitch | 29.4 px | 44 px | 43.7 px |
| Label QR, dark modules | 84 px | about 88 px | 88 px |
| Label ruled-line pitch | 30.4 px | about 31.4 px | 31.6 px |
| Labels per sheet | 2 on one sheet | one a sheet | one a sheet |

The labels shrank far less than the manifest in that PDF: their print set no page margins, so it laid out across the full 8.5 in sheet. Their real fault was the sheet: both labels printed on one, though the window promises one a sheet.

**The cause.** Both windows printed with `body * { visibility: hidden }`. A hidden page still takes its width, and the Jobs page's tab strip (Materials … Inspections) runs to x≈1049 at the manifest's 720px printable width, so Chrome shrank the manifest to fit (720/1080 ≈ 0.67). Taking every other child of `<body>` out of the print layout restored its full size, which is how the fix was proven before it was built. `documentElement.scrollWidth` under emulated print media still read 720, so that check does not catch it; measuring the PDF does.

## What changed

- **The kernel** [`lib/printRoot.ts`](../../src/lib/printRoot.ts) (pure, 5 tests): `printRootCss(rootClass)`, the print rules for a window portalled to `<body>` — every other child of `<body>` is `display: none` in print, so nothing behind can widen the layout; the root prints `position: static`, in the normal flow, so its sheets paginate; the body the scroll lock pins with `position: fixed` is let go; `@page` Letter with half-inch margins. `LETTER_PRINTABLE_PX` names the 720 × 960 px sheet.
- **The manifest** (`ManifestPrintModal.tsx`): `createPortal(…, document.body)` and `printRootCss('on-site-manifest')`; its pages list prints as a block. Its render smoke now asserts the root sits on `<body>` with no `visibility: hidden` rule.
- **The labels** (`LabelsModal` in `JobsMaterialsTab.tsx`): the same portal and rules, and `break-before: page` between labels, so each label gets its own sheet as the window says (*N labels, one a sheet*). The scroll-lock clip the v2.6366 fragment left on the labels is gone with it.
- **The ruled lines** `MANIFEST_MIN_ROWS` 14 → 11 (`containerManifest.ts`). At full size an empty box's page laid out 1037px against the sheet's 960 and spilled its ruled block onto a second sheet; at 11 it lays out 905px, room for a job name that wraps once more. A box with one item lays out 861px.

## Checks

Playwright `page.pdf({ format: 'Letter', preferCSSPageSize: true })` on the dev server against the Lift stations job (two boxes): the manifest prints 2 pages with the foot line on each; labels print 2 pages for 2 labels and 7 pages for 7 (the label node cloned in the DOM, nothing written); the measurements above come from those PDFs at 96 dpi. The screen view of both windows is unchanged. One trap for the next harness: `page.pdf` prints with whatever media `emulateMedia` last set, so reset it with `{ media: null }`, never `'screen'`.

## Decisions

- **Portal plus `display: none`, not a print window.** Both prints stay in-page as the house's other Materials papers do; a portal is the app's usual way out for an overlay (`RfqComposeModal`, `PlugInScheduleModal`, …), and nothing else on `<body>` belongs on the paper.
- **One label a sheet, forced.** At full size two labels would fit on a sheet, but the window has always promised one a sheet, and v2.6043 designed it so.
- **Fewer, full-height ruled lines** over more, smaller ones: 11 lines at about 12 mm beat 14 at 8 mm for a pen through a laminated holder.

## Left

- Nothing for these two prints. No other print in `src` used the `visibility: hidden` rule.
