Punch list #52 (`to-dos/fuel-is-a-job-cost.md`, Found along the way) left this open since PR 5 (v2.4653): People → Vehicles → Wheels added fuel by person from `mercury_transaction_attributions` alone, so a held card's fuel with no attribution sat in *fuel has no person on it* by card, while People → Spending (`buildSpendingRollup`) and Review's fuel on no job (`reviewVehicleFuel.ts`) gave it to the card's holder. The owner picked the follow-up on 2026-11-07. Client only; no migration.

- **The read**: `loadWheelsSnapshot` (`wheelsData.ts`) reads the window's card charges through `fetchCardChargesWindow` (`list_card_charges_window`, Spending's own read, labelled *wheels card charges*) — one read, 90 days is inside the RPC's 366 — and the names through `loadSpendingDirectory`, skipped when the org has no fuel tag. The reads it no longer makes: the `raw` payloads for card ids (the window row carries `debitCardId`), the attributions (on the row), and the debit-card directory (`cardNickname` and `cardRole` are on the row). The transactions read stays, for the off-card label check alone: a fuel-family row the window does not carry has no card.
- **The kernel**: `lib/people/wheelsFuel.ts` (pure, 3 tests). `wheelsFuelFromSpending` runs `buildSpendingRollup` over the charges (no Office job, no sorting floor — neither moves a row's ⛽ column) and reads each login's fuel off its row; then walks the same charges with the same classifier (`categoryTagForCharge`), the same card rule (an Internal Transfer is not spend, `cardChargeExclusionsFromRows`) and the same owner (`spendingWhoForCharge`) to list by card the fuel that reaches no login — nobody attributed and no holder, or a person record with no login — and the fuel-tag charges Spending gives to *Company cards*, which Wheels keeps setting aside as management tools (an attributed one is that person's now, as on Spending). `sumFuelByUser` and `unattributedFuelByCard` left `wheels.ts`; `splitFuelFamily` stays for its `offCard` half.
- **The words** (`PeopleVehiclesWheelsSection.tsx`): the *no person on it* title says what the list holds and that a held card's fuel is its holder's; the company-card title says an attributed one is the person's; the footnote names the rule (*attributed to them in Banking → Accounting, else on a card they hold*). `WheelsSnapshot`'s shape is unchanged, so Review (`loadTeamReviewUnion`, which takes only each deal's fixed rate from it) and the section's render test need nothing.
