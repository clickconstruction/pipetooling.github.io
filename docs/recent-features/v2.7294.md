# v2.7294 — Four portal kernels write each row as one alias, so the portals no longer upload the slim database types (punch list #359, PR 7) (2026-11-15)

Infra only: no screen and no running code changes. The seventh cut on the #359 card, the slim database types out of the portals, the piece v2.7293 left.

## Why

v2.7293 taught the copy of the kernels to inline a database alias written as one statement (`type X = Database['public']['Tables']['t']['Row']`) and import the 7 KB core of the types in place of the 315 KB slim file. Four kernels wrote their rows another way, so the fourteen functions that read the index, and messages-notify through `legalRoute`, still uploaded the slim file for them: `gc/drawRows.ts` took the table map (`type Tables = Database['public']['Tables']`, then `Tables['gc_draws']['Row']`), `gc/changeOrderOfficeRows.ts` joined the view's row with two columns in one statement (`Database[…]['Row'] & { … }`), and `customerContactDisplay.ts` and `messages/legalRoute.ts` used the `Tables<'t'>` helper.

## What changed

Each writes its rows as one alias per row now, the app's own types unchanged:

- **`src/lib/gc/drawRows.ts`**: the five row aliases name `Database['public']['Tables'][…]['Row']` each; the table map is gone.
- **`src/lib/gc/changeOrderOfficeRows.ts`**: `ChangeOrderOfficeViewRow`, the view's row on its own line, and `ChangeOrderOfficeRow` joins it with the two columns as before.
- **`src/lib/customerContactDisplay.ts`**: `CustomerRow` names the row.
- **`src/lib/messages/legalRoute.ts`**: `LienFilingRow`, `LienDeskItemRow` and `DemandLetterTableRow` name the rows, and the four `Pick<…>` types pick from them.
- **The copy**: the generator inlines all four (thirteen alias files now), and no portal kernel imports the slim file. `edgeUploadGraph.test.ts` holds that customer-portal uploads no slim file and that bridge-weekly-sheet, whose own `index.ts` takes its client type from it and runs the overhead reads, still does.

## Is this the best we can do?

- `Tables<'t'>` is the generated file's own helper and reads well; a kernel the copy holds pays 315 KB for it, so in the copy's files a row is one alias. A test could hold that rule for every file the copy reaches; `check:edge-bundles` prints the five biggest uploads on every run, which is the same alarm a size later.
- The slim file is now held by one importer, the Bridge's email, through its typed client and the overhead reads. Its 1.18 MB is far from the ceiling, so it stays.
- The `Pick<…>` types in `legalRoute.ts` could have been written on the aliases the copy inlines by hand; the aliases keep the row's shape the generated file's.
