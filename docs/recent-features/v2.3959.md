# v2.3959 — GC Review: a call sheet — one call covers an account man's GCs (2026-09-27)

Client only; no migration, no edge function. Step 3 of punch list **#49** (`to-dos/gc-review-one-operator/`).

## What shipped

- **`src/lib/jobs/gcCallSheet.ts`** (pure, 15 tests):
  - `payPromiseStatus(expectedPayBy, todayYmd, amountOpen)` → `{ payBy, late, daysLate }`; late from the day **after** the date, only while money is open. `payPromiseLabel` → "promised Sep 20 — 7 days late" / "pays by Oct 10". Step 5 reads the same rule for the worklist and the header pill.
  - `buildCallSheet({ group, boardRowByGc, todayYmd })` — a worklist group's rows with the newest word, the promise, whether this week's word is in, and `noChangeAllowed`. Broken promises first, then no word yet, then the largest balance. Skipped GCs are left off.
  - The draft rules: an untouched row is not saved (`callSheetDraftIsEmpty`); a started row needs a temperature and a sentence of 8+ characters — the mark form's bar (`callSheetDraftProblem`).
  - **No change** (owner decision 3, taken as proposed): `noChangeNote` writes "No change since Sep 18: “…”" with the last read and its pay date; `isNoChangeNote` recognises it, so a second one in a row is refused.
  - `callSheetAnswers` → the rows to save and the rows held back with the reason. `buildCallSheetPrintHtml` — the sheet on paper (light, escaped).
- **`src/components/jobs/GcCallSheetModal.tsx`** (render smoke 4) — the rows with inline temperature chips, the sentence, the pay date and "no change"; the footer's **Whose word** (the account man preselected) and how it was heard; **Save N answers**; **Print sheet**.
- **`GcWorklistPanel`** — a **Call sheet** button on each account-man group and on "No account man yet"; none under the line.
- **`JobsGcReviewModal.tsx`** — `saveCallSheet` writes each answer through `mergeRoundMarkWrite` (a word over a sent mark keeps it sent) and refreshes once; a row that fails is named and the rest are kept.
