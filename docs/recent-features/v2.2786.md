# v2.2786 — Sub work orders from sheets, PR 2: the Work order box on the sheet (2026-09-04)

Second PR of the Sub Work Orders train (schema in v2.2785). A Sub Labor sheet can now send its sub a scoped, priced, signed work order.

- New [`SubSheetWorkOrderPanel`](../../src/components/jobs/SubSheetWorkOrderPanel.tsx), mounted in the Edit Sub Labor modal right under the "Shown on the sub's portal" box. Loads the sheet's live work order (`step_commitments` where `labor_job_id` = sheet, `step_id IS NULL`), the sheet's assignees (junction → people), the scope library (`sub_scope_items`), the Contract Book's sub-audience documents, the pay-run day, and the sub's paperwork (Master Subcontract Agreement line, General Conditions standing via `generalConditionsStanding`, COI expiry).
  - **Editor**: trade picker (defaults to the linked job's `service_type_id`), the library scope checklist (defaults pre-ticked, first 8 shown, "show all"), job-specific lines, exclusions, terms (amount = `frozenAmountFromSheetTotal(sheet total)` — read-only, fixed at send; window; offer good through; retainage; bond; special provisions), attached-by-reference checkboxes (book docs with version dates, pay wording, insurance with COI expiry), and the signing acknowledgements. `Send for signature` writes status `offered` with the frozen snapshot (`buildSheetWorkOrderSnapshot`) and notifies; `Save draft` writes `draft`.
  - **Summary** after send: sub chip, amount, window, expiry; the signed banner with signer + ticked acknowledgements; the declined banner with reason + Re-offer; the drift note when the live sheet total no longer matches the signed amount (`signedAmountDrift`). Actions: Nudge, Mark accepted, Withdraw, Edit and send, Discard draft.
  - Rail from `sheetWorkOrderRail`: Draft → Awaiting signature → Signed → Working → Walk-through → Customer pays → Paid.
  - The globe button sits in the header so the office can copy the sub's portal link without leaving the sheet.
- Notification: `notifySheetWorkOrderOffered` in [`workOrderNotifications.ts`](../../src/lib/workflow/workOrderNotifications.ts) rides the existing `work_order_offered` email template (project = the sheet label, stage = "Sub work order", link = the sub's portal address — custom slug, else the live token link, else a freshly minted one). `send-workflow-notification` now accepts `labor_job_id` in place of `step_id` (push tag + history row use whichever anchor; no step lookup for sheet orders). **Redeploy `send-workflow-notification`.**
- Ledger rows on Jobs → Sub Labor show a small chip under the stage cell: `✍ Signed Sep 4` / `Awaiting signature` / `Draft work order` / `Declined` (one query per page of sheets, chunked by 300 ids).
- Kernel: `buildWorkOrderReferences` added to `subWorkOrder.ts` (tested).
- Help: new guide *send a sub a work order from a sheet*; *record sub labor on a job*, *manage subs end to end*, and *share a sub their portal* point at it.

Not in this PR: the portal's rendering of references/acknowledgements and the signing acknowledgements (PR 4) — until then the portal shows a sheet work order as a plain offer card titled from the snapshot's sheet label fallback.
