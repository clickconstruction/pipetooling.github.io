# v2.7340 — Paint a map: the groundwork for a map on a task (2026-11-15)

Punch list #345, step 5, the first of two PRs. The card drew a task's place carrying the painted map that leads to it, and held it until maps had been counted. On 2026-11-15 Taunya reviewed the card and picked it now: "I want to build both, also a tasks place carries it's painted map". This PR is the column and the gate. It has no screen.

## What changed

- **A task points at a painted map** (`20261115063000_task_painted_maps.sql`, documented in `docs/migrations/`): `painted_map_id` on `checklist_items` and on `checklist_tech_tree_group_tasks`. The task as written carries it, so a repeating task keeps its map every day, and a roadmap task carries its own for the reason it carries its own place.
- **Whoever reads the task reads the map.** A task has no job, and the person it is given to may be on no job's crew. The map's own gate asks about its job, its development and its maker, so it would turn that person away. A second SELECT policy on `painted_maps` answers yes when a task the caller can read carries the map. It reads the task tables under the caller's own RLS and restates none of their rules.
- **A task may point only at a map its writer can open.** A trigger on both task tables holds that. Without it, anyone who may write a task could point one at any map and so open it.
- **A map thrown away leaves its tasks standing**, with no map.

## Is this the best we can do

- **One pointer, not tied to the place.** The card says *a task's place carries the map*, and the first screen will set it with a place. Taunya also asked for a painted map on a checklist item, "I want someone to be able to assign a task with a map". A pointer on the task serves both, so that ask needs no second migration.
- **A policy, not a copy.** The map could have been copied onto the task. A copy goes stale the day somebody adds the back gate. A pointer stays current, and one map serves ten tasks.
- **The read brings the map's standing rule with it:** whoever reads a map may add a stroke or a place. A person given a task stands on the spot, which is who the rule was written for. They rename, move and remove nothing, and they cannot make a link.
- **Migration before client.** The column is additive and nothing reads it. The screen comes in the next PR, after the push, so no crew meets a client that asks for a column the database does not have.
