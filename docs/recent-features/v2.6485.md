# v2.6485 — The logbook’s TDLR check reads the level and Class B numbers, and a journeyman is not the top rung (2026-11-04)

Five confirmed bugs in the logbook (punch list #255) and its TDLR check, read off `main` at d03168f0e. The HVAC technician levels share one TDLR `license_type` (`A/C Technician`) and differ only in `license_subtype` (`REG` / `CER`), which the check never read, so Paige's registered-tech number answered **Matches** for a certified-tech pick and the dev seat's `check_license` answered `found`. The number reader accepted `TACLA` and a `TACAA` that TDLR never prints but refused `TACLB`, the Class B AC contractor prefix (about 9,700 contractors in TDLR's open list), so **Check TDLR** sat disabled with no word why. `goalsFor` put any top-held class with no seeded requirement into `topOfLadder`, so a journeyman electrician read "top rung" on the page and the print while master was the next rung. The TDLR `fetch` had no timeout in the app or in `dev-mcp`, so a Socrata stall left *Checking…* lit for good. The desk's Logbook press was a plain `<a href>` that reloaded the app.

## What changed

- `src/lib/logbook/licenseText.ts`: `TDLR_TYPE` entries are `{ type, subtype? }`; `registered_tech` needs subtype `REG`, `certified_tech` needs `CER`, and a contractor's subtype (its class and endorsement) is never checked. When the number holds the type at another level, the reason names what TDLR lists ("TDLR lists that number as A/C Technician REG, a different level."). `tdlrNumberFor` reads `/^(?:TACL[AB])?0*(\d+)[A-Z]?$/i`. New `TDLR_TIMEOUT_MS` (10 s), `TDLR_TIMEOUT_REASON` and `isTimeoutError` for both readers.
- `src/lib/logbook/logbook.ts`: `goalsFor` answers a third list, `noRuleYet` (`{ holds, next: { level, name } }`), for a top-held class with a level above it in `LICENSE_LEVELS[trade]` and no `REQUIREMENTS` row from it; `topOfLadder` is only a class with nothing above it.
- `src/pages/Logbook.tsx` and `src/components/logbook/LogbookPrint.tsx`: a `noRuleYet` row reads "Master Electrician next. Its rule is not seeded yet." beside the license; the no-goals card and the print's empty row say the same, and keep "top rung" for the licenses that are.
- `src/lib/logbook/licenseSaveIo.ts` `fetchTdlrRows` and `supabase/functions/dev-mcp/index.ts` `check_license`: `fetch(url, { signal: AbortSignal.timeout(TDLR_TIMEOUT_MS) })`; the timeout throws (the app) or refuses (the seat) with `TDLR_TIMEOUT_REASON`, the 10 seconds named.
- `src/components/personDesk/sections/PersonDeskFieldSection.tsx`: the desk's Logbook press is a `<Link>`, as the Licenses tab's is.
- `supabase/functions/_shared/gcKernels/lib/logbook/licenseText.ts`: regenerated by `npm run gen:edge-kernels`; `dev-mcp` is server 0.24.1 and its `docs/EDGE_FUNCTIONS.md` sentence names the three changes. **`dev-mcp` needs a redeploy after the merge.**

## Tests

- `src/lib/logbook/licenseText.test.ts`: a `TACLB12345C` number reads as 12345 and `TACAA…` is refused; `A/C Technician REG` is found for `registered_tech` and refused for `certified_tech` with the level named, and `CER` the other way round; `isTimeoutError` names only the `TimeoutError` and the reason carries the seconds.
- `src/lib/logbook/logbook.test.ts`: a journeyman electrician is in `noRuleYet` with master next, never `topOfLadder`; a master plumber, an AC contractor and an electrical contractor are `topOfLadder` with `noRuleYet` empty.
