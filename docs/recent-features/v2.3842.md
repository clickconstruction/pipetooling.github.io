# v2.3842 — Checklist: a repeating task counts from the day you finish it (2026-09-25)

The owner's call (2026-09-25) on the open question [v2.3836](v2.3836.md) left: *days after it's completed* counts from the completion day. Client only, no migration.

## Before

Every path that materializes the next `days_after_completion` occurrence — the activity panel's ✓ (`completeChecklistInstance`), Today's checkbox, Review's ✓ and the Dashboard inbox, all through `createNextChecklistRepeat` since v2.3836 — counted from the finished occurrence's **scheduled** date (Review's Missed view: the newest missed date). The add and edit windows say *days after it's completed* and the guide *30 days after each time*, so a task done 5 days late got its next date 5 days early — sometimes already overdue.

## The change

- [`createNextChecklistRepeat(checklistItemId, completedOnYmd = todayYmdInAppTz())`](../../src/lib/checklistCompleteInstance.ts) — the base is the day of the ✓ in the company time zone; `checklistNextRepeatYmd`'s first argument is that day. `completeChecklistInstance` no longer reads `scheduledDate` for the repeat (callers still pass it). Today, Review and the Inbox call it with the item id only.
- Review's `repeatFromDate` and the now-unread `MissedGroup.newestScheduledDate` ([`checklistMissedGroups.ts`](../../src/lib/checklistMissedGroups.ts)) are gone: a Missed-view ✓ that clears a backlog makes one next occurrence, N days from today.
- The exists-check stays, so completing several outstanding copies of the same item on one day still makes a single next occurrence.
- Guide *schedule a task or make it repeat*: the next one counts from the day you check it off. The windows' wording already said so.

## Verified

- `checklistCompleteInstance.test.ts` (+3, `TZ=America/Chicago` and `TZ=UTC`): done late (due Sep 1, done Sep 7, every 3 days → Sep 10), done early (due Sep 20 → Sep 10), and the default reads today in Central (03:00Z on Sep 8 is still Sep 7). `checklistMissedGroups.test.ts` without the dropped field.
