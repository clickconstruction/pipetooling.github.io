## What shipped

- **`bid_submittals`** — one revision per (bid, rev): title, status (`draft · shared · reviewed · superseded`), note, the rendered `package_path`, `source_files` (the vendor PDFs dropped on the revision, each a path + house + page count + `trimmed_at`), shared/created stamps, and a nullable `job_ledger_id` for stage 4's won question.
- **`bid_submittal_items`** — one row per fixture tag on a revision: the specified product, the submitted product (the picked quote line, `source_quote_line_id`), the status, the reason and lead time, the sheet (`sheet_file` + `sheet_pages` into `source_files`, `sheet_source`), `carried_from_item_id` for the revision diff, and stage 4's review columns (decision · note · typed reviewer name and email · time).
- **Helpers** `is_pricing_sharer()` and `can_access_submittal(id)`; RLS for both tables mirrors the RFQ store (the five pricing-side roles on bids `can_access_bid_for_pricing` admits); all three fence appliers.
- **Bucket `bid-submittals`** (private), `<bid_id>/<submittal_id>/…`, four `storage.objects` policies for the same audience keyed on the bid-id folder — the `job-test-reports` bucket's shape.
- [`ACCESS_CONTROL.md`](../ACCESS_CONTROL.md) → "Submittals" names the audience for all the stage 1–2 tables and the bucket.
