# v2.5290 — Messages: the office can see which papers a customer opened on their page (2026-10-12)

Cut 8 of the Messages build, by GC Reviews helper 8, directed by GC Review: the office's read-back of customers' pages, owned here so the four readers share one list. Those readers are helper 1's thread pill, helper 2's Follow up portal rows, helper 5's So far and helper 6's Portal column. It is stacked on #5436 (v2.5263), whose `portal_paper` rows it reads. One migration, `20261012210000_customer_portal_papers.sql` (`docs/migrations/20261012210000_customer_portal_papers.md`). Not pushed to prod. Dev only.

- **`customer_portal_papers(customer_ids)`**: each paper sent to the customer as its non-money half, for the office team (a definer), with the first outside open.
  - The papers are our contract's newest send per job, each change order that went and each pay application that went.
  - The columns are the job, number, description, day and answer, never a dollar or a token.
  - The lead's call (a), 2026-10-12: assistants drive Messages and the three tables read for the money team only. `ACCESS_CONTROL.md`'s Owner Billing door says so.
- **The kernel** (`src/lib/portal/papers.ts`):
  - `customerPaperViews(customerIds, papers, pages)` gives each customer `{ lastOpenedAt, opens, papers: PaperView[] }`, contract first, every customer asked for included.
  - `pillPapers` returns the contract on each job, the change orders still out and the newest pay application per job, for `portalWords`.
  - `papersWaitingOnThem` returns Follow up's papers waiting on a signature, never a pay application.
  - `PaperView` gains an optional `jobId`.
- **The IO** (`src/lib/portal/customerPortalViewsIo.ts`): `loadCustomerPortalReadBack(customerIds)` runs both reads in one batch, untyped until the types regenerate. A refusal surfaces in words, never as an empty "never opened".

  - `customerPortalViewsIo.test.ts` (3): one batch with each id once, nothing for no customers, a refusal in words.
