# v2.6702 — Messages: an email from the reply box goes through Gmail as the box (punch list #207, PR 2) (2026-11-08)

Punch list #207 (`to-dos/messages-estimator-mailbox/README.md`), PR 2 of the train, on the owner's calls 5 and 6 of 2026-11-08: send through Gmail as the box the reply comes back to, named with the replying person and the company, *Wendi Doll · Click Construction*; every other app email keeps Resend; the sent mail sits in the box's Sent because the box sent it. The owner's calls 1, 5 and 6 are written into the card's table. No migration.

## What changed

- **The raw mail** (`src/lib/emailOut/rawMail.ts`, mirrored to the edge): `rawMailMessage` builds the RFC 2822 mail Gmail's `users.messages.send` takes as `raw`: the headers (From, To, an optional Reply-To, Subject, Date, Message-ID), the words and the HTML as `multipart/alternative`, wrapped in `multipart/mixed` with each file attached when there are files, every part base64 and wrapped at 76 so UTF-8 and long paragraphs travel whole; a subject or a display name that is not ASCII goes as an RFC 2047 encoded word (`encodedWord`, `mailboxHeader`), which is how the middle dot in *Wendi Doll · Click Construction* travels. `senderDisplayName` is the From's name; `messagesEmailMessageId` the line's own Message-ID in the box's domain; `mimeByName` a file's type from its name; `rawMailBase64Url` the bytes as Gmail wants them. Tests in `rawMail.test.ts`.
- **The function** (`supabase/functions/messages-email/index.ts`): after the line is written and the files placed, when the box the answer comes back to (R6) is one `readerBoxes` names and `GOOGLE_SERVICE_ACCOUNT_JSON` is set, the mail goes through `gmailSend` as that box under `googleServiceToken(…, GMAIL_SCOPES, box)`, from `mailboxWithName(senderDisplayName(name, letterhead), box)`, with no Reply-To. The line is then updated with `rfc_message_id`, `gmail_id` and `gmail_thread_id`, so the box's own read of its Sent (PR 3) and a copy it gets back write no second line (v2.5504's fence, `email_write_line`'s `ON CONFLICT (gmail_id)`). The function writes the `email_send_log` row and files the sent copy itself (`logEmailSendBestEffort`, `fileSentEmailBestEffort`), and answers `sentAs`. When no reader box answers the thread, the secret is missing, or Google refuses the token or the send, Resend sends it as before with the box as Reply-To, the refusal logged.
- **The reply box and the send window** (`compose.ts`): `emailSenderName` is the person and the company; `fromLine` reads *from Wendi Doll · Click Construction · bids@…* for an email with a box (the company alone with none); `fromHeader` takes the sender's name the same way. `ReplyBox` passes the signed-in person's name (the view's names, else the profile's); `SendWindow` the sender it already loads.
- **Tests**: `src/lib/emailOut/messagesEmailGmail.run.test.ts` runs the handler through the fake Google (`gmailMineFakes.ts` learns `users.messages.send` and a refused box) and a fake Resend: the send as bids@ with the encoded From and no Reply-To, the Message-ID and Gmail ids on the line and no Resend call; the fallback to Resend with the box as Reply-To when Google refuses; Resend with the sender's own address as Reply-To when no box is set. `edgeFakeDb.ts` keeps an inserted row with an id and answers it, and changes matched rows on an update. `compose.test.ts` and `ReplyBox.render.test.tsx` carry the new from words.
- **Docs**: `docs/EDGE_FUNCTIONS.md` § messages-email, `docs/MESSAGES_ARCHITECTURE.md` (Email out), the guide *reply to a person from their thread* (the grey line, the From and the Sent folder), the card's table (calls 1, 5 and 6 answered), status and *Where it stands*.

## Read closer than the card

- The card drew the Gmail path alone. The code falls back to Resend on Google's refusal so a delegation hiccup never loses an email; the line carries the box either way, and the log says which way it went.
- The send window keeps its **Replies to** line: as the box, the From is that address, so the words stay true.
