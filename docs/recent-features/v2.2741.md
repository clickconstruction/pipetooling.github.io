# v2.2741 — Signed bid → job → contract: the link closes itself (2026-09-04)

**Why.** After a GC signs in the bid room, the signature files into the Estimates Ledger and the Jobs → Stages contract chip already knows how to show it — but only for a job that carries the bid, and nothing set that link. The owner also wanted the job visible from the Bid Board, for the roles that can open jobs.

**What.**
- **The job inherits the bid automatically.** Creating a job from a signed bid-room proposal (Estimates Ledger → Create job), linking the proposal to an existing job, or applying it through `apply_estimate_to_job` now stamps the job's bid — migration `20260904010000_estimates_link_job_stamps_bid` (a trigger on `estimates`; never overwrites a bid picked by hand). From then on the Stages contract chip reads *Signed · Bid room proposal* and opens the signed record, and Edit job shows the linked bid.
- **The Create-job modal says so** when the estimate is a signed proposal.
- **Bid Board → Links column**: a green **J####** chip (briefcase) opens the job made from the bid. Shown only to **assistants, masters, controllers and devs** — estimators cannot open Jobs, so they never see it (`canSeeBidBoardJobLinks`). Newest job wins if a bid somehow has two.
- No Create-job button on the Cover Letter or the board, on purpose: jobs are sometimes accepted long after the signature, and the Estimates Ledger's Create job / Link existing job remain the doors.

**How.** `src/lib/bids/bidBoardJobLinks.ts` (role gate, label, index; tested). `Bids.tsx` loads `jobs_ledger(id, hcp_number, bid_id)` for the board's bids only when the role passes, batched by 200, and hands `jobsByBidId` to `BidsBidBoardTab`, which renders the chip in `renderBidBoardLinksCluster`. `EstimateForCreateJob` gains `bid_id`.
