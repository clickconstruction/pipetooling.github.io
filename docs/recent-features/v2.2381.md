# v2.2381 — Counts bid list: the count column (2026-08-27)

Owner request (demoed with live prod numbers first — half the working bids
had zero counts, which made the case): the Counts tab's bid picker leads
each row with a subtle count of that bid's `bids_count_rows`.

- `BidPickerStandardList` gains an optional `countBadges: Record<string,
  number> | null` prop — when provided, rows lead with a narrow
  right-aligned tabular number (muted) or a dim "—" for zero (owner-picked
  zero treatment), hover title spelling it out. Other tabs pass nothing and
  render unchanged.
- `BidsCountsTab` fetches the tallies once per bid-set (id-only select over
  `bids_count_rows`, chunked ×100 so the `.in()` URL stays sane, keyed on
  the sorted id list so search keystrokes never refetch; fetch failure just
  leaves the column absent). ~293 bids in the picker → 3 requests.
- Counts are whole-bid row counts (all versions' rows carry bid_id), which
  matches "has counting started" — the question the column answers.

Verified live on the dev server against prod data: 293 rows, 209 numbered
/ 84 dashed, spot-checked against a direct SQL tally (ALSATIAN 30, RBFCU
69, Galloway 83).

Help guide `count-with-the-count-sheet.md` gained the intro line.
