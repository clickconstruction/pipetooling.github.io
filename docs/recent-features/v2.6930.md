# v2.6930 — Lien desk: the batch print says when an affidavit takes a second sheet (2026-11-11)

Punch list #305. The docs catch-up pass of 2026-11-11 (PR #7659) found that the Affidavits list's **Print N for notarization** (v2.6918) never ran the check the Lien window runs under its own print press (v2.6896). v2.6895 records that a homestead paper with a long legal description fills 99% of one sheet, so one more line moves its closing to page 2. In a batch that happened with no word to the office, and a notary could be handed a paper whose signature sits on a sheet of its own.

## What changed

Under **Print N for notarization**, when a paper of the run takes more than one sheet:

- *1 paper in this print takes a second sheet. Keep its sheets together for the notary, or print it alone from its own Lien window.* (*3 papers in this print take…* for more than one.)
- Under it, one row a flagged paper: the job, as a press that opens its paper on the desk, then the line its own Lien window shows. *This paper prints on 2 pages. The last statement, the signature and the notary’s block moved to page 2 together, so none of it is cut.*
- Nothing while every paper fits one sheet.

The press does not change: same count, every ready paper printed, each job's copy filed. A flag holds nothing back (`CLAUDE.md` → *Do what is ready*).

## How

- **`src/lib/jobs/lienAffidavitBatch.ts`** (pure) gains three functions. `lienAffidavitSheetPapers` draws each paper of the run alone, the document its own Lien window measures (`filingDocPrintHtml` with `sheet`, on the short form's tight sheet). `lienAffidavitSheetNext` picks the one paper the frame reads next. `lienAffidavitSheetFlags` returns the lead and the rows, each row's words from `filingSheetWords`. A read is kept with the document it was read from, so a paper whose words changed is read again and an old read never speaks for it.
- **`src/components/jobs/LienAffidavitSheetFlags.tsx`** lays the papers out one at a time in one hidden frame, so a month's run is never a dozen hidden documents at once, and names a paper as soon as it has been read.
- **`FilingSheetFrame`** is the hidden frame lifted out of `FilingSheetNote.tsx`; `FilingSheetNote` draws through it and reads the same. It reports each read with `settled`, true once the paper's fonts are in, and the batch moves on only then. The signature's face can change where the closing lands.
- **`LienDesk.tsx`** builds the run's papers once (`affPrintPapers`, memoized) for both the press and the flags, so what is measured is what prints.

## Decisions

- **Each paper is measured alone.** In the batch document each paper starts its own sheet inside the same page table at its own leading, so its break is the break of the paper printed alone.
- **Beside the press, not a confirm.** The Lien window says it under the press and asks nothing; the batch does the same.
- **Not read yet is silence, not a warning.** A paper is named only once it is known to take a second sheet.

## Proof

- Chromium (Playwright): four sample papers, one a homestead with a long legal description. Each laid out alone in a frame as wide as the sheet, as the bar does, then the batch document through the print engine (`page.pdf`, `pdfinfo`, `pdftotext`). The kernel named the one long paper as moved to page 2; the PDF is 5 sheets for 4 papers, and that paper's item 7, signature and notary's block are alone on its second sheet.
- On the real desk in the local preview (Playwright, table writes refused at the network, the press never pressed). The 12 ready affidavits are still on the earlier form, so the print bar is not drawn for them today. With a read-side fixture that marks the rows short form, the bar's frame read all 12 real papers one at a time at 816 px: the tallest lies 872 px on a 940.8 px sheet, each fits one sheet, and the bar says nothing. With a made-up long legal description fed to some addresses, the bar named exactly the 8 papers whose closing crossed the sheet's foot and none of the 4 that fit.
- Five mutants, each failing a test: a read that ignores its document, a move before the fonts settle, a frame that never settles without fonts, the desk's bar handed no papers, a flag on a one-sheet paper.
- Unit tests for the three functions; a render test for the flags (one frame at a time, the wait for fonts, a paper that changed or left the run); a render test on the desk's own bar that a flagged run still prints both papers.

Not observed: a real printer.

## Found, not changed

Neither the list's **Send N for approval…** nor the pane's **Send for approval ▸** on an affidavit calls `tellLeaderOfLienApproval`; only the notice send does. An affidavit waits in the leader's queue with no push. It is on the card as the owner's question.
