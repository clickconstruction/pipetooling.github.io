# v2.2040 — Billed money modals: full scopes, unfiltered rows (2026-08-21)

v2.2035's known cousin, fixed. The Payment forecast undercounted for the same two reasons the chase queue did — prod on 2026-08-21 had jobs 650 ($26,800, Working) and 878 ($16,054, Working) missing from Past expected ($43,882 shown vs $100,156 truly past-expected). The aging chart and the "Who owes what" breakdown shared both defects, so all three got the same treatment in [`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx):

- **Scopes**: the three modals' open-effects (now one combined effect) fetch ALL `NON_PAID_SCOPES` instead of just `billed_all` — billed invoices hang on working/waiting jobs too, and the board kernel routes them into `billedActiveRows` only when their job's scope is loaded.
- **Filters**: a shared `billedMoneyModalRows` memo derives from `buildJobsStagesBoardLists(jobs, '')` — no hide-groups, no GC/development/account-man filters, no live search. Money-never-hides, same rule as the chase queue (v2.2035) and the story cards (v2.1915). The chase queue's `chaseFullQueue` now reuses the same memo.
- **Honesty while loading**: each modal takes an optional `loading` prop (`!nonPaidScopesMerged`) and shows a "Loading the whole board — totals can still grow…" status line instead of silently rendering a partial total. Render test added for the forecast's hint.

Deliberate call: these modals now *ignore* board filters rather than respect them — a forecast filtered by an invisible board setting is exactly how the undercount hid. Anyone wanting a filtered money view still has the section lists themselves.

Client-only — no migration, no edge-function change.
