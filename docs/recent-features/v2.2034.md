# v2.2034 — Draft Payroll catch-up: earlier weeks with hours but no report (2026-08-21)

Implements the "Payroll Catch-Up" mockup (owner request): person-weeks with
hours but no pay stub were invisible — the Ledger lists only stubs that
exist, Draft Payroll shows one week. Found live: **103 unreported
person-weeks (~$51k est.)** hiding beyond the default paging.

- **Kernel** `src/lib/unreportedPayrollWeeks.ts` (+8 tests):
  `scanWeeksBefore(periodStart, weeksBack)` → Sun–Sat weeks before the
  period's week, newest first; `unreportedPayrollWeeks()` joins hours rows ×
  pay config × salaried windows (flat 8/0 via `salariedHoursForDay`) ×
  stubs (Draft Payroll's overlap predicate) → `{person, weekStart, weekEnd,
  hours, estGross}`. Estimates are wage × hours (the preview's own fallback;
  dual-rate parity deliberately skipped — generation stays authoritative).
  Sub-half-minute sliver weeks (`< 0.005 h`) are dropped (a live 0.049 h week
  rendered as "0.00 h · $0.05").
- **`generatePayStub()`** gained optional `periodStart`/`periodEnd` overrides
  (defaults unchanged) so a catch-up row generates for *its* week.
- **Scan wiring** (People.tsx): on Draft Payroll open, one `people_hours`
  query over the scan range + `fetchSalariedPayrollWindows`; stubs read via a
  ref so generating doesn't re-run the scan (fresh rows flip to
  View / Record payment instead of vanishing). "Scan 8 more weeks" bumps
  `catchUpWeeksBack`.
- **Entry button** (DraftPayrollModal action row): amber
  "⏳ Earlier unreported: N", or quiet "Earlier weeks ✓" at zero — always
  rendered once the scan resolves, because a clean first 8 weeks must not
  hide the door to deeper scans (exactly the live state found: 0 in 8 weeks,
  103 further back).
- **`PayrollCatchUpModal`** (new, `src/components/pay/`): stacked at
  `Z_PEOPLE_PAY_MODAL + 50` (under the record-payment/view modals at
  `_NESTED`); rows carry Report (per-week generate, "report created" chip
  after) / Open week (sets the parent period and closes) / View /
  Record payment via the existing callbacks.
