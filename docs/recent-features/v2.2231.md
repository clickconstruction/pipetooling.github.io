# v2.2231 — People → HR: exhibits (file attachments) (2026-08-24)

The HR file can now hold its evidence. Third PR of the HR files v2 train
(v2.2232 DB foundations, v2.2230 markdown UI).

- **`person_file_attachments`** (migration `20260824144656`, details in
  `docs/migrations/`): metadata for files in the new private `hr-files`
  storage bucket, attached per person and optionally per raw entry.
- **Tab**: an Exhibits panel on the Raw entries view (person-level files,
  "+ Add exhibits" uploader), 📎 "Attach files" staging in the entry composer
  (files link to the entry they're saved with), and per-entry attachment chips.
  Chips open via 10-minute signed URLs.
- Dev-only end to end; `hr_agent` can read + insert metadata (agent byte
  uploads use the storage API — see `docs/HR_FILES.md`). No UPDATE path
  anywhere: replace-and-note, like entry corrections.
- Storage bucket + `storage.objects` policies are configured out-of-band like
  the project's existing buckets; SQL documented in `docs/HR_FILES.md`.
