## What shipped

1. **Viewer grant.** `BidBasisCard` opens the tab synchronously on the click (user activation), invokes the new **`bid-basis-grant`** function (`POST { bid_id }`, JWT in-handler, Cover Letter roles, bid read through the caller's client), and points the tab at the returned URL: the bid's CountTooling link with `export=bid-basis&ref=` plus a 24 h grant (`via: 'pipetooling-bid-basis'`) naming the caller, minted with `_shared/viewGrant.ts` over `COUNTTOOLING_VIEW_GRANT_SECRET`. CountTooling skips its email gate and logs the visit under the person's name. No secret / mint failure → the bare link; the waiting dialog says which happened ("Opened as you" vs "may ask for your work email once"). `src/lib/viewGrant.test.ts` pins the `via` claim.
2. **Confirmed file name** (CountTooling side): with the File System Access API (Chrome / Edge) the export asks where to save BEFORE rendering — the click's activation would not survive a minutes-long export — and the manifest carries the name the person actually chose (`saveMethod: 'confirmed'` → `save_method = 'confirmed'`, the card says "name confirmed by your browser"); Safari / Firefox keep the plain download (`intended` → `reported`). Cancel = nothing saved, the dialog re-opens.
3. **Lighter render**: the bid-basis preset renders at 3x / 0.85 JPEG (about a third of the bytes of 4x / 0.95); Export PDFs by hand is unchanged.
4. **Approval PDF**: `approvalPdf.ts` reads `bids.bid_to_marked_plans` and the current `bid_plan_basis_exports` row fresh (like the Schedule of Values) and passes the clause into `buildCoverLetterText` — the Approval PDF says what the letter says. `approvalPdf.test.ts` covers on/off.
5. **Docs**: `ACCESS_CONTROL.md` gains the `bid_plan_basis_exports` entry; `EDGE_FUNCTIONS.md` the `bid-basis-grant` section; help guide updated.
6. **The dark-mode pill** — explained, no change needed: the studio pills carry `transition: background-color 0.12s, border-color 0.12s` (the global `button` rule), and Chrome does not advance CSS transitions in a hidden tab, so a pill that turns on while the tab is hidden keeps its off-state fill and border until the tab is shown (text has no transition and flips at once). Confirmed with `getAnimations()`: five running transitions at `currentTime 0` while `document.hidden`. Visible tabs resolve in 120 ms. The earlier reading came from the in-app browser pane while hidden.
