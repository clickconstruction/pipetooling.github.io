# v2.8233 — State roll: our own plumbing licenses, checked against the state (2026-11-21)

Punch list #411, step two of [`to-dos/state-roll/`](../../to-dos/state-roll/README.md): the Our own view, after [v2.8202](./v2.8202.md) made the pull keep a row whose number is ours. No migration and no edge function change.

## Why

Until now a plumbing license on People → Licenses was checked against the state by hand, if at all. The pull has kept the state's row for each of our own numbers since `license-roll-pull` was redeployed on 2026-11-21 with v2.8202's change, on Taunya's go. This view lays the two side by side, so a date we hold wrong, a license about to lapse or a number typed wrong is seen without anyone looking it up.

## What changed

- **`src/lib/licenseRoll/ownLicenses.ts`** (new, pure, 16 tests): `ownLines` reads each license through `parseLicenseType`, the reader the Licenses tab already uses, and looks for the state's row by number within its rank (`rollNumberKey`, so `J-000277`, `#277` and the state's `000277` are one number). A master is looked for on both master files. It never matches by a name, and a number the state lists under another last name reads **Another name** and offers no date.
  - How a matched license reads, first that applies: **Left the roll**, **Lapsed**, **The state has a later date** or **an earlier date**, **Lapses in N days** inside 60, **Matches**.
  - A license that cannot be matched says why: **No number**, **No rank**, **Not on the roll**.
  - A master who contracts with the public carries the insurance on file with the board. Insurance that ended, or ends inside 60 days, is how a matching line reads.
  - A license of another trade is counted and not checked.
- **`src/components/prospects/StateRollOwn.tsx`** (new, render smoke of 10): a card a license, two chips (**Needs a look**, **Matches**), and **Use the state's date**. The view opens on what needs a look, and on the matches when nothing does.
- **`src/lib/licenseRoll/ownLicensesIo.ts`** (new): the reads, and the one write, a `person_licenses` row's `date_of_expiry`. A save the database turns away without an error is said out loud, since row security hides a row by changing nothing.
- **`src/components/prospects/StateRollTab.tsx`**: a strip of two views, **Our own** and **Pulls**, kept on the address as `roll=own` or `roll=pulls`. `StateRollTabForUser` waits for who the person is, so the strip never flashes. A person who may not open People → Licenses has Pulls alone and no strip, and a link that names `roll=own` opens Pulls for them.
- **`src/lib/people/licenseExpiryNotify.ts`** (new): the note to Dispatch after a license's date is saved, lifted out of `PeopleLicensesTab` so both places that save the date send it the same way.
- **The guide** `see-the-state-roll-of-licensed-plumbers` gains *Check our own licenses*.
- `PROJECT_DOCUMENTATION.md`, `GLOSSARY.md`, `ACCESS_CONTROL.md` and `PROSPECTS_TABS_ARCHITECTURE.md` carry the view.

## Who sees it

The tab's gate is unchanged: the Hiring switch. Our own is drawn only when the person also passes People → Licenses' gate (`canAccessLicenses`). The view reads and writes `person_licenses` under that table's own policy, so the screen's gate is a courtesy and the database holds the line.

## Values in place

One fact a line on each card (`ValueLines`). What the state says is worked out, so it is plain bold. Our own date is the one value a person can change, so it is a `ChangeableValue`: a press turns it into its date field with **Keep** and **Cancel**. **Use the state's date** is the same save with the day already chosen.

## What is not here

- Subs. The view reads a license kept on a person's own record (`people.license`) and tags a sub's, but no record holds one today, so no sub shows. The drawing's Teammates and Subs chips wait for the first.
- Electrical and A/C, which are step five.
- `check_license` on the dev seat still refuses a plumbing number.
- The apprentice file is not on **Pull 4 files**. It is read on its Monday job, so a new apprentice's license reads **Not on the roll** until then.
