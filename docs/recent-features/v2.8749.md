# v2.8749 — A lower layer of `src` reads nothing from one above it: `check:layers` and its list (punch list #434, the split's step 1) (2026-11-27)

Infra, no screen. No migration, no edge function. It owes nothing on prod. One workflow file gains one step.

## Why

The type check holds every line of one program in one heap, about 4.5 KB a line, and its largest part peaked at 9,337 MB of a runner's 13,312 MB cap on 2026-11-27 (`to-dos/type-check-in-parts.md`). Nothing cheap cuts it. The one cut left is TypeScript project references: a project is checked alone, and the programs above it read its declarations.

A project cannot read a file of a project above it, a type included. The feature folders under `src/components` import each other in one ring of 62 folders, so the split goes by layer first: `src/lib`, `src/utils`, `src/types`, `src/constants` and the edge kernels as the lowest project, the components above it.

On 2026-11-27 the lowest folders reached up from 168 files and the hooks reached into the components from 39. The count grew by three files in six hours, on a day when nobody was looking at it. This step stops it growing while the rest of the train is sized and measured.

## What landed

- **The rule** (`LAYER_RULES` in `scripts/lib/layers.mjs`). A file under `src/lib`, `src/utils`, `src/types`, `src/constants` or `src/content` reads nothing from `src/hooks`, `src/contexts`, `src/components`, `src/pages`, `src/test` or a file straight under `src`. A hook reads nothing from `src/components`, `src/pages`, `src/test` or a file straight under `src`. A type import counts, and so does a dynamic `import()`.
- **A test may import anything.** The tests are programs of their own and will read every project. A `.d.ts` file answers to no rule.
- **The check** (`npm run check:layers`, `scripts/check-layers.mjs`). It reads the 11,500 files the rules speak for and takes each one's imports from the TypeScript scanner (`ts.preProcessFile`), so a name inside a string or a comment is never an import. It takes about three seconds and holds no tree.
- **The list** (`scripts/layers-allowed.txt`): 232 rows, each one file, an arrow and the file it reads. 178 rows are the lowest folders' and 54 are the hooks'. An import that reaches up and is not on the list fails the pull request. The words name the file, what it reads, the rule and the mend.
- **The list only shrinks.** `npm run check:layers -- --write` takes off every row whose import is gone, and never adds one. A row is added by hand alone, when a listed file was renamed.
- **A mended row still on the list is a notice, not a failure.** A change that makes things better is never stopped for it. The next sweep of the train takes the row off.
- **`npm run check:layers -- --list`** prints every import that reaches up today.
- **CI runs it** in the pull request's checks, after the nested-windows check.

## What it does not rule yet

- **A hook that reads a context.** 50 hooks read 8 contexts, 33 of them the toast's. 10 of the 32 contexts import components, so where each context sits is part of a later step.
- **The components among themselves.** The ring is not cut by this train's short way.

## The mend the check names

Give the type or the constant its home in the lower layer and import it from there. The upper file can export it again, so no other import changes. 92 of the 178 lowest rows are one type, `UserRole`, read from the sign-in hook: the train's step 2.

## Tests

`src/lib/layers.test.ts`, 21 tests: which rule a file answers to, how an import resolves (the `@/` alias, a relative name, a folder's index, an asset, a package), a file's rows, the list's reading and its ratchet, the words of a run, and the wiring of the script, the list and the workflow.
