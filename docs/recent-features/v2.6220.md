## The order, and why

The reverse of `check:calls-ahead`'s case (which labels a PR whose client calls what only its migration creates): here the migration drops what the OLD client and the OLD function could still call. So: merge → the Pages deploy (the v2.6220 client) → `supabase functions deploy statement-round-email-dispatch` → `supabase db push` → `npm run check:migration-drift` → `src/types/database.ts` regenerated and the dev-mcp catalog rebuilt in the chore PR that also deletes the to-do folder.
