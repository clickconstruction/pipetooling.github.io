# v2.5408 — Three Stripe server functions pass their own type check again (2026-10-12)

A type-only fix to `create-stripe-invoice`, `preview-stripe-invoice` and `void-stripe-invoice-for-revert`, three of the 24 edge functions a `deno check` sweep of all 151 found failing on 2026-10-12. Each error came from Stripe's client being `any` to the checker. No migration and no screen. Nothing behaves differently.

- **The root**: `https://esm.sh/stripe@16.12.0?target=deno` is `any` to `deno check`. A probe assigning an invoice to a string literal type compiles. So every Stripe value is `any`, and three things followed.
- **Lines read off `unknown`** (TS18046):
  - Under TypeScript 6.0.3 (deno 2.9.6), `stripeInvoiceLinesDataForFixtureOrderDisplay<T>(data: T[])` given an `any` infers `T` as `unknown`. A probe with a plain `any` argument gives `unknown[]` too, so it is not the `?? []` fallback.
  - So `_shared/stripeInvoiceSnapshot.ts` (3 errors) and `preview-stripe-invoice` (7) read `description`, `amount` and `quantity` off `unknown`.
  - Both calls name the line type now, `<Stripe.InvoiceLineItem>`. It is `any` today. If the Stripe types ever load, it is the real line type, whose fields the code already reads.
- **A narrowed `let` widened back** (TS2322 ×2): `preview-stripe-invoice` sets `ephemeralCustomerId = ep.id`, where `ep` is a customer Stripe just created.
  - Assigning an `any` widens the `let` back to its declared `string | null`, so `customerIdForPreview = ephemeralCustomerId` was refused.
  - A created customer always has its id. Both read `ep.id as string`, as v2.5377's `gc-card-bill` does.
- **A callback with no type** (TS7006): `void-stripe-invoice-for-revert`'s `existingCn.data.find((cn) => …)` runs on an `any`, so `cn` had nothing to take its type from. It reads `(cn: Stripe.CreditNote) =>`.
- **The shared file**: `scripts/lib/edgeBundle.mjs`'s `walkBundle` finds `_shared/stripeInvoiceSnapshot.ts` in `create-stripe-invoice` alone, so no other function drifts.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3): 13 errors on `main` (`create-stripe-invoice` 3, `preview-stripe-invoice` 9, `void-stripe-invoice-for-revert` 1), 0 here.
  - Each changed file, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
  - Every column the three functions select exists in `src/types/database.ts`.
- **Deploy**: redeploy the three once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
