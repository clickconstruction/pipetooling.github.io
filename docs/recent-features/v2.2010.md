# v2.2010 — Checklist Manage: expandable card activity (history + notes) (2026-08-21)

Clicking any card on **Checklist → Manage** now expands an inline activity
panel: the item's creation stamp, every `checklist_instance_events` row across
its instances (completed / reopened / accepted / comment, the v2.1842 spine),
and an "Add a note…" composer.

- **New kernel** `src/lib/checklistManageActivity.ts` (+ tests):
  - `buildManageTimeline(item, instances, events)` — merges the item's
    `created_at` with events into one oldest-first timeline; each event carries
    its instance's `scheduled_date` so repeating items can show which day an
    event belonged to (rendered only when it differs from the event's own date).
  - `commentTargetInstance(instances, todayStr)` — where a new note lands: the
    latest instance scheduled today-or-earlier, else the earliest future one,
    else null (composer hides). "Latest overall" is wrong because repeating
    tasks pre-materialize instances years ahead (found live: newest instance
    dated 2028).
- **`ManageCardActivity`** (in-file component in `src/pages/Checklist.tsx`,
  rendered by `renderLibraryRow` behind new `expandedItemId` state): self-loads
  on expand — past instances capped at 120 (`scheduled_date <= today`, desc,
  with a "Showing the most recent 120 occurrences" note when hit) + up to 30
  future instances (asc) in parallel, then events for those ids
  (oldest-first) and actor names. Posting inserts a `comment` event on the
  target instance and appends optimistically — same write path as the History
  ledger's composer.
- **Row semantics**: the card body became a `role="button"` toggle
  (`aria-expanded`, Enter/Space) with an "activity for …" label; links inside
  titles still navigate (`closest('a')` guard). The ⋮ actions menu is
  unchanged; its absolute positioning moved to the row wrapper so the expanded
  panel doesn't shift it.

Help guide: `src/content/help/see-a-tasks-full-history-and-notes.md` (new).
