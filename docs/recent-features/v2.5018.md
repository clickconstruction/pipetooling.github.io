# v2.5018 — Estimates: start a recommended add-on ticked (2026-10-09)

This builds the owner's call of 2026-10-09 on estimate options, call (2): the office may pre-tick a recommended add-on. The add-ons shipped with v2.3554–v2.3556 with *none pre-ticked*. No migration. **Edge functions:** the four that bundle `_shared/estimateOptions.ts` redeploy after merge (see Deploy).

## Why no migration

Options are not rows: they live inside `estimates.options_snapshot` (jsonb, the v2.2457 shape decision), so the mark is a field on the option, as `kind` was in v2.3554. What the customer ticked is already recorded: acceptance writes `estimates.accepted_option_keys` (migration `20260917053000`), and the snapshot keeps the mark beside it. So the record shows both what the office suggested and what the customer kept. `recommended` is not reused, because it is the single ★ that pre-selects a choice.

## The change

- **The kernel** (`src/lib/estimates/estimateOptions.ts`, and its twin `_shared/estimateOptions.ts`):
  - An option may carry `preticked: true`, on an add-on only. Both normalizers drop it from a choice and drop any value but `true`.
  - `defaultEstimateSelection` now starts with the ★ choice plus every pre-ticked add-on, in offered order. An all-add-on estimate with none marked still starts empty.
  - The new `setEstimateAddOnPreticked` marks and unmarks an add-on. `setEstimateOptionKind` drops the mark when an add-on becomes a choice.
- **The builder** (`Estimates.tsx`): beside ★ Recommended, an add-on's row has **✓ Start ticked** (`aria-pressed`). The *Customer experience → Page* preview restarts from the new default. The draft save carries the mark with the option.
- **The customer page**: `EstimateAccept`, the staff *Preview as customer* and the builder's preview all seed from `defaultEstimateSelection`, so the add-on starts ticked. `EstimateOptionsPicker` gives it the **Recommended** badge. Unticking is the ordinary toggle. `accept-estimate` freezes, and records in `accepted_option_keys`, exactly what is ticked at Approve, as before.
- *offer options on an estimate*: a ✓ Start ticked bullet.
- `docs/EDGE_FUNCTIONS.md` → get-estimate-for-customer: the 200 response's options may carry `preticked`.

## Deploy

After merge, from a checkout at `main`: `supabase functions deploy get-estimate-for-customer accept-estimate send-estimate-to-customer log-estimate-option-view`, then `npm run check:edge-drift`.

- The customer read normalizes through the shared module, so until `get-estimate-for-customer` is redeployed it drops the field. A marked add-on then starts unticked, which is today's behavior.
- The other three bundle the same module and behave as before.
