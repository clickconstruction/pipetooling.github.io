## Is this the best we can do?

1. **One builder, two hosts**: the item is built once in `buildNeedsYouItems`, so the Dashboard and Quickfill cannot drift from each other; the hosts only wire the hook and the press.
2. **One predicate, two readers, one pin**: the SQL function and the tab's kernel are held to the same rows by a test that reads the bed's own JSON — change a row or the expectation in one place and both readers are re-tried. The strip and the line say the same number by construction.
3. **Fail-soft**: the hook treats an error as "no line", so the client ships before the migration; the tab's door waits for its own data instead of opening an empty modal.
4. **Plain words**: the detail is three short sentences; the guide's four new sentences pass the plain-words sweep.
5. **Cut**: no second strip on a phone, no snooze (the line clears itself as charges are moved or windows close), no per-house breakdown on the card (the worked list is one press away).
