# v2.8365 — Dashboard: a name on the texts row stays on one line (2026-11-23)

Punch list #424, a fault the live look at v2.8336 found. Client only: no migration, no edge function.

## What was wrong

The Needs you row for texts to send draws the names the texts go to under its title (v2.8336). At a phone's width three names do not fit one line, and the line broke at any space. So a first name ended one line and its last name began the next, and the two read as two people.

v2.8336 already held the count of the rest (*+2*) to the last name with spaces that do not break. Nothing held a name to itself.

## What changed

`NeedsYouRowWords` draws the names line in pieces, `[data-needs-you-piece]`: a name with the dot after it, each an inline block no wider than the row. A piece stays on one line while it fits, so the line breaks after a dot. The count of the rest is in the last name's piece, because the kernel joins the two with spaces that do not break. A piece wider than the whole row still wraps inside itself, so nothing runs off the card.

A first try wrapped each name alone. The dev server showed the count of the rest then started a line by itself: a browser may break beside an inline block even at a space that does not break.

The kernel is untouched: `todaysSendsNeed` marks a name with `val('who', …)` as before, and the plain line a screen reader hears is the same.

## Checked

- `NeedsYouRowWords.render.test.tsx` reads each name as one piece with its dot and the holding style, and the line's words unchanged.
- On the dev server at 430 and 320 px wide, by hand, with nothing pressed: each name on one line, and the count of the rest beside the last name.
- The live look that found it was by hand, one page, at a phone's width, with nothing pressed.

## The card

`to-dos/todays-sends-row/README.md` now says the row is built and live (it still said the row was left), and names what is left on the owner's word: the window, the name and the Customers row.
