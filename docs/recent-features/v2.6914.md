# v2.6914 — Bid Board: a grey icon for every missing link, and one Files window (punch list #306, PR 5) (2026-11-10)

The card's PR 5, direction C: the Links column holds five slots on every row, a blue link goes straight out as it always did, and a grey icon opens one window for the bid on the row that was pressed. No migration and no edge function change.

## What changed

- **A grey icon where a link is missing.** The second look (v2.6883) gave each link kind a fixed slot and left a gap for one the bid does not have. The gap is now the link's own icon in grey, named for what is missing (*No plans yet*, `BOARD_LINK_MISSING_TITLE`), on the desk's table and on the phone's card. The grey is the photos icon's grey.
- **The bid's Files window** (`BidFilesModal.tsx` over the kernel `src/lib/bids/bidFilesWindow.ts`, tested): five rows in the column's order. `bidFileRows` turns the bid's photo count, folder link, plan sets, CountTooling link and sources, and submission link into rows that say whether each is there, a line of state (*12 photos*, *3 sets*, *Linked · Google Drive*, *Not linked yet*) and what the row opens. A row the bid has offers **Open ↗**, once for each set of plans or CountTooling project when there is more than one. A row it does not have says what sets it and offers **Set it in Edit bid**.
- **Set it in Edit bid lands on the field.** Three landings joined `BidFormFocus` (`driveLink`, `countLink`, `submissionLink`, beside `plansLink`), and the form's Project Folder and Bid Submission inputs took ids. The press closes the window and opens the bid with the field ringed, through the page's one focus effect.
- **The photos are the window's first row.** The photos' rules, read and presses moved to `useBidPhotosPanel.tsx`, which hands a host window a title, a body and a foot; `BidPhotosWindow.tsx` is that panel in a window of its own and the board no longer opens it. The camera opens the Files window with the photos open. A grey link icon opens it with the photos folded away, so `bid-photos` is not called and no camera is held until **Add photos** or **Show the photos** is pressed. One photo opened large shows alone and comes back to the rows.
- **One home for the four link glyphs** (`src/lib/bids/bidLinkIconPaths.ts`, drawn by `bidLinkGlyphs.tsx` in the window): the board's column and the window draw the same paths.
- A new guide, `see-what-files-a-bid-has`; `add-photos-to-a-bid` amended; `docs/BIDS_SYSTEM.md`, `docs/GLOSSARY.md`, `docs/PROJECT_DOCUMENTATION.md`.

## What it did not change

- **A link is still set in Edit bid.** Pasting a link in the window itself, and **Make the project folder**, are the card's PR 7.
- The plans icon with two or more sets still opens its picker from the board. In the Files window each set has its own Open.
- Where the page draws no photos icon (no photo counts handed to the board) the column is as it was: no grey icons, and a dash for a bid with nothing.

- `bidFilesWindow.test.ts` (10), `BidFilesModal.render.test.tsx` (5), and one test on the Bids page: a grey icon opens the window on its row with nothing read for the photos, and its press opens Edit bid on the CountTooling field.
- Walked on the dev preview against prod as the dev login, at 1,440 wide and at 375, dark and light: all 85 rows measure one layout for the five slots; the grey CountTooling icon on the ZZ Test bid opened the window on its row; **Set it in Edit bid** landed on the field with the ring; the bid was closed untouched. Nothing was written.
