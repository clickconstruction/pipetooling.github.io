# v2.4023 — My Time day editor: Save keeps each part on its own job — `orderedSegmentsFollowTheirRows` (2026-09-28)

Client only; no migration, no edge function. **Payroll fix.** Found by the tests of [v2.4021](v2.4021.md) (the map's quirk 25); punch list **#46** row 10.

## The bug

A block in the day editor groups contiguous clock rows whatever their job. When the editor held one part per row, the save wrote part *i* onto row *i* — branch 7's "seams slid" path — checking only that each part sat inside the block. A split in one row plus a merge across two others also leaves one part per row. Rows a (j1, 0–2 h), b (j2, 2–4 h), c (j1, 4–6 h); split a at 1 h and merge b with c: the save wrote a 0–1 h, b 1–2 h, c 2–6 h. Job j2 went from 2 h to 1 h on an hour that was j1's, and the job chosen in the merge window (a `segmentJobOverrides` entry) was never written. The merge window sets that entry on every cross-row merge, so the shape is reachable with two clicks. The assign flow's twin (`persistMyTimeClusterAndGetSegmentIds`) and, for punch + salary blocks, the coalesced partition (branch 8) made the same mapping.

## The fix

- **`orderedSegmentsFollowTheirRows(c, split, nowMs)`** in [`lib/myTimeDaySavePlan.ts`](../../src/lib/myTimeDaySavePlan.ts): one part per row, in order, where each part shares more than a second with its own row and any job chosen for it is that row's own.
- **It gates every path that writes part *i* onto row *i*:** the ladder's ordered path (`lib/myTimeDayPersist.ts`), the assign twin's, the per-row gate `mixedClusterSegmentsAllowPerRowPersist` (which also drives `canSave` and the merge guard), and `coalescedMixedClusterPartitionForSave` when parts equal rows.
- **What a save does now:** a one-origin block cut out of line goes to the replace RPC, which writes each part with its chosen job or the job of the row it covers most. A punch + salary block cut out of line cannot be rebuilt (the rows' metadata differs), so the save is refused (`canSave` is false; pressing Save shows the editor's existing "add focus notes… at least 0.01 hours" line, which does not name the real reason — the merge window may still allow the merge on the way there). Seams slid within a block still save row by row, unchanged.

## Not changed

Mixed-origin paths write times and notes only, so a job chosen for a part of a punch + salary block is still not written. Rows already saved wrong are not repaired: the editor keeps no record of which saves took the old path.
