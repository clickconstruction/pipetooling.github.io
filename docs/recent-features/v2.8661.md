# v2.8661 — Activity and tasks: a test note that answers a tag says it stays, before you press (2026-11-26)

Punch list #443, row 13, finding 273 of the fixing thread's ledger (2026-11-26), briefed as `443-note-a-tag-answers-has-a-live-delete.md`. Seen while v2.8649 was built. Client only. No migration, no edge function. Nothing owed after the merge.

**Read.** A dev's **Delete…** on a ZZ test job's note, and on a comment of a ZZ task (v2.8626), was drawn by a rule that knew the job's name or the task's title and nothing of the tags. A note a tag names as its answer cannot go: the tag's `answer_note_id` / `answer_event_id` is `ON DELETE SET NULL`, and the database would forget the answer without a word. So the press was live, the confirm opened, and the reason came after it in a red toast: *1 tag names this as its answer. It stays.* The sentence was right. It came one press late.

**The mend.** A press that cannot act is dead and says why.

- **No new read.** An answer is always a note of the tag's own job (`job_note_post_tagged` updates `WHERE t.job_id = v_job`) or a comment of the tag's own task (`task_note_answers_tags` updates `WHERE t.item_id = …`). Each panel already reads its job's or its task's tags for the chips (`useJobNoteTags`, `useTaskNoteTags`). Those two reads ask for one more column each, and `NoteTagRow` gains an optional `answerNoteId`. The brief asked for one read for the listed notes; this costs none, for a dev or for anyone.
- `src/lib/notes/testNoteDelete.ts`, pure: `noteAnswerCounts` counts each note's answers from the tag rows by note, and `noteDeleteWhy` puts the fixed reason first and the answers after it, in `noteAnswersProblem`'s own words.
- `JobThreadNotesPanel.tsx` and `ChecklistItemActivity.tsx`: each row reads its own reason. A note or comment a tag names draws **Delete…** grey with *N tags name this as their answer. It stays.* beside it, and a press on it opens no confirm. The ask itself stays live: nothing names it, and its tags go with it.
- **The count inside the delete stays as the last check**, unchanged. If the tags did not load, the panel holds no counts, every press stays live as before, and the delete's own count answers.

**Differs from the brief:** only in costing no read where the brief allowed one.

**Who sees it.** A dev, on a ZZ test job's note or a ZZ task's comment. Nobody else reads the press, by the tests of v2.8626, which still pass.

**Tests.** Each new case was written first and failed on main with the press live.

- `testNoteDelete.test.ts`: the counts from the tag rows, an ask that is no answer, an empty map, and the reason's order.
- `JobThreadNotesPanel.noteDelete.render.test.tsx`: an answered tag in the job's tags, so the answer's press is dead with the one reason line, a press on it opens no confirm, and the ask's press is live and opens its confirm.
- `ChecklistItemActivity.commentDelete.render.test.tsx`: the same for a comment a tag on another day names.

**Not walked.** Nothing was pressed on the live site. No ZZ job holds a tagged ask with its answer since the walk of 2026-11-26 deleted them, so the render tests are the proof unless a walk makes a pair: two posts and a push to whoever is tagged, each on its own yes.
