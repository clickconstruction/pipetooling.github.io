# v2.5401 — Eight more server functions pass their own type check again (2026-10-12)

A type-only fix to eight of the 24 edge functions a `deno check` sweep of all 151 found failing on 2026-10-12. Each failed on one line, the message its outer `catch` sends back. No migration and no screen. Nothing behaves differently.

- **The fault**: TypeScript types a `catch` variable as `unknown`, and each outer `catch` read its message straight off it.
  - `claim-dev`, `create-user`, `login-as-user`, `send-checklist-notification`, `send-workflow-notification` and `set-user-password` read `error.message` (TS18046).
  - `dev-login` and `send-scheduled-reminders` read `error?.message`, and the optional chain narrows `unknown` to `{}`, which has no `message` (TS2339).
- **The fix**, in types alone: they read `(error as Error).message`, or `(error as Error)?.message` where the chain was, as `invite-user`, `merge-users` and v2.5376's `notify-dispatch-request` do.
- **What each `try` can throw**: none of the eight throws anything itself, and what can reach the outer `catch` is an `Error` in each.
  - A body that is not JSON (`SyntaxError` from `req.json()`), in all but `send-scheduled-reminders`, which reads its body with a `.catch`.
  - VAPID keys web-push refuses, in the three that push.
  - `send-workflow-notification`'s Resend `fetch`, which can fail (`TypeError`) or answer with something other than JSON.
  - Push sends, `send-scheduled-reminders`' emails and `create-user`'s `ensureLinkedRosterRow` catch their own. supabase-js hands its failures back as `{ error }` rather than throwing.
  - The cast changes no JavaScript, so whatever is thrown is handled exactly as before.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3): 1 error each on `main`, 0 here.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
- **Deploy**: redeploy the eight once merged, `create-user` with `verify_jwt = false` kept from `config.toml`. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
