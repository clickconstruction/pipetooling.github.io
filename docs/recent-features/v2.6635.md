# v2.6635 — Documents → Photos lists task card photos (2026-11-07)

Punch list #273's second follow-up, the last piece v2.6602 named: *the gallery on Documents → Photos does not read task photos (`uploaded_photos` has no sixth branch)*. Now it does, and the card is retired.

## What changed

- **Migration `20261107093000_uploaded_photos_task_branch.sql`**: the `uploaded_photos` view gains a sixth branch, `source = 'task'`, over `task_photos`. A card has no job, so the job columns are null and the card's words ride the shape instead: `caption` is the card's title (the server-side search finds it), `stage_name` the shot's own caption (*75%*, *finish*, the line's words) and `status` the shot's kind (`progress`, `finish`, `line`). The joins on `checklist_instances` and `checklist_items` are left joins under their own policies; the row itself is `task_photos`' gate, `can_see_checklist_instance`. Same columns, so no types regen; no table, so no fence. `docs/migrations/20261107093000_uploaded_photos_task_branch.md`.
- **The kernel** (`lib/photos/uploadedPhotos.ts`): `UploadedPhotoSource` gains `task`; the **Task cards** chip for every role; `sourceWords` *Task card*; `taskStandWords` (*At 75%*, *The finishing photo*, *Done when… Pipe is racked by size*, *A photo on the card*) and `aboutWords`, the row's second line, which is the job for every other source; `thumbSource` reads a task shot from its bucket as it reads a text's picture, since the Tasks folder is outside the `job-photos` function's reach and the sweep leaves the bucket copy; `whereWords` answers the press `tasks-folder` when the sweep's reason is the unset Tasks folder (`waitsOnTasksFolder`); `sourceDoorWords` *Open the checklist*; the empty state's tail names a task card. The Development page's Photos look (`sitePhotos.ts` → `siteSourceChips`) leaves the Task cards chip out, since a task card's photo is on no job and a site never holds one.
- **The tab and the viewer** (`DocumentsPhotosTab.tsx`, `UploadedPhotoViewer.tsx`): the source chip's door for a task row is Checklist → Today (`TASK_CHECKLIST_PATH`); **Set the Tasks folder** links to Documents → Where files go (`WHERE_FILES_GO_PATH`); the second line and the viewer's job line read `aboutWords`.
- The guide *find every photo that was uploaded* names the chip, the row's words, the door and the Tasks folder press. `ACCESS_CONTROL.md` and `PROJECT_DOCUMENTATION.md` name the sixth branch.
- **The card retired**: `to-dos/task-cards-progress/` is deleted (the mock-up and the before-after page live in git history at this commit); the to-dos index carries its closing paragraph.

## Deploy

`supabase db push` after the merge. The client reads only columns the view already has, so a client ahead of the push lists no task photos and breaks nothing; `check:calls-ahead` labels the PR for the view it replaces.
