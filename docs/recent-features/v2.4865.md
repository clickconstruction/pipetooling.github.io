# v2.4865 — People: Offsets folds archived people by who they are, not their name (2026-10-07)

Punch list #29 ([`to-dos/people-spine-residuals.md`](../../to-dos/people-spine-residuals.md)), item 3, the second id-first PR. It builds on v2.4862's `ArchivedRoster`. Client only.

## The change

- **[`PeopleOffsetsTab`](../../src/components/people/PeopleOffsetsTab.tsx)** takes `archived` (the page's `ArchivedRoster`) in place of `archivedUserNames` and `archivedPeople`. The settle-up board groups by name. So each board name looks up the one `person_id` its offsets and approved hours carry, and asks `isArchivedRosterRef` with it. The hours read now selects `people_hours.person_id`.
- **[`personIdByName`](../../src/lib/people/rosterPeople.ts)**: the name, trimmed and in lower case, maps to its rows' single id. Two different ids under one name are two people, so the name gets no id and the name decides. That matches the board, which already merges them into one row.
- **The archived-people list leaves Offsets.** It added every archived roster person's name with no namesake guard. The roster's names already hold those people, with the guard. Contracts still takes the list until its own PR.

## What a person sees

- A living person whose name matches an archived person's no longer folds under Archived users, when their offsets or hours carry their own id.
- A person whose offsets are under an old name folds once they are archived.
- Everyone else stays where they were. Pay reports still match by name, since the shared stub read carries no id. A person with only reports falls back to the name.
