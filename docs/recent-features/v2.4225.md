# v2.4225 — An alternate nobody answered stays in the job (2026-09-30)

Found in the live walkthrough of the alternates work (after [v2.4224](v2.4224.md)). BP398 was started before alternates existed and records no accepted alternates, so its Break room rows read as **declined**: they dropped out of the job's scope, Takeoffs counted 6 fixtures instead of 8, and the Bid Board said *alt declined* — for a question nobody had been asked. The same would happen to any group made an alternate after a win. Migration `20260930050000_bids_declined_alternate_tags.sql` ([doc](../migrations/20260930050000_bids_declined_alternate_tags.md)); **redeploy `sign-bid-room`**.

## What changed

- **Declined is said, not inferred.** `bids.declined_alternate_tags` beside `accepted_alternate_tags`: each alternate is taken, declined, or unanswered (in neither). [`alternateAcceptance.ts`](../../src/lib/bids/alternateAcceptance.ts): `alternateAnswer`, `setAlternateAnswer` (a tag sits in at most one list), `boardAlternateState`; `isDeclinedRow` / `jobScopeRows` drop only a **declined** alternate's rows; `acceptanceWords` says *— did they take Break room?* while one is open.
- **Every door that answers writes both lists.** Edit Bid's Won section: Taken / Declined / Not sure per alternate, Not sure to start, so an autosave mid-edit never declines anything (`useBidEditForm.declinedAlternateTags` → `bidFormPayload`, cleared unless won; `bidUpdatePrune` carries it with the outcome). A per-GC Won's *No* is declined (`askAndRecordAcceptedAlternates`). [`sign-bid-room`](../../supabase/functions/sign-bid-room/index.ts) declines the room's unticked add-ons and leaves alternates the room did not carry as they were.
- **A won bid asks where you are.** On the Counts tab (By group), a won bid's alternate heading shows *Won — did they take it?* **Taken** / **Not taken**, or the answer with **Change** (`recordAlternateAnswer`, which also recomputes the agreed value). The Bid Board shows an amber **alt ?** until every alternate is answered.
- Types hand-added (generator order), dev-mcp catalog regenerated; tests in `alternateAcceptance.test.ts`, `bidFormPayload.test.ts`, `bidUpdatePrune.test.ts`. Guide, BIDS_SYSTEM, GLOSSARY and EDGE_FUNCTIONS amended in place.
