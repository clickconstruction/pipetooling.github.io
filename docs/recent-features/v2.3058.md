# v2.3058 — Refused writes: one guard, every bids and takeoff update, and the `rls_refused` beacon (2026-09-07)

Mechanical sweep (merges alone). Client only; no migration or edge-function change.

## Why

PostgREST answers an UPDATE that row-level security filtered out with success and zero rows. Without checking the returned rows the screen closes as if the save landed and the edit is gone. v2.2454 found it on Edit Bid and v2.2461 guarded one more site; the hygiene to-do carried "23 sibling `bids` update sites" and "the takeoff tables" as two sweeps never run, and the journey map's `rls_refused{table, role}` telemetry was "not built" (v2.2920).

Measured today, the sibling list was stale: of 38 `bids` update sites outside tests, 32 already carried the guard. Six did not, plus the two takeoff-line updates.

## What shipped

- **`src/lib/refusedWrite.ts`** — the one kernel: `updateApplied(rows)`, `refusedUpdateMessage(what)`, and `updateRefused(rows, table, op)` which returns true on zero rows **and fires the beacon**: one `ui_nav_clicks` row, control `rls_refused`, target `/<table>?op=<op>`, the role on the row — queryable by table and role without a migration, the same best-effort posture as the nav-click and bill-truth beacons. `setRefusedWriteIdentity` is fed by the auth provider (an effect on user id and role) so the beacon knows who was refused; a dev build also logs `[rls_refused]`. Never throws.
- **`src/lib/bids/updateGuard.ts`** keeps `BID_UPDATE_NOT_APPLIED_MESSAGE` and `updateApplied` and adds `bidUpdateRefused(rows)`.
- **Sweep (scripted):** every negated guard `!updateApplied(x)` in 15 files became `bidUpdateRefused(x)`, imports following usage — 33 sites now report. The one positive use (`gcPacketOutcome` un-rolling a bid only if it still reads won) keeps `updateApplied`: zero rows there is a hand change, not a refusal. The RFI queue's status change updates `bids_rfis`, so it reports under that table with an "RFI" message rather than as a bid.
- **Newly guarded:** the Bid Board robot request toggle (reverts the optimistic patch and toasts), the Robot queue's axis and hold-out saves, the Counts tab's undo-import link restore, and both takeoff rough-line updates (save and reorder) with a "takeoff line" message. The Job form's conditional bid-value carry (`.is('agreed_value', null)`) stays unguarded on purpose, with a comment: zero rows is the already-set case.

## Tests

`refusedWrite.test.ts` (5) and `updateGuard.test.ts` (4): the check, the beacon's row and target, silence when signed out, a throwing sink never reaching the caller, the copy. `gcPacketOutcome` and the nav-click suite unchanged and green; bids render suites green.

## Reading the beacon

```sql
select role, target, count(*) from ui_nav_clicks
where control = 'rls_refused' and created_at > now() - interval '7 days'
group by 1, 2 order by 3 desc;
```

A row is a person who saw "Save didn’t apply"; the target says which table. Expected sources: the twin write fence (estimator twins), a bid deleted mid-edit, a role outside a table's policy.
