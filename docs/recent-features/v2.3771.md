# v2.3771 — Job window test: the History tab check waits for the window to load first (2026-09-23)

`npx vitest run src/components/jobs/JobWindowModal.render.test.tsx` failed on main on the owner's machine — "History is the fourth tab: it mounts the single-job day grid on first visit and hides the form pane (T5-05)", `Unable to find an element by: [data-testid="history-grid-stub"]` — while the other six tests in the file passed and CI on main stayed green.

## Cause

Neither of the two suspects. `JobWindowModal` still mounts the History pane on the first click (`historyMounted`, unchanged since v2.3361), and the test's `vi.mock('../projects/ProjectsJobHistoryTab')` matches the modal's lazy import exactly; the mocked dynamic import resolves in under a millisecond. Measured at HEAD and again at v2.3487: identical.

The test was the only one in its file that clicked a tab **straight after `render()`**. At that moment the window's first load is still draining — the stubbed job lands and `DetailJobModal` and `JobFormModal` each re-render about ten times (roughly 360 ms of CPU in jsdom). The History pane's lazy component shows its Suspense fallback at once, but its reveal is a low-priority Suspense retry, and React keeps deferring it behind those higher-priority updates until the cascade calms. On a quiet machine that is ~500 ms of wall time, inside `waitFor`'s 1 s budget; on the owner's machine (load average in the hundreds, two apps at ~100 % CPU) it stretched to 1–4 s and the wait ran out every time. After a settled click the same reveal takes ~6 ms of CPU and no data calls — a tab switch fetches nothing.

## Fix

- `src/components/jobs/JobWindowModal.render.test.tsx` — the T5-05 test now awaits the Job pane's header button (Share with supply house) and the form's name field before clicking History, the same markers its neighbours already wait on. Every assertion stays: no grid before the click, the grid mounts on the first visit with the job id, History is selected, and the grid stays mounted after switching back to Job.

No component change, no migration, no edge function.
