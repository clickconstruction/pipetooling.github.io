# v2.5752 — Robots: the rounds run on their own, with no Claude session open and no question asked (2026-10-22)

Punch list #142's structural fix. The rounds (v2.5735) were a Claude Code routine on the Mac that stays on, made by pasting `docs/twins/kickoffs/rounds-operator.md` into a Code session there. On 2026-10-22 the session's Auto permission mode refused the scheduled task silently, so no routine existed until the owner switched modes and retried (v2.5748 and v2.5754 were the stopgaps in words, and every sentence they added is replaced here: there is no routine left to refuse and no mode to set before a paste), and any run that met a new tool prompt could stall. Now **Set up on this Mac** with *This Mac makes the rounds* ticked installs the **Robot rounds agent**: a per-user LaunchAgent that runs the Claude Code CLI headless every five minutes with the round text and the connector — no Code session, no mode, no question.

- **The agent** (`src/lib/bids/roundsLaunchAgent.ts`, the pure kernel; `desktopKickoff.ts` embeds it in the command): `~/Library/LaunchAgents/com.clicktooling.robot-rounds.plist` (`StartInterval` 300, `RunAtLoad`, stdout and stderr to `~/Library/Logs/ClickTooling/rounds.log`) runs `~/Library/Application Support/ClickTooling/round.sh`, which finds the CLI, hands it `round.md` with `-p`, loads `mcp.json` with `--strict-mcp-config`, runs in `--permission-mode dontAsk` with `mcp__twin-mcp`, `mcp__twin-pricer-mcp` and the plan tools (`Bash`, `Read`, `Write`, `Edit`, `Glob`, `Grep`) pre-allowed and the built-in set cut to those, keeps no transcript (`--no-session-persistence`) and logs one JSON line per round (`--output-format json`: the result, the turns, the cost). launchd never overlaps rounds on one Mac; the wrapper kills a round after two hours, and the round text's fifteen-minute orphan rule picks up what it left. The Console's **Stop the rounds** stays a server order the round obeys (`heartbeat` with `round: true`, `orders` stop and leave); the uninstall is `launchctl bootout gui/$UID/com.clicktooling.robot-rounds`.
- **Where the CLI comes from.** The Claude desktop app keeps its own copy of the CLI under `~/Library/Application Support/Claude/claude-code/<version>/<hash>/claude.app/Contents/MacOS/claude` (this session's `CLAUDE_CODE_EXECPATH`), a native binary that runs headless on its own; the wrapper takes the newest at every run, else `~/.local/bin/claude` (what `claude.ai/install.sh` installs), else the PATH's, and the setup command runs that installer only when a Mac has none of the three.
- **The sign-in.** Outside the app the CLI is *Not logged in* (checked here from a bare environment: the app hands its Code tab a token the CLI never stores), so the command runs `claude auth login` once — a browser window, the same Claude account — before it spends the one-time code; the credential lands in the login Keychain, which a LaunchAgent in the `gui` domain reads. Pasted into Claude Code instead of Terminal while the CLI is not signed in, the command says the one line to run in Terminal and spends nothing. Watch item: the Keychain item belongs to the binary that made it; if the app's CLI and a native install differ in signing identity, the first round from the other binary may raise a Keychain prompt on the Mac's screen — the wrapper and the command resolve the CLI the same way, so that only happens when the resolution changes.
- **The connector.** The CLI never reads Claude Desktop's config, so the command writes the rounds' own `mcp.json` (mode 600): the connector as an HTTP server (`type: 'http'`, the key as the `X-Twin-Token` header) — no mcp-remote, no Node in the loop. Desktop's config is still written (the Code tab and chats keep the connector), and the Claude app is left alone (the rounds do not need it open). The pricer's **Set up on this Mac** adds its key to an `mcp.json` that already exists, so the pricing robot joins the rounds; a Mac without the rounds gets no second copy of a key.
- **The cost of one session per round, and the cheaper idle round to build next.** twin-mcp's `tools/list` is 48.9 KB (about 12k tokens); with the CLI's system prompt and the round text the fixed prefix is about 25k tokens per session. An idle round is six model turns (`heartbeat`, `get_assignments`, `next_shadow`, `next_plan_question`, `next_submittal_task`, the closing line): one cache write and five cached reads, roughly $0.13 at Sonnet-class list prices and five times that on Opus — 288 rounds a day, so $35–190 a day on API pricing if every round were idle, or a large share of a subscription's limit. The log's JSON lines carry `total_cost_usd` and the token counts, so the real number is read from `rounds.log` after a day. The recommended next step, not built here: a twin-mcp verb `round_check` that answers `{ stop, work }` (the key's `stopped_at`, and whether `next_shadow`, `next_plan_question`, `next_submittal_task` or the orphan rule would hand anything back) and writes the idle heartbeat itself when nothing waits; `round.sh` asks it with `curl` first and starts the CLI only when work waits, so an idle round costs one HTTP call and a stopped Mac costs nothing, while Alive still means the Mac made the round.
- **The Mac's settings shrink to one.** Claude no longer needs to open at login, and no Code session reads settings back; the Energy setting remains (launchd runs no `StartInterval` job while the Mac sleeps), and the command says in one line when `pmset -g` reports a sleep timer. `caffeinate -i` holds the Mac awake for the round itself.
- **Words**: the round text (`rounds-operator.md`: the routine's two sections gone, the top reads as the robot's instruction whether launchd or a person hands it over; briefs regenerated — **deploy `twin-setup`**), the dialog's tick and steps 3 and 4, the Console's *Make this Mac the rounds* row (its button is **Copy the round**: one round by hand in a Code session), the Rounds card's empty state, the Dashboard's silence line (`robotSilence.ts`: *The Mac is asleep, or its rounds were never set up* — a closed Claude no longer stops the rounds), the guide *run the robot estimator from the Claude app* → *Rounds from a Mac that stays on* (the four steps, the log, the uninstall, and the routine to delete on a Mac set up before), `docs/twins/HANDOFF.md`, `docs/EDGE_FUNCTIONS.md`.
