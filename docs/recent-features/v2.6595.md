# v2.6595 — Done when…: the lines a task card is done by, ticked one at a time (2026-11-06)

Punch list #273, PR 2 of six, on PR 1's ground (v2.6592, migration `20261106230000`). Taunya's goal 3: "the user making a card to have the option to list success criteria on each todo card where each optional success criteria can be checked off." The percent a card reads from its ticks is PR 3's ring; here the lines land, the ticks land, and the database's recount (the trigger of PR 1) carries the day row's percent so PR 3 has nothing to backfill.

## What changed

- `src/lib/taskLinesIo.ts`: the reads and writes over `task_criteria` and `task_criteria_checks` (`loadTaskLines` for a screen's cards, `loadItemLines`, `writeItemLines`, `writeTaskLines`, `syncItemLines` through `diffLines`, `tickLine` with its `criterion` event); the writer's id falls back to the session's, since the policy refuses a line in another's name. The tables are younger than the generated types, so the client is cast as the stage checklists' io is.
- `src/hooks/useTaskLines.ts`: one read for every card on a screen, `linesFor(instance)`, a `tick` that shows at once and lands through the io, `allTicked` so the screen reads its cards again when the database closes one, and a re-read on `checklist-item-saved`.
- `src/components/checklist/ChecklistInstanceCard.tsx`: `lines` and `onTickLine`; the card variant draws the count line and the boxes under the title, the next open line ringed amber (the stage checklists' mark), the stamp under a ticked one; the row variant carries a *2 of 3 done when…* chip that opens the lines under the row; a done card's boxes are read-only. The card's own thread and `ChecklistItemActivity` read a `criterion` event as its words and a `progress` event as the percent and the what-is-left words. Six cases in `ChecklistInstanceCard.lines.render.test.tsx`.
- `src/components/ChecklistAddModal.tsx`: the **Done when…** fold under Links, a box with one line a row (`parseLines`: bullets stripped, a twice-typed line once, twelve at most); Send writes the lines after the card, and a line that did not land keeps the dialog open with the reason and the way to add it later, since sending again would make a second task. `ChecklistItemEditModal.tsx`: the same box filled from the card's live lines; Save diffs (kept lines take their place, new ones are added, gone ones are retired so their ticks keep their words). `ChecklistTechTreeAddTaskModal.tsx` and `ChecklistTechTreeTab.tsx`: the box on a new roadmap task, written with `roadmap_task_id`, so every card the sync makes from the task carries them.
- `src/pages/Checklist.tsx` (Today) and `DashboardMyInboxCard.tsx` (Due Today and Overdue, so Quickfill's copy too) mount the hook and pass the lines; the Dashboard's boot read and the card's own reads now carry `roadmap_group_task_id`.
- Guides *give someone a task* (section *Say what done looks like*) and *check off my daily tasks* (section *Tick the lines*).
