## What changed

- **The schema says one firm.** A partial unique index on a constant, `legal_firms_one_active ON public.legal_firms ((true)) WHERE active`, refuses a second row with `active = true`. A guard before it stops the migration with a count when prod already has two active firms. Migration page: [`docs/migrations/20261006031612_legal_firms_one_active.md`](../migrations/20261006031612_legal_firms_one_active.md).
- **Settings says it in the app's words.** `LegalFirmSettingsBlock` sends a save failure through [`src/lib/legal/legalFirmSave.ts`](../../src/lib/legal/legalFirmSave.ts) `legalFirmSaveErrorWords`: the index's refusal reads *One firm at a time: another firm is already active. Reload Settings to edit it.*; any other failure keeps its message.
- **`docs/ACCESS_CONTROL.md`** (Legal desk and legal matters): the firm row says one active firm at a time and names the index.
- The guide (`send-a-customer-account-to-your-attorney`) already said *One firm at a time*; no change.

## Is this the best we can do?

- **Index or trigger?** The index: one line Postgres enforces on every write, including a hand edit. A trigger can be disabled or written wrong.
- **What if prod has two active firms?** The guard stops the push with the count. Nothing changes until someone retires all but one.
- **Does changing firms still work?** Yes: retire the old firm (`active = false`), then add the new one. Inactive rows are unlimited.
