# v2.2235 — HR Report card + People → HR Pending reports (2026-08-24)

Field reports about *people* (not jobs): masters and devs capture an
observation from the Dashboard; it queues on People → HR until a dev or the
HR agent files it as an append-only entry on that person's record.

- **`person_reports`** (migration `20260824170000`, details in
  `docs/migrations/`): subject person, author (user FK + denormalized name),
  `occurred_date` (when it happened) vs `created_at` (when written), free-text
  `content`, `status` pending → filed/dismissed, `filed_entry_id` link to the
  resulting HR entry, resolution note/at/by. RLS: masters+devs insert as
  themselves, authors read their own, devs read/update all, **no DELETE**.
- **RPCs**: `file_person_report(p_report_id, p_content?, p_source?)` appends a
  `person_file_entries` row (source `report`, entry_date = occurred_date,
  "Reported by <author>" preamble) and marks the report filed;
  `dismiss_person_report(p_report_id, p_reason)` keeps the text + required
  reason. Both SECURITY DEFINER, gated `is_dev() OR current_user='hr_agent'`,
  idempotent. `hr_agent` gets SELECT/UPDATE + the RPCs, and the live
  `hr_agent_write` allow-list gains the `report` source, so the nightly agent
  review can file the queue too.
- **Dashboard**: `DashboardPersonReportCard` ("HR Report", collapsed by
  default, people cluster directly above My Team) — who / when / what, a
  facts-and-dates guidance line, and "Your recent reports" with
  pending/filed/closed status chips. Fail-soft before the migration lands.
- **People → HR**: `HrPendingReportsSection` at the top of the tab (dev-only,
  hides when empty) — per report: **File to <name>'s record**, **Open their
  file**, **Dismiss…** with required reason. `report` joins the HR entry
  source set with an amber "Field report" chip.
- Kernel `src/lib/people/hrPendingReports.ts` (`formatHrReportWhen`) + tests;
  help guide `send-an-hr-report-about-someone`.
