# v2.2395 — New bid versions clone every price scenario (2026-08-27)

Wendi: "when creating new version of bid it keeps prices on the new one and
the alternate has no prices in it. should copy all prices" — and separately she
lost all her prices by deleting the alternate they secretly lived on.

Two gaps combined into that surprise:

1. `create_bid_version` cloned exactly ONE pricing scenario — the passed
   `p_pricing_source_version_id` (the source's ★). Any other price options on
   the source version were left behind.
2. `BidVersionPicker` passed `p_clone_pricing: false` whenever it couldn't
   derive a ★ from the source version (no star + not the selected version), so
   the new version silently started with no prices at all — just an info toast.

Fix (migration `20260827191047`, see `docs/migrations/` fragment +
`BidVersionPicker.tsx`):

- The RPC now clones **all** `price_book_versions` owned by the source version
  (names/offers/order preserved), stars the clone of the source's ★ (fallbacks:
  the passed hint, then the first clone), and keeps the legacy single-clone path
  for source versions that own no scenarios (shared-template pricing).
- The client always passes the checkbox's value for `p_clone_pricing` (default
  on), treats the source-pricing id as a ★ hint only, and "＋ Add GC" always
  copies. Checkbox label now says "Copy all … prices — every price option comes
  along".

Deploy order: client merged first; `supabase db push` after. New client + old
RPC degrades to the old behavior (no breakage) until the push.
