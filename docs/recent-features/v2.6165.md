# v2.6165 — The Bid Board's search is back on a phone (2026-10-30)

Fix, no migration, no edge function. The owner's first item of the day: *adding search back to the bid board*. The search never left the code; on a phone it had no room. v2.6109 measured it at 27 px on a 375 screen and left that draw alone (its fix wrapped the row only under 366 px, for the 320 overflow). Measured again today on the dev server at 375 × 740: the input drew **18 px** wide — its own border and padding, not one letter of the placeholder — so the board read as having no search.

## Cause

The tools row (`BidsBidBoardTab.tsx`) is one flex line: the search (`flex: 1 1 auto`, `min-width: 0`), the development filter and a no-shrink group of four presses. The search is the only part that shrinks, and on a phone column the fixed parts take all of it.

## Fix

- **`lib/bidBoardToolsRow.ts`**: `bidBoardToolsRowLayout(phone)` — on a phone the row wraps, the search takes `1 1 100%` (the first line whole) and the press group keeps `margin-left: auto` on the line it shares with the filter; over 660 px the three values are what they were (`nowrap`, `1 1 auto`, none). The ≤365 px media query and its constant are gone: the phone rule covers 320 too (there the filter and the group cannot share a 288 px column, so the group takes a third line, still inside it). `bidBoardSearchPlaceholder(phone)` names what the box finds on both widths — *Search project, GC or bid number…* on the phone instead of the bare *Search...*.
- **`BidsBidBoardTab.tsx`** reads the layout from `narrowViewport` (`useNarrowViewport660`, the same boolean that switches the rows to cards) instead of a second media query.
- **Docs**: `BIDS_BOARD_FORM_ARCHITECTURE.md` (B14, the toolbar paragraph), the guide *read the bid board*.

## Tests

- `bidBoardToolsRow.test.ts` (3): the phone layout's three values, the desk layout's three values, the two placeholders. jsdom cannot measure a flex line, so the structure is pinned and `e2e/viewport-smoke.spec.ts` (320 and 375, unchanged) measures the page for sideways overflow.

## Verified

Dev server from the worktree, signed in as the dev, Bid Board → Plumbing, the input measured with `getBoundingClientRect` and `document.documentElement.scrollWidth` against `innerWidth`.
