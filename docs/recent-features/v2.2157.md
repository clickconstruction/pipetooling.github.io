# v2.2157 — Partner statement: the partner's view becomes the portal's sibling on paper (2026-08-23)

Owner: "make the page the partner sees stunningly beautiful like the customer portal."
Mockup (Option A, approved with all defaults D1–D7):
claude.ai/code/artifact/541d815b-4aea-45d0-8481-b696eb37530e

**Thesis.** The customer portal works because it's a *document* — letterhead, paper,
ink rules, one copper accent, a double-rule total. A partner's ledger is the same kind of
thing (a statement of account between two parties), so it gets the portal's identity, not a
nicer dashboard widget.

- **New page `/my-statement`** ([`PartnerStatement.tsx`](../../src/pages/PartnerStatement.tsx) →
  [`PartnerStatementPaper.tsx`](../../src/components/partner/PartnerStatementPaper.tsx)):
  `CLICK.` letterhead · copper eyebrow *Partner statement* · name + "partner since … · field $50
  · estimating $35 / h" · balance (900-weight, signed) with its words **YOU OWE CLICK / CLICK
  OWES YOU** in copper (D3: words carry the meaning; amounts are ink with signs) · the selected
  week as the paper statement (‹ Older / WEEK OF … / Newer › band → Week opened → lines →
  **So far this week / Week closed** on a double rule → actions) · **D7:** the last closed
  statement sits under the open week *only while unacknowledged*, with Acknowledge on it ·
  **Your jobs** as ruled rows (portal trade-first style, posted profit share inline, *Costing ›*
  opens the cost sheet on a copper-ruled band) · **Full ledger** (stacked two-line rows on
  phones, Date/Posting/Amount/Balance grid on desktop; partner-visible notes on the quiet band)
  · footer. Inline-styled and `data-theme="light"` like every customer/print surface.
- **D4 print is the page:** "Print / save PDF" renders the identical paper with
  `renderToStaticMarkup` (`react-dom/server`, lazy-imported) into `openHtmlPrintWindow` —
  the separate statement HTML builder is gone.
- **Dashboard entry card** — [`DashboardPartnerLedgerSection.tsx`](../../src/components/dashboard/DashboardPartnerLedgerSection.tsx)
  is now the quiet door: *Your statement* · week + "N sessions pending approval" / "Last week's
  statement is waiting on your sign-off" · settle-up position colored + "you owe Click · Open ›";
  the whole card is a `Link` to `/my-statement`. It fetches the summary only (`usePartnerLedger(…,
  { ledger: false })`), not the 520-week ledger. **Your jobs** stays on the Dashboard unchanged.
- **Lens (D1):** Partnerships → "View as …" embeds `<PartnerStatementView asPartnershipId>` —
  the same page through the dev-only `*_as` RPCs; actions hidden, ack status shown as text.
- **Shared pieces:** [`portalTheme.ts`](../../src/lib/portal/portalTheme.ts) (INK/PAPER/COPPER…
  extracted from `CustomerPortal.tsx`, which now imports it — one identity, one place);
  [`usePartnerLedger.ts`](../../src/hooks/usePartnerLedger.ts) (`usePartnerLedger`,
  `usePartnerJobs` — the RPC loading the old card did inline); kernels
  [`partnerStatementModel.ts`](../../src/lib/partnerLedger/partnerStatementModel.ts)
  (`awaitingStatementCard`, `balanceHeadline`, `longDate`, `partnerSinceLabel`; 8 tests) and
  [`partnerJobsPayload.ts`](../../src/lib/partnerLedger/partnerJobsPayload.ts) (jobs/costing
  parsers, also used by the Dashboard jobs card).
- **Route + access:** `App.tsx` `my-statement`; `/my-statement` added to the sub-like path
