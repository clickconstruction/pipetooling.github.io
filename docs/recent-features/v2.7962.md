# v2.7962 — Robots: an assistant can set a Mac up to make the rounds (2026-11-19)

A script, `scripts/twin/install-rounds.ts`, and its pure kernel, `src/lib/bids/roundsInstall.ts`. The owner, 2026-11-19: "Yes, please build all the gaps".

## Why

The audit of what an agent can stand up alone listed it as the fourth gap. The Robot rounds agent was installed by one thing only: the app's **Set up on this Mac** command with *This Mac makes the rounds* ticked, pasted into Terminal by a person. An agent that set a Mac up through the dev seat and the twin toolkit could redeem a rounds key and could not put the agent in place.

## What it does

`python3 scripts/twin/redeem_setup_code.py <code> --rounds` already leaves the key in `~/pt-twin-digest/twin.token` and the round text in `kickoff-rounds.md` beside it. The new script reads those two files and installs what the app's command installs.

```
npx vite-node scripts/twin/install-rounds.ts -- --dry-run
npx vite-node scripts/twin/install-rounds.ts
npx vite-node scripts/twin/install-rounds.ts -- --uninstall
```

- The connector file `mcp.json`, mode 600, with the key as its header. A file already there is kept and this seat's entry set, so a second seat joins it.
- The round text `round.md`.
- The wrapper `round.sh`, from `buildRoundScript()`.
- The LaunchAgent plist, from `buildRoundsLaunchAgentPlist()`, with the home directory filled and escaped.
- Then `launchctl bootout`, `enable` and `bootstrap`, in the app's order.

## One kernel

The plist and the wrapper come from `roundsLaunchAgent.ts`, the kernel the app's command embeds. `roundsInstall.ts` adds the plan: which file goes where with which mode, and which launchctl calls load it. The tests hold the plan to the app's command, line for line where it matters.

## What it checks before it writes

- The key file holds one key.
- The round text is the round text. The batch kickoff is refused, since it waits for a person. The repo's unfilled template is refused, since it still carries a placeholder.
- The connector is `twin-mcp` or `twin-pricer-mcp`.
- Claude Code is on the Mac and signed in. With neither, nothing is written, and the script names the line to run.

## What it leaves alone

- It does not sign in. `claude auth login` is a browser window and a person's.
- It does not write Claude Desktop's own config. The rounds never read it.
- It does not change the Energy setting. It says when the Mac would sleep.

## The key

The key is read into the plan and written into the connector file. No line the script prints carries it, and a test holds that.

## Not run for real

The script ran here as a dry run only. Installing it starts a paid Claude run every five minutes, and this Mac was set up on demand, with no rounds. The first real install is a person's call.
