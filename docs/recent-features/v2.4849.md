# v2.4849 — Demand letter: a pay code for each bill, under the amount box (2026-10-07)

Client only. Grace, on job 878's Lien window: *I would like the QR codes to pay to be in the demand letter preview here, it is on other screens as part of the packet — is this a good idea?* Yes: the § 53.056 notice packet has carried a pay page since v2.3758 (one code per unpaid Stripe bill, each at the bill's `/pay/<id>` address so it never expires), but the demand letter had only *Balance due* and *Pay in full by*, and its packet's exhibits — the invoices as sent, the agreement, the delivery record — carry no code either.

## What changed

- **Kernel** [`demandLetter.ts`](../../src/lib/jobsDocuments/demandLetter.ts): `DemandStatementInvoice` carries `invoiceId` and `payable` (`buildDemandStatement` reads them from the bill: `stripe_invoice_id` means a page); `demandPayCodeRows(statement, assets)` is one row per covered Stripe bill with money open, in the statement's order — the bill's number, its balance, `payLinkDisplay(id)` and the code when drawn; `DemandLetterFields.includePayCodes` (on by default in the prefill, absent on letters saved before reads as on); a new block `payCodes` right after the `amountBox`; `DemandLetterRenderOptions = { payAssets }` as a third argument on `buildDemandLetterModel`, `buildDemandLetterEmailHtml`, `buildDemandLetterText`, `buildDemandLetterPrintHtml` and `buildDemandLetterPdfBlob`.
- **The letter**: a *Pay online* heading, one line — *Scan a code with a phone camera, or type its address. Each opens that bill's own payment page.* — and up to four codes a row, each over the bill's number, its balance and its address (`data-demand-pay-codes`, `data-demand-pay-code="<id>"`). The PDF draws 22 mm codes with the same three lines, four to a row. The plain text lists them. No sentence about liens: the notice's *Once these bills are paid, there will be no lien filed* stays on the notice.
- **The window** (`LienInstrumentsModal`): the codes are drawn in the browser by `buildPayPageAssets` (the notice's own builder) keyed on the bill ids, and handed to the preview, the packet and the email; the tick **Pay codes** under *What the letter may say* says how many, and reads *not offered — no covered bill has a payment page* greyed when none.

## Counsel

Counsel's memo said the GC's § 53.056 envelope is "the form and invoices only", and the notice's pay page stays off the GC's copy until counsel and the owner say (`PAY_PAGE_ON_GC_COPY`). The demand letter is the company's own collection letter, not the statutory form, so this does not read as the same rule; the owner may still want counsel to see the one *Pay online* line.

## Tests

`demandLetter.test.ts` (+3): the rows (a Stripe bill with money open, not a paper or a paid one; the address; the row before the code is drawn; an old statement with no ids), the block's place and the tick, the HTML and the text. `LienInstrumentsModal.render.test.tsx` (+1): the tick, the preview's codes block with the bill's address.

## Not done

- Letters recorded before this carry no codes; their saved PDF is what went out.
- The code is the bill's own page, so a bill marked uncollectible or already paid in Stripe is not a code the letter should carry — the rows follow the statement's balance, which `buildDemandStatement` reads from the job's payments, not from Stripe.
