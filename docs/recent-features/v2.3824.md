# v2.3824 — The fact sheet says more exactly who reads and changes each value (2026-09-25)

Three blind spots in `scripts/map-surface.mjs` (v2.3820) turned up when the 2026-09-25 architecture-map sweep's verifiers checked 2,712 map claims against the source: they found themselves correcting ownership claims that came from the fact sheet's **Read by / Written by** columns.

## The change

- **A setter passed down counts as a write.** `onChange={setX}` or `onNotesTabChange={setBidBoardNotesTab}` used to leave the state with no writer, because only calls counted. Now any reference to a setter counts, so a state that a child changes stops looking parent-owned.
- **Property names are not reads.** `e.pile`, `{ pile: 1 }`, `<X pile={…} />` and `{ pile: p } = …` no longer count as reads of the component's `pile` state (`LienDeskModal`'s `affVisible` / `retVisible` were credited with reading it).
- **Innermost unit, never nothing.** Each reference is credited to the smallest named unit that contains it (a branch inside a derived local wins over the local); a reference only the return holds is `render`, and one that no named unit holds is `L<line>` instead of vanishing (`Quickfill`'s `dockHiddenThisVisit` showed as read by nobody).

The per-unit Reads / Writes columns of the effect, memo, handler and branch tables use the same property-name filter and setter rule.
