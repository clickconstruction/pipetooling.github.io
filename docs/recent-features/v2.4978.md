# v2.4978 — Bids: History no longer shows half a change at the bottom (2026-10-08)

Punch list #73 ([`to-dos/bid-history`](../../to-dos/bid-history/README.md)), found on the live walk of Past values, Put back and the History paging (v2.4952, v2.4954, v2.4963) on ZZ Test, 2026-10-08. No migration, no edge function.

## The bug

The window reads a page of 1,000 rows at a time (v2.4963), and an action is a burst of rows. The action that holds a full page's oldest row can go on into the next page, and it was drawn as if whole. On ZZ Test the first page ended with *Removed Toilets and what hung on it · Show the 21 rows*. After **Show older changes** the same action read *Removed 8 count rows and what hung on them · Show the 80 rows*. The data was right and the press fixed it, but until then the caption and the count were wrong.

## The change

- **`bidHistoryWholeActions(actions, olderRemain)`** in the kernel [`bidHistory.ts`](../../src/lib/bids/bidHistory.ts): while a full page says older rows remain, the oldest action waits for the older page. A page that is one action (a 1,000-row import) is drawn anyway, marked `continues`, so the window never opens empty.
- **The window** ([`BidHistoryWindow.tsx`](../../src/components/bids/BidHistoryWindow.tsx)) draws, counts and filters those actions, so *N changes so far* counts only whole ones. A marked action's second line ends *· continues in older changes*.
