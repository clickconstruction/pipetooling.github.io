# v2.3838 — Job Summary: sub labor counts on the job its sheet is on (2026-09-25)

Quirk #19 of [`JOBS_TABS_ARCHITECTURE.md`](../JOBS_TABS_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Money display; client only, no migration.

## The bug

Sub sheets link to their job by `people_labor_jobs.job_ledger_id` since v2.3055, and migration `20260914240000_sub_sheet_link_cleanup.sql` retired the number fallbacks ("every reader moved to the link"; 0 of 77 sheets unlinked). [`Jobs.tsx`](../../src/pages/Jobs.tsx) was missed: `jobSummaryData` summed sub cost into `laborCostByHcp` keyed on the sheet's `job_number` text and looked jobs up by `hcp_number`, its per-job sheet list matched the same text, and `laborJobHcps` (the Billing tab's needs-labor flag) was a set of numbers. So —

1. a job with no HCP number (click number only) got $0 sub labor — the lookup was skipped outright;
2. a renumbered job kept its linked sheet but lost its cost (no trigger re-syncs the sheet's text), and Billing flagged it "no labor";
3. two jobs sharing a number (`hcp_number` is not unique) each got the combined cost — counted twice;
4. a hand-linked sheet whose typed number differs from its job's was missed.

Job Summary, the Pipeline burn card and the budget footings all read `jobSummaryData`, so each case overstated or understated profit by the sheet cost.

## The change

- New kernel [`lib/jobs/subLaborByJobId.ts`](../../src/lib/jobs/subLaborByJobId.ts) — `subLaborSheetsByJobId(sheets)`: sheets grouped by `job_ledger_id`; an unlinked sheet belongs to no job.
- `jobSummaryData` sums `laborJobSubCost` per linked job and reads `subLaborJobs` from the same groups. `laborJobHcps` becomes `subLaborJobIds` (the linked job ids), and [`billingJobNeedsAttention`](../../src/lib/jobs/billingTab.ts) tests `job.id` against it — the audit still applies only to jobs with an HCP number (its v2.1619 rule). `JobsBillingTab`'s prop is renamed to match.
- Unchanged: the `?editLabor=` door (id first, number only as a fallback), and the Subs tab / Crew P&L, which already read the link.

## Verified

- `subLaborByJobId.test.ts` (3): grouped by link not number (renumbered job, hand-linked sheet), a click-number-only job keeps its sheets, unlinked sheets belong to none. `billingTab.test.ts` (+1): a renumbered job's linked sheet clears the flag; another job carrying the sheet's number gains nothing. `JobsBillingTab.render.test.tsx` on the id set.
- Typecheck, lint.

## Parity on prod (read after merge, 2026-09-25)

A read-only count of the sheets where the link and the number disagree — exactly the jobs whose numbers move:

- **82** sheets. **2** unlinked (number *1032*, no such job) — $0 before and after.
- **14** linked to **click-number-only** jobs (no HCP): Heron Construction ×6, Springtown ×3, Limitless Renovations & Design ×2, SPACEX BA-02N, Terrell sewer line repair, Michael Palmer. They read **$0 sub labor** on Job Summary before; they now count.
- **1** sheet on HCP **662**, a number two jobs share: both jobs carried its cost before; now only the job it is linked to.
- `hcp_number` duplicates on prod: 662 and 621 (no sheet on 621).

```sql
select plj.id, plj.job_number, jl.hcp_number, plj.job_ledger_id
from people_labor_jobs plj
left join jobs_ledger jl on jl.id = plj.job_ledger_id
where plj.job_ledger_id is null
   or lower(trim(coalesce(plj.job_number, ''))) <> lower(trim(coalesce(jl.hcp_number, '')));
```
