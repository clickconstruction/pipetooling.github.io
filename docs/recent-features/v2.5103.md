# v2.5103 — Workflow: a projection that will not delete says why (2026-10-09)

Client only; no migration, no edge function. **A behaviour change on purpose**: a refused projection delete used to say nothing, and now it reports the refusal. Punch list **#21** (`to-dos/decomposition-residuals.md`), the Workflow page's leftovers: the first of the two behaviours the decomposition move pinned but did not change ([`docs/WORKFLOW_PAGE_ARCHITECTURE.md`](../WORKFLOW_PAGE_ARCHITECTURE.md), quirk 24).

## Why

`deleteProjection` in `src/hooks/useWorkflowProjections.ts` did not read the delete's error. When the database refused, the re-read showed the projection still in the list and nothing said why. The same hook's insert and update already handed a refusal to `onError`. The v2.4005 move kept the silence and pinned it in `useWorkflowProjections.render.test.tsx`, so the fix could be its own PR.

## What changed

- **`projectionWriteError(action, error)`** (`src/lib/workflow/projectionEdit.ts`): what a refused insert, update or delete says, `Failed to <action> projection: <the database's message>`, or null when the write went through. The insert and update messages are unchanged, now built by the kernel.
- **`deleteProjection`**: the delete itself is unchanged. It now reads the delete's `error` and hands the kernel's words to `onError`. The re-read still runs either way, so the list shows what is left.
- On the page `onError` is `setError`. A refused delete therefore takes the place of the page with its message until a reload, exactly as a refused save does today. The banner that ends that is the map's quirk 21, the card's next fix.

## Left as it is

- A delete that RLS filters to zero rows returns no error, so it still says nothing. Only dev and master load projections, and both pass the delete policy, so no viewer of the list reaches that case today. Telling it apart would mean changing the delete (`.select('id')` and a count). This fix leaves the delete as it was.

## Tests

- `lib/workflow/projectionEdit.test.ts` (16, 2 new): the three actions' words; null for no error.
- `hooks/useWorkflowProjections.render.test.tsx` (11): the delete case is flipped. A refused delete calls `onError` once with `Failed to delete projection: rls`, the re-read still runs, and the row stays. It is red against the old hook.
