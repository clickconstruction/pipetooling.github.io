# v2.7374 — Box labels: stop a run, print the rest, and pick a range of boxes (2026-11-15)

Taunya's ask of 2026-11-15, the same afternoon as v2.7373's shorter strip, with a run of 455 strips stopped after five by a printer that quit answering: "I would also like the ability to stop a print, midprint. and to select what range of what I'm printing I want to print". Client only: no migration, no edge function.

## What changed

- **Stop printing.** `endsTheRun(index, total, stopAsked)` in `ptouchRaster.ts` (pure): a label ends the run when it is the last, or when Stop was asked before it was sent. `PtouchLink.print` in `ptouchUsb.ts` takes a third argument, `stopAsked`, reads it before each label, sends that label as the run's last (fed out and cut, as a run's end always was) and sends no more. The press sits beside *Printing 6 of 455…* in both windows and reads *Stopping…* once pressed, with the line *Stopping. One more strip prints, so the printer can cut the tape.*
- **The rest, in Print labels.** `labelPick.ts` (pure, new): `boxesPrintedWhole` (a box's copies go together, so a box counts once every copy is out), `leftAfterStop` and `printedUntickedWords`. A run that ends part way, by the press or by the printer, unticks the boxes it printed whole and says so: *7 of 455 printed, then you stopped the run. G1 printed whole and is unticked. The press prints the rest.* Before this the press still counted every ticked box and started again from the first.
- **A range by its two ends.** `tickedRange` and `leftAfterRangePick` in `labelPick.ts`. Print labels shows **From** and **to** over **Copies of each** when the job has more than two boxes: two lists of the job's boxes that read the first and the last ticked box. Picking an end ticks every box between the two and unticks the others; an end picked past the other pulls it along. The chips, **None** and **Every box** work as before, and the ends follow them.
- **Print blank stickers** gets the Stop press; a stop keeps the rest as a printer's stop already did (`restAfterStop`), with `stickersStoppedWords` for the line, so the press reads *Print the rest, 0103 to 0130*.
- The two guides and the map's office Labels paragraph say it.

## The picks

- **One more strip, not a dead stop.** Every label but a run's last is sent to wait in the printer for the next, so the run shares one blank lead-in (v2.6881). The label printing when Stop is pressed was already sent that way, and no command that feeds a waiting label out by itself has been proven on this printer. So the next label is sent as the last. To the printer a run stopped at its seventh label is a run of seven, which is the one thing a printer nobody could reach from here is known to do right. A stop costs one strip and about three seconds, and leaves no strip inside to feed out by hand.
- **The chips are the state.** Print labels has no run in the database to resume, so the rest is what is still ticked. A box stopped half way through its copies stays ticked and prints all of its copies again: a few spare strips, never a box short.
- **A range is two lists, not a typed box.** Names are not numbers (`G12`, `RM4`, a name of words), so the ends are picked from the job's own boxes in the order the chips show them.
- **No range in Print blank stickers.** A run there is already a range of numbers, and its fold has **Print the rest** for the stickers still blank. Left until someone asks.
