# v2.6111 — Other job charges: the save keeps a row's id (2026-10-29)

Punch list #215, PR 3 of 3 (`to-dos/other-job-charges-date-memo/`), cut ahead of PR 2 because it needs no schema change and PR 2's columns ride this save. No migration.

## The defect

`writeMaterialsSlice` ([`src/lib/jobs/jobFormSliceWrites.ts`](../../src/lib/jobs/jobFormSliceWrites.ts)) deleted every `jobs_ledger_materials` row for the job and re-inserted the form's rows on each autosave of the materials slice. So a charge's `id` and `created_at` changed on every save of the job's charges, and a row written by a cost batch (`docs/COST_BATCHES.md`, an `other_charge` op) lost the id the batch's before-image holds: one edit of the job's Other job charges after the apply, and `cost_batch_revert` could no longer find the row it had written. Found while drawing the #215 mock-up, the evening the overhead batch of 2026-10-29 was applied.

## What changed

- **`materialInsertRows`** ([`src/lib/jobs/jobFormAutosaveSlices.ts`](../../src/lib/jobs/jobFormAutosaveSlices.ts)) carries the row's own `id`: a hydrated row keeps the id the database gave it, a new row keeps the one the form minted (`crypto.randomUUID()`), so the payload identifies the row it updates.
- **`writeMaterialsSlice`** upserts the rows worth keeping in one call (`upsert(rows, { onConflict: 'id' })`), then deletes the job's rows not among them (`.delete().eq('job_id', …).not('id', 'in', '(…)')`); with nothing worth keeping it only deletes. The upsert runs first, so a refused write leaves the old rows standing (before, a refused insert after the delete left the job with no charges until the next save). Columns the payload does not name (`created_at`, `source_bid_id`) are untouched by the update.
- Tests: `jobFormSliceWrites.test.ts` (the three cases above; the client mock learned `.not()`), `jobFormAutosaveSlices.test.ts` (the id rides the payload).
- `docs/COST_BATCHES.md` — Revert: one sentence that since v2.6111 a batch-written row stays revertible after the job is edited.

## Verify

Open a job → Costs → Other job charges, change a description, wait for the autosave, reload: `select id, created_at from jobs_ledger_materials where job_id = …` shows the same ids and dates as before the edit. `npm test -- jobFormSliceWrites jobFormAutosaveSlices`.
