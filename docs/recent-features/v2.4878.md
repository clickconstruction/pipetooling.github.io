# v2.4878 — Map: a new address gets pinned again (2026-10-07)

Edge function `geocode-one` changed (**redeploy after merge**); no migration, no client change. Found on the close-out walk of punch list #95, the job address pin ([v2.4783](v2.4783.md) the job form's line, [v2.4790](v2.4790.md) the night).

## What was wrong

[v2.4783](v2.4783.md) taught `geocode-one` to answer with the county. It added `answer(out)`, which fills a missing county from the Census lookup and builds the 200. It also replaced each `return new Response(JSON.stringify(out), { status: 200, … })` in the handler with `return await answer(out)`. That swap reached the line inside `answer()` too, so `answer()` called itself.

Every call that reached an answer recursed until the stack overflowed. That was every hit, every miss and every cache hit, everything past the auth and role checks. Deno sent a 500 with no CORS header, which the browser reports as a CORS error. The `refresh_google_only` path (*Not right? Pin from Google*) went the same way.

Broken from that deploy on 2026-10-07:

- **The job form's ON THE MAP line** read *could not place it · the map services did not answer; the night will try once more* for any address the cache did not hold. The walk typed *100 Congress Ave, Austin, TX 78701* on New Job and got exactly that.
- **The Map page** could not place an address it had not seen before.

**Cached addresses masked it.** The form and the Map page read `address_geocodes` directly. A known address showed *placed ✓ · pinned earlier* without calling the function, so only new addresses failed.

**The precinct nightly is not affected.** `court-precinct-nightly` geocodes with its own calls into `_shared/googleGeocode.ts` and `_shared/censusGeocode.ts` and has no `answer()`. Its first run is 06:20 UTC on 2026-10-08.

## What changed

`answer()` builds the 200 `Response` itself, with the CORS headers, as the handler did before v2.4783. Nothing else moves.

## Tests

New: `src/lib/map/geocodeOne.run.test.ts` (3). It runs the function's own handler with its URL imports stood in for, a fake database and a fake network: a cached address, a new address placed by the street map, and an address nobody can place. Each answers 200 with `Access-Control-Allow-Origin: *` and the county where there is one. On main's code all three fail with *RangeError: Maximum call stack size exceeded*.
