# v2.3551 — The Accounts Receivable close-out smoke stops flaking (2026-09-17)

Test-only. One `.render.test.tsx`, no source change, no migration, no user-facing surface.

## Why

`src/components/jobs/BankPaymentsModal.closeOut.render.test.tsx` failed three CI or full-suite runs on 2026-09-16/17, every time on a branch that does not touch Banking or Accounts Receivable:

| Where | Failure |
|---|---|
| PR #3299 (a Pipeline jump-strip refactor) | `AssertionError: expected '' to be 'vendor_refund'` — cleared on a re-run |
| a local full suite on a Bids → Labor branch | the same assertion; the file then passed 3 runs out of 3 alone |
| PR #3321 (a **docs-only** ledger change) | the same assertion again |

Each failure cost a CI re-run, and a test that reddens on unrelated work teaches people to ignore it — which is how a real regression gets waved through.

## The race

`BankPaymentsModal` seeds the suggested reason in an **effect**:

```ts
useEffect(() => {
  …
  setCloseReason(closeOutOffer?.suggestedReason ?? null)
}, [selected?.mercury_transaction_id, closeOutOffer?.suggestedReason])
```

So the strip paints once with `reason === null` — an empty select — and the pre-pick lands on the next tick. The test did:

```ts
await screen.findByTestId('ar-close-out')
expect(select.value).toBe('vendor_refund')   // ← synchronous, one tick too early
```

`findByTestId` only proves the strip exists. On a loaded machine the assertion read the intermediate render. The second case failed the same way from the other side: it changed the select to `other` before the seeding effect had run, and the effect then overwrote the choice, so the request button was not disabled when the test looked.

## The fix

One helper, used by all three tests:

```ts
async function openWithSuggestedReason(): Promise<HTMLElement> {
  open()
  const strip = await screen.findByTestId('ar-close-out')
  await waitFor(() => expect(reasonSelect().value).not.toBe(''))
  return strip
}
```

Every test now waits for the state it is about to assert on or change. **No assertion was weakened** — the reason really is pre-picked to `vendor_refund`, the button really is gated on a note, and the applied deposit really shows no strip. The file's header records the rule so the next person adding a case here waits too.

## Verified

- The file passes on its own, and the **full suite twice in a row** (the condition the flake needed).
- Typecheck, lint, theme check clean.
