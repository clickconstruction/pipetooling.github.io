# v2.4711 — Legal desk: open the law firm from its name (2026-10-06)

Client only; no migration, no edge function. PR 1 of 2 of the firm's door, approved by the owner on 2026-10-06. His words: *"Where do I set the firm? I would like the option to be able to open up settings for setting the firm from this modal."* Mockup: `to-dos/legal-portal-firm-ready/mockup-firm-door.html`. PR 2 is *Replace with a new firm*, which needs a migration.

## The defect

The firm lives in Settings, under Jobs & billing, in the **Collections law firm** block, which only a dev sees. The Legal desk named it once, in small grey text (*Firm: ZZ Test Firm (temp — replace with the real firm).*), with no way to it. With no firm, the header said *No firm yet — add one on Settings → Jobs & billing.* and the release sheet said the same in red.

## What changed

- **The firm's name is the door.** The header's subtitle ends with a chip: *⚖ <firm> ✎*, or amber *No firm yet · Set up the firm…*, which reads *No firm yet* for a role that cannot set it up. It opens the new [`LegalFirmWindow.tsx`](../../src/components/jobs/legal/LegalFirmWindow.tsx), over the desk (`overlayZIndex + 14`), so the account list keeps its place. Esc and a click outside close the window alone.
- **The same form as Settings.** For a dev the window mounts [`LegalFirmSettingsBlock`](../../src/components/settings/LegalFirmSettingsBlock.tsx) with `inWindow`: no frame of its own, the section heading *Who we release accounts to*, and `onSaved`, which calls the desk's `legal.reload()`. The header, *Click keeps* and the release sheet then read the saved firm. The block's drafts are shared with Settings, so closing the window with unsaved typing keeps it for the next open.
- **What hangs on the firm, before a change.** Above the save, *On this firm now:* with its open accounts, the people on its email list and whether its portal link is on (kernel [`legalFirmFacts.ts`](../../src/lib/legal/legalFirmFacts.ts); the link is one read of `legal_portal_links`). A rename keeps all three with the firm. The save hint now says so in place of *The firm's own people and their email rules arrive with the portal*, which was stale.
- **Read only for everyone else on the desk.** The database lets only a dev change `legal_firms`. The office roles see the firm as text, the same facts, and *Only a dev can change the firm. Ask a dev to update it.* The desk takes a new `canEditFirm`, which defaults to `canMarkReady`; the Pipeline passes `authRole === 'dev'`, so opening it to masters later is one line.
- **Open in Settings ↗**, a dev's only, opens `/settings?tab=settings-jobs#settings-legal-firm` in a new tab. The anchor is now registered in [`settingsDeepLink.ts`](../../src/lib/settingsDeepLink.ts), so a hash alone lands on Jobs & billing too.
- **The release sheet's red line** reads *No firm is set up yet.* with **Set up the firm…**, which closes the sheet and opens the window.
- **The particulars count**, *3 of 8 filled*, beside *Click's particulars for filing*, in Settings and in the window (`particularsFilled`).

## Is this the best we can do?

- **A new tab to Settings, or a window over the desk?** A window. The owner was mid-review when he went looking, and leaving loses the place. The desk's other tools open as windows over it. *Open in Settings* stays for the full page.
- **A third header button?** No. Two firm buttons already sit there, and the name is where he looked. Folding *Firm's emails* and *Firm's link* into this window is the cleaner end state, left for later.
- **Rename or replace?** Renaming is right for a typo, but keeps the firm's people, link and accounts. The window shows them first. Replacing a stand-in cleanly is PR 2, because retiring the old firm and adding the new one must be one database step.
- **Who may change it?** A dev, as today. Masters read it; the owner kept that call.
