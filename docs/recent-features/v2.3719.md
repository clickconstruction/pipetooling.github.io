# v2.3719 — Lien paper: an address never ends in "Null" (2026-09-22)

Punch list #16 (`to-dos/gc-on-notice/`), the engineering half of the "TX Null" item the 2026-09-21 preview pass found live: job 273's `job_address` is stored as `9703 Lenox Hl San Antonio, TX Null`, and the GC run's cover letter and the § 53.056 form printed it as stored. Migration `20260922143000_strip_null_address_token.sql`; client change in the paper kernels.

## What was wrong

v2.2609 traced the token to the original spreadsheet imports and stripped it at display time in `stripTrailingZip` — which also drops the zip, right for a compact list row and wrong for a legal notice — and deliberately left the stored rows alone. The paper never went through that layer: `buildLienNoticeFieldsForJob` (the notice's *Project description and/or address* line), `buildLienAffidavitFieldsForJob` (the affidavit's property address), `fillCoverLetter` (the run's `{{property}}`), the demand letter's service address and the Lien window's three inline builders all read `job_address` raw. No code in the repo writes the token (checked `src/`, `scripts/`, `supabase/functions/`); it is import residue.

## The change

- **[`cleanStoredAddress`](../../src/lib/displayAddress.ts)** — a stored address as paper and fills should read it: trimmed, the trailing `Null` token gone, the zip kept, never stripped to empty, a mid-string "Nullarbor" untouched. `stripTrailingZip` is now built on it (same results as before).
- **Applied once per kernel, so every caller is covered**: `buildLienNoticeFieldsForJob` and `buildLienAffidavitFieldsForJob` ([`lienNoticeDraft.ts`](../../src/lib/jobs/lienNoticeDraft.ts)) — the desk, the GC run, the affidavit pane, the notice preview and `approveAll` all build through them; `fillCoverLetter` ([`gcOnNotice.ts`](../../src/lib/jobs/gcOnNotice.ts)) cleans the `property` fill for the run, the desk and the preview; the demand letter's `serviceAddress` ([`demandLetter.ts`](../../src/lib/jobsDocuments/demandLetter.ts)); the Lien window's notice, affidavit and release-of-record builders ([`LienFilingTabs.tsx`](../../src/components/jobs/LienFilingTabs.tsx)); and the owner-of-record rows ([`ownerConfirm.ts`](../../src/lib/jobs/ownerConfirm.ts)), which is what Step 1 of Put a GC on notice lists.
- **[`20260922143000_strip_null_address_token.sql`](../migrations/20260922143000_strip_null_address_token.md)** — the one-time cleanup v2.2609 wrote out: `jobs_ledger.job_address`, `customer_addresses.address` and `customer_addresses.owner_mailing_address` lose a trailing token; `RAISE NOTICE` prints the three counts at push time. Idempotent, data only.
