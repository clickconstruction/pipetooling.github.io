# v2.4563 — Documents: a pay application workbook is kept when you download it (2026-10-05)

Step 5 of the Sent copies train ([`docs/SENT_COPIES.md`](../SENT_COPIES.md)), first part: a paper that leaves the app as a file. A pay application is downloaded as a workbook and sent to the GC by hand; the saved application "stays editable after sending" by design, so nothing held what the GC was actually given. Client only: no migration, no edge function.

## The change

`AiaG702G703Modal`'s **Generate** files the workbook it downloaded: `fileSentCopy` with `how: 'download'`, `kind` `pay_application`, the job, and the saved application (`job_pay_applications`) as its source when the save took. The file is the same bytes the browser was handed, under the download's own name. It lists under *Sent from this job* as *Saved as a file*; pressing its name opens it through a five-minute link. A download whose application could not be saved (no number typed) is still filed, with no source.

## Tests

`AiaG702G703Modal.render.test.tsx`: each Generate files the workbook, the second one on its saved row, with the file's name, type and size.
