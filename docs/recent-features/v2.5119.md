# v2.5119 — Contracts: the link doors hand out the link an agreement already has (2026-10-09)

Punch list #104 (`to-dos/contract-copy-link-keeps-pdf-send.md`), fix (a). Built by PUNCHLIST Helper 14. Client only: no migration, no edge function.

## The bug

An agreement sent with **On paper → Email the PDF** reads `sent_channel = 'pdf_email'` and keeps a signing link ([v2.3631](v2.3631.md)). Four doors in the Contract window take `lastLink ?? invokeSend('link')`:

- **Copy link**
- **Text the link**
- **Sign here, now**
- the text-only branch of **Send a link**

With no link made in this session, each one called `send-job-contract` in link mode. That stamps `sent_channel: 'link'`, adds one to `send_count` and resets the reminders ([v2.3723](v2.3723.md)). After that, `isAwaitingPaperCopy` was false. **File the signed copy** disappeared, and filing the paper inserted a new signed row beside the one still out. [v2.5101](v2.5101.md)'s record cannot form then: the first signature through the link with the second on paper. It was found when v2.5101's live walk pressed Copy link.

## The fix

- **`jobContractLinkOnRow(row, origin, nowMs)`** (`src/lib/jobs/jobContractLifecycle.ts`) returns the link a sent agreement already carries, `jobContractSigningUrl(origin, public_token)`. That is the link the signed rail builds. It counts only while the row is out (`sent`, not voided), has a token, and the token has not expired. Each link send moves `public_token_expires_at` on, so a token can outlive its link. Every other row gets null:
  - a draft, even one carrying the token Void & redo moved onto it;
  - a voided or signed row;
  - a row with no token;
  - a lapsed link.
- **`linkToHandOut`** in the Contract window takes the link made this session, then the row's own link, and only then a send. All four doors use it. Handing out a link the row already has records nothing, so a PDF emailed to sign stays a PDF send.
- A row with no link of its own goes through `send-job-contract` as before, which mints or renews the link and stamps the send. That covers the draft rail's **Copy the link** and a lapsed link.
- **Send by email** is unchanged: it does send the link, so it still reads as a link send.

## Tests

- `jobContractLinkOnRow.test.ts` (new, 3): a sent row's own link, built as the signed rail builds it; no link for a draft carrying a moved token, a voided or signed row, or no token; none for a lapsed link.
- `JobContractModal.copyLink.render.test.tsx` (new, 2):
  - On a `pdf_email` row with a live token, Copy link copies `…/contract/sign?t=<token>` and invokes no function. It writes no `sent_channel`, and **File the signed copy** stays. This case fails on main, where Copy link copied the minted link and called the send.
  - With a lapsed token, Copy link goes through `send-job-contract` and copies the renewed link.

On a ZZ TEST job: send **Email the PDF** to our own address, press **Copy link**, then reload the window. The strip still reads *📎 PDF emailed to sign by hand*, the send count is unchanged and **File the signed copy** is there.
