# v2.5119 — Contracts: the link doors hand out the link an agreement already has (2026-10-09)

Punch list #104 (`to-dos/contract-copy-link-keeps-pdf-send.md`), fix (a). Built by PUNCHLIST Helper 14. Client only: no migration, no edge function.

## The bug

An agreement sent with **On paper → Email the PDF** reads `sent_channel = 'pdf_email'` and keeps a signing link ([v2.3631](v2.3631.md)). Five doors hand out that link:

- in the Contract window, **Copy link**, **Text the link**, **Open the signing page on this device** (`signInPerson`) and the text-only branch of **Send a link**, each through `lastLink ?? invokeSend('link')`;
- outside it, the Dashboard's **Hand the phone** (`openInPersonSigning`).

With no link made in the window's session, each one called `send-job-contract` in link mode. That stamps `sent_channel: 'link'`, adds one to `send_count` and resets the reminders ([v2.3723](v2.3723.md)). After that, `isAwaitingPaperCopy` was false. **File the signed copy** disappeared, and filing the paper inserted a new signed row beside the one still out. [v2.5101](v2.5101.md)'s record cannot form then: the first signature through the link with the second on paper. It was found when v2.5101's live walk pressed Copy link.

## The fix

- **`jobContractLinkOnRow(row, origin, nowMs)`** (`src/lib/jobs/jobContractLifecycle.ts`) returns the link a sent agreement already carries, `jobContractSigningUrl(origin, public_token)`. That is the link the signed rail builds. It counts only while the row is out (`sent`, not voided) and has a token with more than **`JOB_CONTRACT_LINK_HANDOUT_MARGIN_DAYS`** (7) left before `public_token_expires_at`. Each link send moves the expiry on by 90 days, so a link texted on day 88 would die on day 90. Inside the margin the door sends, which renews it. The margin also covers the office machine's clock against the server's. A link with no expiry counts as live, as `sign-job-contract` reads it. Every other row gets null:
  - a draft, even one carrying the token Void & redo moved onto it;
  - a voided or signed row;
  - a row with no token;
  - a link with a week or less left.
- **`linkToHandOut`** in the Contract window takes the link made this session, then the row's own link, and only then a send. Before handing out the row's own link it reads the row again (`freshJobContractLink`, `src/lib/jobs/jobContractLinkHandOut.ts`). Another tab may have voided it or moved its token to a new draft, and a stale row would hand out a dead link with no word to the office. On any doubt the door sends, and the send says what is wrong. All four window doors use it.
- **`openInPersonSigning`** (`src/lib/jobs/jobContractInPerson.ts`) reads the job's rows fresh. For a sent row with a live link it opens that link with the in-person flag and calls nothing.
- Handing out a link the row already has records nothing, so a PDF emailed to sign stays a PDF send. A row with no link of its own goes through `send-job-contract` as before, which mints or renews the link and stamps the send. That covers the draft rail's **Copy the link** and a link near its end.
- **Send a link**'s text-only branch belongs to the signing rail, which renders only for a draft. There the send still runs and records as before.
- **Send by email** is unchanged: it does send the link, so it still reads as a link send.

## Left on purpose

- **No trace for a hand-out.** Copying or texting a link the row already has records no event. Its send was recorded when it went out. A trace would need a new `job_contract_events` type, and so a migration. The existing `shared` type is not one to reuse: the customer journey counts every `shared` event as the signed copy emailed again. Card #104 names it.
- **`send-job-contract` itself** still re-stamps a sent row in link mode. The doors no longer ask it to while the link is live. A guard in the function would cover any door added later: return the URL without a stamp for a sent row with a live link. That is #104's follow-up and needs a deploy.

## Tests

- `jobContractLinkOnRow.test.ts` (new, 3): a sent row's own link, built as the signed rail builds it; no link for a draft carrying a moved token, a voided or signed row, or no token; the margin at its boundary (7 days and 1 ms hands out, 7 days exactly sends).
- `JobContractModal.copyLink.render.test.tsx` (new, 5):
  - On a `pdf_email` row with a live token, Copy link copies `…/contract/sign?t=<token>` and invokes no function. It writes no `sent_channel`, and **File the signed copy** stays. This case fails on main, where Copy link copied the minted link and called the send.
  - **Text the link** and **Open the signing page on this device** hand out the same link (`&inperson=1` on the second) and send nothing.
  - A link with three days left goes through `send-job-contract` and copies the renewed link.
  - A row another tab voided after the window loaded goes through the send, never its old link.
  - A draft carrying a moved token, from the rail's **Copy the link**, still sends.
- `jobContractInPerson.handOut.test.ts` (new, 2): the in-person door opens a sent row's live link with no send, and sends for a link with five days left.
