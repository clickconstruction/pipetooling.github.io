# v2.7743 — Lien receipts: a wrong receipt taken off goes to Drive's trash, and you can put it back (2026-11-18)

The second half of the owner's ask of 2026-11-17 ("a press that clears a wrong receipt photo without a retake, or remove or delete a wrong file from the drive"). v2.7699 built Drive's trash door and put it on the mailed copy. This change puts the receipt press (**Take off** and **Replace**, v2.7688) through the same door. No function change and no migration.

**What the press does now.** `LienReceiptPhotoPress`:
- **Take off** forgets the link first (the caller's `onTakeOff`), waits for that write, then asks `takeFileToTrash(jobId, driveFileIdOfUrl(url))`. The line under the press is the mailed copy's line (`fileTakenOffWords`): *Taken off. The file is in Drive's trash.* with **Put it back**, or *Taken off. The file stays in Drive.* with the reason and, where a second try can help, **Try again**.
- **Put it back** untrashes the file when it was trashed (`untrashJobFolderFile`), then hands the link to `onSaved`, so the record names the file again. A file that came out of the trash and did not reach the record reads as in Drive, with both presses still offered.
- **Replace** saves the new file, waits for `onSaved`, then sends the old file to the trash and says *The old one went to Drive's trash.* or *The old one stays in Drive.* with the reason. It offers no **Put it back**: the record names the new file, and Drive keeps the old one 30 days.
- The ask reads *Take this receipt off? The file goes to Drive's trash. Drive keeps it there 30 days.* (`LIEN_RECEIPT_WORDS.takeOffAsk`, ending in `TAKE_OFF_FILE_WORDS.askTail`). A link that is not a Drive file's asks *Take this receipt off?* alone (`lienReceiptTakeOffAsk`), is only forgotten, and draws no line.
- The clerk's stamped page is not a receipt. A new photo of it leaves the old file alone.

**The race this closes.** `drive-link` refuses a trash with *A lien record still uses it.* while any lien row of the job names the file. `onTakeOff` and `onSaved` were fire-and-forget, so the trash call could arrive before the write. Both props are now `void | Promise<void>`, and the press awaits them. A caller whose write did not land rejects after it has said why in its own words; the press then leaves the file where it is and adds nothing.

**Each caller, and which kind it is.**

| Caller | Kind | What changed |
|---|---|---|
| `LienServeWindow` (*Filed liens: copies to mail*) | writes the filing at once | `keepCopy` answers whether the filing took it. `setReceipt` sets the draft, awaits `keepCopy` and rejects when the write failed. It did `void keepCopy(...)`. |
| `LienFilingMailProof` through `LienMailProofBlock` (**What went out**) | writes the filing at once | `receipts.onSet` answers the promise of `setReceipt`, which rethrows after its toast. Its toast no longer says the file is still in the folder. |
| `LienFilingTabs` service step, phone sheet and computer box | a form seeded from the filing | New `setServiceReceipt`: a receipt the filing already holds comes off the filing now, or gives way to the new one there (`keepLienCopyProof`). Without that the trash would always be refused for a saved receipt. A receipt added in the form alone waits for **Record service**, as before. |
| `LienFilingTabs` § 53.056 sends (`noticeReceiptPhoto`) | form state only | Nothing. No record names the file until **Record**. |
| `LienDeskRunModal` through `LienRunChecklist` (`receiptFor`) | form state only | Nothing. The run writes the receipt with the send. |
| `LienFilingTabs` clerk's page | form state only, not a receipt | Nothing, and no trash. |

**Not in this change.** A **Put it back** after **Replace**. A take-off whose write failed leaves the file in Drive when **Record** later writes the draft. Receipts taken off before today stay where they are.

**Tests.** `LienReceiptPhotoPress.render.test.tsx` (the write is awaited before the trash; the line; **Put it back**; a refusal with its reason; **Try again**; a write that did not land; **Replace**, both outcomes; a link that is not Drive's; the clerk's page), `lienReceiptFile.test.ts` (the ask), two cases each in `LienServeWindow.render.test.tsx`, `LienFilingMailProof.render.test.tsx` and `LienFilingTabs.serviceProof.render.test.tsx` (the order of write and trash, and a failed write).

**Deploy.** None. The door is `drive-link`'s `trash` and `untrash`, live since v2.7699.
