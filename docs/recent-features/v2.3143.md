# v2.3143 — Won → Dispatch opens the job: the hand-off to-do (2026-09-07)

Client only — no migration, no edge function. Owner's ask: "If a role cannot create jobs maybe we should send a to do to dispatch where it is easy as the dispatch clicking one button on the dispatch inbox to make that job." Designed, critiqued and mocked up before the build (mock-up artifact *Won → Dispatch opens the job*, 2026-09-07); the decisions are recorded below so the mock-up need not be kept.

## What we weighed

| Option | Verdict |
|---|---|
| Create the job automatically on Won | Rejected — a job needs a human call on the price ("carry $48,200 over?"), the winning GC and the crew; v2.2838 added a guard against silent auto-creates for a reason. |
| A derived "won bids with no job yet" list | Not instead of this — no owner, no push, nothing to dismiss. A Dashboard safety-net card remains a candidate later. |
| A checklist task | Task Dispatch requests already carry a bid, a `pending_action`, push, thread notes and a close note, and four one-button actions ride on them today. Same rail, one more action. |
| **A `dispatch_requests` row with `pending_action = 'open_job_from_bid'`** | **Built.** |

**The role matrix is narrower than the premise.** Who can mark a bid Won (`bids` update policy): dev, master, assistant, estimator, **primary**. Who has the New Job door (`wonMomentActions`): dev, master, assistant, controller, estimator. So **primary is the only role that can win a bid and not open the job**; superintendents cannot mark Won at all. The automatic send is for primary; for everyone else the value is the hand-off button.

## What shipped

- **Kernel** [`wonDispatchHandoff.ts`](../../src/lib/bids/wonDispatchHandoff.ts) (12 tests): `OPEN_JOB_FROM_BID_ACTION`, the title (*Open the job for B398 · ZZ Test — won with Southern Post Construction*), the `reference_summary` (*B398 · ZZ Test — address*), the close note (*J1007 opened from B398 · ZZ Test*, or *… was opened from B398 elsewhere — nothing left to do*), `decideWonHandoff` (a job already on the bid beats an open request; an open request means already asked), `shouldAutoAskDispatchOnWon` (auto mode + the transition INTO won only), the *Dispatch asked · by Wendi · 2 min ago* chip label, and the sweep pickers. `wonMomentActions.ts` gained `wonHandoffMode(role)` → `button` (has the door) / `auto` (primary) / `none`, and a new `ask_dispatch` action: quiet beside "Open the job", primary for `auto`, absent while `dispatchAsked`.
- **Writes** [`openJobFromBidDispatchRequest.ts`](../../src/lib/bids/openJobFromBidDispatchRequest.ts): `askDispatchToOpenJob` reads the bid, dedupes on an open to-do for the bid and on a job already carrying it, then `createDispatchRequest` (push via `notify-dispatch-request` as every request). `closeOpenJobFromBidRequests` closes the bid's open rows with the note and tells each requester through `notifyDispatchRequestClosure`; zero rows for a role RLS keeps from updating is fine — the inbox sweep closes those.
- **The bid** — [`BidWonJobActions`](../../src/components/bids/BidWonJobActions.tsx) (full variant: Edit Bid's Job block, Waiting to hear's win strip): the ask button, and while the to-do is open an amber **Dispatch asked** chip in its place ([`useOpenJobFromBidRequest`](../../src/hooks/useOpenJobFromBidRequest.ts), fail-soft, refetches on `DISPATCH_REQUESTS_CHANGED_EVENT` / `JOB_CREATED_FROM_BID_EVENT`). The board's compact link is unchanged (one query per bid stays one).
- **The inbox** — [`DispatchInboxSection`](../../src/components/DispatchInboxSection.tsx) renders **Open the job** on an open `open_job_from_bid` row (`useJobFormModal().openNewJob({ prefillBidId })`, so every host — Dashboard Teams inbox, Dispatch Mode → Inbox, Checklist → Review, Quickfill — gets it without new props); `useDispatchInbox` now selects `bid_id` and runs a second self-heal sweep: open to-dos whose bid already carries a `jobs_ledger` row close with the *elsewhere* note.
- **The job form** — after the insert that fires `JOB_CREATED_FROM_BID_EVENT`, `closeOpenJobFromBidRequests({ elsewhere: false })` with the new J number.
- **The automatic send** — `Bids.tsx` `autosaveBid`: when the outcome write is the transition into Won and `shouldAutoAskDispatchOnWon` says so, the to-do is filed silently and one toast says *Dispatch has been asked to open the job from this bid.*
