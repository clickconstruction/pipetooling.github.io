# v2.3234 — Record your best effort, then open the robot's envelope (2026-09-10)

Migration `20260910210000_bid_best_efforts.sql` (client first, then `supabase db push`); no edge function change. Grace's thesis, after v2.3222 opened the envelope at send: "have it reveal when the user gets to the cover letter stage and is past pricing … record best effort before sending off to unlock robot. This is the moment in time when the user has the most information about the bid and can answer all of the robots' questions the most accurately and is also in a position where they can receive the most benefit." Mockup and the "is this the best we can do" pass: https://claude.ai/code/artifact/3088fe43-6dce-4b87-b4d7-0981073019ff.

**Owner decision this touches (flag for Robert):** the robots are now scored against the recorded best effort where one exists — robot-blind against human-blind — and against the sent value where none does. Gate B measures the same thing it did on every run without a record; with a record it measures a cleaner reference. The seal is not loosened: the reveal still follows a human number going on the record, only the record moves earlier.

## Why earlier

At send, the robot can only teach. Before send it can still change the bid, and what it changed becomes measurable: the best effort is the blind number, the sent value is the number after the reveal, and their gap per bid is what the robot was worth. The two rules that make it safe: the robots never read the record (its own table, closed to twin accounts; the scorer reads it as definer), and first record wins (insert-only for staff — a number re-recorded after the reveal would be the anchoring the seal exists to prevent). The first sketch put the number on the bid row and added an ordering rule to the scorer; both were wrong (the column leaks to the robot, the rule punishes a robot that was merely late), so the table and a lock-time trigger replace them.

## What shipped

- **Schema** ([`docs/migrations/20260910210000_bid_best_efforts.md`](../migrations/20260910210000_bid_best_efforts.md)): `bid_best_efforts` (one row per bid, value / recorded_at / recorded_by / note; robot-audit roles read + insert with `recorded_by = auth.uid()`; no update or delete; a RESTRICTIVE `NOT is_digital_twin()` policy), `twin_shadow_runs.reference_kind`, `score_locked_shadows` preferring the best effort (teacher = estimator → recorder → attested sender → creator; the scorecard note says *best effort $X (recorded before the reveal, unsent)* or *$X (sent)*), two new triggers into it (on the record's insert; on the run's lock), and `list_shadow_runs()` recreated with `reference_kind`.
- **Kernel** [`src/lib/bids/bestEffort.ts`](../../src/lib/bids/bestEffort.ts) (+9 tests): `bestEffortCardMode` (record · recorded · hidden — sent without a record, opted out, no amount), `bestEffortRecordNote`, `bestEffortGap` / `bestEffortGapNote`, `bestEffortStamp`, `summarizeBestEffortMoves`.
- **The Cover Letter card** [`BidBestEffortCard.tsx`](../../src/components/bids/BidBestEffortCard.tsx), rendered by [`BidsCoverLetterTab`](../../src/components/bids/BidsCoverLetterTab.tsx) between the letter's amount and Mark sent (single-GC letters): **Record best effort · open the robot's envelope** with the letter's proposed amount; the line under it says whether the robot has sealed, is still estimating, or has not run. The record inserts the row, leaves a `[best effort]` ledger note, and stamps the bid reviewed (`buildBidReviewPatch`, the flow's Review step) when it was not. Once recorded: the number, its stamp (*best effort 9/10 · Wendi*), and **Open the robot's envelope** when the run has scored, else the waiting line. Hidden on sent bids without a record and on opted-out bids; hidden entirely when the table is not deployed yet.
- **The envelope** ([`robotEnvelope.ts`](../../src/lib/bids/robotEnvelope.ts), [`RobotEnvelopeModal`](../../src/components/bids/RobotEnvelopeModal.tsx)): `envelopeRefusal` accepts a recorded best effort in place of sent-with-value; `EnvelopeRun.scoredAgainst`; the KPI reads *Ours · best effort* / *Ours · sent*, and the header line on a live bid says the bid can still change — that is the point. `Bids.tsx` → `offerRobotEnvelope` reads the record; the Cover Letter's `onBestEffortRecorded` / `onOpenRobotEnvelope` open it; a mirror row scored against the best effort opens it before send.
- **At send** (`Bids.tsx` → `noteBestEffortGap`, called from the Cover Letter's Mark sent through `onBidSentRecorded`): when the sent value differs from the record, one `[best effort gap]` note on the bid — *Sent $151,400 against a best effort of $148,200 (+$3,200, +2.2%) — the change after the robot's envelope · robot had $171,940*. Once per bid.
- **The Robot Board** ([`robotMirror.ts`](../../src/lib/bids/robotMirror.ts) +2 tests, [`BidsRobotMirrorTab`](../../src/components/bids/BidsRobotMirrorTab.tsx)): rows carry `bestEffort` and `gap`; runs carry `scoredAgainst`; the mirror carries `moved`. **Ours** shows *$148,200* with *best effort 9/10 · not sent yet* on a live bid, *$148,200 → $151,400* with *+$3,200 after the reveal* once sent, and a scored live row now shows the robot's number (the seal held: the human number was on record first). The strip gains *N bids moved after the robot's envelope · $X* when any did, and the sealed pill reads *waiting on your number*.

## Not changed

- Bids sent without a record: the v2.3126 send trigger scores against the sent value, the envelope opens at send (v2.3222), exactly as before.
- Backtests (decided bids already have a sent value), multi-GC letters (the card waits for the single-letter case to prove itself), the Mark reviewed door on the flow strip (still there; recording a best effort stamps it too).
- Twin-mcp's manual `score_shadows` still scores against the sent value; the DB triggers run first, so it finds nothing to score on recorded bids.
