# v2.5111 — Bid room: a signed room still names the alternate the GC took (2026-10-09)

Client only. No migration, no edge function, nothing to deploy beyond the client. Found while building punch list #103's PR 1 (v2.5105), when the sample room was first signed in `sign-bid-room`'s own shape.

## What was wrong

The bid room's *Signed by …* line names the option and every with-and-without alternate the GC took (v2.4197). `BidRoom.tsx` read the names from `outcome.metadata.add_on_names`. Only the page's own just-signed state ever set that key. `sign-bid-room` saves the names on the signed event as `add_ons_taken`, beside `add_on_keys`, and `get-bid-proposal-room` serves that metadata as saved. Both shipped in the same commit (v2.4211, 2026-09-30) under different keys.

So the line was right only until the GC reloaded. A GC who took *Alternate 1 — Break room* and opened the link again read *Signed by Dana Ruiz — “To Plans” · $16,800.00.* The total counted the alternate, but its name was gone.

Read on prod 2026-10-09, read-only, counts only: one proposal has ever been signed in a bid room, and it took no add-on. No row carries `add_on_names`. Nobody has seen the dropped name yet.

## What changed

`src/pages/BidRoom.tsx` reads `add_ons_taken`, the key `sign-bid-room` saves. The page's just-signed state writes the same key, so one key serves both the moment of signing and every reopen. `sign-bid-room` is unchanged: the page reads what is saved.

## Tests

`src/pages/BidRoom.render.test.tsx` (+1): a room served with a signed event, key for key as `sign-bid-room` writes it, reads *Signed by Dana Ruiz — “To Plans” with Alternate 1 — Break room · $16,800.00*. It was red on `main` before the change. The add-on test that signs in the page still reads the name.
