# v2.8557 — Word to every trade: a send that fails says the mail service's reason (2026-11-24)

Punch list #205, from its two live checks tried on 2026-11-24. Client only. No migration, no edge function.

## What was wrong

**Word to every trade** was pressed twice on the test project and the test trade company, and both times the window read *The email did not go out. Try again in a minute.* The function `gc-trade-email` had passed the mail service's own reason back in `detail`. The press dropped it (`wordToTradesIo.ts` read the refusal's key alone), so nobody could tell a bad address from a service that was down.

## What changed

- `src/lib/gc/tradeEmail.ts`: `gcTradeEmailRefusalWords(answer)`, new and pure. For a send the service refused (`sendFailed`) with a reason, it answers *The email did not go out. The mail service said:* and the reason, on one line, cut at 200 characters. Every other refusal reads as it did.
- `src/lib/gc/wordToTradesIo.ts` uses it for each company a word did not reach.

## What this does not mend

Read in the code the same day, and not built here, since each needs the function changed and deployed:

- The word goes as **one** email, the company's main contact on *To* and its other people on *CC* (`gc-trade-email`, `_shared/gcTradeEmail.ts`). One address the service refuses fails the whole send, and no row is written to `gc_trade_messages`.
- The test company's main contact is on example.com and gets all four kinds of mail, so it is on *To* whoever else is added. That is the likely cause of both failed tries. The service's reason was never seen, because it was dropped. With this change the next try shows it.
- Nothing skips a placeholder address before a send, and the function logs no failed send.

## Tests

`gcTradeEmail.test.ts`: the reason on one line, the cut at 200 characters, the old words when no reason came, and no reason shown for any other refusal.
