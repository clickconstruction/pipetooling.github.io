# v2.7655 — Trips: a place to keep a trip (2026-11-17)

Punch list #379, PR 2 of nine: the table. One migration, its doc, its SQL bed. No client code and no edge function. The migration is not pushed by this PR.

## What landed

- `supabase/migrations/20261117234500_trips.sql`: four tables (`trips`, `trip_people`, `trip_jobs`, `trip_dismissals`), their row security, and one write door, `trip_save(p, p_dry_run)`. The whole of it is in [`docs/migrations/20261117234500_trips.md`](../migrations/20261117234500_trips.md).
- A person's days are one `jsonb` object of day to kind on `trip_people.days`, checked by `trip_days_ok`. Where a trip stands is never stored; the kernel of v2.7653 reads it.
- `trips_office()` names who reads and changes every trip: the Development page's office door. A person on a trip reads it through `trip_is_mine`.
- `supabase/tests/trips/20_scenario.sql` with `scripts/pgtest-trips.sh`, a line in `scripts/sql-beds.txt` and `npm run test:pg:trips`.
- `docs/ACCESS_CONTROL.md` gains *Trips*.

## One table past the card

The card names a trip, its people with their days, and its jobs. This migration also makes `trip_dismissals`, the days somebody said were *Not a trip*. PR 5's finder needs it, and one migration against the live database is better than two.
