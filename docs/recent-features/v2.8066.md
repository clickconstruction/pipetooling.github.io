# v2.8066 — Document builder: a draft that did not save says so, and a save that lands after you leave is kept (2026-11-20)

Punch list #404, found by the audit of 2026-11-20. No migration and no function. Two faults in the save both builders run a moment (0.7 s) after the typing rests.

## The two scenarios

1. **A failed save read *Draft saved*.** A dev types on the Sub NDA and the save is refused. The reason showed, but the bar still read *Draft saved* beside it, and the next keystroke cleared the reason. The guides tell the reader to wait for *Draft saved*, so a dev who did left, and the words were lost. Nothing sent the failed draft again either: leaving the builder only sends a save that is still waiting on its 0.7 s.
2. **A save that landed after the dev left was thrown away on this side.** Type on the Sub NDA and press **‹ Document builder** within a second. Leaving sends the save and it lands on the server. The editor was gone by then, and the save stopped at "the editor is gone" before it handed the saved row up to the tab. The tab reads the rows once and keeps them, so **Open** drew the editor from the old row: the typed words were missing on the screen, and the next keystroke saved the old draft over them.

## Which save had which fault

| Save | Read *Draft saved* after a failure | Dropped a save that landed after leaving |
|---|---|---|
| The Sub NDA's draft (`WalkedBuilder`) | Yes | Yes |
| The usual sheet's draft (`FilledBuilder`) | Yes | No. It already handed the row up whether or not the builder was still open. |
| A job's sheet's draft (`FilledBuilder`) | Yes | No. Nothing above the builder holds a job's sheet. The builder reads the sheets again each time it opens. |

## The fix

- **A third save state, `failed`.** The bar reads **Draft not saved** in the refusal's red (`var(--text-red-700)`). The refusal line keeps the reason, which the io layer already words through `formatErrorMessage`.
- **It holds until a later save lands.** Typing again does not turn the bar back to *Saving the draft…*: it reads *Draft not saved* until a save lands, then *Draft saved*. On the filled builder the bar speaks for the usual and every job's sheet together, so it reads *Draft not saved* while any one of them is not saved.
- **A failed draft is sent again by the next keystroke and by leaving.** There is no retry press. An `unsaved` ref is set when a save does not land, and cleared when a save is asked for again and when one lands. The flush that leaving and Publish run sends an `unsaved` draft as well as one still waiting on its 0.7 s. The filled builder keeps one per thing saved, beside its `pending` map. A ref cleared only on a landed save was the other choice. It was passed over because a flush during a save already on its way would send the same draft twice.
- **The saved row goes up whether or not the editor is still there.** In `WalkedBuilder` the `onRecord` call now runs before the `here.current` check. Only the editor's own `setRefusal` and `setSaveState` stay behind it. The tab's `onRecord` is a `setRecords` with an updater and the tab is still mounted when a builder is closed, so the late call is safe.
- The 0.7 s, the publish paths and the read mark are unchanged.

## What it does not do

- A save that fails after the builder is left has nobody to tell and is not sent a third time.
- A publish writes the draft too. A publish that lands right after a failed save leaves the bar on *Draft not saved* until the next typing.
- **Open** pressed again before the save has landed still draws the old row. The window is one round trip to the server.
