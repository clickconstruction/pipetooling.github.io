# v2.2185 — Partner nav cache is per user (2026-08-23)

Found testing Bryan-as-primary on prod through the dev "imitate" hand-off in Chrome: the
Dashboard "Your statement" card was right but the Statement icon was missing — the nav cache
(`useIsPartner`, v2.2165) had been written as `isPartner:false` while the tab was still the
dev's session, and Bryan inherited that negative for ten minutes because the cache wasn't
keyed by user (sessionStorage is per tab, not per account).

- [`partnerNavStatus.ts`](../../src/lib/partnerLedger/partnerNavStatus.ts): cache entry
  carries `uid`; `parsePartnerNavCache(raw, now, uid)` ignores another user's entry (key bumped
  to `partner_nav_status_v2` so stale v1 entries are simply ignored). Test added.
- [`useIsPartner(role, userId)`](../../src/hooks/useIsPartner.ts): reads/writes the cache for
  the signed-in user id and refetches when the user changes; `Layout.tsx` passes `authUser?.id`.
