# v2.7572 — Short Dashboard: the bar's Dashboard tab opens the short page (2026-11-17)

Punch list #365, the first half of PR 4. Client only. No migration and no edge function.

## What was wrong

A leader's Dispatch Mode is on unless he turns it off (`useDispatchModeEnabled` defaults it on for `master_technician`). With it on, the bottom bar's **Dashboard** tab opened `/dispatch-mode`, the Dispatch home. The app opens on `/dashboard`, where the short page is drawn (v2.7466). So a leader on Short had two homes: the short page on open, and a different, full page behind the tab named Dashboard.

## What landed

- `DispatchModeFooter` takes `shortHome`. With it, the fixed bar's Dashboard tab goes to `SHORT_DASHBOARD_PATH` (`/dashboard`), and that page lights the tab. `Layout.tsx` sets it from `useDashboardView` and `canHaveShortDashboard`, the same two the page reads.
- The press carries `SHORT_DASHBOARD_HOME_STATE` in the navigation's state. `Dashboard.tsx` reads it (`isShortDashboardHomePress`) and leaves **Everything else**, so the tab is the way home from the full page too. Only that press carries the mark: a link or a query change on the full page does not send him back.
- Job Mode's bar already opened `/dashboard`, and its card still comes first on that page. The assistant's phone dock is untouched: its slots are her own.

Nobody is on Short today, so nobody's bar changes with this PR.
