## Where it went, and why

The map files the picker with the modes ("Move with (or into) the modes hook"). The picker's open, intent and cell already went into the modes hook in v2.4986, because the picker is a mode. Its list is not part of the exclusion rule, so it went *beside* that hook rather than into it. That keeps the one owner of exclusion about exclusion.

**`src/hooks/useScheduleDispatchAssignJobPicker.tsx`** (new, 156 lines; `.tsx` because a subtitle is JSX) takes these from `ScheduleDispatchHubPage.tsx`, verbatim:

- the search, the number query and the money-rail evidence map
- the job rows and bid rows they narrow
- the evidence effect: only while the picker is open over 1 to 30 rows, after 250 ms, only for rows it has not seen, failure-silent
- the same-address notice
- both subtitles
- `onPickerOpened`, the reset to empty

## The guard rails

- The hook owns no mode. It reads whether the picker is open, why and for which cell from the modes hook.
- The modes hook resets the list as it opens the picker, so it reaches `onPickerOpened` through a bridge.
  - The bridge is a ref the page fills right after the list hook, as v2.4992 did for the add-block window.
  - The modes hook only calls it from event handlers.
- The page reads the same names as before. The two text setters it gets back take a value, not an updater.

`ScheduleDispatchHubPage.tsx` goes from 1,262 to 1,190 lines.
