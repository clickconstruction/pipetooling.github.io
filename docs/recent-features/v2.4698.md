# v2.4698 — Release of Lien: a draft keeps the leader you picked to sign (2026-10-06)

Punch list #87, item N (`to-dos/lien-screens-stale-words.md`), found by the second read of [v2.4679](v2.4679.md). Client only: no migration (`job_lien_releases.signer_user_id` already exists), no edge function.

## What changed

- **The draft saves its Signs pick.** `buildRowPayload` in [`LienReleaseModal`](../../src/components/jobs/LienReleaseModal.tsx) (the autosave's and the mint's shared payload) now carries `signer_user_id`: the pick, else the row's saved leader. Picking a leader in **Signs** counts as an edit, so a pick alone autosaves. Before, only a signature request or a signature wrote the column, so a draft whose saved Signed by line named one leader reopened with the job's default in the pick, and **Send it to his desk** asked the default leader to sign a page that printed the other's name.
- **A resumed draft opens on its saved leader.** The resume effect seeds the pick from a draft's `signer_user_id`, as v2.4679 did for a waiting request. A draft that **Cancel request** turned back, which kept the asked leader's id, now reopens on him too.
- **A saved leader off the list gives way.** When the saved leader has been archived or is no longer a leader, the pick falls back to the job's default: in the resume effect when the leaders list is already loaded, else in the masters effect, which reads the row through `releaseRowRef`. A waiting request's asked leader still stays, named from his own row (#87 M).
- **On a draft the pick rules.** `signerOfRecord` read the row's `signer_user_id` first; a draft's saved id trails the pick, since the autosave reads nothing back. On a draft the pick is the signer of record; on a minted row the column still is.
- A leader's list (`useLienSignatureLanes`) reads only waiting and signed rows, so a draft with a saved leader appears in no one's queue.

## Guides

*give a customer a lien release* and *send a GC our lien waiver* say a draft you come back to keeps the leader you picked. The map `docs/LIEN_RELEASE_MODAL_ARCHITECTURE.md` carries the resume and who-signs changes.
