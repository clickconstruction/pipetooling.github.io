# v2.1901 — Roadmap: the task modal becomes a task card with the live conversation (2026-08-20)

Owner ask: on the Roadmap, long-pressing a task only offered the Edit form — "I don't have the ability to see updates or add comments." The Edit-task modal is replaced by `ChecklistTechTreeTaskCardModal`: it leads with the stage name, the task title, status chips (on list / in review / signed off + assignee names), then the **activity thread** read from the bridged checklist instance's events spine (`checklist_instance_events`) with a note composer — comments posted here land on the exact card the assignee sees on Today, and vice versa. "Open on the checklist ↗" jumps to the Today tab (new optional `onOpenTodayTab` prop threaded from `Checklist.tsx`). Title/assignee editing folds into a collapsed "Edit task" section shown only to structure editors, so the destructive path is no longer the *only* path.

Everyone can now open the card — the long-press (and its `openEditTask` handler) no longer gates on `canEditStructure`; the edit section self-gates instead. Unbridged tasks (no assignee, or locked stage) show the nudge "Not on anyone's list yet — assign someone and this task lands on their list when the stage unlocks" instead of a thread. `BridgeState` gains `instanceId` (bridge query now selects `checklist_instances(id, …)`) to feed the thread fetch. `ChecklistTechTreeAddTaskModal` returns to add-only (its edit-mode props are unused). Client-only — no migration; comment inserts ride the existing insert-own-comments RLS, and non-office viewers see only the events their RLS allows (same rule as the review queue).

Verified live from a worktree dev server against the Default roadmap: bridged task shows chips + composer + Open link with the edit section prefilled (18 users, Robert checked); unassigned Collect-artifacts task shows the assign nudge with no composer. 6 new render smokes in `ChecklistTechTreeTaskCardModal.render.test.tsx`; full suite green.
