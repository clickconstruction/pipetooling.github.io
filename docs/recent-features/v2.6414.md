# v2.6414 — Signed hours statement: the dev MCP's verbs (punch list #212, PR 5) (2026-11-03)

The last of the five PRs on the card (`to-dos/signed-hours-statement/README.md`): PR 1 (v2.6069) the kernel and the print, PR 2 (v2.6097) the window and the table, PR 3 (v2.6411) the signing, PR 4 (v2.6413) the matter. This one is the owner's ask of 2026-10-29, *"I would like this accessible via MCP"*: a dev's agent reads a statement's rows, makes one, sends it and files the signed copy on a matter, through the dev seat (server 0.18.0).

## What changed

- **`get_hours_statement(job, person, from, to, with_pay?, add_stated_block?)`** (`_shared/devMcpHoursStatement.ts`): a composite over the door as the reader — the Hours statement window's own reads, each catalog-checked (the sessions on the job in the span with their approver, the roster row, the office job's setting, the app's first clock day, the typed days; with the pay, the pay config, the pay reports touching the span with their days, deductions, additional lines and payments) — handed to the shared kernel `buildHoursStatement`, so the answer is the paper: the groups by week, the totals, the pay lines, the gap, the stated block and the attestation, with `reading` first (*118.5 h on 23 days, 4 weeks paid in full; nothing in the app before 2026-03-12, so … is the worker's own statement*), the counts, and `statements_made` (the statements already made for that job and person, with their state). The job and the person resolve by id or by what `find_job` / `find_person` resolve to one; the span is cut at the door's 200 rows and the reading says so. `hoursStatementStanding` moved into the shared kernel so the server and the window name a worker's standing the same way.
- **`plan_hours_statement(statement)` → `apply_hours_statement(statement, plan_hash)`** on `WRITE_VERBS` over `dev_hours_statement_write` (migration `20261103003000_dev_hours_statement_write.sql`, `docs/migrations/…`), modeled on `dev_legal_statement_write`. The server shapes the agent's `statement` first (`prepareHoursStatementWrite`): **make** resolves the job and the worker, reads the clock into the snapshot the window saves (`stated_days` the office states from outside records parsed by the signing's own kernel, each marked *stated by <dev>, <today> · <source>*), and plans the row — the wrapper's dry run names the record id it would take (`HS-<job>-<n>`, minted in SQL as the window mints it), the job's live statement count and the row as it would be written, the caller as the preparer whatever the payload says; the plan hash commits to the snapshot, so a clock that moved refuses the apply. At apply the snapshot's as-of is stamped after the hash check and the row lands as a draft; with `send: { how: 'email' | 'link' }` the server then runs the window's two calls as the dev (`invokeAsDev`: `hours-statement-signing` prepare, `send-contract-for-signature` by email to the roster address or `mode: 'link'`), marks the row sent through the wrapper's `mark_sent` (the server's own step, never an agent's) and answers `signing` — the link in the reply, never in the call log, which keeps args and the target alone; a leg that fails leaves the row a draft and says why. **file_on_matter** reads a signed statement's PDF through `open-contract-form-pdf`'s gate into the file facts the document wrapper checks (the plan commits to them), and at apply stores it under the matter as the dev before the row, writes the Evidence row through the live `dev_legal_document_write` and ties the statement to it — what the Legal desk's Add to evidence does, the title and the shows line from `_shared/hoursStatementEvidenceWords.ts`, where PR 4's words moved so both name a copy the same way. A statement not signed, with no signed copy or on a matter already is refused in words; `view_as` refuses the writes as every write.
- **The server** (`dev-mcp/index.ts`, 0.18.0): the three tools, the composite case, the write labels in the write branch, the prepare and file legs, the send leg, the instructions' counts (thirty-five verbs over twelve RPCs; v2.6367's Materials verbs took 0.16.0 and v2.6422's get_person_file 0.17.0 while this PR waited in the queue). The catalog is rebuilt: `EDGE_FUNCTIONS` lists `hours-statement-signing` for `check_edge_boot`.
- **Docs**: `docs/dev-mcp/README.md` (the two rows, the counts), `docs/EDGE_FUNCTIONS.md` → dev-mcp, `AGENTS.md`, the migration's fragment; the card reads PR 5 built with what is left.
