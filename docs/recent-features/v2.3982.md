# v2.3982 — Bids: Last contact no longer opens Followup for roles that cannot open it (2026-09-27)

Client only; no migration, no edge function. A role-gate gap found during punch list **#46** row 5 (the Bids.tsx second pass); fixed on its own, outside the decomposition.

## The gap

`src/lib/bids/bidsTabAccess.ts` says a `primary` opens four Bids tabs (journey map P-B1/P-B2/P-B3) and a `superintendent` is turned away from `submission-followup` (v2.2882). The URL router enforces that for `?tab=` links. Two doors set the tab by React state and never reached the router:

- the Bid Board's **Last contact** cell and the phone card's "· Last contact" (`onLastContactClick` → `handleLastContactClick`) — drawn for every role that reads the board, so for a primary and a superintendent;
- Followup → By builder's **View submissions** glass (`onViewSubmissions`) — By builder is the one Followup lens a superintendent keeps.

Either click landed on Submission & Followup (By status); a primary also got the full Followup lens bar. RLS still limited the rows — this was a gate the page did not draw, not a data leak.

## The fix

`src/pages/Bids.tsx` hands each door to its child only when `bidsTabOpenFor('submission-followup', myRole)` — the shape `onLinkJobToBid` already has, and the way the board treats its other office-only pieces for these roles (`showEstimatingHealth`, `canSeePricingTabs`: not drawn, rather than drawn and refused). Both doors now share `handleLastContactClick`.

- `BidsBidBoardTab`: `onLastContactClick` is optional. Without it the cell and the phone card show the date and the days since as text; a bid with no contact shows nothing where the `+` was.
- `BidsBuilderReviewTab`: `onViewSubmissions` is optional. Without it the glass is not drawn.

The kernel is untouched: its matrix stays the one statement of who opens what.

## Checked, and left alone

The page's other state-set tab changes either write `?tab=` as well (so the router's gate runs: `openCountsForBid`, `openBuilderLensForCustomer`, `selectBidsTab`) or start inside a lens these roles cannot reach.

## Tests

`src/pages/Bids.followupDoors.render.test.tsx` (14 cases) mounts the page with one bid under one builder, for every Bids role: the door is drawn exactly when `bidsTabOpenFor('submission-followup', role)`, a click lands on By status, and the date stays readable when the door is not drawn. Run against the code before the fix, the primary and superintendent cases failed — three of them, the gap as reported.

## Docs

`docs/ACCESS_CONTROL.md` said a primary has "all tabs" on Bids; it now names the four, and the superintendent's line names the two doors. One sentence each in `docs/BIDS_TABS_ARCHITECTURE.md`, `docs/BIDS_BOARD_FORM_ARCHITECTURE.md` and `docs/BIDS_DOCUMENT_TABS_ARCHITECTURE.md`.
