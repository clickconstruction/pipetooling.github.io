# v2.2880 — Dispatch inbox badge counts open only; closing a request notifies the requester; Job Mode "My requests"; red-phone auto-close (2026-09-05)

Journey-map Phase 4, Tier-2 **#24** (C58 — the dispatch-inbox badge counts closed rows; J19-F1/F6/N1) and **#25** (C59 — closing a field request tells the tech nothing; J19-F2, J2-F4) from `pipetooling-journey-map` → `docs/JOURNEY_MAP.md` rows 24–25 / `docs/journeys/office-field-loop.md`. Client + one edge-function change; **no migration**.

## Why

The live walk (2026-09-03) found the Dispatch Mode footer badge reading **"7 unread"** while the Inbox page's own headers said Dispatch **3 open** · Estimator **1 open**: `DispatchModeFooterLive` summed `dispatchRequests.length + estimatorRequests.length`, and both arrays exclude only the *viewer's own* `dispatch_request_dismissals` — so every closed row nobody had dismissed inflated the badge (an assistant's read **35** over 3 open, with a 30-row closed backlog), each closed row had to be dismissed once per group member (5 today) to clear it everywhere, and the aria label said "unread" though nothing in the model is read/unread. Separately, "Add & Close" was a bare `dispatch_requests.update(...)`: `notify-dispatch-request` fired on create only, so the closing note — often written *to* the requester ("job done and billed 8/11") — reached no one; techs had no surface listing their own requests (Job Mode Inbox mounted the Settings push-log component verbatim → "No push notifications have been logged" on day one); and red-phone (`add_job_phone`) requests never auto-closed when the number was added — only `link_job_pictures` did.

## What changed

### #24 — badge = open only

- **Kernel** [`src/lib/dispatchInboxBadge.ts`](../../src/lib/dispatchInboxBadge.ts): `dispatchBadgeCount(rows)` (open only), `dispatchBadgeCounts(rows, dismissedIds)` → `{ open, closed }` where `open` ignores dismissal entirely and `closed` = closed rows this viewer hasn't dismissed (telemetry only — what the old badge over-counted), `addDispatchBadgeCounts`, `dispatchBadgeAriaLabel(n)` → **"N open"**, `dispatchBadgeShownTarget` → `#open=<n>&closed=<n>`. Tests [`dispatchInboxBadge.test.ts`](../../src/lib/dispatchInboxBadge.test.ts).
- [`useDispatchInbox`](../../src/hooks/useDispatchInbox.ts) and [`useEstimatorInbox`](../../src/hooks/useEstimatorInbox.ts) compute the counts from the **raw** row list *before* the dismissal filter and expose `dispatchBadgeCounts` / `estimatorBadgeCounts` (+ `dispatchRequestsLoaded`). The lists themselves still drop the viewer's dismissed rows.
- [`DispatchModeFooter.tsx`](../../src/components/dispatchMode/DispatchModeFooter.tsx): `DispatchModeFooterLive` badges `counts.open`; the badge's `aria-label`/`title` is `"N open"`.
- **Per-viewer dismissal is unchanged as a list-hygiene tool** (hides a closed row from *your* Dispatch section; archive still searchable) — it just has no effect on the badge any more. The "dismiss five times" ritual is retired without touching the table.
- **Telemetry** `dispatch_badge_shown{open, closed}` via `recordNavClick` (`ui_nav_clicks`, control `dispatch_badge_shown`, target `#open=3&closed=4`) — once per footer mount and again only when the pair changes, after the dispatch rows have loaded (never the 0/0 the first paint shows).

### #25 — close / reopen tells the requester

- **Kernel** [`src/lib/dispatchRequestClosure.ts`](../../src/lib/dispatchRequestClosure.ts): `requestClosureNotification(request, note, mode)` → the fn payload `{ dispatch_request_id, mode: 'closed'|'reopened', note }` (note trimmed, capped at 500), `recipientUserId`, and the push wording (`composeDispatchClosurePush`: title **"Dispatch answered"** / **"Dispatch reopened your request"**, body `Handled: <title> — <note>` / `Reopened: …`, capped at the fn's 220); `dispatchRequestClosedTarget(mode, notified)` → `#closed?notified=1`. `notifyDispatchRequestClosure(...)` is the fire-and-forget I/O wrapper: invokes the fn, then records **`dispatch_request_closed{notified}`** (control `dispatch_request_closed`). Tests [`dispatchRequestClosure.test.ts`](../../src/lib/dispatchRequestClosure.test.ts).
- [`useDispatchInbox`](../../src/hooks/useDispatchInbox.ts): `submitDispatchNoteAndClose` → after the close lands, `notifyDispatchRequestClosure(mode 'closed', note = the closing note)`; `submitDispatchNote` on a closed row (the "Send and reopen" path) → `mode 'reopened'`. The status update stays first and unchanged; the notification never blocks or fails it.
- **Edge function** [`notify-dispatch-request`](../../supabase/functions/notify-dispatch-request/index.ts) gains `mode` (default `'created'` = the existing group fan-out, author-only). `'closed' | 'reopened'`: caller must be a dispatch group member, a dev, or the row's `closed_by_user_id`; the **one recipient is `from_user_id`** — push to each of their `push_subscriptions` (`url: /job-mode/inbox`, `tag: dispatch-<id>-<mode>`) and **always** insert a `notification_history` row (`template_type` `dispatch_request_closed` / `dispatch_request_reopened`, `channel: push`) so the answer is on record for people who never enabled push (masters/techs mostly haven't). Skips when the closer *is* the requester. Response adds `mode`, `notified`. **Deploy after merge:** `supabase functions deploy notify-dispatch-request` (`verify_jwt = false` in `config.toml` — unchanged). Doc: [`docs/EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md) → notify-dispatch-request.
- **Job Mode → Inbox "My requests"** — new [`JobModeMyRequests.tsx`](../../src/components/jobMode/JobModeMyRequests.tsx) replaces the `SettingsRecentPushNotifications` mount in [`JobModeInbox.tsx`](../../src/components/jobMode/JobModeInbox.tsx). Reads the tech's own `dispatch_requests` (`from_user_id = me`, the requester's rows are readable under the existing `dispatch_requests_select` policy; newest 60), realtime on the table filtered to `from_user_id` + the same-tab `DISPATCH_REQUESTS_CHANGED_EVENT`. Kernel [`src/lib/myDispatchRequests.ts`](../../src/lib/myDispatchRequests.ts): `summarizeMyDispatchRequest` → **"Waiting on Dispatch · 3d ago"** / **"Office answered (Maria) · today"** + the closing note rendered as **Office answered: "…"**; `splitMyDispatchRequests` (open newest-first, answered newest-closed-first, cap 10 + "N older answered"). Empty state points at the red icons instead of apologising about a log. Mobile-first (375 px: full-width card, 3 px status rail, wrapping text). Tests [`myDispatchRequests.test.ts`](../../src/lib/myDispatchRequests.test.ts) + render smoke [`JobModeMyRequests.render.test.tsx`](../../src/components/jobMode/JobModeMyRequests.render.test.tsx). The Settings → Notifications push log is untouched (it now also shows the "Dispatch answered" rows).
- **Red-phone auto-close** — kernel [`src/lib/jobDispatchAutoClose.ts`](../../src/lib/jobDispatchAutoClose.ts): `pickJobDispatchAutoCloses({ prev/next pictures link, prev/next phone })` → the `pending_action`s whose field went **blank → set** this save (`link_job_pictures`, `add_job_phone`), with fixed audit notes (`Customer Pictures URL added` / `Customer phone number added`). [`JobFormModal.persistIdentitySlice`](../../src/components/jobs/JobFormModal.tsx) generalises the old pictures-only branch into `autoCloseJobDispatchRequests(jobId, action)`: the update now `.select('id, from_user_id, title')`s the rows it actually closed (RLS lets only devs / dispatch members update, so anyone else's save matches nothing and notifies no one) and calls `notifyDispatchRequestClosure` for each. A new `persistedCustomerPhoneRef` mirrors `persistedPicturesLinkRef`. Tests [`jobDispatchAutoClose.test.ts`](../../src/lib/jobDispatchAutoClose.test.ts).

## Not changed / follow-ups

- The `useDispatchInbox` self-heal sweep still retires only orphaned `link_job_pictures` requests (jobs whose link was already set when the request was filed). The `add_job_phone` analogue (jobs whose `customer_phone` was set outside the Job form, or before the request) is the natural next step — same kernel shape, add `customer_phone` to the sweep's `jobs_ledger` read.
- `dispatch_request_dismissals` is untouched; a shared (non-per-viewer) dismissal is no longer needed for the badge and was not built.
- Help guides updated: `dispatch-mode.md` (badge sentences, "closing tells the tech"), `job-mode-clocking.md` (Inbox bullet), `ask-dispatch-for-missing-job-info.md` (you hear back; phone auto-closes).
