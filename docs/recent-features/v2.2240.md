# v2.2240 — Manual payments auto-link to their bill + hygiene flags (2026-08-24)

Billing Truth Plan Phase 2a+2b (the "payments always know their invoice" leak — ~155 hand-entered check payments had `invoice_id` null, so they never fed pay-speed history or paid bills down). New pure kernel [`paymentInvoiceLinking.ts`](../../src/lib/jobs/paymentInvoiceLinking.ts) (`autoApplyInvoiceId`, `paymentRowNeedsInvoiceLink`, `paymentDateBeforeBilled`) + wiring in `JobFormPaymentsTable`:

- **Auto-default**: the first positive amount typed on an unlinked manual row sets `invoice_id` to the job's single `status='billed'` invoice (visible in the Applies-to selector, reversible to Job (unassigned); ambiguous/zero open bills → no default).
- **Unlinked flag**: a positive unlinked row on a job with open bills renders an amber ⚠ line with a jump that opens the row's details fold; jobs with nothing to link stay quiet.
- **Impossible-date flag**: `paid_on` strictly before the linked invoice's bill day (billed_at date part, est-date fallback) renders a red ⚠ — the exact error class the HCP jobs-export import mass-produced. Same-day is legitimate and silent.
- Flags force the memo sub-row visible so they can't hide in a folded row; locked Stripe/Mercury rows are exempt throughout. Help guide `see-when-a-customer-will-pay` gains "Recording payments so they count".
