# v2.3201 — Mark reviewed: the Review step of the bid flow gets a record (2026-09-09)

Migration + client. Follows v2.3200 (the flow strip), where the poster's *review* step was drawn as *not tracked in the app* because nothing recorded a review. Grace: "add the Mark reviewed button, that button will need to save the time and the person who reviewed it and any notes they have."

- **Migration [`20260909200531_bid_review_stamp.sql`](../migrations/20260909200531_bid_review_stamp.md)** — `bids.reviewed_at timestamptz`, `bids.reviewed_by uuid → users ON DELETE SET NULL`, `bids.review_note text` (the **current** review), plus `twin_no_review_guard`, a BEFORE INSERT OR UPDATE trigger on `bids` that refuses any change to the three columns from a digital-twin session (reviewing is a human act, the `twin_no_send_guard` shape). Additive, idempotent, no new table, no RLS change. Push after merge; `database.ts` carries the three columns by hand until `npm run gen-types:linked` reconciles.
- [`src/lib/bids/bidReview.ts`](../../src/lib/bids/bidReview.ts) (tests) — `bidReviewFields(bid)` reads the stamp from a row that may or may not carry the columns yet (null = pre-migration, so nothing lies); `buildBidReviewPatch` (who / when / trimmed note or null); `buildBidReviewedNoteBody` → *Reviewed by Wendi.\nNotes: …*; `reviewStampLabel` / `reviewStampTooltip` → *by Wendi · Sep 9* and the notes. `BID_REVIEWED_EVENT` is the window event the Bids page reloads on.
- [`src/hooks/useMarkBidReviewed.ts`](../../src/hooks/useMarkBidReviewed.ts) — the button's whole path: `usePromptDialog` (one optional notes box, *Mark reviewed* / *Cancel*), `UPDATE bids … .select('id')` guarded by `bidUpdateRefused` (the refused-write doctrine — a training-mode user or an RLS miss reads "Save didn't apply", never a silent success), then a **method-less** `bids_submission_entries` note so the review shows in the bid's timeline **without moving `last_contact`** (v2.2413: notes without a method never do), a toast, and the event. Re-reviewing overwrites the stamp; the earlier line stays in the ledger.
- [`BidFlowStrip`](../../src/components/bids/BidFlowStrip.tsx) — the full strip gains a **Mark reviewed** button at its right end (label flips to *Reviewed by … · Review again* once stamped), the Review node becomes a door to the same action, its caption reads the stamp, and its tooltip carries the notes. The kernel's Review step now reads `reviewed_at` (null → *not yet*, a value → done), so the summary says "of 10".
- Hosts: the Bid Board's opened row and the five workflow tabs route the `review` door through `useMarkBidReviewed`; [`Bids.tsx`](../../src/pages/Bids.tsx) listens for `BID_REVIEWED_EVENT` and reloads bids (the `JOB_CREATED_FROM_BID_EVENT` pattern). Reviewer names resolve from the roster the board already loads (`estimatorUsers`); when the reviewer isn't in it the caption shows the date alone.

Help: new guide `mark-a-bid-reviewed.md`; `see-where-a-bid-is-in-the-flow.md` step 7 updated. `BIDS_SYSTEM.md` → Bid flow section touched. Release note `v2.3201.ts`.
