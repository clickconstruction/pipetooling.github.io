# v2.3286 — Their Word follow-up: call mode's promised outcome carries who said it, through the promise RPC (2026-09-11)

Client only; no migration, no edge function. Closes the first open item from the four-PR train (v2.3280 → v2.3285).

## Why

After v2.3283 the Billed row's *They said…* wrote promises through `add_job_payment_promise` with `said_by` and `channel`, but call mode (Pipeline's `PaymentChaseModal`) and the Dashboard AR call card still went through `set_job_promised_pay_date`. The v2.3280 trigger logged those as events, but with no source — the record read "by the customer" for a promise Taunya took from Dana on the phone.

## What shipped

- **[`paymentChaseIo.ts`](../../src/lib/jobs/paymentChaseIo.ts)** — new `addJobPaymentPromise({ jobId, ymd, saidBy, channel, note })` calling `add_job_payment_promise`, with the same `PGRST202` fallback to `setJobPromisedPayDate` the modal uses. `recordPromiseForJobs` (the one shared promise gesture for both chase surfaces) takes optional `saidBy` and `channel` (default **`'phone'`** — a chase surface is a call unless told otherwise) and writes through it; the per-job `add_payment_chase_touch` (`outcome: 'promised'`) is unchanged, so the queue's broken-promise escalation still counts.
- **Call mode** (`PaymentChaseModal`): a small *who said it* box beside the note (optional, 120 chars, cleared when the card advances); `applyPromise` passes it with `channel: 'phone'`.
- **Dashboard AR call card** (`DashboardArCallCard`): the same box and the same write.
- Help: `chase-late-payments.md` mentions the box; `know-whether-a-customer-keeps-their-word.md` already said call mode records the same way — now true.

## Verified

typecheck · lint · `npm test`; call mode opened on the dev server shows the two inputs side by side; a promise marked there (ZZ Split Test Claude via the AR card — not exercised, prod data) would land as `channel='phone'` — the RPC path is the v2.3280 one already scenario-tested on the scratch database.

## Notes for the next session

- The chase touch row still duplicates the promised date (`job_payment_chase_touches.promised_date`); it is the queue's memory, not the record's. If the queue ever reads `job_payment_promises` directly, the touch's date column can go.
