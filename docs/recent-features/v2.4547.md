# v2.4547 — AIA G702-G703: choose how the rows start (2026-10-05)

A job with no bid schedule started its continuation sheet as one row, even when the job's own Line Items already split the price (job 892: Rough In $15,098, Top Out $15,098, Trim Set $7,549). The owner, 2026-10-05: *"I would like the option for the user to choose if it is three rows or one row"*, then on the mock-up (https://claude.ai/artifact/CQwWBK5vLZpXpzBJBWFJEW): *"One row default, everyone sees it, build it."* Client only: no migration, no edge function.

## The change

- **Kernel** [`aiaLineSources.ts`](../../src/lib/aiaLineSources.ts) (new):
  - `linesFromJobLineItems(items)` — a row per named Line Item in the Bill tab's order: its name (with `× N` when the count is more than one), count times unit price as the scheduled value, its stage when the name is one (`bidStageOfJobLine`), id `item-<fixture id>` so it carries forward like any line.
  - `aiaLineSources({ oneLine, lineItems, bidSchedule })` — the starts a job has, in the order offered: **One row** always; **A row per Line Item** with two or more named Line Items, listed but off (`lines: null`, the reason in `detail`) when one has no price; **The bid's schedule** when the bid has one. Any Line Items, not only stage names.
  - `defaultLineSource` — the bid's schedule when there is one, else one row.
- **Window**: a `START THE ROWS FROM` radio group at the top of LINES (`data-testid="aia-line-source"`), shown only on a new application with nothing saved on the job and more than one start, and only once the job's saved applications and bid have been read (`loadedJobId`). Picking a start replaces the rows and the split, and makes them the baseline (a start nobody typed over is not unsaved work). Rows that were typed in are asked about first (*Replace the rows?* Replace / Keep). After the first Save the group is gone: rows carry by id from the saved application. The note under the list names the bid only while the bid's schedule is the start picked.
- The bid's schedule was picked silently before; it is now the third option, still picked by default when the job has one.

## On live data, 2026-10-05

Unpaid jobs: 34 have two or more Line Items; on 28 every one is priced and all 28 add to the job's price exactly; the most on one job is five. No Line Item carries a reported percent today, so the crew's offer shows only where a stage has one.
