# v2.2701 — Person Desk PR 1: the spine and the drawer (2026-09-03)

First of the Person Desk train (owner-approved proposal, artifact 321baa3e, defaults taken). Managing one person was a tour of ~22 surfaces in three incompatible key spaces (`users.id`, `people.id`, name text) with no shared pointer across People's 17 tabs. This PR adds the identity spine and a drawer that opens from a person's name, with the four sections that buy the most: Hours & approvals, Portal & paperwork (subs), Team & alerts, Access & account. No migration. No new permissions.

## Client only

- **Kernel** [`lib/people/personKey.ts`](../../src/lib/people/personKey.ts) (+10 tests): `resolvePersonKey({ user, person, emailMatchedPerson, payConfigNames })` → `{ userId, personId, payName, displayName, role, personKind, archived, isSub, gaps, … }`. Pay name = trimmed account name when an account exists (Phase A finding), else the roster name. Gaps: `no_roster_row`, `no_login`, `unlinked_email_match` (email-matched roster row with null `account_user_id` — reported, never auto-linked), `pay_name_mismatch`, `no_pay_config` (skipped for primaries and when the caller cannot read pay config). `describePersonGap` gives each gap its label / action / detail; `personDeskParam` / `parsePersonDeskParam` encode the deep link (`u:<uuid>` / `p:<uuid>`); `describeLastSeen`.
- **Gates** [`lib/people/personDeskGates.ts`](../../src/lib/people/personDeskGates.ts): one function per control, each restating the surface's existing gate (account edits / archive / training mode / imitate = dev; team leads = office; Full/Strip and groups = dev; hours = `canAccessHours || canAccessPay`; every write also requires the viewer not be in training mode). Owner decision 2 (widen archive/restore + training mode to controller/master) lands as one-line changes here plus the edge-function / policy checks, in its own PR.
- **Loader** [`hooks/usePersonDesk.ts`](../../src/hooks/usePersonDesk.ts): from either id, loads the account row, the linked roster row (else an email-matched unlinked one), and which pay-config names exist; refetches on the context's `changeKey`.
- **Opener** [`contexts/PersonDeskContext.tsx`](../../src/contexts/PersonDeskContext.tsx) (`open({ userId | personId, displayName })`, `markChanged`) + [`PersonDeskDeepLinkHandler`](../../src/components/personDesk/PersonDeskDeepLinkHandler.tsx) (`?person=` on any route, stripped after opening — the `?userReview=` precedent). Provider in `App.tsx` inside the User Review provider; drawer + handler mounted from `Layout.tsx`.
- **Drawer** [`components/personDesk/PersonDeskDrawer.tsx`](../../src/components/personDesk/PersonDeskDrawer.tsx): right panel (min(600px, 96vw)) at z 60, full-screen under 640px, Esc / backdrop close, training-mode banner for a read-only viewer, gated by `canOpenPersonDesk` (office roles). Viewer object built from `useAuth` + `usePeopleAccess`.
- **Header** [`PersonDeskHeader.tsx`](../../src/components/personDesk/PersonDeskHeader.tsx): initials, name, role + trade names (from `service_types`), the three identity dots, one amber line per gap with its button — **Link account** (`people.account_user_id` update), **Reconcile** (`people.name` update + `cascadePersonNameInPayTables`, the one rename path), **Create roster row** (kind select; the same insert Employment does on first save; `master_user_id` = the viewer) — all behind confirms; `no_login` / `no_pay_config` show guidance toasts until PR 2 wires them. State chips (on the clock with job label; sessions waiting · hours via the v2.2694 kernel), **Day · week · month** (User Review opener), **Email**, **Imitate** (dev, confirm, `loginAsUser`).
- **Sections** (`components/personDesk/sections/`), each a thin wrapper on the tab's write:
  - *Hours & approvals*: open session with **Force clock out**; waiting count · hours · oldest · flag summary; **Open approvals** → `PeopleHoursApprovalsQueueModal` with the new `pinUserId` / `pinDisplayName` / `zIndex` props (and `fetchAllPendingClockSessions({ userId })`); Edit → `ClockSessionEditSplitModal` at z 1150; this week's closed hours; reviewed-through from `hours_reviewed` by pay name.
  - *Portal & paperwork* (subs; needs `personId`): `SubPortalGlobeButton` inline with on/off from `useSubPortalLinkOff`; compliance chips via `buildSubComplianceBadges`; open work orders (`step_commitments` offered / accepted); linked sheet count from the junction.
  - *Team & alerts*: leaders for this member (assign / remove for office roles; Full / Strip select dev-only); the viewer's own **Alert me on in/out** pref (assignment-keyed upsert, as My Team); Dispatch / Estimator group membership (dev toggles; others see a pointer).
  - *Access & account*: role select (dev; confirm), trade chips, sign-in with **Send sign-in email** and **Manage account…** (opens the Active Accounts modal for password / name / merge), training-mode checkbox (dev, never self, reconciles from the returned row like the panel), Active / Archived with **Archive…** (routes to the Active Accounts row so customer reassignment is offered) and **Restore** (`restore-user`).
- **Doors**: the name on People → Users rows (account rows open by `userId`, roster-only rows by `personId`) and People → Subs rows (by `personId`). Both render as plain text when the viewer cannot open the Desk.
- Shared chrome [`personDeskShared.tsx`](../../src/components/personDesk/personDeskShared.tsx): `DeskSection` / `DeskRow` / `Chip` / `LockTag`, button styles, `DESK_Z` = 60 and `DESK_EDITOR_Z` = 1100.
