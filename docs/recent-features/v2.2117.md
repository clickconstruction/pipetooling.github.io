# v2.2117 — Cover Letter Old / New: New bundles bid versions at their ★ (2026-08-23)

F1 of the "Send or Compare" train (owner-approved review + prototype: claude.ai/code/artifact/1d998cbd-10f1-430e-9e82-092e0ae75b88 · 7130dcd4-0852-4900-bad8-a2639cc9f386). The review found the send surface contradicting the Pricing tab's language: the Cover Letter bundled **price scenarios** (`price_book_versions.include_in_submission`) and labelled them "Versions in this submission", while the picker badge read `bid_versions.include_in_submission` — two flags, client-mirrored, already disagreeing in prod (BP329: To Plans "not in cover letter" yet its WENDI scenario was bundled).

**Old / New pills** on the Cover Letter tab header (same per-device pattern as Pricing, key `bids_cover_letter_view_v1`, default **New**; `BidVersionPicker`'s "Send… →" sets it to New before jumping). **Old** = today's letter, untouched (scenario checkboxes, one letter each). **New**:
- Step 1 panel **"In this cover letter"** lists the bid's **versions** (split bids): checkbox = `bid_versions.include_in_submission`; **Base / Alternate** segmented control = new `bid_versions.is_alternate`; each row shows its ★ scenario name + revenue; ▲▼ reorder `bid_versions.sort_order`. Unsplit bids get one line: "One bid — the letter shows ★ {scenario}. To offer an alternate, make it a bid to send."
- Bundle = included versions, **base first then alternates**, each priced at its **★** — resolved by the new kernel [`coverLetterVersionBundle.ts`](../../src/lib/bids/coverLetterVersionBundle.ts) (`starredPricingIdForVersion` → `bid_versions.starred_price_book_version_id` when it belongs to the version, else its first scenario; `planLetterSections`, `letterTotal`, `sectionLabel`, `bundleSummary`; 8 tests). A split bid bundles even a single included version (the letter follows what's checked, not what's active); zero checked falls back to the active bid's letter with a hint.
- Headline amount = **letter total** (sum of base bids); caption "letter total · 2 base bids · 1 alternate"; **Apply to Bid Value** writes it. Section headings in the combined document: "Bid: To Plans" / "Alternate: Value Engineered — in lieu of To Plans" (Old keeps "Pricing: WENDI"). Per-GC packets unchanged (sections carry `bidVersionId`).
- Mirror for Old: toggling a version in New sets that version's ★ scenario flag to match and clears its other scenarios' flags, so Old never bundles a scenario the picker says is out.

**Per-version ★** — migration `20260823022731_bid_versions_letter_role_and_star.sql` adds `bid_versions.is_alternate boolean not null default false` and `bid_versions.starred_price_book_version_id uuid null → price_book_versions` (+ index), backfilling each version's ★ from the bid's saved ★ when it belongs to the version, else its first scenario. `saveBidSelectedPriceBookVersion` now also stamps the active version's star; `deriveActivePricingId` gains `versionStarredPricingId` (wins when it belongs to the version) so switching versions no longer loses the other version's ★ (previously the bid-level `selected_price_book_version_id` was the only star, and the non-active version silently fell back to its first scenario). Types: the two columns are typed locally (`BidVersionLetter`) until `gen-types:linked` runs after the push — a follow-up PR drops the casts.

Picker chip badge: "in letter ✓ · base" / "in letter ✓ · alternate" / "not in letter". Verified live on BP329 (Nick & Moe's): New default; checking To Plans → badge flips, headline $219,517.52 → $499,096.32 (2 base), scenario flags mirrored; unchecking restores; Old view unchanged.
