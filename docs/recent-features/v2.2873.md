# v2.2873 — Estimates: the row says opened or never opened; customers can say no thanks and staff can record a decline (2026-09-05)

Journey-map Tier-2 #34 (J17-F1 / F6 / N1 / N2) with the estimate-view half of #37. Live on 2026-09-02: five sent rows, #83 with **zero** link views wearing the same "sent 7d ago — nudge?" chip as #76 (7 views / 4 IPs) and #71 (12 views / 8 IPs); `declined` in the status enum with **no writer anywhere** — the customer's only "no" was silence, the office could not record a phone "no", and `splitFollowupRows` buried `declined` in Sent where `computeSentWait` kept it asking for a nudge. Builds on v2.2856's Resend link (untouched).

## What changed

- **Opened / never opened on the Sent row.** `EstimateList.load` still selects `estimates` alone; a second, chunked query (`fetchAllRowsChunkedIn`, `estimate_customer_events` `.in('estimate_id', …)`) loads every sent + declined row's events, grouped by `groupEventsByEstimateId`. The new kernel `src/lib/estimateOpenState.ts` folds them into the chip: `never opened · sent 9d ago — nudge?` (keeps `computeSentWait`'s numbers and level), `opened Thu · quiet 2d`, `opened today`, `opened 8/28 · quiet 8d — nudge?` (amber after a week of *quiet*, not a week since send), overdue response-requested-by still wins. `public_link_view` and `option_viewed` count as opens; accept/decline do not. **Scanner heuristic (J17-F3):** link views from 2+ distinct IPs inside the first 60 s after `sent_at` are mail-gateway prefetches and are dropped; one IP clicking straight away stays. Until the fetch lands the chip is `computeSentWait` alone, as before. Hover title: "Customer opened this N times" / "No customer has opened the link yet".
- **Declined bucket.** `splitFollowupRows` moved out of `Estimates.tsx` into `estimatePipelineRefresh.ts` (generic, tested) and gained `declined`; the Pipeline renders a **Declined** section only when non-empty (same convention as before for empty buckets). Its rows read `Declined by customer · 2d ago` / `Declined — office heard it by phone · 1h ago` from the row's `declined` event.
- **Customer "No thanks"** (`EstimateAcceptBody`, interactive variant only): a quiet underlined link under Approve (44 px tall, muted) → inline confirm panel "Not going ahead?" with an optional reason (≤ 280) and **Keep looking** / **Decline this estimate** (change orders: "Decline this change order"). `EstimateAccept.tsx` POSTs `accept-estimate` with `{ token, action: 'decline', declineReason }`; success renders a "Thanks for letting us know" thank-you. Sample mode short-circuits like acceptance.
- **`accept-estimate` `action: 'decline'`**: same token contract, no name/signature/terms; `sent → declined` status-gated (`.eq('status','sent')`, a race with an acceptance answers 409), then `insertEstimateCustomerEvent` `declined` / `accept-estimate` with `metadata { by: 'customer', note }`. Idempotent (`alreadyDeclined`), 409 `already_accepted`, 410 `expired` on the token. One structured log line `estimate_declined {by, estimateId, hasReason}`.
- **Staff writer.** On a sent estimate's detail, **Record a decline (phone / in person)** (`EstimateRecordDeclineControl`) → How did you hear (phone / in person / email / text / other) + optional note → **Mark declined** → RPC `record_estimate_decline(p_estimate_id, p_note, p_channel)` (migration `20260905170000`): one SECURITY DEFINER transaction that flips `sent → declined` and appends the `declined` event with `metadata { by: 'staff', channel, note, user_id }`. Gate mirrors `estimates_select`. Telemetry `recordNavClick(…, 'estimate_declined', '#staff')`; the customer side's telemetry is the event row itself.
- **Declined detail view**: "Declined. Nothing more is waiting on the customer…" + the Customer activity feed (now also loaded for `declined` rows). Activity lines read `Declined by customer — “went with another bid”` / `Declined — office heard it by phone — “call back in spring”`.
- **Office previews don't count** (#37, estimate side). `src/lib/estimateViewPreview.ts`: `isEstimateViewStaffPreview(search, hasStaffSession)` is true for `?preview=1` **or** a signed-in staff session on the accept page; `withEstimatePreviewMarker` appends the marker to the URL **Open customer link** opens (Copy stays the raw link the customer gets). `EstimateAccept.tsx` sends `preview=1` to `get-estimate-for-customer`, which then **skips `record_estimate_public_link_view`**. The marker can only under-count, so it needs no server-side proof.
