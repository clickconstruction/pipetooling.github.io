# v2.1964 — Task numbers inside stages + nested ordering (2026-08-21)

Part 4 of the stage-numbers train (v2.1940 badges, v2.1941 Order modal,
v2.1946 Plan order): tasks get **N.M** numbers and become orderable.

- **Kernels** (`src/lib/roadmapStageNumbers.ts`, +5 tests):
  `taskNumbersByTaskId(stageNumbers, tasksByGroup)` → "N.M" per task
  (derived from the existing per-stage task `sort_index` order, never
  stored); `computeTaskOrderUpdates(taskOrdersByGroup, tasks)` → changed
  rows only, within-group only (skips deleted/moved ids).
- **Display**: new `RoadmapTaskNumber` — a muted tabular label, not a chip
  (stages keep the one strong badge; 89 tasks whisper). Shown on Map
  cluster rows (replacing the disc bullets, both static and Edit-Tasks drag
  rows), Plan task rows, and the task card crumb ("· task 4.2",
  `taskNumberLabel` prop).
- **Order modal** → "Order stages & tasks": each stage row gains a ▸ that
  expands a nested dnd-kit sortable of its tasks (ids prefixed `g:`/`t:` in
  one DndContext; task drags constrained to their own stage — cross-stage
  moves stay on the Map's Edit-Tasks drag). Save persists both orders via
  the existing parallel-update + reload pattern. No migration.
- Help guide `number-and-order-roadmap-stages` extended to cover tasks.
