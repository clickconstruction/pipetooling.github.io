# v2.2325 — Nav access reconciliation: superintendent dead ends, deep-link prefix matching, pin validation (2026-08-26)

CX-audit Phase 1 (Journey Atlas findings F1–F3, F8): nav chrome and the per-role
route allowlists were maintained by hand in three places and had drifted apart.
This PR makes `src/lib/layoutRouteAccess.ts` the single source of truth and
reconciles every mismatch against the documented intent in
`docs/ACCESS_CONTROL.md` → Page Access Matrix.

- **One source of truth**: `Layout.tsx` no longer declares its own
  `SUBCONTRACTOR_PATHS` / `PRIMARY_PATHS` / `SUPERINTENDENT_PATHS` copies — the
  redirect guard is now a single `isPathAllowedForRole()` call (estimators still
  bounce to `/bids`, everyone else to `/dashboard`).
  `src/lib/dashboardPinnedRow.ts` likewise drops its third (stale, narrower)
  copy and filters pin chips through the same kernel — pins to `/my-statement`,
  `/estimates`, `/documents` etc. now display for roles that can open them.
- **Allowlists match by root + subpath** (previously exact-match for sub-like /
  primary / superintendent): `/estimates` also admits `/estimates/123`,
  `/workflows` admits `/workflows/:id`. The `'/'` entry matches only itself.
  Fixes deep links (global search, emailed links, quick-estimate follow-ups)
  bouncing restricted roles to the dashboard.
- **Superintendent dead ends fixed** (`Layout.tsx`):
  - Customers/People header icons no longer render for superintendents (both
    pages are blocked for the role — ACCESS_CONTROL.md:650 — so the icons only
    ever bounced).
  - The Dispatch Mode gear toggle is now staff-only (dev / master / assistant-like):
    every `/dispatch-mode*` tab is outside the superintendent allowlist, so the
    toggle rendered a footer of dead tabs. Supers keep `/schedule-dispatch`
    editing (`CAN_USE_SCHEDULE_DISPATCH_EDIT_ROLES` unchanged).
  - Top nav now shows **Estimates / Jobs / Bids** for superintendents (before:
    only Schedule + Projects, though all three pages are in their allowlist),
    and the gear menu **Documents** item includes them (route was allowed and
    documented ✅ but the menu item was omitted).
- **Pin for someone validates the target's access**: the dev "Pin for" flow now
  fetches each user's `role` + `estimator_prospects_access` and refuses to save
  a pin the target's allowlist rejects (error message instead of a dead pin).
- **Dead code removed**: the `role === 'dev' && !isMobile` Review icon inside
  `renderMobileHeaderLinks()` (only ever called from the mobile branch).
- **Not changed (deliberate)**: controller exclusion from the Dispatch-Mode PO
  tab (`dispatchModePoRoleAllowed`), estimator People icon hidden on mobile —
  both flagged in the Journey Atlas as possibly intentional; left for a product
  decision.
- Tests: `layoutRouteAccess.test.ts` (+6: prefix matching, `/` non-wildcard,
  sibling-prefix guard, superintendent dispatch-mode/customers/people blocks),
  `dashboardPinnedRow.test.ts` reworked to the unified filter.
