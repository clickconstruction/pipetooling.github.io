# v2.3030 — Test-gap audit, pass 40: creating a job from an estimate gets its first tests (2026-09-07)

Follow-up to v2.3029. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`createJobFromEstimateSubmit.ts` (152 lines) turns an accepted estimate into a job: the Specific Work fixture rows the `create_job_from_estimate` RPC receives, the bid dollars the modal previews, and the submit itself with its gates, argument shaping, customer link and error mapping. Two callers (the Estimate detail modal and Edit Job's from-estimate path) and a render smoke, but no test of the submit.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- A fixture row is named by its line item, else its description, else "Item" when it carries money; a row with none of those is skipped, but the original index is kept as its sequence. A separate description is only kept when the row has a line item. Unit prices round to cents.
- The previewed bid is the sum of count × unit price over the fixture rows, or the estimate total when no row qualifies.
- The submit refuses an estimate that is not customer-accepted, one already linked to a job, and a blank HCP number before any lookup runs.
- The RPC receives the trimmed HCP, name and address (blank name and address omitted), the fixture rows, and the chosen customer when one is picked; a change order lets credit lines stay negative through normalisation.
- A missing job id, an RPC error and a failed master lookup each map to an error message, with "Could not create job" for anything unnamed.
