# v2.6844 — An agent can settle the proposed theme marks on a file in one plan (2026-11-10)

The owner, 2026-11-10, with a former teammate's HR file open: an agent had proposed 153 theme marks on it four days earlier, every one still dashed, and the only door that kept a mark was the Keep press in the By theme view, one mark at a time. The dev seat could make a mark but could not keep one: `plan_theme_marks` reads a proposed mark as *already*. The `dev-mcp` function (server 0.59.0) and one migration. No client change.

## What was there

`legal_theme_marks` (v2.6545) holds a mark as what it was when made: the table's trigger refuses every change but the kept stamps and the removed stamps. The app writes those two through `keepMark` and `removeMark` (`src/lib/legal/legalThemesIo.ts`), a row at a time under the dev's own RLS. The seat's `dev_theme_marks_write` (v2.6552) inserts marks, kept or proposed, and has no word for a mark that already stands.

## What changed

- **`plan_theme_review` → `apply_theme_review`** (`supabase/functions/dev-mcp/index.ts`, `_shared/devMcpWrites.ts`): `keep` is a list of mark ids and `take_off` a list of `{ id, why }`, 1 to 200 marks across the two, no mark named twice. The kernel checks the shape; the database resolves each mark.
- **`dev_theme_review_write`** (migration `20261110100000`, `SECURITY DEFINER`, devs only, closed to anon): the dry run says *ready*, *already* or *held* for each mark with its theme, the first words of the thing it hangs on and the mark's own why and grade, and counts each list. Apply stamps the ready ones as the dev (`kept_at` / `kept_by`, or `removed_at` / `removed_by` / `removed_why`) and skips the rest, so one held mark never stops the others.
- **What it cannot do**: reword a mark, change its theme or its grade, delete one, or keep a mark that came off. A mark under the wrong theme comes off here and is made again with `plan_theme_marks`.
- The seat's instructions, the verb count (seventy-seven) and the docs carry the pair: `docs/dev-mcp/README.md`, `docs/EDGE_FUNCTIONS.md`, `docs/HR_FILES.md`, `docs/ACCESS_CONTROL.md`, `docs/GLOSSARY.md`, `docs/migrations/20261110100000_dev_theme_review_write.md`.

## Tests

- `npm run test:pg:theme-review` (`supabase/tests/theme_review/20_scenario.sql`, in `scripts/sql-beds.txt`): on a copy of the whole schema, as a dev and as an estimator — who may call it, every bad shape, a dry run that writes nothing, the apply, a replay that finds nothing ready, a kept mark taken off and then held from keeping, and the table's trigger still refusing a reworded mark.

## Deploy

Push the migration, then `supabase functions deploy dev-mcp`. A session already connected to the seat lists the old verbs until it reconnects. The generated types and the seat's catalog gain the function with the next `chore(types)` pass.
