# v2.5270 — Messages: the reminders the app sends by itself each morning (2026-10-12)

Messages, cut 5: the morning run of the app's own reminders, as a pure kernel for the `messages-nudge-dispatch` edge function (`BUILD_PLAN.md` → Cut 5; section 7's decision 3, per step and off until the owner turns it on). On cluster 5's `nudges.ts` (v2.5255). No screen, no table, no migration, no edge function yet.

- **`src/lib/flows/nudgeDispatch.ts`**: `planNudgeRun` reads Follow up's rows (`nudgeRows`) at the run's morning, so it sends only what Follow up shows as due; holds, quiet days, our last message and a change order on a portal row (`NudgeOptions.skip`) keep a reminder out the same way. Of each row's due steps it takes those whose reminder the app sends (`nudge.send` is `app`) and whose step is switched on (`AppSends`, off for every step by default). It keeps back a reminder for a person snoozed on Follow up until the snooze day (`contacts.snoozed_until`: Snoozed is a person's "not now", and the app never overrules one of ours), a reminder one of ours or the app sent inside the step's days (`nudge_sent`, at least the same day, so a second run the same morning sends none), a number that sent STOP, a person with no number, a channel that is not a text, and a second text to the same person that morning; each comes back in `notSent` with why and its words for the run's log ("snoozed until Mon Oct 5"). Each text carries the step's own line, the `nudge_sent` row to write once Quo takes it, and the thread's event line ("The app sent the Portal opened reminder by text.").
- **`nudgeLine`**: the reminder's own line, lifted from the prototype v1.178's `nudgeLine` and `NUDGE_DEFAULT`. It is the team's quick reply for the step when there is one (cut 3's `stepLine`), with the portal link when the step waits on a paper of theirs; else the step's own words; else a check on that paper; else a check-in on the step. Three of the default lines joined two sentences with a semicolon and now read as two sentences; a test holds every line to `plainWordsFailures`.
- **What the edge function adds**: each text goes through cut 5's `planSend` with the purpose `nudge`, which adds the opt-out line on a first text or after thirty quiet days and refuses a number that sent STOP, so the run never builds its own opt-out line.
- **Tests** over the prototype's demo people on Fri Oct 2 at 9 AM: with every step off nothing sends; with Portal opened on, Tom gets one text and a second run the same morning sends none; Priya snoozed until Monday gets nothing until Monday. In the prototype Tom pressed Got it on Mon Sep 28 and we texted Tom on Wed Sep 30, so the test puts Tom back on Portal opened with nothing from us since the invitation.
