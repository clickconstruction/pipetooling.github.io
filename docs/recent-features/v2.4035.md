# v2.4035 — My Time day editor: the salary sync note shows whenever salaried time is re-cut (2026-09-28)

Client only; no migration, no edge function. From the map's quirk 27 (found by the tests of [v2.4021](v2.4021.md)); punch list **#46** row 10. Stacked on [v2.4033](v2.4033.md).

## The bug

`salary_sync_one_user_clock_sessions` may rewrite `salary_schedule` rows, so after a save that re-cuts them the editor shows *Saved. Rows tied to the salaried workday template may be adjusted when salary sync runs.* Only the two partition branches (a single part across several rows, and the coalesced partition) set it. A moved seam between a punch row and a salary row, a split of one salary row, or a rebuild through the replace RPC re-cut salaried time with no note.

## The fix

[`lib/myTimeDayPersist.ts`](../../src/lib/myTimeDayPersist.ts) sets the flag once per written cluster, after whichever branch wrote it: when the block holds a `salary_schedule` row and its parts are not the rows as they were (`segmentsAreTheRowsUnchanged`). The two branch-local settings are gone; they are covered by the one rule. A notes-only save raises no note.

## Verified

- `myTimeDayPersist.test.ts` (78): the moved punch / salary seam now raises it; one salary row split raises it; a notes-only save of a block with a salary row does not; a block with no salary row never does; the partition cases unchanged.
- The 292 tests of the day editor's libs and components; eslint; `npm test` in full; typecheck.
