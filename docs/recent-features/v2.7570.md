# v2.7570 — Task notes: the database can now hold a tag for a teammate (2026-11-17)

Punch list #375, PR 1 of six: the ground. One migration, `20261117160000_task_note_tags.sql`, and its SQL bed. No client code, no edge function, and no screen calls the new names yet. The detail is in `docs/migrations/20261117160000_task_note_tags.md`.

## What is new

- **`task_note_tags`**: one row a person tagged in a task note, with how it ended (`answered` with the answering note, or `done`) and when the asker saw that. It ends with the four fence calls.
- **Eleven functions**: `task_note_taggable` (the list at the box), `task_note_post_tagged` (a typed note and its tags in one transaction), `task_note_tags_write` (its definer half), `task_note_tags_mine`, `task_note_tags_count`, `task_note_tag_done`, `task_note_tags_seen`, the internal `task_note_people`, the trigger function `task_note_answers_tags`, and the two that read both kinds, `note_tags_mine` and `note_tags_count`.
- **One trigger** on `checklist_instance_events`: a typed note answers the tags that wait on its writer on that task.
- **The `task-note-tags` SQL bed**: `scripts/pgtest-task-note-tags.sh`, `supabase/tests/task_note_tags/`, a line in `scripts/sql-beds.txt` and `npm run test:pg:task-note-tags`.

## Three choices worth knowing

- **The answer is a trigger.** On jobs it lives in the post function, because a job's notes table cannot tell a typed line from a stamp. A task's thread names each line's kind, so the rule sits on the table. History's box, the Roadmap card, Review's Reopen with comment and My Inbox answer a tag with no client change. Only a `comment` answers: a tick, a stuck line and a handed line do not.
- **The list is read for the day row, not the task.** The card planned it over the task's own assignees too. A person who gave away one day of a repeating task is still on the task's list and can no longer read that day's thread, so they are not offered on it. This keeps the owner's first pick whole: only people who can already open it.
- **The read of both kinds says `source`, not `kind`.** The job read already uses `kind` for waiting and asked.
