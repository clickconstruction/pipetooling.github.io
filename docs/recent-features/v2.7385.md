# v2.7385 — Job notes: the database can now hold a tag for a teammate (2026-11-15)

Punch list #363, PR 2 of six: the ground. One migration, `20261116100000_jobs_ledger_note_tags.sql`, and its SQL bed. No client code, no edge function, and nothing calls the new names yet. The detail is in `docs/migrations/20261116100000_jobs_ledger_note_tags.md`.

## What is new

- **`jobs_ledger_note_tags`**: one row a person tagged in a job note, with how it ended (`answered` with the answering note, or `done`) and when the asker saw that. It ends with the four fence calls.
- **Eight functions**: `job_note_taggable` (the list under the box), `job_note_post_tagged` (a typed note and its tags in one transaction), `job_note_tags_write` (its definer half), `job_note_tags_mine` (the section in one read), `job_note_tags_count` (the number above Jobs), `job_note_tag_done` (No reply needed), `job_note_tags_seen` (the asker has seen the answers), and two internal ones, `job_note_people` and `job_note_caller_sees_test`.
- **The `job-note-tags` SQL bed**: `scripts/pgtest-job-note-tags.sh`, `supabase/tests/job_note_tags/`, a line in `scripts/sql-beds.txt` and `npm run test:pg:job-note-tags`.

## Three choices worth knowing

- **The post is two functions, not one.** `job_note_post_tagged` is `SECURITY INVOKER`, so the note is inserted under the writer's own policies, as the note box inserts it today. Only the tag rows go through a definer. A single definer would have had to restate the notes' insert policy.
- **A tag clears on a typed note, not on any insert.** The notes table cannot tell a stamp from a typed line, so the clearing lives in the post function and not in a trigger. PR 3 sends typed notes through it and leaves stamps and % lines on the plain insert.
- **The card planned six functions and this has eight.** The two more are the definer half of the post and the test-login rule, which lets a dev tag the walk tester on a ZZ Test job and offers no real teammate a test login.
