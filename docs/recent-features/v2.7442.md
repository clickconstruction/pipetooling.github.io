# v2.7442 — Lien desk: To do says Print and mail (2026-11-16)

Taunya, on the Lien desk's To do list (2026-11-16): asked for a clearer way to say *Send* and *Send the run*, "this needs to be intuitive to someone", and picked *Print and mail*, *Print and mail 3* and *Enter mail numbers*. On the same list she did not like that the first column's tags differ in size. Client only: no migration, no edge function.

## The words

- An approved notice's row (`send`) reads **Print and mail**. So does an approved retainage notice's.
- A GC with two or more approved notices (`send_run`) reads **Print and mail N**, N being the notices the row stands for.
- Two or more printed notices whose mailing is not recorded (`record_mailing`) read **Enter mail numbers**.

The words live in `BUTTON` in `src/lib/jobs/lienNextUp.ts`. The run window's own title, the desk's top bar door (*The run · N*), the Monthly notices footer and the steps' names still say *Send the run* and *Record the mailing*; this change is the To do list's presses only.

## The run opens on the GC's notices

The run window always held every approved and printed notice on the desk, whichever row opened it, so *Print and mail 2* on one GC's row opened a window of fifteen. A To do press now carries its GC: `lienRunEntriesFor(ready, printed, gcId)` hands the window that GC's approved notices alone (no printed ones, no retainage), and the desk's own doors pass no GC and get everything, as before. A single approved notice with a GC now opens the run on its GC too, which holds that one notice; a notice with no GC on record keeps its pane. A press on the row itself still opens the notice.

Walked on the dev server against prod data: *Print and mail 6* opened *Send the run · 6 notices*, *Print and mail 5* five, a single *Print and mail* one, and the top bar's *The run · 15* fifteen. Nothing was printed or recorded.

## The tags in the first column

A tag you can press (*Notice ✓*, *Affidavit ①*) drew larger and lighter than a plain one (*Notice*, *Run*, *Retainage*). Its style spread the tag's 0.68rem bold first and set `font: 'inherit'` after it; a spread keeps an overridden key in its first place, so the shorthand came last and reset the size, the weight and the line height to the row's. The press now inherits `fontFamily` alone (`lienPaperDoorStyle` in `LienDeskNextUp.tsx`), and every tag on the walk measured 10.88 px, bold, 18 px tall. A phone keeps the press's thumb-tall size. jsdom ignores `font: inherit`, so the render test holds the style object itself; it failed with the old style in place.
