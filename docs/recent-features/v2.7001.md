# v2.7001 — First look: the files are kept in Google Drive, in Customer supplied photos (2026-11-12)

Punch list #319, PR 2 of the train, with the sweep's half of PR 3. The owner's ask of 2026-11-11: the files live in Google Drive, in a **Customer supplied photos** folder under the customer.

- **Where.** The customer's own folder (found or made by `FolderTree.customerFolder`), then **Customer supplied photos**, then a folder for the look named by its day and place, *2026-11-12 · Kitchen* (`lookFolderName`). The look keeps the folder's id (`first_looks.drive_folder_id`). The folder is made when something first lands in it, whatever the *made up front* setting says. `_shared/driveLookFolder.ts`.
- **The sweep's twelfth source** (`sweepLooks` in `photo-save`): finished files not in Drive, the ones not tried lately first, so a file that cannot file yet never starves the rest. A file is due once the look was sent, or half an hour after it finished with no Send.
- **A video goes in pieces.** A file over 8 MiB is copied through Drive's own upload in pieces, each piece read from the app's storage as one range. The function never holds more than a piece. Drive's address and the offset are kept on the row (`drive_upload_uri`, `drive_upload_offset`), so a copy cut off by the pass's 40 seconds picks up on the next run. A photo goes in one request, as every photo does.
- **A caller who is not a customer yet** has no folder. The reason is written on the row and the card reads *Files to Drive once this number has a customer.* The moment the office names them, the next sweep files them.
- **Texted pictures** from that person since the ask go to the same folder (the owner's call 12), unless a ticked job's own save took them first.
- **No Send, counted as sent.** A look whose newest file has sat for half an hour with no Send is stamped sent by the sweep, with the thread line the Send would have written. The customer added what they had and closed the page.
- **The card** gains a Drive line (`lookCardDriveLine`): *Open in Drive*, *1 of 3 in Drive so far.*, or why not yet.
- **Documents → Where files go** draws the folder under the customer in *What is inside*.

The app's own copy stays, since the thread draws the pictures and plays the video from it.

Migration `20261112110000_first_look_drive.sql` (`docs/migrations/20261112110000_first_look_drive.md`): seven nullable columns and one partial index. **Push it after the merge, then deploy `photo-save`.** The card reads three of the columns; a read that meets a database from before them reads without (`isMissingColumn` in `threadIo.ts`), so the card keeps drawing in the hour between the merge and the push.

Not in this PR: the folder under a job, and its move when a job is made from a look (PR 6).

Tested: `drive.test.ts`, `card.test.ts`, and `driveCopyInPieces.test.ts`, which runs the copy's loop (`_shared/driveCopyInPieces.ts`, four doors the sweep hands it) against a stand-in Drive: every byte once, a stop past the deadline, a pick-up where Drive says, an address Drive forgot, a short read.
