# v2.2750 — Debit cards: one modal for nickname, role and person; company cards leave fuel (2026-09-04)

Follow-up to the Wheels train (v2.2733 / v2.2735 / v2.2739). Owner's call: recurring-service cards (cash app, GPS, Tesla) are management tools, "kind of like software", not fuel.

## Migration

- `20260904153002_debit_card_role.sql` — `mercury_debit_card_nicknames.card_role text NOT NULL DEFAULT 'person'` (CHECK `person | company`). See `docs/migrations/`.

## Data layer

- [`lib/banking/debitCards.ts`](../../src/lib/banking/debitCards.ts): `loadDebitCardDirectory` (nicknames + roles, `card_role` read through a cast until types regenerate), `saveDebitCardRole`, `loadDebitCardLinks`, `saveDebitCardPerson` (writes `user_id` = `auto_assign_user_id` on `mercury_debit_card_user_links`, then runs `backfill_mercury_auto_attributions_for_debit_card`), `debitCardsHref(cardId)`.

## Client

- **[`BankingDebitCardsModal.tsx`](../../src/components/banking/BankingDebitCardsModal.tsx)** replaces `BankingDebitCardNicknamesModal` + `BankingUserCardLinkModal` (both deleted; the green "User Card Link" button on the Sorting header is gone, the Nicknames menu entry reads "Debit cards"). One row per card: nickname (Save / Clear), role select, person picker + Link; "Nobody yet (N)" filter; `highlightCardId` scrolls to and outlines a row.
- **Banking.tsx**: `roleByDebitCard` state from the directory loader; `?cards=<id>` (or `=1`) opens the modal on that card and strips the param.
- **Wheels**: `splitFuelFamily(rows, companyCardIds)` gains a `companyCard` bucket; the snapshot's `companyCardSpend` renders as "Not fuel: $… on company cards (…)"; the "no person on it" card names are `Link`s to `debitCardsHref`.
