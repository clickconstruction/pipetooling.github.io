# v2.4408 — Lien instruments: the lientooling.com prefill window is deleted (2026-10-02)

No migration, no edge function, no behaviour change. [v2.4403](v2.4403.md) removed the last door to the prefill window and left its code unreachable; this PR deletes it. Five files and about 1,100 lines out.

## What went

- `LienToolingPrefillModal.tsx` (466 lines): the field-review window that built a `#d=` link to a lientooling.com form. Only [`JobsStagesTab`](../../src/components/jobs/JobsStagesTab.tsx) mounted it; its import, its `lienToolingPrefillModal` state and its mount are gone.
- `lib/lienToolingPrefillUrl.ts` and `lib/buildLienToolingPrefillFromJob.ts`, with their tests: only the window imported them. What they leaned on (`txLocalityAddressSplit`, `physicalInvoiceIssuer`, `openInExternalBrowser`) has other callers and stays.
- `VITE_LIEN_TOOLING_ORIGIN` in `vite-env.d.ts`: `lienToolingOrigin()` was its only reader.
- Two comments in [`LienInstrumentsModal`](../../src/components/jobs/LienInstrumentsModal.tsx) that still promised the external fallback, one of them the orphaned doc line of the removed `onOpenExternalPrefill` prop.
- The maps: the row and counts for the window in [`JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md) (cluster N is 53 states, 19 single-job opener targets) and its row in the sibling table of [`LIEN_DESK_ARCHITECTURE.md`](../LIEN_DESK_ARCHITECTURE.md).

## What stays

- `onOpenLienTooling` in the row props: despite the name it opens the Lien instruments window.
- The LienTooling link in the Tooling family list (`lib/toolingFamily.ts`), a different door.
- The comment in `lib/jobsDocuments/demandLetter.ts` naming lientooling.com: it says where the letter's structure came from, which is still true.

## Not done

- The guide *send a final demand letter* still says the lientooling.com button "still opens the old external forms". It is on the plain-words legacy list, so fixing that sentence means rewriting the guide.
