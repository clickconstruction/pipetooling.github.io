# v2.2955 — Add document → Send now accepts fillable forms (2026-09-06)

Found by the Direct Deposit Authorization signing test (People → Contracts → Claude Test Sub). **+ Add document → From Contract Book → a form → Send now** refused with *Add contract text, a canonical document URL, or a reference link before sending for signature*, while **Save for later → Send** on the same row worked.

- **Cause**: `saveContractDocumentAndOpenSend` ([`PeopleContractsTab.tsx`](../../src/components/people/PeopleContractsTab.tsx)) called `hasContractSigningContent` with only `signing_body_html` / `canonical_document_url` / `url` from the upsert payload. A form entry has none of those — its signing content is the `form_template_id` on the Contract Book entry, which the kernel already honours (`src/lib/contractSigningContent.ts` returns true for it) and which the row-level Send button passes.
- **Fix**: the guard now resolves the picked Book entry (`applied_contract_template_document_id` → `contractTemplateDocuments`) and passes its `form_template_id` alongside the three text fields. Nothing else changes: the row is still created only on Send email (v2.2851), and Save for later is untouched.
- Also noted from the same test (not fixed here): a signed **form** row's Delete removes the record and the signature PNG but leaves `contract-form-pdfs/<id>/signed.pdf` in the private bucket (service-role only); a `digits` box validates to exactly its mask length, so a percentage must be a `text` box (the Direct Deposit form was corrected the same day).

Client-only; no migration, no edge deploy. Docs: `to-dos/contract-forms-publish-authored.md` records the test.
