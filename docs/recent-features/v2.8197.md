# v2.8197 — HR files: the dev seat says when each section of a document last changed (2026-11-21)

Punch list #315, upgrade 5a, the seat's half. `dev-mcp` server 0.124.0. No new verb, no migration. Built on 2026-11-19 as v2.8002 and server 0.121.0, and held until the seat's upload had room (v2.8117, v2.8126).

## What was wrong

People → HR has said when each section of the summary and the narrative last changed since v2.7108, and how many entries are newer. The seat's `get_person_document` answered a section's size and nothing of its age, so a session relied on a section an entry had moved past without knowing.

## What changed

- **`get_person_document` takes `freshness: true`** on the summary's or the narrative's index: `kind`, no `section`.
- The reply gains `freshness`:
  - for each section, `changed`, the day it took its present words, or *not changed since before* the oldest version read, with `at_least`;
  - `newer_entries`, the entries written since, and `newer_citing`, those whose words cite the section;
  - `look_again`, how many sections an entry cites since; `versions_read` and `older_versions`.
- It reads the document, its newest twelve prior versions and the entries, each as the dev, and hands them to the tab's own kernel, `supabase/functions/_shared/sectionFreshness.ts`.
- It is asked for and never the default. A version is the whole text, and twelve of a long narrative is a large read.
- A read that fails answers `held`, and the index still comes. A named document keeps no versions this reads, and says so.
- **The parse of a citation moved** into that kernel from `src/lib/people/hrDocCitations.ts`, which re-exports it, so the tab and the seat count a citing entry with one function.
- The version's note is in `docs/dev-mcp/SERVER_NOTES.md`.

## Is this the best we can do?

The card put the freshness on every index. The tab reads prior versions only when its fold is opened, for the same reason the seat reads them only when asked: every version is the whole document.

The first cut counted newer entries and left out which of them cite the section, since the citation parser lived on the app's side. That count is the half that tells a reader to look again, so the parser moved.
