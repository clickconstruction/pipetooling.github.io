# v2.2800 — twin-mcp: `open_backtest` rounds + `score_backtest`, and the round-2 kickoff for Wendi's bids (2026-09-05)

Owner ask: set up a fresh robot (a new Claude Fable session with no memory of the first runs) to re-bid Wendi's past bids blind, so the doctrine banked from her 2026-09-04 audit pass (v2.2795) gets measured. Two harness gaps stood in the way.

## twin-mcp (edge; deploy after merge, `briefs.ts` regenerated)

- **`open_backtest(reference_bid, round?)`** — `round: 2` (or higher) opens a new shell `ZZ Twin <PROJECT> (backtest R2)`. Before this the verb was idempotent per (twin, project name) and a re-run got the round-1 shell back — whose ledger carries the STG-6 scorecard (reference value, delta), so the re-run could not be blind. The STG-0 note names the round and declares prior rounds off limits until the scorecard stamp; a round-1 reuse now returns a warning to read the ledger first.
- **`score_backtest(bid, run_label, axis, locked_total, counts_note?, scope_verdict?, note?)`** — the STG-6 unseal for backtests, the way `score_shadows` is for shadows. Refuses unless the twin bid's ledger already carries a LOCK note. Reads the reference's value / outcome / loss category / sent date server-side, computes `delta_pct`, the presence grade, the quality flags (`roundValue`, `weakLoss`, `lossUncategorized`, `stale` — the `referenceGrade.ts` rules, mirrored) and `gate_eligible`, inserts the `twin_run_scores` row (previously hand SQL — the Scoreboard only ever showed BT-6..16), stamps `[STG-6 SCORECARD]` on the twin ledger, returns the facts. Idempotent per `run_label`. Fence: created_by / estimator only.
