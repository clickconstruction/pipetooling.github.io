# v2.6073 — Where files go: the picker finds a paid job, and the refusal's period (punch list #211, after the live run) (2026-10-29)

Two gaps the live run of Documents → Where files go found on 2026-10-29, once PR 1's verbs were deployed: the picker under **Check a job's folder** could not reach the owner's test job 972, which is paid, and Drive's 404 refusal read with two periods.

## What changed

- **The picker looks a job up among every job** (`DocumentsWhereFilesGo.tsx` → `Presses`): the tab's live list keeps the Pipeline's own scope (a status that is null or not paid), so when the typed text matches none of it the picker waits for the typing to rest, then reads `findWhereFilesGoJobs` (`whereFilesGoIo.ts`: `jobs_ledger` by `hcp_number`, `click_number` or `job_name`, any status, eight at most, the newest number first) and offers those rows under *Among every job:* with the same press; *Looking among every job…* while it reads, the read's failure in its words, and the filter words (*No jobs match ‘zzz’. Clear the search*) when nothing is found anywhere. `pickerQuery` (`whereFilesGoTab.ts`) is what goes to the filter: one space between words and none of the marks a filter would misread.
- **One period** (`supabase/functions/_shared/whereFilesGo.ts` → `writeCheckWords`, `cannot_open`): Drive's reason loses its own trailing period before the sentence adds one, so *Drive answered 404: File not found: <id>. Share it with …* reads as one sentence. The same words serve the root card, a job's folder and the photo sweep's reason.
- The guide *set where a job's files go* → Check a job's folder says a paid job is looked up by its number; `folderName.test.ts`, `whereFilesGoTab.test.ts` and the render smoke hold the two.
