# v2.4586 — Lien desk: links land on Next up (2026-10-05)

Client only; no migration, no edge function. PR 4 of 5 for punch list #82 ([`to-dos/lien-desk-next-up/`](../../to-dos/lien-desk-next-up/README.md)). Stacked on PR 3.

## What changed

- **A bare `?liendesk=1` lands on Next up.** [`stagesDeepLinks.ts`](../../src/lib/jobs/stagesDeepLinks.ts) read a link with no `kind` as Notices. With no job, no pile and no kind it now reads `next`, the tab the desk's own buttons open on. `liendeskJob`, `liendeskPile` or `kind=notice` still mean Notices; `kind=affidavit` and `kind=timeline` are unchanged.
- **The Dashboard's cards land on what they describe.** The lien deadlines card (`lien-notice-draft`) uses the bare link, so it lands on the list it counts from. The leader's *Approve N lien notices* card (`lien-notice-approve`) now names `liendeskPile=awaiting`. Same in Quickfill. The tracking, letter two, missed, filing window, suit year, serve and demand cards were aimed in v2.4561 and v2.4562.
- **A GC's run as a row** shipped with the kernel (PR 1): a GC with two or more notices ready is one **Send the run** row.
- The guide *see which supply houses are owed on a lien job* links to the desk's Notices tab, where the mark it describes is drawn.

## Checked in the app

Prod data, nothing written: `?liendesk=1` opened on Next up; `?liendesk=1&liendeskPile=awaiting` opened on Notices with *Awaiting approval* pressed.
