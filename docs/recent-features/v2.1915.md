# v2.1915 — Pipeline gets Old/New views: the money story + Today's money moves (2026-08-20)

Owner-approved prototype ("Pipeline 2.0" artifact), shipped with the Old/New playbook (Counts precedent, v2.1909): the Pipeline tab gains **Old / New** pills (per-device `jobs_pipeline_view_v1`, default **Old** — the classic board alone, untouched). **New** renders two money layers between the toolbar and the jump strip; the jump strip (Waiting → Working → Ready to Bill → Billed, with counts) and the board below are identical in both views.

- **Money story strip** — four clickable answer cards from the lean `StagesHeaderStats` spine (v2.1821), zero extra fetches:
  - **ready to ask for** = capable-to-bill + Ready to Bill exposure → opens the Capable of Being Billed list
  - **waiting on customers** = Billed remaining, with an age bar (under-30 / 30–90 / 90+ by the aging-chip clock) → aging chart (dev/controller) or jump to Billed
  - **in collections** → jumps to Collections
  - **collected · last 8 wks** = payments by Monday-start week with a sparkline → paid profit chart (dev/controller)
- **Today's money moves** — a system-written queue derived from the same stats: *Bill the finished work — $X* (→ Capable list), *Chase the 90+ tail — $Y* (→ applies the existing 90+ filter and opens Billed), *Allocate N bank deposits* (→ Accounts Receivable; AR-role gated), *N bills have no bill date* (→ Billed). Header shows the Σ of the dollar moves; empty queue renders "the pipeline is clean".
- **Kernels**: new [`pipelineOverview.ts`](../../src/lib/jobs/pipelineOverview.ts) (story + moves view-models, 7 tests); `stagesHeaderStats.ts` extended additively with `collectedByWeek` + `billedNoDate` (lean selects gain `payments.paid_on` and `invoices.billed_at`; parity fixtures updated); `invoiceBilling.ts` gains `countBilledRowsMissingDates` (positive remainder, no billed_at/est date, Collections excluded — the aging-chip cohort).
- Component: [`PipelineOverview.tsx`](../../src/components/jobs/PipelineOverview.tsx); wiring in `JobsStagesTab.tsx` reuses the existing openers (Capable modal, aging/profit charts, AR modal, `focusStagesSection`, `setBilledAgingFilter`).

Deferred to iteration 2: the underwater-bills move (needs `get_billed_aging_costs` + billed rows) and any board demotion/re-layout.
