# v2.6126 — A Note or a Walk report's Save no longer names a job percent (punch list #189, a follow-up) (2026-10-30)

Punch list #189's camera live run of 2026-10-30 found it: on the camera-first report form, a Note filed on the ZZ Test job read *Save · job 0% · 1 photo*, though a Note has no percent field and the report left the job's unset percent unset. Fix, no migration, no edge function.

## Cause

`AdditionalReportModal` gave Save's words (`reportSaveWords` → `saveWords`) the job's number on every report type: the stage lines' number when the job has them (`useJobLineProgress` loads them for any type), else the typed or seeded percent, else 0. A percent is filed only when the chosen type has a `percent_0_100` field (`percentFieldLabel`), so a Note, a Walk or any other type without one named a number it never wrote.

## What changed

- **`saveWords`** (`lib/reports/stagePct.ts`) takes `jobPct: number | null`; null reads *Save report*, *Save report · 1 photo*, *Save report · 2 photos*. **`reportSaveWords`** (`lib/photos/reportPhotos.ts`) passes it through. Both tested.
- **`AdditionalReportModal`**: `jobPctForSave` is null when the type has no percent field, so the camera-first Save names none. The stepper (`FieldPctUpdateModal`) always files a percent and is unchanged.
- **Test**: `AdditionalReportModal.camera.render.test.tsx` switches to the Walk on a job with stage lines, reads *Save report*, sends a shot, reads *Save report · 1 photo*, saves, and finds no percent in the report and *1 photo* on its Stage progress line. Its table stub now keeps a template's own fields (`.eq('template_id', …)`), which it had ignored, so every template had read the Status report's fields.
- **Guide** *take photos for a report*: the Save section says a Note or a Walk files no percent.
