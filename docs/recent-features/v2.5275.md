# v2.5275 — Messages: By company reads a job that ended as declined or not carried (2026-10-12)

Messages build, wave 1, cluster 6, a follow-up to v2.5253 (`flows/board.ts`) that the lead asked for. A kernel change and its tests. No table, no screen, no edge function, no migration.

**The gap.** By company's job lines read the step a company is on for each job, else "done" from `jobsDone`, else "not started". A job whose lane ended at a fork has no step on now and is not done. That is a customer who declined, or a trade whose quote we did not carry. So it read "not started", which says the opposite of what happened.

**The change.** `BoardCompany` gains `jobsEnded`, by job: the fact that ended the lane. It is `flows/state.ts`'s `perJobJobs(reading)[].ended`, one of the facts `flows/facts.ts` marks `endsLane`. The job lines move into an exported `companyJobLines`, which `companyTable` calls. A job with no step on now reads how it ended first ("declined", "not carried", else the fact's own words), then "done", then "not started". Each line carries `ended`, so the screen can mute it. The field is optional, so the loaders and tests that do not set it read as before. A lane that ends on a fact with no short word here reads the fact's own words. The trade's `quote_declined` (v2.5279, helper 4) reads "they declined to quote" that way.

**Tests.** Tejas Power with Stone Oak ended `not_carried` reads "not carried" even with the job also listed as done. Marcus Bell's reading from `flowFixtures.ts` (`readFlow`, then `perJobJobs`) reads Bell Family Dental as "declined" in `companyJobLines`. He stays off By company's table, since he is off the flow.
