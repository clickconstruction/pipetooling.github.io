# v2.8707 — The type check's memory line names the heap only when the number is real (punch list #434) (2026-11-27)

Infra, no screen. No migration, no edge function, no workflow file changed. A correction to v2.8696, found the same day by reading its line on three cold runs.

## What was wrong

v2.8696 ends every `tsc` with one line: its time, the heap it ended holding after a forced collection, and the most it held resident. Its fragment says the heap number holds for a run that checked something. It does not.

- Three cold parts on a GitHub runner, each checking everything: `ended holding 33 MB` (and 29, and 30) `of its 13,568 MB heap (0%)`, after peaks of 8,857, 7,363 and 9,337 MB.
- The deploy's `tsc -b` of the app part, cold, the same day: `ended holding 7,995 MB of its 13,312 MB heap (60%) after a collection of 4.9 s, and held 9,357 MB resident at most.` That one is right.
- So `tsc -b` still holds its program as it exits, and `tsc -p` with a build-info file has mostly let it go, cold or warm. One warm part that had this change's tests to check still held it (3,492 MB). The config program held it too, with or without a build-info file.

A line that read 33 MB on a run that had held 9 GB said something false to whoever read it. The warning was never wrong: it reads the larger of the two numbers.

## The change

- **The line names the heap only when the number is the program's** (`heapIsReal` in `scripts/lib/typecheckMemory.mjs`): a collection ran, and the heap in use is a quarter of the peak or more. On the runs measured it was 68% to 90% of the peak when tsc held its program and under 1% when it had let it go.
  - Held: `build: app's tsc took 5:49, ended holding 7,995 MB of its 13,312 MB heap (60%) after a collection of 4.9 s, and held 9,357 MB resident at most.`
  - Let go, or not collected: `typecheck: app's tsc took 5:35 and held 8,857 MB resident at most, 65% of its 13,568 MB heap.`
- **A dev machine's line is the peak alone** unless `TYPECHECK_COLLECT=1`. Without a collection the heap in use is partly what was not yet thrown away. v2.8696 printed it with the words *not collected first*.
- **The warning is unchanged**: from four fifths of the cap, on the larger of the two numbers, and the exit code is `tsc`'s own.
- The comments in the hook, the kernel and `scripts/typecheck-queued.mjs`, the sentence in `docs/SESSIONS.md` and the card say what was measured, in place of what v2.8696 claimed.

## Why both numbers stay

- **The peak resident size** is exact everywhere and is the only number a part of `npm run typecheck` has. It moves a few hundred MB from run to run with the collector's timing: the app part read 8,857 MB as `tsc -p` and 9,357 MB as `tsc -b` on the same day.
- **The heap after a collection** is steadier, and it is the number the card's tables hold. The deploy prints it for the app program, cold, on every merge: 7,995 MB on 2026-11-27 against 8,087 MB measured the same way on 2026-11-24.
