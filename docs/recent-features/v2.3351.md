# v2.3351 — legal-notify-dispatch: unheard events are consumed, not saved up (2026-09-11)

Follow-up to v2.3325 (Legal portal PR 5), found on the first live walk-through. **Edge function `legal-notify-dispatch` changed — redeployed 2026-09-11.** No migration.

## Why

The dispatcher did `if (recipients.length === 0) continue` per firm, so a firm with no confirmed recipients (the state every firm starts in) never had its `legal_notification_queue` rows stamped. The first person to confirm would have been sent every `referred` / `answer` / `pulled` event since the firm was created, and the first digest person would have got the same backlog under "since your last digest". Live symptom: two rows sat with `sent_now_at IS NULL` through three cron ticks that each returned `{ok:true, now:0}`.

## What changed

- No confirmed recipients → every open row gets `sent_now_at` and `digested_at` stamped, then the firm is skipped as before.
- Recipients but no digest-mode people → open rows get `digested_at` stamped before the digest lane (which has nobody to run for).
- The rule, stated in the function: an event is heard by whoever is subscribed when it happens, never replayed to whoever joins later.

`docs/EDGE_FUNCTIONS.md` → *legal-notify-dispatch* carries the same sentence.
