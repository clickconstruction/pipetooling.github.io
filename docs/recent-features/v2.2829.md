# v2.2829 — Work Orders tab, PR 3: the job window row, the unpriced-draft nudge, and the doors (2026-09-05)

Third PR of the **Work Orders tab** train (PR 1 [v2.2814](./v2.2814.md), PR 2 [v2.2819](./v2.2819.md)): the intake path the owner described — an assistant takes a job in, the master already plans to subcontract it, she drafts the work order for that sub from the job window and the master prices it from the dashboard.

- **Job window row** — [`JobWorkOrderStrip.tsx`](../../src/components/jobs/JobWorkOrderStrip.tsx) + [`JobWorkOrderChip.tsx`](../../src/components/jobs/JobWorkOrderChip.tsx) (pattern of `JobContractStrip` / `JobContractChip`; `useJobWorkOrderCoverage`). `JobFormEditFactRows` gets a **Sub work order** fact row right under Contract (`workOrderJob` / `workOrderAuthUserId` props, passed from `JobFormModal`): chip + one door — *Draft a work order…* (none) · *Set a price…* / *Open draft* (draft) · *View* (sent) · *View record* (signed) · *Re-offer…* + *Draft for another sub…* (declined). The door mounts `WorkOrderAssemblerModal` with `jobs=[job]` so the job is pre-anchored (step 1 skipped). Side fix: both the Contract and the new row now fall back to the modal's fetched job (`initialJob ?? editing`), so the `?edit=<id>` deep link shows them too (Contract used to vanish there).
- **View bill** — `HostedStripeBillPanel` shows the strip read-only under the contract strip (`readOnly`: chip + *View*).
- **Needs You** — new hook [`useUnpricedWorkOrders`](../../src/hooks/useUnpricedWorkOrders.ts) (draft rows with `amount IS NULL`, `summarizeUnpricedWorkOrders` kernel: count, sub names, oldest age; refreshes on `work-order-changed`). `dashboardNeedsYou.ts` gains `work-orders-unpriced` (rank 40, amber, kicker *Work orders*, *Price it / Price them*), gated `unpricedWorkOrdersEnabled` (office roles) — tested. `DashboardPinnedQuickRow` wires the hook and the action → `/jobs?tab=work_orders&wof=drafts`; the board reads `?wof=<filter>` as its initial filter.
- **Doors** — `SubSheetWorkOrderPanel` takes `onOpenAssembler`; when the sheet's job is in the Sub Labor modal's jobs cache (`JobsSubLaborFormModal`), *Write a work order for <sub>…* and *Re-offer…* open the assembler pre-anchored to the job, the sub and the sheet with the **sheet total as the price** (`WorkOrderAssemblerInitial.amount`); the inline editor stays for multi-assignee sheets and sheets without a cached job. `StepCommitmentPanel` rows (any status past draft) link *Work Orders ›* to the board (`?wo=<id>`); the step editor itself is unchanged — step-anchored orders have no job, and the assembler's document is built from one. `PersonDeskWorkOrdersSection` links every non-step order to the board (`Work order ›`), shows `WO-…` record ids and *unpriced* drafts, and labels job-anchored orders *Job*.
- Guides: [assemble a sub work order](../../src/content/help/assemble-a-sub-work-order.md) (job window + dashboard sections), [send a sub a work order from a sheet](../../src/content/help/send-a-sub-a-work-order-from-a-sheet.md) (the box is a door).

No migration, no edge deploy. Follow-ups: a step-anchored path through the assembler (project facts instead of job facts); a Pipeline row chip (row context threading).
