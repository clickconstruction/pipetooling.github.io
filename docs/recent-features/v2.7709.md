# v2.7709 — Painted maps: a list that is closed while it loads no longer finishes behind your back (2026-11-17)

A merge-queue build passed every test and still failed, on one unhandled rejection caught after a test's page was torn down: `ReferenceError: window is not defined`, from a `setRead` in `JobDocumentsPaintedMaps` right after its `await loadMaps(…)`, reported against `JobWindowDocumentsTab.render.test.tsx`. Builds around it passed. It was a race, and the pull request it failed touched neither file.

## Why it raced

- The Documents tab's **Painted maps** section set state after its read with no check that it was still on screen.
- The tab's render test faked every read but that one. The section's read went to the address a test run holds, which answers nobody, so each test made a real name lookup and moved on while it was out.
- A lookup that failed fast landed inside the test. One that failed slowly landed after the last test, when the page was gone. React reads `window` on every state set, so the late one threw, and a rejection nobody holds fails the run.

## What changed

- `useTakenDown()` (`src/hooks/useTakenDown.ts`) answers whether the component has been taken off the screen, as one function that never changes. A read asks it after each `await` and stops.
- Five reads ask it, on the failed branch and the landed one: the Documents tab's section (`JobDocumentsPaintedMaps`), the Documents page's tab (`DocumentsPaintedMapsTab`), a job's strip and a development's strip (`JobPaintedMapsStrip.tsx`) and the layer on a map (`usePaintedMapsLayer`). All five had the same shape: one `load` started by the effect, by a change heard elsewhere in the app and, on two of them, by **Try again**. That is why the guard is a hook and not a `cancelled` flag in one effect, which would leave the other two callers open.
- `JobWindowDocumentsTab.render.test.tsx` fakes the section's read, so no test there looks up the dead address for it, and an `afterEach` waits until the section has left *Loading…* before the tab is taken down.
- `JobDocumentsPaintedMaps.render.test.tsx` holds it: the section is mounted on a read that has not landed, taken down, the page's `window` removed, and the read then fails or lands. On the old code both cases throw the build's own error.

## Not changed

- Nothing on screen. A read that lands while the section is up draws as before, and a job swapped under a mounted section still takes the last read to land.
- `TaskMapField`'s picker and the header search's read already checked. So do the tab's two other sections that still reach the dead address in this test, the job's papers and the statements of charges.

## Left

- The tab's test still makes those two real lookups a test. They are guarded, so they cannot fail a build, but they are slower than a fake.
