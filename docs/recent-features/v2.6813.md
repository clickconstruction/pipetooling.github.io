# v2.6813 — The rest of the Bridge leaves ZZ test jobs out: Build, the people, Sales and the Collect scorecard (2026-11-09)

Follow-up to v2.6807 (PR #7491), which gave the ZZ test-job rule to `loadBridgeData` and the Bill desk and listed the Bridge loaders that still had none. This PR surveys those loaders and applies the same rule, the same way: a required `zzTestJobIds: ReadonlySet<string> | null` (null keeps every row, for a dev whose switch shows them), rows dropped by their own `job_name, customer_name` where the read carries them and by the shared ids otherwise, the filtering in the pure kernel `src/lib/bridge/zzTestJobs.ts`.

## What changed

- **`src/lib/bridge/zzTestJobs.ts`**: `bridgeZzJobIds(namedRows, ids)` is the shared ids plus the jobs a read's own rows name as ZZ (null stays null), and `withoutZzJobKeyedRows(rows, jobIdOf, ids)` drops rows keyed to a job by an id alone. `withoutZzFieldSessions` is now the second with a session's key. Both are the existing rule (`isZzTestJob`), not a new one.
- **The loaders** take the required option: `loadBuildPaceInputs`, `loadBridgeVectorInputs(db, data, { zzTestJobIds })`, `loadVectorSessions(…, zzTestJobIds)`, `loadVectorDaysInputs`, `loadDemandInputs`, `loadMarketDeskReads`, `loadSalesDeskReads`, `loadCollectScorecardReads`. The job reads add `job_name, customer_name`; the people's event, percent and report reads add the job id.
- **`Bridge.tsx`**: one `readZzTestJobIds` (the shared read while `useZzTestJobsHidden(role)` hides, else null) feeds each of these loads, and the read keys of the desks and the days cache carry the switch, so a dev who flips it reads again.
- **`sheetReads.ts`** passes the ids to the people, the eight weeks, the build pace and the demand read. The copies under `supabase/functions/_shared/gcKernels/` are regenerated.
- Tests: the kernel's two new functions in `zzTestJobs.test.ts`; the loaders on a fake client in `loadBuildPace.test.ts`, `loadDemandPace.test.ts`, `loadBridgeVectors.test.ts` (new), `sales/loadSalesDesk.test.ts` (new) and `collect/loadCollectScorecard.test.ts`.

## A ZZ job made from a bid

The job leaves; the bid stays a bid. So the test job is no started work and no win. A bid with no outcome whose only job is a ZZ job reads as open again, which is what it is if the job was a test. Bid 398 is marked `started_or_complete`, so it does not return to the pile.

## The bids (asked, not applied)

Bids have their own ZZ rule, `isZzBidName` (`src/lib/bids/bidPickerRobots.ts`, a project name that starts with the word ZZ), used by the bid picker's Hide robots and nowhere on the Bridge. The demand, Market and Sales reads should follow it: the robots' shadow and backtest bids are rows in `bids`, each one counts as a bid invited on Market, and about 36 of them fall inside today's 8-week window. They carry no sent date and no value, so they move the ask count and the relationship book, not the dollars. It is a rule the Bridge has not used, with one open question (the picker keeps a ZZ bid marked by or for the person; the Bridge has no such person), so it waits for a yes. Estimates have no ZZ rule anywhere.
