# v2.5132 — Bids: History offers no Undo on a change no person made (2026-10-10)

Bid history follow-up (punch list #73), found on the ZZ Test walk of PR 5 and PR 6 on 2026-10-10. Directed by PUNCHLIST, built by Helper 11. No migration.

## The bug

An action whose rows carry no author and no app tag (`changed_by` and `by_app` both null), such as a server job's removal of set-aside labor rows, reads *the app* in the History window (`bidHistoryWho`). Yet it offered **Undo**: `bidUndoPlan` held back only the app's tagged writes (`by_app`). ZZ Test's *Removed 9 set-aside labor rows* of 2026-10-08 showed it, against the docs' rule that the app's own actions offer none.

## The fix

`bidUndoPlan` now returns *Undo is off. No person made this change.* (`BID_UNDO_NO_AUTHOR`) for an action whose every row has no author and no app tag. A robot's paste (`robot-paste`) keeps its Undo: the window names it *the robot*. The app's tagged writes still offer nothing at all. An action with a person's rows is not held.

## Tests

- `bidHistoryUndo.test.ts` (+3):
  - a no-author action is off with the reason;
  - a robot's paste with no author keeps its Undo;
  - the app's tagged writes still offer nothing, and a person's rows are not held for this reason.
