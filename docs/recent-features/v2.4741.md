# v2.4741 — Lien desk: the old caller search code is removed (2026-10-06)

**Why:** v2.4731 (#4745) retired the search inside `LienCallerDoor`; the desk's find box became the only reader of [`lienCallerMatch.ts`](../../src/lib/jobs/lienCallerMatch.ts), and it reads `findOnDesk(find, sentIndex).sent` alone. Everything else the door used was left in the kernel with only its tests calling it.

## What was removed

- `lettersOutNow`, `CALLER_LETTERS_OUT_MAX`, `callerTryWords`, `CallerTryWord` and `STREET_SKIP`.
- The jobs with nothing mailed: `CallerMatchInput.deskJobs`, `DeskJobRef`, `CallerJobHit`, `CallerIndex.unsent`, `DeskFind.unsent` / `unsentMore`, `DEADLINE_WORDS`, and `CallerFmt.money`. `LienDeskModal`'s `callerInput` memo no longer builds the three tabs' `deskJobs`.
- The GC signposts: `CallerGcHit`, `CallerHit`, `CallerIndex.gcs`, `DeskFind.gcs`.
- `DeskFind.sentMore`, `deskFindIsEmpty` and the index rows' `open` / `street` / `owner` / `gcId` / `gcName`; `jobWords` returns the haystack and the numbers only.
- The stale *Open the job ›* comment in `LienDeskModal` (its `openDeskJob` went in v2.4731).

## What changed in behaviour

The slip forgiveness now looks for a cut word in the sent letters' words only. Before, a word that matched a job with nothing mailed was never cut, so *Also sent* stayed empty; now such a word (four letters or more) can be cut back until it matches a sent letter. A three-letter word is never cut.

## Tests

`lienCallerMatch.test.ts`: the *letters out now*, *words to try*, *nothing mailed* and *GC signpost* cases removed; a GC's name finding its sent letters, and a job with nothing mailed finding no letter, added. The `j300` / `j301` fixtures went with them.
