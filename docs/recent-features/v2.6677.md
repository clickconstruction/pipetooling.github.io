# v2.6677 — The estimate text’s link ends in ten letters (2026-11-08)

Punch list #281 (`to-dos/short-estimate-link/README.md`), PR 2 of three. PR 1 (v2.6657) put the share link in the text the Tell the customer sheet sends with an estimate: 32 base64url characters, 75 characters of link. The owner's call 2 on 2026-11-07: the code is 10 characters, with the guard.

## What changed

- **Migration `20261108053000_estimate_short_codes.sql`** (`docs/migrations/20261108053000_estimate_short_codes.md`) re-states `share_estimate_link` to mint ten letters from `23456789abcdefghjkmnpqrstuvwxyz`, 31 letters with no look-alikes, unbiased (a byte at or past 248 is thrown away). The row keeps the code's SHA-256 as before, so the shape check, the unique, the 14 days and `_shared/estimateTokenLookup.ts` are unchanged; a link made before the push opens until its day. The link goes from 75 characters to 53.
- **The guard on guessing**: `estimate_link_misses` (the hour, a hash of the caller's address, the count) and `estimate_link_miss(p_source_hash)` for the service role alone; `_shared/estimateLinkMisses.ts` (`recordEstimateLinkMiss`, with its unit test in `src/lib/estimateLinkMisses.test.ts`) counts a lookup that finds no hash against its source and the three functions that open an estimate from a link (`get-estimate-for-customer`, `accept-estimate`, `log-estimate-option-view`) answer **429** `locked` once a source passes 20 misses in the hour; every miss logs one line. Misses only, so a working link from the same address still opens; a bump that fails is no lock. A nightly `pg_cron` line drops hours older than a day.
- The SQL bed `scripts/pgtest-estimate-share-links.sh` re-applies both migrations and checks the alphabet, the length, the guard's count and its grants; `estimateTextLink.test.ts` holds the new length.
