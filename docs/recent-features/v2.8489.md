# v2.8489 — The push check no longer says the deploy holds when it does not (2026-11-24)

`npm run check:calls-ahead` ended every finding with one sentence: *the deploy holds until the push*. The deploy's own step (`--prod`) holds only for a name a pending migration **creates**; a function a migration **replaces** is a warning there, and prod's old body answers until the push. So a pull request that only replaced functions was told something false. #9324 (v2.8251, punch list #417) was kept out of the merge queue on those words, and the card and a PR comment repeated them until 2026-11-24.

## What changed

- **`callsAheadAdvice(ahead)`** in `src/lib/callsAhead.ts` picks the sentence by kind. Any call to a created name keeps `CALLS_AHEAD_ADVICE`, the hold. A change whose every call reaches a replaced function gets `CALLS_REPLACED_ADVICE`: push right after the merge, no deploy waits for it, the old function answers until it lands.
- **`scripts/check-calls-ahead.ts`** uses it in three places: the line under the findings, the step summary, and each annotation, which carries the advice for its own kind.
- The step summary's opening names which case it is, in place of *creates or replaces*.
- The label's description now reads *Its client calls what its migration creates or replaces: push right after the merge*. It said *what only its migration creates*, which is wrong for a change that only replaces functions. The check writes the description only when it makes the label, so the label on GitHub was changed by hand on 2026-11-24, on a yes given in the building session.
- `docs/migrations/20261109160000_on_site_move_job.md` said the same wrong thing about a restated function and is corrected in place.

## What it does not change

- The label. A replaced-only pull request is still labelled *push right after the merge*, because the push is still owed promptly.
- `--prod`. It fails on a created name and warns on a replaced one, as before.

## Tests

`src/lib/callsAhead.test.ts` holds the three cases: created, replaced only, and mixed. Run by hand against v2.8459's change (#9620, a migration that only replaces functions): the check now ends with the no-hold words. A second hand run, on a change that creates a function the client calls, was started as a control and did not finish on a loaded machine. The hold's words are unchanged and rest on the unit test.
