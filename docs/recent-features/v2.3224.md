## Why the setup command

The kickoff's setup step 3 said "open Edit Config … add the `twin-mcp` entry inside `mcpServers`". On 2026-09-09 Grace's Desktop run ended with the robot correctly reporting "the twin-mcp connector isn't attached to this conversation": her `claude_desktop_config.json` had **no `mcpServers` block at all** (a fresh install has none; there is no obvious place to type), so the bridge was never configured, no log file existed, and the newest key on the fleet card read *never used*. A second cause waits behind that one on every Mac: Desktop launched from the Dock cannot see a shell's PATH, so `"command": "npx"` fails silently when Node came from Homebrew or nvm. Prose cannot fix either for a non-developer; a command can.

## Left alone, on purpose

- The kickoff's **loop rules** (a table read by a fresh agent, 2026-09-09, found five gaps: the plans-blocked shell has no legal exit under "never call `next_shadow` while a shell is open and unlocked"; `ask_question` never names an `audience`; a plans ask needs no `choices` since v2.3212 but the prompt implies it does; no resume check for an orphaned open shell; the non-plumbing branch hard-stops the batch). They want an owner decision on whether a blocked shell is voided or left open, so they are a separate change.
- Windows: the setup command is Mac-only (Desktop's config path); the kickoff says "on Windows ask a dev".
- The calibration standard stays on Settings — it is a user attribute, not an operator tool.
