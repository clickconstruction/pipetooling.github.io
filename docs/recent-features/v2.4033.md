# v2.4033 — My Time day editor: a new session right beside another one saves — `insertDraftClockSession`, `MY_TIME_DRAFT_IN_BLOCK_EDITED_MESSAGE` (2026-09-28)

Client only; no migration, no edge function. From the map's quirk 27 (found by the tests of [v2.4021](v2.4021.md)); punch list **#46** row 10. Stacked on [v2.4032](v2.4032.md).

## The bug

A draft session (`draft:people-hours:` id — People → Hours manual entry, or + Add session) is inserted on its first save. Add session's overlap check is half-open, so a new session may end exactly where a saved one starts; blocks group rows within a second of each other, so the two became one block. Saving it failed either way: left as it was (one part per row) it hit the guard for splitting a draft and was refused with *Splitting a draft session before its first save is not supported yet*; merged into one part it reached the replace RPC with the non-uuid draft id. The draft was never inserted.

## The fix

- **In the ladder** ([`lib/myTimeDayPersist.ts`](../../src/lib/myTimeDayPersist.ts)), a block of several rows holding a draft is handled first. Left as it is (`segmentsAreTheRowsUnchanged`), each row saves on its own in row order: the draft is inserted (`insertDraftClockSession`, the single-row insert moved into a helper, same values and checks), the saved rows get a note update. Split, merged or with a seam moved, it is refused with `MY_TIME_DRAFT_IN_BLOCK_EDITED_MESSAGE`.
- The single-row draft insert and the single-row "splitting a draft" refusal are unchanged.

## Known limit

Rows are written one after another (quirk 26): if the insert is refused after a saved row's note was written, that note stays written.
