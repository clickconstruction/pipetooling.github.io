# v2.3372 — The newest % complete wins, whoever set it (2026-09-12)

Owner bug report: Mission Hills (J523) was set to 90 % by hand on Sep 3, but the Pipeline's *Today's money opportunities* read "J523 Mission Hills 100% spent at 77% done". The 77 % was a field report from May 15. Every reader took the latest report's % over the job's own whenever a report existed, with no look at the dates. Migration [`20260912155909_report_pct_newest_wins.md`](../migrations/20260912155909_report_pct_newest_wins.md).

## The rule

The newest dated % wins. A report's % stands only when no hand-set is recorded on the job or the report was filed after the last hand-set; a hand-set at the same instant or later means the office typed it knowing the report, so the job's own `pct_complete` is the current answer. Hand-sets are dated by `job_pct_events` (source `manual`; the trigger on `jobs_ledger.pct_complete` is the single writer, so every hand-set since 2026-08-07 carries a timestamp — `seed` rows are the back-fill and `service` rows are report-derived, neither counts).

## Where it lands

- **RPC** `list_latest_report_completion_pct` now returns `reported_at` and `manual_at` beside the percent (dropped and recreated — the OUT list changed). Same percent parse, same SECURITY INVOKER.
- **Kernel** [`jobSummaryPercentComplete.ts`](../../src/lib/jobSummaryPercentComplete.ts): `reportPctIsCurrent(reportedAt, manualAt)` and `currentReportPctByJobId(rows)` — the RPC's rows become the `job id → report %` map with stale reports left out, so `resolveJobSummaryPercentCompleteWithSource` falls through to the office % without changing. Both RPC readers use it: [`useJobSummaryData`](../../src/hooks/useJobSummaryData.ts) (Job Summary's % column and Burn, the Pipeline's burning-jobs card) and [`useQuickfillCompleteNoBillJobs`](../../src/hooks/useQuickfillCompleteNoBillJobs.ts).
- **Costs tab** ([`useJobChargesTimelineInputs`](../../src/hooks/useJobChargesTimelineInputs.ts)): one more per-job read, the job's manual `job_pct_events`, folded into the value events as `kind: 'manual'` (`buildJobManualPercentEvents`). [`jobChargesTimeline.ts`](../../src/lib/jobChargesTimeline.ts) `newestPercentEvent` picks the newest dated % (a hand-set beats a report on the same day); [`jobBurn.ts`](../../src/lib/jobs/jobBurn.ts) reads it for `percentDone` and reports `percentSource: 'job'` when a hand-set won, so the verdict line reads "90% done (set on the job)" instead of naming a stale report. The chart's value line steps at the hand-set too; `hasReportMarker` ignores manual events, so no 🚩 is drawn for one.

## Verified

Prod counts on 2026-09-12 before the change: two open jobs had a hand-set newer than their last report — J523 (90 vs 77; Sep 3 vs May 15) and J804 Summit GC Auto Zone (80 vs 24; Aug 10 vs May 26); both were the card's "burning" jobs. Seven more open jobs disagree with no hand-set on record; the report keeps winning there.

Tests: `jobSummaryPercentComplete.test.ts` (the rule and the map), `jobChargesTimeline.test.ts` (newest event, same-day tie, no flag for a hand-set), `jobBurn.test.ts` (a hand-set after the last report reads as the job's %).
