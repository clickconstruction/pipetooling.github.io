# v2.6719 — The case search unions the text of a record's files (punch list #285, PR 2) (2026-11-08)

Punch list #285 (`to-dos/search-reaches-linked-file-text.md`), PR 2 of three, on PR 1's rows ([v2.6714](./v2.6714.md)): `dev_case_search` gains the `file` source, so the seat's `search_case` finds a line of a transcript, an email file or a text PDF on an evidence record or a matter's Evidence tab, naming the record it hangs on. The owner's ask of 2026-11-08: any line from any recorded call searchable in the app, with no retyping.

## What changed

- **Migration [`20261108220000_case_search_files.sql`](../migrations/20261108220000_case_search_files.md)**: `dev_case_search` replaced. Every branch of the union gains three trailing columns, `record_kind`, `record_id` and `record_title` (null off a file hit), and the `file` branch joins `file_index` rows with `source <> 'drive'` and text, on the person (`person_id`) or the matter standing on them (`matter_id`), each to the attachment, its evidence record or entry, or the unvoided matter document — so a hit carries the file's name as its `title`, the record's day, the row's `counsel_only` mark, `ts_rank_cd` and `ts_headline` over the text, and the record it hangs on (`record_kind` evidence | entry | file | matter_document). `p_in` accepts `files`. A partial GIN over `to_tsvector('english', coalesce(text, ''))` on the record rows makes the prefilter cheap. A row whose record is gone or voided is left out until the sweep drops it.
- **The seat** (`_shared/devMcpCaseSearch.ts`, `dev-mcp` server 0.46.0): `CASE_SEARCH_SOURCES` gains `files`; a `file` hit's `read_next` names the index row (`read_rows` on `file_index` by `drive_file_id = id`) and the record (`get_person_file` by `record_id`, or `legal_matter_documents`); the `matter_document` hit's `read_next` now says its file's words are a file hit; the reply's note explains the file hit and what is not found yet (a scan, a kind the index does not read, a file filed in the last ten minutes, counted by `read_file_index_status`). `search_case`'s description and its `in` enum carry `files`.
- **Tests**: `src/lib/devMcp/devMcpCaseSearch.test.ts` (the seventh source, a file hit's record fields and `read_next`, the migration pinned: the GIN, the seven branches, the three nulls on six of them, the person-or-matter join, `in: files`, the jsonb keys).
- **Docs**: `docs/EDGE_FUNCTIONS.md` (dev-mcp), `docs/dev-mcp/README.md` (`search_case`), `docs/HR_FILES.md` (Evidence), the card.

## Read closer than the card

- The card's PR 2 row drew *the HR file's search box* showing a file hit. The app's HR file has filters, not a search box; the card's own mockup line names the seat's `search_case` as the box, and that is what this PR delivers. An app-side case search is a card of its own if the owner wants one.
- The hit carries no page or line: the index keeps a file's text whole, not its page positions. The snippet marks the line.
- #288 (one documents table, `20261108210000`) replaces `dev_case_search` too. Migrations apply by stamp, so this later stamp is the final body and carries #288's sectioned union over a matter document kept as text, and the file union leaves such a document's bytes out so one line is not found twice. The push therefore waits until #288's migration is on main (the body names its table and column).
