# v2.2058 — Checklist scheduling overhaul 4/4: the "When" Add modal (2026-08-22)

The UI phase, per the approved "Checklist Item Anatomy" mockups.

- **When control** (first-class, replaces the Advanced-buried scheduling):
  `Today | On a date | Repeats` segments; Repeats sub-selects
  `Weekly on…` (S–S day pills, Starts, Ends-optional) or
  `— days after it's done` (count + Starts). Component state `when` /
  `repeatMode` maps onto the unchanged storage fields at save
  (`effRepeatType`/`effStartDate`); no schema change.
- **Live summary sentence** — `checklistScheduleSummary()` kernel
  (`src/lib/checklistScheduleSummary.ts`, +8 tests) renders a green
  `role="status"` line recomputed per keystroke; `startNotOnChosenDay()`
  appends "First occurrence lands on the next chosen day." when the start
  date's weekday isn't selected.
- **`show_until_completed` untangled** (S1): the checkbox ("Stays on the
  list until done") only renders for one-off modes and is forced `false`
  for repeats — the accidental repeating meaning (Manage misclassification +
  Outstanding pile-up) can no longer be created. `repeat_end_date` also only
  persists for weeklies.
- **Notify consolidated**: one row — "Me" checkbox
  (`notify_creator_on_complete`) + "add someone else" select
  (`notify_on_complete_user_id`). Advanced now holds only the dev reminder
  fields and hides entirely for non-dev.

Verified live end to end with a throwaway weekly task: Mon+Thu from a Friday
start → 10 instances (Aug 24–Sep 24, horizon-limited, none before start);
edit to Tuesday-only → 5 Tuesday instances (phase-3 regeneration); deleted
after. Help guide: `schedule-a-task-or-make-it-repeat.md` (new).
