# v2.8065 — Document builder: a Sub NDA draft that breaks a rule still opens (2026-11-20)

Punch list #404, found by the audit of 2026-11-20. A fix to step 7 (v2.8024). No migration and no edge function.

## What was wrong

The Sub NDA's editor saves the draft 0.7 s after the typing rests, with no check, and hands the saved row up to the tab. The tab then decided whether to draw the editor with `readPaperDef`, which is the shape of a paper **and** every rule of one: the plain-words rules on every line, a meaning on every level, at least one breach line, no empty line.

So a dev who typed `(`, `;` or a dash into any field, or cleared a topic's meaning, or took off a level's only breach line, lost the editor one save later. The tab drew **Sub NDA cannot be shown** with "The contents the database holds for this builder do not read as a paper." A reload read the same row, so the builder stayed shut, with no way back in the app.

## The fix

`DocumentsBuilderTab` gates the editor on the draft's shape alone, `parsePaperDef`. A draft shaped like a paper opens in the editor whatever rule it breaks. The rules stay where the editor already lists them: `walkedPublishPress` keeps **Publish revision N** dead and draws `paperDefProblems` under **Before this can be published**.

A draft that is not shaped like a paper still draws **cannot be shown** with its problems, so the flow never draws half a paper.

A draft that parses and has a topic with no row for one of the paper's levels now opens too. The editor cannot make one and cannot mend one: the page draws empty and the Publish press names the missing level. Before this it drew **cannot be shown** with the same line.

## What was left alone

`WalkedBuilder` still reads the published copy with `readPaperDef`. It does not have the lockout: a published copy that fails a rule reads as no published copy, which hides the changed marks and the **Back to revision** presses and shuts nothing. The Publish press never lets such a copy be made.

The help guide's line under **Publish a revision** is true again and did not change: fix each line and the button wakes.
