# v2.5663 — Report by line: the list on the New report and Additional report windows (2026-10-20)

Punch list #130, PR 2 of 5, on PR 1 (v2.5661, the kernel). The stage-weighted picker of v2.3192 opened only behind an Order row and asked one stage per report; the whole-job slider stood everywhere else and took the fifties. No migration; no edge function.

- **The hook** ([`hooks/useJobLineProgress.ts`](../../src/hooks/useJobLineProgress.ts)): one hook behind every door that asks for a job's percent — the two report windows here, the My Schedule stepper in PR 3. It reads the job's priced lines through `list_job_stage_progress` (SECURITY DEFINER; field roles cannot read line items) and `jobs_ledger.pct_complete`, the job's number on record; keeps the tech's picks, the open row and the list switch; and says what the lines add up to (`derivedPct`, `moved`). A one-line job, a refused or missing RPC (a client ahead of a push) or any error reads as no lines, and the caller keeps its slider, the v2.3192 fallback unchanged. `stampMovedLines` writes one `record_stage_progress` call per moved line after the report saves, best-effort.
- **The field** ([`ReportLinesProgressField.tsx`](../../src/components/ReportLinesProgressField.tsx)): *How far along is each line?* over the lines in plan order (a number on an In-order stage, declared or recognized; ◆ on an Any-time line), each row's own number on the right (`lineWords`: ✓ Paid · ✓ Done · 35% → 50% · 35% · —), one row open at a time with the 25 · 50 · 75 · Done ✓ chips and the slider, a paid row locked, the **Job** line once under the list (*Job 32% → 43% · was 32%*, quiet until something moves) with **how?** unfolding the shares and points, and **Set the whole-job % instead** when the host offers it.
- **The windows**: [`NewReportModal`](../../src/components/NewReportModal.tsx) and [`AdditionalReportModal`](../../src/components/AdditionalReportModal.tsx) mount the field in place of the template's `percent_0_100` field when the job has two or more lines, mirror the derived number into the field's value so the copy text and the saved field agree, write the moved lines into the *Stage progress* field (one sentence: *Rough In 35% → 50% · Water heater — → 100% · job 32% → 43%*; the v2.3192 label, so the report view prints it as before) and stamp each moved line after the insert. A report that moves nothing files the job's own number, as the slider does. **Mark each line instead** brings the list back after the escape. The one-stage `ReportStageProgressField` is no longer mounted; PR 5 deletes it.
- **Tests**: `useJobLineProgress.render.test.tsx` (the read, the recorded number, the open row, the picks adding up, the switch off; one line, a refused read and a closed window as no list; a failed pct read keeps the list; the stamps, one a line, a refusal swallowed), `ReportLinesProgressField.render.test.tsx` (the rows and their words, the controls on the open row only, picks and slides, opens and closes, the quiet job line, the escape; a moved row, the job line's before and after, how?), the kernel's nine.
