# v2.3660 — Lien desk: change the notice's wording right in the preview window (2026-09-20)

Client only; no migration, no edge function. Follows v2.3522 (the preview window, read-only, with the typed values marked).

## Why

The owner, 2026-09-20, on the desk's Wording line: *"I would like for this wording text to also be editable from the 'Preview in a new window ↗' view."* The preview is where the office actually reads the paper; sending them back to the desk to change a word, then re-opening the preview to see it, was the long way round.

## The shape

The preview is a static blob page with no app code, so it must not grow a notice builder of its own — two builders would drift. **The desk stays the one source of truth**: the preview posts what was typed, the desk layers it onto its wording edits and rebuilds the pages with the same builders the pane uses, and posts the HTML back for the preview to swap in.

| Message | Direction | Carries |
|---|---|---|
| `lien-notice-preview-edit` | preview → desk | `{ field, value }` — typed fields only |
| `lien-notice-preview-save` | preview → desk | — ; the desk runs its own Save draft |
| `lien-notice-preview-pages` | desk → preview | `docHtml`, `coverHtml`, `diff`, `values`, `editedBy`, and `saved: 'ok' \| 'failed'` after a save |
| `lien-notice-preview-field` (v2.3522) | preview → desk | the read-only fallback: focus that field on the desk |

## What shipped

- [`lienNoticePreview.ts`](../../src/lib/jobs/lienNoticePreview.ts) — `editable` on the preview input turns the four typed items in the side list into text boxes (value escaped into the attribute; placeholder = where the default comes from), each with a hidden-until-changed *changed from the default · Back to the job's wording*; a **Save draft** button with a status line; `data-page` slots on the two pages. The page script posts edits, swaps the pages in on the desk's answer and re-marks the tints, follows the desk's values in any box the office is not typing in, and — when the opener is gone — disables the boxes and says so. `lienNoticePreviewPages()` builds the desk's answer. Without `editable` the page is exactly the v2.3522 page.
- [`LienDeskModal.tsx`](../../src/components/jobs/LienDeskModal.tsx) — keeps the window it opened and the job it opened it on. An edit is accepted only from **that window**, on **that job**, for a **typed field**, while the wording is **not locked** (office role, drafted item) — the same gate as the desk's own boxes. An effect posts the pages whenever they change, whichever side changed them (a box here, a box there, the cover-note tick). `run()` now reports success so the preview can be told whether its save landed.

## Verified

- Kernel: the editable page carries the four boxes, the escaped value, the reset with the job's default, the hidden/visible changed lines, the save button, the page slots and the three message names; the read-only page carries none of them; the desk's answer has the rebuilt pages, the four values and the diff.
- Render: an edit from a window the desk did not open is ignored; from the preview it lands on the desk's paper and the desk posts pages with the new text, diff and value; a derived field (`claimAmount`) is never writable.
- Dev server on prod data, job 883 (preview page loaded in a frame with the desk as opener, since the hidden browser pane blocks popups): typing *Electrical labor and materials* changed the preview's page and the desk's paper, both showed *edited (1) by Robert*; *Back to the job's wording* restored both. Save draft was not pressed — prod data.
- Typecheck, lint, theme check, guide and release-note suites.
