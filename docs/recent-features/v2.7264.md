# v2.7264 — The box page answers a locked connection the same way for every code (2026-11-14)

Two small things from the 2026-11-14 read of Materials on site's edge functions (punch list #209's surface). Edge functions only: no migration, no client change beyond the shared kernel and its test.

## box-read: the guess lock before the sticker

v2.7240 made the public box page refuse a source past 20 wrong codes in the hour even when its next code opened a box. The sticker branch (v2.7072) sat ahead of that check: a blank sticker's 404 and a lost sticker's 410, each carrying the sticker's number, were answered before the lock was read. A locked source could still learn which sticker numbers exist.

Now `box-read` reads the lock first of all (`readEstimateLinkLock`, a plain read that counts nothing and fails open) and answers 429 `locked` to every code from a locked source: a hit, a miss, a blank sticker or a lost one. The order is a pure kernel, `boxPageEarlyAnswer(locked, sticker)` in `_shared/boxPage.ts`, so the client test holds it. A locked source's sticker is not read at all. A source under the limit is answered as before: the sticker's own answer, then the box.

A side effect worth naming: a locked source's further wrong codes are no longer counted as misses, since the refusal comes before any read. The hour's lock stands either way, and the next hour's count starts clean, as it did.

## dev-mcp: the on-site read names all seven write pairs

`read_on_site`'s answer ends with a `writes` line naming the plan → apply pairs an agent may call next. It named the four of v2.6367 and left out the three that came after: `plan_materials_move` (v2.6808), `plan_container_edit` and `plan_part_rename` (v2.7241). The line now names all seven, each with its one-line meaning from the architecture map's The agent's door.
