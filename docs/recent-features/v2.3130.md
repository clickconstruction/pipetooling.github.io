# v2.3130 — Edit Bid autosaves; New Bid keeps "Create bid" (2026-09-07)

Client only — no migration, no edge function. Owner's ask: the Won you click in Edit Bid was not on the bid until Save ("change edit bid to automatically save"), and "New Bid should still have a dedicated save button — at the bottom it says Create bid". Groundwork for the follow-on prompt that opens the job the moment a bid is marked Won.

## What changed

- **The Edit tab autosaves.** [`Bids.tsx`](../../src/pages/Bids.tsx) runs the Job window's autosave engine ([`useJobFormAutosaveSlice`](../../src/components/jobs/useJobFormAutosaveSlice.ts), ~1.2 s debounce, in-flight/queued serialization) over the bid form: the slice JSON is every persisted form field plus the parent-owned Bid Date Sent, its pending attestation and the attestation's follow-up note ([`bidAutosaveSliceJson`](../../src/lib/bids/bidFormAutosave.ts)). `autosaveBid` writes the **dirty-only diff** through the same `pruneUnchangedBidUpdateFields` every explicit save used (an untouched field never clobbers a column stamped server-side), then re-reads the row: the boards, every tab holding the bid, `editingBid` itself, and the window's Bid tab (`BidWindowModal` gained `refreshKey`). A refused write (RLS / twin fence) or an error toasts and resolves false, so the footer reads *Couldn't save your latest change · Retry*.
- **Baseline follows the writes.** [`useBidEditForm`](../../src/lib/bids/useBidEditForm.ts) gained `markSaved(values | updater)`: after each pass the values it wrote become `initialValues`, so the next diff is against the row, not the modal's open-time snapshot. The per-GC Sent panel's roll-up (which already wrote `bids.outcome` and its own Win/Loss note server-side) calls the new `onOutcomeRollupPersisted` prop → `markSaved` patches just `outcome`, so autosave neither re-writes it nor logs a second note.
- **Bid Date Sent keeps its attestation.** The field's blur prompt still opens the confirm-sent checklist and reverts the input until it is confirmed. Autosave drops `bid_date_sent` from the diff while `validateBidDateSentAttestationForSave` objects, writes everything else, and writes the date + attestation columns + the optional follow-up note on the pass after the checklist is confirmed (the attestation timestamp is in the slice JSON, so confirming re-dirties the slice). The engine is disabled while the attestation modal is open and while a required field (Project Name / Service Type) is blank — an invalid row must never persist; the footer says which field holds it.
- **Close guard.** `requestCloseBidForm` (the window's ✕, Esc, the pane chips' Open-in-Bids, and **Open Counts**) cancels the pending debounce and, when the slice is dirty or a write is in flight, runs `flushForClose` under a 15 s `withOperationTimeout`. Failure → a strip above the footer: *Couldn't save your latest changes — the window stays open* with **Retry** / **Keep editing** / **Close without saving** (the last clears the baseline and closes, the same explicit choice the Job window offers). The trade switcher's *Duplicate* / *Open existing* flush first too. A tab switch or phone backgrounding flushes on `visibilitychange`.
- **Footer per mode** ([`bidFormFooterLabels`](../../src/lib/bids/bidFormAutosave.ts)): Edit — status line (*Changes save as you make them* / *Unsaved change…* / *Saving…* / *Saved* / the required-field hold / the error + Retry) and **Open Counts**; Enter submits nothing. New Bid — **Create and open counts** and **Create bid** (was Save and Open Counts / Save).
- **One payload builder.** [`buildBidSavePayload`](../../src/lib/bids/bidFormPayload.ts) replaces the two hand-written payload literals in `Bids.tsx`; they had drifted (*Save and Open Counts* never wrote `account_manager_id`). `saveBidAndOpenCounts` is now the New Bid path only; on the Edit tab the button flushes and navigates.

## Not changed

The New Bid form's Save flow (insert + Win/Loss note + follow-up note + service-type switch), the attestation modal, the per-GC panel's own writes, `BidWonJobActions`, the Copy Bid popover.

## Verify

1. Bids → Bid Board → pencil on a test bid (Edit tab). Change **Notes**, wait a beat → footer reads *Saving…* then *Saved*; flip to the **Bid** tab → the note is there. Change **Win / Loss** to Won → *Saved*; the board pill updates without closing the window; Followup's notes show the "Open → Won" line once.
2. Type in a field and press **✕** inside a second → the window closes and the change is on the bid (the close flushed it).
3. Blank **Project Name** → the footer says *Required: Project Name — changes save once it's filled in*; nothing writes until it is refilled.
4. Change **Bid Date Sent** → the confirm-sent modal opens; **Cancel** → the date reverts, other edits keep saving; confirm it → the date (and attestation) write.
5. **New** bid → the footer reads **Create and open counts** / **Create bid**; the ✕ still discards.
