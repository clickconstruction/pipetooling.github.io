# v2.3288 — Bill Customer: "What the customer will see" is filled from the job's lines before Stripe can answer (2026-09-11)

Client only — no migration, no edge change. Found on the owner-driven discount live pass (2026-09-11): on a job with no customer email the preview showed only *Draft line: Custom service.* — no work lines, no discount line, no total — and the note blamed the missing bill row when the real blocker was the email.

## Why

Stripe's own preview (edge `preview-stripe-invoice`) asks Stripe to render a draft against a Stripe customer, so the modal only calls it once the job has a customer with an email, the bill row exists (written on send), the amount is positive and a due date is set. Before that the only thing on screen was the single-line placeholder. The line builder the edge function feeds Stripe is a pure shared kernel the client already imports for the Bill tab's *Stripe preview* dialog and the physical invoice — nothing stopped the modal from showing the bill locally.

## What shipped

- **Kernel** [`localStripeBillPreview.ts`](../../src/lib/billing/localStripeBillPreview.ts) (+6 tests): `buildLocalStripeBillPreview` mirrors the edge function step for step — cents, hazmat extras off the fixture target, `fixturesForInvoiceBill` scoping (a bill that does not exist yet scopes as the primary remainder bundle, `PENDING_BILL_SCOPE_ID`), `buildStripeInvoiceItemsFromFixtures` for the work lines and the negative discount shares, extras appended, the PipeTooling invoice number the edge would mint — and returns the same `StripeInvoicePreviewSuccess` shape. `stripePreviewBlocker` / `stripePreviewBlockerHint` name the first real gate (loading · ensure error · no customer · no email · no bill row).
- **[`StripeBillPreSubmitPreview`](../../src/components/jobs/StripeBillPreSubmitPreview.tsx)** (+3 render tests) takes `localPreview` and renders it in the identical layout — hero amount, To / From / Invoice, the lines, Total due — with dashed borders and a *from the job's lines* tag (or *loading Stripe's preview…*). Stripe's answer replaces it the moment it arrives; a Stripe error now says "Showing the bill's lines below." *Draft line: …* survives only when neither exists (amount 0, extras that swallow the amount).
- **[`SendRecordInvoiceModal`](../../src/components/jobs/SendRecordInvoiceModal.tsx)** builds the local preview from `billCustomerJobDetails.fixtures` with the same extras math as the Stripe call, for both the job and the invoice openers, and the idle hint reads *Add the customer's email above and Stripe's exact preview appears here — the lines below are what the bill will list* when that is the blocker (the bill-row and preparing/ensure-error hints keep their wording).
- Help: `ready-to-bill-pipeline.md` describes the preview as it is now.

## Not changed

The edge function and what Stripe receives. A preview without a customer email would need throwaway Stripe customers with no address, which the function deliberately avoids.
