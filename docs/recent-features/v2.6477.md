# v2.6477 — On a laptop, the reply box waits as one row (2026-11-03)

The third of three PRs that fold a person's thread by height (the owner's pick A of three mock-ups, 2026-11-03), after v2.6474 (the header) and v2.6476 (the sort card). The reply box took 195 px of a 676 px window; folded it takes 62 px, and the lines of a Bid it? thread reach 455 px, from about 100 before the train.

## What changed

- `replyBoxFolded` (`src/lib/messages/replyFold.ts`): the box folds while the open thread says `short`, the box is not a job's, nobody has pressed into it since it last sent, it is blank (an email's pre-typed opening counts as blank), no file waits, nothing opened it with words (a nudge, a won bid's words, a settle) and Send texts is not holding a text.
- `ReplyBox`, folded: the kinds and the box on one row, the box one line high and not resizable; the quick replies strip, the from line, the count and the *Tie to* / *Attach* / *Send* row wait. A focus on the box or a press on a kind opens it whole (the same textarea, so the caret stays); `after`, which every send and note runs, folds it back.
- Guides: a paragraph under *Open the reply box* in `reply-to-a-person-from-their-thread`, and a line under *Read a thread on a short screen* in `find-every-message-with-a-person-in-one-place`.

## Decisions

- **Folds back after a send, not on a blur.** A blur folding the box would pull *Attach* or a quick reply out from under the press that caused the blur (Safari does not focus a pressed button), so only a send folds it.

## Test

`npx vitest run src/lib/messages/replyFold.test.ts src/components/gc/messages/reply/`, `npm run typecheck`. Live at 1000×700 on a Bid it? thread: the box 62 px folded; a press into it opens it whole with the caret in place.
