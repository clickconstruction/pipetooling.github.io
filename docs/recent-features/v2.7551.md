# v2.7551 — Checklist: yesterday's unticked task asks once, did it or skipped (2026-11-16)

Punch list #369, step D3 of the Task Mode train, the last of the three small ones and the last step, stacked on D2 (v2.7550). It carries a small migration of its own.

## Why

Read through the dev seat on 2026-11-16, 135 days of repeating tasks had gone unticked since February. A repeating task that is not ticked drops off the list the next morning (`qualifiesOutstanding`), so nobody learned whether the work was done and not ticked, or not done. History read both as *Missed*.

## What changed

- **A strip at the top of Today**, under the map: *Yesterday · 2 not ticked*, then *Did you do it? Say which, so the record is right. It asks once.* (`missedLabel`, `MISSED_ASK`, `MISSED_WORDS`). Each task has two quiet presses.
- **Did it** finishes that day's row by the tick's own path (`toggleComplete`). It is for work that was done and not ticked.
- **Skipped** writes a `skipped` line in the task's thread (`sayTaskStuck` with the new kind). The row stays not done and leaves the question.
- **It asks once.** A task answered either way is not asked about again, on any device, since the answer is in the database and not on the phone.
- **It looks back three days** (`YESTERDAY_REACH_DAYS`), and asks about the latest day in reach that has an unanswered task. So Monday asks about Friday, and a day a week old is left to History.
- **History tells the two apart**: a skipped day wears a grey **Skipped** chip where an unanswered one reads *✗ Missed* (`ledgerChip`, kind `skipped`). A day sent back still reads *Reopened*.
- With nothing unticked in reach, the strip is not drawn.

## The migration

`20261117130000_task_skipped_line.sql` (documented in `docs/migrations/`): `skipped` joins the thread's kinds, and whoever can read a day row may write it as themself. No function and no column. The bed `task-doer-acts` gains a second scenario, `20_skipped.sql`.

## How it is built

- `src/lib/tasks/yesterdayMissed.ts`, pure, 6 tests.
- Today's read already fetches the past rows that are not done and sets aside the repeating ones that do not stay on the list. Those rows are kept now (`missedRows`), and the read of their lines asks for `skipped` beside `completed` and `reopened`. No new query.

## Release order

Push the migration right after the merge. Before the push the **Skipped** press is refused by the table's check and the page shows the refusal; **Did it** and everything else work without it.
