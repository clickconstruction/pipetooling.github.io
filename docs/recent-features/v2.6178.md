# v2.6178 — The Development page prints the state in capitals (2026-10-30)

Fix, no migration, no edge function. The first finding of the owner's live walk of the real site's Development page (punch list #208, `to-dos/developments/README.md` → *next*): the head read *Gun Dog Trail, Neeses, Sc* and the *not in it* line under it the same.

## Cause

`sharedAddressWords` (`src/lib/developments/overview.ts`) prints the most common raw spelling among the members of the most common normalized address key, so the head reads words and not a key. The real site's nine jobs were typed with *Sc*; its bids were normalized to *SC* on 2026-09-08 (v2.3142) but none of them is in the development yet, so the jobs' spelling won.

## Change

- `stateUppercased(spelling)`, pure, beside it: a two-letter word after the last comma reads in capitals, with or without a trailing zip code (`Neeses, sc 29107` → `Neeses, SC 29107`); a city alone after the comma, a street with no comma and a state already in capitals pass through unchanged. `sharedAddressWords` returns through it, so the head, the *not in it* line and the search box's drop words (`siteDropWords`) read it.
- Tests beside it in `overview.test.ts`.

Read on the dev server against the real site: both lines read *Neeses, SC*. No data was edited; the jobs keep their typed addresses.
