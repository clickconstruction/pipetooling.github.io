# v2.3163 — Save as Assembly prefills "<count> - <project>" (2026-09-08)

Client only — no migration, no edge function. Estimator Wendi's ask, verbatim: "can you have it autopopulate the assembly name as the name of count - name of project." Until now **Save as Assembly** on a Takeoffs count row opened the Add Assembly form with `<fixture> assembly` (e.g. "I-6 assembly"), so every assembly saved from a job carried no trace of which job it came from and the Assembly Book filled with look-alike names.

## What shipped

- **[`saveAsAssemblyDefaultName(fixture, projectName)`](../../src/lib/bids/bidTakeoffHelpers.ts)** (pure, 3 tests): both halves whitespace-collapsed and trimmed, joined with ` - `; a blank half is dropped rather than leaving a dangling dash; nothing at all → `New assembly` (the old fallback).
- **`openSaveAsAssemblyFromRough`** in [`BidsTakeoffTab`](../../src/components/bids/BidsTakeoffTab.tsx) calls it with the count row's `fixture` and `selectedBidForTakeoff.project_name`. The other door into the same form — **Add assembly** from a fixture's assembly picker when nothing matches — is unchanged (it seeds the name from the search text).
- The name stays fully editable; nothing about save, bundle prices or **Use for takeoff** changes.

## Docs

- Help guide *create an assembly while doing a takeoff*: one line under the Save as Assembly bullet naming the prefilled form.
