## Why this shape

- **The sanctioned recipe, automated.** The 2026-09-22 live passes cleaned up by hand exactly this way — zero the lines, reassign into the permanent test job — because a job with any cost row refuses a plain delete and the reassign door keeps every child in the archive. The sweep is that recipe with the two chores done for you, one RPC per row (the RPC locks both jobs; a loop is the honest shape).
- **The sink by name, not number.** The plan first looked for J1032, the permanent test job the 09-22 passes used — and found it gone (deleted since; the header search has no J1032). A number is a handle someone can reuse; the word *sink* in a ZZ job's own name is a declaration. If the sink is ever renamed or deleted the section says *no sink* and sweeps nothing, rather than folding test residue into a customer's job.
- **Age, not status.** A pass in flight leaves rows it will come back to; seven days is the default because no pass has run longer. Zero sweeps everything but the sink.
