# v2.8573 — On a phone, the Add Task offer stands on the Dashboard alone (2026-11-25)

Punch list #428 (`to-dos/lien-to-do-on-a-phone/README.md`), the third of its three phone calls. Client only. No migration, no edge function.

## The fault

The walk of 2026-11-25 in an iPhone simulator (Safari, 402 by 874 points) found the Lien desk's list in a window of about 355 points. One cause was the orange line that offers the **Add Task** Home Screen icon, about 56 points, above the header of every page. It shows in iOS Safari until it is dismissed. Under the new phone layout it had already left for one quiet row of the Dashboard. A phone without that tick, which is every new phone, kept it everywhere. Card #398's walk met the same line.

## The call, and the answer

Asked of the owner on 2026-11-25: *On a phone without the new layout switched on, where should the orange Add Task banner show?* The answer: *On the Dashboard alone*, as the new phone layout already has it. The other answer was over every page, as it stood.

## What was built

- `src/lib/phoneLayout/addTaskOffer.ts`: `addTaskOfferPlace`, the one rule for where the offer is drawn. The new layout on: the quiet row, on `/dashboard` alone, as before. A phone's width with it off: the line, on `/dashboard` alone. A wider screen: the line on every page, as before. Tests: 3.
- `src/components/Layout.tsx`: both places the shell draws the offer ask that rule. The line is keyed by the role, as the quiet row already was, so the offer is decided once the role is known.
- `src/components/Layout.newPhoneLayout.render.test.tsx`: the smoke that held the line on every page now holds it on the Dashboard alone on a phone, off another page on a phone, and on every page at a desk.

## What it changes for a person

- This is the app's shell and not the Lien desk, so it changes every page on a phone in Safari.
- A person who never opens the Dashboard on a phone no longer meets the offer. The new layout already works that way.
- The installed app never showed the offer and still does not.

## Seen, and not seen

- **Tests:** the kernel and the shell's smoke.
- **Not seen:** a phone, a simulator, the live site. The walk in a simulator comes after the deploy.
