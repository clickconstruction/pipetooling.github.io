## What shipped

- **`master_assistants` / `master_shares` are views** over `users` (owners × assistant/controller/estimator; owners × owners), replacing the synced tables, which are renamed `retired_*` and kept for a quiet week. `sync_company_access_grants()` now fills only the primary / superintendent tables.
- **Policy re-bind**: `scripts/one-company-policy-sweep.py --rebind` emits DROP + CREATE for every live policy naming the pair, bodies byte-identical, so the expressions bind to the views. 84 policies on 36 tables.
- **Docs**: plan doc (Phase 5 shipped, Phase 5c = drop chore), `ACCESS_CONTROL.md`.

## Why views instead of a function sweep

Phase 2's census listed 45 functions that still read the pair inline, in 33 PL/pgSQL and 12 SQL bodies of every shape (payment RPCs, label scoping, schedule emails, tally follow-ups). Rewriting each by hand with no staging database is the riskiest change in the whole plan for no behavioural gain — every one already answers yes for the office because the sync kept the tables complete. Same-named views give the identical answer by rule, retire the sync, and leave the function bodies for ordinary maintenance.
