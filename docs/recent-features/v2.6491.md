# v2.6491 — The file index keeps a revised file's newest sense, reads a scan on one download and takes held files again (2026-11-04)

Search every file deeply (punch list #240, `to-dos/search-every-file-deeply.md`). A PR review on 2026-11-04 read the shared index pass (`supabase/functions/_shared/fileIndex.ts`) and found four defects, all fixed here with a unit test each that failed before (`src/lib/documents/fileIndexPasses.test.ts`, the pass against a recording stand-in for the service-role client and a scripted Drive, Document AI and Gemini).

## What changed

- **A chunk write is fenced on the row's index stamp.** `embedRow` takes the row's `indexed_at` and every stamp it writes (embedded, refused) lands only while the row still carries it. Before, the sweep read a row's text, spent up to twenty seconds on Gemini, then deleted and re-inserted the chunks and stamped `embedded_at` with no guard: a press that re-indexed the file meanwhile saw its new chunks overwritten by the old text's, and the row read as current for good. Now a stamp that finds the row gone on is not written, the chunks that call put in go (by its own `embedded_at`, so a newer pass's chunks stay), the row's `embedded_at` is cleared so it is due again, and the pass answers `EMBED_STALE_NOTE`.
- **The embedding queue reads the catch-up rule.** `embedPass` asked for `embedded_at IS NULL` alone, since PostgREST cannot compare two columns, while the migration's comment and partial index say `embedded_at < indexed_at` is the rule. The new RPC `file_index_embed_due(max_rows)` (migration `20261104160000`, `docs/migrations/20261104160000_file_index_embed_due.md`) asks the rule the index serves, service role only; a queue the database refuses is logged and the pass embeds nothing that run.
- **A text with no words keeps no chunks.** `embedRow`'s zero-chunk branch stamped the row without deleting the old chunks, and `indexOneFile` dropped chunks only when the text was null, so a file revised to whitespace kept its old wording's chunks. `settleChunks` (one place for both passes) embeds when meaning is set up and the text has words (`textHasChunks`, the rule `chunkText` cuts by), else drops the chunks when the text has none.
- **The OCR queue finds a scan by the plan's rule.** `ocrPending` filtered `mime IN OCR_MIMES` while `indexPlan` (`ocrMimeOf`) also matched by the name's extension, so a scanned PDF Drive lists as `application/octet-stream` was never queued until the file changed. `ocrKernel.ts` now holds one extension table (`OCR_EXTENSION_MIMES`) that `ocrMimeOf` reads (the mime Drive gives first, then the name) and `ocrQueueFilter` turns into PostgREST's `or` (the mime, or the name ending in an extension it reads).
- **A known scan is OCR'd on one download.** The OCR catch-up re-ran the whole index of a scan: a `reading` stamp that wiped `text` and `ocr_tried_at`, a second Drive download and PDF parse on the sweep's shared clock (a `slow` answer there left the row held with no retry), and a third download for OCR. `ocrKnownScan` downloads once, sends the bytes to the processor and patches the row with the read (`readColumns`, the columns `indexRowOf` writes for a read, so the row reads the same whichever pass read it) or the refusal (`ocrRefusedColumns`: the try, its reason, checked now), fenced on `indexed_at`; a scan whose file changed since its row is read whole, as any changed file is.
- **Held rows are taken again.** The sweep's own pass never retried a held row. `retakePass` (step 5, `retake` = 5 a run, `SWEEP_RETAKE_ROWS`) takes rows held `slow` or `reading` (`RETAKE_WHYS`) whose last check is an hour old (`RETRY_HOLD_MS`, as a press's retry waits), oldest first, through the one pass with `retry`; a row slow again waits another hour; a file Drive no longer answers for is checked now so it leaves the head until the recheck drops its row. The sweep's answer gains `retake: { tried, read, held }` and the line *Retook N of M held files*.

## Decisions

- **Fence and clear, not an atomic write.** An RPC that checks the stamp, swaps the chunks and stamps in one transaction would close the window entirely, but it moves the whole write path into SQL. The fence plus the clearing costs one extra embedding in the rare race and converges on the new text either way, which is what the done criterion asks.
- **The mime Drive gives wins; the name decides only when the mime is not one Document AI reads.** `ocrMimeOf` used to check the PDF rule first by either, so a `.pdf` name on a `image/png` mime read as a PDF. Drive's mime is the better word on the bytes.
- **The retake is general, not a scan's alone.** A `slow` row does not say whether it was a scan, and a dense text PDF held slow on a spent clock deserves the same hour-later retry. The retake runs whether or not OCR is set up.
