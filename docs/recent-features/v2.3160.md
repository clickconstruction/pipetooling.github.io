# v2.3160 — Job account visible in the job window (2026-09-08)

Follow-up to v2.2669 (job-account invoice flag). Until now the only signal that a job had a supply house job account lived *inside* the share modal ("Already shared with …"); the header storefront icon was static grey. Owner asked for the job window to show it.

## Header icon — `DetailJobModal`

- New `useJobAccountShares(jobId, enabled, refreshKey)` hook reads the job's `supply_house_job_accounts` rows (newest first, ≤50). Enabled for the same office roles that can share (`canShareSupplyHouse`).
- Storefront icon color → teal (`#0f766e`, literal — no teal tokens) when any share exists; `data-job-account="on-file"` attribute for tests/automation. Tooltip from the new pure `jobAccountShareIconTitle()` (ledger kernel): "Job account on file — shared with {contact} · {date} · +N more. Click for history or to resend." Aria-label unchanged (`Share with supply house`) so the render smoke still finds it.
- The share modal's `onClose` bumps the hook's refresh key, so a send logged in the modal recolors the icon immediately.

## Parts Cost — `JobDetailMaterialsCostSection` + `fetchJobMaterialsCostSnapshot`

- The allocation embed now selects `is_paid, on_job_account`; `JobSupplyInvoiceLine` gains `isPaid` / `onJobAccount` (missing embed fields read false).
- Invoice cell shows a teal "Job acct" chip on flagged lines; below the table, when any unpaid line is on a job account: "$X of the $Y unpaid here is on a job account — the house bills the property owner if it goes unpaid, not you." Split math in the pure `jobAccountSplitFromLines()`.

## Tests / docs

- Ledger kernel: `jobAccountShareIconTitle` cases. Snapshot kernel: select string, line fields, `jobAccountSplitFromLines`. Existing job-window render smoke passes unchanged.
- Help: job-window-tabs (icon state) + mark-an-invoice-on-a-job-account (where it shows) updated.
