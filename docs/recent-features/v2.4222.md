# v2.4222 — Pipeline: GC jobs with no owner get the property badge too (2026-09-30)

Owner, from a Pipeline screenshot the day after [v2.4212](v2.4212.md): *912 PLUM — Limitless Renovations & Design LLC* had no badge while the NexGen row under it had a C. The job has a GC and no `customer_id` (person line "—", *Not in Customers*), and v2.4212 drew nothing for a job with no customer because there was nobody to save a property on. Edit Job's Property record row already answers that: `propertyHomeId = customerId || gcCustomerId` — a GC job's property lives on the GC.

- `JobsStagesTab` feeds `usePropertyKinds` `customer_id ?? gc_customer_id`, so every job with either gets '' and draws the ?.
- `renderJobAddressWithMap` hands `PropertyKindBadge` the same fallback as `customer_id`, and the GC's name (`gcCustomer.name`) as `customer_name` when the job has no customer — the popover's footnote and the toast name the GC. The writer is unchanged: `linkJobPropertyAndSaveKind` inserts on whichever customer id it is given.
- Render test: a GC-only job gets the unlinked ? and its popover names the GC; a job with neither still has no badge. Guide and GLOSSARY amended.

No migration, no edge function.
