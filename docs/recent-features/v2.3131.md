# v2.3131 — "Your jobs on a map" Dashboard card, every role (2026-09-07)

Owner's ask (2026-09-07, after the superintendent-projects question): a map of a person's active jobs on their Dashboard — "build it for all users". Mock-up approved the same evening (desktop popup, phone bar under the map, status-colored pins, Fit all / Hide map, the "no map location yet" line).

## What shipped

- **[`DashboardJobsMapCard`](../../src/components/dashboard/DashboardJobsMapCard.tsx)** mounts once in `Dashboard.tsx`, directly above `DashboardAssignedJobsSection`, for every role; it renders nothing when the viewer has no job to show. Jobs come from the Dashboard's own lists — `assignedJobs` (`list_assigned_jobs_for_dashboard`, team membership, waiting/working) plus `superintendentJobs` (`list_superintendent_jobs_for_dashboard`, project assignment) — deduped by id; no new RPC, nothing wider than what RLS already returned to the page. Header: pin glyph + title, legend counts (`3 working · 2 waiting`, the Projects-card status dot colors), **Fit all** (desktop, ≥ 2 pins), **Hide map** (per-device, `pipetooling_dashboard_jobs_map_hidden`). Footer: the rule ("Only jobs you're assigned to") and *N job(s) have no map location yet* with up to three job links. Phone form (`isMobile`): 260px map, legend under the title, the selected job as a tinted bar under the map with 44px **Open job** / **Directions** — no Leaflet popup.
- **[`DashboardJobsMapCanvas`](../../src/components/dashboard/DashboardJobsMapCanvas.tsx)** — the Leaflet half, `React.lazy` so Leaflet / react-leaflet stay out of the Dashboard bundle (the `/map` chunk already carries them; Vite shares the vendor chunk). OSM tiles (dark theme inverts them via the existing `.leaflet-tile-pane` rule), one `CircleMarker` per pin (radius 8, `fillOpacity .8`, weight 1; the selected pin rings in `#1d4ed8`), `fitBounds` on load and on Fit all (padding 28, maxZoom 15). Desktop popup: label, status chip, address, `Rough-in · last report 2 days ago`, **Open job** → `openJobDetailFromDashboardJobRow(row)` (the read-only pane for superintendents, the tabbed window for the rest — `resolveJobWindowMode` unchanged), **Directions** → `openInExternalBrowser` on the job rows' Google Maps search link.
- **[`useDashboardJobsMapPins`](../../src/hooks/useDashboardJobsMapPins.ts)** — reads `address_geocodes` in the Map page's batches (`batchGeocodeCacheKeys`), paints the hits at once, then sends cold addresses to `geocode-address-batch` in chunks of 20 and paints each chunk as it lands; a miss stays in the unmapped line and is not re-asked until the next mount. Skipped entirely while the card is hidden.
- **Kernel [`dashboardJobsMap.ts`](../../src/lib/dashboardJobsMap.ts)** (10 tests): merge/dedupe/label (`J1021 · Bexley Park Bldg C`), status mapping (assigned rows carry status; a superintendent row has none and reads as waiting; ready_to_bill / billed / paid never pin), address key (`normalizeAddressForGeocodeKey`), pin resolution, legend, bounds (a lone pin gets a padded box), copy helpers, the hide preference (storage-safe).

## Access (migration + edge function)

- **`20260908035852_address_geocodes_all_roles.sql`** ([fragment](../migrations/20260908035852_address_geocodes_all_roles.md)) — the cache's SELECT / INSERT / UPDATE policies open to every signed-in user (they were the four Map roles); DELETE stays with the Map roles (Review geocodes). No new table, so no fence appliers; the read-only restrictive policies on the table are untouched.
- **`geocode-address-batch`** — role gate becomes "active `users` row with a role" (was dev / master / assistant / estimator); a cache upsert refused by RLS (`42501`, a read-only training user) no longer fails the batch — the coordinates return, the cache is skipped. **Deploy**: `bash scripts/deploy-functions.sh geocode-address-batch`. Until deployed, non-Map roles see cached addresses only; cold ones sit in the "no map location yet" line.

## Not changed

The `/map` page and its role gates; `KIND_COLOR` on the office map; the Assigned Jobs / Superintendent Jobs rows. **Known and left alone**: `list_superintendent_jobs_for_dashboard` still ORs on `master_superintendents` (company-wide since v2.921), so a superintendent's section — and now their map — lists every project-linked job, not only assigned ones; the v2.2836 helper rewrite did not touch that RPC. Filed as a follow-up, not folded in here.
