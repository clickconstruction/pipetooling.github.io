# v2.2124 — Per-version sends: "Mark sent today", sent badges, Board value rule (2026-08-23)

F5 of the "Send or Compare" train (decision D5). Until now a bid had one sent date and one value (`bids.bid_date_sent`, `bids.bid_value`), so a package of versions could not say which bid went out when or for how much — Followup, hit rate, pending $ and the Board treated the package as one indivisible number. This PR gives each **version** its own send record and keeps the bid-level roll-up in sync, so every existing reader keeps working.

**Migration `20260823031729_bid_version_sends.sql`** — new table `bid_version_sends` (id, bid_id → bids, bid_version_id → bid_versions, `sent_on date`, `value numeric` = the version's ★ revenue at send time, `is_alternate`, `round_label`, `note`, created_at/by). Append-only from the app; the **latest row per version is its current send**. RLS mirrors `bid_versions` (`can_access_bid_for_pricing(bid_id)` for select/insert/update/delete); ends with both read-only block calls. Types hand-added to `src/types/database.ts` (table + the two v2.2117 `bid_versions` columns) pending the next `gen-types:linked`.

**Kernel [`versionSends.ts`](../../src/lib/bids/versionSends.ts)** (+5 tests): `latestSendByVersion` (newest `sent_on`, then `created_at`), `latestSentOn`, `boardValueForRule('base_sum' | 'active_star', sections, activeStarRevenue)`, `parseBoardValueRule`, `formatSendBadge` ("sent 7/7 · $279,579").

**UI**
- Cover Letter (New) panel: each bid's row shows its latest send after the ★ line; new **Mark sent today** button inserts one send per bid in the letter (today in `APP_CALENDAR_TZ`, its ★ revenue, base/alternate), then sets `bids.bid_date_sent = today` and `bids.bid_value` = the board value per rule (only when > 0), dispatches `bid-version-sends-changed`, reloads bids. Until the migration is pushed the insert fails with a plain toast ("Could not record the send") and nothing else changes.
- Headline amount follows the rule: `base_sum` (default) = letter total; `active_star` = the active bid's ★ (caption says which). Apply to Bid Value writes the same number.
- `BidVersionPicker` chips: "sent 7/7 · $279,579" line when the version has a send (listens for the event).
- Followup → Full bid details: new **Bids in this package** block (`BidPackageSendsDetails.tsx`) — version · base/alternate/not in letter · latest send or "not sent". Nothing for unsplit bids.
- Settings → Templates & testing (dev): **Bid Board value for a package of bids** — `app_settings` key `bid_board_value_rule_v1` (`BidBoardValueRuleSettingsBlock.tsx`); default sum of base bids in the letter. The prototype's "range" option was dropped: `bid_value` is one number, so a range is display-only (revisit if wanted).

Deliberately NOT done: silent auto-writing of `bid_value` when the letter changes (it would have rewritten 11 prod bids' values just by opening the New tab). "Mark sent" and "Apply" are the explicit writes; a visible "Current Bid Value: $X" hint shows drift, as before.

Verified live on BP329: panel renders the Mark sent button and badges path (empty until the table exists), headline follows the rule, no console errors. Help: `try-the-new-cover-letter-layout.md`.
