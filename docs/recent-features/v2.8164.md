# v2.8164 — State roll: the weekly read of the state’s plumbing licenses (2026-11-21)

Punch list #411, step one of the train in [`to-dos/state-roll/`](../../to-dos/state-roll/README.md), after the tables of [v2.8159](./v2.8159.md). One edge function, [`license-roll-pull`](../EDGE_FUNCTIONS.md#license-roll-pull), its two kernels, and one migration that schedules it, [`20261121141000_license_roll_pull_cron`](../migrations/20261121141000_license_roll_pull_cron.md). No screen changes.

## Why

Taunya asked on 2026-11-20 for a way to find experienced, licensed plumbers from the state's public roll: who was recently licensed, and whose license just lapsed. The plumbing board publishes the roll as free files that say what is true today and keep no history. So something has to read them every week, keep our counties, and write down what changed.

## What changed

- **`supabase/functions/_shared/licenseRoll.ts`**, the rule, with no fetch and no database in it.
  - `tsbpeRows` reads one of the board's files into rows. It refuses a file missing a column it needs, naming the column. It skips a line with no number, no name or a status it does not know.
  - `nameKeyOf` makes the key that joins one person's rows across ranks: last name, first name, middle initial and ZIP.
  - `planRollPull` compares the file with the rows already kept. It answers the rows to add, the rows to patch, the changes to write, and the rows to take off.
  - `rowChanges` turns a difference into what a person reads: renewed, lapsed, current again, moved, an endorsement, a name.
  - `fileLooksCutShort` refuses a file that would mark over a third of the kept rows gone.
- **`supabase/functions/_shared/zipFirst.ts`**: the one file inside a zip. The board zips its journeyman file. A deflated entry is dressed as gzip with the checksum the zip already holds, so every runtime reads it and a damaged file is refused.
- **`supabase/functions/license-roll-pull/index.ts`**: one file a call. It logs the pull first, so a pull that fails is on the ledger with its reason.
- **`supabase/migrations/20261121141000_license_roll_pull_cron.sql`**: four jobs, Mondays from 12:30 UTC, five minutes apart.
- `supabase/config.toml` and `docs/EDGE_FUNCTIONS.md` carry the function.

## Rules it settles

- **A row is kept for its county.** Bexar, Travis, Hays, Comal and Guadalupe to start, from `license_roll_counties`.
- **A person left off is never kept**, by number or by name, and one already kept is taken off with their history.
- **A row that leaves our counties is taken off.** Only our counties are kept.
- **A row the state drops is marked gone, then taken off after 28 days.** The wait covers a file that was cut short.
- **No phone, street address or email is kept.** The board gives none for a person. A responsible master's business address and phone are in the file and are read past. A test holds that.
- **The apprentice file is not pulled.**

## Not one transaction

The writes go as batched requests. A pull that stops partway leaves the roll short of the file, and the next pull brings it level. The lines of history between the two can be missed, and nothing else.

## Verified

- `npx vitest run src/lib/licenseRoll`: 34 tests pass. Every person, number and company in them is made up.
- The zip reader is tested against zips written by hand in the test: deflated, stored, with a data descriptor, behind a comment, with a bad checksum and cut short.
- The function has not run. It runs first as a dry run, once it is deployed, against each of the four files.
- The migration ran twice on a local Postgres 15 with a stand-in for pg_cron: four jobs after both runs, each posting its own file. It has not run against the app's schema, and it makes no table.
