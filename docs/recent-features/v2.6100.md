# v2.6100 — Offline in the field, PR 3: notes and field reports through the queue (punch list #163) (2026-10-29)

Punch list #163 ([`to-dos/offline-field-queue/README.md`](../../to-dos/offline-field-queue/README.md)), the third of five PRs, on PR 2's store, bar and RPC (v2.6099). The two remaining presses the card names go through the queue: a job note from Job Mode and a field report from Leave Report.

## What changed

- **The server side**, migration [`20261030040000_field_presses_notes_reports.sql`](../migrations/20261030040000_field_presses_notes_reports.md): `land_field_press` is replaced with the clock kinds as PR 2 wrote them and two more. `job_note` inserts the row in `jobs_ledger_thread_notes` with `created_at` at the pressed time, so the thread reads in the order things happened; `field_report` inserts the `reports` row at the pressed time, an estimator through `insert_report` (the definer path the form already uses for that role) and everyone else under their own policy. Still `SECURITY INVOKER`. The table is unchanged; its CHECK already named the four kinds.
- **The note** ([`useJobThreadNotesForModal`](../../src/hooks/useJobThreadNotesForModal.ts), the hook behind Job Mode's Note sheet, the job window's thread and Quickfill's): `submitNoteWithBody` goes through `pressThroughOutbox` as a `job-note` press (an Arrived or Leaving stamp is a note too, so it goes the same way). Landed, the row is read back by the id the server answered and replaces the optimistic one as before; queued, the optimistic row stays on the thread and the toast reads *Kept on the phone. It goes out when the signal is back.*; refused, the row is taken off and the server's reason is the toast. When a queued note lands (`OUTBOX_LANDED_EVENT`) the thread reads again, so the optimistic row gives way to the real one. The hook takes `about` for the list's row (Job Mode passes the job's label).
- **The report** ([`NewReportModal`](../../src/components/NewReportModal.tsx)): `submitReport` goes through the outbox as a `field-report` press carrying the template, the field values, the job, project or bid, the location when the phone gave one, and the moved lines of a report by line (v2.5663). Landed, the form does what it did: the two notifications, the moved lines stamped, the job's percent mirrored, the Ready to bill prompt on a 100% report. Queued, the form closes on the kept toast, and the same follow-ups run from the replay when the press lands ([`afterLanding.ts`](../../src/lib/offline/afterLanding.ts), +4 tests), all best effort: the notifications, `stampMovedLines`, `propagateReportPctToJob`. The Ready to bill prompt is not drawn then, since the form is long closed; the job's percent still moves. A refusal shows the server's reason on the form as before; a fetch-layer failure while impersonating keeps the Retry panel.
- **Not through the queue**: the Turnaway report, which raises a dispatch alert in the same act, and the office's Additional report; both fail as they do today with no signal. The Jobs page's inline thread (`useJobThreadNotes`) is the office's and stays live.
- **The kernel**: `FieldReportPayload.movedLines` (`MovedLineStamp`: the fixture and the percent it moved to). `landFieldPress.test.ts` (+4) pins the RPC's kind names, every payload's columns and the refusal's wording (the server's own sentence, never the log prefix).
- **Docs**: `GLOSSARY.md` (*The waiting bar*), `ACCESS_CONTROL.md`, the card's front matter.

## Deploy

From the main checkout after the merge: `supabase db push` (PR 2's migration first if it is not on yet; this one replaces the function), then the types chore. Client first is fine: until the push a queued note or report is refused with the function's reason on the bar and nothing is lost until the person drops it.

## Test

`npx vitest run src/lib/offline src/hooks/useOutboxReplay.test.ts`. Live, after the push: on the dev server with the pane's network offline, a note from Job Mode's Note sheet reads *Kept on the phone…* and stays on the thread, the strip counts it with the clock press; back online it lands in order after the clock-in, the thread reads it at the moment it was written, and the strip turns green.
