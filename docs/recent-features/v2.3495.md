# v2.3495 — Price requests: ask several houses in one pass (2026-09-16)

Owner, 2026-09-15, from the Edit Bid window: "there is a price request section, I would like to add the functionality to add multiple price requests, where once I add a supply house, a button is available to add an additional supply house." Then, on the mock-up's two open questions: **one date per supply house**, and **a quote link for every house**.

Plan and before/after: [`to-dos/price-requests-loop/pr1-build-plan.md`](../../to-dos/price-requests-loop/pr1-build-plan.md) (PR 1 of the four-PR train in that folder's `README.md`); mock-up artifact *Ask Three Houses*.

## What changed

**Edit Bid → Files & Links → Price requests.** `+ Add a request` used to open one table row: pick a house, set the date, paste a link, Save — and Save closed the editor. Three houses meant three passes, and the date reset to today on each one.

It now opens a **block**. Picking a house appends a card and closes the picker; **+ Add another supply house** reopens it for the next one. Each card carries its own `when it went out` date and its own quote link, so a batch mailed the same day can still carry the one quote that has already come back. The Save button counts what it will write — *Add request*, *Add 2 requests*, *Add 3 requests* — and one insert writes every row.

The picker gained two marks, both from data the table already loads:

- a house already in the block is disabled and reads *already in this batch*;
- a house this bid has asked before reads *asked Sep 2 · already on this bid*, and stays pickable — asking again on a revised scope is legitimate, it just should not happen by accident.

**Editing a saved row is untouched**: one row, one house, its link box, `validateOutsideRequest`. Only the add path became a batch.

## Where the code is

- `src/lib/bids/bidPriceRequests.ts` — new `planOutsideRequests(draft)` returning either rows to insert or the first error plus the `atHouseId` it belongs to, so the component can name the house; new `askedHouseSummary(groups)` returning count and newest day per house. Both pure. `validateOutsideRequest` is unchanged and still serves the edit path.
- `src/components/bids/BidPriceRequestsTable.tsx` — the single `editorRow` constant was serving both add and edit; it is now `editorRow` (edit, verbatim) plus `addEditorBlock` (new). The block is one `<td colSpan={4}>` rather than four cells, because the add form is no longer row-shaped; that also gives it a working phone layout without touching the table's `narrow` width logic. The house search and list moved into `housePickerBody(onPick, marks)`, shared by both. `save()` split into `saveEdit()` and `saveBatch()`.
- Tests: 7 new kernel cases in `bidPriceRequests.test.ts`; new `BidPriceRequestsTable.render.test.tsx` (the component had no coverage before) for mount, pick-two-and-count, Cancel-writes-nothing, and the insert payload itself — two rows, `sent_via: 'outside'`, `status: 'sent'`, `quote_url: null`, the pasted link normalized and the blank one `null`.
- Guide: `src/content/help/get-supply-house-prices-on-a-bid.md` → "Requests you sent yourself".
- One copy fix caught on the live pass: a hand-sent row with no link read *no request link* under a column headed **Quote link**. It now reads *no quote link yet*. Batch-added rows usually have no link on day one, so the old wording went from rare to common. `RfqDeskModal`'s identical string is left alone — its column really is the request.

## No migration

`bid_rfqs` already carries `sent_via`, `requested_on`, `request_url` and `quote_url` (migration `20260909001806`, v2.3175, applied). Its RLS is one blanket `FOR ALL` policy for dev / master_technician / assistant / controller / estimator, so a multi-row insert behaves exactly as the single-row one did.

## Two pre-existing oddities this PR did not change

Recorded here so the next reader does not rediscover them, and because the second one is now written literally in the code.

1. **The box labelled "Quote link" writes `request_url`, not `quote_url`.** v2.3477 relabelled the box and kept the column. The consequence: a link pasted there does not mark the row `quoted` and is not counted by the header's "N quotes in", because `quoteCellFor` reads `quote_url`. It *does* reach the pricing robot, since `buildPriceMatrixSources` prefers `quote_url` and falls back to `request_url`. The new per-house link writes the same column deliberately — if the add path wrote `quote_url`, editing a row afterwards would move its link between columns.
2. **A hand-added row always saves as `status: 'sent'`.** The old insert read `status: v.quoteUrl ? 'quoted' : 'sent'`, but `draft.quoteUrl` has no input on this surface, so the first branch was unreachable. `saveBatch` writes `'sent'` outright rather than carrying a dead ternary forward.

Both are worth a decision of their own; neither is a bug anyone is hitting today.
