# v2.5170 — GC mode: a place to keep the files trade partners send, behind the scenes (2026-10-10)

P5a-m of the trade partner portal's real build (`to-dos/gc-mode/PORTAL_REAL_BUILD.md`; plan `to-dos/gc-mode/mockups/portal-p5a.md`, both on branch `spike/gc-mode`). Migration `20261010100000_gc_portal_p5a_files` (doc `docs/migrations/20261010100000_gc_portal_p5a_files.md`); the lead pushes it after the merge. No client or function change.

- **`gc_trade_files`**: one row for each file a trade puts in the job's Drive folder from its portal, and each signed paper the portal makes for it. It records the purpose (`submittal`, `change`, `quote`, `waiver`), the record it went with once stored, the name, type (PDF, JPEG, PNG, HEIC, HEIF), size (10 MB at most), the Drive file and its https link, and who made it (`trade` or `portal`). The office team reads it; only the service role writes it; the training-mode and twin blocks are on it.
- **The three verbs that store a file's link**:
  - `gc_trade_ask_change` gains `p_file_url` (dropped and made again, since a function's arguments cannot change in place; a call without it reads the same);
  - `gc_trade_submit_quote` reads `q->>'file'` into `gc_quotes.quote_file`;
  - `gc_trade_submittal_send` is unchanged in what it takes.
  Each ties the company's own uploaded file to the record it made (`gc_trade_file_tie`), never another company's. A link that is not https is `badRequest` (`gc_trade_file_link`).
- **The bed** `gc-portal-p5a` (`npm run test:pg:gc-portal-p5a`, in `scripts/sql-beds.txt`) passed locally on Docker, applied twice. It covers the grants, RLS, the CHECKs, each verb storing and tying its link, the old call, and the blocks.
- **Docs**: the migration's doc and `ACCESS_CONTROL.md`.
