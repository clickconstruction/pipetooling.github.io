## Item 10 — loss-categorization nudge at outcome time

One shared line, `LOSS_UNCATEGORIZED_NUDGE` in [`src/lib/bidLossCategories.ts`](../../src/lib/bidLossCategories.ts) ("Add why: an uncategorized loss can't teach the robots."), shown in amber wherever a bid is marked lost without a category and the six reason chips are already on screen:

- **Per-GC Sent panel** (`BidGcSentPanel` lost editor): nudge under the chips while none is selected.
- **Afterwards — the Bid Board lost strips** (`BidsBidBoardTab`, table strip AND phone card, new shared `renderLostStripReason`): an uncategorized lost bid's "Why did we lose?" strip now shows the nudge plus the six chips inline (with `suggestLossCategoryFromNote` on the free-text note). One tap calls the existing `onSaveLossReason` prop (the Lost-summary modal's write: `bids.loss_category` + reload) — no new write path. A categorized bid's strip now leads with the category label before the free text (and the strip's two literal grey hexes became theme tokens in passing).

Marking lost without a reason stays exactly as easy as before — the nudge explains *why* the tap matters, nothing blocks.

## Item 12 — record-grade chip on the Counts tab header

[`src/lib/bids/referenceGradeChip.ts`](../../src/lib/bids/referenceGradeChip.ts) (+ test): a thin presentation kernel over `referenceGrade` — never a fork — returning the letter plus a muted one-liner naming the gap when below A ("no priced rows — robots can't learn pricing from this bid", "no takeoff rows…", "no final value recorded…", "no plans link…", "plans-only census reference"). `referenceGradeChipApplies` = sent (`bid_date_sent`) or decided (`outcome`).

`BidsCountsTab` renders the chip beside the bid title (both the wide and narrow headers): letter badge in the board's `GRADE_COLORS`, "Reference grade" label, muted gap line. Presence inputs: `plans_link` / `bid_value` from the bid row, counts from the tab's own `countRows`, pricing from a one-row `bid_pricing_assignments` head query (the RPC the board uses only returns decided bids; the chip also covers sent-undecided ones). The chip waits for that read (`gradeHasPricing === null` renders nothing) so it never flashes a wrong letter. Purpose: nudge all estimators, not just the robot program — today's bids are tomorrow's training corpus.

## Item 8 — shadow-coverage pill on the robot Scoreboard

[`src/lib/bids/shadowCoverage.ts`](../../src/lib/bids/shadowCoverage.ts) (+ test): `isShadowEligibleLiveBid` (unsent, `plans_link` present, project name not `'ZZ '`-prefixed — the SQL `NOT ILIKE 'ZZ %'` rule, case-insensitive) and `shadowCoverage(bids, shadowReferenceBidNumbers)` → `{ covered, live }`. Matching is by bid **number** because staff read shadow runs through `list_shadow_runs()` (direct `twin_shadow_runs` select is RLS-closed since v2.2544) and that RPC names bids by number.

`BidsRobotScoreboardTab` takes a new optional `bids` prop (Bids.tsx passes `peopleBids`, the same array the Queue lens gets) and renders a fourth pill next to "audits pending" / "shadows awaiting score" / "scored runs on record": **`2/40` shadow coverage**, hover text explaining that every uncovered live bid is a free future grade-A reference. Note the count follows the page's trade-pill scope, like the Queue count beside it.
