# v2.7366 — Tasks: paint a new map while you write the task (2026-11-15)

Punch list #345, *A map on a task*, step 8. Taunya's ask of 2026-11-15, "I want someone to be able to assign a task with a map", and her yes to the design the same day. Step 7 (v2.7364) picks a map that is painted. This paints one from the task.

## What changed

- ***A map for this task* has a first half now: Paint a new one.** Two presses, **Draw it by hand** and **Walk or drive it**. The second shows only on a device that can say where it is.
- **A press opens the painting window that exists,** over the task's window, with no start sheet in between. The task's words are the map's name, and the painter can change it there.
- **The painter saves as on any map.** When the painting window closes, the map goes onto the task if a line or a place was saved. The row then shows it lit with its picture, as a picked map does.
- **Nothing saved is nothing changed.** A painting window closed empty leaves the task with no map.
- **With a place on the task, the painting window opens at the place.** With none it opens as it does from the search with no job.

## Taunya's call 3: the map is on no job

A painted map hangs on a job, on a development, or on nothing. A task has no job, so a map painted from one hangs on nothing. Its maker and the office read it, and so does whoever reads a task that carries it. The office puts it on a job later with **Put it on a job…**, which exists. The sheet says so under the two presses.

## How it is built

- `paintedMapDoor.ts`: a third ask, `paint`, and `paintPaintedMap(start, onClosed)`. The caller makes the map's id and names the map, so the host opens the window straight away. `onClosed` is called once when that window closes, saved or not.
- `PaintedMapHost` answers `paint` with the window it already opens after the start sheet, and calls `onClosed` from its close.
- `TaskMapPress` makes the id, asks the door, closes its sheet, and on `onClosed` reads the map by that id with `loadPaintedMap`. `taskMapFromPainted` turns what came back into the task's map, or into nothing.
- `taskMapNewName` is the name: the task's words without their link marks, cut to a map's sixty characters, or *A map for a task* when nothing is typed yet.
- `TaskFormRows` hands the task's words down as `mapWords`.

## Is this the best we can do

- **Read back, not handed back.** The painting window does not know a task asked for it. The press reads the map by its id when the window closes. So a map saved and then thrown away in the same window comes back as nothing, which is right.
- **A reload while painting loses the task's draft, not the walk.** A walk is kept on the phone and offered back, as always. The task's window is not, so the painter picks the saved map from the list afterwards.
- **A map painted and then not used stays.** Close the painting window, then close the task without sending: the map exists, on no job, its maker's and the office's. It is found by its name in the search.
