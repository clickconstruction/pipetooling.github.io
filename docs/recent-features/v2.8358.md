# v2.8358 — Working hours: the dev seat sets a person's week (2026-11-23)

Punch list #429, PR 5 of the working hours train. `plan_pay_setup` → `apply_pay_setup` read a salaried person's week since v2.7882 and said *the seat reads the week and does not set it*, because no screen set one. The **Working hours** row sets it now, through `set_working_hours`. This gives the seat the same door.

## The ask

`pay.working_hours` is a week by day: `{ mon: '06:00-12:00', tue: ['07:00-11:30', '12:00-15:30'], … }`. Each of `sun` to `sat` takes one range or two around a break, `HH:MM-HH:MM` on the 24-hour clock and the quarter hour. A day left out is a day off. `null` takes working hours off again. `pay.working_hours_from` is `this_week` (the default) or `next_week`: the Sunday the hours start on. The shape is checked with the row's own `workingWeekProblem`, so a refusal reads as the sheet's would.

## The plan

- **Reads** the person's `set` rows on `person_available_hours` and answers the hours in force today, a save waiting for a Sunday ahead, and how many saves there are with the newest one's time. The plan's hash holds them, so a save by anyone since refuses the apply.
- **Runs the door's own dry run** (`p_dry_run = true`), which writes nothing, and puts its answer in the reply. A refusal of the door's is the plan's refusal.
- **Says what moves.** For an hourly person, nothing on pay. For a salaried person whose day changes its length, the seven numbers before and after, the new weekly figure, and the weeks and crew days the change prices again (`reaches_back`, now priced with the old week before and the new week after). For a change of times alone, that pay stays.
- **Refuses before the door would** when a change to what a salaried day pays is asked for next week, with the two weeks in words, since pay carries no date.
- **Says when the clock follows**: from the day after the save for a person whose schedule clocks them in and out, never for a person who punches.
- **The newest save wins.** The same week again is no change. The same week saved for this week while another waits for next Sunday is a change, and the plan says the waiting one will never hold.

## The apply

One more step, `working_hours`, after `set_pay_config` and before the workday template. So with Salaried turned on in the same plan the door reads a salaried person and writes the seven numbers. The read-back carries the newest two set rows.

## The kernel on the edge

`src/lib/people/workingHours.ts` joins the edge copy (`scripts/edge-kernels.mjs`), so the lines, the hours and the seven numbers on the seat are the sheet's. The copy takes types only from a file that runs no code, so `Segment`, `WeekDays` and `AvailableHoursAnswer` moved to `src/lib/people/weekTypes.ts`. `weekAvailability.ts` and `utilization.ts` hand them on under the names every reader imports, and nothing else changed there.

## Words that changed

Three sentences said the seat does not set the week: the salaried week's note, the refusal of a workday of another length, and `not_written`. Each now points at `working_hours`.
