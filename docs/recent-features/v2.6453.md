# v2.6453 — Job photos keep the time the camera fired, and every photo form takes its shots the same way (2026-11-03)

Punch list #244's follow-up, named in v2.6359 and on the card: the Job photos window's `useShotTiles` had been lifted from the report form's `useReportPhotos` and kept beside it so the report's tests stayed untouched. The two are now one machine with two hosts, and the report form's tests pass unchanged.

## What changed

- **The engine** `useShotTileEngine` in `hooks/useShotTiles.ts`: one hidden file input, the camera's time (`readTakenAt`), the shrink to the office's size, the bytes kept, the send through the host's `ShotIo`, the tile kept on the phone when the host's own send error says no signal, Retry, Remove, `drop`, `clear` and `own` (a press that owns the shots, so a close drops nothing). A host passes its tile's own fields (`tile`), one file a press or every file (`multiple`), its send error's name, its words for a shot with no job, its `pickedAt` and its input's test id.
- **`useShotTiles`** (the Job photos window) is the engine plus each tile's words, *Use these words for the rest*, the stage, and the press's queued photos. Its shape is unchanged.
- **`useReportPhotos`** (the four report forms) is the engine plus the report's own: `reportShotIo` over `sendReportPhoto` and `discardReportPhotos`, the checklist questions and their chips, a stage chip that lets go of a question, the attach at Save with its answers and toasts, and the queued photos with their captions. One file a press, the `report-camera-input` test id, `ReportPhotoSendError` and *Photos ride on a job's report.* are as before.
- **`lib/photos/shotTiles.ts`** (new, pure): `ShotTileBase`, `sendLostSignal` (the io's own error class by name, the network kind) and `fileTimeOrNow`.

## The one thing a person sees

The window's shots now keep the camera's time, as the report form's have since v2.6375 (punch list #247, PR 3). v2.6375 wrote that rule into the report form, the checklist sheet and `PhotoPress`, while the window was built beside it without it. A file with no camera time keeps the file's own time, as before.

## Tests

`useShotTileEngine.render.test.tsx` (new: the camera's time on a job photo, the file's own without one, a report form's one shot a press, and the lost signal kept only for the host's own error class), `shotTiles.test.ts` (new). Unchanged and passing: `useShotTiles.render.test.tsx` and the report forms' photo tests (`AdditionalReportModal.camera`, `NewReportModal.photos`, `ReportEditModal.photos`, `TurnawayModal.photos`). `JobPhotosWindowLazy.render.test.tsx` now waits up to ten seconds for the window's chunk, since under load the default second was too short.
