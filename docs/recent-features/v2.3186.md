# v2.3186 — Robot questions get an audience: estimator or operator (2026-09-09)

Migration `20260909045818_twin_question_audience.sql`; twin-mcp v1.3.14 (redeploy); `docs/twins/estimator.md` §9 (briefs regenerated).

## Why

Wendi, reading the Standing rulings panel: "this robot is talking to you not me, quite a few of them are like that." She was right — on 2026-09-08 seven of the twelve open questions were the robot describing its own machine: the sandbox blocked a substrate insert (twice), the browser sign-in was blocked, the write fence denied `cost_estimate_labor_rows`, an insert into `fixture_types` was refused, a Drive file wasn't shared with the intake service account, and one "ANSWER PARKED" row that was a finding, not a question. `ask_question` was the robot's only outlet when stuck (its own description said "park a question for the owner/operator instead of stalling"), so every infrastructure failure wore the same 🤖 as a real doctrine question. The answered history shows the pipeline can write good questions — the R2-BT-14 / BT-16 ones are one decision each, sheet-anchored — the lane was just unfiltered.

## What shipped

- **[`twinQuestionAudience.ts`](../../supabase/functions/_shared/twinQuestionAudience.ts)** (new shared kernel, Deno + client, 8 tests): `classifyTwinQuestionAudience(text)` → `estimator` unless machine vocabulary fires (sandbox, sign-in, the write fence, RLS, service account, API key, substrate, harness, twin-mcp, a verb, a run workspace, the permission layer, a DB lane, `JSON`, `403`, a `get_…` tool name, any snake_case table name, a leading "ANSWER PARKED"), with the signals named; `effectiveTwinQuestionAudience(row)` trusts the column when present (a human's bounce beats the text) and classifies otherwise; `twinQuestionAudienceColumnPresent(rows)` gates the bounce buttons. The test pins the live 2026-09-08 queue: the seven operator questions route right, the eight estimator ones fire no signal, and fixture tags / sheet numbers / bid numbers / run codes never trip it.
- **Migration** — `twin_questions.audience` (`NOT NULL DEFAULT 'estimator'`, CHECK, partial index on open rows) + a backfill of the OPEN rows by the same signals in SQL, so Wendi's panel drops from 12 to 5 the moment it lands. See `docs/migrations/20260909045818_twin_question_audience.md`.
- **twin-mcp v1.3.14** — `ask_question` takes `audience` (`estimator` | `operator`); omitted, the text decides; the reply says which lane it landed in and why ("Filed for the OPERATOR (classified: sandbox, table name)"). The insert retries without the column if the function is deployed ahead of the push. The tool description now carries the estimator-lane writing rules.
- **The brief** (`docs/twins/estimator.md` §9 → `briefs.ts`): "Two kinds of stuck, two audiences" — operator = the machine is in your way (pair with the `blocked` heartbeat; table names, tool names and run codes belong here); estimator = a judgment about the job, written for her: **one decision per question, two sentences, name the project and the sheet, never a run code / table / tool name, a `topic` for doctrine**; a three-part ask is three questions; a blocker with both halves is two questions; a finding or an answer is never a question (that's `add_bid_note` / `submit_report`).
- **Bids → Audits, Standing rulings** — `groupStandingRulings(rows, { audience: 'estimator' })` keeps the estimator lane only (`openCountByAudience` for the rest). Each ruling and single gets **Not mine** (moves every open copy to the operator lane; hidden until the column exists) and **Dismiss** (status `dismissed`, which the panel never had — junk sat forever). The intro says what belongs here; dev sees "🛠 N robot problems for the operator — Settings → Digital twins".
- **Settings → Digital twins, Twin questions** (dev) — reads `select('*')`, shows a 🛠 OPERATOR / 📐 ESTIMATOR chip on every row (tooltip says whether the lane was set or read from the text), sorts open operator questions first, and offers **Send to estimator** / **Take as operator**.
- **Help** — *audit a robot bid* → Standing rulings gains the lane rule, the bid-number link, Not mine and Dismiss.
