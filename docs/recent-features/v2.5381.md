# v2.5381 — Lien desk: the two server functions that talk to the mail service, behind the scenes (Docsmit train, PR 3) (2026-10-13)

PR 3 of the Docsmit train (`docs/DOCSMIT_LIEN_RUN_PLAN.md`, *The PR train*): the edge functions, with nothing on screen yet. They lean on the kernels (v2.5375) and the `mail_pieces` table (v2.5379). Both sections are in `docs/EDGE_FUNCTIONS.md`.

**`_shared/docsmitClient.ts`** — Docsmit's HTTP and only that: `POST /token` with the SHA-512 hex and the software id, the token as the Basic username with one retry on 401; `accountInfo`, `multiCass`, `newMessage` (the id by whichever name the docs spell), `upload` (multipart `file`), `priceCheck` (the price by whichever field), `send` (201 sent, 402 with `shortfall`), `parties`, `documentation` (the Certification PDF, null until Docsmit has one), `sentList`. The base URL decides which Docsmit: Tracksmit, the sandbox, unless `DOCSMIT_BASE_URL` says the live site. No Deno globals, so a test hands it a fake `fetch`.

**`_shared/mailSend.ts`** — the pure rules the functions share: the status fold (a vitest case holds it equal to `src/lib/mail/mailPiece.ts` on ten provider strings), the client message id, `mailPrepareProblems`, the party and CASS shapes, the CASS verdict, the message title, `mailPieceUpdateFromParty` (the number, the fold, the mailed and delivered instants from `DStatusao`, who signed; a settled status never backs off; the mailed instant is set once), `sendsWithPiece` (the filing's `sends[]` with `via`, `piece_id`, the number and the Central day as `sent_on`), `ymdInZone`.

**`_shared/mailDocsmitRefresh.ts`** — the read-back both functions use: `loadOpenPieces`, `loadPiecesByIds`, `writeTrackingToFilings`, `refreshPiece` / `refreshPieces` (one `/parties` read, the patch, the event, the filings, and the Certification PDF filed at `mail/<piece id>/certification.pdf` in the piece's bucket once it reads delivered). The database is a small structural type so a recording fake stands in.

**`mail-send-docsmit`** — office-only (Bearer + `getUser`, the role from `users`, not read-only), one `action` per call: `ping` (the account's name and balance and which Docsmit), `prepare` (CASS first, 422 with the correction when it will not mail; the row as `prepared`; new message → upload the PDF the client already put in the bucket → priceCheck; a Docsmit failure after the row exists marks it `failed` with the reason), `send` (one at a time in order; 402 stops with *Docsmit credit is short by $X, nothing more was sent*; a sent piece reads `/parties` once and marks its filings), `refresh`. `docsmit_paused` in `app_settings` refuses everything but `ping` with 409. A state longer than two letters fails the check instead of being cut to two (the handler test caught `Texas` passing as `TE`).

**`mail-poll`** — the cron's read-back (`X-Cron-Secret`): every open Docsmit piece through the shared refresh, then, while `docsmit_match_site` is `'true'`, a message sent by hand from Docsmit's own site becomes a piece of kind `other` with a problem line; a `dry_run` lists and writes nothing; one piece's provider error is logged on it and the rest still read. The hourly cron row itself comes with PR 6.

**Tests**: `mailSendShared.test.ts` (4), `mailSendDocsmit.run.test.ts` (9, the handler itself with `mailRunFakes.ts`: a recording database, a scripted Docsmit, a bucket), `mailPoll.run.test.ts` (5). `config.toml` gains both entries with `verify_jwt = false`.

**Owed after merge**: `supabase functions deploy mail-send-docsmit mail-poll`; the owner sets `DOCSMIT_EMAIL`, `DOCSMIT_PASSWORD_SHA512` and `DOCSMIT_SOFTWARE_ID` (Tracksmit first; `DOCSMIT_BASE_URL` unset). The Developer-settings PR moves the three to Vault.
