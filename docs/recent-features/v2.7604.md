# v2.7604 — Documents: the rules for one list of every agreement (2026-11-17)

Punch list #376, PR 1 of five: the rules. One pure file and its tests. No screen, no migration, no edge function, and nothing reads the file yet.

## What is new

- **`src/lib/documents/agreementsLedger.ts`**: the kernel behind the coming Documents → Agreements tab. It reads one row shape, `AgreementRow`, which the `agreements_on_file` view of PR 2 will answer, and says what a line shows:
  - the tag (`agreementTag`: Contract, Warranty, Their paper, Staff, Sub, Partner, Work order) and its group's colours;
  - the name (`agreementName`: the paper's own name, or *Signed paper · Google Doc*, *· link*, *· scan* for a paper the office filed with no name);
  - the job (`agreementJobTitle`, `agreementJobTail`: *J2418 · name*, then the address or *and 2 more jobs* for a paper over several);
  - the state (`agreementStateChip`): one of three tones, `waiting`, `signed`, `ended`, with the words each kind's own window uses;
  - the day (`agreementDayWords`: *Signed Nov 14*, *Sent Nov 16*, *Voided Oct 15*, the year once it is not this one);
  - what a press opens (`agreementDoor`): the Contract window, the signed record window, People → Contracts on that paper, or the work order window.
- The chips (`AGREEMENT_KIND_CHIPS`, `AGREEMENT_STATE_CHIPS`, `kindsOfPick`, `statesOfPick`, `waitingChipLabel`), the find box's words (`agreementFindWords`), the month bands (`agreementMonthGroups`), the count and the empty words (`agreementCountWords`, `agreementsEmptyWords` over `emptyWords`), and `canSeeAgreements`, the four office roles.
- **`agreementsLedger.test.ts`**: 38 tests over every export.

## Choices worth knowing

- **The words are not rewritten here.** A job contract's chip is `jobContractChips`, their paper's is `theirPaperLine` without its leading *Their paper*, a work order's is `workOrderChipLabel` over `buildJobWorkOrderCoverage`. The tests assert the line equals what those kernels say, so a line and its window cannot drift apart.
- **`facts` carries each kind's own columns.** The view hands a JSON object of the few columns a kind's words are made from, and no money column. The kernel reads them by name and tolerates one that is missing.
- **An unknown kind still draws.** A kind the kernel has not met reads *Agreement* with the common state words, so PR 5's GC kinds can reach prod before or after their words do.
- **The tab id is not registered yet.** `documentsPageTab.ts` is untouched: an address that parsed to a tab nothing draws would blank the page. It lands with the tab.
