# v2.4079 — Workflow: the stage list is its own piece (2026-09-28)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 9 (`to-dos/decomposition-queue.md`): the Workflow map's step 10, second PR — the stage cards (`docs/WORKFLOW_PAGE_ARCHITECTURE.md` → "Stage cards list"). Built on v2.4066 (the step windows). This closes the map's ten steps.

## What shipped

- **`src/components/workflow/WorkflowStagesList.tsx`** — the whole region, JSX verbatim: the empty state and its "Create from template" card, the Hide Old Steps summary row, every stage card (all three rows, the notify tables, the action ledger, both notes, the Money drawer, sub work orders, Line Items For Office, the footer), the money markers between cards, and the ledger rail with its sticky margin card.
- **Its props are grouped and typed by the hooks that make them** — `engine`, `writes`, `projections`, `roster`, `templates` — plus the loaded `project`, three gates, and the window openers. The component destructures them into the page's own names, so the JSX needed no edits.
- **Moved into the list** — what only it reads: which card sections are open, which money markers are open, and whether the window is wide enough for the rail (with its resize listener).
- **Kept in the page, and why**:
  - `rowCollapsed` — the page's `onStepApproved` folds the approved card and opens the next one after the write (the `onApproved` seam of v2.4078);
  - `oldStagesCollapsed` — the header's Hide Old Steps button writes it;
  - every window's state — the page draws the windows;
  - the template cluster, as a new hook **`src/hooks/useWorkflowTemplates.ts`** the page calls — its read has to start on mount, not when the list mounts after the page's `Loading...` return (the reason v2.3936 gave for the header strips).
- **`src/pages/Workflow.tsx`** — 2,109 → 1,010 lines; 26 → 20 `useState`, 4 → 2 effects. Across the train, 4,354 → 1,010.

## Left, on purpose

A separate `WorkflowStageCard`. The card body reads the list's rail helpers and its open-section state, so a card component would take most of the list's props again; the map records it as worth doing only when a feature needs a smaller file. The contact modal still sits in the page.
