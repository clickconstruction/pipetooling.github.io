# v2.7913 — drive-link: a read of one file's bytes for the office (2026-11-19)

## Why

The owner's ask of 2026-11-19: the copy of a filed lien the office mails must be the clerk's stamped scan, not a page redrawn from the record. The scan is the filing's saved copy, a file in the job's Drive folder under Team only, Sent by us. The browser has to hold its bytes to put its pages in the print, and `drive-link`'s office door answered a list, Drive's viewer (`open`) and our public link (`link`), never the bytes to a signed-in reader. A public link for every print would open a Team only file to anyone holding it for thirty days.

## What changed

- **`{ action: 'read', job, driveFileId }`** on the office's door. The same gate as every ask there (a signed-in member of the office team, never a twin, the papers lock) and the same check as `open`: the file's parents must reach the job's folder (`halfInside`), so another job's file answers 403.
- The body is Drive's own (`alt=media`), passed through and never held whole, always `application/octet-stream`. The reader tells a PDF from a picture by the file's first bytes.
- Refusals in words, with `why` and `retry` as the door's other failures carry them (`DRIVE_READ_WORDS`, `_shared/driveLink.ts`): in Drive's trash 409, a Google document or a folder 415, over 30 MB 413 (`READ_CAP_BYTES`), Drive did not hand it over 502.
- A read: a training account may run it, and a twin is told it cannot read Drive (`OFFICE_READS`).

## Decisions

- **The door's own action, not a new function.** The gate, the papers lock, the job's folder and the inside check are already here, and a second function would copy them.
- **Thirty megabytes.** A stamped scan is under one. The cap is there so the door is never a way to pull a plan set through the function.
- **No name and no type in the answer.** The caller knows which file it asked for, and a type Drive guessed is not what decides whether a page prints.

## Tests

`src/lib/documents/driveLink.test.ts`: the ask parses with a job and a Drive id and nothing looser, a twin's refusal reads *cannot read Drive*, the cap and the words.

## Owed after the merge

`supabase functions deploy drive-link` from main. Nothing in the client calls `read` until the Lien desk's change ships, so the gap is safe.
