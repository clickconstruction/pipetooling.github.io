## The press nothing took back

**Turn off**, then **Turn the portal off**, in a customer's portal window (the globe on Customers, under Advanced settings, Reset) sets `revoked_at` on the `customer_portal_links` row and keeps it for the window's History. The table grants the office `SELECT, INSERT, UPDATE` and nobody `DELETE`, so every walk that turned a ZZ Test customer's portal off left a row for good: six stood on one ZZ Test customer on 2026-11-25.

## What changed

- **Migration `20261126023047_portal_link_delete_test.sql`**: `customer_is_zz_test(uuid)`, the ZZ convention in SQL for a customer beside `job_is_zz_test`, internal; and `delete_test_portal_link(uuid)`, `SECURITY DEFINER`, which refuses in words anyone but a developer, a link that is not there, a live link, a link of a customer whose name does not start with ZZ, and a link a GC's proposal names (`job_paper_proposals.portal_link_id` is `ON DELETE SET NULL` since 20261125023655, so the brief's *nothing points at the table* no longer held), then deletes the one row. No table is made or changed. Page: `docs/migrations/20261126023047_portal_link_delete_test.md`.
- `src/lib/portal/portalLinkDelete.ts`, the rule, pure: `portalLinkDeleteDrawn(role)` is true for a dev alone; `portalLinkDeleteProblem(entry, customerName)` refuses, in a sentence, a History line that is not a link's, a line with no row id, a live link, and a customer whose name does not start with ZZ (`isZzTestName`); `portalLinkDeleteConfirm` names the link and the customer, and its button reads **Delete the link**.
- `src/lib/portal/portalLinkDeleteIo.ts`: `deleteTestPortalLink(entry, customerName)` runs the rule, then calls the function once and passes its refusal on in its own words.
- `src/lib/portal/portalLinkState.ts`: a link row's `id` rides through `buildPortalLinkHistory` and `buildPortalTimeline` as `linkId`, null when a read did not select it. The window's read selects `id`.
- `src/components/customers/CustomerPortalGlobeButton.tsx`: under *History*, a dev reads **Delete…** beside every link that is turned off or rotated away. On a link that cannot go the press is dead and the line says why. On one that can, a confirm asks, the function runs, the toast reads *The turned-off link was deleted.* and the window reads its rows again.
- The guide *share a customer their portal* says so in one sentence, and `docs/ACCESS_CONTROL.md` names the two functions.
