# v2.5061 — Division 22 codes: add, change and delete rules and sections (2026-10-09)

PR 4 of the Division 22 rules manager train (`to-dos/division-22-rules-manager.md`): the manager's write side. It is built on the kernel (v2.5054) and the read side (v2.5058), with no migration.

**It merges only after `20261010015000` (PR 2's archive trigger) is on prod.** Otherwise the first deletes would be permanent, and the words promise that they can be put back.

## What changed

- **`SpecSectionRuleForm`** (new): add or edit one rule.
  - The fields are *Looks for*, *How* (starts with / contains / exactly), *Files under* (a section, or *No code*) and *Order*. The order carries its band, and a new rule's order follows its kind until typed: an exact name goes with the pins at 60, a pattern after the last pattern (`defaultPriorityFor`).
  - Before saving, it shows what the change moves (`previewRuleChange`): *Codes N, recodes N, leaves N uncoded. Coverage A% → B%.*, plus the first eight names with their codes before and after.
  - Refusals disable **Save rule**: no section yet, an empty pattern, an unknown section, a bad order, the same words the same way as another rule.
  - Warnings let it save: a two-letter pattern, and an order shared with a rule that catches some of the same names (`orderTies`, `orderTieWarning`).
- **The Rules tab**: **Add a rule** above the list; **Edit** (the row becomes the form) and **Delete** on each rule. Delete first says what it would move and that it can be put back for 90 days. Then it waits for **Delete rule**, or **Keep it**.
- **The Sections tab**: **Add a section** (the number in the ledger's shape, such as 22 45 00, `validateSectionDraft`), **Rename** a title, and **Delete**.
  - A section that still holds rules is refused, with the count in the words (`sectionDeleteRefusal`): *22 42 13 holds 1 rule. Move it to another section or delete it first.* An empty section asks first.
  - The window re-checks before it deletes, so `ON DELETE CASCADE` never runs from here. The restore caveat in `docs/migrations/20261010015000_d22_ledger_archive_on_delete.md` never arises.
- **`SpecSectionAuditModal`** owns the writes (insert, update with `updated_at`, delete) and one sorted `reloadRules`, which *Pin it* now shares. The section picker carries a label (*Files under*).
- **Docs**:
  - The guide *send a bid pricing package* names the writes in plain words.
  - `docs/GLOSSARY.md`'s *Division 22 codes* entry gains the manager's writes.
  - The card's status moves to PR 4.
