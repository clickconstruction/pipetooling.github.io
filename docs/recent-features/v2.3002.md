# v2.3002 — Test-gap audit, pass 19: the shared Stages loader gets its first tests (2026-09-07)

Follow-up to v2.3000. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`fetchJobsLedgerWithDetailsForStages.ts` (441 lines) is the one loader behind the Jobs board (Stages), the Job Summary tab, Dispatch Mode's home and the Accounts Receivable page: a primary `jobs_ledger` query shaped by status scope, the ready-to-bill companion query, the Job Summary min-HCP floor, and the batched enrichment (materials, fixtures, schedule blocks, estimates) in chunks of 150. Four callers, no test. Its helpers (`stagesJobReferenceDates`, `pickLinkedEstimateForStagesBanner`, `jobSummaryHcpFilter`) were already covered; the composition was not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Each scope's filter: `non_paid` and `working` use `or(...)` so SQL-null status counts as working; `paid` / `waiting` / `ready_to_bill` / `billed_all` are plain equality; `all` sends none. Every primary query pre-sorts by HCP number descending.
- The ready-to-bill scope runs the working-with-RTB-invoice companion (the `rtb_gate` inner embed does the gating), merges it without duplicates, and strips the gate alias before the rows reach the board. An `ids` list ignores the scope and never runs the companion.
- The min-HCP floor drops numeric HCPs at or below it before any enrichment, keeps non-numeric and blank numbers, reports the hidden count, and short-circuits enrichment when nothing survives. `-1` is the lowest floor; `NaN` and `null` apply none.
- Row mapping: payments and invoices sorted by sequence, to-one embeds accepted as an object or a one-element array, the linked bid's `service_type_id` defaulting to null, raw embed keys never leaking through.
- Every batch is chunked at 150 job ids, and a failed batch logs a warning and leaves that enrichment empty while the others still run. The Job Summary slim path batches materials only.
