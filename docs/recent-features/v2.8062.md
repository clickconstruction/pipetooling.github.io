# v2.8062 — Document builder: a page put back leaves nothing to publish (2026-11-20)

Punch list #404, found by the audit of 2026-11-20. A fix to step 7 (v2.8024). No migration and no function.

## What went wrong

On the Sub NDA, a dev changed a topic's name and then pressed **Back to revision 2** on that page. The list of changed pages went empty and read *Nothing waiting on a publish*, but the bar still offered a live **Publish revision 3**. A press on it made a revision with the same words as the last. A new revision is unread again, so the attorney's read mark was lost for nothing.

Four of the seven topics (photos, phones, getting on site, talking on site) have no `fact`, and the three that are in every paper have no `offSays`. `revertPage` put a name page back with `fact: was.fact`, and an Off page with `offSays: was.offSays`, so on those topics the draft gained a key holding `undefined`. `sameContents` compares through `stable()`, which printed that key as `"fact":null`. The published copy came back from JSON and has no such key. The page-by-page compare reads `topic.fact ?? null` and saw no change, while the whole-paper compare behind the Publish press saw one.

The stored draft was never wrong: the save drops such a key. The live press lasted until the builder was opened again.

## The fix

Both halves, each enough for the press by itself:

- `src/lib/documentBuilder/standing.ts`, `stable()`: a key holding `undefined` is left out, as `JSON.stringify` leaves it out. Contents that are stored the same now compare the same. A key holding `null` is still a key, and a list still keeps its places.
- `src/lib/documentBuilder/paperEdit.ts`, `revertPage`: a topic's `fact` or `offSays` is put back only where the published topic has one. Where it has none, the key is taken off the draft, so the draft is clean in itself.

Every caller of `sameContents` holds a draft against a copy that came back from the database: the walked builder's changed pages and Publish press, the filled builder's usual and a job's own sheet, and the *Changes not published* chip. None relies on a key holding `undefined` differing from no key.

## Tests

- `paperEdit.test.ts`, 2 new: a name changed on a topic with no `fact` and put back reads *Nothing to publish*, dead, and so does an Off page put back on a topic that is in every paper. A `fact` and an Off line the published revision has are put back whole, and a `fact` it never had is taken off. The first failed before the fix with *Publish revision 3*, live.
- `standing.test.ts`, 1 new: `{ a: 1, b: undefined }` is the same as `{ a: 1 }`, nested and inside a list too. `null` is not the same as no key. `[1, undefined, 2]` compares as JSON stores it.
