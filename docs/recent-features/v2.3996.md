# v2.3996 — Pipeline: the Working header’s pills look like pills again (2026-09-28)

Client only; no migration, no edge function. Found while checking new styles in a browser: rules added at the end of `src/index.css` did not apply.

## What was wrong

- The `.quickfillRoundScreen input, select, textarea` rule in `src/index.css` had no closing `}`. v2.3788 appended the Working header's styles straight after it, so the browser read every rule from there to the end of the file as nested inside it.
- A nested `.stagesWhenPill` only matches inside a Quickfill round screen's input, which is nowhere. `.stagesWhenPills`, `.stagesWhenPill` (with `:hover`, `:focus-visible`, `.isWarn`, `.isOn`, `.isSort`) and `.stagesWhenDoneNote` have not applied since v2.3788. The pills worked; they drew as unstyled buttons.
- Nothing fails on a missing brace: the file parses, the build passes, and any rule appended later is lost the same way.

## What shipped

- The missing `}`.
- **`src/lib/cssBraceBalance.ts`** (pure) — `cssBraceProblems(css)` returns each `{` still open at the end of the file, by the line it opened on, and each `}` that closes nothing. Braces inside comments and quoted strings are not counted.
- **`src/lib/cssBraceBalance.test.ts`** runs it over every `.css` file under `src/` (`index.css`, `components/authPublicLanding.css`, `pages/Calendar.css`), so CI fails on the next one and names the line.

## Verified

- `cssBraceBalance.test.ts` (7): four cases for the kernel, one per stylesheet. Before the fix the `index.css` case fails with `{ kind: 'unclosed', line: 3184 }`.
- In a browser, on a scratch page loading `src/index.css`: before, `document.styleSheets` holds the rules after line 3184 as children of the Quickfill rule; after, they are top-level rules.
- Not run in the live app: this worktree has no env file.
