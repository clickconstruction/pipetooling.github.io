# v2.2842 — GC-review nudge counts "Sent it" round marks as sent (2026-09-05)

Journey-map Phase 4, Tier-1 #11 (J20-F1/N1, J20-F2/F3 follow-through, J27-F1). One RPC edit, one guide correction, no client logic.

## The bug

`gc_review_week_status.gcs_sent` — the spine of the Dashboard "GC review is due" card / Needs-you badge — counted only `gc_statement_emails` rows (app sends). The personal statement round's **Sent it ✓** writes `gc_statement_round_marks`, and nothing bridged the tables. Live on Wednesday 2026-09-03 at day's end: RPC `{outstanding 10, certified 10, sent 0}`, the week's marks table empty, and the only three sends that week were whole-report internal copies (`gc_customer_id` NULL) — the 7:02 AM "All GCs" schedule moved `gcs_sent` not at all. v2.2705 made it louder: with everything certified the badge shows `outstanding − done` = **10** all week and the copy says "every group is certified; send each statement off" — a duplicate-statement prompt on the company's outward face. Meanwhile the modal strip (`mergeMarksIntoLastSent` → `gcReviewWeekProgress`) and the morning round email (`get_statement_round_for_user.last_statement = GREATEST(max sent-mark acted_at, max email sent_at)`, v2.2812) already counted marks — the RPC was the last emails-only surface.

## Migration — [`20260905130000_gc_review_week_status_counts_round_marks.sql`](../migrations/20260905130000_gc_review_week_status_counts_round_marks.md)

`CREATE OR REPLACE FUNCTION public.gc_review_week_status(p_week_start date)` — same signature, same four keys, outstanding/certified maths byte-for-byte v2 (`20260903184432`). Only the `sent` flag changes:

```sql
-- before (v2)
exists (select 1 from gc_statement_emails e
        where e.gc_customer_id = g.gc_customer_id
          and (e.sent_at at time zone 'America/Chicago')::date >= p_week_start)

-- after (v3)
exists (select 1 from gc_statement_emails e
        where e.gc_customer_id = g.gc_customer_id
          and (e.sent_at at time zone 'America/Chicago')::date >= p_week_start)
or exists (select 1 from gc_statement_round_marks m
           where m.gc_customer_id = g.gc_customer_id
             and m.week_start = p_week_start
             and m.action = 'sent')
```

- `action = 'sent'` only — `contacted` (v2.2813, "counts for the week and never as a statement") and `skipped` never count.
- `week_start = p_week_start` is the same scope the modal reads (`listGcStatementRoundMarks(certWeekStart)`) and `get_statement_round_for_user`'s `marks` CTE uses; `gc_customer_id` is NOT NULL on marks, and the emails predicate still requires a per-GC id, so whole-report "All GCs" copies stay excluded.
- `gcs_done` (certified ∧ sent) inherits the fix → `gcReviewGcsToDo` reaches 0 → `gcReviewNudgeState` returns `done` → the banner goes green on Wednesday and hides for the rest of a completed week.

## Telemetry — `gc_statement_sent{lane}`

Nothing new to record: both tables already carry the lane. Query for a week:

```sql
select 'app_email' as lane, count(distinct gc_customer_id) from gc_statement_emails
 where gc_customer_id is not null and (sent_at at time zone 'America/Chicago')::date >= :week_start
union all
select 'round_mark:' || coalesce(channel, 'unknown'), count(distinct gc_customer_id) from gc_statement_round_marks
 where week_start = :week_start and action = 'sent' group by channel;
```
