The bridge's safety net: drift is CAUGHT weekly, not prevented by sync machinery (locked
decision). Three pieces:

- **Pure kernel `supabase/functions/_shared/ctRosterDiff.ts`** (+10 unit tests in
  `src/lib/ctRosterDiff.test.ts` importing it directly — one copy, no Deno port needed
  since the kernel is dependency-free). Diff categories: only-in-CT (unmanaged seats),
  linked-but-gone (dangling join keys), active mismatch (the offboarding hole),
  twin-flag mismatch, email changed under a linked uuid, and backfill candidates
  (unlinked PT emails that exist on CT). Twin fleet domains normalize
  (`@twins.pipetooling.local` ↔ `@twins.counttooling.local`) so cross-app twin pairs
  don't false-positive as email changes.

  (PT service-role select, CT `manage-user roster` via `_shared/ctBridge.ts`), diffs,
  renders a sectioned HTML email with per-category fix hints, and sends to every
  unarchived dev via Resend. **Always sends** — all-clear is the heartbeat.
- **Migration `20260828110000`**: weekly pg_cron entry (Mon 13:00 UTC — off the
  5-minute email-dispatch lanes, no lane coordination needed). Push after merge; deploy
  `ct-roster-audit` after merge too.

Lean stream by design: no request table, share modal, or schedule-surface integration —
it's a fixed dev infra audit, rowed in `docs/REPORT_SUBSCRIPTIONS.md` as such.
