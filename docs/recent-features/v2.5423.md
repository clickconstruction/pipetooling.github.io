# v2.5423 — The code no longer carries a stale build cache (2026-10-12)

Repo hygiene only. Vite's dependency pre-bundle cache sat in git as 18 files under `.vite/deps/`, committed in the first two commits (`7d65e9cb0` "first push", 2026-01-17, and `997e483d7`, 2026-01-18) and never touched since. They leave the index, and `.vite/` joins `.gitignore`. No migration, no edge function and no screen.

- **What the files were**: pre-bundled copies of supabase-js (2.90.1; the app installs 2.99.2 today), react, react-dom/client, react-router-dom and the JSX dev runtime, three shared chunks, a source map for each, `_metadata.json` and `package.json`.
- **Nothing reads them**: Vite 5.4 keeps its cache in `config.cacheDir`, or else in `node_modules/.vite` beside the nearest `package.json`. It falls back to a root `.vite/` only when it finds no `package.json`. `vite.config.ts` sets no `cacheDir`, and no script, workflow, `package.json` entry or doc names the folder.
- **Why remove them**: they showed up in repo-wide searches as if they were source. `git grep banned_until` matched the bundled supabase-js source map.
- **Other checkouts**: the next pull deletes the folder from each working tree, since git removes files that leave the index. Vite rebuilds its cache under `node_modules/.vite` whenever the dev server needs it.
- **Checked**: `npm run build` passes with the folder moved out of the worktree. The build wrote `node_modules/.vite` and no root `.vite/`. The release-notes test passes.
