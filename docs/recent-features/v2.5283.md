# v2.5283 — The portals’ server code passes its own type check again (2026-10-12)

A fix to the edge copy of the kernels (`scripts/edge-kernels.mjs`, the schedule's PR 14b), asked for by the GC Review lead. On main, `deno check` of `gc-trade-portal` failed with 504 errors and `customer-portal` failed too. `supabase functions deploy` does not type-check, so nothing failed at runtime, but the type check meant nothing. Fixed by helper 3. No migration and no screen. `gc-trade-portal` and `customer-portal` want a redeploy, though nothing in them behaves differently.

- **The cause**: the copy turned an import of types alone, from a file outside it, into a path back at `src` with no `.ts`. Deno erases it at run time, but `deno check` cannot resolve it (TS2307), and every type that came through it became `any` (hundreds of TS7006 errors). Adding `.ts` alone was not enough. `gc/types.ts`, `payAppFile.ts` and `scopeBook.ts` import other `src` files the same way, so the check failed one level deeper.
- **The rule now**: types taken from a file outside the copy go one of three ways.
  - A file that imports nothing is pointed at in `src` with its `.ts`: the database's types and the schedule's. The copy never holds the generated database file.
  - A file of types whose own imports are types alone is copied, so its imports resolve inside the copy: `gc/types.ts`.
  - A file that runs code of its own is refused, with a word to move the types to a types file.
  - The generator now reports which files it holds for their types alone. `edgeKernels.test.ts` plants all three cases.
- **Two types moved**: `PayAppParties` (from `payAppFile.ts`) and `ScopeBookProject` (from `scopeBook.ts`) now live in `gc/types.ts`, and both old files re-export them. `building.ts`, `ownerBilling.ts` and `projectRows.ts` take them from `./types`.
- **Three type errors the broken imports had hidden**, each fixed in types alone:
  - `gc-trade-portal`'s empty schedule typed its to-dos as `never[]`.
  - Two of `customer-portal`'s job reads cast the client's inferred row straight to `PortalJobRow[]`. They now go through `unknown`.
  - `customer-portal` handed the supabase client to `loadGcStageInputs`, and TypeScript's structural check ran too deep. It is now cast to the loader's own `GcStageAdmin`.
- **Now**: `deno check` passes for both functions with no errors. The GC kernels' tests (1,857) and the generator's (9) pass.
