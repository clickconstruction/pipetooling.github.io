# v2.5359 — Seven more server functions pass their own type check again (2026-10-12)

A type-only fix to seven edge functions that `deno check` refused on errors in their own `index.ts`. They were found while fixing `_shared/fileSentCopy.ts` (v2.5348). No migration and no screen. Nothing behaves differently.

- **The fault**: each handed its service-role client to a helper typed `ReturnType<typeof createClient>`. Under supabase-js 2.117 (what `esm.sh/@supabase/supabase-js@2` serves today) that type resolves to a client with no schema, `SupabaseClient<unknown, …, never, never, …>`. So the real client, `SupabaseClient<any, "public", …>`, could not be handed in, and a write through the helper took `never`. `submit-portal-request`'s TS2589 is the same family: handing the client to `loadGcStageInputs` sent TypeScript's structural check against `GcStageAdmin` too deep. `supabase functions deploy` does not type-check, so nothing failed at runtime.
- **The fix**, in types alone:
  - `accept-estimate` (`handleDecline`), `mercury-webhook` (`generateSuggestion`, `autoApproveIfSwitchedOn`), `send-report-email` (`AdminClient`), `send-stripe-invoice` (`persistSendAfterEmail`, `sendBillCopies`), `share-job-contract` (`fetchBytes`) and `sign-bid-room` (`gcNamesForVersions`, `notifyStaff`) type the client as `SupabaseClient`, as `stripe-webhook`'s `recordStripeCase` already does.
  - `submit-portal-request` casts the client to the loader's own `GcStageAdmin`, as `customer-portal` has since v2.5283.
  - The writes the errors flagged were read against `src/types/database.ts` and exist as written: `insert_accounting_label_suggestion_service(p_rows)` and `auto_approve_pending_accounting_label_suggestions(p_tx_ids)` in `mercury-webhook`, the `report_email_dispatch_log` columns in `send-report-email`, and the `jobs_ledger_invoices` columns in `send-stripe-invoice`.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3) of the seven went from 25 errors to 0, on `main` with v2.5348's `fileSentCopy.ts`. On `main` without it, each shows only that file's 2 errors.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
- **Left alone**: eight functions outside v2.5348's 52 carry the same `ReturnType<typeof createClient>` and fail `deno check` too (`dev-mcp`, `gc-card-bill`, `geocode-one`, `get-stripe-invoice-details`, `notify-dispatch-request`, `notify-team-lead-clock`, `plan-fetch`, `twin-mcp`), with other errors of their own beside it.
- **Deploy**: redeploy the seven once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
