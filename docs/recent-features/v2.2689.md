# v2.2689 — Prospects Follow Up: "never called" chip outlives the call (2026-09-03)

Taunya (assistant) reported "shows never called but has call notes" on Follow Up. Two causes, both confirmed against prod data (Drymalla Construction, 2026-09-03 13:30–13:31):

1. **Stale state.** `handleDidntAnswer` / `handleAnswered` inserted the call row and reloaded the comments, but `calledProspectIds` (never-called chip + queue badges + calling order) and `prospectLastCallMap` (Prospect List sections + "answered Nd ago" labels) were only rebuilt inside the two tab loaders. The chip stayed up after the call until the next full load.
2. **Enter files a note, not a call.** The composer's "press Enter to add" path writes `interaction_type = 'user_comment'`, which the v2.2301 "called" definition deliberately excludes. Callers type the result ("left a vm", "he answered and hung up on me") and press Enter — 10 of Taunya's 12 most recent rows were call outcomes filed as plain notes — so the prospect stays "never called", the Activity week report undercounts, and warmth never moves. Clicking Answered afterwards added a boilerplate "Contacted" row beside the real note.

## Client only — no migration

- New kernel [`lib/prospects/callLogState.ts`](../../src/lib/prospects/callLogState.ts) (+7 tests): `findRetaggableNote(comments, userId, nowMs)` — order-independent; returns the caller's own `user_comment` when it is the newest thing on the prospect and within `RETAG_NOTE_WINDOW_MS` (10 min); `withCalledProspect` / `withLastCall` — immutable patches for the two derived stores.
- [`Prospects.tsx`](../../src/pages/Prospects.tsx): `writeCallOutcome(prospectId, type, fallback)` is the single call-row writer for both outcome buttons. With an empty composer and a retaggable note it **retags** that note — `prospect_comments` has select/insert/delete policies but no UPDATE, so it inserts the call row with the note's text and original `created_at`, then deletes the note (insert-first so a failed delete leaves a duplicate, never a lost note). Otherwise it inserts the typed text or the old fallback. Insert errors now toast. `markCalledLocally` patches `calledProspectIds` + `prospectLastCallMap` after either outcome. Composer placeholder + header hint say Enter = note; an amber line under the box ("Saved as a note, not a call…") shows while a retaggable note exists. Chip tooltip reworded.
- Help guide `work-the-prospect-calling-queue.md`: "Log how the call ended" explains Enter vs. the outcome buttons and the retag.

Not changed: the "called" definition (v2.2301) — plain notes and emails still don't count, by design; the two Feb-2026 site-visit prospects (G. Morris, D.R. Horton Austin) stay "never called" until someone logs a call. Backfilling Taunya's earlier plain-note call outcomes is a data decision for the owner, not done here.
