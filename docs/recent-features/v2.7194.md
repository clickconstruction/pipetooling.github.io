# v2.7194 — Print labels: the Which job? window is wider and never scrolls sideways (2026-11-13)

The owner's ask, with a screenshot of Materials → On site → **Print labels**: the window forced a sideways scroll and should be wider.

## What was wrong

`PrintLabelsWindow.tsx` drew the window 460 wide as a grid, with the jobs in a second grid inside it. Neither grid named its column, so the column took the width of its widest child, and a job's row holds its name on one line with `white-space: nowrap`. A name longer than the window made the column wider than the window. The window has `overflow: auto`, so it scrolled sideways, and each row's label count and the window's close press sat off its right edge. Since v2.7162 a row leads with the job's number, which made the names longer.

## The change

- The window is `PRINT_LABELS_WINDOW_WIDTH`, 640, on a desk, and the screen's width less its margin on a phone, as before.
- Both grids are one column of `minmax(0, 1fr)`, so no child can widen them, and the window takes `overflow-x: hidden`.
- A job's name wraps onto a second line in place of an ellipsis, so the whole name reads. Its label count stays on one line at the right.

Client only.

## Verified

A render test holds the width, the two column rules and the wrapping name. Walked on the dev server as the dev, read only, at 2,000, 1,400, 768 and 375 wide: the window is 640 wide on the first three and 343 on the phone, it does not scroll sideways at any of them, every row's label count ends inside its row, and the close press is inside the window. At 375 the two long names take two lines.
