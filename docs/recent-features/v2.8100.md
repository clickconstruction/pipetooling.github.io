# v2.8100 — Sub papers: the window says it is getting the papers ready (2026-11-20)

Client only: no migration, no edge function. Punch list #350, found in the audit of the card.

## Before

The papers window reads three things before it can draw a paper: the letterhead from Settings, the person's roster row and their rows in the register. `SubPapersWindowConnected.tsx` returned nothing until they were in, so the press drew nothing for as long as the reads took, and a second press did nothing more.

Walked on the dev server with the Settings read held for seven seconds: two and a half seconds after the press there was no window and no word on the page.

## What changed

- `SubPapersWaiting` (`SubPapersWindow.tsx`) is the window's own frame: *Papers · <name>*, **Close**, and *Getting the papers ready…* as a status line. The connected window draws it until the reads are in, then the window itself.
- It stacks where the window does, so on a phone it opens over the *What we owe* sheet as the window does since v2.8094.

## Tests

`SubPapersWindow.render.test.tsx` (+1): with the letterhead's read held open the frame says it is getting the papers ready and draws no paper, Close answers, and the paper draws once the read lets go. It fails with the frame taken out. One older test waited for the first heading on the page and now waits for the window's own.
