# v2.2954 — The anon key could read the jobs ledger: EXECUTE revoked on 28 unguarded RPCs (2026-09-06)

First result of the RLS / exposure audit (Plan B, audit 1 of 4). One migration (`20260906180000_revoke_anon_rpc_exposure.sql` — **`supabase db push` after merge**); no client code, no edge function.

## What was found

A static pass over all 477 migration files (`rls-audit.mjs`, scratchpad) found every live public table has RLS enabled, no table was created after the last read-only applier call, and no policy is granted `TO anon`. Anonymous REST reads on every suspicious table returned zero rows. The tables are sound.

The RPC layer was not. Supabase grants EXECUTE to PUBLIC on every function and a SECURITY DEFINER body with no caller check runs as its owner for anyone. With only the anon key from the client bundle and no session, prod answered:

| RPC | anon result |
|---|---|
| `get_jobs_ledger_by_status('paid')` | 714 rows — job name, address, revenue, payments made, Drive and plans links |
| `search_jobs_ledger('')` / `search_bids_for_clock('')` / `search_jobs_for_reports('')` / `search_jobs_for_tally_mercury_assign('')` | ~50 rows each — jobs, bids, addresses, customer names |
| `list_customer_review_job_hours()` | 98 rows — customer name and hours |
| `get_archived_user_names()`, `get_location_enabled_user_ids()` | the roster |
| `count_pending_accounting_label_suggestions`, `count_pending_clock_session_approvals` | the nudge totals, one with a dollar amount |

A completeness pass then probed all 160 read-style SECURITY DEFINER functions the same way. About twenty correctly raise "not authorized" to anon and `search_estimates_for_nav` returns nothing — those are the shape to copy. The Tally search is the instructive failure: its only gate is a deny-list ("caller is not a helper or sub"), which a missing session passes.

## What shipped

- **Migration**: `REVOKE EXECUTE … FROM PUBLIC, anon` on 24 signatures with signed-in callers (`authenticated` / `service_role` grants untouched), and `… FROM PUBLIC, anon, authenticated` on five functions with no caller in the repo, four of them SECURITY DEFINER writers (`create_project_with_template`, `duplicate_purchase_order`, `copy_workflow_step`, `create_takeoff_entry_with_items`) plus `debug_cost_estimate_policies`. Full list and rationale in `docs/migrations/20260906180000_revoke_anon_rpc_exposure.md`.
- **`ACCESS_CONTROL.md`** → new "SECURITY DEFINER RPCs and the anon key" section: the rule (gate on the caller inside the body, allow-list not deny-list, `REVOKE … FROM PUBLIC, anon` when the RPC has no anonymous consumer) and the two RPCs public pages legitimately need.

Deliberately not done here: a blanket `REVOKE EXECUTE ON ALL FUNCTIONS IN SCHEMA public FROM anon` plus `ALTER DEFAULT PRIVILEGES`. It would close the class for good, but policies on the anon-facing tables (`public_page_views`, `estimate_customer_events`, the portal slugs) may call helper functions at evaluation time and there is no staging to prove nothing breaks. Owner decision, listed in `to-dos/owner-decisions-pending.md`.
