# v2.2417 — last_contact hand-bump cleanup (2026-08-28)

The Phase 1 follow-up promised in `docs/PER_GC_BID_PLAN.md`: with migration
`20260828040000` (the `bids_submission_entries` → `bids.last_contact` sync trigger) applied
to prod, every client-side hand-bump of `bids.last_contact` is redundant — and the
unconditional ones were actively wrong (a method-less note's bump would overwrite the
trigger's correct value right after the trigger computed it).

Removed the stamps at all nine sites (the entry writes remain and fire the trigger):

- `Bids.tsx`: bid-sent confirmation note + Win/Loss change note (both method-less — pure
  bug fixes), and the save payloads now seed `last_contact` **only on INSERT** (a saved
  bid's field is the read-only derived display + Log contact, v2.2413).
- `BidGcNotesPopover` + `UnifiedBidCustomerNotes` (edit + add paths) + `BidNotesTable`
  (edit + add paths) — the add paths were still unconditional.
- `BidsCallQueueTab` + `BidsWaitingToHearLens`: chase patch no longer carries
  `last_contact` (update skipped entirely when the patch ends up empty).
- `BuilderCallSessionModal` + `BidsBuilderReviewTab` quick log: the
  `bidLastContactUpdates` output was removed from the `builderCallSession` /
  `builderQuickLog` kernels (tests updated).
- `BidLogContactControl`: replaces its forward-only client mirror with a re-read of the
  trigger-derived value after the insert.

Also updates `docs/PER_GC_BID_PLAN.md`'s Status log: Phases 1–3 shipped
(v2.2413/v2.2414/v2.2415), Phase 4 (`bid_gcs`, v2.2416) in flight.
