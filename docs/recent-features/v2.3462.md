# v2.3462 — Pipeline: the Progress & payment column widens so "Done, not billed" never wraps (2026-09-15)

Client only; no migration, no edge function. Owner's screenshot after v2.3459: the legend's amber row read `24% Done, not` / `billed` on two lines in the 12rem column while the other rows held one.

## What changed

- Both Stages tables' colgroups (`JobsStagesTable`, `JobsStagesUnifiedTable`) and the shared header (`StagesProgressPaymentHeader`) set the Progress & payment column to **14.5rem** (was 12rem). Measured: the widest legend row — `100% Done, not billed` beside a six-figure amount at 0.75rem — needs ≈198px of content; 14.5rem gives 208px inside the cell's padding.
- `STAGES_TABLE_MIN_WIDTH` moves 760 → **800** so the Job column keeps its ≥ 284px floor with the sized columns now totalling 516px (the comment derives it).
- `StagesProgressPaymentCell`'s legend labels are `white-space: nowrap`, so a label can never wrap again — a too-narrow embed would clip rather than stack.

## Verified

Render smokes for the cell, bar and the three tables green; typecheck, lint, theme check. Live on the dev server: every expanded section's legend rows measure on one line inside the 232px column; the tables still scroll sideways inside their wrapper below 800px.
