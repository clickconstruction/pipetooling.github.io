# v2.3582 — `pay:backfill` starts tracking on 2026-04-01 (2026-09-18)

The owner, 2026-09-18, on the by-person standings: *"I like it and we should not go all the way back because we weren't tracking back then. I think we should only go back to April first."*

## The rule — `PAY_BACKFILL_SINCE = '2026-04-01'` ([`paySources.ts`](../../src/lib/people/paySources.ts)), `sinceYmd` on [`buildBackfillPlan`](../../src/lib/cashapp/backfillPlan.ts)

- Cash App sends before the date are **filed as before records** (one lane action each, never matched).
- Recorded payments before the date are **neither matched nor counted** — not linked, not listed as unbacked.
- Mercury payouts before the date are counted in "Mercury before records", not listed.
- A person's **open balance counts only reports ending on or after the date**; March reports with a balance are out of scope.
- `--since YYYY-MM-DD` overrides for one run; the plan header states the date in force.

## Why a rule and not a filter

The standing table (v2.3581) is only honest if every column uses the same start. Making the date a kernel argument means the lanes, the matching, the unbacked list and the open balance all move together, and a robot cannot forget it. 1 kernel test.
