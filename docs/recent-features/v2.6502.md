# v2.6502 — My logbook opens for every teammate (2026-11-04)

Found in the live check of v2.6483 (punch list #255, the logbook shown to its teammate). The Layout's route guard (`isPathAllowedForRole` in `src/lib/layoutRouteAccess.ts`) keeps a path allowlist for helpers and subcontractors, primaries, superintendents and estimators. `/my-logbook` was in none of them, so the gear menu's **My logbook** row sent those teammates, the apprentices among them, straight back to the dashboard (an estimator to Bids). Dev, master technician, assistant and controller pass every path, so the office's own check could not show it.

## What changed

- `/my-logbook` joins `SUBCONTRACTOR_PATHS`, `PRIMARY_PATHS`, `SUPERINTENDENT_PATHS` and the estimator's list. The page still answers only once the office shows the logbook (`my_logbook()` is NULL without a `logbook_shares` row), so the path opens nothing new.
- `layoutRouteAccess.test.ts`: every role in `ROLES` reaches `/my-logbook`, with and without prospects access. The case fails on main's lists (first on `subcontractor`).
