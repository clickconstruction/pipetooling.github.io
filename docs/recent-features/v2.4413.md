# v2.4413 — Bids: a copy takes one version, its own prices and its quoted costs (2026-10-02)

Punch list #79, found while building #78 (v2.4388) when the owner asked of that plan *is this the best we can do?* Four gaps in the functions that copy or move a bid, each with a default. The owner, 2026-10-02: "yes to all 4".

## What changed
- **Migration `20261002130000_bid_copies_carry_costs_prices_one_version`** ([doc](../migrations/20261002130000_bid_copies_carry_costs_prices_one_version.md)):
  1. **Quoted fixture costs follow a copy.** A new version and a same-trade duplicate copy them, each package under an id of its own, so reverting a package in one leaves the other alone. A duplicate into another trade leaves them. An adopt moves them. The table gains the foreign key to its count row it never had.
  2. **A duplicate of a bid with versions copies the version the bid is on**, as one plain bid. Before, every version's rows were stacked and the counts doubled.
  3. **A duplicate owns its prices.** Each price the bid owns is cloned with its entries, and the custom prices, hidden rows, assignments and saved price point at the clone. Before, they pointed at the first bid's prices, which the copy's Pricing tab never found.
  4. **An adopt leaves a submittal's takeoff picks with the retired bid.** Decided, no change.
- **The quoted costs read again when the version changes** ([`useBidCustomCosts`](../../src/hooks/useBidCustomCosts.ts)), so a version made a moment ago shows the costs it brought, as the stage boxes do since v2.4393.
- **The Copy Bid window says what a copy takes**, in plain words, and that a bid with versions copies the version you are on.
- **Guide:** new *copy a bid into another trade or duplicate it*.
- **Roles:** a primary or a superintendent may make a version and may not write a quoted cost, so for them the copy is made without the costs (`can_write_bid_custom_costs()`, `ACCESS_CONTROL.md`).
