# v2.7240 — Materials on site: the record says who really made each press, and when (2026-11-13)

Punch list #344, PR 5, on the owner's word (*Yes, build PR 5*): what a teammate may change. The gate on the on-site tables says which job a person may write; nothing said which columns. The migration is `20261114013000_on_site_teammate_guards.sql`, and its doc, `docs/migrations/20261114013000_on_site_teammate_guards.md`, has the detail.

## What was open

Found by the review of Materials → On site, none of it from a screen: a box photo's row could be pointed at any Drive file, which the public box page streams; a box's `job_id` could be changed by a direct update; the ledger's `by_user_id`, `by_name` and `at` were whatever the phone sent; and the box page's guess lock turned a wrong code into a 429 and still answered a right one.

## The change

**The migration** adds four triggers, one helper and one nullable column, for a direct caller alone (the sweep, the box page, a combine and the dev seat's move pass untouched):

- A new ledger row and a new box move take the caller as `by_user_id` and the caller's own name as `by_name`. A dev's name is kept as sent, for the dev seat's agent label. A time ahead of the server's becomes the server's; an earlier one, a press that waited for signal, is kept.
- `job_material_movements.recorded_at` is when the row reached the office.
- A box photo's `drive_file_id`, `filed_at`, `refile_due_at`, `fail_why` and the status `filed` are the sweep's. Its box, job and taker never change. Its `storage_path` is `<a job's id>/<its own id>.jpg`.
- A box's `job_id` cannot be changed by a direct update.

**`box-read`** reads the hour's miss count before it answers a hit (`readEstimateLinkLock` in `_shared/estimateLinkMisses.ts`, a plain read that counts nothing and fails open) and refuses a locked source either way. A box's code is eight characters; an estimate's ten-letter link keeps its lock on misses alone.

No client code changes: every write the app makes already fits the guards, and no screen reads `recorded_at` yet.

## Proved

- `supabase/tests/on_site_guards/20_scenario.sql`, a new bed in `scripts/sql-beds.txt`: 26 checks through RLS as a helper on a job's team. Run on a scratch Postgres 15 with a stand-in for the surrounding tables, the migration applied twice. With each trigger disabled in turn the scenario fails at that trigger's first check. Docker was not available to this login, so the bed over the whole schema is CI's to run.
- `src/lib/estimateLinkMisses.test.ts`: four more cases for the lock's read (past the limit, at it, last hour's and another source's, a read that fails).
- `npm run check:edge-bundles` links all functions with the change.
- Read only, on prod, through the dev seat's view-as: the primary on the site's main job and a helper on its second job each read their job's boxes, so the gate lets in everyone on those teams today.
