# v2.2977 — Test-gap audit, pass 7: the Banking per-user preferences, the built-in accounting labels and the debit-card helpers get their first tests (2026-09-06)

Follow-up to v2.2975, which named the banking drag-sort storage next. Tests only — no kernel, client, migration or edge-function change.

## Why these

`bankingDragSortStorage.ts` (260 lines) is every per-user switch on the Banking Drag Sort, Accounting and Card Review tabs — hide labeled rows, cards expanded, reorder mode, apply-rules-by-default, the ledger modal's filters and sort, the rules section, approvals grouping, the chart view. Each has its own default and encoding (some store `'1'` for on, some store `'0'` for off), which is exactly the kind of thing that silently flips when a key is touched. `dragSortDefaultLabels.ts` (235) is the Schedule C label table the org is seeded from, plus the Internal Transfers guard. `banking/debitCards.ts` carries two small pure helpers.

## What shipped

- **`bankingDragSortStorage.test.ts`** (15) — through a Map-backed `window.localStorage` stand-in: the four **opt-in** flags (absent = off, only the literal `'1'` = on, cleared on off, per user), the three **opt-out** flags (absent = on, `'0'` = off, legacy `'1'` still reads on), the ledger filters as raw JSON (empty or null clears), the ledger sort (default not stored, non-default stored and parsed back, malformed reads as default), the Card Review chart view (device-global, `pie` stored, `table` clears, the old `user_review` key migrated on first read, unknown values read as table), and the two failure modes — no `window` at all and a storage that throws — where every read returns its default and every write is swallowed.
- **`dragSortDefaultLabels.test.ts`** (5) — the table has unique snake_case keys and no blank fields, every Schedule C line is a recognised form reference, the Internal Transfers built-in is present and the guard recognises only it; `ensureDragSortDefaultLabels` upserts one system row per definition in table order with `sort_order = index × 10`, keyed on `default_key` with `ignoreDuplicates` so existing rows are never overwritten, and surfaces a database error as a `DatabaseError` carrying the code and details.
- **`banking/debitCards.test.ts`** (3) — only `'company'` is a company card, the two role options, and the Debit cards door URL (encoded card id, or the general modal).

All 23 passed on the first run.
