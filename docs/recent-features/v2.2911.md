## RFQ (B2)

1. **Parser strips `/` and folds plurals (J12-F4, was WORSE since v2.2651)** — [`src/lib/rfq/parseVendorReply.ts`](../../src/lib/rfq/parseVendorReply.ts). Root: `fixtureTokens` split fixture names on `[^a-z0-9/]+` (kept the slash) while vendor lines split on `[^a-z0-9]+`, so "Shower/tub combos" tokenized as `shower/tub` and no vendor line could ever overlap it; neither side folded plurals, so "Kitchen sink" never met "Kitchen sinks". Now: one `WORD_SPLIT` (`[^a-z0-9]+`) for both sides via `tokenizeWords`; `foldPlural` (exported) drops `-es` after a sibilant and a trailing `-s` on words of four letters or more (short abbreviations `fs` / `gas` / `sv` untouched); the verbatim-name +4 bonus is a `fixtureNameRegExp` built from the folded words joined by `[^a-z0-9]+`, so it tolerates separators and plurals too. The Rung E file-drop lane (`PlugInQuotesModal.runMatch` → `extractReplyText` rows joined by two spaces) feeds the same function, so it inherits the fix. Tests (`parseVendorReply.test.ts`, new describe): the walked line "Shower tub combo: call for pricing, can't supply until Oct" → can't-supply row on the slash-named fixture; "shower tub combos 3 @ $900" → exact; singular↔plural both ways; the two-space sheet shape; `foldPlural` guard cases; the original sample still parses.
2. **Caret labeled (J12-F1)** — [`PricingShareMenu.tsx`](../../src/components/bids/PricingShareMenu.tsx): share-capable roles see "Supply house prices (RFQ) ▾" instead of a 25-px "▾" whose only name was a hover title; menu item "Supply house list" → "Supply house prices" (hint keeps the names+counts, no-prices framing and now mentions the quote link); aria-label/title updated; the non-share "Export ▾" variant unchanged.
