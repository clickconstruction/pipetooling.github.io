# v2.4291 — Day book: Month opens the month you are in (2026-10-01)

CI went red on every PR on 2026-10-01: two `PeopleDayBookTab.render` cases failed (*Month draws the rhythm grid…* found no done cells; *tells the page where it is…* remembered September). Not a flake. Oct 1 2026 is a Thursday, so this week runs Mon Sep 28 – Sun Oct 4, and **Month** opened `dayBookMonthOf(range.from)` — the month of the week's first day, September — so today's activity sat outside the grid. The tests only fail on the first days of a month whose week began in the month before, which is why they had passed since v2.3735.

- [`PeopleDayBookTab.tsx`](../../src/components/people/PeopleDayBookTab.tsx) `showMonth`: a shown range that holds today opens `dayBookMonthOf(today)`; any other range keeps opening the month of its first day. This is the rule `showWeek` already used.
- [`PeopleDayBookTab.render.test.tsx`](../../src/components/people/PeopleDayBookTab.render.test.tsx): a case that fakes only `Date` to 2026-10-01 and asserts the opening week (Sep 28 – Oct 4) and then the month asked for (Oct 1 – Oct 31). It fails on the old `showMonth` and passes on the new one, on any day it runs.

Found while fixing CI for v2.4288 (PR #4233); shipped apart from it.

Verify: `npx vitest run src/components/people/PeopleDayBookTab.render src/lib/people/dayBookRhythm`.
