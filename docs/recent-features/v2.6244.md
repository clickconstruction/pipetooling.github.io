# v2.6244 — dev-mcp: a sworn statement drafted onto a matter's Timeline (2026-10-31)

Punch list #220 (`to-dos/legal-desk-affidavits/`), the robot path the card deferred past its seven-PR train: a dev's agent can leave a draft affidavit or unsworn declaration on a legal matter's Timeline for the office to print, sign and file. Until now the seat filed the signed scan (`plan_matter_document`, v2.6004) but the text itself was retyped by the office, which is the nine-steps-across-four-tools problem the card opened with.

- **Migration** [`20261031190000_dev_legal_statement_write.sql`](../migrations/20261031190000_dev_legal_statement_write.md): `dev_legal_statement_write(p, p_dry_run)`, the dry-run wrapper modeled on `dev_legal_plan_write`, devs only. `p = { action: add | update, matter_id | entry_id, on, title, body, affiant { kind team | witness, user_id?, name, role? }, form? (notary | declaration), incident_to?, venue_county? }`; on an update a JSON null clears the span or the county. The office RPCs' own checks run in the wrapper first (the affiant's shape through `legal_statement_affiant_problem`, a team affiant's `user_id` a real `users.id`, the caps, the day never ahead of today, the span in order), so the plan refuses in words. The dry run returns the matter, the statement before (on update), the draft as it would be written with the Said lane's state words (*Draft · not signed.*; a printed draft says the office prints again), `statements_on_matter` (the live count, so one added or dropped since the plan changes the hash), a `then` line on what the office does next and `firm_reads_it`. Apply writes through `legal_statement_add` / `legal_statement_update` with `p_source = 'mcp'`; a signed statement, a dropped one or a row of another kind is refused. The wrapper never reaches `legal_statement_print` or `legal_statement_sign`. Run end to end on a throwaway local Postgres 15 (the two migrations over stubbed gates; applied twice): non-dev refused, the dry add's shape, five refusals in words, the apply landing as a draft by the dev with source `mcp`, the count moving, an update with null clearing the span and the county while the body stays, a printed draft still plannable, the signed refusal, a plan row refused.
- **Server** ([`dev-mcp/index.ts`](../../supabase/functions/dev-mcp/index.ts), 0.13.0; [`_shared/devMcpWrites.ts`](../../supabase/functions/_shared/devMcpWrites.ts)): `plan_matter_statement(statement)` / `apply_matter_statement(statement, plan_hash)` on `WRITE_VERBS`, the same plan → hash → apply grammar as every write; `writeRpcBody` holds the shape (an add needs its matter, day, title, body and affiant; an update its `entry_id` and at least one change; a witness carries no `user_id`; the affiant goes through as its four keys trimmed), `planReply` points at the apply verb, `alreadyApplied` says the draft is on the Said lane. The instructions string reads twenty-one verbs. `statementByWords` in `legalTimeline.ts` already tagged an mcp-sourced statement *· dev MCP* for the office, so the desk needed nothing.
- **A fix found in the dispatch**: v2.6187's `mint_twin_setup_code` block (#6590) had been merged between the eleven older write verbs' `case` labels and the write branch they fell through to, so from that deploy `plan_cost_batch` through `apply_history_entry` fell into the mint block and answered *mint_twin_setup_code needs label*.
