# v2.2569 — AR bank list: sorting-config race fix + org-filter clobber guard (2026-09-01)

Root-caused from a live report ("Accounts Receivable showed me bank transactions"):
the AR modal's left list is narrowed to deposit kinds/accounts ONLY by the org-wide
Banking Sorting config (`app_settings.bank_payments_sorting_config_v1`) — the
`list_mercury_transactions_for_bank_payments` RPC itself has no deposits-only rule.
Three failure modes fixed in `BankPaymentsModal` + `bankingSortingConfig`:

- **Stale-response guard**: `refreshList` now carries a monotonic request id and
  discards responses that are no longer the newest request. Before, the cold-cache
  unfiltered query (slow, ~1000 rows) started first, finished last, and overwrote
  the correctly filtered list a few seconds after open (reproduced live).
- **Cold-cache gating**: the first list fetch is held (`sortingConfigResolved`,
  skeleton shown via `listBusy`) until the `app_settings` config read resolves, so
  the modal never issues the unfiltered default query at all on a fresh browser.
- **Error vs missing row**: `fetchBankPaymentsSortingConfigFromAppSettings` returns
  `outcome: 'row' | 'no-row' | 'error'` instead of a conflated `rowExists`. The new
  pure kernel `resolveSortingConfigAfterFetch` (unit-tested) only allows the
  legacy-local migrate-upsert on a confirmed `no-row`. Before, a transient read
  failure on any dev browser upserted the local default over the org-wide filter —
  **this actually happened during the investigation** (2026-09-01, console 401s from
  a dev-login session): the prod row was found reset to `kinds: []` / start today−90.
  The healthy value was captured beforehand: kinds `checkDeposit, incomingDomesticWire,
  other`; accounts Taunya `63fb1084…` + Recivables `f4c77adc…`; start `2026-04-01`;
  exclude counterparty `Housecall`, `sixth`. Restore via AR → Dev: Mercury filter →
  Edit sorting configuration.

No schema/RPC changes. `resolveBankPaymentsSortingConfigForAr` (Dashboard/Quickfill
count, Moneyfill week close) keeps its behavior: org row when read, else legacy local.
