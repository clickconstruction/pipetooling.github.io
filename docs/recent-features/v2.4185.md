# v2.4185 — Deploys unblocked: the contract window's Edit & re-send test settles before it clicks (2026-09-29)

Two Pages deploys (main `801bf95fe`, `9f77e4bbb`) failed on one test: `JobContractModal.reopen.render.test.tsx › arms with what the customer may be holding, then unlocks the agreement in place` — *Unable to find an element by: [data-testid="contract-reopen-note"]*. On main it fails about one run in six, on both sides of the commits those deploys carried (bisected: it fails at `4e0adeb4a` too), so it is a flake, not a regression.

**Mechanism** (instrumented): the test held the node `findByTestId('contract-edit-resend')` returned and clicked it; at the click the node was **detached** (`document.body.contains(btn) === false`) while a fresh *Edit & re-send* button was on the page. The open's loads (`loadRows` → the sent-event channel → the templates) land in more than one render, and a render right after the button first appears can replace its node; a click on the old node reaches no handler, so the arm never happens and the note never renders. Waiting for the note (`findBy`) does not help — the click was lost, not late.

**Fix** (test only): `await settle()` after the button first appears, then click `screen.getByTestId('contract-edit-resend')` — the node on the page now. 15/15 runs pass (was ~5/6). The component is unchanged; which render replaces the node is not pinned down, and a follow-up could make the sent panel's button stable across the open's loads.
