# v2.6887 — A check that keeps the blank page from coming back (2026-11-10)

v2.6868 and v2.6876 each wrapped `lazy()` routes outside the Layout in `<Suspense fallback={null}>`, and v2.6876 closed with *No test holds this*. This is that test. The audit and the walks that found the routes are in `v2.6876.md`. No screen changes, and `src/App.tsx` and `main.tsx` are untouched.

## The rule it holds

In `src/App.tsx`, a route between `<Routes>` and the Layout route (`path="/"`) whose `element` draws a name declared `const X = lazy(` carries a `<Suspense>` around that name inside the same `element`. The Layout wraps its `<Outlet>` in one, so the routes nested in it are not read. `main.tsx` keeps `v7_startTransition: false`, so the answer is a boundary, never a transition.

## What changed

- **`src/lib/lazyRouteBoundaries.ts`** (pure, takes the source text):
  - `lazyComponentNames(source)`: the names declared with `lazy(` or `React.lazy(`.
  - `routesOutsideLayout(source)`: each `<Route>` above the Layout route as `{ path, element }`, the `element` read by matching its braces. It stops at the route whose path is `/`.
  - `lazyRoutesWithoutSuspense(source)`: the paths at fault, in the file's order. A route is at fault when a lazy name in its element has no open `<Suspense>` before it, so a `<Suspense>` that sits beside the page and not around it does not pass.
  - `lazyRouteWithoutSuspenseWords(path)`: the failure's words, which name the route and say to wrap the page in `<Suspense fallback={null}>` as `/t/:token` is.
  - Comments are removed before anything is read, so a comment that mentions `<Suspense>` or a lazy name counts for nothing. Words in quotes are skipped, so `to="/Jobs"` is not the page.
- **`src/lib/lazyRouteBoundaries.test.ts`**: the kernel on made-up snippets (a bare lazy route, a wrapped one, one wrapped inside `ProtectedRoute`, one that `ProtectedRoute` alone wraps, a plain import, a `<Suspense>` beside the page, a comment, a quoted path, the Layout's own routes), then two tests on the real `src/App.tsx`. The first expects the parser to find `GcTradePortal` and `Jobs` among the lazy names, `/sign-in` and `/t/:token` among the routes, and neither `/` nor `dashboard`, because a parser that found nothing would pass the second without checking anything. The second expects no route at fault.

- **`docs/APP_SHELL_ARCHITECTURE.md`**: the sentence that said the staff preview mounts outside the Layout's boundary and only cold-loads now names the five lazy pages outside it, their own `<Suspense>` and this test.

## Tried

- On main before v2.6876 the real-file test failed and named `/estimate/customer-accept-preview/:id`, the route that PR wraps.
- With v2.6876 in, it passes. Taking the `<Suspense>` off `/t/:token` locally made it fail with that path in the message; the wrap was put back.

## Not covered

- A nested route outside the Layout whose parent holds the `<Suspense>` around an `<Outlet>` would be named, since the check reads each route's own element. There is none today; such a route would carry its own boundary or the kernel would learn the parent's.
- A lazy page declared in another file and imported into `src/App.tsx` is not seen as lazy. Every lazy page is declared in `src/App.tsx` today.
