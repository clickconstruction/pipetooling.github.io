## Applied — the bulk clone (2026-09-03, owner call: "make it durable")

The display fallback above was not enough on its own: `bid_pricing_assignments` / `bid_count_row_custom_prices` reference `price_book_versions` (and entries) **ON DELETE CASCADE**, so deleting a template would silently wipe every legacy bid's pricing, and template edits floated legacy revenue (BP190 sent at $40,560.05, priced $37,780.59 today). [`scripts/backfill-legacy-template-pricing.sql`](../../scripts/backfill-legacy-template-pricing.sql) ran the existing `clone_price_book_version_to_bid` RPC for every (unsplit bid with no copy × shared non-robot template it references), pointed each bid at the copy of its majority template, and un-offered the secondary copies on the 13 bids keyed to two or three templates (v2.2392 would otherwise list them as letter alternates). Dry run with ROLLBACK first (counts matched), then COMMIT via psql through the session pooler with `request.jwt.claims` set to the dev user so the RPC's `auth.uid()` check passes.

- 188 bids · 202 copies · 20,802 entries · 1,899 assignments + 2,768 custom prices carried · 0 mismatches · every candidate bid now owns a copy and points at it. Template rows were left in place (additive).
- Skipped: 17 twin/shadow bids on `🤖 Robot Default` (`is_robot` — the robot write fence keys on the robot-flagged parent version) and the 33 bids that already owned copies.
- Verified in the app on live data: BP190 opens on its own **★ Default** copy ($37,781, 6/6, letter $37,780.59 "from Pricing · Default"); BP73 (three templates) shows Default on the letter with Trace / RSmeans as "Only you see this"; BP398 unchanged.
