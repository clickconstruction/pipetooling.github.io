# v2.2720 — Legacy template-keyed bids open on their own book (2026-09-03)

Wendi: BP190 (Church Video Cafe Reno, won, $40,560) opened on Pricing as "$0 · assign…" on every row. Investigation (read-only via the app's session): the bid holds 11 `bid_pricing_assignments` + 15 `bid_count_row_custom_prices` rows — all keyed to the shared **Default** template (`bid_id IS NULL`), the pre-frozen-copy pattern; it owns no pricing copy and `selected_price_book_version_id` is null. `deriveActivePricingId` then fell through to `pickDefaultTemplatePricingId()` = the viewer's last-picked book (v2 of the dropdown, 2026-06-18) — WENDI for Wendi — so the engine loaded WENDI's rows for the bid and found none. 206 bids in prod are in this state (template-keyed rows, no copy; sent through 2026-06-30; 16 won / 51 lost), 33 more are mixed. Nothing in the deletion archive; the Old-view retirement (v2.2707) did not cause it — the Workbench drawer's **Use ‹book› on this bid** was, and still is, the manual door.

## Client only — no migration, no data written

- New kernel [`legacyTemplatePricing.ts`](../../src/lib/bids/legacyTemplatePricing.ts) (`pickLegacyDataTemplateId`, 6 tests): given the `price_book_version_id` of every assignment / custom-price row on the bid, the service type's templates, and the bid's own copies, returns the template holding the most rows (ties → template display order; own copies and deleted ids never answer).
- [`pickActiveVersion.ts`](../../src/lib/bids/pickActiveVersion.ts): `deriveActivePricingId` gains `legacyDataPricingId`, consulted for an unsplit bid **after** the saved pointer and **before** the viewer's default (`… ?? legacyFallbackPricingId ?? legacyDataPricingId ?? defaultTemplatePricingId`). Split versions are unchanged (no template fallback there). +1 test block.
- [`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts): `loadLegacyPricingRefs(bidId)` (two id-only selects, non-fatal) runs in the bid-changed resolve only when the bid has no versions and no copies; its result feeds the resolve's derive, `switchActiveVersion`, and the templates-arrived safety net (state `legacyPricingRefs`, keyed by bid id, added to that effect's deps so the fix survives the resolve-before-templates race).
- Not changed on purpose: `defaultPriceBookTemplateId` (the "your default for new bids" chip and `BidVersionPicker`'s clone source) still follows the viewer's last pick — this fix is about *showing* legacy prices, not about which book new work starts from.
