# v2.2055 — Checklist scheduling overhaul 1/4: materialization kernel + unique index (2026-08-22)

Phase 1 of the four-PR plan from the "Checklist Item Anatomy" investigation
(owner: "build it all"). Groundwork — no visible behavior change except one
bug fix.

- **Kernel** `src/lib/checklistMaterialize.ts` (+10 tests):
  - `materializeDates(cfg, windowStart, windowEnd)` — the ONE place deciding
    which dates an item has occurrences on. String-YMD math (`dowOfYmd` uses
    a noon anchor) — **fixes the UTC-anchor bug** where a weekly item whose
    chosen weekday was adjacent to its start date materialized its first
    occurrence a day *before* the chosen start (born overdue).
  - `planEditRegeneration(cfg, instances, today)` — pure decision function
    for phase 3 (what edits delete/create/move): past + completed + discussed
    occurrences never move; one-offs move their open occurrence (notes
    preserved); in-flight after-completion chains untouched; weeklies
    reconcile the future window. `MATERIALIZE_HORIZON_DAYS = 35`.
- **Migration** `20260822004547_checklist_instances_unique_item_date.sql`:
  defensive dedupe + unique index on `(checklist_item_id, scheduled_date)`
  (see `docs/migrations/` fragment). Prod pre-verified duplicate-free.
- **Add modal** switched to the kernel + `upsert(onConflict)` — same 104-week
  span for now (phase 2 shrinks it to the rolling horizon).

Next: phase 2 (rolling 5-week horizon + cron top-up + far-future cleanup),
phase 3 (edits regenerate the future), phase 4 (modal redesign).
