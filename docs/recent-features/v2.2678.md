# v2.2678 — Review tab ranked view: verdict, hygiene, ranked bars, math drawer (2026-09-03)

First slice of the People → Review refresh (owner picked variant C, "Ranked bars + math drawer", from the three-way mock-up artifact after the 2026-09-03 review + math audit). The table stays; the tab now opens on a view that says what the period means before it lists the columns. Nothing in the allocation math changed — every number in the new view is read off the same enriched `TeamSummaryBreakdown[]` rows the table renders, so the two views cannot disagree.

## Client only — no migration

- **Kernel** [`lib/people/reviewRanked.ts`](../../src/lib/people/reviewRanked.ts) (+13 tests):
  - `classifyReviewPerson` → `field` / `office` (overhead hours exceed field hours) / `none` (no time, no money).
  - `priorPeriodRange` + `inclusiveDayCount` → the same-length window immediately before the period.
  - `compareProfit` → up / down / flat with a ±5% flat band (the Overhead pool-trend rule); null delta when the prior period has nothing to compare.
  - `buildReviewVerdict` → team gross / net / overhead labor / burden / profit, the field / office / no-time groups, the gross→profit composition segments, and the trend.
  - `buildReviewRankedBars` → bars scaled to the widest value with a shared zero line (losses grow left), rank by profit / profit-per-hour / gross / net, name search, nulls last.
  - `buildReviewPersonMath` → the formula chain (gross → − parts, subs & team labor → net → − own office/bid wages → − parts burden → profit → ÷ hours with the assumed/clocked basis), data-derived levers (assumed-% jobs and the gross riding on them, no-bill jobs, one-job concentration ≥ 40%, worst job, unaccounted hours, zero-hour crew rows) and the watch-outs (today's % complete restates history; salaried hours assumed; only own overhead wages charged; office rows negative by construction).
  - `buildReviewHygiene` → pending approvals (via the v2.2671 count RPC), distinct no-bill jobs, distinct assumed-% jobs, salaried-assumption count. Click-only jobs label by name, not "Unknown".
- **Components** in [`components/people/review/`](../../src/components/people/review/): `PeopleReviewVerdictStrip` (lead KPI + trend pill + composition bar/legend), `PeopleReviewHygieneStrip` (Overhead's amber maintenance grammar), `PeopleReviewRankedList` (rank-by select, search, the bars; names are `aria-pressed` buttons driving the existing selection pointer), `PeopleReviewMathDrawer` (opened at rest with a prompt; formula grid + levers + watch-outs for the selected person).
- **Tab wiring** ([`PeopleReviewTab.tsx`](../../src/components/people/PeopleReviewTab.tsx)): `reviewView` (`ranked` default | `table`) persisted via [`lib/people/reviewViewStorage.ts`](../../src/lib/people/reviewViewStorage.ts); a Ranked / Table segmented control under the period controls; in ranked mode the table mount renders the verdict strip → hygiene strip → ranked list + drawer grid instead of `TeamSummaryInline`, the "Overhead (split)" meta line loses its drilldown click (the drilldown lives in the table), and the person panel's headline card is skipped (the drawer replaces it — Jobs Worked / Hours and Pay / Reports / Tasks still render below).
- **Prior period**: a new effect keyed on the current rows' identity loads the prior window through the same `loadTeamReviewUnion` + `derivePersonTeamSummary` path (request-id guarded, ranked view only) and enriches it with the same 90-day parts rate; the main load's refresh-deferral choreography is untouched.
- Verified live as dev on prod data: verdict $35,892 (7 field · 6 office & bids · 3 no time), composition 54 / 5 / 4 / 37%, drawer chain reconciles for Malachi ($49,063 − $25,737 = $23,326; − $604 − $828 = $21,894; ÷ 176 assumed h = $124/hr).
