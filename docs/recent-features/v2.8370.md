# v2.8370 — Dashboard: a bid you hide on My Bids is hidden on every device (2026-11-23)

Step 6 of punch list #426, the client half. The owner's pick of 2026-11-23: *Hidden follows you*. It reads and writes `user_bid_notes_read_state.hidden_at`, added by v2.8369 (`20261123160430_my_bids_hidden_at.sql`). No migration of its own, no edge function.

## What was there

`DashboardMyBidsSection` kept the hidden ids in one browser's localStorage, under `dashboard_my_bids_hidden_<user>`, and wrote the whole set there on every hide and every Show again. A bid hidden on the phone was back on the desk.

## What changed

- **The hide is the person's own row.** **Hide**, by swipe or by word press, upserts `{ user_id, bid_id, hidden_at, updated_at }` into `user_bid_notes_read_state`. **Show again**, and **Undo** after a hide, upsert `hidden_at: null`. The write names no read mark, so **Mark read** and a hide never touch each other.
- **The card reads it with the read marks.** The loader already read the person's rows with `select('*')`. The hidden set is now the rows with `hidden_at` set (`myBidsHiddenInReadState`), joined with whatever the browser kept by itself.
- **One move, once.** The ids the browser kept for bids on the card move into the person's rows the first time the card loads (`myBidsLocalIdsToMove`), and leave the browser when the write lands. An id for a bid the read did not bring stays in the browser. A refused move stays put and is tried again on the next load.
- **A refused hide stays on the device.** The bid stays hidden in this browser, and a toast says *Hidden on this device only:* with the reason (`formatErrorMessage`). A read-only account in training mode sees this, since its writes are refused.
- **View as writes nothing.** While View as is on, a hide is this browser's alone, as **Mark read** is held there too.
- **One bid's writes run in turn.** Each bid's hides and shows wait for the one before, so an **Undo** pressed at once lands after the hide it undoes.
- **Show again writes only what the row holds.** A bid this browser kept by itself just leaves the browser, so a training account can always show its bids again.

## The window before the push

The client works if it lands before the column. The read finds no `hidden_at` and reads the browser as before. A hide is refused and stays on the device with its toast. The move is refused quietly and waits. The PR is armed only after the push, so this window is not expected on prod.
