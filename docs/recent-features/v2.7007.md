# v2.7007 — First look: the customer's page is an entry of its own (2026-11-12)

Punch list #319, PR 4. The spike measured the page at 2,465 KB over the wire on a first visit, 12 files, nearly all of it the app's shell, which a customer never uses. A caller on a weak signal waited on all of it before the first word.

- **`show.html` over `src/showEntry.tsx`**, a second input of the build (`build.rollupOptions.input` in `vite.config.ts`). It holds React and the page and nothing else of the app: no router, no sign-in, no service worker. Built, it is three scripts, **181 KB raw and about 60 KB over the wire**, and the photo shrinker's 5 KB worker when a photo is picked.
- **The link is the same.** `index.html`'s first script, before anything else in the head, sends `/show/<ten letters>` to `/show.html#<code>` with `location.replace`. GitHub Pages serves `404.html`, a copy of `index.html`, for that address, so the script runs there too and the app is never asked for.
- **`ShowUs` reads no router** now. It takes the code as a prop; `ShowUsRoute.tsx` is the app's own `/show/:code` route over it, for the smokes and for a browser the redirect does not reach.
- **The service worker** leaves `/show.html` to the network (`src/sw.ts`'s denylist), as it does the other real pages, so a signed-in browser is not handed the app's shell for it.
- `showEntry.test.ts` holds the four files together, since none of them is code a unit test runs.

Walked on a build served the way GitHub Pages serves it (a stand-in that answers `404.html` for a path that is not a file): `/show/<code>` landed on `/show.html#<code>`, the page drew with no service worker, and the three scripts and the function's read were all it asked for.
