# v2.4417 — Pricing: a slim Add price button, so the one-price line is shorter (2026-10-02)

No migration, no edge function. Owner feedback on Bids → Pricing: the **＋ Add price** button was taller than the line it sits on and set the height of the whole bordered band. Three mock-ups were drawn (a slim button, a quiet link with no box, the band folded into the figures strip); the owner picked the slim button.

## What shipped

- [`PricingCardsRow`](../../src/components/bids/PricingCardsRow.tsx): `AddPriceDoorButton` takes `slim`, a small pill (`0.76rem`, padding `0.14rem 0.6rem`, fully rounded). The solo band passes it and its own padding drops from `0.5rem 0.9rem` to `0.25rem 0.9rem`. Measured live on BP403: the band is 35px tall where it was about 52px, and the button 25px.
- The button at the solver line's end (a solo bid with no prices yet) and the stacked one beside the price cards keep their full size: there the button does not set the height.

## Tests

- [`PricingCardsRow.render.test.tsx`](../../src/components/bids/PricingCardsRow.render.test.tsx): the solo band's door is the slim pill and the band has thin padding; the default and stacked buttons keep their padding.
- Live, headless on BP403: the band's height, the door opens and cancels, the phone layout wraps cleanly, no console errors.
