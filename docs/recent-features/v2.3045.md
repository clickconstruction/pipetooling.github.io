# v2.3045 — Test-gap audit, pass 42: the Jobs → Team week loader gets its first tests (2026-09-07)

Pass 42 of the test-gap audit, renumbered from v2.3032 after a version race. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`fetchTeamBoardWeek.ts` is everything **Jobs → Team** needs for one week in four reads — live closed clock sessions (approved and pending), dispatch blocks, sub sheets dated in the week, and the pay flags — plus the office-job setting and the soft acknowledgement read, mapped into the pure board kernel's shapes with labels resolved here so the kernel stays pure. The kernel (`teamBoard.ts`) was tested; the loader was not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Sessions are bounded to the week, unrejected, unrevoked and closed, ordered by clock-in and capped at 3,000; blocks are bounded and capped the same way; sub sheets by job date, capped at 500; acknowledgements by work date, capped at 2,000.
- Labels resolve once per target with the first embed seen winning (a session's job embed is not overwritten by a block's copy), using the org's ledger prefixes; a sub sheet links to a job by its trimmed HCP number when a session or block this week carried that job, else stays unlinked; undated sheets are dropped.
- Person names and pay-flag names are trimmed; a null salary flag reads as false; the ack map is keyed by `kind|date|person|target`.
- A missing acknowledgements table (before the migration push) or a failed office-job read is soft: no acks, no office job, everything else intact. A failed core read throws; null results read as empty.
