# v2.6922 — Bid Board: set or change a bid's links in its Files window (punch list #306, PR 7) (2026-11-10)

The card's PR 7. PR 5 (v2.6914) gave the Bid Board a grey icon for every missing link and one Files window, where a row with nothing sent the person to Edit bid. The window now sets the link itself. No migration and no edge function change.

## What changed

- **A box under the row** (`BidFilesModal.tsx`). A row the bid does not have offers **Set the link**; a row it has offers **Change** beside **Open ↗**. Either opens a box under the row with the link's label, a **Paste** press and **Save the link**. A grey icon on the board opens the window with that row's box already open and the cursor in it.
- **The pasted link's rules** (`linkDraft`, `src/lib/bids/bidFilesWindow.ts`, tested): the press is dead while the box is empty, while it holds something that is not a link (*A link starts with https:// and has no spaces.*) and while it holds the link the bid has now. A project folder that is not a Google Drive folder saves, with a line that the bid's photos cannot be filed there (`isDriveFolderLink`).
- **The writes** (`src/lib/bids/bidFilesIo.ts`): one column of `bids`, the one the bid's form writes (`drive_link`, `count_tooling_plans_link`, `bid_submission_link`), with the refused-update guard, so a write that applies to no row is said as a refusal and the box stays with its reason.
- **Make the project folder**, in the project folder's box on a bid with none: the `bid-photos` function's `make`, which names the folder by the office's bid pattern, makes it in the shared Drive with Team only › Photos inside and writes the bid's link. The toast names the folder made.
- **Add a set** on the Plans row opens the form's own plan sets field (`BidPlanSetsField`) under the row. The field took a `host` prop: in the window its words name the robot's set by its chip, since there is no Plans link field above it. **Robot reads this set** there writes `bids.plans_link`.
- **Open Edit bid**, a quiet press at the foot of each box, is the door to the whole form, landed on that row's field. It is where a link is cleared and a second CountTooling project is added.
- **The board reads again after a change**: `useBidBoardScope` hands out `refreshBidFiles`, which re-runs the plan sets and CountTooling sources reads, and the page reloads the bids. The window draws its rows from the page's own row for the bid, so a saved link turns its row and its icon blue at once.
- **A training account** reads the rows and is offered no change, with the reason in a line.
- The guides `see-what-files-a-bid-has` and `keep-more-than-one-set-of-plans-on-a-bid`; `docs/BIDS_SYSTEM.md`, `docs/GLOSSARY.md`, `docs/EDGE_FUNCTIONS.md`.

## What it did not change

- The window does not clear a link. Edit bid does.
- The CountTooling box sets the bid's own link. The list of CountTooling projects behind the counts stays in Edit bid.
- A blue icon on the board still goes straight out.
