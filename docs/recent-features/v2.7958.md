# v2.7958 — Robots: an assistant can ask the pricing robot to price a bid (2026-11-19)

A new pair on `dev-mcp` (server 0.114.0, 141 write verbs, 88 naming no RPC, 192 tools): **`plan_price_matrix_request`** → **`apply_price_matrix_request`**. The owner, 2026-11-19: "Yes, please build all the gaps".

## Why

The audit of what an agent can stand up alone listed it as the seventh gap. The pricing robot works its queue through the twin seat. Putting a bid on that queue was a person's press, *Price it with the robot* on Bids → Pricing.

## What it does

- `request = { bid_id }` queues the bid with every readable quote link ticked, as the window opens.
- `request = { bid_id, sources: [rfq_id] }` ticks fewer.
- `request = { bid_id, take_back: true }` takes the open ask back while it is still queued.

## A request is a snapshot

The caller gives neither the rows nor the links. The plan reads them off the bid, as the dev.

- The rows are the counted fixture rows of the pricing the tab opens on, by name and count.
- The links are the quote links on the bid's Price requests. A request's `quote_url` wins over its `request_url`. Closed and draft requests drop out.
- A house asked with nothing linked yet is listed as skipped. The robot never invents a quote.

The rules are the window's own. `buildPriceMatrixScope`, `buildPriceMatrixSources`, `activePriceMatrixRequest` and `canTakeBack` moved from `src/lib/rfq/priceMatrixRequest.ts` to `supabase/functions/_shared/priceMatrixAsk.ts`. The client file re-exports them. The window did not change.

## What the plan says

- The rows, the links ticked and not ticked, and the skipped houses.
- The pricing it read the rows from.
- Whether a pricing robot holds a live key. With none, the ask would wait in the queue, and the plan names the call that mints one.

## Refused in words

No such bid. An ask already open on the bid. No counted rows. No readable link. A source the bid does not offer. Nothing to take back, or an ask the robot has started.

## The write

One row on `bid_price_matrix_requests`, as the dev under the table's own RLS. It is the row the window inserts, with the open pricing's id in `bid_version_id` as the window writes it. Take back sets `status` to `cancelled`, held to an ask still queued.

Nothing else is written: no email, no cost, no change to the bid.
