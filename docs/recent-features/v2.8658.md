## What was wrong

The *Out the door* card's press read *Enter mail numbers · 4* and opened a window titled *Print and mail · 14 notices*. The press was a plain open of the whole run, which holds every approved notice, and the window titles itself *Enter mail numbers* only when every notice it holds is printed (`runOpening`, `src/lib/jobs/lienDeskRun.ts`). So while one approved notice still waited to print, or was held, the title and the count were the whole run's and not the card's. The number boxes were on the rows either way: nothing was lost but the words. v2.8634's note said the press *opens it on recording*, which was true only once nothing waited to print.

## What it does

- **The press hands the desk the card's own notices** (`onRecordMailing(lines)`, `LienGetItRight.tsx`), and the desk opens the run window on those jobs' notices alone (`openRunOnMail`, `LienDesk.tsx`).
- **`lienRunMailEntriesFor`** (`src/lib/jobs/lienNextUp.ts`) picks them: the notices of the jobs the card counts, read from both piles as *Just this one* reads them, so a notice taken back inside the open window is still found.
- Every one of them is printed, so the window opens on recording, titled *Enter mail numbers · N notices* with the press's N. No retainage notice still to print rides in.
- The Board's presses, the title bar's door, a To do row and the calendar open the whole run as before.
