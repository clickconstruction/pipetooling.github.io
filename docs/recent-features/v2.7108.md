# v2.7108 — One text, many views: when each section of an HR document last changed (2026-11-12)

Punch list #315, upgrade 5a. No migration, no function, no seat change.

## What was wrong

A summary or a narrative is rewritten a section at a time. The document's date said only that something in it moved. A reader of one section could not tell whether that section was written before or after the entries that bear on it.

## What changed

- **The fold** (`PersonFilePanel.tsx` → `renderDocFreshness`): under the summary's and the narrative's facts, *When each section last changed*. Opened, it lists every section with the day it took its present words and how many entries were written since. The count is amber when one of those entries cites the section (`N§2`).
- **Read on demand** (`sectionFreshnessIo.ts`): the prior versions are whole texts, so nothing is fetched until the fold is opened, and then the newest twelve. A read that fails says why and takes only the fold out.
- **Kernel** `supabase/functions/_shared/sectionFreshness.ts` (door `src/lib/people/sectionFreshness.ts`, 8 tests): the sections of a text, the walk back through the versions, the words. A section changed at the moment the newest version that reads differently was replaced. Spacing alone is not a change. A section that reads the same in every version read says *not changed since before* the oldest of them, and its count says *at least*.
- **Help**: `keep-private-employee-files` gains *See when a section last changed*.

## Access

`person_file_revisions` is a dev's alone by its RLS, as before. The fold is drawn for a dev only. Nothing new is readable by anyone.

## Is this the best we can do?

The card drew a chip on every section. A chip on every heading means reading every prior version each time a file opens, and a long narrative has many versions of hundreds of kilobytes each. A fold that reads when pressed gives the same answer for no cost to every other visit, so that is what was built. The limit: it reads the newest twelve versions, so a section older than those says *before* a day, not the day.

Not in this PR: the seat's `get_person_document` does not carry the freshness yet (the kernel is shared so it can), and a named document has no fold.
