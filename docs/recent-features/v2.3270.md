Edge functions `twin-mcp` (v1.4.0) and `plan-fetch` — **deploy both after this merges** (`supabase functions deploy twin-mcp` / `plan-fetch`; nothing runs until then). Needs v2.3263's migration pushed (it is). Plan: [`docs/PRICE_MATRIX_PLAN.md`](../PRICE_MATRIX_PLAN.md); canvas boards 6, 7.

## Why

PR 2 gave Wendi the button; this PR gives it something to talk to. A **second twin that never bids** — `twin-pricer-1` — so reading a live bid's fixture list can never contaminate a shadow, with its own key and its own kickoff, refused every bid verb by its kind.

## What shipped

- **A twin kind.** `resolveTwin` reads `users.twin_kind`; `callTool` gates before the switch. A pricer key gets a plain-words refusal on `next_shadow`, `open_backtest`, `paste_counts`, `lock_shadow` and every other bid verb; a bid robot gets the same on the pricer's. `heartbeat`, `add_bid_note` (now admitting a pricer on a bid whose request it holds), `ask_question`, `get_answers`, `submit_report` and the doc verbs serve both.
- **Seven verbs** ([`twin-mcp/index.ts`](../../supabase/functions/twin-mcp/index.ts), documented in [`EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md) → twin-mcp): `get_pricing_guide` · `get_component_rules` · `next_price_matrix` (the dispatcher — a conditional `UPDATE … WHERE status = 'queued'` is the claim, so two pricers never share a request; a request already held comes back first) · `get_quote_documents` (lists every source's files, or stages the named pages of one as single-page PDFs, like `get_plan_pages`) · `put_quote` (one house's structured quote onto the bid — kit subtotals, component roles, option groups, page refs — validated against the request snapshot; idempotent per house with `replace: true`) · `finish_price_matrix` (robot picks with reasons, estimator-lane asks, the `result` the chip reads, the request flips `ready` or `blocked`) · `extend_component_rules`.
- **plan-fetch learns quote links** ([`plan-fetch/index.ts`](../../supabase/functions/plan-fetch/index.ts)): `?request=<uuid>&source=<n>[&part=<m>][&list=1]` reads the n-th link on a request with the plan set's Drive plumbing (folders merged, parts streamed, 60 MB cap). A twin may read only a request it claimed; staff may read any.
- **The brief** [`docs/twins/pricer.md`](../twins/pricer.md) (how a fixture quote is written and how to write it back — kits by subtotal, carriers on a second sheet, size lists never summed, printed totals never job totals) rides the bundle as `PRICING_GUIDE` ([`build-twin-mcp-briefs.mjs`](../../scripts/build-twin-mcp-briefs.mjs)). **The kickoff** [`docs/twins/kickoffs/pricing-operator.md`](../twins/kickoffs/pricing-operator.md) mirrors the Desktop kickoff: setup once, then the loop (`next_price_matrix` → read → `put_quote` → `finish_price_matrix`), the owner's hard rules, three requests per chat.
- **The seat.** Settings → Digital twins → **Mint pricing twin** creates `twin-pricer-<n>@twins.pipetooling.local` (role estimator for the quote store's RLS, `twin_kind = 'pricer'`, no CountTooling or TakeoffTooling seats) and the fleet row wears *pricer · quotes only, no bids*. [`nextTwinSeat`](../../src/lib/twinConsoleDisplay.ts) numbers each kind separately.
- **The Console** ([`BidsRobotConsoleTab`](../../src/components/bids/BidsRobotConsoleTab.tsx)) gains the third *Pricing robot · never bids* column: Copy setup command, **Copy pricing kickoff**, preview.
- Tests: seat numbering per kind; the pricing kickoff carries the connector placeholder, names every loop verb and the hard rules.
