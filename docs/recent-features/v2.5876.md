# v2.5876 — Ask the customer how we did, answered with one tap (2026-10-26)

Item 6 of the measuring follow-ups (the Zendesk/Intercom comparison of 2026-10-26): both tools anchor on a rating the customer gives after the conversation; the app had none. This PR is the plumbing — the table, the mint, the public page and its function. The `{rate}` fill that puts the link in the reply box and the strip's tile are the next two PRs.

## The pieces

- **`customer_ratings`** (`20261026100000`): one row per ask — contact, job, the customer's name, a plaintext `public_token` (the `job_contracts.public_token` pattern), who asked and when, and the customer's `score` (1–5), `words` and `answered_at`. Office reads by RLS (`gc_office_team()`); no client writes.
- **`mint_customer_rating(contact, job, name)`**: SECURITY DEFINER, office only; returns the token, reusing a fresh unanswered ask to the same contact about the same job so a re-send never forks the asked count.
- **`job-rating`** (new function, `verify_jwt = false`): GET by token answers the page's state (first name, score, words, answered); POST saves the tap — `answered_at` keeps the first answer's time, a later tap may change the score. Service role; the token is the capability.
- **`/rate`** (`CustomerRating.tsx` over `lib/ratings/rating.ts`): *Dana, how did we do?* with five faces, Bad to Great, each a one-tap save; a 1 or a 2 is thanked with the honest line; the optional words box sends separately. Customer-facing, so the page stays light.

## Tests

`rating.test.ts` (tokens, scores, the state parse, plain words on every line); `CustomerRating.render.test.tsx` (the ask by name, a tap's POST body, the words send, the low-score thanks, an answered ask shown answered, a bad link refused with no fetch).

## Deploy

`supabase db push` (the migration), then `supabase functions deploy job-rating`. The client deploy carries the page.

## Verify

Mint a row as the dev (`select mint_customer_rating('<a contact id>', null, 'ZZ Test')`), open `/rate?t=<token>` signed out: one tap on a face saves and thanks, the words send, and the row carries both. A second tap changes the score and keeps `answered_at`.
