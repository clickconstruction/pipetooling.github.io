# v2.6822 — The dev seat leaves a note where the team reads it: plan_activity_note (2026-11-09)

The owner, 2026-11-09, on the submittal verbs (v2.6804): an agent that loads submittal entries should be able to *"let others know their status"*. v2.6804 reads status back in the conversation; this pair leaves the word in the app, where the team reads it. She chose it as its own verb once v2.6804 was live. No migration.

## What changed

- **`plan_activity_note` → `apply_activity_note`** on `dev-mcp` (server 0.54.0, numbered behind v2.6793's 0.53.0, which merged first; writes are sixty-seven verbs): `note = { job | bid, text, on?, gc_customer_id? }`. A **job** note is the row the Pipeline's Note press writes — `jobs_ledger_thread_notes`, the dev as `author_user_id` — and shows in the row's Job activity / notes, the job window's Activity, and the customer's Hub and Timeline. A **bid** note is the row the Bid Board's Notes popover writes — `bids_submission_entries` with `notes`, no `contact_method` (so the sync trigger leaves `bids.last_contact` alone), `occurred_at` now or noon of the day given — the bid's own note, or about one GC on the bid (`gc_customer_id`), which the GC line's popover scopes to and the feed tags with their name.
- **No RPC**: both tables take the app's own inserts under RLS, so the seat writes the same rows as the dev (`restRows`). The dry run (`_shared/devMcpActivityNote.ts`: `readActivityNoteWorld` → `activityNoteDryRun`) is the server's read of the job or the bid and its latest three lines, hashed with the payload, so a line landed since the plan asks for a new plan; `on` ahead of today is refused; `gc_customer_id` on a job note is refused in the shape check. The plan says where the line shows (`lands`), who it is by, and what it does not do.
- **It tells nobody**: no email, text or push. The customer's thread stays the job window's Note · Text · Email; a call or email against a GC stays the Bid Board's Log contact; a development's History stays `plan_history_entry`.
- Docs: the seat's README row and counts, `EDGE_FUNCTIONS.md`'s dev-mcp block, the submittal guide's *Load rows with your agent* section.
