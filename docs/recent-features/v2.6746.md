# v2.6746 — A trade partner sees its files on a job, and can send Click a file with one line (punch list #205, PR 4) (2026-11-08)

Punch list #205 (`to-dos/trade-portal-vs-jobtread.md`), row 3, the owner's mark of 2026-11-08: the files list, with the free press. PR 4 of six, stacked on PR 3 (v2.6744). One migration, the slice, a write kind and the page.

## What changed

- **Migration `20261109011500_gc_trade_files_note`**: widens `gc_trade_files_purpose_known` to add `'note'`, the P5b migration's way (drop, add `NOT VALID`, validate). Nothing else. Page: `docs/migrations/20261109011500_gc_trade_files_note.md`.
- **The slice**: `files` on `TradePortalRows` and `TradePortalSlice`, read by `company_id` (newest 200) and held to the company and its projects; `TRADE_PORTAL_FIELDS.files` is `id, project_id, purpose, paper, name, drive_url, uploaded_at, made_by`. Never `drive_file_id`, `record_id`, `bytes` or `mime` (the slice test's never list names them).
- **`_shared/gcTradeFile.ts`**: `TRADE_FILE_FOR` gains `'note'`; `RECORD_FIELD.note = 'projectId'`; `parseTradeFile` reads `note` (1 to 200 characters, required, `TRADE_FILE_NOTE_MAX`) and names the file `${cleanFileName(note)}${ext}` with the pick's extension kept, so the note is the Drive name after the minute. `tradeFileFolders` already puts a non-submittal under Team only → From trades → the company.
- **`submit-gc-trade-portal`** `fileHome` for `'note'`: the project is past bidding with a trade awarded to the company through its own invite and a signed statement of work, else `notAwarded`. The row's `purpose` is `note`; no kind follows it. `freeTextCounts` stays; the file cap of 20 an hour covers it.
- **`src/lib/gc/tradePortalPage.ts`**: `tradeFilesByProject(slice)` → `PortalFileRow[]` by job (`what`, `paper`, `name`, `url`, `day`), newest first, an https link required.
- **`GcTradePortalFiles.tsx`** (new): **Your files on this job** under `GcTradePortalSow` on a signed job: a table of the company's rows (the name, what it is — *submittal*, *change you asked for*, *your quote*, *waiver you signed*, *a file you sent* — the day, **Open ↗**) and the plan sets we sent with a Drive link (*Plans Addendum 1 from Click*); then **Send Click a file**: `PortalFilePick`, one `<input>` *What is it? One line.*, **Send** live once both are there → `press.upload({ for: 'note', projectId, name, base64, note })`; the answer's file joins the top of the list as *a file you sent*, and *Sent. The office has it.* says so; nothing is read again. A refusal shows under the control in the company's words and keeps the line typed. The page hands `files` down (`GcTradePortal.tsx` → `GcTradePortalView` → `GcTradePortalProject`). The waiver's form label stays a portal word, not `WAIVER_FILE_LABELS`, whose module imports the PDF loader and would break the portal's rule of importing no Supabase client.
- **Sample**: three `files` rows on Sample Dental Office (a submittal's cut sheet, a change's photo, a signed conditional waiver), the Drive id, record and bytes planted to show the slice drops them.
- **Tests**: `gcTradeFile.test.ts` (the note shape, the name, the folder, the refusals); `tradePortalSlice.test.ts` (files held to the company and its projects, the never fields); `tradePortalSample.test.ts`; `GcTradePortal.files.render.test.tsx` (the table, the links, the block's place between the statement of work and the report, the press and its post, the file joining the list, a refusal, a slice with no files).
- **Docs**: both function sections in `docs/EDGE_FUNCTIONS.md`; the guide *see what a trade partner sends from its portal* under **Its files** (the note file's folder; the office opens it in Drive, since no office screen lists a company's uploads today and the Draws window reads only waivers); the guide *share a trade partner its portal*'s job paragraph; the migration page.
