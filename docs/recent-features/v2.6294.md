# v2.6294 — Photos reach Drive again, and the job folder press works (2026-11-01)

v2.6284 (#6719) merged at 21:50 UTC; its migration was pushed and `job-drive-folders` and `photo-save` were deployed from main, and by 22:05 UTC both answered 503 BOOT_ERROR (the dev seat's `check_edge_boot`). `_shared/jobFolders.ts` imports `driveFolderMeta`, `FOLDER_MIME` and `metaOwner` from `_shared/driveSettings.ts`, which exported none of them: the part of #6719's edit that published them never landed, and the Mac it was built on has no Deno, so nothing linked the modules before the deploy. Deno refuses a missing named export when the module loads, so neither function started. Photos waited in the app instead of reaching Drive, the press and the Where files go tab failed, and the folder sweep's first cron call (22:00 UTC) stamped no job.

- **`_shared/driveSettings.ts`**: `FOLDER_MIME` exported; the private `meta` read published as `driveFolderMeta`, with the write check's two calls renamed; `metaOwner` defined (the owner's name or address, null inside a Shared Drive), where #6719 had inlined it away and left two calls to a function that did not exist.
- **Checked by bundling**: all 173 functions bundle with esbuild (`--bundle --packages=external`, remote imports external), which fails on a missing named export the way Deno's loader does. Before the fix, the five whose bundle holds `jobFolders.ts` failed: `job-drive-folders`, `photo-save`, `drive-link`, `job-photos` and `messages-email`. Only the first two had been deployed since #6719; the other three still ran bundles from before it, booted, and would have broken on their next deploy from main.
- **Deploy** `job-drive-folders` and `photo-save` once this is on main. Then `check_edge_boot` with `after: "job-drive-folder"` should name no boot error, the folder sweep's next run should stamp `drive_folder_tidied_at` on up to 25 live jobs, and the photo sweep files the photos that waited. `drive-link`, `job-photos` and `messages-email` are safe to deploy from main from then on.
- **The gap**: CI typechecks the app, not the functions, so a missing export between two `_shared` modules passes every check. A CI step that bundles each function the way the check above did would have refused #6719.
