# v2.6088 — Supply-house bills: the reader behind a switch (punch list #179, PR 2) (2026-10-29)

Punch list #179, the second of three PRs. PR 1 (#6451) rewrote the card to the approved second redraw: the Add invoice window stays the one way a bill is recorded, the PDF fills its fields like an autofill, a guess asks for a look in a sentence, and two doors open the form from where the PDF already sits. This PR is the reading, behind a switch that ships off. Nothing is on a screen yet; PR 3 puts *The bill* on the form and the two doors.

## What changed

- **`bill-read`** (new edge function): `POST { attachment_id, supply_house_id? }` for a file on the house's thread, or `POST { supply_house_id, file: { name, mime, base64 } }` for a file dropped on the form, which it puts in the `message-attachments` bucket under `bills/<house>/<uuid>/<name>` first. It fetches the bytes, sends the PDF as a document block or the picture as an image block to `claude-sonnet-5-5` (a dev may name `claude-haiku-5-5` for the trial) with a fixed JSON schema through structured output and Anthropic's default fallback on a refusal, reads the answer into cents and a kind, writes one row to `supply_bill_reads`, and answers the read with where the file is and what it cost. The caller is the office (dev, master_technician, assistant, controller), a real account, not read-only; the switch `app_settings.bill_read_on_v1` must read `'true'` except for a dev; the function stops at 150 fills in a rolling day. The key comes through `_shared/modelKey.ts` as `report-draft`'s does: Vault, filled from Settings → Phone and texts → Model keys, else `ANTHROPIC_API_KEY`. It never writes an invoice.
- **`_shared/billRead.ts`** (new, pure): the models, the switch key, the cap, the request's shape, `BILL_SCHEMA` (every amount a string of the digits as printed, so the schema needs no nullable number), the system words, `readBillAnswer` into `BillRead` (cents, a kind, a YYYY-MM-DD, the lines, the statement's numbers), the cost at each model's rates, the bucket path, and the function's words. `src/lib/materials/bills/billRead.ts` re-exports it and adds the app's shape: each field with its source (`read` · `guessed` · `typed` · `none`) and `BillRowRead`, what the row keeps.
- **The kernels** (new, `src/lib/materials/bills/`): `billMatch.ts`, the letterhead against the house the form is open on (the generic words dropped), the job as a guess with its evidence (the PO Generator code against the house's ledger, the account reference against the job accounts, the ship-to and the job text against the jobs), the job-account default, the credit's pair from its *RE:* number, the due date from the terms; `billChecks.ts`, the lines to the total with the tax to the cent, the duplicate by number, the statement, the house; `billWords.ts`, every sentence the form will show, in the approved drawing's words, held to the plain-words rules.
- **The made-up test set** (`src/test/fixtures/bills/`, drawn by `scripts/bills-fixtures.mjs` with pdf-lib): five PDFs, each beside the answer the model should give — the card's bill whose five lines add to $952.28 with the tax, its credit memo naming it, a bill whose printed total is $36.00 off its lines, a bill from another house, and a statement. The kernels' tests read the answers; `scripts/bill-read-compare.mjs` sends the PDFs to the deployed function with each model and scores the answers.
- **The write lifted** (`src/lib/materials/supplyInvoiceWrite.ts`): `saveInvoice`'s payload rules and its three writes, out of `SupplyHousesTab.tsx` and tested over a fake database. The form calls it; the rules are unchanged, and the read a filled bill keeps goes in the payload only when the draft carries one, so a typed bill's save names no new column.
- **Migration `20261030010000_supply_bill_read.sql`**: `supply_house_invoices.bill_read` and `bill_attachment_id`, the switch row and its policy, the `supply_bill_reads` ledger with RLS and the three fences (`docs/migrations/20261030010000_supply_bill_read.md`). `docs/EDGE_FUNCTIONS.md` → bill-read; the dev-mcp catalog names the function.

## Decisions

- **The job is always a guess.** The paper never prints the job's id; a PO Generator code on the ledger is strong evidence, and the form says so in the sentence, but the person says yes. That is the approved drawing's amber card.
- **The amounts come back as printed digits**, never numbers the model rounds, so the sum check compares the paper with itself and a transposed total is caught.
- **A small ledger over no ledger**: the cap of fills a day needs a count that outlives the form, and the later question of how often the reader is right needs the answers kept. One service-role-written table, read by the office.
- **A dev may try the function with the switch off**, so PR 2 can be verified on prod before PR 3 turns anything on. Nobody else can.

## Deploy

From the main checkout after the merge: `supabase db push` for `20261030010000_supply_bill_read.sql`, then `bash scripts/deploy-functions.sh bill-read`, then `dev-mcp` (its catalog names the function); `npm run check:edge-drift` prints the list. The key: Settings → Phone and texts → Model keys, if the card holds none. Then `npm run gen-types:linked` as its own `chore(types)` PR.

## Test

`npx vitest run src/lib/materials/bills src/lib/materials/supplyInvoiceWrite.test.ts`. Live, once deployed, as the dev: `node scripts/bill-read-compare.mjs --jwt <the dev's access token> --house <a ZZ test house's id>` sends the five fixtures and scores the answers; `read_rows` on `supply_bill_reads` then shows one row per fill with its model, tokens and cents; `--model claude-haiku-5-5` runs the trial. Nothing is written to an invoice.
