## Three choices worth knowing

1. **A shared book is copied first.** The tab writes on the shared book and then copies it to the bid, leaving the written rows on the shared book, inert. The apply copies first (`clone_price_book_version_to_bid`, SECURITY INVOKER, as the dev), points the bid at the copy, plans again on it and writes there. The bid ends where the tab leaves it; the shared book is untouched.
2. **A sent bid needs `revise: true`.** The tab locks a sent bid's prices until someone presses Revise, a mark kept in that browser tab alone. No database rule reads it, so the plan holds the same line in words.
3. **The margin stamp stays the tab's.** The tab refreshes `bids.priced_*` after its own price writes, and its cost reads the company crew rate the browser computes.
