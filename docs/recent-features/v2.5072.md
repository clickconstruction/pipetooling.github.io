# v2.5072 — GC Review: the round's data is a hook, useGcStatementRound (2026-10-09)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 2 (`to-dos/decomposition-queue.md`): the Stages map's steps 4 and 7 wait on the GC Review map's step 8 (`docs/GC_REVIEW_MODAL_ARCHITECTURE.md`), so this is that step. The Stages board's round block moves onto the same hook in its own PR.

## What shipped

- **`src/hooks/useGcStatementRound.ts`** (new): the round's data, moved verbatim from `JobsGcReviewModal.tsx`:
  - the week's certifications and whether they were read (`certRows`, `certsRead`, `refreshCerts`);
  - this week's marks and six weeks of marks for the temperature board (`roundMarks`, `boardMarks`, `refreshRoundMarks`);
  - each round GC's standing sender (`roundSenders`);
  - the three reads that run while the window is open, the senders' with its `cancelled` flag.

  One function is new: `reloadSenders`. It is the two lines `assignSender` ran after a save, moved into the hook, so a failed read still rejects to the window's catch. Inputs: `{ open, certWeekStart, roundGcIds }`, named as the window named them, so the moved lines are byte-identical.
- **`JobsGcReviewModal.tsx`** calls the hook where the senders effect stood, after `roundGcIds`, which it reads. `certsByGc` moved under it. It no longer holds a setter for the round's data. Its five writers reach the data only through the hook:
  - Save mark (`markRound`) and the call sheet (`saveCallSheet`) call `refreshRoundMarks`;
  - undo (`undoRoundMark`) calls `refreshRoundMarks`;
  - the account man's pick (`assignSender`) calls `reloadSenders`;
  - a check (the Certify modal's `onCertified`) calls `refreshCerts`.

  2,744 → 2,698 lines. The imports only the moved code used are gone.
- **Kept in the window, by decision**:
  - The derived memos (`mergedLastSent`, the worklist, the board's rows and temperatures) stay, because the Stages board derives different cards from the same data.
  - The writes and `roundBusy` / `roundError` stay, because they need the window's signed-in name, its toasts and the word promises.
- **Docs**: the GC Review map's step 8, its two loader rows, the data-engine paragraph and hazards 4 and 14; the Stages map's step 4; the playbook's file row and its `useGcStatementRound` row.
