# v2.5667 — The Directory's Kind column retires: a chip on the exceptions, a Ledger only band (2026-10-20)

Client only; no migration, no edge function. Punch list **#131** (`to-dos/directory-kind-column/`, deleted with this PR; the mock-up lives in git history at the deleting commit). The owner's ask, 2026-10-20: *I don't like how the Supply house box looks on this screen* — the Kind column's pill on the office's Directory (Materials → Supply houses), wrapped into a two-line oval and repeated down most rows. All four calls taken as recommended: retire the column (not the nowrap fallback), the band, one muted chip for every ledger kind, the chip on the phone card too.

## What shipped

- **The Kind column is gone.** The office table in [`SupplyHouseDirectory`](../../src/components/materials/SupplyHouseDirectory.tsx) takes the estimator's five columns (the first still headed *Vendor* for the office); the freed width went to Reps, the column carrying the amber job-accounts sentences. The pill that wrapped — no `white-space: nowrap`, no column width — no longer exists to wrap.
- **The exceptions carry a chip.** A ledger-only vendor (any `vendor_kind` but `supply_house`) shows a small muted chip beside its name — *Insurer*, *Rental yard*, *Sub ledger*, *Other* — with the vendor form's one-line hint (`VENDOR_KIND_HINTS`) as its hover title. A supply house is the default and unmarked; the coverage line and the bands already bound the group.
- **A "Ledger only" band** draws where the middle group starts — the sort (`rowGroup`) has always put ledger-only vendors between the rep'd houses and the needs-a-rep group; the band names it once: *Ledger only · N vendors — paid through Accounts payable, never quoted. Estimators don't see these.* It is the Needs a rep band's quiet sibling (gray, not amber), and only draws on the office's *All kinds* view — narrowing the kind select makes it redundant. `ledgerBandInfo(rows)` lands in [`supplyHouseDirectory.ts`](../../src/lib/materials/supplyHouseDirectory.ts) with tests.
- **The phone card gains the same chip** beside the vendor's name — the office's narrow cards had shown no kind at all — and the band draws between the cards as the Needs a rep band does. The estimator's tab (already supply houses only, no Kind column) renders byte-for-byte as before.
- **Phone numbers normalize on display** (the owner's follow-up ask the same day: *we should normalise phone numbers where possible*). The column held every typed shape at once — `210-344-4950`, `+12106954440`, `2107646444`, `(830) 460-3060`. The Phone column, the narrow card's Counter line and the Job accounts chip now print through [`phoneContact`](../../src/lib/phoneContact.ts) (the v2.3247 kernel the call buttons already use): US-dialable numbers as `(210) 344-4950`, anything else as typed. Display only — the stored value and the Edit form are untouched.
- **The guide** *find a supply house and its rep* gained one paragraph naming the band and the chip, in plain words.
