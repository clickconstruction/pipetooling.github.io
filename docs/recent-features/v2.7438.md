# v2.7438 — Stickers: the running number is gone (2026-11-16)

Punch list #329. Taunya's call of 2026-11-16, after PRs 8 to 10 of section 10 were live. Shown the named strip with the sticker's number small on its own line, she asked what the number was for, said she had taken it for the link, asked *Shouldn't we get rid of that number and only use that eight-digit link code?*, and picked **Drop it everywhere** over keeping it on stickers with no name. Client only: no migration, no edge function. The number stays in the database: `box_stickers.number` still orders a run and tells two stickers of one name apart, and `mint_sticker_run` still gives it.

## What changed

- **The strip.** A named sticker is its name over the link's two lines, dot for dot a box label. A sticker with no name has no stencil: its code is drawn half again as large in the name's place (`tapeStripLines`' `bare`, `bigCodeSquare`: three dots a square, capitals 3 mm where the link's are 2). `tapeStripBlock` places a strip with no stencil as the two lines alone, centred. The number's line of v2.7391 is gone, so 18 mm tape no longer closes its lines up. The print-window strip draws the same. The test strip reads TEST where it read 0000.
- **The print window.** No line says where the last run ended or where this one starts (`lastRunWords` and `fetchLastStickerNumber` are gone). A run with no names is said by its count: the title *60 stickers · …*, the count line, *Print 60 sets*, *Print the rest, 29 stickers*. The From and to lists read a sticker with no name by its code. The progress line names the strip in hand by its name or its code. The CSV drops its Number column, and its file is named by the run's names or its count.
- **The preview fold** draws a named run as before. A run with no names draws one sticker, with *and 199 more, each with its own code*, since every other strip differs only by its code.
- **The Runs fold.** A run with no names is titled by its count, *Run of 200*. The line under says who and when, with no *numbers 0225 to 0447*. *Not used yet* says how many, and by name for a named run, *3 stickers not used yet, G79 to G81*.
- **The scan sheet.** A sticker with no name is *This sticker is new*, with its code at the top as the tape prints it. The press reads *Put this sticker on R76*. The new box has no *Sticker 0147* chip. The outcomes say *the sticker* or *this sticker*.
- **The box rows.** A sticker with no name says nothing beside its box's name, as one printed with the box's own name already did. Only *sticker reads G78* is ever said there.
- **The pages a scan opens.** Signed in and signed out: *This sticker is not on a box yet*, *This sticker was marked lost*, *This sticker is on a box of a job you are not on*, *This sticker is on R76, which was retired*. The signed-out page of a box opened by a sticker drops *Sticker 0147,* before the code, and its tab title reads *Blank sticker* or *Lost sticker*.
- **Scan a label** takes the eight characters alone. Digits typed are a short code, not a sticker's number (`fetchStickerByNumber` is gone).
- `readStickerRange`'s empty kind is `unnamed`. Both site guides, the map and the Glossary say the sticker as it is now.

## The picks

- **Drop it everywhere, as Taunya chose,** over keeping the number on stickers with no name. Such a sticker now reads its code, which is what a person types when a scan fails and what never changes.
- **The code a size up on a sticker with no name.** It is the one thing on that strip to read; the picture she was shown had it so. Under a name the code keeps the link's own size.
- **The number stays in the database.** Dropping the column would change `mint_sticker_run`, the events' judge and `box_sticker_facts` for nothing a person sees; the screens simply never say it.
- **`box-read` is not redeployed.** The function still answers `number` for a blank or lost sticker and `stickerNumber` for a box opened by one; the page no longer shows either. Leaving it out of the answer is a deploy of `box-read`, which needs Taunya's go by name.
