# v2.7771 — Documents tab: a list that reads again after a window closes no longer finishes behind your back (2026-11-18)

v2.7709 fixed a merge-queue build that failed on `ReferenceError: window is not defined`: a section set state after its read landed, once the test's page was gone. Its fragment left one gap by name. **Hours statements** and **Statements of charges** read again when their window closes, and that read had no guard.

## Why it was open

- Each section's `reload` returns the function that sets its `cancelled` flag, and the effect hands that function back to React. The read on mount was guarded that way.
- `closeWindow` calls `reload()` too, and dropped what it returned. Nothing ever set `cancelled` for that run.
- A section taken down while that read was out set state after it was gone. In the app React ignores that. In a test run whose page is already torn down, React reads `window` on the state set and throws, and a rejection nobody holds fails the run.

## What changed

- Both sections ask `useTakenDown()` (`src/hooks/useTakenDown.ts`) on every landed and failed branch, beside the `cancelled` flag. The hook is for a read more than one caller starts, which this is: the effect and the window closing.
- A search of `src` for the same shape found seven more: a `reload` that returns a stop function and is also called from a handler that drops it. Each now asks the hook the same way.
  - The Documents tab's own pay applications and sent copies (`JobWindowDocumentsTab`), read again when the pay application window closes and when one is put back.
  - The tab's contract (`JobDocumentsContract`), read again on a change the Contract window announces.
  - The tab's lien paper (`JobDocumentsLienPaper`), read again when the Lien window records.
  - The tab's test reports (`JobDocumentsTestReports`), read again on a change in the Test report window.
  - A job's review line (`JobReviewLine`), read again after **Save the call**.
  - The permit names card in Settings (`PermitOurNamesSettingsCard`), read again on **Try again**.
  - The ticket press (`TicketPress`), whose day's jobs are read again on each open.
- `HoursStatementsSection.render.test.tsx` and `StatementsOfChargesSection.render.test.tsx` hold it. The window is opened and closed on reads that are held, the section is taken down, the page's `window` is removed, and the reads then fail or land. On the old sections each case throws the build's own error, one for each read.

## Not changed

- Nothing on screen. A read that lands while its section is up draws as before.
- The `cancelled` and `live` flags stay. They still stop the effect's read when the job or the person changes under a mounted section, which the hook does not. A read a handler started still takes the last answer to land when the job changes under it, as v2.7709 left for painted maps.
- The seven other reads have no test of their own. Their change is the same one line of guard, and every test that mounts them passes as before.

## Left

- A press's own await sets state after it lands too: **Put it back** on a deleted pay application, **Open the signed PDF** and **Put in Sent by us** on an hours statement, **Save the call** on a review line. That is a different shape, common across the app, and none of these tests reach it.
