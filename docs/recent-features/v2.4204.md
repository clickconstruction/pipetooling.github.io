# v2.4204 — Counts: quick add lands in a group (2026-09-30)

Alternates round two, PR 7 (after [v2.4202](v2.4202.md)). No migration, no edge function. Round one's Count Sheet could mark a group as an alternate but quick add always landed a row outside every group, so growing an alternate by hand meant a second edit in the row's Group cell.

## What changed

- **Quick add's Group box** ([`BidsCountsTab`](../../src/components/bids/BidsCountsTab.tsx), `qaGroup`): an input with a `<datalist>` of the bid's distinct group tags (an alternate's option is labelled *· ALT*, and the box's border turns amber when the typed group is an alternate). The insert carries `group_tag`, the duplicate check runs within that group (`findDuplicateFixture(..., { groupTag })`), the toast says *added to <group>*, and the group stays for the next add. It resets with the rest of the panel when the bid changes.
- **"+ add here" on every By group heading**: sets the Group box to that group, opens the panel and focuses the count.
- **Render smoke** ([`Bids.render.test.tsx`](../../src/pages/Bids.render.test.tsx)): the stub now serves `bids_count_rows`; a Counts case with an alternate pins the Alternates tile, the ALT mark, the By group heading, its add and the Group box. A Workbench-line smoke was not added: the Pricing tab's derive needs a cost estimate, a pricing version and a price book on the stub, which the smoke does not model — the line's numbers are covered by `alternateScope.test.ts` and the pills by `workbenchSolveScope.test.ts`.
