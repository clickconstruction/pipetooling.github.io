# v2.5724 — Sign-in: the dev login and Log in as find every account (2026-10-22)

Punch list #142 PR 0, the walk kit's first PR, and the one with no dependency: it ships before any 51st account exists, the kit's tester included (`to-dos/walk-kit/BUILD_PLAN.md` § 0.2).

- **What was wrong**: `dev-login` and `login-as-user` looked the target up with `auth.admin.listUsers()` and no page, which answers the first 50 accounts and nothing else, then `.find(email)`. Prod held exactly 50 auth users on 2026-10-21. The 51st account, whoever it was, would have pushed any account past the page, the dev-login identity included, and every session's sign-in would have answered *User not found*.
- **The helper** (`supabase/functions/_shared/authUserByEmail.ts`, Deno-free so vitest imports it): `findAuthUserByEmail(listPage, email)` asks for 1,000 a page and keeps going until the address is found (trimmed, case-insensitive on both sides), the server names no next page, a page comes back short, or a page errors (the walk ends with the error's words and no user). A hard stop at 100 pages.
- **Both doors** take it: `dev-login` as the plan says, and `login-as-user` beside it, since it had the same read and the same 51st-account hazard. Their answers are unchanged: 404 *User not found*, 500 *Failed to find user: …*.
- **Tests**: `src/lib/devLoginLookup.test.ts` — found on page 1 and on page 3, not found after a short page or an empty one, a full last page the server marks as last reads no further, case-insensitive, stops on an error, copes with an account that has no email.
- **Deploy**: `dev-login` and `login-as-user` after merge. Verify: `/dev-login?as=1` on a local preview still signs in.
- **Docs**: `EDGE_FUNCTIONS.md` § dev-login and § login-as-user.
