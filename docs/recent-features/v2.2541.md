# v2.2541 — Won / week + Bidding cost / week cards (2026-08-31)

Two additions to Estimating Health (follow-up to v2.2537's Avg / week):

- **Won / week** (pulse strip, everyone): `stats.wonDollars / windowWeeks`, same
  quiet-weeks-count convention. `StatCard` exported from the pulse section for reuse.
- **Bidding cost / week** (dev-only, top of the estimator-labor section — wage-derived,
  so it keeps the same gate as the labor table): new kernel
  `averageWeeklyBiddingCost` in `bidBoardWeeklyEstimatorLaborCost.ts` (estimator
  clock-hours × wage across the window ÷ window weeks; flags estimators with hours but
  no configured wage; +3 unit tests). Sub-line shows the cost as a % of won $/week —
  `BidBoardEstimatingHealthSection` computes `wonDollarsPerWeek` with the same
  `buildPulseStats` math the strip uses, so the two never disagree.

Verified live: Won / week $65K ($1.7M ÷ 26, matches the Won rate ($) card);
Bidding cost / week $4,753.67 · 7.3% of won $/week (÷ $65K checks out).
