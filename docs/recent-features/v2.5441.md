# v2.5441 — Jobs: a customer's name on a phone card opens their profile again (2026-10-13)

Found while preparing residential Messages R2 PR 3 (the openers), by customer communication helper 9 for the customer
communication lead. A fix of its own, so the openers PR stays one change.

- **The bug:** the Jobs stages board's phone cards draw a customer's name through `renderJobCustomerAndAddressLine`
  (`jobsStagesRowShared.tsx`), a button that calls `ctx.openCustomerProfile?.(job.customer_id)`. The desktop tables
  (`JobsStagesTable.tsx`, `JobsStagesUnifiedTable.tsx`) put the profile opener in their row context. Both card lists
  in `JobsStagesCardList.tsx` (`JobsStagesCardList` and `JobsStagesUnifiedCardList`) built theirs without it, so on a
  phone the press did nothing, and a GC's name (`renderGcTimelineDoor`) fell back to plain text.
- **The fix:** each card list reads `useCustomerProfileModal()` and passes `openCustomerProfile` into its context, as
  the desktop tables do. Nothing else changes.
- **Tests:** a new case in `JobsStagesCardList.render.test.tsx` and one in `JobsStagesUnifiedTable.render.test.tsx`
  (the unified phone cards) press a linked customer's name and expect the profile to open. Taking the opener out of
  either context failed its case.
