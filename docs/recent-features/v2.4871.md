# v2.4871 — Contracts: the signed copy names its signers the same way as everywhere else (2026-10-07)

Edge function `sign-job-contract` changed; no migration, no client change. Punch list #64 ([`to-dos/contract-second-signer-names.md`](../../to-dos/contract-second-signer-names.md)), the second item *Left after this row*.

## What changed

[v2.4590](v2.4590.md) put the signers' names into one kernel, `supabase/functions/_shared/jobContractSigners.ts`, and [v2.4596](v2.4596.md) moved `customer-portal`, `share-job-contract` and `legal-portal` onto it. `sign-job-contract` still joined the names itself when the last frame signed. Its join read *<first> and <second>* from the row and this signature's printed name.

It now reads `signerNamesLine` over the row as this signature leaves it: the row it loaded, this frame's columns, and `signed_at`. That is the same overlay the update writes. The words go to two places:

- the customer's signed copy (`buildJobContractSignedCopyEmail`'s `printedName`)
- the office notice's subject and first line, *✍ Contract signed — Job #… · Sam Owner and Alex Owner*

The words are the same as before: *Sam Owner and Alex Owner*, whoever signs last, or the one printed name on a one-frame agreement. A part-signed agreement returns before this point, as before.

## Deploy

`supabase functions deploy sign-job-contract` after the merge.

## Tests

`jobContractSigners.test.ts` (+1) builds the row the way the function does: the second signer completing it, the first signer completing it, and one frame. No local Deno, so the function is type-checked at deploy.
