# v2.3024 — Test-gap audit, pass 34: the Copy Day Job Mix plan builder gets its first tests (2026-09-07)

Follow-up to v2.3022. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`dayJobMixApply.ts` (165 lines) is the pure planner under **Copy Day Job Mix**: it takes a source person's job percentages for a day and turns the target person's clock blocks into one replace call per time-contiguous cluster, each cluster cut into segments by the mix, with the minimum-length guards that keep a segment from dropping under 0.01 h. The percentage kernel it uses was tested; the planner was not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Percentages normalise (3 : 1 reads as 75 / 25); an empty mix, a zero-sum mix and a target with no sessions each refuse with their own message.
- Sessions are sorted first, contiguous ones form one cluster, a gap starts another, and every cluster is cut by the same mix. The last non-zero segment always ends exactly at the block end; an open last session ends its cluster at now with an open last segment; a zero-percent row produces no segment.
- A segment inherits the longest note of any session it overlaps, else "Job mix (<source>)", capped at 4,000 characters.
- A block shorter than 0.01 h refuses with its length in seconds; a mix that would leave a segment under 0.01 h refuses, but a single-row mix on a short-but-valid block is fine.
