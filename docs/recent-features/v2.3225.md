# v2.3225 — Robot Board: every live bid lists with its door, "Add bid value", where the delta lives, and a strip in plain words (2026-09-10)

Client only — no migration, no edge function. Grace's six carry-overs from the Results mockup (https://claude.ai/code/artifact/0e926513-62bf-422b-9234-a1b8d94f9beb) onto the v2.3222 mirror, after comparing the mockup with what shipped: the mirror only listed bids that already had a run, so the bids that most needed a person were the ones it hid; its "live" count took never-sent lost leads as live; a sealed run on a bid sent without a value had no way to fix that from the row; the delta split lived only in the envelope; and the strip spoke operator vocabulary.

## What changed

- **Every live bid lists** ([`robotMirror.ts`](../../src/lib/bids/robotMirror.ts), +4 tests): `buildRobotMirror` takes `rowStateFor` — the Bid Board icon's own kernel, `robotRowState(robotRowInputFor(bid))` from `Bids.tsx` — and lists each unsent, undecided, non-archived, non-ZZ bid with no run as a row: `needs` (the first blocking gap and its fix; the amber `?` / question-count glyph), `queued` (`front of the line` when stamped, else `next batch`) or `off` (opted out / not plumbing, muted, no door). Without `rowStateFor` the kernel behaves as v2.3222 (front-of-the-line requests only). `MirrorRunStatus` gains `needs` and `off`; `RobotMirrorRun` gains `need` / `offReason`; `RobotMirror` gains `listedCount` (the lens label), `needsCount`, `sealedCount`; `rowCount` now counts real runs only. `compareMirrorRows`: robot activity newest first, then needs by due date (undated last), then queued, then off. The unsent header reads *N need a person before a robot can start · five minutes each*.
- **The doors** ([`BidsRobotMirrorTab.tsx`](../../src/components/bids/BidsRobotMirrorTab.tsx), render test rewritten, 4 smokes): a `needs` row's door is named for the fix — **Paste the plans →** (no plans link), **Share the plans →** (plans not shared with the intake account), **Fix the plans link →**, or **Answer →** (questions only) — and opens the robot needs sheet (`onOpenNeeds` → `setRobotNeedsBid`); `queued` / `estimating` / `sealed` live rows get **Robot status** (`onOpenStatus` → the status sheet with Front of the line); a sealed run on a bid sent without a value gets **Add bid value →** (`onAddBidValue` → `openEditBid(bid, { focus: 'bidValue' })`).
- **Where the delta lives on the row**: a scored / audited row with a shell and both numbers expands (one toggle per row, shared with the earlier-runs fold) into the v2.2935 waterfall — both takeoffs priced through `loadPricedTakeoffRows`, `diffTakeoffs` + `diffWaterfall`, the envelope's chip strip (missed · added · counts · priced differently · everything else = delta) — plus **Robot's own note**, the audit's `self_assessment` (now in the mirror's `bid_audits` select). Rows the diff can't price say why.
- **Sealed rows say whose number**: `vs Wendi` / `vs Grace · practice teacher` before send (the run's `teacher_name` / `teacher_standard`), not only after. An open run reads `estimating`, not `working`.
- **The strip in plain words**: six pills — *of our bids have a robot run* · *live plumbing bids shadowed* · *sealed, waiting on you to send* · *need something from a person* (amber) · *audits waiting · oldest N d* · *kinds of job earned first drafts →* (a button to the Scoreboard for every audit role, the lens's own door since v2.3221).
- **Live means live** ([`shadowCoverage.ts`](../../src/lib/bids/shadowCoverage.ts), +2 tests): `isShadowEligibleLiveBid` rejects decided bids (`outcome` set) and working-board-archived bids (`working_board_archived_at`), the human board's own Unsent rule (v2.518). On 2026-09-10 the mirror read *2 / 21 live plumbing bids shadowed · 19 more have no robot yet*; the human board's Unsent section had 11 rows, 3 with plans. It now reads *2 / 3*. The same kernel feeds the Scoreboard's coverage pill and the mirror's uncovered count.

## Not changed

- The seal: a live row still shows status only; the detail expander only opens on a sent bid with a scored or audited run, and `list_shadow_runs` still NULLs the money before that.
- The needs / status / envelope sheets themselves, the icon kernel, and the human board.
- The ZZ sandbox human bid (`ZZ Takeoffs Test`) lists on the human board but not the mirror — the mirror skips `ZZ ` names as the coverage kernel does.
