# v2.2520 — Audits tab view-only for read-only roles (2026-08-30)

Handoff leftover from the Audits-tab train (v2.2516–2519): primary and
superintendent can SELECT `bid_audits`/`bid_audit_notes` but every write is
RLS-denied, so the tab's composers surfaced raw 42501 errors for them.

- New kernel gate `canWriteBidAudit(role, isDigitalTwin)` +
  `AUDIT_WRITE_ROLES` in `src/lib/bids/bidAudits.ts` — mirrors the write policy
  in `20260830230000_bid_audits.sql` (dev / master_technician / assistant /
  controller / estimator), and returns false for flagged twin accounts (their
  write lanes are API-only: question/receipt).
- `BidsAuditsTab` takes `myRole` (from Bids.tsx's existing role state) + reads
  `useIsDigitalTwin()`; when the gate is false it hides the question answer
  boxes, the five sectioned note composers, and Finish audit/Reopen, and swaps
  the intro blurb for a "view only for your role" line. Unanswered questions
  render the same "Unanswered" state the post-finish view uses.
- Tests: `canWriteBidAudit` role matrix + twin override in `bidAudits.test.ts`;
  a read-only render smoke in `BidsAuditsTab.render.test.tsx` (card content
  present, zero write surfaces).
