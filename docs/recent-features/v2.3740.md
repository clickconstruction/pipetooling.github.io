# v2.3740 — The app updates itself at quiet moments (2026-09-22)

PR 1 of the auto-reload train the owner asked for after [v2.3739](v2.3739.md) ("instead of showing Reload I want the app to auto reload when possible without losing changes"). Client only, no migration. PR 2 adds the unsaved-work registry and the idle moment; PR 3 reload-safe drafts.

## What was wrong

Prompt mode (v2.813) leaves the new service worker waiting until someone taps **Reload**. A customer who opens an estimate link, never taps the pill and comes back two weeks later is still on the build her phone cached the first time — v2.3739's screenshot showed the pre-Sep-8 signing sheet under the pill. The office rides stale builds the same way on phones left open.

## The change

- **[`autoReload.ts`](../../src/lib/autoReload.ts)** (+9 tests) — `decideAutoReload(snapshot)`: the one place that says whether this moment may reload. Never without a waiting worker, never framed, never twice within a minute (a sessionStorage stamp, `pipetooling-auto-reload-last`, the same shape as chunk recovery's), never within ten minutes of *Not now*, never with a focused text field / textarea / select / contenteditable, an open `[role=dialog]` / `[aria-modal]` / `<dialog open>`, or any unsaved-work hold (PR 2's registry; 0 today). Then by moment: **first-paint** — no interaction since load (pointerdown / keydown / touchstart / wheel) and within 15 s of load; **route-change** — always; **idle** — hidden ≥ 5 min (wired in PR 2). `isEditableFocused` / `isDialogOpen` read the DOM.
- **[`UpdatePrompt.tsx`](../../src/components/UpdatePrompt.tsx)** (+6 render tests) — `onNeedRefresh` tries the first-paint moment before showing the pill; the route-change effect tries a reload before the v2.1007 resurface; a reload in flight renders the pill as *Updating to the newest version…* with no buttons, so the flash has a caption. The manual Reload path is unchanged (`applyUpdate`: SKIP_WAITING, reload on `controllerchange`, 4 s fallback).
- Help guide *update the app when a new version is ready* and `TROUBLESHOOTING.md` amended.

## Not verified live

The dev server has no service worker, so the moments were exercised through the render test's mocked `registerSW`. The first production deploy after merge is the live run: a tab left on the Dashboard should reload itself on its next route change, and a customer link opened fresh should never show the pill.
