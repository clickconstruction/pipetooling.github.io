# v2.3009 — Edit customer: contacts and properties in one list each, the property sheet, and "from this customer's jobs" (2026-09-07)

Customer properties train, PR 3 of 4 (v2.3004 the lookup, v2.3008 the primary row). Client only — no migration, no edge function. This is the modal refresh the owner approved from the 2026-09-07 mock-ups, with one change asked for on approval: **Contacts sit above Properties**.

## What shipped

- **Two columns** ([`EditCustomerForm.tsx`](../../src/components/EditCustomerForm.tsx), host widened to 900px): the left column is what rarely changes — Name, Type, Phone, Email, Date met, Customer files / pictures, Advanced (Customer master); the right column is the working list — **Contacts** then **Properties**. One column under 720px. The **Address field is gone**: the ★ property row is the address, and `customers.address` mirrors it by trigger, so the form's Save no longer writes it (it still saves the left column; the footer says *Contacts and properties save as you go*).
- **Contacts** ([`CustomerContactsSection.tsx`](../../src/components/customers/CustomerContactsSection.tsx)): rows read as people — name, role chip ("Spouse · signs contracts", "PM for 55 Pecan Ct"), phone · email — with *Edit* opening an inline sheet (name / phone / email / role, Done / Cancel / Remove). Same table (`customer_contact_persons`), same per-row persistence.
- **Properties** ([`CustomerPropertiesSection.tsx`](../../src/components/customers/CustomerPropertiesSection.tsx)): every `customer_addresses` row, ★ primary first, each answering the three office questions — **county**, **lien readiness** (✓ lien-ready / N lien fields missing / not looked up yet), **how many jobs sit there** (linked by `customer_address_id`, plus unlinked jobs whose street line matches). ☆ sets primary. *Edit* / *+ Add property* opens the **property sheet** ([`CustomerPropertySheet.tsx`](../../src/components/customers/CustomerPropertySheet.tsx)): the job form's Google address autocomplete, the note, and the v2.3004 record panel — which **runs the lookup as soon as an address is picked**, so most properties arrive lien-ready without anyone asking. The first property a customer gets is starred automatically. *Remove* is disabled while jobs sit at the property, with the count as the reason.
- **From this customer's jobs**: job addresses with no saved property show as dashed rows — "3311 Loop 337 · from this customer's jobs · 2 jobs · not saved as a property" — and *Add as property* opens the sheet pre-filled, lookup included. Kernel [`customerPropertiesFromJobs.ts`](../../src/lib/customers/customerPropertiesFromJobs.ts) (+5 tests): `jobCountsByProperty`, `suggestPropertiesFromJobs` (one row per street line, newest spelling, most jobs first).
- Guide `see-a-customers-full-history-and-lifetime-value` rewritten for the new layout; `GLOSSARY.md` gains *Properties (customer)*.

Deliberately unchanged: Merge with another customer (still below the form), Archive / Delete, the New Customer page (its Address field creates the ★ row through the trigger).

## Verify

Edit customer on a customer with jobs: two columns, Contacts above Properties, the ★ row first with county / readiness / job count, dashed "from this customer's jobs" rows below. *Add as property* → sheet opens with the address, the lookup runs, *Add property* saves and the dashed row disappears. ☆ on another row → it becomes ★ and the hub header address follows. *Remove* on a property with jobs is disabled with the count in its tooltip. Phone width: one column, Contacts then Properties.
