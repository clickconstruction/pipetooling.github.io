# v2.4612 — Liens on job: the next-step button always lands on the desk's tab (2026-10-05)

Client only; no migration, no edge function. The one gap left by punch list #82 ([`to-dos/lien-desk-next-up/`](../../to-dos/lien-desk-next-up/README.md)), fixed at the owner's ask the same evening.

## The defect

v2.4585 let a door re-aim an open Lien desk, keyed on the job it names changing. When the desk had been opened on job N, the person moved to Calendar, opened job N's Lien window from there and pressed **Open it on the Lien desk ›**, the job was the same, so the window closed and the desk stayed on Calendar.

## The fix

- [`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx) stamps the door with `aim: Date.now()` and passes it as `aimKey`.
- [`LienDeskModal.tsx`](../../src/components/jobs/LienDeskModal.tsx) re-aims when the job **or the key** changes; a re-render with the same key changes nothing.

## Tests

`LienDeskModal.render.test.tsx` (+1): the same job with a new key lands on Notices; the same key leaves Calendar alone.
