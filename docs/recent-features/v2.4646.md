# v2.4646 — Legal portal: the firm reads a plain sentence when something breaks (2026-10-05)

Two edge functions (`legal-portal`, `submit-legal-portal`, deploy after merge) and the firm's page; no migration. Item 7 of punch list #85 ([`to-dos/legal-portal-firm-ready/`](../../to-dos/legal-portal-firm-ready/README.md)). Mockup: `mockup-7-generic-errors.html` beside the card — the error card and the save notice before and after, and the table of sentences that stay.

## The defect

Both functions' top-level `catch` answered a thrown error with `{ error: e.message }` and status 500, and `LegalPortal.tsx` printed `body.error` as it came, on the error card (opening the portal) and on the notice above the forms (an act). A Postgres error names tables and columns; on a law firm's screen that reads as a system nobody looks after.

## What changed

- [`_shared/legalPortalErrors.ts`](../../supabase/functions/_shared/legalPortalErrors.ts) holds the rule, and `src/lib/legal/legalPortalErrors.ts` re-exports it for the page and its tests:
  - `LEGAL_PORTAL_GENERIC_ERROR`: *The office’s system could not answer. Please try again in a minute, or contact the office.*
  - `firmFacingErrorMessage(status, message)`: a 4xx keeps its own words (every 4xx sentence in both functions is a literal written for the firm); a 5xx keeps only the three sentences the functions write themselves (`LEGAL_PORTAL_FIRM_WRITTEN_5XX`: *Could not record the step.* · *Could not save that.* · *Could not save the rule.*); anything else, or nothing, becomes the generic sentence.
  - `unexpectedErrorBody(fn, e)`: what each function's `catch` now returns. It logs the real error as `<fn>: unexpected error (ref XXXXXXXX)` and answers `{ error: <generic>, ref }`, the reference eight random letters and digits.
  - `firmFacingErrorLine(status, body)`: what the page prints, the sentence plus *Reference XXXXXXXX.* after a 5xx when the body carries a reference of that shape.
- `legal-portal` and `submit-legal-portal`: the `catch` calls `unexpectedErrorBody`. The deliberate 4xx answers are untouched.
- `LegalPortal.tsx`: the error card and the act notice go through `firmFacingErrorLine`, so the page holds the rule even while an older function is deployed.

## Is this the best we can do?

- **Is a generic sentence enough for the firm to act?** Not alone: the office would have nothing to look up. Refined to carry a short random reference, printed on the page and logged beside the real error.
- **Does the reference leak anything?** No. It is random per failure, and the page prints only a reference of letters and digits, four to sixteen long.
- **What if the old function is still deployed tomorrow?** The page applies the same rule on any 5xx, so the demo is safe as soon as the page ships.
- **Why not filter the 4xx too?** They are all literals written for the firm. The one place that reads a database error (a person added twice) turns it into *That address is already on the list.*
- **What about `legal-notify-dispatch`?** Its GET answers the confirm and stop page with a kind only, and its POST is the cron tick behind a secret. No firm reads an error's words from it, so it is left alone.
