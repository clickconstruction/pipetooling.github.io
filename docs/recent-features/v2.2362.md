# v2.2362 — Hide people on the Health board (2026-08-26)

Estimator request: selectively hide people on the Bid Board Health section
(Estimating Pulse), and stop showing the nameless "—" person. The dash was
an archived account: the `users` SELECT policy hides archived rows from
non-dev roles, so the bids `estimator`/`account_manager` join comes back
null and `formatBidStaffDisplayName` falls back to `—`.

- **Kernel** (`src/lib/bids/estimatingPulse.ts`, +tests): new
  `PulseHiddenPeopleState` `{ hidden, shownArchived }` —
  `buildPulsePeopleView(people, directory, state)` resolves "—" names
  through a directory map and splits rows into visible people + hidden
  chips; archived people are hidden by default (shown only via
  `shownArchived`). Helpers: `withPulsePersonHidden`,
  `withAllPulsePeopleShown`, `parsePulseHiddenPeopleState` (junk-safe),
  `emptyPulseHiddenPeopleState`.
- **Names + archived flags** come from the existing SECURITY DEFINER RPC
  `list_user_display_names` (Schedule dispatch's name resolver) — one
  fetch for the person ids on view; no migration, no RLS change.
- **UI** (`BidBoardEstimatingPulseSection.tsx`): muted ✕ top-right of each
  person card hides that person (card + field-band marker); a "Hidden:"
  chips row under the People heading restores one ("+ Name", archived tag
  when applicable) or all ("Show all", shown when 2+ hidden). Footnote
  states hidden people still count in company totals / chart / ALL marker
  (band items are built from visible people only; stats are untouched).
- **Persistence**: localStorage `bid_board_pulse_hidden_people_v1`, per
  browser. Archived default-hide needs no stored state.
- Help guide `read-estimating-health.md`: new "Hiding people" section.
