# v2.4628 — Lien desk: a job's name opens the job, over the desk (2026-10-06)

Client only; no migration, no edge function. The owner's ask on the Next up view (2026-10-05): *when I hover over the job number and name I would like to see it underlined, and if I click on that text only I would like to see the job detail modal that goes away when it is closed but doesn't close the lien desk modal, and when the modal is closed the lien desk modal refreshes.* Mock-up: artifact 5Xwd7iuCuNmLUH4pN51uDN. Two calls taken with the go: refresh on close **and** on save; the other views' chips become text too.

## What changed

- **The Next up title is a door.** `LienDeskNextUp` takes `onOpenJob?`; a row with a job id draws its `title` as a text button (`.lienJobDoor`, `data-testid="lien-next-up-job-<id>"`) that stops its click and calls `onOpenJob(jobId)`. A GC's run row has no job and stays plain words. The phone card's title is the same button. Without `onOpenJob` nothing changes. The desk passes its existing `onOpenJob` down.
- **Every job door on the desk is text now.** `LienJobNumber` with a door was a blue chip (v2.4531); it is now the number in the row's own size and color, bold, no fill, underlined on hover and focus by the one class `.lienJobDoor` (renamed from `.lienCalJobNo`; `index.css`). Muted (a closed window) keeps the muted color. `LienJobHeading` with a door is now one button of the whole line, *663 · Knight Contracting*, instead of a chip beside a bold name. The door's words live in `LIEN_JOB_DOOR_TITLE`. Without a door the chip is unchanged.
- **The Job window says when it closes.** `OpenJobDetailOptions.onClosed?` in `JobDetailModalContext`: held in a ref, called once by `closeJobDetail` by any route (×, Esc, backdrop) and then dropped; `openJobWindowEdit` clears it. The Pipeline's desk mount passes `onEditJobSaved` and `onClosed`, both `refetchLienDesk`, so the desk re-reads after a save while the window is open and again when it closes.
