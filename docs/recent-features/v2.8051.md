# v2.8051 — Schedule on a phone: the block sheet and the copy bar sit right above the tabs (2026-11-20)

The follow-up v2.8035 left: two screens kept their own copy of the old bottom offset, the tab bar's 60 px plus `env(safe-area-inset-bottom)`. No migration and no edge function.

## The cause

`ScheduleBlockSheet` and `HubPeoplePhoneBoard` each wrote `BOTTOM_INSET` as that sum. The sum is wrong twice. On an iPhone the tab bar's 60 px already holds the inset, so the sum is 10.22 px more than the bar. On a screen with no tab bar the sum still leaves 60 px for one.

## The fix

`src/lib/bottomChrome.ts` gains `footClearanceCss`: the larger of `--app-bottom-chrome` and the home indicator's inset, never the two added. Both screens read it.

- **The block sheet** (`ScheduleSheet`, which the Supply House, Subs and Sub labor sheets share) pads its last row by 1rem plus that clearance. Its padding is written as four longhands now, so a test can read the bottom one.
- **The copy bar** (the People board's dark bar while a block is copied or moved) floats 0.5rem above that clearance.

## Verified

Walked on the dev server with Playwright as a phone at 3x, the inset set through Chrome's `Emulation.setSafeAreaInsetsOverride`. *Before* is the old sum put back on the same element in the same page.

| Case | The copy bar above the tabs or the foot | The sheet's bottom padding |
|---|---|---|
| Tabs up, 34 px inset, 440 and 320 wide, light and dark | 18.22 px before, 7.22 px after | 110 px before, 99 px after |
| Tabs up, no inset | 8 px, unchanged | 76 px, unchanged |
| No tabs, 34 px inset | 102 px before, 42 px after | 110 px before, 50 px after |
| No tabs, no inset | 68 px before, 8 px after | 76 px before, 16 px after |

With tabs and an inset the bar stands 7.22 px over the tab bar, not 8: the published tab bar height is rounded down to a whole pixel. With no tabs it stands 8 px over the home indicator's inset.
