# v2.7136 — Bids: a fixed price in the text you share with a teammate reads as one price for the line (2026-11-13)

Grace's ask, 2026-11-13, in its own session: the row the v2.7045 work saw and left alone. In **Copy for text**, a fixed-price row read `Mobilize — 3 × $5,000 = $5,000`, a sum that does not add up, because a fixed price is one price for the whole line whatever the count. Make that row read true, and change only the text.

## Where it lives

- **The press:** Bids → Pricing → **Share with a teammate** → **Copy for text**, in `PackageAndSendBidPricingModal.tsx`. It puts the text on the clipboard. The app sends no text.
- **The builder:** `buildBidPricingPackageSmsText` in `src/lib/buildBidPricingPackageSmsText.ts`. It feeds this one press.
- **The flag:** `bid_pricing_assignments.is_fixed_price`. `computeBidPricingRows` reads it as `isFixedPrice` and prices the row once for the line (`standardUnitRevenue`). It was lost on the way to the window: the share's rows carried the fixture, the count, the price, the line total and the hide flag, nothing more. So the builder guessed: a price equal to its line total was taken for a fixed one.

## What changed

- **The line.** A fixed-price row reads `{fixture} — {count}, fixed price ${line total}`. There is no `×` and no `=`.
- **The flag rides through.** `sharePackageRows` in `src/lib/bids/starAwareShare.ts` lays each row's `isFixedPrice` on the package rows. Both ways the window gets its rows use it: `useBidPricingRows`'s `pricingPackageSource` for the price on screen, and `scenarioPackageFromInputs` for the ★ price and for Send both. `PackageRowInput` and `PackageExternalRow` (`src/lib/buildBidPricingPackageHtml.ts`) take an optional `isFixedPrice`, and `buildBidPricingPackageExternalRows` copies it.
- **The guess is gone.** `shareUnitPrice` drops the clause that took a price equal to its line total for a fixed one. The flag decides now.
- **Why not in `scenarioPackageRows` itself:** `src/lib/bids/scenarioPricingRows.ts` is copied to the edge for the dev seat (`npm run gen:edge-kernels`). A field there would change `dev-mcp`'s bundle and owe a redeploy for a field the seat never reads. `sharePackageRows` keeps the one projection and adds the flag beside it; `npm run gen:edge-kernels -- --check` says the copy still matches `src`.

Before and after, on made-up rows (Mobilize and Permit fixed, Heater a plain row with a count of 1):

```
LAV-A — 3 × $2,900 = $8,700        LAV-A — 3 × $2,900 = $8,700
Mobilize — 3 × $5,000 = $5,000     Mobilize — 3, fixed price $5,000
Permit — 1 × $750 = $750           Permit — 1, fixed price $750
Heater — 1 × $6,400 = $6,400       Heater — 1 × $6,400 = $6,400

Total: $20,850                     Total: $20,850
```

## The rule for a fixed row

- **No `×` and no `=`**, so the line cannot show a sum that does not add up.
- **The count shows as stored.** A count of 74.29 stays 74.29.
- **The one figure is the line total**, rounded from the true amount like every line total (v2.7045). For a fixed row that is the price itself, so every line total and the Total print exactly as before.
- **"Fixed price" is the app's own name.** The margin breakdown says "Fixed price — not multiplied by count", and the print marks the price "(fixed)".
- **A count of 1 reads the same way.** `1 × $750 = $750` adds up, but it reads as a price for one. The reader should know the price stays put if the count changes. Keyed on the flag alone, a row never changes shape with its count.

## A plain row

Every row that is not fixed reads as before, with one kind of exception. A unit price that rounds to the same whole dollar as its line total, with a count other than 1, used to pass for fixed. That takes a price of a dollar or so, or a count within a hair of 1. The old text drew such a row as `2 × $1 = $1`. It now keeps the cents the sum needs: `2 × $0.60 = $1`.

## Left alone

The email from **Send for me** and **Send via my mail**, its plain-text body, the window's preview table, the Pricing tab, the print, the CSV and the stored prices. The Deno mirror `supabase/functions/_shared/bidPricingPackage.ts` is untouched, so nothing waits on an edge deploy. A new test holds the two copies' table and plain text equal for a fixed row.

## How it was checked

- `buildBidPricingPackageSmsText.test.ts`: the old fixed case now reads the new line, and eight new cases cover a count over 1, a count of 1, a count that is not whole, a fixed price with cents and one under 50 cents, a plain row with a count of 1, every line total and the Total unchanged against the same rows read as plain, a fixed row in each price of Send both, and a plain row that no longer passes for fixed.
- `starAwareShare.test.ts`: `sharePackageRows` lays each flag on its own row and leaves the rest as `scenarioPackageRows` draws it, and the ★'s package carries a fixed assignment.
- `buildBidPricingPackageHtml.test.ts`: the row builder carries the flag, and a fixed row draws the same email in both copies.
- `PackageAndSendBidPricingModal.render.test.tsx`: a fixed row in each price reaches the copied text as one price. With the flag dropped in the window's row builder, this test fails on `Mobilize — 3 × $1,500 = $1,500`.
- Walked on the local build against production data, every write refused, no text sent (2026-11-13). Production holds no fixed-price row: 0 of every `bid_pricing_assignments` row. Two real priced bids, 40 and 27 rows, copied text byte for byte identical to the same bids on clicktooling.com, which runs the code before this change. The only requests refused were the page's own activity pings.
- On the 40-row bid, one per-foot row's assignment was read as fixed in the browser only: the read's answer was rewritten and nothing was written. The copied text drew it as `<fixture> — <count>, fixed price $<price>`, with the count as stored. The window's preview drew `<count> | $<price>.00 | $<price>.00`. Only that line and the Total changed against the same bid without the flag, and the text's Total was the window's total rounded.

## Is this the best we can do?

For the text, yes. The line says what the row is, shows nothing to multiply, and keeps every figure the text printed before. Two things limit what it is worth today, and neither was changed here:

- **No production row is fixed, and no press in the app makes one.** The Pricing tab's writes never set `is_fixed_price`, the copies made by migrations only carry it over, and the dev and twin seats write `false`. The flag is read by the pricing kernel, the print, the margin breakdown and the email's edge function. So until something sets it, no real text draws this line.
- **The email still reads a fixed row as `3 | $5,000.00 | $5,000.00`**, with no marker. It is the same misreading in a table. Marking the Sale Price cell "(fixed)", as the print does, would take both copies of the email builder and a redeploy of `send-bid-pricing-package`.

## Not verified

- The text was read off a stubbed clipboard, not pasted into a phone's text app.
