# v2.3751 — Send a job as a task: the job is a bar above the box, not a code in it (2026-09-23)

Taunya, 2026-09-22, with a screenshot of the dialog: "When I click on the new to-do button on a job on Jobs pipeline, instead of looking like this can I get a cute bar with job name where this weird job identifier goes." Client only, no migration. Three options were drawn as a before/after page in the session (a bar above the box, a chip inside the box, the job in the header); option A, the bar, is built as drawn.

## What the "weird identifier" was

The four "send this job as a task" doors — the Pipeline row's purple arrow (`jobsStagesRowShared.tsx`), the phone card's *Send as task* (`JobsStagesCardList.tsx`, twice) and the Job Detail header (`DetailJobModal.tsx`) — each seeded the title box with the checklist's own link grammar, `{{1:1016 · Mission faucet}} — `, plus the job's `/jobs?jobDetail=<id>` URL as link [1]. `ChecklistTitleWithLinks` renders that as a link once the task is on a list; in the box it was braces and a "1" to the person typing, and one stray backspace broke the link silently.

## What shipped

- **Kernel** [`src/lib/checklistJobPreset.ts`](../../src/lib/checklistJobPreset.ts): `buildChecklistJobPreset(job, origin)` turns a job into `{ number, name, trade, address, customer, path, url }` (HCP number first, else C#; the trade pill uppercased like the pipeline's); `composeChecklistJobTitle` writes the pre-v2.3751 title byte for byte; `checklistJobLinks` keeps the job as link [1] once whatever happened in the Links section; `checklistJobModalPreset` is the one-liner the doors call. Braces in a job name are dropped from the label so they can never close the token early. 5 unit tests.
- **The dialog** [`ChecklistAddModal.tsx`](../../src/components/ChecklistAddModal.tsx): `preset.job` (a new optional field on `ChecklistAddModalPreset`) renders **the job bar** above the title box — purple-tinted, the number + trade pill in the trade color, the name, `address · customer` in a muted line that truncates rather than wraps, **open ↗** (navigates the page behind to the job and keeps the dialog open, the "Go to checklist" rule; the standalone `/task` page closes first, as it does there) and **×** (`aria-label="Remove job"`: bar gone, link [1] gone, typed text kept). The placeholder reads *What needs doing on this job?* while the bar is up. The header Send still waits for typed text. On Send the stored title is composed around the job and the links start with the job's URL.
- **The four doors** pass `checklistJobModalPreset(...)` with the job's number, name, address, service type and customer — the GC's name when the job has no customer of its own, which is what the pipeline row prints under the address (1016 Mission faucet reads *Johnny Ingram* that way). Job Detail falls back to the limited snapshot's fields for roles without the full row, and its arrow is disabled (half-opacity) until the record has landed: the live walk clicked it during the fetch and got a bar reading "Job Detail" with no number — the same race that used to store `{{1:— · Job Detail}}`.
- **Render tests** (`ChecklistAddModal.render.test.tsx`): open with a job preset → bar text, empty box, no raw grammar, one Send; type → two; Send → the `checklist_items` insert carries `{{1:1016 · Mission faucet}} — Pick up the Moen cartridge` and `[jobUrl]`. × → bar and `(1)` gone, text kept. open ↗ → `/jobs?jobDetail=job-1` behind, draft kept. The supabase stub now records inserts (`vi.hoisted`).
- **Help guide** `give-someone-a-task`: a *Send a job as a task* section with the bar as a chip.

## Not in this PR

The row on Checklist → Today still renders the job as today's underlined link. Drawing the same bar there (a `{{n:label}}` token whose link is a job door → chip) was mock-up option "+", an XS follow-up once the bar has been seen in use.
