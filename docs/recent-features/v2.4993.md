# v2.4993 — Dev login: one sign-in per URL, not two (2026-10-08)

Client only, and only the dev server: `/dev-login` sends production builds to `/sign-in`. No migration, no edge function.

## What was wrong

Helper 3 saw one 403 in the console on every Bids load as the dev and could not name it, because the browser pane's request list filled before it could be read. It is not on Bids, and it is not a refusal.

The request is `POST …/auth/v1/verify` on `/dev-login`. A probe that wrapped `fetch` before the page loaded caught it, with supabase-js's auth client in its stack. A plain reload of `/bids` while signed in made no failed request.

The cause:

- `main.tsx` mounts the app in React's `StrictMode`. On the dev server, StrictMode runs every effect twice.
- `DevLogin`'s auto sign-in effect called the `dev-login` function twice. The probe saw both calls, 171 ms apart, from one page load.
- Each call minted a magic link, and the auth server keeps only the newest. Whenever the second link was minted before the first was verified, verifying the first answered **403**. Then the second link signed in and the page moved on.
- So the 403 came and went with the race. The sign-in itself always worked.

## What changed

`src/pages/DevLogin.tsx` keeps the query string it last signed in for in a ref, `signedInFor`. The effect returns early for the same URL. StrictMode keeps refs across its second run, so the second run does nothing. A new `?as=` or `?to=` still signs in again.

## Tests

`DevLogin.strictMode.render.test.tsx` (new, 1 case) mounts the page under `StrictMode` with the function and the verify stood in for. It expects one `dev-login` call, one verify of that call's token, and one redirect to `?to=`. On main's page it fails: two calls. `DevLogin.render.test.tsx` (2) passes unchanged.

## Verified

- Typecheck clean and eslint clean.
- **On the dev server, with the probe:**
  - Before the fix, two `dev-login` calls per load. One load had the 403 on the first link's verify.
  - After the fix, three dev-logins to `/bids`. Each made one `dev-login` call and one verify (200), with no failed request.
