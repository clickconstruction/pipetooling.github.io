# v2.7055 — Bills sent: one bill's record, every send in order (2026-11-12)

Punch list #327, PR 4 (the record; its doors on the Pipeline follow once the stacks that edit the billed row have merged). A bill can go out more than once and by more than one route. The billed row on the Pipeline keeps one stamp, and a resend writes over it. The record puts every send of one bill in order.

## What changed

- **The kernel** (`src/lib/billing/billsSent.ts`, 34 tests in all):
  - `billsSentRecord(billId, lines, input)`: the bill's name, job, payer, amount and state (*Not paid*, *Paid Nov 9*), then one event a send, newest first: *Thu, Nov 12 · 11:02 AM*, *Emailed again by Marcus*, *To Accounts Payable, ap@… Delivered 11:02 AM.* A text reads *Texted the pay link*, a print *Printed*, a Housecall Pro day *Sent from Housecall Pro* with the day alone. A bill with no line still has a record, with no events. Null for a bill the page does not know.
  - `madeWords`: *Bill made Tue, Nov 3 at 4:38 PM.*, from the bill's own `billed_at`, which the reads now carry.
  - `billsSentRecordPath(billId)`: `/bills-sent?bill=<id>`.
  - `billsSentRecordHtml(record, printedAt)`: the record as one page, every word escaped, with what *Delivered* means and when it was printed.
- **The screen**: a bill's name on a line, and on a row of the strip, is a link to its record (the underline alone marks it). With `?bill=` in the address the page draws the record in place of the list: **← All bills sent**, the heading, the events each with **Copy as sent**, the bill-made line, and **Print this record**. A bill the page does not know says so and offers the list.
- **The print ratchet** (`sentCopiesCoverage.test.ts`): the record is our own reading of the sent copies, for a file or for counsel, so it is on `NOT_A_SEND` and files no copy.
- **The guide** gains *See every send of one bill*.

## Not changed

- Nothing is written. No table, policy or function.
- The billed row's own stamp and the Billed header on the Pipeline: those doors wait for the Pay calendar (#323) and lien line (#325) stacks, which edit the same files.
- A statement does not say which bills it listed, so a bill's record does not list the statements it was on. PR 6 files that with each statement.
