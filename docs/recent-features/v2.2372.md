# v2.2372 — Typing a workbench price overwrites the old one (2026-08-26)

Estimator report (Wendi): typing a price into the workbench's **Sale
price/unit** box merged with what was already there instead of replacing
it, and a cleared box snapped back to `0` — so `45` could land as `450`
and `164.75` as `16475`, with rework to fix each miss.

Two root causes, fixed in two PRs that crossed in flight:

- The keystroke-parsing controlled input (empty → `0` snap-back, eaten
  decimals, digits merging around the caret) was replaced by v2.2373's
  draft-while-typing + save-on-Enter/blur rework
  (`wbPriceDrafts` / `commitWorkbenchTypedPrice`), which landed first and
  covers everything this PR originally carried for that half.
- **This PR adds the remaining piece: focus selects all.** The sale-price
  input gets an `onFocus` that selects the current number after the
  click's own caret placement lands (`setTimeout(select, 0)`), so typing
  overwrites the old price instead of splicing into it. Esc-cancel and
  the no-op on unchanged blur were already part of v2.2373's commit path.
- Help guide `price-a-bid-with-the-workbench.md`: "Typing is overwrite,
  not surgery" paragraph.

Verified live on bid BP392's workbench (select-all on click and tab,
decimal typing, empty blur, Esc, tab-through).
