# v2.7751 — Bill Customer: one shared disclosure piece (2026-11-18)

Client only; no migration, no edge function, no screen change. The sixth cut on the Bill Customer window, row 7 of the *Remaining cuts* table in `docs/SEND_RECORD_INVOICE_MODAL_ARCHITECTURE.md`. Unlike the five before it, this one is a rewrite of a repeated wrapper, not a move.

## What shipped

- **`BillCustomerDisclosure.tsx`** (79 lines) — one disclosure: a press with a caret, a title and a summary, and under it the region panel the press opens. The panel stays in the page while closed (`hidden`), so what is typed in it is kept. The open state is the caller's, since the line and memo disclosures stay open from tab to tab.
- The seven places that wrote that wrapper out by hand now use it: the line item override, memo and footer of `BillCustomerStripeModifications.tsx` (388 → 286 lines) and of `BillCustomerPhysicalModifications.tsx` (360 → 258), and HouseCall Pro's memo in `SendRecordInvoiceModal.tsx` (3,248 → 3,216). The rewrite was done by script over the exact repeated markup; each panel's contents are untouched.
- HouseCall Pro's memo stands alone, so it passes its own gaps (`toggleMarginBottom`, `panelMarginBottom`); the cards stack tight, the default.

No submit path, effect, state, RPC or edge call was touched. `supabase/` is untouched.

## Proof it changes nothing on screen

The same throwaway dump as v2.7733 (62 states across 12 scenarios, with every disclosure of both cards and HouseCall Pro's memo closed, open and typed in) is byte-identical before and after the rewrite: the same ids, the same `aria-expanded` / `aria-controls` / `aria-labelledby`, the same inline styles in the same order.
