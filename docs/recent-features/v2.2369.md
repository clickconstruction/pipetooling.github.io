# v2.2369 — Assign book entries without retyping the row name (2026-08-26)

Estimator request (Wendi): clicking **assign…** on a Workbench (Pricing → New)
takeoff row seeded the book search with the whole fixture name — `ft of 2" Demo
Water Line` — and the filter required that entire phrase as a substring of a
book entry's name. Book entries are named for the material (`feet of water
line`, `2" Schedule 80`), so the seed matched nothing and every row meant
manual deleting/retyping.

Two changes, both kernel-backed:

- **Seed without the unit prefix** — `stripCountRowUnitPrefix` added to
  `src/lib/bids/countRowUnit.ts` (the one place that reads the name
  convention): drops `[Group]`, `ft/feet/lin ft of`, `px of`, `sq ft of`
  prefixes; unprefixed names (fixture tags like `FT-1`, `112 - MOP SINK`) pass
  through unchanged. Trailing `PER FT` stays.
- **Word-by-word ranked matching** — new kernel
  `src/lib/bids/priceBookAssignSearch.ts` (`seedPricingAssignmentSearch`,
  `filterPriceBookEntries`): an entry qualifies when any search word appears in
  its name; all-words matches rank first, then most-words, then A→Z. The
  Workbench dropdown keeps its 12-entry cap; the Old view's "Search or
  assign..." input uses the same filter uncapped (it scrolls). A single-word
  search selects exactly what the old substring filter did; empty search still
  lists entries in book order.

Wired in `src/components/bids/BidsPricingTab.tsx` (both dropdown sites).
Tests: `src/lib/bids/priceBookAssignSearch.test.ts`. Help guide updated:
`price-a-bid-with-the-workbench.md` ("Price from the book").
