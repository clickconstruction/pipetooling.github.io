# v2.4036 — Pricing → Supply house list: a second quote link is a fresh one (2026-09-28)

Client only; no migration, no edge function. A fix the quote-window smokes found (v2.4022).

## The bug

After one **Copy with quote link**, the next one — on the same bid, for any house — re-copied the first link and wrote no request row. `PricingQuoteModals` keeps the Supply house list mounted and only toggles `open`; the open effect reset the filter, the picks, the house and the needed-by date, but not the quote-link lane. The lane stayed at `minted` with the old draft, so `copyWithQuoteLink` reused the draft (old token, old house, old scope) and the insert was refused as illegal in that state — silently: no toast, no chip update, the window stayed open.

The estimator would paste house B a link that belongs to house A's request. House B's prices would land on A's request, and B would have no request at all.

## The fix

`src/components/bids/PrepareFixtureCopyModal.tsx` — every open resets the lane to `idle`, drops the draft and clears the busy flag, beside the resets it already did.

## Tests

`PrepareFixtureCopyModal.render.test.tsx` — 1 added (11): mint for Ferguson, close, reopen as the parent does, pick National Wholesale Supply, copy: a second row is written for the new house with a new token, and the clipboard carries that token. It fails on the old component.
