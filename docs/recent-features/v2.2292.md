## Out-of-band storage setup (run once in Dashboard → SQL editor)

Storage schema objects are not tracked by the migration ledger (same as `estimate-acceptor-signatures`, `contract-signer-signatures`, `hr-files`). After `db push`, run:

```sql
insert into storage.buckets (id, name, public)
values ('estimate-field-photos', 'estimate-field-photos', false)
on conflict (id) do nothing;

drop policy if exists "estimate_field_photos_read" on storage.objects;
create policy "estimate_field_photos_read" on storage.objects
  for select to authenticated
  using (bucket_id = 'estimate-field-photos');

drop policy if exists "estimate_field_photos_upload" on storage.objects;
create policy "estimate_field_photos_upload" on storage.objects
  for insert to authenticated
  with check (bucket_id = 'estimate-field-photos' and owner = auth.uid());
```

Read access is signed-URL based from the client (same pattern as signature images); upload happens from the wizard with the user's JWT, so `owner = auth.uid()` holds. Table-level RLS on `estimate_field_photos` is what scopes which photos a user can list.
