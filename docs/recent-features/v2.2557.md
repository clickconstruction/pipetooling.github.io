# v2.2557 — Late chip on the job-week grid (2026-08-31)

The deferred third Late-chip surface. `ScheduleDispatchGrid` gains an optional
`latenessByCell` prop (chip suppressed under time-off chips, same as the hub
cells); `ScheduleDispatchJobWeek` feeds it.

- **One definition everywhere (the product decision)**: lateness stays GLOBAL —
  the person's earliest block across ALL jobs that day vs their first clock-in.
  The job-week view's own blocks are job-scoped and would miscall anyone whose
  day started on another job, so `refreshLateness` fetches the week's blocks
  via `fetchScheduleBlocksForRange` (all jobs, RLS-filtered) + the lane users'
  clock-ins, then filters to lane users before the kernel. Verified in dev: a
  person 2h55m late against a different job's 9:00 start shows correctly on
  this job's week.
- Receipts on this surface omit the job label (the range fetch doesn't join
  job titles); scheduled time, clock-in, exact minutes, and grace all present.
- Quickfill's grid usage is untouched (optional prop, not passed).
