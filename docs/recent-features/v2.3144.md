# v2.3144 — Superintendent Jobs on the Dashboard: assigned projects only, active jobs only (2026-09-08)

Migration `20260908050000_superintendent_dashboard_jobs_assigned_only.sql`. Follow-through on v2.2836 (journey map J31): that PR removed the `master_superintendents` adoption branch from every project-access helper but not from the Dashboard RPC `list_superintendent_jobs_for_dashboard()`, which still had `… OR EXISTS (master_superintendents …)`. Adoption has been company-wide since v2.921 (`sync_company_access_grants()`), so the branch meant "every superintendent sees every project-linked job" — on the Dashboard **Superintendent Jobs** section (`useDashboardAssignedJobs` → `DashboardSuperintendentJobsSection`) and, since v2.3131, on the **Your jobs on a map** card, which feeds from the same rows.

## The RPC

- `WHERE` keeps only the `project_superintendents` branch — the same predicate the v2.2836 helpers use for superintendents (`user_assigned_to_project_as_superintendent`). Body otherwise verbatim from `20260722258000`.
- Filters `jl.status IN ('waiting', 'working')` like `list_assigned_jobs_for_dashboard` — billed / paid jobs no longer sit in the field list or on the map.
- Appends `jl.status::text AS status` as the last column. `DashboardTeamAssignedJobRow` already has optional `status`, so no client change is needed; the map kernel (`dashboardJobsMap.ts`) now colors superintendent pins from the real status instead of defaulting a status-less row to waiting. `DROP` + `CREATE` because the return type changed; grants re-issued.

## Docs

`docs/ACCESS_CONTROL.md` superintendent section (adoption list no longer says "dashboards"; new Dashboard bullet) and the Dashboard matrix row for the map card. `src/types/database.ts` is regenerated after the push, not hand-edited (the client casts the RPC rows through the row type).
