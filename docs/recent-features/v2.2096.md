# v2.2096 — Checklist reminders opened up: presets, reachability + email fallback, escalation, day-before (2026-08-22)

The Add/Edit checklist modals' dev-only "Advanced — reminders" fold (raw time input + today_only/today_and_overdue dropdown) becomes an open **Remind** section, and the reminder cron grows three behaviors. Mockup: claude.ai/code/artifact/8b45fd54-8c35-4c3b-b864-76bd122e4331

**Migration `20260822162303_checklist_reminder_upgrades.sql`** — `checklist_items.remind_day_before boolean NOT NULL DEFAULT false` + `checklist_items.escalate_after_days integer` (CHECK ≥1, NULL = never). Additive; no new table.

**Kernel** `src/lib/checklistReminderOptions.ts` (+ tests): `REMINDER_PRESETS` (Morning 7:00 / Midday 12:00 / End of day 4:00), `scopeFromDaily`/`dailyFromScope` (the scope dropdown became one "keep reminding daily" checkbox, legacy null scope reads as daily), `reminderTimeLabel`, `assigneeListLabel`, `reminderSummary` (the green one-liner), `dayBeforeApplicable` (repeat always; dated only when ahead; today never).

**Modals** (`ChecklistAddModal.tsx`, `ChecklistItemEditModal.tsx`):
- Section un-gated from dev — every role that can open the modal can set reminders.
- Preset chips + Custom… time; plain-words checkboxes (daily-until-done default ON; day-before; "Still not done after N days? Remind me too" with 1–30 day input).
- **Reachability line** (dev/master/assistant-like — the roles with `push_subscriptions` SELECT policy): per assignee, "📱 phone alert" or "✉️ email — no phone alerts set up" (client queries `push_subscriptions` for the selected assignee ids).
- Green summary restates the plan; the old "What each option means" explainer modal is deleted.
- Inserts/updates cast the two new columns until `gen-types:linked` reruns post-`db push` (remove casts then).

**Edge function `send-scheduled-reminders`** (redeploy required):
- Per-user **buckets**: due/overdue (assignees, per scope), due-tomorrow (assignees, `remind_day_before` items), escalated (creator `created_by_user_id`, instances ≥ `escalate_after_days` past due). One grouped message joins the non-empty parts (" · ").
- **Email fallback**: a user with zero push devices (or all pushes failing) gets the same body via Resend (`team@noreply.pipetooling.com`); `notification_history.channel` logs `'email'`; response adds `email_fallbacks`.

**Deploy order**: merge → `supabase db push` (before the Pages deploy finishes — the new client writes the new columns and the edit modal selects them) → `npm run gen-types:linked` (+ drop the two casts) → `supabase functions deploy send-scheduled-reminders`.

Help guide `schedule-a-task-or-make-it-repeat.md` gains a "Remind" section.
