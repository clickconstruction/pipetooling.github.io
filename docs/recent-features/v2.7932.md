# v2.7932 — Documents: a waiting agreement can be sent again from its own line (2026-11-19)

Punch list #376, the second train, PR 1 of three: a waiting line acts where it sits. The tab was a read with doors. The owner asked on 2026-11-19 for the Agreements section to be finished, so the office manages a paper there and does not only find it. Nothing leaves People → Contracts. No migration and no edge function change.

## What is new

- **Send again** and **Copy the signing link** on a staff, sub or partner line that waits on a signature (`agreementCanBeSentAgain` in the new `src/lib/documents/agreementsActs.ts`). A trade company's paper keeps its GC door, since it goes out with its trade email in GC mode.
- **Send again** opens the Send for signature window on that paper, with the person's address read from the roster (`readPersonPaperSendFacts`). The window says the paper goes out again and that the link sent before stops working. Its button reads **Send the email again**.
- **Copy the signing link** asks first (*This makes a new signing link for Priya. The link sent before stops working. Nothing is emailed.*, button **Make and copy the link**), then calls `send-contract-for-signature` in link mode and puts the link on the clipboard. A closed clipboard shows the link in a window to copy by hand.
- **A job contract that waits opens its Contract window** (`agreementOpensContractWindow`), where **Resend email**, **Void & redo** and **File the signed copy** already are. It used to open a read-only preview.
- The list reads again after each act, and the count on **Waiting on a signature** with it.

## One sender, lifted and not copied

People → Contracts held the Send for signature window and its send inline. Both are now shared files, and People mounts them with the same words and the same behaviour:

- `src/components/contracts/ContractSendWindow.tsx`: the window. It holds the address, the subject, the opening words, the preview and the send.
- `src/lib/contracts/personPaperSendIo.ts`: `sendPersonPaperForSignature` (email mode or link mode), `materializeQuickSendRow` (the write a quick-send pick defers until Send email) and the portal read behind the preview's band.
- `src/lib/contracts/personPaperSend.ts`: the rules. The default address, the one roster person a name finds, the sender, the address check and the toast.

`PeopleContractsTab.tsx` lost about 370 lines and gained the mount. The lift was done by a script, so a rebase over another change to that file re-runs it.

## Choices worth knowing

- **Why the preview was kept for a voided contract.** The Contract window opens on the job's live contract or a new draft, never on a voided record. So a voided line still opens the page that went out. Only that reason holds: a contract that waits *is* the job's live contract, so the window is right for it.
- **Their paper** that is not signed keeps the preview too. It is not one of the window's own rows.
- **A confirm before a new link.** Link mode and email mode both mint a new token, so the email already in the signer's inbox stops working. The copy press says so before anything is made. Send again says it in the window.
- **The acts show under the Search tab too**, since it mounts the same list.
