## The change

- **[`devMcpWrites.ts`](../../supabase/functions/_shared/devMcpWrites.ts)** (new, pure) — `WRITE_VERBS`: five verbs over three RPC names, fixed here and nowhere else (`cost_batch_apply`, `cost_batch_revert`, `dev_hr_entry_write`); `writeRpcBody` (the POST each verb becomes, refusing in words when the input is not the RPC's shape — apply needs `plan_hash`, revert needs a uuid and a reason); `planHash` — sha256 over the canonical payload plus `planCommitment`: for a cost batch the op count, the money by job and each op's seq, kind and **before** image (never the after images, which carry the dry run's own ids and timestamps); for an HR entry the whole reply less the flag. `planReply` puts the hash and the next step first; `planMismatch` says *Nothing written*.
- **[`dev-mcp/index.ts`](../../supabase/functions/dev-mcp/index.ts)** 0.4.0 — `restPost`, a second path reached only from the five verbs' branch, as the dev. `plan_` POSTs `p_dry_run = true`; `apply_` POSTs the dry run **again**, hashes it, and writes only when it equals the quoted hash; `revert_` is one POST. `view_as` refuses a write verb before resolving its target; the branch also refuses any non-dev identity. `whoami` names the verbs and the rule; the instructions say plan → apply and "write only what the person asked for".
- **Migration [`20260922102017_dev_hr_entry_write.sql`](../migrations/20260922102017_dev_hr_entry_write.md)** — `dev_hr_entry_write(p, p_dry_run)`: dev-gated definer, calls the live `hr_agent_write` with `author_label` overwritten by the dev's name, dry run by the same private-SQLSTATE unwind `cost_batch_apply` uses.
- Docs: `dev-mcp/README.md` (the idea, the verbs, what is refused), `EDGE_FUNCTIONS.md` → dev-mcp, `COST_BATCHES.md`, `HR_FILES.md`, `ACCESS_CONTROL.md`, the guide *connect my coding agent to PipeTooling*, the to-do.

## Why the hash is re-derived, not looked up

The brief said to keep the plan's hash in the plan call's log row and look it up within ten minutes. Re-running the dry run at apply time is strictly better: no table, no clock, and a world that moved under the plan (an allocation changed between plan and apply) changes the before images, so the hash no longer matches and nothing is written — a log lookup would have applied it. The cost is one extra dry run per apply, which is the RPC's own validation path anyway.
