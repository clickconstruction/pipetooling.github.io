## Why

Without a customer-level default, Done Right Foundation's ~200 jobs a year would each need the *Show it on their statement* tick — a chore, not a feature. This is the third layer the plan named: the GC's card, the job's memory, the bill's stamp; each only pre-fills the next.

## What shipped

- **`customers.sees_customer_bills`** and the **Sees their customers' bills by default** box on Edit customer, under *Pays as GC by default*, with the same voice.
- **Kernel** `shouldDefaultShowOtherParty({ gc, customerId, current })` in [`billVisibility.ts`](../../src/lib/jobs/billVisibility.ts) (+1 test): true only when the GC's card carries the flag, the GC is not the job's customer row, and the memory is still off — the mirror of `shouldDefaultBillsToGc`.
- **New Job** ([`JobFormModal`](../../src/components/jobs/JobFormModal.tsx)): the once-per-GC-pick effect that already flips *Bills go to* now also switches a **new** job's memory on; the create payload carries `show_bills_to_other_party`. A saved job is never touched by the card — its Edit-tab *Show <GC>* row and each bill's stamp decide. Both customers selects name the column.
- **Data**: [`scripts/sweeps/share-this-bill-done-right-repairs-2026-09-13.sql`](../../scripts/sweeps/share-this-bill-done-right-repairs-2026-09-13.sql) (dry run / rollback pattern; the owner runs the committing pass) — flags Done Right, switches the memory on for its open owner-paid jobs, and stamps their billed, unpaid invoices `gc` (never a pretest, never a typed recipient, never a paid job), then reads back what the portal will list. Prod on 2026-09-13 holds **one** open owner-paid job under a distinct GC and no billed one, so today the read-back is empty; the script is for the day the next repair bills.
