# v2.7486 — Reserve stickers: the preview no longer reads as a sticker with no link (2026-11-16)

Punch list #329, the second PR of the owner's word of 2026-11-16 (the first is v2.7484). He opened the window with Names `G92-200` and read the fold **What the stickers will look like**: six strips, G92 to G97, each over `PRTS.CO/B/0000-0000`. He took that as the window printing stickers with no link. The line that said the code was a sample sat under the strips, in grey, below the *and 103 more* row. Client only, no migration.

## What changed

- **The stand-in.** `STICKER_SAMPLE_CODE` is eight X's, `XXXX-XXXX` on the strip (`STICKER_SAMPLE_WORDS`). X's read as a place to be filled where zeros read as an empty link. A sticker's code is cut from hex, so no code is ever all X's and a scan of a preview strip opens nothing. Eight characters still, so the QR's squares and the strip's length are the ones that print.
- **The line, over the strips.** `STICKER_PREVIEW_CODE_WORDS`: *Each sticker gets its own link when it prints. XXXX-XXXX stands in for it here.* A named run's line opens with *The names are the run's own.* It is the fold's one line in the strong colour, set off by a rule, between the head line and the first strip, with the stand-in kept on one line. The grey line under the strips is gone, moved and not repeated.
- **A run with no names** reads *1 sticker of 200.* and *and 199 more, each with its own link*, where it read *with a sample code* and *its own code*.
- The guide's paragraph on the fold says the same.

## Why the real link is not drawn before the press

The map said a run's numbers are given at the mint and never shown ahead, since a range read before the lock could be another session's. That was about the running number, which no strip has carried since v2.7438. A code needs no lock: it is the first eight characters of the sticker's own random id. So there are three honest ways to draw a real link, and the first is what is built:

1. **Given at the press, shown after it (built).** The press reserves and prints in one. Before it, the fold draws the shape with a stand-in and says so. After it, the window draws every strip with its own link and says the stickers are reserved. Nothing is ever reserved that was not printed.
2. **Picked on the screen, made real by the press.** The window makes the stickers' ids itself, draws their links in the fold, and sends them with the run; `mint_sticker_run` takes them and cuts another only where one is taken. The fold then shows the very links the press will print. It needs a migration to the mint function and its trigger, and the links are not held until the press: close the window and open it again, and the fold shows other links.
3. **Reserve first, print second.** A press makes the run, the window shows its real links, a second press prints. The links are held from the first press. It leaves runs that were reserved and never printed, whose names then hold the next run's press, so it needs a way to release a run as well. A migration and a new write.

The pick is 1. If the owner wants to see the links before the tape moves, 2 is the one to build: it shows them without leaving a run nobody printed.
