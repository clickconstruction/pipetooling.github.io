# v2.4246 — Forms that save as you type wait for a finished date (2026-09-30)

The follow-up to [v2.4241](./v2.4241.md), whose "Left alone on purpose" list this closes: the five screens that save on a debounce. A date box reports a date on every key that completes one, so the year "2026" arrives as `0002-…`, `0020-…`, `0202-…`, `2026-…`, and a form that saves 800–1500 ms after the last change wrote whichever one it held when the typist paused. The next debounce wrote the finished year, so the bad date stayed only when the form was closed mid-year — or when the year was typed as two digits (`26` → `0026-…`), which never becomes a finished date on its own.

One rule for every gate: a half-typed date is never turned into null. On these screens the payload is also the dirty check, or is written as a whole row or a whole JSON object, so null would erase the saved date while the new one is typed. The date is left out of the write, or the write waits.

- [`autosaveDateHold.ts`](../../src/lib/autosaveDateHold.ts) — `isUnfinishedDate(value)` (something is in the box and it is not `isPlausibleDate`; an empty box is a cleared date, not an unfinished one), `heldDatesToTell(told, held)` (a held box is said once, not on every pause of a slow typist) and `draftHeldByDateMessage(year)`. The toast is v2.4241's `unfinishedDateMessage`.

The five gates:

1. **Job contract** ([`JobContractModal.tsx`](../../src/components/jobs/JobContractModal.tsx), kernel `jobContractDatesUnfinished` in `jobContractDocument.ts`). Start and completion ride inside the one `fields` object, so the draft autosave waits while either is unfinished. After the same 800 ms the status line under the paper reads *Not saved: a date is not finished. Type the year in full, like 2026.* in red; the finished year saves the draft with everything that waited.
2. **Lien waiver** ([`LienReleaseModal.tsx`](../../src/components/jobs/LienReleaseModal.tsx), kernel `lienWaiverDatesUnfinished` in `lienWaiverRelease.ts`). Same shape: through and signature dates are columns and ride inside `fields`. The through date counts only on a form type that has one — a final waiver hides that box, and a value left in it must not hold a draft nobody can fix.
3. **Edit Bid** ([`useBidEditController.ts`](../../src/hooks/useBidEditController.ts) `autosaveBid`, kernel `holdUnfinishedBidDates` in `bidUpdatePrune.ts`). After the prune, `bid_due_date` (with `bid_due_time`, its prune group), `estimated_job_start_date` and `design_drawing_plan_date` leave the update when unfinished; every other changed field saves. Not through `enabled`: a disabled slice makes the close guard report clean and drops the other edits. `markSaved` records the held box at its last saved value, not the half-typed one, so the next prune still reads the box as changed. `bidFormPayload.ts` is untouched — Create builds its row from it.
4. **Payments** ([`jobFormSliceWrites.ts`](../../src/lib/jobs/jobFormSliceWrites.ts) `writeBillingSlice`, kernel `paymentUpsertStatements` in `paymentRowsDiff.ts`). **This one is not the survey's gate.** The survey said to skip the billing write while a Sent or Received date is unfinished. The invoice actions (`useJobFormInvoiceActions`: create invoice, segment invoice, Ready to Bill) call `flushBillingAutosave()` and then read the rows it wrote — *"the link UPDATE below keys on the sequence_order positions the flush wrote"* — so a skipped write would bill from stale line items. Instead the date is left out of its row: rows with every date finished go in the one upsert they always did, and a row with an unfinished date goes in an upsert of its own that carries no such column, so PostgREST's `ON CONFLICT DO UPDATE` does not touch it. One statement per set of dates left out, because a bulk upsert writes the union of its rows' columns and a row missing one is written null. Revenue, line items, amounts, notes and links all save. (Since [v2.4244](./v2.4244.md) a Sent date changed alone starts a billing save, so the Sent box reaches this gate on its own.)
5. **Estimates** ([`estimateDraftPersist.ts`](../../src/lib/estimates/estimateDraftPersist.ts) `buildEstimateDraftPersistPayload`). An unfinished Expires-on leaves `valid_until` out; an unfinished Response-requested-by leaves `change_order_fields` out whole, because the date rides inside it. The builder is shared with Save draft and with the save that precedes a send, so two things follow in [`Estimates.tsx`](../../src/pages/Estimates.tsx): **Send** and **Publish to room** stop with *Finish the "Expires on" date before this goes out* (what is sent is what is saved, and the screen would show a date the customer does not get), and Save draft says the date was not saved instead of *Saved*.

Where only the date waits (3, 4, 5) the form says so with the info toast *That date was not finished, so it was not saved. Type the year in full, like 2026.* — once per box per visit. The change order's version says its details waited too.

Tests: `autosaveDateHold.test.ts`; the kernels in `bidUpdatePrune.test.ts`, `paymentRowsDiff.test.ts`, `jobFormSliceWrites.test.ts`, `estimateDraftPersist.test.ts`, `jobContractDocument.test.ts`, `lienWaiverRelease.test.ts`; the billing slice through `useJobFormAutosaveEngine.render.test.tsx`; Edit Bid through `Bids.render.test.tsx` → *Edit Bid writes*; `JobContractModal.dateHold.render.test.tsx`; and `LienReleaseModal.dateHold.render.test.tsx`, the modal's first render test. With `isUnfinishedDate` forced to false, the new kernel, engine and render cases fail (22 across the eight files run that way).

Walked live in dev (Chromium) on paths that save nothing. Edit Bid, an empty Design Drawing Plan Date: `09/30/2` and a three-second wait left `0002-09-30` in the box, showed the toast, and after a reload the bid's plan date was still empty; closing with the box half typed closed at once. The Contract window on a test job with no contract: `10/15/2` in Start, and after the pause the status line read *Not saved: a date is not finished…*; closed, reloaded, the job still had no contract. Not walked: the lien waiver (its date boxes open full, and a slip onto the month would write a draft), and payments and estimates, where the held pass still writes the rest of the form to production. Those are covered by the tests above. Not seen in Safari.

**Not changed:** any saved date. A bad year already stored on one of these shows in its box; on a contract or a waiver draft it holds the autosave until it is retyped, which the status line says.

**Left alone on purpose:**
- The click paths. The contract's Send and the waiver's Issue / Send for signature write what is on the screen, a half-typed year included, as they did before — the person pressed the button with the date in front of them. Worth a guard of their own: a waiver minted with the year 0026 is locked.
- A box with a part emptied. Typing `0` into the month of a full date fires a change with `''` (measured for v2.4241), which these forms read as a cleared date, and a pause there saves null until the date is finished. A payload cannot tell that from a box emptied on purpose; only the input's `validity.badInput` can, at the box.
- New Bid, New Job and the Quick Estimate wizard save on a click, not a debounce.
- Bid Date Sent: its blur checklist owns when that date is written.
- The year window is `dateBoxEntry.ts`'s 2000–2100. A plan set dated 1998 is held like a half-typed year.
