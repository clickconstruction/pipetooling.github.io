# v2.5400 — Four contract server functions pass their own type check again (2026-10-12)

A type-only fix to `accept-contract`, `complete-contract-form-office`, `contract-form-paper-entry` and `submit-gc-trade-portal`, four of the 24 edge functions a `deno check` sweep of all 151 found failing on 2026-10-12. Each failed on one line, its import of the cursive font's engine. No migration and no screen. Nothing behaves differently.

- **The fault**: each reads `import fontkit from 'https://esm.sh/@pdf-lib/fontkit@1.1.1'` and hands `fontkit` to pdf-lib's `registerFontkit` (through `_shared/fillFormPdf.ts` or `_shared/tradeWaiverPdf.ts`) to embed the signature font. esm.sh answers with `X-TypeScript-Types: …/fontkit.d.ts`, the package's own declarations, which name only `create` and its interfaces, with no default export. So the checker refused the default import (TS1192).
- **What runs**: esm.sh's Deno build (`denonext/fontkit.mjs`) ends in `export{E8 as default}` and exports nothing else. A probe in Deno 2.9.6 read the default import as the fontkit object (`logErrors`, `registerFormat`, `create`), and a namespace import as `{ default }` alone, with no `create`. So the default import is right, and the namespace import the types would accept would hand pdf-lib an object with no `create`.
- **The fix**, in types alone: each import carries `// @ts-expect-error` with the reason on the line above. If esm.sh's types ever gain a default export, the directive itself errors, and the line gets looked at again. A local declaration file through `@deno-types` would type it too, but it adds a file that `scripts/lib/edgeBundle.mjs` never walks, since the walk skips comments and type-only imports.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3): 1 error each on `main`, 0 here.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
- **Deploy**: redeploy the four once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
