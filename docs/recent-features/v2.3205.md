# v2.3205 — Bids on a map: the "no map location" line opens an address sheet; the title toggles the card (2026-09-09)

Client only — no migration. Owner asks on the Bid Board map card (v2.3162): "clicking on the Bids on a map title should also hide and show the map", "remove *follows the search and the trade pill*", and "where it says *53 bids have no map location yet* I would like to click on that and have a modal open where I can enter the address". Mock-up *Bids the Map Can't Place* (with a second-look pass: two reasons not one, the pin lands while you watch, the customer's address as a hint never a default, distance rides along).

## The address sheet

- **Door**: the footer line `N bids have no map location yet · add their addresses` is a link button (`LINK_BUTTON_STYLE`, underlined, 44 px on phones). The old ≤3 inline bid links are gone — the sheet lists everything.
- **Kernel** [`bidBoardMissingAddresses.ts`](../../src/lib/bids/bidBoardMissingAddresses.ts) (+7 tests): `composeMissingAddressRows({ noAddress, unmapped, pins, resolving, keepIds })` — no-address bids first, then the ones the geocoder couldn't place (`checking` while `resolving`), then any bid the person fixed this session that is now a pin (`reason: 'placed'`, so the row shows *Placed ✓ · N mi from the office* instead of vanishing). `customerAddressHint` (the customer's / GC's `address` when it differs), `missingAddressSummary` ("3 without an address · 5 the map couldn't place · 1 placed just now"), `addressDraftReady` (≥ 3 chars and changed), `missingAddressStatus` (the per-row line and tone).
- **Sheet** [`BidBoardMissingAddressesModal.tsx`](../../src/components/bids/BidBoardMissingAddressesModal.tsx): one row per bid — section dot, bid number (lights the row and closes the sheet), project, GC, due; the address input (Enter saves); **Save** (enabled only when the draft changed); the status line; **Check on Google Maps ↗** for the *draft* (`bidBoardMapDirectionsUrl`); **Edit bid**; the customer-address hint with **Use it** (fills the box only). Bottom sheet on phones.
- **Save** (in [`BidBoardMapCard.tsx`](../../src/components/bids/BidBoardMapCard.tsx), `saveAddress`): `bids.address` via `withSupabaseRetry` + `bidUpdateRefused` (RLS refusals toast, never silently no-op); a blank `distance_from_office` fills from the new address through `computeBidDistanceToOffice` (the v2.3142 bid-form rule — routed miles, straight-line estimate fallback; a typed number is never overwritten); then `onReloadBids()` (new card prop, from the board's existing `onReloadBids`) so the board rows, the map's address list and the geocoder pick the change up. Fixed ids are kept in `fixedIds` for the session.

## The title toggle

The `h3` wraps a button on the same `toggleHidden` as the corner link (`aria-expanded`, *Hide the map* / *Show the map* titles, 44 px on phones). The muted "follows the search and the trade pill" span is removed.

## Tests

`bidBoardMissingAddresses.test.ts` (composition order, checking state, dedupe, customer hint, summary, draft rule, placed distance line); `BidBoardMapCard.render.test.tsx` — the unplaced-bid test now opens the sheet (reason line, prefilled input, bid-number focus closes it), plus the title-toggle case; the test mocks `ToastContext`.

## Verified live (dev, port 5183, prod data)

Bid Board → map card: the line reads "53 bids have no map location yet · add their addresses"; the sheet opens with 44 without an address first and 9 the map couldn't place; the customer hint shows on residential bids; Save writes the address (and filled a blank distance), the toast names the miles, the row flips to *Placed ✓* once the pin lands.
