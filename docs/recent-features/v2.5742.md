# v2.5742 — Robots: the setup command brings its own Node, and is right wherever it lands (2026-10-22)

The owner's Mac Mini, the first Mac set up for the rounds (punch list #142, v2.5735): it had no Node, so **Set up on this Mac**'s command stopped at its first line — and that line's `exit 1` ended the Terminal window's shell, leaving "[Process completed]" as the only word. Before that the command had been pasted into Claude Code, whose session read a command that would quit Claude under it and offered its own rewrite. The owner's call: the command the app serves should install Node itself and cover every such case, so a setup is seamless for whoever does the next one.

- **The command brings its own Node** (`buildDesktopSetupCommandFromCode`, `desktopKickoff.ts`). The shell prelude takes the Mac's own `node` when it is 18+, else one a previous run fetched, else it fetches the newest patch of `SETUP_NODE_LINE` (`v24`, one constant to bump) from nodejs.org's `latest-v24.x/` door: the chip from `sysctl hw.optional.arm64`, the tarball named by `SHASUMS256.txt`, verified with `shasum -a 256 -c`, unpacked into `~/Library/Application Support/ClickTooling/node`. No installer, no admin password, nothing on the PATH. **The connector is written by absolute paths**: `command` is that Node binary (realpath), `args[0]` npm's `npx-cli.js` beside it, and the entry's `env.PATH` puts that Node's bin first — a Dock-launched Claude has no shell PATH, and the fetched Node is on nobody's. Setups made before keep their `npx` entry; only new setups take the new shape.
- **It never ends the shell.** No `exit` in the interactive shell, in this command or the key-based one: a miss prints one plain line (what happened, press **Set up on this Mac** again for a fresh command) and the heredoc is skipped, so the Terminal window stays. The code is checked for the Claude app (`open -Ra Claude`) before it is spent.
- **Pasted into Claude Code, it still works.** Under `CLAUDECODE` the script skips quitting and reopening Claude (which would kill the session running it), writes the config, copies the kickoff and says *Now quit Claude with Cmd+Q and open it again … The kickoff is on your clipboard.* Both paths also leave a copy at `~/Library/Application Support/ClickTooling/last-kickoff.md`, for a clipboard lost before the paste. The command's first line says as much to whoever, or whatever, reads it.
- **Words**: the dialog's intro, step 2 and step 3; the guides *run the robot estimator from the Claude app* and *get supply-house prices on a bid*; the kickoff docs `desktop-operator.md` and `pricing-operator.md` (briefs regenerated — **deploy `twin-setup` and `twin-mcp`**).
- **Tests**: `desktopSetupCommand.run.test.ts` runs the pasted command under bash and zsh against a stand-in Mac (a stub `node` of 16, 20 or none; a stub `curl` that is a fake nodejs.org with real checksums, or down; a corrupt checksum) and runs the Node half against a local stand-in twin-setup (the config shape, other servers kept, the token never printed, the clipboard and the file, the Claude Code branch, a refused code, no Claude app).
