# v2.2401 — Workbench margin brush; Apply-margin column retired (2026-08-27)

Owner-designed via the "Margin Brush" prototype artifact (approved before
build): "to the left of the Solve > we add a paint brush that when clicked …
allows you to put in a margin and the user can click and sweep multiple rows
at one time to apply that margin to them."

`BidsPricingTab.tsx` (Workbench only):

- **Strip control**: 🖌 **Margin ›** (Font Awesome Free brush glyph, CC BY 4.0)
  left of Solve ›. Armed, it unfolds a purple ring — margin input, recent-margin
  chips (loaded one solid purple; same `recentMargins` store as the Old grid's
  Margin mode), ↩ Undo sweep, and ‹ to fold. Arming folds the solver ring
  (one tool at a time); Esc disarms (cancelling any mid-flight stroke).
- **Sweep mechanics**: capture-phase `pointerdown` on the rows container starts
  a stroke (suppressing row clicks/typing while armed), pointer-capture +
  `elementFromPoint` paints every `wb-row-*` the pointer crosses. A paint
  drafts `unitPriceForTargetMargin(cost, count, m)` into `wbPriceDrafts` —
  live totals and the sale cell update for free — and rows tint violet while
  in flight. Pointer-up commits changed rows through the same
  `writeUnitPriceOverrideRow` typed prices use (batch, then one
  `loadBidPricingAssignments`), drops painted rows from any pending solver
  preview, records the margin as a recent, and arms one-level undo
  (`writeUnitPriceOverrideRow` accepts null, so undo restores "unpriced" too).
- **Skips**: fixed-price rows, 📌 held rows (`wbLocks`), no-cost rows.
- **Cursor**: the same brush glyph as a data-URI cursor (hotspot at the
  bristle edge), grid outlined purple, `touchAction: none` while armed so
  touch sweeps work.
- **Apply-margin column removed** from the Workbench grid (added v2.2393; the
  Old view's Margin mode column is untouched, and `applyMarginToSingleRow` /
  the "…" picker remain for it).

Help guide `price-a-bid-with-the-workbench.md` item 5 rewritten for the brush.
