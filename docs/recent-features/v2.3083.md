## Kernel — [`src/lib/jobs/stagePlan.ts`](../../src/lib/jobs/stagePlan.ts) (19 tests)

Pure; every later PR consumes it. `buildStagePlan({ fixtures, windows, orders, sheets, invoices, payments, todayYmd })` returns rows in plan order — Order rows by `sequence_order`, then Any rows, then plain — plus `byFixtureId` so the ① Line Items grid can keep its own order and look each row up. Per row: `number` (Order rows only), `badge` (`done` / `live` / `later` / `any` / `any-done` / `none`), `work` (`none` / `window` / `offered` / `scheduled` / `working` / `inspection` / `passed`, from the window, the fulfilling order and its sheet — a signed order beats an open offer, the same rule as `gcStages.ts`), `draw` (`paid` / `billed` / `ready` / `waits` / `later` / `open` / `none`), the dates behind them, and `stateParts` / `stateLine` — the second line the Bill tab prints (`Stage 2 · on site Sep 9 – 10 · 50% · draw 2 billed Sep 5`, `◆ done Sep 16 · ready to bill`, `not a stage · bills with the final draw`).

The rules it enforces:

- **Done is paid.** An Order row is `done` when its draw is paid (or it passed with no draw to pay); the first row not done is `live` — the headline stage — and the rest are `later`. `headline(plan)` reads "Stage 2 of 4 · Top-out · on site now" and counts Order rows only.
- **Nothing bills out of order.** An Order row that passed inspection is `ready` only when every Order row above it is on an invoice; otherwise `waits` ("draw 2 waits on stage 1"). An Any row is `ready` when its sheet reads inspection called or 100%. A plain row is `later` (with the final draw) on a job with Order rows, `open` on a job without. `billable(plan)` lists the `ready`, uninvoiced, non-zero rows.
- **Never a name.** `gcView(plan)` numbers the shared Order rows 1..M with one `now` (started), one `next` (the only `askable` row — an open ask reads back "You asked for Sep 24 – Oct 2 · we'll confirm", a re-pick "We're picking new days inside the window"), the rest `later` ("After trim & final"); shared Any rows land under `also`. Percent only on the live row, in words (`pctWords`: just started / about a third / about halfway / nearly done). The order input type has no `display_name` field, and the test feeds one in anyway and asserts it never comes out.

Open questions 1–3 in the to-do are built as proposed (done = paid; an Any row is done at the sheet's 100% / inspection called; Offer to GC and bundles go away in PR 4).
