# v2.3577 — Payroll: the Payments view — one row per payment made, sortable (2026-09-17)

The owner, 2026-09-17, on `people?tab=pay_stubs`: *"can I see a view of just the payments made? … I would like to be able to sort in various ways."* Mock-up in `to-dos/pay-run-payments-view/before-after.html`; the owner chose flat + sort with the memo-derived chip (no method field, no band modes) on 2026-09-17. Client only; no writes.

## The view — [`PayRunPaymentsView.tsx`](../../src/components/people/PayRunPaymentsView.tsx)

A third pill on the Payroll tab's *Pay run · Balances* toggle (the same dev-only toggle, `?view=payments` deep-links it): **Payments**. One row per `pay_stub_payments` row joined to its stub — *Paid on · Person · Period (w#) · Amount · Memo · Recorded (who · when) · Stub*. Every header is a sort button with `aria-sort`; the first click opens dates and amounts newest / largest first and text A → Z, the second flips. Window chips *30 d · 90 d · This year · All (N)* (90 d by default; All carries the count from one head query), the name box also matching memo text, a summary line (*121 payments · $61,777.39 in the last 90 days · 14 people · newest Sep 16*) and a total row over what is showing. The window and sort are remembered per device (`localStorage`, fail-soft). *Stub* opens the pay report in the same modal the ledger's View does.

The query is Employment's pay-history one without the person filter (`pay_stub_payments` + `pay_stubs!inner`, `gte('paid_at', windowStart)`), so a 90-day view is one request of a hundred-odd rows and *All* is 337 today.

## The kernel — [`payRunPayments.ts`](../../src/lib/people/payRunPayments.ts)

`paymentWindowStartYmd`, `filterPayRunPayments` (name or memo), `sortPayRunPayments` with `defaultSortDir` and a stable paid-at tiebreak, `payRunPaymentTotals` / `payRunPaymentsSummaryLine`, and `derivePaymentMethod`: a chip read off the memo's first words — *Cash App* in its spellings, *Mercury*, *check*, *client-direct* — and nothing for a note that merely mentions a client. Six tests over the eight real rows the mock-up drew.

`ledgerPayPeriodShortLabel` in `PeoplePayStubsTab` is exported so the Period column reads exactly as the ledger's (*9/6–12 (w37)*).
