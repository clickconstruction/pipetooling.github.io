# v2.3411 — Pipeline: the red "% done" box on billed jobs with no percent (2026-09-14)

Client only; no migration, no edge function.

## Why

Owner, 2026-09-14: "Once a bill has been sent for a job, I would like to see a red box around '% done' on jobs, pipeline when there is no value." Mock-up offered two treatments (A: the box only; B: the box plus a red line naming the send day); the owner chose **B**.

## What shipped

- **Kernel** [`stagesBillSentPctAlert.ts`](../../src/lib/jobs/stagesBillSentPctAlert.ts) (+6 tests): `stagesBillSentPctAlert(job)` returns `{ sentAt, label, title }` or null. Fires when a bill has actually gone out — an invoice in `billed` (a Ready to Bill draft is not a sent bill), or the job itself sits in Billed / Collections (`status = 'billed'`, which older records reach with no invoice row) — and `pct_complete` is null. **A Working job with a break-off bill already sent counts** (the dev-server pass found one: two open invoices on a job still in Working, so the rule keys on the bill, not the section). A typed 0 clears it; paid jobs never flag. `sentAt` is the earliest sent invoice's `billed_at` → `sent_to_customer_at` → `created_at`; the label reads *Bill sent Sep 2 · set % done* in the company calendar (or *Bill sent · set % done* when no date parses).
- **The cell** [`StagesProgressPaymentCell`](../../src/components/jobs/StagesProgressPaymentCell.tsx): a `billSentAlert` prop. Editable: the `% done` input gets a 2px red outline on `--bg-red-tint`, `aria-invalid`, the hover title, and *% done* turns red and bold. Read-only (a viewer without the edit right): an empty red box drawn in place of the blank, so the board reads the same for everyone. Either way one red line under the top row carries the label (`data-bill-sent-alert-line`). +3 render cases.
- **Wiring**: every mount of the cell passes `stagesBillSentPctAlert(job)` — the three job-row mounts in `JobsStagesUnifiedTable` (bare job, bundled job, draft-line row), the Waiting / Working / Paid table (`JobsStagesTable`, so the Working row of a job with a break-off bill out reads the same as its invoice rows in Billed), and both phone card lists in `JobsStagesCardList`.
- Help guide *set a job's progress from the Pipeline board* gains "When the box turns red".

## Decisions taken as proposed in the mock-up (owner can flip)

- Where it shows: wherever a job with a sent bill appears — Billed Awaiting Payment, Collections, and a Working row that already has a break-off bill out. The mock-up said "Billed and Collections only"; the live board showed the Working case and the ask ("once a bill has been sent for a job") covers it.
- "Sent" = an invoice in `billed`, whether Stripe or recorded as sent outside.
- Not counted anywhere (no Dashboard item, no header chip) — the box is the whole signal.
- Not on the Edit Job Billing bar (a different component, `MoneyLifecycleBar`); easy to add if the owner wants the same box there.

## Verified

Kernel suite, the cell's render tests, the Jobs render-smoke neighborhood, release-note + guide drift tests, typecheck, lint, theme check; dev-server pass on Jobs → Pipeline → Billed Awaiting Payment (blank-percent billed rows carry the red box and line; rows with a percent do not).
