# v2.3341 — Bid Costs refresh PR 2: the Cost to win lens (2026-09-11)

Client only. Mockup B of the 2026-09-11 Bid Costs review, stacked on PR 1 (v2.3336, the Pursuit ledger).

## What changed

- **Kernel** [`src/lib/bids/bidCostToWin.ts`](../../src/lib/bids/bidCostToWin.ts) (tests beside it): `costToWinBy` folds the ledger's window rows into one `CostToWinRow` per estimator or per GC — bids (every bid in the group), bids with time, hours, spend, won / lost / open / unsent counts, won and lost value, `hitRateByValue`, `usdPerThousandWon`. Counts and values read every bid; hours and spend only the clocked ones (the bid clock started 2026-03-20, so won work before then has no pursuit time and would otherwise vanish from the hit rate). `costToWinTotal` is the Everyone footer; `costToWinWords` words the tile.
- **Tab** [`BidsBidCostsTab.tsx`](../../src/components/bids/BidsBidCostsTab.tsx): a lens strip (Pursuit · Cost to win); the Cost-to-win view shares the window segment and the robot checkbox, adds a By estimator / By GC toggle, three tiles ($ per $1k won · hit rate by value · bids in the window), the table with an Everyone row. Row click sets the ledger's estimator or GC filter and switches back to Pursuit; the ledger gained a GC chip beside the estimator chip. `showDollars=false` hides Spent bidding and $ per $1k won and reads the first tile in hours.
