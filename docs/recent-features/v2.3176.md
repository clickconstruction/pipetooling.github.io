# v2.3176 — Job Summary: one Job column for number, name and address (2026-09-09)

Client only — no migration, no edge function. Owner's ask on the Jobs → Job Summary table: "I would like the job number, name and address to all be combined into one column. How can we make this look tasteful?" Designed on a mock-up first (artifact *Job Summary, One Job Column*: three options over the real rows from the owner's screenshot); the owner picked **Option A** — number leads, address whispers.

## What it replaces

The row spent three columns and four wrapped lines on `Job #` (caret + `JobIdentityCell`), `Name` (+ the ✂ write-down / ⚑ collections chips) and `Address` before the first dollar figure — about 45% of the row on a laptop, with True % and $/hr scrolling off the right edge.

## What shipped

- **[`JobSummaryJobCell`](../../src/components/jobs/JobSummaryJobCell.tsx)** (new, presentational): a two-column grid — the expand caret, then two lines. Line 1: the standard `JobIdentityCell` (trade pill + J-number), the job name in semibold (`white-space: nowrap`, so a long customer name never breaks mid-name), and the row chips passed as `chips` (write-down when the viewer may see money and the job was agreed down; collections when flagged). Line 2: the address at 0.8rem in `--text-muted`, `text-overflow: ellipsis` past `44ch`, the full address in `title`. Empty name / address render as `—`, as before.
- **[`JobsJobSummaryTab`](../../src/components/jobs/JobsJobSummaryTab.tsx)**: the three headers become one `JobSummarySortHeader label="Job" sortKey="job"` (same sort as the old Job # header — Name and Address were never sortable); the three `<td>`s become one (`minWidth: 23rem`, enough for "plum J754 Lavender Springs Assisted Living" on one line); the detail row `colSpan` 15 → 13; the totals footer's first cell loses its `colSpan={3}`. The `<tr>` keeps its own click / Enter / Space toggle.
- **[`JobSummaryCutByPanel`](../../src/components/jobs/JobSummaryCutByPanel.tsx)** `JobSummaryGroupRow`: the group label cell loses its `colSpan={3}` so the Cut-by subtotal rows still line up under the money columns.
- Not touched: the Days / Timeline / Months / Cycle / Scatter / Capacity / Ahead / Rework views, the CSV export and the print builder (they are built from the data, not the table), the expanded row (its own `Job #` block stays).

## Tests

- `JobSummaryJobCell.render.test.tsx`: number + pill + name + address + chips render on the two lines, the address carries its full text in `title`, the caret follows `expanded`, and empty name / address fall back to `—`.
