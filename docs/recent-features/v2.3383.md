# v2.3383 — Accounts Receivable: the billed-line picker as two-line rows, payer first (2026-09-13)

Client only; no migration, no edge function. Follows the four-PR AR refresh (v2.3379–v2.3382). Owner, on a screenshot of the open picker: "I really don't like how this dropdown works, I do not think it presents well or has good information density." Three mock-ups were offered (two-line rows · a ledger table · grouped by payer); the owner chose the two-line rows with the grouped option's ordering.

## Why

The picker's options were the raw search string — `$250.00 · 1015 · Montolongo Post Test · Arturo Montolongo · 545 Slippery Rock, Cibolo, TX 78108 · 1015 · Billed line · Stripe` — so the job number printed twice, a bill wrapped to four lines, the panel was as narrow as the trigger, and the list was capped at the shared picker's 140px: one bill visible, then scroll. The closed control truncated to *— Select billed lin…* and, after a pick, showed the same string clipped.

## What shipped

- **Kernel [`arBilledLineOptions.ts`](../../src/lib/jobs/arBilledLineOptions.ts)** (+9 tests): `arBilledLineRowParts(t)` → `dollars` · `number` · `title` (job name, or the line's kind when the job has none) · `secondary` (payers not already in the job name, via the new `bankPaymentTargetPayerNames` export from `jobsStagesBoard`, then the address, then `Invoice #2` / `Billed line` / `Job balance` from `arBilledLineKindWords`) · `stripe`; `orderArBilledLineTargets(targets, { payerKeys, amountMatchKeys })` — tiers `payer_match` → `payer` (largest remaining first) → `amount_match` → `other`, stable otherwise; `arBilledLineTriggerText`; `arBilledLineFooterText` (*10 open bills · $28,371.20 unpaid*); `AR_BILLED_LINE_MATCH_ROW_STYLE` (green tint + left stripe).
- **[`ArBilledLineOption`](../../src/components/jobs/ar/ArBilledLineOption.tsx)**: the two-line row as a grid — amount column, `1015 **Montolongo Post Test**` on line one, the muted secondary on line two, *✓ matches this deposit* and/or the `StripeTag` (now exported from `ArPayerMatches`) on the right, every cell placed explicitly (auto-placement seats row-spanning cells first and put the tags in the job column). `ArBilledLineTrigger` is the one-line closed state.
- **[`BankPaymentsModal`](../../src/components/jobs/BankPaymentsModal.tsx)**: `targetSelectOptions` moved below `depositAmountMatchKeys` and built from the ordered targets with `labelContent` / `triggerContent` / `optionStyle`; `label` stays `searchLabel`, so search and the render suites' `Apply allocation` / option names are unchanged. Picker props: `listMinWidthPx={560}`, `listMaxHeightPx={320}` + `fillViewportHeight`, `listOptionPadding="0.45rem 0.75rem"`, `searchPlaceholder="Name, job #, address or amount"`, `listFooter`.
- **[`SearchableSelect`](../../src/components/SearchableSelect.tsx)**, opt-in only: options accept `triggerContent` (closed trigger shows it instead of `labelContent`) and `optionStyle` (merged onto the row unless highlighted); `searchPlaceholder` (default *Search…*) and `listFooter` (rendered under the list while it has rows). Nothing else about the picker changes for its other ~100 call sites.
- Guide *match bank deposits to the bills they pay* describes the rows and the order.

## Verified

Kernel, `jobsStagesBoard`, `SearchableSelect` and the three AR modal render suites (102 tests); typecheck, lint, theme check. Live on the dev server against the AR modal with the Sep 11 deposit selected: rows read amount · number · name / payer · address · line, Stripe tags on the right, the list fills the modal's height and the footer counts the bills.
