# v2.5778 — Quickfill: a Focus view that keeps only the groups with work open (2026-10-23)

Punch list #147, PR 1 of 2 (`to-dos/quickfill-views/`). The owner asked for other ways to present `/quickfill` and named a roller; the to-do drew five and the owner picked Focus first, then the Roller. Read as the dev on 2026-10-23 the page was 28 stations and 20,999 px tall at 1,024 px, about 27 screens, with 13 stations carrying work and 7 at zero. Focus is one rule on the same run: a station with nothing in it folds to one line.

- **The kernel** ([`lib/quickfill/views.ts`](../../src/lib/quickfill/views.ts), [its test](../../src/lib/quickfill/views.test.ts)): `QuickfillView` (`page` | `focus`), `focusBucket` (forced → open; marked within 12 h → fresh; a personal door → door; still loading → open; a reported 0 → zero; no reporter → open, since the page cannot say it is empty), `focusGroups` (the page's order, split four ways), `focusHeadline` (*13 groups with work · 7 at zero · 5 marked today · 3 doors*), `focusHeading` (*7 at zero · still get a ✓* / *5 marked today* / *3 doors · no mark*), `parseQuickfillViewRequest` (`?view=`), and the per-person device memory (`readStoredQuickfillView` / `writeQuickfillView`, the Needs you card's Cards / Walk precedent).
- **The switch** ([`QuickfillViewSwitch.tsx`](../../src/components/quickfill/QuickfillViewSwitch.tsx), [its smoke](../../src/components/quickfill/QuickfillViewSwitch.render.test.tsx)): beside the title in a three-column row, `aria-pressed` on the chosen view; hidden under 640 px, where the round stays.
- **The page** ([`Quickfill.tsx`](../../src/pages/Quickfill.tsx)): `view` state from `?view=`, else the stored choice, else `page`; `focusBucketOf` over the metrics context's live `metrics` (reactive, unlike `getOutstandingCount`), `isCollapsed` and `forceExpandedSections`, handed to the wrappers through [`QuickfillFocusContext`](../../src/components/quickfill/quickfillViewContext.ts) (null on the whole page). In Focus the list is the open stations first, then each folded run under its heading. The list is one flat keyed array under one provider in both views, so a switch reorders the stations and never remounts them (a remount reloads every station and flashes its count). `quickfillSectionBlock(meta, { first })` lets the first open station skip its top divider.
- **The wrapper**: a station the context puts at `zero` or `door` draws the marked strip's layout in grey — *○ Warnings · 0 open · Last marked … · 📈 · ✓ Mark · Open now*, or *› My Inbox · no mark · Open now* — above its usual branches. The ✓ is the same `onMarkUpToDate`; Open now is the same `onOpenNow`, so the station opens in place and the bucket goes to `open`. Note-first stations (Texts, Email, Physical inbox) keep their mark inside and the strip has no ✓.
- **What changes on screen**: nothing until Focus is pressed. Then the dev's page fell from 18,876 px to 8,175 px on the live preview, every station still on the page, every ✓ still reachable.
- **Guide**: *run the office day with Quickfill* § Only the groups with work.
- **Docs**: `QUICKFILL_ARCHITECTURE.md` (the view state and the wrapper's fold), `GLOSSARY.md` → Quickfill (page), the to-do's status.

## Is this the best we can do?

- The to-do asked whether Focus is a view or the page's own rule. It ships as a view because a switch is opt-in and changes nothing for anyone who does not press it; the Roller's PR can make Focus the default for a role once the office has used it.
- The fold reads the station's own count, so a station that reports nothing (Field photos while loading, Jobs Cleanup's two lists) stays open rather than guessed closed. That is the honest side of the rule and costs a few open stations on a quiet day.
- The memory is per device for now, the Needs you card's precedent. The Roller adds `roller_show_done` and a cross-device table in one migration rather than two.
