## Why

The owner answered the open question from PR 4: **Done Right Foundation pays for pretests.** That is a fact about Done Right, not about each of the ~200 pretest jobs the office opens for them — so the customer row says it once and the job form applies it.

## What shipped

- **`customers.gc_pays_by_default boolean NOT NULL DEFAULT false`.** Edit customer gains a **Pays as GC by default** checkbox under the billing email.
- **Kernel** `shouldDefaultBillsToGc({ gc, customerId, current })` in [`billToParty.ts`](../../src/lib/jobs/billToParty.ts) (+2 tests): true only when the GC row carries the flag, the GC is not the job customer row, and the job still sits on the `customer` rule.
- **Job form**: an effect in [`JobFormModal`](../../src/components/jobs/JobFormModal.tsx) judges each newly picked GC id once (a ref remembers the id it was loaded with or last judged, so a saved job's deliberate choice is never overridden, and the judgment waits until the customers list holds the row — a bid import that sets the GC before the list loads still gets its default). Both customers selects carry the column.
- **Data**: [`scripts/sweeps/who-pays-done-right-pretests-2026-09-11.sql`](../../scripts/sweeps/who-pays-done-right-pretests-2026-09-11.sql) marks Done Right's **pretest-priced** GC jobs (`revenue ≤ 450` — the $250 pretest and the $450 pinpoint — or a name saying test / pretest / pinpoint; 197 jobs, $43.6k, all but three paid) as `bill_to_party = gc`, and sets Done Right's `gc_pays_by_default` once the column exists (a `DO` block, so the script runs before or after the push). The 53 repair-priced Done Right jobs (> $450, all paid, $102.7k) stay on the customer rule — the owner has not said who pays repairs. Dry-run/rollback pattern; the owner runs the committing pass (agent writes are refused by the permission classifier).
- Help: `choose-who-gets-the-bill` gains **Make a GC pay by default**; `GLOSSARY.md` "Bills go to" notes the flag.
