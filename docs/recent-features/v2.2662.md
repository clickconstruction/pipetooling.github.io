# v2.2662 — "Open as email" preview in the email template editor (2026-09-03)

Settings → Email templates: the editor modal gains an **Open as email ↗** button beside Test Email. It renders the current (possibly unsaved) subject + body into a standalone light HTML document — From/To/Subject header, house-ish email chrome, `{{variables}}` filled with sample data — and opens it in a new tab via a blob URL (`noopener`; pop-up-blocked → error toast; URL revoked after 60s).

- Kernel: `src/lib/emailPreviewHtml.ts` (`buildEmailPreviewHtml`, `emailPreviewSampleVarsFor`, `isDigestPreviewType`, `EMAIL_PREVIEW_SAMPLE_VARS`) + unit tests. Reuses `renderEmailWording`/`escapeEmailHtml` from `emailWording.ts`, so substitution semantics match the real senders (unknown vars stay visible).
- Digest types (the 9 digests + `gc_statement_scheduled`) get a `{{default_subject}}` sample and an amber-labeled **SAMPLE DATA** table under the intro — their real tables are server-built from live jobs and can't be reproduced client-side. Attachment-bearing types (`lien_release_to_customer`, `hazmat_notice`) show a fake attachment chip.
- Preview document is always light (emails don't follow the app theme) and uses literal hexes intentionally — it's a customer-facing email mock, same class as print surfaces.
- Fidelity note honored in-UI: preview is "sample data" fast loop; the Test Email send stays the byte-for-byte truth.
