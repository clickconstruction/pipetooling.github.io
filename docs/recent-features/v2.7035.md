# v2.7035 — My email: the app leaves no mark in your Gmail (2026-11-12)

A tag copies a conversation into the app whole: each mail as a line, its files, and the raw mail. Nothing about a tagged conversation depends on Gmail afterwards. Yet the tag put the label *Tagged in ClickTooling* on each mail in the person's own box, which reads as a live link that does not exist. The owner asked what happens in the app when a labelled mail is deleted in a mail program. The answer is nothing, and the label is what made the question reasonable. His word, 2026-11-12: undo the label in every user's mail first, *so to our users it looks like we were never there in their email inboxes.*

## What changed

- **Nothing adds the label.** The tag, the follow that brings later mail, the Sent read that places sent mail by itself, and the dev seat's tag all ran through one helper, `labelMails`. It is gone, with the calls that made the label and put it on.
- **Untag makes no Gmail call.** It used to read the conversation's headers and take the label off each mail, and counted the ones it could not as `labelLeft`. The lines are the app's own copies, so the untag now reads the database alone. `labelLeft` is out of the contract.
- **The Tagged list reads the app's own record.** This was not in the brief and would have broken: Tagged was a Gmail search for `label:"Tagged in ClickTooling"`, so deleting the label would have emptied the list. With no search of the person's own, a page is now the person's tagged conversations from `email_tag_threads`, the newest mail first, fifteen conversations a page, each read whole from Gmail and drawn mail by mail. It shows an archived mail too, which the old search (Inbox or Sent) left out. With a search typed, it searches as All does and keeps what is tagged.
- **The Sent read's search drops `-label:`.** A sent mail already on a job is passed by on the database's own fences (the conversation's row, the line's Message-ID), as it already was.
- **The words.** The settings card says *Nothing writes to your Gmail. A tag adds no label and changes no mail.* The guide loses the label line and says the line on the job is a copy that stays if the mail is later deleted in Gmail. The dev seat's verb descriptions no longer mention the label.

## The one-time clean-up

`clearOldLabel` runs at the start of each five-minute follow, so it needs no key and no person:

- It covers every login whose address is on the Workspace's own domain, the office team or not, archived or not. The dev seat tagged out of boxes whose people have no My email tab. A sample, a twin and the walk tester are never asked.
- For each mailbox it lists the labels and, when one is named exactly *Tagged in ClickTooling*, deletes it (`users.labels.delete`). Gmail takes a deleted label off every mail that carried it, so no mail is read or listed.
- Ten mailboxes a run. Each is marked in one `app_settings` row, `my_mail_label_cleanup_v1`, as `deleted`, `none` or `failed` with Google's reason, every address taken out of it. A mailbox Google will not open is asked three times, then left and counted.
- When every mailbox is settled the row is marked finished. Each later run reads that one row and does nothing more. A label of that name someone makes by hand afterwards is theirs.
- A failure in the clean-up is logged and never stops the follow.
- One log line a run, `gmail_mine_label_cleanup`: mailboxes, checked, deleted, none, failed, left, finished. Never an address.

It must ship in the same deploy as the stop. The follow runs every five minutes and would put the label back on later mail otherwise.

**Not touched**: every saved conversation. Each line, file, raw copy and tag row stays. Only the Gmail label goes.

## After this, what the function does to a personal mailbox

It reads. The only call that is not a read is the clean-up's delete, once a mailbox. `gmailMine.run.test.ts` checks this after every one of its cases: any Gmail call that is not a `GET` fails the case unless it is a label delete, and the cases for a tag, an untag, the follow, the Sent read and the Tagged list each assert that there was none at all.

The shared boxes' reader is out of scope and unchanged. `gmail-sync` puts the label *In ClickTooling* on each mail it takes from the bids and team boxes, and makes that label when a box has none. It deletes, archives and marks nothing else.

## Deploys

`gmail-mine` from `main` after the merge. The deploy starts the clean-up in real mailboxes on the next follow run. `dev-mcp` for its verb descriptions. No migration.

## Not verified

- The clean-up has not run against a real mailbox. `users.labels.delete` under the reader's `gmail.modify` scope is as Google documents it, and the function already made labels under that scope.
- The Tagged list was not opened in the live app.

## Found, not fixed

- The Sent read logs Google's refusal whole (`gmail_mine_sent_refused`), and Google's words can carry the mailbox's address. The function's rule is that no log line holds an address.
- The clean-up's code and the `MY_MAIL_GMAIL_LABEL` name should come out once the row says finished. After that the function will hold no call that changes a mailbox at all.
- An untag still mints a Google token at the door though it no longer needs one, so a box whose Workspace account is gone still cannot be untagged.
