# v2.2410 — Scenario-card price copy works across GC packets (2026-08-27)

Follow-up to v2.2405 (flagged there as an observed gap): the Workbench
scenario cards' "copy prices from …" link (`copyPricesIntoViewedScenario`,
`BidsPricingTab.tsx`) computed the source scenario's effective prices with
`computeBidPricingRows({ countRows: pricingCountRows, … })` — the VIEWED
version's count rows — while the source's assignments/custom prices are keyed
to its OWN version's rows (per-version counts since v2.2132). A cross-version
source therefore produced zero priced rows and the copy failed silently
("has no prices to copy" on a scenario visibly full of prices).

- When the source scenario's `bid_version_id` differs from the viewed
  `selectedBidVersionId`, the source version's `bids_count_rows` are loaded
  and the source's per-row prices are computed against THOSE rows.
- Each priced source row is then mapped onto the viewed version's rows with
  `mapCountRowsByFixture` (the v2.2405 kernel — trimmed case-insensitive
  exact fixture-name matches, ambiguous names match nothing) and written
  through `writeUnitPriceOverrideRow` as before.
- The toast reports matched/dropped like v2.2405's `copyBasePriceFromVersion`:
  "Copied N prices — M had no matching row in this packet's counts", and a
  fully-unmatched copy says so instead of pretending the source was empty.
- Same-version sources (and legacy version-less ones) keep the exact old path.
