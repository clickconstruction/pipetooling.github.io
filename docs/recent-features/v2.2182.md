Owner, from the phone: "From this screen I would like to be able to edit tasks." Mockup ("Edit from where it fits") → built as shown.

- **Shared write path** — new [`src/hooks/useTechTreeTaskMutations.ts`](../../src/hooks/useTechTreeTaskMutations.ts): the tab's rename/assignees (`updateTaskInGroup`), Plan staffing (`assignTaskToUser`), ★ pin (`toggleTaskPin`), done/reopen (`toggleTaskDone`, the Map checkbox's rule: staff always, else unlocked + assignee), `canActOnTask`, and the card's thread (`loadInstanceEvents` / `postInstanceComment`) moved verbatim out of `ChecklistTechTreeTab` behind a `getTask` / `isGroupUnlocked` / `reload` seam. The Roadmap tab passes it gated by `canActOnTask`. +2 render tests.
- **Sheet** (`RoadmapTaskContextModal`): new props `canEditStructure`, `currentUserId`, `onChanged`. Its loader became a reusable `load()` that also fetches `pinned_at`, users, and the focus stage's bridge rows; stage-box rows are now buttons ("›", hint line "Tap a task to open it — rename, assign, pin, mark done, add a note") that open the task card over the sheet (z 10050 > 1000; React-event bubbling from the portal is stopped so card clicks don't dismiss the sheet; Esc closes the card first). The sheet uses the same hook; every save reloads the sheet's graph and calls `onChanged`.
- **Review tab**: passes `canEditRoadmapTasks={canEditTechTree}` + `currentUserId`; `onChanged` bumps a `goalsReloadTick` that refetches the Goals ledger so ★ / names / counts are already right when the sheet closes.
