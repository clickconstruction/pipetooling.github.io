# v2.2127 — Roadmap: task-less stages with no prerequisites read "not planned yet" (2026-08-22)

Owner decision from the Roadmap deep-look: on Farm 1, stage #17 "add solar and powerwall to everyones roofs" — no tasks, nothing leading into it — rendered **✓ reached** on the Timeline, a green zone in the Review Goals strip, and "1 done" in the stage ledger, because v2.1913's milestone rule made an empty stage complete once *every* predecessor is complete, which is vacuously true for a root. That conflated *not planned yet* with *achieved*.

- **Rule change**: a task-less stage is a milestone only when at least one stage leads into it. With no predecessors it is **unplanned** — unlocked (nothing gates it) but never complete, so its dependents stay locked until it gets tasks or a predecessor. Stages with tasks and milestones with predecessors are unchanged (the lock-trap fix stays intact).
- **Kernels** (`src/lib/checklistTechTreeGraph.ts`): `computeCompleteGroupIdsWithMilestones` skips empty stages with no incoming edges; new `unplannedGroupIds()` helper. `goalsStageRows` (`roadmapBridge.ts`) gains state `'unplanned'` and `goalsStripRows` drops unplanned stages from `currentStages`; `timelineRows` rows and `goalMilestones` cards carry an `unplanned` flag. Tests updated/added in all four kernels (the old "empty root is vacuously complete" test now asserts the opposite, plus a dependents-stay-locked case).
- **Renders**: Timeline — hollow dashed ◇ + muted "not planned yet" label (footer legend updated); Plan Goals card — "◇ title" with a dashed empty bar and "not planned yet — add tasks, or link a stage into it"; Review Goals strip segment + stage ledger chip — dashed hollow segment, "not planned yet" chip (tooltips say so); task-context modal — same segment + legend entry (only when one exists); Map cluster — dashed "not planned yet" chip in the badge row.
- **Migration** [`20260823031912_roadmap_unplanned_roots.sql`](../migrations/20260823031912_roadmap_unplanned_roots.md): `CREATE OR REPLACE sync_roadmap_to_checklist` — the milestone fixpoint now requires ≥1 incoming edge, mirroring the client. Apply with `supabase db push` after merge; until then the client shows the stage as unplanned while the RPC still treats it as complete (benign — only affects which *dependents* of an empty root materialize; self-heals on push).
