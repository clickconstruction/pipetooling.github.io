# v2.8387 — People → HR: a link to one person opens their file (2026-11-23)

A small fault the walks found and left: a cold load of `/people?tab=hr&person=<people.id>` landed on People → Paperwork → HR with *Pick a person to open their file*, and the address became `/people?tab=hr`. First seen 2026-11-13 (`to-dos/hr-files-five-upgrades.md`), reproduced twice on 2026-11-23. Client only: no migration, no edge function.

## The cause

`PersonDeskDeepLinkHandler`, mounted on every route from Layout, opens the Person Desk for `?person=u:<users.id>` or `?person=p:<people.id>` and then strips `person`, `section` and `flow` from the address. It stripped every `person=`, also one it could not read as a desk key. HR's link carries a bare `people.id`, so the handler took it off before the HR tab read it (and the pay Ledger's name key the same way).

## What changed

- **The desk claims only its own key.** `claimPersonDeskLink` in `src/lib/people/personDeskLink.ts` answers the desk's open and the address without its params, or null when `person` is not `u:` / `p:` + an id. The handler leaves a null alone.
- **HR reads the link once the roster is in.** `readHrPersonLink` in `src/lib/people/hrPersonLink.ts` opens an id that names someone the reader can see. An id that matches no one, or a person the reader may not see, lands on the roster with one line, *No one you can see matches that link. Pick a person from the list.*, and the person leaves the address.
- **The address follows the file.** A press on a name (the roster, the reports queue, the kept plans) writes `person` with `hrPersonParams`, which drops `theme` when the person changes; *‹ All people* on a phone takes both off; leaving HR for another People tab drops them too (`dropHrPersonParams` in `goToPeopleTab`). All writes replace the history entry, as the theme pick already did.
- Help: *keep private employee files* gains *Send a link to one file*.

## Tests

- `hrPersonLink.test.ts`: the desk leaves a bare HR id and a Ledger name key on the address and claims `p:` / `u:` keys with their section and flow; the HR link opens a visible id, reads none, and names an unknown one; the address keeps or drops the theme by person and empties on the way back.
- `PeopleHrTab.render.test.tsx`: a cold load with `person` opens the file and keeps the address; a press on a name writes it; an unknown id draws the line and the roster.
