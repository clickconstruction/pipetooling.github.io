# v2.7841 — Materials on site: put a box change back (2026-11-18)

The seventh PR of the train on seeing what one person does with the material on a site. Client only, and no new table: it writes through the store's own box writes.

## What landed

- **Put it back…** on a box change in the By person look, for a dev. A retire is undone by bringing the box back, a bring-back by retiring it again, a change to the kind, the where line or the words by writing the old value, and a rename by renaming back.
- **Only while it still stands.** `sitePersonActs` works out the way back for each change (`PutBack`) against the box as it reads now: a retire is offered while the box is still retired, an edit while the box still carries the value the edit left, and nothing on a retired box, which takes no edit. An older change under a newer one is not offered, so a put-back never walks over later work.
- **Asked first.** The app's confirm window names the act on its press (*Bring G22 back*). The write is the store's own (`unretireContainer`, `retireContainer`, `editContainer`), so it goes through the same outbox, name rule and triggers as the office's own press, and the trail then holds both changes with who made each.

## The limits

- A part tie or a site price that someone took off is shown in the list and is not put back from here. It is answered again on the site's By part look.
- The put-back is one change at a time.

## Tests

`sitePersonActs.test.ts` (the way back for a retire, a bring-back, each edit and a rename, and when none is offered) and two new cases in `SitePeopleView.render.test.tsx` (a dev is asked and the write is handed to the screen's store; the office is offered nothing, and neither is a dev once the box has changed again).
