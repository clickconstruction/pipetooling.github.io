# v2.7657 — Prospects: New Prospect on an empty lane opens on that lane (2026-11-17)

A fix, written down as quirk 33 when `src/pages/Prospects.tsx` was mapped, and confirmed by the render smoke before it was changed. The owner said to fix it.

**The defect.** An empty lane says *Nobody on Subs yet. New Prospect adds the first sub.* That press called `setNewProspectModalOpen(true)` and nothing else. The header's **New Prospect** button calls `openNewProspect`, which sets the window's kind to the lane's and clears its boxes first. So the empty lane's press opened the window on whatever kind was picked last, a customer on a fresh visit, and kept whatever was left in its boxes.

**The fix.** The press calls `openNewProspect`. `ProspectsFollowUpTab` takes that one function in place of the open flag's setter, so the header's button and the empty lane's press open the window the same way. On a trade filter the press is still **All subs**, unchanged.

**The Dashboard's link** (`?newProspect=true`) is unchanged: it opens the window as it did, on the Customers lane it lands on.

**Proof.** Four new cases in the render smoke, 123 in all: an empty Subs lane, an empty Jobs to GC lane and an empty Customers lane each open the window on their own kind, and an empty lane opens it with clean boxes after something was typed and left. Three of the four fail on the code before the fix.

**Not checked live.** No lane on the live site is empty, and none was emptied to look.
