# v2.6716 — One documents table for people and matters; a text document on a matter is kept as text, rendered and searched (punch list #288, PR 1) (2026-11-08)

Punch list #288 (`to-dos/matter-documents-counsel-only.md`), PR 1 of three. The card's blocker was the owner's pick between a nullable text column beside a matter's file and the one documents table for people and matters that #277 named as the long-term shape; asked on 2026-11-08, the owner said "Shared documents table". Migration `20261108210000_shared_documents.sql` ([`docs/migrations/`](../migrations/20261108210000_shared_documents.md)): push right after the merge, then deploy `legal-portal` and `dev-mcp` (server 0.44.0, behind v2.6712 and v2.6713), then regenerate the types and the catalog.

## What changed

- **The table**: `person_documents` is renamed `documents` and owns a document by `person_id` (the HR file's named documents, as before) or `matter_id` (a matter's text documents); `person_document_revisions` becomes `document_revisions`. The old names stay as read views, so every deployed reader — the HR panel's read by id, `dev_person_doc_write`, `dev_doc_read`, `dev_doc_history` — keeps working unchanged until each moves. The office roles read, add and change the matter rows; devs keep every row; nothing is deleted.
- **A text document on a matter**: `legal_matter_documents.text_document_id` points at the words. The Evidence tab (`LegalMatterDocumentsPanel.tsx`) takes `.md` beside `.txt`, reads a text file's words in the browser when it is dropped (*kept as text · N characters* under the pending row), and `addLegalMatterDocument` writes the `documents` row first, then the Evidence row pointing at it (the file still goes to the bucket); **Read** on the row draws the words under it through `hrDocMarkdownToSafeHtml`; **Remove** archives the words with the row.
- **The firm's portal** (`legal-portal`): each travelling document carries `text` when it has words (a held one's never leave); `LegalFirmMatterView`'s documents table draws **Read here** under the row.
- **The seat** (`dev-mcp` 0.42.0): `plan_matter_document` takes `markdown` in place of `content_base64` (the server makes the `.md` file), and a `.md` or `.txt` sent as bytes — the mail door's text attachments included — is decoded and kept as text; `dev_legal_document_write` names the text's size and sections in the plan and writes both rows at apply.
- **The search**: `dev_case_search`'s `matter_document` source unions a text document's words a section at a time (`hr_doc_sections`), the hit carrying the Evidence row's id and the section; `search_case`'s `read_next` says how to read it on.
- **Words**: the guide *review a collections account before it goes to your attorney* (Documents for the firm), `docs/dev-mcp/README.md`, `docs/EDGE_FUNCTIONS.md` (dev-mcp, legal-portal), `docs/ACCESS_CONTROL.md` (the Legal desk's documents row), `docs/HR_FILES.md` (Named documents), `docs/GLOSSARY.md`, `docs/PEOPLE_TABS_ARCHITECTURE.md`, the card.

## Not here

The counsel-only mark on a matter document (PR 2), the seat's section reads and edits on a matter's text document and the move of `dev_person_doc_write` / `dev_doc_read` / `dev_doc_history` and the seat's own reads onto `documents` (PR 3, once the catalog knows the name). #286 and #287 add columns to the same table in parallel: this migration is pushed only after theirs are on `main`, since their `ALTER TABLE person_documents` would land on the view.
