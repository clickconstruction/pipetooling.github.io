# v2.4302 — Pipeline: the activity box buttons sit under the box (2026-10-01)

Grace, 2026-10-01, with a screenshot of Water Sample Test in Ready to Bill: the **+ Add** and report pills sat on the newest note, so its last words never showed. Her call: keep the box the same height and put the button below it. Mock-up canvas https://claude.ai/artifact/7cCmD7Sh5zmxVmEBFWRQd7 (Now · A · B); option B built. No migration, no edge function.

## What was wrong

[`JobsStagesActivityBox`](../../src/components/jobs/JobsStagesActivityBox.tsx) floated its pills over the box's bottom-right corner and kept a 52 px right gap on the feed for them. That gap was sized for **+ Add** alone; v2.3197 added the report pill beside it (~105 px for both), so the newest note ran under both. The composer bar also slid over the bottom of the box, and the corner expand arrows sat on the end of the top line.

## What changed

- The component's root is now a column: the bordered box (unchanged: 96 px feed cap, two-line clamp per entry) and, under it, a 22 px strip. The feed lost its right gap and the Next line its corner inset — nothing floats over the box.
- The strip: **See all N** on the left (the old corner arrows, same `aria-label="Expand job activity"`, now with the box's note + report count once the feed loads; hidden on an empty box), **+ Add** and the report pill on the right, without the floating shadows. Hover colour is a class in `index.css` (`.stages-activity-see-all`) because inline styles block `:hover`.
- **+ Add** swaps the strip for the composer bar at the same height, so opening it never moves the row.
- Measured live at 1440 px on all 95 loaded boxes before building: median 90 px of dead space under the box, minimum 19; after the change no row's height is set by the box column.

## Tests

`JobsStagesActivityBox.render.test.tsx`: See all names the count and opens the full-page view; an empty box has no See all; the composer takes the strip's place.
