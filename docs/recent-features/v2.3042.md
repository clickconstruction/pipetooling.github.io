# v2.3042 — Test-gap audit, pass 52: the Customer Summary loader gets its first tests (2026-09-07)

Follow-up to v2.3041. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`customerSummaryActivity.ts` (126 lines) is what Dispatch Mode's Customer Summary modal shows: every interaction across a customer's jobs — thread notes, reports, schedule blocks, clock sessions and activity events — tagged with its job and sorted newest first, over at most sixty jobs. One caller, no test; the item mappers and the sort key beside it were tested.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Jobs read newest first for the customer, a row without an id is dropped, and the list is capped at sixty with the `truncated` flag set when more exist. Each job maps to its effective number (HCP, else Click, else an em dash), "Job" for a blank name, a trimmed address, and numeric revenue and payments (null and unparsable → null and zero).
- Every job loads five sources in parallel — notes in creation order with the author join, the role-aware reports RPC, schedule blocks, clock sessions and activity events — and each item is tagged with the job's id, number and address.
- Each source degrades on its own: a failed notes or reports read contributes nothing, and a source pack that returned an error contributes nothing, without failing the load.
- Items are ordered newest first by the shared sort key; a failed jobs read comes back empty with the message; a customer with no jobs loads nothing further.
