# v2.4344 — Change the email someone signs in with (2026-10-01)

PR C of the *Account on the desk* train (canvas `UC4ZYvy8qDy3XLsz41TCM3`, board *After 3*). Stacked on PR B ([v2.4343](v2.4343.md)). One new edge function, **`change-user-email`** — deploy it from `main` right after the merge, then redeploy `dev-mcp` (its catalog lists the new function). No migration.

## What was wrong

The Active Accounts window's Edit → Save wrote `public.users.email` and nothing else. No code changed `auth.users.email`, the address the person actually signs in with (checked 2026-10-01: no trigger, no function). So after an email edit the app showed one address, the login kept the other, and *Send sign-in email* looked the account up by the new address and minted a link for an address with no login behind it.

## The change

- **[`supabase/functions/change-user-email`](../../supabase/functions/change-user-email/index.ts)** (dev only, Bearer + `users.role` like `set-user-password`; `verify_jwt = false` in `config.toml`): checks the address, refuses one another account has (409), moves the login with `auth.admin.updateUserById(… { email, email_confirm: true })` so no confirmation email goes out, writes `public.users.email`, and moves the account's own roster row's email only where it still held the old one. If the app's copy fails, the login is put back. Section in [`EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md#change-user-email).
- **[`_shared/signInEmailChange.ts`](../../supabase/functions/_shared/signInEmailChange.ts)** — the one address rule (`checkSignInEmail`: trimmed, lowercased, shaped like an email; `unchanged` when it is theirs already; `exactIlikePattern`), loaded by the function and the app. Tests in `src/lib/people/signInEmailChange.test.ts` (4).
- **Desk → Access & account → Email → Change…** ([`PersonDeskAccessSection`](../../src/components/personDesk/sections/PersonDeskAccessSection.tsx)): a small window — *Now: …*, **New email**, *They sign in with the new address from now on. The old one stops working.* — that checks the address with the shared rule, then calls `changeSignInEmail` ([`accountWrites.ts`](../../src/lib/people/accountWrites.ts)). The form sets `noValidate` so the app's own words show, not the browser's bubble.
- **The Active Accounts window** ([`useActiveAccountsManagement.saveUserEdits`](../../src/hooks/useActiveAccountsManagement.ts)) sends a changed email through the same function before it saves the rest of the row.
- `dev-mcp` catalog rebuilt (`node scripts/build-dev-mcp-catalog.mjs`). Guide *open a person's desk* names Change….
