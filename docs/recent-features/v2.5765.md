# v2.5765 — Pipeline: scrolling over the % done box no longer changes the number (2026-10-23)

The owner, 2026-10-23, on Jobs → Pipeline: "I don't like that a user can scroll up and scroll down and increase and decrease his number while hovering over the percent complete. Help me disable this scroll to increase and decrease." A focused `<input type="number">` steps on the wheel in every browser, so a person who tapped into the box and then scrolled the Pipeline walked the % up or down without meaning to — and the blur that followed saved it.

- **The fix** (`StagesProgressPaymentCell.tsx`): the box's `onWheel` blurs it, the idiom the Bids labor and sub-labor forms already use. The page scrolls, the value stays what was typed, and the blur commits only a changed value (`updateJobPctComplete` returns at once when the value equals the previous one).
- **Scope**: the % done box is the only number input a Pipeline row draws (the stage bar's % is a drawn tick, the money is text). The same box in Edit Job's money card (`JobFormMoneyCard.tsx`) and the other number inputs around the app are left as they are.
- **Test**: `StagesProgressPaymentCell.render.test.tsx` — a wheel over the focused box drops focus and leaves the number as typed.
