# v2.4429 — Email reports: Save stays in view while you edit a person (2026-10-02)

No migration, no edge function. The item v2.4428 left: in Email reports, the person editor's Save row scrolled with the body.

## What changed

- **The person editor's Save row is pinned.** In [`EmailReportPersonEditor`](../../src/components/jobs/emailReports/EmailReportPersonEditor.tsx) the row of *Save*, *Cancel*, *Send now* and *Remove* is `position: sticky; bottom: 0` (`data-testid="email-report-person-actions"`), opaque, with a rule above it. It sticks to the foot of the window's scrolling body (`email-reports-body`, v2.4428). Nothing was lifted out of the editor.
- **What a save or a send says is in that row.** The error line and the *Send now* result moved inside it. Left above it, a failed save would have written its message under the pinned buttons, off screen.
- **The dock is not this change's.** The live walk found the Dispatch Mode dock drawing over the window's last 60 px, which is where the pinned row sits. [v2.4431](v2.4431.md) fixed that for every window (the dock to 700, this window to 760) and merged first, so this change leaves the window's layer alone.

The schedule editor is left as it is: a name, the weekdays and a time, shorter than any screen it is used on.

## Tests

- `EmailReportPersonEditor.render.test.tsx` (new, 2): *Save*, *Cancel* and *Remove* sit in the sticky row, the row is the editor's last child and holds no field; *Pick a person.* from a refused save shows inside the row.
