# v2.3231 — Job window on a phone: the ✕ is back on screen, the window fills the screen, the tabs wrap (2026-09-10)

Client only; no migration.

## What was wrong

Taunya, on dispatch mode's Schedule from her phone: the job window (Job · Edit · Bill · Costs · History) could not be closed — the top corner was cut off. Measured at 375 px: the tab row (five tabs + *esc to close* + ✕) was 437 px wide inside a 343 px dialog, so the ✕ sat at x = 422–452, past the dialog's right edge and past the viewport, hidden by the dialog's `overflow: hidden`. Escape is not a key a phone has, and the backdrop was a 16 px gutter. The window also sat inside the padded overlay as a rounded card, which is what showed as "the corner is cut off".

## What shipped

`JobWindowModal` gets the same phone treatment the bid window has (`@media (max-width: 640px)` in a scoped stylesheet):

- Full-bleed sheet: overlay padding 0, dialog `max-width / max-height: 100%`, no radius (the safe-area inset moves into the tab row's top padding).
- Tab row wraps and shrinks (`flex-wrap`, tighter tab padding, 0.8 rem), *esc to close* is hidden (no Escape key on a phone), and the ✕ is `margin-left: auto`, larger, on the first row.
- Body pane gets `overscroll-behavior: contain` + momentum scrolling and safe-area bottom padding.
- Desktop unchanged (same DOM; the classes only bite under the media query). Render test unchanged.

Measured after: ✕ at x = 328–367 of 375, visible on every tab including History; a tap on it closes the window.

## Notes for the next session

- History's day grid is ~6,500 px wide inside the pane on a phone; it scrolls sideways under the finger and can feel like the window is stuck. Not changed here — the grid is `ProjectsJobHistoryTab` in single-job mode and deserves its own phone layout.
