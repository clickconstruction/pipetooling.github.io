# v2.6050 — Materials on site: a box photo that waits says every reason (2026-10-29)

Punch list #209. After v2.6049 the waiting photo on test job 972 still read nothing within two cron windows, and with no log in reach the row had to say why. The sweep now writes every reason it hits on the row, not only a missing folder: Drive not set up for the app (`GOOGLE_SERVICE_ACCOUNT_JSON` absent), Drive refusing the app's token, a bucket copy that did not read, a Drive refusal on the upload, a row that did not keep the Drive id. A filed row clears it; every row is tried again each run.

## What changed

- **`photo-save`**: a `fail(row, why)` helper in the box pass writes `fail_why` (cut to 300 characters) and reports; the token mint is caught per run.
- Docs: `docs/EDGE_FUNCTIONS.md` → photo-save, the release note and this fragment.

## Deploy

`supabase functions deploy photo-save`. Within five minutes a waiting photo reads its reason on the phone's box screen and the office panel.
