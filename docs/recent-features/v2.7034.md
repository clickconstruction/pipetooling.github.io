# v2.7034 — Deploy: the build check no longer names the app's bundle (2026-11-12)

Every Pages deploy failed from 18:58 UTC on 2026-11-12. The last good one was the 18:43 run. Merges kept landing on `main` and none reached clicktooling.com.

**Cause.** v2.7007 (First look, PR 4) gave the build a second entry, `show.html`, through `build.rollupOptions.input` in `vite.config.ts`. With two named inputs the app's bundle takes its input's name, so `assets/index-<hash>.js` became `assets/main-<hash>.js`. The build was fine. The deploy's **Verify build output** step in `.github/workflows/deploy.yml` asked `grep -q "assets/index-" dist/index.html`, found nothing, and stopped the job before the upload with *index.html does not reference built assets correctly*.

**Fix.** The step now asks what it means, that the built page loads a script the build made: `grep -qE 'src="/assets/[^"]+\.js"' dist/index.html`. It names no bundle, so a rename cannot fail it again. The check beside it, that the page no longer loads `main.tsx`, is unchanged. Nothing else in the workflow, the service worker, the scripts or the E2E specs reads the bundle's name (searched).

**Why CI did not catch it.** CI's checks do not run `vite build`, and the deploy repeats no checks job, so a change to the build's shape is first met by the deploy itself. `CLAUDE.md` already says to run `npm run build` before merging a change to `vite.config.ts`; a local build passes here too, because the failing line lived in the workflow, not the build. The new test closes that gap for this line.

**Is this the best we can do?** For the outage, yes: one line, checked by meaning. Not done here: the step still does not look at `show.html`, the new entry, so a First look page that came out unbuilt would deploy unnoticed. That is a check for the First look train to add with its own knowledge of the page.

**Tests:** `src/lib/deployVerifyBuildOutput.test.ts` reads the step out of the workflow and holds its pattern to both bundle names, to a page that still points at the source, and to naming no bundle. Proven twice with the step's own script, lifted out of the workflow: on the `index.html` the failed 18:58 run printed, and on the `dist/` of a local `vite build` of this commit. Both times the old script exits 1 and the new one exits 0, and the new one still exits 1 on the unbuilt source page.

No migration, no edge function deploy, no app code.
