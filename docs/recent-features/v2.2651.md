# v2.2651 — RFQ Round 2, Rung E: drop the vendor's file (2026-09-02)

Rung E of `docs/RFQ_ROUND2_PLAN.md` (canvas artboard 9). Vendor replies
as files stop meaning "copy the text out by hand".

- **One pipeline**: a dropped .xlsx / .csv / .pdf becomes plain text that
  lands IN the paste box — visible, editable provenance with a
  `[file: name — N lines]` header — then the existing `parseVendorReply`
  match grid runs. The header line is display-only (never parsed).
- **The extended-price trap, defused** (`extractReplyText.ts`, +4
  tests): sheets carry unit AND extended price columns and the parser
  prefers the last number on a line — the flattener detects the header
  row and DROPS ext/total/amount columns, naming them in the header
  ("dropped Ext Price column (unit prices only)").
- xlsx reads via the exceljs dependency the app already had (first
  sheet, 500-row cap); csv/txt native (quote-aware split); text-layer
  PDFs via lazy-loaded pdf.js (y-grouped lines, 20-page cap); scans get
  an honest "no readable text — copy/paste it for now" (the LLM lane
  stays deferred until real files demand it).
- **Rung-G groundwork**: lines with package wording (all-in / package /
  lot / combo / bundle) wear an amber "one price for several items?"
  hint in the grid.
- Live-tested: a generated vendor xlsx (with an Ext Price column and an
  ALL-IN row) dropped in → unit prices matched ✓ (185.5, not the 742
  extended), package hint fired, meta line stayed out of the grid.
