# v2.3292 — Bids: one cost total everywhere, and the Labor autosave that says why (PR 3 of the Labor refresh) (2026-09-11)

Client only — no migration. Rung 3 of [`to-dos/bids-labor-refresh/`](../../to-dos/bids-labor-refresh/README.md): the two extractions the plan called for before the crew-rate card and the direct-costs section (PR 4) can be built on one number.

## `bidTotalCostBreakdown.ts` — one total

[`computeBidCostBreakdown`](../../src/lib/bids/bidTotalCostBreakdown.ts) (+5 tests) takes the material totals, the labor rate and rows, the distance, the `cost_estimates` row, the count-row count, the five direct-cost tables as one list (`directCostRowsFromTables` for callers holding the tables, or the `cost_estimate_direct_costs` view rows) and the bid's team labor, and returns every part — labor, driving, estimator, travel, team labor, each direct-cost kind, `otherDirectCost`, `laborCostWithDriving` (the Labor page's "Labor total"), `directCost`, `totalCost`.

Before it the arithmetic lived in four places and disagreed: the Workbench counted the five amber tables and team labor; the Pricing print/CSV, the Labor page print and the approval PDF did not. Now:

- [`BidsPricingTab`](../../src/components/bids/BidsPricingTab.tsx) `derivePricingWorkbench` reads the kernel (same fields, same numbers as before); `buildPricingPrintContext` hands the print/CSV the tagged direct-cost rows and the team labor cost.
- [`pricingPage.ts`](../../src/lib/bidDocuments/pricingPage.ts): `buildPricingPrintRows` and `buildPricingCsvForBid` read the kernel; `PricingPrintContext` / `PricingPrintRowsInput` gained optional `directCostRows` + `teamLaborCost`. **The print and CSV totals now include the direct-cost tables and team labor** — the Workbench's number.
- [`costEstimatePage.ts`](../../src/lib/bidDocuments/costEstimatePage.ts) (both materials models): the kernel with the tab's string-box overrides for $/mile and hours per trip; `CostEstimatePrintContext.directCostRows`; [`laborPage.ts`](../../src/lib/bidDocuments/laborPage.ts) prints an **Other direct** line when > 0 and its "Our total cost is" includes it.
- [`approvalPdf.ts`](../../src/lib/bidDocuments/approvalPdf.ts): the Labor page fetches the view and prints the Other direct row; the page-1 margins "cost estimate amount" reads the kernel too — it now counts travel and the direct-cost tables (it counted neither).
- [`bidPricingRowCalculations.ts`](../../src/lib/bidPricingRowCalculations.ts) `costEstimateLaborRowHours` (the Pricing grid's per-row labor) now routes through `laborRowHours` via `normalizeLaborRowCalc`, so task, sub and per-100-ft rows (v2.3291) price the same on the grid as on the Labor tab; `CostEstimateLaborRowCalc` carries optional `kind` / `unit`.

## `costEstimateAutosavePayload.ts` — the autosave as data

[`buildCostEstimateAutosavePayload`](../../src/lib/bids/costEstimateAutosavePayload.ts) (+6 tests) turns the ten string boxes into the `cost_estimates` UPDATE with the tab's defaults, or `{ ok: false, reason }` naming the first bad box. `laborRowAutosaveUpdate` and `stageAmountRowAutosaveUpdate` are the row payloads every writer sends (the debounced effect, `saveLaborRows`, the five direct-cost loops).

The L2 effect in [`BidsLaborTab`](../../src/components/bids/BidsLaborTab.tsx) shrank to debounce + writes. **Architecture quirk #4 is gone**: an invalid box used to `return` with the status stuck on "Saving…"; it now sets `costEstimateAutosaveStatus = 'invalid'` and the footer reads *Not saved — the labor rate must be a number, 0 or more* until the box is fixed, then saves.

## Verified

Kernel + document tests (`vitest` green), typecheck, lint. Live on dev against prod (BP398): a negative labor rate shows *Not saved — …* and writes nothing; a valid rate saves and clears the notice; the Workbench totals are unchanged — see the PR comment.
