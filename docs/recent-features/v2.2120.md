# v2.2120 — Share / Print / CSV default to the ★ (2026-08-23)

F2 of the "Send or Compare" train (review: claude.ai/code/artifact/1d998cbd-10f1-430e-9e82-092e0ae75b88, decision D3b). The Workbench's structure bar, tour step and ★ confirm all promised "the ★ starred scenario is what the customer sees — Cover Letter, Share, and the bid value all use it", but **Share** (`PackageAndSendBidPricingModal`), **Print** (`printPricingPage`) and **CSV** (`downloadPricingCsv`) all took `selectedPricingVersionId` — the card the user last clicked (`viewWorkbenchScenario` deliberately views "without touching what the customer sees", and then Share sent it).

[`BidsPricingTab.tsx`](../../src/components/bids/BidsPricingTab.tsx):
- `requestWithStarCheck(action)` fronts all three. When the viewed scenario ≠ `bids.selected_price_book_version_id`, a chooser dialog ("Send / Print / Export which price?") offers **Customer's price — ★ {name}** (default) or **The one you're viewing — {name}** ("for a teammate to check a scenario. Not customer-facing"). Same scenario → acts immediately, as before.
- Picking ★ does **not** switch the view: `loadScenarioInputs(bidId, starId)` fetches the ★ scenario's entries / assignments / custom prices / submission hides; `packageRowsFromInputs` (same math as `useBidPricingRows.pricingPackageSource`) builds the Share modal's rows (`shareOverride`), and `buildPricingPrintContextFor` overlays them on the print context for Print / CSV. The modal header, audit row (`bid_pricing_package_sends.price_book_version_id`) and the 4-column table all carry the ★'s id and prices.
- Copy: bar, tour and ★ confirm now read "Cover Letter, Share, **Print**, and the bid value all use it" — and it is true.
