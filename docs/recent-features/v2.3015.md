# v2.3015 — Test-gap audit, pass 27: the Projects Forecast loaders get their first tests (2026-09-07)

Follow-up to v2.3014. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`projectsForecastData.ts` (191 lines) is the data layer under **Projects → Forecast** (the All stages and Specific stage tabs): the project-linked jobs with their project name and a single workflow id per project, every step for those workflows in `(workflow, sequence)` order, and the grouping helper the charts read. Three callers, no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Jobs are read newest-HCP-first with the project name joined, restricted to one customer only when asked; no jobs means no workflow read at all.
- One workflow per project: when a project has more than one, the first by id wins, so results are stable across reloads. A job whose project has no workflow yet is dropped, since there is nothing to chart.
- The stage read de-duplicates the workflow ids, asks nothing for an empty list, orders by workflow then sequence, and maps a null result to an empty list.
- The grouping helper keeps first-seen workflow order and each workflow's stage order.
