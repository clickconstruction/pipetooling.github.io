# v2.3654 — dev-mcp 0.3.1: check_edge_boot probes in batches — the platform rate-limits function-to-function calls (2026-09-20)

Found by the first live run of PR 5's verbs ([`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md)), with a dev key the owner issued for the check and revoked after.

## What the live run showed

Every database verb answered on prod: `check_sampler` (1,440 samples, no gaps over 90 s in 24 h, slowest 193 ms), `check_connections` (27 of 160), `check_locks` (no waits; `client_backends: 16` — the definer reads other roles' backends in full, the open question in the brief), `check_migration_ledger` (624, newest `20260921010003`). `view_as` a helper → `403 (42501): dev_health_locks: devs only` — refused by the database, as designed.

`check_edge_boot` did not: **60 of 123 answered, and the last 63 in name order came back "no answer in time"**. The error text behind them was `Rate limit exceeded for function. Retry after 59641ms.` — Supabase refuses an edge function's calls to other functions past about 60 a minute. Both of the "unreachable" functions probed directly answered `200` in under a second. So the verb could never finish in one call, and its report blamed the functions for the platform's refusal.

## The change

- **[`_shared/devMcpHealth.ts`](../../supabase/functions/_shared/devMcpHealth.ts)**: `EDGE_BOOT_BATCH = 50` and `edgeBootBatch(names, after)` — the next batch in name order and the cursor after it; `edgeBootReport` gains `rate_limited` (a `429`, or an error that says *rate limit* — reported as "says nothing about those functions; wait a minute and probe them again", never as unreachable or dead), `total`, `next_after`, and a reading that names the slice probed and how to continue.
- **[`dev-mcp`](../../supabase/functions/dev-mcp/index.ts)** 0.3.1: `check_edge_boot(after?)` probes one batch per call; the tool description tells the agent to follow `next_after` about a minute apart. Three calls cover today's 123.
- Tests: the cursor visits every function once, in order, in three calls and then ends; a rate-limited probe is never counted unreachable; the slice reading.
- Docs: `EDGE_FUNCTIONS.md` → dev-mcp, `dev-mcp/README.md` (the verb row), the to-do — which now records the live results for PRs 3 and 5 and what is still owed (one pass of the batched verb; `get_brief` with a `ptt_` key).

## Deploy

`supabase functions deploy dev-mcp` after merge. No migration, no client change.
