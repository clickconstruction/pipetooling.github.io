# v2.3669 — Contract sweep refresh: "We already have one", the Drive pass in the list, and the contract field on the job (2026-09-21)

The owner, 2026-09-21, on a screenshot of the sweep: *"I don't think this modal is as good as it could be … some of these people do have contracts with us and there should be a field to upload a link to the contract as it is stored in Google Drive. And then in the edit job modal, there should be a field for their contract."* Mock-up first, then "is this the best we can do?", then the build — [`to-dos/contract-sweep-refresh`](../../to-dos/contract-sweep-refresh/README.md) keeps both passes. No migration.

## What was true

Both asks **already existed and could not be found**. The sweep's footer had a small text link, *Already signed? File it*; Edit Job's *Customer Contract* row offered only **Send contract**. Both wrote the link to the job's contract record (`job_contracts.signed_document_url`) through `fileSignedJobContract` — the right home, because the sweep's list, every contract chip, the nudges and Bill Customer read that record. So this adds **no second field on the job**; it makes the existing door first-class, in both places. The pane also asked *how* to get a signature before asking *whether one is needed*.

## The change

- **The first question first** ([`JobsContractSweepModal`](../../src/components/jobs/JobsContractSweepModal.tsx)). The pane opens with the job it is about (number · name · customer · address — it used to be "look left"), then two doors: **We need a signature** / **We already have one**. The second *is* the sweep's existing `filing` state, so the tested send engine is untouched. A builder's row opens on it by itself (their paper is the agreement — it used to take two clicks), and rows already out keep it as the way to file the copy that comes back. The buried footer link is gone; the filing footer gained **Skip**.
- **The Drive pass runs by itself.** The scan that lived in a window under ⋯ (`drive-contract-scan` + `matchDriveContracts`) now runs when the sweep opens. New kernel [`contractSweepDrive.ts`](../../src/lib/jobs/contractSweepDrive.ts): one best find per job (confident over check, then newest), the list chip (*📄 in Drive* / *📄 in Drive? check*), the header clause, the default door. An **In Drive** tab appears when there is something in it. The scan takes about a minute (measured live: 66 s, 123 files, 273 job folders), so [`driveContractScanCache.ts`](../../src/lib/jobs/driveContractScanCache.ts) shares one scan between callers and keeps it 15 minutes, a failure is never remembered, and the header says *checking Drive…* meanwhile.
- **A "check" find is shown, never filled in** (`driveFindPrefills`). Found on the first live look: for J651 the pass offered *"Plumbing Proposal REVISED.pdf"* in a folder 23 jobs matched — and the first build had pre-filled its link and lit **File it & next**, one click from recording a proposal as a signed agreement. Now only a **confident** find pre-fills the link and the file's date; a check find is amber, says *open it first*, and waits for **It is — use this file**.
- **The filing sheet arrives pre-filled** ([`JobContractFileSheet`](../../src/components/jobs/JobContractFileSheet.tsx)): `initialLink`, `initialSignedOn`, `foundNote`, `recordLabel` (*File it & next*), `cancelLabel`. From the sweep the date starts **empty**, or from the file — a contract already on file was not signed today (the Contract modal's sheet still starts on today).
- **The contract field on the job** ([`JobContractStrip`](../../src/components/jobs/JobContractStrip.tsx), inline variant — Edit Job's *Customer Contract* row; kernel [`jobContractLinkField.ts`](../../src/lib/jobs/jobContractLinkField.ts)): while nothing is signed or out, a field — *Already have their contract? Paste the Drive link…* — and **File it**, filed as signed by the job's customer, a live draft or a copy out on paper converting in place. Once signed with a link, **Open the contract ↗** on every strip.
- Small: the pane's label column is 74 px (at 56 px *STANDARD TERMS* wrapped into its value) and reads *Terms*; a list row with several chips gives them their own line instead of squeezing the job name.

## Not built from the mock-up (in the to-do)

The three signing ways as one compact switch, and folding the footer's secondary actions into **⋯ More** — cosmetic, and both sit on render-tested radios and buttons; a follow-up.

## Verify

Open the sweep: the pane names the job; the two doors; *checking Drive…* then *N look like they are already in Drive* and the **In Drive** tab. A confident find opens pre-filled → **File it & next** → the row leaves. A check find: amber, nothing filled, **It is — use this file** fills it. On a job with no contract: paste a Drive link on *Customer Contract* → **File it** → the chip reads ✍ On file · Google Doc and **Open the contract ↗** appears.
