## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- The write stamps `completed_at` and `completed_by_user_id` only on a row that is still open and visible to the caller; a write error is returned with its message, and zero rows returns the "already complete, or no access" message. Either way nothing else runs and no event fires.
- Notifications go to the notify-on-complete user and, when asked, the creator — once each, never to the completer — as "<name> completed: <title>" tagged by instance; an unnamed completer reads as "Someone"; a missing item or a failing send never touches the result.
- The next occurrence lands at scheduled date + N days, skipped when one already exists, the task does not repeat after completion, the day count is missing, nobody is assigned, or the next date passes the end date (which is inclusive). Every assignee is copied onto the new row; a failed insert copies nobody; a thrown read is swallowed.
