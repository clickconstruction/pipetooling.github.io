# v2.2920 — Role sweep: one predicate per audience — controllers reach the bank data their shell shows, primaries read their steps, estimators lose a People door they were never meant to have (2026-09-06)

Journey map Phase 4, **Tier-2 #28 "Shells admit a role the data refuses"** (`JOURNEY_MAP.md` row 28; `_FINDINGS.md` clusters **C21** role-gate contracts broken by literal role lists and **C24** robot audiences disagree), plus the RLS gaps five earlier Phase-4 builders verified and queued for this sweep (#7, #32, #4b, B21 J31-N4, B15). A mechanical role sweep — it merges alone. One migration ([`20260906010000_role_sweep_predicates.sql`](../migrations/20260906010000_role_sweep_predicates.md)), two edge functions, six client files.

**The shape.** A client gate admits a role through a predicate (`isAssistantLike`, `canAccessBanking`, `canAccessProspectPipeline`, the Users-tab kind picker, the estimator route list) while the data layer hard-codes a literal role list that omits it — so the UI arms controls the DB rejects (empty Banking queues, refused splits, 403s, a Job window that closed itself) or hides work the DB won't show. v2.662 made `is_assistant()` assistant-LIKE and promised every assistant grant "extends to controller automatically"; that was true only where a policy *called* the function. The fix is the same everywhere: one list per audience, the data layer owns it, the shell mirrors it.

## Decisions called out

- **Banking RPC bodies gain the literal `'controller'`, not `is_banking_staff()`.** Sixteen long SECURITY DEFINER bodies (one redefined six times) — the safe mechanical transformation is "append controller to the exact three-role literal in the live definition", asserted loud. The resulting set is identical to the predicate; the comment on `is_banking_staff()` names the RPCs as mirrors.
- **`jobs_ledger` family: literal + controller, not an `is_assistant()` swap.** Same reason (24 deparsed bodies with adoption arms); same v2.662 rewrite pattern that has run in prod once already. The inner `master_assistants` / `assistants_share_master` arms are role-agnostic — only the outer array refused a controller.
- **Job-window client predicates widened in this PR** (#7 asked for it "in the same PR" as the DB widening). Zero controllers exist (Will's decision 3 — no account created here), so the merge → `db push` window has no one in it.
- **Telemetry: none** — refusals are server logs (`rls_refused{table, role}` is the map's suggestion; not built).
