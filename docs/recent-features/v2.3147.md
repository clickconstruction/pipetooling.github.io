# v2.3147 — Share cards: every app link unfurls, and help guides get a share link (2026-09-08)

The owner texted `clicktooling.com/help?g=split-a-job-into-stages` on iOS and got a bare grey strip. Three causes, all in the shell: no `og:image`, an SVG `apple-touch-icon` (iOS ignores SVG there), and every app URL serving the same index.html — a crawler never runs the app, so a help link could never say which guide it was. Client only; the build writes the per-guide pages.

## The site-wide card

- [`public/og-card.png`](../../public/og-card.png) (1200×630, the app's own look — dark, the gear-and-wrench mark, the ClickTooling wordmark, "Jobs, bids, crews and money — one app for the office and the field.") and [`public/apple-touch-icon.png`](../../public/apple-touch-icon.png) (180×180). Both rendered from HTML with Playwright (`scratchpad/render-og-card.mjs` in the session; the HTML is short enough to re-create from the PNG).
- `index.html`: `og:image` (+ width / height / alt), `og:url`, `twitter:card summary_large_image`, a `description`, and the PNG touch icon. The v2.1767 job-share wording is replaced by the app's line.

## Per-guide share pages — `/g/<slug>/`

- [`src/lib/helpShareCard.ts`](../../src/lib/helpShareCard.ts) (pure, 4 tests): `helpShareUrl` (`https://clicktooling.com/g/<slug>/` — the trailing slash is what GitHub Pages serves an `index.html` at), `helpShareTitle` ("How do I …?", the Help page's own heading), `helpShareDescription` (the guide's first paragraph with mock-UI tokens and markdown stripped, cut at a sentence under 200 characters, skipping a leading recording token, headings and `:::` blocks), `helpSharePageHtml` (OG + Twitter tags, `noindex`, the absolute card image, a meta-refresh + JS bounce to `/help?g=<slug>`, an escaped fallback link).
- `helpSharePagesPlugin` in [`vite.config.ts`](../../vite.config.ts) runs at `closeBundle` next to `copy404Plugin`: reads every `src/content/help/*.md` through `parseHelpGuideFrontmatter` and writes `dist/g/<slug>/index.html` (247 pages today). The service worker's navigation route denylists `^/g/` ([`src/sw.ts`](../../src/sw.ts)) so a signed-in phone with the SW installed still gets the real page and its bounce, not the SPA shell 404-ing an unknown route.
- Same pattern as the portal shell (v2.2033, a Cloudflare Worker) and job-share (an edge function) — this one needs neither, because the guide list is known at build time.

## The button

[`GuideBrowser.tsx`](../../src/components/GuideBrowser.tsx): **Copy share link** beside the category chip on an open guide copies `helpShareUrl(APP_ORIGIN, slug)` and toasts; when the clipboard is refused it toasts the link itself. New guide *share a help guide with someone* (Getting Started, all roles).

## Live check

After the deploy: `curl -s https://clicktooling.com/g/split-a-job-into-stages/ | grep og:` shows the guide's title and first line; `curl -sI https://clicktooling.com/og-card.png` is 200. Text the `/g/` link from an iPhone: the card carries the mark, the question, the first line and the domain. A previously shared `/help?g=` link may keep its cached bare preview for a day or two — share the `/g/` link instead.
