# v2.3221 — Robots → Scoreboard, opened to estimators and rewritten in plain words; the Shadows lens folds in (2026-09-10)

Client only — no migration. The scores table (`twin_run_scores`, staff SELECT since `20260901090000`) and `list_shadow_runs()` were already readable by every signed-in staff user; the only gate was the client's `myRole === 'dev'` check. Owner ask (via Grace, 2026-09-10): expose the Scoreboard to estimators as a tab, but "it does not look amazing and I don't think we are doing the best we can with this tab." Mockup → self-critique → revision: https://claude.ai/code/artifact/a03e89b7-6bfd-46e9-8b18-5bafb7f2fe10.

## Why

The v2.2560 Scoreboard was a dev instrument: Gate B, axis, in-band, holdout, VOID, BT/SH, PRACTICE tags on people, the robot's operator notes pasted raw into the cards and the Counts column, five counts and 32 rows with no next action, and a second lens (Shadows, v2.2544) telling the same story per run. Wendi's "idk" answers to twin-vocabulary questions (v2.2795) were the precedent for what estimators do with that vocabulary.

## What changed

- **Kernel** [`src/lib/bids/robotScoreboard.ts`](../../src/lib/bids/robotScoreboard.ts) (+17 tests) phrases the existing gate math; `confidenceBoard.ts` is untouched.
  - `jobTypeLabel(axis)` — `JOB_TYPE_LABELS` maps the ten operator slugs to names an estimator would say (`mid-size TI (fitness)` → *Fitness club finish-out*, `proto/auto-service` → *Auto-service prototype*); unknown slugs are tidied, never hidden.
  - `deltaPhrase(pct)` — `+44.2` → *44% high*, `−1.2` → *1% low*, past 100% a multiple (`+413` → *5.1× high*), `on the nose` inside ±0.5.
  - `buildJobTypeRows(cards, shadows, receipts)` — the dev card's chip tone becomes one of four plain states (*Ready for first drafts* · *N of 5 in a row* · *Waiting on a score* · *Needs a fix first*); `plainSlots` re-labels the five-slot bar (sealed runs stay pending as `b420 🔒`); `rankJobTypeRows` orders closest-to-ready first (ready → streaks longest first → waiting → blocked); `lessonLine` is the newest **digest receipt** for that job type (`bid_audit_notes.kind = 'receipt'`, matched to the axis through the robot bid's number in `twin_run_scores.twin_bid_number` / `list_shadow_runs.shadow_bid_number`), stripped of the `🤖 Learned:` prefix, cut at a sentence, and credited *After Wendi's audit* from `bid_audits.completed_by` — else what the axis is waiting on (*Sealed on b420. Scores once b391 has a bid value.*). The operator's raw note line survives as `rawNote`, dev-only.
  - `recentRuns` — the last five scored runs that count (gate-eligible, standard teacher), newest first: the page's trend line.
  - `buildYourPart(input)` — sentences with doors, from the same `robotRowState` kernel the Bid Board icon uses (`stateFor`), so the strip and the row can never disagree: the viewer's sealed bids and when each scores (the office's when the viewer has none), scored-against-your-number, queued/working, *Robots can't see N live bids* with the reason breakdown and how many are the viewer's, audits + questions waiting on anyone, and the coverage line.
  - `buildLiveRuns` / `buildPracticeRuns` — shadows first (in flight newest, then scored, voided last; *waiting on **you** to send b385* when the reference is the viewer's), backtests newest first; voided runs kept and marked with the operator's note; `counts` = scored against a calibration standard.
- **Component** [`BidsRobotScoreboardTab.tsx`](../../src/components/bids/BidsRobotScoreboardTab.tsx) rewritten: rule + recent-runs strip → **Your part** → **Job types** (one row each: name, scored/sealed counts, status chip, five slots, lesson) → **On live bids** (a row expands into the v2.2544 sealed-envelope stepper via `shadowStorySteps`) → **Practice on past bids** (six shown, *Show all N*) → one footnote naming the calibration standard rule. Devs get a **Show robot notes** toggle that reveals `rawNote` under each job type. Loads: `twin_run_scores`, `list_shadow_runs()`, `users.calibration_standard`, plus three fail-soft reads for the receipts (`bid_audit_notes` → `bid_audits.completed_by` → `users.name`). The holdout fetch, the pills, the Teacher column and the ledger table are gone from this lens (holdout toggles stay on the dev Queue).
- **Lens bar** ([`Bids.tsx`](../../src/pages/Bids.tsx)): Robot Board · Audits · **Scoreboard** · Queue (DEV). The Scoreboard button and render gate on `canWorkRobotAudits(myRole)` (the group's own door: dev, master_technician, assistant, controller, estimator); the bar's more-than-one-lens rule counts it. New page-level `robotRowStateForScoreboard` and `robotQuestionsWaiting` (estimator-lane open questions minus plans asks, which sit on the bid as a need).
- **Shadows' runs live here too**: the Shadows lens (v2.2544) was deleted in the same hour by v2.3222, which folds it into the Robot Board mirror and sends `?tab=robot-shadows` and the Dashboard's *robot locked* item there. This lens keeps the per-run story from the run's side — every shadow under **On live bids** with the stepper on expand — while the mirror shows the same runs per human bid with the envelope door. The two read the same `list_shadow_runs()` rows.
- **Copy**: no *Gate B*, *axis*, *in-band*, *holdout*, *VOID* or *PRACTICE* on the estimator-facing page. The teacher rule is one footnote: runs count only when scored against a calibration standard's number; others are shown for comparison.
