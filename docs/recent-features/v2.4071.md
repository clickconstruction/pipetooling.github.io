# v2.4071 — Write up a change: pick a half-done write-up back up (2026-09-28)

Migration `20260928190000_estimates_field_write_up.sql` (`docs/migrations/20260928190000_estimates_field_write_up.md`) — pushed before this client deploys. No edge function. The first of the three v2.2293 deferrals, the one that loses work in the field: a write-up closed before Send sat in Estimates → Unsent and the wizard started blank every time.

## What changed

- **`estimates.field_write_up jsonb`** — the wizard's own marker, NULL on every office-made estimate: `started_at`, the `job` it was opened on (id, HCP, name, address, customer — the row's `job_ledger_id` stays reserved for the created-from link), `phone`, `free_customer`, `dismissed_at`. `ensureDraft` writes it on insert and merges the job on a Back-and-forward change; `saveProgress` keeps the phone and free-typed customer on it. Interim `as never` cast on the insert until gen-types runs.
- **The check on open** — before the seeded door runs, the wizard reads its newest five drafts by this person (`created_by`, status draft, never sent to Dispatch or a customer, marker set, photos embedded) and `quickEstimateResumeCandidate` picks the first with content: typed words, a reason or schedule note, a ballpark, or a photo. An empty draft (job picked, nothing typed) is never offered.
- **The prompt** (stage `resume`, no Back) — *Pick up where you left off?* with the CO/Estimate line, *started N min/h/days ago*, the photo count and the first 140 characters. **Pick it back up** restores every field (`quickEstimateResumeFromDraft` strips the "Job: …" and "Phone: …" paragraphs the wizard itself wrote into the change description, reads the ballpark back off its placeholder line, the estimate branch's description off the *Field write-up* line), re-signs the photos, re-reads the customer for the estimate branch, and lands on *What's the change?*. **Start fresh** leaves the draft in Unsent and it is offered again next time. **Leave it for the office** stamps `dismissed_at` and it is never offered again.
- **Kernel** `src/lib/quickEstimate.ts` — `quickEstimateSplitChangeDescription`, `quickEstimateResumeFromDraft`, `quickEstimateResumeCandidate`, `quickEstimateResumeAge`; 7 tests in `quickEstimateResume.test.ts`.
- Guide *write-up-a-change-order-from-the-field* (Good to know); PROJECT_DOCUMENTATION's Quick Estimate line.
