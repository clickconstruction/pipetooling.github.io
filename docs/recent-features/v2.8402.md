# v2.8402 — Permits: a failed nightly reading can no longer skip issued permits (2026-11-23)

Punch list #405 (`to-dos/permits-market-page/README.md`). `permit-pull` reads and writes the second reading's own start, which [v2.8400](v2.8400.md) keeps on `permit_pulls`. The function needs a deploy; it works before or after the migration's push.

## The fault

San Antonio's applications are read twice a night: by filing day, then by issued day. v2.8328 starts the second reading 30 days before the newest issued day held, worked out before either reading writes. The first reading writes issued days too, so that day moves on every night the first reading runs. If the second reading alone failed for over 30 nights, its start would pass the permits issued while it was down. Nothing would read them again, and they would read as waiting.

## What changed

- **Each run keeps the second reading's word.** `issuedReadingRecord` in `_shared/permitCities.ts` gives the row's `issued_since` (the second reading's start) and `issued_whole` (it read to its end). Not to its end: an error, the time budget, or a first reading's error that kept it from beginning. The page cap ends a reading as it always did. A feed read once, a run on the body's `since` and a read back as history keep nothing, so a one-off read never clears a failure's start.
- **The next run reads it first.** `keptIssuedReading` reads the source's newest row with `issued_whole` set, before the readings begin. `heldPassStarts` holds the second reading to that row's `issued_since` while `issued_whole` is false, and never moves a start later. A failed run's start is itself held, so a run of failures carries the first one's start until a reading finishes. The first reading's start is unchanged.
- **Ahead of the migration.** The read finds no column and holds nothing. The run's row is written again without the two columns, so `permit_pulls` keeps its line. Before, a failed insert was not checked at all.
- `docs/EDGE_FUNCTIONS.md` → permit-pull, *The second reading's own start*.

## Tests

`src/lib/research/permitCities.test.ts`, *the second reading keeps its own start*:

- Thirty-one nights of failed second readings while the first reading moves the newest issued day every night: the second reading's start stays on the first failure's day, where counting from the days held would have passed it. The night it reads to its end it still starts there, and a permit issued on the second night down is inside it. The night after, the start counts from the days held again.
- A kept start later than the computed one changes nothing; a whole reading, a row with nothing kept, and a feed read once start as v2.8328 does; the body's `since` starts every reading on its day and keeps nothing.
- The source order: the kept start is read before the starts are worked out, both before the readings' loop, and the row's retry without the two columns is there. v2.8328's order test now names the held start.
