# v2.2345 — Job Address autocomplete (2026-08-26)

Owner ask; mockup https://claude.ai/code/artifact/1d6efc13-8ce6-4094-9eeb-e4fe7ca3ec5f.
Google Places suggestions under the Job Address field, New + Edit Job alike
(one shared component: `JobFormIdentityFields`).

- **New edge function `address-autocomplete`** (docs/EDGE_FUNCTIONS.md):
  proxies Places Autocomplete (New) with the existing server-side
  `GOOGLE_MAPS_API_KEY` — no key in the browser. Service-area location bias
  (50km circle over San Antonio–New Braunfels–Seguin — the Places bias maximum), US-only, ≤5
  suggestions, in-body getUser auth (`verify_jwt = false`). 503/502 → the
  client silently degrades to a plain input.
- **Client**: kernel `src/lib/addressAutocomplete.ts` (parse, bold-split at
  Google's match offset, `, USA` stripping, saved-shape helper) + hook
  `useAddressSuggestions` (5-char minimum, 300ms debounce, stale-guard) +
  dropdown `JobAddressSuggestions` (pin glyph, bold match, locality right,
  ENTER hint on the active row, footer with keyboard help + the required
  "powered by Google" attribution).
- **Behavior**: ↑↓/Enter/Esc + click; a pick fills the field via
  `titleCaseAddress` in street-comma-city shape, feeding the statement
  preview + comma nudge unchanged; Esc or a pick suppresses the list until
  the next edit; free typing/pasting never blocked.
- **Geocode pre-warm**: a pick fire-and-forgets `geocode-address-batch`, so
  `address_geocodes` learns the address before the Map/travel hints ask.
- Tests: kernel suite + render smokes (fetch/debounce, bold rows +
  attribution, click pick + pre-warm payload, keyboard flow, degrade path).
