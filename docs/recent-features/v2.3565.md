# v2.3565 — Labor tab decomposition, L4 Stage A: the driving and travel formulas are one kernel (2026-09-17)

Client only, behavior-preserving. The Stage-A half of region L4 in [`docs/BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md`](../BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md) — the last step of the Pricing/Labor train in `to-dos/engineering-hygiene.md` that pays for itself; the train closes with it.

## What moved

[`laborTabCostSummaries.ts`](../../src/lib/bids/laborTabCostSummaries.ts), two functions with the arithmetic of the four IIFEs verbatim:

- `drivingSummaryFromInputs` — trips = Σ hours ÷ hours per trip; cost = trips × $/mile × distance. The rate and hours-per-trip boxes read `parseFloat(s) || default` (0.70 / 2.0), so an empty, unparseable **or zero** box shows the default — the number the autosave will write.
- `travelSummaryFromInputs` — people × nights × (meals + hotel), people and nights rounded and floored at 0, the meals and hotel halves kept apart for the expanded lines.

Both the **Vehicle Travel** box (collapsed one-liner and expanded body) and the **Lodging and Meals** box (the same pair) in [`BidsLaborTab.tsx`](../../src/components/bids/BidsLaborTab.tsx) read them now. Until this PR each formula lived twice as a string-parsing IIFE, so a default fixed in one copy could drift from the other.

**Deliberately not folded into `bidCostCalc.ts`** (map quirk 7): that file reads the persisted `cost_estimates` row, where a stored `0` is honored and only null falls back. The boxes read the in-flight strings. Both readings are right for their input; the kernel's header says why they stay apart.

**The box components (the other half of L4) are not built**, and the train closes without them: 253 lines behind 18 props — seven engine string pairs edited in place — is a component that would carry more surface than it removes. The formulas were the duplication; that is gone.

Numbers: `BidsLaborTab.tsx` 1,940 → 1,928 lines.
