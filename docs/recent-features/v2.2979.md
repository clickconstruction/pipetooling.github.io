# v2.2979 — Test-gap audit, pass 8: the sub portal's "How do I get paid?" guide gets its first tests, with an en/es parity guard (2026-09-06)

Follow-up to v2.2977, which named the sub-portal guide strings next. Tests only — no kernel, client, migration or edge-function change.

## Why this one

`subPortal/subPortalGuideStrings.ts` (224 lines) is the bilingual content of the sub portal's help guide (v2.2922): the bottom line, the four steps of a sub's money, the one button, offers, documents, deductions and what is coming — every line an en/es pair the page's language toggle picks. Pure content with no logic, so nothing checked that the two languages still had the same shape, or that the guide still quoted the buttons the page actually shows.

## What shipped

**`subPortalGuideStrings.test.ts`** (7):

- **Shape parity** — the Spanish tree has exactly the English tree's keys, array lengths and leaf types, recursively: four steps, facts per step 2 / 3 / 3 / 2, two coming-soon items. Add a fact to one language and forget the other, and this fails naming the path.
- **Copy hygiene** — no leaf in either language is empty, padded, or carries an unfilled `{placeholder}`.
- **The time chip** appears only on the "paid" step, in both languages.
- **Sync with the page** — the bottom line and the one-button body quote `subPortalT(lang, 'workDoneButton')` verbatim, the demo confirm is `workDoneConfirm`, the offers section names the New work heading and the documents section names the Sign now button. Rename a button in `subPortalI18n.ts` and the guide's test fails until the guide follows.
- **The story order** — Work → Pre-inspection → Post-inspection: Trigger draw → You're paid, in both languages, every fact addressed to someone.
- `subPortalGuide` serves Spanish for `es`, English otherwise, as stable references.

All 7 passed on the first run — the two languages are in step today.
