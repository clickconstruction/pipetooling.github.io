## Why

`lib/overheadPartsAccountingBuckets.ts` imported `type OverheadPartsDetailLine` from `lib/overheadOfficePartsReads.ts`, the overhead reads with a client passed in, which import the in-kind cost lines and ledger, the paging, the retry wrapper and the slim database types. dev-mcp reads the buckets through `_shared/devMcpComposites.ts` (a customer's parts by bucket) and never runs the reads, so it uploaded 74 KB of them for one type. bridge-weekly-sheet runs the reads and keeps them.

- **`overheadPartsAccountingBuckets.ts`** and **`overheadPoolSnapshotReads.ts`**, which took the type alone, import from the new file.
- **The copy**: the generator points `overheadPartsAccountingBuckets.ts` and `overheadOfficePartsReads.ts` at the file in src with its `.ts`, its rule for a file of types that imports nothing, so the deploy uploads it, 1 KB. Not an entry, for the reason v2.7290 gives.
- **`edgeUploadGraph.test.ts`** holds it: dev-mcp uploads no `overheadOfficePartsReads.ts` and reaches the line's file through the buckets; bridge-weekly-sheet keeps the reads.
