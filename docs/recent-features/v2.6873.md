# v2.6873 — Permits: read the city's records further back (punch list #307, the rest of PR 4) (2026-11-10)

A builder's year needs a year of rows, and the pull held ten weeks. v2.6857 made the counts say so. This is the other half: reading further back, without putting old permits on the skim.

## What changed

- **Migration `20261110224035_permit_history.sql`** (`docs/migrations/20261110224035_permit_history.md`): `permits.backfilled`, and `research_permits` replaced in place so a backfilled building permit is never on the skim, the lists or the ledger.
- **`supabase/functions/permit-pull`**, **`_shared/permitCities.ts`** and **`_shared/permitFeed.ts`**: `city` with `since` and `until` is a read back as history. A feed reader that can be read up to a day carries `pageUrlBefore`; San Antonio's two do (`feedPageSql`'s `untilDay`), and a city without it is refused (`HISTORY_CITIES` hides the press there). Rows land flagged, duplicates are ignored so a row already held is never rewritten, and the run refuses when the column is missing. The builder-key pass covers plumbing permits too.
- **`src/lib/research/permitReach.ts`**: `historyAsk` (the next 92-day step back, stopping at `HISTORY_GOAL_YMD`, January 2025), `historyDoneWords`, and `recordsStartOf`, which now reads the start of the records as the day every feed reaches: one feed read further back than the other does not move it.
- **`permitResearchIo`**: `pullPermitsBack(city, since, until)`; a feed that stopped short is a failure with its reason. `loadRecordsStart` reads each feed's runs.
- **`PermitBuilders`**: the line over the list carries the press **Read back to May 26**, then reads where the records start again and reloads the list. `usePermitRecordsStart` takes a refresh key.
- Guide `research-permits-for-work-to-bid`, `docs/EDGE_FUNCTIONS.md` (permit-pull), `docs/PROJECT_DOCUMENTATION.md`.
