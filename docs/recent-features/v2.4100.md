# v2.4100 — The GC statement email says what paid each bill (2026-09-28)

**Migration `20260928213000_statement_email_paid_by.sql` (`db push`) + edge function `gc-statement-email-dispatch` (redeploy)** + client. To-do #55 piece 1; the owner's pick from the mock-up (artifact `M7p77GTmhsXY97ciMmso1M`) the same day. Follows [v2.4044](v2.4044.md), which put the line on the printed statement, GC Review's bill lines and the portal.

## What shipped

- **`supabase/functions/_shared/billPaidBy.ts`** — the one wording rule, moved out of the client kernel so Deno can call it: `billPaidByWords({ bills, payments, retainageHeld }, invoice)`, plus the label helpers (`paymentKind`, `checkNumberText`, `isDepositRef`, `checkLabel`, `formatYmdShort` / `formatYmdLong`, `money`). `src/lib/jobs/gcChecksApplied.ts` re-exports them and its `billPaidByWords(job, invoice)` is now a wrapper; its 16 tests still pass unchanged.
- **The RPC** (`docs/migrations/20260928213000_statement_email_paid_by.md`) — each row of `get_gc_statement_email_payload` carries `invoice_id`, `invoice_amount`, `retainage_held`, `job_bills` and `job_payments`.
- **`render.ts`** (`rowPaidBy`) and **`gcStatementEmail.ts`** — the line under the job line in HTML (11px grey, like the job line), and after the amount in the plain text. A payload from before the migration prints no line; a client row without `paidBy` prints no line.
- **`gcStatementEmailParity.test.ts`** — the fixture carries the facts once (bills, payments) and derives the client row's `paidBy` from the same shared rule, so both lanes are pinned on one truth; a new case checks the line in HTML and text, and its absence on a row without payments.
- Share all (every GC in one email) gets the line the same way, in both lanes; `send-gc-statement-email` (the app-sent lane) takes the client's HTML and needs no change.

## Decided here

- **One rule, in `_shared`** — like `paymentAttribution.ts` and `billToParty.ts` before it: the client imports the Deno module, never a copy.
- **Facts on the row, words in the render.** The RPC ships payments and bills, not a sentence, so the wording stays in one TypeScript file and a change to it never needs a migration.

## Deploy

1. `supabase db push` (the migration is on main with this PR).
2. `supabase functions deploy gc-statement-email-dispatch`.
Order does not matter; either side without the other prints no line.
