# v2.2935 — Audit cockpit: rate gaps ("Priced differently") + the delta waterfall (2026-09-06)

The 2026-09-05 regression batches (11 runs) showed the robots' counting has converged and nearly all remaining error is **pricing posture** — tier rates, uplift overrides, all-in boundaries. The audit card couldn't display that class at all: `diffTakeoffs` compared matched rows on quantity only, so a row counted right but priced 5× wrong landed silently in "✓ N rows match within 15% — nothing to judge there."

- **Kernel** ([`takeoffDiff.ts`](../../src/lib/bids/takeoffDiff.ts), +5 tests): `diffTakeoffs` gains a fourth bucket, `rates` — quantity-matched rows whose unit rates (ext/count) disagree beyond `rateTolerance` (default 15%); a side with no pricing has no rate to disagree with, so unpriced rows stay matched-ok instead of minting $0 rate gaps. `matchedOkCount` now means quantities AND rates agree. New `diffWaterfall(diff, robotTotal, ourTotal)` decomposes the headline delta into `missed + added + gaps + rates + other = delta`, where `other` is what the row diff cannot see (the sent letter's uplift over raw rows, in-tolerance drift) — labeled instead of vanishing.
- **Card** (`BidsAuditsTab.tsx`): a violet {{chip}}-style **PRICED DIFFERENTLY** section ("same row, same count — different money") renders `robot $X/u · ours $Y/u ×N` with the same one-tap verdicts; a **Where the delta lives** strip above the system rollup shows the waterfall as signed dollar chips summing to the delta. Rate-gap verdicts route to the **pricing** section (`entrySection(label, 'rates')`) and their drafted notes describe rates, not counts (`buildVerdictDraft(…, 'rates')`).
- Help guide `audit-a-robot-bid.md`: four lists + the waterfall strip documented.

Client-only; no migration, no edge deploy.
