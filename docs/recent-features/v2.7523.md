# v2.7523 — Reserved stickers: a press that prints them, right where they are named (2026-11-16)

Punch list #329. The owner opened Print future stickers' *Which job?* window on the day v2.7492 shipped, read a card's amber line (58 stickers reserved and not on a box yet, their names, who and when) and wrote: *I love that I can see stickers that were reserved, but I don't see any tools to print them?* Client only, no migration, no function.

## What was found first

1. **How many presses to print them from that card.** Four, over three screens, and no word on the card pointed the way: **Open the job's boxes** (the window closes and the job's page opens), **Runs** on the line over the boxes (the fold opens), **Reprint 58 stickers** in the fold (with none on a box the fold draws no *Print the rest*, so the only press says *Reprint*), then the stickers window's own *Print 58 stickers*, after **Connect the P-touch** where the printer is not linked.
2. **A run minted and never printed.** A run is made at the press, before a strip goes out. Over USB the press is held until the printer answers and its tape fits, so a printer that is off cannot mint. Past that: a printer that fails or a **Stop printing** keeps the window on the run, says how many went and offers *Print the rest*, which is enough while the window stays open. Once it is closed (a click outside it closes it) or the page reloads, nothing remembered the run as unprinted and no screen offered to print it. Through the browser's print window a cancelled dialog leaves the same state with no line said. The app keeps no record that a strip came out: `sticker_runs.printed_at` is the moment the run was made, and every line reads *Printed Nov 16 by Dana* whether or not anything printed.
3. **Which places that show reserved stickers offered a print.** None. The *Which job?* card, the job's line over its boxes and the window's own *This job has 58 stickers reserved…* line named them with no press. The phone's line under the boxes has none either, and keeps none: the phone prints no stickers.

## What changed

- **The press.** `reservedRunsToPrint` (`reservedPrint.ts`) reads a job's runs into one press for each run that still holds stickers on no box, lowest names first: *Print the 58 reserved stickers, G93 to G150* through `countedLabel`, a broken stretch by its first names (`namesSpanWords`), a run with no names by its count. It says *reserved*, the line's own word, and never *again*, since nobody knows the first print came out. With more than one run each press says who printed its run and when.
- **Where it sits.** `ReservedPrintPresses.tsx` draws it in the card's amber box (`PrintStickersWindow.tsx`, off `StickerJobFacts.toPrint`), under the job's line over its boxes (`JobsMaterialsTab.tsx`, off `useJobStickers`' new `toPrint`, so Jobs → Materials and Materials → On site both have it) and under the count in the window's ask (`PrintStickersModal.tsx`, whose one read of the job's runs now feeds the count and the presses; the `blankCount` prop became `jobRuns`).
- **What it opens.** The stickers window on the run, as the fold's **Reprint** and **Print the rest** open it: `StickerRunToPrint` gained `printing`, the stickers the press starts on, so the reserved ones print while **From** and **to** still reach the whole run. Nothing is minted. From the ask the window turns to the run in place (`openRun`) and keeps its link to the printer.
- **Told apart from a new reservation.** Under the presses: *This prints the same stickers with the same links. It reserves nothing new.* On a card with reserved stickers the line before **Print future stickers** reads *Print future stickers reserves new ones. A new run opens on G151.* (`nextNameWords`). A window opened on a run already made says *Printing them again reserves nothing new. Each sticker keeps the link it has.*, the fold's two presses included.
- **Who.** A role `canMintStickers` refuses sees the press dead, with the database's sentence in the line under it and in its label for a screen reader.
- **The hole, in part.** A run that stops part way now says *The 28 stickers left are still reserved. Print them now, or later from the job's reserved line.* (`restKeptWords`), and that line now has the press.

## Left for its own PR

Recording that a run's strips went out. With it a line could say *reserved Nov 16, never printed* and the press could read *Print* or *Print again* truthfully. It needs a column on `sticker_runs` and a write after the print, so it waits for the owner's go.

Looked at on a page drawn from the render output with made-up names. Not walked on the live screen: a worktree has no `.env`, and no run was minted or printed to test.
