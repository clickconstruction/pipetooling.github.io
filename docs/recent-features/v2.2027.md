# v2.2027 — Goals strip: segmented stage bar + tap-open stage ledger (2026-08-21)

Implements mockup variants A+B from the "Goals Strip Redesign" artifact (owner
pick): the Review tab's Goals strip shows per-stage progress instead of one
task-weighted bar.

- **Kernel** `goalsStageRows()` in `src/lib/roadmapBridge.ts` (+6 tests):
  per-stage `{groupId, title, done, total, state: complete|current|locked,
  openAssigned, blockedBy}` in **`sort_index` order** (the owner's "Order
  stages" arrangement, not dependency depth — an early-finished stage shows
  green out of sequence, matching the canvas). Reuses
  `computeCompleteGroupIdsWithMilestones` / `computeUnlockedGroupIds` /
  `blockingStageTitles`, so milestone auto-completion behaves identically.
- **Segmented bar**: one flex segment per stage — complete `#16a34a`, current
  amber-ringed (`#d97706` outline) with its own blue fill fraction, locked
  `var(--bg-muted)`; `title` tooltip carries name + count. Falls back to the
  old solid bar when a roadmap has no stage rows.
- **Stage ledger**: the goal card is now a `role="button"` accordion
  (`expandedGoalId`, one open at a time). Rows: index, title, state chip
  (✓ done / current + "N on lists" / 🔒 with first blocker, full
  `lockedStageHint` in the tooltip), 110px mini bar, `done/total` count
  (— for milestones). Locked tail folds behind "▸ N more locked stages" when
  more than 3 (`showAllLockedStages`, reset per expand). "Open roadmap →"
  moved inside the ledger header — card click no longer teleports to the
  canvas.
- **Query change**: the goals loader's groups select adds `sort_index`. No
  new queries, tables, or migrations.

Found while verifying live: Farm 1's "1 done" stage is #20 ("add solar…"), a
milestone that auto-completed — exactly the shape the old single bar hid.

Help: `review-my-teams-completed-tasks.md` → "Goals on the board" documents
the segments and ledger.
