# v2.5394 — Messages: the New lane sorts what came in, behind the scenes (2026-10-12)

Residential R7, PR 1 of 3: the New lane's kernel, pure and tested, in `src/lib/followUp/newLane.ts`
(`to-dos/gc-mode/messages/RESIDENTIAL_BUILD_PLAN.md` → R7; mockup A on screen 7 of `customer-messages-prototype.html`
v0.8, both on branch spike/gc-mode). No migration, no edge function and no screen.

- `newLane(contacts, messages, activeJobIds, now)`: one row per person, the oldest waiting first, with one sort.
  **Who is this?** is a sender with no record. **Which job?** is someone with two or more active jobs whose newest line
  sits on the default job with no hand tie. **Who has it?** is a line nobody has answered on a conversation nobody is on.
  The sorts win in that order. Each row carries the line's words, when it came in words, the box and why it is there.
- `whoGuesses(row, box, known)`: the team line offers a customer by a number on file or a last name in the line, then a
  new lead on Prospects, then a new customer. bids@ offers a trade partner whose own domain matches, the ones on an open
  ask first, each with someone new at that company, then a new trade partner, then a supply house. Both end with a
  candidate and someone else. A line with no box reads as the team line. `nameInText` reads "this is Kevin Alvarez";
  `companyDomain` drops open mail services such as Gmail.
- `jobChoices(row, jobs)`: the person's active jobs in the rail's order with the default marked. `hasChoices(row,
  people, rule)`: the has rule's pick first (passed in), then the office, then everyone else.
- `newLaneCount(rows)` for the Messages badge. `queue.ts` is not touched; the lead wires the count in later.

Two inputs stand in for columns that are not on main yet: `mailbox` (R6's `messages.mailbox`) and `tiedByHand` (R7's
`messages.tied_by`, null when the default job took the line). The guesses carry their own kinds (`lead`, `supply_house`,
`candidate`) until R0 widens `ContactKind`.
