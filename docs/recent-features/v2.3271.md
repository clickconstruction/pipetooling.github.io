# v2.3271 — The cost chart shows overhead: an amber band stacked on the cost line (2026-09-10)

Client only; no migration. Owner call 2026-09-10 after a five-option mockup (band on cost · dashed true-cost line · overhead as a seventh marker · band under the cash line · end labels only): **"I like A, build A."** Mockup: https://claude.ai/code/artifact/6acad838-43fc-4158-bcab-bea166cf0074

## What shipped

- **`lib/jobChargesTimeline.ts`**: `JobOverheadDayInput { dateKey, amount, activityUsd?, carryUsd? }`; `buildJobChargesTimelineChartData(…, overheadDays)` adds per row `overheadToDate` / `overheadActivityToDate` / `overheadCarryToDate` / `trueCost` / `overheadBand: [expense, trueCost]` / `overheadOnlyBucket`, and to the data `overheadSeriesAvailable` / `endOverhead` / `endTrueCost`. Rules: overhead on or before an event bucket folds into that bucket (so the x-axis never gains a bucket for a day the crew did nothing); overhead after the last event makes ONE trailing bucket dated at the last landing, with cost, payments and value flat, so the band keeps growing while the job stays open; the unknown-date bucket never takes overhead; non-positive and undated days are ignored. `computeChargesTimelineAxisDomains` reaches the true-cost edge. Six tests.
- **`JobSummaryChargesTimelineChart`**: `LineChart` → `ComposedChart`; an `Area` (amber `#f59e0b` at 22 %) fills `overheadBand` under the lines, and a 1.5 px `#d97706` step line draws true cost. With the band on, the source icons ride the true-cost edge instead of sitting inside the fill, the red end label tucks under its point, and an amber "$X true cost" label sits above the amber point. Tooltip: *Overhead to date $X (by hours · carry) · true cost $Y*, and the trailing bucket's header says *overhead landed since the last charge*. Legend: *Amber = overhead landed so far, stacked on cost (true cost on top)*.
- **Job Summary tab**: passes the enriched row's `overheadLines` when the viewer sees money and the Overhead method is Day-share — so the band's end equals the row's Overhead cell; under lenses A / B / C the chart is unchanged.
- **Costs tab** (`JobCostsTabCharts`): `useJobBurnOverhead` now runs once in the wrapper (it returns `days`, the share's lines) and feeds both Burn and the Cost Timeline (`firstChargeYmdOf` shared). `JobChargesTimelineStandalone` takes `overheadState`, or runs the hook itself for the Job Detail window (wage roles only), so every host draws the same band.
- Help guide `job-charges-timeline.md`: the band, the trailing point, and the tooltip line.

## Not changed

The red cost line and the green cash line, the Overhead column and the allocation. On a job the office pool never touched (anything before 2026-02-19) there is no band.

## Known difference between the two hosts

Job Summary's band is the row's Worked-in window share, so its end equals the Overhead cell. The Costs tab's band comes from `useJobBurnOverhead`, whose window is [first charge … today] capped at 120 days (v2.3189, so an old job stays cheap to load) — on a job with carry older than 120 days the Costs tab's true cost reads lower (J621 on 2026-09-10: $960 on Job Summary's 12-month window vs $791 on the Costs tab). Same rule Burn's projection already followed; widening the cap is a separate call.
