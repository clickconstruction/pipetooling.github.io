# v2.6799 — Find a part on this site from a scanned label, and a front door at prts.co (punch list #294, PR 3) (2026-11-09)

The owner's ask ([`to-dos/prts-box-page/README.md`](../../to-dos/prts-box-page/README.md)): from the signed-out box page, search the materials on site. The privacy call the card made: the scanned code is the key and the search covers that box's job, never the whole company, since an open search would publish the inventory to anyone with the address.

## What changed

- **`box-read`** takes `?code=<code>&find=<words>`: the same job's live boxes (never Unsorted, never retired) whose stencil, place, where-note or lines hold every word typed, each with the lines that matched, the scanned box first and marked, stencil order after, at most 30 with the true count. The rule is `boxPageFind` in `_shared/boxPage.ts`, tested from `src/lib/materials/boxPage.test.ts`. No code, no search. [`EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md#box-read). **Redeploy** `box-read`.
- **The box page** gains **Find a part on this site** (`?find=1` opens on it): the words, Find, the hits with a door to each other box, *Nothing on this site matches …* with the Short press named, and *Boxes on this site only, as of right now* with the sign-in for every job. A successful read remembers the box on the phone for a day (`src/lib/materials/boxPageMemory.ts`).
- **`/b`, Scan a label** (`src/pages/BoxScan.tsx`, outside the sign-in): the camera words, a box to type the code with the dash put in as it is typed, **Open the box**, and on a phone that scanned a box today, **Find a part on that site**. A signed-in person goes to the On site tab. Its row in `customerSurfaceRegistry.ts`.
- **The prts.co zone** gets a second redirect rule, bare host → `clicktooling.com/b`, ahead of the first: mirrored in `scripts/cloudflare/prts-co-redirect.md` with the API body; the live rule is the owner's step and nothing else here waits on it.
- Docs: the guide, `APP_DIRECTORY.md`, `MATERIALS_ON_SITE_ARCHITECTURE.md`.
