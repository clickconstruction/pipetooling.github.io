# v2.2130 — Pipeline aging clock: billed date, hand-set est. date wins (2026-08-22)

Owner question from the Who-owes-what modal ("why do so many show no date?"). The Billed aging clock — [`stageRowBilledAgeDays`](../../src/lib/jobs/invoiceBilling.ts) — read ONLY `jobs_ledger_invoices.estimated_bill_date`, a hand-typed field (the Billed row's "Edit est. bill date" pencil, or the Fix-bill-lines backdate). No normal billing path sets it (Bill Customer / Stripe / HCP / split all write `null`), so on 2026-08-22 prod had **60 of 65 open billed invoices with no age** ($214k of $258k) — while every one of them carried `billed_at` (the `jobs_ledger_invoices_billed_at_fn` trigger stamps it the moment a line becomes billed; its column comment even says "Used for aging in UI").

- **Kernel**: new `stageRowBilledAgeReference(row) → { ymd, handSet } | null` — a hand-set est. bill date wins (it exists to correct the date: bills entered after the fact, backdated lines — the 5 hand-dated prod rows all have a `billed_at` 13–195 days later than the real date), otherwise `billed_at`'s Chicago calendar day (`calendarYmdInAppTzFromIso`). Job-shell rows (billed job, no bill line) have neither. `stageRowBilledAgeDays` and `billedStageRowAgingBucket` both read it, so everything downstream moves together: the 30+/90+ header chips, `buildBilledAgingBuckets` → `stagesHeaderStats.billedAging` → the money card's age bar + "Chase the 90+ tail" move, `sortStageRowsForTotalByNameDetail`, the Total-by-Name detail ages, and [`billedByCustomerBreakdown`](../../src/lib/jobs/billedByCustomerBreakdown.ts) (new `ageHandSet` / `worstAgeHandSet` flags).
- **Not touched (already their own clocks)**: `paymentChase.ts` (`billedYmd` = billed_at first), `billedAgingChart.ts` (billed_at, falling back to est), `billedPaymentForecast.ts` (expected-pay model takes both), `printBilledRowReferenceDate` (billed_at first, "(est.)" suffix). The no-bill-line cohort (`billedStageRowHasNoBillLine`) is unchanged.
- **Modal** [`BilledByCustomerBreakdownModal`](../../src/components/jobs/BilledByCustomerBreakdownModal.tsx): chips always show days now; a hand-set age carries a trailing dot + tooltip; "no date" → "no bill line". Chip titles in `JobsStagesTab` read "(by bill date; a hand-set est. bill date wins)".
- **Prod effect** (same day): 90+ chip 3 → 7 bills, 30+ 0 → ~16; Who-owes-what goes from 22/27 customers "no date" to all aged. Help: `read-the-pipeline-money-view.md`.

Client-only; no migration, no edge functions. Tests: `invoiceBilling.test.ts` (fallback, Chicago-day boundary, override), `billedByCustomerBreakdown.test.ts`.
