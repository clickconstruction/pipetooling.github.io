# v2.6479 — The Subs tab counts paid sheets as settled, and opens documents under the sub (2026-11-03)

People → Subs fixes from a screenshot of the live tab.

## What changed

- **Track record's settled count** (`buildSubsHqRows`, `src/lib/people/subsHqRows.ts`): `settledCount` counted only `step_commitments` with status `settled`, so a sub paid on sheets read "27 sheets · 0 settled". It now adds each attributed sheet paid in full (`totalCost > 0 && balance <= 0`). A settled work order on a sheet (`sheetLabel` set) is no longer counted, since its sheet already is; a settled step work order still counts. Live after the fix: Behar Kraja 27 sheets · 26 settled.
- **Documents opens under its row** (`PeopleSubsTab.tsx`, `renderDocsPanel`): the panel was drawn after the table, 20 rows away from the press on a long roster. It is now a full-width row beneath the sub's own row.
- **Wrapped names stay left**: the name is a button, and a button centres its text by default, so "Airlowe Heating & Air Conditioning" wrapped centred. `textAlign: 'left'`.
- **Unlinked-sheets banner**: the subline named an "Owed" column the table does not have; it now names **Balance due**. "Assigned to" reads the sheet's piped multi-sub name as a comma list (`assignedNamesLabel`) in the body font instead of a quoted monospace string; the raw text stays in the tooltip.
- Tests: `subsHqRows.test.ts` (settled sheets, `assignedNamesLabel`), `PeopleSubsTab.render.test.tsx` (documents row sits under its sub).
