# v2.2457 — Estimate Options, Phase 1: schema + builder + staff preview (2026-08-28)

Owner-approved plan (2026-08-28 mockup artifact; all five decisions went to the leans):
one estimate offers the customer several priced options — Repair vs. Replace, Good /
Better / Best — and the customer picks one on the acceptance page before signing. Options
live INSIDE the single estimate row (one quote number, one token, one signature), never as
sibling rows; acceptance freezes the chosen option into `line_items_snapshot` +
`total_cents` + `accepted_option_key` so every downstream reader keeps working untouched.

This PR (Phase 1 of 3):

- **Migration `20260828190617`**: `estimates.options_snapshot jsonb` +
  `estimates.accepted_option_key text`, both nullable — null = today's single-option
  estimate, zero behavior change.
- **Kernel `src/lib/estimates/estimateOptions.ts`** (+13 tests): normalize (tolerant of
  junk, strict on keys — an unkeyed option is dropped, since the key is what acceptance
  records), exactly-one-recommended repair, MAX 4 cap (owner decision), totals,
  `freezeAcceptedEstimateOption` (Phase 2's server write, kernel-tested now), and
  `estimateOptionsDraftPersistFields` — the save shape: snapshot + the RECOMMENDED option
  mirrored into `line_items_snapshot`/`total_cents` (owner decision 3: Pipeline/list show
  the number you'd forecast until the customer decides).
- **Builder (option cards, owner-picked variant B)** in the draft editor above Line items:
  ＋ Option converts a single estimate into two (current lines → Option 1 ★, Option 2 an
  editable clone — the Bids move) or clones the viewed option; cards show name/total/count
  and *editing*; fields under the cards edit name + customer-facing pitch; ★ Recommended
  moves the star; Remove option collapses back to a single price at one. The Line items
  editor below always edits the card marked *editing* (`lines` state = viewed option,
  folded back on switch/save). Change orders are excluded (their document is single-scope).
- **Customer-side components built now, lit up in Phase 2**:
  `EstimateOptionsPicker` (stacked choice cards, owner-picked variant A — radio cards,
  Recommended badge, "What's included" expandable) + `EstimateCustomerDocument` gains a
  `beforeLineItems` slot + `EstimateAcceptBody` takes `options`/`selectedOptionKey`/
  `onSelectOption` and shows the SELECTED option's lines and total with a "Your selection —
  <name>" heading. The staff **Customer experience → Page** preview renders all of it live,
  so the office rehearses the exact customer flow today.
- **Send gate**: a 2+-option estimate can't be sent until Phase 2 (toast explains); the
  customer page can't render options yet. Single-option estimates send exactly as before.
- Help guide `offer-options-on-an-estimate` ships now and grows with Phases 2–3.

Deferred to Phase 2: edge functions (`get-estimate-for-customer` options payload,
`accept-estimate` option key + freeze, `send-estimate-to-customer` email block with every
option's price — owner decision 5), the new-tab "Preview as customer" snapshot plumbing,
CX override key for the picker heading. Phase 3: option events in the activity feed,
accepted-view "of N offered", list badges.
