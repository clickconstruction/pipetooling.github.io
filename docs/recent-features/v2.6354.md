# v2.6354 — The Pipeline search finds every job in a development, Paid in Full ones too (2026-11-02)

The owner, 2026-11-02: "in the jobs, pipeline search at the top, it doesn't seem to include the names of developments." The board's own matcher (`filterJobsByStagesSearch`, v2.1199) has read `development.name` over loaded rows since developments shipped, and every Pipeline row carries the `development:development_id(id, name)` embed. What missed was the second half of the search: the server-side lean lookup (`src/lib/jobs/leanJobSearch.ts`, v2.1825) that finds the jobs the board has not loaded — every Paid in Full job, and the sections not yet opened — ilikes the five flat `jobs_ledger` columns and said so in its header ("GC/development names live on other tables and keep matching client-side over loaded rows"). A built-out development is mostly paid houses, so its name found a few working rows and the Paid in Full header read nothing. Client only: no migration, no function change.

- **The kernel.** `fetchDevelopmentIdsMatching(term)` reads `developments` by `name ilike %term%` (archived ones included, since their jobs still carry the id and the board's matcher reads the name either way; capped at `LEAN_DEVELOPMENT_MATCH_LIMIT`, 50), and `buildLeanJobSearchOr(term, developmentIds)` appends `development_id.in.(…)` to the same `or` the flat columns ride, so the customer filter, the 200-row cap and the full-row fetch for the hits are unchanged. An id that would break the list is dropped, never quoted. `fetchLeanJobSearchIds` runs the developments read first; a failure there is the search's failure, with its reason, as any read's.
- **Not changed.** The `#` jump matches numbers only. The global search's `search_jobs_ledger` RPC (header box, `HeaderGlobalSearch.tsx`) reads the same flat columns and does not match a development's name either; that is a migration, left as a follow-up. The GC's name still matches loaded rows only, for the same reason.
- **Guides.** *search jobs on the Pipeline board* lists the development name among what the search matches; *group bids and jobs into a development* says the Paid in Full jobs come up too.
- **Tests.** `leanJobSearch.test.ts` pins the gap and the fix with a mocked client: a development's name finds a job the board had not loaded, the `or` carries the flat columns first and the development clause after, the customer filter and the cap are as before; a term no development carries searches the flat columns alone; one letter asks the server nothing; the builder drops an id with a breaker.
