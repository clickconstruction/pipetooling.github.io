# v2.6985 — Permits: a map point for Austin's permits in Williamson County (2026-11-11)

Punch list #320, PR 3b. Since v2.6958 `permit-pull` fills the point of an Austin row the city sent without one from the lot's parcel at Travis County. The rows over the county line carry Williamson's id, which Travis's layer does not hold, so they stayed without a point: 71 of the 422 left on 2026-11-11.

- **Kernel** (`_shared/permitParcelPoints.ts`): `WILLIAMSON_PARCEL_POINTS` asks Williamson County's parcel layer for shapes by `QuickRefID` (`williamsonParcelQuery`, 50 ids a request by POST). `TRAVIS_PARCEL_POINTS.idOf` now leaves an R id out, so no id goes to both layers. `idOfAny(sources)` reads a row's id by the first layer that takes it, and `fillPoints` takes anything with an `idOf`.
- **The hook**: `FeedReader.fillPoint` is now `fillPoints`, a list. `AUSTIN_READER` names Travis's layer and Williamson's.
- **In the pull**: per page each layer is asked for its own ids. A refusal ends the asking of that layer for the run and no other's; its rows are written without their point columns, as before. `points.error` in the feed's outcome carries the first refusal.

Measured live on 2026-11-11 through the new kernel, without writing (the 75-day window, every kind the pull keeps): 4,238 rows, 1,742 with no point. **1,393 would take one** (1,325 before this change), 68 of the 70 rows with an R id among them, from 22 of the 23 ids Williamson was asked about. 349 stay without. 10 requests, under 4 seconds. No point landed outside the Austin area.

Tests: `permitParcelPoints.test.ts` (each id to its own layer, Williamson's question, a row filled from either layer, a row held when its layer did not answer). Every id and shape is made up.

Deploy: `permit-pull` and `permit-lookup` after the merge (both bundle the shared files). No migration. The rows already held take their point when Austin's window is read again once, as after v2.6958: `{ city: 'Austin', since: <75 days back> }` through the deployed pull, a dry run first.
