# v2.3210 — Robot questions answer with one tap: the ask_question door enforces one decision + 2–4 choices, and the Standing rulings card renders them as buttons (2026-09-09)

Migration `20260909233000_twin_question_choices.sql` (two nullable columns on `twin_questions`); edge function `twin-mcp` v1.3.15 (redeploy).

## Why

The Standing rulings panel became more than a person can process. The robot's contract already said an estimator question is "ONE decision, two sentences", but `ask_question` accepted any string, so a backtest slate arrived as one card with three decisions, a dozen percentages and a book-entry approval. Two cards beside it ("attach the plumbing sheets") were fine because they were one decision each. The load was shape, not count.

## What shipped

- **The door** (`supabase/functions/_shared/twinQuestionShape.ts`, shared Deno + client): `checkEstimatorQuestionShape` refuses an estimator-audience question unless it is under 320 characters, carries at most one question mark, is not a numbered list of decisions ("(1) … (2)", "Also confirm"), and comes with 2–4 distinct `choices` of ≤40 characters; `recommended`, when given, must be one of them. The refusal lists every problem and one fixed hint: split per decision; numbers, sheet refs and the pattern go in `add_bid_note` on the shell. The operator lane is unconstrained (machine problems are messy); choices are stored if given.
- **twin-mcp v1.3.15**: `ask_question` gains `choices` + `recommended` in its schema and description; the insert writes both (retrying without them if the columns are absent, same ladder as `audience`); the success line says how many taps the estimator will see and which pick is first. `get_answers` returns both columns, so the robot reads the tapped label verbatim. Bundled briefs regenerated (also picks up the v2.3207 APP_DIRECTORY/TWIN_HARNESS edits that were not rebuilt).
- **Migration**: `choices jsonb` (CHECK: NULL or JSON array) + `recommended text` on `twin_questions`, comments. Only the edge function writes them; twins still cannot update or delete their questions.
- **The buttons** (`src/components/bids/TwinQuestionChoiceButtons.tsx`, kernel `src/lib/bids/twinQuestionChoices.ts`): `orderedChoices(row)` puts the robot's pick first and marks it; the component renders it filled with a ★, the rest outlined, plus a dashed **Something else…** that swaps the buttons for the free-text box. On a grouped ruling each button carries "· all N" and the tap answers every open copy through the existing `answerRuling`. Wired into both loops of the Standing rulings panel (Bids → Audits) and into the operator console's question list (Settings → Digital twins). Rows with no choices (pre-migration, free-form robots) render exactly as before.
- **Docs**: `.claude/skills/bid/SKILL.md` AUDIT paragraph, `docs/twins/estimator.md` §9 ("She answers with one tap"), `docs/twins/kickoffs/desktop-operator.md`, `docs/EDGE_FUNCTIONS.md`, `docs/migrations/20260909233000_twin_question_choices.md`; help guide `audit-a-robot-bid.md` step 2 rewritten around the buttons. `database.ts` hand-adds the two columns.

## Tests

`src/lib/bids/twinQuestionChoices.test.ts` exercises the door with the actual wall from the screenshot (four problems fire), the one/five/long/unoffered-recommended refusals, a plans ask that passes once it names its choices, normalization, and button ordering. `BidsAuditsTab.render.test.tsx` seeds a topicless question with choices and asserts the buttons (pick first, ★) render and the free-text box is gone for that card.
