# v2.7654 — A dismissed alert stays dismissed on your other devices (2026-11-17)

A fix, found while cutting `src/pages/Prospects.tsx`: the same shape as that page's calling-lock release, once more, in another file. The owner said to fix both.

**The defect.** `startDismissalSync` (`src/lib/dismissalSync.ts`, v2.2951) registers the pusher that mirrors every alert dismissal to `user_dismissals`. The pusher was written `void supabase.from('user_dismissals').upsert(…)`. The Supabase client sends a query only when it is awaited: its builder is a thenable, and the request goes out inside `then`. A builder that is made and dropped sends nothing. So no dismissal ever reached the server, the table stayed empty, and the sign-in seed that reads it had nothing to seed. A dismissal lived only in the browser where it was pressed.

**The fix.** The upsert now ends in `.then(() => undefined, () => undefined)`, which sends it. A refusal or a lost signal is let go, as the comment in the store always said it should be: the device's own copy still holds the dismissal.

**What it reaches.** The five kernels that call `pushDismissal`: the bulk-delete notice, the bulk-hours notice, the dev-rejected banner, the robot backlog and the robot silence alerts.

**What it does not do.** It does not go back for dismissals made before today: those are in each browser's own storage, and this change does not upload them. The next time one of those alerts is dismissed, on any device, it is saved.

**The table's rule** (`20260906170000_org_defaults.sql`) already allows it: a person may write their own rows. Nothing to migrate.

**Proof.** `src/lib/dismissalSync.test.ts`, 4 cases, against a stand-in that is lazy the way the real client is (a write is recorded only when it is awaited): a dismissal after sign-in is sent on the person's own row; a refused save is let go and the dismissal does not throw; the device is seeded from the server where it has nothing; after sign-out nothing is sent. Two of the four fail on the code before the fix.

**Not checked live.** No dismissal was pressed on the live site by this session.
