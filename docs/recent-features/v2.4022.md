## What the smokes found (nothing changed here)

Pinned as today's behaviour where a test touches it; each is a fix for its own PR.

**In more than one window**

- **A refused save loses its reason.** The catch tests `instanceof Error`, which a supabase-js write error never is. Division 22's audit and Plug in quotes show only a generic line; Plug in the schedule shows "Could not save: [object Object]".
- **A failed load looks like an empty list.** Compose, the RFQ desk and Plug in the schedule each swallow the failure, so the window reads as "nothing here yet" — and in Plug in the schedule a paste-and-save could then overwrite rows the user never saw.

**One window each**

- **The fixture copy** — after one *Copy with quote link*, a second one on the still-mounted window re-copies the first house's link and writes no row: the lane and its draft are never reset on open.
- **Plug in quotes** — hand-added lines can share a key (add two, remove the first, add another), so typing in one fills both and one *Remove* removes both; *Match to fixtures* discards hand-added lines; the quote, its lines and the price memory are three writes with no rollback, so a failure after the first leaves a quote with no lines and a retry inserts a second quote; Escape with only the house list open closes the whole window.
- **Plug in the schedule** — the × on a saved row only drops it on screen (Save never deletes); every save rewrites `created_by` / `confirmed_by` / `confirmed_at` and `source` on rows nobody touched.
- **The RFQ desk** — the bounce-fix box writes onto the row object held in state, so a reload drops the correction; an emptied box sends an empty address rather than the original.
- **Compose** — a send where some requests failed still reports `onSent` and closes.
- **Division 22's audit** — a wrong pin cannot be corrected from the window (coded rows have no controls; the update branch in `pin()` is unreachable); the busy guard holds only the last row clicked.
