# v2.5671 — Pricing: a price card you just opened reads … until its prices arrive (2026-10-20)

Client only; no migration, no edge function. The two gaps [v2.5669](v2.5669.md) left on purpose (Grace's report): the short window after a price card is clicked on Bids → Pricing, before that price's book and rows land. In that window the Workbench still holds the price you left, and v2.5669 taught only the open card to say so (`pricingPricesReady`).

## The gaps

- **The strip and the rows read the price you left through the open price's eyes.** `scenarioPricingRows` prices only the open price's own rows, so Revenue, Profit and Margin read $0 (or a name-matched book price), the priced count 0, and every row's sale price a dash, for the ~250 ms the reads take (longer on a slow connection).
- **A price write in the window looked up "existing" rows and entries in that state.** `writeUnitPriceOverrideRow`, `savePricingAssignment` / `removePricingAssignment`, `fillMatchingBookEntries`, `copyPricesIntoViewedScenario`, `applyWorkbenchPreview`, the margin brush and the book-offer and entry-form writes all key the write to the open price but find its assignment, custom price and book entry in state. Reproduced in the page test below on the code before this change: *Fill 1 matching from book* clicked in the window inserted Alternate 1's floor-drain assignment pointing at **WENDI's** entry (`e-w3`). The unique keys on `(bid_id, count_row_id, price_book_version_id)` keep a true duplicate out, so the other writes fail loudly rather than double up, but a cross-price entry pointer goes through.
- **A failed read never settled.** v2.5669's loaders cleared the "read for" mark on an error, so a failed book or rows read left the open price loading for good, with nothing on its way to clear it (the book effect reads again only when another price opens).

## What shipped

- **`guardPriceRowsWrite`** ([`BidsPricingTab.tsx`](../../src/components/bids/BidsPricingTab.tsx)): the sent-bid lock, then a refusal with the toast *This price is still loading. Try again in a moment.* while `openPriceLoading` ([`priceReadGate.ts`](../../src/lib/bids/priceReadGate.ts)) is true. Every write that looks up the open price's rows or book uses it; the bid-level writes (markup, tax, row marks) still ask only `guardPricingWrite`. The priced-margin stamp reads nothing while loading, so it can't stamp the price you left. The guard reads the render's own `pricingPricesReady`, which is what makes it right: the blur save of a price typed before the click runs from the render where that price was open and ready, so it still saves (Grace's gesture); anything started from a render of the new price waits.
- **The margin brush** ([`useMarginBrush.ts`](../../src/hooks/useMarginBrush.ts)): its guard is now asked when a stroke starts as well (each touch keeps the row's saved price for Undo, so a stroke must not start against the wrong rows), and a stroke refused at pointer-up is dropped with its drafts instead of being left painting.
- **Loading reads …**: the strip's Revenue, Profit, Margin and Multiple, the alternates line, the priced chip (`…/N`) and the coverage line; each row's sale price, Revenue, Profit and Margin cell (no box to type into, so no draft is made against the price you left); the sent-vs-today line is held back. `figureWhileLoading`.
- **A failed read settles** ([`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts)): the book and rows loaders mark the price read on an error too, so the error banner shows and the Workbench leaves …. An abort is no failure: the read that replaced it lands. Every path that opens a price (a card, the ★, a new price, the package map, a version switch, the Cover Letter's ★ alignment, the default fallback) ends in the book effect's read and the resolve effect's rows read.
- **Tests**: [`Bids.pricingSwitchWindow.render.test.tsx`](../../src/pages/Bids.pricingSwitchWindow.render.test.tsx) renders the page on Pricing with the alternate's book and rows held back. The strip and the row read … then the alternate's own $270 and $50.00 (failed before: `$0`). *Fill matching from book* in the window waits with the toast and writes nothing, then writes the alternate's own entry once it lands (failed before: no toast, and the cross-price insert above). The open card reads …, never *No prices yet*. The engine test gains three failure cases (a failed book read and a failed rows read settle, failed before; a failed read of the price you left changes nothing). The brush test gains a refused press and a refused pointer-up. `priceReadGate.test.ts` holds the kernel and the plain words.
- **Docs**: the Pricing map's preserve-quirk 21.

## Left

- The cards below the grid (Price breakdown, By kind, By tag, the profit bar) still show the window's figures; only the strip and the rows read ….
- The margin brush's Undo survives a price switch and would write the old price's prices into the new one. That is not the loading window, so it is not touched here.
