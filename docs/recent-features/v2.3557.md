# v2.3557 — The punch list links every mock-up and update, and is worked by several people (2026-09-17)

Tooling + docs. The to-do kernel derives two more things per to-do, the board and the index render them, the board is published with the mock-ups as supporting files and the `db` + `user` capabilities declared, and the artifact's URL is recorded in the repo. No migration, no edge function, no in-app surface.

## Why

The owner asked three things of the punch list on 2026-09-17: whether every to-do was on it (yes, mechanically, since v2.3497), whether the mock-ups and updates of each item could be reached *through* it (no — a row linked only its to-do file), and how several people could work it at once (they could not: the published copy had never been declared the `db` capability, so every viewer's picks stayed on their own device, and nobody knew the artifact's URL — the repo did not record it and the owner did not have it).

## The rule: derive, never declare

Nothing new is written by hand. A to-do's links are computed at render time from what is already beside it, so they cannot drift and the existing CI check (`npm run check:todo-drift`) keeps enforcing them:

| Link | Source | Goes to |
|---|---|---|
| **Mock-ups** — one chip per file | every `.html` in the to-do's folder; for a flat to-do, the top-level pages named after it (`job-summary-follow-ups-earned-revenue.html`); never the board itself | the board: the file **by its path relative to `to-dos/`** (`submittals/mockup.html`), so the same href opens the file next door on the local copy and the published copy on the artifact; the index: a rendered page via `raw.githack.com` (the repo is public) |
| **Artifacts** — one chip per link | every `claude.ai/…/artifact/…` URL in the prose. A markdown link keeps its text; a bare URL is labelled from the tail of its line — the last *italic title* or `code title`, "design canvas", "Mock-up:" — and numbered when a to-do links two pages with one label | the artifact |
| **Versions** — each `v2.NNNN` in the version chip | `versionsCited()` | `docs/recent-features/v2.NNNN.md` — the update record for that step |
| **history** | the to-do's path | GitHub's `commits/main/to-dos/<slug>` — every PR that touched the to-do, newest first |
| **folder** | folder to-dos only | the folder on GitHub, for the drift reports and scripts beside it |

Measured on main today: 24 mock-up pages across 13 to-dos, 12 artifact links across 9 to-dos, all now reachable from their row.

## What shipped

**Kernel — `src/lib/todos/todoBoard.ts`** (48 tests, was 39). `TodoDoc` gains `mockups: string[]` and `artifacts: TodoLink[]`; `readTodoDoc` takes the folder listing as a third argument and derives both (`mockupsFor`, `artifactsCited`, `labelFromContext`). `renderBoardItems` emits them; `renderIndexBlock` adds a fifth **Links** column (`renderIndexLinks`). `PUNCH_LIST_ARTIFACT_URL` is the one place the artifact's address lives.

**Script — `scripts/check-todo-drift.ts`** passes each to-do's siblings in, and `--fix` now prints the republish reminder with the URL whenever it rewrites the board.

**The board — `to-dos/punch-list.html`**:
- a links line per row (mock-ups in copper, artifacts, then history / folder in grey), and the version chip's `v2.NNNN`s link to their fragments;
- every interpolated string is HTML-escaped (they were not — a `<` in a summary would have been markup);
- **pointer rows** (`next-up`, `owner-decisions-pending`, `journey-map-tier-1`) show *standing list* instead of the pick segment and are left out of the counts — the header's "37 open items" and the filter chips' "All 40" had disagreed since v2.3497;
- each pick stores `by` — the viewer's opaque id from `user.id()` — and a *by whom · date* line under the segment resolves it through `user.profiles()` on every paint (names are never stored; they differ per viewer);
- the sync line says plainly when picks are device-only and when they are shared.

**The artifact.** Published fresh (there was no reachable copy — a fresh publish loses nothing) with `capabilities: {db: {}, user: {scopes: ["profile"]}}` and the 24 mock-up pages as supporting files at their `to-dos/`-relative paths. Its URL is in `to-dos/README.md` → *The punch list* and in the kernel constant.

## How several people work it

Anyone in the organization the owner shares the artifact with sees the same board. Signed-in viewers with interact access read and write the shared picks (`db`'s default rule); view-only links read them. A pick records who made it; the row shows the name. Claude reads the picks back from any session with `read_db` on the artifact's `picks` collection — the way to say "here is what I would do next" and have a session start from it.

## The process, stated once

In `to-dos/README.md` → *The punch list*: the file is the source; the artifact is a copy that carries the picks, so it is **republished, never edited** — after a board-changing PR merges, republish `to-dos/punch-list.html` to the recorded URL with the mock-ups as supporting files and the two capabilities declared. `--fix` prints the reminder. A publish without `url` makes a second board with none of the picks.
