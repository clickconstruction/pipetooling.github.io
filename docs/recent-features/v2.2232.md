# v2.2232 — HR files v2: doc history, coverage marker, agent RPC + role (2026-08-24)

DB-layer upgrade of the People → HR files system (migration
`20260824141540_person_hr_files_v2.sql`, details in `docs/migrations/`):

- **Nothing loses history anymore**: `person_file_revisions` archives the prior
  version of every summary/narrative rewrite via a definer trigger (dev
  read-only; rows written only by the trigger).
- **Explicit freshness**: `person_files.covered_through` records exactly which
  entries a doc has folded in; the tab's freshness kernel switches to it in
  v2.2229 (falls back to `updated_at`).
- **Provenance**: `author_label` on entries and docs identifies non-user
  writers ("HR agent") where `created_by`/`updated_by` are NULL.
- **One safe write path for the agent**: `hr_agent_write(jsonb)` validates and
  atomically applies entries + summary + narrative(-append) in a single call,
  and the new least-privilege `hr_agent` role is append-only on entries *by
  policy*. Password is set out-of-band; see `docs/HR_FILES.md` § "Agent
  credentials".

No UI change in this version (that is v2.2230). `docs/HR_FILES.md` updated.
