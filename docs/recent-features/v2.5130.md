# v2.5130 — Bids: Undo of a price book switch puts the Pricing tab back on the first book (2026-10-10)

Bid history follow-up (punch list #73), found on the ZZ Test walk of PR 5 and PR 6 on 2026-10-10 (step 15). Directed by PUNCHLIST, built by Helper 11. No migration.

## The bug

Undo on *Switched the price book* wrote the bid's pick and its version's ★ back, and the database read WENDI again. But the open Pricing tab kept showing the Default book until a reload. A price typed in that state would have gone into the Default copy.

The put-back listener in `Bids.tsx` reloaded the assignments and data for the tab's current `selectedPricingVersionId`, the old book. The engine's resolve effect re-reads the book pick only when the bid changes.

## The fix

- **The engine follows.** `useBidPricingEngine` now hears `BID_HISTORY_PUT_BACK_EVENT` itself. When a put back or an Undo wrote the bid's row or a version's ★ (`bidPutBackMovesBookPick`: `bids`, `bid_versions`) on the bid it resolved, it unstamps `pricingBidIdRef` and re-fires its retry tick. The re-run takes the full path, reading the versions' ★ and the books afresh. That's the path a failed resolve's Retry already uses.
- **No race.** `Bids.tsx` no longer reloads the old book's prices for those tables, which would race the re-resolve with the old book's rows. A put back on any other table reloads as before.
- **The right table.** The History window's Undo names `bid_versions` when it touched a version but not the bid.
