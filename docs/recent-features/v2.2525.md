# v2.2525 — App identity renamed ClickTooling (home screen, tab, unfurls, push) (2026-08-31)

Owner report post-cutover: iOS "Add to Home Screen" on clicktooling.com still
pre-filled **PipeTooling**. Part of the DOMAIN_CUTOVER.md "text sweep" —
the four user-visible places the app names itself:

- `index.html` `<title>` → ClickTooling — this is what iOS pre-fills in Add to
  Home Screen (no `apple-mobile-web-app-title` override exists; comment added
  so the next rename knows the coupling). Also the browser-tab name.
- `vite.config.ts` VitePWA manifest `name` + `short_name` → ClickTooling —
  the installed-PWA label (Android; iOS ≥15 reads short_name too).
- `index.html` `og:site_name` / `og:title` → ClickTooling — link-unfurl cards
  (v2.1767) when a job link is texted.
- `src/sw.ts` push fallback title → ClickTooling.

Deliberately unchanged: the `pipetooling-hard-reload-restore` localStorage key
(functional identifier, renaming breaks in-flight restores), package.json name,
and every code/docs identifier. Already-installed home-screen icons keep the
name they were added with — users re-add the icon to pick up the new one.

Known remaining "PipeTooling" in user-visible surfaces (separate, server-side):
the `EMAIL_FROM` display name (`PipeTooling <team@noreply.clicktooling.com>`,
an edge-function secret — flip via `supabase secrets set EMAIL_FROM=…`) and the
Supabase Auth SMTP sender ("Pipe Notifications", dashboard-configured).
