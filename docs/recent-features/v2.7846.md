# v2.7846 — Lien desk: Filed liens: copies to mail saves everything by itself and shows each lien's document number (2026-11-18)

Two things from the desk on 2026-11-18. The owner: *"when she is recording receipt numbers she would also like a place one click away from the Lien to do page to add the document number the recorders office gave her back"*. Then Taunya's report from the window itself: *"I uploaded all the PDFs. After each the Mail box on the right side of the page auto checks. If I uncheck the mail (because I haven't mailed them yet, it removes them from blue button on the bottom right to Record the liens served"*.

**What the look found.** The number had a home (`job_lien_filings.recording_number`) and one place to type it, the job's Lien window, four presses from To do. The copies window showed no number and no stamped copy, so nothing on it said what the clerk had already given back. The one press that took a PDF was **Add the receipt**. All 22 receipt slots of the 11 filed liens took a file, the same file on both envelopes of a lien, before anything was mailed. Each file ticked *Mailed*. The record press counted only ticked liens, so unticking read as work being dropped, though every file was already kept.

**The owner's calls.** Everything on the window saves by itself, the tick too. A mail number ticks *Mailed* and a file alone does not. The field is named **Document number**.

**The tick (`src/lib/jobs/lienServeNumbers.ts`, `lienServeMailedIo.ts`).** No Record press. A tick writes the *Mailed on* day to that lien at once (`served_at`, and the day on each copy's send), and an untick takes it back and keeps the proof (`lienSendsWithMailedDay`). `lienServeNumberTicks`: a kept mail number ticks a lien once, never a lien a hand has ticked or unticked in the sitting, and never a receipt alone. The write reads the `sends` fresh and answers with the row it changed, so a refused write is said as *Not saved* and the box goes back.

**Mailed liens stay.** A lien mailed on one envelope's number would have left the window before the other number went in. `lienServeMailedJobsFromDesk` lists mailed liens that still lack a number or a receipt (`lienServeProofMissing`), and the window draws them under **Mailed**. A lien that leaves the desk's list while the window is open stays on screen until it closes.

**The card (`lienDocNumber.ts`, `lienDocNumberIo.ts`).** *Document no. 2026… · Alder County · filed Nov 16*, **Stamped lien · Open ›** from the filing's saved copy, and **Change**. A lien with no number shows the box open, and the print's held line reads **Type it on its card ›**. A typed number is saved when its box is left. `lienDocCheck` holds a number another lien in the county holds and asks about one that is not the county's length or does not start with the year filed, learned from the numbers on record (`lienDocShape`). **Save it anyway** keeps an odd one. A number changed on a lien whose copies were printed says to print them again. The desk reads again at once, since the print reads the number.

**The receipt (`lienReceiptDoubt` in `lienReceiptFile.ts`, `LienReceiptPhotoPress`).** On this window the press reads **Add the mail receipt** and the number box *the number on the mail receipt*. A file whose name holds the lien's document number, or says lien or affidavit, or that the other envelope just took, is asked about before it goes to Drive: **It is the mail receipt** or **Leave it out**. The press also reads a photo's barcode here now, and a read number fills an empty box.

**No database change.** The writes are the same two columns the Lien window's form writes, and `recording_number`, each under the table's own update policy.
