# v2.4558 — Put a GC on notice: printing the run marks the notices printed (2026-10-05)

Client only; no migration, no edge function. Row 4 of the lien defects card (punch list #83, `to-dos/lien-defects.md` on PR #4528).

## The defect

`LienDeskRunModal` stamps `printed_at` through its `onPrinted` prop when the packet is printed (v2.4119), and the desk files a stamped notice under *In the mail · tracking owed*. The Lien desk passed `onPrinted`. The run mounted by `GcOnNoticeModal` did not, so a packet printed from Put a GC on notice left every notice in *Ready to send* with nothing saying it had gone to the printer.

## The fix

- [`GcOnNoticeModal.tsx`](../../src/components/jobs/GcOnNoticeModal.tsx): the run gets the same `onPrinted` the desk passes — `markLienDeskItemsPrinted(ids, authUserId)`, best-effort, then the window's own re-read and the host's `onChanged`. A printed notice keeps its `approved` status, so it stays in this window's run.

## Tests

`GcOnNoticeModal.render.test.tsx` (+1): a notice approved and waiting, **Open the run**, **Print the packet**, and the stamp is written for that item by the signed-in user.
