# v2.2890 — Every hand-off lands on its station: Quickfill deep links, in-place Needs You, a way back from AR, four wrong landings (2026-09-05)

Journey map Tier-2 #17 (cluster C11 — "cross-surface buttons land at page top or on a standalone page with no way back"; J5-7, J4-9, J5-2, J27-F5, J28-F3, J6-6, J18-F11). Six independent fixes, one PR; no migration, no edge function.

## 1. Quickfill station deep links — `/quickfill#<station>`

- New kernel [`src/lib/quickfill/stationDeepLink.ts`](../../src/lib/quickfill/stationDeepLink.ts) (tests in `stationDeepLink.test.ts`): `parseQuickfillStationRequest(hash, search)` accepts `#<sectionId>`, `#quickfill-<sectionId>` (a copied DOM id) or `?station=<sectionId>`; `resolveQuickfillStation(location, SECTIONS, rendersForThisUser)` returns `{ raw, sectionId, domId, found, hidden }`; `quickfillStationHref(sectionId)` is the one address form every Quickfill-bound button should use; `quickfillStationTelemetryTarget()` shapes the `ui_nav_clicks` row.
- [`Quickfill.tsx`](../../src/pages/Quickfill.tsx): a page-level effect waits for the `app_settings` layout read (`layoutSettingsLoaded`, so an org-hidden section reads as *hidden* rather than racing the fetch), resolves once per URL (`appliedStationKeyRef`), then `openSectionNow(sectionId)` (force-expand + restore the dock chip) and a bounded ~4s poll for the element → `scrollIntoView`. **Fail-soft:** a hidden / role-gated / unknown station toasts "That section isn't on your Quickfill." and leaves the page as it was — never a blank page, never a resurrected hidden section.
- **Telemetry:** `recordNavClick(userId, role, 'station_deep_link', '#<station> found|hidden|unknown')` — count found vs hidden per station in Usage.
- **Buttons re-pointed:** the codebase had no remaining bare `navigate('/quickfill')` hand-offs (J5-1's card-charges button was rerouted to Banking in v2.2849; the header/☰ nav links are the page itself). The one prose hand-off — People → Vehicles → Check-in settings' "Drives Quickfill's Vehicle check-ins station" — is now a link to `/quickfill#vehicle-odometers`. Future cross-links (Needs You actions, emails, Moneyfill) use `quickfillStationHref`.

## 2. Needs You "Match deposits" in place + a way back from Accounts Receivable

- New [`DashboardArDepositsModal`](../../src/components/dashboard/DashboardArDepositsModal.tsx): the v2.2751 `lien-unconditional` pattern — the SAME `BankPaymentsModal` the `/accounts-receivable` page renders, fed by the shared jobs cache exactly as `JobsAccountsReceivable.tsx` feeds it, opened over the Needs You card on both hosts ([`DashboardPinnedQuickRow.tsx`](../../src/components/dashboard/DashboardPinnedQuickRow.tsx), [`QuickfillNeedsYouSection.tsx`](../../src/components/quickfill/QuickfillNeedsYouSection.tsx)). The card refetches its unallocated-deposits count on close. The "Opening Accounts Receivable…" toast and the bare `navigate('/accounts-receivable')` are gone; the item copy says "right here".
- [`JobsAccountsReceivable.tsx`](../../src/pages/JobsAccountsReceivable.tsx): new kernel [`inAppHistory.ts`](../../src/lib/inAppHistory.ts) (`hasInAppHistory(history.state, location.key)` — React Router's `idx > 0`, or a non-`default` location key) decides between **← Back** (`navigate(-1)`) and the old **Back to Jobs** fallback for cold opens; the modal's close follows the same rule; a "Jobs" link joins Dashboard on the right when Back is history-driven.

## 3. Moneyfill → "See the week's report", pinned to the picker's week

- New kernel [`weeklyMoneyReportLink.ts`](../../src/lib/weeklyMoneyReportLink.ts): `weeklyMoneyReportHref(weekMonday)` → `/jobs?tab=stages&stagesMoney=1&stagesMoneyWeek=<monday>`; `parseStagesMoneyWeekParam` validates a real `YYYY-MM-DD` (rejects rollovers like `2026-02-31`) and normalizes to the Monday.
- [`Moneyfill.tsx`](../../src/pages/Moneyfill.tsx) renders the button beside the tagline; [`Jobs.tsx`](../../src/pages/Jobs.tsx) reads `stagesMoneyWeek` alongside `stagesMoney` (same handle gate, same role gate from v2.2882, stripped together); `JobsStagesTabHandle.openWeeklyMoney(weekMonday?)` → `JobsWeeklyMoneyModal` `initialMondayYmd` prop (the Section-tools menu opener passes null = this week, as before). Closes the WEEKLY_MONEY_PLAN.md "a card on Moneyfill" drift.

## 4. Four wrong landings

- **Probe-code card → Settings → Advanced** (J27-F5): both Needs You hosts' `claim-dev` action now navigates to `/settings?tab=settings-advanced-tools#settings-claim-code`; [`SettingsAdvancedTab.tsx`](../../src/components/settings/SettingsAdvancedTab.tsx) gives the form `id="settings-claim-code"` and opens its collapsed group when that hash is present; `settingsDeepLink.ts` maps the anchor to its tab; the "Claim code" search entry carries the anchor.
- **Settings search "Page pins" → Your dashboard** (J28-F3): the entry moved from `settings-account` to `settings-dashboard` with `anchorId: 'settings-page-pins'` (the Dashboard Page Pins group in `SettingsDashboardTab.tsx` now has that id); `Settings.tsx` opens the collapsed `financialPinsSectionOpen` group on that anchor (deep link and search pick alike). "Financial pins" shares the anchor.
- **Job Summary deep link → Edit Job refused forever** (J6-6): the tab list that kicks the shared jobs-list load is now the kernel [`jobsListLoadGate.ts`](../../src/lib/jobsListLoadGate.ts) (`JOBS_TABS_THAT_LOAD_THE_JOBS_LIST`, tested) and includes `job-summary` — `jobsListLoading` initialises true and only a load flips it, so every "wait for the jobs" gate on the page was unsatisfiable from that tab.
- **Day-view schedule link renders today** (J18-F11): [`scheduleDispatchDayLink.ts`](../../src/lib/scheduleDispatchDayLink.ts) resolves `?day=` once (`resolveScheduleDispatchLinkedDay`) and feeds BOTH the week-grid column focus and the Day tab's `dayTabWorkDateYmd` (`scheduleDispatchDayTabWorkDate`), so `/schedule-dispatch?hubTab=day&day=<ymd>` opens that day.
