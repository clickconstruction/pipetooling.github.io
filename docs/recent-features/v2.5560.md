# v2.5560 — Prospects → Subs: what the bench needs heads the lane, and the bench points back (2026-10-15)

Punch list #110, PR 2 of four (after v2.5559, the kind and the two lanes). The Subs lane now knows what the bench needs and where a company ends up, so the caller is never guessing which trade to hunt and never types a company the bench already has.

- **`src/lib/prospects/subsLane.ts`** (new, pure; 13 tests): `benchNeeds(benches, subs)` — the bench's trades biggest gap first (`BENCH_WANTED` − `dependable`, the bench's own `tradeBenches` rule), each with how many subs in the queue name it, then the trades only the subs name; `benchNeedWords`; `subsForTrade` (case-blind); `subGap` and `orderSubsByNeed` (By need: the biggest gap, then never called, then the caller's order, stable); `sourceSuccess` (every row of the lane by where we found them, `No source` for a blank); `benchDouble` (the same name case-blind, or the same phone of seven digits or more); `subsLaneHref` (`/prospects?tab=subs&trade=…`); `stillQueued` (the strip counts the lane as it stands: a sub the deck took off by an outcome or a delete leaves the count at once, found live on 2026-10-15 when a deleted test sub stayed counted); `tradesLeftToPick` and `withTrade` (the bench's trade names as picks under Trades on New Prospect and Edit prospect, since the strip counts a sub by the bench's own spelling and a name typed by hand can miss it); `BY_NEED_NOTE`.
- **`callingOrder.ts`**: `CallingOrderMode` gains `by_need`; the kernel reads it as coldest and the deck orders it (`orderSubsByNeed`), so the customer deck is untouched when a stored `by_need` follows the caller there.
- **`Prospects.tsx`**: on the Subs lane (or while New Prospect has A sub picked) the page reads the bench the way GC projects does (`loadGcProjects` → `loadGcBoardRows` → `boardStateFromRows` → `tradeBenches`; fail-soft, a role the GC tables refuse sees the lane without the strip) and keeps the bench's companies for the double; **What the bench needs** heads Follow Up — one chip a trade, pressed to filter the deck (`?trade=`), All subs to widen; `loadFollowUpProspects` keeps the whole queue for the counts (`laneQueueAll`), filters to the trade, and applies By need; the queue rail's head names the trade; the order toggle gains **By need** on Subs; **Call script** sits beside the phone number and opens `GcCallScriptWindow`; New Prospect warns under Company Name when `benchDouble` finds the company on the bench, with a door to `/gc?view=partners`; the Activity tab of a new kind loads the lane's rows and shows **Source success** (a bar a source, landed of total) above the 30-day table.
- **`GcTradePartners.tsx`** + `GcProjects.tsx`: the bench rule's "Find N more" line gains **Find on Prospects →** (`onFind`, the GC page navigates to `subsLaneHref(trade)`; a plain link when no `onFind` is passed, so the render test's router-less mount stands).
- **Guide**: `find-subs-for-the-bench` reads the strip, By need, the script and the double. **Docs**: the Prospects map's kind note, the Glossary's Prospects entry, ACCESS_CONTROL (the lane reads the GC board under the GC tables' own policies).
