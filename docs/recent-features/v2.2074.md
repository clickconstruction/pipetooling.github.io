# v2.2074 — Floaty: the first easter egg (2026-08-22)

Owner request (mockup demo artifact f7e8bee1; approved with a 7-second visit): a character that occasionally floats around targeted users' screens, playing near the cursor and fleeing when chased.

**Kernels** (both pure, 13 tests): [`easterEggMotion.ts`](../../src/lib/easterEggMotion.ts) — the demo's exact steering math (`stepEgg`: enter 0.9s → play `PLAY_MS` 7000 → leave 1.4s → done; orbit-the-cursor wander, flee inside 140px with speed caps, viewport clamp, facing hysteresis; `eggOpacity`/`eggTransform` for fades, bob, lean). [`easterEggsConfig.ts`](../../src/lib/easterEggsConfig.ts) — the `easter_eggs_v1` app_settings JSON (tolerant parse, sprite + surface registries, `eggActiveFor`, `EASTER_EGG_APPEAR_ODDS` 1/50). The `followup` surface = /bids with tab builder-review or submission-followup.

**Runtime** ([`FloatingEasterEgg.tsx`](../../src/components/FloatingEasterEgg.tsx), mounted in Layout): `EasterEggHost` loads the config, rolls 1-in-50 once per targeted-surface OPEN (signature-guarded, not per render), and listens for the Settings preview event. The sprite is a fixed `pointer-events: none` img at zIndex 9000 (under every modal), animated by one rAF loop writing transforms via refs — zero React re-renders; `@media print` hidden; never mounted under `prefers-reduced-motion`.

**Management**: [`EasterEggsSettingsBlock`](../../src/components/settings/EasterEggsSettingsBlock.tsx) (Settings → Dashboard & alerts, dev only) — per-sprite card: enable toggle, Who (user chips + picker), Where (surface registry pills), "Preview here now" (skips the dice via a window event). Whole admin is those three choices; frequency/personality are hard-coded. Asset `public/easter-eggs/floaty.webp` (82KB), excluded from the SW precache via `globIgnores` alongside `help/`. A future egg = a `EASTER_EGG_SPRITES` entry + asset.

Config was set live during verification: Floaty enabled, targeting Wendi, on Followup. Verified: Settings card renders + saves + survives reload; Preview mounts the sprite (pointer-events none, z 9000), runs the full visit, and unmounts. Client-only — no migration.
