# v2.7354 — Materials on site: the groundwork for a box's own line (2026-11-15)

Punch list #351, PR 2 of four, the column (`to-dos/box-names-and-what-is-inside/README.md`). The owner took the card's seven calls on 2026-11-14, PR 1 (the name) is v2.7276, and Taunya said on 2026-11-15 to carry on once the stickers work the card waited behind had merged. This PR is the column alone. The screens are v2.7348, which follows the push.

## What changed

- **`job_containers.description`** (`20261115210000_box_line.sql`, documented in `docs/migrations/`): a person's own words for what is in a box, nullable, at most 80 characters, never an empty string. While it is null the screens will write the line from the box's parts, so the app's line is never stored and never stale. Clearing a person's words writes null, which hands the line back to the app.
- **No policy, trigger or function changes.** Whoever may rename a box may say what is in it. A combine or a whole-job move carries the words with the box, since the box moves by its `job_id`.

## Why a migration alone

The box reads on the phone and the office page list their columns by name. A build that named this column before the push would be refused every read of a job's boxes, and `check:calls-ahead` holds a deploy for a function, a table or a view only a pending migration creates, not for a column. So the column goes first and is pushed, and no crew meets a page that asks for a column the database does not have. It also lets the screens be walked on the ZZ test job before they merge.
