**It moves state and handlers that write, so its PR opens unarmed and on hold.** It is armed once the walk of v2.8755 has read clean on the live site, on the managing session's word.

## Why

The price-book drawer's pencil and **Add entry** write to the shared book. A bid prices from its own copy, taken when it was first priced, so the edit stops at the book unless someone carries it across. After each book save the drawer offers to do that for the bid on screen (v2.2444): add the entry to the bid's copy, or bring the copy's price up to the book's, with the bid's other prices that still hold the same old price following (v2.2445).

That lived in the tab as two state values, a token, an effect and two handlers of about 120 lines. No test read an offer.

## How it was done, in order

1. **Tests first, on the tab as it stood.** Ten cases joined the render smoke and passed before the move (the branch's first, second and fourth commits):
   - a book entry the bid's copy lacks is offered to it, and **Add it to this bid too** writes it to the bid's own price
   - **Leave this bid alone** writes nothing, and closing the drawer retires an offer
   - a price the copy already holds is offered the book's new one, and **Use $… on this bid** updates the copy and reads it again
   - the update carries to the bid's other price when it holds the same old price, and says how many
   - the update is aimed at the copy's own entry and at the other price's entry, by their ids
   - a bid with one price asks about no other price
   - a copy that already agrees is offered nothing, and neither is an entry saved from a row's assign search
   - a book edit that brings the book back to the copy's price takes a standing offer away
   - an offer goes away when the open price changes
   - on a sent bid the offer is drawn and its press is refused
2. **The page's HTML and its database writes** at the end of each of the smoke's 54 cases, written twice to see it was steady. 3.7 MB.
3. **The move.** [`src/hooks/useBookEditOffer.ts`](../../src/hooks/useBookEditOffer.ts) holds the two state values, the token, the retiring effect and the two handlers, each as it stood.
4. **The same tests, the same HTML and the same writes**, byte for byte in all 54 states.

The tab is 3,862 lines, from 3,973.

## Two things that are not a bare lift, and why each changes nothing

- **The hook is called lower in the tab than the retiring effect stood.** It reads the forms' target and the bid's current book, and both are worked out further down. So that one effect now runs later among the tab's effects. Nothing between the two places reads the token or the offer: the effects there keep the solver's stash, the solve menu, the forms and the assign search. Effects of one render all run before the next render, so the order cannot be told apart. The cases on a price switch and on a book edit hold it.
- **The drawer's own effect stays in the tab.** It listens for Escape, and it also retired an offer when the drawer shut, with two statements. Those two are now `retireBookOffer`, the hook's, and the effect calls it. That effect carries one lint line with its reason: it cannot list a function from a hook that is called below it.

## Not pinned

- **A refused write.** The smoke's database stand-in never refuses, so *the error line is set and the offer stays* is read in the code and not by a test.
- **The token race.** An offer planned for a price that was switched away while its read of the other prices was out is dropped. No case holds a read open across a switch.

## Proved, and what is not

- **Mutants.** 20 changes to the hook and 7 to the tab's call each fail the smoke, after a control in which it passes. Four survived at first, each a real gap, so four of the ten cases above were added and run on the tab as it stood too.
- The smoke's database stand-in now also keeps which rows a write was aimed at, apart from what it kept before.
- Lint and a focused `tsc` on the tab, the hook and the smoke. Every bids test and every test that reads the source tree pass.
- **Nothing was written on prod and no live site was opened.** Every name in the tests is made up.
- Not seen: the offer on the live site. Making one appear takes a save to the shared book, which is a write, so the walk below reads the drawer without one.
