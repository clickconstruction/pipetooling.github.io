# v2.5490 — Messages: where a residential customer is on their job is read in its own place, behind the scenes (2026-10-13)

A pure move, no change in what anything reads or does. R4 · 2 (v2.5395, #5560) appended the residential customer's stamps to `src/lib/flows/load.ts`, with five value imports: `billing/billTruth`, `jobs/billedExpectedPay`, `jobs/billToParty`, `jobs/paymentAttribution` and `jobReportsTimeline`. The edge functions' copy of the kernels (`scripts/edge-kernels.mjs`) reaches `load.ts` through `personFlowFrom` → `flowStampsFor` for the morning reminder run (`messages-nudge-dispatch`, #5639). So it would have carried every one of those files. - **`src/lib/flows/residentialLoad.ts`** (new) holds the section as it was: the Pipeline row types (`PipelineJobRow` … `ResidentialRows`), `isOnOurWayText`, `isReviewAskText`, `visitStamps`, `estimateStamps`, `statusStamps`, `reviewStamps`, `billedRounds`, `paidRounds` and `residentialStampsFor`, with the five imports.
- **`load.ts`** loses those imports and the section. It now exports the four small helpers the section shares (`stamp`, `nameOf`, `newest`, `lane`). Its header points at the new file.
- **The test** moves with it, `load.residential.test.ts` → `residentialLoad.test.ts`, its imports pointed at the new file and nothing else changed.
- The two tests that read the moved code from `./load`, `stageSends.test.ts` (#5572) and `card.strip.test.ts` (#5580), import `residentialStampsFor`, `PipelineJobRow` and `ResidentialRows` from `./residentialLoad`.
