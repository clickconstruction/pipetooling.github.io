# v2.3047 — Test-gap audit, pass 56: the paid-job email client gets its first tests (2026-09-07)

Follow-up to v2.3046. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`paidJobEmailClient.ts` (118 lines) is the client side of the `paid-job-email` edge function: preview, test send, test push and real send, shared by the Stages "Paid notifications" gear modal and the Job Detail ✉ modal so the two cannot drift, and reused by the crew-day, payment-forecast and billed-report email clients. Five callers, no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Each mode sends exactly its body: preview with the variant and, for Ready to Bill, the kind; test send to the caller by default or to a chosen user; test push likewise; the real send to a chosen user, whose role picks the variant reported back.
- Error text comes from the function's own response body on a non-2xx (supabase-js's generic "non-2xx" message is only the fallback when the body is unreadable), from the data on a 2xx, else each mode's fallback; an empty preview is refused.
- A test push reports how many devices it reached, zero when the function says nothing.
- Opening rendered HTML writes into a fresh tab, or falls back to a Blob URL when the popup is blocked, revoked a minute later.

## What shipped

- **`paidJobEmailClient.test.ts`** (7) — the edge invoke as a spy with real `Response` bodies for the non-2xx cases, `window.open` and the object-URL helpers stubbed, fake timers. Covers the tab opener's two paths, the preview bodies and five error shapes, the test send and test push bodies and results, and the real send's variant and errors.
