# v2.5273 — Messages: the reply box, quick replies and the phone read one list of types, behind the scenes (2026-10-12)

A types follow-up by helper 3, directed by the GC Review lead ("one list of types is worth it"). Cut 3's and cut 5's kernels (v2.5250, v2.5261, v2.5268) declared their own shapes while the spine (v2.5249) and the flows (helper 4) were still open. Both are on main now, so the kernels read theirs. No behavior changes, no screen, no table, nothing to deploy. Stacked on v2.5268 (#5443), whose Quo files it retypes.

- **Quick replies** (`quickReplies/kernel.ts`): who a line is for is the spine's `ContactKind` without `unknown`, plus `any`. `StepRef` is the flow's own `FlowStep` by its id and name. New `stepsByKind(flows)` reads a line's steps from the flows, the seed until the flows table is read. The test now takes its steps from `SEED_FLOWS` instead of a copy, and checks that every step `qrGuess` names is one the flows have.
- **The reply box** (`messages/compose.ts`): `ReplyKind` is the thread's `MessageChannel` narrowed to text, email and note. `OptoutRecord` is the spine's `ThreadMessage['optoutLine']`, so the opt-out line's values have one home. New `replyRecipient(contact)` reads the send window's recipient from the spine's `Contact`. The number is the first one that can still take a text, else the first they have, so a STOP from one number leaves the next one open.
- **The phone** (`quo/events.ts`, `quo/send.ts`): `QuoLine` and `SentLine` extend the spine's `ThreadMessage` fields, and their channel and direction are its `MessageChannel` and `MessageDirection` narrowed. The Quo kernels run on the edge, and the spine's contact kernel reaches outside `src`, so `events.ts` does not import it. Its tests hold the two together instead: `toE164` gives the same ten digits as the spine's `normalizeChannel` for every sample, and `unknownContact`'s result is checked at compile time against the spine's `Contact` and `ContactChannel`.
- **Escapes restored**: `compose.ts`'s carrier alphabet promised its Greek capitals "written by code point". The Write tool had turned the `\u` escapes into the letters themselves. They are escapes again, and so are `compose.test.ts`'s ohm sign and increment, which looked like Ω and Δ in review. Same code points, so nothing behaves differently.
- **Left for helper 4**: `flows/facts.ts` keeps its own `FlowKind`, which has the same four values as the spine's `ContactKind`.
