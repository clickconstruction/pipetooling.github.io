# v2.2195 — ChecklistAddModal: one form reset per open (2026-08-23)

Root cause of the day's CI flake (`ChecklistAddModal.render.test.tsx` "keeps the draft open by default" — failed full-suite runs for #1832, #1891, #1893 while passing in isolation) and a real bug: the form-reset effect in [`ChecklistAddModal.tsx`](../../src/components/ChecklistAddModal.tsx) depends on `users` / `authUser?.id` (to compute the default assignee), so the roster's async settling re-fired the reset and **wiped a draft already being typed** whenever it landed after the user started.

- `formResetKeyRef` guards the effect: reset only when the modal (re)opens or `initialAssigneeUserId` / `initialPreset` change; cleared on close. The separate fill-default-assignee effect (which runs when `users` lands and nothing is selected) keeps handling the late roster.
- Deps unchanged (lint-clean); behavior change is only "don't re-reset an open modal".

Client-only.
