# v2.8297 — Permits: every city can be read back to January 2025 (2026-11-22)

One of the things punch list #307 left when it closed: *the read back is San Antonio's alone so far*. The owner's word on 2026-11-22: do it here now. No migration. One edge function to deploy after the merge.

## What was there

Builders' **Read back to …** press reads a city's older permits three months at a time, so a builder's counts cover more than the weeks since the pull began. Only San Antonio's two feeds could be read up to a day. The other four cities' records start on 2026-08-27, the day their first pull read back to, and every count there says *since Aug 27*.

## What changed

- **Each of the four doors can be read up to a day.**
  - Austin's Socrata dataset: the same `$where` with `issue_date <` the day.
  - New Braunfels, San Marcos and Seguin, each a map layer: the layer's own test, with each of its day columns held to the window by itself.
- **`HISTORY_CITIES` is every city the pull reads.** The press, its words and the goal are unchanged: about 92 days a press, no further back than January 2025.
- **Nothing else moves.** The daily pull asks each door the page it always asked. A read back still flags every row `backfilled`, ignores a row already held, and refuses to run where the column is missing.

## Asked of each door before shipping

One small page and a count, from the URL the pull will ask, for the first step back and for the oldest step. Public open data, and nothing of ours was sent.

Every door accepted its window and holds records back to the goal. The counts are the door's, before the pull keeps the kinds it wants and drops a permit handed over twice. Austin's rows carry the contractor's phone, which v2.8296 keeps.

## What a press will do

- Seven presses a city reach January 2025 from August 27.
- A run reads up to twelve pages a feed inside 110 seconds. Austin's largest step is three pages of 2,000, and New Braunfels' is four of 1,000.
- Austin's rows that come without a point are filled from the county's parcel layer on the way in, as the daily pull fills them. That is the slow part of an Austin step. Austin's first pull read 75 days in one run.
- **Not pressed here.** A read back writes rows, and it is a person's press. The first press in Austin is the proof of its time. A read that stops on the time budget says so and leaves the start of the records where it was, and nothing it read is lost.

## How it is built

- `austinWhere(sinceDay, untilDay?)` and `AUSTIN_READER.pageUrlBefore`.
- `layerDayWindow(columns, since, until?)` writes a layer's day test. With no `until` it is the text each layer had, to the letter, which the tests hold.
- `mapLayerReader` builds both pages from one function.
