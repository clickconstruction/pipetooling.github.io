# v2.4853 — Send the run: print one copy or one envelope (2026-10-07)

Client only. Grace, with the run open on nine notices: *I want to be able to print individual items.* The run printed one way — **Print the packet · 9 envelopes**, everything in envelope order — and each copy row offered only *Preview ›*. A reprint of one lost page, or one envelope going out ahead of the rest, meant printing all nine again, which also filed a second copy on every job.

## What changed

- **Kernel** ([`lienDeskRun.ts`](../../src/lib/jobs/lienDeskRun.ts)): `runPagesHtml(pages, title)` is the packet's print shell, pulled out of `runPacketHtml` so one copy and one envelope print with the same paper. `runCopyHtml(n, r, …)` is one recipient's copy, its pages as `runCopyPages` stacks them; `runEnvelopeHtml(env, …)` is every copy inside one envelope in packet order. `runCopyKey` and `noticesFullyPrinted(notices, printed)` say which notices have every copy printed.
- **The run window**: *Print ›* beside each copy's *Preview ›* (`run-print-<job>-<recipient>`; it reads *Printed ✓ · Print again ›* once pressed), *Print this envelope ›* under each envelope's address line (`run-print-envelope-<n>`), and **Print this copy** in the preview overlay's footer (`LienRunPreviewOverlay` `onPrint`). Each goes through `printAndFile` with kind `lien_notice`, the copy's title, its job ids and the recipient, so Documents → Sent keeps it like the packet ([`SENT_COPIES.md`](../SENT_COPIES.md)).
- **The printed stamp**: printing one copy at a time stamps an item printed (`onPrinted`, into *In the mail · tracking owed*) only once every recipient of that notice has a copy, so a notice whose GC copy is still unprinted never reads as in the mail. Once every notice has printed this way, step 1 shows done as after *Print the packet*.

## Tests

`lienDeskRun.test.ts` (+2): a copy's document holds that copy's pages and no other notice, an envelope's holds every copy inside, the shell escapes its title; `noticesFullyPrinted` over half and whole notices. `LienDeskRunModal.render.test.tsx` (+2): Print › files the owner's copy alone with its title, jobs and recipient, the notice is stamped only after the GC copy prints and step 1 then reads done, the envelope door prints everything inside; the preview's button prints the copy on show. The `sentCopiesCoverage` test still sees every print go through `printAndFile`.

## Live

Dev server on prod data, the run of nine: the three doors drawn — *Preview › · Print ›* on each copy row, *Print this envelope ›* under each address, *Print this copy* in the preview footer. Not pressed: a press prints and files a real copy on a real job.

## Not done

- A reprint files a second copy on the job, as a second *Print the packet* does; Documents → Sent shows both.
- Printing one copy does not record the mailing; the tracking numbers and *Record the run* are as before.
