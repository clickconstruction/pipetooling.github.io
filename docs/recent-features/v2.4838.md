# v2.4838 — GC mode: New here? walks the GC projects page (2026-10-07)

*New here?* on real data (`to-dos/gc-mode/mockups/new-here-real.md` on branch `spike/gc-mode`), right behind door 1 (v2.4832). The prototype's walk is of the Project Board, which is not on main yet; this one walks the page testers use today.

- `src/lib/gc/tour.ts`: ten stops — the **Trades | GC** switch, **New project**, a project's card, its Drive line, **The plans**, **A new set of plans came in**, **Questions about the plans**, the red gap line, the scope book and **New here?** itself. A stop on a card points at the first card; on a page with no project it centers and says what will show there (`missingBody`). The footer links the guide *start a GC project*.
- Anchors are named for the thing (`gc-plans`, `gc-new-set`, …), not the place, so the board's move of the cards onto a project's own page (B3-a) carries them. `tour.test.ts` reads the page's source and fails when an anchor, a label a stop names or one of New project's four step names is gone, and holds every stop to `plainWordsFailures`.
- It opens by itself on a first visit, once per browser (`gc-new-here-seen-v1`, every storage call in try/catch), and on **New here?** in the header.
- Recorded for the testers' triage in `ui_nav_clicks`, no new table: `control = 'gc_new_here'`, target `opened?by=first-visit|button&of=<n>` on open and `closed?stop=<last stop reached>&of=<n>` on close (`gcNewHereTarget`). `SpotlightTour` gains an optional `onStep(index)` for it (an addition; other tours unchanged), and `Btn` in `gcUi.tsx` an optional `dataTour`.
- Guide `start-a-gc-project` says where the walk is. `GcProjects.render.test.tsx` covers the first-visit open, the missing card's words, the close's record and the button.
