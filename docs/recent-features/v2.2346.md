Tier 1 of the start/due-date design (owner report: a task dated next Monday
wore the red "open today" chip). `openAgeLabel` collapsed every future date
into "open today" — scheduled work was indistinguishable from overdue work.

- **Kernel** `checklistManageGroups.ts`: `openAgeLabel` gains a future
  branch — "starts Mon, Aug 31" (same date wording as the repeating rows'
  `nextOccurrenceLabel`); new `isScheduledAhead()` (strict YMD string
  compare); +2 test blocks.
- **Manage tab** (`Checklist.tsx`): one-offs split into
  `ONE-OFFS · N open` (actionable today) and `SCHEDULED · M` (future,
  soonest start first) in both the One-offs and All views; the "starts …"
  chip renders blue (`--bg-blue-tint`) instead of the red open clock. The
  One-offs pill keeps the combined total.
- Tier 2 (optional `due_date` on one-offs) ships separately: migration
  first, then client + reminder-cron re-keying.
- Help guide *schedule a task or make it repeat* documents the section.
