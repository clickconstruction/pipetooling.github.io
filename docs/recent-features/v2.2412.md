# v2.2412 — Recently deleted: price-option bundles restore whole (2026-08-28)

Incident follow-up (same 2026-08-27 BP384 deletion as v2.2409): the deleted
`price_book_versions` 69491f86 could not be restored — Preview reported
"Cannot restore — nothing was changed: price_book_entries.version_id … no
longer exists (required)".

**Diagnosis** (live-schema dump, 2026-08-27): nothing was missing from the
archive. All five tables in the cascade (`price_book_versions`,
`price_book_entries`, `bid_count_row_custom_prices`, `bid_pricing_assignments`,
`bid_count_row_submission_hides`) have live `zzz_archive_on_delete` triggers
(20260716120000 + 20260716150000) and every row was captured. The failure is
group-key wiring: the pbv row and the three satellites archive under the
**bid** uuid, the entries under the **pbv** uuid — one user-level deletion,
two bundles. The pbv-keyed bundle (the one a dev naturally picks) contains
only entries, whose NOT NULL `version_id` FK reads as a hard blocker.

**Fix** (migration `20260828031500_deleted_records_price_option_bundles.sql`,
DB-only — no client change):

- `restore_deleted_records` seeds three ways: rows grouped under the handle,
  the archived record whose `record_id` IS the handle (the deleted parent that
  archived under a higher group), and — only when that parent is itself among
  the deleted — rows whose `row_data->>'price_book_version_id'` points at it
  (the satellites). Both the pbv-keyed and the bid-keyed partial bundle now
  assemble the complete deletion. Trigger group keys are deliberately
  untouched: re-keying the satellites to the pbv would have fragmented
  Clear-all-counts bundles (they also cascade from `bids_count_rows` deletes).
- Pass-2 inserts run newest-first per table with `ON CONFLICT DO NOTHING`:
  archived stale generations (assignment/custom-price churn, re-created
  composite-PK hides) are skipped with a warning instead of a unique-key
  violation aborting the all-or-nothing restore. FK violations still abort.
  `inserted`/`total` now report actually-inserted counts.
- `list_deleted_records` head-row lookup falls back to `record_id = group_key`,
  with a `price option` kind and a "〈name〉 · Bid 〈number〉" label, replacing
  "Partial delete under 69491f86". Return shape unchanged.

Verified on a scratch Postgres loaded with the prod schema dump: price-option
delete (with unassign churn) previews + restores the full set from the pbv
handle; Clear-all-counts-shaped and whole-bid bundles restore unchanged.
