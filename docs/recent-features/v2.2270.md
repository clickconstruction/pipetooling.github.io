# v2.2270 — Hold-to-reorder on Outstanding by person (2026-08-25)

The Review tab's per-person task rows (`OutstandingByPersonSortableRow`/`List`
in `src/pages/Checklist.tsx`) reorder by **press-and-hold anywhere on the
card** (mockup artifact 1647b4e5), restoring mobile reordering — the desktop
grip has been hidden on phones since the v2.2201 two-line rows, leaving no
touch path at all.

- **Sensor**: the list's `PointerSensor` activation constraint changes from
  `{distance: 8}` to `{delay: 280, tolerance: 8}` — hold to lift (mouse or
  finger); a tap under the delay still expands; movement >8px inside the
  delay cancels the lift so native scrolling wins (`touch-action: pan-y` on
  the row keeps it alive).
- **Drag surface**: the sortable listeners moved from the grip button to the
  `<li>` itself; the grip stays as a desktop affordance (and keeps the
  aria attributes). `user-select: none` on rows stops long-press text
  selection fighting the hold.
- **Lift styling**: while dragging the card composes `scale(1.02)` onto the
  sortable transform, goes fully opaque on a `--surface` background with a
  floating shadow and z-index 5 — replacing the old 0.85-opacity ghost.
- **Ghost-click guard**: a `wasDraggedRef` set while `isDragging` and consumed
  by an `onClickCapture` on the li swallows the browser's trailing click
  after a drop (it used to be able to toggle the expansion or hit ✓/🗑/cost);
  reset on every fresh `pointerdown` so the next tap works.
- Reordering + persistence unchanged: dnd-kit sortable + per-person
  `checklist_item_assignees.display_order` sequential writes (quirk #9 in
  `CHECKLIST_TABS_ARCHITECTURE.md`), same order Today follows.
