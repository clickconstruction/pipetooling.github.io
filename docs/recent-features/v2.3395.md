# v2.3395 — Subs board polish: the five residuals from the 2026-09-08 live test (2026-09-14)

Client only; no migration, no edge function. Clears the "Subs board follow-ups" section of `to-dos/subs-residuals.md` — the five cosmetic defects seen when v2.2963's Work board, tile queues, calendar and row forms were driven live (PR #2832). Each fix lives in a pure kernel with a test; the components changed only where they read the kernel.

## Why

The live test left five small wrongs on the board: the calendar's sibling list read "Claude Test Sub · Claude Test Sub", the rail and the move said "good through 2026-09-14" in raw ISO, Offers out opened a live offer on Re-send the moment it arrived, Undo in the handshake queue left a row reading "No longer on a handshake" when what had happened was a withdraw that kept a draft, and a sheet with no items read "unpriced" beside a $1,200 order. None blocked, all confused.

## What shipped

1. **Calendar sibling names** — [`stageCalendar.ts`](../../src/lib/subs/stageCalendar.ts) gains `calendarRowName(stageName, kind)` (+1 test): the stage the order carries, else `Sheet` / `Stage`; the sub's name rides only on the sibling line's second half. `JobsSubsWorkView.tsx` uses it for the calendar title and the siblings, so a sheet row reads "Sheet · Claude Test Sub".
2. **Short-day dates** — [`sheetRail.ts`](../../src/lib/subWorkOrders/sheetRail.ts) and [`standingMove.ts`](../../src/lib/subs/standingMove.ts) format `sentAt` / `expiresOn` / `signedOn` through `formatWorkDateYmdMonthDayShort` from `src/utils/dateUtils.ts` (the same "Sep 8" words `stageWindowLabel` uses): "Sent · Sep 8 · good through Sep 14", "signed Sep 5", "expired Sep 11". The calendar's sub line ("offer out since Sep 8", "signed Sep 5") reads the same helper. Tests updated in `sheetRail.test.ts` / `standingMove.test.ts`.
3. **Which row opens on arrival** — [`subsTileQueues.ts`](../../src/lib/subs/subsTileQueues.ts) gains `initialOpenKey(rows, keyOf, wantsForm?)` and `offerWantsForm` (an expired offer wants the Re-send form; a live one does not) (+1 test). `useQueueState` takes the optional `wantsForm`; `OffersQueue` passes `offerWantsForm`, so a queue of live offers arrives with every row collapsed, and the first expired row still opens on Re-send. Handshake / Stages / Signed keep opening their first row.
4. **Undo says what it did** — `HandledMark` gains an optional `action` (label · run · danger) and `HandledCell` draws it beside Undo. `SubsTileActions.withdraw` now resolves a boolean (false when the office backs out of the confirm or the write fails) and gains `discardDraft` (the board's existing Discard-the-draft confirm + write). In `HandshakeQueue` and `OffersQueue`, Undo on a sent / re-sent row withdraws and re-marks the row **Withdrawn · draft kept** with **Discard**; discarding puts a handshake row back in the queue (the sheet is on a handshake again) and marks a re-sent row "Draft discarded".
5. **Agreed falls back to the order** — [`workOrderBoardRows.ts`](../../src/lib/subWorkOrders/workOrderBoardRows.ts): when a sheet's items total zero and its sent or signed order carries an amount, `agreed` is that amount, `unpriced` is false and `open` = amount − paid − back-charges (+2 tests). Items on the sheet still win over the order; a draft carries no price, so a sheet with no items behind a draft stays unpriced. The rail, the next-move hint, Make Payment's default and the money column all read the same row fields, so they agree.

Guide *clear the four Subs tiles from the board* updated for the arrival rule and the Undo mark. Release note v2.3395.
