# v2.6124 — dev-pane-login: a session signs the browser pane into the deployed app itself (2026-10-30)

Taunya's ask of 2026-10-30, after sessions kept reporting *the pane isn't signed in to clicktooling.com and lands on /sign-in, so I can't walk the deployed app without a password*: a tool that lets a session test on production without prompting her, saved on the machine so it survives restarts, with the rule that a session may make test things as long as it cleans them up afterward.

## What changed

- **`scripts/dev-pane-login.mjs`** calls the `dev-login` edge function exactly as the dev server's `/dev-login` page does (`X-Dev-Login-Secret` from `.env.local`'s `VITE_DEV_LOGIN_SECRET`, the anon key, `DEV_LOGIN_EMAIL`), with `redirectTo` on clicktooling.com instead of localhost, and prints the `action_link`. A session navigates the Claude app's browser pane to it; the verify redirects to the site with the session in the URL hash, the app's client picks it up, and the pane's persistent profile keeps the sign-in across app restarts. One use per link. A path argument chooses the landing page.
- **`AGENTS.md`** → *Logging in as an agent* carries the one line and the rule for a session on the live app: read as the task needs; test rows only under the ZZ test name, every one deleted before the session ends; never a real customer's or person's row.
- **Not in the repo:** the permission rule that lets a session run it without a prompt lives in the main checkout's gitignored `.claude/settings.local.json` (`Bash(node scripts/dev-pane-login.mjs:*)`), set on this machine on 2026-10-30.

## Decisions

- **The existing door, not a new one.** The function and its secret already exist for the dev server; the client-side `/dev-login` page stays DEV-only, so the deployed bundle still ships no secret. The script is where the secret already is.
- **It is a real login.** The identity is the dev-login account on prod with its full rights, so the cleanup rule is written where every session reads first, not only in the script.

## Test

`node scripts/dev-pane-login.mjs` prints one `https://…/auth/v1/verify?…redirect_to=https://clicktooling.com/dashboard` link; the pane navigated to it lands on the dashboard signed in; a second navigation to the same link is refused (used). Quit and reopen the Claude app: the pane is still signed in. Not run by the session that wrote it: the safety classifier refused to mint a prod link from the agent, so the first run is Taunya's from Terminal.
