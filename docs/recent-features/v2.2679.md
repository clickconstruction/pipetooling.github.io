# v2.2679 — Contract Desk PR 1: job_contracts schema + contract coverage on the Pipeline (2026-09-03)

First PR of the owner-approved "Contract Desk" build (proposal artifact 63e6de80, 2026-09-03): every job carries a customer-signed agreement, the office sends one from wherever it is already looking at the job, the customer signs on a phone, and the app counts only the true gaps. This PR lays the schema and makes the coverage visible; sending (PR 2), the public signing page (PR 3), and the backlog sweep (PR 4) follow.

## DB (migration `20260903141146` — fragment in docs/migrations/)

- `job_contracts` (one live draft|sent per job; frozen document + e-signature audit on signed rows; voided rows keep the trail), `job_contract_events`, `contract_template_documents.audience` (staff | customer), the `job_contracts_to_activity()` bridge trigger (`contract_sent` / `contract_viewed` / `contract_signed` / `contract_voided`, all financial). RLS mirrors `job_lien_releases`; read-only appliers + twin fence. Bucket `job-contract-documents` is out-of-band SQL in the fragment.

## Client

- **Coverage kernel** [`lib/jobs/jobContractCoverage.ts`](../../src/lib/jobs/jobContractCoverage.ts) (+10 tests): per job, a signed `job_contracts` row wins, a paper upload counts, a customer-accepted estimate WITH the e-signature consent stamp counts (owner decision 1, proposed default), a signed bid-room proposal on the job's bid counts; then sent → draft → none. Chip label/title vocabulary (`No contract`, `Contract sent · opened 2× · 6d`, `✍ Signed Sep 1 · M. Palmer`, `✍ Signed · estimate #84`, `✍ On file · paper`), the `missing | sent | signed` filter, and the `?contract=` deep-link parser.
- **Chip** [`components/jobs/JobContractChip.tsx`](../../src/components/jobs/JobContractChip.tsx): gray / amber / green, the `BidRoomStateChip` grammar; becomes a button once a surface passes `onOpenJobContract` (PR 2).
- **Pipeline**: `JobsStagesTab` loads coverage side-data (one `job_contracts` scan + one customer-accepted `estimates` scan, fail-soft, office roles only, refreshed on the `job-contract-changed` window event) and passes it through `StagesRowRenderContext`; every job row's Job cell footer renders the chip above the Stripe hint. The ⋯ menu's Filters group gains a contract-state select (Any / No contract / Contract out for signature / Contract signed) with the matching active chip in the search bar; `?contract=missing` deep-links it on.
- **Activity registry**: the four contract event types render with a `Contract` tag in the billing bucket.
- Help guide `get-a-job-contract-signed.md` (coverage + filter now; the send and sign sections grow with PR 2/3).

## Owner decisions taken as proposed (change any in the kernel's options)

1. An estimate accepted through the accept page counts as the agreement. 2. Every non-paid stage is in scope. 3. Senders = the lien-release office set. 4. Templates seed in PR 2. 5. Amount = job total → accepted estimate total → typed. 6. Reminders default on (PR 5).
