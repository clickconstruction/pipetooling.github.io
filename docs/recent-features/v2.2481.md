# v2.2481 — The customer document paints its own paper (2026-08-29)

Second and third finds from the owner's screenshot review (first was the bid room,
v2.2478): the estimate acceptance page and the in-app document had mirror contrast bugs.

- **Public accept page**: renders inside the auth landing shell, whose base text is
  light-on-photo — the title, option names and prices, "Your selection" heading, total,
  and terms carried no color tokens of their own and inherited near-white on the white
  card.
- **Dark-mode app**: the pinned-light document resolved light-palette ink against the
  app's dark card — dark-on-dark for every tokened element.

One fix covers both, and it's the printing-house rule: `EstimateCustomerDocument`'s
pinned-light wrapper now paints its own ground and ink — `var(--surface)` background,
`var(--text-strong)` base color, a little padding — so the customer document is a white
sheet wherever it renders: the accept page, the dark-mode detail, staff previews, the bid
room (which shares the components). Also: the option picker's name row wraps now, so the
Recommended badge no longer crowds the price on phones.
