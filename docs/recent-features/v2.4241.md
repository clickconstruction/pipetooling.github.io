# v2.4241 — Four more date boxes save a finished date only (2026-09-30)

The follow-up to [v2.4239](./v2.4239.md), which fixed the procurement log and listed four more date boxes that write on the change event. A browser reports a date on every key that completes one, so the year "2026" arrives as `0002-…`, `0020-…`, `0202-…`, `2026-…`, and each of these boxes wrote every one of them. Measured in Chromium on the Sheet date while building this: typing `0` into the month of a full date also fires a change with `''`, which the old Sheet date, expires and sign-by boxes wrote as null.

- [`dateBoxEntry.ts`](../../src/lib/dateBoxEntry.ts) — the shared kernel. `isPlausibleDate(iso)` (a real `YYYY-MM-DD` day, year `DATE_BOX_MIN_YEAR`–`DATE_BOX_MAX_YEAR`, 2000–2100), `readDateBoxEntry(raw, shown)` (`save` / `unchanged` / `unfinished`), `holdsDateBoxChange(typed, raw, shown)` (a typed change waits; a pick waits only when unfinished) and `unfinishedDateMessage(year)`. These are v2.4239's `isPlausibleLogDate` / `readLogDateEntry` under shared names. The procurement log still carries its own copies: moving them is a separate, mechanical PR, held until the open procurement-log work on the same three files (v2.4243) has merged. The panel keeps its own `dateBox()` either way (its Expected box compares against the stored date, not the derived one it shows).
- [`FinishedDateInput.tsx`](../../src/components/FinishedDateInput.tsx) — the shared box: `value` is the date it shows when nothing is being typed, `onCommit(value | null)` fires for a finished date or an emptied box and never for a half-typed one. Same rules as v2.4239's `dateBox()`:
  - a change that follows a key press in the box is **typed**: it waits in the box's own draft, and commits on blur or Enter;
  - a change with no key press is a **pick from the calendar**: it commits at once, unless it is unfinished;
  - on blur an unfinished draft, or a box with a part missing (`validity.badInput`), is dropped with the toast *That date was not finished, so it was not saved…* and the box shows `value` again. The box is put back with `el.value = value`, not `''`, so a box over a saved date does not read empty when no re-render follows.
- The four boxes, each now a `FinishedDateInput` and none of them disabled while its save runs:
  1. **Edit Job → Our contract on this job → Date** ([`JobFormLienContractRow.tsx`](../../src/components/jobs/JobFormLienContractRow.tsx)) → `jobs_ledger.lien_contract_ended_on`. `setDate` and `setEnded` check `isPlausibleDate` where they checked the `^\d{4}-\d{2}-\d{2}$` shape, so a state button cannot carry a half-typed year either. `save()` is a one-at-a-time promise queue reading `loadedRef`, where it used to return early while `busy`: a date committed during another save is queued, not lost. The Still open / Complete / Terminated / Abandoned buttons are no longer disabled while a save runs — a click on one of them is what leaves the date box, that blur saves the date, and the click has to land. The retainage box and the bond buttons are as they were.
  2. **Jobs → Subs → a sheet → Sheet date** ([`JobsSubLaborTab.tsx`](../../src/components/jobs/JobsSubLaborTab.tsx)) → `people_labor_jobs.job_date` through `onUpdateLaborJobDate`.
  3. **People → Subs → Documents → expires** ([`PeopleSubsTab.tsx`](../../src/components/people/PeopleSubsTab.tsx)) → `person_contract_documents.expires_at`.
  4. **Partnerships → Agreements → sign by** ([`PartnershipAgreementsTab.tsx`](../../src/components/partnerships/PartnershipAgreementsTab.tsx)) → `person_contract_documents.sign_by`.
- Guides: *send lien notices from the lien desk*, *sub labor outstanding* and *keep a sub's paperwork current* each say when the date saves.

**Not changed:** any saved date. Nothing here touches prod data; a bad year already saved on one of these four shows in its box and can be retyped or cleared.

**Left alone on purpose — the debounced autosaves.** The job contract's start and completion dates, the lien waiver's through and signature dates, Edit Bid's due / estimated-start / plan dates, a payment's Received date and an estimate's valid-until and response-requested-by save on an 800–1500 ms debounce, so a pause mid-year can write `0002-…`. Unlike the boxes above, none of them disables or reverts the box, so the finished year is written by the next debounce; the bad date stays only if the form is closed mid-year. Each needs a different gate, surveyed here so the next session need not repeat it:
  - job contract and lien waiver (`JobContractModal.tsx` / `LienReleaseModal.tsx`, `buildRowPayload`): the dates ride inside one `fields` jsonb, so the gate is *skip the autosave*, not drop a key;
  - Edit Bid (`useBidEditController.autosaveBid`): delete the date key from the pruned payload, the way `bid_date_sent` is deleted on an attestation error; never through `enabled`, which makes close report `clean`;
  - payments (`useJobFormAutosaveEngine.persistBillingSlice` → `diffPaymentRows`): the upsert rewrites the whole row, so skip the write; nulling the value would clear a saved date;
  - estimates (`estimateDraftPersist.buildEstimateDraftPersistPayload`): omit `valid_until` / `change_order_fields`; the payload is also the dirty check, so mapping to null would autosave a null.
  - Read from the code in passing, not reproduced: the billing slice's dirty check (`buildBillingSliceJson`) carries `paid_on` but not `sent_on`, so a change to a payment's **Sent** date alone does not start an autosave.

Walked live in dev (Chromium) without saving anything. People → Subs → Documents, an empty expires box: `09/30/2` and leaving wrote nothing, emptied the box and showed the toast; `09/30/2026` fired the four change events and wrote nothing while the box had focus; backspacing the year and leaving wiped it. Jobs → Subs → a sheet's Sheet date (08/20/2026): backspacing the month and leaving put 08/20/2026 back with the toast; typing the month to 09 held `2026-09-20` in the box for two seconds with no write, and typing it back to 08 and leaving wrote nothing. The saves themselves (blur, Enter, a pick, an emptied box) are render-tested, not walked, because they write to prod. Not seen in Safari: if Safari sends no key events from its date field, a typed date saves on the change that finishes a plausible date, and a half-typed year is still held back.
