# v2.7969 — Papers: a mail kept as a paper takes only its real files (2026-11-19)

Punch list #368, a follow-up to v2.7954. Client only: no migration and no function.

## The wrinkle

**Keep this mail as a paper** has no form to tick files in: it sends every file on the mail's line into the paper's folder, **Plans › <paper name>** under the job's Drive folder. A signature's logo (*image001.png*) and Gmail's picture of a Drive link sit on that line as files, so each would have landed in the folder beside the spec book.

A read of prod on 2026-11-19 found no paper kept through the press yet, so no folder holds such a picture. Of the 47 emails on Pipeline jobs, 10 carry a real file, 3 carry only a logo and 5 carry only a link's preview picture beside the link.

## The rule

The press's file split asks the same name rule the bid's press asks, `isInlinePicture`, which moved to `src/lib/messages/inlinePicture.ts` so both can import it (`bidMailSet.ts` still exports it).

- `splitMailFiles` (`src/lib/plans/planSetFiles.ts`) answers a third list, `pictures`: the pictures from inside the mail's words. They are in neither `ready` nor `left`, so none is sent and none is named as *stays in Gmail*.
- The line under the mail counts them after what landed (`picturesLeftOutWords`, `MailFilesResult.pictures`): *One picture inside the mail's words was left out, a logo or a link's preview.* The press takes every file with no tick to give back, so a picture left out is said, never dropped in silence. The count alone never turns the line amber.
- A second try of files that did not land keeps the count from the first read.
- `realFileCount` counts a mail's files without such pictures. The two places that hand the door a count for *This mail's file stays in Gmail for now* use it (`MyMailReader`, `EmailViewerActions`), so a mail no line holds, with only a logo, no longer says a file stays behind.

A picture left out is still on the mail's line, where it opens as before. A person who wants it in the folder can put it there in Drive.

## Not in this change

My email's reader still offers **Keep this mail as a paper** on every mail tagged to a job, with or without a real file, while the mail's window in Messages offers it only on a mail that carries one. Which of the two rules both screens should follow is not decided yet.
