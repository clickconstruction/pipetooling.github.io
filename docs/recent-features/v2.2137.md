# v2.2137 — Adopt an existing bid into a package (2026-08-23)

F6b of the "Send or Compare" train (decisions D7b/D7c/D8; plan: claude.ai/code/artifact/7610faf4-e0ff-4d39-b42c-1c2b18748cb9). The reverse of split: a bid that already sits on the board becomes a **version** of another bid. This is how the Jakes project (eleven board bids, each with its own counts) becomes one package.

**Migration `20260823041240_adopt_bid_as_version.sql`**
- `bids.adopted_into_bid_id uuid NULL → bids` (+ partial index). Set on the source when adopted; lists filter `adopted_into_bid_id IS NULL`. Never deleted; the number still looks up.
- RPC `adopt_bid_as_version(p_target_bid_id, p_source_bid_id, p_name, p_target_base_name DEFAULT NULL) RETURNS uuid` (SECURITY INVOKER; both bids must pass `can_access_bid_for_pricing`; source must be unsplit and not already adopted; target ≠ source). An unsplit target first materializes its current setup (`materialize_bid_version`, name `p_target_base_name` or "To Plans"). Then: new `bid_versions` row (in letter, base, `customer_id` = source GC only when it differs from the target's); **moves** the source's NULL-version count rows, takeoff mappings, rough-in lines, price scenarios (and their custom prices / hides / assignments) under the new version; ★ = the source's saved ★ when it moved; inserts a `bid_version_sends` row from the source's `bid_date_sent` / `bid_value` (`round_label` "adopted from B345"); marks the source `adopted_into_bid_id` + `working_board_archived_at`. Cost estimate / labor stay on the source row for reference (D8).
