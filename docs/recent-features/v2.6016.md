# v2.6016 — A residential job's step notes and presses file on the Pipeline job (2026-10-28)

The follow-up v2.6007 left. A residential customer's job is a Pipeline job (`jobs_ledger.id`), filed in `jobs_ledger_id`, and v2.6007 taught the run and the marks (`nudge_holds`, `nudge_sent`) to read that column; a step's team note (`messages` with a `step_key`) was still read from `project_id` alone, so a note on a Pipeline job's step read as a note on no job. Checking how a note is written turned up the deeper gap: the client's presses (`flowPresses` in `flowPersonIo.ts`, behind the step card and Follow up's Nudges) named every job a GC project (`p_job_kind: 'project'`), so `contact_job_check` refused a Pipeline job's id with *No job with that id*, and no note, skip, hold or Remind now on a residential customer's per-job step ever filed (the dev seat sees no step note and no hold in prod). The RPCs themselves (`flow_add_note`, `flow_skip_step`, `nudge_hold_until`, `nudge_record_sent`) already took `'pipeline'` and filed it on `jobs_ledger_id`.

- **The press names the job in its column** ([`flows/person.ts`](../../src/lib/flows/person.ts), [`flowPersonIo.ts`](../../src/lib/flows/flowPersonIo.ts), + 2 tests): `PressJob` is `{ projectId, jobsLedgerId? }`, the shape `jobOfMark` reads; `pressJobOf(kind, jobId)` gives a residential customer's job as `jobsLedgerId` and anyone else's as `projectId`, the column the run's `jobAtFor` files on; `job()` sends `'pipeline'` for the one and `'project'` for the other. [`useFlowPerson.ts`](../../src/hooks/useFlowPerson.ts) (the card's Add a note, Skip for them, Hold until and Remind now) takes the kind from the person's reading, [`useFlowNudges.ts`](../../src/hooks/useFlowNudges.ts) (Follow up's Hold until Mon and Remind now) from the row's person, and the card's Let it go finds the hold through `jobOfMark`.
- **A note reads on its job** (`person.ts`, [`flowNudgesIo.ts`](../../src/lib/flows/flowNudgesIo.ts), [`messages-nudge-dispatch`](../../supabase/functions/messages-nudge-dispatch/index.ts)): `StepNoteRow` carries `jobs_ledger_id`, `personFlowFrom` keys each note by `jobOfMark`, and the three readers select the column, so the step card and the run's `PersonFlow.notes` show a Pipeline job's note on that job.
