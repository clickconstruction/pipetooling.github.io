PR 1 of three on [`to-dos/ticket-text/README.md`](../../to-dos/ticket-text/README.md), the mock-up's frames T2 to T5 and the plan's *Copy the receipt link*. It sends no text: the office hands the link out by hand, which proves the page on real charges before PR 2 lets the app text it.

## What changed

- **The page `/r/<code>`** (`src/pages/ReceiptLink.tsx`, outside the Layout, lazy, in its own Suspense): one charge's store, amount, the time of the swipe, whose card by first name and its job; **Take a photo of the receipt**; a photo or a PDF already on the phone; the holder's jobs around the day as chips that can be skipped, with **Not for one job**. After the upload: *Got it*, the thumbnail, **Retake**, **+ Add a page**, and the chips to change the job. A charge that has its ticket from Tally or the desk says so and takes one more page. A link past its day reads *This link has closed* with the door to Tally; a code that opens nothing reads the same headline with no press; twenty wrong codes in an hour hold the source off for the hour (`estimate_link_miss`, the estimate link's guard). A link that names several charges draws each with its own press (PR 2's one text for two charges in an hour).
- **One record, two doors.** A photo through the link is a `counter_tickets` row with `source = link`, already on its charge with `match_kind = link`: no minute, no total, no question. The holder is its taker, so it shows in their My tickets; the pages go to the `counter-tickets` bucket under the holder's id; the photo sweep files them under Team only › Tickets once the ticket has a job, as any ticket. The matcher never looks at it, since it is matched.
- **The job it carries** (`receiptTicketJob`): the office's sort wins (the largest split's job, and the page asked nothing); else the chip tapped, when it is one of the jobs the page was offered (a job id from anywhere else is dropped); else none, and the office's Tickets list asks, as it does for a Tally ticket with no job. The day's jobs are Sort mode's own rule, moved to `supabase/functions/_shared/dayJobsOrder.ts` so the function reads the one source (`src/lib/tally/sortModeDayJobsOrder.ts` re-exports it).
- **The function `receipt-link`** (`verify_jwt = false`; the ten-letter code is the capability): `GET ?code=` the charges; `GET ?code=&page=` one page's bytes for the page's own thumbnail; `POST page` (base64, at most 8 MB, its first bytes a JPEG, a PNG, a WebP or a PDF, eight pages a ticket; a second try with the same page id writes nothing twice; `replace` is Retake, and a page the sweep has filed already is kept with the new shot added); `POST job`; and, signed in as the office, `POST desk.mint`. `docs/EDGE_FUNCTIONS.md` → *receipt-link*.
- **The database** (`docs/migrations/20261113061500_receipt_requests.md`): `receipt_requests`, one row a charge; `receipt_links`, one row a code, only its SHA-256 kept; `receipt_request_ensure`, which reads the holder from the charge's attribution, else the card's link; the two new words on `counter_tickets`.
- **Copy the receipt link** on a Team queue charge line with no ticket (`TallyTeamDayCard.tsx`, `TallyTeamQueue.tsx`, `copyReceiptLinkFor`). Safari writes the clipboard only inside the press, and the link is not there until the function answers, so the clipboard is handed a promise of the words. ## Two things that differ from the card, and why

- **A link is its own row, not a column on the request.** The card keeps *the code's hash* on the request. Only the hash is kept, so a code can be handed out once; the office's second Copy and PR 2's reminder each need a code after the first, and a second code must not close the first. So `receipt_links` holds one row a code, naming the requests it opens (up to ten, which is also how one text opens two charges).
- **The link is the app's own address, `clicktooling.com/r/<code>`, not the short host's.** The Worker on `my.clickplumbing.com` forwards `/e/` and `/pay/` and has no rule for `/r/`; it is edited in the Cloudflare dashboard. `RECEIPT_SHORT_ORIGIN` is null until the rule is live, and the text of PR 2 wants it (a shorter link is a cheaper text).

## Is this the best we can do?

For a page with no sign-in, close to it, with four known limits.

- **No outbox.** A photo that has not sent lives on the page alone. The page says so, asks before it is left, offers Try again and sends by itself when the signal returns. The Tally press is still the door that survives a dead zone.
- **The bytes go through the function** as base64 (the card's shape, the sub portal's signature). It keeps the first-bytes check and the write in one place, at the cost of an 8 MB ceiling; a store's PDF over that is refused in words. First look's one-file upload address would lift the ceiling and is the change to make if a real PDF ever hits it.
- **Whose card is a first name, not the last four.** The feed row carries the card's id and nothing printed on the card, and the app keeps no last four, so the mock-up's *ending 4471* is not drawn.
- **A link forwarded is a link shared.** Whoever holds it can add a page to that one charge and read its store, amount and day. It cannot read another charge, a job's folder or a price, and it closes in fourteen days. The source and match kind are written by the service role; a signed-in person could still write `source = link` on their own ticket by hand, which changes a chip's words and nothing else.

## Proved, and what is not

- 23 kernel tests (`receiptLink.test.ts`), 17 render tests (`ReceiptLink.render.test.tsx`), the ticket words and chips.
- The migration applied twice on a throwaway Postgres 15 with stub tables and the real `counter_tickets` table, then 41 checks: the two words taken and the old checks standing, the request made once a charge with the right holder in four cases, the shapes, and that no signed-in role writes either table or calls the ensure. The fences are stubbed there, and Postgres 15 is not the app's 17.
- Not proved until the push and the deploy: the function against the real tables and bucket, a real phone's camera through the page, and the sweep filing a link's page in Drive. PR 1's walk is on a ZZ Test person's charge.
