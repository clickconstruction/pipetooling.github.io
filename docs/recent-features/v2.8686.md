# v2.8686 — Agreements: the ground for saying a paper prints its site's address (2026-11-27)

Punch list #439 (`to-dos/site-nda-for-vendors/README.md`), piece 3: the view migration behind a line on the lists that says a paper prints its address. Asked on 2026-11-27 as a follow-up of v2.8676, which named it as found and not built.

**Read.** v2.8676 let the office tick **Print the site's address on the paper**, kept on the paper's row as `site_prints_address`. Documents → Agreements reads the view `agreements_on_file`, which answers three of the four site columns (v2.8659) and not this one. So no list could say which papers that are out show their signer the address.

**The mend.** Migration `20261127050501_agreements_on_file_site_print.sql` restates the view from its newest definition with one column at its end: `site_prints_address`. A person's or a party's paper answers its own, false unless the box was ticked. A contract, a work order, our contract with an owner and a statement of work answer null. Every column before it is the same and in the same order. `security_invoker` and the grant are as they were.

**Nothing on a screen changes.** No screen reads the column yet. Who reads a line does not change.

**Three beds changed with it.** A view never loses a column, so an older definition can no longer replace this one. `agreements-on-file` and `paper-party` already dropped the view before applying its older files again, and each now applies this file last. `paper-site` applied the view's file over itself: it now drops the view first too, and applies both of the view's files in order.

**Tests.** The `paper-site` bed reads the view: its last four columns in order and of their types, no paper printing its address until the box is ticked, the one ticked paper saying so and no other, and null on a line that is no such paper. No whole-schema bed runs on the Mac that built this, so the SQL beds job on the PR is the proof.
