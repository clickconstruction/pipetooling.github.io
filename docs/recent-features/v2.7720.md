## What shipped

- **`src/lib/bids/rekeyClonedPricing.ts`** (18 tests): `rekeyClonedPricingToVersion(supabase, …)`, lifted out of the tab as it was, the way `loadScenarioInputs` left in v2.3856. When a GC with no prices starts from another GC's base price, the clone's custom prices, assignments and submission hides still name the other version's count rows. This reads both versions' rows, pairs them by fixture name within the alternate scope, and moves each child to its row's counterpart or deletes it when there is none.
  - `rekeyRowMap`: the pairing, over the tested `mapCountRowsByFixture` and `alternateScopeKey`.
  - `rekeyPlan`: the pure part. One table's children in the order read, each a move or a drop.
  - `rekeyTableCounts`: the toast's two counts are prices. Only custom prices count, never assignments or hides.
- **`BidsPricingTab.tsx`**: its `rekeyClonedPricingToVersion` is the call and the error line, 18 lines where 72 stood. With the import, 53 lines out.

## What stays as it was

- **The order.** Both row reads first, the source before the target. Then one table at a time, custom prices, assignments, hides: one read, then one write per child, in the order read.
- **Not atomic** (the map's quirk 20). A write that fails stops the run where it stands, the children before it stay moved, and the reason goes to the tab's error line. Making it one transaction is an RPC and a migration, not this move.
- **The error said.** A failed rows read touches no child. When both rows reads fail, the target's reason is the one shown, as before.

A failed read or write at each point stops where the inline code stopped.
