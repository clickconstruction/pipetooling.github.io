# v2.3188 — Add checklist item docks to the top on phones (2026-09-09)

Client only. Owner, with a phone screenshot circling the top of the modal: "I think there is excessive white space at the top of add checklist item." Measured from the CSS on an iPhone 13: the overlay's `1rem + env(safe-area-inset-top)` (≈63px) plus the card's `1.5rem` padding put ~90 CSS px between the top of the screen and the title, with the keyboard covering the bottom third. Owner picked "dock to the top, careful about the top bar on iPhones" over a full-screen sheet.

## What shipped

- [`ChecklistAddModal`](../../src/components/ChecklistAddModal.tsx) reads `useIsMobile()` (≤640px). On a phone: the overlay's padding is **only** `env(safe-area-inset-top, 0px)` on top (and the bottom inset below) — `index.html` sets `viewport-fit=cover`, so on a Face ID iPhone the inset is the status bar's height and the card never slides under it; in Safari with the URL bar showing the inset is 0 and the card starts at the page edge. `alignItems: flex-start` instead of centering. The card is `width: 100%`, `borderRadius: 0 0 14px 14px`, `padding: 0.75rem 1rem 1rem`, `maxHeight: 100%` (it scrolls inside above the keyboard, as before). Desktop / tablet keep the centered 480px card with `1.5rem` padding.
- Nothing else in the modal changes: the header Send, the go-to-checklist and × buttons, the form, and the no-backdrop-close rule (v2.2742) are as they were.

## Verify

Phone: open the checklist icon → the card's top edge touches the status bar's bottom, the title is the first line; rotate / show the keyboard — the form scrolls inside the card. Desktop: unchanged centered card.
