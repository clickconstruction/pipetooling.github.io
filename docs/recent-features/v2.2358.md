# v2.2358 — Effort-weighted Timeline (Tier 1) (2026-08-26)

Client half of the estimated_days design (migration v2.2355). Rule: an
estimate is a task's WEIGHT, never its dates — x-axis stays dependency
sequence, calendar stays pace-derived; no estimates anywhere ⇒ bit-for-bit
the old tasks/week math (weights all 1).

- **Kernel `src/lib/roadmapEffort.ts`** (+tests): `averageEstimatedDays`
  (unestimated tasks weigh the roadmap mean), `taskWeightDays`,
  `effortDaysLabel`/`effortSumLabel`, `observedEffortPace` (days completed
  per week; same recent-4-weeks/all-time rules as `observedPace`).
- **`roadmapTimeline.ts`**: `TimelineRow` gains `totalDays/doneDays/
  remainingDays`; `timelineRows` takes `avgDays`; `paceProjection` divides
  remaining DAYS by days/week; new `taskSlotRectsWeighted` (proportional
  widths, min-width floor; equal weights reproduce `taskSlotRects`).
- **Timeline view**: weighted slots (collapsed bar + expanded waterfall),
  wave/stage day sums, estimate labels on waterfall rows ("2.5d" set /
  "≈2d" average), day-aware caption + needed-pace + what-if dial units
  (units appear only once ≥1 task is estimated), footer copy.
- **Task card** (`ChecklistTechTreeTaskCardModal`): ⏱ Estimate section —
  stepper in half-day steps + clear for editors, read-only line otherwise;
  tab wires `onSaveEstimate` → update + reload. `PlanTask.estimated_days`
  threaded through `useChecklistTechTreeData`.
- Tier 2 (edge-drag to resize estimates on the Timeline) ships next.
