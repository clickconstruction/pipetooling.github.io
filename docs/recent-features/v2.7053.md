# v2.7053 — Bills sent: each email says whether it arrived (2026-11-12)

Punch list #327, PR 3. A bill that was sent and bounced has not gone out. The record of that lives on `email_send_log`, which the assistant and the controller cannot read for a bill, so the people who send the bills could not see a bounce. This PR adds one definer read and draws its answer on each line.

## What changed

- **The read**, migration `20261113030000_bill_send_marks.sql` (see `docs/migrations/`): `bill_send_marks(p_ids)` answers, for the sent copies the caller can read (`is_office_staff()`), the mail service's last event and its time, the email's type, and for a paid bill the newest payment's day and how. No table. The SQL bed `bill-send-marks` holds it.
- **The kernel** (`src/lib/billing/billsSent.ts`, 31 tests in all):
  - A line's `delivery` words from the last event: *Delivered 9:28 AM* (the day too when it is not the send's day), *Opened …*, *Bounced. It did not arrive.*, *Delivered. The reader marked it as spam.*, *Delayed by their mail server.*, *Sent. Their mail server has not answered yet.* No event says nothing, never that it did not arrive. `deliveryTone` is ok, bad or quiet.
  - `stillMissed`: a send that did not arrive (a bounce, a text Quo could not deliver) on a bill not paid, with no later send of that bill that arrived. The tile and the chip read it.
  - `billsSentPaidWords`: *Paid Nov 9* when the day is known, *Paid since* when only the fact is.
  - `billsSentByWords`: a statement whose email type is `gc_statement_scheduled` reads *by the app, on Marcus's schedule*.
  - A day's band names the sends that did not arrive: *1 did not arrive*.
- **The reads**: `readMarks` in `billsSentIo.ts`, 200 copy ids a call, best effort. Before the migration is pushed the call is refused and the lines say nothing of arriving.
- **The screen**: the words on each email line in green, red or grey; a red border on a line that is still missed; a red tile **Did not arrive** with its count; the chip **Did not arrive**; the foot line says what *Delivered* means.
- **The guide** gains *Did the email arrive*.

## Not changed

- The mail log's own policies. Nothing is written.
- The service keeps only its last event, so a line shows one word, not a history. Keeping every event is PR 7, if counsel wants it.

## Deploy

The client calls a function only the migration creates, so **push right after the merge** (`bash scripts/db-push.sh` from a checkout at `origin/main`), then the types regenerate as their own `chore(types)` PR. Either side of the push the page stands.
