# v2.6345 — Drive and photos: one folder per set, the crew's as-built from the phone, the mail's file filed (punch list #239, PR 5) (2026-11-02)

The card's fifth PR, stacked on the papers doors (v2.6313). The design's as-built was a link: the crew had to put the marked sheets in Drive by hand and paste the folder. And a set's Drive folder was whatever link someone pasted, so the register and Drive could drift.

## Change

- **Edge function `plan-set-files`** (`docs/EDGE_FUNCTIONS.md` → plan-set-files; `config.toml` `verify_jwt = false`): `folder` makes **Plans › <set name>** under the Drive folder of the set's job (the job that made the set, else the part's own job, else the first job naming the part) and, when the set has no link, writes the folder's link onto the set (the mirror then carries it to `job_plans_link`); `put` lands one file from the phone or this computer in it (10 MB); `save_attachment` copies our copy of a mail's file into it. The set row is read under the caller's RLS; a write needs `plan_part_can_write` or the set's own author; a training account and a twin change nothing. A set on a site part no job names, or a job with no folder yet, is told so in words.
- **Kernel `src/lib/plans/planSetFiles.ts`** (pure, `planSetFiles.test.ts`): `splitReadyFiles` (a hold on one file never stops the rest: over 10 MB, not a photo or a PDF), `pickedFilesWords`, `asBuiltFileName` (*As-built · JP972 · 2026-11-02 · 1 of 3.jpg*; a PDF with a real name keeps it), `asBuiltPressWords` over `batchWords`, `filingWords`, `filedWords` over `batchOutcomeWords`.
- **Io `planSetFilesIo.ts`**: `folder`, `put`, `saveAttachment`, `attachmentsOf`.
- **`PlanSetForm.tsx`**: the as-built mode gains **Photos or a PDF** (`image/*,application/pdf`, several at once), the picked files with the held ones and their reasons, and the press naming its count. **`JobPlansSection.tsx`**: after the as-built row saves, the files go up one by one (*Filing 2 of 3…*), past a file that fails, and the outcome line says what landed; a set or as-built added with no link gets its folder made.
- **`MailPaperDoor.tsx`** (+ `MyMailReader` passing the line's `messageId`): after the paper keeps, the mail's files are filed into its folder, and the kept line says so.
- **Docs**: guides *keep the plans on a job* (the as-built step) and *keep the papers with the plans* (the mail's file); `GLOSSARY.md` → *Plan sets by part (Jobs)*; the card's front matter; the dev-mcp catalog regenerated for the new function.
