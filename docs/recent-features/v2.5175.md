# v2.5175 — GC mode: a waiver a trade partner signs in its portal is kept as a PDF (2026-10-10)

P5a-2 of the trade partner portal's real build (`to-dos/gc-mode/PORTAL_REAL_BUILD.md`; plan `to-dos/gc-mode/mockups/portal-p5a.md`, both on branch `spike/gc-mode`). It writes P5a-m's `gc_trade_files` (`20261010100000`, v2.5170) with purpose `waiver` and the form in `paper`, and stacks on P5a-1 (v2.5172). No migration.

- **The signed PDF** (`submit-gc-trade-portal`):
  - After a waiver kind's verb (`unconditional_waiver`, `pay_app`, `final_pay_app`) and its e-sign ledger row, `fileSignedWaiver` builds the signed paper and files it. It is best effort: no job folder, Drive refusing or a row not kept is logged and never undoes the signature.
  - The form is the one the kind signs (`tradeWaiverPaperFor`), filled from the draw, the job and the company as the portal fills it before the trade signs (`tradeWaiverPaper.ts`).
  - It goes to **Team only → From trades → <company>** as `<form title> - <trade> - draw <n> - signed <YYYY-MM-DD>.pdf`, with a `gc_trade_files` row: its form, its draw in `record_id`, `made_by` `portal`.
  - The hourly file cap now counts only the company's own uploads (`made_by` `trade`).
- **The paper** (`_shared/tradeWaiverPdf.ts`): one Letter page in Times. The name signs in Great Vibes, fetched from `APP_ORIGIN` as `contract-form-paper-entry` fetches it, else in italics. Under it: the day signed, the audit sentence and the e-sign statute line. pdf-lib is passed in, so the Deno function and the test share the file.
- **The words** (`_shared/lienWaiverWords.ts`): a copy of the Release of Lien window's forms (`src/lib/jobsDocuments/lienWaiverRelease.ts`), counsel's words, never new ones. `src/lib/gc/lienWaiverWords.test.ts` holds the copy equal for all four forms.
- **The office's links**:
  - `tradeFiles.ts` keeps each draw's newest file of each form, labelled by the row's form: **Conditional waiver PDF**, **Unconditional waiver PDF**, **Conditional final release PDF**, **Final release PDF**.
  - `tradeFilesIo.ts` reads the open job's rows when the Draws or Closeout window opens and after each read of the draws (`GcProjects.tsx`). A read that fails links nothing.
  - `GcDrawsWindow` links them quietly beside each draw's waiver chip. `GcCloseoutWindow` links **Final release PDF** on the finalWaiver step, done or not.
- **Tests**: `tradeWaiverPdf.test.ts` (the form per kind, the same paragraphs as the portal's paper, the foot and audit line, the name, a PDF that opens, the cursive face), `lienWaiverWords.test.ts`, `tradeFiles.test.ts`, and render tests in `GcDrawsWindow.render.test.tsx` and `GcCloseoutWindow.render.test.tsx` with a file and without one.
- **Docs**: `EDGE_FUNCTIONS.md`, `PROJECT_DOCUMENTATION.md`, `DRIVE_INTAKE_SETUP.md`. Guides: `pay-a-trades-draw` and `close-out-a-trade-and-close-a-gc-job`.
- **Deploy** (the lead): only `submit-gc-trade-portal` bundles the changed files.
