# v2.7400 — Job notes: a note that tags a teammate shows who it waits on (2026-11-15)

Punch list #363, PR 3 of six: the list of names on the Pipeline's note boxes. Taunya asked for the feature on 2026-11-15. Client only: no migration, no edge function. It calls `job_note_post_tagged` and `job_note_taggable` and reads `jobs_ledger_note_tags`, all on prod since v2.7385.

## The list is open to a dev alone, on purpose

`canTagInJobNotes` in `src/lib/jobs/noteTags.ts` answers true for the dev role only. Until PR 4 lands the Tagged job notes section and the count above Jobs, a tag would reach its person on that job's row and nowhere else. PR 4 widens the rule to everyone the list offers. Everything below that is not the @ button and the list is live for every reader.

## What changed

- **`src/components/jobs/NoteTagBox.tsx`** (new): `useNoteTagBox`, the picks, the list and the keys for one note box. The box keeps its own input and its own Post. The hook hands back the chips above the box, the list, the @ button, a key handler that reports whether the key was the list's, and the ids to send. The list is read once per job from `job_note_taggable`, the first time it opens. Enter or Tab picks, the arrows move, Escape shuts the list and leaves the words alone.
- **`src/components/jobs/TaggedNoteBody.tsx`** (new): a posted note's words with each tagged name as a chip, amber when it is the reader, then the words from `noteTagMark`: `waiting on Dana · 4d`, amber after two working days, then `answered by Dana` or `Dana: no reply needed` in green.
- **`src/hooks/useJobNoteTags.ts`** (new): one job's tag rows by note, read when the job's feed is loaded and again when it grows.
- **`JobsStagesActivityBox.tsx`**, the Pipeline row's own box, and **`JobActivityView.tsx`**, the floating window and full screen: both take the hook, pass the picked ids with the post, and draw `TaggedNoteBody` on note lines. The row's list opens above the strip so the strip keeps its height.
- **`useJobThreadNotes.ts`**: `submitJobThreadNoteWithBody` takes a fourth argument, `{ tagged, typed }`. A typed note posts through `job_note_post_tagged` and is then read back by its id. A stamp, and a % line (`typed: false`, from `useJobsStagesMutations.ts`), keep the plain insert, so they answer no tag. If the read back fails the post still counts and the thread reads itself again.
- **`noteTags.ts`**: `shortNames`, `tagsByNote`, `noteTagMark` and `canTagInJobNotes`, with eight more tests.

## What the card had wrong

The card named `JobActivityView` as the Pipeline row's box. The row's own box is a third component, `JobsStagesActivityBox`, the one in Taunya's screenshot. Both are done here. The card also planned the job window's box as a small last PR. That box posts through the outbox (`pressThroughOutbox`, kind `job-note`) so a note typed on a phone with no signal is kept, and it never reaches `job_note_post_tagged`. Until PR 6 changes the server side of that press, a note typed in the job window answers no tag. PR 6 is a migration and no longer small.
