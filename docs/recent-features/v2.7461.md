# v2.7461 — Lien desk: keep what was mailed with each notice, PR 2 of 2, the press (2026-11-16)

The owner, 2026-11-16: "after we print we should have the user upload what they are going to mail for easier reference later of what actually went out." He picked one file per notice. PR 1 (v2.7460) added the column `job_lien_desk_items.mailed_copies`; this is the press. Client only: no migration, no edge function. **Merge after the column is on prod**: the press writes the column.

## What a person sees

- On the run's checklist, a row whose paper has printed carries **Add what was mailed**. It opens this computer's file picker, or a phone's camera roll. A PDF or a picture up to 10 MB is taken.
- The file goes into the job's own Drive folder, under Sent by us, named for what it is: *Lien notice as mailed · 650 · 2026-11-16.pdf* (*· 2* for a second file that day).
- The row then lists the file as a link that opens it in Drive, and the press reads **Add another**.
- A row not printed yet has no press. A paid row and a row that goes by email have none either: nothing is in an envelope.
- A file that is not a scan or a photo, an empty one, or one over 10 MB is refused with its reason in a sentence, and nothing goes up. An upload Drive refuses says Drive's own reason.
- When the mailing is recorded, the notice's record keeps the first file's link as its saved copy, and its note names every file. A Drive link the office typed under More still wins as the link, with the files named after its note.

## Where it lives

- [`src/lib/jobs/lienMailedCopies.ts`](../../src/lib/jobs/lienMailedCopies.ts) (+ test): the list as stored, the file's name, the reasons a file is refused, the record's saved copy, the words.
- [`src/lib/jobs/lienMailedCopiesIo.ts`](../../src/lib/jobs/lienMailedCopiesIo.ts) (+ test, over a fake io): `addLienMailedCopy`. It reads the notice's list fresh after the upload, so two people adding files to one notice keep both.
- `RunNotice.mailedCopies` (`lienDeskRun.ts`, read off the item in `buildLienDeskRun`) and `LienRunRow.mailedCopies` (`lienRunChecklist.ts`).
- `LienRunChecklist.tsx`: the files and the press (`mailedCopies` prop). `LienDeskRunModal.tsx`: `addCopy`, and the `addMailedCopy` prop a test hands its own upload through.
- `lienDeskRunIo.ts`: each filing takes `lienMailedCopyDocument(n.mailedCopies, typed)`.
- Guide *send lien notices from the Lien desk*: **Keep what you mailed.** Glossary and `LIEN_DESK_ARCHITECTURE.md` amended.

## Left for later

- A retainage notice's row in the run has no press yet: `buildLienRetainageRun` does not read the column.
- A combined notice (several jobs at one property) keeps its files on the lead job's folder and notice.
- A file cannot be taken off the list from the run. It can be removed in Drive; the row would still list its link.
