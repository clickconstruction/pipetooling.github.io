# v2.3816 — A renamed Settings tab can no longer quietly break the after-deploy check (2026-09-25)

The E2E Smoke workflow (`docs/E2E_SMOKE.md`) had failed on every main commit since at least v2.3812, always on `e2e/settings-tabs.spec.ts` › *every dev-visible Settings tab renders its marker without page errors*: `locator.click: Timeout 15000ms exceeded` on all three retries. The spec clicks each tab by exact name, and v2.3705 (People spine, PR 6) renamed the System-zone tab **Digital twins** to **Digital twins & samples** in `src/lib/settingsGroups.ts` without touching the spec. The suite runs after deploy and never gates a PR, so the rename went unseen (E2E_SMOKE.md rule 6 is the same failure v2.1164 and v2.3489 fixed).

## The change

- The label itself was fixed in #3689 (merged first, no version): `e2e/settings-tabs.spec.ts` clicks `Digital twins & samples`; its marker *Mint a twin* is unchanged. This PR adds a pointer to the guard in the spec's header.
- **The guard:** `src/lib/settingsGroups.test.ts` gains *e2e/settings-tabs.spec.ts follows the tab list*. It reads the spec's `TABS` block and checks it against `getZonedSettingsGroups('dev')`: every label the spec clicks is a dev tab, and every dev tab is in the spec in the same order. That test runs in `npm test`, which gates every PR, so the next Settings tab rename fails its own PR and names the spec line to change.
- `docs/E2E_SMOKE.md` rule 6 names the exception.

## Verified

The guard failed on the spec before #3689 (it named *Digital twins*) and passes on main's spec now. All sixteen tabs were walked in the running app at the CI's 1280×720 desktop size as a dev: each tab clicked (and *▶Advanced* expanded), each marker visible, no page errors.

The same run's other red, `viewport-smoke` › */bids?tab=bid-board* at 375 px, was **flaky** (it failed once and passed on retry) and is not touched here.
