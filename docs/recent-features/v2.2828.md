# v2.2828 — Job Summary: Capacity view (2026-09-05)

PR 7 of the Job Summary analysis plan (artifact 9c02d29a), stacked on v2.2826.

## Client only — no migration

- [`jobSummaryCapacity.ts`](../../src/lib/jobs/jobSummaryCapacity.ts) (new kernel): `buildCapacitySeries({ ledger, people, hoursPerDay = 8 })` → weeks (Monday-keyed, clipped to the window) with `workdays` (Mon–Fri inside the window), `people`, `availableHours`, `fieldHours` (ledger `days[].fieldHours`), `peopleWorked` (distinct names from `days[].byJob[].people`), `utilizationPct`; totals; `peak` (weeks with ≥ 3 workdays); `weeksUnder60` / `weeksOver100`; `crewNow`. **Roster source**: `people` rows with `kind ∈ {master_technician, helper}` active on the weekday (`start_date` ≤ day, `end_date` ≥ day, not archived by then) × hours per day. **Clocked fallback** (no readable roster): people who clocked field hours that week × workdays × hours per day, labeled as an estimate. `CAPACITY_FIELD_KINDS`, `CAPACITY_HOURS_PER_DAY`. Three tests.
- [`useFieldRoster.ts`](../../src/hooks/useFieldRoster.ts) (new): one `people` select (id, kind, dates); null on RLS error so the kernel falls back.
- [`JobSummaryCapacityView.tsx`](../../src/components/jobs/JobSummaryCapacityView.tsx) (new): tiles, the weekly outline-vs-filled SVG (labels thinned past 20 weeks, month ticks, hover band + `<title>`), legend, and a footnote that names the source and the PTO/holiday caveat. The roster hook lives inside the view (the tab stays hook-free).
- [`jobSummaryLedgerView.ts`](../../src/lib/jobs/jobSummaryLedgerView.ts): view mode `'capacity'`. Toolbar: Capacity in the View chips (ledger-driven like Days/Timeline — Show / Compare / Target don't apply). Tab renders the view.
- Help guide: new `see-whether-the-crew-was-full.md`.

PTO / holidays off the available hours (salary work schedule day overrides); overtime as its own slice (needs per-person hours per week, which the day ledger doesn't carry); the Needs you "under 60% three weeks running" card.
