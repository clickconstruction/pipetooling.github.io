# v2.3043 — Test-gap audit, pass 53: the checklist cost-estimate store gets its first tests (2026-09-07)

Follow-up to v2.3042. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`checklistCostStore.ts` (126 lines) is the dev-only store behind checklist cost estimates (the Review inbox chips, the cost modal, the estimates hook): one shared load into a module cache so chips stay synchronous, estimate writes and removals, the "actual hours" write from sign-off taps, and the window event that fans every change out to mounted consumers. No test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- The first load fetches every estimate once (numbers coerced), concurrent callers share the one fetch, and the load announces itself with a null key; a failed load rejects and lets the next call retry; a null result empties the cache.
- Saving an estimate upserts it stamped with the signed-in user (null when signed out) and now, keeps a recorded actual across a re-estimate, and announces the key; saving null deletes the row by key and drops it from the cache; a failed write leaves the cache alone and throws.
- Recording an actual writes the hours with who and when, or clears all three with null; it updates a cached estimate but does not invent one for an unknown key, and always announces the key.
