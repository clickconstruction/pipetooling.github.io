# v2.7660 — Tell the dev: a press on every error line, and a wrench in a window on a phone (2026-11-17)

Punch list #380, PR 3 of six: the doors. The two-week test of the wrench starts with this one, because these are the doors that need no finding.

## What a person sees

- **The error line's press.** An error toast carries a **Tell the dev** button. It opens the box on *Something went wrong when I…* with the error already listed under *Goes with your note*, so one more press sends it with no words. The toast stays nine seconds so there is time to press.
- **Never for a lost signal.** The owner's rule. A line that only says the signal dropped, and any error while the browser says it is offline, carries no press: the outbox keeps that press and sends it later.
- **A window's title row, on a phone.** The shared window (`ResponsiveModalShell`, about 65 windows) carries a small wrench before its close button. On a phone the header's wrench is out of reach behind a window, and most confusion happens in one. At a desk the floating wrench is always in reach, so the title row carries none.

## How it is built

- **Every error toast passes through `ToastContext.showToast`**, so the press is one change there (`errorLinePress`), using the toast's own action slot.
- **A door outside the shell asks first.** `isTellTheDevListening` is true only while `TellTheDevRoot` is mounted for a signed-in person with Fix Mode on, so a public page, a signed-out page and a person with Fix Mode off see no door.
- **`TellTheDevButton`** is the small wrench in a file of its own, so the shared window can draw it without importing the root, which draws that window.
- **The box's own sheet** passes `tellTheDevDoor={false}` and carries no wrench.

## Not in this PR

A window that draws its own frame, and not the shared one, has no title-row wrench yet. The answer coming back to the sender is the next PR.
