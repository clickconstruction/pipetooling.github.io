# v2.6733 — Lien desk: the master's signing code at the run's amber card and the office's Ready footer (2026-11-08)

Punch list #150 (`to-dos/lien-sign-on-any-screen/`), residual A. v2.5791 gave the master's code a field on the desk's awaiting footers; the run window's held envelope (*Leader here, sign ▸*, v2.5086) and the office's Ready footer still offered his hand and the pen record alone, so a master standing at the counter with a code set had to draw, or the office had to carry the laptop to the awaiting pile. This PR puts the same line in both places.

## What changed

- **[`lienCodeSigner.ts`](../../src/lib/jobs/lienCodeSigner.ts)** (new, pure): what every sign line that offers his code reads — `lienCodeSignerFrom(leaderName, status)` (the status row, `not_live`, `loading` or null → the line's `codeSigner` with his first name and `ready · none · locked · not_live · loading`, the lock's clock in the app's time), `lienCodeRefusalWords` (*That is not Malachi’s code. 3 tries left.*), `lienCodeStatusStale` (a lock, a missing code or a database side not live reads the status again), `lienOtherScreen`, `lienFirstName`. The desk's inline copies of these became calls; `LienNoticeSignLineCodeSigner` moved here and the sign line re-exports it.
- **[`LienDeskRunModal`](../../src/components/jobs/LienDeskRunModal.tsx):** when the sign sheet opens on a held envelope whose leader is not the one signed in, the card reads `lienSignCodeStatus` for him and the line gets `codeSigner`; with a code set it opens on the code field (*Robert signs here with his code*), else on the pad with the reason. **Sign ▸** reads the line's mode: a code goes to `signLienDeskItemWithCode` for each unsigned notice in the envelope with `approve: false` (the row is already approved; the record names this sign-in's screen, and the function tells him his code was used), a drawing to `signLienDeskItem` as before. A refused code stops at the first notice, lands under the field with the tries left and in the toast, and re-reads the status after a lock; the envelope stays held. The hint under the line says *types his code or draws* while his code can be taken.
- **[`LienDeskModal`](../../src/components/jobs/LienDeskModal.tsx)** Ready footer: for an assistant or controller on another master's job, an unsigned ready notice draws `signLine()` (his name in cursive, his code field or his pad) and a green **Sign ▸** (`data-lien-desk-office-sign-press`) beside *He signed the paper ›*; the press is the desk's `signOnly`, so the code path and the drawing path are the awaiting footer's. The leader's own **Sign ▸** on another master's job says in its title that the master signs here with his code or his hand.
- **Words:** `RUN_UNSIGNED_PROBLEM` ([`lienDeskRun.ts`](../../src/lib/jobs/lienDeskRun.ts)), the run paper's held reason ([`lienRunPaper.ts`](../../src/lib/jobs/lienRunPaper.ts)) and the envelope chip's next line ([`runEnvelopeStage.ts`](../../src/lib/jobs/runEnvelopeStage.ts)) read *types his code or draws it here with Leader here, sign ▸*. The guide *send lien notices from the Lien desk* says so under **Signing on someone else's screen** and **Leader here**.

## Is this the best we can do?

- **One line, three places, the same words.** The awaiting footer, the Ready footer and the run's card now read the same kernel for his name, his code's state and a refusal's sentence, so a master meets one block wherever the office stops him.
- **The record is the same honest one.** *Typed by Malachi with his signing code … on Taunya’s screen* from the run is the sentence v2.5788 wrote; the approval is untouched (`approve: false`) because the row reached the run approved already.
- **A wrong code never signs half an envelope wrong.** The loop stops at the first refusal; what signed stays signed and in the run, what did not is still held with its reason.
- **Not done here:** the desk's piles still call every leader *you* on another master's jobs (*Only you can approve · 3* on a dev's desk for Malachi's notices) — residual B, the next PR.
