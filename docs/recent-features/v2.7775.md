# v2.7775 — Painted maps: a place can say what kind of thing it is (2026-11-18)

## Why

A place on a painted map is a numbered dot with a name, a word and a photo. Every dot looks the same, so a reader has to match each number to the list to learn which dot is the gate and which is the shutoff. A kind lets each dot wear its own mark.

## What ships

Migration `20261118080000_painted_place_kind.sql` ([its page](../migrations/20261118080000_painted_place_kind.md)):

- `painted_map_places.kind`, a short lowercase word such as `gate`, `meter` or `hazard`, or null for a plain place.
- `painted_map_places_kind_check`, which holds it to one lowercase word of 2 to 24 letters and underscores.

The list of kinds is the app's, not the database's. A new kind needs no migration, and an app that meets a kind it does not know draws the plain dot.

Nobody new reads or writes anything. The table's four policies are by row, so whoever may set or change a place may set or change its kind.

## What the card asked and what was found

The card's pick was to build kinds *once places are in use, so the list of kinds comes from what people mark*. Read on 2026-11-18 as the dev, prod held no place on any painted map. So the first list comes from the card's own examples and the name chips the place panel already offers. It is a list in the app, and it is the owner's to change.
