# v2.4212 — Pipeline: every job with a customer gets the property badge (2026-09-29)

Owner, on the same Pipeline screenshot as [v2.4210](v2.4210.md): "I am not seeing it on many addresses." Measured on the live board: 42 of 79 addresses had no badge, every one a job with no `customer_address_id` — 25 with a customer, 17 with none (mostly ZZ TEST rows). v2.4160 drew nothing for those because the kind lives on the property and there was no property to keep it on.

- **`propertyKindBadge`** takes `customerId`: unlinked + customer → the red ? with `unlinked: true` and a title/label that say the pick saves the address as a property; unlinked + no customer → still null.
- **`planPropertyLink`** (`lib/jobs/propertyLinkPlan.ts`, tested): given the customer's properties, reuse the one the job address matches — whole address, else the street line (the text before the first line break or comma; `suggestCustomerAddressForJob` keys on the comma alone, which a `street\ncity, TX` job address never has on its first line) — else create one from `emptyPropertyDraft(jobAddress)` with the kind on it, `sequence_order` after the customer's own, never `is_primary` (the primary row mirrors `customers.address` by trigger).
- **`linkJobPropertyAndSaveKind`** (`propertyKindWrite.ts`): reads the customer's `customer_addresses`, runs the plan (update the kind on the reused row, or insert), then sets `jobs_ledger.customer_address_id`. Returns the property id and whether it was reused.
- **`usePropertyKinds`** gives '' to every unlinked job with a customer (so the badge draws) and remembers links made from the badge (`linkByJobId`, `linkJob`) until the board reloads with the row's own column. `StagesRowRenderContext` gains `propertyLinkByJobId` / `onPropertyLinked`, threaded through both tables like the v2.4160 pair.
- **`PropertyKindBadge`** gets `onLinked`; the popover's footnote names the customer — *Not one of Dudley Mason's saved properties yet — picking saves this address as one and links the job* — and the row toasts *Saved as a property on … and marked residential* (or *Linked to …'s saved property …*).
