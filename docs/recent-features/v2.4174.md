# v2.4174 — Submittals: under the rows, what the GC's page will read, live as you edit (2026-09-29)

Punch list #62 (*See what they see*), Layer 1. The owner's ask: "an active view of what they change and how it changes what the customer can see". This is the smallest true piece: one line, in the reviewer's exact words, that changes as the rows do.

- **`describeForReviewer(items, shared)`** in `lib/submittals/seeWhatTheySee.ts` runs the room's own kernel on the draft — `roomRowsFrom` → `roomCounts` → `roomHeadline` / `roomSubline` from `_shared/submittalRoomPayload.ts`, the file the edge function and the app both import — and quotes the result: *The GC's page will read: "1 row needs a call" — 3 rows match the plans and are marked approved. 1 differs — each says why. The GC sees nothing until you share.* A shared revision reads *The GC's page reads: … That is what the link shows now.* Because the kernel is the room's, the line can never say something the GC's page would not.
- **Where**: under the rows table on the newest revision (`reviewer-line`, after *What do the statuses mean?*) — where the rows are edited, so it is in view exactly while fixing them; the Share stage folds until it is reached (v2.4169). `toRoomItemSource` narrows the stored row to the fields the room reads.
- Guide *build a submittal package* → *Share it*: one sentence.

Tests: `seeWhatTheySee.test.ts` (the quoted headline and subline for a mixed draft; the shared wording; an empty draft); the tab test reads the line on a draft with a matching row and a differing row.
