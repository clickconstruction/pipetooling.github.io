# v2.7596 — Estimates: the send client and its answer become a kernel (2026-11-17)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 3 (`to-dos/decomposition-queue.md`): cut 1 of the eight the owner asked for on 2026-11-17, Stage-A row 1 of the re-drawn Estimates map (`docs/ESTIMATES_TABS_ARCHITECTURE.md`).

## What shipped

- **`src/lib/estimates/sendEstimateIo.ts`** — `postSendEstimate({ estimateId, mode, customerEmail?, timeoutMs? }, door?)` builds the one request to `send-estimate-to-customer` (the session's JWT, the anon key, the body per mode) and answers `no-session`, `slow` or `reply` with the HTTP verdict and the JSON. `sendEstimateAnswerFrom(httpOk, json)` is the reply as the Tell the customer sheet hears it. The browser (the session, `fetch`, the functions URL, the window's origin, the timeout signal) is a `SendEstimateDoor`, so a test stands in for it.
- **`Estimates.tsx`** — the three hand-written `fetch`es call it: `sendEstimateEmailAnswer` (the first send and the sheet's Send the link again, 20-second timeout), `resendCustomerLink` (no timeout, needs `accept_url`), `remailCustomerLetter` (no timeout, throws on a no). Each keeps its own toasts, its own state and its own handling of the reply. The page is 5,362 lines (was 5,423).
- **15 tests** (`sendEstimateIo.test.ts`): the body per mode, the URL and headers, no request with no session, a timeout signal only when a timeout is given, `slow` on a `TimeoutError`, a lost connection still thrown; then the answer — ok with and without the email, `already_sent` with a good, missing or bad time, `not_draft` in the resend rule's words, a plain refusal with the server's reason or *Send failed*.
- **Docs**: the Estimates map (the send flow's dossier, the Supabase inventory, the Stage-A row, quirk 12, the order), the playbook's edge-call seam and inventory row, the queue's row 3.

## What stayed the same, on purpose

- The request the function receives is the same for each mode (the JSON's key order differs, which the function does not read).
- A missing session still says *Not signed in. Sign in again and retry.* on the sheet, toasts *Not signed in* on Resend link, and throws on the letter again.
- Only the sheet's path has a timeout. Resend link and the letter again wait as long as the browser does, as before.
- A reply that is not JSON, or a lost connection, still throws into each caller's own catch.
