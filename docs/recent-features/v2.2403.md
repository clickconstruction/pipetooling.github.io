# v2.2403 — Solver: the "or total" box rides the margin slider (2026-08-27)

Wendi: "we should make the ideal total rise and fall when the user moves the
slider so the user knows what is going on and can step over to edit it."

`BidsPricingTab.tsx`, `runWorkbenchSolve`:

- After every **margin** solve (slider drag or typed margin), the solve's
  `resultingRevenue` is written into `wbTargetTotalInput`
  (comma-formatted, whole dollars) and the last target-solve chip clears —
  the "or total" box now tracks the slider live, the reverse of the
  existing target→slider sync (which is unchanged).
- Guard: a new `wbTargetTotalFocusedRef` is set in the box's
  `onFocus`/`onBlur`; while she's IN the box, margin solves never overwrite
  it — stepping over to fine-edit is safe mid-drag.
- The box also gains select-on-focus, so stepping over from the slider is
  type-to-replace (matching the sale-price cells' v2.2393 behavior).

Verified live on test bid BP398: slider 60 → box 69,820; 35 → 42,970;
focused box held its value through a slider drag (landing chip moved, box
didn't); resumed tracking after blur.
