# v2.2171 — Per-GC hit rate + Why we lost; a GC win marks the others lost (Bids by GC, 2026-08-23)

Mockup approved in the session (claude.ai/code/artifact/6d6314e6-a858-4c1f-ba23-f065d46dcd7c). Rule: **a builder's numbers count the packets that went to that builder.**

- **Kernel [`gcOutcomeRows.ts`](../../src/lib/bids/gcOutcomeRows.ts)** (+7 tests): `gcOutcomeRowsForBid(bid, builder, packets)` → one `GcOutcomeRow` per GC (`gcKey`, `outcome` won/lost/pending/unsent, `perGc`, `sentOn`, `value` = packet ★ send value ?? bid value, `lossCategory`/`lossNote`, `reasonInferred`, `siblings`, `sharedLetter`, `versionIds`, `packetKey`). Resolution: explicit packet outcome → that; nothing marked on the bid → the bid's outcome (legacy, byte-identical for single-GC bids); a sibling packet won → `lost` with `gc_lost` inferred (`reasonInferred`) unless recorded; else pending/unsent by send. `tallyGcOutcomeRows`, `gcRowIsPacketScoped`, `classifyBidOutcome`.
- **Migration `20260823161953_bid_versions_loss_category.sql`** — `bid_versions.loss_category text` (per-GC reason; note in `outcome_note`). Types hand-added. Single-GC bids keep writing `bids.loss_category`.
- **Writer** [`gcPacketOutcome.ts`](../../src/lib/bids/gcPacketOutcome.ts): `setGcPacketOutcome` takes `packetsAfter` with `versionIds`/`name`; on `won` it marks the bid's other sent, unanswered packets `lost` (+`outcome_at`), returns `autoLost` names for the toast ("… — Burd & Assoc. marked lost · GC lost the project."); the reason is inferred by the kernel, not written, so clearing the win un-infers it. New `setGcPacketLossCategory({ versionIds, category, note })`. Board rows + Followup pass the richer `packetsAfter`.
- **Hook hoisted**: `Bids.tsx` calls `useBidGcPackets(bids, recipients)` once and passes `gcPacketsByBid` to the board, Call queue, Why we lost, Waiting to hear and By builder (the board's own hook call removed; `useBidGcPackets` selects `loss_category, outcome_note`).
- **Call queue** (`BidsCallQueueTab`): one entry per bid × GC (`rowKey`), stats/chase/reasons per GC; chase Won/Lost and reason taps on a multi-GC row write the packet (`setGcPacketOutcome` / `setGcPacketLossCategory`) instead of the bid.
- **Why we lost** (`BidsWhyWeLostLens`): rows replace `bids.filter(lost)` + recipient expansion; rail/pending/won counts per GC; selection/optimistic saves by `rowKey`; new GC line on the card (GC · outcome chip · ★ value · sent · "also went to X won") with "this reason is {GC}'s — the bid stays won"; recorded line shows {{auto}} for inferred reasons; save path per packet when `gcRowIsPacketScoped`.
- **Waiting to hear** (`BidsWaitingToHearLens`): rows with `outcome === 'pending'` (a GC that answered drops off); rollup dedupes per bid; chase outcome on a multi-GC row writes the packet.
- **By builder** (`BidsBuilderReviewTab`): header chips tally rows per GC (`builderBidMapStats`); the card's bid lists (`customerBidRows`) include bids whose packet points at this GC under that packet's outcome; call sheet open bids follow. Call session header and builder call sheet inherit the numbers.
- **Map builder focus** (`useMapPageData` → `MapPageEntity.bidGcSections`, `MapPageView.focusSectionOf`): multi-GC bids get a per-GC section; focus counts/pin colors use the focused GC's packet; bids with a packet to the focused GC join the focus set.
- Help: `follow-up-with-builders` "One bid, several GCs" rewritten; `see-where-you-win-and-lose-with-a-builder` notes the per-packet count.

Not changed: the "By status" lens and the customer hub (bid-level). `npm run gen-types:linked` follow-up after the migration.
