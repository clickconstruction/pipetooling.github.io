# v2.2875 — Usage tab shows real numbers; office previews stop counting as customer views; the portal globe says "Opened N times" (2026-09-05)

Journey-map Tier-2 #37 ("the office cannot tell whether a customer ever looked", C52 — J21-N1/F4, J35-F3). Three related truths, one PR.

## 1. Settings → Usage rendered all-zero against row-bearing RPCs (J21-N1)

`SettingsUsageTab`'s `call()` unwrapped `{ data }` inside the callback and returned the rows; `withSupabaseRetry` then returned `result.data` — `.data` of an ARRAY, i.e. `undefined` — and `?? []` blanked all four panels to "Nothing recorded". Every other caller hands the wrapper the raw envelope; this tab was the odd one out.

- New tested loader `src/lib/usageDashboardLoad.ts` (`loadUsageRows(rpc, fn, days)`) hands the wrapper the envelope so it unwraps exactly once; `null` still means "this reader failed" (the tab keeps its "reader functions may not be deployed" note). The regression test reproduces the old shape (`withSupabaseRetry` over a pre-unwrapped array → `undefined`) next to the fixed path.
- Nothing in `errorHandling.ts` changed — other callers were right.
- No Stripe "viewed" figure existed on the tab (Stripe has no `invoice.viewed` event), so nothing to relabel.

## 2. Office peeks no longer count as customer views

Every "view" on record was staff: the globe modal's live preview iframe + its Edit-chips fetch wrote two `public_page_views` rows per open; `get-bid-proposal-room` logged `room_view` unconditionally, so an estimator checking their own link read as the GC "opened 1×" on the board chip.

- **Shared predicate** `supabase/functions/_shared/publicViewCounting.ts` — `shouldCountPublicView({ preview, isStaff })`, `isPreviewFlag`, `withPreviewFlag`, `userBearerToken`, `requestIsStaff`, `publicViewDecision(req, admin, anonKey)`. App twin `src/lib/publicViewCounting.ts` re-exports it; 26 tests in `src/lib/publicViewCounting.test.ts` cover both the pure rules and the request-level decision.
- **Two signals, either one skips the write:**
  - `?preview=1` — the office openers add it: `CustomerPortalGlobeButton` (iframe, Preview as customer, Full screen, the chips fetch), `SubPortalGlobeButton` (iframe, Preview as …). The copyable link never carries it. `CustomerPortal.tsx`, `SubPortal.tsx`, `BidRoom.tsx` forward the flag to their edge function.
  - **a verified staff session** — the public pages now call their edge function with `staffAwarePublicHeaders()` (`src/lib/publicFunctionStaffHeaders.ts`): the browser's own Supabase access token when one exists (an office user opening a customer link from the browser they work in), else the anon key exactly as before. The edge function verifies it with `admin.auth.getUser(jwt)`; any valid account is staff — accounts exist only by invitation, customers/GCs/subs never sign in. Anything unverifiable (absent, anon key, expired, garbage) counts as a customer — the failure mode is "count it", never "hide a customer's open".
- **Edge functions** (deploy after merge): `customer-portal`, `sub-portal` skip the `public_page_views` insert; `get-bid-proposal-room` skips `room_view` (GET) and `option_viewed` (POST) for the same requests. Signed / declined / sample paths untouched; the sample branch already wrote nothing.
- Historic rows (all office pairs from Aug 26 on) stay — there is no actor column to clean by. Counts start meaning "customer" from the deploy onward.

## 3. The globe gear answers "have they looked?"

- `customer-portal` returns `officeViewStats: { opens, lastOpenedAt }` — the customer's own `public_page_views` count + latest — **only** to a verified staff session (the table's RLS is dev-only; the function reads it with the service role). A customer's payload never carries the block. No new RPC, no migration: the globe's existing chips fetch is the carrier (it now sends the staff session + `preview=1`).
- Gear row **Opened** — kernel `src/lib/portal/portalOpenedLabel.ts`: `parseOfficeViewStats(body)` + `portalOpenedLabel(stats, now)` → "Not opened yet" / "Opened once · today" / "Opened twice · yesterday" / "Opened 14 times · last Aug 26" (year appended when it differs); `null` stats (old function build) omit the row rather than show a zero it cannot vouch for. 7 tests.
- Hint under the figure: "Customer opens of this portal. Your previews and staff opens don't count."
