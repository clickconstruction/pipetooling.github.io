# v2.5808 — Prospects → Subs: the Board by trade, and Call the top 3 as a run on the deck (2026-10-23)

Punch list #153, PR 2 of 4 (`to-dos/subs-bench-board/`), on PR 1's v2.5807. The owner's pick: "we are looking for specific kinds of subs at any given time. And often we will get a set of plans and then have the need to contact that particular sub as swiftly as we can." This PR is the board and the run; the drag and the priority wait for PR 3's migration, the ask on landing for PR 4.

- **The kernels** (all pure, all tested): [`subRecord.ts`](../../src/lib/prospects/subRecord.ts) reads each sub's record from the lane's call rows at the bench's own thresholds (`answerRecord`'s: two calls the least judged on, *answers* at three in four, *hit or miss* at two in five, *often silent* under that), a text or an email back on the thread Messages ties to the prospect counting as an answer; [`subsBoard.ts`](../../src/lib/prospects/subsBoard.ts) builds the columns over `groupSubsByTrade` (every trade the panel knows, the picked project's first and lit, the rest folded behind a count), orders a column (pins when PR 3 lands, then the office's priority, then the record, then never called, then the queue's coldest-first), names the top three, *call next* and *also in*, and reads the column's head (the project's ask when picked, the bench's line); [`callRun.ts`](../../src/lib/prospects/callRun.ts) is the run: the ids on the link (`?run=a,b,c` with `?trade=`, `?for=`, `?pkg=`), the caller's place, the head's words, the callback hour (3 pm today before 2:30, else 10 am tomorrow), the text's words, the receipt.
- **The board** ([`SubsBoard.tsx`](../../src/components/prospects/SubsBoard.tsx)): Hiring's shape, 300 px columns scrolling sideways, each with its head and **Call the top 3 →** (*Call the 2 here →*, *Call now →* on one, *Add a sub* on none); a card is #rank · name · gear, the chips, one fact a line (the phone and town, the last call and the record's fact, a callback set), the presses **Call now →**, **To the bench ✓**, **Pass** (one question, since Send back lives on the list). The priority picker draws only when the page passes `onPriority` (PR 3).
- **The page** ([`Prospects.tsx`](../../src/pages/Prospects.tsx)): the `board` sub-tab on Subs (`?tab=board`, refused on another kind), fed by the list's loader plus `loadLaneExtras` (the lines back on the threads through `contacts.prospect_id` → `messages.direction = 'in'`, and the upcoming callbacks; both fail-soft); the run on Follow Up (`loadFollowUpProspects` takes the run's ids in order when the link names one, the head over the deck, *The run* on the rail with the order toggle hidden, **Next in the run →** and **Finish the run →** instead of a wrap, the receipt with **Back to the board →**); Didn't Answer in a run writes the callback through `prospect_callbacks` as Set callback does (the Calendar shows it) and draws the ledger line with **Text them** / **Ask first** (`textRefusal`) and the next press; `sendRunText` finds the prospect's thread and phone channel and calls `quo-send` (no thread: *No Messages thread for them yet. Open Messages to start one.*), noting the text on the card; every outcome handler notes the run's outcome; **By rank** on the order toggle (`CallingOrderMode` `by_rank`); the call script names the run's trade and project (`callScript(caller, company, job)`, `GcCallScriptWindow`'s `job`).
- **Guide**: *find subs for the bench* § The Board and § Call the top three when plans land. **Docs**: the Prospects map, the Glossary, the page map.

## Is this the best we can do?

- The run is a slice of the queue fixed at the press, so the deck's machine (the lock, the clock, Activity's counts) is untouched and two callers never dial one company.
- The record is computed from what the lane already logs, in the bench's words, so a company reads the same on the board and on Trade partners.
- Cut on purpose: a text to every unreached company at once (one press a company, after the call, is the texting rule), a run across trades (one trade a run keeps the script right), Hiring's three bars.
- Checked live as the dev with a ZZ sub: the board with For lighting Concrete and folding fourteen, Call the top 3 → opening the run with the head and the rail, Didn't Answer setting the callback and reading Ask first, Finish the run → showing the receipt; the ZZ row deleted after.
