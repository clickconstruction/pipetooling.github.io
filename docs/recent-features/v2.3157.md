# v2.3157 — the phone view switch is the last thing on the People tab (2026-09-08)

Follow-up to [v2.3156](./v2.3156.md), same day. Client only — no migration, no edge function.

## Why

The owner's ask was explicit: the way to the desktop view "can be at the very bottom of the page." v2.3156 rendered that switch inside [`HubPeoplePhoneBoard`](../../src/components/schedule/HubPeoplePhoneBoard.tsx), but `HubPeoplePanel` appends the **Expected manpower** section after the board — so on the hub route (`showExpectedManpower` is true for every non-Quickfill mount) the switch sat *above* a long table of person-hours, not at the bottom. The grid rendering carried a second, near-duplicate block for the way back.

## What changed

- **One exported [`PhonePeopleViewSwitch`](../../src/components/schedule/HubPeoplePhoneBoard.tsx)** (view + onChange) replaces both blocks. `HubPeoplePanel` renders it as the **last child of its fragment**, after the Expected manpower section, so it is literally the final thing on the tab in *both* renderings: **▦ Show the desktop view** on the board, **📱 Back to the phone view** on the grid, each with the same "remembered on this phone" caption.
- **It stands down mid-placement.** While `cardPlacementMode` / `hubAssignJobPlacement` / `linkedCopyMode` / `hubMultiCellAddActive` is set (`phonePlacementActive`), the switch is not rendered — the fixed mode bar owns the bottom of the screen at that moment, and a switch underneath it could not be read or reached.
- `HubPeoplePhoneBoard` loses its `onShowDesktopView` prop; the board no longer renders any footer of its own.

## Also noted (not changed here)

The subs lanes strip (`HubSubsLanes`) lives inside the grid's horizontal scroller, so it does not render on the phone board — the desktop view, one tap away at the bottom, still shows it. Worth a follow-up if sub lanes turn out to matter on the phone.

## Tests

`HubPeoplePhoneBoard.render.test.tsx` gains a `PhonePeopleViewSwitch` case (both labels, both directions, both captions) and the board case drops its switch assertions — 5 tests in the file. Verified live at an iPhone viewport against prod data: the switch is the last child of the panel, with Expected manpower directly above it; both directions flip the rendering and persist the per-device preference.

## Verify

Phone → Schedule → People → scroll past **Expected manpower**: the switch is the last thing before the tab bar. Tap it → the week grid, whose bottom offers the way back. Start a copy → the switch disappears while the dark mode bar is up, and returns on Cancel.
