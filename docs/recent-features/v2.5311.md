# v2.5311 — Messages: choose who gets a new message, in Settings → Phone and texts (2026-10-12)

Messages wave 2, cut 2's screens, PR D of four (A data, B the Follow up tab, C the pieces in the thread window, D this).
It reads and writes the seats cut 2's migration made (`app_settings.messages_assign_rule_v1`,
`20261012160000_messages_follow_up.sql`, v2.5274), so it goes live once that migration is on prod. Quo's rows (cut 5)
join the same Settings tab.

- **`src/lib/messages/assignRule.ts`**: the seats parsed from the setting (anything it cannot read, a bad id or a bad
  value, is an empty seat), written back with the three keys, and compared; who may set them (the owner and a dev, the
  setting's `master_or_dev_update_messages_assign_rule`) and who sees the tab (the GC office team); who can sit in a
  seat (the office team with a name, by name); and the rule's table with the seats' names in the prototype's order,
  an empty architects' seat sharing the trade partners' and a departed person read as *Someone no longer on the team*.
  Its test holds the table to `whoGetsIt` (`followUp/queue.ts`) on the same seats.
- **`src/lib/messages/assignRuleIo.ts`**: the setting and the office team in one read; the save is an update of the
  migration's row that must return it, so a policy's refusal or a missing row says *The seats did not save. Only the
  owner or a dev can change them.* rather than passing quietly.
- **`src/components/settings/PhoneAndTextsSettingsSection.tsx`**: **Who gets a new message** under the new
  `settings-phone-texts` group (`settingsGroups.ts`, mounted while open in `Settings.tsx`): the rule's first step, the
  table, and what the pill says after. The owner and a dev get a picker per seat, **Save the seats** and **Put them
  back**; everyone else reads the names and *The owner or a dev sets the seats.*
- **Guide** `choose-who-gets-a-new-message`; APP_DIRECTORY, PROJECT_DOCUMENTATION and GLOSSARY entries;
  `e2e/settings-tabs.spec.ts` lists the tab.
- **Tests**: `assignRule.test.ts`, `assignRuleIo.test.ts`, `PhoneAndTextsSettingsSection.render.test.tsx` and the
  settings groups' order and roles.
