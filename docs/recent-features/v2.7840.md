# v2.7840 — Pay: job costs can read a salaried person's own week (2026-11-18)

The second database step of a per-person salaried week, after the column (v2.7826). The owner asked on 2026-11-18. No screen changes.

## Why

A salaried person was costed as 8 hours on a weekday and nothing on a weekend. Five database functions each wrote that rule out for themselves, so a week of the person's own shape could be stored and still be costed as 8 hours a day.

## What ships

Migration `20261118190000_salaried_week_in_cost_functions.sql` ([its page](../migrations/20261118190000_salaried_week_in_cost_functions.md)):

- `get_man_hours_by_job`, `keep_job_baseline`, `list_project_board`, `superintendent_scores` and `get_weekly_money_movement_payload` ask `salaried_hours_on` for a salaried day's hours. The rule lives once.
- `list_people_pay_flags` returns the week as a last column, so the app's own cost readers can see it without reading a wage.

Each body is the newest one on file with only the salaried lines changed. A script copied them, and its line-by-line report is in the PR.

## What does not change

Every pay row reads 8 hours on the five weekdays, so each function answers exactly what it answered before. No screen sets a week yet. The press that sets one ships after the app's cost readers read the week too, so a person is never paid on one week and costed on another.

## The bed

All five functions check a statement only when it runs. A second scenario in the salaried week bed runs each once as a dev, with a person on 6 hours and a 4-hour Friday beside a person on the default week. The man-hours read 10 and 8, and the job's baseline keeps 18 hours and $180.
