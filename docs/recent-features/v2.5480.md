# v2.5480 — Lien desk: what each Docsmit envelope cost, read from the mail service (Docsmit train, 6b, the cost line) (2026-10-13)

The cost line of 6b (`docs/DOCSMIT_LIEN_RUN_PLAN.md`, *Delivery drives the desk*), built from two parts of the Docsmit API the train had not used: `billTo` on a new message and `GET /messages/{id}/transactions`. Docsmit's own demo calls `priceCheck` with no parameters and the train already tolerates a refusal there (v2.5475), so the charge the account actually paid is read after the fact instead.

**`_shared/mailSend.ts`** — `mailChargeFromTransactions(raw)` sums the `price` of the transaction rows (a list, one object, or `{ transactions }`), a `CoR` of R negative, to the cent; null with no priced row. `mailChargeRead(events)` says whether a `charged` event is on the piece. **`_shared/docsmitClient.ts`** — `transactions(messageId)`, a 400 or 404 giving null. **`_shared/mailDocsmitRefresh.ts`** — `refreshPiece` reads the charge once the piece has `mailed_at` and no `charged` event, writes `mail_pieces.price` with the event (the raw answer kept on it), and never asks again; `RefreshOne.charged`. A refusal leaves the price unread and the next poll asks again. **`mail-send-docsmit`** `prepare` puts `billTo` = the job number on `POST /messages/new`.

**`src/lib/mail/lienMailPieces.ts`** — the row carries `price`; `filingMailLines` adds `cost` (*$2.49*); `mailCostDollars`; `filingMailCostWords` is the footer's *Docsmit cost $12.34 · 1 not read yet*. `useLienDeskData` reads `price`; the notice footer shows the charge after each envelope's number and the cost line (`data-lien-mail-cost`).

**Tests**: `mailSendShared.test.ts` (the sum), `mailSendDocsmit.run.test.ts` (`billTo`), `mailPoll.run.test.ts` (read once, not again), `lienMailPieces.test.ts` (the words).
