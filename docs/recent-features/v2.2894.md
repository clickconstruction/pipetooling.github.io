# v2.2894 — Marking a GC Won states the cascade first, and "↩ waiting" un-rolls it (2026-09-05)

Journey map Phase 4, **Tier-2 #21** (`JOURNEY_MAP.md` → "One tap marks a GC Won, auto-Losts its siblings and rolls the bid Won even over a hand-set Lost — and ↩ waiting doesn't un-roll it"; findings J14-F3 / J14-N1 / J10-N1 / J15-F5; family C29 SILENT-WRITE). Builds on Tier-1 #8 (v2.2859, `BidWonJobActions`) — every "Open the job" door on a Won moment is unchanged.

**Why.** `setGcPacketOutcome` (v2.2162) did three writes on one tap — the packet Won, every sent-and-unanswered sibling Lost, `bids.outcome` → won (even over a hand-set Lost) — and explained them only in the after-toast. "↩ waiting" then cleared the one pill and wrote `bids.outcome` only when the roll came back won/lost, so a mis-tapped Won left the bid in the Won section with its siblings still Lost. BP398 was the live specimen every board walker read (board Won · both pills "waiting"). The packet path also never wrote the Win/Loss note the Edit-Bid form has written since v2.507.

## What changed

- **Pure kernel [`wonCascade.ts`](../../src/lib/bids/wonCascade.ts)** (+ `wonCascade.test.ts`, 13 tests):
  - `wonCascadePlan(bid, gcs, targetKey)` → `{ target, willLose, willLoseGcIds, willRollBidOutcome, overridesHandSetOutcome, bidOutcomeBefore }` — the same rule the writer applies (sent, unanswered, real packets with versions lose; won / started block the roll; a hand-set Lost is overridden and named).
  - `wonCascadeConfirmMessage(plan, { gcName })` — the one sentence every writer shows: *"Mark Southern Post Won? This marks the other GC (Burd & Assoc.) Lost — GC lost the project and the bid Won. ↩ waiting on the winner puts all of it back."* + *"The bid is currently marked Lost by hand — it flips to Won."* when it applies. `wonCascadeNeedsConfirm` skips the dialog only when nothing beyond the tapped packet changes (bid already won / started, no siblings to lose).
  - `wonCascadeUndo(snapshot)` → `{ versionPatches, bidPatch, restoredSiblingNames }`; `inferWonCascadeSnapshot(...)` rebuilds a snapshot from the rows when none was taken this session (reload, or a **signature-set** Won from the bid room, v2.2697): same-day, reason-less Lost siblings are the cascade; a reasoned or earlier Lost stays; the bid goes back to Not set when it reads won.
  - `bidOutcomeSetTarget(path, outcome, undone)`, `wonCascadeNoteBody`, `wonCascadeUndoNoteBody`, `cascadePackets` (GcPacket → CascadePacket).
- **Writer [`gcPacketOutcome.ts`](../../src/lib/bids/gcPacketOutcome.ts)** — `setGcPacketOutcome` gains `previousOutcome` and `actor: { userId, role, path }`:
  - **Won**: plans the cascade, reads `bid_versions (id, outcome, outcome_at, loss_category)` for the winner + would-lose siblings **before** writing, keeps the snapshot in a module-level `Map<bidId, WonCascadeSnapshot>` (`peekWonCascadeSnapshot` for tests/devtools), writes as before, records `bidOutcomeWritten`.
  - **Undo** (`outcome: null` with `previousOutcome: 'won'`): session snapshot (matched on the winner's version ids) or inferred one → winner to waiting; siblings restored to their prior `outcome / outcome_at / loss_category` (one update per distinct prior state); `bids.outcome` set back to `bidOutcomeBefore` guarded by `.eq('outcome','won')` so a hand change since the tap stands. Result carries `undone: { restoredSiblings, bidOutcomeRestoredTo }` (`undefined` = bid left alone).
  - **Note**: with an `actor`, the packet path inserts a `bids_submission_entries` row (`gc_customer_id` = the winner's GC, `contact_method` null — not a contact): *"Marked Won via packet — Southern Post · siblings marked Lost: Burd & Assoc. (GC lost the project) · bid Lost → Won."* and *"Won undone via packet — … back to waiting · bid back to Lost."* Fail-soft.
  - **Telemetry**: one `ui_nav_clicks` row per packet outcome write, `control = 'bid_outcome_set'`, `target = '#<path>:won|lost|waiting'` or `'#<path>:undone'`; paths `edit-bid` · `board` · `followup-details` · `waiting-to-hear` · `call-queue` · `job-import`.
- **Writers that got the confirm** (all pass `previousOutcome` + `actor`): Edit Bid's per-GC panel [`BidGcSentPanel.tsx`](../../src/components/bids/BidGcSentPanel.tsx) (Won button; "↩ waiting" title now says it undoes the win; `onOutcomeRollupChanged` widened to accept `null` so the form's Win/Loss segment follows the un-roll — `BidFormModal` maps `null → ''`); the Bid Board pill [`BidBoardGcRows.tsx`](../../src/components/bids/BidBoardGcRows.tsx) (+ exported `undoneToast`); Followup → Full bid details [`BidPackageSendsDetails.tsx`](../../src/components/bids/BidPackageSendsDetails.tsx); one-tap **Won** on [`BidsWaitingToHearLens.tsx`](../../src/components/bids/BidsWaitingToHearLens.tsx) and [`BidsCallQueueTab.tsx`](../../src/components/bids/BidsCallQueueTab.tsx) (`runAction` / `chaseAction` confirm first on packet-scoped rows, then the unchanged optimistic body `runActionNow` / `chaseActionNow`); the import picker [`PickWinningGcModal.tsx`](../../src/components/jobs/PickWinningGcModal.tsx) (its paragraph IS the confirm — now the same vocabulary, names a hand-set Lost via new `bidOutcome` prop; `JobFormModal` passes the actor, path `job-import`).
- **Not changed**: the **signature path** (`sign-bid-room` edge function) — the GC's click can't be confirmed by staff; its cascade is undoable through the inferred snapshot and its email already names the auto-Lost GCs (v2.2697). No toast carries an Undo action (the house `showToast` has none) — "↩ waiting" / the pill's *waiting* on the winner is the undo.
