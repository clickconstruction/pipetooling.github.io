# v2.1928 — Pipeline % done input clamps out-of-range entries (2026-08-20)

Owner request: typing 110 into the Stages board's "% done" box did nothing — the blur handler in [`StagesProgressPaymentCell`](../../src/components/jobs/StagesProgressPaymentCell.tsx) only committed values already in 0–100, so out-of-range entries were silently dropped (the stale number kept showing in the uncontrolled input). Now the value clamps to the nearest bound before committing (110 → 100, −5 → 0) and the input is rewritten to the normalized value so what you see is what saved. Covers every section's inline % box in both Pipeline views plus the mobile card list (single shared cell). New render smoke `StagesProgressPaymentCell.render.test.tsx` (clamp-high commits 100, clamp-low commits 0, in-range/cleared unchanged); help guide `set-job-progress-on-stages.md` notes the snap. The activity-panel slider is inherently 0–100 and unchanged. Client-only — no migration.
