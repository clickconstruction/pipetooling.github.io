# v2.4790 — Court areas: the night places the addresses the map never saw (2026-10-07)

The `court-precinct-nightly` function (**redeploy after merge**); no migration; no client. PRs 2 and 3 of `to-dos/job-address-pin/`, folded into one because both are a few lines in the same function. The count on 2026-10-07 found 149 property records with no point and, among the 194 outside every drawn area, only a handful with a county on file.

## What changed

- **The night geocodes first.** Before it classifies, the function takes up to `GEOCODE_PER_NIGHT = 300` addresses that have no point in `address_geocodes` and places them — Google when the key is set, else the Census — into the same cache the Map page and the job form's *On the map* line use. A miss is counted and left for the next night.
- **A blank county is filled from the point.** A record that fell in a drawn area already took the area's county (`map`, v2.4778). One outside every area now takes the county the point sits in — Google's answer when it geocoded tonight, else the Census geographies lookup (`censusCountyFromPoint`, v2.4783) — as `county_source = 'geocoder'`, the rung the record already knows. A county on the record is never changed.
- **The answer** adds `geocoded`, `geocodeMisses` and `countyFilled`; the Map page's *Classify now* reads the same function, so the office can run it by hand.
- **Dropped from the plan:** the job form writing the county onto a linked record itself. The night does it for every record within a day, and the form does not know which record a new job will link to.

## Is this the best we can do?

- **Google before the Census**, as owner-confirm-nightly does: the street map is rate-limited to a request a second and the night has 300 to place.
- **300 a night, not all.** 149 clears in one night today; a bad year of pasted addresses never makes the cron run long.
- **The county from the point is marked `geocoder`**, not `map`: it is the geocoder's reading of a point, not the county's own line.

## Tests

`deno check` on the function matches main's baseline. The classification kernel's tests are unchanged.
