- **`.mcp.json`**: the `twin-mcp` connector points at the new address (the connector key is unchanged, so allow rules hold).
- **[`mcp-router.wrangler.toml`](../../scripts/cloudflare/mcp-router.wrangler.toml)** (new): the Worker deploys from the repo — `npx -y wrangler@3 deploy --config …` — where the two older Workers are dashboard-edited and mirrored. The Worker file's header and the v2.3633 fragment say so.
- Docs: `TWIN_HARNESS.md` (the HTTP door; regenerated into `briefs.ts`), `HANDOFF.md`, `EDGE_FUNCTIONS.md` (the Endpoint sentence and `TWIN_MCP_PUBLIC_URL`), the to-do's status.

## Deploy

`supabase secrets set TWIN_MCP_PUBLIC_URL=https://mcp.clicktooling.com/twin`, then `supabase functions deploy twin-setup twin-mcp` (secrets apply on cold start; twin-mcp for the briefs). The Supabase address keeps answering, so no installed Claude Desktop config breaks; the repo's Python toolkit (`scripts/twin/`) stays on it because it also reads REST from the same origin.
