# v2.5589 — The app builds again: the Training card reads a course's size from its own file (2026-10-16)

Every `deploy.yml` run on main from ea73ca32d (v2.5575, 17:19 UTC) failed in **Build**, so clicktooling.com stayed on v2.5574 (443999f18, 16:09 UTC) while v2.5573–v2.5578 merged; the run before that (v2.5573) had failed on a network flake in the test job, which hid the change of cause. The CI log showed only `[copy-404] ENOENT … dist/index.html`, the `closeBundle` hook running after the real error; a local `npm run build` said it: `src/content/training/osha-30-refresher/01-how-safety-works-on-a-site.md (28:128): Failed to parse source for import analysis because the content contains invalid JS syntax`.

- **Cause** (`src/lib/training/courseFacts.ts`, v2.5575): to say *30 lessons* on the Dashboard card without loading the lesson text, the module counted the lesson files with `Object.keys(import.meta.glob('../../content/training/*/[0-9][0-9]-*.md'))`. A lazy glob loads nothing in dev and in vitest, so the page worked and the smokes passed; in a production build Rollup still bundles every globbed module as a dynamic import, and a `.md` file with no `?raw` query is parsed as JavaScript. The `checks` job does not run `vite build`, so the PR was green.
- **Fix**: `course.md` carries `lessons: 30` beside `minutes: 176`, `courseFacts.ts` reads both from the frontmatter and globs no lesson file, and `courseContent.test.ts` holds `TRAINING_COURSE_FACTS[slug].lessons` and `.minutes` equal to the lessons on disk, so the stated numbers cannot drift. The only globs on the lesson markdown are the two `?raw` ones in `courseRegistry.ts` (the course page's lazy chunk) and `helpGuideRegistry.ts`.
- **Proof**: `npm run build` passes locally on this branch; the next deploy carries v2.5573–v2.5586 to the site.

Open for a dev: the `checks` job could run a `vite build` (or a cheaper import-analysis pass) on pull requests, so a build break fails the PR instead of the deploy. It costs minutes per PR; the call is the owner's.
