# v2.7564 — Stickers: a sticker gains a place to remember that its strips printed (2026-11-17)

Punch list #373 ([`to-dos/sticker-print-record.md`](../../to-dos/sticker-print-record.md)). The owner's words of 2026-11-16 on Print future stickers: *add Recording that a run's strips came out. It needs a new column*. PR 1 of 2, the database. The reserved line, the *Which job?* card, the Runs fold and the stickers window that write and read the mark are PR 2.

## Why a stored mark

A run of stickers is reserved at the press, before any strip leaves the P-touch. `sticker_runs.printed_at` is the moment the run was made, so every screen read *Printed Nov 16 by Dana* whether or not anything printed. A printer that fails, a stop, a closed window or a cancelled print dialog all leave stickers with no strip, and nothing told them apart from the ones that printed.

## What ships

Migration `20261117140000_sticker_printed.sql` ([its page](../migrations/20261117140000_sticker_printed.md)):

- `box_stickers.printed_at`, a nullable `timestamptz` with no default. NULL means the app has not seen the sticker's strips go out.
- The one column of a sticker a client writes. Table-level `UPDATE` is revoked from `anon` and `authenticated` and granted back on `printed_at` alone, and the migration fails if either did not take.
- `box_stickers_update`, the SELECT policy's own predicate: whoever reads a sticker writes its mark, through `on_site_can_touch_job`.
- `box_stickers_stamp_printed`: a direct caller's time becomes the server's `now()`. NULL, the mark taken back off, is let through.
- The bed `supabase/tests/sticker_names/40_printed_mark.sql` plays it through RLS, and `scripts/pgtest-sticker-names.sh` applies the migration twice.

A sticker still moves only through a `box_sticker_events` row. `docs/ACCESS_CONTROL.md` and the on-site map say the one column.

## Order

The push can come any time after this merges. PR 2 must not merge before the push: it names the column in the read of every sticker.

## Not here

- No screen reads or writes the column.
- A sticker made before the column reads NULL whether or not it printed. PR 2 counts a NULL as *not printed yet* only for a sticker made after the mark began.
