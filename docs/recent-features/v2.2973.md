# v2.2973 — Test-gap audit, pass 5: the estimate customer experience and seven estimate siblings get their first tests, including a client ↔ edge sync guard (2026-09-06)

Follow-up to v2.2971, which named the estimate customer experience next. Tests only — no kernel, client, migration or edge-function change.

## Why these

`estimateCustomerExperience.ts` (383 lines) is the copy the customer reads: the estimate email, the acceptance page, the thank-you, the document headings — merged from builtins, org `app_settings`, the change-order overlay and per-row overrides. Its header says "keep in sync with `supabase/functions/_shared/estimateCustomerExperience.ts`", and nothing enforced that: the edge function sends the email while the client renders the page, so a drift means the two disagree. Seven untested siblings ride along: line-item normalisation (money), the customer attachment link, the staff "Preview as customer" snapshot, the catalog recents, the header brand, the route segment parser and the terms link. (`estimateCatalogApi.ts` and `estimateMasterUser.ts` are Supabase reads and stay untested by design.)

## What shipped

- **`estimateCustomerExperience.test.ts`** (16) — **the sync guard**: builtins, the change-order overlay, the `app_settings` key map and the field cap must be identical between the client and edge copies, and both must resolve the same inputs to the same copy for estimates and change orders. Then the contract: template substitution (every placeholder, everywhere; empty title → "Your estimate"), override parsing (known keys only, trimmed, non-empty except the footer which may be emptied on purpose, capped), the precedence ladder builtins < org settings < change-order overlay < per-row overrides (with an empty org value ignored and an unknown docKind treated as an estimate), the resolved shape with substituted email and its cap, snapshot serialisation round-trip and refusals, the client shape dropping only the email fields, the strict client parser defaulting a missing footer to the builtin, the fallback, and the Settings key lists (16 keys labelled, the subject template fetched but not editable).
- **`estimateLineItemNormalize.test.ts`** (9) — extended cents (round, clamp ≥ 0 unless change-order negatives allowed, non-positive quantity as one), the modern and legacy element shapes, unit price derived from a legacy line total, blank / zero / junk quantities, the empty object, array guard and sum.
- **`estimateCustomerAttachment.test.ts`** (6) — https-only URL within the cap, label trim and cap, a label without a URL dropped, the stored-payload parser, Drive file / `open?id=` links to the preview embed and every non-Drive or malformed form to null.
- **`estimateStaffAcceptPreview.test.ts`** (9) — the snapshot builder's normalisation, then write → read-and-consume through a stand-in localStorage: round-trip and consumption, the one-hour TTL, another estimate's snapshot refused, a legacy unwrapped payload from sessionStorage, malformed JSON / non-object / bad envelope timestamp, defensive optional fields (bad brand, http attachment, negative total), and a missing required field.
- **`estimateLineItemRecents.test.ts`** (3), **`estimateAcceptHeaderBrand.test.ts`** (2), **`estimateRouteSegment.test.ts`** (2), **`estimateTermsPageHref.test.ts`** (1) — MRU order / cap / dedupe / junk tolerance / three chips only for ids still in the catalog; the two brands and their image src; UUID vs quote-number segments (variant nibble, leading zeros, unsafe integers); relative vs absolute terms link.

All 48 passed on the first run; the client and edge copies are in sync today.
