# v2.1909 — Counts gets Old/New views: the Count Sheet arrives behind a toggle (2026-08-20)

Owner-approved prototype (the "Count Sheet" artifact), shipped with the Old/New playbook: the Counts tab's selected-bid card gains **Old / New** pills (per-device `bids_counts_view_v1`, default **Old** — the classic drag-sortable table, untouched). **New** is the Count Sheet:

- **Summary strip** — Items · Total units · **No plan page** (red when nonzero; click to filter to the offenders) · Plan pages cited.
- **List / By plan page** toggle — the audit view groups rows under each page they cite ("Plan page 26 — 13 items, N units"; multi-page rows appear under each) with a red **No plan page** bucket at the bottom. Kernel [`countSheet.ts`](../../src/lib/bids/countSheet.ts) (tokenizer, summary, grouping with numeric-then-text page sort, duplicate finder; 4 tests).
- **Quick add** — fixture chips from the service type's `counts_fixture_groups` (same source as the row editor's suggestions), then Count → Fixture → Plan page with **Enter adds and refocuses Count** for heads-down entry; inserts through the existing `insertCountRows` path.
- **Duplicate guard** — typing a fixture already on the bid disables Add and offers **Merge into existing (+N)** (bumps the row's count) so one name never forks the takeoff assignment.
- **Two-tap delete** — 🗑 → Delete/Keep inline.

Group/Tag column renders only when a row actually has one. Row reordering and inline edits stay in Old for now (the pills note says so); **downstream badges** (costed/priced per row, from the pricing engine) are the planned iteration 2 — they need the engine to load pricing data on the counts tab. Verified live on B273: 15 items · 253 units, pages 5/26/38/39 grouped, no-page bucket caught the waterline row, dup guard + merge offer on "wc". Client-only — no migration.
