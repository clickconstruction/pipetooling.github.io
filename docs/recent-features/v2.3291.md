# v2.3291 — Bids → Labor: the data rung — units, kinds, sources, the burden factor, and one view over the direct costs (PR 2 of the Labor refresh) (2026-09-11)

Migration `20260911161857_labor_rows_kind_unit_source.sql` ([fragment](../migrations/20260911161857_labor_rows_kind_unit_source.md)); push it the moment the PR merges (the new client writes the columns). Rung 2 of [`to-dos/bids-labor-refresh/`](../../to-dos/bids-labor-refresh/README.md): PR 1 (v2.3276) shipped the New view on the old columns, so "Task" meant `is_fixed`, footage rows had no per-100-ft reading, and the source chips were derived by comparing hours to the book. This PR makes those facts columns.

## Schema

- `labor_book_entries.unit` (`each` | `per_100ft`) and `.kind` (`fixture` | `task`), both defaulted. `cost_estimate_labor_rows.kind` (`fixture` | `task` | `sub`), `.unit`, `.source` (`book` | `alias` | `typed` | `robot`; NULL = pre-v2.3291), `.source_note`. `is_fixed` rows backfill to `kind = 'task'`; `is_fixed` stays (Old's checkbox, the sub-sheet prints and `approvalPdf` read it).
- `app_settings.labor_burden_factor_v1` = 1.20 — [`appSettingsKeys.ts`](../../src/lib/appSettingsKeys.ts) `APP_SETTINGS_KEY_LABOR_BURDEN_FACTOR_V1` + `parseLaborBurdenFactor` (1–3, else 1.20). Nothing reads it yet; the crew-rate card (PR 4) does.
- View `cost_estimate_direct_costs` (`security_invoker`): equipment · permit · sub · waste · other rows as one list with `kind`. [`costEstimateDirectCosts.ts`](../../src/lib/bids/costEstimateDirectCosts.ts) (+8 tests): `sumDirectCosts` (by kind, by stage, total), `directCostKindWords`, `DIRECT_COST_KIND_TABLE` (the view is read-only — writes go to the table the kind names).

## Kernels

- [`laborRowHours.ts`](../../src/lib/bids/laborRowHours.ts): `laborRowMultiplier` — 0 for a sub line, 1 for fixed hours (`is_fixed` **or** `kind = 'task'`), count ÷ 100 per 100 ft, else count. Old, the sub sheets, the cost-estimate page and Pricing all read through it, so a per-100-ft row is right everywhere without touching them (+4 tests).
- [`laborBookMatch.ts`](../../src/lib/bids/laborBookMatch.ts): entries carry `unit` and `kind`; `laborRowPatchFromMatch(match, bookName)` is the one place that says what filling a row from the book writes (hours, unit, kind + `is_fixed`, `source` = `book` for a name match and `alias` for an alias or code match, and the note "Toilet · Robot Default (by code)"); `laborRowAnswered` / `laborRowIsSub` keep sub lines out of the queue; `laborRowSource` returns `robot` when the row says so (+2 tests).
- [`bidLaborSummary.ts`](../../src/lib/bids/bidLaborSummary.ts): completeness counts sub lines separately (`subRows`, a muted pill) and never asks them for hours; the footage share reads `unit` first, then the row's words (+2 tests).

## Writes

- **Minting** ([`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts) → `loadCostEstimateLaborRowsAndSync`): a row minted from the applied book takes the entry's unit and kind and stamps `source` (`book` by name, `alias` by alias) and the note; the `fixture_labor_defaults` fallback stamps `book · fixture defaults`; a zero row stamps nothing.
- **The New view** ([`BidsLaborNewView.tsx`](../../src/components/bids/BidsLaborNewView.tsx)): the queue row's segmented control — Fixture · Task · fixed hours · Sub. Fixture: Read as… (entries show `· per 100 ft` / `· task`), New book entry… with a unit picker (defaults to per 100 ft for footage words; locked to the entry's unit once one is picked). Task: three fixed-hour inputs. Sub: no inputs — Save writes `kind = 'sub'`, zero hours. Every save stamps `source` + `source_note` ("learned on B375: "WC 1&2" reads as Toilet · Robot Default"); a new entry is created with its unit. Fill from the book writes `laborRowPatchFromMatch`. The grid: "hours per 100 ft · 729.5 ft" under the row, a `sub · priced under direct costs` chip with no inputs, `🤖 robot`, `· per 100 ft` on the chips, the totals row counts robot and sub. The head's sixth tile, **Other direct**, sums the view.
- **The Labor book panel** ([`BidsLaborTab.tsx`](../../src/components/bids/BidsLaborTab.tsx)): the entry form gains *Reads as* (Fixture · hours × count / Task · fixed hours) and *Hours are per* (each / per 100 ft, disabled for a task); the entries table tags `per 100 ft` / `task · fixed hours`. Old's fixed checkbox now flips `kind` (task ↔ fixture; a sub stays a sub) and the autosave / `saveLaborRows` carry `kind`.
