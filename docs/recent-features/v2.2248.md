# v2.2248 — Pay-speed quarantine for unverified import same-day pairs (2026-08-24)

Billing Truth Plan Phase 1 close-out. The HCP jobs-export import wrote job-level "paid in full" dates as `paid_on` while the invoice backfill dated bills by HCP send dates — when both derive from the same bookkeeping moment the sample reads "+0 days", an artifact (owner-confirmed). `get_billed_customer_pay_speeds` v5 (migration `20260824215810`) excludes from samples **and** receipts any payment dated on/before its bill day whose `payment_type` is HCP-import-ish and whose note lacks the `hcp-paydate-corrected`/`hcp-payments-split` true-date tags (stamped by the payments-report correction pass). Verified same-day payments (Mercury, Stripe, corrected, app-recorded) still count — measured verified data shows on-the-spot payment is genuinely common (40 of 113 strictly-verified samples are zero-day). Impact at ship time: 301 → ~240 samples, company median 1d → ~3d. No client changes — payload shape unchanged.

Companion one-off (psql, owner-run): the HCP **payments report** correction pass — 60 `paid_on` values re-dated to true received dates (job-scoped unique matches via the customer+job-created bridge to the jobs export; Mercury/Stripe rows skipped), 9 import rollups split into 18 real payments ($69k, per-job sums verified unchanged; split rows link to the bill only when dated on/after it). The 61 unmatched export payments ($438k gross, mostly near-miss amounts) were reviewed by the owner and deliberately **not** imported.
