# v2.5278 — Messages: a place for calls and texts from the company number, behind the scenes (2026-10-12)

The Messages build's cut 5 SQL (`to-dos/gc-mode/messages/BUILD_PLAN.md` → Cut 5, on branch `spike/gc-mode`), by helper 3, directed by the GC Review lead. Migration `20261012170000_quo_messages.sql`, stacked on the spine's (v2.5258). A draft until the spine's SQL lands and its bed is green. Nothing calls it until the `quo-webhook` and `quo-send` edge functions are deployed. Not pushed to prod: `supabase db push` comes after merge.

- **`messages` gains** `quo_id` (unique, so the webhook upserts a line by it), `recording_url`, `transcript`, `summary`, `duration_seconds`, `delivery` and `quo_rev`. Each has a rule: the call columns sit only on a call, a voicemail or a missed call; a length is never negative; an ending rides only on a text we sent; a Quo id is never blank. See `docs/migrations/20261012170000_quo_messages.md`.
- **`quo_write_line`** is the webhook's one write. It takes the line the kernels merged and writes it only over the revision the webhook read. Otherwise nothing changes and the webhook reads and merges again. The kernels prove any order of a call's events ends on one line. This makes that hold when two events arrive at the same moment, too.
- **`quo_webhook_ids`** is the webhook's memory of the deliveries it took. `quo_webhook_claim` takes one once, `quo_webhook_release` gives one back after a failure, and `quo_webhook_ids_forget` drops what is past 28 hours, matching `webhook.ts`'s `seenBefore`.
- **Access**: the office reads the new columns under the spine's policy and writes none. Only the service role runs the four functions or reaches the memory. The three house fences run at the end. `ACCESS_CONTROL.md` has its line.
- **The bed** `quo-messages` runs in the SQL beds workflow. It checks these things:
  - a text sent twice is one line;
  - a stale revision is refused, and after a re-read both the summary and the transcript stand;
  - the new columns keep their rules;
  - the delivery memory works;
  - who reads and writes what.
