## What the decision asked for, and how it was built

The proposal was a nightly snapshot of the queue counts under the owner's account, because the counts the Day book wants for history — deposits still to match, jobs still without a contract — are computed by client kernels for a signed-in viewer (the AR sorting filter is per user; the contract rule is `summarizeContractNudge` with the floor and the not-needed marks) and a cron has no account to run them as. Porting both to SQL would drift from the card. So the snapshot is written **by the owner's (or any dev's or controller's) own Dashboard**: once a day per device, when the Needs You card's counts have resolved, `record_day_book_queue` upserts the day's figures, stamped with who looked. Same numbers as the card, no impersonation, no port. A day nobody looked has no row and stays unknown — the grid stays plain there, honestly. If a true nightly run is still wanted, the impersonation route is a follow-up.
