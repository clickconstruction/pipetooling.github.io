# v2.4518 — Pipeline: a hidden map becomes a Map button (2026-10-04)

Client only; no migration, no edge function. The owner's ask: a collapsed *Jobs on a map* card still took a full-width bar for its title and *Show map*. It should become a **Map** box beside the search instead.

## What changed

- **The board holds the choice.** `jobsMapHidden` / `toggleJobsMapHidden` in [`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx) read and write the same per-device key as before (`readJobsMapHidden` / `writeJobsMapHidden`, `lib/jobs/jobsMap`). [`JobsMapCard.tsx`](../../src/components/jobs/JobsMapCard.tsx) takes it as optional `hidden` / `onToggleHidden`; left out, the card keeps the choice itself, as its own tests do.
- **Desktop: no card while hidden.** The tab does not draw the card at all, so the folded title bar is gone (and a hidden map still asks the board for nothing).
- **The way back.** [`JobsStagesCommandBar.tsx`](../../src/components/jobs/JobsStagesCommandBar.tsx) takes `onShowMap`: a **Map** button with the pin, after *Forecast* and before the search box, drawn only while the map is hidden. *Hide map* on the card puts it away again.
- **Phones.** The phone board's map sits inside the *Overview* fold; a hidden card there still folds to its title line with *Show map*.

## Tests

`JobsStagesCommandBar.render.test.tsx` (+1): no button while the map shows; hidden, the button sits after *Forecast* and before the search box and calls back. `JobsStagesTab.render.test.tsx` (+1): a hidden map is a button and no card; the button brings the card back and clears the stored choice; *Hide map* puts it away and stores it.
