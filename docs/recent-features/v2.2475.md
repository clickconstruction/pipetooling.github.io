# v2.2475 — Bid Room signatures actually record (2026-08-29)

The full live end-to-end test of the Bid Room train (run the same day it shipped, on the
ZZ Test bid against prod) caught a Phase 2 schema bug: `sign-bid-room` mints the signed
proposal as an `estimates` row with `doc_kind='bid_proposal'`, but the
`estimates_doc_kind_check` constraint (added by the CO train, `20260819171817`) still
allowed only `estimate`/`change_order` — so every real signature died at the INSERT with
"Could not record the signature". Unit and parity tests couldn't see it: they validate
kernel logic, not live schema constraints.

Fix: migration `20260829005728` widens the check. No client change. The same live test
verified the rest of the loop before hitting this wall: publish & send (room + rev 1 +
`link_sent` + real email), the GC page (rev line, three option cards including a G1
offered scenario, fixture lists), option selection swapping the document/total/Approve
label, and `option_viewed` telemetry.
