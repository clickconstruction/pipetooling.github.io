# v2.4579 — Submittals: save the whole vendor PDF from its line (2026-10-05)

Client only; no migration, no edge function. The owner, on the vendor file's line under step 3 of the SpaceX bid: "in this section I would like a save PDF button that downloads the entire PDF uploaded".

## What changed

- **Save PDF on the file's line** (`SubmittalSheetStrip`, `data-testid="save-file"`), after *Assign pages…* and before *Done with this file*. It downloads the stored file under the name it was dropped with.
- **A trimmed file** keeps the button. *Done with this file* rewrites the stored file to the pages on rows, so the button then saves those pages; its hover line says which it is (*all 75 pages as it was dropped* or *the 64 pages kept*).
- The row's own **Save PDF** (one row's cut sheet, v2.4546) is unchanged.

## How it is built

- `saveSourceFile` in `BidsSubmittalsTab.tsx`: a five-minute signed link to the file's bucket path with `download` set to its name, opened the way the stored package is (`openStoredPackage`). A link that cannot be minted is a toast; nothing is written.
- `SubmittalSheetStrip` takes `onSaveFile`; with no handler the button is not drawn. The button is not held by `busy`: it reads and writes nothing on the revision.

## Tests and checks

`SubmittalSheetStrip.render.test.tsx`: drawn only with a handler, its name and hover line, the call, and the trimmed file's line.
