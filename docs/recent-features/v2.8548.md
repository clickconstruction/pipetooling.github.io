# v2.8548 — Bill Customer: the bill's face shows the Service address line the made bill carries (2026-11-24)

Punch list #343, the third of the three faults its live walk of 2026-11-24 found. Client only.

## What was wrong

The face headed *On the bill* drew the office's memo alone. `create-stripe-invoice` has led the made bill's memo with `Service address: <the job's address>` since v2.1001, so the made bill opened with a line the face had not shown.

## What changed

- `supabase/functions/_shared/stripeBillMemo.ts`, new and pure: `stripeBillMemoWithServiceAddress(jobAddress, memo)` gives the memo as the made bill holds it, the address line, a blank line, then the office's memo, or null when both are empty. It sits in `_shared` so the function can read the same rule. **This PR does not change the function**, which still writes the line itself. Nothing is owed to a deploy.
- `StripeBillPreSubmitPreview` takes `serviceAddress` and draws the Memo row from the kernel, with the line break kept. A caller that passes nothing draws the office's memo as before.
- Bill Customer (`SendRecordInvoiceModal`) and `ConvertBillToStripeModal` pass the job's address. Both make their bill through `create-stripe-invoice`.
- The guide `ready-to-bill-pipeline` says the face's Memo opens with the service address.

## Tests

- `src/lib/billing/stripeBillMemo.test.ts`: both parts, either alone, neither, and that the function's source still writes the same line, by the kernel or by its own words.
- `StripeBillPreSubmitPreview.render.test.tsx`: the Memo row with both parts, with the address alone, and no row with neither.

## Not done

The bill's header on Stripe's page and PDF also carries a *Service address* field. The face has no header block and does not draw it.
