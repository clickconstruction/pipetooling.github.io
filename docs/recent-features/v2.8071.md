# v2.8071 — HR files: Waiting on you says when it could not be read, and names the plans on other files (2026-11-20)

Found by the audit of punch list #315. No migration, no seat change.

## What was wrong

- **A failed read hid the list.** `HrKeptPlansSection` kept only the rows of `loadKeptPlans` and dropped `heldWhy`. With no rows the section returns nothing, so a read that failed looked exactly like no plan waiting. The comment excused it for the days before the table's migration was pushed; the table has been live since 2026-11-13. Seen on the local app with the read answered 503: no section and no word about it.
- **Plans on other files were hidden behind an open file.** The list of every file is drawn only while no file is open. The open file's own list counted the plans on other files, but returned before drawing that line when the open person had none. On a wide screen there is no press that closes a file, so a dev reading one person's file never saw that a plan waited on another's.

## What changed

- The section keeps `heldWhy`. A failed read draws *Waiting on you could not be read:* with the reason and a **Read it again** press.
- The line for other files is drawn whenever a plan waits elsewhere, and names each person as a press that opens that file. With no plan on the open file the section is that one line.
- `PeopleHrTab` hands the open file's list the roster's names. It handed it the open person's name for every id.
- The help guide `keep-private-employee-files` said the list shows only when a plan is waiting. A plan that stopped matching this week shows too, and the guide says so.

## Verification

`HrKeptPlansSection.render.test.tsx`: the failed read and its second read, the line with a press on a file that has a plan, and on a file that has none. The test that pinned the silent hide is replaced.

## Left for the owner

The read takes the oldest 200 waiting and stale rows, and a stale row is never removed. Past 200 the newest waiting plans would fall off. Three rows exist today. It is in the audit's report.
