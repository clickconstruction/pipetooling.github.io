# v2.4857 — GC mode: each trade partner company can have its own portal link (2026-10-08)

P1a of the trade partner portal's real build (`to-dos/gc-mode/PORTAL_REAL_BUILD.md` on branch `spike/gc-mode`): the tables behind the portal's link and its messages. Migration `20261008050000_gc_trade_portal_links` (doc: `docs/migrations/20261008050000_gc_trade_portal_links.md`). No screen and no edge function yet.

- **`gc_trade_portal_links`**: one link per trade partner company (`gc_companies`), the sub portal's `sub_portal_links` keyed to a company. The raw token and its SHA-256 hash, no expiry, `revoked_at` as the kill switch, one link on per company.
- **`gc_trade_messages`**: every email sent to a company, as it went: kind, mail group, a key that sends once, language, subject, lines, who it went to, the day, and the `email_send_log` row. The portal's *Their messages* will read it.
- **`mint_gc_trade_portal_link(company, rotate)`** and **`revoke_gc_trade_portal_link(company)`**: `SECURITY DEFINER`, dev only until the door, with answers in plain words.
- **`public_page_views`** counts the new surface `gc_trade_portal`.
- RLS: a SELECT policy for dev on each table, nothing writable under RLS, nothing for `anon`. It ends with the three block calls.
- Checked on a local Postgres 15: it applied twice, and the mint, rotate, revoke, message and role checks passed (the migration doc lists each).
