# v2.2473 — Followup defaults to the Call queue lens (2026-08-28)

Owner ask: the Bids tabs that carry a "new | Old:" lens strip should default to **new**. There
is exactly one such strip in the app — the Followup group on `src/pages/Bids.tsx` (Call queue
{{new}} | Old: By builder / By status / Why we lost / Waiting to hear, from the v2.2105
parallel-run). Its single default door was the main **Followup** tab button, whose onClick
landed on `builder-review` (or kept `submission-followup` if already there).

New behavior, one onClick:
- Entering the group from outside → **`call-queue`**; superintendents → `builder-review`
  (call-queue is role-blocked for them by the URL guard and the hidden lens button).
- Re-clicking Followup while already on any of the five lenses keeps the current lens (before,
  it yanked why-we-lost/waiting-to-hear/call-queue back to builder-review) — still through
  `selectBidsTab`, so a lingering `bidId` param is dropped per v2.2043.

Deliberately unchanged: every explicit deep link (`?tab=submission-followup&bidId=…` share
links and clock-strip/My-Bids rows, `?tab=why-we-lost` from the Dashboard pinned quick row and
Quickfill Needs-you) — those point at specific destinations, not defaults. `openBuilderLensForCustomer`
still lands on By builder by design. Landing on `/bids` with no `tab` param still defaults to
`bid-board` (unchanged).

This is the soft first step of the v2.2105 "stage 3: retire old lenses" decision — the old
lenses stay fully functional behind the `Old:` divider.

Help guide `follow-up-with-builders` intro now says Followup opens on the Call queue.
