# v2.7149 — The theme check reads a ternary whatever its other side is (2026-11-13)

A sweep. The theme check missed every colour written as `cond ? '#hex' : undefined`. It reads them now, and the 53 it found are on tokens.

## The gap

`node scripts/theme-tokenize.mjs --check src` read a style ternary only when both sides of the colon were quoted strings on one line (`TERNARY_TAIL`). With `undefined`, a variable or a second ternary on the other side, the line was never read. v2.7143 fixed the one that was reported: the open supply house's row, near-white words on a near-white band in dark, 1.03:1.

## The change to the check

- The tables and the rewrite moved to `scripts/lib/themeTokenize.mjs`, so they can be tested. `scripts/theme-tokenize.mjs` is the command and reads the disk. The tables did not change.
- New in the kernel: `ternaryBranches` reads one style value from its `prop:` to the comma or brace that closes it and returns the quoted strings that stand as a branch. That covers an unquoted other side, a nested ternary, grouping parens, a ternary laid over several lines and a `??` fallback. The branch is mapped by the prop that holds the ternary.
- Left alone on purpose: a string the condition compares against (`paper === 'white' ? …`), a string handed to a call, and anything inside a template string.
- `src/lib/themeTokenize.test.ts` pins eight cases, the first being `background: isExpanded ? '#f0f9ff' : undefined`.

## What it found

53 literals in 35 files, each rewritten by the script to the token whose light value is the same hex.

- **A picked row, pale band under pale words in dark (9 lines):** Bids → Follow-up (three tables), the Prospect List, Banking's two review tabs, the bids working board's drop target, the dispatch note picker, and the supply house row v2.7143 also fixes (the same edit, so the two merge in either order).
- **A white fill under token words (2):** the off state of the service type search toggles and of the Stripe billing mode toggle.
- **Four other fills:** today's column on the Projects forecast, a calendar dot on the GC stage strip, the bid map's dot and a dead press. The last two are under *By hand*.
- **Words that kept a light-theme colour on the dark page (33):** negative amounts in People → Review and Sub Labor, loading figures on Job Summary, link and status colours in a dozen places.
- **Borders (5):** hairlines that stayed light grey in dark.

## By hand, three lines

- `BidBoardMapCard.tsx`: the dot on a lit chip sits on a saturated fill beside white words, so it stays white as `'rgb(255, 255, 255)'`. The script had made it the surface colour.
- `UnifiedBidCustomerNotes.tsx` and `ScheduleJobModal.tsx`: each is a dead press whose grey the script moved onto a token. Both now read `DEAD_PRESS_FILL` and `DEAD_PRESS_TEXT` from `src/lib/deadPress.ts`. In light their words are darker than before, 8.33:1, as on every other dead press.

On a rebase conflict: re-run `node scripts/theme-tokenize.mjs src`, then make these three edits again.
