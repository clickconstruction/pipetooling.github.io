# v2.5661 — Report by line: the rule and its kernel (2026-10-20)

Punch list #130, PR 1 of 5 (the plan and mock-up in `to-dos/report-by-line/`; the owner took the defaults and said build it all, 2026-10-20). A field report asks *How complete is the job?* and a tech halfway through the rough-in types 50, meaning the piece they stood in; the job then reads half done everywhere money is counted. The stage-weighted picker of v2.3192 fixes it only behind an Order row almost no job has, one stage per report. No migration; no edge function; no screen change — the kernel alone, so PR 2 (the field on the report) and PR 3 (the stepper) stand on tested rules.

- **Why no migration**: `record_stage_progress(job, fixture, pct, report)` already gates on `can_report_stage_progress`, validates 0..100 and filters to Order / Any rows, so one call per moved line serves; a batch RPC would buy a push and a types regen for nothing. `list_job_stage_progress` already returns every priced Order and Any row with its share, whether or not an Order row exists.
- **The kernel** ([`lib/reports/lineProgressReport.ts`](../../src/lib/reports/lineProgressReport.ts), over v2.3192's `StageProgressRow`): `linesModeAvailable` (two or more priced lines; a one-line job keeps the slider), `linePct` (a paid draw is 100, else the tech's pick, else the record, else 0), `jobPercentFromLines` (Σ share × line percent, rounded; equal to `jobPercentFromStages` with one override), `defaultOpenLine` (the first Order stage not done, else the first Any-time line, else none), `movedLines` (the picks that differ from the record, in row order; a paid draw never moves), `jobLine` (*before* is the job's recorded number when the caller has it, since the office may have typed one the lines do not add up to; *after* is what the lines say), `lineProgressFieldValue` (the report's *Stage progress* field, one clause per moved line and the job's move: *Rough In 35% → 50% · Water heater — → 100% · job 32% → 43%*; empty when nothing moved), `lineWords` (a row's right side: ✓ Paid · ✓ Done · 35% → 50% · 35% · —), `howRows` (the arithmetic behind the job line: share, standing, points, the total), and the four strings the screens print.
- **Tests**: `lineProgressReport.test.ts` (9 cases on the mock-up's job: the gate, a line's number, the job's number against the one-stage math, the row that opens, the moved lines, the field's sentence, the job line with a typed number, the words, the arithmetic).
- **Docs**: this fragment; the to-do's plan is amended once its own PR (#5893) lands.
