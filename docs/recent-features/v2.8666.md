# v2.8666 — A developer can set a seat's role on CountTooling and TakeoffTooling from here (2026-11-26)

The third PipeTooling piece of the accounts train (one staff account across PipeTooling, CountTooling and TakeoffTooling, managed from People). Edge only: no migration, no client change.

## What was there

`ct-bridge` forwarded seven verbs to CountTooling's `manage-user`, none of which touched a role. `tt-bridge` forwarded four to TakeoffTooling's, none of which retired a seat or touched a role. The owner approved a drawing of the person desk on 2026-11-26 whose *Sites* rows retire a seat and set its role on each site.

## What changed

- **`ct-bridge` forwards `set_flags`.** `{ ct_user_id, is_admin?, is_overseer?, is_lead? }` changes only the flags it names and answers with all three. CountTooling's function (deployed 2026-11-26, version 9) refuses to switch off its last admin, and its `roster` now sends the overseer and lead flags beside the admin flag.
- **`tt-bridge` forwards `deactivate`, `reactivate` and `set_role`.** The first two set and lift the seat's auth ban by `tt_user_id`, as CountTooling's do. `set_role { tt_user_id, role }` takes `user`, `admin` or `dev`; TakeoffTooling's function (deployed 2026-11-26, version 6) refuses to demote its last dev.
- `docs/EDGE_FUNCTIONS.md` names the verbs in both sections.

Both functions stay devs-only doors. `update_email` is still not forwarded to TakeoffTooling.
