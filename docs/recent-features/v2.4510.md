# v2.4510 — Pipeline: Not scheduled is the button, the Assign work link is gone (2026-10-04)

Client only; no migration, no edge function. The owner's read of a Working row: the blue **Assign work…** line under *Activity* repeats the green calendar at the start of the row.

## What changed

- **The link is gone from the desktop row.** [`jobsStagesRowShared.tsx`](../../src/components/jobs/jobsStagesRowShared.tsx) `renderStagesFieldAndBillingLines` drew it under the *Activity* line on an unscheduled row (v2.3752). It called `ctx.openQuickAssignForJob(job)`, the same call as the green calendar in the row's icon rail.
- **The flag is the door.** For a planner (`ctx.canOpenJobScheduleModal`) the *Not scheduled* flag is now a `<button class="stagesWhenFlag isDoor">` that makes that call, so the way to fix the row still sits on the words that name the problem. Everyone else gets the plain flag as before. Hover underlines it and darkens its border; it takes a focus ring.
- **`index.css`**: `.stagesWhenDoor` (the link's look, now unused) is replaced by `.stagesWhenFlag.isDoor`.
- **Phone cards are untouched.** [`JobsStagesCardList.tsx`](../../src/components/jobs/JobsStagesCardList.tsx) has no icon rail; its **Assign work…** chip beside *not scheduled* is the one-tap way in and stays.

## Tests

`JobsStagesTable.render.test.tsx` (+1): the flag is a button that opens the sheet for the job, no *Assign work…* line is drawn, and without `canOpenJobScheduleModal` the flag is a plain span.
