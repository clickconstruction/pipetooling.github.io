# v2.4116 — Bids: saving a bid that has not been sent writes only what changed (2026-09-28)

Client only; no migration, no edge function, no screen change. Two things. The fix below is the quirk punch list #51's page guard pinned (v2.4072) and left for after the train. And this is the train's close-out: #51's card is retired (the record: `to-dos/README.md` → *Closed 2026-09-28*), #46 row 5 marks the Bids map's step 9 shipped, and `docs/BIDS_TABS_ARCHITECTURE.md`'s step 9 no longer links the card.

## What was happening

`bidDateSentAttestationMerge` (`src/lib/bids/bidDateSentAttestation.ts`) answered "cleared" for any empty sent date, so every Edit Bid save on a bid **never sent** spread the eight stamp columns (`bid_date_sent_attested_at` … `bid_date_sent_ack_honesty_by`) as `null` over the payload, and `pruneUnchangedBidUpdateFields` does not drop columns that are not form fields. Null over null — no data changed — but every autosave wrote nine columns for one, and cancelling the "Confirm bid sent" checklist on an unsent bid wrote the eight nulls alone (seen on the #51 live walk, identically on `main`).

## The fix

The nulls go out only when a **saved** sent date is emptied (`serverBidDateSent` non-empty). A bid never sent has no stamps to clear, so an empty date adds nothing. The stamp columns have no default other than null, so a new bid's insert is the same row without them. Before changing it: no unsent bid carried any stamp in production (0 of 117 unsent, 399 bids, read as the dev account), so no row relied on the old cleanup.

- `Bids.render.test.tsx`: the three *Edit Bid writes* cases that pinned the quirk now expect the changed field only; a new case — emptying a sent date writes `bid_date_sent: null` and the eight nulls, once. `useBidDateSentAttestation.render.test.tsx` (a sent bid) unchanged and passing.
