# v2.4131 — Pipeline: the job you opened is marked (2026-09-29)

The owner, on Jobs → Pipeline: when a job is clicked and *Job activity / notes* opens under it, nothing tied the panel to the row that opened it — "I should highlight or orange-border the job above this section to make the app feel more reactive. How could I do this tastefully?" Mock-up (proposed beside today): artifact `H1J3g2JFR2pJGRtSjG5yEn`.

**Not orange.** Amber already means one thing on the board — the flash (`stagesJobFlashId`, a 2.6 s outline) that says *we scrolled you here* — and orange is the loudest color on every row (the service chip, *Not in Customers*, past-expected). So the open state is the link blue, and the row and the panel become one card.

- **`stagesOpenRowStyle` / `STAGES_OPEN_ROW_BAR`** (`jobsStagesRowShared.tsx`): `background var(--bg-blue-tint)`, `box-shadow: inset 3px 0 0 var(--text-link)` (an inset shadow, so nothing shifts), `border-bottom: none`, a 150 ms background ease. Both tokens exist in the light and dark themes.
- **The row** (`JobsStagesTable.tsx`, `StagesUnifiedJobRow.tsx`, `StagesUnifiedInvoiceRow.tsx`): the style spreads in when `expandedJobThreadId === job.id`, before the flash's spread so the amber flash still wins for its 2.6 s; `aria-expanded` on the `<tr>` says the same to a screen reader.
- **The thread row** (`StagesExpandedThreadRow.tsx`): its cell takes the same tint and bar, no top padding, and the row rule (`--border-job-row`) returns under the panel; `data-stages-thread-for={job.id}` for tests.
- Tests: `JobsStagesTable.render.test.tsx` — the open row and its thread cell carry the tint, the bar and `aria-expanded`; a closed row carries none of it.

Verify: `npx vitest run src/components/jobs/JobsStagesTable src/components/jobs/JobsStagesUnifiedTable src/components/jobs/StagesExpandedThreadRow`. Live: Jobs → Pipeline → click a row's empty space — the bar and tint appear on the row and run down through the notes panel; click again and both go.
