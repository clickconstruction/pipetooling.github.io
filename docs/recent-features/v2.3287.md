# v2.3287 — Dashboard: "Robots have work waiting" — the robots' backlog as one Needs You line for devs (2026-09-11)

Client only. No migration, no edge function.

## Why

The owner asked how to show a dev, on their Dashboard, what needs to be bid and what needs a price comparison — tastefully. The Dashboard already has the pattern: every backlog on it is a Needs You item, ranked worst-first, with a door and snooze/dismiss. A separate "Robot backlog" panel would have been the one permanent box whose count is usually zero. So it is one line that is absent when the robots are caught up.

## What shipped

- **Needs You · Robots** (dev only, hygiene tier — below anything with a deadline): *Robots have work waiting* · "4 bids want a shadow (oldest asked 3 days ago) · 2 price matrices queued (oldest 5 hours) — BP482 Marriott shell · BP359 SpaceX BA-2 matrix." Blue. **Amber only when something is stuck**: a matrix working with no heartbeat for over an hour (or blocked), or a human bid request older than a week. Door: **Open the Console**. Snooze 24h / dismiss until the count rises, like the other backlog items. Absent at zero.
- **Kernel** [`robotBacklog.ts`](../../src/lib/bids/robotBacklog.ts): `buildRobotBacklog(bids, twinExists, requests, now)` runs the open human bids through the Console's own `buildRobotQueue` (same 30-day stale rule), so the Dashboard's count can never disagree with the Console's (the Dashboard reads every trade, like its other cards; the Console's count follows the trade pill — verified live: 8 all-trades = Plumbing 1 + Electrical 3 + HVAC 4); counts queued + working + blocked matrices; `describeBacklogAge` is coarse on purpose. 5 tests. Item wording: 4 tests in `dashboardNeedsYou.test.ts`.
- **Hook** [`useRobotBacklogNudge`](../../src/hooks/useRobotBacklogNudge.ts): four light selects (open, unadopted bids; the twin user ids, so human vs robot is the board's own `isRobotBid` rule — older shells carry no `twin_source_bid_id`, which the first live check caught; the set of shadowed source ids; open requests joined to the bid), refetch on focus, fail-soft; per-device snooze/dismiss state in `robotBacklogDismiss.ts`.

## Deliberately not

No whole-queue counts (stale bids stay on the Console). No robot violet on the Dashboard — it keeps blue and amber. Estimators are not shown this: they already get *Matrix ready*; the queue itself is the operator's concern.
