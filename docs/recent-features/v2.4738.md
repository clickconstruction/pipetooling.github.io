# v2.4738 — Edge drift check: it names each function still running old shared code (2026-10-06)

**The ask (Robert, 2026-10-05):** `npm run check:edge-drift` only warned generically when `_shared/` changed ("importers may be stale") and still reported every function current. Name the stale importers instead.

**What the audit behind it found.** Each function's bundle (its `index.ts` and every relative import, transitively) was compared with its deployed source (`supabase functions download --use-api`):

- 2026-10-05: 18 importers of `_shared/resendSendEmail.ts` ran the copy from before v2.4557 (#4526), and `dev-mcp` ran the catalog from before #4521 and #4532. Six of the 18 were deployed less than 72 h before the shared edit, so the old dir check's grace window would never have named them.
- 2026-10-05: two ran code from an older tree, deployed after the change merged. `resolve-ip-geolocation` lacked v2.3427's `ipGeoValidation.ts`, and `update-collect-payment-stripe-customer-email` still refused a customer filed under another office, as before the one-company change (dcd9968e0).
- 2026-10-06: `send-bid-room-link` missed v2.4728's `_shared/bidRoomPayload.ts` while its two siblings were redeployed.
- Eight that commit dates called stale were deploys made from the branch before the merge, byte-identical.

All of these were redeployed from `origin/main` and re-read as identical.

## What shipped

- [`scripts/lib/edgeBundle.mjs`](../../scripts/lib/edgeBundle.mjs), plain JS because the workflow runs on bare Node: `runtimeImportSpecifiers` (static imports and re-exports, side-effect and dynamic imports; a statement-level `import type` or `export type` is dropped, as the deploy drops it), `walkBundle`, `commitsByFile` and `commitsSince` (one `git log` pass), `historyBlobIds` and `gitBlobId`, `compareBundles` (current, behind or elsewhere) and `configVerifyJwt`.
- [`scripts/check-edge-function-drift.mjs`](../../scripts/check-edge-function-drift.mjs): a function is read when any file in its bundle has a commit after its deployed `updated_at`. Its deployed source is downloaded, four at a time, and compared byte for byte.
  - Behind fails and names the files, the commits and the redeploy command. The command adds `--no-verify-jwt` where prod has the gateway check off and config.toml would turn it on.
  - Elsewhere (a deployed file this history never had, as when a branch deploys before it merges) is a warning.
  - When a download fails, commit dates decide, with the old grace.
  - `--full` reads every function.
  - A verify_jwt difference between prod and config.toml is a warning.
  - The generic `_shared` warning is gone.
- [`.github/workflows/edge-function-drift.yml`](../../.github/workflows/edge-function-drift.yml): the daily and manual runs pass `--full`, and a push touching the kernel runs the check too.
- Tests: [`src/lib/edgeBundle.test.ts`](../../src/lib/edgeBundle.test.ts) (22). Docs: EDGE_FUNCTIONS.md → Verify Deployment.

## Verified

- Against prod at 2d09f4edb: the default run is OK in 3 s with nothing to read; `--full` is OK in 85 s with 133 read.
- A throwaway commit to `_shared/bidRoomPayload.ts` made it name exactly `get-bid-proposal-room`, `send-bid-room-link` and `sign-bid-room`, its three run-time importers, and exit 1. The eight functions that only `import type` from it were left out.

## Open when this merged

The verify_jwt warning compares prod with config.toml, so it cannot see a config.toml that is itself wrong:

- `crew-day-email-dispatch`, `money-waiting-email-dispatch`, `schedule-share-dispatch` and `statement-round-email-dispatch` have no `[functions.*]` block. A plain deploy on 2026-10-06 at 06:29 UTC turned their gateway check on, and their pg_cron calls, which send `X-Cron-Secret` and no JWT, have been refused with `UNAUTHORIZED_NO_AUTH_HEADER` since.
- `[functions.auto-send-test-reports]` lost its `verify_jwt = false` line in v2.3319's merge (621ee92b1). Its cron has been refused the same way at least since its 2026-10-05 18:52 UTC deploy.

The fix is a redeploy of the five with `--no-verify-jwt` plus a `verify_jwt = false` line for each in config.toml, so a plain deploy keeps it.
