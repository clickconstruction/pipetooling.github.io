# v2.8383 — Messages: the database can write what a heard day is (punch list #421, PR 2 of 5) (2026-11-23)

Punch list #421 (`to-dos/messages-heard-day.md`), the database half, on the owner's calls of 2026-11-23 (*build it*, *straight to the choice*). One migration, `20261123185942_heard_day_write.sql` (`docs/migrations/20261123185942_heard_day_write.md`). No edge function, no client change.

## What changed

- **`write_down_heard(p_message_id, p_kind, p_day, p_writes)`**: a heard day and its kind written in one press, or just talk with its day. Their own text or voicemail only, from a customer, a trade partner or an architect, each only the kinds the screen offers them. A payment is refused here: it goes through #129's sheet. The same kind takes a new day, and another kind over a written day is refused in words.
- **`message_promises.job_id`** and **`write_down_payment`'s `p_job_id`**: a payment mark names the Pipeline job it is for, the card's small extra. The two-argument function is dropped and made again with the job last and defaulted, so the live client's call is answered unchanged.
- **The bed**: `supabase/tests/messages_follow_up/50_heard_day.sql`, run by `scripts/pgtest-messages-follow-up.sh`.
