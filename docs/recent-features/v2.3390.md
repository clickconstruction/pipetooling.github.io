# v2.3390 — Contract sweep, the Drive pass: Found in Drive (2026-09-14)

New edge function `drive-contract-scan` (**deploy after Drive is connected** — see below); no migration. The last PR of the train in [`to-dos/contract-sweep-seen-first/`](../../to-dos/contract-sweep-seen-first/README.md) (PR 0 v2.3384 · PR 0c v2.3385 · PR 1 v2.3386 · PR 2 v2.3387 · PR 3 v2.3388 · PR 4 v2.3389).

## Why

The owner (September) said most signed contracts live in Google Docs, so the contract pile is mostly a *filing* gap, not a signing gap. The drive-intake service account already reads the jobs Shared Drive, and job folders are named after the project. One pass can file dozens of jobs with no customer contact.

## What shipped

- **Edge function [`drive-contract-scan`](../../supabase/functions/drive-contract-scan/index.ts)** (`docs/EDGE_FUNCTIONS.md` section): office-role staff JWT; one name-contains query across what the SA can see (contract · agreement · subcontract · signed · executed · proposal · terms), the jobs root's child folders as the job-folder map, one parent lookup per unknown parent so files one level down are attributed; returns the files with their job folder. Read-only, writes nothing. Its Google auth helper is a local copy of drive-intake's with the read-only scope, so the twins' intake path is untouched. `config.toml` gains `[functions.drive-contract-scan] verify_jwt = false`.
- **Kernel [`driveContractMatch.ts`](../../src/lib/jobs/driveContractMatch.ts)** (+5 tests): `contractFileStrength` (strong / weak / no — invoices, plans, lien waivers, change orders are never contracts), `contractFileKind` (GC subcontract vs agreement), `streetKey` (number + first street word), `folderMatchesJob` (job number first — two jobs can share a street, never a number — then street, job name, customer/GC name), `matchDriveContracts` (Confident = a strong file in a folder that names the number or street with no tie; Check = a name-only folder, a weak word, or two jobs on one folder; None otherwise; every row carries a reason), `signedOnFromModified`, `summarizeDriveMatches`.
- **[`DriveContractsFoundModal`](../../src/components/jobs/DriveContractsFoundModal.tsx)** (+2 render cases): the summary (*41 contract-looking files in 38 job folders · 104 jobs without a contract · 31 covered by a confident match*), **Confident · Check · No match** groups, rows as job · customer · amount, the file (linked to Drive) · date · folder · reason, a *GC subcontract* chip; **File the N confident** (one file per job, the newest) and **File** on Check rows, each through `fileSignedJobContract` with the Drive link as the signed document, signer = the job's customer, signed on = the file's date; the sweep marks the jobs filed and the chips refresh. Drive not connected → the 503's words in an amber box.
- **The door**: the sweep's ⋯ → **Look in Drive for signed contracts…**, devs only (owner decision 6 taken as "a dev runs the first pass") until the matcher has been right a few times.
