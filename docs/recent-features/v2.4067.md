Owner ask 2026-09-28: estimator Wendi opened Submittals and was confused; "offer a walkthrough for this page that walks a user through how to use it and the steps involved, and the button that triggers it". ## What shipped

- **`src/lib/submittals/submittalJourney.ts`** (pure, 12 tests) — `submittalJourney({ scheduleTags, picks, rev, room, decisions })` → seven stages (`picks · build · rows · package · share · review · resubmit`) each `done | current | waiting | later` with a `data-tour` anchor, and `next` (`kind: next | waiting | done`, the sentence, the action and its label). Reads the tab's own state: `specified`, `picks`, `tiles` (`alternatesWithoutReason + designChangesWithoutReason`, `sheetsNeeded`), `package_path`, the room (status, view count, identified names), `summarizeDecisions`. An older revision on screen reads as the record, not the work.
- **`SubmittalJourneyStrip`** (`src/components/bids/`, render test) — the pills (green ✓ done, blue current, amber waiting), the next line with its button, **Walk me through it ▶**, and the first-open offer line (**New here?** … / **Not now**). Presentational; the tab's `runJourneyAction` maps each action onto the handler the button row already calls (`onOpenPricing`, `askRobot('read_schedule')`, `createFirstRevision`, the vendor-PDF file input, `buildPackage`, `setSharing(true)`, the room-link clipboard copy, `newRevision(true)`); `goToStage` scrolls to the stage's `data-tour` element and rings it (`.submittal-journey-flash`, `index.css`).
- **`src/lib/submittals/submittalTour.ts`** — the 12 stops in process order (`submittals-journey · source · robot · build · revisions · tiles · rows · drop · package · share · room · resubmit`), each with a `missingBody`; `SUBMITTAL_GUIDE_HREF`; `hasSeenSubmittalWalkthrough` / `markSubmittalWalkthroughSeen` on `localStorage['pt.submittals.walkthrough.seen']` (storage unavailable reads as seen so the offer never nags).
- **`SpotlightTour`** — a step may carry `missingBody`: when its anchor is not in the DOM the card centers over the dimmed page and the line says what will appear and when (`data-testid="tour-missing"`); `spotlightTourStepsPresent` keeps such steps. Pricing's tour is unchanged (its steps carry none).
- **`BidsSubmittalsTab.tsx`** — the strip mounts after *Loading…*; a "?" beside the title (the same glyph Pricing has) starts the walkthrough; `data-tour` anchors on the source line, the robot card, the empty card, the revision chips, the tiles, the rows table, Drop a vendor PDF, Build package, Share, the room line, and the resubmit button (the *Rev N+1 from the rows sent back* button when it is there, New revision otherwise).
- Guide `build-a-submittal-package.md` gains **Where you are**; `docs/GLOSSARY.md` Submittals tab entry and `docs/BIDS_DOCUMENT_TABS_ARCHITECTURE.md` (SU-12) amended.

## Decided here

- **Strip over card.** The Pricing "?" card was kept out: the strip answers "what now?" every visit, the tour explains the road once, and the "?" only starts the tour.
- **The tour keeps every stop.** On a fresh bid nine of twelve stops center with their not-yet line rather than being dropped; the test pins which ones.
- **Nothing new is stored.** The first-open flag is per device, like the Takeoffs view choice. No behavior of the button row changed.
