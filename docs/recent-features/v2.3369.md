# v2.3369 — Sent bids get their labor hours from the book (2026-09-12)

PR 3 of the Costs-tab refresh (owner: "zero people who have been bidding have been adding in labor… collect labor baselines instead of guessing"). Migration [`20260912053412_labor_rows_from_book_on_send.md`](../migrations/20260912053412_labor_rows_from_book_on_send.md).

## What changed

The Labor tab has always minted a bid's labor rows from its count sheet with the book's hours — but only when someone opened the tab. (An earlier count of "7 of 187 sent bids with hours" was capped by PostgREST's 1,000-row limit on the labor-rows read; the real picture, measured with count queries after this back-fill, is below.) `mint_labor_rows_from_book(bid)` does that mint in SQL, with the same rules (the bid's book, else the first by name for its trade; hours by fixture-type name, alias, then `fixture_labor_defaults`; a zero row keeps no source and waits in the New view's queue; a row a person touched is never overwritten). The `bids_mint_labor_on_send` trigger runs it the first time `bid_date_sent` is set; the migration back-filled every sent bid with a count sheet. No client change: the Labor tab, Bid vs actual, and the job budget snapshot read the rows they would have made.

## Verified

Pushed 2026-09-12: the first file minted or filled **507 rows across 118 sent bids** (all time); the second file re-ran with the prefix rule. Measured with count queries (not the capped list read): of the **187** bids sent in the last 180 days, **146 carry labor rows and 102 carry hours** — but **0 have every row answered**. What stays unanswered is plan codes and pipe footage the book has no name or alias for — `FCO` (44 bids), `HB` (36), `ft of 3/4" CW` (30), `ft of 1" CW`, `ft of 3/4" HW`, `ft of 2" SV`, `ft of 4" SV`, `FS-1`… — exactly the New view's queue ("HB ×7 · no match in the book · Read as… Hose bib"). One alias saved there answers every future bid, and the mint reads aliases from then on. Migration 20260912054036 added the code-prefix rule so `FS-1`-style codes match once their letters are an alias.

## What this does not do

It does not invent hours for fixtures the book has never seen — those rows read *none* and sit in the Labor tab's queue for a person. It does not touch bids without a count sheet (130 of 187); the Jobs baseline tile (v2.3367) is the book's answer for those.
