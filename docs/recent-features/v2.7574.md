# v2.7574 — Task notes: the @ in a task's note box (2026-11-17)

Punch list #375, PR 2 of six: the @ in `ChecklistItemActivity`. Client only: no migration, no edge function. It calls `task_note_taggable` and `task_note_post_tagged` and reads `task_note_tags`, all on prod since v2.7570.

## The @ is open to a dev alone, on purpose

`canTagInTaskNotes` in `src/lib/jobs/noteTags.ts` answers true for the dev role only, as #363's PR 3 held job tags. Until PR 3 lands the count above Checklist and the Tagged task notes section, a tag would reach its person in that task's thread and nowhere else. Everything below that is not the @ button and the names is live for every reader.

## What changed

- **One box, six screens.** `ChecklistItemActivity` is the note box of Today, Still open and so Task Mode, Review's Outstanding by person, Manage, People → Vehicles tasks and the My Inbox cards. It now runs `useNoteTagBox` with the day row the note lands on, so all of them get the @ button, the row of names, the mark in the words and Backspace from PR A (v2.7566).
- **The names come from the day row.** `useNoteTagBox` takes `taskInstanceId` and reads `task_note_taggable`. A job's names wait for the first `@`. A task's are read when the box is drawn, so the task's own people can be offered before a letter is typed.
- **The task's own people are offered first**, after the word *Tag*: whoever gave it, then whoever has it, three at most (`taskOffer`, `TASK_OFFER_MAX`). Under each name the press says *gave this task*, *has this task* or *office* (`tagPersonSays`).
- **A caller the list refuses gets a plain box.** A primary who can open the task and does not have it is not one of its people. The list answers 42501, and the box draws no @ and no error.
- **A note with a tag posts in one call**, `task_note_post_tagged`, the note and its tags or neither. A note that tags nobody is inserted as it always was.
- **A posted note draws its chip and who it waits on** through `TaggedNoteBody`, from `useTaskNoteTags`, one read of `task_note_tags` for the task, since a tag stays with the task and not the day.
- **After any typed note** the box sends `noteTagsChanged`, because the database's trigger answers a tag that waited on its writer.
- **A read of the names that was dropped is asked again.** Typing `@` and taking it back at once dropped the read before it answered, and the box then said *Reading the names…* from then on, on a job's box too. The read is now asked again the next time the names are wanted.
- The box is see-through over the mark, so its background moved to a wrapper and its words take `var(--text-strong)`. In the dark theme the box is now the surface colour, where it was the browser's own field colour.
