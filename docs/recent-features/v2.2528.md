# v2.2528 — twin-mcp ct_finish_takeoff: one-call STG-3 finisher (2026-08-31)

The manual tail of every backtest — a user-run curl script that extracted a CT JWT from
captured headers, POSTed `import-takeoff`, flipped review status, and minted a view
link — is now a single twin-mcp verb. `ct_finish_takeoff(bid, name, takeoff)` runs the
whole chain server-side (twin-mcp v1.2.0):

- Fence-checks the bid (own/assigned — same rule as `add_bid_note`).
- Mints the twin's CT session in-function: per-twin token first, fleet-secret fallback,
  then **walks the magic link itself** (`fetch(action_link, {redirect:'manual'})` — the
  verify redirect's location fragment carries the access token; no browser).
- POSTs CT `import-takeoff` with `external_ref` **always** set to the bid number
  (bid-stamp doctrine enforced by construction) and the plan set riding
  `plan-fetch?bid=` under the caller's own token (`skip_pdf` opts out).
- `set_project_review_status → 'ready'`, `create_view_link`, then PT-side:
  stamps `bids.count_tooling_link` and ensures the `bid_audits` row (idempotent),
  logging a `ct-finish:<bid>` entry in `twin_runs`.

Verified live by re-running BT-7's import through the verb (idempotent replace of the
same CT project, 86 markers, PDF leg ok, new view link, audit row already present →
skipped). The CT anon key compiled into the function is the **publishable** client key
from CT's `config.js` — public by design. `docs/EDGE_FUNCTIONS.md` twin-mcp section
carries the contract; deployed alongside this PR.
