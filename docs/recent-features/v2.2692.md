# v2.2692 — Job Summary refresh PR 1: ledger controls + true profit (2026-09-03)

Owner ask: Job Summary "does the job but is missing things" — sort by % complete, open on finished (100%) jobs, and find TRUE profit now that overhead is sorted (v2.2670–v2.2676). Proposal approved with all four leans (day-share default; no-field-day overhead unallocated and visible; earned revenue for in-progress jobs; the Days view inside Job Summary — that's PR 2). The tab stays presentational; everything new is page-side state + pure kernels.

## Client only — no migration

- **Day ledger kernel** [`lib/jobs/jobDayLedger.ts`](../../src/lib/jobs/jobDayLedger.ts) (+8 tests): one calendar-day table — per day the overhead pool $ (office labor + bid labor + office parts, internal transfers excluded) and every approved, closed field session grouped by job (hours, labor $, people). `allocateJobOverheadDayShare` = Σ pool(d) × jobHours(d) ÷ fieldHours(d) with the per-day lines; `jobOverheadByMethod` also does A (hours × pool÷field hours), B (revenue × pool÷invoiced revenue), C (field labor $ × pool÷field labor $) over the SAME window; `unallocatedJobDayOverhead` = pool on days with no field hours (charged to nobody, shown in the strip); the reconciliation test proves charged + unallocated = pool. JSON (de)serializers for the session cache.
- **Loader** [`lib/jobs/loadJobDayLedger.ts`](../../src/lib/jobs/loadJobDayLedger.ts): the Overhead snapshot's scans widened to any window (`buildOverheadDailyLabor`, `buildOtherJobsLaborByDay`, `loadOfficePartsUsdByDayExcludingInternalTransfer`, invoices Chicago-bucketed with test-mode excluded), plus pending field sessions (hygiene) and each touched job's approved hours BEFORE the window (flagged, not charged). Paged, caller RLS.
- **View kernel** [`lib/jobs/jobSummaryLedgerView.ts`](../../src/lib/jobs/jobSummaryLedgerView.ts) (+13 tests): prefs (status Finished/In progress/All · window 90d/This year/12 mo/All · method · sort key/dir; localStorage `jobs_jobSummary_view_v1`), window starts ("All" = 2025-01-01), `enrichJobSummaryRows` (resolved % via the existing precedence; finished = 100; revenue = contract when finished else EARNED = contract × % (no % → 50%, flagged); gross, margin, hours · days in window, prior hours, overhead by method, true profit, true margin, flags), search/status/window filters (window membership = hours in window OR last work / created date inside it), sorts with nulls last (job # numeric-aware, blanks first — the memo's old rule), totals + flag counts, hygiene.
- **Hook** [`hooks/useJobSummaryView.ts`](../../src/hooks/useJobSummaryView.ts): prefs + the ledger behind a one-hour per-user, per-window sessionStorage cache (Dashboard Overhead card pattern) + the enriched/filtered/sorted rows and totals. Called from `Jobs.tsx` next to the P&L memo; passed to the tab as one `view` prop.
- **Tab** [`components/jobs/JobsJobSummaryTab.tsx`](../../src/components/jobs/JobsJobSummaryTab.tsx) + new [`JobSummaryLedgerToolbar.tsx`](../../src/components/jobs/JobSummaryLedgerToolbar.tsx): search + Show / Worked in / Overhead segmented controls, totals strip (jobs, revenue, gross + margin, overhead charged + share of gross, true profit + true margin, true $/field hour), hygiene chips (no contract $, no %, pending approvals, prior hours, unallocated overhead); sortable headers (`JobSummarySortHeader`); columns Revenue (earned marker on in-progress rows) · Labor · Subs · Parts · Gross · Margin · Hours · days (+ marker for prior hours) · Overhead · True profit · True % · %; tfoot totals; expanded row gains "Overhead — the math" (day lines for day-share; the one-line formula for A/B/C). "Revenue before Overhead" and "Total Bill" labels retired. Empty-state copy for a filter that hides everything. Pay lockdown unchanged (`showTeamLaborAndProfit` gates labor, gross, margin, overhead, true profit).
- **Parts fixes** in [`hooks/useJobsMercuryAllocations.ts`](../../src/hooks/useJobsMercuryAllocations.ts) + the `jobSummaryData` memo: card charges per job now exclude the Banking → Accounting **Internal Transfers** bucket (same exclusion as Overhead; bucket/link lookups degrade to "everything counts" under RLS), and card charges linked to a supply-house invoice (`mercury_transaction_supply_house_invoice_links`) are subtracted from parts once (`cardChargesLinkedToInvoices` on the row) since the invoice allocation already counts them. Paged with `fetchAllRowsChunkedIn` (the old single `.in()` silently capped at 1,000 rows).
