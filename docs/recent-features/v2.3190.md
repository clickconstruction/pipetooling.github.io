# v2.3190 — Job Mode card: Clock In opens the Clock In modal when nothing is running (2026-09-09)

Client only. Owner, impersonating Tristen on the Job Mode dashboard: "in this view for users, I don't think the clock in button works?" It did not.

## The bug

`DashboardJobModeCard`'s right button in the `no-clock-no-schedule` state is **Clock In** (`kind: 'manual-clock-in'`), and its handler calls the bridge's `requestOpenUpdateFocus()` — the same door as **Choose Next Job**. `ClockInOutButton` registers `handleOpenUpdateFocusModal` as that opener, and its first line was `if (!openSession) return`. No session is precisely the state that shows Clock In, so the tap resolved to nothing: no modal, no toast, no error. The visually-hidden `ClockInOutButton` mount in the Job Mode early return (the Dashboard comment about the bridge) was present and registered — the opener itself declined.

## The fix

- **[`resolveBridgeFocusTarget`](../../src/lib/clock/bridgeFocusOpener.ts)** (pure, 3 tests): `'clock-in'` with no session, `'update-focus'` with one, `'none'` without a user id / display name (the visible buttons' own guards).
- **[`ClockInOutButton`](../../src/components/ClockInOutButton.tsx)** `handleOpenUpdateFocusModal` now consults it: `'clock-in'` → `setClockInModalOpen(true)` (the same modal the visible Clock In button opens, with its notes gate and offline recovery); `'update-focus'` → the existing Update Focus modal. Nothing else changes — the card's Choose Next Job still lands in Update Focus, Wrap Up Day still runs the guarded clock-out, and the visible buttons keep their handlers.

## Verify

As a field user with nothing scheduled today (Job Mode on, not clocked in): tap **Clock In** on the card → the Clock In modal opens (job search, "what do you intend to accomplish today"). Clock in from it → the card flips to the on-job state. While clocked in, **Choose Next Job** still opens Update Focus.
