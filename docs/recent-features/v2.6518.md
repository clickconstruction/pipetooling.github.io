# v2.6518 — Attach a login to someone already on the roster — PR 4 (punch list #260) (2026-11-04)

PR 4 of 5 on punch list #260 (the model: every worker a users row from day one, a login attached later — PR 1 [v2.6511](v2.6511.md), PR 2 [v2.6514](v2.6514.md), PR 3 [v2.6517](v2.6517.md)). The spike's finding that makes it one press: GoTrue's admin create-user has taken a chosen `id` since v2.155.0 (prod runs v2.197.0), so the auth account is created on the person's own `users.id` and `handle_new_user`'s `ON CONFLICT` (v2.6511) stamps the row. Nothing that points at the person moves. No migration.

## What changed

- **`create-user`** takes `user_id`: the id of a users row with no login behind it. The function reads the row as the caller (a dev), refuses one that already has a login, a sample or twin, an archived row, or an address another row holds (a login already behind the id → 409), creates the auth account on that id with the body's address (default the row's own) and password (default an unguessable one), skips the `public.users` upsert so the row's name, role, standing and flags stand (stamping `login_attached_at` and the address itself if the trigger did not), and runs `ensureLinkedRosterRow` as before, which finds the record already linked. The response carries `attached: true`. Redeploy after the merge.
- **`invite-user`** refuses an address that belongs to a no-login row with *… is on the roster with no login. Attach a login from their desk instead*, so the invite never mints a second id for a person who has one. Redeploy after the merge.
- **Kernel `src/lib/people/attachLogin.ts`**: `attachEmailProblem`, `attachLogin` — `create-user` with `user_id` and the address, then `send-sign-in-email` (unless a password was set), the function's reason thrown as the error.
- **The desk's Access & account** (`PersonDeskAccessSection.tsx`): for a users row with `login_attached_at` null a **Login** row reads *No login attached. Their hours, pay, portal and paperwork work without one.* with **Attach a login…** for a dev — an inline form (the email, prefilled with the row's address; *Attach and send the sign-in email*; Cancel) whose success toast says the email went. Until a login is attached the section hides Training mode, Sign-in, the CountTooling seat, Change… on the address (its hint reads *The address a login attaches to.*) and Archive, each of which looks the account up by its sign-in; Role, Name, Trades, Charged as, Supervision, extra access and Merge a duplicate stay. The desk's user read carries `login_attached_at`.
- **People → Users** ⋯ menu: **Attach a login** on an account row with none (dev), opening the desk at Access & account. **Who counts as what**: *· no login* beside the role of a person with no sign-in.
- **Guide** *invite someone to sign in*: the section *Attach a login to someone already on the roster*. Docs: EDGE_FUNCTIONS (`create-user`'s `user_id`, `invite-user`'s refusal), ACCESS_CONTROL, the card.
