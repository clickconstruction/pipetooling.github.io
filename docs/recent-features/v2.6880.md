# v2.6880 — The dev seat reads a mailed file's words: read_mail_file_text beside read_mail_file's bytes (2026-11-10)

Punch list #296, carded 2026-11-09 with the ranged reads (v2.6806). Since that release `read_mail_file` hands any file off a mail back whole, in base64 pieces of at most 54,000 bytes. That makes the bytes reachable, but it is a costly way for an agent to read a supplier's PDF: a 180 KB file is four replies of 72,000 characters before a word of it is read. The file index already reads a file's words from its bytes on the server. The seat now asks for those words off a mail.

## The two calls the card left open

- **A sibling verb, not a mode.** `read_mail_file_text(account, id, name, offset?)` stands beside `read_mail_file`, as `get_person_document` stands beside `get_person_file`: each verb's reply keeps one shape, and `offset` means bytes in one and characters in the other without a flag deciding which.
- **A page is characters, not PDF pages.** Paging by character means every call parses the PDF again, since the function keeps nothing between calls. Measured: a 40-page written PDF (60 lines a page, 236,700 characters) parses in about 120 ms on a laptop, and a 120-page one in about 310 ms. The reader's own note puts the platform at three times that, so 40 pages are about 350 ms against the reader's 800 ms for one file and the platform's 2 s for a request. A text file and an `.eml` have no pages, so characters are the one contract that holds for every kind the reader reads. Paging by PDF page (`from_page`) was not built.

## What changed

- **`supabase/functions/_shared/devMcpMailFile.ts`** (pure; tests `src/lib/devMcp/devMcpMailFile.test.ts`):
  - `mailFileTextArgs` takes the account, the hit's id, the file's name and `offset` (a whole number from 0; 0 when left out) and refuses anything else in words.
  - `MAIL_FILE_TEXT_MAX_CHARS = 60_000`. JSON writes a line end as two characters, so 60,000 leaves the door's 80,000 room for a page of short lines and the file's facts.
  - `textPieceEnd(text, offset, max)` ends a piece on a line end when one sits within 2,000 characters of the cut, and never between the halves of a surrogate pair.
  - `mailFileTextReply(account, id, file, read, { offset })` takes the file as bytes (`MailFileRaw`) and the reader's answer (`FileTextRead`) and replies `{ account, id, name, mime, size_bytes, sha256, text_source, pages, pages_read, chars, offset, next_offset, read_next?, text }`. `chars` is the whole text's length; `next_offset` is null on the piece that ends it. The reply is built, written as the door writes it (`replyText`) and shortened by a quarter until it is under `REPLY_MAX_CHARS`, so a text that escapes long (quotes, short lines) still never has the door's cut land inside it.
  - `read_next` (`mailFileTextNextWords`) stands before the words whenever they are not the whole file's: which characters these are and the `offset` to call with next, and, when `pages_read` is under `pages`, that the reader stopped at its time or its 200,000 characters and the pages past that are read from the bytes.
  - `mailFileTextHeldWords` is the refusal for a file with no words, each naming the next press: a scan (no text layer: read its bytes with `read_mail_file`, or file it on its job with `plan_mail_file`, where the file index reads a scan by OCR once OCR is set up), a kind the reader does not read, a file past the reader's size, a read that ran out of time, a PDF the reader cannot open. A file the reader read and found empty, and an offset at or past the end, are refused too.
- **`supabase/functions/dev-mcp/index.ts`** (server 0.60.0): the verb's declaration and handler, and a line in the server's instructions. The handler reads the file with `read_mail_file`'s own `fileOff`, then `readWithin(() => textFromBytes(bytes, { name, mimeType }, { limits: INDEX_PDF_LIMITS }), …, INDEX_READ_MS)`: the index's limits for one file, since the request reads one file, and `readWithin` so a parse that throws answers `error` and never fails the request. `_shared/fileText.ts` is untouched; it was already in the bundle through `_shared/fileIndex.ts`. Read-only and logged as `read_mail_file` is; no role gate beyond the seat's own, and `view_as` runs it as it runs any read.
- **Docs**: a row in `docs/dev-mcp/README.md` and its *Oversized asks* line, a paragraph in `docs/EDGE_FUNCTIONS.md` → dev-mcp, and a line in the `mail-search` skill that says to reach for the words first.
- **`to-dos/dev-seat-mail-file-text.md`** (#296) is deleted: this is the build.

## Tests
