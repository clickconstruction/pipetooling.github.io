# v2.7226 — Paint a map: a file for Google Earth or a hiking app (2026-11-13)

Punch list #345, PR 5b. The last of the ways out of the app that the owner asked for. Google's own maps cannot show our line from a link: a Google Maps link carries points routed along its own roads, not a line. So the line reaches another map only as a file.

## What changed

- Under **Or hand over a copy** in **Share this map**, a row **A file for another map** with two presses: **A .kml file** (*Google Earth and Google My Maps*) and **A .gpx file** (*A hiking app or a handheld*).
- A phone whose share sheet takes the file gets the share sheet. Everything else gets the file in Downloads, named after the map.
- The guide `paint-a-map` gains **A file for another map**.

## How it is built

- `paintedMapFiles.ts`, pure. KML 2.2: a `LineString` for each line in the paint's colour and a `Point` for each place, numbered as on the map, longitude first as the format asks. GPX 1.1: a waypoint for each place, then a track for each line, in the schema's order.
- **No clock.** A `.gpx` track usually has a time on every point. Ours has none, and a test holds that the file contains no `<time>` and nothing shaped like one: a saved line is a shape, and a file made from it cannot say more than the table does.
- **No photo, no name of who painted what.** The file's own words are the map's words, the company, the day it was made and that a length is a guide.
- A name is written as text. A test feeds it markup and checks the file still parses and holds no element of the name's making.

## Is this the best we can do

- **Two formats, not five.** KML and GPX between them open in every tool the card named. GeoJSON, a shapefile and a DXF were considered and left out: nobody who would ask for one lacks a converter from KML.
- **Not filed as a sent copy.** A file is the same shape the link shows, and the sent-copies ratchet is for paper and mail. If the owner wants a record of who took a file, that is one line through `fileSentCopy`.

## Checked

- Eight kernel tests, each file parsed as XML; two render tests for the presses.
- **Not checked**: opening the files in Google Earth and in a hiking app. The formats were written to their published schemas, and that is the first thing to try once it is live.

No migration, no edge function.
