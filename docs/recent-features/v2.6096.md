# v2.6096 — Needs you: the statement round and a returned check open in place (2026-10-29)

D's PR 6 of punch list #178 (`to-dos/needs-me-rail/`). Two of the assistant's lines on Today's lines were doors to other pages whose destination is a modal: *N GC statements are ready to send* opened the Pipeline on `?round=1`, which opens GC Review, and *<payer>'s check came back* opened Accounts receivable on `?check=<id>`, which opens the deposits window on the case. The Needs you rule says a door opens in place where the destination is a window, so both now do, on both hosts, like Today's sends ([v2.5595](v2.5595.md)) and the deposits ([v2.2890](v2.2890.md)). No migration, no edge function.

## What changed

- **The doors** ([`needsYouDoors.ts`](../../src/lib/needsYouDoors.ts)): `statement-round` is `{ kind: 'window', window: 'statement-round' }`; `returned-check` is `{ kind: 'window', window: 'returned-check', depositId }` with the one case's deposit id, or null for the list when several came back; before the cases load the line still opens Edit Job on ③ Payments received. The window door carries `depositId`, so `useNeedsYouPress` keeps the door, not the name, as its open state.
- **The statement round's window** ([`GcReviewWindow.tsx`](../../src/components/dashboard/GcReviewWindow.tsx)): GC Review, the Pipeline's own `JobsGcReviewModal`, over the card, the pattern of `DashboardArDepositsModal`: the billed and collections rows from the shared jobs cache through `buildJobsStagesBoardLists`, the customers (for the email's To), the office roster (`fetchActiveUsers`), the last-sent hints and the promised pay dates (`useBilledMoneyData`) read as the Pipeline reads them; Edit Job and Job Detail through their contexts; the send through `sendGcStatementEmail` with the Pipeline's toast. Loaded lazily when it opens, as Today's sends is, so the hosts' chunks stay as they were.
- **The shell glue is shared** ([`gcReviewShellIo.ts`](../../src/lib/jobs/gcReviewShellIo.ts)): the print (`printGcReviewGroups`, filed as a send) and the copy for email (`copyGcReviewGroupForEmail`) that `JobsStagesTab` wired inline since v2.1414 moved there, and the tab calls them, so the window and the tab drive the modal with one set of words.
- **The returned check's window**: `DashboardArDepositsModal` takes `initialDepositId` and hands it to `BankPaymentsModal`, the page's own `?check=` prop, so the case opens on top of To match as it does on the page.
- **The lines re-read on close**: `useStatementRoundNudge` gains `reload`; it and `useBankReturnedPaymentsNudge`'s `reload` join the handles as `reloadStatementRound` and `reloadBankReturned`; the deposits window's close also refetches the unallocated count as before.
- **Tests**: `needsYouDoors.test.ts` (six named windows on both hosts; the returned check's window on its case, the list with several, Edit Job before the cases load); [`useNeedsYouPress.windows.render.test.tsx`](../../src/components/needsYou/useNeedsYouPress.windows.render.test.tsx) (the deposits window on the case and on the list with the re-read on close, GC Review in place with its re-read); [`GcReviewWindow.render.test.tsx`](../../src/components/dashboard/GcReviewWindow.render.test.tsx) (the modal mounted with the cache's rows, the roster, the office gates, the close handed back).
- **Guide**: *work the Needs you list on the dashboard* says both open over the card.
- **Docs**: `DASHBOARD_SECTIONS_ARCHITECTURE.md` (seven windows), `QUICKFILL_ARCHITECTURE.md`, the Glossary's *Needs You card*, the to-do's status and its *Where it stands* table.
