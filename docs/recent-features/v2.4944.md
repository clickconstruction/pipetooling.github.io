# v2.4944 — My Time day editor: the Arrow keys move a boundary off a row join (2026-10-08)

Client only; no migration, no edge function. Punch list **#46** row 10 (`to-dos/decomposition-queue.md`): the behaviour bug the step 7 gestures move found and pinned (v2.4908), shipped apart as the map asks.

## The bug

In a cluster of two or more clock rows that share metadata (all punches, or one salary segment), the boundary between two rows sits on their row join. Focus its handle and press ArrowUp or ArrowDown: `handleStripKeyDown` nudged it a minute, then ran `finalizeInnerBoundaryMsForCluster`. For those rows the finalize is `snapBoundaryMs` with `ROW_JOIN_SNAP_MS` (60 s). A minute off the join is exactly 60 s away, so the snap put it straight back. The keys could never move a join; only a drag could.

## The fix

`useMyTimeBoundaryGestures.ts` → `handleStripKeyDown`: when the finalize would put the boundary back where the key found it and the cluster's rows share metadata (`clusterSharesClockSessionClusterRpcMetadata`), the nudged minute is kept. Everything else is as before:

- a step that ends within a minute of a join still lands on it
- drags and taps still snap
- a mixed cluster's finalize, which keeps each segment inside its row, always stands

## Tests

`useMyTimeBoundaryGestures.render.test.tsx`:

- The pinned case now holds the fixed expectation. From the 16:00 join, ArrowUp gives 15:59 and again 15:58. ArrowDown lands back on 16:00 (15:59 is a minute off it), and once more gives 16:01. With the fix switched off it fails.
- New: a mixed cluster's seam (a salary row, then a punch) still moves a minute each way.
