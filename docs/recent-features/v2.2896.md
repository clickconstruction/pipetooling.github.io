# v2.2896 — Every card says the same number as the page it opens (2026-09-05)

Journey map Tier-2 #16 (cluster C4 — "cards whose figure ≠ the page they open"; J33-F7, J29-F4, J14-F6, J20-F2/F3, J19-F4, J32-adj-1). Six pairs, one PR; no migration, no edge function. House precedent: v2.2751's one-hook card+queue. Rule applied per pair: **either one hook feeds both surfaces, or the destination carries the card's gloss in the card's words** — never a third count.

## 1. Tally card ↔ `/tally` header — one hook (J33-F7)

- New [`src/hooks/useTallyUnlinkedCounts.ts`](../../src/hooks/useTallyUnlinkedCounts.ts): both RPCs (`count_unlinked_mercury_transactions_for_tally`, `…_stale` with `TALLY_STALE_MIN_AGE_DAYS`) read together, focus-refetch, `refetch()`; a failed read leaves that count `null` (nothing rendered), never `0`. Replaces the two inline loaders in `DashboardPinnedQuickRow.tsx` and the one in `QuickfillNeedsYouSection.tsx`.
- `buildNeedsYouItems` gains `tallyUnlinkedCount`; the `tally-self` card detail says "… on a job yet (105 unlinked in all) — sort in Job Parts Tally." when the total is wider than the aged figure, and carries `destinationFigure`.
- `JobTally.tsx` header: beside its own "105 unlinked" it says "· 100 over 2 days old (the Dashboard card's count)" via [`src/lib/tally/tallyStaleGloss.ts`](../../src/lib/tally/tallyStaleGloss.ts), reading the same hook; the page's own reload calls the hook's `refetch()` so a sort updates both at once.
- Telemetry: `needsYouClickTarget(item)` → `#tally-self&dest=105` on the `ui_nav_clicks` row when the destination's number differs (`DashboardNeedsYouCard.act`). Card-vs-page drift is now measurable after the fact.
- Tests: [`src/lib/tally/tallyStaleGloss.test.ts`](../../src/lib/tally/tallyStaleGloss.test.ts) — parity on fixtures (card figure = gloss figure; total rides the click; no gloss while loading or when the piles coincide).

## 2. Division 22 card ↔ audit modal — fold the client kernel (J29-F4)

- Root (map finding, confirmed in SQL): the card's RPC `spec_section_uncoded_name_count` counts `DISTINCT lower(btrim(fixture))`; the modal's `spec_section_fixture_name_audit` groups `BY btrim(fixture)` (case-preserving) and the client classified each row. Rule matching is case-insensitive on both sides, so "WC-1"/"wc-1" was always one decision counted twice in the modal (1,145 vs 1,187 live).
- Fix in the kernel, not the RPC: `foldFixtureNameSpellings()` in [`src/lib/specSectionAudit.ts`](../../src/lib/specSectionAudit.ts) groups audit rows by `lower(trim)`, names the group by its most-used spelling, sums `bidCount`, and carries `spellings[]`. `buildFixtureNameAudit` consumes the fold, so `uncodedCount` equals the card's RPC by construction. The modal shows "also spelled …" beside a folded name and a tooltip on "N uncoded" saying it is the card's count.
- Tests: `specSectionAudit.test.ts` — parity on fixtures against the card's predicate (`Set(lower(trim)) ∩ unmatched`), plus the fold itself.
