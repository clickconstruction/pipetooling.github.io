# v2.8054 — The app's first download is lighter again: the permit rules load when a list asks for them (2026-11-20)

The start-check readers fetch the permit read when a bullet asks for it. The permit rules leave the main chunk, where v2.8015 had put them. No migration, no edge function, and nothing a person sees changes.

## Why

The main chunk crossed the 9 MiB precache cap in `vite.config.ts` on 2026-11-20 and every Pages deploy failed. One step of that growth was not plain growth. v2.8015 added `src/lib/startChecks/startCheckReadersIo.ts`, which imported `RESEARCH_CITIES` from `src/lib/research/permitResearch.ts` by name, with `bidSite`, `bidSiteIo`, `ourNames` and `ourNamesIo` beside it. The start-check hooks are reached from eager screens, so a static import there is in the first download. The permit rules had lived in a lazy chunk (`bidSiteIo-*.js`) that only the screens that read permits fetched. The import moved them into `assets/index-*.js`.

## What changed

- `src/lib/startChecks/startCheckPermitsIo.ts` (new) holds the permit read, `readPermitsOnSites`, moved as written: our names, the address read against the city list, the permits at the house number, the plumbing permits in our name.
- `startCheckReadersIo.ts` imports nothing under `research/` by name. Its `readPermits` checks the seat first, as before, then fetches the read with `await import('./startCheckPermitsIo')`.
- A seat that cannot read permits is told so without the fetch. A field phone never downloads the permit rules.
- A fetch that fails (a phone with no signal and no cached copy) lands in the same `guard` a failed read does: the permit bullets say *The app could not read this just now.* and the other kinds still read.

88,165 bytes left the main chunk: nineteen modules, four of the five named above (`ourNames.ts` stays, read by other eager code) and the fifteen they read (`permitCities`, `permitFeed`, `permitParcels`, `permitParcelPoints` and `permitCoords` from `supabase/functions/_shared/`, and `permitSkim`, `permitReach`, `permitPublic`, `permitCityDoors`, `permitBuilders`, `bidSitePanel`, `nameLikeness`, `nameAnswers`, `lookAlikeWorklist`, `lookAlikeCountMemory`). No module entered it. Two small chunks are new: `startCheckPermitsIo-*.js` (709 bytes) and `ourNamesIo-*.js` (1,068 bytes).

The main chunk is still 15,915 bytes over 9 MiB (9,437,184), so this change does not clear the cap by itself. The cap and the code-split pass its comment asks for are separate work.

## The other imports v2.8015 added

The build's own import graph was read for every module the main chunk holds only because of `startCheckReadersIo.ts`. After this change two remain: `submittals/procurementLogIo.ts` and `submittals/procurementItemSources.ts`, 6,590 bytes together before minifying. They stay, since a second fetch on a job's Documents tab costs more than they weigh. The order log's rules (`procurementLog.ts`) and the trips files were in the main chunk before v2.8015 by other doors.
