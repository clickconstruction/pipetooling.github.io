# v2.5797 — Messages: the flow rail waits until the sender is named (2026-10-23)

Punch list #149, PR 3. The owner's screenshot of an unnamed sender's thread, the sort card open, showed the right-hand rail reading *ONCE*, one hollow dot, *0 / 1*: "in this view, when a message is at this stage, this right hand side bar doesn't make sense, should we hide it during this stage of messaging?" He took the recommendation to hide it.

- **The gate** ([`threadSlots.tsx`](../../src/components/gc/messages/threadSlots.tsx)): cut 4's `flow` slot draws nothing while the contact's kind is `unknown`, so neither the rail nor the panel it opens to is mounted. An unnamed sender has no flow of their own, only the placeholder seeded for the unknown kind (`flows/seed.ts`, one `once` lane with one step, *Who is this?*, fact `named`), which repeats what the pill beside the name (v2.5793) and the sort card (v2.5795) already ask. The rail appears the moment *Who is this?* names them and their kind's flow applies, which the card's press already causes through the window's re-read. The seed, the unknown flow and its `named` fact are untouched: Follow up's lanes and the nudges may still read them.
- **Tests**: [`ThreadWindow.flowRail.render.test.tsx`](../../src/components/gc/messages/ThreadWindow.flowRail.render.test.tsx): the window for a number nobody has named draws no rail; the window for a named person draws it.
- **Docs**: `MESSAGES_ARCHITECTURE.md`'s slot list and its `useThreadSlots` sentence; the Glossary's step-card sentence.
