## What was open

A confirm is written by `sub-portal` after it reads the sub's answers and finds none for this copy. Two presses at one moment both read before either writes. Both would write, and the copy would hold two confirms with two times. A payment's *Got it* has been held to one row by the table since `20261117150000`. A confirm was held by the function alone.

## What changed

- **The table holds it.** `sub_paper_acks_confirmed_paper_key` is unique on `paper_id` for the rows with `kind = 'confirmed'` that name a paper. Each revision of a paper is its own row in `sub_papers`, so one row per `paper_id` is one confirm per revision. A copy made after the sheet changed takes its own.
- **The second press reads the first one back.** `sub-portal` reads the refused write (`23505`) as already confirmed. It reads the copy's confirm again and replies `{ ok: true, already: true, confirmed }`, as a second press a moment later always did. `portalConfirmKept` in `supabase/functions/_shared/subPortalPapers.ts` builds that reply, and stands the press's own row in if the read after the refusal hands back nothing.
