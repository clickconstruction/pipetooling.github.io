Server 0.30.0 (0.29.0 was the file verbs alone; both ship here). No migration.

## What changed

- **A file off a mail** (`_shared/devMcpMailFile.ts`): `read_mail_file(account, id, name)` hands one file on a `search_mail` hit back as base64 (10 MB cap; the part's own bytes or `gmailAttachment` under the read-only scope). `plan_mail_file(file)` / `apply_mail_file(file, plan_hash)` take it straight off the mail and file it: `to.kind` `job` POSTs drive-link's `put` as the dev (the Documents tab's own door; `where` top · plans · pictures · sent · photos) after a plan whose hash commits to the job, the landing and the file's sha256, so apply writes only when the file read again is the same bytes to the same place; `person_evidence` and `matter_document` run the evidence and document verbs themselves with the file as `content_base64`, so their plan, hash and refusals are the ones the agent reads. One apply per plan is asked of the log under the outer verb; `view_as` refuses the two writes.
- **A conversation onto a job** (`_shared/devMcpMailTag.ts`): `plan_mail_tag(tag)` / `apply_mail_tag(tag, plan_hash)` run gmail-mine's own `tag` as the login whose box the conversation is in, through a door on that function for the dev seat alone: `as` (the login) and `plan` (the dry run) on a `tag`, let through only with the `X-Dev-Seat` header on a `dev`'s own JWT, for a current login of the Workspace, under the same delegation and the same planner (`planTag`), so every mail lands at its own time, a line the boxes already hold is tied, a mail under a label the person leaves out is skipped, and later mail follows by itself. The plan (`tagPlanPreview` → `MyMailTagPlanOk`) lists each mail as write · tie · skip with why, the counts and the job the conversation was on before; the hash commits to the account, the thread, the job and that list; apply plans again and compares before the real tag. A person's own press carrying `plan` or `as` is refused.
- **gmail-mine**: `USER_COLUMNS` reads `role` and `archived_at`; the seat's branch comes before the person's gates (the office team, `my_mail_on`, the sign-in address, the imitation record), which are the press's own; logs `gmail_mine_seat_tag` and `gmail_mine_tag_plan`.
- **The skill** `.claude/skills/mail-search/SKILL.md` (`/mail-search`): the verbs as a working method, so a session in the repo searches and files mail this way unasked; the seat's README, `EDGE_FUNCTIONS.md` (dev-mcp, gmail-mine) and the server's own instructions carry the same.
