# v2.6364 — Search every file deeply: the index check says which files are in the index and which are not (2026-11-02)

Punch list #240, after the one-time backfill (v2.6343): the owner asked how we track which uploaded files are in the index and which are not, so we know when to index again or index more. A `file_index` row is the record of a file a walk reached, with its reason when it has no text; nothing recorded the files no walk reached (a folder the function could not list, a file deeper than three folders or past 2,000 in one folder, a folder outside the Shared Drive). This adds the record of those: one reconciliation of what the Shared Drive holds against what the index holds. No migration; `drive-link` redeployed.

- **`drive-link` `{ action: 'index_check', max? }`** — the sweep's own lister (`filesChangedSince` from the dawn of the drive, inclusive, folders left out, capped at 10,000 files, `capped` when the drive holds more) against every row (read a thousand at a time, since PostgREST answers at most a thousand a call), reconciled by `_shared/fileIndexCheckKernel.ts` → `{ filesInDrive, capped, rows, filesWithNoRow, rowsWithNoFile, filesChangedSinceRow, rowsWithText, rowsByWhy, missing: [{ id, name, mime, modified }] }`, the first 25 files with no row newest first. A read of Drive and of our table, nothing written; a dev's door (403 for the other roles), so the training-account line PRs 3 and 4 edit stays untouched. Modified times compare as instants (Drive's `Z` against PostgREST's `+00:00`).
- **`scripts/file-index-check.ts`** — `npx vite-node scripts/file-index-check.ts [--list]`: signs in as the dev-login identity (`scripts/lib/paySession.ts`), calls the door and prints one line, *Drive holds 3,010 files; the index holds 2,618 rows: 400 with no row, 3 changed since their row, 8 rows for a file gone. 1,080 with text, 1,538 with none (730 scans, 620 too big, 132 of a kind the index does not read, 54 cut short, 2 failed).*, then whether the index wants a pass; `--list` adds the files with no row by name, which stay on that computer.
- **Tests**: `src/lib/documents/fileIndexCheckKernel.test.ts` (the reconciliation: files with no row, rows for a file gone, changed instants in both spellings, duplicates in a listing, the reasons, the sample's order and cap, the words and the capped words); `driveLink.test.ts` takes the new ask.
