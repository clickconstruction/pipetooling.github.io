# v2.5352 — Messages: texts say when they are paused for the phone balance (2026-10-12)

The owner's ask, part 1 of 2 (kernel and functions), by helper 3, directed by the GC Review lead. Stacked on v2.5281 (#5452, the Quo edge functions), and like them not deployed: the lead deploys `quo-send` and `quo-webhook`. Part 2 is the send window's strip and the line under Settings → Phone and texts → Company phone seats.

- **New `quo/paused.ts`**, with its tests:
  - **`readQuoRefusal`** reads Quo's refusal of a text. Quo documents no refusal for an empty prepaid balance (API version 2026-03-30), so a `402` (Subscription Expired, `0201402`) or a refusal whose words name money reads as paused: `402 paused`, "Texts are paused until the phone balance is topped up." Code `0206400` (A2P registration not approved) is `503 not-registered`, "Texts start once the carriers approve the company number." Code `0204403` (the A2P 10DLC daily cap) is `429 daily-cap`. Anything else stays `502 quo`. Any other `403` is a permission or a setting and never pauses, so the owner is not sent to top up a funded balance.
  - **The row** is `app_settings` `messages_quo_paused_v1`, `{ since, reason, at }`. `since` is the first refused text's time. `at` is the newest deciding text's own time.
  - **`nextPause`** holds the time rule both ways: a word about a text no newer than `at` changes nothing. So a slow take for an older text never ends a newer pause, and a slow refusal never pauses again after a newer text went. A take while nothing is paused writes nothing.
  - **`notePause`** writes over the row as read, through a `PauseStore`, three tries.
  - **`pausedLine`** is part 2's Settings line, "Texts are paused since Wed, Oct 7. Top up the phone balance.", and `QUO_BILLING_URL` is Quo's billing page.
- **`sendText`** (`_shared/quoLines.ts`, the path of `quo-send` and the webhook's HELP answer) logs Quo's status, code and title on a refusal, never its message. A refusal for money pauses texts and a text Quo takes ends the pause (`notePauseRow`: an `app_settings` read, then a write only over the words read). A word not written is logged and never fails the send.
- **`quo-webhook`**: a `message.delivered` ends the pause under the same rule. A failed or undelivered text never pauses: its `errorCode` is the carrier's raw code, and Quo's reference lists none for the balance. The HELP answer is retried only for a refusal not read above.
- **No migration**: the service role writes the row, and every signed-in user already reads `app_settings`.
- **Edge copy**: `scripts/edge-kernels.mjs` adds `quo/paused.ts`, so `quo-send` and `quo-webhook` read as behind on `check:edge-drift` until their deploy.
- **Docs**: `docs/EDGE_FUNCTIONS.md`'s `quo-send` and `quo-webhook` sections.
