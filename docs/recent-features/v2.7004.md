# v2.7004 — First look: the estimate remembers the look it came from (2026-11-12)

Punch list #319, PR 5 of the train.

- **`estimates.first_look_id`** (migration `20261112120000_estimate_first_look.sql`). Start an estimate on a look's card passes the look through `useLookDoors` and `useLeadDoors` to `leadDoorsIo.startEstimate`, which writes it on the new draft. A database from before the column still starts the estimate, without the look. The reply box's own Start an estimate row passes none.
- **The office's editor** mounts `EstimateFirstLookStrip` (`src/components/firstLook/`) under the field photos' strip. It reads the look the estimate remembers and draws its photos, its video in a player, the customer's place and words, and Open in Drive. With no look it draws nothing. It reuses the card's `LookFile`, so a file the browser cannot draw is a named chip with Open.
- **The customer's page.** `get-estimate-for-customer` answers `priced_from_photos`, read in its own small query so no miss there can stop an estimate from opening. `EstimateAccept` shows the owner's call 7 above the estimate: *Priced from your photos. The tech confirms the price at your home before any work starts.* The customer's page never draws the photos.

**Push the migration after the merge, then deploy `get-estimate-for-customer`.** Either order is safe: the function and the client each read without the column.

Not in this PR: the pictures the customer texted in are on the thread's card and not on the estimate's strip.
