## Found on the live pass: every guide-to-guide link was dead

The pointer sentence rendered as a link and did nothing. `helpGuideHtml.ts` runs guide bodies through the contract-signing sanitizer (deliberately untouched — it guards a signing surface), and that sanitizer keeps an `href` only when it is absolute http(s). A link written as `/help/<slug>` came out as a bare `<a>` with no address. **Six guides had been shipping dead cross-links** (`record-sub-labor-on-a-job`, `review-a-collections-account-before-it-goes-to-your-attorney`, `send-a-customer-account-to-your-attorney`, `sub-labor-outstanding`, the lien map, and now this one) — checked live on `record-sub-labor-on-a-job`, whose two links had no `href` either.

The fix follows the file's own pattern for `code`/`pre` tags: `encodeHelpGuideLinks` rewrites `href="/help/<slug>"` and `href="/help?g=<slug>"` to a placeholder https host before sanitizing (only a bare `[a-z0-9-]+` slug qualifies), and `restoreHelpGuideLinks` turns it back into `href="/help?g=<slug>" data-guide="<slug>"` after. The sanitizer is not loosened. `GuideBrowser` catches a click on `a[data-guide]` and opens the guide in place through its existing `openGuide`, so no full reload. Four node tests on the encode/restore pair plus a jsdom twin (`helpGuideHtml.dom.test.ts`) that runs the real DOMParser path and pins the surviving href.
