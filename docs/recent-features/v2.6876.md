# v2.6876 — An estimate's customer preview: Back no longer lands on a blank page (2026-11-10)

v2.6868 found that `/b` and `/b/:code` are `lazy()` routes with no `<Suspense>` above them, and that a press from one to the other blanked the page. This is the audit of the rest of the routes outside the Layout in `src/App.tsx`, from `/sign-in` down to the Layout route, and the one more route it found.

## The audit

Five routes in that block are `lazy()`. Every other one (`/sign-in`, `/dev-login`, `/reset-password`, `/reset-password-confirm`, `/accept-invite`, `/task`, `/estimate/accept`, `/e/:code`, `/bid-room`, `/submittal`, `/q/:token`, `/contract/accept`, `/contract/sign`, `/estimate/terms`, `/hazmat-notice`, `/portal`, `/p/:slug`, `/sub`, `/pay/:id`, `/rate`, `/s/:slug`, `/legal`, `/ask`, `/legal/confirm`, `/files/:source/:id`, `/contract/book-preview`) is a plain import in the main bundle. It never suspends, so no press, `<Navigate>` or Back onto it can blank the page. The one lazy piece inside those pages, the rules sheet on `/legal`, has its own `<Suspense>`.

| Route | Lazy component | Boundary before | Verdict |
|---|---|---|---|
| `/b/:code` | `BoxCode` | none | At risk. Fixed by v2.6868. |
| `/b` | `BoxScan` | none | At risk. Fixed by v2.6868. |
| `/t/:token` | `GcTradePortal` | its own | Safe. |
| `/f/:link` | `FileLinkPage` | its own | Safe. |
| `/estimate/customer-accept-preview/:id` | `EstimateAcceptStaffPreview` | none | At risk by Back. Fixed here. |

The presses that leave a public page go to `/sign-in`, `/legal`, `/s/:slug` (all plain imports) or into the Layout (`/`, `/dashboard`, `/people`, `/tally`, `/estimates`), whose pages are lazy under the Layout's own `<Suspense>`. None of them can blank.

## A second way in: Back

No `<Link>` or `navigate(...)` opens the staff preview. The Estimates page opens it with `window.open` in a new tab, which is a fresh load, and a fresh load may suspend at the root. So it looked safe by the first rule.

It was not. React gives a `popstate` the same priority as a click, so Back or Forward onto a lazy route whose chunk this document has not loaded suspends in a synchronous update, exactly as a press does. The chunk is unloaded whenever the page reloaded since the route was last drawn, which on a phone includes the browser dropping the tab in the background.

Reproduced on a dev server at 375 wide, before the change:

- Signed out, on main without v2.6868: `/b`, press **Sign in**, reload, Back. Blank page, *A component suspended while responding to synchronous input*.
- Signed in: `/estimate/customer-accept-preview/zz` (a made-up address, which reads no estimate and shows *Invalid estimate.*), press **← Estimates**, reload, Back. Blank page, the same error.

## What changed

`src/App.tsx`: the staff preview's route wraps `EstimateAcceptStaffPreview` in `<Suspense fallback={null}>` inside its `ProtectedRoute`, as `/t/:token` and `/f/:link` do. `main.tsx` keeps `v7_startTransition: false`.

## Walked

The second walk above again after the change, in one document (a mark set on `window` before Back was still there after it): the preview drew *Invalid estimate.* and its **← Estimates** link.
