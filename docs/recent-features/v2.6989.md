# v2.6989 — Permits: the county's own address for the lot, when it is not the permit's (2026-11-11)

Punch list #320, PR 5 of the card's list. Since v2.6974 an Austin permit's owner comes from the lot the permit names. A big lot holds many addresses, so the lot's owner can be a centre's or a campus's, filed under a number the permit does not carry. The card showed the owner and nothing that said so.

- **Kernel**: `sameStreetAddress(permitAddress, countyAddress)` in `_shared/permitParcels.ts`. The same house number and the same street name in any spelling. The county writes the suffix, the city and the zip behind the name, with or without a comma or a line break, so two names match when one starts the other on a whole word. A blank or numberless county address is never the same.
- **Words** (`parcelPointWords` in `permitCityDoors.ts`, which now takes the permit's address): found by the permit's own id on a lot whose county address is another one, the sheets say *The county calls this lot …*. With a lot over the county line it follows *This lot is in Williamson County.* Found by the street address or at the point, nothing changes.
- **Callers**: `PermitBuildingSheet` and `WhoPulledItSheet` pass the permit's address. The skim card's lot line is unchanged.

Measured on 350 Austin commercial addresses through the kernel: of 308 answered by the id, the county's address is the permit's on 193 and another on 115, so the line shows on about 4 cards in 10. As a check, all 186 answers by the street address read as the same address. A first cut read 11 of them as another, because Travis writes the city with no comma ("… LN AUSTIN 78701"); the whole-word rule is the fix.

Tests: `permitParcels.test.ts` (each county's way of writing an address, another number, another street, a blank), `permitCityDoors.test.ts` (the line, and each case with no line).

Deploy: none needed for the cards. The kernel sits in a file `permit-lookup` and `permit-pull` bundle, so `check:edge-drift` names both after the merge; they run the same code.
