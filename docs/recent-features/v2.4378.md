# v2.4378 — CI catches a window that closes on the press (2026-10-02)

No migration, no edge function, nothing a user sees. Grace asked for it on 2026-10-02 so the rule from [v2.4347](v2.4347.md) holds: a window closes on a click outside it only when the press and the release are both outside it. [v2.4370](v2.4370.md) fixed the one window that slipped back in — it was merged while the sweep was in review.

## What changed

- **`--check` on the sweep's codemod** ([`backdrop-click-sweep.mjs`](../../scripts/codemods/backdrop-click-sweep.mjs)): the same TypeScript-parser scan as `--dry`, and it exits 1 when any backdrop still closes on the press (an `onMouseDown` handler that closes only when `e.target === e.currentTarget`), naming each file and line and the fix — run the codemod without a flag, which renames the handler to `onClick`. In GitHub Actions each finding is also an `::error` annotation on the line. `npm run check:backdrop-click`.
- **A step in both checks jobs** — [`ci.yml`](../../.github/workflows/ci.yml) and [`deploy.yml`](../../.github/workflows/deploy.yml), after the nested-windows step, as the workflow parity check requires: *Windows close on a click outside, not on the press*.
- **A window meant to close on the press can say so**: a `backdrop-click: allow — <why>` comment up to two lines above the element or inside its opening tag lets it through (the run lists it); a bare note with no reason does not count. The codemod skips an allowed window too.
- `docs/AI_CONTEXT.md` → Windows (modals) names the check.
