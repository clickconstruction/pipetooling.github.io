# v2.2963 — Jobs → Subs: the four Work tiles open queues, and both toolbars ride the Work / Pay row (2026-09-06)

Follow-up to the three-party scheduling train (v2.2927–v2.2934). Owner's ask, in order: the Pay toolbar to the right of the Work / Pay control; the Work toolbar (+ New work order, search, rail-group chips) likewise; then "the four modals could be a little more actionable" — each tile becomes a queue the office clears from inside the modal. Client only; no migration, no edge function. **Every write a queue performs is one the board already performs** (assembler send, withdraw, nudge, signed on paper, stage-window upsert, GC-ask answer, sheet stage, Bill Customer, Make Payment) — the queues add no write path.

## Toolbars on the Work / Pay row

- [`JobsSubsTab.tsx`](../../src/components/jobs/JobsSubsTab.tsx) takes `workToolbar` / `payToolbar` slots and draws the active view's after the segmented control (the hint moves to the end of the row). A Pay-only viewer (superintendent) still gets the row with just the toolbar.
- Pay: [`JobsSubLaborTab.tsx`](../../src/components/jobs/JobsSubLaborTab.tsx) exports `SubLaborToolbar` (New Sub Labor + search) and takes `hideToolbar`; `Jobs.tsx` mounts the toolbar in the slot. The "Sub Labor Due" total stays on the view's own header, right-aligned.
- Work: [`JobsSubsWorkView.tsx`](../../src/components/jobs/JobsSubsWorkView.tsx) keeps its filter / search / assembler state and renders the toolbar through a **React portal** into a `display: contents` host `Jobs.tsx` places in the slot (`toolbarHost` prop: `undefined` = inline as before, `null` = host mounting, element = portal).

## The tiles as queues (`src/components/jobs/subsTiles/`)

- Kernel [`src/lib/subs/subsTileQueues.ts`](../../src/lib/subs/subsTileQueues.ts) (+12 tests): `buildHandshakeQueue` (no-agreement rows, most money first, unpriced last, `daysWorking`, `needsJob`), `quickOfferDefaults` / `quickOfferProblem` (window from the sheet date, ten weekdays past today, good for 7 days, price = sheet total; the one sentence stopping a send), `buildStagesQueue` (stage rows grouped passed → open → ahead → no dates, `askOpen`, a `suggestedSpan` for a passed window), `buildOffersQueue` (sent offers, expired first, `daysOut` / `daysLeft`), `buildSignedQueue` / `signedNextKind` (the office's move read off the rail: `inspection` / `bill` / `pay` / `wait_sub` / `done`; office rows first) + `monthOf` / `shiftMonth` / `monthName` / `signedCountForMonth`, and `subAvailabilityForSpan` / `availabilityTone` / `availabilityLabel` (other live orders and off days across a span — the dispatch lanes' data).
- Send helper [`src/lib/subWorkOrders/quickSendWorkOrder.ts`](../../src/lib/subWorkOrders/quickSendWorkOrder.ts): the assembler's step-3 defaults as a function — trade library default scope lines, sub book documents, pay-run day, issuer, the sub's COI / MSA, `next_work_order_record_id`, one insert (or one update for a re-send, keeping the WO number), the same `notifySheetWorkOrderOffered`. Returns `needsAssembler` when the trade has no default lines. `roleTitle` moved here and the assembler imports it; the two paths carry a "keep in step" comment.
- Shell [`SubsTileModal.tsx`](../../src/components/jobs/subsTiles/SubsTileModal.tsx): title = the tile's words, the number large at right, a **queue bar** (`N of M handled`), the rows, the counting rule + footer buttons. Escape / ✕ / backdrop close (ignored while the assembler or the inspection modal sits above). [`useQueueState`](../../src/components/jobs/subsTiles/useQueueState.ts): open row, handled marks with Undo, a snapshot at open so a row that leaves the tile's filter on reload still shows as handled (green, sunk), `next()`.
- **HandshakeQueue** — the open row is a mini order (job picker when `needsJob`, price, window from / to, takes about, good for); Send / **Link and send** (links the sheet quietly first); Undo = withdraw; **Send the rest as drafted · N** (one confirm). Multi-name sheets and orders without a sheet fall back to the assembler.
- **StagesQueue** — the sub picker with availability chips (`fetchSubOrdersForRange` + `fetchSubOffDaysForRange`, today −30 … +180, loaded when the modal opens), benched subs behind **+ N on the bench**, window inputs (pre-moved for a passed window → **Move window and send offer**, which upserts the window first), price from the line item; **Accept …** / **Answer with…** (dates + why → `answerGcAsk`) on an open GC ask; **Crew does this one** → `removeWindow`.
- **OffersQueue** — expired first; **Re-send** form (good for · price · window · takes about) via the helper's `existingId`; **Offer someone else…** (confirm → quiet withdraw → assembler pre-filled); live rows: **Nudge**, **Extend +7 days** (new `extendOffer`: `offer_expires_at` + N from its current end or today), **Withdraw**, **Signed on paper**; "seen" from `useSubPortalVisitSummaries` (enabled while the queue is open); phone on the row; footer **Nudge everyone unopened · N**.
- **SignedQueue** — keyed by month (re-mounts on ‹ / ›); per row: record, portal / on paper (`signer_signature_mode`), their pick or the proposed span, the rail's label; Next: **Schedule inspection…** (`AddInspectionModal`, now mounted by the Work view) + **Passed → bill** (`onSetSheetStage(sheetId, 'customer_pay')`, Undo = back to `walkthrough`), **Bill <customer>** (`useBillCustomerModal` with `jobBillingContextFromJob`, refuses without a billing customer), **Pay <sub> · $open** (`onOpenMakePayment`), or the chip *Waiting on the sub* / *Nothing — done*. Month counts read board rows only (paid-up sheets with no open money have left the board — same rule as the tile).
- Work view: the tiles are buttons with a door line ("Get it in writing ›" …); roster select adds `email, phone, end_date` (contacts + bench); `saveWindow` returns a boolean; new quiet writes `withdrawQuiet`, `extendOffer`, `linkSheetToJobQuiet`, `billCustomerForJob`. `Jobs.tsx` passes `onSetSheetStage={setLaborJobStage}` and `onOpenMakePayment` (the page's payment modals ref).

## Compact board prototype (dev only)

The owner asked for the three column merges as a prototype on real data before deciding. The Work toolbar gains a **Classic | Compact · prototype** switch for the `dev` role (`canPrototype` prop from `Jobs.tsx`; the choice is a per-viewer `localStorage` convenience). Compact renders the same groups in four columns:

- **Window** — [`WindowTextCell.tsx`](../../src/components/jobs/WindowTextCell.tsx): the dates as text (a dotted-underlined link that opens the row's details; the calendar modal in the next PR) with the GC's chip beside them (`WindowGcChip`: grey *GC off* when the job does not share stage dates, dashed *Offer to GC ›* which offers after one confirm, teal *On ‹GC›'s portal ›* and amber *GC asked ›* which open the details), and one line beneath — "set by the office · Change", "picked Sep 9 – 10" in green, "as ‹GC› asked", "· passed" in grey. An open GC ask strikes our dates through (they are the ones being replaced), puts their dates with **Accept** and **Answer…** on line 2, and their reason in italics on line 3. Rows with no window keep "Set a window…" beside the chip. A time-track version was prototyped and rejected (dates in a header axis read as clutter; text is exact and narrow).
- **The stage calendar** — clicking the dates (or the *On ‹GC›'s portal ›* / *GC asked ›* chip) opens [`StageCalendarModal.tsx`](../../src/components/jobs/StageCalendarModal.tsx): the months the window, pick and ask touch (kernel [`src/lib/subs/stageCalendar.ts`](../../src/lib/subs/stageCalendar.ts) +tests: `calendarMonthsFor`, `calendarDays` — Monday-first, 35 or 42 cells, per-day flags for window / passed / pick / ask / today / off / sibling / siblingPick — `workingDaysIn`), weekends dimmed, our window a light fill, the pick a solid bar, the GC ask a dashed ring, today outlined, the sub's off days hatched (`person_availability`, loaded when the calendar opens), the job's other stages as thin marks. The side panel: our window + *Change our window…* (opens the row's inline editor), the GC's ask + **Accept** / **Answer with…** (the propose form renders inside the panel), the GC portal state + *Offer to ‹GC›* / *Take it off their portal*, the sub's line (offer out since · signed · pick · off days), and the stages on the job with the current one bold. Looking on the calendar, acting on the buttons — no click-a-day writes.
- **Agreed · Paid · Open** — the stacked money column.
- **Where it stands → next** — [`StandingMoveCell.tsx`](../../src/components/jobs/StandingMoveCell.tsx): the rail (or a stage row's one-line standing), an arrow, and the move from [`src/lib/subs/standingMove.ts`](../../src/lib/subs/standingMove.ts) (+tests): `standingMovesForRow` reads the coverage and the rail's current dot → one primary in its tone (blue normal, amber lapsed, green money, quiet text when the sub owns the step) and a second only at Pre-inspection (`Schedule inspection…` + `Passed → bill`); a ⋯ `MoreMenu` holds what the actions column held. Every move calls the board's existing handler (assembler, nudge, Add Inspection, sheet stage, Bill Customer, Make Payment).
- Narrow screens keep the classic cards. Classic stays the default; nothing changes for other roles.

Deliberately not built: "Not a sub — crew pay" on a handshake row (needs a per-sheet flag, i.e. a migration); an inspection form with city / date / who meets (the existing Add Inspection modal is the write path); Print all (browsers block stacked popups). Text vs email channel switches from the mock-up were dropped — the offer notice has one channel.
