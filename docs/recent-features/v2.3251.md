# v2.3251 — Bids on a map: hovering a bid row pulses its pin (2026-09-10)

Client only — no migration, no edge function. The second half of the v2.3162 map-to-row link. Clicking a pin already lights the row on the board; now hovering a row on the desktop board rings the row's pin on the map, so the eye can go list → map as well as map → list.

## What shipped

- **Row hover → pin halo.** `BidsBidBoardTab`'s desktop table rows set the hovered bid id on `mouseenter` and clear it on `mouseleave`. The map card rings that bid's pin with a halo in the pin's own section color: on the Leaflet canvas a `CircleMarker` with class `pins-map-pulse-halo`, animated by CSS (stroke swells from 3 px to 16 px and fades, 1.1 s, repeating; `prefers-reduced-motion` gets a steady 5 px ring instead); on the Google canvas a steady wide circle symbol, since Symbol markers cannot animate. Phone cards do nothing — there is no hover on a phone, and the phone form passes `pulseId = null`.
- **A pin inside a cluster pulses the cluster disc** (v2.3213 clustering on): the halo sits on the disc at the disc's radius, so the row still points at something on the map. A hovered bid whose pin is hidden by a section chip, or off the map for want of an address, draws nothing.
- **No board re-render on hover.** The hovered id lives in [`bidBoardHoverStore.ts`](../../src/lib/bids/bidBoardHoverStore.ts) — a 20-line external store the rows write into and only the map card reads (`useSyncExternalStore`). Keeping it in the tab's React state would have re-rendered every row on each mouse move across a 300-row board. The store is created once per tab mount and handed to the card as `hoverStore`; the Dashboard card, which shares the canvases, passes nothing and is unchanged.
- **Kernel [`pulseTarget.ts`](../../src/lib/map/pulseTarget.ts)** (5 tests): given the pins, the clustered items when clustering is on, and the pulsed id → the halo's position, color, radius (pin radius + 6 px, or the cluster disc + 6 px) and the mark it rings, or null. Both canvases call it; `mapCanvasTypes` gains nothing — `pulseId` is a canvas prop, not a pin field.

## Tests
