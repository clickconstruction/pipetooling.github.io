# v2.6639 — The dev sign-in door opens a dev or a digital twin and no one else (2026-11-07)

Edge function `dev-login` (`docs/EDGE_FUNCTIONS.md` → dev-login); no migration, no client change. Found while closing punch list #239: a session needed a Workspace login's My email press and read the door. `dev-login` took a secret and any address and minted a magic link; `login-as-user` records every imitation in `user_imitations` before its link exists so that `gmail-mine` refuses the session (v2.6290), but a dev-login link was never on that record. A session minted as a teammate would have passed `gmail-mine`'s check and read that teammate's Gmail through the app. The session declined to use it and put the gap on a card; the owner said to close it here.

## Change

- **`_shared/devLoginGate.ts`** (pure, no imports; `src/lib/devLoginGate.test.ts`): `devLoginMayMint(account)` admits `users.role = 'dev'` or `is_digital_twin = true`, the two kinds of account the door was written for (`src/pages/DevLogin.tsx`'s fixed identity and its `?as=twin:<role>` alias, `scripts/dev-pane-login.mjs`); `DEV_LOGIN_NOT_FOR_THEM` names View as as the door for anyone else.
- **`dev-login/index.ts`**: after the auth account is found, its `users` row is read as the service role; a read that fails answers 500 and mints nothing, and an account the gate refuses answers 403 with the words. The link is minted only past both.
- Holding the door was picked over recording an imitation on every mint: a record would have marked the dev's own sessions as imitations for a day, and the door has no caller to put in `operator_id`.
