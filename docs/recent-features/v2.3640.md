# v2.3640 — MCP servers, PR 4b-1: dev-mcp — a dev's agent reads the app as the dev, GET-only (2026-09-20)

PR 4b-1 of [`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md): the server, its keys, its call log and the generic read door. The resolvers, `get_job` / `get_customer` / `get_bid` and `view_as` are 4b-2.

## The owner's three calls this builds

Reads **as the dev**, not the service role · the generic door first-class · the audience is a dev's agent in Claude Code.

## The change

- **`supabase/functions/dev-mcp/index.ts`** (new; `verify_jwt = false`): key → active `dev` (re-checked every call) → that person's own session minted in-function (`generateLink` + `verifyOtp`, in-memory per warm instance, nothing stored) → **`GET /rest/v1/…` as them**. PostgREST runs GET in a read-only transaction, so the *database* refuses writes (`25006` is turned into plain words); RLS and `auth.uid()` checks apply as on the screen. Six verbs: `whoami`, `find_rpc`, `find_table`, `get_table`, `call_read`, `read_rows`.
- **`_shared/devMcpDoor.ts`** (new kernel, 11 tests in `src/lib/devMcp/`): identifiers, RPC args → query string (arrays as Postgres literals, objects as JSON, nulls omitted), table reads (`select` / ten filter ops / order / limit 1–200, every column checked against the catalog), five never-read credential tables, **secret redaction at any depth** (`token`, `secret`, `password`, `api_key`, `hash` — the catalog has 26 such columns, portal and public tokens among them; `…_token_expires_at` is left alone), a filter on a secret column refused so redaction cannot be turned into an oracle, request ≤ 6,000 URL chars, reply cut at 80,000.
- **`_shared/mcpJsonRpc.ts`** (new): the stateless JSON-RPC shell twin-mcp has carried inline since v2.2431, lifted for the second server; twin-mcp adopts it when it is decomposed.
- **`dev-mcp/catalog.ts`** (generated, 181 KB: 400 tables/views, 519 RPCs) by **`scripts/build-dev-mcp-catalog.mjs`** — the TypeScript AST of `src/types/database.ts`, overloads kept; `--check` mode, and `devMcpCatalog.test.ts` fails CI when a types regeneration forgets it.
- **Migration `20260920063130_dev_mcp_keys_and_calls.sql`**: `dev_mcp_credentials` (a dev inserts **only their own**: `is_dev() AND user_id = auth.uid()`) and `dev_mcp_calls` (devs read; service role writes); three fence appliers.
- **Settings → System → Digital twins → Dev MCP keys** (`DevMcpKeysCard.tsx`, dev-only; kernel `src/lib/devMcp/devMcpKeys.ts` +3 tests; 2 render smokes): issue a `ptd_…` key per machine — generated in the browser, sha256 stored, shown once with its `export PT_DEV_MCP_TOKEN='…'` line — and revoke by label. Before the migration is pushed the card reads "not switched on yet".
- **`/dev`** on the `mcp-router` Worker; **`.mcp.json`** registers `dev-mcp` with `${PT_DEV_MCP_TOKEN}`.
- Docs: `docs/dev-mcp/README.md` (new), `EDGE_FUNCTIONS.md` → dev-mcp (+ TOC), `ACCESS_CONTROL.md`, `GLOSSARY.md`, the migration fragment, help guide *connect my coding agent to PipeTooling*.
