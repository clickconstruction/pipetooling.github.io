# v2.5954 — A check that keeps evening times on the right day (2026-10-26)

What is left of this PR after v2.5949 (#6271) landed first. It was cut to fix `src/lib/arCustomerChase.ts`'s `touchYmd`, which read a chase touch's UTC day (`/^(\d{4}-\d{2}-\d{2})/.exec(t.createdAt)`) against Chicago's `todayYmd`. #6271 shipped the same fix while this sat in the queue, and more besides: a bare `YYYY-MM-DD` keeps its own day, and the newest touch is the latest instant. The merge takes main's file and main's tests whole.

- **`check:timezone` rule 6** (`scripts/check-app-calendar-tz.mjs`): no stored instant's day read off its UTC prefix with a regex. The lean read (v2.5940) and the AR chase (v2.5949) were that spelling. It flagged one more copy, below, and nothing else. `docs/TIME_AND_ZONES.md`'s rules sentence names it.
- **`convertBillToStripe.ts`**: `convertDueDateYmd` read a `billed_at` timestamptz the same way. The convert modal already passes a Chicago day and never calls it, so nothing shipped wrong. It now dates a timestamp on Chicago's calendar and keeps a bare `YYYY-MM-DD` as is; `convertBillToStripe.test.ts` gains the evening case (01:30 UTC on Jul 7 is Jul 6) and the bare date.

The `.slice(0, 10)` spelling of the same bug is v2.5956's sweep (#6277), and its rule follows once `notify-lien-approval` is fixed.

No migration, no edge function.
