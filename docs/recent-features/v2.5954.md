# v2.5954 — An evening call reads as today, not tomorrow (2026-10-26)

The rest of v2.5940's fix. v2.5940 put `leanRead.ts`'s `touchYmd` on Chicago's calendar, but `src/lib/arCustomerChase.ts` kept its own copy of the same function — `/^(\d{4}-\d{2}-\d{2})/.exec(t.createdAt)`, the touch's UTC day — compared with `todayYmd`, which is Chicago's. From 7 PM to midnight Chicago (5 PM in winter) every call of the evening read as tomorrow and every older call's age read one day short, in four places: `arLastTouchLine` (*couldn't reach · Oct 27 · Marisol* for an Oct 26 call — the Dashboard's AR call card and the lean read's last-touch line both draw it), the *Touched* quiet pill, and the *can't reach* snooze's window and *back in Nd* count (one day long). It now reads the touch's day with `calendarYmdInAppTzFromIso`.

- **`convertBillToStripe.ts`**: `convertDueDateYmd` read a `billed_at` timestamptz the same way. The convert modal already passes a Chicago day and does not call it, so nothing shipped wrong; it now dates a timestamp on Chicago's calendar and keeps a bare `YYYY-MM-DD` as is.
- **Guard**: `npm run check:timezone` gains rule 6 — no stored instant's day read off its UTC prefix with a regex — which flagged the two copies above and nothing else (`docs/TIME_AND_ZONES.md`).
- **Tests**: `arCustomerChase.test.ts` +2 pinned at 8:30 PM Chicago (01:30 UTC the next day: the line reads *today*, an evening five Chicago days back reads *5d ago*, the pill reads *Touched Sep 1*, the snooze *back in 7d*) — both fail on the old code; `convertBillToStripe.test.ts` +2 cases. They and the lean read's tests pass under `TZ=UTC` and `TZ=America/Chicago`.

Not swept: 49 `*At` / `_at` timestamps read with `.slice(0, 10)` across 31 files (the people money ledger, the lien timeline, `notify-lien-approval`, Collect, GC IO, …) — the same bug class in a different spelling; each needs its own look, so it stays out of this fix.

No migration, no edge function.
