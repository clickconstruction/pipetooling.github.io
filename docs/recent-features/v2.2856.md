# v2.2856 — "Resend link" on a sent estimate: a fresh link goes out and can be copied once; the tooltip stops promising an admin who can't (2026-09-05)

Journey-map Phase 4, Tier-2 #35 (J17-F2 "lost-link recovery is self-contradictory", J17-N3 "the accept link lives only in the sending tab"). Client + edge function `send-estimate-to-customer`; **no migration**. Deploy after merge: `supabase functions deploy send-estimate-to-customer`.

## Mechanism

**Before.** The tokened accept URL (`/estimate/accept?t=<64-hex>`) was minted once by `send-estimate-to-customer`, returned to the sending tab, and kept only in that tab's `sessionStorage` (`estimate_accept_url:<id>`). The DB stores `public_token_hash` (SHA-256) — never the raw token — so no server-side path could recover it. The sent detail's Copy / Open customer link buttons were disabled in every other browser with a tooltip ending "…or ask an admin to resend", while the edge function rejected any non-draft (`Only draft estimates can be sent`) and the client gated `sendToCustomer` on `status === 'draft'`. Nobody could resend. The only recovery was a treasure hunt — expand Customer experience → Email — because the stored `customer_experience_sent.emailBody` is saved post-substitution and carries the URL; and if an org's template omits `{{accept_url}}`, even that is gone (N3).

**After — one shared kernel.** [`supabase/functions/_shared/estimateLinkResend.ts`](../../supabase/functions/_shared/estimateLinkResend.ts) (Deno-free; the client imports it directly, like `paidJobBillGuard`):

- `canResendEstimateLink(status, sentAt, now, { validUntil, inBidRoom })` → `{ ok: true } | { ok: false, reason }`. Only `sent` rows with a `sent_at` pass; refused with a named reason for `draft | accepted | declined | superseded | never_sent | bid_room | unknown_status`, and `pricing_expired` when `valid_until` is before today in `APP_CALENDAR_TZ` (the accept page would 410 — "start a new estimate" is the honest answer). **Token expiry is not a blocker**: an expired 14-day token is exactly what a resend fixes.
- `estimateLinkResendBlockMessage(reason)` — one office-worded sentence per reason, used by the edge function's 400 and the panel.
- `rewriteEstimateAcceptUrl(body, newUrl)` — swaps every `<origin>/estimate/accept?t=<token>` in the stored email body for the new URL. Without it the Letterhead builder would keep the paragraph holding the dead link (it only drops the paragraph containing the *current* URL).
- `customerLinkUnavailableTitle(resendAvailable)` — the corrected tooltip.

**Edge function** ([`send-estimate-to-customer`](../../supabase/functions/send-estimate-to-customer/index.ts)): body gains `mode?: 'send' | 'resend'`. In `resend` mode the select adds `sent_at, customer_email, bid_room_id, customer_experience_sent`; the kernel gates (400 `{ error, code }` on refusal); `customer_email` is optional (defaults to the row's; a supplied one replaces it). A fresh 32-byte token is minted and hashed exactly as on a first send; the email is built by the same `buildEstimateLetterheadEmail` from the **stored snapshot** (parsed with `parseEstimateCustomerExperienceSnapshot`, `emailBody` rewritten) — never re-resolved from today's templates, so the customer sees the copy they already saw; rows without a parseable snapshot fall back to resolving from current settings like a first send. The UPDATE writes only `public_token_hash`, `public_token_expires_at` (now + 14 d), `customer_email`, and the re-saved `customer_experience_sent` (so the on-page Email snapshot shows the live URL), gated `.eq('status','sent')`. **Overwriting the hash is what retires the old link** — `get-estimate-for-customer` looks up by hash and 404s it. Untouched: `status`, `sent_at` (Tier-2 #34's "sent N d ago" chip keeps counting from the first send — the customer has been waiting that long), line items, terms, total, attachment. Response adds `resent: boolean` and `sent_to`. No `resent_at`/`resend_count` column exists and `estimate_customer_events.event_type` is CHECK-constrained to the three customer events, so no DB stamp is written (a migration was out of scope by design).

**Client** ([`Estimates.tsx`](../../src/pages/Estimates.tsx) detail): `resendVerdict` memo runs the kernel on the row; `resendCustomerLink()` POSTs `{ mode: 'resend', estimate_id, public_origin }`, then stores the new URL in state + `sessionStorage` (so the existing Copy / Open customer link buttons light up in this tab), sets `resentInfo`, toasts **"Link resent to <email>."** (or "New link ready — email did not go out" when Resend is unconfigured/failed), records telemetry, reloads. `resentInfo` clears when the row changes. The "Waiting for customer… (or ask an admin to resend)" paragraph is replaced by [`EstimateResendLinkPanel`](../../src/components/estimates/EstimateResendLinkPanel.tsx): names the address the link went to; **Resend link** when the verdict is ok; otherwise the reason sentence (+ "Use New estimate at the top of the Estimates page." for `pricing_expired` / `declined`); after a resend, a `role="status"` box with the URL in a `<code>` and **Copy link** — shown once, this tab only. Bid-room change orders keep their existing "signed in the bid room" sentence. [`EstimateCustomerAcceptLinkButtons`](../../src/components/estimates/EstimateCustomerAcceptLinkButtons.tsx) gains `resendAvailable` and both disabled-state tooltips now read from `customerLinkUnavailableTitle` (accepted rows: "…this estimate is past resending").

**Telemetry.** One [`ui_nav_clicks`](../../src/lib/navClickTelemetry.ts) row per successful resend: `control = 'estimate_link_resent'`, `target = '#emailed' | '#link-only'`, `role`, `from_path`. A steady stream of `#link-only` means Resend's API key is missing; a high resend rate per estimate is a delivery-problem signal worth reading against `email_send_log`.

**Security note.** The one-time on-screen URL is the fresh token the staff member just minted, shown to the authenticated office user who asked for it, in their tab only — the same exposure as the first send's `accept_url` response (and less than the pre-v2.2747 snapshot, which rendered the live URL to anyone opening the detail). The old token is dead the moment the new one exists.

## Tests

- `src/lib/estimateLinkResend.test.ts` — kernel: sent+sent_at ok; token expiry ignored; `valid_until` today ok / yesterday `pricing_expired`, compared on the Central civil day (11 PM Central Sep 4 with good-through Sep 4 still ok); malformed `valid_until` ignored; every non-sent status → its reason; missing/garbage `sent_at` → `never_sent`; bid room → `bid_room`; one distinct sentence per reason; `rewriteEstimateAcceptUrl` swaps both stored occurrences, handles other origins / encoded tokens / punctuation, leaves URL-less bodies and other app links alone.
- `src/components/estimates/EstimateResendLinkPanel.render.test.tsx` (jsdom) — button present + fires on an ok verdict; disabled "Resending…" while busy; `pricing_expired` hides the button and shows the good-through sentence + New estimate nudge; the one-time URL box with Copy after a resend; the "did not go out" wording; the tooltip never says "admin".

## Verify

1. Open a **sent** estimate in a browser that did not send it (or a fresh tab). Copy / Open customer link are disabled; hover — the tooltip names the tab-only storage and points at Resend link. Under Customer activity: "Waiting for customer. The link went to <email>." + **Resend link**.
2. Press Resend link. Toast "Link resent to <email>."; the box shows the new URL once with Copy link; Copy / Open customer link are now enabled in this tab. The customer's inbox has a second copy of the same letter whose button opens the accept page.
3. Open the **old** link from the first email → "Not available" (404 from `get-estimate-for-customer`). The new link opens.
4. Set an estimate's Expires on to yesterday (or pick one already past): no Resend button; the sentence names the good-through date and points at New estimate.
5. An accepted estimate: no Resend; the Customer experience section's Copy/Open tooltip reads "…past resending".
6. `select target, count(*) from ui_nav_clicks where control = 'estimate_link_resent' group by 1`.

## Rollback

Revert the PR and redeploy `send-estimate-to-customer` from the previous main — the function ignores an unknown `mode` (treats every call as a first send, refusing non-drafts as before), so an old function behind a new client simply returns "Only draft estimates can be sent" to the Resend button; a new function behind an old client changes nothing (the old client never sends `mode`). Links minted by a resend keep working after rollback: they are ordinary hash-stored tokens.
