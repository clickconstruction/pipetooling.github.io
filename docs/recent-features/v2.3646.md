# v2.3646 — MCP servers, PR 4b-2b: dev-mcp's named verbs — find_*, get_job / get_customer / get_bid, view_as (2026-09-20)

Second half of PR 4b-2 of [`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md); v2.3645 lifted the parts-cost math this builds on. `dev-mcp` goes to 0.2.0 with eight more verbs. The keyed path of 0.1.0 was verified live the same day (the `bump_user_app_activity` probe: the **database** answers `cannot execute INSERT in a read-only transaction`, the row identical before and after).

## The change

- **`_shared/devMcpComposites.ts`** (new): `findJob` / `findBid` (the app's own search RPCs, labelled through the `ledgerDisplayPrefixes` mirror that already lived in `_shared`), `findCustomer`, `findPerson`; `getJob`, `getCustomer`, `getBid`. Written against an injected **`Reader`** (`rpc`, `rows`) — no network in the file. Money comes from the screens' kernels, never restated: `get_job` → `jobMaterialsCostLines` + `jobSubLaborInputs` + `buildJobProfitSummary` + `profileJobRowMoney`; `get_customer` → `customerMoneyStats` / `customerDaysToPay` / `customerEstimateOutcomes`; `get_bid.totals` is a sentence saying the priced total lives in `useBidPricingEngine`. A part that fails is `{ error }` in place; a failed cost source takes `money` only. A text ref resolves when it matches exactly one; several come back as ids to choose from.
- **`_shared/jobSubLaborInputs.ts`** (new, +2 tests): the assembly `useJobDetailSubLaborCost` did inline (items by sheet, the two drive settings and their 0.7 / 0.02 defaults); the hook now calls it.
- **`dev-mcp/index.ts`**: `callTool` becomes `resolveDev` → `runVerb(identity, lazy session, verb, args)`; `readerAs(jwt)` applies the generic door's catalog, denied-table, query and redaction rules to every composite read; **`view_as(role | user, verb, args?)`** mints the target's session the same way (a role's `is_sample` account, or a user id), refuses a `dev` or archived target, logs `as_user_id`, and heads the reply `// read as …`.
- **Tests** (`src/lib/devMcp/devMcpComposites.test.ts`, 6): the fake reader **enforces the generated catalog and the door's rules** — an unknown RPC, argument, table, filter / order / plain select column fails the test — so every read a composite makes is one the live door accepts. It caught five guessed column names before they shipped. Also: the money equals the kernels over the rows, `jobNumberOf` agrees with the app's `effectiveJobLedgerNumber`, partial failure, the several-matches refusal.
- Docs: `docs/dev-mcp/README.md` (verbs, where the money comes from, extending), `EDGE_FUNCTIONS.md` → dev-mcp, the to-do.

A misstep recorded: a `git mv` of `src/lib/ledgerDisplayPrefixes.ts` failed (a smaller mirror already exists in `_shared`) and the next line of the same command overwrote the app's file with a stub; restored from git at once, nothing committed. The composites use the existing mirror.

## Deploy

`supabase functions deploy dev-mcp`. No migration, no Worker change.
