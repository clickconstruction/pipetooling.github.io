## Decisions

- **Print saves.** A paper handed to a worker to sign should name its record, so Print writes the row (or moves a draft to printed) before the page opens; a second Print updates the same row. Nothing is filed: the signed copy is filed where it is sent for signature, from PR 3.
- **The snapshot is the record.** A row keeps the read as it stood, so the list prints a statement again exactly as it was even after a session is edited or approved; Open re-reads live and Save replaces the snapshot while the row is still a draft or printed.
- **The id is the job's count.** `HS-1042-0007` is minted from the ids on the job, not the number's, so a job numbered later keeps counting.
- **An assistant's paper is hours only by policy, not by screen alone.** The switch is fixed off on the window, and the table refuses an assistant's row with `with_pay = true`; the pay tables never answered them anyway.

## Deploy

After the merge, from the main checkout: `supabase db push` (the table, the gate, the consent kind); then `npm run gen-types:linked` as its own `chore(types)` PR (`hoursStatementsIo.ts` reads the table by name until then). No edge function.
