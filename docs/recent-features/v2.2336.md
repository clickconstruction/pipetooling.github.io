# v2.2336 — My Inbox desktop ledger rows (2026-08-26)

Owner-approved mockup from the CX audit: on desktop, My Inbox items were
~200px cards that were mostly air (full-width Reopened banner, half-width
note button); three items filled the screen. Mobile keeps the sunlight-pass
cards untouched (v2.1843/v2.1854/v2.1858 decisions all preserved).

- **`ChecklistInstanceCard` gains `variant?: 'card' | 'row'`** (default
  'card' — every existing call site unchanged). 'row' is a one-line ledger
  row: 22px checkbox, title (same click-to-thread behavior), statuses as
  compact chips — "Reopened · <stamp>" amber chip carrying the reason as a
  tooltip, "Waiting on review" / "Signed off" chips — an "N notes" chip or a
  quiet "＋ Note" button, and the parent's actions (mute/fwd) at the row end.
  Same state, handlers, and thread block as the card; only the closed-state
  markup differs.
- **`DashboardMyInboxCard`** passes `variant={isMobile ? 'card' : 'row'}` on
  Due Today + Overdue, and (desktop only) count chips on both group headers
  (red for Overdue) counting incomplete items.
- **`.myInboxRow` CSS** (index.css): secondary actions at 55% opacity,
  full on row hover/focus-within; last row drops its divider. Divider uses
  `var(--border-rule)` — note for future work: `var(--border)` computed
  empty on the running page despite being defined in index.css; unresolved,
  worked around with the semantically-correct rule token.
- Tests: +4 row-variant render smokes (compact checkbox, notes chip toggling
  the thread, reopened chip tooltip incl. no full-width callout, hover class
  + strike-through). Verified live at 1280 (light + dark), 768 (titles wrap,
  no overflow), 375 (original cards, zero ledger rows).
