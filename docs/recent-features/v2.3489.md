# v2.3489 — The Tier-1 smoke suite un-stranded: every marker rebuilt against the running app (2026-09-15)

Test-only. Three `e2e/` specs, no source change, no migration, no edge function, no user-facing surface.

## Why

The Playwright smoke suite (`docs/E2E_SMOKE.md`) had **not passed in its last 100 runs** — 2026-09-14 08:04 through 2026-09-16 03:46, 61 failures and the rest skipped or cancelled. This is precisely the failure mode rule 6 of that doc names ("move a button, fix its spec in the same PR"; it had already happened once for ~110 versions, fixed in v2.1164).

Every reproducible failure was a **renamed label, not a defect**. Each was driven by hand against the running app on real data before being changed:

| Spec | Looked for | The app says |
|---|---|---|
| `deep-links` | heading `Weekly movement` | **Stage moves this week** — renamed in v2.2913 (the emailed report keeps the old name). The modal opens correctly; only the heading moved. |
| `settings-tabs` ×2 | tab `Data & migration` | **Data & recovery** |
| `jobs-tabs` | `Revenue before Overhead` on job-summary | gone since the overhead train (v2.3258–v2.3261); the tiles are Revenue / Gross profit / Overhead charged / True profit |

The fifth failure, `no sideways overflow at 375px: /bids?tab=bid-board`, is a **flake** — it passes on retry #1 in the same run, and does not reproduce locally at 375 px (measured `scrollWidth` 375, zero offending elements). Left alone deliberately.

**The Settings drift was far worse than CI could show.** That spec dies at the first mismatched label, so CI only ever reported one. Checked against `src/lib/settingsGroups.ts`, **eight of twelve labels had drifted**, the tab list had moved out of `src/pages/Settings.tsx` entirely (the spec's comment still pointed there), and the landing-tab assertion was wrong — `/settings` opens **Your account**, not Notifications.

## What shipped

- **[`e2e/settings-tabs.spec.ts`](../../e2e/settings-tabs.spec.ts)** — `TABS` rebuilt in the app's own tab order, 12 entries → **16**. Renamed: Notifications → **Activity logs**, Dashboard & alerts → **Your dashboard**, People & accounts → **People & teams**, Email & notifications → **Emails & reports**, Data & migration → **Data & recovery**, Jobs & dispatch → **Jobs & billing**, Catalogs & trades → **Bids & materials**, Templates & testing → **Email templates & testing**. Added, never covered before: **What customers see**, **Company**, **Usage**, **Digital twins**. Landing assertion → `My Profile`. Deep-link test → the `Data & recovery` tab. The comment now points at `src/lib/settingsGroups.ts`.
  - Only **one** marker was genuinely dead: `Job creation overrides` (Jobs & billing) → **`Collections law firm`**. Every other marker survived its tab's rename and is unchanged, which keeps the diff to labels.
- **[`e2e/deep-links.spec.ts`](../../e2e/deep-links.spec.ts)** — the `?stagesWeekly=1` heading and the test name. The sibling `?stagesMoney=1` test is untouched: `Weekly money movement` is still the heading in `JobsWeeklyMoneyModal.tsx`.
- **[`e2e/jobs-tabs.spec.ts`](../../e2e/jobs-tabs.spec.ts)** — job-summary marker → **`True profit`**. Chosen over `Overhead charged`, which only renders for some overhead-dial settings; `True profit` is on the default view and appears on no other Jobs tab (verified against `?tab=stages`).
- **[`docs/E2E_SMOKE.md`](../E2E_SMOKE.md)** — the settings-tabs coverage line records the rebuild and the new count.

## Verified

The suite runs against **production** as a dedicated test user, and `E2E_TEST_EMAIL` / `E2E_TEST_PASSWORD` are not in this machine's `.env.local`, so Playwright itself could not be run here. The honest substitute: each spec was **replayed by hand in the running dev app** (`localhost:5190`, dev login, real prod data).

- All 16 Settings tabs: clicked in order, each marker asserted **visible** (`innerText`, matching the spec's `useInnerText: true`), Advanced expanded first. **16/16 pass, landing assertion passes, zero page errors.**
- `?stagesWeekly=1` → the param self-strips and the **Stage moves this week** heading renders.
- `/jobs?tab=job-summary` → `True profit` visible, no `Something went wrong`; `/jobs?tab=stages` → none of the Job Summary strings leak across.
- `/bids?tab=bid-board` at 375 px → no sideways overflow.

Typecheck, lint, full test run and build all green.
