## The template, version 2

- `gc_schedule_templates` gains `phases` and `rows` (jsonb, the kernel's `TemplatePhase[]` and `TemplateRow[]`),
  `kind` (40 letters at most), `working_days` (false for every template saved before, the owner's call 4),
  `version_of` (the row it replaced, call 2) and `superseded_on` (the day a new version replaced it). A template
  made from nothing came from no job, so `from_name` and `from_done_pct` may be null, and `lines` may be empty
  once the row has `rows`. The name is unique among the current versions
  (`gc_schedule_templates_name_once_current`, `WHERE superseded_on IS NULL`), so a new version keeps its name and
  the one it replaced keeps it too; the client's *Another template has that name* still reads the index's name.
- **Append only stands.** `authenticated` may update `name`, `aside_on` and now `superseded_on`, and nothing else;
  `GC_SCHEDULE_APPEND_ONLY` in `src/lib/gc/doors.ts` names the third column, and `doors.test.ts` reads the grant.
- `gc_schedule_template_save(p_template, p_version_of)`: one press that writes the new row and, for a new version,
  marks the one it replaces the same day, so no save leaves a template half replaced. It refuses in the kernel's
  words: a blank name, no day, no phase or no row, a row with no name, in a phase the template does not have, with
  no days, or assigned to anything but a trade, Us or Office, under a week, a kind too long, another current
  template's name, a version already replaced (*saved again since you opened it*), one that is gone. A new version
  keeps the job the old one came from and its being set aside when the save says nothing of them. SECURITY INVOKER:
  the team policy and the training-mode blocks are its gate.

## The job's side

- `gc_schedule_activities.phase` and `gc_schedule_milestones.phase`, the template phase each was drawn in by name,
  and `gc_schedules.phases`, the phases in order. `gc_schedule_draft` reads them from the draft (`phases: string[]`
  on the draft, `phase` on each bar and date to meet), checks each named phase is listed, none twice and none blank,
  and writes them; a draft with no phases clears them. A bar's phase is a record, not the plan: the guard lets it
  change outside a plan write, as a place does.
