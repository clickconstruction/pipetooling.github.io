# v2.3281 — Standing discount lives on the real Edit customer form (2026-09-11)

Client only — no migration. Found on the owner-driven live pass: Customers → ✎ → no *Standing discount* field. v2.3272 put the field in `src/pages/CustomerForm.tsx`, but the `customers/:id/edit` route has redirected into the app-level Edit customer modal (`EditCustomerModal` → `EditCustomerForm`) since the v2.3009 refresh — nothing renders that page, so the feature was unreachable in production.

## What shipped

- **[`EditCustomerForm.tsx`](../../src/components/EditCustomerForm.tsx)** carries the field now — the same `%` box and reason chips (Negotiated · Referral · Repeat customer · Goodwill · Price match) under Email, loaded from `standing_discount_pct` / `standing_discount_reason` and saved in the ordinary update payload (`null` when cleared). Everything downstream — the offer chip on the Bill tab, "Use it" in Bill Customer, "not on this job" — was already reading the columns and now has something to read.
- The help guide's path (Customers → Edit → Standing discount) is true again. The unrouted page keeps its copy; it is dead code either way and a separate cleanup.
