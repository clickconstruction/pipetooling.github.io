# v2.2461 — Lost-summary loss reason: RLS-refused save no longer silent (2026-08-28)

The v2.2454 sibling noted in that fragment: `saveLossReasonFromLostSummaryModal`
(`src/pages/Bids.tsx`) fired its `bids` UPDATE without checking affected rows, so an
RLS-filtered save (twin write fence, or a bid deleted mid-edit) silently dropped the
loss reason and category. Now appends `.select('id')` and, via the v2.2454
`updateGuard` kernel, toasts `BID_UPDATE_NOT_APPLIED_MESSAGE` on zero rows (toast, not
inline error — the Lost summary modal has no error surface of its own and the save is
fire-and-forget from its edit row).

Remaining known siblings (unchanged): the many `from('bids').update(...)` sites across
bid components (cover letter, counts, sent panel, review modals, …) share the shape;
sweeping them is a mechanical pass for a separate PR if wanted.
