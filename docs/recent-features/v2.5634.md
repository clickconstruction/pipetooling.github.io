# v2.5634 — Every Stripe bill email, resends too, a line in the job's trail (2026-10-19)

The owner's follow-up to v2.5633 ("Log every Stripe bill email in the job's trail", done here on his word). v2.5633 drew the bill's send in the Pipeline row's activity box from the job's `invoice_sent` event, but the invoice trigger logs only a bill's first send (`sent_to_customer_at` first stamped), so a resend from the row's Stripe **Resend** button made no line, though `send-stripe-invoice` logs every send in `jobs_ledger_invoice_stripe_email_sends`. One migration, `20261019010000_stripe_email_sends_to_activity.sql` (`docs/migrations/`), no client change.

- **The trigger**: AFTER INSERT on the sends log writes one `invoice_stripe_email_sent` event per send (the backfill's kind from 2026-06-08, which `JOB_ACTIVITY_EVENT_RENDER` draws as *Emailed* and the box as *Bill emailed through Stripe*), `detail.invoice_id` and `detail.source_id` = the send row, financial, actor `auth.uid()` (null for the service role, so the box says *The app*). A send whose invoice already has a sent event within two minutes writes nothing: `send-stripe-invoice` stamps the invoice (the invoice trigger's `invoice_sent`) and appends the log row with the same `sent_at` in one call, so a bill's first send keeps its one line. The guard reads the job's own events through the `(job_id, occurred_at)` index.
- **The backfill**: the sends since the first backfill with no line of their own get one, under the same guard and skipped by `source_id`, so a second run of the migration changes nothing.
- **Proof**: the bed `scripts/pgtest-stripe-email-sends-trail.sh` over `supabase/tests/stripe_email_sends_trail/` (stand-in tables; the migration applied twice; a first send keeps one line, a resend gets its line with the right job, invoice and time, a resend logged before the migration gets its line from the backfill, nothing doubles), registered in `scripts/sql-beds.txt` for the SQL beds workflow.
- **Docs**: `BILLING_FLOWS.md`'s send-log line; the Glossary's job activity entry.
- **Deploy**: `supabase db push` after the merge; the box subscribes to `job_activity_events` inserts, so a resend's line appears live.
