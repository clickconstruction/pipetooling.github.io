# v2.3276 — Bids → Labor: the New view, "Hours that learn" (PR 1 of the Labor refresh) (2026-09-11)

Client only — no migration. Owner call after the mock-up *Hours That Learn* (kept in [`to-dos/bids-labor-refresh/`](../../to-dos/bids-labor-refresh/README.md)): "build this as a new tab under the bids labor, leaving the current as an old tab." Same shape as the Takeoffs parallel run (v2.2768): **Old · New** pills on the selected-bid card, remembered per device, Old the default and untouched.

## Why

Read on prod 2026-09-11: the Labor rate box is blank on every won bid (labor $ reads $0 on all 33), SPACEX's 26 count rows carry zero hours because the book keys on "Toilet" while the sheet says `WC 1&2` / `LAV2` / `ft of 3/4IN WATER`, and the Old view's Apply matched the primary name only (architecture quirk #6). Nobody scans 26 rows for zeros. The New view puts the rows the book could not answer first, says where every filled row's hours came from, and reads the whole bid back as crew-days, dollars and revenue per field hour.

## What shipped

- **Kernels** — [`laborBookMatch.ts`](../../src/lib/bids/laborBookMatch.ts) (+9 tests): `matchLaborRow` exact → alias → code prefix (`LAV2` → `lav`, `WC 1&2` → `wc`; a prefix needs two letters and a digit after it, so footage never becomes `ft`), `laborRowSource` (book · edited · typed · none), `laborRowsNeedingHours`, `entryAlreadyKnows`. [`bidLaborSummary.ts`](../../src/lib/bids/bidLaborSummary.ts) (+5 tests): `summarizeBidLabor` (hours by stage, crew-days at 2 techs × 8 h, labor $ at the rate, revenue per field hour against the bid value, the footage share) and `laborEstimateCompleteness` (usable = hours on ≥ 90 % of rows and a rate — the same reading the job's Burn budget will use after the win). [`laborView.ts`](../../src/lib/bids/laborView.ts) (+2 tests): the per-device Old/New switch, key `bids_labor_view_v1`.
- **[`BidsLaborNewView`](../../src/components/bids/BidsLaborNewView.tsx)** (+3 render tests) replaces the HOURS region when New is picked: the head (completeness bar and pills, five tiles, the labor-book select); the **queue** — every zero row with the book's guess pre-filled ("reads as Toilet (by alias) — hours from the book"), a *Read as…* picker (book entries · New book entry… · Task · fixed hours), three stage inputs and **Save** / **Save & learn**; **Fill N from the book** takes every matched zero row at once and never touches typed hours; the **grid** of filled rows with a chip per row (`book · by alias`, `✎ edited · book 1/1/1`, `✎ typed`) and a totals row. A queue save writes the row immediately (durable whatever the autosave thinks of the other inputs) and, when the row's text is new to the chosen entry, appends it to `alias_names`; *New book entry…* creates the fixture type and the entry in the bid's applied book with the row's text as its alias. Grid cell edits go through the same `setCostEstimateLaborRow` + `markCell` path as Old, so the tab's autosave persists them unchanged.
- **[`BidsLaborTab`](../../src/components/bids/BidsLaborTab.tsx)**: `laborView` state + [`LaborViewPills`](../../src/components/bids/LaborViewPills.tsx) beside Print; the HOURS block (book select, Apply, the grid) sits behind `laborView === 'old'`; the rate row, sub-sheet prints, Labor total, the amber boxes, Direct Costs and the Labor book panel render for both views; the rate input carries a ref so the New view's "set a labor rate ↓" scrolls to it.

## Not in this PR (the plan's later rungs)

Footage rows per 100 ft and row kinds need columns (PR 2); the crew rate from People and the overhead tile (PR 4); the revenue-per-field-hour history band and calibration from linked jobs (PR 5, after the Burn to-do's bid ↔ job link); folding the human books into the robot's (PR 6). The alias-aware matching is the New view's rule only — Old's Apply keeps quirk #6 until retirement.

## Verified live (dev, port 5179, prod data — the ZZ Test bid BP398)

Pills switch and persist per device; New on a bid with no book reads *Not yet usable · hours on 0 of 3 rows · no labor rate · materials from takeoff*; picking the Default book shows Toilets *reads as Toilet (by alias)* and Kitchen sinks *(by name)*, **Fill 2 from the book** writes both (verified in `cost_estimate_labor_rows`), the grid shows `book · by alias` / `book · by name`; typing 35 in the rate box flips the strip to $1,365 at $35/h and $1,445 revenue per field hour; the task path saves fixed hours on the unmatched row and the head flips to *Usable as a job budget*. The alias-learn and new-entry paths were not exercised against prod (no empty plumbing book to learn into; a test must never write into a real book) — they are covered by the kernel tests and code review. The bid was restored to how it was found (no book, zero hours, no rate). Old renders unchanged.
