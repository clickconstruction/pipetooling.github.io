# v2.1925 — Billed payment-forecast modal (2026-08-20)

Part 2 of the expected-payment train (part 1: v2.1924 chips; part 3: promised
dates). The "timeline view" of when billed money should arrive.

- New **Payment forecast** button (📅) in the Billed Awaiting Payment header's
  quiet action tier (next to Chart), gated to the same roles as the
  expected-pay chips (dev / master / assistant-like / primary).
- The modal buckets every open billed row by expected payment date (the
  chips' model — bill date + customer median pay speed): **Past expected**
  (red, the follow-up queue) / **This week** (blue) / **Next week** / the
  following two weeks (date-range title) / **Later** / **No pay history**
  (no reference date or no pay-speed data). Company weeks start Sunday.
- Tile row of bucket sums + per-bucket row lists sorted by expected date;
  each row shows job number/name, customer, pay-speed source, and open
  dollars, and clicking jumps the board to that bill
  (`applyStagesInvoiceFocus` — the aging chart's jump). Footer counts
  paid-to-zero rows not shown, so no money hides silently.
- New kernel `src/lib/jobs/billedPaymentForecast.ts` (+7 tests): Sunday week
  starts, week-distance bucketing, date-range titles, sort, and skip
  accounting. Modal `BilledPaymentForecastModal.tsx`; opening it keeps
  kicking the billed scope fetch until merged (the aging-chart pattern), so
  it works from a collapsed section.
- No migration — reads the v2.1924 `get_billed_customer_pay_speeds()` RPC;
  with pay speeds unavailable every open row still lists under No pay
  history (nothing hides).
- Help guide `see-when-a-customer-will-pay` extended with the forecast
  section.
