# v2.6541 — A piece of evidence on an HR file can link a file already in Drive, so a recording over the cap still has a record (2026-11-05)

Punch list #269, PR 1a. The owner's case folder for a former teammate holds two dozen call recordings of 32 to 146 MB; the evidence door refused anything over 10 MB and told the office to put it in Drive by hand and note it in the memo, which left the recording without a record, a day or a chip. The 10 MB cap is the edge function's body and the base64 round trip, so a bigger cap was not the fix: a link keeps the file where it already is, in the People drive, and the record says so. Migration `20261105200000_evidence_linked_file.sql` ([`docs/migrations/`](../migrations/20261105200000_evidence_linked_file.md)): push right after the merge, then redeploy `hr-evidence-drive` and `dev-mcp`.

## What changed

- The kernel (`supabase/functions/_shared/personEvidence.ts`, shared with the seat): `PersonEvidenceLink { name, driveUrl }`, `evidenceLinkProblem` (a name, and a Drive address on drive.google.com or docs.google.com), `driveFileIdFromUrl`, `evidenceFileIsLinked` (a row with `drive_url` and no `storage_path`), `evidenceFileWhereWords` (*in Drive* · *in Drive, linked* · *kept here, on its way to Drive*). `evidenceDraftProblem` takes the links as a fourth argument: a file or a link is enough, and the over-the-cap words now end *link it here*. `evidenceDriveState` counts a linked file as in Drive, and `evidenceDriveWords` reads *In Drive, linked* when every file is.
- The panel (`PersonFilePanel.tsx`): under the file picker, *Or a file already in Drive* with a name box, a link box and **+ Add the link** (Enter adds too); the link joins the list with a 🔗 and its own ✕; the title starts from the first link's name when nothing was picked. The save writes a linked row (`storage_path` null, `drive_url`, `drive_file_id` from the link, `filed_at` now) and asks Drive only when something was staged; the toast says *The file is linked in Drive.* The chip's tip reads the file's whereabouts from the kernel.
- The filer (`hr-evidence-drive`): a linked row is left alone and counted as filed; a record of linked files alone is stamped filed without a Drive call.
- The seat (`dev-mcp` 0.25.0, `devMcpWrites.ts`, `dev_person_evidence_write`): `files[]` takes `{ name, drive_url }` beside `{ name, content_base64, mime? }`; `evidenceBytes` holds the link to a Drive address and stages nothing for it; the apply names it in `p_files` as `{ id, drive_url }`; the RPC writes it with its link alone and replies with `linked` and `staged` counts. The tool descriptions and the server's instructions say so.
- The guide *keep private employee files* gains the evidence section it lacked, with the link in it.
