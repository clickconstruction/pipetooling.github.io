# v2.4215 — Robot counts from TakeoffTooling keep their groups and alternates (2026-09-30)

The PipeTooling end of TakeoffTooling's alternates PR (clickconstruction/takeofftooling.github.io#23). Edge function only — **redeploy `twin-mcp` (v1.4.5)**; no migration.

## What changed

- **`paste_counts`** ([twin-mcp](../../supabase/functions/twin-mcp/index.ts)): each row's `group` (or a `[Group] ` prefix on the fixture, lifted off it as the Counts tab's paste import does since v2.4188) lands as `bids_count_rows.group_tag`; before, the twin path never wrote a group, so the Workbench line, the Takeoffs rail and the Labor card could not split. A row with `alternate: true` — what TakeoffTooling's `tt_manifest.rows[]` carry for a group priced with and without — names its group in `bids.alternate_group_tags` (a union with what the bid already has, case-insensitive; the Counts tab's switch owns removal). The ledger note and the response name the alternates.
- Tool schema: `group` and `alternate` on the row; docs in [EDGE_FUNCTIONS](../EDGE_FUNCTIONS.md) and the estimator brief (regenerated `briefs.ts`).
