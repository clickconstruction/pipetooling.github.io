# v2.4862 — People: the Hours grid and Teams tell archived people apart by who they are, not their name (2026-10-07)

Punch list #29 ([`to-dos/people-spine-residuals.md`](../../to-dos/people-spine-residuals.md)), item 3, the first of the id-first PRs. v2.4671 moved the archived folds onto the `roster_people` read but still matched by name. Now the Hours grid and the Teams member filter match by the row's `person_id` first. Client only.

## The change

- **[`buildArchivedRoster` / `isArchivedRosterRef`](../../src/lib/people/rosterPeople.ts)**: one index from the same roster read. It holds each roster row's `is_archived` by `person_id` (`people.id`) and by `user_id`, and `archivedRosterNames` as the fallback. A row whose id the roster knows takes that row's verdict, whatever its name. Only a row with no known id falls back to the names, matched trimmed and without case, as the namesake guard already compares. By name the Hours grid and Teams matched exact case before. Before the read lands, `NO_ARCHIVED_ROSTER` knows no one, the same no-verdict path as before.
- **[`hoursGridRoster.ts`](../../src/lib/people/hoursGridRoster.ts)**, rule 1: the pay-config row's `person_id` decides first. Rule 2, the pay roster's verdict, is unchanged.
- **[`hoursTeams.ts`](../../src/lib/people/hoursTeams.ts)** and [`usePeopleHoursTeams`](../../src/hooks/usePeopleHoursTeams.ts): `loadTeams` now also reads `people_team_members.person_id`. Each team carries `memberPersonIds`, and the filter asks by id first. A member added since the load has no id yet, so its name decides until the next load.
- **[`People.tsx`](../../src/pages/People.tsx)** keeps the index (`archivedRoster`). Offsets, Contracts and Review still take its `names`, the same set as before, until their own PRs.

## What a person sees

- A pay row or team member under a person's old name now leaves the grid or the team when that person is archived. By name it stayed.
- A living person whose row carries an archived person's name, and no living namesake, now stays. By name they were hidden.
- Everyone else is where they were.

## Tests

`rosterPeople.test.ts` adds six cases for the index: a renamed row, the id winning over the name both ways, namesakes told apart by id, the name fallback for no id or an unknown id, the person id asked before the user id, and no verdict before the read. `hoursGridRoster.test.ts` and `hoursTeams.test.ts` each add the renamed-row and stale-name cases through their kernel.
