# v2.2598 — Division 22 audit modal: pin the uncoded names (2026-09-01)

Phase 3 of the Division 22 ledger (schema v2.2580, grouped copy v2.2587;
mockups 4–5 on the "Division 22 Ledger" design canvas). Closes the manual
seam: uncoded fixture names no longer need a hand-written rules migration.

- **Migration `20260901211245_division22_fixture_name_audit.sql`** (applied
  2026-09-01): RPC `spec_section_fixture_name_audit()` — distinct trimmed
  fixture names across ALL bids + per-name bid counts. SECURITY DEFINER
  (avoids per-row RLS fan-out over bids_count_rows), gated inside to the
  ledger-writer roles. Read-only, no new tables.
- **New kernel `src/lib/specSectionAudit.ts`** (+ tests):
  `buildFixtureNameAudit(names, rules)` → uncoded/coded split (deliberate
  no-code counts as covered), most-bids-first sort, coverage percent, rule
  provenance labels. `AUDIT_PIN_PRIORITY = 60` — pins land after the seeded
  exacts (10–50), before every pattern rule (100+).
- **New `SpecSectionAuditModal`** (`src/components/bids/`): coverage bar,
  uncoded rows (amber) with a section SearchableSelect + "Pin it" + "No code",
  coded names behind a toggle with provenance ("via 'starts with WC-'").
  Pinning inserts an exact rule — or updates an existing exact rule for the
  same name (case-insensitive), so a wrong pick is re-pinnable without
  duplicates. Rules-only refresh after each pin; classification re-runs
  locally.
- **Entry point**: fifth Share ▾ item "Division 22 codes" (`PricingShareMenu`
  `onOpenD22Audit`, optional — passed only for `canPackageAndSendBidPricing`
  roles, matching the ledger's RLS writers; hidden from the Export ▾ variant).

Not built: the count badge on the menu item (mockup shows one; needs the audit
fetch before the menu opens — revisit if Wendi wants it) and the full rules
manager (mockup 2).
