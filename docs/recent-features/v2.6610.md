# v2.6610 — Edit a person's HR summary or narrative in People → HR (2026-11-07)

PR 2 of v2.6608's pair; no migration. The summary and the narrative on a person's HR file (`person_files`, `docs/HR_FILES.md`) rendered as markdown with no editor: a dev who wanted to change a line waited on the agent or on psql. This puts an editor on the two headings that saves through `dev_person_doc_write` (`20261107013000`), the same function the dev seat's `plan_person_doc` / `apply_person_doc` write through, so a dev and an agent never write over each other.

## Change

- **`PersonFilePanel.tsx`** (People → HR → Narrative): each heading carries *Edit* (*Write* when the document does not exist yet) while nothing is under edit. The editor is a textarea in markdown, a line from `hrDocDraftWords` under it (nothing changed yet, an emptied document, or the size and how it moved), *Save the narrative* dead until the words change, Cancel, and a fold *How it will read* that renders the draft through the same `hrDocMarkdownToSafeHtml`. Save sends `{ p: hrDocSavePayload(…), p_dry_run: false }` — the whole text and the `updated_at` the editor loaded as `expect_updated_at` — then reloads the file and tells the host. A refusal keeps the box open with its reason from `formatErrorMessage`; the stale refusal (the function's own words, read by `hrDocSaveWasStale`) adds the way out: copy the words, Cancel, open again.
- **`src/lib/people/hrDocEditor.ts`** (pure, unit-tested): the payload, the draft words, the stale read and the failure words.
- **Smoke** `PersonFilePanel.docEditor.render.test.tsx`: Edit opens the text, Save wakes on a change and posts the payload with the loaded `updated_at`, a refusal keeps the box open with the way out, Write on a missing summary saves with no expectation.
- **Help guide** `keep-private-employee-files.md`: the section *Edit the summary or the narrative*.
