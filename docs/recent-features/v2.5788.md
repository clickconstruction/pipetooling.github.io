# v2.5788 — Settings: a master sets his own signing code for the Lien desk (2026-10-23)

Punch list #148 (`to-dos/lien-sign-on-any-screen/`), PR 1 of 2. The owner, with three screenshots of the desk: a dev who presses *Approve* opens the notice with the master's line under it and nothing to do but carry the laptop to him. The findings: the block was worse than a dead end — it typed the dev's name over the master's license and the guard would have taken the press (a dev is a signer role). Three options were mocked up; the owner chose **C, a code the master types on any screen**, and set its shape himself: a code *he* sets in Settings, four to six digits, never sent to his phone.

- **Kernel** ([`lienNoticeSignature.ts`](../../src/lib/jobs/lienNoticeSignature.ts)): `LienSignatureMode` gains `code`; the audit line reads *Typed by Malachi with his signing code in ClickTooling on October 23, 2026 at 2:14 PM CT, on Robert’s screen.* with *Confirmed by … from his own sign-in on …* once he has; the chip and `lienPenAwaitsConfirm` treat a code signature as they do a pen record. The guide *send lien notices from the Lien desk* gains **Your signing code**.

## Is this the best we can do?

- **The owner's call, taken whole.** The findings recommended A then B (draw in his name on the dev's screen, or send him the notice); the owner wants the code, and nothing about it is half-built: the code is his alone, hashed, rate-limited, checked in the database, named in the record with the screen it was typed on.
- **The record says what happened.** *Typed by Malachi with his signing code … on Robert’s screen* is a true sentence; the guard's old refusal was a refusal of the office *placing* his name, and a code only he knows is not that. His own sign-in can still stand behind it (*Yes, I signed it*) or clear it (*Not what I signed*), the pen train's doors, so a watched or guessed code is undone by him in one press.
- **Not a text, not a PIN typed into the open.** The owner said no code to his phone. The field will be a password field (PR 2), the code never lands in a URL, a log line or a toast, and the status RPC answers *set / locked*, never a hash.
- **One table, no columns on `users`.** `users` carries privileged-column guards and every picker reads it; a code belongs beside the dev keys and twin credentials, in its own row with its own salt.
- **Left for PR 2:** the desk's block — his name in cursive, the code field, the words when the code is wrong, locked or not set, the *Draw instead* on another's screen attributed to him, the push that tells him his code was used, and the confirm/disown group on his Ready pile for a code signature.
