# v2.7524 — Liens: add several stamped scans at once, one file a lien (2026-11-16)

Punch list #366. v2.7480 took one scan on one job's **Record filing…**. The office files liens in batches and the clerk's stamped copies come back together, so twelve filed liens were twelve trips to twelve windows. The owner's steer of 2026-11-16: "we should aim towards one PDF per lien, but if they are all for one person a user may scan a whole stack". This is the first half, several files with one a lien; the stack's splitter is the second. Client only: no migration, no edge function.

## What changed

- **`LienScanBatchWindow.tsx`** (new): *Add the stamped scans*. It lists every filed affidavit with no saved copy, by county and then by job number, the order a batch was printed for the clerk. The office picks every file at once; each is shown with the lien it is matched to, a line saying how it was matched, *Open* to look at it, and a list to change the lien. One press saves what is ready.
- **`src/lib/jobs/lienScanBatch.ts`** (new, pure). `lienScanTargetsFromDesk` reads the desk's own data, no read of its own. `lienScanMatches` gives each file a first match: a name that carries one lien's recording number (however it is punctuated, six digits or more), then a name that carries one lien's job number as a word of its own, then the next lien nobody has, in the list's order. A name that fits two liens fits none. `lienScanPlan` says what the press saves and what it holds, and `lienScanPlanWords` words it through `batchWords` (*Save 12 scans · 1 held ▸*).
- **Held with a reason, never all or nothing**: a file with no lien picked, a second file for the same lien (a filing keeps one saved copy), and a file the folder cannot take (`lienScanProblem`: not a scan, empty, over 10 MB). The rest are saved.
- **`lienScanBatchIo.ts`** (new): each scan is its own pair of writes, the file as it is into its job's Drive folder under Team only, Sent by us, named as the single upload names it, then the link on its filing with `LIEN_CLERK_SCAN_NOTE`. The batch keeps going past one that fails. A scan that reached the folder but not the filing says so, since the file is there to link by hand.
- **One file a lien, each on its own job**: a job's folder never holds another job's affidavit.
- **Doors**: a third part of *Filed liens: copies to mail* (`onAddScans`), and the address `/lien-desk?scans=1` (`lienDeskRoute.ts`, consumed once by the page as `records` and `property` are), which a line under the single upload on a job's Record filing opens in a new tab so the form keeps what is typed.
