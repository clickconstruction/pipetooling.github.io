# v2.3159 — Bid Room: drawn signatures via the shared Type / Draw input (2026-09-08)

No migration, no edge-function change — `sign-bid-room` already accepted `signaturePngBase64` for both the proposal and change-order branches and stored it in `estimate-acceptor-signatures`; only the client never sent one.

## Shared component

- New [`components/contracts/SignatureTypeOrDrawInput.tsx`](../../src/components/contracts/SignatureTypeOrDrawInput.tsx) — the Type / Draw segmented switch, cursive typed preview (`EstimateAcceptTypedSignatureLine`), `signature_pad` canvas and Clear button, lifted out of `ContractAcceptSignatureForm`. Parent owns `mode`; the drawing is read through a `forwardRef` handle (`isEmpty` / `toDataURL` / `clear`) at submit. `align: 'center' | 'left'` and `maxWidth` let the Bid Room's inline form and the centered contract pages share it. Render smoke: `SignatureTypeOrDrawInput.render.test.tsx`.
- [`ContractAcceptSignatureForm.tsx`](../../src/components/contracts/ContractAcceptSignatureForm.tsx) now composes it (identical DOM, labels, and payloads — the contract-accept page and `LienReleaseSignModal` are unchanged from the signer's view; their existing render tests pass untouched).

## Bid Room

- [`pages/BidRoom.tsx`](../../src/pages/BidRoom.tsx): `signMode` + `signPadRef` on the proposal approval; `RoomChangeOrderCard` gets its own pair. Both call the new kernel and spread its fields into the `sign-bid-room` post (`signaturePngBase64` only in draw mode). Consent lead: "Your typed or drawn signature below applies to the option selected above…".
- Kernel [`lib/bids/bidRoomSignature.ts`](../../src/lib/bids/bidRoomSignature.ts) (+tests): `bidRoomSignatureError(input, agreeHint)` (name → agreement → "Please sign in the box.") and `bidRoomSignatureFields(input)` (never emits a PNG from a type-mode pad).
- Render smoke [`pages/BidRoom.render.test.tsx`](../../src/pages/BidRoom.render.test.tsx) with mocked `fetch`: Draw shows the pad and refuses an empty one; a drawn approval posts the PNG + `esignConsent`; a typed approval carries no `signaturePngBase64` key.

## E-sign consent

- [`lib/esignConsent.ts`](../../src/lib/esignConsent.ts): the GC paragraph now reads "a typed or drawn signature has the same legal effect"; per the file's rule, `ESIGN_CONSENT_VERSION` 1 → 2 (signatures from now on store version 2; `/estimate/terms` shows "Version 2"). Tests updated.
