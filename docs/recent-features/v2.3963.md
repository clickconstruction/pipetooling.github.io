# v2.3963 — Bid Board and Dashboard maps: scrolling past them no longer zooms them out (2026-09-27)

Client only; no migration, no edge function. Owner ask, after v2.3951 did this for the Pipeline map: the same for the Bid Board and Dashboard maps.

## What shipped

- **`BidBoardMapCard`** passes `scrollZoomAfterClick` to `PinsMapCanvas` and `PinsMapGoogleCanvas`.
- **`DashboardJobsMapCard`** passes it to its two adapters. `DashboardJobsMapCanvasProps` gains the optional `scrollZoomAfterClick`, and `DashboardJobsMapCanvas` / `DashboardJobsMapGoogleCanvas` hand it to the shared canvases.
- The gate itself is v2.3951's (`src/lib/map/scrollZoomGate.ts`, the two shared canvases); nothing in it changes.
- Two maps keep the wheel from the start, on purpose: the clocked-in map (a modal, with no page to scroll behind it) and the `/map` page (the map is the page).
- Help guides `see-your-bids-on-a-map` and `see-your-jobs-on-a-map` say it beside Fit all / Hide map.

## Verified

- `BidBoardMapCard.render.test.tsx` (12, one new) and `DashboardJobsMapCard.render.test.tsx` (7, one new): both canvases receive the prop, Google first and OpenStreetMap after the fallback. New `DashboardJobsMapCanvas.render.test.tsx` (2): each adapter hands the prop on, and leaves it off when the card does not ask.
- The gate's browser check is v2.3951's (the Leaflet canvas on a scratch page); these cards mount the same canvas with the same prop.
- Not run: the Google canvas in a browser, and the cards inside the live app — this worktree has no env file and no Maps key.
