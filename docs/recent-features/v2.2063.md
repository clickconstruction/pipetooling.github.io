# v2.2063 — Report % propagation failures surface as a toast (2026-08-21)

Field-report investigation follow-up (Abraham's "my 100% doesn't stick" report): [`propagateReportPctToJob`](../../src/lib/propagateReportPctToJob.ts) called the `set_job_pct_from_field` RPC and discarded the result — the RPC reports failures **in-band** (`{error}` with HTTP 200: authorization, validation), so neither transport-level nor in-band failures ever reached the tech. A mirror failure looked exactly like "the app ignored my 100%".

- The wrapper now checks both the RPC transport error and the in-band `{ok, error}` payload, and returns `{ jobStatus, pctError }`; the lookup `catch` also reports instead of silently nulling.
- Both callers — [`NewReportModal`](../../src/components/NewReportModal.tsx) and [`AdditionalReportModal`](../../src/components/AdditionalReportModal.tsx) — toast a warning ("Report saved, but the job's % done could not update: …") when `pctError` is set. The report save itself stays non-blocking, and the Ready-to-Bill prompt still fires when the status lookup succeeded.
- New unit tests ([`propagateReportPctToJob.test.ts`](../../src/lib/propagateReportPctToJob.test.ts)): success, in-band RPC error, transport error, unchanged-pct skip, lookup failure.

Client-only — no migration, no schema change.
