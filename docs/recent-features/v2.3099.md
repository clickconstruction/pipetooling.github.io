# v2.3099 — Teacher attribution on backtest scores (2026-09-07)

Completes v2.3080: shadows already recorded whose number they scored against; backtests did not, so the gate bars mixed Wendi's references with Malachi's and William's without saying so. Migration `20260907180000_backtest_teacher.sql`; twin-mcp v1.3.12.

## What shipped

- **`twin_run_scores.teacher_user_id` / `teacher_name`** — resolved from the reference bid exactly as shadows are (`estimator_id` → `bid_date_sent_attested_by` → `created_by`). `score_backtest` stamps new rows and names the teacher and their standing in the `[STG-6 SCORECARD]` ledger note. The migration backfills every existing row by joining `reference_bid_number` to `bids.bid_number`; all 23 resolve on the first hop (18 Wendi, 3 Malachi, 2 William).
- **Standing is decided at read time.** The Scoreboard fetches the set of `users.calibration_standard` ids and passes it to the kernel as `standardTeacherIds` (`BoardOptions`, `confidenceBoard.ts`). A backtest whose teacher is stamped and not in the set is **practice**: excluded from the gate entries (so it cannot fill a slot or break a streak), counted in "N practice-teacher runs set aside" on the axis card, and shown in the ledger as `practice` with the teacher's name and a PRACTICE tag. `void` (gate_eligible false) still wins over teacher standing. No stamped teacher, or no set loaded, means the old behaviour — gate on `gate_eligible` alone — so a client ahead of the migration renders exactly as before.
- **Effect on today's bars** (with Wendi the only standard): small TI drops BT-11 and BT-12 (Malachi) and mid-size TI drops BT-13, kitchen/occupied drops BT-14 (William). Flagging either estimator as a standard in Settings → Digital twins (v2.3091) restores their runs without a code change.

## Tests

`confidenceBoard.test.ts` +3: practice backtests set aside only when a standard set is given (and unchanged without one), an unstamped backtest stays eligible, ledger marks practice/eligible/void with the teacher carried.
