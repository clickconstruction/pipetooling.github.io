# v2.2313 — Payment history on customer invoices + portal (2026-08-25)

Owner ask (HCP screenshot): a payment-history section on every delivered
invoice. Approved mockup: claude.ai/code/artifact/1231bd7a-9d14-4984-bd23-e0bcc1be3f91.
A bare list already existed on detailed physical invoices; this upgrades it
and adds the missing surfaces.

## Document model + renderers

- `physicalInvoiceLineItems.ts`: `formatPaymentHistoryRows` now prints the
  **method only** — the internal `note` (which carries hygiene tags like
  `hcp-paydate-corrected-…` since Billing Truth) no longer reaches customer
  paper. Dates gain the weekday ("Dec 17, 2025 · Wed"); no time-of-day —
  `paid_on` is date-only and `created_at` is entry time (owner-approved
  honesty call). New `buildPaymentHistoryTotals` → `{totalPaidFormatted,
  balanceDueFormatted, paidInFull}` (balance clamped ≥ 0, full at ±0.005).
- `physicalInvoiceDocument.ts`: `PhysicalInvoiceDocument.paymentTotals`;
  email bodies (HTML + text, BOTH layouts — simple had no payment block at
  all) render the boxed table with Total paid + Balance due / Paid in full
  via shared `paymentHistoryHtml`.
- `PhysicalInvoicePreview.tsx`: right-aligned bordered box (max 340px) with
  totals rows; `physicalInvoicePdf.ts`: totals rows in `drawPaymentHistory`
  + the simple-layout builder now draws the section too.

## Customer portal

- Edge `customer-portal`: payments select widened to
  `paid_on, payment_type, sequence_order` (note deliberately excluded);
  `_shared/portalMergedBills.ts`: `PortalBillOut.payments` (date/method/
  amount, oldest first) + `totalPaid` (job-remainder rows use the cached
  aggregate). **Edge function deployed 2026-08-25.**
- `portalPayload.ts` parser + `CustomerPortal.tsx`: dashed sub-ledger under
  each open bill with per-payment rows + bold Total paid.

Unaffected: Stripe-hosted page/email (Stripe renders those), GC statements
(owner-approved skips).
