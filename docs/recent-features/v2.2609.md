# v2.2609 — Addresses no longer end in "Null" (2026-09-01)

Old-import `jobs_ledger.job_address` values carry a literal `Null` token where the zip belongs ("9703 Lenox Hl San Antonio, TX Null") — spotted on the Who-owes-what bill cards (v2.2596).

- `src/lib/displayAddress.ts` — `stripTrailingZip` now strips a trailing case-insensitive `null` token before the zip pass (also handles "… 78751 Null"), with the same never-strip-to-empty guard. Fixes all consumers at once: Who-owes-what cards, Dashboard financials, Schedule Dispatch hub, supply-house job accounts, unified job/bid search, sub-labor job picker, recently-added jobs.
- Display-layer only: the stored `job_address` values still carry the token. A one-time data cleanup (`UPDATE jobs_ledger SET job_address = regexp_replace(job_address, '[\s,]+[Nn][Uu][Ll][Ll]\s*$', '') WHERE job_address ~* '[\s,]null\s*$'`) is possible but was deliberately not run — surfaces that show the raw value (Edit Job) still show it.
