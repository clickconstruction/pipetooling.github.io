# v2.3172 — Vendor kind: five words for what a supply_houses row is (2026-09-08)

PR 5 of six from [`to-dos/supply-house-directory/`](../../to-dos/supply-house-directory/README.md). Migration `20260908190704_supply_houses_vendor_kind.sql` — **push after the client deploys** (the client writes the new column and falls back to the legacy payload until it exists).

## Why

The roster is also the accounts-payable vendor ledger. On 2026-09-08 it held 22 rows: sixteen real counters, a workers-comp insurer, a rental yard, the "Outside Subcontractors" invoice bucket, a fuel account, Amazon and the robot's price source — and the only signal separating them was `is_insurer`, a negative flag nothing had ever set. So the RFQ pickers offered a quote link to Texas Mutual, and the estimator's new directory listed a rental yard as a place to ask for prices. A four-value enum would have forced a wrong answer on five of those rows; the to-do's mock-up carried a five-value classification the owner approved.

## What shipped

- **`supply_houses.vendor_kind`** — `supply_house` (default) · `insurer` · `rental_yard` · `sub_ledger` · `other`, CHECK-constrained, indexed. The migration **seeds by hand**: rows already flagged → insurer; *Texas Mutual (Workers Comp)* → insurer; *Sunbelt Rentals* → rental yard; *Outside Subcontractors* → sub ledger; *Alexander Oil Company*, *Amazon*, *🤖 Web Research* → other; everything else stays a supply house. A `BEFORE INSERT OR UPDATE` trigger derives **`is_insurer = (vendor_kind <> 'supply_house')`** from here on, so a stale client's pickers keep hiding the same rows; the flag itself retires in a later PR.
- **[`vendorKind.ts`](../../src/lib/materials/vendorKind.ts)** (new kernel, 3 test groups): the list, labels, one-line hints, `vendorKindOf(row)` (reads the column, falls back to the flag before the push), `isQuotableVendorKind`, `isInsurerFor`.
- **The form's Quotes checkbox becomes Kind chips** — five pills with a hint line under the chosen one. Estimators never see the row: a house they add is a supply house, a house they edit keeps its kind. The editor writes `vendor_kind` and, on the one "unknown column" error a pre-push database returns, retries with the legacy payload.
- **Directory**: the office's Kind column and a new **All kinds / Supply houses / Insurer only / …** filter beside the search; the estimator's list is `supply_house` rows only (`buildDirectoryRows` takes a specific kind now, not just a boolean). Coverage and the "Needs a rep" band count quotable houses only, so a rental yard is neither "with a rep" nor "needs one".
- **Quote pickers** (`fetchSupplyHousePickerRows`, used by RFQ compose, Plug in quotes, Prepare fixture copy) filter on `vendor_kind = 'supply_house'`, falling back to the flag and then the roster while the column is unpushed.
