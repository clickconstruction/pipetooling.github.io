# v2.1922 — Change-order documents headed "Change Order for …" (2026-08-20)

Owner feedback: a sent change order's accept page opened with "Estimate for Knight Contracting" — the stored `estimates.title` defaults to "Estimate for <customer>" regardless of `doc_kind`, and the CO experience overlay (v2.1834) only swapped the section headings, not the `<h1>`. Two-part fix:

- **Display rewrite (covers already-sent COs)**: new kernel [`changeOrderDocDisplayTitle`](../../src/lib/estimateChangeOrder.ts) rewrites the estimate-flavored defaults — `Estimate for X` → `Change Order for X` (case-insensitive prefix match), bare `Estimate`/`New estimate` → `Change order` — and passes hand-written titles through untouched. Applied in [`EstimateCustomerDocument`](../../src/components/estimates/EstimateCustomerDocument.tsx) whenever the `changeOrder` prop is set, so every render site follows: public accept page, staff preview, editor accepted-record view.
- **Editor default (new COs store the right title)**: `defaultEstimateTitle` in [`Estimates.tsx`](../../src/pages/Estimates.tsx) is now doc-kind-aware ("Change Order for <customer>" on CO drafts) at both defaulting sites (initial load + customer select); the customer-switch "was it still the default?" check matches either flavor, and `isGenericEstimateTitle` learned the no-name defaults (`Estimate for customer` / `Change Order for customer`).

Kernel tests in [`estimateChangeOrder.test.ts`](../../src/lib/estimateChangeOrder.test.ts). Client-only — no migration.
