# v2.7556 — Bids and jobs: a logo in an email's signature is not a file to keep (2026-11-16)

Punch list #368, a follow-up found on the first look at real mail tied to bids. No migration and no function.

## The wrinkle

An email program puts the picture in a sender's signature inside the mail as a file, named *image001.png* and the like. It sits on the mail's line in Messages as a file like any other. Of the mail tied to bids on the day the press was built, one carried only such a picture. **Keep its files on the bid…** would have shown on it, and on most mail a customer ever sends.

## The rule

`isInlinePicture` (`src/lib/bids/bidMailSet.ts`) knows the name: *image*, up to four digits, and a picture's extension. It reads the name alone, so a photo of a marked sheet (*IMG_4411.jpg*, *site-photo.jpg*) is still a file.

- **No press** on a mail that carries nothing else: `bidMailState` answers `none`, the mail window's rule does not count it (so the job's **Keep this mail as a paper** follows the same rule), the Development page's History line draws no *Keep its file…*, and the list under the bid's Plan sets leaves the mail out.
- **Unticked** beside a real file: the form lists it with its tick off. A person can still tick it.
- A logo never brings the press back on a mail whose real files are already kept.

The History read takes the files' names for this (`TIED_MAIL_FILE_COLUMNS`).
