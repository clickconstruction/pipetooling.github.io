# v2.4892 — Bid room: two base bids are two options, never one added-up price (2026-10-07)

Found by Punchlist reading the v2.4723 / v2.4728 code, proved and fixed here. No migration, no edge function (`_shared/bidRoomPayload.ts` is parse-side only and unchanged).

## The bug

v2.4723 made two or more base bids in a letter **options** the GC picks between, never a sum, and v2.4728 handed the bid room every signable combination (`roomSectionsForLetterOptions`), each carrying its version. But the Cover Letter tab built that list only in the branch for a bid **with no versions**, and only a bid with versions can have two base bids. A bid with versions handed its room the raw sections, without their versions. `buildBidRoomRevisionPayload` folds every base section into one option, so the room offered a single *Base bid* at the sum: To Plans $120,000 and Value Engineered $95,000 published as one $215,000 proposal with no version, in either layout. Signing it would have won the whole packet at a number nobody quoted.

Punchlist read prod: no bid room revision was published between v2.4723 (2026-10-06) and this fix, so no live room carries a summed base and nothing needs re-publishing.

## The change

- **Kernel** `roomSectionsForPacket(sections, labels)` in [`wonOption.ts`](../../src/lib/bids/wonOption.ts): plans the GC's priced sections (`planSamePageLetter`, whatever the letter's layout); with options it returns `roomSectionsForLetterOptions` named by the letter's labels, otherwise the sections as they are, each now carrying its version.
- **The tab** ([`BidsCoverLetterTab.tsx`](../../src/components/bids/BidsCoverLetterTab.tsx)): both room panels go through it (`roomOptionLabels` names the options with `buildOptionsBlock`'s labels). A single base on a bid with versions now carries its `bid_version_id` too, so a signature records the version as v2.4728 meant.
- **Separate pages** is covered as well: there each base is a full letter of its own, so the room never summed them correctly either.
