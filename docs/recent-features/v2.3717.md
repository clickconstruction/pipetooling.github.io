# v2.3717 — Pay: say how each payment was sent — one method on every Record payment door, a Method column and filter on Payments (2026-09-22)

PR 3 of [`to-dos/pay-run-payments-view`](../../to-dos/pay-run-payments-view/README.md) (#23) — the follow-up the owner left open on 2026-09-17 ("derive a chip from the memo, or add a real method field?"). Built on 2026-09-22 when the owner asked to work through #23, asking at each step whether it was the best we could do. Client only, no migration: the column is v2.3578's `pay_stub_payments.source_kind` / `source_id`.

## What was wrong

- `source_kind` existed, but only `record_pay_send` and the backfill wrote it. The app's own doors — the pay-run row's **Record payment**, Balances' **Record one payment, oldest first…** (v2.3693) and the Cash App reconcile's **Record** / **Split oldest first** — wrote a memo alone, so every hand-recorded payment since the column shipped carried nothing in it.
- The Payments view guessed the method from the memo's first words in a vocabulary of its own (`cash-app · apple-pay · mercury · check · client`) that did not match the database's five kinds. Two names for one fact.
- The Record payment modal's *Cash App ID* box upper-cased what was typed and passed it through: an id typed without its `#` went into the memo as `Cash App D-…`, which the matcher's rule (a) (`#D-[A-Z0-9]+`) never reads back.

## One vocabulary — [`paySources.ts`](../../src/lib/people/paySources.ts)

The five kinds (`cashapp · mercury · apple_pay · client_direct · other`) are now the method everywhere:

- **`paySourceWrite(kind, cashAppId, note)`** → `{ source_kind, source_id, memo }` — the columns and the memo `paySendMemo` builds (`Cash App #D-… "note"`, `Mercury "note"`, `Payment "note"`), byte-equal to the SQL `pay_send_memo`. No kind → the note alone and both columns null, exactly what the door wrote before. Only Cash App carries an id a person can read off a screen; Mercury and Apple Pay ids are the app's own rows and stay null from a hand door.
- **`normalizeCashAppId`** — trimmed, upper-cased, wearing its `#`. `paySendMemo('cashapp', null, …)` no longer leaves a trailing space.
- **`paySourceKindFromMemo`** — the memo reading, moved here from the view's kernel and re-worded to the five kinds. *Check* is gone as a derived kind: the office has never recorded one, and a real *Other* is only what a door recorded as one. A memo like *Check 1044* stays readable in the memo cell.
- **`isPaySourceDuplicateError`** + `PAY_SOURCE_DUPLICATE_MESSAGE` — the per-report unique index (`pay_stub_payments_source_per_report_uidx`) now reaches the hand doors; when it refuses a second row with the same Cash App id on the same week, the door says *That Cash App send is already recorded on this week* instead of the index's name.

## The picker — [`PaySourcePicker.tsx`](../../src/components/pay/PaySourcePicker.tsx)

**How it was sent**: five pills in the kinds' order; a second press clears (a method is welcome, not required — the owner did not ask for a gate, and *Other* covers the rest). Cash App alone opens the transaction-id box. Used by:

- **[`People.tsx`](../../src/pages/People.tsx)** — the pay-run row's Record payment modal: the picker replaces the *Cash App ID (optional)* box (the id box lives under the Cash App pill now); the insert writes `source_kind` / `source_id`; the reconcile-queue update keys off the normalised id; the duplicate sentence lands in the modal's error line.
- **[`RecordSplitPaymentModal.tsx`](../../src/components/pay/RecordSplitPaymentModal.tsx)** — the picker between the date and the note; every part row carries the columns; *Memo* is now *Note*, since the memo's head is the method's.
- **[`CashAppReconcileModal.tsx`](../../src/components/people/CashAppReconcileModal.tsx)** — no picker needed: both inserts stamp `cashapp` and the transaction's id.

Balances' **Move extra** (v2.3691) still copies the memo alone when it moves a slice of a payment to another week; the moved row reads its method from that memo's first words. Carrying the columns there means threading `source_kind` through the pay-stub loads and the open-reports kernel — left for a later PR if the dashed chip on a moved row ever bothers anyone.

## The view — [`PayRunPaymentsView.tsx`](../../src/components/people/PayRunPaymentsView.tsx) · [`payRunPayments.ts`](../../src/lib/people/payRunPayments.ts)

- **A Method column**, sortable like the others (A → Z by label; unmarked first, like blank memos), between Amount and Memo. The chip is the row's `source_kind`; a row with none is read by its memo's first words (`paymentSource()` says `fromMemo`) and drawn **dashed** with a title saying so — the guess is visible, not passed off as a fact. A stamped Cash App chip's title carries the id.
- **A method filter**: *All methods · Cash App (87) · Mercury (12) · … · No method (4)* — only the kinds the window has rows for (plus the chosen one, so a filter never vanishes under its own result); the row hides when nothing in the window has a method. It stacks with the search; the total row is over what is showing.
- The chip left the memo cell; the memo is the memo.
