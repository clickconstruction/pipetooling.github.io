# v2.6707 — person_available_hours: the answers table for Utilization (train PR 1) (2026-11-08)

The Utilization train (a design spike the owner ran on 2026-11-08: a People view that reads the hours each person said they can work against what the clock recorded, so a dev knows when to add people or use people more) ships as three PRs. This is the first: the migration alone, `20261108175919_person_available_hours.sql` (`docs/migrations/20261108175919_person_available_hours.md`). Nothing on screen changes.

## What changed

- **`person_available_hours`**: one append-only row per answer — `hours_per_week`, `days` (the week as drawn: seven JSON arrays, Sunday first, of `[start, end]` minute pairs on the company clock; NULL for a number alone), `effective_from` (the Sunday it holds from), `note`, `set_by`, `created_at`. RLS reads for the clock's readers (dev, assistant, controller, payroll access) and one's own rows; inserts stamped with the caller, one's own or, for those roles, anyone's; no update or delete; the four fences.
