# v2.2833 — Hours approvals queue: the name door sits beside the person toggle (2026-09-05)

Fix for a React DOM-nesting warning that fired every time the all-weeks approvals queue opened (People → Users → clock cell): `validateDOMNesting: <button> cannot appear as a descendant of <button>`.

- **Cause** — [`PeopleHoursApprovalsQueueModal.tsx`](../../src/components/people/PeopleHoursApprovalsQueueModal.tsx) `renderPerson()` rendered the person's collapse toggle as a `<button>` whose children included [`PersonNameDoor`](../../src/components/personDesk/PersonNameDoor.tsx), which is itself a `<button>` when the viewer can open the Person Desk (v2.2713).
- **Fix** — the header row's left group is now a plain flex wrapper with two siblings: the `PersonNameDoor` (bold name, still the Desk opener) and the toggle `<button>`, which wraps only the chevron, the summary text (sessions · hours · weeks · oldest) and the `FlagSummary`. `aria-expanded` stays on the toggle; it also gets an `aria-label` naming the person and the counts, since the name is no longer part of its accessible content. Same row, same typography, same flex-wrap behavior on narrow widths.

No migration, no edge deploy. `npx vitest run src/components/people` + typecheck green.
