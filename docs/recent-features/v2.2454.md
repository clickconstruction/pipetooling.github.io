# v2.2454 — Edit Bid: RLS-refused saves are no longer silent (2026-08-28)

Found by the digital-twin M3 fence probe (results table in
`docs/twins/missions/estimator.md`): when row-level security filters the target row
out of an UPDATE — the twin write fence editing a bid it doesn't own, or a bid
deleted by someone else mid-edit — Supabase returns success with **zero affected
rows**. Both Edit Bid save paths (`saveBid`, `saveBidAndOpenCounts` in
`src/pages/Bids.tsx`) treated that as a successful save: modal closed, no error,
changes gone.

- New kernel `src/lib/bids/updateGuard.ts` (+tests): `updateApplied(rows)` and the
  shared `BID_UPDATE_NOT_APPLIED_MESSAGE`.
- Both update paths now append `.select('id')` and, on zero rows, keep the modal
  open with the error ("Save didn't apply — you don't have permission to edit this
  bid, or it no longer exists").
- INSERT paths were already loud (RLS violations error on insert — that's how the
  fence probe's second half surfaced); this closes the UPDATE half.

Known sibling not touched here: the mark-lost chips' loss-reason update
(`Bids.tsx` ~1797) can no-op the same way; different surface, separate change if
wanted.
