# v2.4822 — Moving a payment Stripe holds: the right words, and no Stripe bill left open (2026-10-07)

Client only; no migration, no edge function. Punch list #98 (`to-dos/held-stripe-marks/README.md`), from the test-mode run of [v2.4801](v2.4801.md) and [v2.4803](v2.4803.md) on two throwaway jobs the same day.

## What the run found

The run (J904 and J907, *ZZ TEST held check A/B*, a Stripe **test** bill on A, a HouseCall Pro bill on B) passed both recipes, and showed four faults in the Move window on a payment Stripe holds:

- **"Check" for any payment.** The Stripe-held row it moved was cash (the only way left to get a bill marked paid in Stripe at once, since a check now waits). The window said *Move this check*, *Stripe holds this check as paid*, *The $10.00 check pays…*.
- **"Held for seven days like any check" for any bill.** The landing step said it for B's HouseCall Pro bill, which Stripe never sees.
- **A Stripe bill left open behind a Paid bill.** Not hit on the run, read from the code while fixing the words: a whole cash payment landing on another job's open **Stripe** bill went through `mark_invoice_paid` alone, so the app read Paid while the Stripe invoice stayed open, and the sweep (`close-held-stripe-marks`) never closes it because it only closes checks. A part payment there would also have skipped the credit note that lowers the pay link.
- **The moved line said the job twice**: *$10.00 moved → J907 · ZZ TEST held check B · Robert · Moved to J907 · wrong job*. The event carried the credit note's reason instead of the office's.

## The fix

- [`stripeHeldPaymentMove.ts`](../../src/lib/jobs/stripeHeldPaymentMove.ts): `heldMoveNoun` (check or payment), `stripeHeldMoveTitle` / `stripeHeldMoveIntro` / `stripeHeldMoveDoneWords`; `planHeldLanding` returns what is left on the bill and whether it is a Stripe bill; **`heldLandingWrite`** follows Mark Paid's rules on that bill — not a Stripe bill, or a whole-balance check: `mark_invoice_paid` (the check is held for the sweep); any other whole payment on a Stripe bill: `mark_invoice_paid`, then `record-stripe-invoice-out-of-band-payment` with `allow_app_paid` (the Accounts Receivable close, v2.1639); a part payment on a Stripe bill: the same function's credit-note path, which writes the row and returns its id. The steps say which (*…and Stripe closes that bill at once*, *…pays part of J922's $9,000.00 bill, and its pay link asks for the rest*, *…Stripe closes that bill the next morning, since the check is over seven days old*). A new stop, `close`, says what to do when the bill landed but Stripe did not close it. `heldMoveEventRow` keeps the office's reason alone; the credit note's memo and the `removed` event keep *Moved to J907 · wrong job*.
- [`JobPaymentMoveModal`](../../src/components/jobs/JobPaymentMoveModal.tsx) runs those writes; its Stripe calls on the landing carry no mode, so the bill's own row decides it, as Accounts Receivable's close does.
- [`heldStripeMark.ts`](../../src/lib/jobs/heldStripeMark.ts): `heldStripeMarkNote` takes today, so a check dated over a week back says *Stripe closes the invoice the next morning* (the run's back-dated check read *on Oct 6* on Oct 7); the line under it says *the next morning* instead of *the next sweep*.
