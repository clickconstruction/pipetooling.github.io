# v2.6141 — Supply-house bills on a thread: Not a bill and Record this bill take the offer away (punch list #179, a follow-up) (2026-10-30)

The thread door's live walk of 2026-10-30 (a ZZ forward from Robert's mailbox to team@, named as ZZ Test Supply) found both of a bill's answers refused by the database:
- *Not a bill* on the October statement sent `paper_answer = 'not_it'`. It came back 400, `23514 … violates check constraint "message_attachments_answer_to_a_guess"`.
- *Record this bill*'s `filed`, which `markRecorded` writes after Save, hits the same check. Its `.catch` swallows it, so the offer would have stayed under a recorded bill.

The check dates from the W-9 and certificate offers (`20261013080000`). It allowed an answer only where the reader guessed a paper, and v2.6095's bill offer has no guess.

## What changed

- Migration `20261030080000_bill_answer_on_a_kept_file.sql` (`docs/migrations/20261030080000_bill_answer_on_a_kept_file.md`) replaces the check with `message_attachments_answer_to_an_offer`. An answer stands on a guessed paper, or on a file we keep a copy of. A link, or a file left in Gmail, still takes none.
- No client change. `PaperOffers`' *Not a bill* and the form's `markRecorded` were right all along, and start working once the migration is pushed.

## Deploy

`supabase db push` (the migration), any time after the merge. Nothing waits on it.
