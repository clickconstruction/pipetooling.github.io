# v2.2904 — Papercut batch B20: a job's birth is logged, price edits carry an author, every RFQ has a creator, last-contact edits leave a trace (2026-09-05)

Journey map Phase 4, **Tier-3 batch B20** (`JOURNEY_MAP.md` → "Authorship & events (C43 — the standing rule, applied to old tables)"; findings J1-F10 · J15-F7 · J11-F9 · J12-N3 · J10-F11 · J14-N1 · J29-N4 · J16-F1; family TELEMETRY-BLIND). One migration, one client kernel entry, no UI files touched.

**Why.** C43's root: every `jobs_ledger` activity trigger is `AFTER UPDATE`, so a job's birth (and its bid import) was structurally unloggable — Tier-1 #8 (v2.2859) could only drop a `job_created{source}` row into `ui_nav_clicks`; `bid_pricing_assignments` / `bid_count_row_custom_prices` carried `created_at` only; the RFQ copy lane minted rows with `created_by: null` until v2.2851 stamped it client-side; New Bid's Last Contact wrote `bids.last_contact` with no `bids_submission_entries` row behind it. Same standing rule ("rework ships with event logging"), different tables — `bid_count_row_custom_costs.applied_by/applied_at` (v2.2655) is the model.

## What changed

Migration **`20260905233000_authorship_events.sql`** (see `docs/migrations/20260905233000_authorship_events.md`):

1. **Job birth event — done.** `jobs_ledger_birth_to_activity()` (SECURITY DEFINER, `AFTER INSERT ON jobs_ledger`) writes one `job_activity_events` row, `event_type = 'job_created'`, `summary` = *Job opened* / *Job opened from bid B398* / *Job opened under a project*, `detail = {source_id: <job id>, source: bid|project|manual, bid_id, bid_number, project_id, status}`, `financial = false`, actor `auth.uid()`. Skips service-role inserts (`auth.uid()` null) because `auto_create_job_from_signed_estimate` already writes its richer `job_auto_created_from_estimate` row — a second generic line would be noise. **Backfill**: every existing job with a `created_at` and no birth row of either type gets one at `created_at` (actor null, `detail.backfilled = true`); idempotent on `(event_type, detail->>'source_id')`. Client: `job_created` added to `JobActivityEventType` + `JOB_ACTIVITY_EVENT_RENDER` (`Opened`, green, `status` bucket) in `src/lib/jobActivityEvent.ts` — the RPC mapper drops unknown types, so without this the row would never render. *Not done*: bid surfaces reading the birth row — `BidWonJobActions` (v2.2859) already shows the job the bid opened via `useJobsOpenedFromBid`; surfacing *who* opened it there means a second query into `job_activity_events` per bid, not a trivial read.
2. **Author on price/margin edits — done (DB-side).** `bid_pricing_assignments` and `bid_count_row_custom_prices` gain `updated_by uuid → users(id) ON DELETE SET NULL` and `updated_at timestamptz NOT NULL DEFAULT now()`; new reusable `stamp_updated_by()` (`BEFORE INSERT OR UPDATE`) sets `updated_at = now()`, `updated_by = coalesce(auth.uid(), new.updated_by)`. Pre-existing rows have `updated_at` set back to `created_at` (run before the trigger is attached, or the stamp would reset it) and `updated_by` null (unknown). No client write changed — every path (book assign, override, custom price, workbench batch fill, apply-picks) is stamped by the trigger; `src/types/database.ts` carries the two new columns + FK relationship on both tables (hand-added; the next `gen types` run reproduces them). Margin itself is not a stored column — the Pricing workbench solves a margin into per-row `bid_pricing_assignments` / custom-price writes, so authoring those rows *is* authoring the margin edit.
3. **`created_by` on every RFQ — done.** `bid_rfqs.created_by` gets `DEFAULT auth.uid()` plus `stamp_created_by_if_missing()` (`BEFORE INSERT`, fills only when NULL — the edge functions' explicit `sender.id` always wins). The copy lane's client stamp (v2.2851, PR #2594) stays; this is the floor under it. Same default + trigger on `bids_submission_entries` (the note ledger had `created_by` null for legacy rows and any future lane that forgets).
4. **New Bid Last Contact leaves a ledger entry — done (DB-side).** `bids_seed_last_contact_entry()` (`AFTER INSERT ON bids`, SECURITY DEFINER): when a new bid arrives with `last_contact` set and **no** `bids_submission_entries` rows, inserts one row at that time with `contact_method = 'Other'`, notes *Last contact entered by hand on the New Bid form (no method recorded).*, `created_by = auth.uid()`. `sync_last_contact_from_entries` then computes the same max and leaves the column alone. Duplicate-bid / adopt-as-version RPCs don't copy `last_contact`, so they never trip it; a deleted-records restore of a bid whose entries are gone would seed one line (acceptable — it is the only story that bid has).
5. **Packet Won logs a note — verified, not redone.** `gcPacketOutcome.ts` → `writePacketNote` runs on the Won cascade (`finish`) and on the undo, whenever an `actor` is passed (every client writer does since v2.2894 / PR #2634). No change.
6. **Tally POs stamp the tallier — skipped here.** Client-side in B14 (in flight).
7. **CO paper with no record — skipped (no table).** Copy / Google Docs on `BidChangeOrderTab` remain a document generator; there is no `bid_change_orders`-style table to write, and the tracked record is an `estimates` row (`doc_kind = 'change_order'`) minted only by the Send-for-signature bridge. B4 owns the copy; a record row for the paper paths needs a schema decision first.

## Verify

1. After `db push`: Jobs → any job → Activity → the oldest row reads *Job opened* (or *Job opened from bid B…*) tagged **Opened**, dated when the job was created. Open a job from a won bid → a new *Job opened from bid B398* row with your name.
2. Bids → Pricing → assign a book price / type a custom price → `select updated_by, updated_at from bid_pricing_assignments where bid_id = … order by updated_at desc limit 1` shows you, now.
3. Bids → Pricing → Supply house prices → Copy with quote link → `select created_by from bid_rfqs order by created_at desc limit 1` is never null.
4. New Bid with Last Contact typed → Save → Edit Bid → the story panel shows the *Other* contact at that time; `bids.last_contact` equals it.
5. `select count(*) from job_activity_events where event_type = 'job_created'` ≈ jobs with `created_at`, minus those with a `job_auto_created_from_estimate` row.
