# v2.3775 — The Ready-to-Bill remainder nets each open bill to what is still unpaid on it (2026-09-23)

Taunya, Springtown HVAC (job 978): "There's still $631 left to bill but when I try to create it, I get this red error message" — Bill Customer read **Nothing left to bill for this job** while the Progress & payment cell beside it read 83% Paid $2,999 · 1% Billed $54 · 16% Done, not billed $578 · Left on Job $631.

## Cause

The remainder everywhere is `revenue − payments_made − Σ open lines`, and every copy summed each open line's **face amount**. `payments_made` holds every payment on the job — including the $1,018.87 applied to the job's one billed line ($1,072.50) — so that line's paid part was subtracted twice: 3,630 − 2,999 − 1,072.50 < 0, clamped to $0, "nothing left". The line's unpaid $53.63 is all that stands against the job; $577.37 was left to bill. The same face-amount sum lived in the ensure RPC and in six client mirrors, so Edit Job → Make Invoice read $0 left and the Pipeline's Create partial invoice clamped to $0 on the same job.

## Fix

- **Migration `20260923233000_ensure_rtb_remainder_nets_invoice_payments.sql`** — `ensure_single_ready_to_bill_invoice_for_job` sums `GREATEST(0, amount − Σ payments applied to that line)` over the same rows (RTB + billed, never-sent primary excluded). Everything else byte-identical to `20260828170937`. Apply with `supabase db push` after merge; either order with the client is safe (the old client shows the old error and never reaches the RPC; the new client with the old RPC shows the right amount and the RPC's error on Send).
- **`src/lib/billing/openLineAllocation.ts`** (new, 19 tests) — `allocatedOpenCents(invoices, payments, { excludeRtbPrimary })`, `appliedCentsByInvoiceId`, `openLineCents`. One kernel for the sum; the RPC comment and this file point at each other.
- The mirrors now call it, each with a job-978 test: `proposedPrimaryRtbAmount.ts` (Bill Customer's plan; the modal passes the job's payments it already fetches), `wouldEnsureNothingLeftToBillForJob.ts` (Dashboard Prepare bill; the billed rows carry `invoice_payments`), `jobsStagesBoard.ts` (Pipeline remaining + the partial-invoice clamp, from `job.payments`), `jobFormBreakOff.ts` + `editJobBillingBar.ts` + `jobSegmentsCoverage.ts` (Edit Job's Make Invoice remaining, the slider's billed base, the bar, the ② strip's spoken-for hatching — `JobFormModal` and `useBreakOffSlider` pass the payments table).
- Not touched: `buildReadyToBillDashboardUnits.dashboardJobBillingUnallocCents` sees only RTB rows (no billed line can be there), and `jobBilledUnpaidDollars` / `invoiceOpenRemainingOnJob` already netted — they are what made the cell read $54.
