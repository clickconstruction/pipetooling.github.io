# v2.4756 — Legal desk: short, custom portal addresses for the firm (2026-10-06)

One migration (`20261007080000_legal_portal_custom_address.sql`, pushed after merge), two edge functions redeployed (`legal-portal`, `submit-legal-portal`), the office's Firm's link window and the guide. The owner's call on 2026-10-06, an hour after [v2.4750](v2.4750.md) shipped a twelve-character tail: *"I think I should make the code at the end much smaller like 4 digits or 3 digits … like: my.clickplumbing.com/snell-law-f6a … I want it to be 3 characters at the end, help me make this custom url and the tools to make custom URLs."*

## The decision

A three-character tail after a name anyone can guess is 46,656 keys, and a script tries them in a minute against a public function. The owner was shown that, with two ways to keep a short address: a six-digit passcode the page asks for once per device, or the short key alone with a throttle on wrong guesses. He chose the key alone with the throttle. So the lock is now the throttle, and the fragment says so plainly.

## What changed

- **The address is the office's to pick.** The window's editor ([`legalPortalAddressDraft.ts`](../../src/lib/legal/legalPortalAddressDraft.ts)) shows `my.clickplumbing.com/`, a name part the office types (lowercase, dashes for spaces, at most 36 characters; it starts as the first two words of the firm's name) and a three-character tail with a 🎲 (no 0, o, 1 or l, so it reads aloud). It sits under *Create the firm's link* and *Add a link*, and behind **Change address…** on every live link. The server checks the same shape (`legal_portal_address_problem`: 5 to 40 characters, ending in a dash and three characters) and refuses an address a customer or a sub already holds, because the `/p/` page resolves a customer first.
- **`create_legal_portal_link(firm, label, address)`** and **`rotate_legal_portal_link(link, address)`** take the address; null means a default one (`legal_portal_link_new_key`: the first two words and three rolled characters). A plain **Rotate** keeps the name part and rolls the tail; on a key from before (hex, or v2.4750's twelve characters) it mints a default address. **Change address…** is a rotate to the address typed: the old one stops working the moment the new one is saved, and the editor says so.
- **The throttle.** `legal_portal_misses` (service role only, RLS on, swept past a day) records every wrong key the two portal functions see, by caller IP ([`_shared/legalPortalGuessGate.ts`](../../supabase/functions/_shared/legalPortalGuessGate.ts), `legal_portal_guess_gate(ip, miss)`). A caller with ten misses in an hour gets 429 *Too many wrong links from this connection. Wait an hour, or contact the office for the right one.* before any lookup; the `/p/` probe and the firm's acts count too. A right key is never refused, so the throttle cannot lock the firm out. A caller with no address (`unknown`) is counted but never locked.
- The key is still kept hashed, with the raw address in Vault, as item 22 built it; the list reads it back as in v2.4750.

## Is this the best we can do?

- **How strong is it now?** Ten guesses an hour from one address. A guesser with a hundred addresses gets a thousand an hour, so the full 46,656 takes about two days of steady work against one name part. The office can make the name part less obvious than the firm's name, and a Rotate makes every guess so far worthless. That is the posture the owner chose over a passcode, and the passcode stays the next step if the firm's book ever asks for more.
- **Lock the firm's address outright after a storm?** No: that hands a stranger a way to shut the firm out. The throttle is per caller for that reason.
- **Keep the address in plain text now that it is short?** No. A table dump still holds nothing; Vault costs nothing more.
- **Why keep the hex and twelve-character keys working?** The firm's inbox holds the old link and the owner has a meeting on it. Nothing changes until the office presses Rotate or Change address….
