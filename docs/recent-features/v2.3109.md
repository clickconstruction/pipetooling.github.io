# v2.3109 — `/bid` skill + `scripts/twin/` toolkit (2026-09-07)

Infra. No client behaviour, migration or edge-function change. The bootstrap for a robot-estimator session moves out of one machine's memory notes into the repo.

## Why

Every twin session began by recreating the same helpers (a JSON-RPC caller for twin-mcp, a mint-session → JWT → REST helper, the plans probe, a ZZ-shell plans repointer) as untracked scratch files, then reading PLACEMENT, FEEDBACK_LOOP, the CT guide, EXTRACTOR and a memory prompt template to reassemble the pipeline order. Twenty minutes of setup and a fresh chance to skip a stage each time. "Bid it" should be one command.

## What shipped

- **`scripts/twin/`** (stdlib Python, no secrets): `twin.py <tool> [json]` (one twin-mcp verb), `twinrest.py [--as twin|dev] get|patch|post|rpc` (signed-in PostgREST/RPC — twin via `mint_session`, dev via `dev-login`), `probe_plans.py [--force|--bid]` (the v2.3080 plans-readable probe), `set_plans.py bNNN url [--apply]` (repoints a **ZZ shell only**, then probes), `twinenv.py` (URL/anon key from `.env.local`, key from `$TWIN_TOKEN_FILE` default `~/pt-twin-digest/twin.token`, dev secret from `.env.local`). `README.md` carries the one-time machine setup, including the one allow rule to add to the main checkout's gitignored `settings.local.json` (`Bash(python3 scripts/twin/*)`).
- **`.claude/skills/bid/SKILL.md`** — the project skill (versioned, like `db-freeze`): `/bid b482` shadow, `/bid next` dispatcher, `/bid backtest b376|next`, `/bid status`. It encodes the fixed order — score_shadows first, orient, blindness rules, STG-0 claim → STG-1 plans → STG-2 substrate → STG-3 takeoff → STG-5 counts/prices → LOCK → AUDIT questions → STG-6 (backtests only) → submit_report — with the hard rules (never send, never touch a bid that isn't yours, never invent a number without plans, at most two parallel agents, **every subagent as Fable**). Folder plans links and the `X-Plan-Parts` merge cap are described for the intake change shipping alongside.
- **`docs/twins/TWIN_HARNESS.md`** "Bootstrapping" section points at the toolkit and the skill.

All five scripts were run against prod on 2026-09-07 (queue read, `list_shadow_runs` as the twin, a dev-seat users read, a single probe, and the ZZ-only refusal path of `set_plans.py`).

## What stays on the machine

The twin key file and the settings allow rule. A second machine issues its own key from Settings → Digital twins.
