# v2.3184 — Pipeline: a live search hides the money story and the money moves (2026-09-08)

Client only — no migration. Owner, typing "diamond" into the Pipeline search: "When a user starts typing, I would like for it to hide everything between the search bar and Waiting (9) → Working (0) → …". That stretch is [`PipelineOverview`](../../src/components/jobs/PipelineOverview.tsx) — the four money-story cards, the contracts-signed card, and the Today's money opportunities queue (v2.1915) — a screen and a half between the query and its matches.

## What shipped

- Kernel flag `pipelineOverviewHiddenBySearch(query)` in [`pipelineOverview.ts`](../../src/lib/jobs/pipelineOverview.ts) (+1 test): true for any non-whitespace query.
- [`JobsStagesTab`](../../src/components/jobs/JobsStagesTab.tsx) renders `PipelineOverview` only while that flag is false. The overview's state (nothing local — it reads the header stats memo) is unaffected; it simply remounts when the search clears. The jump strip, the paid-match hint, and the sections below are untouched, so a query lands on `Waiting (9) → …` with the matches immediately under it.
- Help guide `read-the-pipeline-money-view.md`: one sentence on the behaviour.
