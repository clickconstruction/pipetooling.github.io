# v2.3227 — Count & import opens the Import Counts box itself, cursor in it (2026-09-10)

Client only; no migration.

## Why

Of the ten landings (v2.3216), Count & import was the one whose target was a button whose only job is to open a dialog — one press short of the paste box the step is about. The estimator's loop is CountTooling → copy → step 4 → paste; the ring on the button added a click every time.

## What shipped

- **The door opens the dialog** (`Bids.tsx` → `BidsCountsTab`): the page-level door handler bumps `openImportRequest` when the Count & import step is used; the Counts tab opens the Import Counts dialog (the paste box) once a bid is selected. Deliberately not `handleCountsImportClick`, which imports straight from the clipboard when it can — a person who clicked a step did not ask for that.
- **The landing prefers the paste box**: the step's targets are now `counts-import-text` (the textarea, new id) then `counts-import-tooling` (the button). `landOnBidFlowTarget` gained `preferFirstMs` (default 1.5 s): it holds out for the first target before accepting a fallback, because the button paints a beat before the dialog exists and would otherwise win every time. Tests cover both the hold-out and the fallback.
- **The board's doors go through the page** (`onOpenBidFlowDoor` on `BidsBidBoardTab`, preferred when present): one handler for every strip, so the board's Count & import opens the dialog too. Review stays local to the board (it is the Mark reviewed prompt).
- Help guide step line updated.
