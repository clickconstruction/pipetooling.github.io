# v2.2347 — Quickfill nudge sections: lost bids, GC weekly, job follow-ups (2026-08-26)

Owner request from the dashboard-vs-Quickfill notification audit (mockup-first
on the design canvas): the three dashboard nudges Quickfill lacked become
independent, markable Quickfill sections.

- **Three SECTIONS entries** (`Quickfill.tsx`): `lost-bid-reasons` (after
  Crew Jobs), `gc-weekly-review` and `job-followups` (after Billed Awaiting
  Payment). Gating = `warningsSectionEligible` (dev/master/assistant-like) —
  same posture as Warnings: the wrapper always renders for office roles so
  the Mark button can stamp the ritual on a clean day; the inner cards
  self-hide when quiet.
- **Content = the exact dashboard banners** (no forked copy):
  `DashboardLostBidsMissingReasonBanner` (fed by the new
  `useLostBidNudge` hook — the same whole-team query the Dashboard quick row
  runs inline; unify the quick row onto the hook when the Needs You
  follow-ups next touch that file), `DashboardGcReviewWeeklyBanner`, and
  `DashboardJobFollowupsBanner`.
- **Metric seams**: the two self-loading banners gain an optional
  `onCount?: (n: number | null) => void` prop (job-followups queue size; GC =
  GCs left to certify when the week is 'due', else 0) so
  `QuickfillMetricReporter` can feed the header counts and the phone
  freshness tally. Dashboard mounts pass nothing — zero behavior change
  there.
- Verified pre-push in the running app (a real Wednesday, conveniently):
  61-lost-bids card with Start call mode, "GC review is due today — 0 of 11
  certified" with Open GC Review, "12 jobs are waiting on a follow-up" with
  Start review; headers show 61/11/12 open; 375px shows no overflow.
