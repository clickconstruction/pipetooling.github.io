# v2.2421 — bids: shorthand/longhand style-mix fixes (2026-08-28)

React dev console was warning "Removing a style property during rerender … don't mix
shorthand and non-shorthand properties" on two bid surfaces — the same class of bug as the
v2.770 tab-pill fix (PR #450): when a longhand property (e.g. `fontWeight`) is added or
removed across rerenders while its shorthand (`font`) sits in the same style object, React's
style diffing resets the shorthand to the UA default, silently blowing away the styling.

Fixed by using longhands only:

- `BidFormModal.tsx` — the Win/Loss outcome segments mixed `font: 'inherit'` in the base
  style with a `fontWeight: 600` that only the selected segment's spread added; deselecting
  a segment removed `fontWeight` against the `font` shorthand. Now `fontFamily: 'inherit'`
  with an explicit `fontWeight: 400` base (selected spread overrides to 600), so the
  property updates instead of being removed. Two other `font: 'inherit'` + `fontWeight`
  buttons in the file converted to `fontFamily` for the same reason.
- `BidBoardGcRows.tsx` — `GcOutcomePill`'s `PILL_BASE` used the `border` shorthand while the
  won/lost variants overrode `borderColor`; split into `borderWidth`/`borderStyle`/
  `borderColor`. `font: 'inherit'` → `fontFamily: 'inherit'` in `PILL_BASE` and the GC-name
  link button.

Verified in the dev preview against BP398 (ZZ Test): toggled the GC pill
waiting → won → waiting and the Edit Bid segments Won → Open with zero console warnings;
computed `fontSize` stayed at the authored 0.82rem through the transitions (previously the
`font` reset would revert it to the UA default).
