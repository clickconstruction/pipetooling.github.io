# v2.7510 — Lien filings from a scan: the groundwork for recording them without a browser (2026-11-16)

PR 1 of the dev seat's lien filing verbs. The owner, 2026-11-16, after the office filed eleven lien affidavits at two county clerks and scanned what came back: "long term I would like to not have to use chrome and I would like to build the verbs". This PR is a move and a bucket. No verb and no screen change.

## The move

`buildLienAffidavitFieldsForJob`, `lienOriginalContractor` and `LienAffidavitJobFacts` moved from `src/lib/jobs/lienNoticeDraft.ts` to **`src/lib/jobs/lienAffidavitJobFields.ts`**. `lienNoticeDraft.ts` re-exports all three, so every import stands. The type `LienAffidavitFields` moved from `lienFilingDocuments.ts` to **`src/lib/jobsDocuments/lienAffidavitFieldsType.ts`**, re-exported the same way.

Why: the edge copy of the kernels (`scripts/edge-kernels.mjs`) refuses a file whose type imports reach a file that runs code. The recipe sat behind the cover letters and the settings file. It now names the company by a shape of its own, `LienAffidavitIssuer` (name, mailing address, physical address, signing county), as `lienNoticeJobFields.ts` did for the notice in v2.7229. `lienDeskAffidavitFields.ts` imports from the new files, so the next PR can add it to the copy and the seat can fill a filing's snapshot with the desk's own recipe.

Nothing in the recipe changed. `lienAffidavitJobFields.test.ts` holds the re-export to the one function.

## The bucket

Migration `20261117100000_dev_seat_staging_bucket.sql` ([its doc](../migrations/20261117100000_dev_seat_staging_bucket.md)): a private storage bucket, `dev-seat-staging`, where a file an agent hands the dev MCP server waits between its plan and its apply. A dev alone, inside the folder named for their own user id. 10 MB a file, a PDF or a picture.

The seat already takes a staged file one way: `plan_file_plans` hands back a signed upload address in the `bid-submittals` bucket, keyed by a bid. A lien's scan belongs to a job, and a scan is 485 KB, far too large to pass as base64 in a call. So the seat gets a staging bucket of its own.
