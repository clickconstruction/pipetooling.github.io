# v2.5783 — GC mode: a guide to the gaps between trades, from the walk's Gaps stop and the card's red line (2026-10-23)

The owner, 2026-10-23, with the walk's Gaps stop on screen: "as we take in bids those bids have exclusions and we need to list them to fill in what we still need to find to get the job completed. I have not gotten to that part of testing the app, but I would like to first make sure we do a good job explaining this to a user." The flow was walked end to end on the test project (the quote with an exclusion, the card, Compare quotes, the cover, Our number); the one logic hole it found shipped as v2.5779. This PR is the words and the doors.

- **The guide** ([`fill-the-gaps-between-trades-on-a-gc-project.md`](../../src/content/help/fill-the-gaps-between-trades-on-a-gc-project.md), share page `/g/fill-the-gaps-between-trades-on-a-gc-project/`): the two kinds of gap, each with where it shows and what closes it. A **known exclusion** is set at New project's Each scope step, where *Gaps between the trades* has **Add it to HVAC** and **Add HVAC**; on a project already made the scope changes only through **A new set of plans came in** (its *+ Add a line this set brings*), which the guide says in a fold. A **quote's exclusion** is closed in Compare quotes with a cost to cover it, and the guide says which rows need none (a Known exclusion another trade does, a unit price for if it comes up) and what *+ ?* and *Set the missing cost* mean. The three ways a gap closes are named in one paragraph: another trade, us, the owner.
- **The walk's Gaps stop** ([`tour.ts`](../../src/lib/gc/tour.ts)): the sentence after the example now says a quote can leave work out too and that Compare quotes lists each one with a box for our cost; the stop carries `guide`, a new `SpotlightTourStep` field ([`SpotlightTour.tsx`](../../src/components/SpotlightTour.tsx)): a link under the body that closes the walk. The footer's guide stays the page's.
- **The card's red line** ([`GcProjects.tsx`](../../src/pages/GcProjects.tsx)): **How to fill a gap →** after the gaps, the same guide. Before, the line was the one red thing on the card with no door.
- **Tests**: `tour.test.ts` (the stop's guide and that the guide file exists, the card's line opens the same slug), `SpotlightTour.render.test.tsx` (a stop's guide link draws and closes the walk), and the four guide suites (content, plain words, links, share card) over the new guide.
- **Docs**: `APP_DIRECTORY.md` (the gap line and the guide), `PROJECT_DOCUMENTATION.md` (the Gaps stop), `GLOSSARY.md` (a gap, in the GC project entry).

## Is this the best we can do?

- The guide says what the app does today, including the awkward part: a known-exclusion gap on a live project has no button of its own, only a new set of plans. Writing around that would have left the owner's first real gap unfixable from the page.
- One field on the tour step instead of a Gaps-only prop: the next walk whose stop deserves its own guide gets it for free.
- Left for the owner, as findings from the walk (not built): a trade's known exclusions and scope lines cannot be edited after the project is made, so the red line's natural doors (**Add it to HVAC**, **Mark it the owner's**) do not exist yet on a card; a quote's exclusion cannot be marked as the owner's or another trade's after the fact, only given a cost, so an owner-furnished item has no honest mark on a live project; the portal's quote form offers the trade's usual exclusions but not the ones our scope book learned (`exclusionsFor(trade)` without the book); and the word *gap* is used on the card for one kind and *+ ?* for the other, which the guide bridges but the screens do not.
