# v2.6167 — One New Bid on a phone: an estimator's Bids page no longer repeats the header's Bid press (2026-10-30)

Fix, no migration, no edge function. The owner's second item of the Bids tab day: *if someone has "bid" in the header they don't see "new bid" on the bid board on mobile*.

## Cause

`Layout.tsx` draws a blue **Bid** press in the app header for an estimator (`role === 'estimator' && !farmModeActive`), on every page and every width; it opens New Bid through `/bids?new=true`. `Bids.tsx` draws its own **New Bid**: at the right of the tab row on a wide screen (≥1151 px), and below that on a row it shares with the trades, directly under the header. An estimator on a phone saw the two presses a thumb apart.

## Fix

- **`lib/headerTaskDispatchEstimatorEligible.ts`**: `showHeaderNewBidButton(role, farmModeActive)` — the header's rule, in one place beside the header's other presses. `Layout.tsx` reads it where the literal was.
- **`Bids.tsx`** reads the same rule (Farm Mode from `useFarmModeEnabled`, as Layout does) and draws its New Bid only when the header is wide or the header has no Bid press. The empty lists' *New Bid* press (`onNewBid`) is untouched: an empty pile still names its press whatever the width.
- `BIDS_TABS_ARCHITECTURE.md` (the header paragraph).

## Tests

- `headerTaskDispatchEstimatorEligible.test.ts` (+3): the estimator's press and Farm Mode; every other role and no role; Layout draws the header press on the rule alone (the literal is gone).

## Verified

Dev server from the worktree at 375 × 740: as the estimator twin the Bids page draws one *Bid*/*New Bid* press (the header's) and as the dev it draws the page's own; at 1,400 both roles draw the page's New Bid at the tab row's right as before.
