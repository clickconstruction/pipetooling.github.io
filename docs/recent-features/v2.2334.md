# v2.2334 — Nav-click telemetry (CX measurement plan, step 2) (2026-08-26)

Owner decision from the CX audit: keep the dashboard as is, measure how people
actually navigate for ~3 months (decision checkpoint ~Dec 1, 2026), and let the
data drive the bigger redesign. Complements `user_app_activity_page_daily`
(time-on-page, recording since 2026-07-03) with the click half.

- **Migration `20260826141136`**: `public.ui_nav_clicks` — append-only rows
  (user_id, role, control, target, from_path, occurred_at). RLS: authenticated
  INSERT own rows only; SELECT `is_dev()`; no UPDATE/DELETE policies. Both
  read-only sweep calls (read-only training users' clicks are not recorded —
  acceptable, they're not real usage). Details:
  `docs/migrations/20260826141136_nav_click_telemetry.md`.
- **Kernel `src/lib/navClickTelemetry.ts`**: `resolveNavClick` (pure — nearest
  `data-navtrack` ancestor names the control, the clicked `a[href]` is the
  target; jsdom-tested) + `recordNavClick`/`recordNavClickFromEvent`
  (fire-and-forget, single attempt, errors swallowed — same posture as the
  activity heartbeat; navigation never waits on it).
- **Instrumented chrome**:
  - `Layout.tsx`: one capture listener on the `<nav>`; regions marked
    `data-navtrack` — `top-nav` (default), `gear-menu`, `mobile-menu`,
    `icon-cluster`.
  - `DispatchModeFooter` (dispatch + job variants): `bottom-tab` via the
    button onClick (component now reads `useAuth` itself).
  - Dashboard `SectionDock`: new optional `onChipClick` seam → control `dock`,
    target `#<section-id>` — this is the series that answers which of the 12
    dock sections earn their place.
  - `DashboardPinnedQuickRow`: the three navigating banners (AR deposits,
    stale tally, lost-bid reasons) record control `banner`; pin chips and
    quick-action buttons record `pin` / `quick-button` via the delegated
    listener. Self-contained banners (team reviews, roadmap needs-name,
    job follow-ups, GC weekly) are NOT yet instrumented — noted for a
    follow-up if their numbers matter.
- **`scripts/audit-nav-usage.sql`** (read-only): the measurement queries —
  60-day page-minutes by role, top pages, near-zero pages, click rollups, and
  the dock-section ranking. Header carries the psql session-pooler one-liner.
- **Deploy order note**: client may deploy before the migration is pushed; the
  insert fails silently until `supabase db push` lands the table (by design).
  After push: `npm run gen-types:linked` (the kernel uses an `as any` insert
  until then — swap to typed once regenerated, or leave; house pattern allows it).
