# v2.2521 — BT-2 learnings: seam dedup, developed length, sheet coverage (2026-08-30)

First three items of the BT-2 (b405 / MPH Casa Linda) build list from the
[pipeline STG-6] scorecard:

- **Tile-seam dedup** (`dedupeSeamMarks` in `src/lib/takeoffPlacement.ts`): the
  crop-tile walk reads overlapping tiles, and BT-2's FD-2 counted 12 vs 11 off a
  ~22 px seam pair. Same-counter same-page marks within 24 raw px (at each mark's
  dpi; mixed-dpi pairs use the wider window) collapse to one; the assembler
  (`scripts/placement-engine/assemble.ts`) runs it by default, prints every drop,
  and `"seamDedupePx"` in the manifest overrides (0 disables).
- **Developed-length model** (`DevelopedLengthFactor`, `developedFeetBySystem`,
  `DEFAULT_DEVELOPED_LENGTH_FACTOR = 1.6`): twin footage ran 55–65% of the human
  reference on every system even after vertical allowances — the residual is
  developed length (fitting take-up, offsets, sub-resolution laterals). Manifest
  `developedLength` factors scale DRAWN feet inside the size-split tooling rows
  (price-book names still match); allowances ride unscaled; the assembler prints
  drawn × factor = developed per system, and uncovered systems are reported
  carried-as-is. Doctrine section + recalibration duty added to
  `docs/twins/PLACEMENT.md`.
- **Sheet-coverage doctrine** (`docs/twins/PLACEMENT.md`): the sheet inventory is
  a checklist — every sheet walked and accounted for in the import note, demo
  plans (PD-*) counted as demo-scope counters on a `Demo` canvas (BT-2's unread
  PD-100 hid 27 demo fixtures ≈ $13.5k).

Tests: seam-dedup pair/mixed-dpi cases, developed-length row scaling +
per-system report in `takeoffPlacement.test.ts` (35 total).

Remaining BT-2 items (separate work): robot price book reshape (loaded fixture
