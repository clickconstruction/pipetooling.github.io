# v2.8295 — Permits: a lawn sprinkler permit no longer reads as Has a plumber (2026-11-22)

The first of the things punch list #307 left when it closed. Its card had it under *Found in passing, not fixed*: `research_permits` pairs any plumbing-kind permit on an address with a building permit, so an irrigation permit can close a building permit as *Has a plumber* on the skim. The owner's word on 2026-11-22: do it here now. One migration, no client change.

## What was wrong

A city files lawn sprinklers, gas lines, sewer taps and backflow under plumbing, and the pull stores them all as plumbing. San Antonio holds 12,741 irrigation permits that way, beside 17,269 general plumbing permits. The reads behind the skim, the ledger, Builders and Market paired any of them with a building permit.

Counted on prod, read only, over the last 180 days of San Antonio's commercial building permits: 842 buildings, 319 reading **Has a plumber**. Seven of those had an irrigation permit and nothing else. One had only a gas, sewer or repair permit.

## What changed

- **Only the building's own plumbing permit counts.** That is a general plumbing permit, or a plumbing type with no qualifier, which is how the other four cities file theirs.
- **It is the rule a bid's window already reads by.** `plumbingTypeOf` has told general from gas, sewer and irrigation since #307's first panel. The skim now agrees with it.
- **Every read that pairs a plumbing permit follows**: the plumber and his day on the skim and the ledger, a builder's open count, the permits said as *at this address, not counted*, a job's first plumbing day on Market's clock, and a builder's plumber on Builders.
- **A sprinkler permit is no longer listed as a permit at the address either.** It is not plumbing news.

Eight San Antonio buildings read as waiting again. Austin, New Braunfels, San Marcos and Seguin read as before: 943 Austin buildings, 303 taken, with the rule and without it.

## How it is built

- `permit_is_building_plumbing(permit_type)` holds the rule in SQL, and the five reads ask it beside each `kind = 'plumbing'`, nine places.
- The migration was built by script from each read's newest file. Each body was held against prod's own by its md5 before a line was added, and all five matched.
- The rule in SQL and the rule in the client are two copies. A test and the bed each hold the same thirteen types, every plumbing type prod has, so one cannot change without the other failing.

## A call that was made

The fault as written names irrigation. The rule taken is the wider one the bid's window uses, so a gas-only or sewer-only permit does not say a plumber has the building either. The difference today is one building in 180 days. A building wrongly waiting costs one call. A building wrongly taken is never called.
