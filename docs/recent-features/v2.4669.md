# v2.4669 — Legal portal: the firm's link behaves like a key (2026-10-05)

Two edge functions (`legal-portal`, `submit-legal-portal`, deploy after merge), the firm's page and the office's Firm's link dialog; no migration. Item 22 of punch list #85 ([`to-dos/legal-portal-firm-ready/`](../../to-dos/legal-portal-firm-ready/README.md)), the functions-and-dialog half; the hash-only token at rest is its own PR with the migration. Mockup: `mockup-22-headers-links.html` beside the card — the headers, the PDF link life, and the two confirms before and after.

## What changed

- **Headers.** Every answer from both functions, the CORS preflight included, carries `Cache-Control: no-store` and `Referrer-Policy: no-referrer`.
- **Signed PDF links: fifteen minutes.** `legal-portal` signs the agreement PDFs for `SIGNED_PDF_SECONDS = 15 * 60` (was 3600). A link copied out of the page, or still on the screen of a firm whose link was just turned off, stops opening a quarter of an hour later.
- **The page reloads before they die.** `LegalPortal.tsx` remembers when the payload arrived and reloads it quietly once it is ten minutes old ([`src/lib/legal/legalPortalFreshness.ts`](../../src/lib/legal/legalPortalFreshness.ts), `portalPayloadIsStale`): when the tab comes back into view, on window focus, and on a one-minute check while it is in view. The selected matter and tab stay. The sample never reloads.
- **No referrer from the page.** While the portal is open it adds `<meta name="referrer" content="no-referrer">`; its PDF links already carry `rel="noreferrer"`. The page's own address holds the firm's key.
- **The hash first.** Both functions look the link up by `token_hash` and fall back to the raw `token` column, the other way round from before. Harmless now, and the hash-only migration can land without another function change.
- **The office's confirms** ([`src/lib/legal/legalPortalLinkWords.ts`](../../src/lib/legal/legalPortalLinkWords.ts)): **Rotate** now asks (it minted on one click before): *The link … has now stops opening at once. That includes the link in every email already sent to the firm. Send the new link to the firm after you mint it.* **Turn off** adds the same sentence about the emails.

- **Integration pass (review fixes).** A quiet reload that fails keeps the payload already on screen and says so on the notice line (*This page could not refresh itself just now…*), never swapping the page for the error card. The quiet reload sends `&refresh=1`, and `legal-portal` writes no `public_page_views` row for it, so a firm reading for an hour is one visit. The Rotate confirm reads *The link {firm} has now stops working the moment you mint a new one.* Renumbered from v2.4629, which another PR took on main.

## Is this the best we can do?

- **Does a Referrer-Policy on a JSON answer protect anything?** Barely; a JSON answer opens no links. The real path is the page's own address, so the page sets a no-referrer meta while it is open. The header stays as a cheap default.
- **Will fifteen-minute links break a firm that reads slowly?** They would on their own. The ten-minute reload is what makes the shorter life safe.
- **Why confirm Rotate?** It looks like housekeeping and silently kills every link in the firm's inbox. Now it asks and says to send the new link.
