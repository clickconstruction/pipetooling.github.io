# v2.2440 — clicktooling.com domain-cutover prep (2026-08-28)

Owner decision: this app moves to clicktooling.com; pipetooling.com stays on this app
forever as a path-preserving 301 (the old clicktooling.com app moves to
plumbingtooling.com separately). This PR is the zero-behavior-change groundwork —
current values everywhere, so nothing flips yet:

- **`src/lib/appOrigin.ts`** — client flip point (`APP_ORIGIN`/`APP_HOSTNAME`/`appUrl`);
  the three client call sites that hardcoded the domain now use it (PeopleUsersTab
  imitate gate + redirect, useGcPortalLinks and hazmatIncidents no-window fallbacks).
- **Edge functions** — every link-building function now reads the `APP_ORIGIN` secret
  with a pipetooling.com fallback (job-share already did; now also
  gc-statement-email-dispatch, invite-user, send-sign-in-email, billed-report-email
  render, payment-forecast render, send-scheduled-reminders, twin-mcp mint default).
  Cutover for ALL email links = set one secret, no redeploys. Functions redeploy with
  their next regular deploys; until then their baked fallback is identical behavior.
- **Auth allowlist** — `https://clicktooling.com/**` added in config.toml (inert until
  `supabase config push`).
- **`docs/DOMAIN_CUTOVER.md`** — the full runbook: prerequisites (DNS, GitHub domain
  verification, evacuating the old clicktooling.com app), the ordered cutover-day steps,
  post-cutover items (PWA reinstall + push re-subscription comms, cosmetic text sweep,
  optional Resend domain move), and what deliberately never changes (noreply sending
  domain, twin fleet emails, my.clickplumbing.com).

Found during prep (separate issue, CT side): CountTooling's auth `site_url` was still
the localhost default — twin magic links there redirected to localhost:3000. Local
`counttooling config.toml` now carries the correct values mirrored against remote;
applying needs an interactive `supabase config push --project-ref hrqxvfydmvtvwhvefmqc`.
