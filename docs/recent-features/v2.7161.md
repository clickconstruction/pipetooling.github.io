# v2.7161 — Materials on site: Count this box no longer steps over a line (2026-11-13)

Found by the review of Materials → On site (2026-11-13), read in the code and then shown by a test. Tally → On site → a box → **Count this box**.

## What was wrong

`TallyOnSiteTab.tsx` drew the walk from `ls.filter((l) => l.onHand > 0)`, read again on every step, and moved on with `index + 1`. A press writes to the store's cache first, so by the next render a line counted to none (**Not in A1 any more**, or a typed 0) had left that list, and every line after it had moved up one place. The walk then showed the line after the next one.

On a box with lines A, B, C, D, saying A is gone showed C next. B was never shown and wrote no `counted` row. The closing toast counted the shortened list, and the box stopped reading *due a count*, since any count row in a box sets its last count. The person had no sign a line was missed. Whether it has happened on a real box is not known: the ledger shows a count, not the lines a walk passed over.

## The change

- `src/lib/materials/countWalk.ts`, a pure kernel: `countWalkKeys` lists the walk's lines by part key when it starts, and `countWalkAt` reads the line at the walk's position fresh from the box, passing over one that has left the box since.
- The count view keeps `keys` in its state. **Count this box** sets them once. The position, the *2 of 3* and the toast's line count read that list.
- The guide *keep track of the material in the cages and boxes on site* names the walk's presses as the screen does.

## Tests

`countWalk.test.ts` (7), and a render test in `TallyOnSiteTab.render.test.tsx`: three lines, the first counted to none, then the second is on screen as *2 of 3*, three count rows are written and the toast reads *A2 counted. 3 lines, 2 corrected.* It fails on the tab before this change with the second line missing.

## Not changed

The walk still visits only lines with parts on hand, so a line at none with a Can't find on it is cleared by the office's Correct… alone. A fast second tap on **N is right** can still land on the next line's button. Both are on the review's list.
