# v2.4867 — People: Contracts lists archived people by who they are, not their name (2026-10-07)

Punch list #29 ([`to-dos/people-spine-residuals.md`](../../to-dos/people-spine-residuals.md)), item 3, the third id-first PR. It builds on v2.4862's `ArchivedRoster`. Client only.

## The change

- **[`splitNamesByArchived`](../../src/lib/people/rosterPeople.ts)** splits a roster listed by name into the living and the archived. Each row asks `isArchivedRosterRef` with its own id. A name is living when any row carrying it is living. The archived list holds the names of rows archived by id plus every archived roster name, less any name a living row carries. Living names keep their rows' spelling, because documents match on it.
- **[`PeopleContractsTab`](../../src/components/people/PeopleContractsTab.tsx)** takes `archived` in place of `archivedPeople` and `archivedUserNames`. Each `people` row asks by `person_id`, and each account by `user_id`. The v2.1409 rule still holds by id: a roster person whose linked account is archived is one archived roster row, so it folds.
- **The archived-people list leaves Contracts**, as it left Offsets in v2.4865. Its names had no namesake guard. The roster's names hold the same people, with the guard.
