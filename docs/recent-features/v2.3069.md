# v2.3069 — A job opened from a bid decides the bid, and says so (2026-09-07)

Per-GC bids Q1, open since Phase 3 and live daily since v2.2859 made the bid → job link routine. The owner's answer (2026-09-07): yes, auto-derive, so long as the person is told — a toast that lingers about five seconds.

## What shipped

- **Migration `20260907150000_bid_outcome_from_linked_job.sql`** — `AFTER INSERT OR UPDATE OF bid_id` trigger on `jobs_ledger`: a job that carries a `bid_id` marks that bid `outcome = 'started_or_complete'` (unless it already reads that). SECURITY DEFINER so it never depends on the job writer's `bids` access; skipped in digital-twin sessions; removing a link never clears an outcome. Covers every writer — the Job form, **Open the job** from a won bid, the signed-estimate auto-create, imports. Back-fills bids that already have a job (count in the push log).
- **The toast** — `src/lib/bids/bidOutcomeFromJob.ts` (pure, 4 tests): `shouldAnnounceDerivedOutcome(before, after)` fires only on a real move; `bidOutcomeDerivedMessage` reads *"Bid #1842 · Riverside is now Started or complete (was Won) — it has a job."*; `BID_OUTCOME_DERIVED_TOAST_MS = 5000`. The Job form reads the bid's outcome just before its own write and again after, on **create** and on an **edit that changes the link**, and shows the toast when the outcome moved. A save that lands in a twin session or is refused shows nothing, because nothing moved.
- **Docs**: `docs/BIDS_SYSTEM.md` outcome note; help guide *bid one project to multiple GCs* → "Turning the bid into a job"; the decision line retired; `to-dos/per-gc-bid-retirement.md` Q1 closed.

## Why a trigger and not the client

Three writers link jobs to bids and only one has a person in front of it. The trigger makes the rule true everywhere; the client's job is only to tell the person when it happened.

## Deploy

After merge: `supabase db push` (standing approval; the agent runs it), then `npm run check:migration-drift`.

## Verify

Open a job from a won bid on the Bid Board: the bid's pill reads *Started or complete* and the toast names the bid for five seconds. Edit Job → Import → a different bid: same. Re-save the job without changing the link: no toast.
