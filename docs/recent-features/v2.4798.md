# v2.4798 — GC mode: the schedule’s tables (2026-10-07)

PR 2 of the schedule's real build (`to-dos/gc-mode/SCHEDULE_REAL_BUILD.md`; its plan `to-dos/gc-mode/mockups/schedule-pr2.md`, both on branch `spike/gc-mode`): the schedule and its bars as tables, in `supabase/migrations/20261007210000_gc_schedule_tables.sql` (`docs/migrations/20261007210000_gc_schedule_tables.md`).

- Nine tables: `gc_schedules`, one row per GC project with a schedule drawn, with the version every plan write checks and bumps; `gc_schedule_activities`, `gc_schedule_activity_parts`, `gc_schedule_links`, `gc_schedule_milestones`, `gc_schedule_inspection_failures`, `gc_schedule_baselines` with `gc_schedule_baseline_dates`; and `gc_schedule_changes`, one line for each plan write, append only.
- Every table with a `project_id` references the schedule's own row, and both ends of a link are bars of one job.
- Dev only while it is built: one policy a table for `(SELECT public.is_dev())`, `anon` revoked, and the three house sweeps (read-only training mode and the twin fence).
- Nothing reads or writes them yet. The RPCs are the schedule's PR 5 and the first screen PR 7. The types come in the PR after the push.
