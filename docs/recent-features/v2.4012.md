# v2.4012 — GC Review: the pay date shows for GCs under $10,000 too (2026-09-28)

Client only; no migration, no edge function. Found in the live test of v2.3991: a word saved with a pay date on a $142.50 GC showed "warm · Sep 28" on its row and nothing about the date.

## Cause

The worklist row and the GC's header read the pay date from the Temperature board's rows (`boardRows` → `expectedPayByByGc`, `boardRowByGc.get(...)`). `buildTemperatureBoard` lists only the GCs at or over `GC_ROUND_THRESHOLD`, so a GC under the line had no row to read from. The temperature beside it never had the gap — it reads `latestTemperatureByGc(boardMarks)`, which covers every GC with a mark. A broken promise on a small GC therefore never turned red or sorted first either.

## What shipped

- **`latestExpectedPayByGc`** in `src/lib/jobs/temperatureBoard.ts` (2 tests) — per GC, the pay date on the newest word that gave one, by the word's own day; the same pick the board makes, without the line.
- **`JobsGcReviewModal`** — `payByByGc` feeds `buildGcWorklist` and the header pill. The board's own column is unchanged.

## Verified

- `temperatureBoard.test.ts`, the jobs and GC component suites (421 files, 3,337 tests), `npm run typecheck`, eslint on the touched files.
- **Live, as dev**: a test word with Oct 9 on a four-bill GC owing $5,410, every bill unticked so no promise was filed. The row read "$5,410.00 · 4 jobs · oldest 10d · pays by Oct 9" and the header carried the green "pays by Oct 9" pill. Undone from the row; the mark is gone and nothing else was written.
