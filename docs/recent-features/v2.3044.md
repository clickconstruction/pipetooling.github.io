# v2.3044 — Test-gap audit, pass 54: the Prospects team-activity loader gets its first tests (2026-09-07)

Follow-up to v2.3043. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`prospectTeamActivity.ts` (125 lines) is the loader behind **Prospects → Team** and the Quickfill prospects chart: the last thirty local calendar days of calling activity, per user per day — the unique prospects touched by timer events ("marked") and by comments ("updated"). The chart-data kernel beside it was tested; the loader was not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Eligible users are the office roles plus estimators who were granted Prospects access, ordered by name; events and comments are bounded to local midnight twenty-nine days ago through the end of today.
- The result is thirty zero-filled local days, oldest first, with every eligible user on each day, named by name, else email, else "Unknown".
- Counts are unique prospects per user per local day: repeat touches of one prospect count once, and a timer event with no prospect counts nothing.
- A failed read names its source and throws.

## What shipped

- **`prospectTeamActivity.test.ts`** (4) — a recording Supabase client passed in, the retry wrapper and error check mocked, fake local time so the day math runs in the test runner's own zone. Covers the user filter and window bounds, the thirty-day shape and naming, the unique-count rules, and the named failure.
