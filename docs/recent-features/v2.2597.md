# v2.2597 — AR billed-line dead-end steers to the recorded payment (2026-09-01)

User report (taunya, 2026-09-01): "I sent the job back to billed awaiting and it doesn't
come up when searched to apply the check to." Prod state of J989 (Montolongo- Pretest),
verified read-only via the dev session: job status `billed` (send-back worked), revenue
250 / payments_made 250, sole invoice status `paid` (job send-back doesn't touch invoice
status), one recorded $250 Check payment (ref 3403) with `mercury_transaction_id` null —
recorded by Mark Paid the day before the deposit was allocated.

**Not a data bug**: the billed-line picker (`bankPaymentTargetsFromStageRows`) correctly
lists only lines with a remaining balance — a marked-paid job has none. The deposit should
LINK to the existing recorded payment (the v2.1191 "Payment received" kind, listed by the
`list_unlinked_payments_for_bank_payments` RPC, which does include J989's payment). The gap
was discovery: the billed-line search dead-ends at "No matches" with no pointer.

**Fix**: the billed-line `SearchableSelect` in
[`BankPaymentsModal.tsx`](../../src/components/jobs/BankPaymentsModal.tsx) now passes a
`noMatchesAction` (the v2.1327 affordance): when the dead-ended query matches recorded
payments, the empty state offers "No billed line — but N recorded payment(s) match. Link it
instead"; pressing it switches the allocation line to Payment received and auto-picks the
payment when exactly one matches. New kernel
`arRecordedPaymentMatchesForQuery` in
[`arRecordedPaymentTargets.ts`](../../src/lib/arRecordedPaymentTargets.ts) mirrors
SearchableSelect's filter (case-insensitive substring on the option label), excludes
payments taken by other allocation lines; unit-tested with the J989 fixture.

- Complements v2.2591 (link-vs-create guard), which fires only after PICKING a billed line —
  this covers the case where there is no line to pick.
- Help guide `match-bank-deposits-to-bills.md`: new section "If the job doesn't come up in
  the billed-line search".
- Client-only — no migration, no edge deploy.
