# v2.7189 — Tasks: two lines that read wrongly (2026-11-13)

Punch list #348, PR 3 of 4. Two wordings the New task walk (v2.7155) saw.

## What changed

- **The roadmap's sentence doubled a full stop.** `roadmapTaskSentence` wrote `It joins the stage ${stage}.`, so a stage named with its own full stop read *It joins the stage North fence.. Nobody has it yet.* The name is now closed as a sentence once (`endedOnce` in `src/lib/tasks/newTaskWindow.ts`): its trailing full stops and spaces come off and one goes on. A name that ends in a question or an exclamation keeps its mark and takes none. A name that is nothing but full stops falls back to *It joins this stage.*
- **Edit task told a one-time task about days to come.** Every Edit task drew *Saving reshapes the days still to come. The ones already done keep their notes.* under the When row. A one-time task has one day. `editTaskWhenNote` shows the line when the task repeats as saved, or is being made to repeat in the window, since either save rebuilds the days ahead. `ChecklistItemEditModal` keeps `savedRepeats` from the loaded row.

## Tests

`newTaskWindow.test.ts`: one case for the stage name's ending (a full stop, a full stop and a space, three, a question, an exclamation, a lone full stop) and four for `editTaskWhenNote`, one of them the plain-words check. `ChecklistItemEditModal.render.test.tsx`: the line is absent on a one-time task, appears when **Repeats** is pressed, and is present on a task saved as repeating.
