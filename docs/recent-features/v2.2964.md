# v2.2964 — Test-gap audit, pass 2: the My Time day editor's two kernels get their first tests (2026-09-06)

Follow-up to v2.2958, which named these as the next targets. Tests only — no kernel, client, migration or edge-function change.

## Why these two

`myTimeDayTimeline.ts` (887 lines) and `myTimeDaySavePlan.ts` (532 lines) are the pure core under `DashboardMyTimeDayEditorModal` — the shared clock-day editor with 13 call sites whose save path writes `clock_sessions` and, through it, payroll (`MY_TIME_DAY_EDITOR_MODAL_ARCHITECTURE.md`). Every split, merge, drag and job assignment a person makes on their day runs through the reducer here, and every save decision (per-row UPDATE vs cluster RPC vs refuse) runs through the plan. Neither had a colocated test.

## What shipped

**`myTimeDayTimeline.test.ts`** (36 cases): the geometry constants (0.01 h minimum segment, 1 s contiguity, 60 s join snap and warning tolerance); boundary snapping and clamping; the contiguity rule (closed row, next starts within 1 s either side) and both cluster groupings; reference boundaries (join = later of clock-out / next clock-in, open last runs to now); the 1 s match tolerance; RPC-metadata sharing (origin + salary segment, `null` ≡ `undefined`); pairwise overlap at both tolerances and the split-on-overlap expansion; `finalizeInnerBoundaryMsForCluster` for homogeneous clusters (soft snap), mixed punch/salary clusters (a straddling boundary jumps to the nearest row join, ties to the earlier one; a seam between consecutive rows slides along the hull; a split inside one row stays inside it); the containment repair pass; the day timeline (gaps only over 1 s, open last to now); and the full `splitReducer` contract — drag/nudge clamp and clear overrides, `addSplit` halves the longest segment and shifts later overrides, tap-splits refuse near a boundary, mid-splits snap to a join, merge-with-prev keeps the earlier note first while merge-with-next puts the later note first, merges drop both merged overrides and shift the rest, and a merge that would leave the open last segment under the minimum is refused.

**`myTimeDaySavePlan.test.ts`** (18 cases): when a job assignment needs the split persisted first; when a merge needs the job-choice prompt (different allocations, unless both simply unlinked); allocation inference for a re-cut segment (largest overlap, ties to the earlier row, midpoint fallback); the three per-segment views (effective job, unlinked row ids, target row) in both aligned and re-cut states; the label ladder (map → truncated id → "No job or bid linked") and "Mixed allocation"; payload allocation precedence (override → aligned row → inference); and the mixed punch/salary save gates — per-row persist allowed for one segment per row or a partitionable single segment, refused when there are fewer segments than rows, the mismatch description text, the user message with details, an intermediate cross-row merge allowed while the hull can still be partitioned, and the coalesced partition's five refusal conditions plus one accepted shape.

Two first-run expectations were wrong and the kernels right: the open last segment's minimum is measured from its start to *now* (its stored end is ignored), and rows that overlap by more than 1 s already form separate blocks before the overlap option applies — that option only guards clusters built elsewhere. Both tests now say so.
