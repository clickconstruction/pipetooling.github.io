## What changed

- **EXECUTE on every public function is revoked from `PUBLIC` and `anon`.** anon could run 524 of prod's 868 public functions. Now it runs two, granted by name:
  - `get_hazmat_notice_by_token(uuid)`, the one call a signed-out page makes (`/hazmat-notice`)
  - `list_my_contract_dashboard_prompts()`, on the owner's word; for anon it returns nothing
- **New functions start closed.** `ALTER DEFAULT PRIVILEGES FOR ROLE postgres` drops `PUBLIC` globally and `anon` in `public`. A new public function gets `authenticated` and `service_role`, and a function anywhere else gets its owner only.
- **The two database agent roles keep working.** They reached their policy helpers only through `PUBLIC`, so the helpers are now granted by name:
  - `cost_agent`: `is_primary()` and `primary_can_access_job(uuid)`
  - `hr_agent`: `is_dev()`, `is_digital_twin()` and `is_read_only()`
- **`authenticated` loses exactly two:** `sync_controller_banking_attributors()` and its trigger function, which `20260804100000` meant to keep from it. The trigger still fires.
- **`supabase/tests/bid_changes/20_scenario.sql`** grants its `pg_temp.price_change()` helper to `authenticated`, since a new function no longer carries `PUBLIC` EXECUTE.
- **`docs/ACCESS_CONTROL.md`** amends the anon-key rules and the agent roles' paragraph:
  - grant a signed-out caller's function by name; no revoke needed
  - anon holds exactly two
  - the agent roles' helpers
