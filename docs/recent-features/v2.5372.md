# v2.5372 — Messages: a place for our own links to a job's Drive files, behind the scenes (2026-10-12)

Messages, cut 7a (GC Reviews helper 9, directed by the lead session GC Review): the data behind files going out, after cut 6's `message_attachments` (#5520). Migration `20261013110000_drive_links.sql`, note `docs/migrations/20261013110000_drive_links.md`. The mock-up is `to-dos/gc-mode/messages/files-out-mockups.html` on spike/gc-mode.

- **`drive_links`**: our own link to one file in a job's Drive folder (`clicktooling.com/f/<link>`). It keeps the link's SHA-256, never the link. It names the job as the spine ties a line (a bid, a GC project or a Pipeline job) and the file's half: Plans opens in Drive's viewer, Team only comes through the function. It ends 30 days after it is made, and it can be cut off. The office team reads it, and only the `drive-link` function (7b) writes it. The three house calls.
- **`message_attachments`** gains `sent_as` (the file, a link or the picture), `drive_link_id` and `drive_file_id`, each with its check. A file that went as the file keeps its bytes under `out/` in `message-attachments`, so the office's one page (cut 6's `/files/messages/<id>`) opens every file on a line.
- **`public_page_views`** takes the surface `drive_link`, one row per open.
- **`cut_drive_link`** (the office team, never a training account or a twin) and **`drive_link_views`**: the office's read-back of the opens, with each time and never a name, since a link cannot know who opened it (helper 1, 2026-10-12).
- **Bed**: `drive-links`, beside the files group in `scripts/sql-beds.txt`.
