# v2.5679 — Cover Letter: address the letter to any GC on the bid (2026-10-20)

Punch list #133 PR 1 (`to-dos/cover-letter-addressed-to/`), from Grace's 2026-10-20 report: the
letter's addressee was `resolveSingleLetterGc`'s — the active version's GC override, else the
bid's GC — so a same-letter GC (`bid_gc_recipients`) was recorded but their copy was never
produced, and she retyped the other builders' names by hand in the pasted Google Doc, per GC, per
revision. Owner's go on the recommended defaults: same-letter copies ride the bid's one sent date
(no migration), the room folds while one is addressed, and the row serves split bids too.

## The change

- **Kernel `coverLetterAddressees.ts`** (new, +tests): the addressee list — the bid's GC first,
  then every recorded recipient with no packet of its own (a packet GC's letter already follows
  its tab), deduped; `resolveAddressedCustomer` (the override, only ever a `shared` entry);
  `addresseeRowVisible` (two or more — single-GC bids never see the row);
  `bidDefaultPacketKey` (below).
- **`BidsCoverLetterTab.tsx`**: an **Addressed to** row in step 1 — the packet tabs (split bids)
  or the bid-GC chip, then each same-letter chip (dashed, "same letter"), then **+ GC**. A shared
  chip overrides ONLY `letterCustomer`, so the preview, Print, Copy and the Google-Docs copy all
  re-address while the amount, prices and wording stay; the "To …" caption reads "(same letter as
  {bid GC})"; Print and the copy buttons grow a "to {GC}" sub-line. The note under the row is
  honest about tracking (rides the bid's sent date) and offers **track separately**, which opens
  the strip's ＋ Add GC with that builder filled in (`bid-version-picker-open-add-gc` now accepts
  a CustomEvent `detail.gcId`; a bare Event still opens it blank). While a shared GC is addressed
  the Bid Room panel folds to a note — a room carries its own opens and signature, so two
  builders never share one.
- **+ GC** reuses the Edit-Bid picker's kernels (`filterPickableGcs` / `addGcsButtonLabel` /
  `tickedSummary`) over a lazily loaded customer list and inserts `bid_gc_recipients` manual
  rows, so addressing a builder records them — Followup, the board and the strip see the new
  rider (the strip re-reads off the versions reload). The stacked ＋ New GC row stayed in Edit
  Bid for now.
- **Latent bid-default tab fix**: the studio's GC tabs key the bid-default tab `'bid-default'`,
  but `groupSectionsByEffectiveGc` files bid-default sections under the bid GC's customer id when
  it has one — so picking that tab missed its packet and the letter silently stayed on the active
  version's. `bidDefaultPacketKey` translates the studio key before `letterDocument` and the
  studio's own packet lookup.
- On a split bid a shared chip also lands the letter on the bid GC's packet (theirs is the letter
  the rider got); the chips disable with an honest title when nothing of the bid GC's is in the
  letter. Shared chips never mix another packet's prices under a rider's name.
