# v2.6251 — An empty Pricing tab says what is missing and offers Adopt an existing bid (2026-10-31)

Feature, no migration, no edge function. Found in the ZZ Test dry run of 2026-10-31 for the Gun Dog adopts (punch list #208): a target bid with no count rows showed only *The Workbench needs Counts, an active Pricing, and a cost estimate* on Bids → Pricing and no ＋ Add price, so the adopt window had no door until someone added a count row by hand. BP556 has no count rows today, which is exactly the bid the adopts go into.

## Change

- `pricingStartChoices` (kernel): `needs-setup` now says what is missing — `version` (no version to price, or it already has a price), `counts`, or `cost-estimate` — in that order. `pricingSetupWords(missing, doors)` gives the empty state's words: *No counts on this version yet. Open Counts to count the plans or Adopt an existing bid*; *No cost estimate on this bid yet. Open Labor to make one or Adopt an existing bid*; *Nothing to price on this version yet. Adopt an existing bid folds another bid's counts and prices in.* Tests beside each.
- `PricingStartPanel`: the needs-setup branch draws the house `EmptyState` (compact) with those words; the tab passes `setupDoors` — the bid's Counts and Labor tab links and the adopt window's opener. The old sentence is gone. Render tests cover the three cases.
- The guide *bid one project to multiple GCs* says a packet with no counts offers the same press on its empty Pricing tab.

Not in this PR: the ＋ Add price cards row still waits for a scenario or a version to draw; the empty state is the door until then.
