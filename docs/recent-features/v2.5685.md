# v2.5685 — Cover Letter: print every GC's copy at once (2026-10-20)

Punch list #133 PR 2 (`to-dos/cover-letter-addressed-to/`), on PR 1's Addressed to row
(v2.5679): Grace's batch — the same proposal to every builder, each copy addressed — printed one
chip at a time. Now one button prints them all.

## The change

- **`buildAddressedCopiesDocument`** (`src/lib/bidDocuments/coverLetter.ts`, +tests): page-break
  sections with NO heading — unlike `buildCombinedCoverLetterDocument`, whose per-section `h2`
  label belongs on a bundle, never on a letter a builder is mailed. One copy returns unchanged.
- **`BidsCoverLetterTab.tsx`**: the letter builders are parameterized by addressee
  (`combinedHtmlFor` / `packetSectionHtmlFor` / `samePageHtmlFor` → `letterHtmlAddressedTo`), the
  single-letter path now one call of it. **Print {N} letters · one per GC** sits beside Print in
  the sending block when the letter shown is the bid GC's and same-letter riders exist: the bid
  GC's copy first, then each rider's, a page break between. On another packet's letter the button
  never offers the riders — they did not get that letter. The gate and title match Print
  (`totalsResolved`), and the title names every GC in the batch.
- **Do what is ready**: a rider with no address on file still prints, name line alone, and their
  chip reads "same letter · no address on file" — one missing address never holds the batch
  (v2.5533's rule).

## Tests

- `coverLetter.test.ts` +2: page breaks between copies, order kept, no `h2`; a single copy
  unchanged, none the empty string.
- `BidsCoverLetterTab.addressedTo.render.test.tsx` extended: "Print 3 letters" offered with two
  riders (chip flags the missing address), absent on a single-GC bid.
