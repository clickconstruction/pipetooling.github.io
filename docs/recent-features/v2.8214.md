# v2.8214 — The estimator's word on money: the five untyped calls are typed (punch list #129, the leftovers) (2026-11-21)

Punch list #129 (`to-dos/estimator-money-word/README.md`), the card's fourth follow-up. The seven functions of the train have been in `src/types/database.ts` since v2.5656 and the client went on calling them `as never`; `list_paid_claims` was typed in v2.6695 and `is_job_people` has no client caller (it is a predicate the policies and the other functions call). This types the other five, at every call site. No migration, no edge function, no hand edit of the generated types, no change in what a screen reads or writes.

## What changed

- **`list_bid_money_strip`** (`useBidMoneyStrip.ts`, `useBidBoardMoneyStrips.ts`), **`list_my_money_strip`** (`useMyMoney.ts`), **`list_customer_money_strip`** (`lib/messages/wordFromLineIo.ts`) and **`list_job_payment_promises_for`** (`SetPromisedPayDateModal.tsx`, `useJobThreadNotes.ts`): the name and the arguments drop their `as never`, and the `Json` each returns goes to its defensive parser (`parseBidMoneyStrip`, `parsePaymentPromisesRpc`, both over `unknown`) without the `as unknown` in between.
- **`add_job_payment_claim`** (`SetPromisedPayDateModal.tsx`): typed, and the one place the real type disagreed with the call. The generated arguments are `p_amount?: number`, `p_said_by?: string` and `p_note?: string`, since the function declares each `DEFAULT NULL` (`20261019080000_paid_claim.sql`), and the sheet sent `null` for an amount, a name or a note left empty. It now leaves them off (`undefined`, which the request's JSON drops), so the function's own default stands and the row written is the same: a `NULL` amount, name or note.
- **Tests**: `SetPromisedPayDateModal.render.test.tsx` gains the case with all three left empty and reads the call as it goes over the wire (four keys, no null); the case with every field filled is unchanged and still passes.

## Left as it was

- The older train's calls in the same two files (`add_job_payment_promise`, `list_job_payment_promises`, `set_job_promised_pay_date`, each `as never` since Their Word) are not #129's and are untouched, the pre-push fallbacks beside the typed reads included.
