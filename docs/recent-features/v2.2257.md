# v2.2257 — Crew chips on all three staffing surfaces + assignee search (2026-08-24)

Follow-up to v2.2251's crew tags: the chip row extracts to a shared component
and spreads, and the roadmap Add-task dialog gains a people search.

## Shared component

`src/components/checklist/ChecklistCrewTagsRow.tsx` — the crew chip row +
inline create/edit/delete panel, extracted verbatim from
`ChecklistTechTreeAddTaskModal`. Contract: parent owns selection
(`assignees: Record<userId, boolean>`), the row calls
`onStaffCrew(memberIds, checked, crewName)`; `manage={false}` hides
＋ New / ✎ Edit / long-press (staffing-only surfaces); `countMode: 'toAdd'`
renders "+N" (how many a tap would add) instead of the member count.
Crews still live in People → Teams; the row hides itself when the tables
can't load (RLS).

## The three surfaces

- **Roadmap Add-task dialog** — refactored onto the shared row (behavior
  unchanged; "via crew" pills stay parent-owned).
- **Everyday `ChecklistAddModal`** (the header ＋ Task button) — full row
  (management included) between "Assign to" and the people search; crew taps
  run through the same `dedupeSoloSelfWhenAddingOthers` rule as manual picks.
- **Task card** (`ChecklistTechTreeTaskCardModal`) — `manage={false}`,
  `countMode='toAdd'`, above the person chips in the picker. One tap = ONE
  `onSave` with the merged roster (no per-person save parade); tap again
  removes the crew's members while non-crew assignees stay put.

## Assignee search (roadmap Add-task dialog)

New pure kernel `src/lib/checklistAssigneeSearch.ts` (+10 tests):
`visibleAssigneeRows` (query filter that always keeps checked rows visible)
and `singleEnterTarget` (Enter ticks the sole unchecked match). Wired as a
search box above the checkbox list.

Help guides: new *give someone a task* (the header ＋ Task flow, crews
included); *staff and discuss a roadmap task* + *add a stage and its tasks to
a roadmap* updated.
