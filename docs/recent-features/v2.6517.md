# v2.6517 — Everyone already on the roster without a login gets their users row — PR 3 (punch list #260) (2026-11-04)

PR 3 of 5 on punch list #260 (the model: every worker a users row from day one, a login attached later — PR 1 [v2.6511](v2.6511.md), PR 2 [v2.6514](v2.6514.md)). PR 2 made every new person a users row; the records already on the roster with no account — 21 on prod on 2026-11-04, 17 live (15 subs, 2 helpers) and 4 archived — still could hold no clock session and no Charged as. This PR brings them over.

## What changed

- **Migration `20261104210000_people_without_users_backfill.sql`** ([`docs/migrations/`](../migrations/20261104210000_people_without_users_backfill.md)): `backfill_users_for_people()` gives each People record with no account a users row with no login — the name, the address where no login holds it, the phone, the role from the kind, `archived_at` carried — and links it; skips and names a record whose name another users row carries (the pay tables key on the name, so a second row on one name would re-point someone's pay — the desk's Link account or Combine folds it by hand), a `dev`, a blank name; idempotent. The migration runs it once and prints the answer; a dev may run it again. `people.account_user_id` stays nullable (its key is `ON DELETE SET NULL`; the combine nulls a source's account), and `roster_people` keeps `account_kind 'external'` as the guard that shows a straggler.
- **Bed** `supabase/tests/users_without_login/40_backfill.sql` (X1–X8): the gate, a sub with an address, a helper with none, an archived record carried as archived, the name clash skipped and named and still `external` on the roster, a held address left off the users row, a rerun linking nothing, a backfilled worker holding an imported day and taking a login on the same id.
- Docs: PROJECT_DOCUMENTATION (`backfill_users_for_people`), the card's status.

## What this changes on the screens

After the push, People → Users shows the 17 live records as rows with the *no login* chip under their kind (no longer folded behind *+ N more without a login*, which counts roster-only rows) and the 4 archived ones under Archived; Who counts as what lists them, so the office can set their Charged as; a dev can import their days through `import_clock_sessions`. The desk's *Merge a duplicate* finds no roster-only subs any more; PR 5 re-points it at no-login users through `merge_user_accounts`, which already moves the roster link.
