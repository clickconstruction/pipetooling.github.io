## What changed

- **`dev_legal_narrative_write(p, p_dry_run)`** ([migration page](../migrations/20261007235000_dev_legal_narrative_write.md)): a dev-gated definer wrapper over the Legal desk's own `legal_set_narrative`. The dry run names the matter, the length before and after, when the narrative was last saved, and whether the firm reads it now.
- **dev-mcp `plan_matter_narrative` / `apply_matter_narrative`** ([`_shared/devMcpWrites.ts`](../../supabase/functions/_shared/devMcpWrites.ts)): `{ narrative: { matter_id, markdown } }` in the plan-then-apply shape of the cost-batch and HR verbs. The plan's hash covers the last save, so a save by anyone since the plan makes apply refuse; one apply per plan as before.
- **[`scripts/legal-file-documents.ts`](../../scripts/legal-file-documents.ts)** files a folder onto a matter from its `manifest.json`: `matter_id`, each document's `file`, `title`, `shows` and an optional `hold` reason, and an optional `narrative_file`. A dry run unless `--write`. Every file is read and checked against the desk's rules (kind, 10 MB, the two lines) before anything is written, and a document already on the matter with the same title, file name and size is skipped, so a re-run is safe. It signs in as the owner like the pay scripts, uploads to the private bucket, inserts the row under the app's RLS (the database stamps who added it) and saves the narrative through `legal_set_narrative`.
- **[`legalFilingManifest.ts`](../../src/lib/legal/legalFilingManifest.ts)**: the script's pure kernel. The manifest parse names every problem at once; then the per-file check, the duplicate rule and the narrative check.

## Is this the best we can do?

- **Documents go through a script, not an MCP verb: a change from the mockup.** The mockup planned `plan_matter_document` / `apply_matter_document` with the file as base64. A 10 MB PDF is about 13 MB of base64 through the agent's context and the function's request, for files the session already has on disk. The script reads them from disk, meets the same bucket policy and RLS as the desk's drop zone, and dry-runs by default. The narrative is text the agent writes, so it stays an MCP verb.
- **The same gates as a person at the desk.** The wrapper refuses a non-dev, `legal_set_narrative` checks the office cohort, the bucket and table policies check it again, and training mode still blocks.
- **The firm sees what is filed on its next open.** So both paths show what they would do first and write only on a second, explicit step.
- **Not done:** an MCP verb for documents; the script is the door for now.
