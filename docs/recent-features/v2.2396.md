# v2.2396 — Workbench: $0 = unpriced; price-book browse vs Use; lineage-rooted book resolve (2026-08-27)

Wendi's round-2 feedback, all Pricing-tab:

- **"show unpriced only does not work because everything is set to zero, instead
  set unpriced items to a dash"**: the Workbench now treats a saved unit price
  of $0 as NOT a price — `BidsPricingTab`'s row decoration derives
  `savedUnit = unitPrice > 0 ? unitPrice : null`, so the sale cell shows the —
  placeholder, the priced meter / "Show unpriced only" filter count those rows
  as unpriced, and `runWorkbenchSolve` passes them to the solver as unpriced
  (so "Price unpriced only" fills them). Typed/solver prices were already
  guarded `> 0` at write time, so a $0 can only be legacy/imported data.
- **"going between new and old deselects the pricebook"**:
  `resolveCurrentPriceBookTemplateId` now walks the `source_version_id` chain
  through the bid's own pricings (new `resolvePriceBookTemplateRoot` kernel,
  cycle-safe, 13 tests) — scenarios born from "+ Add price" duplicates or
  bid-version clones record another SCENARIO as their source, and the old
  direct-source read returned null → the Old view's dropdown showed "Select a
  price book…".
- **"when I jump between price books it adds new price versions to the bid …
  make this a button instead of automatic"**: two changes —
  1. Drawer book chips now only **browse** (title/entries switch; nothing
     written). Switching the bid is the explicit **Use <book> on this bid**
     button (with a "Browsing only" note); ★ marks the book actually feeding
     the bid.
  2. `onSelectPriceBookTemplate`'s existing-copy dedupe matches by lineage
     ROOT instead of direct source — switching back to a book the bid already
     uses re-activates the existing copy instead of minting a fresh clone.

Help guide `price-a-bid-with-the-workbench.md` drawer section updated.
