# v2.4402 — Customer pages hold still behind a window too (2026-10-02)

Client only: no migration, no edge function. PR 3 of 4 on the owner's ask "stop background scroll on all modals across the app" ([v2.4399](v2.4399.md), [v2.4400](v2.4400.md)).

## What was wrong

[`BodyScrollLockSentinel`](../../src/components/BodyScrollLockSentinel.tsx) was mounted in `Layout`, which only the signed-in routes render. The 24 routes outside it — `/estimate/accept`, `/contract/accept`, `/contract/sign`, `/portal`, `/p/:slug`, `/sub`, `/s/:slug`, `/bid-room`, `/submittal`, `/q/:token`, `/pay/:id`, `/legal`, `/ask`, `/task`, the sign-in and reset pages, the two staff previews — had no watcher. A window there held the page only if it called the hook itself (two did, since v2.4399); the rest, like the submittal room's *Before you ask* sheet, let the page scroll behind them.

## What changed

- **The sentinel moved to the app root** ([`App.tsx`](../../src/App.tsx), `AppContent`, beside `UpdatePrompt`): one mount for every route. `Layout` no longer renders it.
- **The audit that made the move safe.** At the root, any fixed layer that covers the screen freezes its page, so every fixed layer the public pages can draw was read (the import closure of each route's page, 264 files, 8 with a fixed layer). Seven are windows or small bars. One is a picture: `/task`'s full-screen sign-in photo ([`TaskShortcut.tsx`](../../src/pages/TaskShortcut.tsx)) — it now carries `data-page-scroll="allow"`, or the page would have been frozen for good.

## Verified live

Dev server, 375 × 812. `/portal` (no token, the dead-link page): `body` free; a stand-in window put on the page (a fixed dim backdrop holding a `role="dialog" aria-modal="true"` panel) pinned the body, and removing it freed it — the watcher runs outside the layout. Signed in, the Lien desk still pins the page and frees it on close. `/task` could not be walked in a browser tab (it sends a browser to its install page); its background is covered by the audit, not by a walk.
