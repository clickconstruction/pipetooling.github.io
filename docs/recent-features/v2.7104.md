# v2.7104 — Corrections as links: the dev seat's reads carry them (server 0.81.0) (2026-11-12)

Punch list #315, upgrade 1, PR 3. Builds on v2.6969's `person_file_amendments` and v2.7098's Timeline chips.

## What was wrong

An agent that read a person's file through the seat saw every entry as if it stood. The link that says a later entry corrected it was on the table and on the tab's Timeline, and nowhere in `get_person_file`, `get_case_brief` or `search_case`. A session could quote a corrected entry and never learn of the correction.

## What changed

- **`get_person_file`**: a line or an evidence record that a later one corrected or completed carries `standing` (`corrected` or `completed`), `amended_by` (each later thing: how, its row as `table:id`, its day, the words the Timeline's chip wears), `latest_word` (the newest correction along the chain) and, on the newer thing, `amends`. `brief` keeps the keys. `amendments` counts the links on the file.
- **`get_case_brief`**: `amendments` counts the links and lists the newest ten, each end by its row and day. A newest entry or an evidence record a link touches carries the same keys.
- **`search_case`**: an `entry` or `evidence` hit that a later one corrected says so and names the correction, joined in the kernel as the transcript pair is, so `dev_case_search` stays as it is.
- **`plan_hr_entry`**'s description and schema name `corrects`, `completes`, `amendments` and `withdraw_amendments`. The write itself has worked since the migration's push.
- **One kernel with the tab**: `_shared/devMcpAmendments.ts` reads the links once as the dev under RLS and draws them through `personAmendments.ts`. The links are a source of their own. A read that fails is named in `held` and takes only the links out.
- **Nothing is widened**: another role reads no links, as it reads no entries. A link that touches a counsel-only record reaches the seat only while the counsel-only switch stands open, as the record does. An end the reader does not hold has no day and its words say so.
- Server `0.81.0`. No new verb, no migration, no wrapper RPC.

## Is this the best we can do?

The card planned the search's pair as a change to `dev_case_search`. Joining in the kernel does the same with no migration and no lock on prod, the way the transcript pair was joined, so that is what was built. What it costs is one more read a search. A file with no links answers as it did, apart from the count block.

Not done here: a hit on a document section that cites a corrected entry is not flagged in the search. The tab flags it in the narrative's Jump to. The seat would need the citations read per hit, which is a PR of its own if the owner wants it.
