# v2.8097 — Before we start: a bullet that did not save keeps its words (2026-11-20)

Found by the Fable 5.2 audit of punch list #382 (Before we start). Client only: no migration, no edge function.

## What was wrong

In `src/components/startChecks/StartCheckStage.tsx`, **Add** ran `void act('The bullet was not added.', …).then(() => setWords(''))`. `act` catches a failure and shows it in a toast, so the `.then` ran every time.

- A person types a bullet and presses **Add** with no signal. The toast says the bullet was not added, and the box is emptied. They type it again.
- `act` also returns at once while another row's write is still out. The box's Enter key is not held back by that, so Enter pressed then added nothing, said nothing and emptied the box.

## The fix

`act` now answers whether the write ran and landed: true on success, false when it failed or was skipped because a row was waiting. **Add** empties the box only on true. Every other press that calls `act` reads nothing from it and behaves as before.

## Test

`src/components/jobs/JobDocumentsStartChecks.render.test.tsx`: an add that fails leaves the words in the box and keeps no bullet, and the same press again keeps the bullet and empties the box. It fails on the old code and passes on the new.
