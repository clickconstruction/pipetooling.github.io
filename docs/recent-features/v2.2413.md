# v2.2413 — Contacts foundation: ledger-derived last_contact, per-GC attribution (2026-08-28)

Phase 1 of `docs/PER_GC_BID_PLAN.md`. `bids.last_contact` had seven independent writers —
six hand-bumps after inserting a `bids_submission_entries` row, plus Edit Bid's raw datetime
field which wrote the column with no ledger row at all.

- **Migration `20260828040000`**: `sync_last_contact_from_entries` row trigger —
  `bids.last_contact = max(occurred_at)` over the bid's entries **with a contact_method**
  (owner decision: method-less notes are notes; they don't move the chase clock). NULL when a
  bid's only entries are notes. Backfill converges bids that have entries; bids with no
  entries keep hand-set values. **Behavior change**: note-bumped bids move backward and can
  honestly reappear in Waiting-to-hear.
- **New kernel `src/lib/bids/bidContacts.ts`** (+tests): `isContactEntry`,
  `deriveBidLastContact`, `lastContactByGc(entries, ownGcId)` (NULL-GC and own-GC-id entries
  fold into the own bucket), `entryGcIdFromPacketKey` ('' → null, `shared:` unwrapped).
- **`BidLogContactControl`** (new; in Edit Bid for saved bids): read-only derived display +
  Log contact… (method quick-picks required, backdatable datetime, optional note, GC picker on
  multi-GC bids). Writes an entry; mirrors the trigger's max client-side for the pre-push
  window; **self-syncs from the DB on open** so a stale board row can never be saved back over
  a newer contact. New/unsaved bids keep the raw field (no bid id yet).
- **Attribution**: `buildPendingChaseActionWrites` gains `gcCustomerId` (Waiting-to-hear +
  Call queue pass their row's GC via `entryGcIdFromPacketKey`); `buildCallSessionWrites` and
  `buildBuilderQuickLogWrites` stamp the builder being called on every bid entry.
- **Hand-bumps** in the GC-notes popover and Unified notes are now method-conditional
  (trigger-window duplicates); full removal is the post-push cleanup PR.
- **`BidGcSentPanel`**: each GC row shows `contact YYYY-MM-DD` (company timezone) from the
  ledger — no new column anywhere; per-GC last contact is a query.

Deploy: client first, then `supabase db push`. Verified live on BP398: Log contact…
(method + GC select "This bid's GC / Achilles- Austin") wrote the entry, moved the clock,
per-GC line updated, stale-reopen clobber confirmed dead.
