# v2.2250 — Stage review on Review + dev-only task cost estimates (2026-08-24)

Two interlocking additions to the Checklist Review tab (plus the roadmap Plan
view), from the 2026-08-24 design spike.

## Stage review (Goals strip upgrade — staff-visible)

The Goals strip's expanded stage list stops being read-only:

- **Unlock events** — green banner rows above the stages: "✓ Stage 6 finished ·
  <title> · Aug 22 → unlocked stage 9 …, · moved stage 18 closer". Derived
  entirely from task `completed_at` timestamps + dependency edges (30-day
  window, newest first) by the new pure kernel
  `src/lib/roadmapStageReview.ts` (`recentStageUnlockEvents`, + tests). No new
  storage; unlocking stays automatic — Review narrates it after the fact
  (owner decision: auto-unlock + event, no sign-off gate).
- **Unlock preview** — an unfolded open stage's footer says what finishing it
  opens: "⚡ Finishing unlocks stage N …" (sole blocker) vs "helps unlock
  stage M" (shared blockers), via `stageUnlockPreviewFor` reading the rows'
  `blockedBy`.
- **Stage reminders** — "🔔 Remind N" on an unfolded stage sends one
  `send-checklist-notification` push per assignee with THEIR open tasks in the
  stage (tag `stage-reminder`, lands on `/checklist?tab=today`; honest-outcome
  toast like the person-level Remind). `GoalsLedgerTaskRow` gained
  `assigneeIds` for this (`roadmapGoalsLedger.ts` + test).

## Task cost estimates (dev-only)

"What does this task really cost?" — a calculator icon on Review outstanding
rows, Goals-ledger task rows, and roadmap Plan task rows opens a cost
estimator (`ChecklistCostButton` + `ChecklistCostModal`, bottom-sheet on
phones): pick a person (defaults to the row's assignee), $/hr auto-fills from
`people_pay_config.hourly_wage` via the `hourlyWageForUserName` name-join
(editable — salaried people may have none), set hours (quick-picks), save.

- **Storage**: new `checklist_item_costs` table (migration
  `20260824214954_checklist_item_costs.sql`) — dev-only RLS both directions
  (`is_dev()`), rate snapshotted at entry. `cost_key` = the roadmap task id
  for bridged roadmap tasks (Review and Plan share one estimate per task),
  else the `checklist_items` id. Store: `src/lib/checklistCostStore.ts`
  (module cache + `checklist-cost-changed` window event); lazy hook
  `useChecklistCostEstimates(enabled)` never queries for non-devs.
- **Roll-ups** (gold chips, whole dollars; trailing `+` = partially costed
  floor): per task, per person (Outstanding-by-person header), per stage
  (Goals strip rows + Plan stage headers + locked Up-next rows), per roadmap
  (Plan header "· $X+ left"). Kernel `src/lib/checklistCostEstimate.ts`
  (`estimateDollars`, `summarizeOpenTaskCosts`, `formatOpenCostSummary`,
  + tests).
- `src/types/database.ts` carries a hand-added `checklist_item_costs` entry
  until the post-push regen.

Surfaces: `src/pages/Checklist.tsx` (Review tab),
`ChecklistRoadmapPlanView.tsx` (`showCosts` prop; `ChecklistTechTreeTab`
passes `isDev`).
