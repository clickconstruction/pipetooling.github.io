# v2.5444 — Colours the app named but never set now show (2026-10-13)

A check the theme script cannot do, by GC Mode helper 1 for the lead: `scripts/check-css-tokens.mjs` (`npm run check:css-tokens`) fails on any `var(--name)` under `src/` whose name no CSS file declares and no code sets. It runs in the `checks` job of both `ci.yml` and `deploy.yml`, next to the theme token check, with `check:workflow-parity` green. An undefined name is invalid when the page computes it, so the property falls back to `unset`: a background paints nothing, a border or an outline draws nothing, and a colour inherits whatever is around it. The theme check only sees raw neutral hexes, so this slipped past it.

- **What main had** (re-cut from `c6ed07a1e`, 2026-10-13): 38 names used but never defined, at 288 use sites in 126 files (244 with no fallback). The biggest were `--text` (160), `--text-900` (20), `--bg-blue-50` and `--text-blue-600` (15 each) and `--surface-2` (13).
- **Defined means**: declared in any CSS file under `src` (`index.css`, `authPublicLanding.css`, `Calendar.css`), or set from code: a quoted name as a style key (`Layout.tsx`'s `['--app-bottom-chrome' as string]:`), passed to `setProperty`, or held in a constant (`SCROLL_LOCK_TOP_VAR = '--scroll-lock-top'`). A name only quoted in a comment defines nothing; the first cut counted one (`` `--surface-muted` `` in `ThreadWindow.tsx`'s comment) and so missed three uses. A name built in a template (`var(--timeline-job-${i})`) is defined when a defined name starts with its fixed part.
- **The fix is the script's own** (`--fix`), so this sweep merges alone and a PR that conflicts re-runs it. A use with a fallback is what renders today, so the fallback takes its place when it is a defined token, a keyword or a plain value, and nothing changes on screen (`var(--surface-2, var(--border))` becomes `var(--border)`, `var(--bid-mark-hold-ms, 500ms)` becomes `500ms`, which matches `BID_MARK_HOLD_MS`). Every other use takes its twin from the script's `TWIN` table: the defined token of the same value or role (`--bg-blue-50`→`--bg-blue-tint` #eff6ff, `--bg-blue-100`→`--bg-blue-200` #dbeafe, `--text-900`→`--text-strong`, `--text-blue-600`→`--text-link` #2563eb, `--sunken`→`--bg-muted`, purple→violet). A blue used as a button's fill stays a literal `#2563eb`, the saturated-action rule. 138 rewrites in 74 files (139 sites, one inside another's fallback). Six of those files are in open PRs (`Layout.tsx` #5619 #5620, `DashboardJobModeCard.tsx` #5615, `SubSheetWorkOrderPanel.tsx`, `WorkOrderAssemblerModal.tsx` and `SettingsContractsTab.tsx` #5484 #5487, `SettingsWhatCustomersSeeTab.tsx` #5452 #5492), each a one-token edit.
- **`--text` is split in two.** Its 11 uses that are not a text colour are fixed here (5 backgrounds, 3 outlines, 3 borders on the Bridge and the Legal desk: dark tooltips and the selected day that drew nothing). Its 149 text-colour uses (`color`, an SVG `fill`, or a value with no property on its line) inherit today and mostly look right by accident. They wait in the script's `PENDING` list for a second sweep that maps them to `--text-base` after a screenshot pass. Mapping them tonight would turn a chip that inherited white to the base colour. The check passes them, prints how many are left, and fails once none is, so the entry leaves with the last of them.
- **Left out**: `SendWindow.tsx`'s two `--surface-muted`, which are not on main yet; the lead fixed them in #5497.
