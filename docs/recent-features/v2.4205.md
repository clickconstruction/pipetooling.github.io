## What changed

- **Kernel** [`lib/jobs/billedDatesLedger.ts`](../../src/lib/jobs/billedDatesLedger.ts) — `buildBilledDatesLedger` returns `{ rows, verdict, full }`; the `bar` (segments, caption) is gone. **One deadline row**: when the runway is `notice_due` (a sub job, the § 53.056 notice for the work month not recorded, its date still ahead) the row is *Lien notice by Oct 15*; otherwise it is the lien date, with `sub: 'notice sent'` when the notice is on record. The row is **bold** (filled dot, amber; red inside a week or when the money is expected after it) when the money is not landing before the deadline — expected after it, already past, or never named — with one asymmetry on purpose: a notice asks at any distance (it is cheap and it is what keeps the lien alive), a lien asks inside `LIEN_RUNWAY_AMBER_DAYS` as *File the lien*. A ring, green, when the money is due first. **The verdict only when it adds**: *Can run late · N d* (the slack between the money and the deadline; amber inside a week of it), *Notice first* / *File the lien first · N d short*, *Ask for a date · N d past* (opens They said…; red in Collections) or *Ask for a date* with no value when nobody named a date, *Lien gone* under a *Lien window closed* / *Notice window closed* row; **null** when the deadline row is the to-do, and for a filed lien. 9 tests.
- **`lienPayRunway.ts`** — the output gains `noticeSent: boolean` (the same flag the kernel already computed for `notice_due`), so the ledger can write *notice sent* under the lien date after the notice window has passed too; `marks.notice.done` only existed while the date was ahead. Additive; the 27 runway tests are unchanged.
- **Component** [`BilledDatesLedger.tsx`](../../src/components/jobs/BilledDatesLedger.tsx) — the time bar and its measured width are gone (`useMeasuredWidth` stays in `hooks/` for the stage bar); a bold row prints its label in the tone's ink. 3 render tests.
