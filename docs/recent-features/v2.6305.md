# v2.6305 — Find a file: search every job’s Drive files by their words (2026-11-02)

The owner's ask after punch list #236 put every job's files in one Drive folder: the assistant knows a file exists but not which job holds it. The office found it by Drive's own search or by opening jobs one by one; the app had no search across jobs. The owner floated a markdown corpus scraped by a robot; the answer was that Drive's full-text index already reads the words inside PDFs and OCRs scans, so the app should search through it and land each hit on its job. Client plus one edge-function action, no migration.

- **The box.** `FindAFile` (`src/components/documents/FindAFile.tsx`) sits under the job and bid search on **Documents → Search**. It waits for the typing to pause (`FIND_DEBOUNCE_MS`), needs two letters, and lists the hits under the job or bid whose folder holds each (`groupByHome`, Drive's order kept), with the folder path, the day and the size under the name (`hitMetaWords`, reusing `jobFolderFiles`' size and day words). A hit opens in Drive; a job's group offers **Open the job** through the job window when its provider is mounted, else the Jobs page's `?edit=` door. Nothing found is an `EmptyState`; a refusal shows the function's reason with **Try again**; no jobs root says where to set it. Kernel `src/lib/documents/findAFile.ts`, io `findAFileIo.ts`.
- **`drive-link` `search`** (`supabase/functions/drive-link/index.ts`, `_shared/driveLink.ts`): `{ action: 'search', words }`, the office door's gate, a read a training account may run. `searchFiles` asks Drive `files.list` with `fullText contains` over the jobs root's Shared Drive (`corpora=drive`, the drive id from `driveFolderMeta` of the root; `allDrives` when the root is not in one), folders left out, at most 30 hits. `folderHomes` reads every job's three folder links and every bid's folder into one map, and `walkUp` climbs each hit's parents (cached, in parallel) until a home or the root, naming the folders between. The answer is `{ hits: [{ id, name, mime, bytes, modified, url, home, path }], more, noRoot }`. **Redeploy `drive-link` once this merges** (it carries v2.6303's `put` widening too).
- Tests: `findAFile.test.ts` (the defensive parse, headings, grouping, the meta line, the count and empty words), `FindAFile.render.test.tsx` (pause → search → groups with the links, one letter searches nothing, empty and more, a refusal with Try again and the no-root words), `driveLink.test.ts` (the ask parses, one letter is refused). Guide *find a file when you do not know where it is*; `docs/EDGE_FUNCTIONS.md`'s drive-link section names `search`.
- Honest limits, in the guide: a photo straight from a phone has no words for Drive to read; a file put in a folder a moment ago may take Drive a minute to index; a file outside the jobs Shared Drive is not searched here.
