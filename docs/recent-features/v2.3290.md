# v2.3290 — Upcoming payroll modal: chip rail over a per-person grouped table, what-if exclusion, sort by amount (2026-09-11)

Client only — no migration, no edge change. Owner ask (2026-09-04, on People → Payroll → the "29 upcoming: $19,743.79" link): "see a summary of the people and the amounts at the top, click them to toggle their exclusion from the estimated total, and sort by amounts." Three mock-ups were offered (chip rail / summary table / grouped rows); the owner picked a combination of the chip rail and the grouped table (artifact 4e49ea69).

## What shipped

- **[`UpcomingPayrollModal`](../../src/components/people/UpcomingPayrollModal.tsx)** (new) — the "Upcoming payroll — not yet reported" dialog, extracted from `PeoplePayStubsTab` (which now only renders it and keeps the fetch, the summary memo, and the nested week drilldown). Layout, top to bottom:
  - **Header** — unchanged title and current week; the count line is now live: `N person-weeks · $X estimated · 2 excluded, −$Y` (amber tail only when someone is out).
  - **Chip rail** — one chip per person: name, estimated gross, `Nw` week count. The chip body toggles exclusion (`aria-pressed`); the `▾` tail unfolds that person's group and scrolls it into view. Excluded chips go dashed and struck through (no `display: none` anywhere — nothing silently disappears).
  - **Tools row** — a three-way sort chooser (Amount / Name / Hours; same key again reverses), Collapse all / Expand all, and Include everyone (only while someone is excluded).
  - **Grouped table** — a subtotal row per person (fold caret, checkbox, name, `N wks`, hours, gross) with that person's weeks nested beneath. Clicking the row folds it; the checkbox toggles exclusion (click is stopped from folding). The Period link per week still opens `UpcomingWeekSessionsModal`. Footer total reads `Total (10 of 12 people)` when excluding. The Person / Hours / Est. Gross column headers are sort buttons with `aria-sort`, bound to the same state as the chooser.
- **Kernel [`upcomingPayrollGroups.ts`](../../src/lib/upcomingPayrollGroups.ts)** (+11 tests): `groupUpcomingPayrollByPerson` (one group per person, weeks in the summary's order), `sortUpcomingGroups` (name / hours / gross, ties broken by name for a stable order), `nextUpcomingSort` (new key takes its natural direction — names A→Z, amounts and hours biggest first — same key flips), `upcomingTotals` (included/excluded people, person-weeks, hours, gross, and the excluded dollars for the "−$Y" tail), `toggleExcluded`, `parseUpcomingSort`.

## Decisions

- **Exclusion is a what-if inside the modal only.** It never touches the ledger header's "N upcoming" link, the Dashboard AP card's est. payroll, Draft Payroll, or anything saved, and it resets on close. The owner's stated use is sizing what payroll looks like if someone's weeks wait; a persisted exclusion would quietly understate the header for everyone.
- **Sort persists per browser** (`localStorage` key `people_payroll_upcoming_sort_v1`, parsed defensively). Default stays people A→Z, the order the table had before.
- **Weeks never leave their person.** Sorting by amount orders people by their subtotal; a per-week sort would interleave twelve people's weeks and defeat the grouping.
- Help: `catch-up-on-unreported-payroll-weeks.md` gains a "Sizing up what is still upcoming" section.

## Not changed

The summary math (`buildUpcomingPayrollSummary`), the sessions fetch (paged since v2.2759), the week drilldown, and the header link on the Payroll ledger.
