# v2.1948 — Partnerships Agreements: partnership-scoped signature gating (2026-08-21)

Owner caught it: Bryan's Agreements tab said "signed agreement on file" — but the signed documents were his April sub-onboarding paperwork (handbook + installation agreement), not the partnership contract, which doesn't exist yet. Worse, that any-signed check disabled the "Draft §8a notice" button, so a lapsed real agreement couldn't have produced its termination notice while old paperwork "counted". (The server RPC `generate_agreement_notice` was already partnership-scoped — the bug was client-only.)

New kernel [`agreementGating.ts`](../../src/lib/partnerLedger/agreementGating.ts) (`partitionAgreementDocs`, `agreementGating`; 6 tests): only documents with `person_contract_documents.partnership_id = this partnership` satisfy `dealSigned`, drive `lapsed`, or block the notice. [`PartnershipAgreementsTab.tsx`](../../src/components/partnerships/PartnershipAgreementsTab.tsx): documents render in two sections — "This deal's agreement" (sign-by editing, countdown) and "Other paperwork on file — not this deal" — with a link/unlink button on every row (`partnership_id` write; sign-by editing still auto-links). Chip reads "deal agreement signed / no signed deal agreement"; §8a button gates on `dealSigned` with updated copy. Also swaps the tab's UTC `toISOString().slice(0,10)` "today" for `denverCalendarDayKey` (company calendar, TIME_AND_ZONES convention). Client-only — no migration.
