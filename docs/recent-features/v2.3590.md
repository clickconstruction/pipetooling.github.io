# v2.3590 — Stripe pay links: refresh on read in the portal and View bill (2026-09-18)

Edge functions `customer-portal` and `get-stripe-invoice-details` change (**deploy both**); no migration. PR 2 of two (PR 1: v2.3589, the nightly sweep). Stacked on v2.3589 — the shared loop moved out of the nightly function into `_shared`.

## Why

The nightly sweep keeps a stored link at most a day old, but a run can miss (a deploy gap, a Stripe outage) and the two places a customer or the office actually clicks — the portal's Pay and View bill's Customer pay page — should not depend on it. Both already had the row in hand; View bill already retrieved the invoice from Stripe and threw the fresh link away.

## The change

- **`_shared/stripeInvoiceLinkRefreshIo.ts`** — `refreshStripeInvoiceLinks(admin, rows, { dryRun, concurrency, log })`: the retrieve-and-write loop from v2.3589, now shared. The nightly function calls it; its response and summary line are unchanged.
- **`_shared/stripeInvoiceLinkRefresh.ts`** — `linkMayBeStale(billedAt, now, margin = STRIPE_LINK_STALE_AFTER_DAYS)`: 25 days after `billed_at`, or an unknown billed date. Stripe expires a link 30 days after the due date and `create-stripe-invoice` sets the due date at least one day after billing, so a younger link is provably live and costs no call. +1 test.
- **`customer-portal`** — the invoice select adds `stripe_invoice_id, stripe_mode, stripe_invoice_status`; every open Stripe bill past the margin is refreshed before `buildPortalBills`, the row written, the payload's `payUrl` built from the fresh link. A failure is logged and the stored link stands.
- **`get-stripe-invoice-details`** — the row select adds `hosted_invoice_url`; the silent backfill writes Stripe's current link when it differs; the response gains `hosted_invoice_url`. Client: `parseStripeInvoiceDetailsResponse` reads it (null on older responses; +1 test), and `HostedStripeBillPanel` prefers it over the row's stored copy for Customer pay page and the share cluster.

Not changed: the Bill tab row's own Text · Copy link · Email cluster (`JobFormInvoiceList`) still reads the row — the nightly sweep keeps that within a day, and opening View bill refreshes it on the spot.

## Verified

- Kernel and parser tests; typecheck, lint, the guide and release-note suites; `check:edge-drift` names the two changed functions.
- Deploy: `supabase functions deploy customer-portal get-stripe-invoice-details refresh-stripe-invoice-links` (the nightly one again, for the shared loop); then open a portal with a bill older than 25 days and View bill on the same bill — the function logs read `customer-portal links: N past the stale margin · k renewed`.
