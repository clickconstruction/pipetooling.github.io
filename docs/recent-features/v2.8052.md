# v2.8052 — Sub papers: an assistant can make a statement of account (2026-11-20)

A new pair on `dev-mcp` (server 0.121.0, 154 write verbs, 96 naming no RPC) and a new edge function behind it: **`plan_sub_statement`** → **`apply_sub_statement`** over **`sub-statement`**. The owner, 2026-11-20: "do we have dev verbs to access it? for example can I ask you to make one and give it to me?"

## Why

An agent had just entered a teammate's bonus sheets and payments through the seat. The next ask was the paper that says what is still open after those payments. The app makes it: **Statement of account…** on Jobs → Subs → Pay and People → Subs (punch list #350). The seat had no door to it, so the only way was a person's press.

## What it does

- `statement = { person }` plans a statement to date. `person` is a `people.id`, a `users.id` or the whole name.
- `period` picks one of the window's five chips: `to_date`, `since_last`, `this_month`, `this_year`, or `{ from?, to? }`.
- **The plan writes nothing and takes no number.** It answers the statement as data: each sheet with what it comes to, what was paid and what is open, the payments in the period, the one line of how it adds up, *Still open*, the last statement in the register, what making it does and what it does not.
- **The apply does what the window's Download does**, as the dev. `mint_sub_paper` registers the paper under the next `SA` number. The PDF is drawn under that number. A sent copy is kept on the person and on each job, marked downloaded. The reply carries the number, the file's name, size and sha256, whether the copy was kept and filed, and a link to it that opens for one hour.
- It sends nothing to anyone. It makes no work statement and no payment record, and it changes no sheet, payment or balance.

## Why a function of its own

The papers' kernels weigh about 64 KB (`subPapers.ts`, `subPapersPdf.ts`, `sheetParties.ts`, `teamSheetRule.ts` and the files they read). The seat's upload stood at 4,477,617 bytes against the 4,500,000 the deploy check holds, so it had 22 KB of room. The kernels live in `sub-statement`, and the seat calls it as the dev through `invokeAsDev`. The seat's own share is the input shape, two tool definitions and one handler: about 8 KB.

## How it stays the office's paper

- **The same rows.** `_shared/subPapersRows.ts` reads what `sub-portal` reads for a sub's own page, through the caller's client, so a dev reads them under row security. A refused read is an error, never a sheet counted as missing. `sub-portal` keeps its own reader for now, since moving it would mean redeploying a page subs use.
- **The same sheets.** `portalPaperSheets` picks a person's own sheets by `sheetParties` and `sheetOwedTo`, and `subPortalPapers.test.ts` already holds it to the office's `paperSheetsFor`, sheet for sheet. A shared sheet is left off. A teammate's own sheet is theirs.
- **The same check.** `subPapersAddUp` over the three papers, then the statement's own arithmetic for the period asked. A set that fails is not made, and the refusal lists what is off.
- **The same register and the same copy.** The test holds `statementMintArgs` to `mintSubPaperArgs`, the file name to `subPaperAttachmentName`, the title to `subPaperTitle`, and the sent copy's row to `sentDocumentInsert`.

## How the apply is held to the plan

The plan's reply carries the paper's fingerprint (`subPaperFingerprint`: the period, the closing day, each row's figures and the totals). The seat hashes the reply with the payload. An apply asks the function for the plan again and refuses a hash that moved. It then asks for the paper with `expect` set to that fingerprint, and the function reads once more and refuses a set that no longer matches. One apply per plan. A number once taken is not given back.

## Guards

- The function takes the office roles who see sub pay, refuses an archived account, and refuses a make from an account in training. `mint_sub_paper` holds the same gates in the database.
- The seat takes a dev's own key alone, as for every write.
- The service role reads only the caller's own `users` row.

## Not in this change

- A work statement and a payment record. They stay the window's own presses, and so does Send.
- `sub-portal` reading its rows through the shared reader.
