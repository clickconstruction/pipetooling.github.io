# v2.8261 — Permits: `builders.customer_id` is dropped (punch list #307, PR 6's leftover) (2026-11-21)

Punch list #307 ([`to-dos/bid-permits/`](../../to-dos/bid-permits/README.md)), the line left under PR 6 since v2.6872: *Not built: dropping `builders.customer_id`*. The owner's word on 2026-11-21: build it, then close the card.

## Why

The column was made to say which customer a name on the permits is. The answer on a name went to `builder_customer_answers` instead, where one name can be tied to more than one customer and every answer keeps who gave it. Nothing ever wrote the column. It stayed in the table, in the return of `research_builders` and in the client's `BuilderRow`, null everywhere.

v2.8220 read it and left it, because the live `research_builders` selects it. This PR replaces that function in the same file as the drop.

## What changed

- **Migration `20261122040000_builders_customer_id_dropped`** ([its page](../migrations/20261122040000_builders_customer_id_dropped.md)): `research_builders` is dropped and made again with no `customer_id` in its return, on the body of `20261120150000` with that one column gone. Then the column goes, and its foreign key with it. The table's comment and the function's comment say where a tied customer is kept.
- **`BuilderRow`** (`src/lib/research/permitBuilders.ts`) loses the field. No screen and no kernel read it. Eleven test files drop it from their made-up builders.
- **The bed `permit-skim`** (`scripts/pgtest-permit-skim.sh`, `supabase/tests/permit_skim/`): the four older files that wrote `research_builders` read the column in their bodies, so they cannot run a second time once it is gone. The bed runs this file twice in their place, and then `20261122032000` again, which names no builder's customer. One new line asks for the read's return, the table's columns and its foreign keys by name.

## Not changed

- `research_builders` counts our bids by the same rule. `ourBids.test.ts` now reads this file as the newest body and holds it to that rule.
- The generated types still list the column until they are regenerated after the push. No code reads the read's return through them.

## Tests

- A local Postgres 15 with stand-in tables: the old body, then this file twice. The read lists a name with its mark, its plumber and our bids, its return has no `customer_id`, and `anon` cannot run it.
- The files this PR touches: `permitBuilders.test.ts`, `builderAnswers.test.ts`, `lookAlikeIo.test.ts`, `lookAlikeWorklist.test.ts`, `permitCallList.test.ts`, `permitMarket.test.ts`, `ourBids.test.ts`, the five render tests and `releaseNotes.test.ts`.
- CI's `sql-beds` check runs `permit-skim` on the whole schema.
