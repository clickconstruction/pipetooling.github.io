# v2.7679 — Tell the dev: the dev's push is ready for a went wrong note (2026-11-17)

Punch list #380: the function half of the push, sent ahead of the client that calls it. One edge function, `notify-help-feedback`. No client change.

## Why it goes first

The function as it stood words every push around a Help guide. A note from a page has none, so a call for one would have read *on "null"* and opened a guide that does not exist. The client that calls the function for a page note is a later PR of the card, and it must not be live before this is deployed.

## What changed

- **The row read** gains `kind`, `page_key` and `context`, the columns `20261117235000_help_feedback_page_notes.sql` added. That migration is pushed.
- **A note from a page** gets its own title, *Tell the dev: something went wrong*, names its page from the box's own label (else the page key), says *Something went wrong. No words.* when it has none, and opens `/dashboard`, where the inbox sits with the note's state.
- **A guide's feedback** pushes exactly as before, to its guide.
- **A gate on the kind**: only a guide's feedback and a `broken` note push. A `want` or `confusing` row answers 200 with no push, so no client, old or hand-made, can interrupt a dev for them.
- **Hours are honoured** as before, through `sendPushHonouringHours`.

## Checked

`deno check` passes on the function with no new error.
