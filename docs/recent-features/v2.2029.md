# v2.2029 — Job review: session drill-down + bulk move hours (2026-08-21)

Owner-approved mockup: on the Partnerships → Job review tab, see the partner's clock sessions (with their notes) per job, and bulk re-assign sessions that were clocked to the wrong job. Client-only — no migration.

**Kernel** ([`partnerSessionReview.ts`](../../src/lib/partnerLedger/partnerSessionReview.ts), 4 tests): `sessionHours` (tenth-hour rounding, null for open sessions), `statementWeekFor` (inclusive period match against generated `pay_stubs` weeks), `shapeReviewSessions` (drops rejected/revoked, stamps approved/pending/open status + statement week, newest first), `summarizeSelection` (count/hours/statement-covered count for the action bar).

**UI** ([`PartnershipJobReviewTab.tsx`](../../src/components/partnerships/PartnershipJobReviewTab.tsx)):
- The hours subline gains a **sessions ▾** toggle (stopPropagation — the row still opens the Job window). One job expands at a time; the panel lists day, in–out times, hours, the session `notes` (italic; muted "no note"), an amber "on stmt wk MM-DD" chip when a generated statement covers that week, and approved / pending approval / still clocked in.
- Sessions fetch office-side: `clock_sessions` by the partner's `people.account_user_id` + the job; statement weeks from `pay_stubs`. Fail-soft when the partner has no linked app user.
- **Bulk move**: checkboxes + select-all; a blue action bar totals the selection ("N sessions · X.X h"), a job search picker (HCP/Click/name, trade pills, current job excluded) chooses the target, and **Move hours** updates `job_ledger_id` on the selected rows — the same single-column update the My Time day editor performs, so RLS was already in place. The queue and open panel reload; a success note names what moved where.
- **Guardrails said out loud**: selecting statement-covered sessions shows "pay stays as stamped; the hours move for job costing and review shares"; the panel footnote states the move edits the real clock record (job costing, Crew P&L, shares all follow; approval status untouched).
- **Audit**: every move logs a `partnership_events` row (`config_changed`, patch `sessions_reassigned` {from/to job, session ids, hours}) — the existing CHECK constraint's types are reused, no DDL.

Verified live with a roundtrip on Bryan's data: moved the 9.0 h "Stone Oak" session #813 → #898 (queue recomputed: #813 dropped out, #898 61% → 70%) and back (exact original state restored). Two `sessions_reassigned` audit events from that test remain in the partnership's event log, accurately describing the roundtrip.
