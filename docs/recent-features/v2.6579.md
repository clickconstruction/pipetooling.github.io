# v2.6579 — The archived guard swept into every edge function that reads the caller and switches to the service role (punch list #256, PR 7b) (2026-11-06)

Punch list #256's seventh-and-a-half PR, the mechanical half of the seal. PR 7 (v2.6572) put three locks in the database and wrote the fourth, `refuseArchivedCaller` in `_shared/refuseArchivedCaller.ts`, with a check that listed the 104 functions that read the caller (`auth.getUser`) and switch to the service role without calling it. Such a function queries as nobody, so the pre-request gate and the `archived_fence` policies see no archived caller to refuse. This PR puts the call into all 104 and makes the check part of CI. The seal's migration `20261106120000_archived_seal` was pushed to prod on 2026-11-06, and its rolconfig check lists `pgrst.db_pre_request=public.archived_pre_request` on `authenticator`; a signed-in read of `users` over the API still answers.

## What changed

- **104 functions** gain `const archivedRefusal = await refuseArchivedCaller(<admin>, <user>?.id, corsHeaders)` / `if (archivedRefusal) return archivedRefusal` right after the caller is read and the service-role client is declared, with the import. 97 came from `node scripts/codemods/archived-guard-sweep.mjs` (the two caller shapes, the client by name, by the key's variable or as a helper's parameter, a brace walk so the guard never lands out of scope); seven from `python3 scripts/codemods/archived-guard-hand-edits.py supabase/functions`, each on an anchor that must be found exactly once: the two dry-run helpers that answer a boolean (`bridge-weekly-sheet`, `messages-nudge-dispatch`, an archived dev may not dry-run), two functions whose service client exists only when the key is set (`driving-distance`, `send-workflow-notification`), and three that read the caller in one block and make the client in another (`notify-estimator-request`, `send-physical-invoice-email`, `sync-mercury-transactions`). Nothing else in any function moved.
- **`ci.yml`** runs `npm run check:edge-archived-guard` after the link step, so a new function that reads the caller and switches to the service role without the call fails the PR.
- **`docs/EDGE_FUNCTIONS.md`**'s archived-guard paragraph now reads as the rule for a new function, and the card's row 7b and `next` line are amended (the seal is pushed; PR 8 is next).

## Decisions

- **A mechanical sweep, merged alone.** The change touches 104 files by script; `CLAUDE.md` has it cut from fresh `main` and merged before the next feature PR, and on a rebase conflict the codemod is re-run on the new `main` rather than hand-resolved.
- **The guard sits after the caller read, not after the 401.** `refuseArchivedCaller` answers null for a missing user id, so a request with no caller reaches the function's own 401 unchanged; only a real, archived caller is turned away.
- **Deployed in batches right after the merge.** Editing `supabase/functions/*` does nothing until deployed; the 104 functions were deployed from `main` after the merge, `check:edge-drift` clean after.
