# v2.7014 — Pipeline: the search box wraps to its own line instead of pushing the page sideways at 760 px (2026-11-12)

The post-deploy `E2E Smoke` check `no sideways overflow at 760px: /jobs?tab=stages` has failed on every run since 2026-11-02 14:52 UTC (the document 86 px wider than the viewport). The last green run (41463532056) ran on `133665b81` (v2.6329), and the first red run (41466036920) ran on `380c99d95` (v2.6330, #6774), which added the **Projects** press to the Stages command bar.

**Cause.** `JobsStagesCommandBar`'s row is `flex-wrap: wrap`. Its search box was `flex: 1 1 16rem; min-width: 0`, but everything inside it (the clock and `#` chips, the applied-filter chips, the ZZ chip, the ⋯ tools menu) is `flex-shrink: 0`. With Projects added, New Job + Follow-ups + Forecast + Projects take about 404 px of the 712 px column. That leaves about 308 px, which is still above the box's 256 px basis, so the box stayed on the first line and shrank to the leftover width. Its chips then ran past it and past the page. The ⋯ sat at 765–797 px in a 760 px viewport (dev account: 37 px over; the smoke account: 86 px).

**Fix.** The box carries `.stagesSearchBox` (`src/index.css`), which sets `min-width: min-content` above 640 px. Below 640 px it sets `min-width: 0`, as before. The box is never narrower than its chips, so where they do not fit beside the presses, the row wraps the box onto its own full-width line. On a phone the box already has a line of its own, and `min-content` there would only widen it past the screen, so the old rule stays.

**Measured** (local dev server, dev login, `scrollWidth - clientWidth` on `/jobs?tab=stages` after the Working count lands): 760 → 0 (was 37), 768 → 0, 900 → 0, 1400 → 0 (the box stays on the presses' line). At 375 a dev still measures 57 px, the same as before this change. That overflow comes from the dev-only *N ZZ test jobs hidden* chip and is left for its own fix. The smoke account does not see that chip, and its 375 run was already green.

No migration, no edge deploy.
