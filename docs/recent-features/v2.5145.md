# v2.5145 — Contracts: send-job-contract's link mode stamps nothing on a row already out with a live link (2026-10-10)

Punch list #104 (`to-dos/contract-copy-link-keeps-pdf-send.md`), its follow-up 1. Built by PUNCHLIST Helper 14. Edge function `send-job-contract` changed; no migration.

## Why

[v2.5119](v2.5119.md) made the app's link doors hand out the link a sent agreement already carries:
- the Contract window's Copy link, Text the link, Open the signing page on this device, and Send a link's text-only branch;
- the Dashboard's Hand the phone.

They call nothing when the link is live. But `send-job-contract` itself still stamped any row it was asked for in link mode: `sent_channel: 'link'`, `send_count + 1`, a fresh `last_sent_at` and reminder, and a `sent` event ([v2.3723](v2.3723.md)'s rule). So a door that reached it with a live link would still turn an agreement emailed as a PDF to sign into a link send. That can happen through the doors' fallbacks, or through any door added later, and File the signed copy then no longer converts the row.

## The change

- **`jobContractLiveToken(row, nowMs)`** (`supabase/functions/_shared/jobContractLinkLive.ts`, new, no imports) holds the one rule. It returns the token of a link live enough to hand out as it is: the row is `sent`, not voided, has a token, and the link has more than **`JOB_CONTRACT_LINK_HANDOUT_MARGIN_DAYS`** (7) left. A link with no expiry counts as live, as `sign-job-contract` reads it. Otherwise it returns null.
- **`send-job-contract`**: in link mode, after its refusals (voided, signed, no terms), a row with a live token is answered with `{ ok, emailed: false, sign_url, reused: true }`, and nothing is written. `sent_channel`, `send_count`, `last_sent_at` and `next_reminder_at` stay, and no `sent` event is logged. A draft, a row with no token, or a link with a week or less left goes through the send as before, which mints or renews the link and stamps it. Email mode always sends.
- **The app's `jobContractLinkOnRow`** (`src/lib/jobs/jobContractLifecycle.ts`) now reads the shared rule, so the doors and the function decide the same way with the same margin. `JOB_CONTRACT_LINK_HANDOUT_MARGIN_DAYS` is re-exported from there for its old importers.

Quick send (`jobContractQuickSend.ts`) only ever sends in email mode or as a PDF to sign. Those are real sends, so v2.3723's rule still applies to them.

## Tests

- `jobContractLinkLive.test.ts` (new, 6):
  - the rule: live, a draft carrying a moved token, voided, signed, no token, and the margin at its boundary;
  - the app's `jobContractLinkOnRow` agrees with the rule on every case;
  - `send-job-contract`'s source is pinned: it imports the rule, asks it in link mode only, and answers after its refusals and before any update, `sent` event or email.
- Two kernel mutants each failed it: no margin, and no voided check.
- The link door tests from v2.5119 still pass.
- No local Deno: the function is type-checked at deploy.

## Deploys owed

`bash scripts/deploy-functions.sh send-job-contract` from the main checkout after the merge, then `npm run check:edge-drift`. Until then the doors' own check keeps a live link from reaching the function.

## Verify after deploy

On a ZZ TEST job, send an agreement with **Email the PDF** to our own address. Then, from a page that calls link mode on that row, say the in-person door with the row's own link check bypassed, or the function called directly with the office's session:
- the answer carries `reused: true`;
- the row still reads `sent_channel = 'pdf_email'`, with the same `send_count` and `next_reminder_at`;
- no new `sent` event is logged.
