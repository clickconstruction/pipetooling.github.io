# v2.2266 — Stage-mode gear, ⇊ parallel badges, task delete, hold-to-open (2026-08-25)

Follow-up batch on v2.2264's sequential stages. UI-only — no migration (writes
the existing `checklist_tech_tree_groups.sequential` column).

## Stage-mode gear (Map)

- Every `GroupNode` grows a third hover button (⚙, under ✎ and ＋, editors
  only). It opens a new `stageMode` kind in `ChecklistTechTreeCanvasMenu`:
  header "How tasks in <stage> go out", two items — "→ In order, one at a
  time" / "⇊ All at once (parallel)" — current mode highlighted with a ✓, plus
  a one-line explainer for the active mode.
- Picking a mode updates `groups.sequential` and reloads; the reload re-runs
  the sync, so flipping to parallel materializes every open task immediately
  and flipping back returns not-yet-due tasks to ⏳ Coming up (v2.2264
  semantics — the gear and the stage edit dialog write the same flag).

## ⇊ parallel badges

- New `src/components/checklist/RoadmapParallelBadge.tsx`:
  `ParallelArrowsIcon` (FA double-down-arrows path) + a blue-tint chip
  (`compact` = icon-only). Only the exception is marked — sequential (default)
  stages stay unbadged.
- Shown on the Map node badge row, Plan stage headers
  (`parallelGroupIds` prop), and the Timeline rail rows (compact).

## Task delete (task card)

- `useTechTreeTaskMutations.deleteTask`: removes the roadmap task and any
  materialized `checklist_items` with **no** completed/reviewed instance —
  completed history is never touched. Editors only.
- Task card gains a two-step "Delete task… → Delete permanently" (copy:
  "Removes this task from the roadmap and any unfinished list entry.
  Completed history stays.").

## Hold-to-open task rows (Map)

- `useTaskRowLongPress` in `ChecklistTechTreeGroupNode`: 500 ms press-and-hold
  on any task row (10 px move tolerance; presses on inputs/buttons/links
  ignored) opens the task card — works for every viewer, not just editors,
  replacing the old title-span-only, edit-only long-press.

## Copy

- Stage edit dialog: "→ In order (4.1 then 4.2 …)" trimmed to "→ In order".

Verified live on prod (throwaway TEST GEAR stage): gear round-trip both
directions, badges on all three surfaces, delete round-trip, DOM-level
