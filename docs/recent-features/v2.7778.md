# v2.7778 — Painted maps: a shared link shows each place with its mark (2026-11-18)

Punch list #393, reading B, the shared page. The marks are v2.7776 and the copies v2.7777. A reader of a link at `/way/<code>` saw every place as a plain numbered dot, since the page reads through the `painted-map-link` function and that function names the columns it reads.

## What changed

- **`painted-map-link`** reads `painted_map_places.kind` with a map's places and hands it on in each place of `map.places`.
- **`sharedPaintedMap`** (`_shared/paintedMapLink.ts`) passes a kind through as the table's check keeps it: one lowercase word of 2 to 24 letters and underscores. Anything else is no kind. It holds no list of kinds, so a new kind needs no deploy of the function.
- **The page** (`PaintedWay.tsx`) draws the mark beside each place's name (`PaintedPlaceMark`) and hands the kind to the map, which draws the dot as the app does. A word the page does not know is the plain dot.
- **The sample page** at `/way/sample` gives its truck gate a gate's mark, so the office sees what a reader sees.

## What a reader is told

One more field of a place: its kind. It names nobody and nothing else of the job. The test that a shared map carries no name, job, day or file still holds.

## Order

Any order is safe between the page and the function. A new page with the old function gets no kind and draws plain dots. An old page with the new function ignores the field. The function itself must be deployed after migration `20261118080000_painted_place_kind.sql` is pushed, since its read names the column.
