# v2.1899 — Parallel-session discipline: sweeps merge alone, regen don't resolve, session-card nag (2026-08-20)

Follow-up to the v2.1898 fragments cutover, closing the remaining (minority) conflict sources between parallel sessions — real code overlaps rather than changelog collisions:

- **CLAUDE.md conventions**: mechanical sweeps (grep/script-driven multi-file changes) are cut from fresh main and merged alone, with rebase conflicts resolved by **re-running the transformation**, not hand-merging; generated files (`src/types/database.ts`) are likewise **regenerated** on conflict, never hand-resolved (the v2.1890 regen PR + v2.1891 sweep vs. v2.1895 studio rework both hit exactly this).
- **Session-card nag**: [`claim-version.ts`](../../scripts/claim-version.ts) now warns after a successful claim when `.claude/sessions/active/<branch-slug>.md` doesn't exist — version claims stop number races, but only cards stop two sessions redesigning the same component (the ledger showed 1 card during ~6 concurrent streams today).

Client-only — no migration.
