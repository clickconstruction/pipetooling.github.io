# v2.4728 — Won asks which option the GC took, and the bid room can sign any of them (2026-10-06)

The v2.4723 follow-up (PR 2). No migration. **Redeploy `sign-bid-room` and `get-bid-proposal-room`** (both bundle `_shared/bidRoomPayload.ts`, which now parses `bid_version_id` on an option; `sign-bid-room` also bundles `_shared/bidRoomOutcome.ts`).

## The record

A letter with two options (two or more base versions, v2.4723) needs the win to say which one. The record is **`bid_versions.outcome`**: the taken option reads `won`, the others stay as they were — not taken is not lost, so no loss reason and no *Why we lost* row. The taken option also becomes the bid's active version (`bids.selected_bid_version_id`), so the job opened from the bid, the takeoff and the labor follow what was signed, and `bids.agreed_value` is that option's sent value plus the accepted add-ons (the v2.4211 rule, on the option's number). No new column.

## What changed

- **Kernel** [`wonOption.ts`](../../src/lib/bids/wonOption.ts): `letterOptionVersions(versions, packetCustomerId)` (the packet's base versions in the letter, step-1 order), `wonOptionVersionId`, `wonOptionWrites` (the chosen to `won`, any other option that read `won` back to unanswered), `agreedValueForOption`, and `roomSectionsForLetterOptions` — the room's pickable proposals for a letter with options: Option 1, Option 1 with each of its alternates, each other option, each with its alternates, every one carrying its version. [`wonOptionWrite.ts`](../../src/lib/bids/wonOptionWrite.ts) `recordWonOption` does the writes and returns the option's latest sent value (`latestSendByVersion`).
- **Edit Bid → Won** ([`BidFormModal.tsx`](../../src/components/bids/BidFormModal.tsx)): the form loads the bid's versions and sends; with two or more options a radiogroup *Which option did they take?* sits above the alternates question (`data-testid="bid-won-option"`), each option with its sent value; a pick writes at once and fills **Agreed value**.
- **The bid room**: `RoomOption.bid_version_id` (optional, both parsers, parity test); the Cover Letter tab hands the room `roomSectionsForLetterOptions` named by the letter's own labels (*Option 2 — Value Engineered · Alternate 2*). [`sign-bid-room`](../../supabase/functions/sign-bid-room/index.ts): `wonVersionIdsForSignature` (in `_shared/bidRoomOutcome.ts`) wins the signed option's version alone when the option carries one (else the packet, as before), sets `selected_bid_version_id`, and the agreed value is the option's own total plus the taken add-ons; the `signed` event carries `option_version_id`.
