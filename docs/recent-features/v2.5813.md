# v2.5813 — Quickfill: Roller is the default view from now on (2026-10-24)

The owner, from a screenshot of the Page · Focus · Roller switch with Roller lit: "On quickfill, I would like roller to be the default from now on."

- **How the default was decided.** The view is `?view=` on the URL for the visit, else the one the person chose last, else a fallback. The choice lives per person on the device (`localStorage`, `pipetooling_quickfill_view_<userId>`, the Needs you card's Cards / Walk precedent); there is no preference row in the database and nothing per org, so nothing is migrated. The fallback was the literal `'page'` in the page's `useState` initializer ([`Quickfill.tsx`](../../src/pages/Quickfill.tsx)) and nowhere else.
- **The change.** [`lib/quickfill/views.ts`](../../src/lib/quickfill/views.ts) gains `QUICKFILL_DEFAULT_VIEW = 'roller'` and `quickfillOpeningView(search, userId)` (URL, then memory, then the default); the page's initializer calls it. The effect that re-reads the URL and the memory when the user or `?view=` changes is untouched: it still leaves the state alone when both are empty, so `?view=focus` followed by a station link keeps Focus as before. **Existing choices keep their value**: the memory is read before the default, so anyone who pressed Page or Focus opens there still; only a device with no saved choice changes.
- **The phone.** Under 640 px the page is the round (v2.3783) whatever the view says, and the switch is not drawn; `rollerActive` is `!narrowViewport && view === 'roller'`. So at phone width nothing changes, and the page already opens one station at a time.
- **Tests.** `views.test.ts` pins the default and the three steps: nothing on the URL and nothing saved opens the Roller, a saved Page still opens Page, `?view=focus` wins for the visit. The switch's render smoke takes its view as a prop and needed no change.
- **Guide.** *run the office day with Quickfill*: the switch's paragraph now names all three views and says Quickfill opens on Roller until you pick another; the Roller section says the same. Docs: `QUICKFILL_ARCHITECTURE.md` (the owned-state sentence), `GLOSSARY.md` (the Quickfill entry).
- **Live check** as the dev on a fresh profile: `/quickfill` with the saved view cleared opened on the Roller at desktop width; a saved Page choice opened Page; at phone width the round list drew as before.

## Is this the best we can do?

- The default is one constant and the owner's call; a per-org setting would be a Settings row and a read on every visit for a choice made once.
- A person who never pressed the switch and liked the whole page now presses Page once; the device remembers it from then on.
