# v2.3168 — Price coverage means price coverage: the Parts Book modal drops its house CRUD (2026-09-08)

Client only. No migration or edge-function change. PR 3 of six from [`to-dos/supply-house-directory/`](../../to-dos/supply-house-directory/README.md).

## Why

The green **Price coverage** button on the Parts Book toolbar opened a modal that was two things at once: the per-service-type coverage table it is named for, and — beneath it — an **+ Add Supply House** button, an inline house form, and a Name / Contact / Phone / Email list with **Edit** on every row. That second half was the third copy of supply-house editing in the app (the office tab and the RFQ window being the others) and, since v2.2903 renamed the button, the only door estimators had — reachable by nobody who was looking for it. `MATERIALS_TABS_ARCHITECTURE.md` carried it as **quirk 16**. With the Directory pane (v2.3166) and the estimator's tab (v2.3167) there is now one honest home, so the modal keeps only what its name says.

## What shipped

- **The modal is the coverage table and nothing else**: the service-type headers ("Plumbing: 1,204 items | 62% have prices | 18% have more than 1 price") and the per-house counts. Where the house list stood there is one line: *Houses, reps and websites live on the **Supply houses tab** — add or edit a house there.* For roles that have the tab the words are a button that closes the modal and switches to it; primaries and superintendents (who read the books only) see the sentence without the link.
- **Gone from `Materials.tsx`**: the nine-field `supplyHouse*` state cluster, `openAddSupplyHouse` / `openEditSupplyHouse` / `closeSupplyHouseForm` / `saveSupplyHouseFromFormData` / `deleteSupplyHouse`, the inline `SupplyHouseForm` and the `SupplyHouseFormData` import — the file loses about 200 lines and its last supply-house write. The one editor is `useSupplyHouseEditor` (v2.3166).
- The Price coverage button's tooltip no longer promises "plus the supply-house list".

## Behaviour change, stated

Primaries and superintendents could add and edit houses through this modal until now (the baseline RLS let them). The v2.3167 predicate already withdrew the database side; this PR removes the UI side. Nobody in those roles has asked for house editing; if one does, the answer is a row in `materialsTabsFor` and the predicate, not a modal.

## Docs
