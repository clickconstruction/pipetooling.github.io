# v2.2274 — Reactive ✓ + five-second undo on Outstanding rows (2026-08-25)

Owner request (mockup artifact 55d69b29) on the Review tab's
Outstanding-by-person ✓ (`markComplete` in `src/pages/Checklist.tsx`):

- **Instant press feedback**: while `completingInstanceId` is the row, the ✓
  fills `#16a34a` with white glyph + `scale(1.08)` (120ms transitions) and
  the row's main area strikes through at 0.65 opacity — optimistic, before
  the network answers.
- **Undo toast**: after the batch UPDATE commits, a fixed bar (above the
  phone tab bar, z-index 1001) shows "✓ Completed [×N] — title", an Undo
  button, and a 3px timer draining over 5s (`checklist-undo-drain`
  keyframes). Missed-group rows (v2.2272) undo all N copies.
- **Held side effects**: the watcher notifications and the
  `days_after_completion` materialization moved into a deferred closure
  (`pendingSideEffectsRef`) that runs when the 5s timer fires — Undo cancels
  it, reverses the UPDATE (`completed_at/completed_by_user_id → null`), and
  re-fires `checklist-instance-completed` so the sign-off queue drops the
  row. A second ✓ inside a window commits the first
  (`flushPendingCompletion`), and unmount flushes rather than loses.
- The DB write itself is immediate — only the fan-out waits — so a closed
  tab can at worst skip a notification/next-occurrence, never lose a
  completion. Verified live: full press → toast → Undo cycle with zero
  `send-checklist-notification` calls and the row restored.
