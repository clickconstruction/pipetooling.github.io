# v2.3393 — Drive pass: only a labelled job number matches (2026-09-14)

Client only; no migration, no edge function. Follows v2.3392 the same day, from the same first live pass of Found in Drive ([`to-dos/contract-sweep-seen-first/`](../../to-dos/contract-sweep-seen-first/README.md)).

## Why

`folderMatchesJob` in [`driveContractMatch.ts`](../../src/lib/jobs/driveContractMatch.ts) tried the job number first with an optional `J` prefix, so any bare number token in a folder name counted. The chain walk from v2.3392 put street subfolders into the folder name (`_Hadlow Construction / 105 Dorrow`), and "105 Dorrow" matched J105 (a different customer) at the *number* strength — the strongest there is — ahead of the customer-name match that was right.

## What shipped

- The number branch now requires a label: `J105`, `Job 105`, `HCP 105` or `#105` (optional space), never a bare `105`. Street and customer matching are unchanged, so `105 Dorrow` still reaches J931 Hadlow through the street key.
- Test: a bare number in a street is no match; a labelled one still is.
