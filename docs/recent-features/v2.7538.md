# v2.7538 — Bids: reach Keep its files on the bid from the bid and from the site's History (2026-11-16)

Punch list #368, PR 3 of four. PR 2 (v2.7534) put the press on the mail's window in Messages and in My email. This PR adds the two other doors and the record on the site. No migration and no function.

## From the bid

Edit Bid → Plans → Plan sets has a second press beside *+ Add a set of plans*: **+ From a mail on this bid**. It reads the bid's email that carries a file (`mailsOf`: `messages` on the bid, channel email, with their attachments embedded; a mail whose only attachment is a link is left out) and lists each with its subject, sender, day and file count. Every row draws `BidMailSetDoor`, so it shows the press, or the green *Kept as …* chip once the mail's files are in a set. A keep reads the Plan sets again. An empty list says nothing is waiting, and a read that fails names its reason with **Read again**.

This is the door for the person who starts from the bid and does not know whose thread holds the mail.

## From the Development page

`readTiedMail` takes a third read, the files on the bids' tied mail (`message_attachments` by `message_id`, with the kept mark; read again without the mark's column when the database does not have it; fail-soft). `mailLines` counts each bid mail's files into `mail` on its line: how many we hold that are in no set, and how many already are.

- **Keep its 2 files…** on the line, for a mail with a file to keep. It opens the line's window, which now draws `BidMailSetDoor` under the mail's words. The form needs room, and the window already shows the subject and the whole body.
- ***kept on the bid***, in green, once every file we hold is in a set.

The page reads again when the window closes after a keep, not under it.

A job's mail draws neither: a job keeps a paper, and that press is PR 4.

## A set draws its own line

`setLines` draws one *New set* line for each `bid_plan_sets` row on the site's bids, at the time it was added, by who added it, with *from a mail* when its files came that way. It sits under the **Plans** chip with the plan filings. The set the robot reads is left out: its filing already draws as *New plans* or *Plans again* from the bid's own ledger, and one filing is one line.
