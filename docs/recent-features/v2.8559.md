# v2.8559 — Bills sent: the box of test bills now holds the bills made in Stripe's test mode (2026-11-24)

Punch list #340. A fix for what the live walk of 2026-11-25 (UTC) found: the box v2.8540 shipped never drew on the live site. Client only. No migration, no edge function, nothing owed after the merge.

## What was wrong

v2.8540 gave a dev who shows ZZ test jobs a box of the test bills with no send on record, so **Say how it went…** could be tried on a test bill. Two lines kept that box empty on prod:

- `readBillsSent` (`src/lib/billing/billsSentIo.ts`) read the bills with no send stamp with `.or('stripe_mode.is.null,stripe_mode.neq.test')`. Every bill made in Stripe's test mode was dropped by the database before the page saw it.
- `unsentNewestFirst` (`src/lib/billing/billsSent.ts`) marked a row a test with `isBillsTestRow(null, job)`: by its job's name alone, never by the bill.

Stripe's test mode is the only way a walk is cleared to make a bill. So the box could hold none of the bills a walk makes, and it held a bill only when a live-mode bill stood on a ZZ test job with no send. The walk read the ZZ jobs' bills through the dev seat and found none.

No test crossed the line between the read and the kernel: the kernel's tests handed it rows by hand, and the read had no test at all.

## What changed

- `billsSentIo.ts`: the read of bills with no send no longer filters on `stripe_mode`, and each row carries the bill's mode (`stripeMode`).
- `billsSent.ts`: `BillsSentUnsent` gains `stripeMode`, and `unsentNewestFirst` hands the bill's mode to `isBillsTestRow`. A row is a test when its bill was made in Stripe's test mode or its job is a ZZ test job, the one rule `billTestRows.ts` already held for the list's lines.
- `billsSentGaps` and `billsSentTestGaps` are unchanged: both read `unsentNewestFirst`, so the yellow box leaves both kinds out and the box of test bills holds both.
- `BillsSentLedger.tsx`: the three typed boxes of **Say how it went…** (the name, the day, the note) take `minHeight: THUMB` on a phone. The walk read the name box at 34 px and the day box at 36 (punch list #414).

## What did not change

- The yellow box, the **No send on record** chip, the **Not paid** tile, the print and the spreadsheet hold no test bill, for every role. The filter moved from the database to the kernel and answers the same.
- The box of test bills is still worked out only for a dev who shows ZZ test jobs (`useZzTestJobsHidden`).
- The guide `see-which-bills-went-out` already says a bill made in Stripe's test mode is a test bill and that a developer reads test bills with no send in a box of their own. Its words are now true, so it is not edited.

## The other readers of those rows

- `known`, built from the same rows, feeds `allBills`: the look-up a text's pay link reads, the job read and the payments read (`readPaid`). A wider list there adds a few ids to two reads and changes no line.
- The read's cap: test-mode bills now count toward it. Read on prod through the dev seat on 2026-11-25 (UTC): 89 bills answer the read, 6 of them made in test mode, against a cap of 300 on the first page. The cap is far off.

## Tests

- `billsSentIo.test.ts`, new for the read: a small database in memory answers `readBillsSent`. The read of bills with no send asks for no mode, selects it, and carries it. The read's own answer then goes through `billsSentTestGaps`, `billsSentGaps` and `billsSentOut`: a test-mode bill on a job that is no ZZ job lands in the box of test bills and in no total.
- `billsSent.test.ts`: a test-mode bill is in the box on a ZZ test job or not, once, paid or not; the yellow box and the **Not paid** tile move by the live bill alone; a bill with no mode on a real job is a real gap.
- `BillsSentLedger.render.test.tsx`: the office sees the live bill in the yellow box and no box of test bills; a dev who shows ZZ test jobs sees the same yellow box and the same tile, with the test-mode bill in its own box and no real bill offered to tick. On a phone the three typed boxes read 44 px.
- All three new tests fail on the code before this change.

## Not walked

Not seen on the live page. The recipe is on the card: as the dev with **ZZ test jobs** shown, `/bills-sent` draws the box, and the yellow box's count does not move.
