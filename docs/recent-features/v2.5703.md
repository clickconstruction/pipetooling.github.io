# v2.5703 — Messages: a sent text says whether it was delivered (2026-10-21)

PR 11 of punch list #139 (`to-dos/press-always-answers/README.md`), the first of the six additions the owner took from the holistic mock-up ("I like all of these suggestions, please add them all"). Quo's delivery event already writes `messages.delivery` on our sent line (`delivered`, `undelivered`, `failed`, the kernel's `QuoDelivery`) and a team event on a failure — nothing on the client read the column, so a bounced text read "texted" everywhere. No migration; no edge function change.

- **The thread** (`src/lib/messages/thread.ts` `deliveryMark`, `deliveryOf`; `load.ts`; `messagesIo.ts` `MESSAGE_COLS` + `delivery`; `ThreadLine.tsx`): a sent text's time carries Quo's answer — **✓ delivered** in green, **⚠ not sent** (`failed`, it never went out) or **⚠ not delivered** (`undelivered`, sent and never reached the phone) in red, each with hover words; nothing while Quo has not answered, and nothing on any other line.
- **The lane** (`wentOut.ts`, `wentOutIo.ts`, `WentOutToday.tsx`): each row's mark beside its time; a text that did not reach them draws red with **☎ Call them** on the row (`telHrefFor` of the number it went to, read through `messages_channel_id_fkey`), its own press so the row still opens the thread.
- **Not in this PR**: the owed-call row the mock-up drew (*Call Marcus Calloway · his booking text did not deliver* in We owe them). The honest version is a real call task written when Quo reports the failure — an edge change in the webhook's kernel copy — rather than a synthetic row the lane could not mark done; it follows as its own PR with a deploy.
