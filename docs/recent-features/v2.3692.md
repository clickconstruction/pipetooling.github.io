# v2.3692 — Cash on a Stripe bill: Record payment on the bill, and the hand-typed line never locks (2026-09-21)

Assistant Taunya, on her phone, on job 1022 (a $1,500 Stripe bill sent the same day): *"I type in the 1 and it auto posted and wouldn't let me type the full 1500."* Three tries left three locked $1.00 rows on the job. Not a phone bug — the desktop does the same. Design and phone mock-ups: artifact `H3rbLask4CaMRZxbzPfNns`. Client only; no migration, no edge-function change.

## What was wrong

Four rules, each right on its own, met on one job:

1. `MoneyDecimalAmountInput` commits on every keystroke (`commitOnType`), so "1" is a real $1 payment.
2. A row's first real amount auto-attaches it to the job's single `billed` invoice (v2.2240, `autoApplyInvoiceId`).
3. Any row attached to a Stripe bill (`stripe_invoice_id`, or `external_send_channel = 'stripe'`) is drawn read-only — receipt icon, no amount input, no remove — because the table assumes Stripe wrote it (`stripeBillInvoiceForPaymentRow`).
4. The billing autosave persists ~1.2 s later.

The window that records cash on a Stripe bill correctly — `BilledPaymentConfirmationModal` mode="invoice" → `record-stripe-invoice-out-of-band-payment` (Stripe `paid_out_of_band`, then the webhook writes the ledger row) — only opened from Pipeline's *Mark Paid*, the Dashboard and the Edit tab's Paid step, never from the Bill tab where the bill is.

## The change

- **Kernel [`paymentInvoiceLinking.ts`](../../src/lib/jobs/paymentInvoiceLinking.ts)** — `invoiceRecordsThroughStripe(inv)` is now the one definition of "a Stripe bill" (`jobsLedgerInvoiceIsStripeLinked` delegates to it). `autoApplyInvoiceId` and `paymentRowNeedsInvoiceLink` consider only open non-Stripe bills; new `openStripeBills(invoices)` lists the hand-off targets. [`paymentBillMatching.ts`](../../src/lib/jobs/paymentBillMatching.ts): `billChoicesForPayment` never offers a Stripe bill. Tests for each.
- **[`JobFormInvoiceList.tsx`](../../src/components/jobs/JobFormInvoiceList.tsx)** — every billed, unpaid row gets **Record payment** (`.jobInvoiceRecord`, blue like *Send bill…*; full-width under the Text · Copy link · Email cluster in the ≤420px container) and a *Record payment · cash, check* item at the top of its ⋯ menu; both call the new `onRecordPayment(inv)` prop.
- **[`JobFormPaymentsTable.tsx`](../../src/components/jobs/JobFormPaymentsTable.tsx)** — the pill reads **+ Record a cash or check payment**. A real unlinked row on a job with open Stripe bills shows, per Stripe bill, the amber note *The $X bill went out through Stripe. Record the payment on the bill so Stripe knows it was paid* with **Record on the $X bill →**, which calls `onRecordPaymentOnBill(inv, { amount, draftRowId })`. The Applies-to selector lists only non-Stripe open bills (and hides when there are none). The ⓘ explainer gains the sentence.
- **[`BilledPaymentConfirmationModal.tsx`](../../src/components/jobs/BilledPaymentConfirmationModal.tsx)** — new `initialAmount` (prefills a non-Stripe bill; on a Stripe bill the whole open balance is recorded and a note says *You typed $X … this records $Y*) and `zIndex` props; `payments` accepts any `{ invoice_id, amount }` slice so the form's own rows can be passed; the invoice-mode title is **Record a cash or check payment** for both paths.
- **[`JobFormModal.tsx`](../../src/components/jobs/JobFormModal.tsx)** — hosts the window (`recordPaymentTarget`, nested overlay z-index). `finishRecordPaymentOnBill(draftRowId)`: cancels the pending billing autosave, waits out an in-flight one, deletes the typed draft by id through `remove_jobs_ledger_payment_and_reconcile` (a never-persisted row answers *Payment not found*, ignored), re-reads the job so the row Stripe wrote appears, toasts *Payment recorded.*
- **Guides** — *bill a customer and get paid* (Billed → Paid: the button, the hand-off, the full-balance rule) and *see when a customer will pay* (Recording payments so they count).

## Left open

- Part-cash on a Stripe bill: `record-stripe-invoice-out-of-band-payment` pays the whole invoice, so the window still requires the full open balance.
- The Edit tab's "→ Paid" step (`JobStatusStepper`, mode="job" → `mark_job_paid`) records a job-level payment without linking the bill or telling Stripe.
- The lock still infers "Stripe wrote this" from "this row sits on a Stripe bill"; a `recorded_via` column would make it exact and make the census of other jobs with hand-typed rows on Stripe bills a one-line query. Job 1022's three $1.00 rows are a direct delete (the cleanup RPC refuses rows on a Stripe bill).

## Verified

`paymentInvoiceLinking`, `paymentBillMatching`, `jobFormPaymentPredicates`, `JobFormPaymentsTable.render` (four new cases: the hand-off note on a Stripe-only job, Applies-to without Stripe bills, a mixed job, a genuine Stripe row keeping its lock), `helpGuideContent`, `releaseNotes`; every `src/components/jobs` + `src/lib/jobs` suite; typecheck and lint. Live on the dev server against job 1022: the Bill tab shows **Record payment** on the Stripe bill, the pill's new name, the three old rows still locked; the window opens from the button with the open balance and closes on Cancel — nothing was recorded.
