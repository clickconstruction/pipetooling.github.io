## One rule, in a kernel

- `lossReasonState(bid, packets)` in `src/lib/bidLossCategories.ts`: the bid's own `loss_category` wins when set (`source: 'bid'`, reads as before); else, when at least one real GC packet is marked lost and every lost one carries a category, the bid is categorized from the packets (`source: 'packets'`, one `line` per GC with its label and note); else not (`missing` names the lost GCs without a reason). A shared-letter GC and a GC not marked lost never count; a note alone is a note (`hasNote`), not a category. `lossReasonPacketsFromVersions(versions)` builds the packet shape from `bid_versions` rows alone for the one reader that loads no packets.
- Readers: the Lost pile's strip, now its own component `src/components/bids/BidBoardLostStripReason.tsx` (table row and phone card; the row's `aria-label` reads the same words); the Bid Tabs badge on Lost (`lostBidsMissingLossReasonCount`, still clears on a note alone); `bidSentCounts.lostNeedingReason` (`src/lib/bids/bidSentCounts.ts`, now over `opts.packetsByBid`, typed structurally so the Dashboard's versions-only packets fit) and so the Followup bar's *N need a reason* chip, the Why-we-lost headline and the By-status counts; the board's own `boardCounts` now passes `gcPacketsByBid`; the Lost summary modal's red row and its reason cell (one chip per GC, `packetsByBid` prop); the Dashboard's `useLostBidNudge`, which reads `bid_versions` where `outcome = 'lost'` in a second read (a failure there falls back to the bids' column, never hides the card).
- Not changed: the robots' reference grade (`referenceQualityFlags.lossUncategorized` in `src/lib/bids/referenceGrade.ts`) still reads the bid's own column from its slim fields, so a GC-by-GC loss with reasons on the cards is still held out of the gate denominators until that reader learns the kernel — a follow-up; the strip no longer says *can't teach the robots* on such a bid because the humans have recorded the reason, which is what the nudge asks for.
