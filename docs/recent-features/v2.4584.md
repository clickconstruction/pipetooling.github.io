# v2.4584 — Demand letter: Download PDF shows that it is downloading (2026-10-05)

Client only; no migration, no edge function. The owner, on the Lien window's demand letter: *"when a user clicks Download PDF · 6 documents it quickly flips. I would like it to feel more reactive where it shows a color for a few seconds with the button (staying the same size) says 'downloading...'"*

The packet builds in a fraction of a second, so the old *Building…* label was on screen too briefly to read and the button shrank while it showed.

- [`downloadFeedback.ts`](../../src/lib/jobs/downloadFeedback.ts): `DOWNLOADING_MIN_MS` (1,500), `DOWNLOADED_HOLD_MS` (2,000) and `remainingHoldMs(startedAt, now)`, what is left of the minimum once the build is done.
- [`LienInstrumentsModal.tsx`](../../src/components/jobs/LienInstrumentsModal.tsx): `downloadPhase` (`idle` → `busy` → `done` → `idle`) on the button as `data-download-phase`. Busy is solid blue with a spinner and *Downloading…*; done is solid green with a tick and *Downloaded*. The file is handed to the browser as soon as it is built; only the label holds. A failed build goes straight back to resting, with the toast as before. The resting words stay in the layout, hidden, under the state's words, so the width never changes (224.7 px in all three states on job 878, read in the browser). The timers are cleared when the window unmounts.
- Print packet and Email keep `pdfBusy` as before.

Tests: `downloadFeedback.test.ts` (2), one case in `LienInstrumentsModal.render.test.tsx`.
