# v2.3685 — Share with a teammate: send both prices (2026-09-21)

Estimator Grace's ask, from a screenshot of BP385's **Send which price?** dialog: *"Can we make an option to send both? When texting it to Malachi."* She was viewing *Written to Plan* while the customer's price was ★ *Value Engineered*, and the dialog made her pick one.

## What shipped

- **A third choice, Both** — [`BidsPricingTab.tsx`](../../src/components/bids/BidsPricingTab.tsx): the chooser's `starChoice` is `'star' | 'viewed' | 'both'`; the Both radio shows only when the action is share (Print and Export keep two choices), and the button reads **Send both**. `runStarAwareAction(action, choice)` loads the ★ price's rows as before and, for both, hands the modal the viewed price as `also` (its rows are the tab's own `pricingPackageSource`).
- **The package carries two prices** — [`buildBidPricingPackageHtml.ts`](../../src/lib/buildBidPricingPackageHtml.ts) and its Deno mirror [`bidPricingPackage.ts`](../../supabase/functions/_shared/bidPricingPackage.ts): `PackagePriceSection` (`name`, `starred`, rows, total), `packagePriceHeading` ("★ Value Engineered — customer's price" / "Written to Plan — second price"), `buildBidPricingPackageTablesHtml` (one labeled table per price), and an optional `sections` argument on `buildBidPricingPackagePlainText` and on the client-only [`buildBidPricingPackageSmsText`](../../src/lib/buildBidPricingPackageSmsText.ts) (heading line, rows, Total per price). Without `sections` every builder renders exactly as before.
- **Share with a teammate** — [`PackageAndSendBidPricingModal.tsx`](../../src/components/bids/PackageAndSendBidPricingModal.tsx): new `alsoPrice` prop. The caption reads "★ Value Engineered + Written to Plan", the preview shows both tables ("N rows · both prices, ★ first"), and the three lanes send the same pair — **Copy for text**, **Send via my mail** (plain-text body + the two tables on the clipboard) and **Send for me**, which passes `also_price_book_version_id`.
- **Fix found on the live walk: the ★ price priced against the wrong counts.** `packageRowsFromInputs` / `buildPricingPrintContextFor` ran the ★ scenario over the *viewed* version's `pricingCountRows`; when the ★ is an alternate with its own takeoff (v2.2404, another `bid_version_id`, its own count rows) none of its assignments matched and every row came out $0.00 — on BP385, Value Engineered shared as $0 while its card read $290,464.57. `loadScenarioInputs` now also loads the scenario's own `bids_count_rows` when its `bid_version_id` differs from the one on screen (`countRows`, null when the on-screen rows apply), and share, print and CSV of the ★ use them. Pre-existing since v2.2120; the Edge lane was never affected (it loads counts per version).
- **Edge function [`send-bid-pricing-package`](../../supabase/functions/send-bid-pricing-package/index.ts)** — accepts the optional `also_price_book_version_id`; the per-price fetch + recompute is now `loadPricing(versionId)`, called once per price, and the email uses the labeled tables when a second price is present. One audit row as before, on the ★ version. **Deploy it** (`supabase functions deploy send-bid-pricing-package`) — until then Send for me with Both mails the ★ price only.

## Not in this PR

- Print and CSV stay one price at a time. Viewing the ★ price itself opens no chooser, so there is nothing to pair it with — switch to the other price first, then share.
- `bid_pricing_package_sends` records the ★ version only; no schema change.
- Pre-existing mirror drift left alone: the Deno copy's plain-text header says *Unit price* where the client says *Sale Price*.

## Verified

Kernel tests (`buildBidPricingPackageHtml`, `buildBidPricingPackageSmsText`) and a new render smoke for the modal with both prices (caption, two preview tables, Copy for text's clipboard text); typecheck; lint; theme check. Live walk on the worktree dev server (port 5181, dev-login) against prod data, BP385 viewing *Written to Plan* with ★ *Value Engineered*: the chooser shows the third radio, the button reads **Send both**, the modal caption reads "★ Value Engineered + Written to Plan", the preview shows two labeled tables — ★ 85 rows totalling $290,464.57 (matches its card), Written to Plan 86 rows totalling $452,154.78 — and **Copy for text** put 182 lines on the clipboard with both headings and both totals. Then the ★-only choice: one table, $290,464.57 (it was $0.00 before the fix). Nothing was sent or mailed.
