# v2.3162 — "Bids on a map" card on the Bid Board (2026-09-08)

Client only — no migration, no edge function. Owner's ask (2026-09-08), after liking the Dashboard's Google map: offer it to estimators on the Bid Board, collapsible. Designed first as a mock-up (artifact *Bids on a Map*: desktop card, phone form, the alternatives weighed); the reading that shaped it is recorded there and summarized here.

## The reading

- **Estimators never see the Dashboard map.** RLS returns them zero `jobs_ledger` rows, so `DashboardJobsMapCard` renders nothing for the role — this card is their first map, not a second one.
- **The office map already plots bids by section** (`/map`, builder focus, v2.1162) and estimators can open it — but it is an everything-map (jobs, estimates, Geoman, 278 geocodes on load). Its section colors (`BID_STAGE_MARKER_COLOR`) and its geocode cache are reused; people are not sent there.
- **Most bids can be pinned**: 308 of 365 live bids have an address; 283 carry `distance_from_office` (filled on save since v2.3142).
- **The map is a second view of the board's list, never a filter on it.** That is the part a copy of the Dashboard card would not have had, and what makes it a working tool.

## What shipped

- **[`BidBoardMapCard`](../../src/components/bids/BidBoardMapCard.tsx)** — mounts in `BidsBidBoardTab` between the sticky section pills and the first section, for every board viewer (people board and robot board alike); renders nothing when the filtered list has no bid. Input is `filteredBidsForBidBoard`, so the search, the trade pill and My bids drive the pins. Header: pin glyph + **Bids on a map** + "follows the search and the trade pill", the **section chips** (every section in board order with its pinned count; `aria-pressed` toggles — pins only, never the sections below; **Lost starts off**), **Fit all** (desktop, ≥ 2 pins), **Hide map** / **Show map**. Collapsed = the header line only; the preference is per device (`pipetooling_bid_board_map_hidden`). A pin selects the bid and calls `onFocusRow`; the desktop popup / phone bar is the row compressed — label, GC or customer, section chip, due chip (the due-cell tones), estimator, address + `96 mi from the office`, bid value — with **Open bid** (the preview modal, dropped when the page has no preview context), **Edit** (Edit Bid) and **Directions** (Google Maps via `openInExternalBrowser`). Footer: the rule line and *N bids have no map location yet* with up to three links that light the row. Google Maps when `VITE_GOOGLE_MAPS_BROWSER_KEY` is set and loads, OpenStreetMap otherwise — the v2.3145 provider rule (`resolveDashboardMapProvider`), sticky fallback.
- **Office anchor + rings** — [`useOfficeAnchor`](../../src/hooks/useOfficeAnchor.ts) resolves `office_address_v1` else the Map default view center through `resolveOfficeAnchor` (the bid form's Distance to Office anchor), once per page; the canvases draw a navy diamond labelled *Office* with dashed rings at **25 and 50 miles** (`BID_BOARD_MAP_RING_MILES` — the bands the open travel-pricing question is about; change the constant when Wendi answers it). The anchor is part of fit-to-all.
- **Home fit** — with real data the first fit framed half the country (the Gun Dog Trail, Neeses SC bids at 1,158 mi; Dallas). The map now opens on the pins within **150 miles** of the anchor plus the anchor (`BID_BOARD_MAP_HOME_FIT_MILES`, `bidBoardMapHomeFitPoints`, haversine `milesBetween` — Houston in, Dallas and the Valley out; a 300 mi box on the wide, short card still framed the whole Gulf coast); farther pins still draw, and **Fit all** switches to every pin. No anchor, or nothing within range → every pin. The canvases take an optional `fitPoints` override for this. While cold addresses are still being placed the footer says *Placing N more bids…* instead of calling them unmapped.
- **Due rings** — an unsent bid with `bidBoardDueCellParts(...).urgency` of `soon` gets a thick amber stroke, `overdue` a red one (`BID_BOARD_MAP_DUE_RING_COLOR`); sent and decided bids never ring, per the due-cell kernel's own rule.
- **Kernel [`bidBoardMap.ts`](../../src/lib/bids/bidBoardMap.ts)** (11 tests): the board's rows → `BidBoardMapBid` (section via `getSubmissionSectionKey`, archived-unsent dropped — the buckets' rule; label `B385 · Galloway Park…`; GC/customer; due tone + label; estimator; `parseBidDistanceMiles` reads the leading number out of the free-text column; `$44k` value), no-address split, pin resolution, legend, visibility, distance / unmapped copy, the hide preference.
- **Map → row**: `BidsBidBoardTab` gains `mapFocusBidId`; `rowHighlightId = mapFocusBidId ?? deepLinkHighlightId` drives the amber outline the deep-link highlight already paints, the capped-section uncap effect, and a brief `scrollIntoView` retry (the row may render a frame later when its section just opened). A later deep link takes over; the map focus clears after 8 s.
- **Map pill** — first in the sticky row (`{ key: 'map', jumpLabel: 'Map' }`); it scrolls to `#bid-board-map-card` and bumps `revealSignal`, which un-hides a collapsed card and clears the preference.

## Shared canvases (Dashboard unchanged on screen)

- **[`PinsMapCanvas`](../../src/components/map/PinsMapCanvas.tsx)** (Leaflet) and **[`PinsMapGoogleCanvas`](../../src/components/map/PinsMapGoogleCanvas.tsx)** (Google, with the v2.3145 load / timeout / auth / paint watchdogs and render boundary) now hold the drawing; a pin is `{ id, lat, lng, color, ringColor?, title }` ([`mapCanvasTypes.ts`](../../src/lib/map/mapCanvasTypes.ts)), the caller renders the popup body for an id, and an optional anchor draws the diamond + rings. `DashboardJobsMapCanvas` / `DashboardJobsMapGoogleCanvas` are adapters over them (job pins → status colors, the same popup body); their props and lazy paths are unchanged, so the Dashboard card and its render tests did not move. `dashboardJobsMapBounds` delegates to the new `mapPointsBounds`.
- **[`useAddressGeocodeCoords`](../../src/hooks/useAddressGeocodeCoords.ts)** — the cache-then-`geocode-address-batch` lookup extracted from `useDashboardJobsMapPins`, which now wraps it.
