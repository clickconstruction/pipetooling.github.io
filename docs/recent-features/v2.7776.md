# v2.7776 — Painted maps: a mark for each kind of place (2026-11-18)

Punch list #393, reading B, the screens. The column is v2.7775. The owner asked on 2026-11-17 to set points of interest on a painted map, and ticked all three of the card's readings on 2026-11-18.

## What changed

- **Seven kinds**: gate, parking, door, meter, shutoff, cleanout and hazard. Each has a small drawing of its own, kept as path data in `src/lib/paintedMap/paintedPlaceKind.ts`.
- **The chips on a place's panel are kinds now.** They were six names. A press gives the place that kind, and gives it the chip's name only when it has none of its own. A second press takes the kind off. **Hazard** is a seventh chip.
- **The dot wears the mark.** On the map a place with a kind is a slightly wider disc with the drawing in it and the place's number on its shoulder. A hazard's ring and drawing are red. A place with no kind is the numbered dot it always was, to the letter.
- **The same mark is beside the place's name** in the map's own list and on Look it over (`PaintedPlaceMark`).
- A dot's hover title leads with the kind when the name does not say it: *Hazard: Open trench*.

## Rules the code holds

- The list of kinds is the app's. The table's check holds only the shape of the word, so a new kind is a line in one file.
- A kind the app does not know reads as no kind. An older app draws a newer kind's place as the plain dot.
- A kind is written on a change only when the painter changed it, so an older app saving a place does not wipe a kind it does not know.
- A chip never changes a name somebody typed.

## Words

A place is still a *place* and its dot a *dot*. *Pin* stays off the screen, since Pin Mode pins a page. The drawing is a *mark*. The guide's keywords carry *pin* and *point of interest* so a search for the owner's words finds it.
