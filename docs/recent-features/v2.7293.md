# v2.7293 — The kernel copy inlines a row type where a kernel names it, so dev-mcp no longer uploads the slim database types (punch list #359, PR 6) (2026-11-15)

Infra only: no screen and no running code changes. The sixth cut on the #359 card, the slim database types out of dev-mcp.

## Why

v2.7256 made the copy of the kernels hold a slim `types/database.ts`, the tables, views and functions a string in the copy names, 315 KB, in place of the whole 1.48 MB file. Nine kernels dev-mcp reads imported it by `import type { Database }` for one thing each: an alias of a row (`export type CustomerAddressRow = Database['public']['Tables']['customer_addresses']['Row']` in `lienProperty.ts`, a view's row in `costEstimateDirectCosts.ts`, an insert in `submittalRevision.ts`, eight rows in `bidPricingEngineTypes.ts`, two in `types/bids.ts`). Deno erases the import, but the deploy uploads the file, so dev-mcp carried the slim file for aliases it could have written out. Cutting any one importer saved nothing while the other eight stood, which is why the card's PR 2 ("lienProperty off the slim types") became this: one rule for all nine, with no change in `src`.

## What changed

- **The generator reads a file's database aliases** (`databaseAliases` in `scripts/edge-kernels.mjs`): a file that imports `Database` (and `Json`) from the generated types by one `import type` line and writes `Database` only in alias statements of one part of a table, a view or a function (`Row`, `Insert`, `Update`, `Args`, `Returns`). For such a file the copy inlines each alias's body from the parts the generator already reads (`databaseParts`, `memberPart`: the block brought in from eight spaces to none) and drops the import of the slim file. A body that names an enum (`Database["public"]["Enums"]["…"]`), or a file that uses `Json`, imports **`types/databaseCore.ts`** instead (`DATABASE_CORE`): the generated file with every enum, composite type and helper and no table, view or function, 7 KB, written by `slimDatabase` with no names. A body that names a table, a view or a function (a function's `Args` built on a row) is refused with a word to write that type out, since the core cannot hold it. A file that uses `Database` any other way (`Tables<'t'>`, `Database['public']['Tables']`, an alias joined with `& {`) keeps the slim file as before.
- **Nine files are inlined on today's main**: `lib/bids/bidPricingEngineTypes.ts`, `lib/bids/costEstimateDirectCosts.ts`, `lib/bids/laborRowHours.ts`, `lib/gc/boardRows.ts` (its `Json` alone, now from the core), `lib/jobs/lienDeadlines.ts`, `lib/jobs/lienDesk.ts`, `lib/jobs/lienProperty.ts`, `lib/submittals/submittalRevision.ts`, `types/bids.ts`. Each copy file carries a third header line saying its row types are inlined. Nothing in `src` changed: the aliases were already plain.
- **The slim file is held only by the files that still need it**: in the copy today `drawRows.ts` (`Database['public']['Tables']`), `changeOrderOfficeRows.ts` (a row joined with `& {`), `legalRoute.ts` and `customerContactDisplay.ts` (`Tables<'…'>`) and the overhead reads, all portal or Bridge kernels, so the portals still upload it and dev-mcp does not.
- **`edgeKernels.test.ts`**: four planted cases (an alias inlined and the import dropped; the core imported for `Json` and an enum, holding every enum and no table; a missing member and a body naming a table refused; a `Tables<>` reader left to the slim file), the type files now naming the core; **`edgeUploadGraph.test.ts`**: dev-mcp uploads the core and no slim file, customer-portal still the slim file.
- A types regenerate flows through as before: `gen-types:*` run the generator, which rewrites the slim file, the core and every inlined body.

## Is this the best we can do?

- The rule rewrites a kernel's text in the copy beyond its import lines, which the copy had never done; the header line says so and `--check` regenerates, so the copy can never drift from the rule. The narrower design, a folder of alias-only files that every kernel imports from, would have moved nine aliases in `src` for the same bytes.
- The portals keep the slim file for four kernels whose `Database` uses are not plain aliases. Writing those four plain (`type LienDeskItemRow = Database['public']['Tables']['job_lien_desk_items']['Row']` in place of `Tables<'job_lien_desk_items'>`, an alias on its own line in `changeOrderOfficeRows.ts`, `drawRows.ts`'s table map as named rows) would take the slim file out of every function; that is the card's next piece.
- The core is the whole `Constants` object too (every enum's values as a runtime constant, typed), about half of its 7 KB; `slimDatabase` keeps the parts whole, and cutting `Constants` is not worth a second parser.
