# v2.6630 — Dispatch hears of every license about to expire, every morning, whether or not anyone saved it (2026-11-07)

Punch list **#253** (`to-dos/license-expiry-notices-sweep.md`), the other half of v2.6424. The dispatch notice for a license about to expire was asked for only after a Save on People → Licenses, so the licenses imported in March were never asked about, and by November 14 of the 24 on file had lapsed with nothing sent. The owner's three calls on 2026-11-07, each the card's recommendation: the sweep runs on the server every morning, not on the tab's load; a notice nobody saved goes out under the portal's sender (`app_settings.portal_requests_from_user_id`, else the first dev, the rule `submit-portal-request` already follows); and a license already past its expiry gets no notice, since the Expired section is its place.

## What changed

- **Migration `20261107120000_license_expiry_notices_sweep.sql`** ([doc](../migrations/20261107120000_license_expiry_notices_sweep.md)): `file_license_expiry_notice(license, from_user, link)` is the one row-maker — the thirty-day window and the once-only stamp move into it, so the Save path and the sweep write the same `dispatch_requests` row and never two for one license. `notify_dispatch_license_expiry_if_needed` keeps its signature and files through it under `auth.uid()`. `license_expiry_notices_sweep()` runs with no signed-in user or as a dev, walks every license inside the window with a null stamp, files each under the sender, and POSTs each new row to `notify-dispatch-request` with the Vault `CRON_SECRET`, so the Dispatch group hears the push; it answers `{ ok, filed, dispatch_request_ids, pushed, from_user_id, push_error? }`. Cron `license-expiry-notices`, 13:12 UTC daily.
- **`notify-dispatch-request`** gains a cron door: a POST carrying `X-Cron-Secret` equal to `CRON_SECRET` is an internal caller like the service key, for the `created` fan-out alone (`isCronCaller`, a constant-time compare; an unset secret opens to nobody). Closes, reopens and replies stay user-only.
- **SQL bed** `npm run test:pg:license-expiry-sweep` (`supabase/tests/license_expiry_sweep/`): the morning run files two of five licenses (ten days out and today) under the portal's sender and stamps them, leaving a stamped, a lapsed and a far one alone; a second run files nothing; with no setting the first dev sends; an assistant is refused in words and a dev may run it; the Save path still files under the saver's own name, once, and never for a lapsed license.
- **Guide.** *find my way around the People page* → Paperwork says Dispatch hears of a license expiring within 30 days every morning.
- **Docs.** `PEOPLE_TABS_ARCHITECTURE.md` → the licenses bullet; `ACCESS_CONTROL.md` → the Licenses row; `EDGE_FUNCTIONS.md` → notify-dispatch-request's internal caller paragraph.
