# v2.3441 — Job Summary: the % badge carries the report's date before the row is expanded (2026-09-14)

Client only; **no migration** — the one this item asked for already shipped: v2.3372 (`20260912155909_report_pct_newest_wins.sql`) dropped and recreated `list_latest_report_completion_pct` to return `reported_at` (the report's `created_at`) and `manual_at`, and `src/types/database.ts` already carries both. What was still missing was the client reading `reported_at` for the badge. First bullet of item 8 in [`to-dos/job-summary-follow-ups.md`](../../to-dos/job-summary-follow-ups.md).

## Why

v2.2852's provenance badge ("crew report Aug 27") took its date from the lazy `jobSummaryReportsByJobId` cache, which loads when a row is expanded — so every collapsed row read a bare "crew report" until someone opened it.

## What shipped

- **Kernel** [`jobSummaryPercentComplete.ts`](../../src/lib/jobSummaryPercentComplete.ts): `currentReportDateByJobId(rows, into)` — `job id → reported_at` for exactly the reports `currentReportPctByJobId` keeps (`reportPctIsCurrent`: a report older than the office's last hand-set is dropped, and a later batch clears an earlier entry). A row without `reported_at` — the pre-v2.3372 RPC shape — adds nothing, so the badge falls back to the expanded row's report cache as before. One test.
- **Hook** [`useJobSummaryData.ts`](../../src/hooks/useJobSummaryData.ts): `jobSummaryReportDateByJobId` state, filled from the same RPC batch beside `jobSummaryReportPctByJobId`; returned to `Jobs.tsx`.
- **Tab** [`JobsJobSummaryTab.tsx`](../../src/components/jobs/JobsJobSummaryTab.tsx): optional prop `jobSummaryReportDateByJobId`; the % cell's `PercentProvenanceChip` takes `reportedOn` from it first, then from `latestReportPercent(jobSummaryReportsByJobId)` (the expanded-row cache), then null. Nothing else on the cell moved.
- Docs: `docs/JOBS_JOB_SUMMARY_TAB_ARCHITECTURE.md` (the badge sentence), guide *read true profit on Job Summary*.
