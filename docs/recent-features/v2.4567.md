# v2.4567 — Lien releases: who signs starts fresh on each job (2026-10-05)

Client only; no migration, no edge function. Found while mapping the modal (`docs/LIEN_RELEASE_MODAL_ARCHITECTURE.md`, PR #4535).

## The defect

[`LienReleaseModal.tsx`](../../src/components/jobs/LienReleaseModal.tsx) set `presentSignerId` only through `cur ?? company signer ?? job.master_user_id ?? first leader` (the leaders load) and the step-5 *Who signs* select. Nothing cleared it. `JobsStagesTab` keeps the modal mounted (`open={lienReleaseModal != null}`), so a leader picked on one job was still `cur` on the next: the select, *He signs now* and the minted row's `signer_user_id` all carried the earlier job's pick instead of the new job's default.

## The fix

One effect keyed on `[open, job?.id]` clears the pick. The leaders load that follows sets the default for the job in hand, in the same order as before. The `cur ??` guard stays: a reload of the leaders while the modal is open on one job (its `master_user_id` or `gc_customer_id` changing under it) still keeps what the user picked.

## Tests

`LienReleaseModal.signerReset.render.test.tsx` (2): a pick on one job is gone when the modal closes and reopens on another job, and on the same job; a job swapped under the open modal takes its own leader. Both fail without the effect.
