# v2.6130 — A map pin's count, a robot's X grade and the Dashboard's calendar count read in both themes (2026-10-30)

Punch list #194's lens, after its one-character skip. `auditFrame` ([`lensAudit.ts`](../../src/lib/lens/lensAudit.ts)) measured only text of two characters or more, so a lone count was never read: Moneyfill's `0` counts read 2.93:1 in dark while the whole catalog read clean. This PR first measured a lone letter or digit and read the whole catalog with that rule. While it waited in the queue, v2.6137 (#6529) shipped a broader rule that measures every lone character, a `✓` too. The merge keeps v2.6137's audit as it is, and this PR keeps the fixes its read found.

## The read

The whole catalog, on a `vite build` of main (`ff8a766b9`) with v2.6120 and v2.6122 merged in, served by `vite preview`: 767 screens, 3,068 frames, light and dark at 375 and 1,280. Lone letters and digits were measured; lone marks and symbols were still skipped. None failed and none was left unsettled. Chrome closed after 639 frames, and the 2,429 it dropped were read on the second run. 718 frames flag text under 3:1, in four pairs, each a one-character count:

| Pair | Ratio | Frames | Where |
|---|---|---|---|
| White on `#f87171`, the top bar's Messages count | 2.77:1 | 652 | every screen with the count, dark, desk |
| White on `#9ca3af`, a robot's X grade | 2.54:1 | 52 | the Bid Board, New bid and the envelope, both themes and widths |
| White on `#f59e0b`, a map pin's count | 2.15:1 | 20 | the Map page, both themes and widths |
| White on `#f0f2f5`, the Dashboard's calendar count | 1.12:1 | 10 | the Dashboard, light |

The Messages count is v2.6151's (#6536), which fills it with `#b91c1c` under white. This PR's own fix for it gave way to that one in the merge. The read's other checks match the reads before it: 64 phone frames scroll sideways, and 104 carry Google Maps' `RefererNotAllowedMapError`, the key refusing the local preview's address.

## Named for their own cards

- **A whole-catalog read with v2.6137's rule.** Lone marks and symbols (`✓`, `×`, `▾`) are measured on main now, and the read above skipped them. A read of the whole catalog on main would show any that fall under 3:1.
- **White words on a text token used as a fill.** 40 lines in 37 files write `color: white` beside `background: var(--text-…)` on one line, 31 of them on `--text-link`, and more spread over several lines. Every text token turns light in dark mode, so the white words read 1.05:1 (`--text-strong`) to 2.77:1 (`--text-red-700`) there. The lens's frames do not open the presses and windows they sit behind. v2.6068's rule fits every one: `var(--surface)` for the words reads 5.31:1 or better on each token's dark value. It would make a codemod sweep like v2.6120's.
- **HTML text over a sibling's fill.** The audit reads an HTML text's background from its ancestors, so a count drawn over an icon is measured against whatever is behind both. v2.6137 reads a drawing's words against the shapes under them; an HTML count laid over an icon is still read against the page. The calendar count was the one case this read showed, and it now carries its own ground.
