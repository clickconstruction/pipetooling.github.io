# v2.7087 — The app's own tests use made-up names (2026-11-12)

This repo is public, and the standing rule is that no real customer, GC, owner or job name, street address or job number goes into a test. A read-only walk for punch list #325 saw that a payer on the live board had the same name as a GC hard-coded in a render test's fixture. A sweep from that fixture found the same kind of string in several hundred test files.

## What changed

- **A mechanical rename across the test fixtures**: `*.test.ts`, `*.test.tsx`, `src/test/`, the SQL scenarios under `supabase/tests/`, and two fixture files only tests import (`houseFileParts.bp375.fixture.ts` and `procurementSkylab.fixtures.ts`, renamed from its old file name). Names of people and companies, a few street names and a few email addresses that read like live records were replaced with invented ones.
- Each old string maps to one new string everywhere, so a fixture and the assertion that quotes it still agree, and two fixtures that were different stay different. Every case and shape of a name went in the same pass: as typed, upper case, lower case, and the ids and constants built from it.
- **Two sample-data files in the app** changed with them, because tests quote them: `src/lib/teamSampleEmails.ts` (the sample emails under Settings → What the team sees) and `src/lib/jobs/testReportSample.ts` (the sample test report). Their previews now show made-up names. Nothing else on any screen changes.
- A street name was renamed only where a live record was named beside it. House numbers, cities, ZIP codes and counties stayed, because address tests read them.
- The lead fixture (`LienInstrumentsModal.render.test.tsx`) also got a made-up job number, bill amount and memo.
- Sixteen expectations that are a cut, folded or glued form of a name (a 20-character slice of a row's text, an acronym, a slug, a name folded to letters) were edited by hand to match.

## How it was done

A script outside the repo held the list of old and new strings and rewrote the files in one pass; a second script made the hand edits. Neither is in the repo, the commit or the PR, because they hold the old strings. On a rebase conflict, take `main`'s version of the file and run the scripts again.

## Left as is

- **Git history still holds the old strings.** This change only fixes the files at the tip. Rewriting history is a separate decision.
- **Files that are not test fixtures** were not swept: `docs/`, `to-dos/`, help guides, release notes, code comments, edge functions and one-off SQL in `scripts/` still hold some of the same strings.
- **The rename list came from the repo alone**: the fixture the walk reported, names the repo's own docs describe as live records, and names beside them that read the same way. It was not checked against the live customer list, so a real name that reads like a made-up one can remain, and so can a real street address with no named record beside it.
- **Job numbers** in other test files were not renumbered, and **phone numbers** were not looked at.
- **Team members' names** in tests were not changed.

## Checks

`npm test` (the whole suite), `npm run typecheck`, `npm run lint`. The SQL scenarios run in CI's SQL beds, which need Docker.
