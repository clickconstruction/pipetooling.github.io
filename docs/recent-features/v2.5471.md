# v2.5471 — Job activity shows a job's calls, texts and emails to its techs too (2026-10-13)

Messages cut 10, the owner's answer to J2's question (v2.5365's *Decision for the owner*, 2026-10-13): a tech sees a job's lines in Job activity. GC Mode helper 7, directed by the lead session GC MODE, checked against the residential lead's R5 rules.

- **The gate**: `canReadJobMessages(role)` in `src/lib/gc/access.ts` is the office team (`GC_OFFICE_TEAM`) and R5's field roles (`MESSAGES_TECH_TEAM`, primary and helpers). `JobActivityView` reads a job's messages for it in place of `GC_OFFICE_TEAM`, and gives it the Customer pill. A primary reaches Job activity on Jobs → Pipeline today.
- **What a tech gets back** is the rows' policies, unchanged: R5's `messages_tech_read` (`20261013190000_messages_tech_door.sql`) gives a tech the lines of a customer, lead or sub whose job they were dispatched to or clocked on this week or last, never a line marked `office_only`. `contact_jobs` keeps only the office's policy, so `loadJobMessages`' untied read comes back empty for a tech, and a tech sees only the lines tied to the job.
- **The words**: `JOB_MESSAGE_COLS` reads `office_only`; `noteReaders` gives a team note *only the office sees this* when it is marked so, and *only the team sees this* otherwise, which stays true for a tech since R5's door never shows them an office-only note. The feed draws `readersWord` in place of the fixed words.
- **No thread link for a tech**: *Open the thread with …* goes to Messages on GC projects, which a tech cannot open, so `JobActivityFeed` takes `threadLinks` (`canOpenGcProjects`) and a tech's message line opens only to what it has to show. The link returns for a tech through the residential lead's Job Mode tech door (#5615, *message the customer from the job*), once it is on main.
- **R5's other rules hold**: no phone number or address is drawn (the line's words, a first name and a channel word), and the view writes nothing. Money is unchanged: the message lines carry no billing rows, and the feed's own payment items for a primary are the existing rule of the source tables (the residential lead agreed, 2026-10-13; `noMoney` belongs to the tech's thread window).
- **Docs**: the guide `open-job-activity-full-screen`. The `ACCESS_CONTROL.md` sentence went to helper 2 for #5624.
- **Tests**: `access.test.ts` (`canReadJobMessages`), `jobActivityMessages.test.ts` (`noteReaders`, the office-only mark read from a row), and `JobActivityView.messages.render.test.tsx` (a primary and a helper read the tied lines with the Customer pill and no thread link; an office-only note reads as the office's; a subcontractor reads none).
