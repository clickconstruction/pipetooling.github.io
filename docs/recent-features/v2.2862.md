## The kernel — `src/lib/billing/billTruth.ts` (pure)

`computeBillTruth({ jobs, invoices, payments })` → `{ readyToBill, billed, collections, owed, paidInFull, onPaidJobs, orphans, excludedOwed }`; `computeBillTruthFromJobs(jobsWithEmbeddedRows)` for the board's / Hub's shape. **One rule per bucket:**

| Bucket | Rule |
|---|---|
| **Ready to Bill** | `ready_to_bill` rows whose job is present and not `paid`. Total = Σ draft amounts. (Board/Dashboard bundling into rows is unchanged and mirrored; the strip's "exposure" adds the unallocated gap.) |
| **Billed** | `billed` rows on jobs of ANY non-paid status (decision 6: the 8 progress bills on working jobs count) + ONE shell row per `billed` job with zero billed rows (`revenue − payments_made`). Flagged jobs → `collections`; `owed` = both. **Membership by status**: a fully-paid-but-unmarked bill stays a member at `remaining 0`, `settled: true`, never aged. |
| **Owed** | per row `max(0, billed − applied)` — `openRemainder`, **the only clamp in the app**. Invoice rows net invoice-linked payments; shells net `payments_made`. Never clamped again downstream. |
| **Paid in full** | jobs with status `paid` (head-count). |
| **Excluded, counted** | an RTB/billed row whose job is `paid` (`onPaidJobs`) or absent (`orphans`) is never RTB/Billed/Owed; `excludedOwed` = the billed-status part as remainders, so a surface can say "1 bill on paid or missing jobs excluded ($488)". |
| **Lifetime billed** | `jobBilledContribution`: Σ billed/paid invoice amounts on the job, else the billed/paid job's shell `revenue`. |
| **Lifetime collected** | `lifetimeCollected`: every payment row, invoice-linked or not. |

Predicates are the server twins imported verbatim: `isPaidJobStatus` (paidJobBillGuard) and `jobCarriesOpenBills` / `jobPrintsShellRemainder` (portalBillMembership). The one deliberate client difference — NULL/empty job status coalesces to `working` (the board's convention) while the SQL mirror excludes NULL — is pinned by test. Row primitives (`openRemainder`, `openBillRowsForJob`, `appliedByInvoiceId`, `jobBilledContribution`, `lifetimeCollected`, `billOnOpenJob`, `billIsOnPaidJob`, `jobPrintsBilledShell`, `jobIsInCollections`, `sumRemaining`, `emptyBillTruth`) are exported for the per-customer kernels.

## Adopters (every hand-rolled sum replaced)

- **Spine** — `jobs/fetchStagesHeaderStats.ts` returns `billTruth` (computed over the flat lean rows so orphans are visible); `computeStagesHeaderStats` copies `billed` / `collections` from the kernel and carries `billTruth` on `StagesHeaderStats`. `stageRowBilledRemainingAmount`, `billedStageRowRemainingAmount`, `invoiceOpenRemainingOnJob` all call `openRemainder` (the unclamped variant is gone). `buildJobsStagesBoardLists` and the aging helpers (`buildBilledAgingBuckets`, `countBilledRowsMissingDates`) take RTB/billed invoices only from open jobs (`billOnOpenJob`) — the full-row board matches the lean strip on a paid job's stray bill.
- **Pipeline strip** (`pipelineOverview.ts`) — unchanged code, now reads the kernel's billed/collections via the stats.
- **Dashboard AR card** — `dashboardFinancials.buildArBuckets` is the kernel shaped into `FinancialItem`s (settled rows get sublabel `… · paid in full — not yet marked Paid`, `dateYmd: null`; `excluded` returned); `useDashboardFinancials` fetches the spine's job cohort (`LEAN_STATS_ACTIVE_JOB_STATUSES` + NULL, was billed/RTB/working) and exposes `arExcluded`; `DashboardFinancialsSection` adds the detail line "N bills on paid or missing jobs excluded ($X)" when N > 0. The "Unknown job" row is gone.
- **Dashboard Billed pin** — `useBilledTotal` fetches the spine cohort and reads `owed` (count + total); paid-job/orphan bills no longer pad it.
- **Quickfill "who owes what"** — `billedByCustomerBreakdown` keeps every row (`settled` flag; settled rows `ageDays: null`, `ageHandSet: false`, sort last) so its count equals the strip's; `BilledAwaitingPaymentSection` appends the excluded-bills hint from `res.billTruth.excludedOwed`.
- **Customer Hub** — `customerProfileStats.customerMoneyStats` / `profileJobRowMoney` use `openBillRowsForJob` + `jobBilledContribution` + `lifetimeCollected`; `customerInvoiceRows.buildCustomerInvoiceRows` totals are `Σ jobBilledContribution` per job (the footer gains the shell arm) and `lifetimeCollected(payments)`; `fetchCustomerInvoices` selects `status, revenue`; `CustomerInvoiceJob` gains optional `status`/`revenue`. Profile strip == footer by construction.
- **Customers list** — `customersListLcv.customersListRollup` uses the same primitives; the customer-level `Math.max(0, openBalance)` is deleted (a sum of clamped rows is never negative).
- **Dashboard Stage 2/3 units** — `isDashboardBillOnPaidJob` / `buildReadyToBillDashboardUnits` read `billIsOnPaidJob` (same predicate, one import path). Unit bundling is unchanged.

**Not adopted, on purpose**: `gcReviewRollup`, `billedAwaitingPaymentReport`, `paymentChase`, `moneyWaiting`, `billedPaymentForecast`, `paySpeedsBreakdown`, `billedAgingChart`, `fixBillLines` all sum `stageRowBilledRemainingAmount` over board rows — they inherit the clamp and the membership fix without edits. The GC statement RPC / portal edge function stay as (b) left them.

## Shadow beacon (one release — REMOVE BY the next bill-truth PR, or 2026-09-19, whichever first)

`src/lib/billing/billTruthShadow.ts`: each adopter keeps its OLD sum (`legacyDashboardArOwed`, `legacyBilledPinTotal`, `legacyStripBilledTotal`, `legacyHubOpenBalance`, `legacyListOpenBalance`, `legacyFooterLifetime`) and calls `reportBillTruthShadow({ surface, legacy, kernel, userId?, role? })`. On a > 1¢ difference: `console.warn('[bill_truth_mismatch]', surface, {legacy, kernel})` in dev builds, and — when a user id is passed (Dashboard AR card, Quickfill) — one `ui_nav_clicks` row with `control = 'bill_truth_mismatch'`, `target = '/<surface>?legacy=…&kernel=…'` (no migration: the nav-click table is best-effort by design). Surfaces: `dashboard-ar-card`, `dashboard-billed-pin`, `pipeline-strip-billed`, `quickfill-ar-count`, `customer-hub-lifetime`, `customer-hub-open-balance`, `customers-list-open-balance`. **A fired beacon is the old number being wrong in live data** (an orphan, a negative shell, a settled row, a shell job the footer skipped) — expected on day one for `dashboard-ar-card` (the $488) and `quickfill-ar-count` (the one settled row); a beacon on `pipeline-strip-billed` would mean a negative billed shell exists. Query: `select target, count(*) from ui_nav_clicks where control = 'bill_truth_mismatch' group by 1`. In tests the beacon is inert (`MODE === 'test'`); it never throws.
