# v2.4405 — Bids: every old bid is marked Combined in the data (2026-10-02)

Punch list #77, PR 3 of 3: the last step of the By Stage retirement (v2.4389 switched it off, v2.4396 deleted its code). The owner, 2026-10-02: "I want the data to match the app so later audits and reviews can be more successful."

## What changed
- **Migration `20261002120000_bids_materials_model_all_combined`** ([doc](../migrations/20261002120000_bids_materials_model_all_combined.md)): `bids.materials_model` becomes `'rough'` on the 151 bids that still read `'exact'`, and the column comment says the value is always `'rough'` and why. One column on one table.
- **`updated_at` does not move.** The update trigger that stamps it is held off for the one statement, inside a single atomic `DO` block. 80 of the 151 had been edited in the last 30 days; none of them now looks edited tonight.
- **Nothing else moves.** The By Stage picks on B82, B85, B159 and B403 and the stage PO links on B82, B83 and B85 stay in their tables. The migration doc lists all 151 bid numbers, so the record of which bids carried the flag outlives it.
