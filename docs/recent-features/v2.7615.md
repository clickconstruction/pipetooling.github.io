# v2.7615 — Prospects: the page has its first render test (2026-11-17)

Step 3 of the order in `docs/PROSPECTS_TABS_ARCHITECTURE.md`. Tests only: no app code changes.

**What it is.** `src/pages/Prospects.render.test.tsx` mounts the whole page at an address against a stateful Supabase stand-in and reads what a caller sees. 60 cases:

- **The address picks the tab and the lane** (20): every `?tab=` key on every lane, the four addresses that name a tab its lane does not have and fall back to Follow Up, the `subs` and `gc-leads` doors, Hiring and Permits, the old Research key rewritten, and the lane pills.
- **Who may open what** (7): the three office roles on the deck, Activity for dev and the assistant-like only, an estimator with and without the Prospects flag, Hiring by the switch or by a shared column.
- **The deck** (13): a link to a prospect, to another lane's prospect and to one that left the queue; Next Prospect and its wrap; a row of the queue; Not a fit from the first and a middle card; Can't reach on the last card; Didn't Answer with and without the auto-advance box; Answered; the calling order switch.
- **The Subs lane** (7): the trade filter, a run and its receipt, Didn't Answer in a run, the Board's run press, a priority press, the list by trade, Add a sub.
- **Jobs to GC, Prospect List, Convert, Activity** (7) and **the windows** (6): New Prospect by lane and by the Dashboard's link, Edit prospect, Set callback, Timer history and My time, a template's Copy.

**How it stays honest.** The stand-in answers a query only when it is awaited, as the real client does. The Hiring board and the Permits tab are stubbed: each loads its own data and has its own tests. The router is mounted with `v7_startTransition` off, as `src/main.tsx` mounts it: with it on, the list's jump to a card lost its prospect in the test, because the address and the page's tab state committed in two renders.

**It bites.** Eight deliberate breaks of the page, one at a time: the Activity gate, the Board's lane rule, a run's order, New Prospect's kind, the callback's title, Timer history's load and the template's words each failed at least one case. The eighth, forcing the pointer to the first card after Not a fit, passed: the address names the next card and the pointer follows it, so the break changes nothing a caller sees.

**What the test found.** The page releases a calling lock with `void supabase.from('prospect_calling_locks').delete()…` in eight places, and none of them is awaited. The Supabase client sends a query only when it is awaited, so no release is ever sent. A lock stays until it goes stale after 30 minutes. The test pins today's behaviour (no delete is sent) and the map records it as quirk 36; the fix is its own PR, never a move.

**Size.** 60 cases in about four seconds. `Prospects.tsx` is unchanged at 5,284 lines.
