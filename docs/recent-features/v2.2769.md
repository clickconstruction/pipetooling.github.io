PR 2 of the Takeoffs refresh train (`docs/TAKEOFFS_REFRESH_PLAN.md`). Four pure kernels in `src/lib/bids/`, tests only — nothing renders differently yet. New 1 / New 2 (PR 5 / 6) and Fill-from-book under Combined (PR 4) are built on these.

## Client only — no migration, no edge functions

- [`takeoffFixtureKey.ts`](../../src/lib/bids/takeoffFixtureKey.ts) — `normalizeFixtureName` (exact form: lowercase, trimmed, single-spaced), `stripPlanTag` (one trailing `-12` / `_3a` / ` 2`; the space form only when the rest holds no digit, so "lav 1" → "lav" but "2in 90" stays), `fixtureKey` (never strips `ft of …` / `px of …` rows — the labor and price books key on the prefix), `fixtureKeysEqual`. 20 tests, including the 15 most common prod row names.
- [`takeoffCoverage.ts`](../../src/lib/bids/takeoffCoverage.ts) — `summarizeTakeoffCoverage(countRows, lines)`: fixtures, costed (≥1 line, even $0 — plan decision 9), uncosted ids, costed %, materials total via the existing `sumRoughLinesPreTaxWithCount` (so the strip can never disagree with the Labor tab or the Workbench; a line with no row counts ×1, as there), $0-line ids, bundle / override counts, per-fixture `{lineCount, unitCost, total, hasZeroPriceLine}`; `isBundleLine`, `isOverrideLine`; `nextUncostedFixtureId` (row order, wrapping — New 1's Enter → next). 8 tests.
- [`takeoffBookMatch.ts`](../../src/lib/bids/takeoffBookMatch.ts) — `matchBookEntries(countRows, entries, items)`: per row, the first entry (sequence order) whose primary name or alias matches the exact normalized name, else the stripped key; exact wins over key regardless of order; templates de-duplicated in item order; entries with no items skipped. `fillableBookMatches` narrows to uncosted rows. Replaces the exact-only loop in `applyTakeoffBookTemplates` at PR 4. 5 tests.
- [`takeoffBookLearn.ts`](../../src/lib/bids/takeoffBookLearn.ts) — `planRememberForBook({fixture, lines, existingEntries, existingAssemblyNames})` → the writes "Remember for the book" needs: merged part items for a new `<key> · book` assembly (numbered sibling when the name is taken — additive, never in place), bundle lines linked as their own template, and the entry action (`create` / `alias` with the plan-tag form / `none`). `nextBookAssemblyName`. 5 tests.
