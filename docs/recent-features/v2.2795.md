## Data repair (prod, DML only — APPLIED 2026-09-04 on the owner's say-so)

Six robot bids were opened before `twin_source_bid_id` was stamped, so the Audits tab cannot seal or diff them: shadows b418 → b397 and b419 → b396 (from `twin_shadow_runs`), backtests b411 → b298, b412 → b200, b413 → b168, b414 → b34 (from their STG-0 "Blind backtest of bNNN" notes). The dry run (ROLLBACK) returned exactly those six rows; the COMMIT run (psql via the session pooler) was applied after the owner asked for it — `UPDATE 2` + `UPDATE 4`. Effect: b419 is held sealed until MPH LIVSTE goes out, and the four backtests show "vs ours" + the row diff.

```sql
BEGIN;
with fix as (
  select sr.shadow_bid_id, sr.reference_bid_id from twin_shadow_runs sr
  join bids b on b.id = sr.shadow_bid_id where b.twin_source_bid_id is null
)
update bids b set twin_source_bid_id = f.reference_bid_id from fix f where b.id = f.shadow_bid_id;
with parsed as (
  select e.bid_id, (regexp_match(e.notes, 'Blind backtest of b(\d+)'))[1] as ref_num
  from bids_submission_entries e join bids b on b.id = e.bid_id
  where b.twin_source_bid_id is null and b.project_name like 'ZZ Twin %' and e.notes ~ 'Blind backtest of b\d+'
), fix as (select p.bid_id, r.id as ref_id from parsed p join bids r on r.bid_number = p.ref_num)
update bids b set twin_source_bid_id = f.ref_id from fix f where b.id = f.bid_id;
COMMIT;
```
