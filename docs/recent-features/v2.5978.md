# v2.5978 — Build on the Bridge and Stale open read an evening as that day (2026-10-27)

The rest of the evening-day sweep (v2.5940, v2.5949, v2.5954, v2.5956). Two reads still took a stored timestamp's day from its first ten characters, the UTC date, which is tomorrow's after 7 PM Chicago (6 PM in winter). Both sat inside a local helper, so `check:timezone`'s rules for `_at` never saw them.

**Fixed**
- `src/lib/bridge/loadBuildPace.ts`: its `ymdOf` helper sliced `jobs_ledger.created_at`, `job_pct_events.changed_at` and `reports.created_at`, all `timestamptz`. It now reads `calendarYmdInAppTzFromIso`. A percent or report sent tonight lands in the window that ends today, a Saturday-evening one stays in its own pay week, and a job made the evening before the window no longer starts at 0% inside it. The jobs sold in the window (`createdInWindow`, which feeds `soldUsd` and `soldJobs` and is never re-read by day) are now read from midnight Central on the window's first day (`startOfYmdInAppTzMs`), not from UTC midnight, which is 7 PM Central the evening before. The baseline read 90 days back keeps its UTC bound: it fetches a few hours more, and the kernel windows those points by day.
- `src/lib/jobs/jobSummaryCycle.ts` `staleOpenJobs` (Stale open on Job Summary): a job with no field day counted idle from `ymd(j.created_at)`, the UTC day. It now reads the creation day in Chicago, as `jobCycleRows` reads the bill day. `last_work_date` is a `date` and keeps its own day.

**Evening tests for the three v2.5956 (#6277) fixed without one**
- Collect on the Bridge: `collectMoves` (back on the sheet three days after an evening call), `collectScorecard` (a promise made tonight counts tonight, one made the evening before the plan does not, and the days from a call to the money are Chicago days), `collectPayers` (a no-answer the evening before the oldest bill is not a miss on it) and `collectWords` (the *Last touch* line).
- `jobFollowupStore`: an evening-made job's `createdYmd` is its own day, so its idle days are not one short.
- `loadDemandPace`: tonight's bid, its job and tonight's estimate read as today, and the win counts in the window that ends today.

Each of the 11 new tests fails on the code before its fix (with v2.5956's own evening test, 12 of 76 fail) and passes now. The loader tests run on a new stand-in client, `src/test/proxyFakeSupabase.ts`, which records each builder call and resolves a table's rows whole.

**Not in this PR**: PR #6273 (another session, v2.5950) holds the same Collect kernel fix, now on main from #6277, and one fix main lacks: `loadCollectScorecard.ts` counts notices from UTC midnight on the call day. It has conflicted with main since #6277 merged. `lensWorldAnswers.ts` still slices `clocked_in_at`, in the invented world only.
