# v2.4345 — Merge users works again (2026-10-01)

Found during the *Account on the desk* train (PR D1's live check, 2026-10-01): the person desk's new *Merge a duplicate…* preview, and the Active Accounts window's *Preview merge* it shares a function with, both answered `relation "public.cost_matrix_teams_shares" does not exist`. One migration, [`20261002020000_merge_users_skip_retired_table`](../migrations/20261002020000_merge_users_skip_retired_table.md); no client change, no edge function.

## What was wrong

`merge_user_accounts` (`20260712190000`, `…191500`) lists the membership tables it moves row by row. The Cost matrix retirement (`20260715090000`) dropped `cost_matrix_teams_shares` but left the table in that list, so since 2026-07-15 every merge and every dry run raised on it. The function's dynamic sweep covers tables added later; nothing covered a table removed.

## The change

The migration reads the live definition (the repo file is stale: `20260907160000` had already patched it in place) and removes the one tuple with the same `regexp_replace` pattern the one-company sweep used. Every other table the function names exists.

## Verified
