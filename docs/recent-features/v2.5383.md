# v2.5383 — Messages: our own link to a job's Drive file, behind the scenes (2026-10-12)

Messages, cut 7b (GC Reviews helper 9, directed by the lead session GC Review): the `drive-link` edge function, on 7a's `drive_links` (v2.5372, migration `20261013110000_drive_links`). Its `docs/EDGE_FUNCTIONS.md` section has the whole shape.

- **The open door**, no sign-in, at `clicktooling.com/f/<link>` once 7d's page lands. A Plans file opens in Drive's own viewer, since that half is open to anyone with its link. A Team only file is streamed from Drive, passed through and never held whole, up to 50 MB, so Team only is never opened up. The stream's address is the function's public one, from `SUPABASE_URL`: inside the edge runtime the request's own is the gateway's (job-share met it). A link cut off, ended after 30 days, unknown or too big opens nothing. Each open is a `public_page_views` row under `drive_link`; a staff look or a preview is not counted.
- **The office's door**, a signed-in member of the office team, never a twin. It can *list* a job's folder in its two halves, *put* a file from this computer (up to 10 MB) or a photo into Team only, *link* a file whose parents reach the job's folder, *save* a file that came in to Drive, and *open* a file for the office's `/files/drive/<id>` page. A training account lists and opens, the two reads, and is refused the rest. A plan set's folder in Plans links as the folder; a Team only folder is refused, since it has no bytes to hand over.
- **The rules** are pure in `_shared/driveLink.ts` and tested in `src/lib/documents/driveLink.test.ts`. A link's token is 16 random bytes, 22 characters, short for a text.
- `config.toml` sets `verify_jwt = false`. The dev-mcp catalog is regenerated for the new folder, and `docs/ACCESS_CONTROL.md`'s cut 7a paragraph gains the two doors. The migration is on prod (2026-10-13); the function is deployed once this merges, and dev-mcp with its catalog.
