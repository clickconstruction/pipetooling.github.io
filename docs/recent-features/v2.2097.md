# v2.2097 — Add-task modal: "Go to checklist" navigates behind without closing (2026-08-22)

Owner report: hitting the modal's "Go to checklist" icon by mistake closed the Add-task modal and threw away the draft. The button in [`ChecklistAddModal.tsx`](../../src/components/ChecklistAddModal.tsx) now navigates to `/checklist?tab=today` **without** calling `closeModal()` — the modal is mounted once inside `Layout` (a layout route that persists across child navigation), so all draft state (title, assignees, When, links) survives untouched, and the `?tab=today` param flips the Checklist page's tab even when already on `/checklist` (its tab syncs from search params). Focus returns to the title textarea after the click. New prop `goToChecklistKeepsModalOpen` (default `true`); the standalone `/task` shortcut page ([`TaskShortcut.tsx`](../../src/pages/TaskShortcut.tsx)) passes `false` and keeps the old close-then-navigate behavior, since navigation unmounts that whole page. New render test [`ChecklistAddModal.render.test.tsx`](../../src/components/ChecklistAddModal.render.test.tsx) (2 tests: draft survives + opt-out closes) with a table-aware supabase stub (the modal renders null until the role query resolves). Client-only — no migration.
