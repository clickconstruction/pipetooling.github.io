# v2.6343 — Search every file deeply: the one-time backfill of our own file index, run by an agent (2026-11-02)

Punch list #240's backfill, the owner's rule for it (*done by a Claude agent, one time, after the features land*): a runner an agent session starts from a terminal and walks every job's and bid's Drive folders through PR 1's own door, `drive-link`'s `index_job` (v2.6319), as the dev. No migration, no edge function, no screen: the function already lists a job's folder tree, reads each file's text and writes its `file_index` row; this is the walk over every home, the resume and the log. The card's PR 2 (the dev seat's `plan_index_backfill` / `apply_index_backfill`) is the same walk through dev-mcp and waits on a dev-mcp key; this runner is the route that needs none.

- **The runner.** `node scripts/file-index-backfill.mjs --scope zz|live|bids|paid|all [--workers 1] [--pause 2000] [--dry-run] [--again] [--retry] [--limit N] [--home <id>]`. It signs in as the dev-login identity with the secret in `.env.local` (the steps `scripts/lib/paySession.ts` takes; never the service key from a laptop), reads every job and bid with a folder link as the dev, and walks each home with `index_job` round after round until the function answers `remaining: 0` (at most sixty rounds, forty files each), one home at a time as it ships (`--workers` up to eight), a two-second pause between calls (`--pause`). The platform's own refusal (429, 5xx) is tried three times with a growing back-off; the function's own words (*That job has no Drive folder yet.*, a Drive refusal) end the home and are kept as its reason.
- **The order.** `live` is every job with a folder not Paid in Full, oldest number first (a blank number last); `bids` every bid with a folder, newest first; `paid` the Paid in Full jobs, newest first; `all` is live, then bids, then paid; `zz` is every ZZ test home among them (the ZZ convention, `_shared/zzTestJob.ts`: the job's own name or its customer's; a bid's project name), the dry run before the drive. A row whose link is not a Drive folder is never a home.
- **Resume and log.** `.claude/scratch/file-index-backfill.<scope>.state.json` marks each home done with its counts, so a second run skips it (`--again` walks it anyway) and the function skips every file already current; `.claude/scratch/file-index-backfill.<scope>.log.jsonl` keeps one line per home with the held files and their reasons. `.claude/scratch/` is gitignored from this version: the log holds file names and stays on the computer that ran it. The terminal prints counts only: *job 1234: 40 indexed, 3 held, 160 to go (round 1)*, then *Walked 101 homes (101 jobs, 0 bids): 3,210 files, 2,900 with text, 310 with none (280 scans, 20 of a kind the index does not read, 4 too big, 3 slow, 3 failed). 2 homes the app could not open.*
- **Kernel and tests.** The rules are pure in `scripts/lib/fileIndexBackfill.mjs` (plain JS, no imports, as the drift check's kernel is) and pinned by `src/lib/documents/fileIndexBackfill.test.ts` (22 cases): the scopes and their order, the folder-link rule, the defensive read of the function's answer, the tally across rounds (the held list is the final answer's, which the function fills with every held row of the home), the round cap, the outcome line's counts, the totals, the summary's words and singulars, the resume, the refusal words and which refusals are tried again, and the arguments.
- **The card.** *Where it stands* holds the run's counts as they come (the dry run on the ZZ homes, then the live jobs, the bids and the paid jobs) and the three ways new files can be indexed from then on, with the recommendation marked, as the owner's choice.
