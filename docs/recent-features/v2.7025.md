# v2.7025 — First look: the photo sweep is called for a look's files (2026-11-12)

Punch list #319, a fix to PR 2 (v2.7001) found on its live walk. A photo and two videos sent through a ZZ Test look at 18:50 UTC were not in Drive at 18:57.

**Why.** `photo-save`'s cron calls the function only while one of its sources has something waiting (`WHERE EXISTS …`, eleven clauses). PR 2 added a twelfth source to the function and no clause to the cron, so a look's files sat until some other source woke the sweep.

- Migration `20261112160000_photo_save_looks_cron.sql` schedules the cron again with two more clauses: a look's file not in Drive (never tried, or not tried for 15 minutes, under 30 days old), and a picture texted in since the ask by a customer an open look was asked of.
- `photo-save` no longer stamps a video that is part way through its copy as tried, so the next run five minutes on goes on with it.

The unit tests could not have caught this: the cron's own text is SQL in a migration. The lesson is on the card: a new source of the sweep needs its clause in the cron.

**Push the migration after the merge, then deploy `photo-save`.**
