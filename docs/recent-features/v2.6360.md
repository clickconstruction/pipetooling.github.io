## Decisions

- **One flavour of a request, not a second inbox.** The card's call: the inbox, the push, the thread, the priority card and *Questions on this job* all carry it for free. Nothing new reads it but the sheet's chip.
- **The doors read the payload, the sheet reads the columns.** The inbox's select is read by the whole office on the Dashboard; a column it cannot see before the push would refuse the whole read. So the row's two doors read `pending_payload.stage_check`, which the select has carried since v2.1615, and only the new feature, the send and the chip, waits for the push. The columns stay the record: the dedupe index, PR 2's trigger and window, and PR 3's Pipeline join read them.
- **The chip is words, not a press, in PR 1.** The card has the chip open the thread; the thread's window is PR 2's, so until it lands the chip says what it knows, the age and the reason.
- **The confirm has no aria-label.** The row's press reads *Send to Dispatch: <the question>* and the sheet's confirm the bare *Send to Dispatch*, so a screen reader hears which is which and a test finds one of each.
- **Who may close** (call 2) is unchanged: the dispatch group and a dev, as every request; the sender may not close their own. PR 2 closes the row itself when the check is settled.
