# v2.5906 — Ten more waiting lists read oldest first with an age chip (2026-10-26)

Punch list #184 sweep B, PR 1 (`to-dos/consistency-sweeps/README.md` → *B. Waiting lists*): the ten script sites. The rule (Glossary → *Amber / red age*): a list of rows waiting on a person sorts oldest first and carries a fresh / amber / red chip at a threshold declared as a named constant in `src/lib/ageState.ts`. Each chip keeps the hover text the date already had; closed, answered and dismissed rows keep their newest-first order (a log).

## Is this the best we can do?

The thresholds are the plan's guesses beside the precedents; each is one constant to change. Standing rulings is the one site where "oldest first" would have overridden a documented owner's pick, so it got the chip and kept its order. Can't reach sinks a prospect with no `last_contact` to the bottom, as `compareOldestFirst` does — a row with no stamp can never masquerade as the stalest, though a never-logged try is arguably the longest wait of all; if the station's words ever say otherwise, `nullsFirst: true` is the one-token answer. The Estimator inbox's `(N d ago)` words survive on closed rows only, exactly as the Dispatch inbox does.
