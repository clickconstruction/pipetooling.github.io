## What moved

**[`StagesRowActionButtons.tsx`](../../src/components/jobs/StagesRowActionButtons.tsx)** — five small components, one per icon: Test report (the orange wrench), Lien instruments (amber box while a demand letter is out), Release of lien (blue box while one is issued), AIA G702-G703, and Hazmat fee (green box while the job has a live fee). Each button's markup, including its inline SVG path, had been pasted into both tables — the Test report and Hazmat glyphs three times — so a glyph, title or colour change could miss a copy. The callers keep exactly their gates and click bodies (`showClickTooling &&`, `showAiaG702G703(authRole, job, inv) ?`, the `invForLien` fallback in the bundle row); only the button itself is shared. The boxed states arrive as booleans (`demandOut`, `hasRelease`, `hasFee`), which is what the three `?.has(id)` ternaries computed.

**[`StagesExpandedThreadRow.tsx`](../../src/components/jobs/StagesExpandedThreadRow.tsx)** — the `<tr>` under an expanded job row, with `JobsStagesThreadPanel` and its fourteen props. It was pasted three times (the job table, and both row kinds of the unified table), differing only in the job variable and the column count. Each table builds a `threadRowShared` object once from its own props and spreads it with `job` and `colSpan`; the `expandedJobThreadId === job.id` gate stays where it was.

The script that did it replaced each block by an anchored pattern with a count assertion, then asserted that none of the three SVG path strings and no `<JobsStagesThreadPanel` survived in either table.

Numbers: `JobsStagesTable.tsx` 572 → 508; `JobsStagesUnifiedTable.tsx` 1,291 → 1,096.
