# v2.5630 — Pipeline: the identity block never claims more than it uses (2026-10-19)

The owner noticed (2026-10-18) an exceptional amount of space between a Pipeline row's name block and its activity box on Billed Awaiting Payment rows, on a wide screen. Measured on the dev server in Chromium at 1281, 1900 and 2560 px, the box filled the cell on every row (`JobsStagesActivityBox`'s `flex: 1 1 260px` takes every remaining pixel, v2.1594), so the gap is a browser difference in how the identity block's width is found: the block (`flex: 0 1 auto`, `minWidth: 0`) is sized to its widest line, and his browser sized it to the unwrapped width of the customer line with its globe, bubble and **owner sees the bills** chip (`renderJobCustomerLine`'s tail unit), then wrapped that line anyway, leaving dead space where Chromium already wraps at about 474 px. No migration; no edge function.

- **The cap**: the identity block in `StagesUnifiedJobRow.tsx` and `JobsStagesTable.tsx` takes `maxWidth: 'min(100%, 30rem)'`, so in any engine it never claims more than Chromium already wraps at, and the activity box takes the rest.
- **Not this fix**: a row whose name block's widest line is the Stripe **Resend · Email sent** line (`StripeInvoiceSendFromStripeButton`, compact) is as wide as that line in every browser; the space above it in the block is the block's own, and the box cannot start before it. Letting that line wrap under the button would narrow those rows; left for the owner's call.
- **Walked**: the two Dudley Mason rows and the Michael Palmer row the owner showed, measured on the dev server before and after; Chromium's widths are unchanged (474 and 292 and 251 px blocks, the box from 502, 320 and 279 px). Not reproduced in his browser, since the pane is Chromium.
