# v2.2302 — Fix: hairpin "stray lines" in the Map's routed edges (2026-08-25)

Owner screenshots: edges drawing a long needle into empty canvas and doubling
straight back (one spanned 988px of path for endpoints 89px apart; several
smaller ones tangled above "Eat Natural Food").

## Root cause (two layers)

Dagre models each edge's midpoint as a zero-size virtual label node; its
position can be pushed hundreds of px off the source→target corridor by
unrelated nodes in the alignment pass. The waypoint renderer (v2.2253's
dagre-route edges) draws faithfully through it. Worse, the renderer replaces
dagre's endpoint approximations with the measured node handles — a
substitution that can turn a mild dagre polyline into a ~180° needle even
when dagre's own points looked sane.

Not cycles, not duplicate links, not stale caches — verified on a fresh load
(83 edges, acyclic, no dupes).

## Fix

`dropHairpinPoints` in `src/lib/checklistTechTreeLayout.ts` (+4 unit tests):
iteratively removes interior waypoints whose turn is a near-reversal
(cos < −0.6, i.e. > ~127°) and zero-length duplicates. A legitimate dodge
around a stage turns ~90° per corner and passes untouched. Applied in BOTH
places:

- `layoutTechTreeFlow`: on dagre's raw points (an edge reduced to its
  endpoints downgrades to plain `smoothstep`).
- `ChecklistTechTreeRoutedEdge`: on the final handle-substituted polyline —
  the layer that actually produced most spikes; if nothing useful survives,
  the edge renders as `getSmoothStepPath`.

## Verification (live, Farm 1, 71 rendered edges)

Geometry sweep before: 3 edges flagged (worst ratio 11.05, max deviation
462px). After: **zero direction-reversals across all edges**; the single
remaining long route is a legitimate rise-run-descend dodge (90° corners)
that the filter correctly preserves. Region screenshots clean.
