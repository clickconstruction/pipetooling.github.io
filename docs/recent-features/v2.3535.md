# v2.3535 — Stages tab decomposition, PR 5: the three small confirms are their own components (2026-09-16)

Client only, behavior-preserving. PR 5 of the train in `to-dos/engineering-hygiene.md` — the first three of the inline confirms in the modal tail (region 6 of [`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md)).

## What moved

| Dialog | File | What the tab keeps |
|---|---|---|
| Ready to Bill — the double checkbox | [`StagesReadyForBillingConfirmModal.tsx`](../../src/components/jobs/StagesReadyForBillingConfirmModal.tsx) | the two checkbox flags (the ham-mode path resets them when it skips the dialog, so they are cross-region), `busy` for the job, and the confirm: the billing-email nudge, then `moveJobToReadyToBillWithStripePrep` |
| Are you sure? — the plain send-back to Waiting / Ready to Bill / Billed | [`StagesSendBackSimpleConfirmModal.tsx`](../../src/components/jobs/StagesSendBackSimpleConfirmModal.tsx) | the target and `updateJobStatus` |
| Move to Collections? / Send back to Billed? | [`StagesCollectionsConfirmModal.tsx`](../../src/components/jobs/StagesCollectionsConfirmModal.tsx) | the note draft (the openers clear it), `saving`, and the confirm: `set_job_collections_flag`, the toast, the reload, and the follow-moves focus on the moved row |

Each dialog's JSX moved verbatim; the `onClick` bodies that wrote data became four named handlers in the tab (`confirmReadyForBilling`, `confirmSendBackSimple`, `confirmCollectionsMove`, plus the two close helpers), which is where the map says writes and the focus/flash substrate live. The Collections dialog keeps its z 80, the one that paints over call mode (B6 / J4-7). The Ready-to-Bill dialog's four-way enabled expression, written out three times in the original, is one `ready` const inside the component — the same truth table.

Numbers: `JobsStagesTab.tsx` 5,443 → 5,377 lines.
