# v2.8690 — A job's Lien window closes on Escape (2026-11-27)

No card. Finding 284 of the fixing thread's ledger, from the walking thread's sitting 30 (2026-11-27): one Escape did not close a job's Lien window, and its **×** did. Client only. No migration, no edge function, and no kernel an edge function copies. Nothing owed after the merge.

**The rule is a pick the person may flip.** The managing session put it to the person twice without a no and settled it on its own pick on 2026-11-27: build it. It is the person's to flip before or after the merge. Flipping it is taking the window's keydown listener out of `LienInstrumentsModal.tsx`.

**Read.** `LienInstrumentsModal.tsx` had never listened for a key: `git log -S"Escape"` on the file finds no commit, and no comment or doc says the window keeps the key on purpose. The backdrop, the **×** and **Cancel** each close it with no question. The windows it draws over itself already take their own Escape. So the missing key was an omission and not a guard.

**The rule.** Escape closes the window as the app's other windows close, except while a field inside it holds words typed and not saved. Then Escape does nothing to the window, and the form's own **Cancel** and the window's **×** stand. A window over this one takes the key first, as it does today.

**How it is built.**

- `src/lib/jobs/lienWindowEscape.ts`, new and pure. `lienWindowEscapeAction({ handled, topmost, busy, unsavedWords })` answers `ignore`, `stay` or `close`. `isWordField` says which fields hold typed words: a text box of any typed kind, a day, a number, a text area, an editable block. A select, a tick box, a radio and a file are not words, so changing one never holds the window. `fieldsHoldUnsavedWords` says whether any touched field reads otherwise than when it was first touched.
- `src/hooks/useUnsavedWords.ts`, new. The window holds about 45 fields across its tabs and keeps no one fact that says something is unsaved. So its card watches its own fields: the first time a typed field takes the focus, a key, a paste, a cut or a drop, what it held then is kept. A field that left the page is dropped, since its form was saved or cancelled or its tab was left. It reads the page and writes nothing.
- `LienInstrumentsModal.tsx` joins the app's window stack (`useModalStackEntry`) while it is drawn, and listens for keydown on `window`. It skips a key something marked handled, a key while another window is on top of the stack, a key while a dialog is drawn after it on the page, and a key while a send is being recorded, a PDF built or an email sent.
- A save that changes the job's filings or its demand letters drops what was kept, so a saved form does not hold the window afterwards. The records are compared by what they are, so a read that brings the same records back drops nothing.

**What takes the key first, checked in the code.** The confirm window stops the key before the page hears it. A paper's preview and a stop's paper window do the same and mark it handled. A value changed in place marks it handled and cancels its own field. The serve window, the path window and the property card are on the window stack. Each of these closes or cancels itself, and the Lien window under it stays.

**What changes beside the key.** Being on the window stack, the Lien window is now what is on top while it is open. A window under it that asks the stack before it acts on Escape no longer acts on one pressed in the Lien window.

**Known edges, each on the safe side or as it was.**

- A select or a tick box changed and not saved does not hold the window. The rule is about typed words.
- When Escape leaves the window open it says nothing, by the rule as given. A person who wants out presses **×**.
- A field typed in and then saved by a press that changes neither the filings nor the demand letters still holds the window until it leaves the page.
- A press on the backdrop still closes the window over typed words, as before. Not asked, not changed.
- The Release of Lien window, opened over this one from the Pipeline, listens for Escape with no check of its own. Where it is drawn before this window on the page, one Escape closes both. It closed on any Escape before this change too.
