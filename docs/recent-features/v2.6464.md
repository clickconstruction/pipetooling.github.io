# v2.6464 — The Contract window wraps its lines when opened from a job's window (2026-11-03)

Found on the live screenshots of the warranty (v2.6397–v2.6400) on ZZ TEST Riders Walk (J1088): opened from the job window's **Customer Contract** fact row, the Contract window wrapped nothing. The third line to initial ran off the warranty paper, and the right column ran past the window's edge, so the blue Send button's words were out of sight. Opened from a Pipeline row's chip it wrapped as it should, contract and warranty alike, so the fault was older than the warranty.

## Cause

`JobFormFactRow` keeps a fact's value on one line (`whiteSpace: 'nowrap'` on the value span, for its ellipsis). The Customer Contract row's value is `JobContractStrip` (`variant="inline"`), which draws `JobContractModal` and `AddJobContractSheet` inside itself, with no portal. A fixed overlay escapes its row's box but not its inherited text properties, so both windows took on `nowrap`.

## What changed

- `ResponsiveModalShell`'s overlay sets `whiteSpace: 'normal'`, so every window built on it starts its own lines wherever it is drawn. Its header comment says why.
- `AddJobContractSheet`'s own overlay does the same.
- Tests: `ResponsiveModalShell.render.test.tsx` and `AddJobContractSheet.render.test.tsx` each draw the window inside a `nowrap` span and read `normal` on the overlay. Both fail on the code before this change.

## Seen

This branch on a local server against prod data, J1088 opened from the job window's row, Warranty pressed (the draft autosave answered in the browser, nothing written): nothing in the window runs past its edge (0 px, against the right column cut off on prod), and the third line to initial wraps onto three lines inside the paper.
