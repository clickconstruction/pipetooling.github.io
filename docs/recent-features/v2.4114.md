# v2.4114 — Submittals: a fixture counted as WC 1&2 can be split into WC-1 and WC-2 (2026-09-29)

Stephen, after v2.4107: counts group fixtures the way the plans do (*WC 1&2 × 10*), and a submittal or a procurement log often wants them apart. Mock-up: artifact `CR8QdTBVqtd41Tp69eUajV` (two doors, the rule modal, downstream).

- **Kernel** ([`takeoffCandidates.ts`](../../src/lib/submittals/takeoffCandidates.ts)): a candidate gains `canSplit` (`tags.length > 1`), `storedSplit`, `split`; `candidateCounts(cands, ticks, splits)` counts `rows` (a split candidate once per tag) and `splitCount`; `candidateBar` reads *5 rows will go on Rev 1 · 5 with a product · 1 split into 2 · 4 left out*; `candidateToItemInserts` writes one row per tag with the same product, house and `source_count_row_id`; `rowSplitTags` reads a draft row's tag the same way (*WC-1, WC-2* · *WC-1 / WC-2* · *WC 1&2*; every part must carry a number, so *DWH1 & ET* never splits); `splitExplanation` is the modal's table.
- **Picker** ([`SubmittalTakeoffPicker.tsx`](../../src/components/bids/SubmittalTakeoffPicker.tsx)): a `role="switch"` Split per splittable row (tooltip names the tags), the sub-rows it becomes, *when can a row split?* beside the bar → [`SplitRuleModal.tsx`](../../src/components/bids/SplitRuleModal.tsx). `onConfirm(rows, ticks, splits)`.
- **Tab**: Build / Add write through `candidateToItemInserts` and save splits with the ticks (`saveTakeoffChoices(db, bidId, ticks, splits)`); **Split** beside Edit on a draft row (`splitRow`: the rows after it shift down, the row is replaced by one per tag carrying product, house, lead time, sheets, reason; a takeoff row's split is remembered); *when can a row split?* in the rows' footer when any row or candidate can split.
- **Procurement**: `ProcurementItemSource.sourceCountRowId`; `ProcurementRow.countedWith` (the other tags from the same count row) → *counted with WC-2 on the takeoff* under the product; `tagMatchesFixture` also matches a tag the fixture name spells out, so split rows keep their stage.
- **Data**: `bid_submittal_takeoff_choices.split boolean NOT NULL DEFAULT false` — `20260929033559_submittal_takeoff_choice_split.sql` ([doc](../migrations/20260929033559_submittal_takeoff_choice_split.md)).
- Guide *build a submittal package* → **Split a combined fixture**; the takeoff walkthrough stop mentions the switch.
