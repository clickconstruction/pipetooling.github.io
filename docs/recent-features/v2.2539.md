# v2.2539 — Shadow bidding machinery (fleet Phase 1) (2026-08-31)

Gate A was met on 2026-08-31 (BT-12 −2.6% / BT-13 +4.6% / BT-14 +3.5%, three axes);
this ships the roadmap's Phase-1 machinery so live bids become the twin's backtest
stream — blind by nature, because the shadow opens before the human number exists.

- **Migration `20260831210000_twin_shadow_runs.sql`**: one row per shadow
  (shadow_bid_id, reference_bid_id, axis, status open→locked→scored, locked_total,
  reference_value, delta_pct). Staff read via RLS; writes are twin-mcp-only
  (service role). All three fence appliers run.
- **twin-mcp v1.3.0**, four verbs: `get_shadow_queue` (recent, plans-present,
  UNSENT, un-shadowed human bids — logistics only), `open_shadow` (ZZ Shadow bid +
  run row; refused post-send), `lock_shadow` (blind total pre-send; contamination
  refusal if the reference was sent first), `score_shadows` (the auto-scorecard —
  deltas computed the moment `bid_value` + `bid_date_sent` land, scorecard notes
  stamped on both ledgers, per-axis rolling stats returned: `mean_abs_pct`,
  `last5_in_8pct`, and a `gate_b_met` flag per the fleet roadmap's ±8%×5 bar).
- Confidence-scoreboard UI deliberately deferred: `score_shadows` returns the
  scoreboard data; a dev-gated page lands once shadow volume exists.

`docs/EDGE_FUNCTIONS.md` twin-mcp section documents the verbs.
