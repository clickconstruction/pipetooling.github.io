# v2.8093 — Before we start: a lost signal shows Retry in place of an empty tab (2026-11-20)

Found by the Fable 5.2 audit of punch list #382 (Before we start). Client only: no migration, no edge function.

## What was wrong

Before the list is read, the app asks the database whether this person is on the job's desk (`start_checks_desk`). A check that failed was read as a no.

- `onStartChecksDesk` in `src/lib/startChecks/startChecksIo.ts` returned `!error && data === true`, so an error became false.
- `useJobStartChecks` set the desk to false on a rejection, and `JobDocumentsStartChecks` draws nothing for a person who is not on the desk. One lost request on a phone, or one statement timeout, and the whole **Before we start** section was missing from the job window's Documents tab, with no reason and no Retry, for as long as the window stayed open.
- `useSiteStartChecks` did `io.onDesk(id).catch(() => false)` for each job. A job whose check failed was left out of the Development page's Schedule look without a word, so the banner counted short. With every check lost the look was gone.

## The fix

- `onStartChecksDesk` throws when the check fails, through `withSupabaseRetry` as the other reads in the file do, and answers true or false otherwise.
- `useJobStartChecks`: a check that fails is not a no. The desk stays unknown, the failure is kept (`recoveryFailureFromError`), and `reload` asks the desk again while the desk is unknown and reads the list once it is known. Another job's failure is cleared when the job changes.
- `JobDocumentsStartChecks`: with a failure and an unknown desk it draws its heading with the same `OfflineRetryPanel` the list's own failed read uses. A real no still draws nothing.
- `useSiteStartChecks`: a desk check that fails fails the read, so the look draws its retry panel in place of a look that is a job short.

## Tests

- `JobDocumentsStartChecks.render.test.tsx`: a desk check lost to *Failed to fetch* draws the heading with Retry, and Retry asks again and draws the list. A no on Retry draws no section.
- `DevelopmentScheduleCard.render.test.tsx`: a lost desk check shows Retry in place of a look that is a job short, and Retry reads every job.
- The in-memory io (`src/test/startChecksMemoryIo.ts`) takes `failDesk`, a failure for the first desk check.

All three new cases fail on the old code, where the section and the missing job drew nothing.
