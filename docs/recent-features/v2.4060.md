# v2.4060 — Plug in quotes: hand-added lines keep their own keys, and a half-saved quote is taken back (2026-09-28)

Client only; no migration, no edge function. Fixes the quote-window smokes found (v2.4022) in `src/components/bids/PlugInQuotesModal.tsx`.

## Hand-added lines could share a key

A line added with **+ Add a line by hand** was keyed from the list's length and the count of hand lines. Add two, remove the first, add another, and the two lines left had the same key: typing a price in one filled both, and one **Remove line** removed both. Hand lines are now keyed from a count that only goes up.

## A save that failed partway left a quote behind

A save is three writes: the quote, its lines, then the house's price memory. They ran one after another with nothing to undo, so:

- **The lines fail** — the quote was already on the bid with no lines, the window stayed open, and a retry inserted a second quote. Now the save deletes the quote it just wrote (its lines cascade; the same "Pricing sharers can write" policy allows the delete), says why the lines failed, and a retry starts clean. If the take-back is refused too, the window says an empty quote from that house was left on the bid.
- **The price memory fails** — the quote and its lines were saved, but the window showed an error and stayed open, so a retry saved the whole quote again. The price memory is the "last quoted" hint other bids read; a failure there now keeps the saved quote, closes as a save, and says the memory did not update.
