# v2.5998 — Punch-list numbers are claimed, not derived: `npm run claim -- --todo` (2026-10-27)

Tooling only, no client change. On 2026-10-27 four sessions wrote punch-list cards within an hour, each taking the number `npm run check:todos` printed, and three cards collided — PRs #6330 and #6331 both took #204, #6329 and #6339 both took #205 — so the sessions renumbered by hand to #205, #206 and #207 after the fact. Versions have been safe from that race since v2.4844 (`npm run claim`, a ref under `refs/claims/` on GitHub); punch-list numbers now use the same ledger.

## What changed

- **`npm run claim -- --todo [hint]`** ([`claim-version.ts`](../../scripts/claim-version.ts)) reserves the next free punch-list number for the branch: one past every card on disk and on main, every number git history and the fragments remember (a retired number is never refilled), every other branch's claim and every `#N` on an open to-do PR's title. The claim is the local `todo-<N>.json` (`wx`) and the ref `refs/claims/todo-<N>` pushed with `--force-with-lease=<ref>:`, so two machines can never win the same number; a taken number bumps and retries. It sweeps on every run once a card with its number is on main (`git grep '^number:' origin/main -- to-dos`); `--release '#N'` gives one back.
- **Open to-do PR titles count** (`parsePrTodoNumbers`, [`sessionClaims.ts`](../../src/lib/sessionClaims.ts)): a `docs(to-dos):` title yields every `#N` it names, a range (`#161 to #165`, `#166–#175`) expanded; any other title only its `punch list #N` / `to-do #N` phrasings, so a PR number never counts.
- **`npm run check:todos`** reads the claims ([`todoClaims.ts`](../../scripts/todos/todoClaims.ts): the refs, fetched afresh unless CI, and the local mirror) into the numbers it treats as given out, so *Next free number* is past them, and its OK line says to reserve the number with `npm run claim -- --todo`. The duplicate-number error's "next free one" is past them too.
- **`npm run sessions`** shows main's newest card, the punch-list claims on GitHub and locally (merged / stale / not-on-GitHub flags as for versions), the open PRs writing a new card, and a COLLISIONS line when two PRs carry one new number or a PR's number is claimed by another branch. The `--brief` paragraph names the to-do claim.
- Docs: the *Claim the version* bullet in `CLAUDE.md` names the to-do claim in the same sentence; `docs/SESSIONS.md` (purpose, the ledger paragraph, quickstart step 1, the scripts, the card template), `to-dos/README.md`'s *Add* step and front-matter template, one line each in `AGENTS.md` and `docs/README.md`, and the `number` field's comment in `todoBoard.ts`.

## Tests
