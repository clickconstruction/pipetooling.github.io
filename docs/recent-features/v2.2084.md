# v2.2084 — Settings search bar (2026-08-22)

Owner request. Settings has up to twelve role-gated tabs (`getSettingsJumpGroups`) with sections three clicks deep; the search bar above the tab bar jumps straight to them. Mockup (type-ahead A vs filter-the-page B) → A picked and built.

- **Kernel** [`settingsSearch.ts`](../../src/lib/settingsSearch.ts) (+ tests): `SETTINGS_SEARCH_INDEX` — a **curated** entry list ({label, keywords, tabId, anchorId?}) rather than scraped headings (markup across the tab components is inconsistent, and curation lets entries carry the words people actually type: "vacation" → Personal time off, "trash" → Recently deleted). `searchSettings` ranks label-prefix < word-start < substring < keyword, caps at 8, and only returns entries whose tab is in the caller's role-filtered visible set. `pollScrollToSettingsAnchor` reuses the deep-link effect's bounded polling (sections hydrate async) plus two settle re-scrolls at 700/1800ms because hydrating sections above the anchor push it down after the first scroll.
- **Component** [`SettingsSearchBar`](../../src/components/settings/SettingsSearchBar.tsx): combobox/listbox with ↑/↓/Enter/Esc, bolded match substring, keyword-hint rows ("Re-assign jobs *(move jobs to another user)*"), destination breadcrumb per row ("in Your account →"), mousedown-picks (beats input blur), and a no-match line.
- **Wiring** in [`Settings.tsx`](../../src/pages/Settings.tsx): one block above `SettingsTabBar`; a pick sets `activeSettingsTab` and, when the entry has a real anchor id (`settings-salary-workday`, `settings-recently-deleted`, `settings-recent-emails`), poll-scrolls to it. Maintenance note: when a section moves tabs, update its index entry (one line).
- New help guide `find-a-setting-fast.md`.

Verified live as dev: "not" → 5 ranked results across four tabs with bolds + breadcrumbs; "vacation" keyword-hit → Your account + scroll to the Salaried-workday anchor (settles within a viewport after async hydration); "zzzq" → friendly empty state; Esc/pick both clear. Headless-pane note: results only open on real input focus (document.hasFocus), which is why programmatic verification dispatches `focusin`. Client-only — no migration.
