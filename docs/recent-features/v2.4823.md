# v2.4823 — Lien desk: the run knows the packet already printed (2026-10-07)

Client only. Found on the live desk during the docs catch-up of 2026-10-07: the title bar read **Send the run · 8** while the Do now rail's fourth rung read **Send the run 0**. The 8 were right — eight notices sat in *In the mail · tracking owed* (v2.4119's printed pile), and the run is where their tracking numbers are typed — but the door and the window both talked as if nothing had printed. Pressing the button opened a window titled *Send the run · 8 notices* with **1 · Print the packet** as the current step and **Print the packet · 7 envelopes** as the act, because `LienDeskRunModal` kept `printedAt` only for a print made in the same sitting. An office that followed it printed the packet again, which filed a second sent copy on every job in it (`printAndFile`, v2.4559) and re-stamped the items. The printed notice's own footer (v2.4568) already said *Record the mailing · 8 ▸*.

## What changed

- **`RunNotice.printedAt`** (kernel [`lienDeskRun.ts`](../../src/lib/jobs/lienDeskRun.ts)): `buildLienDeskRun` carries the item's `printed_at`. Two pure helpers beside it:
  - `runOpening(notices)` — `{ step: 'print' }` while any notice has not printed (or the run is empty); `{ step: 'record', printedAt }` with the newest print once every notice has one.
  - `runDoorWords({ ready, printed, retReady })` — the title bar's label: *Send the run* while anything approved is still to print (a ready retainage notice counts), *Record the mailing* when only printed notices wait. The count is unchanged: ready + printed + retainage ready.
- **The run window** seeds `printedAt` from `runOpening`, so a run of printed notices opens with step 1 done — `1 · Printed September 15, 2026 ✓` — step 3 current, the *Back from the post office?* line showing, and the title, the dialog's name and the ? explainer saying *Record the mailing* and the day it printed. The print button reads **Print it again · N envelopes**, plain weight, with a hover line saying every copy is filed on the job. A run that mixes ready and printed notices opens on printing as before.
- **The desk's title bar** draws `runDoor.label · runDoor.count` on `data-lien-desk-run`, with a hover line for each case. The Ready to send pile's title and the ready footer still read *Send the run* — they are on ready notices only.
- The Do now rail's fourth rung is untouched: it counts approved notices still to send, and 0 was right.
