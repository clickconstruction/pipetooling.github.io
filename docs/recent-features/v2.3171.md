# v2.3171 — Bid Board phone cards no longer scroll the page sideways (2026-09-08)

Fix, no migration. At phone widths (375px and 430px) `/bids?tab=bid-board` had document-level horizontal overflow: `document.documentElement.scrollWidth` was 484px in a 375px viewport, so the whole page dragged sideways. Pre-existing and unrelated to the v2.3162 "Bids on a map" card (identical with the card collapsed or hidden).

## Cause

Not the tab rows. The Bid boards strip (Bid Board / Robots / Followup / Unsent…) and the bid-detail strip (Counts / Takeoffs / … / Lien Release) both already render inside `ScrollableTabStrip`, whose scroller is `overflow-x: auto`; their inner flex rows measure ~590px and ~690px but are clipped by the scroller and never reach the document. Hiding them changes nothing.

The overflow came from the phone card rows in `BidsBidBoardTab.tsx` → `renderBidBoardCard`. The header row was a non-wrapping flex row holding the jump-icon cluster (five `1.75rem` jump buttons + optional robot-readiness icon + bid number + gear ≈ 250–270px, `white-space: nowrap`) and, pushed right with `margin-left: auto`, the inline due chip plus "sent" label (≈ 90–185px). Together that is up to ~390px inside a ~320px card. Flex items that can't shrink overflow at the row's end, the card has no clipping, and the page inherited the width. Attribution was done in Playwright via `/dev-login?as=1&to=/bids?tab=bid-board` at 375px by hiding candidate subtrees and re-reading `scrollWidth`: hiding the bid rows alone returned it to 375; hiding the tab strips, the fixed Dispatch footer, or the map card did not.

## Fix

- `src/components/bids/BidsBidBoardTab.tsx` — the phone card's header row gets `flexWrap: 'wrap'` (row gap `0.25rem`) and `minWidth: 0`. When the cluster and the chip fit, nothing changes; when they don't, the chip wraps to its own line and its `margin-left: auto` keeps it right-aligned. Desktop rows (≥660px, the table layout) are a different code path and are untouched.
- `e2e/viewport-smoke.spec.ts` — `/bids?tab=bid-board` joins the phone-width "no sideways overflow" page list (marker `Bid Board`), so the post-deploy suite pins this like the other seven pages. A jsdom render smoke can't measure layout, which is why the pin lives in the e2e suite rather than a `*.render.test.tsx`.
- `docs/E2E_SMOKE.md` — page-list wording updated.

## Verified

Local dev via dev-login at 375×800 and 430×800 (mobile emulation): `scrollWidth === clientWidth` on both; every card header row's `scrollWidth` equals its own width (322px / 377px). Screenshot in the PR shows the chip on its own right-aligned line under the icon cluster.
