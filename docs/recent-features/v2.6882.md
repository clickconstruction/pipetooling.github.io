# v2.6882 — A supply house bill you typed gets its lines by itself, read from the PDF it links (2026-11-10)

Punch list #298 PR 2 (`to-dos/supply-bill-lines/README.md`), over PR 1's tables and check kernel ([v2.6817](v2.6817.md)) and PR 1b's row and Look window ([v2.6819](v2.6819.md)). The office types most bills and pastes a Drive link, so the fill never saw their lines and the Lines cell read *No lines yet* on nearly every row. Step 0 shared the bills' Drive folder with the app's service account on 2026-11-10; this PR is the reader that uses it. No screen is new.

## The sweep

- **`supabase/functions/bill-lines-sweep/index.ts`** ([`docs/EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md#bill-lines-sweep)): every ten minutes by cron, or by a dev's bearer. It plans from three reads (every bill, which have a paper, the holds), takes the files whose rows have no paper, newest bill first, and for each: claims it, asks Drive what it is, downloads it as the service account by the file id in the row's link (the bills are outside the jobs Shared Drive, so the file index never lists one), reads the PDF's text layer, and asks Claude Sonnet 5.5 for every paper in the file. A file over three pages is split with pdf-lib and read three pages at a time, the ranges side by side, and a paper that runs across two ranges is joined. One file is read once however many rows link it.
- **Each row takes its paper by the invoice number, exactly**, both folded to letters and digits. The paper is checked by PR 1's `checkPaper` against the row's amount and, where the PDF has a text layer, every part code against the paper's own text (check 5, which the form's path cannot run), then written with its lines as the service role: `read_by` `sweep:<model>`, the Drive file and pages, `text_layer`. A paper no row took (a second bill in the file, a ship ticket) is kept with no bill and never counted.
- **What it holds** (`supply_bill_holds`, each with a reason and a sentence): the app cannot open the file, the link is no Drive file, the file is not a PDF or a picture, it is over 10 MB or 60 pages, the bill's number is not in its file (with the numbers the file does hold), the paper with the number is not an invoice, the file is a statement, the read was refused, cut or failed. A failed read comes back in an hour; a file the app could not open, a refusal and a cut in a day; the rest wait for a person, and a row whose link or number changes is due again at once.
- **Its own cap and ledger rows**: every model read is a `supply_bill_reads` row with `source = 'sweep'`; the sweep stops at 600 reads in a rolling day, and `bill-read` now counts only its own rows toward the office's 150.
- **Three calls**: `{ sweep: { limit? } }` reads; `{ probe: { n? } }` asks Drive whether it can open `n` linked files, newest to oldest, and reads nothing; `{ status: {} }` answers the counts and the line (*Lines read on 212 of 539 bills · 14 held · 294 to read · 19 with no PDF*), which the backfill's screen (PR 3) will draw.

## The kernels

- **`supabase/functions/_shared/billSweep.ts`**, re-exported by `src/lib/materials/lines/billSweep.ts` and tested in `billSweep.test.ts`: `sweepPlan` and `holdDue` (what is due), `PAPERS_SCHEMA` and `readPapersAnswer` (the bill reader's fields per paper, with its pages), `pageRanges` and `joinPapers`, `matchRows`, `paperRowOf` (the rows written, checked), `HOLD_WORDS` (each reason's sentence and door), `statusWords`, `sweepWords`, `probePick`.
- **`checkPaper` moved beside the functions** (`supabase/functions/_shared/paperChecks.ts`), since an edge function cannot import from `src/`; `src/lib/materials/lines/paperChecks.ts` re-exports it, the way `bills/billRead.ts` re-exports the reader, so the app and the sweep hold one definition.
- **`_shared/fileText.ts`**: a scan now says how many pages it has, so a long scanned stack is read in ranges.
