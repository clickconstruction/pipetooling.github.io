# v2.3848 — Weekly Money plan refresh: mockups retired, the dead `sub-sheets` queue label dropped (2026-09-26)

Docs + one registry edit; no migration, no user-visible surface change. Follows a seven-week audit of the Moneyfill weekly close and the Weekly Money report (built v2.1441–v2.1449; since touched by v2.2849, v2.2858, v2.2898, v2.3500): the surfaces are current and in use — % history has 105 real events past the 48 seeds, the standing Monday send has fired every week (Sep 7 / 14 / 21 within four minutes of 7 AM), and the close week of Sep 14 scored 15 of 22 jobs — but two artefacts of the build had rotted.

## The two fixes

- **`MONEYFILL_QUEUE_LABELS` loses `sub-sheets`** ([`moneyfillWeekClose.ts`](../../src/lib/moneyfillWeekClose.ts)) and the `MoneyfillQueueKey` union with it. Queue 3i (sub days without a priced sub sheet) was planned "v2-optional" and never built; the label had no fetcher and no section, so `fetchWeekCloseCounts` could never return it and the header's "N of M queues at zero" already ignored it (noted in v2.2921). Removing it makes the registry and the page agree by construction — the type now names exactly the eight queues that exist.
- **`docs/WEEKLY_MONEY_PLAN.md`**: the "visual reference" line pointed at the 2026-08-06 concept artifacts, which no longer match the shipped chrome (button labels, the Sun–Sat pay-week note on pending approval, the bank-transfers 90-day scope note, the "still running" suffix, an "Ask crew for report" action that was never built). It now points at the live pages and the help guide; queue row 3i reads **dropped** with the reason; `last_updated` refreshed (the rows had been amended by v2.2849 / v2.2858 without touching it).

## What the audit did NOT change

The close is not being worked to zero — the Sep 14 week showed 2 of 8 queues clear with **$116k across 27 unapplied deposits** — so the report's Cash lens cannot say which jobs got paid. That is exactly what its confidence footer says each week; it is a Monday-routine gap, not a code gap, and is left for the owner.

## Verify

`/moneyfill` header still reads "N of 8 queues" for any week; `npm test` (registry tests unchanged — no test ever referenced `sub-sheets`); `docs/WEEKLY_MONEY_PLAN.md` line 30 names the live surfaces.
