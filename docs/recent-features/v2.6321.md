# v2.6321 — Expected hours: a project's target, set in the open, with its history (punch list #242, PR 2) (2026-11-02)

Punch list #242, PR 2 of five. The table under the board's slider and the phone's target line, with the hook that reads and writes it. The spike kept the targets in browser storage; this is the ledger. Nothing on a screen yet.

## What landed

- **Migration `20261102041411_job_expected_hours.sql`** (`docs/migrations/20261102041411_job_expected_hours.md`): `job_expected_hours`, one row per change, append-only — `job_id`, `hours`, `from_hours`, `set_by` + `set_by_name`, `set_at`, `why` (3–240 characters, required), `cleared_at` + `cleared_by` + `cleared_by_name`; one open row per job (`job_expected_hours_one_open`). `set_job_expected_hours(job, hours, from_hours, why)` closes the open row and writes the new one in one instant; `clear_job_expected_hours(job)` closes it with nothing new (*back to the budget*). `can_set_job_expected_hours()` is the leader and the office (`is_master_or_dev() OR is_assistant()`). RLS: read by whoever sees the job in the ledger, write by the setters on a job they see, delete by the dev; the three fence calls.
- **`src/lib/jobs/expectedHours.ts`** — the read kernel over the rows: `openTargetsOf` (the open target per job), `changesOf` (every set, and every clear with no successor, newest first, for the Recent changes strip), `changeWords` (*110 → 96 h · Robert · framed in a week*, *60 → budget · Taunya · back to the budget*), `undoOf` (after a set, back to the target it replaced or to the budget; after a clear, the cleared target again).
- **`src/hooks/useExpectedHours.ts`** — one chunked read for the board's jobs, `byJob`, `history`, `undo`, `setTarget`, `clearTarget`, `undoLatest`, `reload`, `loading` and `error` in words (`formatErrorMessage`); writes through the two functions, then a re-read, so every card reads the same ledger. Reads through a cast until the types PR after the push.

## Decisions

- **Append-only, with `cleared_at` as the only field that changes.** The history is the strip; a row replaced in the same instant as its successor's `set_at` draws no *clear* line of its own. Undo is itself a change on the ledger (*undo: back to 110 h*), never a deletion.
- **The names ride the ledger** (`set_by_name`, `cleared_by_name`), so *set by Robert on Nov 1* holds after any rename.
- **Who sets**: the card's default — the leader and the office; a superintendent reads.

## Push

`supabase db push` from a checkout at `main` right after this merges; nothing calls the table until PR 3, and `check:calls-ahead` holds the deploy until the push. Then `npm run gen-types:linked` as its own `chore(types)` PR when convenient.
