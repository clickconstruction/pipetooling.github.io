# v2.5972 — What everyone sees: a before-and-after for every style change (2026-10-27)

Punch list #194, PR 8, the last of the plan ([`to-dos/experiences-lens/`](../../to-dos/experiences-lens/README.md)). The theme draft (v2.5969) shows a change before a PR exists. This shows what a PR's change does, in the PR.

- **The capture** ([`scripts/lens/lensShots.mjs`](../../scripts/lens/lensShots.mjs)) opens the report's 16 screens on a served build: each role's busiest pages, from the estimator's Bids to the dev's Bridge. Each is a sealed frame, named on the build's own origin before the page loads, so it draws on the invented world with no sign-in and no request leaving the page.
  - Every capture runs at one fixed moment (`page.clock.setFixedTime`), so a running timer or today's date never reads as a change.
  - It shoots light and dark at 375 and 1280, which makes 64 shots, and keeps each frame's caught errors.
- **The comparison** ([`scripts/lens/lensReport.mjs`](../../scripts/lens/lensReport.mjs)) puts each before and after pair on a headless browser's canvas, with no new dependency. It writes `index.html`: the changed screens first, most changed on top, each with before, after and its changed pixels in red, then the unchanged ones folded. It prints *N screens · M changed · K the same*.
- **The workflow** ([`.github/workflows/lens-report.yml`](../../.github/workflows/lens-report.yml)) runs on a pull request that touches `src/index.css`, any CSS, the portal's palette or the lens, and on demand.
  - It builds main and the pull request and serves both with `vite preview`, then captures each and compares them.
  - It uploads the report as the run's **lens-report** artifact and writes the count to the run's summary.
  - It is non-gating, with no secrets: the build's Supabase address is one the seal answers itself.
  - Until the lens is on main, main's capture shows sign-in pages, and the step is allowed to fail.
