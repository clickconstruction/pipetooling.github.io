## 1 · The rough while bidding from a template with rows

- `roughPress` (`schedule/scheduleWindow.ts`) copies a rows template's phases and rows onto the rough beside its copy of
  the lines (`RoughSchedule.rows`, a `TemplateRowsShape`, now in `schedule/types.ts` so the rough reads it without the
  builder). A redraw with no new pick keeps the copy, as it keeps `like`; a template with lines alone keeps none.
- `roughDraw` (`schedule/rough.ts`) draws the copy through `rowsDraft` from the rough's start with the job's stage days
  for the lines in no row, so the rough's weeks, its stage rows and its dates to meet follow the rows. `drawWeeks` moved to
  `schedule/schedule.ts` (re-exported from `rough.ts`) so the builder and the rough read each other without a cycle.
- `templateDraftPress` draws the first draft from the rough's own copy of the rows when the job was bid on it, even once
  the template is set aside or saved as a new version, and the log's line still counts the rows and phases.
- `gc_rough_schedules.template_rows` (migration `20261107160000`) holds the copy; `roughRowOf` (`writes.ts`) writes it and
  `roughFromRow` (`rows.ts`) reads it when the row carries an object with its arrays, else the rough reads as before.
- `GcRoughSchedule.tsx` hands the pick the rough's own copy, and `GcTemplatePick` says D3's six lines (`RowsFit`, now on a
  `TemplateRowsShape`) for a rows template whether offered or the rough's own.

## 2 · A phase on the job's own work

- **Add an activity** (`GcAddOwnWork`, `GcScheduleCards.tsx`) offers **Phase** when the schedule was drawn with phases:
  the phases in the schedule's order under *Not in a phase*, which is the default and lands the bar as before.
- `ownWorkPress` puts the phase on the activity when the schedule lists it and drops one it does not; `addedForRpc`
  (`writes.ts`) sends it as `p_bar.phase` (`RpcAddedBar.phase`).
- `gc_schedule_add_activity` (replaced by the migration) reads the phase, refuses *That phase is not on this schedule.*
  before the version moves, and writes it on the bar, so By phase lists the work in its phase on the chart and the list.
- Not built, the card's *may*: moving an opened bar to another phase from its form. A bar's `phase` is a record column the
  plan guard lets through, so it is a plain update when wanted.
