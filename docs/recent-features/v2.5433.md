# v2.5433 — Messages: our link to a Drive file opens only what is safe to show (2026-10-13)

Messages, cut 7b's follow-up (GC Mode helper 8, from its review of #5552, agreed with the lead session GC MODE). Four fixes to the `drive-link` edge function. No screen, no migration. **Redeploy `drive-link`** once merged.

- **A page or a script is saved, never shown.** The open door streams a Team only file from the function's own address. A file that came by email from outside, saved to Drive and sent on as our link, could be a web page, an SVG or a script, and inline it would run there. `streamsInline(mime)` in `_shared/driveLink.ts` sends those types as `attachment`, and every stream carries `X-Content-Type-Options: nosniff`. A PDF, a picture or plain text still opens in the browser.
- **The 50 MB cap reads Drive's own length.** The size on a `drive_links` row is the size the day the link was made. A file grown past the cap since is now refused by the `Content-Length` Drive answers with, the same `{ kind: 'off', why: 'tooBig' }`.
- **Save to Drive pressed twice keeps one copy.** A file that came in and already has its `drive_file_id` answers that file, so a second press or a second person makes no second copy.
- **The list's page token is encoded** in Drive's address, so a token with a `+` or a `/` reads the next page.
- Tests: `driveLink.test.ts` gains the inline and attachment types (16). `deno check` on the function is clean.
