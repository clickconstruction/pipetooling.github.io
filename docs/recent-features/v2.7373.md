# v2.7373 — Box labels: a shorter strip, with the link on two lines (2026-11-15)

Taunya's ask of 2026-11-15, as she was about to print a run of hundreds from Print labels: "I don't like how each one says 'scan for whats inside'. I think that that can be removed. I also think `prts.co/b/849f-db0b` could look like `prts.co/b/` on one line and `849f-db0b` on the next, allowing for shorter labels." Client only: no migration, no edge function. The link, the code and the QR are what they were, so a label already on a box scans and types as before.

## What changed

- **`src/lib/materials/tapeStrip.ts`** (pure): `tapeAddressLines` breaks the address after `/B/`, so `PRTS.CO/B/849F-DB0B` is `PRTS.CO/B/` and `849F-DB0B`, and an address with no code (the test strip's `PRTS.CO/B`) stays one line. `tapeStripLines` is the lines under the stencil: the address's lines, then a line of words only when a strip has any. `tapeStripBlock` sets the stencil's baseline and each line's, the block centred on the tape's height; the canvas no longer does that sum itself.
- **`tapeStripCanvas.ts`** draws those lines. The strip's width is still its widest line plus the trim to the last dot of ink, so with the address no wider than ten characters the name sets the length.
- **`tapeLabel.ts`**: `TAPE_WORDS` (*Scan for what is inside*) is gone. The print-window strip was a fixed 72 mm (60 on 18 mm tape); `tapeLayout(width, nameChars)` now cuts it to what the run's longest name needs, never less than the address's first line, and `tapePrintCss` takes the same count for its `@page` size. `longestNameChars` reads it from the names a run prints.
- **`LabelsPrintModal.tsx`** and **`PrintStickersModal.tsx`**: the print-window strip draws the address's two lines; the straight-to-printer strip (`TapeStripBitmap`) takes `words` only for the test strip. **What the stickers will look like** draws through the same component, so the preview follows by itself.
- `StickerStrip.words` is optional; `stickerStrip` and `previewStrip` hand none. `STICKER_TEST_STRIP` keeps *Test strip*, so nobody takes it for a sticker.
- The site guide's **Print a tape label**, the map's two label sentences and cards #294 and #329 say the strip as it is now.

## Measured

Drawn through `TapeStripBitmap` in Chrome on a Mac (Menlo, as the P-touch gets it), in the printer's own dots at 180 an inch:

| Name | 24 mm tape, before | 24 mm tape, now | 18 mm tape, before | 18 mm tape, now |
|---|---|---|---|---|
| G1 | 51.2 mm | 38.1 mm | 43.6 mm | 32.0 mm |
| G81 | 51.1 mm | 41.8 mm | 43.6 mm | 35.3 mm |
| G120 | 51.2 mm | 49.0 mm | 43.6 mm | 41.6 mm |
| a sticker, 0001 | 51.2 mm | 45.3 mm | 43.6 mm | 38.2 mm |

Before, the address was the widest thing on every strip, so every strip was the same length. A run of 91 boxes, G1 to G91, five strips each, was about 23.3 m of 24 mm tape and is about 18.9 m.

The print-window strip, per longest name: 41 mm for two characters, 47 for three, 54 for four, 61 for five, 69 for six on 24 mm tape; 32, 35, 40 on 18 mm.

## The picks

- **The type is the size it was.** Taunya was shown three versions with their lengths: today's, the two lines in today's type, and the two lines with the code a third taller. She picked the two lines in today's type, the shortest for G1 to G9.
- **The QR is not touched.** The same squares at the same whole number of dots, the two squares clear at the cut edge and four before the words. The first 155 columns of the new strip are dot for dot the old strip's, and Chrome's own `BarcodeDetector` reads `HTTPS://PRTS.CO/B/<CODE>` off each new strip.
- **The room the line of words left is not spent.** A larger name is a wider name, and the name now sets the strip's length.
- **The print window's length follows the run's longest name**, since that route cuts every strip of a run to one page size. A fixed shorter strip would have cut off a five-character name that the 72 mm strip held. The room is 0.8 of the type size a character, measured so a name of W's and M's fits.
