# v2.3558 — The Punch list moves into the app: the to-do board as a page, anyone with repo access can change it (2026-09-17)

Client + tooling + docs. A new page, a new build step, a service-worker denylist entry, the generated data file, a role-gate surface, a help guide. No migration, no edge function. Closes the artifact era of the board (v2.3497 → v2.3557).

## Why

Two hours after v2.3557 published the punch list as a claude.ai artifact with shared picks, the owner asked the question that ends that design: *could any agent or actor republish the board from main other than me?* No — an artifact is updated only by the account that published it. The Artifact tool refuses everyone else, a page cannot fetch `main` (CSP), and CI has no way to publish one. So every change to the board, however it was made, waited on one person's session. The owner's requirement was the opposite: **anyone with access to the repo can add to it, subtract from it, and pick it up**, durably.

The repo already had the durable path. The client deploys to Pages on every merge; a to-do's front matter already renders the board's rows (v2.3497); `helpSharePagesPlugin` already writes extra static files into `dist`; `/roadmap` already shows how a role-gated page refuses a link. The board just had to be one more page.

## What shipped

**The page — `src/pages/PunchList.tsx`** at `/punch-list`, gear menu → *Punch list* for dev + master (`canOpenPunchList` in `src/lib/todos/punchListAccess.ts`; a new `punch-list` surface in `roleGate.ts` lands everyone else on Today with the #29 sentence). The same board as the artifact: the readiness tiles, the Show filters, five groups with a colored stripe, each row with its name (the file on `main`), the version chip with every `v2.NNNN` linking to its `docs/recent-features` fragment, the summary, *Next*, the links line, size and blocker, and Do / Later / Drop with a note. Standing lists show *standing list* and take no pick. The row grid stacks under 860px. Theme tokens throughout.

**The data — `src/content/punchList.generated.ts`**, a typed module rendered by `npm run check:todo-drift -- --fix` (`renderBoardData` / `renderBoardModule` in the kernel) and checked in CI, replacing the html's `ITEMS` array. `to-dos/punch-list.html` is deleted; the README index's mock-up links now point at the app's origin instead of raw.githack.

**The mock-ups — `todoMockupsPlugin` in `vite.config.ts`** copies every `.html` under `to-dos/` to `dist/to-dos/<same path>` at build, so `/to-dos/submittals/mockup.html` is a page on the site. `globIgnores` keeps them out of the precache; `src/sw.ts` adds `/^\/to-dos\//` to the navigation denylist so the shell never swallows them (the `/g/` precedent). Verified on a local build: 22 pages under `dist/to-dos`.

**The view kernel — `src/lib/todos/punchListView.ts`** (12 tests): counts, filters, grouping, the toggle, the link chips, `versionSegments`, and a tolerant reader for the picks the old board left in `localStorage` under the same key.

**Picks** are device-local in this PR (`localStorage`, the old key, so a pick made on the artifact's local fallback carries over). The next PR moves them to a `punch_list_picks` table with the picker's name.

## How anyone changes the board now

Stated once in `to-dos/README.md` → *To add, change or retire a to-do*: change the to-do file (front matter for the row, an `.html` beside it for a mock-up), run `--fix`, commit both regenerated views, PR. The merge deploys the client and the board shows the change. There is no publish step, no owner, no artifact.
