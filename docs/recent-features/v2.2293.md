# v2.2293 — Quick Estimate: the field change-order wizard (2026-08-25)

Owner-approved mockup v4 (change-order-first), built on the v2.2292 groundwork. A master in the field writes up a change order (or, via the side door, an estimate) in a 5-screen modal and hands it to Dispatch.

**Kernel** [`quickEstimate.ts`](../../src/lib/quickEstimate.ts) (+16 tests): `parseBallparkDollars`/`formatBallparkUsd`, `quickEstimateCanSend` (description OR photo), `quickEstimateReviewRows` (✓/— rows; skips phrased as the office's next move), `quickEstimateDispatchTitle`/`quickEstimateReferenceSummary`, `quickEstimateBallparkLine` (a **$0 placeholder** line "Field ballpark: ~$X — to be priced" so the rail keeps cost unfinished and no field number can reach a customer), `quickEstimateWorkLine`, `quickEstimateDraftTitle`.

**Wizard** [`QuickEstimateWizard.tsx`](../../src/components/estimates/QuickEstimateWizard.tsx): opens on the user's `job_schedule_blocks` for today/tomorrow (Chicago) — picking a job silently sets `doc_kind='change_order'` + the job's customer; "New work for someone else →" swaps in the customer screen (`customers` search, free-typed name/phone, skip). Work screen = voice-nudged textarea + camera photo uploads (bucket `estimate-field-photos` + `estimate_field_photos` rows). Cost = type-first dollar field + quick chips + skip. Send = `sent_to_dispatch_at` stamp, author added to `accept_notify_user_ids` (the existing accept-estimate email = the acceptance ping), one `dispatch_requests` row (`pending_action: 'review_field_estimate'`, links `/estimates/<number>`, `pending_payload` {estimate_id, doc_kind}) + `notify-dispatch-request`. ✕ always saves-and-closes; the draft exists from stage 1 (created via `resolveEstimateMasterUserId`, exactly like `createDraft`).

**Job linkage note**: `estimates.job_ledger_id` is UNIQUE per job (the created-from/apply link), so the wizard does NOT set it — the picked job travels on the dispatch request's `job_ledger_id`, the customer link, and a "Job: HCP … (address)" first line inside `change_order_fields.description_of_change`.

**Entry points**: Settings → Dashboard & alerts `QuickEstimateToggleSection` (roles: dev, master_technician, primary, estimator, superintendent, subcontractor; stored as `user_dashboard_buttons` key `quick_estimate`, default OFF) → purple ⚡ button at the top of the Dashboard.

**Office side**: Estimates list drafts show an amber **With Dispatch** chip (`withDispatchChip`, both table + cards) when `sent_to_dispatch_at` is set; `DispatchInboxSection` renders an **Open the draft** link for `review_field_estimate` requests; estimate detail mounts [`EstimateFieldPhotosStrip`](../../src/components/estimates/EstimateFieldPhotosStrip.tsx) (self-loading signed-URL thumbnails, renders nothing when empty).

**Help guide**: `write-up-a-change-order-from-the-field.md` (Field).

**Deferred** (small follow-ups): auto-close the dispatch request when the office sends the estimate (lives in `send-estimate-to-customer` edge fn; Dismiss covers it today); "already sent one for this job today" warning; resume-your-last-write-up prompt.
