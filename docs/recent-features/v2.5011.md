# v2.5011 — Dispatch Mode: controllers get the PO tab (2026-10-09)

Client only. No migration, no edge function. This builds the owner's call of 2026-10-09, from the decisions walk: the controller joins the Dispatch Mode PO tab.

## Why it was missing

A controller reads as an assistant everywhere (`isAssistantLike`, `docs/ACCESS_CONTROL.md` → controller), and Dispatch Mode itself was already theirs. But `dispatchModePoRoleAllowed` (`src/lib/dispatchModePoToggle.ts`) spelled its roles out as dev, master technician and assistant. So a controller in Dispatch Mode got neither the PO tab nor its gear item. The role sweep of v2.2920 left it so. Yet the PO-minting RPC, `insert_material_po_generator_entry`, already allowed the controller. So did the tab's default, through `isAssistantLike`.

## The change

- `dispatchModePoRoleAllowed` now admits dev, master technician and `isAssistantLike` roles. That is the RPC's list and Layout's Dispatch Mode gate. The gear item and the footer tab both read it.
- With no choice stored, the tab is on for a controller, as it is for an assistant. The gear menu's **PO tab** turns it off.

## Docs

- `docs/ACCESS_CONTROL.md`: a **Dispatch Mode → PO tab** row in the Dashboard feature matrix, under Job Mode. The controller reads as the assistant column.
- *dispatch mode*: "Assistants, controllers and leaders get it by default."
- `docs/GLOSSARY.md` already said *assistant-like* for the PO Generator and Dispatch Mode → PO, and it is true now.
