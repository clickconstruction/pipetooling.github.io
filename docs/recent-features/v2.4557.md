# v2.4557 — Documents: every bill email is kept as it went (2026-10-05)

Step 2 of the Sent copies train ([`docs/SENT_COPIES.md`](../SENT_COPIES.md)) begins: the owner's *"keep the email"*. The foundation ([v2.4554](v2.4554.md)) files what the client prints; an email is sent by an edge function, which is the only place holding the exact message and its attachments. This adds the edge-side helper and wires the two functions that email a bill. No migration. **Two functions to redeploy**: `send-physical-invoice-email`, `send-stripe-invoice` (`test-email` is already deployed).

## The helper

- [`_shared/sentCopyEmail.ts`](../../supabase/functions/_shared/sentCopyEmail.ts) (pure, no Deno API): `sentEmailCopyHtml` — the page the office opens: a grey head (from, to, cc, subject, the attachments by name) placed inside the message's own `<body>` when it has one, then the message as it was read, an inline image (`cid:`) drawn in place; `sentAttachmentPath` / `sentAttachmentType` (an unknown or `.html` file is plain bytes, never a page); `sentEmailRow` — the `sent_documents` row, ids that are not ids dropped.
- [`_shared/fileSentCopy.ts`](../../supabase/functions/_shared/fileSentCopy.ts): `fileSentEmailBestEffort(filing, message)` — stores the page and each attachment in `sent-documents` (`<row id>/copy.html`, `<row id>/<n>-<file>`; attachments past 20 MB in all are named on the page and not kept), then inserts the row, all by raw REST with the service role. Never throws; the row is still written when the page could not be stored.
- [`_shared/resendSendEmail.ts`](../../supabase/functions/_shared/resendSendEmail.ts): `sendEmailViaResend` takes `options.file`; given it, the helper files after the send log. Mail to our own staff leaves it out.

## The bills

- `send-physical-invoice-email`: files the email with the invoice PDF and any companion PDFs — `bill`, or `bill_resent` for `resend: true` (which wrote nothing anywhere but the email log until now) — keyed to the job, the payer (`customer_id`: the GC when the GC pays) and the invoice.
- `send-stripe-invoice`: the payer's own bill email (`bill`, with Stripe's PDF when attached) and each live copy (`bill_copy`), keyed to the job and the invoice. A test-mode bill and its test copy are not filed. The Stripe-sends-it fallback has no message of ours to keep.

## The self-test

`test-email` (the dev-only door) takes `file_copy_only: true`: it sends nothing and files the message as a `self_test` copy with one small attachment, through the same helper. Deployed first and run against the live project on 2026-10-05: the page (with its head), the attachment and the row all landed, the sender's name was filled in by the table's trigger, and the row was deleted afterwards. The client side was proven the same day from the dev preview (`fileSentCopy`: stored, read back, a repeat pointing at the first file, an update touching no row).

## The ratchet

[`sentCopiesEmailCoverage.test.ts`](../../src/lib/sent/sentCopiesEmailCoverage.test.ts) reads every edge function and shared helper that hands a message to Resend: each files, is on `EMAILS_OWED` (23 today), or is on `NOT_OUTSIDE` with its reason (mail to our own staff, a sign-in link, the sender itself). A new sender fails CI until it has an answer.

## Tests

`sentCopyEmail.test.ts` (7), `sentCopiesEmailCoverage.test.ts` (3). The edge functions have no local type check (no Deno on the authoring machine). The helper itself is proven by the self-test above; each bill function's own wiring is proven by its first live bill after the deploy, on that job's Documents tab.
