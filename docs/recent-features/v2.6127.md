# v2.6127 — A report on a ZZ test job reaches no one (2026-10-30)

Found on punch list #189's camera live run (2026-10-30): saving a Note report on the ZZ Test job would have emailed the one every-report subscription (`report_email_subscriptions` with `all_authors = true`) and pushed *New Note* to every phone opted in for Note reports, exactly as a real job's report does. That run stubbed both calls in the page with a `window.fetch` override, so nothing went out — but every session that walks a flow on a ZZ job and saves a report reaches the office unless it stubs the sends itself. The rule for test rows (`AGENTS.md` → *ZZ test rows need no approval*, v2.6124) is that nothing leaves the building because of one. Now the two functions keep it, so no caller can miss it.

## What changed

- **The rule has one home on the edge.** `isZzTestName` and `isZzTestJob` moved verbatim from `src/lib/jobs/zzTestJobSweep.ts` into `supabase/functions/_shared/zzTestJob.ts` (pure, no imports); the sweep file imports and re-exports them, so its twelve importers and its tests are unchanged, and the generated copy in `_shared/gcKernels/` points at the edge file as the generator's rule says (`npm run gen:edge-kernels`, one file changed).
- **`_shared/reportSubject.ts`**: `readReportSubject(db, report)` reads the report's job (`job_name, customer_name, hcp_number`), project (`name`) or bid (`project_name, gc_contact_name`) once, as a structural client so `src/lib/reports/reportSubject.test.ts` reads it with a fake; `reportSendSkip(subject)` answers `{ reason: 'zz_test_job', message: 'ZZ test job: nothing sent' }` when the job's name or its customer's, the project's name or the bid's project name starts with ZZ — the Pipeline's own rule — and null otherwise.
- **`send-report-email`**: `auto` reads the subject right after the report and answers `{ ok: true, sent: 0, skipped: 'zz_test_job', message }` before it reads a subscription, so no email and no dispatch row; `manual` (**Send now**) leaves such reports out and counts them as `skippedTestJobs`. The job display on the email comes from the same read, word for word as before.
- **`send-report-notification`**: the same read right after the report; a ZZ record answers `{ success: true, message, push_sent: 0, skipped: 'zz_test_job' }` before a preference is read. The push's job words come from the same read.
- **Send now's words** (`EmailReportPersonEditor.tsx`): when the function left reports out it says so — *Emailed 2 reports. 1 report on a ZZ test job was left out.*
- **The callers are unchanged** — `AdditionalReportModal`, `NewReportModal`, `submitStatusReportFromStepper`, the Job Mode `TurnawayModal` and the offline queue's `afterLanding` still fire both; the rule lives where every one of them lands.

Left as it was: `_shared/legalLienBookShape.ts` keeps its own copy of the name rule (`isZzName`); switching it to `zzTestJob.ts` would put `legal-portal` on the redeploy list for a change that alters nothing, so it waits for that function's next deploy.

Until both are deployed, a report saved on a ZZ job still reaches the subscribers and the phones, as before. No migration.
