# v2.5468 — Messages: a picture texted to the company number is kept the moment it comes (2026-10-13)

Messages, cut 10's last item, photos 4 (GC Mode helper 2, directed by the lead session GC MODE): photos saved on
arrival. The quo-webhook (#5452) now keeps our copy of each picture or file on a text, since "Quo's link to the picture
is best treated as temporary" (the prototype's `quo-messages-mockup.html` draft 8, on branch spike/gc-mode).

- **`supabase/functions/_shared/quoMedia.ts`**, new, `keepTextMedia(admin, lineId, quoId, media)`.
  - It reads the files the line already has, so Quo's retry keeps nothing twice (`mediaToKeep`).
  - It fetches each file once from Quo's link with a 10 s timeout, asking again with `QUO_API_KEY` when the link refuses
    a plain read.
  - It uploads a file that read and fits 25 MB (`keepsCopy`) into the private `message-attachments` bucket at
    `quo/<quo id>/<place>.<ending>`, and writes its `message_attachments` row (`quoMediaRow`, v2.5456).
  - A file that does not read or upload, or is over the cap, keeps its row marked `quo_not_copied` (on prod since
    `20261014070000`).
  - A row that does not write throws, so the webhook answers 500 and Quo sends the event again.
- **`quo-webhook`**: `planAndWrite` keeps the line's id from `writeLine` and, for a text in, calls `keepTextMedia`. The
  change is two lines and one import, placed clear of #5523's lines in the same file.
- **`src/lib/quo/mediaKeep.ts`** gains `mediaToKeep(plans, keptOrders)` (a retry's skip) and `keepsCopy(fetched)` (the
  cap, one rule for the row and the upload).
- **The edge copy** (`_shared/gcKernels/`, regenerated) takes `quo/mediaKeep.ts`: 76 files and 18,323 lines.
  `quo-webhook` was already an importer.
- **What follows from it**: once a photo is kept, a ticked job's photos go to Drive with the `photo-save` sweep (v2.5458,
  cron v2.5464). The line's files read `quo_not_copied` as their own words with helper 7's photos 5 (#5631).
