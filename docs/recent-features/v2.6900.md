# v2.6900 — A box label's scan no longer ends on an empty page (2026-11-10)

On 2026-11-10, in the owner's signed-in Chrome, the first open of `clicktooling.com/b/b365b514?preview=1` (the ZZ1 test cage) ended at `/tally?tab=on-site` with an empty `#root` that stayed empty for seven seconds. The second open worked. No console was captured, and several client deploys had landed in the hours before.

## The cause

A page that loses its chunk to a deploy throws, and nothing above the routes caught it. React unmounts the whole app on a render error no boundary catches, which leaves `#root` empty.

`RouteChunkBoundary` sat only around the Layout's outlet. Outside it were:

- every route outside the Layout, `/b/:code` among them. v2.6868 gave it a `<Suspense>`, which answers a page still loading, not one that fails to load;
- the providers above the Layout. `BillCustomerModalProvider` and `TestReportModalProvider` each draw a `lazy()` window when they mount. A scan mounts them for the first time when it moves from `/b/:code` to `/tally`.

How a tab comes to ask for a file that is gone: the service worker holds a build whole, so an old build runs from its cache without the server. But `clientsClaim()` hands every open tab to a new worker the moment it activates (another tab's **Reload** on the update pill, or its automatic reload at a quiet moment), and the new worker's activation drops the old build's files. A tab that booted the old build a moment before then asks the server for old chunks and gets GitHub Pages' 404.

Two endings, both reproduced (below):

1. **The one-shot reload is free.** `main.tsx`'s `vite:preloadError` handler starts the recovery reload and cancels Vite's throw. The `lazy()` page then resolves to nothing, React reports `TypeError: Cannot read properties of undefined (reading 'default')`, the app unmounts, and the page is empty until the reload lands. That reload wipes the worker and every cache first, so the app boots from the network: 2.4 MB over the wire and 8.2 MB to parse on 2026-11-10, with nothing in `#root` meanwhile.
2. **The one-shot reload was spent in the last minute.** The handler stands aside, the import rejects with `Failed to fetch dynamically imported module: …/BoxCode-….js`, the app unmounts, and the page stays empty for good.

## What changed

- **`src/App.tsx`**: `<Routes>` sits in `<RouteChunkBoundary resetKey={pathname}>`. It catches the routes outside the Layout and the providers above it. The Layout keeps its own boundary around the outlet, so a lost page chunk there still leaves the nav standing.
- **`src/lib/chunkLoadRecovery.ts`**:
  - `startChunkRecoveryReload(now, storage, reload)` claims the one-shot guard, remembers that a reload is on its way and calls `reload`. `main.tsx`'s handler and the boundary both start the reload through it.
  - `chunkRecoveryReloadStarted()` reads that memory. `forgetChunkRecoveryReload()` clears it for tests.
  - `chunkBoundaryView(error, reloadOnItsWay)` is what a boundary draws: `page`, `updating`, `lost-chunk` or `broken`. While a reload is on its way the answer is `updating` whatever the error says, which covers ending 1's TypeError.
- **`src/components/RouteChunkBoundary.tsx`** draws from `chunkBoundaryView`. Its words and its Reload and Fix app presses are unchanged.
- **`src/lib/lazyRouteBoundaries.ts`**: `routesSitInChunkBoundary(source)` is true when `<Routes>` in `src/App.tsx` sits inside an open `<RouteChunkBoundary>`. The Layout's own, inside a route's element, does not count.
- `docs/APP_SHELL_ARCHITECTURE.md`: the boundary around `<Routes>` and the test counts.

## Tests

- `chunkLoadRecovery.test.ts` (12 → 17): the reload starts once and is remembered, nothing starts when the guard refuses, and the four views.
- `RouteChunkBoundary.render.test.tsx` (new, 6): the page; a lost chunk reloads once and reads *Updating app…*; a spent guard offers Reload and Fix app and does not reload by itself; another error offers Reload; a cancelled preload's TypeError reads *Updating app…* while the reload is on its way; a route change clears a caught error.
- `lazyRouteBoundaries.test.ts` (17 → 22): the real `src/App.tsx` keeps `<Routes>` inside the boundary, and the reader on made-up snippets.

## Tried

A stand-in for GitHub Pages (a file is 200, anything else is `404.html` with status 404, swapping the folder is a deploy), two builds with a change between, headless Chromium signed in with a `/dev-login` session, the ZZ1 cage's code.

- **Dev server, no service worker:** the scan lands on cage ZZ1. No fault.
- **One tab, the scan is the first load after the deploy:** the old build opens the cage from the worker's cache, the new worker installs, and the first-paint reload brings the new build. No empty page.
- **A second tab takes the update while the scan's tab opens** (before the fix): the box chunk 404s at `/b/:code`, or the Tally's chunks and the bill window's at `/tally`. Ending 1 each time, the page empty until the reload landed.
- **The same with the one-shot reload spent** (before the fix): ending 2 at `/b/b365b514?preview=1`, `#root` empty for the 20 seconds watched.
- **After the fix, the same two walks:** the boundary catches the TypeError (`RouteChunkBoundary caught:` in the console) and the reload brings the cage; with the reload spent, the page reads *This page could not load* with Reload and Fix app, four timings out of four.

## Not covered

- **Whether this is what happened on 2026-11-10 is not proven.** The address had lost `job` and `container`, so the Tally had drawn and read its jobs before the page went empty. That fits a reload that restored `/tally?tab=on-site` and a slow boot behind it. The first load's console would say: a `Failed to fetch dynamically imported module` line, or `RouteChunkBoundary caught:` from now on.
- **The Tally drops `job` and `container` on purpose** once its jobs are read (`JobTally.tsx`, punch list #209), so a reload after that reopens On site without the cage. The one-tab walk showed it: the first-paint reload landed on `/tally?tab=on-site` with no box open. Not fixed here.
- **`#root` is still empty while the app boots.** After a recovery reload that is the whole bundle from the network. `index.html` draws nothing until React does.
