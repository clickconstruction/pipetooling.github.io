# v2.2237 — fix(jobs): Sub Labor ledger names Click-numbered jobs (2026-08-24)

A sub labor sheet on a **click-only job** (empty `hcp_number`, e.g. C977
"Springtown") rendered a bare "977" in the Sub Labor ledger while HCP-numbered
rows read "880 | Reliant Health- HVAC". The `get_jobs_ledger_by_hcp_numbers`
RPC deliberately resolves click-only jobs (migration `20260619140000`) and
returns `click_number` for exactly this purpose, but `useSubLaborLedger`'s
name-map builder keyed rows by `hcp_number` alone — empty for those jobs, so
their names were silently dropped. Same bug class PeopleReviewTab fixed for
its own map (its `mapLedgerNumbers` comment).

- New kernel **`src/lib/subLaborLedgerNames.ts`** (`buildLaborJobNamesByNumber`,
  unit-tested): keys the number → name map by both `hcp_number` and
  `click_number`, trimmed/lowercased, first resolution of a duplicate wins,
  empty names skipped.
- `useSubLaborLedger` uses it for `laborJobNamesByHcp` — fixes the ledger row
  display ("977 | Springtown") and, since `subLaborOutstanding`'s search reads
  the same map, searching those sheets by job name now matches too.
