# v2.4216 — Draft Payroll: making one person’s report no longer opens a new tab (2026-09-30)

The owner's ask (2026-09-30): on People → Pay, drafting a report opened the finished pay report in a new browser tab every time. That preview was the only thing the per-person **Report** button did differently from **Generate Remaining** and the catch-up rows, which had passed `openPreview: false` since v2.2034.

- `generatePayStub` in `src/pages/People.tsx` no longer builds the report HTML or calls `openPayStubWindow`; the `openPreview` option and the wage read that fed the preview are gone, so all three callers behave the same. After `loadPayStubs()` a success toast names the person and points at View / Record payment.
- The stored report is unchanged: `generatePayStubRecord` still writes the stub and its day rows. The Draft Payroll modal's **View** and the Ledger's View / Print are unchanged.
- Help: *run the pay week* says Report makes one person's and that nothing opens on its own.

No migration, no edge function.
