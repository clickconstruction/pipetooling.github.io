# v2.2988 — Takeoffs: the cost-estimate materials total honours the bid version; New 1's Enter yields to dialogs and buttons (2026-09-07)

Two findings from the 2026-09-07 live walkthrough of the Old / New 1 / New 2 parallel run (`docs/TAKEOFFS_REFRESH_PLAN.md`) on B398 (Combined, two versions). Client only — no migration, no edge function.

## The materials total ignored bid versions

- **Symptom**: B398's Takeoffs **Materials** summary said $31,396.71 while the coverage strip, the New 2 rail and Pricing all said $25,787.29 (the base version; Pricing's "−$445.30 vs base" alternate is $25,341.99).
- **Cause**: the cost-estimate load in [`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts) read `bids_takeoff_rough_part_lines` with only `.eq('bid_id')`, while the count rows it multiplies by went through `applyVersionFilter`. The alternate version's lines survive the read, miss the count lookup, and get summed at ×1 — on B398 that is the extra $5,609.42. The same state (`costEstimateMaterialTotalRoughIn`) is the `materialTotalRoughIn` the Labor tab hands to the printed cost estimate, so a multi-version bid printed the wrong materials figure. The pricing-path read, Pricing's per-version alternates query and `costEstimatePage.ts` were already filtered. Introduced with the count multiplier (#53), before bid versions existed.
- **Fix**: the read goes through `applyVersionFilter(…, activeVersionIdForBid(bidId))` like its three siblings. No other behaviour changes.

## Enter in New 1 swallowed the dialog's Enter

- **Symptom**: `TakeoffFocusView`'s window `keydown` treated Enter as **Done · next uncosted** whenever the target was not an input. The remove-line confirm auto-focuses **Delete** and says "press Space or Enter to remove the line" — Enter there was `preventDefault`-ed and moved to the next fixture (running Remember if ticked) instead of removing the line. Any focused button (rail items, Apply, Use these lines, the sheet's role=button cells) had the same double-action.
- **Fix**: new kernel predicate `focusShortcutApplies(target, key)` in [`takeoffFocus.ts`](../../src/lib/bids/takeoffFocus.ts) (+4 tests): nothing applies inside a `[role=dialog]` / `[role=alertdialog]` or on a typing target; Enter additionally stays with a focused `button`, `a[href]` or `[role=button]`; arrows still move the rail from a focused rail item. `isTypingTarget` is unchanged. The help guide `cost-a-takeoff-one-fixture-at-a-time` says so.

## Verify

B398 → Takeoffs → scroll to **Materials**: the total reads $25,787.29 (was $31,396.71) and equals the strip. New 1 → a line's trash icon → Enter removes the line (Cancel / Escape still work); Enter on the page body with nothing focused still advances; ↑/↓ from a focused rail item still move.
