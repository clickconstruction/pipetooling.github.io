# v2.2105 — The Call queue: Followup as one list (2026-08-22)

Stage 2 of the Followup one-queue direction (owner-approved mockup, iterated
three times: colored badges → plain table → card-with-mini-table + clickable
rows). Parallel-run per the Pricing Old/New precedent: the new lens ships
FIRST in the Followup toggle with a "new" chip; the four old lenses sit after
an "Old:" divider, untouched.

- **Kernel `src/lib/bids/callQueue.ts`** (+6 tests): groups bids by builder,
  computes the collect list — chase todo (via `bidNeedsChase`), reasons todo
  (lost without structured category), tab-gettable (any lost bid without a
  tab, or pending sent ≥ `TAB_GETTABLE_AFTER_DAYS` = 21) — plus done counts
  (fresh/recorded), relationship stats (W/L/pending, hit rate, pending $),
  and totals for the header. Sort: builders with work first, oldest contact
  first (never-contacted before everyone), name tiebreak. Builders with
  nothing decided or in flight stay off the queue.
- **`BidsCallQueueTab.tsx`** (+4 render smokes): summary header, search,
  filter chips (All / To chase / Need a reason / Tab gettable), builder cards
  with the fixed three-row **To do / Done** table. Rows drop open in place:
  Chase → pending bids with the six chase chips (Lost… flips to the reason
  chips, Bid tab received opens the capture panel; entry + last_contact via
  `buildPendingChaseActionWrites`, same as Waiting to hear); Loss reasons →
  `BidLossCategoryChips` with note + suggestion (patch-only, like Why we
  lost); Bid tabs → capture panel per gettable bid plus the RECORDED list
  with edit. 📞 Start call deep-links to the builder card (full session).
- **Bids.tsx**: `call-queue` tab key (superintendent-gated like the other
  followup lenses), sub-nav "Call queue (new) | Old: …", caption line.
- **Floaty picker**: `call-queue` joins the Followup section of
  `EGG_BIDS_TABS`.
- Not in v1 (documented): per-GC recipient copies (the queue groups by
  primary customer), promise-date ordering (`customer_followup_prefs` —
  the By builder lens still owns that), opening the call session directly
  from the queue (deep-links to the builder card instead).
