# v2.2455 — Convert: type-ahead prospect picker (2026-08-28)

Third slice of the Prospects-refresh arc (after v2.2452/v2.2453). The Convert tab opened with a flat native `<select>` of every prospect in cache order — 268 unordered options, test rows included.

- **New kernel [`src/lib/prospects/convertProspectSearch.ts`](../../src/lib/prospects/convertProspectSearch.ts)** (+8 tests): `searchConvertProspects` (blank query → `[]`; ranks company-prefix > company-substring > contact/email/phone substring; excludes `prospect_fit_status === 'converted'`; limit 8) and `suggestRecentlyAnswered` (active prospects whose latest call is an `answered` within 30 days, newest first, limit 5 — fed by v2.2453's `prospectLastCallMap`).
- **[`Prospects.tsx`](../../src/pages/Prospects.tsx)** Convert tab: the `<select>` becomes a `type="search"` input (same `convertSelect` class). Results render beneath with company, contact, and a context line (`lastTouchLabel` + phone); Enter picks the top hit; picking sets `convertProspectId` and clears the query. With the box empty and nothing picked, "Suggested — answered in the last 30 days" chips render. The `?tab=convert` default-to-`currentProspect` effect is unchanged, so arriving from Follow Up still pre-selects that prospect.
- The picker pool is the same union as before (`prospectListProspects` ∪ `followUpProspects`); the map/loader came in v2.2453 (`loadProspectListProspects` runs for the Convert tab too).
