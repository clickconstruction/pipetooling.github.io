## (b) Offline recovery

**Kernel** — `src/lib/offlineRecoveryState.ts`: `offlineRecoveryState({ online, lastError, attempts, idempotent?, reconnected? })` → `{ phase: 'idle' | 'offline' | 'back-online' | 'failed', message, showRetry, retryLabel, autoRetry }`.

| Input | Phase | Rendered |
| --- | --- | --- |
| no error | `idle` | nothing |
| `lastError.kind !== 'network'` (refusal, broken link, timeout, unknown) | `failed` | the failure's own sentence, **no Retry** |
| network failure, no `online` event since | `offline` | `OFFLINE_ERROR_MESSAGE` (+ " Still no connection." after a failed retry) + **Retry** |
| network failure, `online` event arrived | `back-online` | "Back online — tap Retry to try again." + Retry; for `idempotent` actions under `OFFLINE_AUTO_RETRY_CAP` (3): "Back online — trying again…" and `autoRetry: true` |

The browser flag only ever proves offline — a fetch that fails while `navigator.onLine` says true (dead wifi, unreachable server) stays in `offline` until an actual `online` **event**, so the "Back online" copy never lies. `recoveryFailureFromError(error, fallback, message?)` builds `lastError` from a thrown value: class from the new `errorKindOf(error)` (`src/utils/errorHandling.ts` — `DatabaseError.kind`, fetch-layer `TypeError` → network, coded object → server, `OperationTimeoutError` → unknown), sentence from `formatErrorMessage` (or `formatPostgrestOrUnknownError` for a plain PostgrestError object from a direct `supabase.from().insert()`). The optional `message` keeps the clock punch's "may or may not have saved" timeout copy.

**Hook** — `src/hooks/useOnlineStatus.ts`: `navigator.onLine` kept live by `online` / `offline` window events.

**Component** — `src/components/OfflineRetryPanel.tsx` `{ failure, onRetry, surface, idempotent?, busy?, style?, messageStyle? }`: renders the sentence as the old `<p>` did; adds the Retry button for network failures; listens for `online` and auto-fires **once per event** (ref-deduped) for idempotent actions; hides the button while `busy`. Telemetry: `recordNavClick(user, role, 'offline_retry_clicked', '#<surface>:tap' | '#<surface>:auto')` on `ui_nav_clicks`.

**Surfaces wired** (Retry re-invokes the exact handler that failed):

| Surface | File | Idempotent |
| --- | --- | --- |
| Dispatch Mode / Job Mode → Schedule agenda (the J2-F3 site) | `DispatchModeSchedule.tsx` (`loadDay`); `fetchDispatchModeDayBlocks` now also returns `errorKind` | **yes** — refetches on `online` |
| Clock In modal | `ClockInOutButton.tsx` (`clockInFailure` → `handleCompleteClockIn`); the old `includes('network') \|\| includes('fetch')` text check on the formatted message is gone (the #6a follow-up note) | no |
| Clock Out review | `ClockInOutButton.tsx` (`clockOutReviewFailure` → `handleCompleteClockOutReview`) | no |
| Leave a report (job picker) | `NewReportModal.tsx` (`submitFailure` → `submitReport()`, split out of the form `handleSubmit`) | no |
| Leave a report (per-job / clock-out missing-reports) | `AdditionalReportModal.tsx` (same split) | no |

Report saves also gain class-based copy: a refused insert reads "You don't have permission to …" instead of the raw PostgREST message. Photo upload was **not** wired — no crew-surface photo upload renders the offline copy today.
