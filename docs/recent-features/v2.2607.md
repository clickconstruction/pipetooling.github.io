# v2.2607 — Division 22 audit: section picker z-index fix (2026-09-01)

Owner-reported on prod minutes after v2.2598 deployed: clicking
"pick a section…" in the audit modal appeared to do nothing. The
SearchableSelect portals its dropdown at default z-index 1100; the audit
modal's overlay sits at 10050, so the listbox opened *behind* the modal
— present in the DOM (which is why the pre-ship DOM-driven test passed:
`element.click()` bypasses visual hit-testing) but invisible and
unclickable for a human. Reproduced with `document.elementFromPoint`
over the listbox (hit the modal's H2), fixed with the component's own
escape hatch (`portalZIndex={MODAL_Z + 10}` — the ScheduleDayEmailModal
/ PartFormModal pattern), re-verified by hit-test + screenshot.

Testing lesson for the file: modal + portaled-dropdown combinations need
a visual/hit-test check, not just DOM assertions.
