# v2.8524 — Bills sent: By day paid no longer names deposits from before Accounts Receivable's start date (2026-11-24)

A fault of v2.8493 (punch list #422), found on the live look the same day. No migration, no edge function.

## What was wrong

v2.8493 named, under a picked day, the bank deposits that landed that day and are on no bill yet. It asked the bank from the first day of the month on the screen. The org's deposit filter also holds a start date, the day the Accounts Receivable window starts its own list, and the read passed the month's first day in its place.

By day paid opens any month. A month from before that start date holds the deposits from before the office began matching deposits in the app. None of them is on a bill in the app, and Accounts Receivable lists none of them. So an old day read like *5 deposits landed that are on no bill yet*, and **Open deposits** led to a list without them.

The Dashboard's Money in bar reads the last two weeks only, so it never reached that far back. The fault was By day paid's alone.

## What changed

- `moneyInDepositsReadFrom` (`moneyInDeposits.ts`): the first day to ask the bank from is the day asked for, or the org's start date when that is later.
- `readPostedDepositRows` (`moneyInDepositsLoad.ts`) passes that day. It is the shared read, so Money in obeys the start date too. For Money in nothing changes unless the start date is set inside its two weeks.
- `readDepositsOnNoBill` (`billsPaidIo.ts`) answers *unread* when the org's deposit setting does not read. Without the setting there is no filter and no start date, and a count would name deposits Accounts Receivable hides. The line then says *The bank deposits did not read.*
- The guide says the line names only deposits Accounts Receivable lists.

## What the live look found

On the live site, 2026-11-24, look only:

- The line draws under a day's facts at desk width, two rows, inside the day's box, with **Open deposits**.
- With the bank's read made to fail in the browser, the line said *The bank deposits did not read. A deposit that is on no bill yet is not shown.* The day kept its figure and its payments, and no failure panel showed.
- The days this week that had the line in the morning had none by the afternoon. Their payment counts had gone up, so the deposits had been put on bills.
- An old month named deposits from before the start date. That is this fault.

## The 150-day limit of v2.8493, measured

v2.8493 noted that on a day older than about 150 days a deposit a typed-in payment carries can read as on no bill, since the typed-in payments are read back 180 days. Read through the dev seat on 2026-11-24 with the org's filter: no deposit from the last 150 days is still unapplied, and none from the start date on is. With this fix no deposit from before the start date is named. So the limit touches no deposit today.

It would take a deposit left unapplied for five months, which Accounts Receivable itself lists the whole time. Widening the typed-in payments' read is a change to a database function, and it is not built.
