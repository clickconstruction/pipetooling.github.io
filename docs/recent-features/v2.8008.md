# v2.8008 — Document builder: a job's insurance sheet opens by a link (2026-11-19)

Punch list #404, step 4 of ten: the sheet's link. One new edge function, `document-builder-link`, and one new public page, `/d/<code>`. No migration: `document_builder_links` came in v2.7988 and is pushed.

**Deploy**: `supabase functions deploy document-builder-link` from `main`, after the merge. Until the function is up, the card on a published sheet shows the reason its read failed, and nothing else changes.

## What changed

- A published job's sheet shows a card, **This sheet's link**. **Switch the link on** makes a link, and the card then shows its address with **Copy the link**, **Make a new link** and **Switch the link off**.
- The link opens `/d/<code>` with no sign-in: the sheet as published, with its revision and the job's name at its foot. It is a second way in for someone with no page of their own, a sub's insurance agent say.
- The page never shows a draft. A publish changes what the same link shows.
- **Make a new link** stops the old one, after a confirm that says so. **Switch the link off** closes the sheet to links until it is switched on, which makes a new link.
- A wrong code, a link switched off and a link a new one replaced all read the same on the page: *This link is no longer open. Ask for a new one.* Nothing tells them apart.
- The card says when the link was made and how often someone outside opened it. A signed-in teammate's look and a preview are not counted (`publicViewDecision`).
- The page stands outside the app's frame: its own `Suspense`, a light page under `data-theme="light"`, its own print rules, and a retry when the signal is lost.
- `/d/sample` draws a made-up sheet with no call to the function, for *What customers see*. The page is a step of the sub's journey there, **The insurance sheet's link**.

## How a link is kept

Only the SHA-256 of a link's code is in the database. The row also keeps a random nonce. The code is an HMAC of the row's id and nonce under a secret the function holds (`DOCUMENT_BUILDER_LINK_SECRET`, or the service role key when that is not set), written as sixteen letters of `23456789abcdefghjkmnpqrstuvwxyz`. So the function can show a dev the same link on another day, and a copy of the database alone opens nothing.

One live link a sheet, held by a unique index. Nobody signed in writes the table: the function does, with the service role, after it has checked the caller is a dev who is not archived, not in training and not a twin.
