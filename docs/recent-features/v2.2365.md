# v2.2365 — Copy a version into another GC's packet (2026-08-26)

Estimator request: "need ability to copy versions between GC categories." The
Send-to strip's "+ version" button created the copy from whichever version was
*selected anywhere on the bid* — invisible, uncontrollable, and often another
GC's packet (the pricing checkbox would name the other GC's scenario with no
explanation). `create_bid_version` always accepted any source; the UI just
never asked.

- **`BidVersionPicker.tsx`** — the "Another version" modal (split bids) gains a
  **Start from** select listing every version labeled by its GC packet, the same
  labeling as ＋ Add GC's picker (`GC · version · ★ scenario / no prices`), with
  the "copies its counts, takeoff and prices" helper. The RPC call now passes the
  chosen source (`p_source_bid_version_id`) and derives the pricing clone from
  that source's ★ (falling back to the active facet when the source is the
  selected version — exactly `submitAddGc`'s derivation). Picking a cross-GC
  source pre-fills the Name field from the source until the user types
  (`newNameTouched`). The pricing checkbox reads "Start its prices from the
  source's ★ — X stays named X" off the chosen source.
- **`gcPackets.ts`** — new pure kernel `defaultCopySourceId(versions, gcId,
  selectedId)`: the modal defaults to the destination packet's own version
  (selected-if-in-packet → packet's ★ version → packet's first by sort order),
  falling back to the bid-wide selection only for an empty packet. This also
  fixes the silent cross-GC clone: "+ version" on packet A no longer copies
  packet B's version just because B was selected. Unit tests in
  `gcPackets.test.ts`.
- Unsplit bids are unchanged (no select; the split modal keeps its flow).
- Help guide `bid-one-project-to-multiple-gcs.md` documents the new picker.

No migration, no edge function.
