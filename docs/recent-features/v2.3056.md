# v2.3056 — Test-gap audit, pass 61: the jobs_ledger embed lists get a parity guard, and Split Bill now voids under the bill's recorded Stripe mode (2026-09-07)

Pass 61 of the test-gap audit. One kernel fix (an additive select column) plus tests; no client, migration or edge-function change.

## Why this one

`jobsLedgerEmbedSelects.ts` holds the explicit child-column lists under every Stages list and job-detail fetch. It avoids `(*)` on child tables on purpose: a new DB column is not pulled until someone opts in. But `JobWithDetails` types each embedded child as the full DB Row, so a column the embed leaves out is simply `undefined` at runtime with no type error anywhere. Nothing checked that gap.

## What the tests found

**A real defect.** The Split Bill modal (v2.1520) voids the current Stripe bill "under the row's recorded mode, else the role default" — but its invoice comes from the job form's embedded rows, and the invoices embed never carried `stripe_mode` (recorded on every invoice since v2.1114). The row-first branch was dead: every split voided under the role default. For most people that is `live` and correct; a dev whose device pref had flipped since the bill was made, or an org default change, would void against the wrong Stripe account and the split would fail at step one.

- **Fix:** `stripe_mode` added to `JOBS_LEDGER_INVOICES_EMBED`. Additive, one small column on invoice rows in both the list and detail selects; the modal's existing branch now sees the value.

Contracts now pinned that were only implied:

- Each embed is exactly its sorted, deduplicated column list; no child uses `(*)`. Every embedded name is checked against the DB Row type at compile time, and every column *not* embedded must be listed in the test as a deliberate omission — a new column on any of the five child tables fails `tsc` until someone decides whether the app should read it. Today's deliberate omissions: the three write-down audit columns on invoices (only the Dashboard billing units read them, through their own select) and `source_bid_id` on materials.
- The Stages list select embeds invoices, payments and team members plus the lean lookups, and never materials or fixtures (those are batch-loaded); the detail select adds them, the newest-report meta and the bid's own GC; the list's children are a strict subset of the detail's.

## What shipped

- **`jobsLedgerEmbedSelects.ts`** — `stripe_mode` in the invoices embed, with a comment pointing at the modal that needs it.
- **`jobsLedgerEmbedSelects.test.ts`** (5) — the column lists as `as const satisfies keyof Row` tuples with `Exclude<…>`-is-never coverage types, plus the two select builders parsed back into their embeds.
