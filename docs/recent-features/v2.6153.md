# v2.6153 — What everyone sees draws every training lesson with a drawing (2026-10-30)

Punch list #194, the follow-up v2.6137 (#6529) named: no lesson was in the lens's catalog. The catalog (`lensScreens` in `src/lib/lens/lensTab.ts`) is the door index read through each role's gates. Its one training door, the dev's *Read a course that is off* (`page-training-preview` in `src/lib/settings/devDoors.ts`), opened `/training/osha-30`, a slug no course has, so its frame could only say *No course is named osha-30*. No door opens a lesson (`?lesson=<key>`), so Settings → What everyone sees's Check every screen and the #194 headless sweep had never drawn a training figure, the app's densest drawings: 84 of the 90 lessons carry one, 128 figure lines in all.

## What changed

- **The door's link.** *Read a course that is off* opens `/training/osha-30-refresher`. `devDoors.test.ts` now holds every dev door into `/training/<slug>` to a course folder with a `course.md`; the route check let the old slug through, since `/training/:slug` matched it.
- **A course that is off** (`Training.tsx`) is one with no `training_courses` row or with `enabled` off. Anyone signed in reads a course that is on; a dev alone reads one that is off, as a preview under a *Preview · switched off* chip. On prod all three courses are on (read 2026-10-30), so the door opens a course anyone can read today. The lens's world holds no `training_courses` row, so there every course is off.
- **The lessons enter the catalog behind that door, not as doors of their own.** `lensScreens(role, sources)` takes the courses as a source (`LensSources`), the way `doorsFor` takes the guides and the punch list, because they live in the Vite-only `courseRegistry`. A role that holds the course preview door gets `lessonScreens(courses)` after its doors: each lesson whose Must know or Traps list holds a figure line, at its own door `/training/<slug>?lesson=<key>`, labelled *<course> · Lesson N · <title>*, kind `lesson`. Today that is the dev alone: 264 screens after the dedupe, the door index's 180 and 84 lessons (30 electrical, 30 plumbing, 24 of OSHA's 30). Every other role's list is unchanged, so the whole catalog reads 851 screens where it read 767.
- **Why not doors.** The door index has other readers. A door per lesson would put 84 rows in the header's Go anywhere box, and its gate would be everyone's, since the courses are on in prod; every role's sheet would then draw each figure nine times, eight of them as *not on yet* in the lens's world. A door per course has the same reach and draws one lesson per course. The door index, global search, the Dev doors card, `docs/twins/APP_DIRECTORY.md` (which already lists the three course pages) and the lens's role lists are unchanged.
- **The tab** (`SettingsWhatEveryoneSeesTab`) loads `courseRegistry` with an `import()` on mount, as Settings → Training does, so the lesson text (its own 360 KB chunk in the build) never rides in the Settings chunk. Where groups the lessons under **Lessons**, Every screen draws them after the doors, and a failed load reads *The lessons did not load: <reason>* on the dev's count line.
- **The headless sweep's `screens.ts`** (in #194's scripts folder) hands in `TRAINING_COURSES` the same way, so its dev list ends with the lessons; on a tree before this version the extra argument is ignored.
