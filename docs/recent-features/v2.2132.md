# v2.2132 — Versions own their counts (2026-08-23)

F6a of the "Send or Compare" train (decision D7a; plan: claude.ai/code/artifact/7610faf4-e0ff-4d39-b42c-1c2b18748cb9 "Jakes as One Bid"). Until now `bids_count_rows` had no version column: every version of a bid shared one count list, so "a version is a separate bid you can send" was only true for takeoff mappings, rough-in, prices and GC — and adopting an existing bid (its own counts) as a version was impossible.

**Migration `20260823034820_count_rows_per_version.sql`**
- `bids_count_rows.bid_version_id uuid NULL → bid_versions (ON DELETE CASCADE)` + index `(bid_id, bid_version_id)`. NULL = the unsplit bid's rows; V = version V's own rows (same convention as `bids_takeoff_template_mappings`).
- New helper RPC `clone_count_rows_to_bid_version(p_bid_id, p_source_bid_version_id | NULL, p_target_bid_version_id)` — clones the source rows onto the target version and **re-keys the target version's children** that point at `count_row_id`: takeoff mappings, rough-in lines (version-scoped), and the target version's price scenarios' custom prices / submission hides / assignments (pricing-scoped via `price_book_versions.bid_version_id`). Returns the row count.
- **Backfill for already-split bids** (11 in prod): the shared NULL rows become the **first** version's rows (lowest `sort_order`); every other version gets its own clone + re-key. Nothing deleted.
- `materialize_bid_version` (first split) now stamps the unsplit count rows onto the base version (and that version's ★ from the bid's saved ★). `create_bid_version` clones counts from the source version and re-keys the new version's mappings / rough-in / price-clone children (runs after the pricing clone so its custom prices etc. re-key too).

**Client**
- `useBidPricingEngine`: every count loader (`loadCountRows`, `loadTakeoffCountRows`, `loadCostEstimateCountRows`, the rough-in `crsForCount`, the pricing loader) goes through `applyVersionFilter(…, activeVersionIdForBid(bidId))`. The Counts effect resolves the bid's active version before loading and re-runs on a version switch.
- Counts tab: `BidVersionPicker` renders above it (`Bids.tsx`), `BidsCountsTab` gets `activeBidVersionId` — inserts (`NewCountRow`, quick add / import `insertCountRows`) stamp `bid_version_id`; "clear all" clears only the active version's rows.
- Cover Letter (New + Old bundles): the bid's rows are fetched once and grouped by version; **each section is priced on its own version's counts** (`rowsFor(bidVersionId)`), not the active one's.
- `approvalPdf.ts`: the three count reads follow the bid's active version. `send-bid-pricing-package` edge function: counts follow the scenario's `bid_version_id` (**deploy after merge**). `Documents.tsx`: per bid, shows the active version's rows (saved choice → first version → unsplit).
- Types: `bids_count_rows.bid_version_id` hand-added pending `gen-types:linked`.

**What did not change:** labor, cost estimates and POs stay bid-wide (the structure bar says so). The Jakes adopt-a-bid flow is F6b.

Verified live (after `db push`) on BP329 — backfill, per-version rows on Counts / Takeoff / Pricing, Cover Letter sections on their own counts — see the PR. Help: `price-a-bid-with-the-workbench.md`, GLOSSARY, BIDS_SYSTEM, EDGE_FUNCTIONS.
