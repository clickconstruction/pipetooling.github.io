# v2.3499 — The tip strip clears itself, plus the types regen after the RPC push (2026-09-16)

## The strip stayed up until the page was reloaded

Caught on the first live pass, recording the real $50 on job 960. The write was correct — `Tip` line, revenue 1805.70 → 1855.70, a job-level payment dated to the deposit's posted day — but the modal kept showing *1 deposit to match · $50.00 unapplied* and the strip stayed offering a tip that had already been recorded. A reload showed the truth: *No matching transactions*.

Cause: `addTipLine` called only `onApplied()`, and on `/accounts-receivable` that callback refetches the **jobs** list for the billed rows ([`JobsAccountsReceivable.tsx:27`](../../src/pages/JobsAccountsReceivable.tsx)) — it never touches the deposits. The modal owns that list itself through `refreshList()`, which the normal Apply path reaches via `finishApply`. The tip path skipped it. It now awaits both, and the deposit's remainder reads zero and it leaves *To match* without a reload.

Worth carrying forward: in this modal, a write that changes a deposit's remainder has to refresh **both** — the caller's jobs and the modal's own candidates.

## Types regenerated after the push

Following v2.3496's `supabase db push`. `npm run gen-types:linked` replaced the hand-carried type for `record_job_tip_from_deposit` in [`src/types/database.ts`](../../src/types/database.ts) with the generated one; **migration drift is clean at 589/589**.

The generated signature is stricter than the placeholder: the optional arguments come back as `p_note?: string` and `p_payment_type?: string`, not `string | null`. The call in [`BankPaymentsModal.tsx`](../../src/components/jobs/BankPaymentsModal.tsx) was passing `null` for both, which typechecked against the hand-written stand-in and failed against the real one. It now passes `undefined`, which is what an omitted PostgREST argument means and what makes the function fall back to its own defaults — for the note, the `'Tip — paid over the bills on this deposit'` sentence written in the migration.

Worth remembering for the next hand-carried RPC type: write optionals as `p_x?: string`, not `p_x?: string | null`, so the interim type matches what the generator will produce and the regen commit stays a no-op at the call sites.
