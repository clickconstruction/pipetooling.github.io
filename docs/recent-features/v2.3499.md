# v2.3499 — Types regenerated after the tip RPC, and the call site tightened (2026-09-16)

Chore following v2.3496's `supabase db push`. `npm run gen-types:linked` replaced the hand-carried type for `record_job_tip_from_deposit` in [`src/types/database.ts`](../../src/types/database.ts) with the generated one; **migration drift is clean at 589/589**.

The generated signature is stricter than the placeholder: the optional arguments come back as `p_note?: string` and `p_payment_type?: string`, not `string | null`. The call in [`BankPaymentsModal.tsx`](../../src/components/jobs/BankPaymentsModal.tsx) was passing `null` for both, which typechecked against the hand-written stand-in and failed against the real one. It now passes `undefined`, which is what an omitted PostgREST argument means and what makes the function fall back to its own defaults — for the note, the `'Tip — paid over the bills on this deposit'` sentence written in the migration.

Worth remembering for the next hand-carried RPC type: write optionals as `p_x?: string`, not `p_x?: string | null`, so the interim type matches what the generator will produce and the regen commit stays a no-op at the call sites.
