# v2.8550 — The merge queue says what each change is doing (2026-11-24)

Punch list #444, PR 4 of four. The owner's ask of 2026-11-24 named, for each change in the merge queue, *whether its checks are running or it is ready*. GitHub gives every entry of the queue one of five states, and `ship-pace` read four facts an entry; the state is a fifth on the same query. One edge function changes and is redeployed after the merge. No migration, no new secret.

## What changed

- **The read** (`supabase/functions/ship-pace/index.ts`): the queue's GraphQL query asks each entry for `state` (`MergeQueueEntryState`), and `readQueue` hands it on as `PaceQueueEntryInput.state`.
- **The kernel** (`supabase/functions/_shared/shipPace.ts`): `PACE_QUEUE_STATES` and `PaceQueueState` (`AWAITING_CHECKS`, `MERGEABLE`, `QUEUED`, `LOCKED`, `UNMERGEABLE`). `paceQueue` keeps the state on each entry through `queueStateOf`, null for no word or one this build does not know. `queueStateWords` says it: *Checks running* (the queue is building it), *Ready* (its checks passed and it waits on the ones ahead), *Waiting its turn* (not yet built), *Merging now*, *Will not merge* (GitHub is about to drop it). `queueStateTone` sorts the five into running, ready, waiting and stopped. `queueLineWords` says a state after the place: *3rd in line, checks running, in the queue 25 minutes, about 12 minutes to go*.
- **`/punch-list`** (`PunchListQueue.tsx`, `punchListQueue.ts`): a **State** column between the title and **In the queue**, each state a chip: blue for *Checks running*, since it is the usual state and amber would read as a warning; green for *Ready* and *Merging now*; grey for *Waiting its turn*; red for *Will not merge*. On a phone the chip sits under the title.
- **Settings → How fast a change ships**: **In line now** says the state in each line's words, through `queueLineWords`.
- **A row written before the redeploy** has no state on its entries. `parseShipPacePicture` reads it as before, the punch list draws no State column (`rowsHaveState`) and the Settings line reads as it did. So the client can deploy before the function with nothing missing.
