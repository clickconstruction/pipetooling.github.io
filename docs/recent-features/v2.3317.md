# v2.3317 — Payroll views renamed: "Pay reports" → Pay run, "Ledger" → Balances (2026-09-11)

Client only — labels and docs, no behavior change, no migration. Owner's call after asking what each view's primary function is: the two views under People → Pay → **Payroll** solve overlapping problems differently, and their names should say the job rather than the artifact.

## The distinction the names encode

| View | Question it answers | Unit · verb · clock |
|---|---|---|
| **Pay run** (was Pay reports) | What do we have to pay this week, and did we pay it? Draft Payroll, the table of reports with Record payment, the amber "N upcoming" link. | pay report · pay · the week |
| **Balances** (was Ledger) | Where does each person stand with us? One running balance per person from earned − paid out − charges + credits, including back-charges and credits that never sit on a report. | person · reconcile · all time |

"Pay report" stays the canonical name of the document (v2.1251–v2.1260 naming audit); only the view names change. "Payroll" was not reused because it names the parent sub-tab. "Ledger" was retired because it names a data structure and is already used by the partner, vehicle, Estimates and Banking ledgers.

## What changed

- [`People.tsx`](../../src/pages/People.tsx): the `Payroll view` tablist reads **Pay run | Balances**. The state keys (`'reports' | 'ledger'`) and the deep-link (`?view=ledger&person=<name>`) are unchanged so saved links keep working.
- [`PeoplePayStubsTab.tsx`](../../src/components/people/PeoplePayStubsTab.tsx): page heading **Pay run**. [`PeoplePayLedgerView.tsx`](../../src/components/people/PeoplePayLedgerView.tsx): page heading **Balances**.
- Help: `see-what-we-owe-each-person.md` (the two-views intro + keywords) and `catch-up-on-unreported-payroll-weeks.md` (its two "Ledger"/"Pay reports" references meant the Pay run table). `GLOSSARY.md` gains both terms; `PEOPLE_TABS_ARCHITECTURE.md` and `ACCESS_CONTROL.md` updated where they name the switch.

## Not changed

Component and file names (`PeoplePayLedgerView`, `payrollView`, `ledgerFilteredPayStubs`, …) keep their code names — a rename sweep of those would touch the hot `People.tsx` seam for no user-visible gain.
