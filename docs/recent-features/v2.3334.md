# v2.3334 — Robot Board: "Paste the plans" opens Edit bid on the Job Plans field, one click (2026-09-11)

Client only — no migration, no edge function. The first of the loose ends left after the v2.3225 Robot Board train ("Paste the plans is two clicks, not one … the Edit form has no way to open focused on the Job Plans field the way it can for the bid value").

## Why

The Robot Board's amber `needs` rows are the bids that most need a person, and on 2026-09-10 seven of the ten Unsent rows were *No plans link*. Their door opened the robot needs sheet, whose only useful control for that gap was **Edit bid**, which opened the form at the top with Job Plans below the fold. The form already knew how to land on a field for **Add bid value** (v2.3225); the plans field had an id but no focus key.

## What shipped

- **Kernel [`bidFormFocus.ts`](../../src/lib/bids/bidFormFocus.ts)** (+4 tests): `BidFormFocus` names the six fields the Edit bid form can land on and `BID_FORM_FOCUS_ELEMENT_ID` maps each to its input id (`bid-form-plans-link`, `bid-form-service-type`, `bid-form-bid-due-date` join the three that existed). `focusForRobotGap(key)` is the field a robot gap is fixed on (plans / unreadable → Job Plans, gc, service type, due date; distance has none — it fills itself on save). `needsDoorFor(need)` decides the mirror door: a `plans` gap with no open questions → `edit-bid` on Job Plans; everything else → the needs sheet, which has the intake address and the taps.
- **`Bids.tsx`**: `openEditBid`'s `focus` option and the focus effect now take the kernel's union and id map; the ring is still the shared `landOnElement` (v2.3228). The landing gains a **settle pass**: 600 ms after the ring, an instant `scrollIntoView` to the same spot — a no-op when the smooth landing already got there, and the only scroll that runs at all in a hidden document (Chrome skips smooth scrolling there, which is how the Browser pane walk exposed it). The mirror gets `onPasteThePlans` → `openEditBid(bid, { focus: 'plansLink' })`; the needs sheet's `onEditBid` forwards its focus.
- **[`BidsRobotMirrorTab.tsx`](../../src/components/bids/BidsRobotMirrorTab.tsx)** (+1 render smoke): the `needs` door calls `onPasteThePlans` when `needsDoorFor` says `edit-bid` and the page offers it (title *Opens Edit bid on the Job Plans field*), else `onOpenNeeds` as before. Label unchanged: **Paste the plans →**. Without the new prop the tab behaves as v2.3225.
- **[`RobotNeedsSheet.tsx`](../../src/components/bids/RobotNeedsSheet.tsx)** (+1 render smoke): every **Edit bid** lands somewhere — the per-gap button on that gap's field, the plans-ask button on Job Plans, the footer button on the first blocking fix (a plans ask alone counts as a plans-link fix). The Bid Board icon's path (icon → sheet → Edit bid) gets this for free.
- Help guide `let-the-robots-shadow-a-bid`: the Robot Board door paragraph and the amber-icon bullet.

## Not changed

The Bid Board icon click still opens the sheet (it is the "see exactly what" door), the door labels, `robotGaps`, and the sheet's answer flow.
