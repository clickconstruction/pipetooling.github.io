# v2.3716 — Robots → Console opens again: the Desktop setup commands accept the public connector address (2026-09-22)

A same-week regression from the address flip in [v2.3634](./v2.3634.md), found by the render test of the twin key card's new panel (the next PR on `to-dos/mcp-servers.md`). Client only; no migration, no edge function.

## What was wrong

`buildDesktopSetupCommand` and `buildDesktopSetupCommandFromCode` ([`desktopKickoff.ts`](../../src/lib/bids/desktopKickoff.ts)) refused any connector address that was not `…/functions/v1/twin-mcp` — written in v2.3224, when that was the only door. v2.3634 pointed every caller at `https://mcp.clicktooling.com/twin` without widening the check, so:

- **Bids → 🤖 Robots → Console crashed on render** — the tab builds the key-based command in a `useMemo`, and the throw took the whole tab down (no error boundary around it). Since 2026-09-20.
- **Set up on this Mac** threw after `twin-setup` minted the code (the function's `connector_url` is the public address).
- **Copy Desktop setup command** on a fresh twin key threw on click.

The v2.3634 fragment's *Verify* line said the commands "carry the new address"; the render test that would have caught it did not exist (`TwinSetupDialog.render.test.tsx` feeds the old address), and the Console has no render smoke.

## The change

- **[`twinConnectorUrl.ts`](../../supabase/functions/_shared/twinConnectorUrl.ts)** — `isTwinMcpConnectorUrl(url)`: https, nothing a quote could break on, and a path that is either the function door or whose last segment is `twin` (`/twin`, or `/count/twin` should CountTooling get its own, per the naming scheme). Both builders use it.
- **[`desktopKickoff.test.ts`](../../src/lib/bids/desktopKickoff.test.ts)** — both builders are called with `TWIN_MCP_PUBLIC_URL` itself, so a future address change fails here, not in the Console; the predicate's accept / refuse cases.

## Verified

`desktopKickoff`, `twinConnectorUrl` consumers (`TwinSetupDialog.render`), typecheck and lint on the touched files. Live: the Console tab renders on prod after the deploy (the owner's check — this session has no browser on prod).
