# v2.3532 — Stages tab decomposition, PR 2: the ⋯ tools menu is its own component (2026-09-16)

Client only, behavior-preserving. PR 2 of the train in `to-dos/engineering-hygiene.md` — region 2 of [`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md), the half of the toolbar that is a single opener with a clear edge. The command bar itself (New Job, Follow-ups, Forecast, the search box, the # jump, the applied-filter chips) stays for the next PR.

## What moved

[`src/components/jobs/JobsStagesToolsMenu.tsx`](../../src/components/jobs/JobsStagesToolsMenu.tsx) — the ⋯ trigger and its menu, cut verbatim: Lien desk (+ *Put <GC> on notice…* while a real GC filter is applied), the Sort radio group, the four filter selects (contract state, GC/Builder, development, Account Man), Contract sweep, Hide groups, Job Book, Total by Name, Combine / Separate, and the five per-device toggles. Two menu-only helpers moved with it (the filter-select style, the On / Off pill); the row style the tab's **per-section** ⋯ menus also use went to its own module, [`stagesToolsMenuStyles.ts`](../../src/components/jobs/stagesToolsMenuStyles.ts), so the component file exports only components.

The props contract is grouped rather than flat, which is the part meant to last:

| Group | Carries |
|---|---|
| `filters` | sort mode, the four filter values and their option lists, the hidden-group count — the menu both shows these and tints the trigger on them |
| `toggles` | the five per-device modes |
| `gates` | four booleans — `lienDesk`, `jobContracts`, `officeTools`, `powerToggles` — decided by the tab through `stagesRoleGates` (v2.3531); the menu never sees a role |
| doors | one `onOpen…` per item; `onPutGcOnNotice(gcId)` receives the filtered GC |

**`open` stays controlled** (`open` / `onOpenChange`), because the tab also reads it: an open menu is one of the conditions that asks the board to load every row (the selects derive their options from loaded rows, v2.1827). The inline *Follow cards I move* setter, which wrote its localStorage key from inside the JSX, became `toggleStagesFollowMoves` in the tab beside its four siblings — same body, same key.

Numbers: `JobsStagesTab.tsx` 6,273 → 5,906 lines; the component is 531 including its types and header.

## What the tab keeps

Every value the menu reads is still owned where it was: the filter and sort state, the toggles and their localStorage writes, the modal open flags the doors set, the two counts (`lienDeskCount`, `contractSweepCount`), and the role decisions. The call site is the one place that turns tab state into the four groups.

## New coverage

[`JobsStagesToolsMenu.render.test.tsx`](../../src/components/jobs/JobsStagesToolsMenu.render.test.tsx), six tests the tab's own smoke never gave this menu: every item and both counts render for a fully gated user; the gated items vanish when the gates are off and the closed menu renders only its trigger; the trigger asks to open and a door item closes first then opens its modal; sort and filter picks report the choice and leave the menu open; the GC-notice item appears only with a real GC filter and carries its id; the toggles call their handlers and show On / Off.
