# v2.5456 — Messages: the rules for saving a job's photos, behind the scenes (2026-10-13)

Messages, cut 10's last item (GC Mode helper 2, directed by the lead session GC MODE): photos saved on arrival to the
job's photos, the file agent copying and naming. `BUILD_PLAN.md` → *Cut 10* on branch `spike/gc-mode`; the design is
`quo-messages-mockup.html` drafts 8 and 9 and `MESSAGES_PLAN.md` decisions 6 and 8. PR 1 of five: the kernels, with no

- **`src/lib/photos/photoName.ts`**, the file agent's name, "named by day, sender and caption":
  `photoDriveName({ at, sender, fileName, mime, words, place }, taken)` gives *2026-10-02 Priya Raman · Ceiling tile op
  3.jpg*.
  - The day is Chicago's (`chicagoDay`). The sender is the person's name, else their number, else *Someone*.
  - The caption is the words for now (the owner's lean, 2026-10-13). It is the file's own name when a person gave it
    one. A name a phone made (`madeUpName`: *IMG_2041*, *PXL_…*, *picture-1*, a screenshot's) gives way to the line's
    words, cut on a word at 60 characters. With no words either, it is *Photo* and its place. Claude reading the picture
    comes later.
  - `driveSafe` drops what a computer cannot save in a name (slashes, colons, quotes, commas, links).
  - `extOf` takes the ending from the type, then the name, so an iPhone's HEIC stays HEIC.
  - A name the folder already holds takes *(2)*, *(3)*.
- **`src/lib/photos/photoSave.ts`**, which photos the sweep copies now: `photosToSave(rows, switches)`.
  - It takes a photo we kept (`bucket_path`), not yet in Drive, from a line that came in (`sent_as` null, direction
    `in`), tied to a job whose tick is on.
  - The line must have arrived since the tick went on. The tick starts off on every job (the lead, 2026-10-13).
  - A line tied to its job after it arrived is caught on the next run.
  - It picks the oldest first, 20 a run (`PHOTO_SAVE_BATCH`), and `notSavedWhy` says why one is left.
  - A job's key follows `drive-link`'s save: a GC project, then a bid, then a Pipeline job.
- **`src/lib/quo/mediaKeep.ts`**, our copy of a text's pictures, since "Quo's link to the picture is best treated as
  temporary" (draft 8):
  - `quoMediaPlans(quoId, media)` names each *picture-1.jpg* or *file-2.pdf* and places it at
    `quo/<Quo id>/<place>.<ending>` in the message-attachments bucket an email's files use.
  - `quoMediaRow` writes the `message_attachments` row: our copy when it read and fits an email's 25 MB
    (`KEEP_FILE_BYTES`), else the mark `quo_not_copied` (`QUO_NOT_COPIED`), which PR 2 adds to the column's CHECK.
- **Owner calls built to the leans**, for `BUILD_PLAN.md` § 7:
  - the tick starts off everywhere;
  - the caption is the words now, Claude later;
  - a Pipeline job's photos land in `jobs_ledger.google_drive_link` › Team only › Photos. Its Customer Pictures link
    (`job_pictures_link`) is used only when it is plainly a Drive folder link (PR 3).
