# v2.2743 — Signed agreements: one email stream, one-click (or automatic) job (2026-09-04)

**Why.** A GC signing a bid-room proposal emailed only the room's master and creator, in plain text; a customer accepting an estimate emailed that estimate's picks plus a hidden org-wide list. Neither told the office what to do next. The owner asked for a role-based notice to assistants, masters, controllers and devs, and for the job to be created — automatically, or in one click.

**What.**
- **Settings → Emails & reports → "Signed agreements"** card: recipients (explicit list; empty = every active assistant, master, controller and dev — the default) and two switches, **Create jobs automatically — estimates** and **— bid-room proposals** (both off by default).
- **One letter for both signatures** ("Signed — <title> — $56,343 (Estimate #N | Bid room proposal #N)"): who signed, option and amount, project and customer, when (company calendar), **Open the signed record**, and either **Open job J####** (auto-created, or already linked) or **Create the job** — a deep link that opens the Estimates record with the Create-job window already up (`/estimates/<n>?createJob=1`).
- **Auto-create** (when the switch is on): `auto_create_job_from_signed_estimate` — returns the job if the record is already linked, links a job someone already made for the same bid, otherwise creates one through the real `create_job_from_estimate` (acting as the estimate's owner) with the next job number and the accepted lines as Specific Work. The v2.2741 trigger stamps the job's bid, so the Stages contract chip shows the signature immediately.
- Per-estimate picks (**Estimate accepted emails** on an estimate) still add to the stream's list; the old org-wide list is folded into the stream once by the migration and no longer read.
- Outbound email catalog row **Signed agreement — staff notice** with a Preview; Recent emails sent maps "Signed — …" to the stream card.

**How.** Migration `20260904020000_signed_agreements_stream` (two service-role functions + fold). Pure builder `_shared/signedAgreementEmail.ts` (app twin `src/lib/signedAgreementEmail.ts`, byte-parity tested); IO in `_shared/signedAgreementNotify.ts` (`notifySignedAgreement`: toggle → auto-create RPC → recipients RPC ∪ per-record picks → send + log `signed_agreement_staff`). `accept-estimate` and `sign-bid-room` call it after the signature is persisted (best-effort; the customer never sees a failure). Client: `signedAgreementsStream.ts` kernel, three `app_settings` keys, `SettingsEmailStreamsSection` card, `?createJob=1` in `Estimates.tsx`, `EstimateAcceptedNotifySettingsModal` now edits the stream list.

**Known edges.** Two signatures in the same second could both take the same next job number (no unique constraint on `hcp_number`); the second create fails loudly in the function log and the email then offers Create the job. Auto-create needs the record to have a customer; a signed proposal always does.
