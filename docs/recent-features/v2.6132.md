# v2.6132 — Leave Report: an untouched Save always files the job's own percent (2026-10-30)

The field report's percent opens on the job's recorded number (punch list #189, PR 5a, v2.6076) and an untouched Save files it. The seed reaches the form's values through a passive effect, so a Save pressed between the commit that draws the field and that effect read the field as untouched, and `normalizePercentFieldValueToString(undefined)` filed `'0'` while the hint under the field said *Opens on the job's 40%. Leave it, and the report files 40%.* v2.6100 (2026-10-30 14:04 UTC) put an inline guard in `handleSubmit` for that moment; this PR moves the rule into the kernel and makes the Save button read it too.

## The incident

Three unrelated PRs each failed one test of `src/components/AdditionalReportModal.render.test.tsx` in CI on 2026-10-30, `AssertionError: expected '0' to be '40'` on the saved report's `field_values['How complete is the job?']`: `claude/214-legal-desk-show` (run 41018835257), `claude/163-offline-queue-pr5` (run 41011841792) and `claude/163-offline-queue-pr3` (run 41011676284). Which test failed varied; locally the file passed every time. All three heads predate v2.6100's guard. Each failure knocked the PR out of the merge queue and cost a 15-minute re-run.

The gap, as read: the tests wait for the hint line, then press Save at once. React flushes passive effects on a scheduler task and Testing Library's `waitFor` settles on a `setTimeout(0)`; on a quiet machine the effect's task runs first and Save reads the seeded value, on a loaded runner the timer fires first and Save's closure still reads `undefined`.

## What changed

- **The kernel** (`src/lib/reportTemplateFieldDisplay.ts`): `percentFieldValueForSubmit(raw, seed, linesActive)` — an untouched field with a seed files the seed (clamped like a pick), a pick files the pick, no seed files `'0'`, and with the lines active (report by line, v2.5663) the seed never applies, since the lines' number takes the field. `fieldValueForSubmit` takes an optional `{ percentSeed, linesActive }` and reads the rule for a percent field; the New report and Report edit forms pass nothing and are unchanged. Six tests in `reportTemplateFieldDisplay.test.ts`.
- **The form** (`src/components/AdditionalReportModal.tsx`): `handleSubmit` builds every field through `fieldValueForSubmit` with the seed and the lines flag, and the inline guard is gone. `jobPctForSave`, the number the phone's Save button says (*Save at 40%*, v2.6083), reads the same kernel, so the button and the filed value agree whichever moment the press lands in. The mirror into `jobs_ledger.pct_complete` (`propagateReportPctToJob`) reads the submitted values and so needs nothing of its own. The passive seed effect stays: the slider still opens on the number.
- **The render tests**: the two untouched-Save tests also assert the control itself opened on 40 (the slider's label). The seeded value has no sign of its own on the screen — the control and the hint read 40 from the seed before the effect writes it — so no test can wait for that moment; the file's header says so, and the third test, which presses Save from the mutation that draws the hint, pins the gap on purpose.

`npx vitest run src/lib/reportTemplateFieldDisplay.test.ts`, then the two Leave Report render files fifteen times in a row, all green; typecheck and lint clean on the touched files.
