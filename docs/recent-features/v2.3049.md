# v2.3049 — Test-gap audit, pass 57: the Dispatch Settings job picker search gets its first tests (2026-09-07)

Pass 57 of the test-gap audit. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`dispatchSettingsJobsSearch.ts` is the data layer under the Dispatch Settings "Jobs that don't require a note" picker: the live job search that hits `search_jobs_ledger` (so billed and closed jobs are findable too), the `get_jobs_ledger_by_ids` label lookup that renders chips for already-saved ids, and the one label formatter both share. One caller (the Dispatch Settings modal), no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- A blank or whitespace query returns nothing without a request; otherwise the trimmed text is sent, and the picker's abort signal is handed to the request when the runtime supports it (and the search still runs when it does not).
- Every search row becomes a chip option carrying the raw search row with its blanks normalised, so the dropdown can render the standard job row.
- The live search is not retried: a stale keystroke fails fast, and an aborted request surfaces as an error with its message for the picker to swallow.
- The label lookup is skipped for no ids, goes through the retry wrapper under its own operation name, and simply omits ids the RPC did not return.
- Labels read `J<number> · <name>`, then `J<number>`, then the bare name, then `(untitled job)`; a Click-only job keeps its number.

## What shipped

- **`dispatchSettingsJobsSearch.test.ts`** (9) — a recording RPC stand-in that optionally exposes `abortSignal`, and a retry wrapper that records its operation name. Covers the formatter's priorities, the search gate, request and mapping, the abort plumbing both ways, the empty and error shapes, and the label lookup.
