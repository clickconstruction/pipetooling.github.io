# v2.4674 — Release of Lien: Issue unconditional selects every bill the conditional covered (2026-10-06)

Punch list #87, item D ("Gap D" held for the owner in the guide PR #4605). Client only: no migration, no edge function. It builds on item I (v2.4659): the bills a cleared conditional covered are usually paid by then, and a paid bill only became one the window can select there.

## The bug

A conditional release can cover several bills. When its payment cleared, **Issue unconditional** opened the Release of Lien window with the first covered bill as the row's bill (`invoice`). The window then selected that bill alone. So the unconditional named one bill, and its amount came from that bill's applied payments only. This happened from both doors: the Dashboard's queue (`DashboardLienReleaseQueueModal`) and Bill Customer's release strip (`BillCustomerLienReleaseStrip`).

## What changed

- **`lienReleaseOpening`** ([`lienReleaseOpening.ts`](../../src/lib/jobs/lienReleaseOpening.ts), +5 tests) takes `invoiceIds`, the bills the opener names together. It selects every one the window can cover, in bill order, and drops any it cannot. When none is coverable it opens as with no bill named, as before. With no form asked for, the row's bill picks it, else the first covered bill. An empty list names nothing, so every one-bill opener reads as before.
- **`LienReleaseModal`** takes an `invoiceIds` prop and hands it to the opening. The open-reset effect keys on it.
- **Both Issue unconditional doors** pass the release's `invoice_ids`, so the window opens with every covered bill selected. The amount fills from all of their applied payments.
- [`docs/LIEN_RELEASE_MODAL_ARCHITECTURE.md`](../LIEN_RELEASE_MODAL_ARCHITECTURE.md): the props line, the two opener rows and the open-reset effect are amended.

## Guide lines this makes true

No guide is touched. *give a customer a lien release* L112 ("The covered bill lines are selected") now holds for a conditional that covered more than one bill.
