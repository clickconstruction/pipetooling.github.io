# v2.4056 — Pipeline: the top cards agree with the section headers (2026-09-28)

Client only; no migration, no edge function. Item 7 of the owner's Pipeline look pass.

## What was wrong

On 2026-09-28 the Pipeline showed "In collections $24,338 · 7 jobs" over a section header reading "Collections (8) - $24.6k", and "Waiting on customers $357,680 · 77 bills" over "Billed Awaiting Payment (76) - $357.3k". Job 838 ($350) had been flagged Collections that day from another screen. The board rows had it (they refresh on every mutation and Realtime event); the top cards read `cacheHeaderStats`, fetched once per board load and refreshed on a 60 s TTL only when this session's own writes force it. A fresh load agreed with itself: the drift was the session's.

The section headers never had this problem: `stagesSectionHeader` reads the live rows once a section's scope is merged, and the aging chips do the same (v2.1824). The cards were the one reader still on the cache alone.

## What changed

- **`src/lib/jobs/stagesLiveHeaderStats.ts`** (new) — `liveBilledStats(jobs)` reads Billed and Collections (count, remaining total), the aging buckets and the no-date count from the board rows with the same kernels `computeStagesHeaderStats` uses; `overlayLiveBilledStats(cached, live)` lays them over the cached stats and leaves everything the rows cannot speak for (capable to bill, collected by day, the bill-truth buckets) as it was.
- **`src/components/jobs/JobsStagesTab.tsx`** — `overviewStats` = the cache overlaid with the live figures whenever the `billed_all` scope is merged; `PipelineOverview` reads it in place of the cache.

## Tests

`stagesLiveHeaderStats.test.ts` — on the same rows the live figures equal the cached kernel's; a job moved to Collections after the cache was taken moves on the cards; a scope not loaded leaves the cache alone; no cache means no cards. The Pipeline tab and overview smokes pass.
