# v2.2045 — Convert a non-Stripe bill to a Stripe bill (2026-08-21)

Owner-picked variant A of the "Bill to Stripe Conversion" mockup: a BILLED
invoice line recorded outside Stripe (`housecallpro` / `physical` / NULL
channel) gains the real hosted Stripe invoice with one button — **the
ledger's `billed_at` never moves** (the create patch has never written it,
and the DB trigger COALESCEs; preservation is structural, not conventional).

- **Edge fn `create-stripe-invoice`**: new `convert_billed: true` body flag
  relaxes the ready_to_bill gate for a billed row, guarded server-side: no
  existing `stripe_invoice_id`, and **zero payments applied to the invoice**
  (a partially-paid line on Stripe would demand the full amount — blocked
  with "unlink them before converting"). Everything else is the normal
  create path, including idempotent retries. **Redeploy required.**
- **Due date = the original billed date**: passed as `due_date`, the Stripe
  invoice NUMBER inherits it (`<job>-<YYMMDD>…`) and the existing
  `daysUntilDue` clamp renders it "due now" (Stripe refuses past dues). The
  memo says "Originally billed <date> — payment due on receipt." Company-TZ
  wall dates via `calendarYmdInAppTzFromIso`.
- **Client**: `⚡ Make Stripe bill` in `JobFormInvoiceList` Actions (billed,
  non-Stripe rows; disabled with tooltip reason when payments are applied or
  the job lacks a customer email) → `ConvertBillToStripeModal` — facts grid,
  the same no-side-effects `preview-stripe-invoice` live preview
  (`StripeBillPreSubmitPreview`), ledger-doesn't-move assurance, Stripe-mode
  via the `stripeModeForBillingFromRole` gate. Success toast; nothing emailed.
- **Kernels** `src/lib/jobs/convertBillToStripe.ts` (+tests): eligibility,
  due-date fallback, TZ-safe long-date + memo builders.
- Help guide `turn-a-bill-into-a-stripe-bill.md`; `BILLING_FLOWS.md` +
  `EDGE_FUNCTIONS.md` updated.
