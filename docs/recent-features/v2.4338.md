# v2.4338 — Windows stay open when a drag ends outside them (2026-10-01)

No migration, no edge function. Grace (2026-10-01, on the Release of Lien signing pad): a window must not close when the mouse is let go outside it after a press inside — a signature drawn off the pad's edge, a text selection in a box. Only a press and a release both outside should close it.

## Why it happened

When the press and the release land on different elements, the browser fires `click` on their nearest common ancestor. Inside a window that ancestor is the backdrop, and the backdrops close on `onClick` — so every drag that ended outside a window closed it. Census on main 771ce8dad: ~430 full-screen fixed layers in `src`, ~360 closing on `click`, none guarding a drag; no shared modal component to fix in one place.

## What changed

- **One page-wide guard** ([`modalBackdropGuard.ts`](../../src/lib/modalBackdropGuard.ts), installed once at the top of [`main.tsx`](../../src/main.tsx)): document capture-phase `pointerdown` / `pointerup` / `pointercancel` remember where the press and the release landed; a capture-phase `click` whose target is a full-screen `position: fixed` layer is stopped (`stopPropagation` + `preventDefault`) before React's root and portal listeners see it, unless the press and the release were both on that same layer. A click from the keyboard or from code (`detail === 0`) passes untouched. No window was edited for it, and new windows get it too.
- **"Full-screen" means three quarters of the viewport both ways** (`isFullScreenFixedLayer`). The size is the only thing that tells a backdrop from a fixed button with an icon in it (press on the icon, release on the button's edge — the same split click). Not 90%: seven windows stop above the Job / Dispatch mode footer (`--app-bottom-chrome`), which on a phone leaves 746 of 844 px. A side drawer (420 px wide) and a fixed button are not guarded; a backdrop smaller than three quarters of the screen is not guarded either.
- **Two windows that closed on the press now close on the click**: Choose from the takeoff ([`SubmittalTakeoffPicker`](../../src/components/bids/SubmittalTakeoffPicker.tsx)) and When can a row split? ([`SplitRuleModal`](../../src/components/bids/SplitRuleModal.tsx)) — backdrop `onMouseDown` → `onClick`, the panel's `stopPropagation` with it.
- **A click outside an inner window closed the window behind it too.** The signing pad ([`LienReleaseSignModal`](../../src/components/jobs/LienReleaseSignModal.tsx)) is drawn inside the Release of Lien window's backdrop, and the rule window inside the takeoff picker's — both outside the outer panel that stops the click. A real click on the inner backdrop bubbled through React to the outer backdrop's `onClick` and closed both (found on the live walk; it predates this change). Both inner backdrops now stop the click before closing. The guard cannot do this for them: React walks the handlers inside one native dispatch.

## Not covered

- 92 windows close on `onMouseDown` with `e.target === e.currentTarget` (the app-wide confirm, the Person desk, Bids, Banking, Checklist and People windows, the My Time Not-coming-in and discard confirms, …). A drag from inside never closed them, but a press outside closes them before the release. Moved to `click` in v2.4347, once this guard is live.
- Other nested windows drawn inside an outer backdrop but outside its panel have the same both-close problem; not audited here.
