# v2.3629 — Contracts: a paper hand-off counts as sent — Mark as handed to the customer (2026-09-19)

PR 2 of [`to-dos/contract-paper-lane/README.md`](../../to-dos/contract-paper-lane/README.md). The owner approved the design for PRs 2–6 on 2026-09-19 ("I approve the Signing it on paper design"), which takes the proposed answers with it: **a hand-off counts as `sent`**. One migration, no edge function.

## Why a stamp at all

`isContractGap` counts only `none` and `draft`, so a job leaves the sweep's 105 exactly when its contract becomes `sent`. PR 1's Download PDF wrote nothing, so a page handed over at the counter left its job in the pile forever and left no record of who asked whom.

## The write — [`jobContractHandoff.ts`](../../src/lib/jobs/jobContractHandoff.ts)

`markJobContractHanded` updates the **draft** (guarded `status = 'draft'`, so a send that won the race is not overwritten) with `handoffPatch`: `status 'sent'`, `sent_channel 'handed'`, `sent_at` (kept if already set), `last_sent_at`, `send_count + 1`, and **`next_reminder_at = NULL`** — the reminder cron emails a signing link, and a handed row has no token. It then writes a `job_contract_events` row of type **`sent`** with `metadata.channel = 'handed'`, the same shape `send-job-contract` writes for `email` and `link` — so no CHECK change, and the Day book's *Sent n contracts* (which reads `sent` and `recorded` events by actor) counts a hand-off like any other send. The to-do had proposed a new `handed_over` event type; the existing `channel` metadata already carried the distinction. `handoffBlocker` names what is in the way (no draft, no terms, already out, signed, voided).

## The column — [`20260920051500_job_contracts_sent_channel.sql`](../migrations/20260920051500_job_contracts_sent_channel.md)

`job_contracts.sent_channel` (`link · pdf_email · handed`, NULL = link). `jobContractSentChannel` reads NULL and anything unknown as a link, so nothing is backfilled and `send-job-contract` is not redeployed.

## The screens

- **Sweep pane** ([`JobsContractSweepModal.tsx`](../../src/components/jobs/JobsContractSweepModal.tsx)): a successful Download PDF sets `pdfTakenJobId`; the footer then shows **Mark as handed to the customer** for that job. Pressing it saves the pane's draft first (a job with no draft yet gets one, through the same `saveJobContractDraft` the send uses), stamps it, adds the job to the sweep's sent set, calls `onSent`, and moves to the next row.
- **Contract window** ([`JobContractModal.tsx`](../../src/components/jobs/JobContractModal.tsx)): a handed row's strip reads *Handed over on paper <stamp> — waiting for the signed copy. Nothing was emailed, and no reminders go out.* with **File the signed copy** as the primary and Void & redo beside it. Resend / Copy link / Text link / Sign in person are not drawn — they act on a link this row does not have. Changing the method is Void & redo until PR 5's three-way block.
- **Chip** (`jobContractChips`): `handed over · awaiting signature` instead of `sent ×1`.

## Filing closes the loop — [`jobContractFileWrite.ts`](../../src/lib/jobs/jobContractFileWrite.ts)

`fileSignedJobContract` converted only a draft in place; for any `sent` row it inserted a fresh signed row and left the sent one live. A handed row is the same document coming back signed, so `isHandedAwaitingPaper(existingDraft)` now converts it in place too (guarded `status = 'sent'`), writing only the signature fields — the record keeps the fields, terms and recipient that were handed over rather than the sheet's prefill. A row sent as a signing link still never converts here. Both filing doors pass the handed row through.
