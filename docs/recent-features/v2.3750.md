# v2.3750 — Stages: a short stage name is shown whole, and a deposit line reads Deposit (2026-09-23)

Taunya, 2026-09-22, on job 1034 (Estimate for Kimberly Coe): *"Instead of first it should say deposit … The wording starts as 1st Draw because it's how I typed it in."* The stage strip on the Stages tab read **1st → Final** for a job whose line items are *1st Draw* and *Final*. Client only, no migration.

## What changed

- **`stageShortLabel`** ([`pipelineStageBar.ts`](../../src/lib/jobs/pipelineStageBar.ts)): after the dictionary and before the first-word cut, two rules. A cleaned name of **ten characters or fewer is returned whole** ("Phase A"). A name that **opens with a number keeps its next word** (the pair whole when it fits ten characters, else nine characters and an ellipsis — never the bare number) — the live case is not a short name at all: Taunya types the scope into the name field, so job 1034's stage is *"1st Draw- Removal of old screen door. Installation of a new screen door that we will provide…"*, and the first-word cut left *1st*; it now reads *1st Draw* (`2nd draw: …` → *2nd draw*, `2 Bathrooms upstairs` → *2 Bathroo…*). "Bathrooms upstairs" still cuts to *Bathrooms*. The dictionary gains **`deposit` (with an optional `50%` in front) / `down[ -]?payment` → Deposit**, ahead of `^demo` so the prefixes never cross.
- **The scope belongs in the scope note, not the name.** The Stripe bill line prints `name — scope` ([`stripeInvoiceItemsFromFixtures.ts`](../../supabase/functions/_shared/stripeInvoiceItemsFromFixtures.ts)), so a scope typed into the name still reaches the customer either way; the chip and the strip are what suffer. Nothing here moves text between the two fields.
- **The guide** *ready-to-bill-pipeline* names the two rules in the sentence that already described shortening.

## What was not done, and why

- **"1st Draw" is not mapped to Deposit.** On this residential job the 1st draw was a 50% deposit paid before work; on a GC job a first draw is rough-in money after work. Whether a first draw should read *Deposit* is the owner's call — the office can name the line *Deposit* today and the chip follows.
- **The customer's bill wording** ("payment 1 of 2 — scope of work") is the second half of Taunya's ask. The Stripe line already prints the line's name and its scope note (`name — scope`, [`stripeInvoiceItemsFromFixtures.ts`](../../supabase/functions/_shared/stripeInvoiceItemsFromFixtures.ts)); an automatic *payment N of M* on ordered draws is an edge-function change and an owner decision, not built here.
