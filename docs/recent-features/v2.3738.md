# v2.3738 — Assistants: one "back to the schedule" rule, and a deep link is never bounced (2026-09-22)

Punch list #30 (`to-dos/taunya-mobile.md`, *Two bugs, not design*, item 1). Client only, no migration.

## What was wrong

Two overlapping rules decided where an assistant lands after being away:

- **Dispatch Mode's** (v2.904, `Layout.tsx` + `dispatchModeReturnFocus.ts`): 5+ minutes since the last activity stamp → `navigate('/dispatch-mode/schedule')`, checked once on mount and on every tab refocus, with **no check of the current pathname**.
- **The mobile landing** (`useAssistantDispatchLanding.ts` + `assistantDispatchLanding.ts`): ~1 hour away, phones only, fires **only from `/` or `/dashboard`**, lands on `/schedule-dispatch`.

The 2026-09-22 phone-width Playwright capture (`scripts/mobile-surface-shots.mjs`, sample assistant) opened `/jobs?tab=stages` cold and ended on `/dispatch-mode/schedule` in two of three runs — the first rule firing on a deep link. Two stamps in two localStorage keys, two thresholds, one missing guard.

## The change

One rule, in the kernel that already had the guard:

- **[`assistantDispatchLanding.ts`](../../src/lib/assistantDispatchLanding.ts)** — `shouldLandOnDispatch` / `resolveAssistantLanding` take `dispatchMode` (Layout's `dispatchModeActive`) and apply the same `HOME_PATHS` guard either way. Dispatch Mode on → `DISPATCH_MODE_AWAY_THRESHOLD_MS` (5 minutes), any viewport, `DISPATCH_MODE_SCHEDULE_PATH`; off → `AWAY_THRESHOLD_MS` (1 hour), phones only, `DISPATCH_PATH`. The last-active stamp (`readLastActiveAt` / `stampLastActive`, one key: `pipetooling:last-active-at`) moves here so the hook and Imitate share it.
- **[`useAssistantDispatchLanding.ts`](../../src/hooks/useAssistantDispatchLanding.ts)** — takes `dispatchMode`, navigates to whatever the kernel resolves (`replace: true`), otherwise unchanged (cold-load one-shot once the role is known; visibility + bfcache returns; a 60-second stamp).
- **[`Layout.tsx`](../../src/components/Layout.tsx)** — the duplicate Dispatch Mode listener (its effect, ref and imports) is deleted; the hook is called once, after `dispatchModeActive` is known.
- **[`loginAsUser.ts`](../../src/lib/loginAsUser.ts)** — Imitate stamps the shared key instead of the Dispatch Mode one (same J5-11 reason: an operator's browser has no activity on record).
- `dispatchModeReturnFocus.ts` and its test are removed.

Threshold choice, stated for the release note: **5 minutes when Dispatch Mode is on, 1 hour otherwise** — both values already shipped; what changes is that the 5-minute variant now respects the home-path guard and the desktop rule stays phone-only outside Dispatch Mode.

## Tests

`assistantDispatchLanding.test.ts` covers both modes: the home-path guard blocks `/jobs`, `/dispatch-mode/inbox` and `/dispatch-mode/schedule` even with an infinite away gap; 5 minutes is enough only with Dispatch Mode on; desktop fires only with Dispatch Mode on; non-assistants never; `resolveAssistantLanding` returns the right path or null.
