# v2.6309 — Company papers live in a Drive folder the app lists, and the office uploads into it (2026-11-01)

The Documents page design spike of 2026-11-01, candidate 3: the owner said the job side has a good Drive tool and the company documents should have the same. The owner's word on who uploads: the four office roles, the estimator reads. No migration; **two edge functions redeploy right after the merge** (`drive-link`, `job-drive-folders`), since the tab's reads and the card's save name asks the deployed functions do not know until then.

- **What jobs have, and Company gets.** A job's papers live in a Drive folder the app makes and lists live (`job-photos` `files`, v2.6299; `drive-link` `list`) with Add a file into it (v2.6303). Company documents were a table of name plus pasted link (`company_documents`, dev-only to add, v2.941) with no folder anywhere. Now the company's papers live in one Drive folder the office sets once, the tab lists it live from Drive, and the office uploads into it. No rows to keep: a newer copy is the newer file in Drive.
- **The setting.** `drive_company_folder_id` on `app_settings` (`DRIVE_COMPANY_FOLDER_ID_KEY` in `_shared/whereFilesGo.ts`, `APP_SETTINGS_KEY_DRIVE_COMPANY_FOLDER_ID` in `appSettingsKeys.ts`, held equal by `folderName.test.ts`); `DriveSettings.companyFolderId`, read by `readDriveSettings` with the other four; nothing fills in for it. `NO_COMPANY_FOLDER_WORDS` is what the door answers while it is empty.
- **Where files go.** `job-drive-folders`' `settings` answers `company: { id, url, ok, words, folder } | null` beside `root`, and `set` takes `company` (a folder link or id), checked with `checkFolderWrite` first and refused `409 company_unwritable` when the app cannot write there. The tab's `CompanyCard` (`DocumentsWhereFilesGo.tsx`, between the root and the naming card; `companyCardWords` in `whereFilesGoTab.ts`, `WhereFilesGoSet.company` in `whereFilesGoIo.ts`): paste, **Check** (`aria-label` *Check the company folder link*, so the root card's Check stays unique), then **Use this folder for company papers** behind a confirm (`confirmLabel` *Use this folder*).
- **The Drive door.** `drive-link`'s office door takes two more asks (`parseOfficeAsk` in `_shared/driveLink.ts`, `driveLink.test.ts`): `list_company` (any office role, a training account too: it is a read) → `{ files, capped, folder: { id, url } }`, `filesUnder` over the one folder; `put_company` (`COMPANY_PUT_ROLES`: dev, master, assistant, controller; `base64` up to the same `PUT_MAX_BYTES` 10 MB) → `{ driveFileId, url }`. Both answer `409 { why: 'no_company_folder' }` while the setting is empty.
- **The Company tab.** `DocumentsCompanyFolder.tsx`, mounted above `SettingsCompanyDocumentsSection` on Documents → Company (Settings → Your account keeps the old list alone): **Company papers**, the files newest change first with day and size (`companyFileRows`, `fileSizeWords`, `companyFilesCountWords` in `lib/documents/companyFolder.ts`), each a press that opens Drive, **Open the folder**, and **Upload a file** for `canUploadCompanyFiles` (= `canSetWhereFilesGo`) through a hidden file input: a nameless, empty or over-10 MB file is held in the browser with its reason (`companyUploadHold`) before anything is sent; a put that lands toasts `companyUploadedWords` and reads again. `loadCompanyFiles` / `putCompanyFile` in `companyFilesIo.ts` carry the function's `why` (`CompanyFolderRefused`). No folder yet: `EmptyState` naming **Where files go** (a link for the roles that can set it, words for the rest); a folder with nothing in it: *No company papers yet. Upload a file adds the first.*; a read that fails: `OfflineRetryPanel`. Render test `DocumentsCompanyFolder.render.test.tsx` (the list, the estimator without Upload, an upload that lands, a held empty file, both empty states).
- **Deploy order.** The client ships with the merge; until `drive-link` deploys the Company tab shows the live function's refusal (*That is not an ask this door takes.*) in the retry panel, a refusal with no Retry, and until `job-drive-folders` deploys the card's Check works but its save is refused. Deno is not on the Mac that built this, so the two functions were read twice, not typechecked locally; CI has no Deno step either.
