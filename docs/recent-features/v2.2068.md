# v2.2068 — Combine-flow reconciliation: activity note, status-conflict warning, tagged migrated events (2026-08-22)

Follow-up to the 2026-08-21 report-%→RTB forensics (job 877 "Johnny Ingram"): `migrate_job_ledger_costs_and_delete` (Combine/Separate + Delete-job modal) silently moved the source job's thread notes, reports and `job_status_events` onto the target and deleted the source. The migrated events told the source's story on the target (breaking the v2.1435 single-writer history assumption for Weekly Money movement / RTB payload consumers), and a tech who had marked the duplicate 100% + Ready to bill saw their work "reverted" with no explanation (root of Abraham's complaint).

- **Migration** [`20260822010000_combine_job_reconciliation.sql`](../migrations/20260822010000_combine_job_reconciliation.md): `job_status_events.source_job_id` (nullable uuid, no FK — forensic id of the deleted source) + redefines the job→job RPC (from `20260619130000`, three additive deltas): tags migrated status events, posts a `Combined "<name>" (Job #<number>) into this job — source was <Status> at <pct>%` thread note on the target authored by `auth.uid()`, and returns `note_body` + `source`/`target` status/pct. Signature unchanged — no types regen needed for callers.
- **Kernel** [`jobCombineNote.ts`](../../src/lib/jobs/jobCombineNote.ts) (+ tests): `composeCombineNoteBody`/`parseCombineNoteBody` mirror the SQL note format byte-for-byte (tests pin it — change SQL and TS together), `describeStatusPct`, and `combineStatusPreview` — warning fires when the source's stage differs from the target's (either direction; RTB@100% into a Billed target was the 877 case) or same stage at a higher %.
- **UI** — [`JobCombineStatusNotice`](../../src/components/jobs/JobCombineStatusNotice.tsx) + [`useJobStatusPctPair`](../../src/components/jobs/useJobStatusPctPair.ts) (fetches `status, pct_complete` for the picked pair; the search rows don't carry them). Rendered in [`JobsCombineSeparateModal`](../../src/components/jobs/JobsCombineSeparateModal.tsx) (Combine tab, between Summary and the confirm) and in [`JobFormDeleteMigrateModals`](../../src/components/jobs/JobFormDeleteMigrateModals.tsx) (job-target path only — the bid path keeps its RPC dry run). Success toasts in both callers mention the posted "Combined" note when the RPC reports one (old-server tolerant).
- **Help guide**: new [`combine-duplicate-jobs.md`](../../src/content/help/combine-duplicate-jobs.md) (Pipeline → tools → Combine / Separate walkthrough incl. the new warning + note).

Deploy order-independent: new client renders the notice from its own fetch; old client ignores the RPC's new payload keys. Apply the migration with `supabase db push` after merge. Follow-ups: history consumers (`stagesWeeklyMovement`, Weekly Money movement) can now skip `source_job_id IS NOT NULL` events once types are regenerated; a My-Schedule card line for crews whose job was absorbed (send-back-note pattern) is possible on top of `parseCombineNoteBody`.
