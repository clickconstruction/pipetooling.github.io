# v2.3243 — Reps carry provenance for real (2026-09-10)

Migration `20260910212000_supply_house_contacts_created_by_default.sql` — push after this client deploys (no ordering risk; the client works before it).

## Why

The Directory (v2.3166) promised "every rep says who added it" and reads `supply_house_contacts.created_by` for the label. Auditing the session's design promises against what shipped found the column never gets written: it has had no default since v2.1605, and neither writer — the reps editor (`SupplyHouseContactsSection`) nor the RFQ window's "remember as rep" (`RfqComposeModal`) — passed it. Every rep added since read as nobody's, so the shared-list trust signal the design leaned on was blank.

## What shipped

- **DB default** — `created_by DEFAULT auth.uid()`: every authenticated path stamps the author from now on, including any future writer nobody thinks to update. Service-role writes stay NULL. Existing rows keep NULL; nobody can say who added them after the fact, and the Directory already renders a rep without provenance as a plain row.
- **Both client inserts pass `created_by` explicitly** (`useAuth().user.id`), so the label works before the migration is pushed.

## Not changed

The Directory, the reps editor's "added by" rendering, and the request-history "who" (which comes from `bid_rfqs.created_by`, stamped by the v2.3126 authorship trigger) are as shipped.
