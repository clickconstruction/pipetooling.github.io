# v2.5504 — Messages: one email sent to both inboxes shows once (2026-10-13)

Residential Messages, R6's reader follow-up (`to-dos/gc-mode/messages/RESIDENTIAL_BUILD_PLAN.md` → R6, on branch
spike/gc-mode). Since v2.5494 the reader reads bids@ and the team box. One email sent to both is two Gmail messages, each
with its own Gmail id, so it landed twice. Built before the owner switches the team box on. The lead pushes the migration
first, then deploys `gmail-sync`, which reads the new column.

- Migration `20261014170000_messages_rfc_message_id.sql` (`docs/migrations/20261014170000_messages_rfc_message_id.md`).
  - `messages.rfc_message_id`: the mail's `Message-ID` header, trimmed. Only an email carries one, 1 to 998
    characters (`messages_rfc_message_id_said`). Nobody signed in writes it.
  - `messages_rfc_message_id_once`: one line a `Message-ID`. One index for both companies' boxes, since a `Message-ID`
    names one mail world-wide.
  - `email_write_line` is recreated from `20261014003000_messages_two_boxes.sql` with the column and one change: the
    insert stands back on the Gmail id or the `Message-ID` (`ON CONFLICT DO NOTHING`, no target). Then it writes no file
    and no note, and answers written false with the line it has.
- `emailIn/emailLine.ts` (in the edge copy): `rfcMessageId(email)` reads `headers['message-id']`, trimmed. It is null
  when the header is missing, empty or over 998 characters. `EmailLine.rfcMessageId` carries it, on a forwarded copy's
  line too.
- `gmail-sync`:
  - Stamps `rfc_message_id` on every line it writes.
  - Before it places the address or copies a file, it asks whether a line already holds the mail's `Message-ID`. When
    one does, it only labels this box's copy and counts it as `already`.
  - A write that answers written false also counts as `already`, no longer `taken`.
- The reader still reads both boxes, and both copies get the label. Lines read before this carry no `Message-ID` and
  are not deduped.
- Tests: `emailLine.test.ts` (the header, trimmed, on a plain and a forwarded line; null when missing, empty or too
  long). The SQL bed `supabase/tests/messages_email/40_message_id.sql` in `scripts/pgtest-messages-email.sh`, with the
  migration applied twice: the second box's write writes nothing and is answered with the first box's line; a Gmail id
  read again is answered as before; mail with no `Message-ID` still lands; a text carries none; the office writes none.
- Docs: `docs/EDGE_FUNCTIONS.md` → gmail-sync, amended in place.
