# v2.2736 — Schedule Dispatch: tap-to-move + press-and-hold Move sheet (2026-09-03)

Taunya (assistant, on her phone): "make it easy for me to click and drag like on a computer. I need to move J1004 to Friday." Drag was the only way to move a block on the hub: a 22px grip, a pointer sensor that lifts after 8px (indistinguishable from a scroll on touch), and the target day 90% off-screen at 375px. Diagnosis + the three options the owner chose from: artifact `1d4eb54f`. Built options B and C.

## Client only — no migration

- **One move path.** [`lib/scheduleDispatchDragEnd.ts`](../../src/lib/scheduleDispatchDragEnd.ts): the drop handler's body is now `moveScheduleDispatchBlockTo(blockId, { workDate, assigneeUserId }, deps) → boolean` (linked-group day move via RPC, same-day person re-home, solo patch, overlap check); `executeScheduleDispatchBlockReassign` just decodes the droppable id and delegates. New `scheduleDispatchDragEnd.test.ts` (7 tests, mocked IO).
- **Tap-to-move placement (option B).** `ScheduleDispatchCardPlacementVariant` gains `'move'` ([`ScheduleDispatchGrid.tsx`](../../src/components/schedule/ScheduleDispatchGrid.tsx) type). On narrow viewports (`HubPeoplePanel`'s `useIsMobile`, passed down as `tapGripToMove`) a **tap on the grip** calls `onStartCardPlacement(block, 'move')` — drag on the grip still works. The page banner for a `move` placement names the block + window and renders **day chips** (`buildMoveDayChips(visibleDayKeys, sourceDay)`, source disabled/dashed) that call `onCardPlacementPickCell(sourceAssignee, chip.ymd)`; any cell tap still works (person + day). `onCardPlacementPickCell` handles `'move'` first on both grids (`blockById` / `hubBlockById`) and toasts "Moved to Fri 9/4."
- **Press-and-hold Move sheet (option C).** New [`hooks/useLongPress.ts`](../../src/hooks/useLongPress.ts) (fires on release ≥450ms, cancels on >10px travel / pointercancel / leave, `consumeLongPress()` swallows the trailing click — the Quick Assign pattern). `HubPeopleBlockCard` spreads it on the card body (iOS callout/select suppressed only on phones so desktop text selection survives) and guards both card click targets. New [`ScheduleDispatchMoveBlockSheet.tsx`](../../src/components/schedule/ScheduleDispatchMoveBlockSheet.tsx) (`ResponsiveModalShell`): week-day chips, `<input type="date">`, person chips from `hubAllPeopleRows`, Save label from `moveBlockSaveLabel` ("Nothing to move" / "Move to Fri 9/4" / "Move to Paige" / both). `onRequestMoveBlock` threads card → cell → panel (both mounts) → hub → page; the page owns `moveSheetBlock` + `saveMoveSheet` (errors land in the sheet, success toasts). Render test (3) + kernel tests for [`lib/scheduleDispatchMoveBlock.ts`](../../src/lib/scheduleDispatchMoveBlock.ts) (7).
- **Help guide** `schedule-dispatch.md`: "Move a block from your phone". `SCHEDULE_DISPATCH_ARCHITECTURE.md` card/cell dossier notes the two entry points.

Verified live on the phone preview as dev: grip tap → banner with Mon–Fri chips (Mon disabled as the source) → Cancel; 550ms hold → Move sheet with days/date/21 people and "Nothing to move" → Cancel. The actual write is the drop's kernel (unit-tested) — no prod block was moved during verification.
