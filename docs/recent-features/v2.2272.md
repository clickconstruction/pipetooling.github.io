# v2.2272 — Missed view collapses to one row per task (2026-08-25)

Owner-reported (with a "Taunya · 505 outstanding" screenshot): every missed
day of a repeating item is its own `checklist_instances` row, so the Review
tab's **Missed** range listed a daily task once per missed day — hundreds of
identical rows, inflated person/tile counts.

Fix (mockup artifact edcb510d) — collapse at render, resolve in batch:

- New pure kernel `src/lib/checklistMissedGroups.ts` (+tests):
  `collapseMissedInstances` groups a person's missed instances by
  `checklist_item_id`, preserving display order; representative = the OLDEST
  instance (drives the age chip), `instanceIds` = every missed copy,
  `newestScheduledDate` for repeat math.
- `loadOutstanding` (Missed range only): each person's list becomes the
  representatives; person counts and the Outstanding tile count groups
  (Taunya 505 → 9 live). A `missedGroups` map (rep id → group) backs the
  handlers.
- Row chip: grey `missed ×N` next to the age chip (tooltip explains the
  batch semantics).
- **✓ resolves the whole group**: one `UPDATE … IN (ids)` completion batch,
  ONE notification, ONE `days_after_completion` materialization computed off
  the **newest** missed date. **🗑 deletes the whole group**; the confirm
  dialog names the count ("Removes all N missed copies").
- One-offs / Next day / Next week ranges unchanged (single instances).

Follow-up worth considering (not in this change): stop materializing a new
daily instance while yesterday's is still incomplete, so backlogs never grow
hundreds deep again.
