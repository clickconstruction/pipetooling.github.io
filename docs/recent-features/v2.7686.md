# v2.7686 — Checklist Review: the map of open tasks is now a Google map (2026-11-17)

The owner asked for the Review tab's map, *Where the open tasks are*, to be a Google Maps map. The app already draws six maps on Google (the Dashboard's jobs, the Bid Board, the Jobs map, the clocked-in map, the home map and Research) through one browser key and one shared canvas, so this card joins them. No new key, billing or console setting.

## What changed

- **The card mounts the shared Google canvas** (`src/components/map/PinsMapGoogleCanvas.tsx`) under the app's one provider rule (`resolveDashboardMapProvider`): Google when the browser key is set and the API loads, and the card's former Leaflet canvas (`TaskPlacesMapCanvas`, streets with the view from above over them) with no key or once Google fails on the page. A failure is kept for the page.
- **Satellite / Streets on Google** (`src/lib/map/googleMapType.ts`, tested): the card's one choice becomes a Google map type. Satellite is `hybrid`, the photograph with the street names on it. Streets is `roadmap`.
- **`PinsMapGoogleCanvas` takes `mapTypeId`**. A card that passes none sends no map type and draws the road map as before, so the other six maps are unchanged. A photograph is held flat (`tilt: 0`): zoomed in, Google tilts to its 45° view where it has one, and a dot would sit off its spot.
- **Kept as they were**: the person chips, *Everyone*, the navy dot with its count, the bar under the map with **Directions**, the line that counts tasks with no place, **Hide map** and its device key, and the wheel that scrolls the page until the map is pressed.
- A selected name's chip set `border` and `borderColor` together, which React warns about on every press. It now sets `border` alone.

## Only this card

The person's own map on Today and in Task Mode (`TaskPlacesMapCard`) still draws on the Leaflet canvas. It shares the canvas file but not this change, so it can follow as its own PR.

## Older dates of the view from above

Not in this PR. What was read on 2026-11-17, for the PR that follows:

- Google's Maps JavaScript API and Map Tiles API serve one imagery, the current one. Neither takes a date. Google's older imagery is shown only in Google Earth, which has no map to embed.
- Esri's World Imagery Wayback publishes each release of its imagery since February 2014 as its own tile layer, with a metadata layer that names the day a photograph was taken.
- Google's Maps Platform terms (3.2.3 (e), *No Use With Non-Google Maps*, as last changed 2026-08-26) say its services are not used with or near a non-Google map in an application, and name linking a Google map to one as an example. Read plainly, an older date from another provider cannot be a layer on the Google map or sit beside it: it has to be its own view.
