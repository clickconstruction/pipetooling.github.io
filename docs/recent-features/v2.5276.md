# v2.5276 — GC mode: asking for a renewed insurance certificate and the renewal list share one 30-day window (2026-10-12)

A one-line kernel fix found while cluster 6 of the Messages build named where "runs out soon" reads its days (v2.5259). No behavior changes: both numbers were 30.

- **The stray copy.** `src/lib/gc/paperSend.ts` decided when insurance gets its next step on the company window with a private `INSURANCE_ASK_WITHIN_DAYS = 30`, "the same 30 days as the renewal ask". The renewal ask's own constant is `INSURANCE_ASK_DAYS` in `src/lib/gc/promises.ts`. The portal's `COI_WARN_DAYS`, the schedule's not-ready check and the Messages papers grid already read that constant. Changing one would have left the other behind.
- **The fix.** `paperSend.ts` imports `INSURANCE_ASK_DAYS` and the private copy is gone. `promises.ts` does not import `paperSend.ts`, so there is no cycle. `paperSend.ts` is not in the edge functions' kernel copy, so nothing there changes.
- **The test.** `paperSend.test.ts` reads Ironhorse with its certificate running out -5, 0, 29, 30, 31 and 90 days out. `paperStep` asks for it on exactly the days `insuranceRenewals` lists it, through day 30 and not on day 31. With the window broken by one day on purpose, the test fails.
