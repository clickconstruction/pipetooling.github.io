# v2.2590 — AR bill-combo suggestions (2026-09-01)

Variant B of the owner-picked AR modal plan (mockups: "Who Sent This Check";
builds on v2.2584's payer matcher). A GC paying three invoices with one check
previously fired no quick picks at all — nothing matched singly, and the
assistant had to know the combination that summed right.

- **New kernel `src/lib/jobs/arPayerBillCombos.ts`** (8 tests):
  `findExactBillCombos(depositRemaining, targets)` enumerates sets of 2–4 of
  the matched payer's open bills whose remainders sum cents-exactly to the
  deposit. Bounded (≤12 bills considered; enumeration bails past 3 exact
  sums) and conservative: singles are excluded (they're the match chips'
  job), and the modal only suggests when **exactly one** combo exists.
- **Modal UI (`BankPaymentsModal`)**: the payer section leads with a dashed
  green chip — "2 bills = $4,091.50 / $2,711.50 · 915 + $1,380.00 · 880 /
  fills 2 allocation lines". Tapping replaces the single untouched allocation
  line with one filled line per bill (amounts = each bill's remaining, sum =
  deposit); Apply is unchanged and Stripe-hosted members still trigger the
  out-of-band confirmation. The chip only renders while the allocation area
  is a single untouched line, so it never clobbers manual work.
- **v2.2584 follow-up polish (`jobsStagesBoard.ts`)**: the payer names now
  appear in the *visible* picker option line too (`bankPaymentTargetCuesAfterAmount`),
  not just the search text — live testing showed searching "foundation" worked
  while the option row gave no hint why. Shared `dedupedPayerNames` also
  drops the duplicate when a job's customer and GC are the same name
  ("Knight Contracting · Knight Contracting").
- New render smoke `BankPaymentsModalCombo.render.test.tsx` (combo chip →
  two filled lines). Help guide updated. Client-only; no schema/RPC changes.
