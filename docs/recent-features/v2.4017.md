# v2.4017 — Bids: the orange tabs are the same height as the blue ones (2026-09-28)

Client only; no migration, no edge function. Found on the live pass of 2026-09-28 (the browser console's React warning about mixing `background` with `backgroundClip` on the Bids tab strip).

## What was wrong

Counts, Pricing and Cover Letter are the three highlighted Bids tabs: orange text, and an orange fill when open. Every page tab is a slim pill inside a taller click target — the extra height is a transparent border, and `backgroundClip: 'padding-box'` keeps the fill inside it (`lib/pageTabStyle.ts`, which says in its own comment never to use the `background` shorthand, because the shorthand resets the clip). `bidsTabStyle` set the orange with `background`.

So when one of the three was the open tab, its orange filled the full height of the click target — a taller box than the blue tab beside it — and once it had been open, the tab kept the wrong clip after it closed. Measured live: `background-clip: border-box` on the open orange tab, `padding-box` on every blue one.

## What changed

`bidsTabStyle` sets `backgroundColor`. `src/lib/bids/bidStyles.test.ts` (5 tests) pins that no Bids tab style carries the `background` shorthand, that the clip is `padding-box` in every state, and that an open orange tab differs from an open blue one by its fill alone.

## What a person sees

Counts, Pricing and Cover Letter, when open, are the same slim orange pill as the blue tabs — not a taller block. The console warning is gone.

## Verified

- Live on a local dev server: the clip reads `padding-box` on every tab through a run of clicks (Counts → Pricing → Takeoffs → Cover Letter → Bid Board).
- eslint; typecheck; `npm test` in full.
