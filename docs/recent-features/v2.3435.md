# v2.3435 — Sub sheets read their job by id only: number fallbacks, the two hcp RPCs and the 10-char cap retired (2026-09-14)

Mechanical cleanup, merged alone. Closes `to-dos/sub-sheet-job-link-followups.md` (deleted in this PR) — the "After all rows are gone" section that v2.3055 / v2.3059–v2.3071 left dated.

## Why

v2.3055 added `people_labor_jobs.job_ledger_id` and back-filled it; the conversion PRs moved every reader to the link and kept a "number fallback" (`job_number` ↔ `jobs_ledger.hcp_number` as text) for one release. Measured 2026-09-14: 77 sheets, **0** with `job_ledger_id IS NULL`. The fallbacks had nothing left to catch, the number-lookup RPCs had one caller, and `job_number varchar(10)` was still silently truncating longer numbers that were only ever display text.

## What shipped

- **Migration** [`20260914240000_sub_sheet_link_cleanup.sql`](../migrations/20260914240000_sub_sheet_link_cleanup.md): `people_labor_jobs_stage_to_activity` and `superintendent_can_access_sub_work_order` read `job_ledger_id` only (no `resolve_job_ledger_id_by_number` / inline `lower(btrim(…))` branch); `DROP FUNCTION IF EXISTS get_jobs_ledger_by_hcp_numbers(text[])` and `_paid_only(text[])`; `job_number` widened `varchar(10)` → `text` with a new column comment. `resolve_job_ledger_id_by_number` stays, used only by the BEFORE trigger `people_labor_jobs_link_job_ledger()` (untouched).
- **People → Review** [`PeopleReviewTab.tsx`](../../src/components/people/PeopleReviewTab.tsx): the last caller of the two hcp RPCs. Both loaders (`loadReviewDataCore`, `loadTeamReviewUnion`) now resolve sheets through `get_jobs_ledger_by_ids[_paid_only]` on the sheets' `job_ledger_id` alone; the `jobIdByHcp` number map, `mapLedgerNumbers` / `mapUnionLedgerNumbers` and the hcp collections are gone. `laborRowJobId(r)` is the link or null.
- **Kernel** [`derivePersonTeamSummary.ts`](../../src/lib/people/derivePersonTeamSummary.ts) + [`teamReviewTypes.ts`](../../src/lib/people/teamReviewTypes.ts): `TeamReviewUnion.jobIdByHcp` removed; the kernel's `laborRowJobId` reads the link only. Test fixtures carry `job_ledger_id` on the rows instead of the map; the v2.3068 "link-less sheet still uses the number map" case now asserts the sheet lands on no job.
- **The 10-char cap**: [`JobsSubLaborFormModal.tsx`](../../src/components/jobs/JobsSubLaborFormModal.tsx) insert/update no longer `.slice(0, 10)` the typed number; [`subLaborJobNumberForStorage`](../../src/lib/jobs/subLaborJobPicker.ts) stores the picked job's effective number uncut (+ test retitled). No `maxLength={10}` existed on the inputs.
- **Types**: the two `get_jobs_ledger_by_hcp_numbers*` entries were removed from `src/types/database.ts` by hand; a `chore(types)` regen PR follows the push (the regen also flips `job_number` to plain `string`, which it already is in the generated type).
- **Edge functions**: `sub-portal` and `submit-sub-portal` only ever *display* `job_number` (the "where" string of a stage-change notice, the sheet number when the job's own number is blank) — no path resolves a job by number, so neither changed and **no redeploy is needed**.
- `laborJobMatchesHcp` (named in the to-do) had already been deleted in v2.3060; nothing in `src/` referenced it.
- Docs: `PROJECT_DOCUMENTATION.md` (`job_number` text), `JOBS_MODALS_ARCHITECTURE.md` (no "max 10 chars"), `PEOPLE_REVIEW_TAB_ARCHITECTURE.md` / `JOBS_TABS_ARCHITECTURE.md` (RPC lists), `to-dos/README.md` (row removed, slug in the Closed paragraph).
