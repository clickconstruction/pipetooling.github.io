# v2.4267 — Deploys: a run that stalls now fails and the next one takes its place (2026-09-30)

On 2026-09-30, deploy run 36727134434 (v2.4228) passed its checks at 14:28 UTC and then sat `in_progress` on the build job's *Install Chromium for the share cards* step (`npx playwright install --with-deps chromium`, added with the help share cards in v2.4190) until it was cancelled by hand at 18:54 UTC — four and a half hours. `deploy.yml` runs one deploy at a time with `cancel-in-progress: false` (the v2.3023 fix for the opposite failure), and GitHub keeps only the newest pending run per concurrency group, so the hung run held the group while the deploys for the 45 merges behind it were cancelled or replaced. Nothing reached clicktooling.com all afternoon. Six seconds after the cancel the next queued run started, and the site was on the newest main by 19:15 UTC. The `build` job had no `timeout-minutes`, so a stall had nothing to end it but a person. No migration, no edge function, no app code.

## What shipped

- **`deploy.yml`: every job has a `timeout-minutes`.** `checks` 30 (normally 10–13 min), `build` 30 (normally 6–7 min), `deploy` 15 (`actions/deploy-pages` waits at most 10 min itself). A run that stalls now fails inside the hour and the next push takes the "pages" group.
- **The Chromium install step has its own `timeout-minutes: 5`** (normally about a minute). A timed-out step counts as failed, and the step's existing `continue-on-error: true` turns that into "no share cards this deploy — the pages fall back to the site card" instead of a lost afternoon. The build job's 30 is the backstop for any other step.
- **`ci.yml`: the `checks` job carries the same 30**, so a stuck PR check fails instead of hanging in the merge queue. The parity check (`scripts/check-workflow-parity.mjs`) compares the multiset of `run:` commands in the two `checks` jobs and nothing else, so job-level `timeout-minutes` keys leave it green; the same budget on both is by hand, for the same reason parity exists.
- Timings for the three budgets come from the day's successful runs (36724912437, 36761297322, 36764162068).
