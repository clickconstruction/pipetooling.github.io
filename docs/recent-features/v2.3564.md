# v2.3564 — Pricing tab decomposition, PR 5: the three price-book forms are their own components (2026-09-17)

Client only, behavior-preserving. PR 5 of the Pricing train in `to-dos/engineering-hygiene.md` — region P5 of [`docs/BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md`](../BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md), measured before the cut: 54 + 91 + 110 lines, every form's state its own, no supabase call in the JSX. Follows v2.3563 (the drawer these forms open from).

## What moved

Three files, one PR, each moved verbatim:

- [`PricingVersionFormModal.tsx`](../../src/components/bids/PricingVersionFormModal.tsx) — New / Edit price version: the four titles (*New template*, *New pricing*, *New pricing (copy)*, and the rename title that follows templates mode), the name box, and **Delete version** offered only when renaming a book that is not *Default*.
- [`DeletePricingVersionModal.tsx`](../../src/components/bids/DeletePricingVersionModal.tsx) — the type-the-name confirmation: the book named, the *Recently deleted* line, Delete off until something is typed, the tab's mismatch line.
- [`PricingEntryFormModal.tsx`](../../src/components/bids/PricingEntryFormModal.tsx) — New / Edit entry: the fixture box with its datalist, one *Price* box in Combined mode or the three stage boxes plus the read-only total in Stage mode, the tab's error line, Delete while editing. It keeps its z-index of 80 above the drawer (v2.2445).

Props are flat and named for what they are (`nameInput` / `onNameChange`, `roughIn` / `onRoughInChange`, …), the way the Labor book panel's form groups are. The one piece of arithmetic that moved is the v2.2644 rule for the Combined box — the raw string stays in the field and Rough In absorbs the change net of Top Out and Trim Set — because it reads only the three strings the form already holds.

**What stayed in the tab.** Every write: `savePricingVersion` (rename / new template / new blank pricing / clone via RPC), `confirmDeletePricingVersion` (and the re-activation through `pickActivePricing` when the active pricing died), `savePricingEntry` (fixture types auto-created, `sequence_order = max + 1`), `deletePricingEntry`; the open / close state and the auto-total effect; and the `templatesMode` / `panelVersionId` gates. The delete dialog's four-way reset is one closure in the tab now, passed as `onClose` to both its backdrop and Cancel.

**Not moved, on purpose:** the fourth dialog between them — the Workbench's *Price* rename-or-delete card (`pricingEdit`, v2.2404) — is not on the P5 map: it reads the star guard, the GC name and `customerFacingPricingId`, so it belongs to the Workbench re-map, not to the book forms.

Numbers: `BidsPricingTab.tsx` 5,205 → 5,008 lines (5,422 before PR 4).
