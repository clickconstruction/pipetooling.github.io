# v2.7644 — Contract sweep: a contract already on file is no longer offered to another job (2026-11-17)

Punch list #377, PR 3 of six: the Drive pass. It ships before anything files a contract by itself, since a filed copy is exactly the kind of file the pass looks for.

## Why

`drive-contract-scan` lists every file in the jobs drive whose name holds *contract*, *agreement*, *signed* and the like, and the client offers each to a job with no contract, by the folder's street or job number or, weaker, by the customer's name. It never checked a file against the papers already on file. So a signed contract sitting under one job could be offered, as a find to check, to the same customer's next job. That was already true of the papers the office linked by hand. Once the app files copies named *Signed contract* into every job's folder, it would happen for every one.

## What changed

- **Every answer drops the papers on file**, the kept scan and a fresh one alike. `papersOnFile` reads every contract row a page at a time and hands them to `knownContractFileIds` (PR 1): the Drive file a signed record keeps, the file inside a signed record's typed link, and every copy the app itself filed, voided ones too.
- **By Drive id, never by name.** A renamed file is still the same paper.
- **At the read, not at the scan.** The function keeps a scan for an hour. The filter runs each time the list is served, so a paper filed after the scan was kept is gone on the next read. The kept row still holds the whole scan.
- **A second net on a fresh scan.** The listing now asks Drive for each file's `appProperties` and leaves out any file carrying `pt_job_contract`, the mark PR 2's upload puts on a copy. That covers a copy whose row write was lost.
- **`on_file`** in the answer says how many files were dropped.
- **A file linked on a record that was later voided may be offered again.** It is nobody's paper any more. The app's own copy of a voided paper stays out.
- **Safe before the migration.** A database without the Drive columns refuses them by name. The function then reads the typed links alone. A read that fails altogether drops nothing, and the pass offers what it offered before.

## One window left

The Contract sweep keeps its own copy of the scan in the tab for fifteen minutes. A paper filed by the sweep's cron inside that window can still show as a find until the tab reads again. PR 4 clears the tab's copy when a person files one from the Contract window.
