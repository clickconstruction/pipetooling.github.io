# v2.6030 — Walk kit: the driver reads .env under .env.local, retries a failed poll, reads a press before a restart, seeds once per kit (2026-10-28)

Punch list #142: the four paper cuts the first green walk (2026-10-23) found in the driver, none in the app (`docs/WALK_KIT.md` § Found on the first walks). No migration, no function: the `walk` function and the kernels it mirrors are untouched.

- **The keys** ([`walkEnv.ts`](../../src/lib/walk/walkEnv.ts), + test): `layerEnv` lays the main checkout's `.env.local` over its `.env` (a later file's value wins; an empty value sets nothing, so a stub line hides no key), and `missingKeyWords` names the missing key(s), the files read and the files not there. [`scripts/walk/run.ts`](../../scripts/walk/run.ts) reads both through `readEnvFiles`, and `realIo` throws those words.
- **A poll that throws is tried again** ([`walkRun.ts`](../../src/lib/walk/walkRun.ts) `waitUntil`): a `check` that throws (`TypeError: fetch failed` on a lost signal) no longer ends the run with the kit kept; the wait sleeps and polls again within its own limit, `onError` prints *poll N failed, trying again on the next: …* as it happens, and `WaitEnd.lastError` carries the last error in words (`errorWords`: name, message and cause) so a held step's *saw* names it (`waitSaw`). A wait that never succeeds still ends with what it saw, as the kit's rule says.
- **A press before the restart** (`pressWindowStart`): with `--owner-presses` the text wait opens at the kit's own `madeAt`, not the run's start, so a send made before a restart on a kept kit is read at once and marked *(pressed before this run)*, and the estimate text's ✓ delivered then reads on the text reply. `outboundLine` and `outboundCount` never take the seed (`isSeedLine`: its who, or its `walk-seed-` quo_id), so a kit older than three days cannot mistake a restart's seed for the press.
- **One seed per kit** (`seedLine`): the driver reads the kit's thread first (`SEED_READ_WAIT_MS`, 30 s, through the same retrying wait) and reports a seed already there instead of calling `seed-old` again; a thread that could not be read holds the step with its reason and makes no second seed.
- **Docs**: `docs/WALK_KIT.md` § Found on the first walks marks each item fixed and the run's two sentences say what the driver reads and how a wait behaves; the card's `status`, `next` and `ver`.

**Checked**: the walk suites (`walkEnv`, `walkRun`, and `walkDriver.run` with three new cases: a first `open` poll that throws, a channel read that always throws, and a kept kit on `--owner-presses`), lint, the typecheck, and the driver on this machine far enough to prove the layering: with no env files it names all three keys and both paths, and with the main checkout's files it gets past the key check to the deployed function. **Not run**: the live walk on prod, which sends real email and texts.
