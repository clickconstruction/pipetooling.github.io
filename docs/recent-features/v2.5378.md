# v2.5378 — The robots’ server passes its own type check again (2026-10-12)

`twin-mcp`, the MCP server the robot estimators work through, passes `deno check` again. It was the largest of the eight edge functions that v2.5359 left alone, with 68 errors. No migration and no screen. One line of emitted JavaScript changes, and it changes only where one key sits in one reply.

- **The client** (62 errors): ten helpers typed their client as `ReturnType<typeof createClient>`: `loadPricerRequest`, `pricerMayTouchBid`, `heldSubmittalTasks`, `resolvePricerHouse`, `plumbingServiceTypeId`, `disciplineRefusal`, `resolveTeacher`, `createShadowShell`, `loadSealedShadows` and `openBacktestShell`. Under supabase-js 2.117.3 (what `esm.sh/@supabase/supabase-js@2` serves today) that is a client with no schema. So 17 calls could not hand them the service-role client (TS2345). Inside `disciplineRefusal`, `createShadowShell` and `openBacktestShell`, every row read was `never` and every insert took `never` (45). They take `SupabaseClient` now, as v2.5359 did. The inserts were read against `src/types/database.ts` and exist as written: the shell's `bids` row, its `twin_shadow_runs` row and its `bids_submission_entries` line.
- **`resolveTwin`** (4 errors): it set `user` to `null`, then cast the row it read `as typeof user`. At that point TypeScript reads `typeof user` as the narrowed `null`, so the row was cast to `null`, and the eligibility check read `is_digital_twin`, `role`, `twin_kind` and `email` off `never`. The row's type is named once now, `TwinUserRow`, and both casts use it.
- **`get_answers`** (1 error): `let out = data` took the select's row type, so the blindness redaction's `Record<string, unknown>` rows could not be put back in it. `out` is a `Record<string, unknown>[]` now. It only goes to `JSON.stringify`.
- **`next_backtest`** (1 error, TS2783): the claim's reply wrote `ok: true` and then spread the shell result. That result always carries `ok: true` by then, because the loop skips a result that is not ok, so the spread always overwrote the literal. The literal is gone. **This changes the emitted JavaScript**: the reply has the same keys and values, but `ok` now comes second, after `claimed`, instead of first. Nothing in the repo reads that reply by position. The `/bid` skill and the docs only name the verb. The server stays 1.4.6, since no verb, argument or description changes.

  - Main's `index.ts` and this one, compiled by TypeScript's `transpileModule` with comments dropped, differ in that one line alone.
