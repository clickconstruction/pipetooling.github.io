# v2.4974 — Edit Job: the On the map line and geocode-one agree on who may pin (2026-10-08)

Client and the `geocode-one` function (**redeploy after merge**). PR #5023's docs pass noted that the Edit Job *On the map* line (v2.4783) showed to controllers while `geocode-one` refused them with a 403, so a controller's form read *could not place it* on every address.

## What was on each side

- **Client** ([`JobFormAddressPin.tsx`](../../src/components/jobs/JobFormAddressPin.tsx)): dev, master_technician, estimator, and `isAssistantLike(role)` — assistant **and controller**.
- **Route rule** (`isPathAllowedForRole(role, '/map')`, the nav's `canShowMapNav`, the Bid map and the Who's in map, v2.4897): the same five roles; the route test names the controller.
- **Function** (`geocode-one`): dev, master_technician, assistant, estimator — the one place without the controller. `geocode-address-batch` admits every signed-in role (v2.3131), and `address_geocodes` insert/update are open to every signed-in user, so the function's 403 was the only wall.
- **Docs** (`ACCESS_CONTROL.md` Map paragraph, `EDGE_FUNCTIONS.md`): the four-role list, which read as "controllers may not".

## The choice, stated

Two ways to agree: hide the line from controllers (the task's first reading of the docs), or admit the controller in the function. This PR **admits the controller**, because the repo's own rule (`ACCESS_CONTROL.md` §controller, from the 2026-09-27 audit, v2.3896–v2.3900) is that a function naming `'assistant'` by hand names the controller too, and `/map` already opens to controllers — hiding the line would have left the Map page's own Google refresh (also `geocode-one`) refusing them. If the owner wants controllers kept off geocoding, the flip is one line on each side: drop `'controller'` from the function and make the line read a stricter list; say so on the PR.

## What changed

- The line's gate is `isPathAllowedForRole(role, '/map', false)` — no literal list; `/map` is on the estimator's path list with or without prospects access.
- `geocode-one` names `'controller'` beside `'assistant'`; the 403 message lists five roles.
- `ACCESS_CONTROL.md` Map paragraph and `EDGE_FUNCTIONS.md` geocode-one say five roles and point at the rule; the delete policy's four-role list (no controller) is stated as such.

## Tests

`JobFormAddressPin.render.test.tsx` (+2: a controller sees the line and the address is placed; a superintendent sees no line and no lookup runs). `geocodeOne.run.test.ts` (+2: the function answers a controller with a 200; a superintendent gets a 403 with the CORS header and no upsert).
