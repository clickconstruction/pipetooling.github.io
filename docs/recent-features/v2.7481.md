# v2.7481 — Lien desk: un-print one notice from its own row (2026-11-16)

Taunya, 2026-11-16, in the run window: "I clicked printed by accident. Can you “un-print” it?" She had pressed *Printed ▸* on one checklist row. The window's only undo was More ▾ → *Take back…*, which takes back every printed notice in the run. Her run had four printed, so it would have undone three real ones. The owner was asked whether to pass a one-row undo on and said: "Yes, pass it". This sits on v2.7477 (the run window's redraw).

## What changed

- **The Printed tick is a press.** On every row the run could take back (`runPrintedItemIds`: printed here or before, no copy through Docsmit) the tick reads *✓ Nov 16 · Taunya · Undo…* and is a button (`run-check-unprint-<itemId>`). The tick's own words keep their test id. A host that hands the window no `onTakeBack` gets the words alone, as before.
- **It asks first.** `runTakeBackOneConfirm({ jobNumber, printedAt, typed })` in [`src/lib/jobs/lienRunTakeBack.ts`](../../src/lib/jobs/lienRunTakeBack.ts) words the confirm (`run-take-back-one-confirm`): *Put 372 back in Approved · to print?*, the approval stands, a copy that printed here stays in the job's Documents, the tracking numbers typed on this row are not saved (`runTypedTrackingCount`), the other notices stay. The button names the act with the job: *Put 372 back in Approved · to print*. The pile's name is `LIEN_RUN_STEP.toPrint`. *Keep it printed* and Esc close the question alone.
- **A short Undo after a mark by hand.** *Printed ▸* on a row, and *Mark N printed* under More, leave a strip (`run-marked-undo`, `runMarkedPrintedWords`): *372 is marked printed. Pressed it by mistake?* with *Undo the Printed mark*. One press, no confirm, since nothing can be lost yet. The strip goes once a number is typed on one of those rows, when the row's own press and its confirm take over. A × keeps the mark.
- **No new write.** `takeBackThese(ids)` in `LienDeskRunModal` calls the host's `onTakeBack(ids)`, which is `takeBackLienDeskItems` on the Lien desk and in Put a GC on notice. A notice already recorded as mailed is not in the run and the write skips it (`canTakeBackItem`); if the write takes nothing back the window says so and changes nothing.
- **It waits for the stamp it undoes.** A mark by hand stamps the desk through `onPrinted`, which the window does not wait on. An undo pressed a moment later could reach the desk first, find the row unprinted, and leave it printed once the stamp landed. The window now keeps the stamps in flight (`stamping`) and both take-backs wait on them.
- **The window follows in the same sitting.** `runNoticesTakenBack` clears the notice's printed day and its typed numbers, and `runSittingWithout` drops its copies, id and stamp from what printed in this sitting. The row is back in the ready part of `lienRunParts`, so the count line, the journey and the one press move: four printed becomes *4 notices = 1 ready · 3 printed*, step 2, *Print 1 notice*. A shared envelope's number stays on the notices still printed.

More ▾ → *Take back…* is unchanged: every printed notice in the run.
