# v2.3432 — Pipeline: a percent from a report or the back-fill carries its date and source on the row (2026-09-14)

## Why

v2.3418's RPC returned `pct_manual_at` — the newest `job_pct_events` row with source `manual` only. A job whose percent came from a field report (source `service`, via `propagateReportPctToJob`) or from the 2026-08-07 back-fill (source `seed`) read *40% typed* with no date, and `percentIsStale` had to treat it as stale whenever a crew had clocked in since — right for Heron's seed, blunt for a report that landed yesterday.

## What shipped

- **RPC** `list_job_crew_position(job_ids, today)` gains `pct_set_at` (the `changed_at` of the newest `job_pct_events` row of **any** source — the event that set the number the job carries now, since the trigger logs every change of `pct_complete`) and `pct_source` (that row's `seed` / `manual` / `service`). `pct_manual_at` unchanged. Drop + recreate (the OUT list changes); grants, SECURITY DEFINER, the office-only guard and the read-only nature identical to v2.3418.
- **Kernel** [`jobCrewPosition.ts`](../../src/lib/jobs/jobCrewPosition.ts): `JobCrewPositionRpcRow.pct_set_at` / `pct_source` (optional — the client deploys before the push), `JobCrewPosition.pctSetAt` / `pctSource`, `PercentSource` (`typed` · `report` · `seed`). `newestPercent` dates the typed number by `pct_set_at` and words it by the event's source; without `pct_set_at` (the old RPC shape) it keeps the v2.3418 reading (the newest hand-set, else the report that carries the same number). `percentIsStale` follows that date, so a report that landed after the last clock-in is fresh and the Aug 7 seed against a Sep 12 clock-in is still stale (+2 tests).
- **Words** [`progressPaymentCell.ts`](../../src/lib/jobs/progressPaymentCell.ts): `percentClause` reads *40% set Aug 7* (seed) · *12% reported Sep 11* (service) · *90% typed Sep 3* (manual) (+1 test, the Heron and SpaceX rows with the new columns).
- `src/types/database.ts`: the Functions entry hand-edited (two fields); a `gen-types:linked` chore PR follows the push, as v2.3422 did for v2.3418.
- Guides: *set a job's progress from the Pipeline board* and *ready to bill on the Pipeline* — the third wording named.
