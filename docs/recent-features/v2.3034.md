# v2.3034 — Test-gap audit, pass 44: Bid Board unread-note badges get their first tests (2026-09-07)

Follow-up to v2.3033. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`bidBoardNotesUnreadCounts.ts` (142 lines) is what puts the unread badge on a Bid Board card: per bid, the bid-submission notes and customer-contact notes written by other people after the viewer's last-seen watermarks, plus the three reads that feed it. One caller, no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- A note counts when someone else wrote it after the viewer's watermark for that bid and kind; no watermark means everything counts; a note at exactly the watermark is read; the viewer's own notes, unauthored notes and undated notes never count; notes on bids not on the board are ignored.
- A customer-contact note counts once for every bid of that customer, each against that bid's own contact watermark, so two bids for one customer can show different counts.
- Every bid on the board gets a number, zero included; the two kinds add.
- The fetch asks nothing without a viewer or bids, folds duplicate bid rows, reads the viewer's read state and the submission entries for the bids, reads contacts only for the bids' distinct non-blank customers, treats null results as empty, and lets a failed read throw.
