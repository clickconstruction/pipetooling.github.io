# v2.6185 — A dev's agent files a plan set for the robots, into Drive and onto the bid (2026-10-30)

PR 2 of 3 for the owner's ask after the Gun Dog intake (*"a verb to upload … so anyone with dev access can direct an agent to set up a bid for estimating"*): the plan set. The intake had the set assembled on a Mac (50 pages, 25 MB) and no door for it — `file_plans` copies from a URL only, and the owner's rule holds (plans are a Drive link, never an upload). No migration: `dev_bid_write`'s `file_plans` action shipped with v2.6183. **Deploy `dev-mcp`** after the merge (and after v2.6183's push).

- **The bytes never ride in a tool call** (25 MB is 34 MB as base64; `content_base64` caps at 10 MB for that reason). `plan_file_plans(plans)` runs the dry run — `plans = { bid, file_name, size_bytes, sha256, replace?, set_name?, memo? }` — hashes it, then hands back `upload_url`, a one-shot signed upload into `bid-submittals/<bid>/robot-plans/<sha16>.pdf` made **as the dev** (the bucket's own policy applies; two hours), with the curl line. The plan commits to the file's size and sha256, the bid's plans link before, its division and folder name.
- **`apply_file_plans(plans, plan_hash)`** re-runs the dry run, matches the hash, refuses a plan already applied, reads the staged copy back and refuses it when its size or sha256 differ, when it has no `%PDF` header or pdf-lib cannot open it, or when it runs past 200 pages (CountTooling's cap); then, as the intake service account, finds or makes the folder named for the project inside the division folder (`_shared/bidPlansFolders.ts`, the three folders the bid form's Find looks in — lifted from `src/lib/bids/bidPlansFolder.ts`, which re-exports them), uploads the PDF (a same-name file already there is reused), POSTs the RPC with `p_link = { folder_link, file_link, pages }` — `bids.plans_link` becomes the **folder** link (plan-fetch merges a folder, so an addendum dropped in later is read too) and a `bid_plan_sets` row named for the set is inserted — removes the staged copy, and runs plan-fetch's readiness probe. The reply: the Drive links, the page count, the probe and the next step. A Drive refusal leaves the staged copy for a retry and says why (a *storage quota* refusal means the division folder is not on a Shared Drive: `DRIVE_IMPERSONATE_USER`, `docs/DRIVE_INTAKE_SETUP.md`); an RPC refusal after the upload names the Drive links so a person can finish on the bid form.
- **What a user sees**: the Bid Board's plans icon opens the folder (with two or more sets, the picker names this one), the Plans button beside the bid's name reads it page by page, the readiness line reads *readable*, and the rounds claim a live plumbing bid within minutes. The set row on the bid carries the file's name and size, one file, checked now.
- **Check once, live**: the intake service account must be able to write into the three division folders (drive-intake's uploads work because the Jobs root is a Shared Drive). The first apply says so if it cannot. Docs: `EDGE_FUNCTIONS.md` → dev-mcp, `DRIVE_INTAKE_SETUP.md` (the division folders), `to-dos/mcp-servers.md`.
