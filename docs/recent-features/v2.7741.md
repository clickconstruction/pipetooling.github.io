# v2.7741 — Lien desk: a last day set by hand shows its reason (2026-11-18)

Left open by v2.7684, which named it under *Not in this PR*: the Lien desk's job read carried a day set by hand but not its reason, its time or who set it.

## What was wrong

- `LIEN_DESK_JOB_COLUMNS` (`src/hooks/useLienDeskData.ts`) selected `lien_last_work_on` and none of `lien_last_work_note`, `lien_last_work_set_at`, `lien_last_work_set_by`. The `LienDeskJob` type has declared all four since v2.4676, so nothing failed to compile.
- The line above Months on this job (`LienLastWorkDayLine`) drew *set by hand* with no day beside it and no reason, on a job whose reason was saved.
- The window under the timeline's LAST WORK stop (`LienLastWorkDayWindow`, v2.7684) seeds its reason from `lienLastWorkDay(job).note`. With no column it opened on an empty reason over a day already set by hand, and asked the office to type the reason again before *Set the day* would light.
- The Lien window and the Edit Job row read the job whole and showed all of it.

## What landed

- The three columns are in `LIEN_DESK_JOB_COLUMNS`, beside the day. The two lists built on it (`LIEN_DESK_JOB_COLUMNS_WITH_FIRST_DAY`, `LIEN_DESK_JOB_COLUMNS_WITH_MONTH_CHECK`) carry them, so every step of the desk's fallback read does, and so does the read of the jobs off the lien path.
- The GC-on-notice run (`useGcOnNoticeData`) builds its job read on the same list and reads them too. Nothing there draws them.
- No component changed. The line's chip reads *set by hand · the day it was set* through `lienLastWorkSourceLine`, with the reason in quotes after it, as in the Lien window. Neither screen looks up the name behind `lien_last_work_set_by`, so the chip names no person on either.
- The affidavit pane's press opens the same window on the same job, so it opens on the stored reason too.
- No migration (the columns are from `20261006120000_lien_last_work_day`), no edge function. The mirrored kernel `lienLastWorkDay.ts` is read and not edited.

## Tests

`LienDesk.render.test.tsx` (+1): a job cut to the columns the read names, as PostgREST hands it back, drawn in the notice pane. The line shows the day, the *set by hand* chip with the day it was set and the reason, and the press under LAST WORK opens the window on the day and on the stored reason. Against the column list before this change the test fails on the chip, which is how it holds the read and not only the drawing.
