# v2.3475 — Counts import skips CountTooling's framed heading lines (2026-09-15)

Client only; no migration, no edge function. Fix for the owner's report on BP485: after **Import from /Tooling**, a row `--- Counts × 2026 · no page` appeared at the top of the Counts list, and deleting every count and re-exporting brought it straight back.

## Cause

- CountTooling's "Copy to /Tooling" export gained a scope header on 2026-09-13 (CountTooling `b66c3b1`, D25 layer-aware copy): the first line is now `--- Counts, <project name> · every sheet · every layer ---` (or `· this sheet · layers: …`). The CountTooling side assumed PipeTooling's paste parser treats `--- … ---` framed lines as headings, the way its own summary reader does for `--- Duct ---`.
- [`parseCountsImportText.ts`](../../src/lib/bids/parseCountsImportText.ts) never had that rule. It picks the delimiter per line (tab if present, else comma), so the header split on the comma into `["--- Counts", "<project> · every sheet · every layer ---"]`; a project whose name starts with a year gave `parseFloat` → `2026`, and the line passed every check as a fixture row with no page. Re-exporting regenerates the header, so the row came back every time.

## What shipped

- **`COUNT_HEADING_LINE_RE`** (`/^---\s.*\s---$/`) in the parser: any framed heading line is dropped before the cell split — like the `View link:` footer, it is structure, not a row, and does not count toward "skipped". A fixture whose *name* merely starts with dashes but is not framed (`--- not a heading\t3`) still imports.
- Tests in [`parseCountsImportText.test.ts`](../../src/lib/bids/parseCountsImportText.test.ts): the D25 header on a year-prefixed project name, a `--- Duct ---` heading, and the dash-prefixed non-heading.

## Left alone

- The `--- Duct ---` block's rows (HVAC duct schedule, `Bid weight\t… lb`) still parse as ordinary rows if a duct takeoff is ever pasted into a plumbing bid — only the heading itself is skipped. No plumbing bid carries one today; revisit if the duct schedule starts crossing over.
- The stray `--- Counts` row already on BP485 (and any other bid imported since 2026-09-13) is data, not code: delete it from the Counts list by hand, or delete all counts and import again on the deployed client.
