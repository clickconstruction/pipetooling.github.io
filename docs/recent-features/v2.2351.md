# v2.2351 — Due dates for one-off tasks (Tier 2b) (2026-08-26)

Client + cron half of the start/due design (migration: v2.2349; Tier 1
Scheduled section: v2.2346). Rule everywhere: **effective due =
`due_date ?? scheduled/start`** — null due = exact legacy behavior.

- **Kernel** `src/lib/checklistDueDates.ts` (+tests): `effectiveDueDate`,
  `dueChipLabel` ("due Fri, Sep 4" / "due today" / "N days late"),
  `doneLateLabel` ("done N days late", company-calendar day compare).
- **Add/Edit modals**: "Due by" date row (one-offs only; hidden for
  Repeats), min = start, clear link, due < start validation; setting a due
  date locks "Stays on the list until done" on and the save forces it true.
  `checklistScheduleSummary` gains `dueDate` — "…from Mon, Aug 31 — due
  Fri, Sep 4, stays until completed."
- **Manage**: age chip is due-aware — starts (blue) / due <day> (neutral) /
  due today (amber) / late-open (red); `due_date` added to the item select.
- **Today**: cards show a due chip under the title (`dueCardChip`);
  Outstanding rows swap the red overdue line for the due-aware one;
  `sortOutstanding` re-keyed to effective due ascending (most overdue
  first — was newest-first).
- **Dashboard My Inbox**: T-n/T+n tags count to the effective due date.
- **History**: green ✓ chip gains a red "done N days late" rider
  (`ChecklistHistoryLedger`).
- **Cron `send-scheduled-reminders`** (redeploy required): day-before and
  escalate-after-N-days key on the effective due date; the daily
  due/overdue reminder is unchanged. `docs/EDGE_FUNCTIONS.md` updated.
- Materialize kernel + Deno mirror deliberately untouched — occurrences
  still land on `start_date`; changing Due by never moves occurrences.
- Help guide *schedule a task or make it repeat* → "Due by" section.
