# v2.3260 — Overhead consumers: the Days view's Charged column and per-chip dollars; Burn charges from the app setting (2026-09-10)

Client only; no migration. PR C of three (kernel v2.3258, dials v2.3259). After this ships the app default is set from the dials to the owner-approved **30 days · 20% carry · 14-day idle cap**, so Job Summary, the Days view and the Burn projection flip together.

## What shipped

- **`useJobBurnOverhead`**: reads the app-wide allocation through `useOverheadAllocationSettings` and passes it to `allocateJobOverheadDayShare(ledger, jobId, settings)`; the effect waits for the setting to load once per page so the projection never runs on legacy and then re-runs. Per field day stays `share ÷ field days` (the projection's unit is still a field day).
- **`useJobSummaryView`**: `view.overhead.allocation` — `buildOverheadAllocation(ledger, settings)` for the window (memoized; the same object `enrichJobSummaryRows` and `jobSummaryHygiene` already hit), handed to the Days view.
- **`JobSummaryDaysView`** (new prop `allocation`): when the settings differ from the original day-share, a **Charged** column (landed = by hours + carry; the carry portion named in amber beside it; hover for the split and any dollars with nobody to charge) and **· $ received** on each Worked chip (`activityUsd + carryUsd` for that job that day). Under legacy settings nothing renders, since charged = pool and each chip's share is the day-share the view already explains. Pool and Per job-day keep their meaning (the office's spend, and the concurrency unit).
- Help guide `see-how-many-jobs-ran-each-day.md`: the table paragraph (Charged, chips' dollars) and *How it ties to true profit* rewritten for the smoothed allocation.

## Not in this train

- Jobs open but never clocked inside the window are not on the ledger and receive no carry; drawing them from `job_status_events` is a loader change for a later PR.
- The pool counts approved office time only (v2.3179 moved job labor to recorded time); switching the pool needs an owner call because it also moves People → Overhead.

## Verified

Typecheck · lint · `npm test` · build; live as dev with the dials on Recommended: the Days view shows Charged with the carry note and dollars on every chip, and hides both when the dials go back to the original day-share.
