# v2.3742 — Auto-reload PR 3: reload-safe drafts (2026-09-22)

PR 3 of the auto-reload train ([v2.3740](v2.3740.md) the quiet moments, [v2.3741](v2.3741.md) the idle moment and the holds). Client only, no migration.

## What was left

After PR 2 an inline editor with unsaved edits held the reload off indefinitely — a tab left on the Form Studio with one field moved never took an update. The owner's ask was "auto reload when possible without losing changes"; the way through is to make the reload not lose them.

## The change

- **[`reloadDraft.ts`](../../src/lib/reloadDraft.ts)** (+3 tests) — `draftStorageKey(scope, id)` → `pipetooling-draft:<scope>:<id>`; `writeDraft` / `readDraft` / `clearDraft` over a storage-like, an envelope with `savedAt`, a day's `DRAFT_MAX_AGE_MS`, malformed or stale entries cleared on read, a refusing store survived. `DRAFT_RESTORED_TOAST` is the one sentence every editor shows.
- **[`useReloadDraft.ts`](../../src/hooks/useReloadDraft.ts)** — `{ read, write, clear }` on sessionStorage for a key (per tab: never another tab, another person, or a shared machine's next login; dies with the tab). The editor writes on every change while dirty (an effect on the dirty flag and the values — a commit always lands before the idle interval's next tick), reads once its own load is done so the draft wins over the server row, clears after a save.
- Wired: **`LegalFirmSettingsBlock`** (two drafts, the firm form and the particulars; the firm's id comes from the server row, not the draft), **`SubPortalPaySettingsBlock`** (day + explainer), **`SubSheetPortalFieldsBox`** (stage, payable-after, hold reason, keyed by the labor job), **`FormStudioEditor`** (schema, name, revision, doc type, keyed by the template; the note lands in the editor's own notice line). Each one's `useHoldsUnsavedWork` narrows from `dirty || saving` to the in-flight part only (`saving`, `pSaving`, `busy != null`).

## The signing forms hold instead

The signing sheets (estimate, contract, sub work order, lien release, bid room) get no draft: a ticked consent box is its own act and should not come back pre-ticked. The estimate sheet is a dialog the gate already refuses to reload over; the contract pages' inline **`ContractAcceptSignatureForm`** and both Bid Room forms now hold the reload off while a name is typed, a box is ticked or a drawing is in progress (`useHoldsUnsavedWork`).

## Verified live

On the worktree's dev server against prod, Settings → Jobs & billing: a sentence typed into the sub-portal *How pay works* box wrote `pipetooling-draft:sub-portal-pay:settings` at once; a full page reload brought the sentence back in the box, the Save button with it, and the toast *Your unsaved edits from before the app updated are back — save when ready.* Nothing was saved; the draft was removed from the tab afterwards. The other three editors share the same hook and were exercised through the unit tests only.
