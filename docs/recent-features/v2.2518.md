# v2.2518 — Finish audit closes the loop everywhere (2026-08-30)

The one-button finish (audit-loop train, after v2.2516 schema + v2.2517 tab). New
edge function **`audit-finish`** (`POST { audit_id, action: 'finish' | 'reopen' }`):

- Auth in-function (`verify_jwt = false`, ct-bridge pattern): estimator+ write
  roles, twins refused — finishing stays structurally human, matching the table's
  restrictive RLS.
- Finish: `bid_audits.status = 'done'` + `completed_at/by`, ledger stamp with the
  note/answer count, and the CT leg — `manage-user set_twin_project_review`
  (new CountTooling bridge verb, deployed) flips the twin's project to `reviewed`
  with a "Audited in PipeTooling by …" review note. Reopen: back to `pending` / CT
  `ready`.
- CT leg is fail-soft: `ct_bridge` response field reports ok/skipped/failed; the PT
  finish stands regardless.

Docs: EDGE_FUNCTIONS.md section + TOC; `config.toml` entry. UI wiring of the
Audits tab onto this function lands with the docs PR of the train.

Deploy: `supabase functions deploy audit-finish` (done alongside merge); CT
`manage-user` redeployed with the new verb.
