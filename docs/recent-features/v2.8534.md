# v2.8534 — A job's paper built from settings is reminded by email like any other (2026-11-24)

Punch list #376, call 1, answered by Diane on 2026-11-24: yes, remind it. One function: `supabase/functions/remind-person-papers/index.ts`. No migration. The function owes a redeploy after the merge.

## What was wrong

Since v2.8156 a job's paper can be built from settings (punch list #389, step 3). Its copy has no body, form or link of its own: its words are the Contract Book's clauses, put together for the job's picks when the paper is read. `send-contract-for-signature` asks the job's row whether it carries settings before it refuses a copy as one with nothing to sign (`withJobPaperSettings`). `remind-person-papers` did not ask. So while the Settings switch was on, the send set a first reminder date, and the hourly run then held the paper as one with nothing to sign and cleared the date. The paper was never reminded.

## What changed

The run reads `job_required_paper_id` with each due row and asks through the same helper, `withJobPaperSettings`, before it holds a paper as one with nothing to sign. A copy with a body, a form or a link takes no extra read, as at the send.

A read of the job's row that fails holds nothing. The paper is named under `failed` with the reason, its date stays as it was, and the next hour reads it again. Before this change a paper could only be held there, and a hold clears the date for good.

## Tests

`src/lib/contractSigningSendJobPaper.test.ts` already holds the helper and the two functions that hand out a signing link. It now holds this function too: the due read carries `job_required_paper_id`, the hold comes from the ask alone, and a failed read is named and skipped, never held.
