## What moved

- **[`StagesUnifiedJobRow.tsx`](../../src/components/jobs/StagesUnifiedJobRow.tsx)** and **[`StagesUnifiedInvoiceRow.tsx`](../../src/components/jobs/StagesUnifiedInvoiceRow.tsx)** — each branch body verbatim (dedented), taking `row` (narrowed to its kinds with `Extract<StageRow, …>`) and one context `t`.
- **`StagesUnifiedRowContext`** (exported by the table) is the table's props **after defaults** (`Required<Pick<…>>` over the five defaulted keys, `Omit` for the rest) plus the fifteen helpers the table builds once per render — the row-render context, the five `render…` wrappers, the column count, the flash style, the four style constants, the thread-row bundle, the wide-viewport flag. The table builds `rowCtx` once as `{ ...props, <defaults>, <helpers> }`; each row file destructures only the names it uses (49 for the job row, 45 for the invoice row — derived by scanning the branch text and letting the compiler prune the rest).
- **Keys are unchanged.** `stagesUnifiedRowKey` in [`lib/jobs/stagesUnifiedRowKey.ts`](../../src/lib/jobs/stagesUnifiedRowKey.ts) (+ test) is the same `job-…` / `job-…-billed-…` / `job-…-rtb-…` / `inv-…` scheme the map computed inline, so React reconciles a section exactly as before.

Numbers: `JobsStagesUnifiedTable.tsx` 1,096 → 442 lines; the two row files are 431 and 358 with headers. The whole `JobsStages*` surface the map covers: **6,934 → 6,241** across more files, with the tab itself at 4,861 (from 6,598).
