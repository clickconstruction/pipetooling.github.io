# v2.1934 — Partnerships Statements: archive-aware close card (2026-08-21)

The "Close week" card on Partnerships → Statements hardcoded its target to last week (`getDefaultWeekRange().start − 7`), blind to the archive — once that week's statement was generated, the primary button became a dead end that could only answer "Statement for that week already exists" until the next Sunday advanced the pointer. It also had no path to older uncovered weeks: `generate_partner_statement` accepts any `p_week_start`, but the UI only ever offered exactly one week.

New kernel [`statementCloseWeeks.ts`](../../src/lib/partnerLedger/statementCloseWeeks.ts) (`planStatementClose`, 7 tests): given the archive's `period_start` list (normalized to company-week Sundays via `companyWeekStartSundayContaining`) and the current week's Sunday, it returns the close target (last completed week, only while uncovered), a `prevWeekClosed` flag with `nextOpensOn`, and `olderUncovered` — completed weeks inside the archive's own span with no statement, oldest first (weeks before the earliest statement are out of scope). [`PartnershipStatementsTab.tsx`](../../src/components/partnerships/PartnershipStatementsTab.tsx) now renders: "Close week of X" with the generate button while last week is open; "Week of X closed ✓ · next close opens Sunday Y" with no button once it's generated; and a chip row of older uncovered weeks ("generate if hours were worked") that feeds the same guarded RPC — the override checkbox stays visible whenever any generate action is offered. Client-only — no migration.
