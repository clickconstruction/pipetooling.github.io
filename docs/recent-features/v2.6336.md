# v2.6336 — Search every file deeply, PR 3: our own OCR for scans, Document AI behind a secret (2026-11-02)

Punch list #240's third PR, on the card's recommended default: **Google Document AI's Document OCR processor** in the `pipetooling-drive` GCP project, the processor read from the secret `GOOGLE_DOCAI_PROCESSOR` at call time. The code is complete and deployed; the provider answers only once the owner's one step is done (`docs/DRIVE_INTAKE_SETUP.md` → Our own OCR). Migration `20261102050700_file_index_ocr.sql` (`docs/migrations/20261102050700_file_index_ocr.md`); `drive-link`, `file-index-sweep` and `dev-mcp` redeployed after the push.

- **The provider behind one module.** `_shared/ocr.ts`: `ocrSetup(saJson)` reads the secret (null when unset or malformed, logged); `cloudPlatformToken` mints the service account's token with the cloud-platform scope (the same JWT grant as Drive's, written here so `driveUpload.ts` and its fifteen importers stay as they are); `ocrText(setup, bytes, mime)` POSTs the bytes inline to `:process` with `skipHumanReview` and `processOptions.fromStart = 15` and answers the text and the page count, or the provider's own reason in one line, never throwing; `OCR_PROBE_PNG` is the one-pixel document the probe sends. The rules are pure in `_shared/ocrKernel.ts` (`ocrMimeOf`: a PDF and the common pictures, never HEIC; `ocrEndpoint` from the processor name; `ocrRequestBody`; `ocrReadAnswer`; `ocrDue`; the state words), tested from `src/lib/documents/ocrKernel.test.ts`.
- **In the pass.** `indexContext(admin, google, saJson)` carries the setup; `indexOneFile` sends a scan (`fileText` answered `scan`, the kind one Document AI takes, under 20 MB) through it and keeps the text with `text_source = 'ocr'` and `pages`; a refusal keeps the row a `scan` with `ocr_tried_at` now and `ocr_note` the reason. `indexPlan` takes a scan once OCR is set up when the row is due (never tried, or tried over a day ago; `KnownRow.ocr_tried_at`), so `index_job` and the backfill's apply catch the held scans up; `ocrPending` / `ocrPass` are the sweep's queue, oldest try first, inside the budget.
- **The sweep's fourth step**: `ocr` (5) scans due per run once set up, the counts in the answer (`ocr: { set_up, tried, read, refused, gone }`) and the line; a scan Drive no longer answers for, or trashed, is stamped tried with the reason so it leaves the queue's head.
- **Hardened in review before the push.** Every `image/*` file is a scan to the index, but Document AI reads only a PDF and the common pictures, so a phone's HEIC was due for OCR forever (`ocr_tried_at` never stamped): it held the sweep's five slots every run and kept a job of such photos from ever reaching `remaining` 0. Now `indexPlan` takes a scan for OCR only when `ocrMimeOf` knows the kind, `ocrPending` filters on `OCR_MIMES`, and a kind outside them is stamped with `OCR_KIND_NOTE`. The request carries `fieldMask: text,pages.pageNumber` and `imagelessMode`, so the answer is the text and not every page's image and layout, and it is waited for `OCR_READ_MS` (twenty seconds) under an `AbortController`. Every pass makes at most `OCR_PER_PASS_MAX` (five) OCR calls (`indexPlan` names the rows due for OCR alone in `forOcr`; past the cap they are left untaken, so `remaining` counts them and the sweep's cursor stops at them), which keeps the request's CPU budget and paces the spend. A scan whose download resets is refused for the day, never the whole pass. `FILE_FIELDS` asks for `trashed`, so the OCR step skips a trashed scan. A scan's base64 and request body count on the pass's clock (`ctx.spend`, PR 2's budget), and the OCR step stops when it is spent. A scan past Document AI's inline cap is stamped once and never due again (`ocrTakes`): since v2.6408 a PDF over 12 MB is `big` before it is ever a scan, so this is a photo over 20 MB, which would have spent a slot and a download every day.
- **The probe**: `drive-link` `{ action: 'ocr_probe' }`, a dev's one made-up call: a one-pixel PNG to the processor, the provider's own words back (`configured`, `secret`, `words`, `answer`; `answer` null while the secret is unset). Run after the deploy and again after the owner's step; the card's *Where it stands* quotes what it said.
- **Words.** The guide's *What the search reads* says a scanned paper is read with OCR once the office has it set up, and what OCR is.
- **Left for the owner** (the one step): in the `pipetooling-drive` GCP project enable the Document AI API, make a Document OCR processor in `us`, grant `drive-intake@pipetooling-drive.iam.gserviceaccount.com` the role `roles/documentai.apiUser`, then `supabase secrets set GOOGLE_DOCAI_PROCESSOR=projects/<number>/locations/us/processors/<id>`. Nothing redeploys: the secret is read at call time. Cost: about $1.50 per 1,000 pages, fifteen pages per scan at most.
