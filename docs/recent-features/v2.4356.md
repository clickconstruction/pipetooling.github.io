# v2.4356 — A click outside a window no longer opens or shuts the row behind it (2026-10-01)

No migration, no edge function. The rows [v2.4352](v2.4352.md) left open: the same bubbling reaches a row that opens on a click.

## Why it happened

A window drawn inside a row sits inside that row in React's tree. A real click on its backdrop closed the window, then bubbled to the row's `onClick`. Each row skips clicks on links, buttons and fields, but a backdrop is a plain `div`, so the row toggled too.

## What changed

Each window's backdrop stops its click before closing — `onClick={(e) => { e.stopPropagation(); onClose() }}` — so the fix holds wherever the window is drawn:

- Bid Board → a GC's notes ([`BidGcNotesPopover`](../../src/components/bids/BidGcNotesPopover.tsx)): a click outside them opened or shut the bid's row, on the desktop table row and the phone card alike.
- Checklist → Review → Cost this task ([`ChecklistCostModal`](../../src/components/checklist/ChecklistCostModal.tsx), dev and controller only): a click outside it showed or hid the task's activity. The Roadmap plan view and Goals draw the same window with no row toggle.
- Mark account opened ([`MarkJobAccountOpenedModal`](../../src/components/materials/MarkJobAccountOpenedModal.tsx)), keeping its target check. `check-nested-windows.mjs --rows` listed it under the Bid Board row through `BidWonJobActions` → `BidJobAccountsRow`, but the board draws `BidWonJobActions` compact, which never draws the accounts row, and the board's own chips ([`BidBoardJobAccountChips`](../../src/components/bids/BidBoardJobAccountChips.tsx)) already stop the click. Walked live, it closed alone before the fix. It now stops its own click like the others, so the check reads clean and the sheet holds wherever it opens.

## Found, not fixed

- `--rows` counts a container as a row only when a child within two levels stops the click. That misses the desktop Bid Board `<tr>` (fixed here all the same, same window) and the Pipeline rows. Without that filter it lists two Pipeline cases: the Send from Stripe confirm ([`StripeInvoiceSendFromStripeButton`](../../src/components/jobs/StripeInvoiceSendFromStripeButton.tsx)) stops only `mousedown` on its panel, so a click on its text toggles the row's thread (and a click outside it too once [v2.4347](v2.4347.md) moves its backdrop to `onClick`); on the phone cards a tap on the open thread, inline or full screen, toggles the thread shut.
- Press and hold: the Bid Board row's hold to mark ([`bidMarkHold.ts`](../../src/lib/bids/bidMarkHold.ts)) and the Checklist row's hold to drag (dnd-kit, 280 ms) take a press from inside a window drawn in the row. A half-second press in the GC notes marks the bid behind and swallows the click that follows; one in Cost this task lifts the task behind. The check cannot see either (the handlers are spread onto the row). Not walked live, since both write.
