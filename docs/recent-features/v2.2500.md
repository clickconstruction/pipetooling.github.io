# v2.2500 — Robot Board: People|Robots scope on the Bid Board (2026-08-30)

Owner decision (amending DIGITAL_TWINS_PLAN's "twin bids sit on the shared board"): as the
estimator-twin fleet took on real bids, twin rows started polluting the human board's
rollups and duplicating projects humans also bid (BP396 vs b403 = the same building). The
amendment keeps "visible, never fenced" but as a **lens, not a wall**: same data, same
board component, two scopes one click apart.

- `src/lib/bidBoardScope.ts` (+tests): `isRobotBid` / `partitionBidsByScope` — a bid is a
  robot bid when its assigned estimator OR creator is a flagged twin
  (`users.is_digital_twin`). Twin ids load without an archived filter (a retired twin's
  bid stays with the fleet).
- `src/pages/Bids.tsx`: 🤖 **Robot Board** tab beside Bid Board (`?tab=robot-board`),
  rendered only when robot bids exist, label carries the live count. Both tabs render the
  same `BidsBidBoardTab` — the human board gets the people partition, so every section
  count and pill scopes for free. Separate section-open state per scope. `?bidId=` deep
  links route to whichever board holds the bid.
- Deliberately deferred: Followup / Unsent-Working / clock quick-pick surfaces stay
  unscoped until twin noise actually shows up there; Why-we-lost queue counts still
  include twin bids.
- Help: `read-the-bid-board.md` gains the Robot Board section (incl. the "bid disappeared
  after assigning the twin" example). Twin docs: APP_DIRECTORY row (briefs regenerated,
  twin-mcp redeployed), DIGITAL_TWINS_PLAN decision amended.
