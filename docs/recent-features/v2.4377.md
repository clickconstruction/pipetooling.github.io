# v2.4377 — Pricing: a version’s ★ base is always one of its own prices (2026-10-01)

Found 2026-10-01 on BP385 Galloway Park (bid `efdae022-8366-488b-9e42-dbb3225491d9`). Both versions, *Written to Plan* (the active base) and *Value Engineered* (an alternate), had `bid_versions.starred_price_book_version_id` = Value Engineered’s price `731c244e`, and `bids.selected_price_book_version_id` named it too. A version’s ★ is meant to be one of its own prices (v2.2117). The letter already ignored a ★ that is not the version’s own and used the version’s first price (`starredPricingIdForVersion`, and the Approval PDF through `deriveActivePricingId` since v2.4373). The Pricing tab read the column raw, so Written to Plan’s own card drew *☆ make base · On their letter · alternate*. The version picker counted the raw ★ plus each offered price, so the GC “gets 3 prices” while the letter has two sections.

## How the stray ★ got written
`confirmDeletePricingVersion`: deleting the price open on the Workbench re-picked `pickActivePricing({ savedVersionId: null, bidPricings: remaining })`. `remaining` was every price on the bid, so the pick was the lowest `sort_order` on the whole bid, and `saveBidSelectedPriceBookVersion` saved it as the active version’s ★ and the bid-level ★. On a split bid that is usually another version’s price. Both prod rows carry this fingerprint: BP385’s stray ★ is the bid’s sort-0 price, and BP384 NORTHSTAR’s is PlanHub’s *WENDI*, the lowest price left after sort 0 and 1 were deleted (BP384’s prices start at sort 2). In both, the bid-level ★ is the same price and the stray version is the active one.

Other doors, closed in the same change: *☆ make base* on the fallback cards row (a version with no price of its own shows the bid’s other prices, v2.2404) and a version switch landing mid-save (the save read the active version after its first await). Version cloning never writes a foreign ★: `create_bid_version` stars one of the new version’s own clones.

## What changed
- **The kernel** [`lib/bids/versionStar.ts`](../../src/lib/bids/versionStar.ts): `resolvedStarPricingId` (the ★ the letter reads: a split bid’s `starredPricingIdForVersion`, an unsplit bid’s new `unsplitStarPricingId`, then a legacy shared book as it is); `starWriteAllowed` (a split bid stars only the active version’s own price, or clears it); `letterPriceCountByVersion` (the sections `planLetterSections` draws with a price); `afterOpenPriceDeleted` (open the version’s ★, never save on a split bid; an unsplit bid re-stars only when the deleted price was the ★).
- **The write** (`useBidPricingEngine` `saveBidSelectedPriceBookVersion`): reads the active version once at the start, asks the database who owns the price, and refuses another version’s with *That price belongs to another version. Open that version to make it its base.* It now resolves `true` / `false`, and a failed version stamp reports instead of passing silently.
- **Pricing tab:** `customerFacingPricingId` = `resolvedStarPricingId`; the delete path goes through `afterOpenPriceDeleted`, and it refuses to delete the version’s resolved ★ (no trigger guards a stand-in ★); *Make base* stops before its toast when the save is refused. Share / Print / CSV take the ★ from the tab (`useStarAwareShare` `starPricingId`), not the bid column, which names the last version starred after a switch (BP18, BP338 and BP363 asked about the wrong ★ before).
- **Cards row:** `cardOwnedByVersion`. A card the version on screen does not own reads *Another version’s price* with no *make base* or *offer* button. The solo band hides *☆ Make base…* the same way.
- **Version picker:** one read of the bid’s prices; *gets N prices* = `letterPriceCountByVersion`; the *Start from* names, *★ stays on …* and both clone hints use `starredPricingIdForVersion`.

## Left as it was
- The two stray rows on prod (BP385 Written to Plan, BP384 NORTHSTAR) wait on the owner. A repair would point each at the ★ the letter already reads, and the bid-level ★ with it.
- The package map (`buildPackageMap` still claims a version’s saved ★, with its legacy shared-book fetch), the own-takeoff alternate card’s revenue (`useAlternateVersionData`) and the *Copy … base price* donors still read the saved column. They agree once the two rows are repaired.
- The help guide *send a bid pricing package* uses BP385 in its *Send both prices* example (“the customer’s price is ★ Value Engineered”). That came from this bug. The guide is on the plain-words legacy list, so it changes with its rewrite.
