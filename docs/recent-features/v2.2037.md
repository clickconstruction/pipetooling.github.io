# v2.2037 — Portal visit picker: properties, not jobs (2026-08-21)

Owner-picked variant A of the "Portal Visit Picker" mockup. The statement's
Request-a-visit "For" control drops the native `<select>` of job labels
("Knight Contracting- Reliant Health · Job 789") for **ruled address rows** —
customers pick the property; job numbers and internal job names never render.

- **Kernel `_shared/portalProperties.ts`** (vitest:
  `src/lib/portal/portalProperties.test.ts`): non-paid jobs with an address →
  one row per exact-normalized address (case/whitespace-insensitive, never
  fuzzy — suites don't merge), street + city with trailing state/zip
  stripped, newest job (highest job number) both ordering rows and standing
  behind each address.
- **Edge fn `customer-portal`**: payload gains `requestableProperties`
  (`{jobId, street, city}`, capped 50); `requestableJobs` stays for
  stale-bundle clients. **Redeploy required.**
- **`CustomerPortal.tsx`**: new `PropertyRow` — hairline-ruled label rows
  with a copper pip, real radios underneath (keyboard/VoiceOver free,
  focus-visible ring via a scoped style tag), "Something new" first and
  default, first 5 properties shown + "Show all N properties" expander.
  `submit-portal-request` contract unchanged (still sends `jobId`).
- `portalPayload.ts` parses the new field defensively (+tests); help guide
  example updated.
