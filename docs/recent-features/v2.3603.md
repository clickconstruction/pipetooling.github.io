# v2.3603 — Pipeline load speed: the tab-switch TTL — a switch back within 30 s is free (2026-09-18)

The small, independent piece of [`to-dos/pipeline-load-speed/README.md`](../../to-dos/pipeline-load-speed/README.md) (the to-do's "also": *a same-key TTL on tab-switch refetches*). Client only; the screen does not change. With it, PRs 1–3 and this leave only PR 4 (owner-gated) on the to-do.

## The change

- **The rule** — [`lib/jobs/boardRefetchTtl.ts`](../../src/lib/jobs/boardRefetchTtl.ts) `boardIsFreshForTab` (4 tests): a tab-switch load is skipped when the rows belong to the same key (user + customer filter), the last load for that key completed less than 30 s ago (`BOARD_TAB_REFETCH_TTL_MS`), and every scope the tab wants is already merged. Anything else reloads: another key, a first load, a scope the rows do not hold, the window passed (the edge reloads).
- **The cache** ([`JobsListCacheContext.tsx`](../../src/contexts/JobsListCacheContext.tsx)): `RefetchKind` gains `'tab'`; `runFetchJobs` (wanting every non-paid scope) and `runFetchScopes` (wanting the open sections' scopes) return at once when `kind === 'tab'` and the board is fresh. Mutation refreshes, `scheduleLoadJobsAfterMutation`, the visibility refresh and a customer-filter change never pass `'tab'`, so they behave as before.
- **The page** ([`Jobs.tsx`](../../src/pages/Jobs.tsx)): the `activeTab` effect's load is `loadJobsScopedForStages({ kind: 'tab' })` on Pipeline and the new `loadJobsForTab` (`runFetchJobs(…, { kind: 'tab' })` + the header stats on their own TTL) on the other list tabs; `loadJobs` — the post-mutation path with its forced header refresh — is untouched.

## Measured (dev server, prod data; Pipeline loaded, every section open; then Parts, then back to Pipeline within ~5 s)

| | before | after |
|---|---|---|
| Requests on the switch back to Pipeline | 54 | **28** |
| Board reloads on the switch back (`jobs_ledger` · enrichment) | 6 · 3 | 0 · 0 |

| Requests on the switch to Parts | 58 | 54 (its full-list load skipped too; the card-charge loader it owns still runs) |

What the switch back still costs is not the board: the labor loaders the Burn feature arms on Pipeline (`people_*`, 11 requests), the map's geocodes, and the per-tab one-shots (evidence gaps, owner-to-confirm, bank-payment counts). Those are the next count to look at if Pipeline is still felt to be slow to come back to.
