# v2.5376 — Five more server functions pass their own type check again (2026-10-12)

A type-only fix to five edge functions that `deno check` refused on errors in their own `index.ts`. They are five of the eight that v2.5359 left alone. No migration and no screen. Nothing behaves differently.

- **The fault**: each typed its client as `ReturnType<typeof createClient>`. Under supabase-js 2.117.3 (what `esm.sh/@supabase/supabase-js@2` serves today) that type resolves to a client with no schema, `SupabaseClient<unknown, …, never, never, …>`. So the real client, `SupabaseClient<any, "public", …>`, could not be handed in, a write through it took `never`, and a row read through it was `never`. `supabase functions deploy` does not type-check, so nothing failed at runtime.
- **The fix**, in types alone:
  - `dev-mcp` (`Admin`), `geocode-one` (`upsertGeocode`), `get-stripe-invoice-details` (`adminForSub`), `notify-dispatch-request` (`notifyRequester`) and `notify-team-lead-clock` (`AdminClient`) type the client as `SupabaseClient`, as v2.5359 did.
  - `notify-dispatch-request`'s outer `catch` read `error.message` off an `unknown` (TS18046). It reads `(error as Error).message` now, as `change-user-email`, `invite-user` and `send-sign-in-email` do. What its `try` can throw (a body that is not JSON, VAPID keys web-push refuses) is an `Error`. Its push sends catch their own.
  - The writes and reads the errors flagged were read against `src/types/database.ts` and exist as written: the `dev_mcp_credentials` and `dev_mcp_calls` columns in `dev-mcp`, the `address_geocodes` upsert on its key `address_normalized` in `geocode-one`, the `jobs_ledger_invoices`, `jobs_ledger_team_members` and `job_collect_payment_flows` columns in `get-stripe-invoice-details`, the `notification_history` columns in both notifiers, and `trial_helper_supervisors(p_helper_user_id, p_work_date)` in `notify-team-lead-clock`.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3) of the five went from 26 errors to 0 on `main`: `dev-mcp` 8, `geocode-one` 5, `get-stripe-invoice-details` 7, `notify-dispatch-request` 3, `notify-team-lead-clock` 3.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
  - `node scripts/build-dev-mcp-catalog.mjs` leaves `dev-mcp/catalog.ts` as it is. The tests that read these sources pass, `geocodeOne.run.test.ts` among them, which runs geocode-one's own handler.
- **Left alone**: the other three carry the same fault with other errors beside it. `gc-card-bill` and `plan-fetch` follow in v2.5377, `twin-mcp` in v2.5378.
- **Deploy**: redeploy the five once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
