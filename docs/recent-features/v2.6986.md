# v2.6986 — The dev seat reads counsel-only material (2026-11-12)

The owner, 2026-11-11, to a session reconciling an HR file: "Because only devs and council can see the council only things, I think it's totally fine for an agent to, And we can drop the security around council only decisions, for now." Asked whether that reaches the records an agent's notes had kept closed and the passages on a minor or a medical matter: "Yes, those too."

## What changed

- **Migration `20261112090000_dev_seat_reads_counsel_only.sql`** ([doc](../migrations/20261112090000_dev_seat_reads_counsel_only.md)): a switch, `counsel_only_held_from_seat()`, that answers `false`. The six restrictive seat fences (`person_file_evidence`, `person_file_attachments`, `file_index`, `legal_matter_documents`, `documents` for a matter's text, `person_file_amendments`) and `dev_matter_doc_read`'s refusal now ask it beside `request_is_dev_seat()`, so they let the seat through. No policy is dropped. Putting the fence back is one migration that makes the switch answer `true`.
- **`dev-mcp` 0.76.0**: a counsel-only record and a counsel-only matter document come back with the rest, each marked `counsel_only: true` (`get_person_file`'s evidence, `get_case_brief`'s matter documents; the evidence list already carried the mark). `search_case` carries a counsel-only record's title on a transcript hit. `get_matter_document` reads a counsel-only paper. `held` on `get_person_file` and `counsel_only_held` on `get_case_brief` count only the counsel-only items a definer's count names that the read did not hand back (`_shared/devMcpCounselOnly.ts`), so they read 0 now and would name the hold again if the switch were shut. `apply_person_evidence` on a counsel-only record says the seat reads it back.
- **Words**: the Add evidence tick (`PersonFilePanel`), the matter document's tick and chip tip (`COUNSEL_ONLY_DOCUMENT_WORDS`) and the guide *keep private employee files* now say devs and the dev seat read counsel-only material and the HR agent's key does not.

## What did not change

The owner's condition is that only devs and counsel see this material. So the Drive filer still skips a counsel-only record, the firm's portal still locks a counsel-only paper and the printed packet still leaves it out, and the `hr_agent` key is still refused a counsel-only record's files and links. Every fence still sits behind the tables' dev-only policies.
