# v2.2857 — "Add document" on a sub's row and their Desk: COI / W-9 get a front door; name-vs-type retype hint (2026-09-05)

Journey-map Phase 4, Tier-2 #33 (J32-F4 "the subs compliance column is red org-wide", J32-N1 "COI / W-9 have no creation path", J32-N2 "any signed contract reads as the sub's Agreement"). Client-only; no migration.

## Why

`buildSubComplianceBadges` was always truthful — `COI missing` means zero rows with `doc_type = 'coi'` — but the only way such a row could come into being was to mint a contract on People → Contracts and then re-type it in the Subs tab's Documents expander (`updateDoc` was the tab's sole write; the expander had no `.insert`). Live counts before this PR: 0 COI rows ever, 2 W-9. The Person Desk's Paperwork section (v2.2710) added readers of the same rows and no door either.

## Mechanism

**Kernel** — [`src/lib/people/subDocumentDraft.ts`](../../src/lib/people/subDocumentDraft.ts):
- `SUB_DOCUMENT_TYPES` (coi / w9 / license / agreement / other, each with a label and a default name such as `COI (filed)`).
- `subDocumentDraftValid(draft)` — the Save gate: a type is required; a COI requires an expiration (`SUB_DOCUMENT_TYPES_REQUIRING_EXPIRY`); an expiry, when present, must be `YYYY-MM-DD`; a file link, when present, must pass `normalizeCustomerAttachmentUrl` (https only).
- `buildSubDocumentInsert(draft, person, nowIso, lineageId)` — the `person_contract_documents` row: `doc_type` set from birth, `status = 'signed'` + `signed_at` (filed paperwork is "on file"; the Paperwork rollup colours unsent/sent red/blue), `expires_at`, `url` (the existing Contracts "Upload signed" path also stores a Drive **link** — there is no storage-bucket upload for person documents, so this reuses the link column rather than inventing a bucket), `contract_lineage_id` fresh, `lineage_version = 1`, `person_id` + `person_name`.
- `suggestSubDocumentType(name)` / `suggestedRetype(doc)` — see the N2 note below.

**Shared door** — [`src/components/people/SubDocumentAddForm.tsx`](../../src/components/people/SubDocumentAddForm.tsx): inline form (type · expires · link · name · Save/Cancel). Nothing is written until Save (decision 17); the type select refreshes a still-default name. On success: `recordNavClick(userId, role, 'sub_document_added', '#<type>')` → `ui_nav_clicks`, then `onSaved()`.

**Two mounts:**
- [`PeopleSubsTab.tsx`](../../src/components/people/PeopleSubsTab.tsx) Documents expander — `+ Add document` next to the heading; the form sits above the row list; on save the tab reloads (`load()`), so the badge column re-computes in the same paint. The `?? 'agreement'` fallbacks at the docs mapper and the type `<select>` are gone — `doc_type` is `NOT NULL` in the DB (typed `string` in `database.ts`), so the fallback was dead code that also hid the N2 problem. Empty-state copy points at the new button.
- [`PersonDeskPaperworkSection.tsx`](../../src/components/personDesk/sections/PersonDeskPaperworkSection.tsx) — `Add document` in the "On file" row's actions (gated `canEdit = viewer.canAccessContracts && !readOnly`, and requires a pay name to key the row); the form renders as its own Desk row; save toasts and bumps `onChanged()` so the Portal section's badges and the facts strip refresh.

**N2 — "any signed contract reads as the Agreement".** The migration `20260801200000_contract_doc_types_expiry.sql` made `doc_type NOT NULL DEFAULT 'agreement'`, so there is no NULL / "untyped" state to render: every Contracts-tab mint arrives as an Agreement by DB default, indistinguishable from a deliberate one. The honest signal available without a migration is a **name that disagrees with the type**: `suggestedRetype` fires only for rows still typed `agreement` whose name matches W-9 / COI (incl. "certificate of liability insurance") / license, and the Subs expander renders an amber `Looks like a W-9 — set type` pill that runs the existing `updateDoc(id, { doc_type })`. Rows typed `other` or already typed are left alone. A true "untyped" state would need `doc_type` to lose its default (or a `doc_type_source` column) — noted as a follow-up, not done here. The W-9 *form template* path already self-types via the `contract_docs_set_form_template` trigger (v2.2830-era); this PR does not touch `PeopleContractsTab.tsx` (another Phase-4 builder owns quick-send there), so custom "Upload signed" mints still default to agreement and rely on the hint.

**Paperwork rollup** — [`paperworkRollup.ts`](../../src/lib/people/paperworkRollup.ts) appends ` · COI` / ` · W-9` / ` · License` to the chip `detail` (tooltip) for typed compliance rows; agreements and `other` stay quiet.

**Roles.** The `person_contract_documents` INSERT policy (baseline) is `is_dev() OR is_pay_approved_master() OR is_master_or_dev() OR is_assistant_of_pay_approved_master() OR is_assistant()`, and `is_assistant()` has meant assistant-or-controller since the v2.714 controller widening — so dev, master_technician, assistant and controller can add. The Subs tab mirrors that set in `CAN_ADD_DOCUMENT_ROLES` (and hides the button under training mode); the Desk uses its existing `canAccessContracts` gate, which resolves to the same four roles in `usePeopleAccess`.

**Telemetry.** `ui_nav_clicks` rows with `control = 'sub_document_added'`, `target = '#coi' | '#w9' | '#license' | '#agreement' | '#other'`. The row to watch is the live count of `doc_type = 'coi'` moving off zero; the invariant is that a sub whose badge reads `COI ✓` has a `coi` row with a future `expires_at`.

## Tests

- `src/lib/people/subDocumentDraft.test.ts` — validity (type required; COI needs expiry; W-9/license/agreement do not; date shape; https-only link), the insert payload (typed from birth, on-file status, name default vs typed, null person id), and the name → type suggestions incl. "fires only on the DB default".
- `src/lib/people/subCompliance.test.ts` — new case: a typed COI with a future expiry clears `COI missing` → `COI ✓`; blank / unknown types count as nothing (equal to the empty badge set). Kernel logic unchanged.
- `src/lib/people/paperworkRollup.test.ts` — typed detail suffix; agreements quiet.
- `src/components/people/SubDocumentAddForm.render.test.tsx` (jsdom) — no insert on open; Save with COI + no expiry shows the kernel's reason and inserts nothing; a valid COI inserts exactly one typed row and records `sub_document_added #coi` for the assistant role.
- Existing `PeopleSubsTab.render.test.tsx` unchanged and green.

## Verify

1. As a master or assistant: People → Subs → a sub with `COI missing` → **▶ Documents** → **+ Add document** → type *COI — insurance certificate*, leave Expires blank → Save → "A COI needs its expiration date." and nothing saved. Set an expiry next year → Save → the row appears as `COI (filed) (signed)` typed `coi`, and the Compliance column now reads {{chip:green|COI ✓}}.
2. Same sub → Person Desk → Paperwork → **Add document** → W-9 → Save → toast "Filed — the compliance badge updates now"; the chip `W-9 (filed)` shows with tooltip `signed <today> · W-9`; the Portal section's badges lose `W-9 missing`.
3. A sub with a Contracts-minted document named "COI 2026" (typed agreement by default) shows `Looks like a COI — set type` in the expander; click → the pill disappears and the badge flips.
4. As a controller the buttons show and the insert succeeds; as a training-mode (read-only) viewer neither button renders.
5. `select target, role, count(*) from ui_nav_clicks where control = 'sub_document_added' group by 1,2` and `select doc_type, count(*) from person_contract_documents group by 1` — `coi` leaves zero.

## Rollback

Revert the PR. Rows filed through the door are ordinary `person_contract_documents` rows (typed, status signed) and stay valid for the old expander; telemetry rows are inert.
