# v2.5095 — Submittals: a reviewer's file puts a revision answered by email on the GC's page (2026-10-09)

Punch list #62 (`to-dos/see-what-they-see.md`), the owner's pick (b) of 2026-10-09, directed by PUNCHLIST. Client and edge-function source. No migration. Three edge functions to redeploy after merge.

## Why

v2.4667 put a revision answered by email on the GC's record when it held a reviewer's answer and had a built package. The package was the guard against an answer typed by mistake publishing a never-sent draft. BP398's Rev 3 was answered by email on Oct 2, then superseded before it had a package. Build package turns on only for the newest draft, so the office had no way to put Rev 3 on the GC's page. The owner picked (b): a reviewer's file dropped in step 6 is the office's own evidence that the revision went out and came back, so it counts as the package does.

## What changed

- **The rule, `supabase/functions/_shared/submittalRecord.ts`.** A revision is on the record when it was shared, or when it holds a reviewer's answer AND has a built package or a reviewer's file (`bid_submittals.reviewer_files`).
  - `hasReviewerFile(json)` reads the column the way the tab's `parseReviewerFiles` does: an entry with a path.
  - `recordStanding` takes `hasReviewerFile`; `revisionStandings` reads each revision's `reviewer_files`; `RevisionStanding` carries `hasReviewerFile`.
  - `loadRevisionStandings` selects `reviewer_files` with the revisions.
  - The standing `waits_for_package` keeps its name and now means: answered, with no package and no reviewer's file.
- **The three functions** import the rule and change only in their comments: `get-submittal-room`, `open-submittal-pdf`, `submit-submittal-review`. `open-submittal-pdf` still needs a `package_path`, so a revision on the record by its file alone has no download.
- **The GC's page** (`SubmittalRoom.tsx`): such a revision's footer reads *This revision went out by email. Its PDF is not here.* instead of *The PDF is on its way.*
- **The office** (`seeWhatTheySee.ts`, `BidsSubmittalsTab.tsx`):
  - Step 6's heads-up (`emailedRecordLine`) counts a reviewer's file as a package, and its waiting words read *once it has a package or a reviewer's file*.
  - The What the GC sees window's list line (`linkListLine`) reads the same.
  - The tab re-reads the record when a file is dropped or removed (`revisionsKey`).
  - Removing the last file from a revision that is on the GC's page by it, with no package, warns: *Rev 3 then leaves the GC's page, because it has no package.*
- **Docs**: `docs/EDGE_FUNCTIONS.md` (the three sections), `GLOSSARY.md` → Review room, `BIDS_DOCUMENT_TABS_ARCHITECTURE.md` → SU-9, the guide *build a submittal package*, `to-dos/submittals/README.md` and the #62 card.
