# v2.6950 — The dev seat changes a property record: the first of the Lien desk's verbs (2026-11-11)

The owner, 2026-11-11, after the county's page showed a homestead exemption on a property with an approved lien affidavit and the seat had no verb to mark it: *help me improve the dev verbs to manage the lien desk so long term everything a user can do a dev can do and eventually we can make and manage filing through this chat.* This is the first PR of that train.

## What changed

- **`plan_property_record` → `apply_property_record`** (`supabase/functions/_shared/devMcpPropertyRecord.ts`, server 0.71.0). The save the Property record row on Edit Job, Edit customer's Properties and the Lien desk's property window make: one PATCH on `customer_addresses` under RLS, as the dev. `record = { job_id | property_id, set: { county, legal_description, property_kind, homestead, owner_mode, owner_name, owner_company, owner_mailing_address, owner_email, owner_phone } }`, any subset.
- **The form's rules.** A typed county is marked `manual` and a cleared one keeps no source (the panel's county input, `payloadFromDraft`). A commercial kind clears `homestead` (`propertyKindPatch`). Homestead is asked only of a residential property; a yes on anything else is refused unless the same plan sets the kind. A yes or a no stamps `homestead_answered_at` where the record carries that column (punch list #305, migration `20261111160000`): the record is read with `select=*`, so the verb works before and after that push and names no column that is not there.
- **The plan.** The record is shared, so the dry run names every job linked to it (the first 25 by label, the count whole), each column before → after, what the Lien desk reads off the record before and after (the dates' footing, the homestead hold, an unanswered question) and what the lien papers still lack (county, legal description, owner of record, owner mailing address). When the named job keeps an owner of its own and the plan changes the record's owner, it says that job's papers read the job's.
- **The hash** commits to the record's `updated_at`, each changed column's before value and the jobs on the record. The apply reads again, refuses a plan the world no longer matches, writes, and reads the record back to confirm the row landed (a row RLS kept is said).

## Not in it

- Linking a job to a property record (Edit Job's row saves the job's address as a property and links it), the parcel lookup, the CAD page paste and the justice precinct.
- The rest of the Lien desk: a desk item's draft, send, approve, hold and pull back; a recorded filing and its service; the claim set by hand; the papers themselves. Each is its own PR.
