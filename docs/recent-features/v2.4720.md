# v2.4720 — Counts: an import runs once, and it is fast (2026-10-06)

Client only; no migration, no edge function. The owner (2026-10-06): *users are reporting that the modal that appears when they go to paste into counts sometimes hangs and they press the button to import twice and it imports their clipboard twice.*

## What was wrong

- **No in-flight guard on either door.** The paste box's Import was disabled only while the text box was empty, and the clipboard button was never disabled. A second press started a second run before the first finished, and each run appended on its own. The v2.4686 review did not catch it: the second press read the sheet's rows from state, which still said the sheet was empty until the first run finished and refreshed.
- **One round trip per row.** `insertCountRows` inserted each row with its own `insert().select('id').single()`, so a 35-row CountTooling copy was 35 sequential requests before the source link and the alternate tags. On a slow connection that was many seconds with nothing on screen changing, and the paste box closed only after the last row landed.

## What changed

- **`BidsCountsTab.tsx`**: `beginCountsImport` / `endCountsImport` — a ref set before the first `await` (so a double click is caught) plus a `countsImportBusy` state. Both doors pass through it in a `try … finally`. While a run is in flight the paste box's Import reads **Importing…** and is disabled, its Cancel and text box are disabled, and the two **Import from /Tooling** buttons read **Importing…** and are disabled (`aria-busy`). The review's Apply keeps its own busy state as before.
- **`insertCountRows`** builds the whole payload and sends it as one `insert(chunk).select('id')` per 500 rows (`COUNTS_IMPORT_INSERT_CHUNK`). RETURNING keeps the VALUES order, so the ids line up with the rows and the row-for-row Undo is unchanged. Quick add, the review's Apply and the undo's re-insert use the same function.

## Tests

- `Bids.render.test.tsx` — *the Counts import is one run and one insert*: opens the paste box on an empty sheet, pastes two lines, presses Import twice, and asserts one `bids_count_rows` insert whose payload is the two-row array with `sequence_order` 1 and 2, and that Importing… is gone once settled.

## Cleaning a doubled sheet

The runs that already doubled a sheet left exact duplicate rows. The v2.4686 review will not help there (an identical paste is "nothing to import"); **Clear all counts** then one fresh import, or deleting the second half of the rows, puts it right.
