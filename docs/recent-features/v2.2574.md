# v2.2574 — Copy fixtures for text: parts-house list in the Share ▾ menu (2026-09-01)

Owner request (via Wendi): "a share mode for parts houses that only has fixture
counts/names copied for text." The existing Copy for text lives inside Package
and send and includes sale prices, so it can't go to a supply house.

- **New Share ▾ menu item** on Bids → Pricing: "Copy fixtures for text"
  (`PricingShareMenu`, below its own divider; the menu's hardcoded `i === 2`
  divider became a per-item `dividerBefore` flag). Visible to every role that
  sees the menu, including the non-share "Export ▾" variant.
- **New pure kernel `src/lib/buildBidFixtureCountsText.ts`** (+ unit tests):
  `Bid: <label>` header, one `fixture — count[ unit]` line per row, `Items: N`
  footer. Filters non-finite/zero/negative counts. Tests assert the output can
  never contain `$` or price/revenue/margin/total wording — the whole point is
  that sale-side numbers never reach a vendor.
- **Wiring** (`BidsPricingTab.copyFixtureCountsForText`): copies the viewed
  version's `pricingCountRows` to the clipboard with a success toast. No ★
  star-check (counts don't vary by price scenario) and no price-book/cost
  gating — enabled as soon as Counts exist, since texting the parts house
  happens *before* costs exist. Bid label reuses `bidPackageLabel` (now
  exported from `PackageAndSendBidPricingModal`).
- Help guide `send-a-bid-pricing-package.md` gained the new item; render tests
  extended for the new row + disabled tooltip.

No schema, RPC, or edge-function changes. The bigger supply-house RFQ flow
(token quote pages, compare view) stayed a mockup — see the design canvas in
the 2026-09-01 session; build only if parts houses outgrow texted lists.
