# v2.8171 — A punch list card cannot say one thing twice (2026-11-21)

CI only: `npm run check:todos` refuses a to-do whose front matter opens one key twice. No screen, no migration and nothing to deploy. From Taunya's note of 2026-11-21.

## What went wrong

The front-matter reader (`parseFrontMatter` in `src/lib/todos/todoBoard.ts`) keeps the last value of a key written twice and says nothing. Punch list #359's card held two `next:` lines, so its board row showed one of them and hid the other from 2026-11-15 until PR #9198 deleted the old line on 2026-11-21. Two PRs had kept the hidden line up to date in that time.

## What changed

- `frontMatterKeyLine` is the one answer to *does this line open a key*. A key starts in the first column, so an indented line is a block's words however it reads. The reader asks it, and so does the check.
- `repeatedFrontMatterKeys` gives each key a card opens more than once, with the file's own line numbers. A key counts once whether its value sits on the line or in a `>`, `>-` or `|` block under it.
- `findRepeatedKeyProblems` turns those into errors, one for each repeated key of each card, all in one pass. The words name the file, the key and the lines.
- `scripts/check-todos.ts` reads every card's text (`readTodoSources` in `scripts/todos/readTodos.ts`) and adds those errors to the ones it already reports.
- The reader's result is unchanged: the build and the dev server still render a card from its last value. CI is what refuses, on every PR and in the merge queue's build.
- `to-dos/README.md` names the new refusal in its *Check* step.

## What the cards held

The check read all 153 cards on main at 0bbd2b503 and found no repeat. Run on #359's card as it stood before PR #9198, it refuses it and names `next:` with both lines.

Tests: `src/lib/todos/todoBoard.test.ts` (a duplicate key refused with its file and key, a key on the line repeated as a block, a block line that reads like a key, several repeats named at once, a clean card).
