# v2.7106 — Rows the system numbers: exhibit numbers, a case's items and log, the database half (2026-11-12)

Punch list #315, upgrade 2, PR 1.

## What was wrong

An evidence record's number was typed into its title by hand, and the next free number, the open items and the log were prose in one document. Two sessions took the same exhibit number and the same item number on one day.

## What changed

- **Migration `20261113080000_person_file_numbers.sql`**. Page: [`docs/migrations/20261113080000_person_file_numbers.md`](../migrations/20261113080000_person_file_numbers.md).
  - `person_file_counters`, moved under a row lock by `person_file_take_number`.
  - `person_file_evidence.exhibit_no`, set by the database on every insert; a file's first number is one past the highest number any old title opens with. `dev_evidence_number_backfill` numbers old records from their titles when the number is worn once and reports a clash, a lettered number and a title with none.
  - `person_case_items` and `person_case_log`, with `dev_case_write` as the door: a new item numbered by the database or carried over with its number, a taken number refused, a log line for every change, a dry run that moves when another session adds an item first.
- **Is this the best we can do?** Three answers changed the map. The floor for a new exhibit number is read from the old titles, so numbering is safe from the first push without running any backfill on a real file. An item can be carried over with the number people already call it by, since notes and hand-overs cite those numbers. And one door, `dev_case_write`, takes items and log lines together, so the seat needs one verb pair and a closed item and its log line land in one write.
- **Kernel** `supabase/functions/_shared/personCase.ts` (door `src/lib/people/personCase.ts`, 15 tests): the label, the number a title wears, the label beside a title that does not already wear it, the backfill report in sentences, the items in reading order, the standing in words, the door's payloads.
- **Docs**: `HR_FILES.md`, `ACCESS_CONTROL.md`, `GLOSSARY.md`, the card.
