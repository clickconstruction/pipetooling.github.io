# v2.6452 — Edge drift check: a commit counts from when it landed on main, so a deploy made while its PR sat in the merge queue is named (2026-11-03)

Found while shipping v2.6417 (#6899): `npm run check:edge-drift` called `drive-link` current although its deployed bundle lacked the PR's new kernel words. The check picks the functions to read by comparing each commit's time with the function's deployed `updated_at`, and a merge-queue squash carries the time the queue BUILT it, not the time it landed: #6899 was built at 10:07:32Z and landed at 10:35:03Z, and `drive-link` was deployed at 10:18:21Z from a main that did not yet hold it, so git's time put the commit before the deploy and nothing was downloaded. The wait is routine, not rare: #6920 was built at 07:36Z and landed at 09:00Z. Only the daily `--full` run, which reads every function, would have caught it.

## What changed

- **`scripts/lib/edgeBundle.mjs`** (plain JS, no dependencies, as the drift workflow's bare Node needs): `pullNumberOf(subject)` reads the pull a squash names at the end of its subject; `commitsToLand(byFile, deployedMsList, windowMs)` lists, oldest pull first and each once, the commits built within the window before some deploy and no later than it that name a pull, since only those can have landed after a deploy they predate; `withLandingTimes(byFile, landedMs)` moves each commit's `ms` to when it landed, never backwards, keeping git's time as `builtMs`, once for every file it touches, each file's commits still newest first. `commitsSince` is unchanged and reads the moved times.
- **`scripts/check-edge-function-drift.mjs`**: the window is a day (`EDGE_DRIFT_LANDING_WINDOW_HOURS`, default 24); the landing times come from GitHub's `mergedAt` through `gh api graphql`, fifty pulls a call, a pull counted only when its merge commit is the commit named; when `gh` cannot answer, a warning says so and those commits are read as landed now, so every function they touch is downloaded and compared instead. A named commit that landed after the deploy prints its built, landed and deployed minutes. The OK line counts the queued squashes it timed.
- **`.github/workflows/edge-function-drift.yml`**: the step gets `GH_TOKEN` from `github.token`, so the push-time run can ask GitHub too.
- **`docs/EDGE_FUNCTIONS.md`** → Verify Deployment says what time the check compares.
- **Tests**: `src/lib/edgeBundle.test.ts` gains nine (31 in all): the pull at the end of a subject, the window and the once-per-hash listing, the move that never goes backwards and is one object across files, the 2026-11-03 shape (built before the deploy and landed after it is a suspect, landed before it is not, and git's times alone miss it), and the fallback that reads an unknown landing as now.
