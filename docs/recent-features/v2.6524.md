# v2.6524 — The dev seat can apply an approval it planned (2026-11-04)

Found approving Joseph's fifty imported Gray Fox sessions through `plan_clock_sessions` / `apply_clock_sessions` (v2.6437): three plans, three hashes, nothing written, each apply answering *the plan you quoted is not what this dry run gives now*. The approval went through `approve_clock_sessions_v2` from the app instead.

- **The cause**: `planCommitment` in `supabase/functions/_shared/devMcpWrites.ts` committed the clock verbs to the whole dry-run reply, and an approve op's `after` image carries `approved_at`, the dry run's own `now()`. The apply re-runs the dry run and hashes it again, so for an approve the hash could never match.
- **The fix**: the clock verbs commit to the counts and each op whole, with the after image's `approved_at` left out (`clockOpCommitment`). Everything that should refuse a stale plan still does: the before image (the session's times, job, notes and approval state as the plan saw it), the op, its outcome and words, and the after image's times and job.
- **Server 0.24.2**; `dev-mcp` redeployed after the merge. `docs/EDGE_FUNCTIONS.md`'s v2.6437 paragraph amended.

Tests: `devMcpWrites.test.ts` (an approve plan hashes the same on two runs seconds apart; a moved end, a moved job or an approval landed since each change the hash; a refused op with no after image still hashes; the version pins).

No migration. Client untouched.
