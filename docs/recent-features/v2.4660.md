# v2.4660 — Help: a warning when a guide sentence opens on "it" or "that" (2026-10-06)

The plain-words sweep (punch list #75, closed by [v2.4613](v2.4613.md)) left one habit the test cannot judge: a sentence that opens on a bare pronoun pointing back across a full stop. "The office gets the same notification. It clears the reminder." Is "it" the office, the notification or the report? The owner's call (2026-10-06) on the measured proposal: a warning on the guides a pull request touches, never a failing test, because only the writer can tell whether the pronoun has one noun it could mean. No guide is touched, no migration, no edge function, nothing on a screen changes.

## What changed

- **`src/lib/pronounOpeners.ts`** finds two things in a guide's prose:
  - a sentence that opens on a bare pronoun. *it, its, they, their, them, he, she, his, her* always count; *that, this, these, those, each, both* only when a verb or a comma follows, so "That section…" is fine. They also count behind an opening *then, so, and, but, if, when*…, as in "Then it…". A demonstrative that ends its sentence on a colon points forward to a list and is fine.
  - a paragraph's second and later sentence opening on "So", the rule that can fail later.
- **The dummy "it" is allowed**, because it points at nothing: "it's been / it has been", "it does not matter", "it is safe / harmless / fine / ok to". These were taken from the 2,193 sentences opening on "it" in the guides; seven matched. "It takes ten seconds" and "It is worth fixing" still count, because there "it" does point back.
- **What it skips**: the frontmatter, headings, `:::example` panels and an italic screen quote, which counts as one quoted word, as plain words reads it. A mock-UI token reads as its label.
- **`scripts/check-pronoun-openers.ts`** (`npm run check:pronouns`):
  - It prints the findings for the guides a change touches. It reads the base the way the deleted `check-plain-words.ts` did: the merge's first parent in CI, the merge base with `origin/main` locally, nothing on a push to main.
  - In GitHub Actions each finding is also a `::warning` on its line, so it shows on the pull request's Files tab. GitHub draws ten per step; the log keeps every one.
  - It always exits 0, even when something inside goes wrong.
- **CI**: one step in both `ci.yml` and `deploy.yml`, *Changed help guides, sentences that open on a pronoun (warns, never fails)*. `npm run check:workflow-parity` finds the two checks jobs identical, 15 commands each.
- **`plainWords.ts`** gains `helpGuideProseLinesNumbered`: the same prose lines, each with its line in the file. `helpGuideProseLines` now reads through it, unchanged. The header names the warning beside the rules.

## Measured

On main at 9979dd5c6, across all 317 guides:
- 3,442 sentences in 269 guides open on a bare pronoun;
- 28 paragraphs in 18 guides open a second sentence on "So".

On the proposal's samples:
- about 99% of what it finds is a real bare pronoun: 236 of 237 on the 22 guides of [v2.4589](v2.4589.md), 60 of 60 in a random sample;
- only about four in ten were ambiguous to a reader.
That is why it warns and does not fail.
