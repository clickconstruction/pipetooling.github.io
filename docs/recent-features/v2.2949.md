## What shipped

- **Shared kernel** [`supabase/functions/_shared/reconcileReceipt.ts`](../../supabase/functions/_shared/reconcileReceipt.ts) (+4 tests in `src/lib/mercuryReconcileReceipt.test.ts`): `buildReconcileReceipt(result)` → per-account presence (N of M), months with something missing, oldest/newest period, live-balance status (`ok` / `drift` / `unknown` at $0.01), and **`reconcileScopeSentence`** — the receipt's scope in words ("presence only, statement → books — books-only rows and amount differences are not checked; manual transactions have no statement"); `receiptVerdict` for the list. Deno- and React-free; imported by the function (writer) and the client (reader).
- **Table `mercury_reconcile_runs`** (RLS: SELECT `is_banking_staff()`; no user write policies; both read-only appliers). One row per run, written service-role by the function.
- **`mercury-reconcile`**: after building the result it inserts the receipt (`ran_by` = caller) and returns `receipt`, `runId`, `receiptSaved`; a persist failure never fails the check. `docs/EDGE_FUNCTIONS.md` updated.
- **Client**: `BankingMercuryReconciliationTab` shows the receipt sentence after a run ("receipt saved below" / "receipt not saved" in the caption), reworded intro (no more "gone when you leave the tab"), and mounts **`MercuryReconcileRunsList`** — the last 10 runs (when · window · ✓/⚠ N / M present · balance · by), tap a result to read its scope. A missing table reads as an empty list. `database.ts` carries the table type by hand until the next gen-types run.
- **Controller in the runner set** — already true: `ALLOWED_ROLES` admitted controller in v2.2920 (#28) and `Banking.tsx` shows the tab to the banking cohort; this PR documents it in the guide rather than re-shipping it.
- Guide `reconcile-the-books-against-bank-statements` (new).
