# v2.4396 — Takeoffs: the By Stage code is deleted (2026-10-02)

Punch list #77, PR 2 of 3. v2.4389 switched By Stage off and left its code unreachable. This PR deletes it: 35 files, about 3,000 lines out and 190 in. The owner, the same night: "it is very important to me that we thoroughly test this so that there are no issues from estimators tomorrow." So the rule for this PR was *no behaviour change*, proved on the live app before it merged, with the three small exceptions listed below.

## What went
- **Takeoffs** ([`BidsTakeoffTab.tsx`](../../src/components/bids/BidsTakeoffTab.tsx), 3,130 → 2,034 lines): the fixture × assembly table and its four functions, `createPOFromTakeoff` and `addTakeoffToExistingPO`, the template picker portal, the assembly preview modal, the exact branches of the book apply and the print, seventeen state hooks and fourteen props.
- **The engine** ([`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts), 1,793 → 1,551): the mappings load, `loadPOTotal`, `loadDraftPOs`, `loadPurchaseOrdersForCostEstimate`, `setCostEstimatePO`, and the stage PO branch of the cost estimate and Pricing loads. Three reads of `bids.materials_model` per bid open are gone, and so is a read of **every purchase order in the company** each time Takeoffs or Labor opened.
- **Under the takeoff** (`BidsTakeoffMaterialsSummarySection`, 379 → 67): the three stage PO pickers and the PO review window. Its stale pointer *Takeoffs → Rough* now reads *the part lines above*.
- **Labor**: the autosave no longer rewrites the three `purchase_order_id_*` columns, so the links on B82, B83 and B85 stay as they are.
- **Assembly windows** (`TakeoffAssemblyAuthoringModals`, 1,230 → 969): the Add Parts to Template window, which only the By Stage preview opened, and the parts-preview cache.
- **Documents**: the By Stage Labor page (`buildExactLaborPageHtml`), the per-stage breakdown print (`buildExactTakeoffBreakdownHtml`), the PO review prints (`costEstimatePO.ts`), and the PO branch of `loadBidMaterials`, which no longer reads the model.
- **Helpers with no caller left**: `normalizeMaterialsModel`, `MaterialsModel`, `poItemsSummary.ts`, `getTemplatePartsPreview`, `stagePoMaterials`, `loadPoTotal`, the `TakeoffMapping` / `DraftPO` / `CostEstimatePO` types.
- **Takeoff book admin**: the Stage column and the Stage picker beside each assembly (the plan's decision 5). Only By Stage read an item's stage. It is still stored, Rough In for a new row.

## The three things a person can see
1. **Fill from book says what it did.** The summary (*Filled 2 fixtures from the book (42 lines) · 2 without a catalog price.*) was written to a line that sat in the Old view, retired in v2.3588, so since then it was computed and never shown. It is a toast now.
2. **Labor's materials pill tells the truth.** It read *materials from takeoff* whenever the company had any purchase order at all, which is always. It now reads *no materials yet* on a bid whose takeoff has no parts.
3. **The Takeoff book lists assemblies without a Stage.**

## Left as it is, on purpose
- The three material slots (`…MaterialTotalRoughIn` / `TopOut` / `TrimSet`) still thread through the engine, Labor, Pricing and `computeBidCostBreakdown`. Top Out and Trim Set are always empty now. Folding them into one number touches the money kernel and its tests for no visible gain. It is on punch list #77's residuals.
- `bids_takeoff_template_mappings`, `bids.materials_model` and the stage PO columns stay (PR 3 and after).
- twin-mcp still counts both takeoff tables in its scorer, and `docs/twins/missions/estimator.md` still names them. Changing either means a regenerated brief and a deploy.

## Tested
- **Unit:** the 233 bids, documents, hooks and page test files, 2,333 tests, green on their own. (Run with the whole suite on a machine other sessions were loading, 17 timing-sensitive render tests in jobs, people and lien files failed; none touch this change, and CI runs the whole suite.) The By Stage builders' own tests went with them; `bidMaterials`, `bidMaterialsIo`, `costEstimatePage`, `takeoffBookFill` and `partFormSaveTarget` pin the one path left.
- **Live, an estimator's day** (headless Playwright, worktree dev server against prod, on a throwaway version of BP398 *ZZ Test* that is deleted at the end). Twenty steps: open the version, apply a book suggestion, add a part line and pick a part, change its quantity, set a stage box, Fill from rules & book, Fill from book, add an assembly, remove a line, print the takeoff, switch One at a time and Sheet, Labor's materials against Takeoffs', change the labor rate and read it back after a reload, print the Labor page, Pricing, Cover Letter, download the Approval PDF, delete the version, and check *To Plans* reads as it did. Run three times: on `main` before v2.4389, on v2.4389, and on this branch. **Every step gives the same result on all three**, down to the Approval PDF's 29,339 bytes, except the pills (gone in v2.4389). No page error in any run.
- **Live, six bids** (B403, B398, B490, B375, B82, B159), the full text of Takeoffs, Labor, Pricing and Cover Letter before and after this PR: Pricing and Cover Letter are identical. Takeoffs differs by the one reworded line. Labor differs by the pill on the two bids with no parts (B403, B82).

No migration, no edge function.
