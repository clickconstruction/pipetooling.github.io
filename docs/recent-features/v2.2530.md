# v2.2530 — Robot readiness icon on Bid Board rows (2026-08-31)

PR-1 of the robot-readiness feature (mockup-gated). Each human Bid Board row gets a
three-state robot icon between the jump-icon cluster and the bid number:

- **Grey glyph** — a robot can't duplicate this bid yet; click opens a checklist modal
  (`RobotBidReadinessModal`) showing every requirement with ✓/✗ and a fix hint, plus
  "Edit bid to fix". Required: plans link + service type. Warn-only: GC/customer,
  distance, due date.
- **Yellow glyph** — robot-ready; click shows the kickoff prompt
  (`buildRobotBidPrompt`) with a Copy button — bid logistics, external_ref instruction,
  and the blind rule baked in. The fleet roadmap's shadow-mode trigger in manual form.
- **🤖 emoji** — a twin bid exists; click deep-links to it on the Robot Board via
  `applyBidBoardDeepLinkToBid`. (The comparison modal is PR-2.)

One pure kernel decides state and modal contents: `src/lib/bids/robotBidReadiness.ts`
(`robotBidReadiness` + `buildRobotBidPrompt`, unit-tested). The icon renders only on the
human board (`robotReadiness` prop omitted on the Robot Board scope).

Pairing: migration `20260831180000_bids_twin_source_bid_id.sql` adds
`bids.twin_source_bid_id` (self-FK + partial index; see `docs/migrations/`), stamped by
twin-mcp `open_backtest` at open time (redeploy twin-mcp after merge). Existing ZZ pairs
(b405–b410) backfilled by an explicit data pass post-push. `src/types/database.ts`
updated by hand to match; regenerate after the push.
