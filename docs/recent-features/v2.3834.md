# v2.3834 — My Time: Apply Schedule % works on a payroll-period day you open for yourself (2026-09-25)

Quirk 2's "flag separately" note in [`MY_TIME_DAY_EDITOR_MODAL_ARCHITECTURE.md`](../MY_TIME_DAY_EDITOR_MODAL_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Client only, no migration.

## The bug

The My Time day editor ([`DashboardMyTimeDayEditorModal.tsx`](../../src/components/DashboardMyTimeDayEditorModal.tsx)) picks its split RPCs as `editingSelf && !fenceOverridden ? own_* : leader_*` in `persistDirtyChangesAsync` and `resolveAssignSessionForSegment`: when the editor was opened with a `saveableRangeOverride` (People's Draft Payroll, the Payroll-ledger upcoming week), a self-edit must go through the `leader_*` family, which honors `pay_access_clock_week_fence_bypass()`. `applyScheduleProportionsToCluster` handed [`applyScheduleProportionsToClockSession`](../../src/lib/applyScheduleProportionsToClockSession.ts) `editingSelf` alone, so a pay-access user splitting **their own** prior-week session across 2+ scheduled jobs hit `split_own_clock_session_segments`, whose week check (`work_date` outside the current Sunday–Saturday week) refuses it: *Session is outside the editable current week*. The one-job path (a direct `clock_sessions` update) was never affected.

## The change

- `applyScheduleProportionsToClockSession` takes an optional `fenceOverridden` and uses `own_*` only when `editingSelf && !fenceOverridden` — the editor's rule. The editor passes its `fenceOverridden` (and lists it in the callback deps). The clock-strip hook (`useApplyScheduleProportions`: People → Hours, Dashboard, Quickfill) has no fence override and is unchanged.

## Verified

- `applyScheduleProportionsToClockSession.test.ts` (+1): a self-edit with `fenceOverridden: true` hands the leader RPC set to the split; with `false` the own set. The six existing cases still pass.
