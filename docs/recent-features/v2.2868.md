## The two fixes

- **Walk-through, not Inspection.** The to-do said the portal calls the third step *Inspection*; the live portal says **Walk-through** (`Work · Walk-through · Customer pays · You're paid`). `SHEET_RAIL_STEP_LABEL.inspection` is now `'Walk-through'` (the key stays `inspection`), `sheetNextAction` reads "Schedule the walk-through", tests and the guide follow.
- **The row hands the assembler its sub.** Draft from a row landed on *Step 2 · Sub* because the assembler only takes `personId` from its `initial`. `WorkOrderBoardRow.personId` is now the single junction assignee (or a single legacy name resolved through the roster; null for multi-assignee sheets), and the tab passes it — with a job and a sub the assembler opens on *Scope and terms*, like the sheet's own door (v2.2829). Three kernel tests.

## Noted, not changed

- A *Not in Pipeline* row's Draft opens the assembler on *Step 1 · Job* (the assembler needs a Pipeline job) — Link to a job… first is the intended order; the mock-up script has it that way.
- Signing writes an open `dispatch_requests` inbox item ("Work order signed & accepted — …"); the table's RLS has no DELETE for the office, so test runs close it with a note.
