# v2.2868 — twin-mcp blind-safe verbs: `get_answers` redaction, `get_robot_book`, `extend_robot_book` (2026-09-05)

Three fixes from the 2026-09-05 evening regression batch (R2-BT-20/21/25/26 — four parallel agents on the new `paste_counts` harness). Edge only (`twin-mcp` v1.3.5 — deploy after merge; `briefs.ts` unchanged, only tool descriptions moved).

- **`get_answers` redacts for blindness.** R2-BT-20 was value-exposed before its lock: the mandated `get_answers` read surfaced a parked answer that named the reference bid and quoted its won number. Now every reference the twin holds an *unsealed* shell against (twin-owned bid with `twin_source_bid_id`, no `twin_run_scores` row, no scored `twin_shadow_runs` row) gets its mentions redacted — matched by `bNNN` token or project-name substring — returning `{redacted: true, note}`; the item reappears after that shell's scorecard breaks the seal. Over-redaction is deliberate.
- **`get_robot_book(bid?)`** — read-only names + prices for the 🤖 Robot Default book (bid's service type, or all robot books). The R2-BT-21 agent could read entry *names* but not *prices* through its environment's permission layer and had to mirror every price as a per-row override; this verb makes override-less rows the norm.
- **`extend_robot_book(bid, entries, mirror_note)`** — the doctrine's "extend it when a tag is missing; mirror sources in the ledger" as a fenced verb: inserts fixture types + priced entries for the bid's service type, stamps `[book extend]` with the mandatory `mirror_note` on the bid's ledger. Existing names are skipped, never repriced — re-mirrors of standing prices stay a digest-session act. (R2-BT-25 wanted a labeled uplift entry and was blocked client-side; owner question 62eca811 rode on it.)
