# v2.6712 — dev-mcp: a named document from a Drive file, the bytes read on the server (punch list #286) (2026-11-08)

Punch list #286 (`to-dos/named-document-from-drive.md`), the owner's yes of 2026-11-08. Two long documents of a former teammate's case sat in the People Shared Drive as linked files on evidence records for two days because no door put their text on the file without a person: `plan_person_doc` carries the text in the call, and a 350 KB document costs a session about a hundred thousand tokens each way, twice. The mail door (v2.6568) already reads a mail's attachment on the server and files it with the agent seeing only the plan; this gives named documents the same door for a file already in Drive. The seat is `dev-mcp` 0.41.0.

## What changed

- **Migration [`20261108190000_person_document_source.sql`](../migrations/20261108190000_person_document_source.md)**: `person_documents.source_drive_file_id` and `source_sha256` (on `person_document_index` too), and `dev_person_doc_write` replaced to carry them — together, on a named document, with `markdown`; kept through a flag-only change, cleared by a text change that names no file. The dry run's `document` gains `source` and `source_before`; the write's reply names `document.source`.
- **Kernel `_shared/devMcpDriveDoc.ts`** (pure, unit-tested): the source a doc names (`drive_file_id`, a Drive file link or a Google Doc link; never beside `markdown` or `ops`, never for the summary or narrative), the kind (a `.md` or `.txt` by mime or name reads as its bytes; a Google Doc exports as plain text; a PDF, an image, a Sheet, a folder or a trashed file is refused with the door that takes it, the evidence record's Drive link where #285 searches the text), the decode (UTF-8 only, the BOM off, CRLF folded, words present, 1,000,000 characters at most; 4 MB of bytes at most), the facts the plan names (the file, its mime, size, sha256, character and line counts, first heading, modified time, link), the rewritten arguments (the Drive keys out, the text in as `markdown` with the source on; the file's name as the title when the doc names no target), the words, and `readDriveDoc`, the two Drive reads with the fetch it is handed.
- **Grammar** (`_shared/devMcpWrites.ts`): the `plan_person_doc` branch passes `source_drive_file_id` + `source_sha256` to the RPC and refuses them half, on the fixed two, with ops or with a bad sha; the shape names `drive_file_id`.
- **Server** (`dev-mcp/index.ts`, 0.41.0): on `plan_person_doc` / `apply_person_doc` with a Drive source, the server takes a Drive token (`googleAccessToken` with `DRIVE_IMPERSONATE_USER`, as `hr-evidence-drive` does for the People drive), reads the file, and runs the grammar on the rewritten arguments; the plan reply adds `source` and `reads`, a mismatched apply adds the bytes as they read now to the refusal, the apply reply adds `source`. The call log keeps the agent's own arguments — the file id, never the text. The two tool descriptions and the seat's own description name the door. The verb count stays fifty-one.
- **Tests**: `src/lib/devMcp/devMcpDriveDoc.test.ts` (the kernel, the read with a stand-in fetch, the migration's gates, the server's wiring, the docs); every dev-mcp test pins 0.41.0.
- **Docs**: `docs/dev-mcp/README.md` (the `plan_person_doc` row), `docs/EDGE_FUNCTIONS.md` → dev-mcp (the version block, the RPC's migrations), `docs/HR_FILES.md` (the named-documents row), the migration page, the card.

## Deploy

`supabase db push` (the migration), then `supabase functions deploy dev-mcp`. `tools/list` on `https://mcp.clicktooling.com/dev` shows `serverInfo.version` 0.41.0 and `plan_person_doc`'s description naming `drive_file_id` once it is up.

Edit the file in Drive and apply the old plan again → refused, naming the bytes as they read now. Plan a PDF → refused, pointing at an evidence record and #285. The result goes on the card.
