# v2.4190 — Help-guide share pages: a landing page and a card per guide (2026-09-29)

The owner, 2026-09-29, texting `clicktooling.com/g/answer-an-owner-who-calls-about-a-lien-letter/` to Taunya: the bubble showed a bare **clicktooling.com** with a compass — no title, no card. *"Help me improve the SEO when a user shares from this url."* Client build only; no migration; one deploy-workflow step.

## Why the card was bare

v2.3147's share page carried every Open Graph tag and bounced instantly (`meta refresh` + `location.replace`). Crawlers that never run JavaScript (Slack, Facebook, WhatsApp) read the tags. **Apple's Messages runs a real WebKit**: emulated with Playwright, the share URL was already at `/help/?g=…` (the app shell, generic "ClickTooling" tags) by the `load` event and at `/sign-in` three seconds later — the preview read the sign-in page. Live checks that day: the page 200 with all tags, `og-card.png` 200 at 1200×630, the no-slash URL 301 to the slash — nothing wrong with the tags.

## The change (`src/lib/helpShareCard.ts`, `vite.config.ts`)

- **A landing page, not a bounce.** `helpSharePageHtml` renders the guide's question, its first sentence, *Open in ClickTooling ›* and one line of explanation; the redirect runs only after `load`, after `HELP_SHARE_REDIRECT_MS` (1.6 s), never in a hidden tab, and never for a user agent in `HELP_SHARE_PREVIEW_AGENTS` (facebookexternalhit, Twitterbot, Slackbot, WhatsApp, Applebot, LinkPresentation, …). Tags gain `canonical`, `og:locale`, `og:image:secure_url` / `:type`, a title-bearing `og:image:alt`, `twitter:image:alt`, `theme-color`; `noindex` stays (the guides are the company's manual, not a public site).
- **A card per guide.** `helpShareCardSvg` draws the 1200×630 card in the site card's look — the wordmark, *HELP GUIDE · category* as an eyebrow, the "How do I …?" question wrapped to fit (`helpShareCardFit` picks 66/56/48 px for ≤ 4 lines), the share address as the footer. `helpSharePagesPlugin` rasterises it with Playwright's Chromium to `dist/g/<slug>/card.png` and points the page's `og:image` at it; if no browser can launch (or `HELP_SHARE_CARDS=0`), the pages fall back to `/og-card.png` and the build says so.
- **`deploy.yml`** build job: cache `~/.cache/ms-playwright`, `npx playwright install --with-deps chromium` (`continue-on-error`) before the build.

- **Every guide, mechanically.** `src/lib/helpShareCard.guides.test.ts` runs over all 295 real guides in CI: the title fits the card (≥ 48 px, ≤ 4 lines), the first paragraph is a plain line (20–200 characters, no token), the page and the card build. All pass today. **`docs/HELP_SHARE_CARDS.md`** is the home of the conventions (what the author gets right, how to check, the Messages caveat); `docs/README.md` indexes it and `CLAUDE.md`'s help-guide rule points at it.

## Verified

`helpShareCard.test.ts` (the landing page, the guarded redirect, the per-guide image, the card's wrapping and escaping); a local build's `dist/g/answer-an-owner-who-calls-about-a-lien-letter/` page and card; Playwright emulation — a Facebook/Messages user agent stays on the page with its tags, a plain browser lands in the app after ~1.6 s.
