# v2.6994 — Lien help sheets: a code to scan that opens the place to record the filing and the mail receipts (2026-11-12)

Punch list #314, change 5, the code half. The owner, 2026-11-11: *it might make sense to offer the user a QR code where if they scan it brings them to that part of the app to enter a number and upload their receipt of the certified mail.* The form half shipped as v2.6982. This puts the code on the sheets.

## What changed

- **A cover sheet's code opens its own job.** `lienHelpRecordCode(jobId)` (`src/lib/jobs/lienHelpGuideCode.ts`) draws `lienWindowHref(jobId, 'affidavit')` on the app's own origin: the job's Lien window on the affidavit tab, which has a phone layout. The tab offers **Record filing…** until the paper is on file and **Record service…** after, so one code serves both steps.
- **A batch sheet's code opens the list.** `lienHelpBatchRecordCode()` draws `lienDeskHref({ kind: 'affidavit' })`, the Lien desk's Affidavits list. A tap on a job there offers **Open the affidavit tab ›**. One code for twelve papers, the card's pick: twelve codes on a table of rows would each be too small to scan.
- **The sheet takes it as `recordCode`.** `LienHelpExtras` gained the key beside `guideCode`. The Lien window's **Print for notarization** and the desk's **Print N for notarization** each hand theirs in. The guide copy takes none: it is a page to learn from, and nothing is recorded off it.
- **The steps say when to scan.** With a code on the sheet, `lienHelpAfterSteps` (its fourth argument) and the new `lienHelpBatchAfterSteps` open the record steps with *scan the code with a phone* and *Scan the code again*. The cover sheet keeps the desk's own door for a computer. Without a code the steps read as they did. The batch sheet's last step now also asks for each mail number and a photo of each receipt, which **Record service…** has taken since v2.6982.
- **The guide's code keeps its corner.** *Scan for the full guide* stays in the band at the top. The code to record is at the other end of the page, marked **Scan to record**, so a phone held over one does not catch the other.

## Where the code sits, and why

The fullest cover sheet fills its page to the point. Measured on the real print (`prependToFilingPrintHtml`, the page the Lien window opens) with a spacer before the foot: one more point of height put the foot on a second page.

- **A column beside the steps** made every step wrap. Second page.
- **The top corner of the steps box**, floated, cut two lines short. Second page.
- **What shipped:** the code hangs from the last step, *Keep the clerk's stamped copy…*, a short line, and runs down beside the names the copies go to, where the box was empty. It is 44pt wide with a one-line caption. The box is the same height to the pixel, with and without it.

The batch sheet has room, so its code is 54pt in the top corner of its steps box with what it opens under it. A batch of three is one page and a batch of twelve is two, as before.

**Small, and still coarse enough.** A job's address is 106 characters, a 41-module code. The picture is drawn with a two-module quiet edge (`LIEN_HELP_RECORD_CODE_QUIET`); the white page around it is the rest. At 44pt a module is a third of a millimetre. `lienHelpGuideCode.test.ts` holds that arithmetic, so a longer address fails a test before it fails a phone.

## How it was checked

- Both sheets were printed to PDF in headless Chrome with made-up names, with and without the code, through the same functions the two presses call. Page counts did not move: cover and paper 2 and 2, a run of twelve 14 and 14, a run of three 4 and 4.
- The rendered sheets were read back with the Mac's own barcode reader at screen resolution, coarser than any printer. Each sheet's two codes read as the addresses above.
- On the dev server at 390 wide, signed in: the batch address opened the Affidavits list, a tap on a row offered **Open the affidavit tab ›** and that opened the Lien window. The job address opened that job's Lien window on the affidavit tab and the door left the address bar. Every write was refused.

## Is this the best we can do?

- **A phone that is not signed in loses the address.** The gate sends it to the sign-in page and, after sign-in, to the Dashboard. A second scan then lands right. The app keeps an asked-for address across sign-in for the **/task** shortcut alone (`POST_LOGIN_REDIRECT_KEY`). Keeping it for every door is its own change, and every emailed link would gain from it. Not done here.
- **The code opens the tab, not the step.** One more press, **Record filing…** or **Record service…**, opens the form. Which of the two is right depends on what is on file, and the tab already offers the right one.
- **A paper cannot be scanned back.** The code is on the help sheet, which stays with the job. The paper itself carries no code: it is sworn and filed, and nothing is added to it.
- **Found, not fixed:** on the real print, the fullest cover sheet of a paper with *blank* county lines (six things to write, an ASK FIRST band, a typed clerk, two people to ask) already runs about 16pt onto a second page, before this change and after it. A paper with its signing county printed fits. Settings hold a signing county, so the blank form is the rare one.
- **Not built:** help sheets for the § 53.056 notice and the retainage notice, the last of the card.
