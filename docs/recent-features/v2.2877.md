# v2.2877 — Job Mode on by default for field roles; a one-tap first-run card for masters and superintendents (2026-09-05)

Journey-map Phase 4, Tier-2 #26 — Job Mode part only (C27; `pipetooling-journey-map` → `docs/JOURNEY_MAP.md` row 26; dossiers J2 `tech-works-a-day.md` F2/P2 + the K1 protected first screen and the punch-control hazard note, J24 `new-hire-first-day.md` F7/P4). Client-only; no migration, no edge function. The kin in the same row (payroll auto-apply per browser, Stripe Test/Live pref, per-device alert dismissals) wait on decision #19 and are **not** touched; Mobile cards got the pure width gate the row asked for.

## Why

`jobModeToggle.ts` read `localStorage['dashboard_job_mode_<userId>'] === '1'` — per user **and** per device, absent key ⇒ OFF. Every new or wiped phone started a helper or sub on the full Dashboard with no pointer to the screen built for them; the gear item was the words "Job Mode" and an empty checkbox; the start-here guide listed Job Mode as a tab that is just there. Both live walks (J2 helpers Tristen/Julia W, sub Michael A; J24 persona N) confirmed the fresh-paint state. J2 is the highest-stakes telemetry-blind journey — nothing recorded whether anyone ever turned Job Mode on.

## What changed

### Role default — `src/lib/jobModeToggle.ts` (pure kernel)

- `isJobModeEnabled(role, storedValue)`: stored value wins; **absent ⇒ `jobModeDefaultForRole(role)`** = `isSubcontractorLikeRole` (subcontractor, helpers); a role that fails `canLeaveJobFieldReport` reads OFF regardless of what the device holds (a stale `'1'` cannot surface Job Mode for an ineligible role).
- Stored values are now three-state: `'1'` (on via gear — also the legacy on-value), `'card'` (on via the first-run card), `'0'` (**explicitly off**). `writeJobModeEnabled(userId, false)` used to remove the key; it now writes `'0'` so a sub-like user's "off" survives the default. Legacy devices holding `'1'` are unchanged; legacy devices with the key removed (= off) now read the role default — i.e. a helper who once turned it off before this release will see it on once, and one gear tap stores `'0'` for good.
- `showJobModeFirstRunCard(role, stored, dismissed)`: `master_technician` / `superintendent` only, nothing stored, not dismissed.
- `jobModeActiveSource(stored)` → `'default' | 'gear' | 'card'` for telemetry; `readJobModeStoredValue`, `read/writeJobModeCardDismissed` (`dashboard_job_mode_card_dismissed_<userId>`).
- Test `src/lib/jobModeToggle.test.ts` (16): the full 9-role × {absent, `'1'`, `'card'`, `'0'`} matrix, null/unknown roles, garbage values, storage round-trips through a fake `localStorage`, per-user isolation.

### Role matrix shipped

| Role | Absent key | Sees first-run card | Gear toggle |
|---|---|---|---|
| subcontractor, helpers | **ON** | no (already on) | yes — off stores `'0'` |
| master_technician, superintendent | OFF | **yes** (once; "Not now" sticks per user + device) | yes |
| dev, assistant, controller, estimator, primary | OFF | no | yes (unchanged) |
| null / unknown role | OFF | no | n/a |

### Hook + consumers

- `useJobModeEnabled(userId, role)` (`src/hooks/useJobModeEnabled.ts`) — new `role` argument; both storage-event and same-tab listeners re-resolve through the kernel; the setter takes an optional `source` (`'gear'` default, `'card'`).
- `Layout.tsx` passes `role`; the gear toggle records `job_mode_enabled{gear}` when turning on.
- `Dashboard.tsx` passes `role` (the early-return gate is therefore role-safe even though its condition text is unchanged), fires the once-per-session telemetry effect, and mounts the first-run card at the top of the full-Dashboard render, above the pinned/quick row and the Clock In slot.

### First-run card — `src/components/dashboard/DashboardJobModeFirstRunCard.tsx`

"Working in the field? Turn on Job Mode." + one line of what it is + {{button:green|Turn on Job Mode}} / {{button:outline|Not now}}. Self-gated by `showJobModeFirstRunCard`; the tap writes `'card'`, records `job_mode_enabled{card}`, resets `jobModeShowFullDashboard`, and the Dashboard re-renders straight into the Job Mode card. Dismissal is per user per device (localStorage — acceptable here because the role default now carries the weight for the roles that matter most). Render smoke `DashboardJobModeFirstRunCard.render.test.tsx` (6): renders for master/superintendent only; hidden after any gear decision; tap → `onEnable` + `'card'` + telemetry; Not now → sticky per user, a second user on the same phone still gets it.

### Telemetry — `src/lib/jobModeTelemetry.ts`

`recordJobModeEnabledOncePerSession(userId, role, source)` → `recordNavClick(userId, role, 'job_mode_enabled', '#default' | '#card' | '#gear')` into `ui_nav_clicks`, guarded by a `sessionStorage` key so the card tap and the Dashboard remount that follows count once. Fired by: Dashboard first render with Job Mode active (source from `jobModeActiveSource`), the card tap, the gear turn-on. Test `jobModeTelemetry.test.ts` (4). Query: `select target, count(*) from ui_nav_clicks where control = 'job_mode_enabled' group by 1`.

### Mobile cards width gate — `JobsStagesTab.tsx`

`stagesMobileCards` initialiser: stored `'true'`/`'false'` wins; absent ⇒ `matchMedia('(max-width: 559px)')`. Six lines; the ⋯ toggle and its `localStorage.setItem(String(next))` are unchanged.

## Verify

1. Impersonate a helper on a browser with no `dashboard_job_mode_*` key → `/dashboard` paints the Job Mode card (Clock In on top, My Schedule below with the Call dispatch link). Gear → Job Mode off → full Dashboard; reload → still full; `localStorage` holds `'0'`.
2. Impersonate a master with no key → full Dashboard with the green "Working in the field?" card above Clock In. Tap **Turn on Job Mode** → Job Mode card; the key is `'card'`; `ui_nav_clicks` has one `job_mode_enabled` / `#card` row for the session. New session, **Not now** on another master → card gone on reload, key untouched.
3. Impersonate dev / assistant / estimator with no key → no Job Mode, no card.
4. Jobs page at 500px with no `jobs-stages-mobile-cards` key → cards; at 700px → tables; the ⋯ toggle still flips and persists.

## Rollback

Revert the PR. Devices that stored `'0'` or `'card'` in the meantime read as: `'0'` → the old kernel treats anything but `'1'` as off (same outcome); `'card'` → off (the user re-enables via the gear). No data migration.
