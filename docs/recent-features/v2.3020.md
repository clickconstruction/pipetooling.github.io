# v2.3020 — Test-gap audit, pass 31: the label catalog gets its first tests (2026-09-07)

Follow-up to v2.3019. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`labels.ts` (177 lines) is the people / user label catalog behind the People → User tags panel and the Users tab tags: the slug rule, the catalog and membership reads, usage counts for catalog maintenance, and the replace-all writes for a person's or a user's labels. Two callers, no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- A slug lowercases, collapses every run of non-alphanumerics to one dash, trims dashes, caps at 128 characters, and falls back to `label` rather than coming back empty.
- Catalog reads order by name; the multi-master read de-duplicates and drops blank ids, and asks nothing for none.
- Membership reads give every asked-for id a bucket (empty when it has no rows) and still keep rows for ids that were not asked for; usage counts are zero-filled for the asked-for labels and counted from both join tables.
- Replacing a person's or a user's labels clears first, then inserts one row per id, and only clears when the new set is empty.
- Every failure throws.

- **`labels.test.ts`** (9) — a recording Supabase stand-in with a one-line-per-query trace. Covers the slug rule, the five reads and their shapes, insert / update / delete, both replace-all writes, and read and write failures.
