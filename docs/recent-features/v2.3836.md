# v2.3836 — Checklist: "repeat N days after it's done" lands on the right day (2026-09-25)

The completion-engine risk flag of [`CHECKLIST_TABS_ARCHITECTURE.md`](../CHECKLIST_TABS_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Client only, no migration.

## The bug

Four places materialize the next `days_after_completion` occurrence when a task is checked off. Three inline copies — Today's `maybeCreateNextInstance` and Review's `markComplete` in [`Checklist.tsx`](../../src/pages/Checklist.tsx), and `maybeCreateNextChecklistInstance` in [`DashboardMyInboxCard.tsx`](../../src/components/dashboard/DashboardMyInboxCard.tsx) — computed the date as `new Date('YYYY-MM-DD')` (UTC midnight) + local `setDate(+N)` + local format. Anywhere west of UTC that is **scheduled + N − 1** (America/Chicago: `2026-09-25` + 3 → `2026-09-27`). Only the activity panel's ✓ (the tested kernel [`lib/checklistCompleteInstance.ts`](../../src/lib/checklistCompleteInstance.ts), `ymdAddDays`) was right, so the same task repeated on different days depending on which ✓ was pressed. For **N = 1** the next date was the day just completed: Today's exists-check found the completed row and returned; Review and the Inbox inserted into the `UNIQUE (checklist_item_id, scheduled_date)` pair, failed silently — either way no next occurrence, and the repeat stopped.

## The change

- The kernel exports `checklistNextRepeatYmd(scheduledYmd, daysAfter, endDate)` (calendar-day string math via `ymdAddDays`, null past the end date) and `createNextChecklistRepeat(checklistItemId, scheduledDate)` (the former private `maybeCreateNextInstance`: read the repeat, skip when an occurrence already sits on the date, insert, copy assignees; best-effort).
- Today, Review and the Dashboard inbox call `createNextChecklistRepeat` instead of their own copies. Review keeps its base — the newest missed date for a Missed-view row — and now also gets the exists-check it lacked. Notifications are untouched.

## Verified

- `checklistCompleteInstance.test.ts` (+4, run with `TZ=America/Chicago`): `+3` and `+1` land on S+3 / S+1, month/year/DST edges, the end date (past → null, on it → allowed); `createNextChecklistRepeat` gives an every-1-day task tomorrow, and writes nothing when that date already has an occurrence.
- Typecheck, lint.

## Open — owner call

- Every path (the kernel included) counts from the occurrence's **scheduled** date. The add modal says *days after it's completed* and the guide says *30 days after each time*; a task done 5 days late therefore gets its next date 5 days earlier than "N days after it was done" — possibly already overdue. Counting from the completion day is a product decision, not taken here.
