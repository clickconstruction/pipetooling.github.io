# v2.2368 — Decimal prices work in the Pricing Workbench (2026-08-26)

Estimator report (Wendi): "my decimal point is not working." The Workbench
sale-price input (`BidsPricingTab.tsx`, New Pricing view) was fully
controlled off the numeric preview state: every keystroke ran
`parseFloat(value)` and repainted the field from the parsed number.
`parseFloat("500.")` is `500`, so the dot died on its own keystroke —
typing 500.25 produced 50025. Emptying the field parsed to `0` and zeroed
the row's revenue. The classic grid's price input in the same file already
used the correct draft-while-editing pattern; the Workbench input didn't.

- **Kernel** `src/lib/bids/salePriceDraft.ts` (+tests): `parsePriceDraft`
  (strips `$`/commas/space; positive-finite or null — partial drafts like
  `"."`/`""` are "nothing to preview", never 0), `commitPriceDraft`
  (`set` rounded to cents / `clear` on empty / `revert` on gibberish),
  `formatPriceDraft` (canonical text, no invented trailing zeros).
- **Wiring**: new `wbPriceDraft` state (`{rowId, text} | null`) holds the
  raw text for the one field being edited; the field renders the draft
  while focused, live-updates `wbPreview` whenever the draft parses, and
  commits on blur/Enter (Enter keeps focus). `clear` deletes the row's
  preview key so the row falls back to its saved price.
- All four wholesale preview discards (scenario switch ×2, Apply, the
  Discard button) also drop the draft so stale text can't outlive its
  preview.
- No visual changes — same amber preview treatment.
