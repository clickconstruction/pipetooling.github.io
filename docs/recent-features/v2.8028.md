# v2.8028 — Dev seat: a new robot's replies name the calls that archive it and make a held seat again (2026-11-20)

## Why

The seat archives a twin since v2.7970 (`plan_twin_archive` → `apply_twin_archive`, and `restore: true` for the way back) and makes a held seat again since v2.7974 (`plan_twin_seat` → `apply_twin_seat`). `plan_twin`'s own words still sent a reader to the panel for both. v2.7918 amended the same sentences for the rung and a key's revoke, and these two were left. Found by the docs catch-up pass of 2026-11-20, which lists a code fault and does not fix it.

## What changed

Words only. No verb, argument, write or server version changed.

- **`apply_twin`'s description in the tool list**: a held seat "is made again with plan_twin_seat, as the link button on the twin's row at Settings → System → Digital twins makes it", where it named the link button alone. Its closing clause names `plan_twin_archive` beside the rung and the key revoke, where it said "Archive stays a press in Settings → Digital twins".
- **`plan_twin`'s `then` line** (`twinDryRun`): names `plan_twin_archive` and its `restore: true`, where it said "Archive is a press at" the panel. A bid robot's plan adds that `plan_twin_seat` makes a held seat again; the pricing robot has no seat in the other apps and its plan names no seat verb. The line ends by saying each is also a press at the panel.
- **`apply_twin`'s closing line when a seat was held** (`twinAppliedWords`): gives the call whole, `plan_twin_seat { seat: { twin: "<its address>" } }`, and names the link button as the same act.
- One comment in the function's `apply_twin` branch names the verb as the retry.

The sentences in the rung, archive and seat kernels that compare a verb to its press ("as Archive on the twin's row … does") were true and stand.

## The plan hash

`plan_twin`'s reply is part of what its hash commits to, so a `plan_twin` answered before the deploy and applied after it is refused as no longer matching. Plan again; nothing was written.

## Server version

Not bumped, as v2.7875 and v2.7919 did not for words alone: `SERVER_VERSION` stays 0.120.0 and `docs/dev-mcp/SERVER_NOTES.md` gains no note.

## Docs

`docs/dev-mcp/README.md` and `docs/EDGE_FUNCTIONS.md` carry none of the four sentences, so neither changes here.

## Deploy

`supabase functions deploy dev-mcp` from `main` after the merge. Until then the seat answers with the old words; nothing it writes differs.
