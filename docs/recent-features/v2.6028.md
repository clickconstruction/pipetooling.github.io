# v2.6028 — Put it back finds a skip on a residential customer's Pipeline job (2026-10-28)

The last follow-up v2.6016 left. A residential customer's job is a Pipeline job (`jobs_ledger.id`), filed in `jobs_ledger_id`; v2.6007 taught the run and the marks (`nudge_holds`, `nudge_sent`) to read that column and v2.6016 the step notes, and made the card's presses name a residential customer's job `'pipeline'` (`pressJobOf`), so Skip for them files their skip on `jobs_ledger_id`. The card's Put it back could not find it: `flow_rows` (through `flow_rows_for`'s `a_skips`) built each skip with `id, step_key, project_id, why, by_name, created_at, undone_at`, so a skip on `jobs_ledger_id` came back as a skip on no job, `useFlowPerson.ts`'s `skipId` (matching by `project_id`) never found it, and `flow_unskip_step` was never called. `flow_rows_for` is defined once (`20261012120000_messages_flows.sql`); `flow_rows` and `flow_rows_kind` read through it, so one function carries the fix.

- **The skip object carries its Pipeline job** ([`20261028190000_flow_rows_skips_jobs_ledger_id.sql`](../../supabase/migrations/20261028190000_flow_rows_skips_jobs_ledger_id.sql), [`docs/migrations`](../migrations/20261028190000_flow_rows_skips_jobs_ledger_id.md)): `CREATE OR REPLACE` of `flow_rows_for` as main holds it, with `'jobs_ledger_id', s.jobs_ledger_id` added to `a_skips`' object and nothing else changed.
- **The readers key the skip by either column** ([`flows/load.ts`](../../src/lib/flows/load.ts), [`useFlowPerson.ts`](../../src/hooks/useFlowPerson.ts), + test): `StepSkipRow` gains `jobs_ledger_id?`, `skipsOf` keys each skip by `jobOfMark` (`person.ts`, the hold's and the note's reader) so a Pipeline job's skip stamps that job's step, and the card's `skipId` finds the skip the same way, so Put it back calls `flow_unskip_step` with its id. `load.test.ts` holds a skip on `project_id` next to one on `jobs_ledger_id` and one with no `jobs_ledger_id` key at all (the shape before the push), each keyed to its job. `residentialLoad.ts`'s `PipelineStepSkipRow` reads its own `jobs_ledger_id` as before.
