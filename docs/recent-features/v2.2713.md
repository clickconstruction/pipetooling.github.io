# v2.2713 — Person Desk PR 5: gate widenings and the HR existence line (2026-09-03)

Owner decisions 2 and 4 from the Person Desk proposal, shipped as their own PR so each is auditable. Migration `20260903191916` (fragment in docs/migrations/) + redeploy `archive-user` and `restore-user`.

## DB

- `users_guard_privileged_columns()` admits **dev, controller, or pay-approved master** for `read_only` (training mode); a non-dev never changes it on their own row. `role` stays dev-only, `archived_at` stays edge-flow only.
- The users UPDATE policy "Masters assistants devs can update user notes" is re-created with `controller` in its role list — it predated the role, so a controller's training-mode write would have filtered to zero rows.
- New RPC `person_file_summary_counts(p_person_id)` → `(entries, has_summary, updated_at)` for office roles, the zero row for anyone else. HR-table RLS unchanged (`is_dev()`).

## Edge functions (deploy both)

- `archive-user`, `restore-user`: the caller may be `dev`, `controller`, or a `master_technician` present in `pay_approved_masters`. Customer reassignment on archive is unchanged (still asks for a target when the user owns customers — the Desk tells non-devs to ask a dev in that case).

## Client

- [`lib/people/personDeskGates.ts`](../../src/lib/people/personDeskGates.ts) (+3 tests): `canArchiveAccount` / `canSetTrainingMode` = dev · controller · pay-approved master, never in training mode. `canEditAccount` (role, sign-in email, password) stays dev.
- Access & account: a non-dev **Archive…** calls `archive-user` directly after a confirm (devs keep the Active Accounts route for customer reassignment); **Restore** already did. The training-mode checkbox unlocks for the widened set.
- End employment's **Archive account after** unlocks for the same set.
- Records: non-devs see the existence line ("HR file on record · 12 entries · updated Aug 24 · ask the dev") via the RPC; content stays dev-only.
