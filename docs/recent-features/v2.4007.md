## How the drag is tested

jsdom has no `PointerEvent` and lays nothing out. The test file stands in a `PointerEvent` that carries what the sensor and the long-press read (button, position, primary), gives each cell its box through `getBoundingClientRect`, and then drags with real pointer events through a `DndContext` set up as the page sets it up — `PointerSensor` with an 8px threshold, `closestCenter`. Nothing in dnd-kit is mocked.

## Two things the repeat runs found

- **dnd-kit holds a click guard for 50 ms after a press on a draggable ends** — the listener that keeps a dropped card from also opening. A case that began inside that window lost its first click, about two runs in five. Every press in the file now waits the window out, and the guard itself has a case, with the clock held so it cannot race.
- **A toast read off the screen is a race on a busy machine.** The card's toast is read off the call instead.
