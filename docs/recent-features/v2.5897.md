# v2.5897 — Help: which guides are opened, and through which door (2026-10-26)

Punch list #187's PR 1 (`to-dos/help-at-the-point/`), the owner's lens of 2026-10-26 (*read `ui_nav_clicks` to see which guides are opened and which never are*). The read that morning found the question unanswerable: 37,990 rows in the ledger since 2026-08-26 and not one naming the Help page or a guide, because no door into a guide wrote a row — not the Help page's list or search, not a `/help?g=` link on a surface, not a walkthrough's stop, not the share page's bounce. The page-minutes side of the measurement plan saw the Help page (406 minutes in 90 days across seven people); the clicks side saw nothing. This PR is the one line that makes the rest of #187 measurable.

- **`lib/guideOpenTelemetry.ts`** (pure): the control names `guide_opened` and `guide_missing`, the nine doors (`list`, `search`, `guide`, `link`, `walk`, `share`, `legend`, `error`, `box`), `guideDoorOf` (anything unknown reads as `link`), `withGuideDoor` (puts `&via=<door>` on an address once, keeping its heading), `guideOpenedTarget` (`/help?g=<slug>#via=<door>`), `guideOpenEvent`, `guideOpenKey` and `parseGuideOpenedTarget` for the readout.
- **`GuideBrowser.tsx`**: one effect on the selected slug writes the row through `recordNavClick`, keyed by slug and door so a re-render or React's double effect never writes twice; the list press sets `via=list`, a press on a search result `via=search`, a link inside a guide `via=guide`; Back clears both params. A slug no guide answers writes `guide_missing` with the same target, so a dead link in the wild is found by the readout.
- **The doors name themselves**: `helpGuideHref(slug, heading?, door?)` gains the third argument for the ? cards and the error doors of the later PRs; `SpotlightTour` puts `via=walk` on a stop's guide link and the footer's; `helpShareCard.ts`'s app path carries `via=share`, so the share page's bounce is counted as the share page's. The sixty-three existing links on surfaces change nothing and read as `link`.
- **Settings → Usage** gains a **Guides** panel (`usageDashboard.ts` `guideOpens`): the guides opened most, each row's hover naming its doors and roles, the count opened against the registry and the count not opened in the window, the opens by door, and in red the links to a guide that no longer exists. The header's note says guide opens start on Oct 26. The guide *read the Usage dashboard* describes the panel.
- **Not recorded**: the words typed in the search box, which can hold a customer's name. The row holds the slug.
- **Tests**: `guideOpenTelemetry.test.ts` (the doors, the address rewrite, the target, the missing case, the key, the parse), `usageDashboard.test.ts` (the ranked rows by door and role, the never-opened count, the limit, the quiet case), `GuideBrowser.render.test.tsx` (one row per open with the door the address names, none on a re-render, `guide_missing` with the not-found line), `helpGuideAnchors.test.ts` and `helpShareCard.test.ts` (the door on the address), `SpotlightTour.render.test.tsx` (the walk's door).

No migration, no edge function: the table, its policies and the dev-only aggregate `usage_nav_clicks` (v2.2342) carry the new rows as they are. What the first ninety days say decides #187's PR 7, the rule for the guides nobody opens.
