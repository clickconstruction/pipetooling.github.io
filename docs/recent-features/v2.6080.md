# v2.6080 — The emails' small print and copper read like the portal's (punch list #199, PR 2 of 2) (2026-10-29)

Punch list #199, the emails PR, after v2.6067 moved the portal. The legal and contract emails still wrote their small print in the old faint grey `#8a97a6`, which v2.5981 retired from the portal: 2.98:1 on white and 2.68:1 on the paper the contract email sits on. Six shared email builders copied the copper `#b0662f` (4.39:1 as words on white and under white on a button). Changing either takes an edge deploy, so they shipped apart from the client. The grey was a go, not a call; the copper follows call 3 (A) of 2026-10-29.

## What changed

- **The grey**: `faint` in [`contractSigningEmail.ts`](../../supabase/functions/_shared/contractSigningEmail.ts) (the *Or open* link line and the reach line) and the four grey values in [`legalEmails.ts`](../../supabase/functions/_shared/legalEmails.ts) (the now and digest emails' footers, the *Stop these emails to you* link, and the confirm email's *Nothing else is sent…* line) are `#5e6d7c`, the portal's `FAINT`: 5.31:1 on white, 4.79:1 on the paper.
- **The copper**: `scripts/codemods/copper-sweep.mjs --emails` moved `#b0662f` to `#9a5b2b` (5.38:1 as words on white and with white on a button) in the six builders — `legalEmails` (the letterhead rule, *Open the portal*, the referred rule), `contractSigningEmail` (`copper`: the wordmark's full stop), `submittalReplyEmail` and `submittalRoomLinkEmail` (*Open the review*), `stripeBillEmail` and `portalAccountCard` (`COPPER`: *Pay now*, the statement card's link) — and in the two tests that read them (`contractSigningEmail.test.ts`, `gcStatementEmailParity.test.ts`).
- **The pin is edited, never regenerated**: [`contractSigningSend.pin.json`](../../src/lib/contractSigningSend.pin.json) holds the signing email byte for byte so that what a person's email says, who it is from and where it replies cannot move. Its four `#8a97a6` and four `#b0662f` values change by hand and nothing else in it does, so `contractSigningSend.pin.test.ts` still proves the words did not move.
- `portalTheme.test.ts` now allows no file under `src/` to carry the old copper. The card `to-dos/portal-last-contrast-flags.md` and the shared mock-up `to-dos/safety-orange-and-portal-contrast-before-after.html` are deleted (#198's card went with v2.6063).

## Deploy

Fourteen functions bundle the changed files and deploy after the merge, from the main checkout, on Taunya's go (`npm run check:edge-drift` before and after names them):

- `_shared/legalEmails.ts`: `supabase functions deploy legal-notify-dispatch`, `supabase functions deploy legal-send-firm-link`, `supabase functions deploy submit-legal-portal`.
- `_shared/contractSigningEmail.ts`: `supabase functions deploy accept-contract`, `supabase functions deploy complete-contract-form-office`, `supabase functions deploy contract-form-paper-entry`, `supabase functions deploy get-contract-for-signer`, `supabase functions deploy send-contract-for-signature`.
- `_shared/submittalReplyEmail.ts`: `supabase functions deploy send-submittal-reply-email`. `_shared/submittalRoomLinkEmail.ts`: `supabase functions deploy send-submittal-room-link`.
- `_shared/stripeBillEmail.ts` and `_shared/portalAccountCard.ts`: `supabase functions deploy send-stripe-invoice`, `supabase functions deploy gc-statement-email-dispatch`, `supabase functions deploy send-gc-statement-email`, `supabase functions deploy send-lien-release-email`.

`create-user` keeps `verify_jwt = false` in `config.toml` on every redeploy. No migration. Until each deploys, that function keeps sending the old grey and copper, which is only a colour; the client already previews the signing email in the new ones.
