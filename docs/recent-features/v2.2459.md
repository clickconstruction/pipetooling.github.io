# v2.2459 — Hiring board: duplicate & contact hygiene (2026-08-28)

Final slice of the Prospects-refresh arc. The Screen board had grown silent copies — the same applicant twice in one column (identical phone/email at ranks #4 and #10) and the same person across three role columns under two phone numbers — and 26 of 27 Screen candidates had never been contacted with nothing surfacing it.

- **New kernel [`src/lib/prospects/candidateHygiene.ts`](../../src/lib/prospects/candidateHygiene.ts)** (+8 tests): `normalizePhone` (digits-only, drops a leading US 1, <7 digits → null), `normalizeEmail`, and `analyzeCandidates(rows)` → `{ duplicateOf (same-role match, keeper = best rank), crossRoles (other role_ids with a phone/email match), neverContactedByRole, callNextByRole (top-ranked uncontacted, duplicates excluded) }`. Callers pass active Screen rows only, so Hired/Passed never flag.
- **[`TeamProspectsTab.tsx`](../../src/components/prospects/TeamProspectsTab.tsx)**:
  - `SortableCandidateCard` gains optional `duplicate` / `alsoInRoles` / `isCallNext` props: red "duplicate of #N" chip + a "Merge (keeps #N, combines notes & reviews)" link; indigo "also in: <roles>" chip; amber "call next" chip.
  - `RoleColumn` gains `neverContactedCount` → amber "N never contacted" header chip (real roles and the Unsorted column).
  - New `mergeDuplicate(dup, keeper)` (confirm dialog first): merges notes (append) and links (URL-deduped via the existing parse/serialize helpers) onto the keeper, re-points the dup's `team_prospect_reviews` to the keeper **before** deleting (the FK cascades; a reviewer who already reviewed the keeper keeps that review), then deletes the dup and reloads. Onboarding statuses are left to the cascade — Screen candidates don't have them.
  - Errors surface through the existing toast; the shared `busy` flag guards the whole merge.
- No schema changes; detection is pure client-side comparison of rows already loaded.
