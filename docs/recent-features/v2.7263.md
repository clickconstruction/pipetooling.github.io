# v2.7263 — Punch list: a search field finds a card by its number, its name or a word (2026-11-14)

The owner's ask of 2026-11-14: a search on `/punch-list`. Since v2.7150 the page had two views, the Show filters, the mock-up toggle and By number's group chips, and no way to find one card among 118 by what it says.

## What changed

One **search field** sits in the filter row beside the **View** choice, in both views. The cards narrow as the person types.

- A card matches when every word of the search is found in its words: the number (`#343` or `343`), the name, the summary, the **Next** line, the shipped versions (`v2.7150`) and its group's name (*owner decision*). The words are read folded, so case, accents and curly quotes never decide a match (`ridgeway` finds *Ridgeway*, `wont` finds *won’t*).
- **By group** keeps only the matching rows in the Shortlist, the Flagged section and each group, and a group with none is left out. **By number** counts them in its header as the filters already do: *3 of 118 cards*.
- The search composes with the **Show** filters, **Waiting on a mock-up** and the group chips rather than replacing them.
- When nothing matches, the list says *No cards match ‘…’.* with **Clear the search**. In By group that sentence stands where the Shortlist and the groups were, and it also names the filters when they are what left nothing, which used to draw a blank page under the row.
- **×** in the field clears it with one press, and **Escape** empties it.
- The address carries the search as `?q=`, beside the view and the order the page already keeps, so a link with a search opens on that search (`/punch-list?view=number&q=ledger`). A View press keeps it. The device does not remember it: a search is for the moment, a view is a habit.
- On a phone the field takes its own line under the View choice, full width; the row's dividers are hidden there, since each lands at a line's start.

## How it is built

- `src/lib/todos/punchListSearch.ts` holds the rules: `foldSearchWords` (lowercase, accents dropped, curly quotes and dashes made plain, blanks squeezed), `cardSearchWords` / `cardMatchesSearch` / `searchCards` (every word of the search somewhere in the card's folded words; a blank search matches every card), `parseSearch` / `searchFromAddress` / `withSearch` (the `q` parameter, every other kept, dropped when blank). No shared fold existed in `src/lib` for this: the app's name keys are `trim().toLowerCase()` (`personNameKey.ts`, `checklistCrewTags.ts`), so this one is written here and tested.
- `src/pages/PunchList.tsx` reads the search from the address, writes it back on each keystroke (replacing the entry, the hash kept), and composes one `visible` rule for both views: the Show filter, the mock-up toggle, then the search. The By group empty state is new here.
- `src/components/punchList/PunchListByNumber.tsx` takes `query` and `onClearSearch`, so its empty words name the search and the press clears the search alone; the filters' press follows if that was not enough.
