# v2.2501 — drive-intake plans upload is idempotent (reuse-or-refuse) (2026-08-29)

Estimator-twin pipeline STG-1 gap: `findOrCreateFolder` was idempotent but `uploadFromUrl`
always created a new file — re-running the same `file_plans` call uploaded a second ~36 MB
copy of the plan set into the job folder, violating the pipeline's cross-cutting rule
(`docs/ESTIMATOR_TWIN_PIPELINE_PLAN.md`: "re-running a stage must never duplicate").

- `supabase/functions/drive-intake/index.ts`: after resolving the target filename (including
  the Drive-source name adoption from v2.2499) and **before** fetching any bytes, the new
  `findExistingFile()` lists the job folder for a non-trashed, non-folder file with the same
  name — same query pattern as `findOrCreateFolder`, with `supportsAllDrives` +
  `includeItemsFromAllDrives`. A hit returns that file's id with `reused: true` and skips the
  download/upload entirely.
- Response gains `plans_reused`; the `[pipeline STG-1]` audit note now says
  `plans uploaded` vs `plans reused`. The graceful `upload_note` degradation (quota /
  share failures never fail the call) is unchanged, as is set-if-empty stamping of
  `drive_link` / `plans_link`.
- Docs: `docs/EDGE_FUNCTIONS.md` → drive-intake updated (idempotency line + body shape).
- Deploy: `supabase functions deploy drive-intake` after merge.
