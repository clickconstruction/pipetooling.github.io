# v2.7018 — Test runs on a developer machine no longer reach the live database (2026-11-12)

`src/lib/supabase.ts` builds its client from `VITE_SUPABASE_URL`. CI's Test steps pass a stand-in (`https://example.supabase.co`), so CI never reached the project. A dev machine has the live address and anon key in `.env.local`, and Vitest reads that file. Every `*.render.test.tsx` whose component makes a Supabase call the test did not mock sent that call to the live database, as `anon`, with the fixture's made-up id.

**What it looked like.** The Supabase dashboard for 2026-11-11 12pm to 11-12 11am Central showed 5,447 Postgres errors in bursts. Read from the log, about 93% were these test runs:

- `invalid input syntax for type uuid: "job-1"` and the same for `"gc-hillside"`, `"c-greg"`, `"cust-dana"`, `"dev-zz"`, `"smoke-auth-user-1"`: 3,673.
- `permission denied for function is_dev`: 1,369. A test's `anon` read of `app_settings`, whose policy calls `is_dev()`.
- `permission denied for function …` on a handful of RPCs: about 270 more.

Each burst was one or more runs; a full `npm test` left about 280 to 300 refusals, from Node's own fetch (user agent `undici`), with no referer. Thirteen runs in the window, from two networks. Nothing was written: every request was refused. No lock timeout, statement timeout, deadlock or connection error was in the log.

**The fix.** `test.env` in `vite.config.ts` sets `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` for every test run. Vitest spreads `test.env` over what it read from the `.env` files and over the shell, so the stand-in wins on a dev machine and in CI alike. The host does not resolve, so an unmocked call fails at once and leaves the machine nowhere.

`src/test/testRunNeverReachesProd.test.ts` holds it: the two values, and the host the client was built on. It failed against the old config on a machine with a real `.env.local` and passes now, with the file and without it.

**A side effect.** A worktree with no `.env.local` runs the suite. The *Missing VITE_SUPABASE_URL* throw at import no longer needs the symlink for tests; a dev server still needs it.

No migration, no edge deploy, no app code. `ci.yml` is untouched: its Test steps still pass their own stand-in values, which `test.env` now overrides with the same address.

**Not fixed here**, found on the same read of the log:

- A scheduled GitHub workflow's password sign-in is refused on every run (166 in the window, 20 of 23 hours).
- Edge functions ask `/auth/v1/user` who the caller is with the anon key in place of a user's token (345 refusals in the window).
- A branch ahead of its migration, run against the live database from a dev server, logs a missing-column error per read. That is the branch's own work in progress; `check:calls-ahead` covers the merge.
