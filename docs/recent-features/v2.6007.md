Punch list #185, a fix inside PR 3's feature (v2.5943). The docs pass of 2026-10-28 (#6357) checked the fragment against the code and found two gaps: the step's done fact `review_asked` read an out text saying *a review* or *review us*, which the app's own line (*{first}, thank you for paying for {job}. Would you tell us how we did? It takes one tap: {rate}*) never says, so the step never turned done when the app's text went and stayed due each morning; and a press on Today's sends minted through `mint_customer_rating`, which has no answered check, so an offer on a job the customer had answered minted a fresh ask. A third turned up on the way: the run filed a residential customer's text, its `nudge_sent` record and its event line on `project_id`, a GC project's column, so a Pipeline job's rows failed their foreign key and the flow never saw the text on the job.
