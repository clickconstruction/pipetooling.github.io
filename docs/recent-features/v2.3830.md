# v2.3830 — Supply houses: Apply Payment keeps each bill's own link (2026-09-25)

Quirk 21 of [`MATERIALS_TABS_ARCHITECTURE.md`](../MATERIALS_TABS_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Client only, no migration.

## The bug

`applyPayment` in [`SupplyHousesTab.tsx`](../../src/components/SupplyHousesTab.tsx) sent `update({ is_paid: true, link: applyPaymentLink.trim() || null })` for every selected bill. `supply_house_invoices.link` is the bill's own paper — the invoice form saves the scan there, and the detail table's **View** opens it — so Apply Payment with the optional link left blank wrote `null` over the link of every bill it marked paid.

## The change

- New kernel `applyPaymentUpdate(linkTyped)` in [`lib/materials/supplyHouseInvoiceForm.ts`](../../src/lib/materials/supplyHouseInvoiceForm.ts): `{ is_paid: true }` when the link is blank, `{ is_paid: true, link }` (trimmed) when one was typed. `applyPayment` sends that. `paid_at` is still stamped by the `sync_supply_house_invoice_paid_at` trigger.

## Verified

- `supplyHouseInvoiceForm.test.ts` — a blank or whitespace link carries no `link` key at all; a typed link goes out trimmed.
- Typecheck, lint.

## Left as is

- A **typed** link still replaces each selected bill's link (the dialog's existing behavior — its placeholder reads "Payment or receipt link…"). Whether a payment receipt should live beside the invoice scan rather than over it is a product call for the owner; there is no separate receipt column today.
