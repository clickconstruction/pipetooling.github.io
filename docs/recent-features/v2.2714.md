# v2.2714 — Bank-category tags, PR 1: tables, seed, rules-engine tag clause (2026-09-03)

Owner picked **Variant D** of the "Rules With Tags" mock-ups (artifact 396170dd): tags are data you manage in Banking, rules point at a tag, and a tag can be its own cost line on Review / Job Summary. This PR lays the data and engine; PR 2 ships the manager modal, the tagged rules list and the tag picker.

## Migration `20260903192740_mercury_category_tags.sql`

Fragment in `docs/migrations/`. Two tables (`mercury_category_tags`, `mercury_category_tag_members`), a `can_manage_mercury_category_tags()` helper behind all policies, and an idempotent `seed_default_mercury_category_tags()` that plants the six families: ⛽ Fuel & gas (FuelAndGas, VehicleExpenses, Parking · labels Fuel / Gas, Car and Truck, Vehicle Maintenance · **show as cost line**), 🛒 Retail & supply, 💻 Office & software, 🧾 Fees & services, 🏛 Government, 🍔 Food & travel. Applied to prod with the PR.

## Client kernels — no UI yet

- [`lib/banking/categoryTags.ts`](../../src/lib/banking/categoryTags.ts) (+3 tests): `DEFAULT_CATEGORY_TAGS` (the same six families, the "Reset to defaults" source — keep identical to the SQL seed), `buildCategoryTagLookups(tags, members)` (tag → categories, category → tag, label → tag), `categoryTagForCharge(lookups, labelId, bankCategory)` — the label's tag wins; a labelled charge in no tag stays untagged; unlabelled falls back to the bank category.
- **Rules engine**: criteria v1 gains `bankTag: { tagId, categories }` — `categories` is the membership snapshot taken at save time; `matchAccountingLabelRuleCriteria(tx, criteria, lookups?)` prefers `lookups.tagCategoriesById` when supplied and falls back to the snapshot. Mirrored in the edge `_shared` twin; parity fixtures + 3 client tests. Existing call sites pass no lookups and keep working.
- **`mercury-webhook`** parses every rule once, reads `mercury_category_tag_members` for the tag ids in play, and matches with live membership — so editing a tag changes what its rules catch on the next sync without re-saving any rule.
