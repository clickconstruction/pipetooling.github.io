# v2.4844 — GitHub as the session ledger: claims in refs/claims/*, open PR titles count, the board flags collisions (2026-10-07)

Tooling only, no client change. Grace, 2026-10-07: *"there are other people merging at the same time as us, how could we manage that where different agents across different machines can coordinate?"* The same evening three GC PRs renumbered themselves from the newest PR title, each landing on a number another session held in the local ledger, and two live duplicates (v2.4833 twice, v2.4834 twice) reached the queue.

## What changed

- **Claims live on GitHub.** `npm run claim` still writes the gitignored local file, and now also pushes `refs/claims/v2.NNNN` (or `refs/claims/migration-<stamp>`) to origin with `--force-with-lease=<ref>:`, which the server accepts only when the ref is absent — the same atomic guarantee the local `wx` flag gives, across every machine and cloud session. The ref points at a parentless empty-tree commit whose message is the claim JSON (branch, time, description). A taken ref bumps and retries; a push that fails for lack of network keeps the local claim and says so.
- **Open PR titles count as claims.** The allocation reads `gh pr list` and clears every `v2.NNNN` an open PR carries, so a number picked by hand on another machine is dodged. Without `gh` the script warns and carries on.
- **Sweeps reach GitHub.** A claim at or below main's newest version, or a migration stamp already on main, is deleted from origin on the next run. `--release` deletes both copies.
- **`--branch <name>`** claims on behalf of another branch (the queue guide renumbering a PR it does not own; a detached checkout). Helpers were already passing it.
- **`npm run sessions`** lists the GitHub claims, the local ones (flagging any not on GitHub), the open PRs by version, and a COLLISIONS section: two PRs on one number, or a PR on a number another branch holds. **`npm run sessions -- --brief`** prints the paragraph to paste into any agent on any machine, then the board.
- Docs: `docs/SESSIONS.md` rewritten around the GitHub ledger; one line each in `CLAUDE.md`, `AGENTS.md` and `docs/README.md`.

## Why refs and not a file on a branch

A ref create is the one write GitHub makes atomic without a workflow, a token or a merge: two machines pushing the same `refs/claims/v2.4845` in the same second get exactly one winner. A ledger file on a branch needs a push race resolved by rebase; an issue or a label needs the API and a token the cloud sessions do not have. Refs under `refs/claims/` are invisible to branches, PRs, the merge queue and CI.

## Verify

- `npm run claim -- probe` from any checkout, then `git ls-remote origin 'refs/claims/*'` shows the ref; `npm run claim -- --release v2.NNNN` removes it.
- Two checkouts (or two machines) running `npm run claim` at once get different numbers.
- `npm run sessions` on a machine that never ran the old ledger shows the same claims as this one.
- `src/lib/sessionClaims.test.ts` covers the parsers and the collision finder.
