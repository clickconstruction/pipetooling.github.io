# v2.1935 — Shell guard on the Edit Job status stepper (2026-08-20)

Part 3 of the no-bill-line remediation (v2.1931 filter/chip, v2.1933 fix
modal): stop minting new shells at the source. The Edit Job status strip's
raw `update_job_status` flip to Billed was the path that created the 64-job
stock — Bill Customer always makes the line; the stepper never did.

- `JobStatusStepper.moveTo('billed')` now probes for an existing billed line
  (one head-count select) and, when the flip would strand open money on no
  line, shows an inline confirm row (the Collections-confirm pattern):
  "No bill line — $X open would not age, be chased, or show in the payment
  forecast" with **Create line & mark Billed** (flips status, then
  `create_billed_shell_invoice` dated today; a line failure still leaves the
  status flipped, with an explanatory toast), **Mark Billed only**, and
  Cancel. Probe failures fail open to the plain flip.
- Kernel `billedMoveNeedsShellGuard` in
  [jobStatusStepper.ts](../../src/lib/jobs/jobStatusStepper.ts) (+1 test):
  guard fires only for to-Billed with open money and no billed line.
- No migration — reuses v2.1933's `create_billed_shell_invoice`.
- Out of scope (noted): the Paid-section "send back to Billed" path can also
  produce shells during payment unwinds; those resolve through the fix
  modal / Send-back machinery rather than this guard.
- Help guide `edit-job-autosave` (status strip section) updated.
