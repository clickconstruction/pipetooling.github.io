# v2.7175 — Materials on site: a job that did not load says so, never zero (2026-11-13)

Punch list #344, PR 3. From the review of Materials → On site: *a failed read draws as a true zero*.

## What was wrong

- **The desk.** `loadDesk` reads the jobs that hold a live box, then reads each job with `loadJob`. A job's read that fails keeps its error on the job (`jobLoadState`) and does not throw, so the desk's own load succeeded around it. The desk never read `jobLoadState`: the job's row drew from an empty cache as 0 containers, 0 lines, $0.00 missing and a green *all this fortnight*. Its site's row added the zeros in.
- **A site's screen.** It draws the jobs handed to it from the store, so a job whose read failed was left out without a word and every tile was short by its boxes.
- **Which job is on which site.** `useOnSiteSites` swallowed a failed read and set `loaded`. `?site=` then filtered every job out and drew *across 0 jobs* and *No part is on hand on this site yet*.
- **The joined names.** `usePartTies` swallowed a failed read, so joined rows split and the worth dropped with nothing said.

## The change

- `src/lib/materials/onSiteReadFailed.ts`: the words, tested.
- **The desk** (`JobsMaterialsTab.tsx`): a job whose read failed is a row that reads *Did not load.* and the reason, with **Read again** (`loadJob` with `force`), in place of figures. Failed rows sort first. The site's row adds *1 job did not load*. A failed sites read draws a panel that says each job is on its own row.
- **A site's screen**: `OnSiteJobsNotLoaded.tsx` above it on both mounts names how many of the site's jobs are not on the screen, and Retry reads just those. A failed sites read is said in place of an empty site.
- **The hooks**: `useOnSiteSites` and `usePartTies` hand back `failed` and `retry`. The site's screen draws a panel when the joined names did not load.
- Every panel is `OfflineRetryPanel` with `idempotent`, so a lost signal reads again by itself, and a refusal shows its reason with no Retry. Each passes its own sentence for a lost signal, since the screen still draws what did load and the shared sentence would not say what is missing.

Client only.

## Tests

`onSiteReadFailed.test.ts` (3). `JobsMaterialsTab.desk.render.test.tsx` (2), the desk's first render test: a failed job's row carries its reason and no figure, the site row counts it, and **Read again** reads that job alone. `MaterialsOnSiteTab.site.render.test.tsx`: a field role's site screen names the job that did not load, and Retry reads it again.

## Not changed

The Needs you card's two lines still leave out a job whose read failed (`useMaterialsOnSiteNeeds.ts`). The card is a count across jobs with no place for a reason; it is on #344's list.
