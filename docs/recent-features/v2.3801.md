# v2.3801 — Day book: a past Billed line says what was still left to bill (2026-09-24)

Close-out of [`to-dos/day-book`](../../to-dos/day-book/README.md) (#20), PR 2 of 2. Decision 6 (v2.3736) let a dev or controller's Dashboard record the Needs You card's counts as the day's queue snapshot, but only `deposits` and `contracts` were ever sent — `record_day_book_queue` and the kernel accepted a `billing` kind that nothing wrote, so a Billed line never ended with what was left.

## The change

- **`useDashboardBillingInvoices`** gains `readyToBillLoaded` — true once both Ready to Bill reads have answered without error, reset when the viewer becomes ineligible — so the recorder never writes the empty pre-load list as *0 left to bill*.
- **`Dashboard.tsx`** passes `readyToBillCount` (the Ready to Bill stage's unit count, null until loaded) to **`DashboardPinnedQuickRow`**, whose recorder effect sends it as the `billing` kind beside deposits and contracts; `planQueueRecord` already merged per kind (v2.3743), so no kernel change there.
- **`dayBook.ts`** — the history "left" for a `billed` line reads *13 left to bill* / *none left to bill* (was *left to send*; the queue is the Ready to Bill stage, bills still to be made). **`PeopleDayBookTab`** — today's Billed line reads the same recorded figure, since the tab has no live hook for the stage's count; the Month grid's Billing row can go amber from the first recorded day (`dayBookQueueHeldWork` already read every kind).
- Help guide *see what the office got done on any day* and `PROJECT_DOCUMENTATION.md`'s `day_book_queue_snapshots` line amended. No migration: the CHECK and the RPC accepted `billing` since v2.3736.
