# v2.2273 — Map goes one-handed: hold-to-lift, tap-to-open, safe-area exit (2026-08-25)

Owner-reported with iPhone screenshots (mockup artifact 9727d235). Three
mobile fixes to the roadmap Map (`ChecklistTechTreeGroupNode.tsx` +
`ChecklistTechTreeTab.tsx`):

- **Hold-to-lift task reorder, no mode needed** (v2.2270's interaction,
  Map edition): the tab's task-dnd `PointerSensor` switches to
  `{delay: 280, tolerance: 8}`; editors' task rows are ALWAYS sortable
  (`d.canEditStructure` gate, was `reorderMode && canEditStructure`) with
  listeners on the `<li>`; the held row scales on a shadow. The grip renders
  only in Reorder mode (`showGrip`), which also keeps the empty-stage drop
  targets; `onTaskDragEnd`'s reorder-mode guard drops to editor-only. Same
  ghost-click guard pattern as v2.2270.
- **Tap opens the task card, every role**: `TechTreeEditableTaskTitle`
  becomes a tap-to-open button (`role="button"`, Enter/Space). The 500ms
  title long-press AND the v2.2253 row-level `useTaskRowLongPress` are
  REMOVED — holding now means "lift", tapping means "open"; the two could
  not coexist (a stationary 500ms hold would open the card mid-drag).
- **Fullscreen escape**: the fullscreen toolbar pads
  `calc(8px + env(safe-area-inset-top))` so it clears the phone status bar
  (the exit ✕ used to hide under the clock — "impossible to get off"), and
  the ✕ grows to a 44px minimum target.

Verified live: tap opens the card, hold lifts (shadow + z-index mid-drag),
the drop's ghost click no longer opens a card. Fullscreen styles are static
(the hidden test pane can't engage the Fullscreen API) — thumb-test on
device.
