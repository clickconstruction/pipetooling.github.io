# v2.2700 — Label fuel as fuel: bank-category rule clause + Review fuel split (2026-09-03)

Owner-approved steps 1 and 2 of the fuel question raised by the parts query (finding 11): fuel was a third of card "parts" on field jobs and indistinguishable from pipe. Banking already had the Schedule C label (**Fuel / Gas**, `default_key = 'fuel_gas'`) and a rules engine; what was missing was a rule clause that can see the bank's category, and a consumer that reads the label.

## Step 1 — rules can match the bank category (client + edge, no migration)

- `AccountingLabelRuleCriteriaV1` gains `bankCategory?: { op: 'contains' | 'equals'; value: string }`, matched case-insensitively against `mercury_transactions.mercury_category` (jsonb holding a JSON string; `mercuryCategoryFromColumn` normalises string / `{ name }` / null). Counts as a substantive clause; empty value = absent. `AccountingLabelRuleMatchTx.mercury_category` is optional so every existing call site compiles; a rule with the clause simply never matches a transaction that was loaded without the column.
- Mirrored byte-for-byte in [`supabase/functions/_shared/accountingLabelRuleMatch.ts`](../../supabase/functions/_shared/accountingLabelRuleMatch.ts); the parity test gains five criteria fixtures and four transaction fixtures. **`mercury-webhook`** now selects `mercury_category` on the upserted row and passes it to the matcher — redeploy required (`supabase functions deploy mercury-webhook`).
- Call sites that carry the column: the Accounting tab's transaction list (`MERCURY_TRANSACTIONS_BANKING_LIST_COLUMNS` already included it), `TransactionDetailModal`'s "Applicable rules". The Tally payroll-rules modal's rows do not carry it (not needed there).
- **Rule editor** (`AccountingRuleFormModal`): new "Bank category" fieldset (equals / contains + a datalist of the categories seen on this org's transactions) with the hint "FuelAndGas → Fuel / Gas is the usual rule"; the at-least-one-criterion message lists it. +3 kernel tests.

## Step 2 — Review names fuel (client, no migration)

- `loadTeamReviewUnion` selects `mercury_transaction_id` on card allocations and builds `fuelChargesByJobId` (new `TeamReviewUnion` field): an allocation is fuel when its transaction carries the `fuel_gas` label (`fetchAccountingBucketByTxId`, the same lookup Overhead/Job Summary use), or — when it has no label yet — when the bank category is `FuelAndGas`. Always a slice of `cardChargesByJobId`; the parts total is unchanged.
- `derivePersonTeamSummary` allocates the cost buckets on the same ratio as revenue: new row fields `allocatedParts` (all parts, fuel included), `allocatedFuel`, `allocatedLabor`, and `fuelCost` on each `netBreakdown` job, so `gross − parts − labor = net` per person.
- Ranked view: the math drawer's single "− Parts, subs & team labor" line becomes "− Parts & job purchases", "− Fuel", "− Subs & team labor" (falls back to the single line for rows without the split); the verdict composition bar gains a **Fuel** segment (`ReviewVerdict.fuel`).
- Live as dev, Last 30 days: verdict bar reads Parts, subs & labor · Fuel · Overhead labor · Parts burden · Profit; the team's fuel slice is visible for the first time.

## Docs

- `EDGE_FUNCTIONS.md` mercury-webhook: criteria v1 now lists `bankCategory`; help guide `read-the-team-review.md` drawer example split into the three lines.

## Operating it (owner)

1. Banking → Accounting → Rules → New: label **Fuel / Gas**, Bank category **equals FuelAndGas**, save.
2. **Apply rules to transactions** for the backlog (creates suggestions to approve, capped per click as before). New syncs are pre-tagged by the webhook once it is redeployed.
3. Review's fuel line already reads the bank category for unlabelled purchases, so it is correct before step 2 finishes; the label lets you override the bank when it is wrong.
