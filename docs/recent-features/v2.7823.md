# v2.7823 — Tasks: an assistant can close a task that no longer applies (2026-11-18)

The fourth of the dev seat's task verbs, on `dev-mcp` (server 0.103.0, 127 write verbs): **`plan_task_close`** → **`apply_task_close`**. The owner, 2026-11-18, about an old open task: "if we don't have dev verbs to do this, I would like to add them."

## What it does

It closes a one-time Checklist task without the work done, as the card's More → *No longer applies* closes it.

- `close = { task, why, day? }`. `task` is an id from `find_task`, or words that find one task. `why` is the reason the thread keeps, 3 to 200 characters. `day` is needed only when a task has more than one open day.
- The write is one call of `task_no_longer_applies` (migration `20261117120000`), the function behind the card's own press, as the dev.
- The day row is marked complete. The thread reads *completed*, then a *dropped* line with the reason.
- The task leaves the open lists and shows in History as closed, no longer applying.

## What it is not

It is not *done*. The close says the work was not done by the person the task is for, and why. No verb marks a task done. A completion can ask for a finishing photo and Done when… lines, and those are the doer's.

## The dry run

No wrapper RPC. The dry run is the server's read of the task, who gave it, who it is for and its day rows (`_shared/devMcpTaskClose.ts`). It holds the function's own refusals, so an apply does not end in one the read could see:

- a task that repeats,
- a roadmap task, whose completion would mark the roadmap task done,
- a vehicle task, whose completion would mark the service done,
- a day already done.

The function cuts a reason at 200 characters without a word. The seat refuses a longer one instead, so the plan shows the words the thread will keep.

## Who is told

Whoever gave the task gets the push the card's press sends (`dropPush`, through `send-checklist-notification`), unless that is the caller. The people the task is for are not told, as the card does not tell them. A push that does not go is named in the reply and undoes nothing.

## One rule, two readers

The reason's rule and the push's words moved out of `src/lib/tasks/taskDoerActs.ts` into `src/lib/tasks/taskDrop.ts`, a file with no imports. `taskDoerActs.ts` hands every name on, so the card reads them as before. The seat reads the same file through the kernel copy. `taskDoerActs.ts` itself cannot be copied to the edge: it reaches `doFirst.ts`, which reads the browser's storage.
