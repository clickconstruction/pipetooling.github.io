# v2.5056 — Division 22 rules: a deleted rule or section can be put back (2026-10-09)

PR 2 of the Division 22 rules manager train (`to-dos/division-22-rules-manager.md`): the archive comes before any screen that deletes. Migration `20261010015000_d22_ledger_archive_on_delete.sql`, with its doc. Punchlist pushes it.

## What changed

- **Both ledger tables join the deleted-records archive.**
  - `spec_section_match_rules` is keyed by `section_code`; a no-code rule falls back to its own id. `spec_sections` is keyed by `code`.
  - The trigger is `zzz_archive_on_delete` → `archive_deleted_record`, the same idempotent DO-block as `20261008070000`.
  - A deleted rule or section is restorable for 90 days from Recently deleted. Before this, a deleted rule was gone for good.
- **Recently deleted** (`deletedRecordContents.ts`) names the tables *Division 22 rules* and *Division 22 sections*.
  - A rule reads in the audit window's words, such as *contains FD- → 22 13 19*.
  - A section reads as its code and title.
- **Restores, caveat:** `restore_deleted_records` finds a parent in the same bundle by `record_id`, and a section has none. So a section deleted with its rules would bring them back as no-code. The manager refuses to delete a section that still has rules (PR 4), and the doc says to restore a section before its rules.
