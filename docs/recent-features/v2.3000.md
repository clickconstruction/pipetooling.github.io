# v2.3000 — Test-gap audit, pass 18: Bill Customer memo presets get their first tests (2026-09-07)

Follow-up to v2.2997. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`billCustomerMemoPresets.ts` (452 lines) is the memo-preset store behind **Bill Customer → Memo** and **Settings → Bill Customer memo presets (dev)**: two shipped built-ins (Standard, Alternate — empty until customised), up to twenty dev-added presets, a default-on-open, all stored once per org in `app_settings` and mirrored to `localStorage` for the session. It also decides the "Standard / Rush / Custom / None" summary the Send & Record Invoice modal shows for a memo. No test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Stored bodies get the same normalisation as the invoice footer (minimal HTML stripped, NFKC, trimmed) and the same 5,000-character cap; labels are trimmed and capped at 200, and a blank label override is dropped.
- The stored JSON is **sparse**: only overrides that differ from the shipped defaults, only non-blank custom presets, and no `defaultPresetId` when it is Standard. When nothing differs, saving deletes the org row instead of writing an empty one. The local mirror holds the same sparse shape.
- A default pointing at a preset that no longer exists (including one cut by the twenty cap) falls back to Standard.
- On first load with no org row, a signed-in dev migrates a device-only mirror up to `app_settings`; other roles read the mirror but never write. Nothing on the device means no write.
- A memo is recognised as a preset after the same normalisation, so a memo pasted with CRLF or minimal HTML still reads "Standard".
- A failed save surfaces to the caller and leaves the session on the old presets; a failed delete on reset is swallowed.
