# v2.2099 — Partner ledger row drill-ins (pay report, charge editor, detail cards) (2026-08-22)

Owner ask (screenshot of the Bryan ledger): every row on Partnerships → Ledger should be clickable — details/edit for chargebacks, the pay report for labor rows. Mockup approved via the "Partner Ledger Drill-ins" artifact, then built.

- **Kernel** (`src/lib/partnerLedger/partnerLedgerJournal.ts`): rows now carry their backing identity — `JournalRow.offset_id` (set from the new `JournalCharge.offset_id`; null on stub-derived rows), `JournalPendingOffset.id` passthrough onto `PendingJournalRow.offset_id`. Pure additive; tests extended.
- **New kernel** `src/lib/partnerLedger/partnerPayReportHtml.ts` (+ tests): `buildPartnerPayReportHtml` — standalone print-ready pay-report document for one partner statement week: per-day hours at the stamped `pay_stub_days` rates, attached additional lines / deductions / payouts, and `partnerStatementRemainder` (gross + additions − deductions − payouts) as the "still on this statement" headline. Partner-safe by construction (no wages of others, no revenue).
- **`PartnershipLedgerTab`**: posting/pending rows get hover affordance (row highlight + `›` chevron) and click routing — suppressed while the note composer is open (rows stay click-to-place date targets):
  - **Labor** → loads `pay_stub_days` + statement attachments, merges same-day same-rate segments, drops empty zero-hour day rows, and shows the built document in `PayStubViewModal` (Print included).
  - **Charges/pending offsets** with editable types (backcharge / damage / employee_credit) → existing `PersonOffsetFormModal` in edit mode; machine-posted types (profit_share, utility_overage) get a read-only card pointing at Job review instead of editing.
  - **Payouts / statement additions / deductions** → read-only detail card (amount, memo, which statement week) with a pointer to the owning flow.
- `PayStubViewModal`: document-level Escape handler (the dialog's own `onKeyDown` only fired with focus inside it) — benefits People → Pay too.
- `Partnerships.tsx`: passes `personName` into the Ledger tab (offset editor + report title).

No migrations; reads ride the existing dev payroll-access RLS. Verified live against the Bryan partnership (report, editor prefill, cards, Escape).
