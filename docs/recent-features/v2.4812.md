## What changed

- **`legal_matters`** gains `narrative_md`, `narrative_updated_at`, `narrative_updated_by` ([migration page](../migrations/20261007234000_legal_matter_narrative.md)); **`legal_set_narrative`** writes them for the office cohort, trims, refuses more than 40,000 characters and stamps who and when from the session.
- **[`_shared/legalNarrative.ts`](../../supabase/functions/_shared/legalNarrative.ts)**: the type, the row reader (none when empty), the defensive parse, the standing line (*The office's account of this matter, written by … on …. The record behind it is on the other tabs, and the documents it names are under Evidence.*), the limit, and the outline of the four parts counsel reads first.
- **[`legalNarrativeHtml.ts`](../../src/lib/legal/legalNarrativeHtml.ts)**: marked, then the contract-signing sanitizer the help guides use (headings, lists, tables, emphasis, links kept; scripts, styles, forms, images and inline handlers dropped; an href only when absolute http(s)), each kept link opening in a new tab.
- **The desk** ([`LegalNarrativeEditor`](../../src/components/jobs/legal/LegalNarrativeEditor.tsx)) is the desk's first tab: *Write* / *Preview as the firm sees it*, *Start from the outline* while empty, *Save narrative*, *Undo changes*, the character count, *Saved … by …*. An account with no matter yet gets one made first (`legal_matter_save_review`). Read only for a role that cannot edit the review. The desk's preview of the firm's view shows the saved narrative.
- **`legal-portal`** sends `narrative` per matter from a separate read that tolerates the columns' absence before the push; `shapeMatterForCounsel` cuts it to its keys.
- **The firm's portal**: *Narrative* is the first tab when the office has written one, and the tab a matter opens on (`firmTabsFor`, `firmTabShown`); otherwise the tab is not drawn and the matter opens on Account as before. The standing line sits above the rendered text (`.legalNarrative` in `src/index.css`).
- **The printed packet** opens with *Narrative*, its standing line and the text, before the exhibit index.
- **The sample matter** carries a narrative in the four parts.
- **On a phone**, the Documents table's kind-and-size line reads 12 px like the portal's other small type (`portalSmall`, [v2.4808](v2.4808.md)).

## Is this the best we can do?

- **Labelled, dated and signed.** Counsel reads it as a brief from the client, which is what it is; the record stays on the other tabs.
- **First when it exists, absent when it does not.** An empty first tab would be noise; a matter with no narrative opens on Account as before.
- **Markdown, not a rich editor.** The office already writes markdown in the help guides, the app already renders it safely, and a session can write it.
- **Not done:** an email to the firm when the narrative changes, versions of it, and the dev MCP verbs to write it from a session (next).
