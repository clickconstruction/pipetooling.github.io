# v2.8165 — Trips: the dev seat's plan refuses a joined trip in the database's words (2026-11-21)

Punch list #379. Taunya, 2026-11-21: "in the dev seat, plan_trip's dry run still says add for a joined trip, and the real save is then refused. The migration page documents this." `dev-mcp` 0.123.0. No migration, no new verb.

## What was wrong

v2.8127 added a trigger on `trips`, `trips_refuse_joined_back` (migration `20261120130000`). It refuses a trip made again under the id of a trip that **Join with the next** joined into another, in words that name both trips and **Split in two**.

`trip_save`'s dry run writes nothing, so it never reaches a trigger. For a joined trip it answered `would: add`. The seat's `plan_trip` passed that on under a `plan_hash`, and `apply_trip` was then refused by the trigger. A plan and its apply disagreed.

## Why the fix is in the seat

The seat is the dry run's one caller. The app saves a trip with `p_dry_run: false` in one place (`saveTrip` in `src/lib/trips/tripsIo.ts`) and sends no dry run, so no screen read the wrong answer.

Teaching `trip_save`'s dry run to hear the refusal would have meant replacing a function three migrations have written, and a new definer for it to read the archive through, since `trip_save` runs as the caller and the archive is the dev's alone. That is more to go wrong on prod, for one caller.

The risk of the seat's way is one rule written twice. It is held three ways:

- The rule is in the seat once: `tripJoinedMark`, `tripJoinedBackWords` and `tripPlanJoinedBack` in `_shared/devMcpTrips.ts`.
- `devMcpTrips.test.ts` finds the newest migration that writes the trigger, builds its sentence from the function's own text (its two formats and its three names) and holds the seat's sentence to it for every case. A later rewording of the trigger fails CI until the seat follows.
- The database still refuses the save. The plan only says it one call sooner.

## What changed

- **`tripPlanJoinedBack`**: after a dry run that says `add`, the plan reads the newest delete of the trip's id that nothing has put back (`deleted_records_archive`, `table_name = 'trips'`, `restored_at` null, newest `deleted_at`), as the dev. When that row carries `joined_into`, it reads whether the joined trip is still kept, which picks between the trigger's two sentences.
- **The refusal**: *plan_trip: this trip would not be saved. Trip 2 was joined into Trip 1, which holds its days. To take the join back, press Split in two on Trip 1. The database refuses the save (22023), and apply_trip would be answered in the same words. Split in two is a press in the app, and this seat has no verb for it.* No `plan_hash` comes with it, so nothing can be applied.
- **What it leaves alone**: a change inserts no trip, so nothing is read. A trip somebody deleted carries no mark and plans `add`, which is how it is put back. A mark the trigger cannot read is passed over, as the trigger lets that save through.
- **An archive that does not read** leaves the plan standing, with a note that it could not check. The trigger lets such a save through too.
- **`apply_trip`** reads nothing more and hashes as before. A join made between a plan and its apply is refused by the database, in the same sentence.
- **Docs**: the migration page's two lines on the dry run, the verb's row in `docs/dev-mcp/README.md`, `SERVER_NOTES.md` and the `dev-mcp` section of `EDGE_FUNCTIONS.md`.

The SQL bed `supabase/tests/trips/95_joined_back.sql` is unchanged: `trip_save`'s own dry run still says *add*, and the bed still pins that.

## Verification

- `devMcpTrips.test.ts`: the sentence against the trigger's text for all eight cases and against the three on the migration page, the read against the trigger's own `WHERE` and `ORDER BY`, the mark and what is passed over, the refusal with the joined trip there and deleted too, every plan left as it was, and the note when the archive does not read.
- `devMcpTrips.run.test.ts`, through the function over a fake database whose save refuses as the trigger does: two trips kept, the second joined away, its plan refused with one dry run and no write, the apply of a plan made before the join answered in the same sentence by the database, a deleted trip planned and put back as before, and a failed archive read.
