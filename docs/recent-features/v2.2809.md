# v2.2809 — Users row needs kernel: hours beside paperwork and account (2026-09-04)

PR 1 of 4 for the People → Users status column (owner pick from artifact 747a0b27: the icon rail on wide screens, an hours counter plus a "Needs you" pill on phones). This PR is the model; the row's rendering switches in PR 3.

- **`src/lib/people/rowNeeds.ts`** (tested): `buildRowNeeds` groups the rail facts, the contract signing light, push and roster state into `{ hoursWaiting, hoursLine, needs: RowNeed[], needCount, attention, reasons }`. Each `RowNeed` has a subject (`paperwork` | `account`), a tone (`red` | `amber` | `fact`), a count, the chip text, the tooltip sentence, the verb that clears it, and the Desk section it opens. One paperwork need folds the old "N doc unsent", "N expiring", "N expired", "docs waiting" and "docs unsigned" chips; the account subject holds "no roster row" (a need) and "no login" / "no push" / "portal on" (facts).
- **Owner decisions:** hours are a routine queue, not an alarm — they never color the dot or count toward Needs attention; facts show but never count.
- **`usersTabRows.ts`**: `applyRowNeeds` re-reads a rail row through the needs (dot + reasons); new **Hours to approve** filter pill reads `hoursWaiting`. `RailRow.rowNeeds` carries the needs for the row.
- **`loadRailFacts.ts`**: contract documents that carry a `person_id` are keyed `p:<id>` (`docFactKey`), so a renamed person keeps their chips; name-only rows and licenses stay keyed by pay name. The kernel reads both keys.
- **Users tab today:** the dot, Needs attention and the new Hours filter already follow the kernel; the old chips still render until PR 3. Help guide "add someone to the roster" names the new filter.
