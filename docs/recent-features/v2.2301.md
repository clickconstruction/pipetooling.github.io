# v2.2301 — Prospects Follow Up: calling-order switch + queue peek (2026-08-25)

Owner: an assistant caller "would prefer … the option to call people that have never been called before as an alternative to the current calling order or to at least see the calling order." Mockup approved (both pieces): https://claude.ai/code/artifact/09334b80-feb2-4b5a-a4d1-18c35846d821

**Root cause found:** the queue was `last_contact ASC NULLS FIRST` (coldest first), but `last_contact` is stamped by any interaction (site-visit note, email) — so prospects nobody ever *called* sink into the 180-day backlog.

- **Kernel** [`src/lib/prospects/callingOrder.ts`](../../src/lib/prospects/callingOrder.ts) (+8 tests): `orderFollowUpProspects` (never-called lead by `created_at` asc, then the coldest-first rest — a re-order, never a filter, so the queue can't run dry), `queueAgeLabel` (`added/noted/called Nd ago`), `readCallingOrderMode`. "Called" = has any `didnt_answer`/`answered` comment (`CALL_INTERACTION_TYPES`).
- **[`Prospects.tsx`](../../src/pages/Prospects.tsx)**: `loadFollowUpProspects` also loads called prospect ids (one `prospect_comments` select) and orders via the kernel; mode is per-user localStorage (`prospects_calling_order_v1_<uid>`), read through a ref so toggling just re-runs the load (the URL-synced `?prospect_id=` keeps the current prospect selected across the reshuffle). New strip under the action row: `Calling order  Coldest first | Never called first` + `N of M · show order ▾` expanding a ≤15-row window (position numbers, never-called badges, age labels, "← you are here"; tap = jump, resets the this-time timer). The info card gains a green **never called** badge beside the due badge.
- No help guide updated — the Follow Up workstation has no guide yet (known gap; team-prospects covers hiring only).

Client-only; no schema changes.
