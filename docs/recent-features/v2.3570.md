# v2.3570 — Email reports, one modal — PR 1: one door, two tabs (2026-09-17)

The owner, 2026-09-16: *"I would like to combine these two into the same modal."* PR 1 of `to-dos/email-reports-one-modal/README.md` — Option A, the shape the owner liked on the before / after (`before-after-pr1.html`). Client only; no migration, no edge function. PRs 2–3 (Option B, one list by person) wait on the owner's pick.

## What changed on screen

- **Jobs → Reports**: the toolbar's *Recurring Email Reports* and *Report email recipients* are one **Email reports** button (on a phone, one **Email reports** link where there were two).
- **The modal** ([`EmailReportsModal.tsx`](../../src/components/jobs/EmailReportsModal.tsx)): title, a one-sentence intro naming the two kinds, then tabs **Digests** *a bundle on a schedule* · **Every report** *one email per report, as filed*. Only the tab that shows is mounted, so each body loads exactly as its old modal did. 900px wide, as the digests dialog was, so nothing in that body reflows.
- **Digests tab** ([`RecurringDigestsPanel.tsx`](../../src/components/jobs/RecurringDigestsPanel.tsx), the old `RecurringEmailReportsModal` body moved verbatim): the schedules list and its inline editor come first; the Org / Recipient / Scope / Filter / Include costs toolbar with *Preview HTML* and *Send test email* folds under a **Preview or send a test** disclosure below the list. Same controls, same handlers; the schedule line keeps today's format.
- **Every report tab** ([`ReportEmailRecipientsPanel.tsx`](../../src/components/dashboard/ReportEmailRecipientsPanel.tsx), the old `ReportEmailSettingsModal` body moved verbatim): today's recipient cards, unchanged.
- **Dashboard → Recent Reports**: the mail button opens the same modal on *Every report* (`initialTab="every"`). Its Digests tab needs the viewer's scope-leader choices, so that loader left `JobsReportsTab` for a shared hook, [`useRecurringReportScopeMasters`](../../src/hooks/useRecurringReportScopeMasters.ts) — the same rule (a master is their own; assistant-like roles get their adopters; a dev gets every active master).
- **Strings**: Settings → My email schedule's two *managed from* lines, Settings → Email streams' Field report emails card, both guides (*email reports to owners and managers*, *see your email schedule*), `docs/REPORT_SUBSCRIPTIONS.md` and the send-report-email section of `docs/EDGE_FUNCTIONS.md` read **Email reports** and name the tab.

Both old modal files are gone (renamed to the panels); nothing else imported them.
