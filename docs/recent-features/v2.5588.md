# v2.5588 — The deploy log shows a build’s real error (2026-10-16)

Main's deploy failed in **build** from `ea73ca32d` (v2.5575) on, and the log said only *[copy-404] ENOENT … dist/index.html → dist/404.html*. The real error (every lesson `.md` parsed as JavaScript by a lazy `import.meta.glob` with no `?raw` — fixed in v2.5589) only showed once the plugin was silenced locally.

- **`vite.config.ts`**, the `copy-404` plugin: Rollup runs `closeBundle` even after a failed bundle, and the plugin's `copyFileSync` threw on the missing `index.html`, replacing the build's own error in Vite's *error during build* line. It now returns when there is no `index.html` to copy, so the error the log shows is the one that stopped the build. A finished build still gets its `404.html`.

The PR checks never run `vite build` (only `deploy.yml` does): run `npm run build` before merging a change to a glob, an asset import or `vite.config.ts`. No migration, no edge function, nothing on screen.
