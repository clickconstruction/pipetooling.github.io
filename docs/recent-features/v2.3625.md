# v2.3625 — Sub sheet payments: the row fits the form; the trace is dated by the company calendar (2026-09-19)

Two fixes from the first live run of [`to-dos/sub-payment-move-remove/README.md`](../../to-dos/sub-payment-move-remove/README.md) (v2.3562 / v2.3605), made on two throwaway sheets for *Claude Test Sub* on J1032 *ZZ TEST GC Notice Job*. Client + one shared edge module; no migration.

## What the live run found

1. **The row did not fit the form.** Edit Sub Labor is `min(400px, 100vw − 2rem)` wide — 352px of content on a desktop, 288px on a 375px phone — and the Payments table (Date · Type · Amount · Memo + a 200px / 110px actions column) measured 401px / 415px inside an `overflow: hidden` wrapper. On a desktop the Date column was clipped; on a phone the **⋯** button sat at x = 365–401 against a wrapper ending at 332, so **Move and Remove could not be reached at all**.
2. **The trace line was dated in UTC.** `subPaymentTraceLines` and the portal's `buildSubPaymentTraceLines` both took `created_at.slice(0, 10)`. The run was at 8:50 PM Central on Sep 19 and both sheets read *9/20/2026*. `buildSubPaymentLines`' fallback for a payment with no `payment_date` had the same slice.

Everything else behaved as drawn: the same sub's other sheet topped the list, *What changes* matched both sheets' own totals, the date and memo travelled, *Moved →* / *Moved here from* drew on both sheets and on the ledger's expanded row, Remove with *Duplicate entry* drew *Removed · Robert · Duplicate entry* with **Undo**, and Undo brought the payment back.

## The change

- [`JobsSubLaborFormModal.tsx`](../../src/components/jobs/JobsSubLaborFormModal.tsx): a payment is two table rows — date · type · amount, then one `colSpan={3}` cell with the memo (wrapping) beside the actions. Trace lines take the same shape, with **Undo** on the second line. Three columns fit 288px; the wrapper is `overflow: visible` so the phone's ⋯ menu drops past the last row. Desktop keeps Edit · Move… · Remove, a phone keeps Edit and ⋯ with 44px items.
- [`subPaymentMoveRemove.ts`](../../src/lib/jobs/subPaymentMoveRemove.ts): the line's date is `calendarYmdInAppTzFromIso(created_at)`; lines sort by the instant, so two events on one day stay newest first. The ledger's expanded row (`PeopleContractsTab`) reads the same kernel.
- [`_shared/subPortalStatement.ts`](../../supabase/functions/_shared/subPortalStatement.ts): `ymdInAppTzFromIso` (over `todayYmdInAppTz` from `_shared/appTimeZone.ts`) dates the trace lines and the payment-date fallback.
- Guide `sub-labor-outstanding`: says the verbs live on **Edit sheet** and that the row is two lines.

## Tests

Kernel: an 01:50Z event reads 2026-09-19 and same-day lines stay newest first. Portal module: the same evening case; two fixtures that sat at midnight UTC moved to mid-day. Render: a payment row has three cells, the memo and **Move…** sit on the next line, and Move… hands the payment to the parent.

## Verified

Dev server on the two test sheets: table 350 / 350px on a desktop and 288 / 288px at 375px; the ⋯ menu opens unclipped with both items; the trace reads 9/19/2026 on both sheets.
