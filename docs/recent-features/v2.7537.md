# v2.7537 — Checklist: add a task for yourself, or a follow-up from one you finished (2026-11-16)

Punch list #369, step B1 of the Task Mode train (tool 6), stacked on A2 (v2.7536). The first of the tools that let the person doing tasks act without waiting on someone. No migration, no edge function.

## Why

A person in Task Mode could already give themself a task, through the header's Task press. At phone width that press is an icon with no name, and nothing on the checklist pointed at it. And a task that turned up more work had no way to say so except a note.

## What changed

- **＋ Add a task for me**, a dashed press under the day's tasks (`ADD_OWN_TASK_LABEL`). It opens the New task window with the person picked and Today lit. It shows on an empty day too, under *Nothing due today.*
- **Follow-up**, a quiet pill on a finished task (`FOLLOW_UP_LABEL`). New task opens with:
  - the first task's words as *After Check the truck fluids: *, cut at 60 characters, the cursor's place after the colon (`followUpTitle`);
  - the first task's place, when it has one. A way in painted for the first task stays with that task;
  - the first task's giver lit under **Tell someone else**, unless the writer is the giver (`followUpTellsId`).
- Both read the day again once the window has sent, so a task for today shows at once.
- **Who sees them:** the roles the header's Task press shows for (`showHeaderTaskChecklistButton`): dev, master, assistant and controller, primary, estimator, subcontractor and helpers. A superintendent may not write a task under the table's rules, so neither press is drawn for one.

## How it is built

- The New task window's preset (`ChecklistAddModalPreset`) gains `place` and `tellUserId`. The window sets its place and its *Tell someone else* from them when it opens. Nothing else about the window changed.
- `ChecklistTodayTab` takes `canAddTask` and opens the window through `useChecklistAddModal`. No write happens on the tab.
