# v2.7534 — Bids: keep an email's files as a set of plans, from the email itself (2026-11-16)

Punch list #368, PR 2 of four: the press. PR 1 (v2.7531) is the function and the column under it. No migration and no function here.

## Where the press is

The owner's question on the plan was how anyone reaches this from a screen. The job's press, *Keep this mail as a paper*, draws only in My email, which shows your own mailbox, so a mail another person tagged or the dev seat tagged offers it to nobody else. The bid's press sits on the mail itself:

- **Messages, the mail's window.** `emailViewerActions.ts` gives a line on a bid a second press, `keep_on_bid`, when it is an email that carries a file (a link is not a file). `EmailViewerActions.tsx` draws `BidMailSetDoor` for it, beside *Open the bid*. The whole office team sees it.
- **My email.** `MyMailReader.tsx` draws the same door on a mail tagged to a bid whose line is on the bid.

PR 3 adds the Development page's History line and a list under the bid's Plan sets.

## What the door draws

`BidMailSetDoor.tsx` reads the line's files and the bid's sets, and `bidMailState` (`src/lib/bids/bidMailSet.ts`) says which of four things to draw:

- **Nothing**, for a mail with no file.
- **The press**, while a file we hold a copy of is in no set yet.
- **Kept as … on B482**, with *Open the set ↗*, once every file we hold is in a set.
- **A line that says why**, when every file stayed in Gmail.

A mail with one file kept and one not shows the mark and the press together.

## The form

Filled from the mail (`bidMailDraft`): the name is the subject with its *Re* and *Fwd* off, the date is the mail's own day, the memo reads *Came by mail from …, Nov 16.*, and every file we hold is ticked.

- **Put them in** offers a new set or one of the bid's sets whose link is a Drive folder (`putIntoOptions`). It shows only when there is a choice. A set of the same name already on the bid is picked for you, since a reply in the same conversation carries the same subject.
- **The button counts** (`keepPressWords`): *Keep 2 files as a set on B482*, or *Add 1 file to Addendum 1*. It is dead only when nothing is ticked.
- **A file that stayed in Gmail** is named in the form and in the foot, and never stops the rest.

## The press

`keep` makes the set once, then the files go one by one past any that fails. The line after it (`bidKeptWords`) says what landed, what stayed in Gmail and what failed with its reason, green only when nothing stayed behind. **File 1 file again** tries the failed files on the same set. A refusal from the function (a folder the app cannot write to, a mail not tied to the bid) stays in the form with its words.

## On the bid

Edit Bid → Plans → Plan sets reads which of its sets hold a mail's file (`mailOfSets`, one embedded read, fail-soft). Such a set wears **From a mail** and carries **The mail ›**, Job activity's door to the thread at that mail.

## Either side of the push

The kept mark's column lands with PR 1's migration. `filesOf` reads again without the column when the database does not have it yet, and `mailOfSets` answers none, so the press and the list stand either side of the push and only the marks wait.

## Left alone

The press never switches the set the robot reads and never touches *Priced on*. Both stay their own presses on the bid.
