# v2.4824 — Map: Classify now answers even with a long backlog (2026-10-07)

The `court-precinct-nightly` function only (**redeploy after merge**). Found running *Classify now* by hand right after [v2.4790](v2.4790.md) shipped: the first run had about 150 unplaced addresses to geocode and records with no county to look up at the Census, one at a time. It ran past the gateway, so the caller saw *Failed to send a request to the Edge Function* while the work went on and finished unseen. A second run took four seconds and wrote nothing.

## What changed

- **One deadline for the outside lookups**: `LOOKUP_BUDGET_MS = 75_000` from the start of the run. Past it, the geocoding loop stops taking addresses and a record with no county skips the Census lookup. The run then classifies with what it has, so it answers inside the gateway's timeout.
- **What waits is counted**: the answer adds `lookupsDeferred`. Those addresses still read as *with no point* on the Map page, and the next run, by hand or the nightly, takes them up.
- **Nothing else moves**: the 300-a-night cap, the hand rule, the classification and the writes are as in v2.4790.

## Is this the best we can do?

- **A budget, not a background job.** The backlog drained in one night, and a day adds a handful of addresses. A queue would be machinery for a rare case; the budget makes the rare case answer and lets the next run finish it.
- **Not done:** the Map page's line does not name the deferred count; the *with no point* count already holds those addresses.

## Tests

None for the function body, which has no kernel of its own; `deno check` matches main's baseline.
