# v2.3187 — "ours b214": a robot's bid reference also links the human bid it pairs with (2026-09-09)

Client only. No migration or edge-function change. Follow-up to v2.3174 (the bid number in a robot's question is a link) and v2.3186 (question lanes).

## Why

The number a robot names is usually its own ZZ Twin copy — `b474` is "ZZ Twin TYE PRESTON MEMORIAL LIBRARY (backtest R2)" — and that link lands on the Robot Board row holding the robot's draft. Wendi's own bid, with her counts and her price, is a separate row on the human board: the twin's `twin_source_bid_id`. For the context she asked for, that is the row to land on.

## What shipped

- **[`twinQuestionBidRefs.ts`](../../src/lib/bids/twinQuestionBidRefs.ts)** (+3 tests): `indexSourceBids(rows)` maps each twin bid id to `{ id, number }` of its source once the source's number is in hand; `unresolvedSourceIds(rows)` names the pairings still to look up; `sourceBidLabel` → `ours b214`.
- **[`TwinQuestionText`](../../src/components/bids/TwinQuestionText.tsx)** takes `sourceByBidId`; every resolved reference (inline or the trailing "· b474") gets a small green **ours b214** link beside it, opening the source bid's board row in a new tab. Unpaired bids (a human's own bid named in a question) get nothing extra.
- **Bids → Audits, Standing rulings** — the two `bids` lookups now select `twin_source_bid_id`; one more query fetches the source numbers not already in hand; both the grouped ruling and the singles pass the map through.
- Render smoke: `b474` → `bid-474` still, and the paired source renders as `ours b214` → `/bids?tab=bid-board&bidId=bid-214`.

Not changed: the dev console's Twin questions card (Settings → Digital twins) resolves through `about_bid_id` only and stays as it was.
