# v2.7482 — Print labels: the Which job? window says what you are about to print (2026-11-16)

Punch list #304. The owner's ask of 2026-11-16, with a screenshot of the window Materials → **Print labels** opens: *I don't like how this modal looks … How could we make this much more informative?* The window was three rows, a job's name and *91 labels*. The mock-up, [`to-dos/materials-one-story/print-labels-which-job.html`](../../to-dos/materials-one-story/print-labels-which-job.html), was drawn and approved the same day (*Yes, build it*, on its five picks). Client only: no migration, no edge function.

## What changed

- **The band.** On top, what this computer prints on (`labelPrefs.ts`' format and tape width), one real label drawn at its printed size (the first box of the first job: a strip in millimetres, or a small Letter page), and **Change to paper** / **Change to Brother tape**, which writes the same preference the labels window reads. On tape, where the browser already has leave to use the P-touch, the window connects quietly (`connectPtouch({ ask: false })`) and says the printer's own line (`ptouchReadyLine`), so a wrong or missing tape is seen before a job is picked; the cards then count strips at the tape the printer holds. The link is closed before the labels window opens, since that window opens its own. A browser with no USB reach on a tape computer gets the amber note here, with **Copy the link to this page** and the change to paper.
- **A job is a card** (`labelJobFacts` in [`printLabelsJobs.ts`](../../src/lib/materials/printLabelsJobs.ts)): the number and the name apart, the site and the street, the count of labels, the kinds counted apart (*88 boxes · 3 cages*), the names (each one up to six, else the first to the last, in the short form a label prints), each place with its count and *No place said yet* last.
- **What changed**, as chips (`labelJobChips`): boxes added in the last seven days, boxes that already wear a sticker, boxes with no part on hand.
- **A run left half done.** The run this computer stopped today (`pt.labels.stoppedRun`, read through `stoppedRunToResume`) is said on its job with how many boxes are left and the name it picks up at.
- **What the job takes** (`printNeedWords`): on tape the strips, their length (each strip at `tapeLayout`'s length for its own name, times the remembered copies) and, past a fifth of one, the share of an 8 m cassette; on paper the pages.
- **Doors** (`LabelJobDoor`): **The rest, 51 boxes** opens the labels window as it always resumed; **The 6 new** opens it with those boxes ticked alone; **All 91** opens it on every box with a kept run set aside. `LabelsPrintModal` takes them as a new `start` prop (`{ kind: 'all' } | { kind: 'ids', ids }`); left out, it opens as before. The card's head opens the job as the old row did. Nothing prints from this window.
- **The order** (`labelJobsInOrder`): a run to finish, then new boxes, then the job's number. Past six jobs a search narrows the cards by number, name, site or street.
- **A job that did not load** is a card with its reason and **Read again** (`OnSiteFindJob.failed`, from the store's `jobLoadState`; `useOnSiteDeskJobs` hands back `readAgain`). It used to be left out without a word, and one such job no longer lets a single loaded job skip the question.
- **The foot**: *Boxes that are not in the app yet?* with **Print blank stickers** (for the roles the strip offers it to), **Scan a label**, and the guide.

## The reads

Two small reads when the question opens, each under the viewer's own RLS and each optional ([`printLabelsIo.ts`](../../src/lib/materials/printLabelsIo.ts)): the jobs' sites (`jobs_ledger.development_id`, then `developments.name`) and the stickers on the listed boxes (`fetchStickersOnBoxes`). A read that fails leaves its fact off the card. `OnSiteFindJob` gained `number`, `name`, `address` and `failed`, filled by `useOnSiteDeskJobs` from the row it already reads.

## Not built

- **A true *not printed yet*.** The app keeps no record of which labels were printed, so the card says *added this week*. A printed mark needs a column and is its own change (the mock-up's call 3).
- **Print blank stickers' twin window** still lists names alone (call 5, the next small change).
- The tape length is the print window's strip length. Straight to the P-touch a strip is trimmed to its ink, so a run comes in a little under what the card says.
