# v2.3216 — Bid flow doors land on the field: every step scrolls to, focuses, and rings the spot it is about, from the board and all five workflow-tab strips (2026-09-10)

Client only; no migration.

## Why

The strip's steps opened a destination (v2.3200) — Edit Bid, Counts, Pricing — and left the person to find the right field on a long page. Grace: "brought to edit bid, but then brought down to where the plans are and have the plans entry field highlighted for a few seconds before that highlight fades so the user knows where it is." The poster's twelve are the app's ten (count/import and send/follow-up/mark-sent each collapsed), so ten landings.

## What shipped

- **Targets on the step table** (`bidFlow.ts`): every `BidFlowStep` carries `target`, element ids tried in order once the destination renders. Review's is empty (its door is the Mark reviewed prompt, not a place).

  | step | door | lands on |
  |---|---|---|
  | 1 Plans in Drive | Edit Bid | `bid-form-plans-link` (Job Plans) |
  | 2 Send RFQ | Pricing | `pricing-price-requests` (the RFQ chip, once a request exists), else `pricing-header` (title + tools row) |
  | 3 Plans in Tooling | Edit Bid | `bid-form-count-tooling-link` |
  | 4 Count & import | Counts | `counts-import-tooling` (Import from /Tooling) |
  | 5 Takeoffs | Takeoffs | `takeoff-lines` (the part-lines table), else `takeoff-header` |
  | 6 Price | Pricing | `pricing-header` (title + tools row — the breakdown title is a modal, so not a landing) |
  | 7 Review | prompt | — |
  | 8 Cover letter | Cover Letter | `cover-letter-generate` (Copy & open in Google Docs) |
  | 9 PDF filed | Cover Letter | `cover-letter-submission-link` (the action row + quick-add box), else the letter button |
  | 10 Sent | Cover Letter | `cover-letter-mark-sent`, else the letter button |

  The ids were added where missing (bid form ×2, Pricing chip + header, Counts ×2 exclusive branches, Takeoffs ×2, Cover Letter ×4 — the two Mark sent buttons are exclusive branches, so one id).
- **The landing** (`src/lib/bids/bidFlowLanding.ts`, no React): `landOnBidFlowTarget(targets)` polls for the first target that exists (the destination renders async after a tab switch or modal open; 6 s cap), scrolls it to center (instant under `prefers-reduced-motion`), focuses it if it is a field or button (`preventScroll`), and adds `.bid-flow-landing` — a 3.2 s blue ring + soft glow that fades (`index.css`; the animation is off under reduced motion, the ring still shows and drops). `parseLandingParam` reads a `focus=` URL parameter defensively.
- **Doors everywhere**: the board's opened-row strip lands after it opens (same `openBidFlowDoor`, now receiving the step). The five workflow-tab strips, which only offered Review since v2.3200, now offer every door through a page-level `onOpenBidFlowDoor` (Edit window or `selectBidAndSyncUrl` to the tab, then land) with the same superintendent gating as the board; Pricing's own three-door handler is replaced by the shared one.
- **URL landing**: `/bids?tab=cover-letter&bidId=…&focus=cover-letter-mark-sent` lands the same way and drops the parameter, so a pointer (a robot's ask, a help link) can point at a field.
- Help guide `see-where-a-bid-is-in-the-flow.md` rewritten around the landings.

## Tests

`bidFlowLanding.test.ts` (jsdom, fake timers): every step but Review has a target and first targets are unique; a landing waits for the element, scrolls, focuses, rings, and un-rings after the fade; ordered fallbacks; quiet give-up; cancel; non-focusable elements ring only; URL param parsing.
