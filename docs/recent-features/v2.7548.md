# v2.7548 — Checklist: hand a task to the right person, and it keeps its notes (2026-11-16)

Punch list #369, step C7 of the Task Mode train (tool 7), stacked on C5 (v2.7547). It calls `task_hand_on` from C1's migration.

## Why

Two things were wrong with passing a task along.

- **Only the office could.** **FWD** drew for dev, master, assistant and controller. A field person holding the wrong task had a note box.
- **It was not the same task afterwards.** `saveFwd` inserted a new one-time task for the other person, with the title, the date and four notify and reminder fields, then deleted the first day row. The row's thread went with it by the foreign key, and the new task had none of the place, the Done when… lines, the photo ask, the links, the due day or *Stays on the list until done*.

## What changed

**For the person doing the task**

- **Hand it on**, a row of **⋯ More** on an open task that is not a roadmap task (`taskMoreChoices`).
- **The sheet** (`TaskHandOnSheet`) asks *Who takes it?* **Back to Imani** is one press when someone else gave the task. Anyone else is found by name: six people show before a letter is typed, and *Find a person* narrows the rest (`handPeople`). The person handing it on is never offered. A reason is asked for and not required.
- **The press names who takes it**: **Hand it to Hal**. A green line says what goes with it: *Hal gets it with its notes and its place. Imani is told.* For a task that repeats: *Hal gets it for this day. The task that repeats stays yours.*
- **The taker gets a push**, and so does the giver when someone else took it (`handPushToTaker`, `handPushToGiver`).

**For the office**

- **Both of this page's Forward windows keep the task whole.** Today's and Review's `saveFwd` call `handOnTask` in place of the copy and the delete. Review names whose task it is, so the function swaps that person for the one picked.
- **The window shows the task's words and no longer takes a new title**, with one line under them: *The task goes as it is, with its notes, place and photos.* The copy could be retitled because it was a new task. A task that stays itself is renamed from Manage → Edit.

## Not in this PR

- **Dashboard's My Inbox has a third Forward** (also on Job Mode, Dispatch Mode and Quickfill), its own copy of the old flow. It still copies and deletes. It is outside the Checklist page and outside this train's ask, and is named here so it is not thought fixed.

## How it is built

- `handOnTask(instanceId, toUserId, reason, fromUserId)` in `taskDoerActsIo.ts`.
- `useTaskDoerActs` reads the people who can take a task once, the first time the sheet opens (`activeUsersQuery` with `withLogin`), and holds `onHand`.
- The words, the list and the pushes are in `taskDoerActs.ts`.
