# v2.3126 — Shadow auto-score on send + the "robot locked" Dashboard nudge (2026-09-07)

Two pieces of LEARNING_PLAN lever 2 (auto-shadow every live bid). A locked shadow used to stay sealed until the next twin agent happened to call `score_shadows`; and nothing on the human side said a robot had a number down on a live bid. Migration `20260908030000_shadow_autoscore_on_send.sql`; no edge-function change.

## What shipped

- **`public.score_locked_shadows(p_reference_bid_id uuid DEFAULT NULL) RETURNS integer`** — SECURITY DEFINER, service_role only. The DB twin of twin-mcp's `score_shadows` loop: for every `twin_shadow_runs` row with `status = 'locked'` (or just the given reference's) whose reference bid carries `bid_date_sent` and a positive `bid_value`, it computes `delta_pct = round((locked_total − bid_value) / bid_value × 100, 1)`, resolves the teacher (`estimator_id` → `bid_date_sent_attested_by` → `created_by`, name + `calibration_standard` from `users`), flips the row to `scored` with `reference_value` / `scored_at` / `teacher_*`, and inserts the same `[shadow SCORECARD] …` note on BOTH the shadow and reference ledgers (authored as the twin seat via `created_by = twin_user_id`, so the sender's Send does not show as having written it). Number formatting matches `toLocaleString()` through two tiny helpers, `shadow_fmt_money` / `shadow_fmt_pct`. Returns the count scored; skips when `bid_value` is null/0 or `bid_date_sent` is null; the `status = 'locked'` guard on the UPDATE makes a race with `score_shadows` harmless.
- **`bids_score_shadow_on_send_trg`** — `AFTER UPDATE OF bid_date_sent, bid_value ON bids FOR EACH ROW WHEN (NEW.bid_date_sent IS NOT NULL AND NEW.bid_value IS NOT NULL)` → `bids_score_shadow_on_send()`, which calls the scorer inside `BEGIN … EXCEPTION WHEN OTHERS THEN RAISE WARNING … END`: a scoring failure can never break a bid update. `score_shadows` stays as the manual/idempotent door and still returns the scoreboard.
- **Dashboard Needs-you `robot-locked` item** — `useRobotLockedShadows(enabled)` reads `list_shadow_runs()` and keeps runs with `status = 'locked'`, `reference_sent_at` null, locked within 14 days, newest first (pure kernel `selectRobotLockedShadows` in `src/lib/bids/robotLockedShadows.ts`; fail-soft to `[]`, null while loading). New `NeedsYouInputs.robotLockedShadows`, key `'robot-locked'` at tier 50, severity blue, kicker "Robot bid", title `The robot has a sealed number on b481 (Galloway Park)` / `The robot has sealed numbers on N live bids`, figure = count, action "Open Shadows" → `/bids?tab=robot-shadows`. Same audience as robot audits (`canWorkRobotAudits`); Quickfill passes null.
