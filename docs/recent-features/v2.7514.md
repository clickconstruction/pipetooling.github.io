# v2.7514 — Lien notices: the pay codes page names the cover letter only when one is enclosed (2026-11-16)

Found on a printed § 53.056 notice the owner scanned on 2026-11-16, and agreed as a fault the same day. Client only: no migration, no edge function.

## Before

`payPageOwnerRule` (v2.3758) repeats the cover letter's rule on the pay codes page: *Please pay these only if the builder has told you in writing that you may pay us directly. Otherwise hold the amount back from the builder, as the cover letter asks.* The last clause printed always. Two papers carry the page with no letter in front of it:

- a notice whose cover letter box is unticked on the desk (`coverLetter` and `coverNote` both null in the run), and
- every notice printed from the job's Lien window, which has never printed a cover letter.

The scanned page was the second kind.

## What changed

- `PayPageInput` takes `coverLetter: boolean`, required, so every caller says whether a letter or a note rides in front. `payPageOwnerRule(gc, us, coverLetter)` ends the sentence at the builder's name when there is none.
- The four callers: the run (`runPayPageBlocks`: the notice's own letter or note), the desk's pane (`coverBlocks.length > 0`, so the page on the desk follows the box), the GC preview (the same), and the Lien window (`false`).

## For counsel, if anyone asks

The sentence without the clause is still the app's own ask to hold the money back. It was the app's before; only the pointer to a letter that is not there is gone. The courtesy notice's line *as the cover letter asked* (`lienCourtesyNotice.ts`) is a different paper and is not changed here.

## Tests

`lienNoticePayPage.test.ts` (+1): the rule with and without a letter, and a page with none never says *cover letter* while every other block is the same. `lienDeskRun.test.ts`: the run's page follows the notice's own letter.
