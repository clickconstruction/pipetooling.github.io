# v2.7961 — Tests, help guides and sample emails no longer match live records (2026-11-19)

This repo is public. v2.7087 swapped names in the test fixtures from a list built out of the repo alone, and said it had not been checked against the live customer list. This is that check, and the sweep that followed it.

## How the values were found

Thirty-two tables were read from prod through the dev seat, read only: customers and their contacts, property records and owners, jobs, bids, general contractors, prospects, job applicants, the team, legal matters and suppliers. Every tracked text file was then matched against their names, job and project names, street addresses, legal descriptions, phone numbers and emails. Names and addresses were matched word by word, so case, spaces and punctuation did not matter. A value held only by a test row on prod was set aside, and so were generic words that happen to be a job's name.

## What changed

- **Test fixtures** (`*.test.ts`, `*.test.tsx`, `src/test/`, the SQL scenarios under `supabase/tests/`): every name, job or project name, street address, legal description and phone number that matched a live record was replaced with an invented one.
- **Help guides** under `src/content/help/`: the same, in twenty-one guides. Their examples read as before with made-up names and streets.
- **Sample and preview data in the app**, because tests quote it and people see it: `src/lib/teamSampleEmails.ts`, `src/lib/emailCatalog.ts`, `src/lib/emailPreviewHtml.ts`, `src/lib/bids/bidRoomLinkEmailPreview.ts`, `src/lib/peopleWeek.ts` and `supabase/functions/_shared/customerSample.ts`.
- **Phone numbers wherever they sat**, outside migrations and the frozen files: tests, one guide, three code comments, six `docs/recent-features/` fragments and three to-do files. Each keeps its area code and takes a number from the 555-01xx range, which is never issued.
- One old word maps to one new word everywhere, so a fixture and the assertion that quotes it still agree, and two fixtures that differed still differ. A new word keeps the old one's first letter where the list of words allowed.
- An address keeps its road type, direction and city, and takes a new house number and a new street name. A road known by its number (a farm road, a county road, a highway) keeps the road and takes a new house number.
- Expectations that are a cut, glued or encoded form of a value (a two-word street key, a URL-encoded address) were edited by hand to match.

## How it was done

A script outside the repo holds the old and new words and rewrote the files in one pass. It is not in the repo, the commit or the PR, because it holds the old strings. On a rebase conflict, take `main`'s version of the file and run the script again.

## Left as is

- **Git history and merged PRs' diffs still hold the old strings.** This fixes the files at the tip. A history rewrite, or a private repo, is a separate decision.
- **Docs, to-do cards, release notes, code comments and migrations** were not swept for names and addresses. They hold about the same number of values again.
- **`public/templates/aia-g702-g703-mission-hills.xlsx`** keeps its file name, which three tests and one constant read.
- **`supabase/seed.sql` and the pre-baseline migration it mirrors** keep the company's own outreach template, with its contact line.
- **Team members' names, suppliers' names, the company's own address and live record ids** were not changed.
- A common name can match a live record by chance. Such a name was swapped all the same.

## Checks

`npm test` (the whole suite), `npm run typecheck`, `npm run lint`. After the sweep the same search found none of the swapped values in the swept files, and no invented value that matches a live record. The SQL scenarios run in CI's SQL beds, which need Docker.

## After the merge

`supabase/functions/_shared/customerSample.ts` and a comment in `_shared/legalOfficeContacts.ts` are in edge bundles, so `npm run check:edge-drift` names the functions to redeploy.
