# v2.6792 — The dev seat gets a teammate online: make the account, fix the name, attach the login, reset a password (punch list #260's seat door) (2026-11-09)

On 2026-11-09 the owner added an office account for a new assistant on People → Users and ended with a users row named wrong, no login behind it, and the invite press refused by `invite-user` (the v2.6518 rule: a login is attached on the desk so hours and pay stay on one person). A Claude session at the dev seat could read all of it — the row, the roster row, the missing login — and act on none of it: the only doors were the row's ⋯ menu and *Attach a login…* on the desk. The owner wanted the seat to do it with him, end to end, and to read whether the person had signed in yet.

## What changed

- **`supabase/functions/_shared/devMcpAccount.ts`** (pure; tests `src/lib/devMcp/devMcpAccount.test.ts`): the shape of each ask, the dry run over the users row, the roster row and the auth account's stamps, the refusals in words, what each write becomes, and the words after. Six write verbs join `WRITE_VERBS` with `rpc: null` (the dry run is the server's own read): `plan_account` → `apply_account` (make a person as the Hire form does — the users row, the roster row, the pay row, the invite or a dictated password, never the paperwork packet — or rename an account with the desk's pay-table cascade, change its role, change its sign-in address), `plan_login` → `apply_login` (the desk's *Attach a login…* on the row's own id with the sign-in email, or a password instead, or *Remove the login…*), `plan_password_reset` → `apply_password_reset` (the sign-in page's own Forgot password email, one per address per ten minutes, or a dictated password). One read, `get_login_state`, answers the stage, the words a session says to the person and the next press.
- **`supabase/functions/dev-mcp/index.ts`** (server 0.50.0, numbered behind v2.6790's 0.49.0, which merged first): every write is the edge function or RPC the desk itself calls, as the dev — `add_worker`, `invite-user`, `create-user`, `send-sign-in-email`, `detach-login`, `change-user-email`, `set-user-password`, `resetPasswordForEmail` — so each function's own dev gate and refusal holds. The auth stamps are read by id as the service role, timestamps picked by name: the fourth thing the seat uses the service role for, and the read is a dev's alone. A password never comes back and reaches the call log as `(set, not logged)`. `restRows` takes a `Prefer` for the pay row's upsert.
- **Docs**: `docs/EDGE_FUNCTIONS.md` → dev-mcp, `docs/dev-mcp/README.md` (four rows), `docs/ACCESS_CONTROL.md` (who may call each door), and the guide `connect my coding agent` gains *Get a teammate online with the seat*.

## Release order

Merge, then `supabase functions deploy dev-mcp` (diff the deployed copy against main first; prod has been ahead of main before). No migration, no catalog change. The owner's live walk on a ZZ Test person follows.
