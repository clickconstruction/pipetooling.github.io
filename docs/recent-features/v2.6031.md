# v2.6031 — Honest and fast, PR 2: the kept-read shape, and the slow line names the time (2026-10-28)

Punch list #183 ([`to-dos/honest-and-fast/README.md`](../../to-dos/honest-and-fast/README.md)), the second of five PRs. The Pipeline has kept the board a device last saw since v2.3610 (`lib/jobs/boardSnapshot.ts`, `boardSnapshotStore.ts`, the paint and the write inside `JobsListCacheContext.tsx`, the `data-board-snapshot` muting in `index.css`). This PR lifts that shape out of the Pipeline into one kernel, one store, one hook and one stamp, re-points the Pipeline at it with no change on screen, and turns on the strip's second sentence. PRs 3 to 5 (the phone's day, Quickfill, Messages) take the hook as it is. No migration, no edge function.

## What changed

- **The kernel** [`src/lib/keptRead.ts`](../../src/lib/keptRead.ts) (14 tests, the board's six moved onto the lifted names): `buildKeptReadKey(userId, page, scope)` (`u1:pipeline:all`; another user, page or scope is another key), a schema number `KEPT_READ_SCHEMA` (a read kept under an older number is not shown), `buildKeptRead`, `keptReadIsUsable` (same key, the schema of today, every wanted scope covered, younger than 24 h, not from the future), `parseKeptRead` (with the page's own check on each row), `describeKeptReadAge` (*just now · 4 min ago · 6 h ago · yesterday*), `formatKeptReadTime` (*7:52 AM*, the device's zone), the stamp's words `keptReadStampWords`, and `keptReadOnScreen`, a registry of the kept parts on screen that the strip reads.
- **The store** [`src/lib/keptReadStore.ts`](../../src/lib/keptReadStore.ts): one IndexedDB database `pipetooling-kept`, one store `pages`, keyed by the kept read's key; every call best-effort as before. `clearKeptReads` also deletes the retired `pipetooling-board` database, so a device carries no second copy. It runs from [`useKeptReadsClearedOnAccountChange`](../../src/hooks/useKeptReadsCleared.ts) (3 tests), mounted once in `AuthProvider` with the user's id and whether auth has settled: nobody signed in once settled (the sign-in page), or another id than before (an account switch, impersonation starting or ending), clears the store; a cold open still loading never does. The board cleared from the jobs cache's user effect, and the Layout's sign-out leaves the page the moment `signOut` resolves, so that clear lost the race with the unload on the live walk; clearing on the sign-in page too makes sign-out hold.
- **The hook** [`src/hooks/useKeptRead.ts`](../../src/hooks/useKeptRead.ts) (13 tests): `useKeptRead(key, rows, { loading, scopes, covers?, failed? })` hands back the kept rows with their `readAt` and `scopes` while a live read of a key this session has not landed runs, then the live rows; it writes the rows on the edge where `loading` turns false, so a page passes `loading` true until its last read landed and **a half page is never kept**. A failed live read leaves the kept rows up with `failed` set and writes nothing; a read again clears `failed`. A twin (`useIsDigitalTwin`) or an impersonated session (`isImpersonationSessionActive`) neither reads nor writes one. While kept rows show it registers on `keptReadOnScreen`. `useKeptReadOnScreen` is the strip's side.
- **The stamp** [`src/components/KeptReadStamp.tsx`](../../src/components/KeptReadStamp.tsx) (3 render tests): *Read at 7:52 AM · reading again…* in the age chip's amber (`.keptReadStamp`), *Read at 7:52 AM · could not read again · Retry* on a failed read, the page's own lead (`lead="Counts from"`). The Pipeline keeps its own *board from 6 h ago* chip and does not mount it.
- **The muting** `index.css`: the `[data-board-snapshot]` block is now `[data-kept-read]` — `.stagesMoney` and the new `.keptMoney` at opacity 0.42 and grey, `.keptCount` at 0.55, a table's buttons, inputs and selects and the new `.keptPress` inert at 0.55. The stamp's smoke reads the rules off the file and proves them on a page (jsdom computes them), so a kept page can never pass as live without a test going red.
- **The Pipeline re-pointed** ([`JobsListCacheContext.tsx`](../../src/contexts/JobsListCacheContext.tsx)): `paintRememberedBoard` and the two `writeBoardSnapshot` calls are gone; the provider calls `useKeptRead` with the key `buildKeptReadKey(user.id, 'pipeline', customerFilter)`, `loading = jobsListLoading || jobsListRefreshing || jobsListEnriching` (so the write waits for the enrichment, as the board's did), the load's wanted scopes, the merged scopes as `covers`, and `jobsListError != null` as `failed`; the paid scope and paid rows are filtered out before the hook sees them. While kept rows show, the handed-out `jobs`, `jobsListLoading` (off), `jobsListRefreshing` (on), `mergedScopes` (the kept scopes) and `jobsListSnapshotAt` read as the board always did; the refs that gate scope fetches and the tab TTL stay untouched. The Stages tab's root carries `data-kept-read` instead of `data-board-snapshot` and its chip reads `describeKeptReadAge`. Its render test moved its mocks to the new modules (and mocks the twin hook); the cache's own seven tests pass as written. The old `pipetooling-board` database is not read: the first Pipeline visit after this deploys loads blank once, as before v2.3610, and keeps its read from then on.
- **The strip** ([`AppHealthStrip.tsx`](../../src/components/AppHealthStrip.tsx), [`appHealth.ts`](../../src/lib/appHealth.ts)): `appHealthStripWords` takes `keptReadAt` and adds *The page you see was read at 7:52 AM.* (`keptPageWords`) right after the lead in every shown state, before a dev's runbook line; the strip reads `useKeptReadOnScreen`. Two of PR 1's fetch-wrapper tests waited a 0 ms timer for the body's code and lost the race on a loaded machine; they now wait for the read itself.
- **Guide** *know what to do when the app is slow*: a section *The page you see*.
- **Docs**: `JOBS_TABS_ARCHITECTURE.md`, `JOBS_STAGES_TAB_ARCHITECTURE.md`, the to-do's status.

## Verified

On the dev server (port 5201, this worktree) as the dev, prod data, nothing written. **The write**: a cold Pipeline visit landed and `pipetooling-kept` → `pages` held one entry, key `<dev id>:pipeline:all`, schema 1, the four non-paid scopes, 95 rows every one enriched (schedule date, materials), no `pipetooling-board` database beside it; the root carried no `data-kept-read` and no strip showed. **The kept paint**: a fresh page session at the Dashboard, `window.fetch` wrapped from the pane so every `/rest/v1/` read resolved 20 s late, then the Jobs link: at 6 s the Pipeline's root carried `data-kept-read`, *Updating jobs… board from 1 min ago* showed, `.stagesMoney` computed at opacity 0.42 with `grayscale(1)`, a table button at `pointer-events: none`, and the strip read *The app is slow right now. The page you see was read at 1:11 PM.* in amber. The wrapper restored, the live board replaced the kept one within 30 s: no attribute, no chip, money at 1, buttons live, no strip, and the store held the same key with a newer `readAt`. **The phone preset** (375 wide), the same cycle: the strip two rows (52 px, the kept sentence on its own row) with no sideways scroll, the chip and the muting as at a desk. **Sign-out** (the gear's Sign out): the store read empty on the sign-in page; the first walk, with the clear still in the jobs cache's user effect, read one entry there, which is why the clear moved to `AuthProvider` and runs on the sign-in page too. The full suite (3,696 files, 33,291 tests), typecheck, lint and the repo's checks (todos, timezone, empty-words, error-words, batch-words, css-tokens, theme-tokenize) pass.

Not exercised live: a failed live read over a kept board (the Pipeline's own *the refresh did not land* line and the hook's `failed`, covered in the hook's tests); a twin's or an impersonated session's refusal (the hook's tests); another account's kept read on the same device (the key carries the user id, and the store is cleared on the switch).
