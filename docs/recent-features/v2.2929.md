# v2.2929 — Dispatch sees the subs (2026-09-06)

PR 3 of the three-party scheduling train (prototype: artifact 3a540149). Stacked on v2.2928 (picks) and v2.2927 (stages). The rule that shaped it: dispatch never writes a schedule block for a sub. Subs are people, not users, and a block would be a second copy of a date that already lives on the order — so the hub reads windows and picks beside its own blocks.

## Kernel — `src/lib/subs/subDispatch.ts` (+test)

- `subDispatchSpan(order)`: a live order's place in time and how sure we are — a **pick** (`picked_start/end`, signed) is definite; a **window** (the stage's span, else the proposed span) with no pick is a maybe; an unanswered offer is `offered`; closed orders and undated orders yield null.
- `buildSubLanes(orders, dayKeys)`: one lane per sub with chips per covered day (`pick` / `window` / `offered`), name-sorted, plus a per-lane order count.
- `buildSubBadgesByCell(orders, teamByJobId, dayKeys)`: `hubPersonDayKey` → `{ count, titles }` for crew assigned to the job (`jobs_ledger_team_members`), **picked days only**.
- `subsOnDay(orders, day)`: `definite` (picks) and `maybe` (windows / offers), name-sorted; `subOrderTouchesRange`; `dayKeysBetween`.
- Loads in `src/lib/subs/subDispatchFetch.ts`: `fetchSubOrdersForRange` (live `step_commitments` with the job label, the stage window and its line-item name, filtered client-side to the range) and `fetchTeamMembersByJobId`.

## Hub

- `ScheduleDispatchHubPage.loadHub` Phase A adds `fetchSubOrdersForRange(weekStart, weekEnd)` in the same `Promise.all` (degrades to a warning toast), then the team members for those jobs; memos `hubSubLanes` / `hubSubBadgeByCell`, threaded like `hiddenByCell` (page → `ScheduleDispatchHub` → `HubPeoplePanel`, both mounts → `HubPeopleDayCell`).
- [`HubSubsLanes`](../../src/components/schedule/HubSubsLanes.tsx) (+render test): the Subs section under the crew table with the week's day columns and a legend; a chip opens its job (`onOpenJob`).
- `HubPeopleDayCell`: a green "sub" / "2 subs" badge (`data-testid="hub-sub-badge"`, names in the tooltip) at the top of the cell; it does not change any click mode.
- Day tab: [`SubsOnSiteForDay`](../../src/components/schedule/SubsOnSiteForDay.tsx) (+render test) mounted above the crew in `QuickfillScheduleSection` when `showDaySettings` (the hub's Day tab, not the Quickfill embed); "Add a site visit ›" navigates to `/schedule-dispatch?placeJob=<jobId>&hubTab=people`, the existing place-a-job deep link.

## Crew Day email

`crew-day-email-dispatch`: `fetchPayloadForUser` attaches `subs` (signed orders with `picked_start ≤ day ≤ picked_end`, with the job label and the stage's line-item name; office-wide like the rest of the email; `[]` on error); `render.ts` adds `subsToday` to the view and a "Subs on site today" section to both the HTML and the text body.
