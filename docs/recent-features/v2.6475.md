# v2.6475 — The dev seat can check and update a teammate's licenses (2026-11-03)

Punch list #255, beside the logbook's edit window (v2.6473). The owner asked that "the dev-mcp be able to update users licenses and experations". The six stale dates fixed on 2026-11-03 were each a registry lookup and a hand edit; an agent on the dev seat can now do both.

## What changed

- **`check_license(trade, level, number)`** (dev-mcp, read-only):
  - It reads TDLR's open list (`data.texas.gov/resource/7358-krk7`) for an electrical or HVAC number.
  - It answers the holder, the type and the expiry of the license of that trade and level, through `tdlrAnswer`. It also lists every license under the number, since one number can belong to several types.
  - A plumbing number is refused with the TSBPE search, which asks a person for a robot check.
- **`plan_license(license)` / `apply_license(license, plan_hash)`**:
  - They POST `dev_person_license_write` (migration `20261103180000`).
  - `license = { license_id? (to change one), person_name? (to add one), trade, level, other_name?, number, expires, note? }`.
  - `licenseInput` in `_shared/devMcpWrites.ts` writes the words with `licenseTypeText`, the logbook's own, so a license the seat saves reads back the same. It refuses, in words with the shape, a trade or level that does not exist, an empty number, a date not written YYYY-MM-DD, or an add with no name.
  - Add or update only. A renewal re-arms the Dispatch expiry notice. Apply sends the notice through `notify-dispatch-request` when the license is inside 30 days.
- **`lib/logbook/licenseText.ts`** joins the edge kernel copy (`scripts/edge-kernels.mjs` ENTRIES → `_shared/gcKernels/lib/logbook/licenseText.ts`).
- **The server** is at 0.24.0, with forty-three write verbs.
- **Tests**: `devMcpWrites.test.ts` gains the license verbs (3 tests), and the version and verb-count strings moved.
