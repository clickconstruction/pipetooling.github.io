# v2.8449 — Document builder: the insurance row says how many jobs have a sheet (2026-11-24)

Punch list #416, part 3, the build *The tab's row chip*, which #404 lists under *Against the mock-up*. Client only: no migration, no edge function.

## What was there

The chip's words were already written. `filledRowChips` (`sheetScreen.ts`) took a count and drew *A sheet on N of M jobs*, and a test held it. The tab handed it `null`, so the chip never showed: nothing read the jobs for the list.

## What changed

- **The count** is `sheetCounts` (`sheetScreen.ts`, pure): of the jobs the **Job** box lists (`listedJobs`), how many have a published sheet. A draft at revision 0 is not counted, since nobody outside reads it. A lost or closed job is counted only when its sheet was published, as the box lists it.
- **The read** is `readSheetCounts` (`sheetsIo.ts`): the jobs and the builder's sheets, read together, through the two reads the open builder already uses.
- **The tab** (`DocumentsBuilderTab.tsx`) reads the count for each filled builder that has a row, each time the list is shown. A sheet published inside the builder is counted on the way back to the list. A builder with no row counts nothing.
- **With no job** the chip reads *No job you run as the GC yet* (`sheetCountChip`), never *0 of 0*.
- **A count that does not read** leaves the row and its **Open** press as they are. A line under the chips reads *Its jobs were not counted.* with the reason from `formatErrorMessage`. The next showing of the list reads again.
- **Docs and help**: the glossary's *Document builder* entry, the Documents page's architecture note, and *set the insurance a job's subs must carry*.

## What the mock-up has that this does not

The drawing's insurance row has two more chips, certificates to check and trades with no certificate, and its Sub NDA row has *Sent to N GCs*, *Link on* and a count of changed pages. #416 names only this chip as ready, so only it is built.

## Tests

- `sheetScreen.test.ts`: the count over a built job, a bid, a draft, a lost job with a sheet, a lost job and a closed job. The chip's words for some, one, none and no jobs, and that they pass the plain-words rules.
- `DocumentsBuilderTab.render.test.tsx`: the chip on the insurance row after one read for that builder alone. No read for a builder with no row. The no-jobs words. A failed read keeps the row and names the reason. The count is read again on the way back from an open builder.
