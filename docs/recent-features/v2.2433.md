# v2.2433 — Digital twins console redesign: the page tells the story (2026-08-28)

Owner-approved mockup ("Digital Twins Fleet Console" artifact) built into
`src/components/settings/DigitalTwinsPanel.tsx`. Same data, same actions as v2.2432 —
zero backend changes — but the console now teaches its own mental model:

- **Pipeline strip**: four step cards (Mint a twin → Issue its key → Connect a harness →
  Watch the runs); every card header carries its step number (`1–2 Fleet`, `3 Connect a
  harness`, `4 Recent runs`).
- **Twin cards with the full safety ladder**: 🤖 avatar block, seat email + copy chip, and
  all three rungs visible per twin — current rung lit (amber read-only / green fenced),
  the actionable transition as a chip on the target rung (`Graduate ↑` / `Back ↓`), rung 3
  (Production) always shown but inert with a tooltip.
- **Tokens as key pills**: label + last-used liveness (`· used 14m ago` / `· never used`)
  + revoke ✕ in one pill; revoked keys collapse to an `N revoked` count. `＋ Issue key`
  is a dashed ghost pill that expands to an inline label input.
- **Connect card**: the old run-on auth paragraph became a definition list (Sign-in mint /
  MCP server / Auth header / Onboarding doc / Kill switch); the rotation command sits
  behind a `show command` toggle — the master secret's value still never appears in-app.
- **Runs in plain English**: new pure kernel `src/lib/twinConsoleDisplay.ts`
  (`describeTwinRun` parses the twin-login/twin-mcp note formats — `mint via=token:<id>
  redirect=<url>`, `report:<mission>` — and resolves key ids to their labels;
  `relativeTimeFrom`; `nextTwinSeat`), 17 unit tests. Rows render as relative time +
  SIGN-IN / REPORT / RUN chip + "Twin Estimator 1 · via key “xAI harness” → /bids".
- Mint flow simplified: the primary button moved into the Fleet header; the optional
  display-name input dropped (seat name defaults to `Twin Estimator <n>`; rename in
  People like any account).
