# v2.5440 — Messages: the owner turns texts on from Settings (2026-10-13)

Cut 5's switch (the lead's ruling after #5452's review, GC Mode helper 5): a text from the company number now waits on
the owner's word instead of a constant in the app (`TEXTS_ON` in `replyIo.ts`, #5497) and a missing secret on
`quo-send`. The owner's Quo secrets are set, so a secret was no switch. Migration `20261014160000_messages_texts_on.sql`
(`docs/migrations/20261014160000_messages_texts_on.md`); guide `turn-on-texts-from-the-company-number`.

- **The row**: `app_settings` `messages_texts_on_v1`, seeded `'false'`, with its own UPDATE policy
  (`master_or_dev_update_messages_texts_on`, `is_master_or_dev()`), the shape of the seats' and Read bids@'s. Only
  `'true'` reads on (`textsAreOn` in `quo/textsSwitch.ts`); a missing row reads off, so the push and the deploy go in
  either order. The key is `APP_SETTINGS_KEY_MESSAGES_TEXTS_ON_V1`.
- **Send texts** (`TextsSwitchSettingsCard.tsx`, under **Inboxes**): for the owner and a dev
  (`canSwitchTexts`), a switch over `textsSwitchIo.ts`. Turning it on asks first (`TEXTS_SWITCH_CONFIRM`); turning it
  off does not. A refused change keeps the switch and says why (`TEXTS_NOT_SAVED`). The card says what goes either way.
- **The send window** reads the row through `useTextsOn` (`reply/useTextsOn.ts`) where it read `TEXTS_ON`: off until the
  read comes back, off when it fails. Only the `waits` line and its import changed, so R3's hunks slide over.
- **The edge**: `sendText` (`_shared/quoLines.ts`) reads the row as the service role before a person's text or the app's
  reminder (`switchGates`: `reply` and `nudge`) and refuses with `503 textsOff` (`TEXTS_OFF`) before anything reaches
  Quo. The answer to HELP or INFO and a stop's confirmation (`answer`, `confirm`) go either way: each answers the
  person's own keyword, and the carriers' rules expect it. `quo/textsSwitch.ts` joins the edge copy.
- **A stop's confirmation is not retried** (#5452's review, finding 1): `quo-webhook` mirrors the STOP before it
  confirms, so Quo's retry read the number as stopped and planned no confirmation. A confirmation Quo turns away is now
  logged instead of answered 500.
- **Tests**: `textsSwitch.test.ts` (the reading, the gate, the roles, the key, the words in plain words),
  `TextsSwitchSettingsCard.render.test.tsx` over a fake io, and `SendWindow.textsOn.render.test.tsx` (off holds the
  text, on sends it).
- **Deploy**: push the migration, then deploy `quo-send` and `quo-webhook` (both read `_shared/quoLines.ts`).
