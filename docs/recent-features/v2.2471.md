# v2.2471 — The Bid Room, Phase 3: read-backs & management (2026-08-28)

The room's state reaches every surface where bids are worked (plan v2.2468, sign flow
v2.2470):

- **Kernel `src/lib/bids/bidRoomState.ts`** (+4 tests): rooms + latest revisions + events →
  one per-GC summary and the shared chip vocabulary — `rev 2 · opened 3× · 8/28`,
  `✍ signed — Base bid $249,971`, `✍ declined`, `room closed` — with a tone per state
  (`BidRoomStateChip`, one look everywhere).
- **Batched** through `useBidGcPackets` (the board's existing one-query-per-table hook)
  as `roomStatesByBid`; single-bid surfaces use `fetchBidRoomStates`. All refresh on the
  new `bid-room-changed` window event the panel dispatches after publish/send/close.
- **Where the chips live**: the Send-to strip's per-GC groups (`BidVersionPicker`), the
  Bid Board's per-GC lines (`BidBoardGcLines`, table + card variants), and **Waiting to
  hear**'s selected-bid panel — the chase call now reads *rev 2 · opened 3× · 8/28*
  right beside "Last contact", which is the whole point: you call knowing whether they've
  been reading.
- **The signature panel grows its verbs** (Cover Letter): outcome-aware — once signed it
  shows the signer + option and a **View the signed record →** link (the estimates-rails
  row); **Email link again** (re-send without publishing), **Close room** (confirm;
  the link shows the withdrawn page; publish/send verbs hide once answered).

No migration, no edge-function changes — pure read-backs.
