# v2.3605 — Sub portal: the trace of a moved or removed payment (2026-09-18)

PR 2 of [`to-dos/sub-payment-move-remove/README.md`](../../to-dos/sub-payment-move-remove/README.md). Edge function `sub-portal` — **deploy after merge** (`supabase functions deploy sub-portal`); no migration. The client reads the new field and defaults to none from an older function, so either deploy order is safe.

## The change

- **Kernel** ([`_shared/subPortalStatement.ts`](../../supabase/functions/_shared/subPortalStatement.ts), tested from `src/lib/subPortal/subPortalStatement.test.ts`): `buildSubPaymentTraceLines(events, sheetsById, sinceYmd)` — a `moved` event whose `from_job_id` is one of the sub's sheets, or a `removed` one not yet restored, becomes `{ date, jobNumber, amount, kind, toJobNumber }`; only the sheet a payment **left** draws a line (the destination lists the payment itself); the destination is named only when it is the sub's own sheet; a payment hidden from the sub stays hidden; same 90-day window and newest-first order as the payment lines; a restored removal draws nothing.
- **The function** reads `people_labor_job_payment_events` for the sub's sheet ids and returns `paymentTraces` beside `payments`. Totals never read the traces — the events are not money.
- **The page** ([`SubPortal.tsx`](../../src/pages/SubPortal.tsx)): the traces sit in the *What you've been paid* ledger as crossed-out grey rows — *Moved to #922 by the office* · *Moved to another job by the office* · *Removed by the office* — with a one-line note under the table; English and Spanish (`subPortalI18n`). `subPortalPayload` parses the field (tested; drops a malformed row; `[]` when absent). The demo page shows one.
- Rules the drawing settled, kept: what happened and that the office did it, never the reason; only the sheet it left; totals untouched.

Guide *manage subs end to end* says where the line comes from; `docs/EDGE_FUNCTIONS.md` § sub-portal carries the field.

## Verified

- The kernel's cases (a move to the sub's own sheet, to elsewhere, a removal, a restored removal, a hidden payment, an old event, a zero amount) and the parser's; the portal render smoke with the demo trace.
- Live: no real payment has been moved yet (the to-do's live test is still owed), so the row is verified on the demo page; the first real move will show on that sub's portal after the deploy.
