# v2.4666 — Send the run: the GC gets the courtesy PDF the desk promises (2026-10-06)

Punch list #87, item B (held for the owner in the guide PR #4603 as "Gap B"). The owner's own words settled which way to fix it: v2.2645 made email "a courtesy channel beside the recorded certified-mail send", and the desk's envelope line has promised *courtesy PDF to <email>* since. So the app now does what the line says. On 2026-10-06 the owner kept the tick on by default and chose the email's wording. Client only: no migration, and `send-lien-filing-email` is unchanged (it already took a subject and text).

## The bug

The desk's envelope line reads *✉ To <owner> and <GC> by certified mail · courtesy PDF to <email>* whenever the GC has an email (`LienDeskModal.tsx`). But `recordLienDeskRun` emailed a copy only when an envelope's method was switched to email. Every run left at certified mail, which is every run the desk sets up, sent no email to anyone.

## What changed

- **`RunRecipient.courtesy`** ([`lienDeskRun.ts`](../../src/lib/jobs/lienDeskRun.ts)): both builders set it on the original contractor's copy when an email is on file. The owner's copy never carries it, because the desk line promises the GC only.
- **`runCourtesyCopies`** lists what a recorded notice owes: copies still ticked, with an email, whose envelope goes on paper. An envelope sent by email already is the email, so it gets no second one.
- **`runCourtesyEmailWords`** gives the subject and text in the owner's wording: *Courtesy copy: notice of claim for unpaid labor or materials — 650 · ATI Schertz*, and *Attached is a courtesy copy of our notice of claim … (Tex. Prop. Code § 53.056). The notice itself is being delivered by certified mail.* It names the notice's own form and route, so a § 53.057 retainage notice or a courier envelope reads true. The function's own default names § 53.056 and certified mail whatever went.
- **`runCourtesyResultWords`** words the record's toasts: who got one, and a warning naming each one that did not go.
- **`envelopeCourtesy`** ([`runEnvelopes.ts`](../../src/lib/jobs/runEnvelopes.ts)) is the tick an envelope offers: the original contractor's copies only, with an email, while the envelope goes on paper.
- **`recordLienDeskRun`** ([`lienDeskRunIo.ts`](../../src/lib/jobs/lienDeskRunIo.ts)) emails the courtesy copies after the notice's `job_lien_filings` row is written and its desk item is marked sent, with the same pages the envelope holds (`emailNoticePdf`). A failure goes to `courtesyFailed` and never into `failed`, so the notice is not kept in the run for a second record. The courtesy email is not added to `sends`: the paper is the statutory record. The function files a sent copy on the job (v2.4574) and logs the send.
- **`LienDeskRunModal`**: the GC's envelope row carries *Courtesy PDF to <email>, emailed when the run is recorded* with a tick, on by default, and *one email per notice* when the envelope holds several. The tick reaches every original contractor's copy inside and never an owner's. It goes away when the envelope is switched to email. The success toast adds *Courtesy PDF emailed to <email>.*; a failed one shows a warning that says the notice is recorded all the same.
- [`docs/EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md): `send-lien-filing-email`'s caller sentence names the run. [`docs/LIEN_DESK_ARCHITECTURE.md`](../LIEN_DESK_ARCHITECTURE.md) § J and the [Glossary](../GLOSSARY.md)'s *The run* say what recording sends.

## Guide lines this makes true

No guide is touched. *send lien notices from the Lien desk* L125 ("The GC also gets a PDF by email when we have an address") and L225 ("The courtesy emails go out, and the row moves to **Sent**") now hold. The desk's own envelope line holds too.
