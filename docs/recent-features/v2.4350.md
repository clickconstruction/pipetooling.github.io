# v2.4350 — Clock in: no more "Lock was stolen" when the app opens (2026-10-01)

Grace, 2026-10-01, on opening the app: *"Failed to clock sessions open for user: AbortError: Lock was stolen by another request Failed to clock sessions today for user: AbortError: Lock was stolen by another request"*.

## Cause
supabase-js (auth-js 2.99) reads the login under a browser Web Lock (`lock:sb-<ref>-auth-token`) before every request. When renewing the login holds that lock past 5 s (`lockAcquireTimeout`), the next request takes it with `{ steal: true }` and the request that was waiting is rejected with an `AbortError` before it is sent. Safari words it *Lock was stolen by another request*; Chrome says *Lock broken by another request with the 'steal' option*. This happens when the app opens after a laptop wakes, on a slow signal, or with several tabs. `isRetryableError` treated every `AbortError` as the user cancelling, so `withSupabaseRetry` gave up at once. The clock button's two reads then printed the raw text twice. For hourly users nothing loaded it again until a reload, so the button could sit on "Clock In" for someone already clocked in. Salaried users reload every 90 s and recovered on their own. Not new: the library has not changed since 2026-09-08.

## What changed
- `src/utils/errorHandling.ts`: `isAuthLockStolenError` matches both browsers' words. `isRetryableError` retries it ahead of the abort rule, which is safe because the request was never sent. Every other abort is still not retried. `formatErrorMessage` and `formatPostgrestOrUnknownError` show `AUTH_LOCK_ERROR_MESSAGE` (*The app was busy renewing your sign-in, so this did not load. Try again.*). Every `withSupabaseRetry` caller gets the retry.
- `src/components/ClockInOutButton.tsx`: a failed load says it once (the two reads' messages are de-duplicated) with a **Try again** button, and the sentence drops its own *Try again.* beside it. While the last load failed, the button loads again when the app comes back on screen (`visibilitychange` / `focus`).
- `docs/TROUBLESHOOTING.md`: a section for the message.

## Tests
- `src/utils/errorHandling.test.ts`: one stolen lock then a good read loads on the second try. Every try stolen reads in plain words in both formatters. Chrome's words count. A user's abort is still not retried.
- `src/components/ClockInOutButton.render.test.tsx` (new): a failed first load shows the line and Try again. Try again reads again. The app coming back on screen clears it.

## Walked live
Dev server, Dashboard, with the page's `fetch` rejecting clock-session reads with Safari's exact `AbortError`:
- **One stolen lock:** retried, and no line showed.
- **Every try stolen:** after the retries, one line under Clock In with Try again, at 800 px and 375 px.
- **Recovery:** Try again cleared it, and so did the app coming back on screen.
