# v2.4576 — Accounts Receivable: Esc closes one thing at a time, and two smaller fixes (2026-10-05)

Client only; no migration, no edge function. Three small hazards found re-reading the Accounts Receivable map (PR #4556), all in [`BankPaymentsModal.tsx`](../../src/components/jobs/BankPaymentsModal.tsx).

## The fixes

- **Esc is one layer at a time.** The document-level handler called `onClose` whatever was open over the window. It now closes the top layer first: `SetPromisedPayDateModal` (*They said…*, which has no Esc of its own), the exact-match review panel (not while it is applying), then the mark question. With `BankingSortingConfigModal` open it stands down, because that modal has its own Esc.
- **A Returned tick keeps a selected case.** `toggleMercuryReturned` re-selected the first deposit when the selection was not in the list. A selected case never is, so the tick threw the user off the case. It now keeps a case id, as the other selection writers do (`caseIdsRef`).
- **The All search asks again.** The effect that reads the All rows behind a To match search dropped its result when `refreshList` ran mid-fetch, and none of its dependencies changed afterwards, so it never ran again. A dropped read now bumps `hiddenRefetch`, which re-runs the effect.

## Tests

`BankPaymentsModal.escTickSearch.render.test.tsx`: four smokes, one per layer of Esc covered (mark question, They said), the tick, and the outdated search. All four fail against the old code.
