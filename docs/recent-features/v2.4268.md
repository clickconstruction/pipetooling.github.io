# v2.4268 — A greyed Archive from board says which field to change, and who to ask (2026-09-30)

Follow-up to v2.4266 (the always-drawn Archive button), minutes after it merged. Grace, reading the first words ("Sent Sep 8, 2026. A sent bid is already off the working board. If it is dead, mark it Lost in Outcome."): "these helper texts are not helpful enough, they don't clearly tell the user what they would have to do to be able to archive the bid." Client only; no migration, no edge function. Mock-up (version 2, the new words on every state): https://claude.ai/artifact/3xduyWrLeF6kB9pbPZo1wf

## What shipped

- **Every reason names the field and the value**, in the form's own labels, so the user can archive the bid themselves (`archiveFromBoardBlockedReason` in `src/lib/workingBoardArchiveEligibility.ts`):
  - sent → *Archive is for bids that have not been sent. This one was sent Sep 12, 2026. To archive it, clear its Bid Date Sent first. If the bid is dead, set Win / Loss to Lost instead.*
  - Won / Lost / Started → *Archive is for open bids. This one is Won. To archive it, set Win / Loss back to Open first.* (the outcome word is the Win / Loss segment's own label, so *Started / Complete* reads as the button does)
  - not yours → *Only this bid's estimator, Wendi, or its account man, Malachi, can archive it. A dev can too. To archive it yourself, set yourself as its Estimator or Account Man first, or ask one of them.*
- **The names** come from the Estimator / Account Man dropdowns' list (`estimatorUsers`, name or email), passed to the kernel as a fourth `names` argument; a person not on that list (archived, or never an estimator) reads as the role alone. `Bids.tsx` builds the map once (`archiveReasonNames`, memoised) and hands it to both the window's button and the press handler.
- The Bid Board guide's sentence lists the three fields; eleven kernel tests (one per reason shape, with and without names) and the footer render case carry the new words.

## Kept from v2.4266

The rule is unchanged (unsent, Open, and the bid's estimator, account man or a dev), the button stays greyed with `aria-disabled` and the reason as its title, and an archived bid's button still reads *Put back on board*.

Words only, on top of the walk v2.4266 recorded; the kernel tests pin each sentence.
