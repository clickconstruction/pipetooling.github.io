# v2.2615 — Crew Day email goes office-only (2026-09-01)

Owner decision, same day the stream shipped (v2.2603): superintendents should come back to the app for their crew rollup, not get it mailed — so they lose the `crew_day` email on BOTH sides (can't schedule, can't receive). The Dashboard Crew Day section (v2.2602) is their window.

Enforced at every layer:

- **Client**: new `isCrewDayEmailRole()` in `src/lib/crewDay.ts` (office roles only, +1 test) gates the envelope button + `CrewDayEmailModal` mount in `DashboardCrewDaySection` (render smokes assert hidden-for-superintendent / shown-for-dev) and filters the modal's recipient picker (re-exported through `crewDayEmailClient.ts`, replacing `isCrewDayEmailRecipientRole`).
- **Edge function** `crew-day-email-dispatch`: `SENDER_ROLES` / `RECIPIENT_ROLES` drop superintendent — redeployed. Pre-existing superintendent-addressed rows stamp "ineligible role" and never send.
- **DB**: migration `20260901232549_crew_day_email_office_only.sql` recreates the `crew_day_email_requests` INSERT policy with office-only requester AND recipient checks.
- Docs: ACCESS_CONTROL superintendent section, REPORT_SUBSCRIPTIONS inventory row, EDGE_FUNCTIONS entry, help guide `get-a-daily-crew-email.md` (roles narrowed).
- Cosmetic rider: the envelope button renders the Font Awesome envelope SVG (owner-picked) instead of the ✉ text glyph.
