# v2.2937 — One "sent": per-bid counts in the trade you're looking at, one sent-date rule, Share with a teammate (2026-09-06)

Journey map Tier-2 #20 (cluster C28 — "Sent" has three truths and five counts; J13-F1/F2/F5/F6, J14-F1/F6/N2, J10-N2, J35-F5). **Decision 8 (Will, 2026-09-06): the unit is the BID (not the packet); the scope follows the trade pill and is labelled; one "sent" date rule; Package & Send is sharing with a teammate, not sending.** Client only — no migration, no edge function.

## The problem

Five doors read one append-only truth (`bid_version_sends` → `bids.bid_date_sent`) and disagreed on the **unit** and the **scope**, never on what "sent" is: the Followup lenses counted per-GC packet rows (`gcOutcomeRowsForBid`) while the Bid Board bucketed per bid and the Dashboard card queried every trade with no `adopted_into_bid_id` filter — 60/59 · 107/101 · 115/114 · 99/96 on the same afternoon (J14-F1, verified live 2026-09-03). Version-less bids stamped the sent date with two writers and no rule, so minting a room link on a hand-marked bid silently moved its date (J13-F2). Package & Send wore the money tab's "Share" with its "with a teammate" audience in a hover title (J13-F1).

## Kernel 1 — [`src/lib/bids/bidSentCounts.ts`](../../src/lib/bids/bidSentCounts.ts)

`bidSentCounts(bids, { scope, packetsByBid? })` → `{ bids, sent, unsent, waiting, won, started, lost, lostNeedingReason, lostNeedingReasonValue, packetsSent, packetRows }`. Rules, stated once in the module header:

1. **The unit is the bid.** A bid with 3 GC packets is one sent bid; `packetsSent` / `packetRows` are sub-counts for the row detail.
2. **The scope follows the trade pill and is labelled.** `{ kind: 'trade', tradeId, tradeName }` | `{ kind: 'all' }`; `scopeLabel(scope)` → `"Plumbing"` / `"all trades"`; `withScopeLabel("60 lost", scope)`.
3. **The pile is `getSubmissionSectionKey`** (the board's rule) + the archived-working exclusion, so pills, section headers and lens headlines cannot disagree. **Adopted bids leave every count** (`adopted_into_bid_id`), as they leave every list (v2.2133) — the Dashboard used to count them.
4. **Package & Send is not a send** — `bid_pricing_package_sends` is not an input; only `bid_date_sent` makes a bid sent (test: a bid with 4 teammate shares and no sent date is unsent).

`bidsAndPacketsLabel(bids, packets, noun)` → `"101 bids · 107 GC packets"` (collapses to `"101 bids"` when nothing is multi-GC). `buildCallQueue` totals now count distinct bids (`chaseCount`, `reasonsCount`) with the rows beside them (`chasePacketRows`, `reasonsPacketRows`).

**Test** [`bidSentCounts.test.ts`](../../src/lib/bids/bidSentCounts.test.ts): a fixture reproducing the walk's afternoon (101 pending Plumbing bids of which 7 are two-GC → 107 rows; 114 lost + one lost packet on an open bid → 115 rows; 59 lost-no-reason + one HVAC → 60; 96 chase bids with 3 two-GC → 99 rows) asserts the old per-packet tallies AND that each pair collapses to one number per scope.

## Kernel 2 — [`src/lib/bids/bidSentDate.ts`](../../src/lib/bids/bidSentDate.ts)

`BID_SENT_DATE_RULE`: **`sentAt` = the earliest successful send to a GC via any lane (send-ledger row, bid-room first send, hand stamp); a later lane never moves a recorded date — only the explicit re-stamp does.**

- `sentDateAfterLedgerWrite(rows)` — versioned bids: earliest ledger row, null once the last row is un-sent (= the `sync_bid_date_sent_from_sends` trigger). Replaces `firstSentOn` in `BidGcSentPanel.syncRollupAfterWrite` and the Cover Letter's `cur < today ? cur : today`.
- `sentDateAfterLaneStamp(current, stampDate, { explicit? })` → `{ next, write }` — null → the lane's date; a date on record → the earlier stands and `write` is false when nothing changes; `explicit` (the button) wins.
- `restampConfirmMessage(current, today)` — the one sentence the re-stamp confirm shows.

**Enforced at each lane:**
- **Room, version-less** (`BidsCoverLetterTab.markSentTodaySimple(…, 'room', current)`): fills an empty date only; a hand-marked date is left alone (J13-F2 fixed). Telemetry still fires.
- **Room, versioned** (`markSentToday(…, { lane: 'room' })`): writes ledger rows as before; the roll-up mirror uses the rule.
- **Hand** (`markSentTodaySimple(…, 'hand', current)`): on a bid with a date the button reads **Move sent date to today** and asks first (`useConfirmDialog`); the caption says "sending the room link keeps this date; only this button moves it".
- **Ledger** (`BidGcSentPanel.markGcSent` / `editGcDate` / `unsendGc` via `syncRollupAfterWrite`): `sentDateAfterLedgerWrite(rows)`.

**Test** [`bidSentDate.test.ts`](../../src/lib/bids/bidSentDate.test.ts): hand-stamp then room send keeps the hand date; room first then ledger keeps the earlier; null → first lane wins; explicit re-stamp moves; un-send the last row → null.

## Telemetry — `bid_sent{lane}`

No new table, no migration: [`bidSentTelemetry.ts`](../../src/lib/bids/bidSentTelemetry.ts) `recordBidSentLane(userId, role, lane)` writes one `ui_nav_clicks` row — control `bid_sent`, target `#lane=ledger|room|hand` — at every writer (Cover Letter button + room first send, both shapes; Edit-Bid per-GC Mark sent). The version-send ledger keeps its per-row record.

## The five doors

| Door | Before | After |
|---|---|---|
| Bid Board header pills (`BidsBidBoardTab`) | `bidBoardBuckets[key].length` per bid, unlabelled | kernel `pillCounts` (same pile rule) + a dashed **Plumbing** / **all trades** chip leading the pill row (title explains the scope) |
| Call queue header (`BidsCallQueueTab`) | "99 bids to chase" = per-GC rows | "· Plumbing · **96 bids · 99 GC packets** to chase · 59 losses need a reason …" |
| Why we lost header (`BidsWhyWeLostLens`) | "59 need a reason · of 115 lost" (rows) | "59 lost bids need a reason · of **114 lost · 115 GC packets** · Plumbing · $… unexplained" (+ "· N GC packets need a reason" only when a packet-level reason is owed); the estimator filter scopes the kernel too |
| Waiting to hear header (`BidsWaitingToHearLens`) | "96 sent bids to chase · of 101 still open" | "… of **101 still open · 107 GC packets** · Plumbing · $…" |
| By status section headers (`BidSubmissionFollowupTab`) | "Not yet won or lost (107)", "Lost (115)" (rows) | "Not yet won or lost (**101 bids · 107 GC packets**)", "Lost (114 bids · 115 GC packets)"; the Unsent header carries "· Plumbing" |
| "N need a reason" chip (`Bids.tsx`) | per-bid, unlabelled | kernel `lostNeedingReason` → "59 need a reason · Plumbing" |
| Dashboard / Quickfill lost-bids card (`useLostBidNudge`, `DashboardPinnedQuickRow`, `DashboardLostBidsMissingReasonBanner`, `dashboardNeedsYou`) | inline `bids` query per surface, every trade, adopted bids included | one hook feeding both surfaces, reading `bidSentCounts(rows, { scope: 'all' })` → `lostBidNudgeFromCounts`; title "60 lost bids have no reason recorded **· all trades**" |

`Bids.tsx` derives `sentScope` from `selectedServiceTypeId` + `serviceTypes` (`{ kind: 'all' }` when the pill is cleared) and passes it to the board, the three lenses and By status.

## Share with a teammate

`PricingShareMenu`'s green button reads **Share with a teammate** (the v2.2198 hover title promoted to the label); `PackageAndSendBidPricingModal` is titled the same with the caption "Shares this package with a teammate — it does not send anything to the GC and does not mark the bid sent." The kernel excludes it by construction (rule 4). Guide `send-a-bid-pricing-package.md` renamed the button.
