| # | Finding | What changed |

| 1 | J30-N1 | **Done — filter moved server-side, no `fetchAllRows` needed.** [`ChecklistReviewInboxSection`](../../src/components/checklist/ChecklistReviewInboxSection.tsx) fetched the 50 newest completed-unreviewed instances company-wide and only then ran `buildReviewQueueRows`' reviewer scope, so a master or assistant whose cards sat past the 50 newest completions saw none of them and the TO SIGN OFF tile undercounted. The read now applies the scope before `.limit(REVIEW_QUEUE_LIMIT)`: non-devs select `checklist_items!inner(...)` and add `.or('created_by_user_id.eq.<me>,notify_on_complete_user_id.eq.<me>', { referencedTable: 'checklist_items' })` — the inner join is what lets a filter on the embedded item drop the parent instance row; everyone adds a top-level `.or('completed_by_user_id.is.null,completed_by_user_id.neq.<me>')` (nobody self-reviews; a row with no recorded completer still queues); devs keep the left join and no reviewer clause. The strings live in the kernel ([`checklistReviewQueue.ts`](../../src/lib/checklistReviewQueue.ts): `REVIEW_QUEUE_LIMIT`, `reviewQueueSelect(isDev)`, `reviewQueueServerFilters(scope)`, `matchesReviewQueueScope(inst, scope)` as the in-memory mirror). `buildReviewQueueRows` still re-applies the same scope client-side — belt and braces, and the dev path is unchanged. |
| 2 | J30-N2 | **Verified NOT covered by #19, then done.** PR #2636 swept 18 files onto `activeUsersQuery` / `activeRosterOnly` but not [`ChecklistComingUpSection.tsx`](../../src/components/checklist/ChecklistComingUpSection.tsx), whose `useComingUpWaitingGroups` still ran a raw `supabase.from('users').select('id, name, email')` — no `archived_at`, no `is_digital_twin` filter. Both hosts (Checklist Today's ⏳ Waiting For and the Dashboard My Inbox strip added in v2.2650 — the "WORSE" half) read that one hook, so the swap to `activeUsersQuery('id, name, email', { includeDev: true })` fixes both. `includeDev: true` because the owner staffs roadmap tasks — the same option the Roadmap tab's own loader uses (`useChecklistTechTreeData.ts`). An archived or twin assignee on the blocking task now resolves to no name and falls through to the existing unstaffed wording. |
