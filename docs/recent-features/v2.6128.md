# v2.6128 — The job window's photos show their pictures (punch list #164, fix) (2026-10-30)

Found on the live walk of v2.6090 on prod, the morning it shipped: the ZZ Test job's strip read *Photos · 1* with the right day and from-line, but its one tile stayed the grey square, and a picture opened in the viewer would have shown nothing.

## What changed

- **`lib/photos/jobPhotosIo.ts`**: `jobPhotoThumb` and `jobPhotoFull` fetch `job-photos` with a plain `fetch` under the caller's sign-in (the session's JWT and the anon key, the house pattern of `PersonContractSignedRecordModal`) and make the object URL from the answer's blob. They had gone through `supabase.functions.invoke`, which makes a `Blob` only of an `application/octet-stream` or `application/pdf` answer and reads every other type as text (`@supabase/functions-js` 2.99.2, `FunctionsClient.js`), so the function's `image/jpeg` came back a string and both doors answered null. `listJobPhotos` keeps `invoke`: its answer is JSON.
- **The test** `jobPhotosIo.test.ts` pins an `image/jpeg` answer to an object URL, both doors, a refusal and an empty answer to null, and no call without a sign-in. The strip's render test runs over a fake io, which is why it never met `invoke`.
- **`docs/EDGE_FUNCTIONS.md`** → job-photos: the Doors line says the bytes come by a plain fetch, and why.

## Decisions

- The fix is in the client, not the function: the function's `image/jpeg` is the right answer, and the client change ships with no function deploy.
- No migration, no function change.
