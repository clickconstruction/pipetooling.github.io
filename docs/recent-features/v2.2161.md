# v2.2161 — "Send to": the version picker grouped by GC (Bids by GC, G2) (2026-08-23)

G2 of the owner's "Bids by GC" model (proposal claude.ai/code/artifact/a2878573-eb4d-47d9-abaf-e4cbd942a811, prototype claude.ai/code/artifact/ce7e9a39-5bfb-4ba3-88d2-42abfe991a9f). Client-only.

[`BidVersionPicker.tsx`](../../src/components/bids/BidVersionPicker.tsx):
- Versions are grouped by the GC they go to (`customer_id`; no override = the bid's GC, new prop `bidGcName` from `Bids.tsx` at all four sites). Each group: GC name (click → switch to its first version), send state (latest `bid_version_sends` across its versions; pre-v2.2124 bids fall back to `bidDateSent` for versions that existed then), "★ {scenario}" of its first version, its version chips (in-letter badge + sends), and **+ version** (opens the new-version modal with `newForGcId` so the new version is stamped with that GC).
- **＋ Another GC…** modal — GC select (customers list), **Start from** (a version; unsplit bids materialize their current setup as the bid GC's packet first), optional name (defaults to the GC). `submitAddGc` → `split_bid_into_versions` / `create_bid_version` (cloning the source's ★), then `stampVersionGc` (sets `customer_id`, upserts `bid_gc_recipients` source 'version' — same as the ✎ dialog).
- Unsplit bids show one group "{bid GC} · one bid" + ＋ Another GC…; "Send… →" unchanged. The Workbench door's "Another bid to send" still opens the plain modal (same GC).
