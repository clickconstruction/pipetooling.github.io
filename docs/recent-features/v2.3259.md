# v2.3259 — Job Summary overhead dials: the app-wide allocation setting, dev sliders, and the math panel's split (2026-09-10)

Client only; no migration (`app_settings` is key/value — new key `overhead_allocation_v1`, JSON in `value_text`, written by devs under the existing "Devs can manage app settings" policy, read by everyone authenticated). PR B of three; the kernel is v2.3258.

## What shipped

- **`lib/jobs/overheadAllocationSettings.ts`** (+3 tests): `parseOverheadAllocationSetting` (null/blank/junk → the original day-share; otherwise normalized field by field, so a future field never breaks an older client), `serializeOverheadAllocationSetting`, `fetchOverheadAllocationSettingFromAppSettings`, `upsertOverheadAllocationSetting`. Key in `appSettingsKeys.ts`.
- **`hooks/useOverheadAllocationSettings.ts`**: one fetch per page load behind a module cache with subscribers; `saveAppDefault` writes the row and updates every subscriber in place; fails soft to legacy for the page load.
- **`jobSummaryLedgerView.ts`**: `JobSummaryViewPrefs.overheadDials` (a dev's per-device exploration; `null` = follow the app default; normalized on read), `enrichJobSummaryRows({ settings })` → rows gain `overheadActivityUsd` / `overheadCarryUsd` / `overheadOpenDays`, and `jobSummaryHygiene(ledger, settings)` now carries the reconciliation (`poolUsd · carriedInUsd · activityUsd · carryUsd · inFlightUsd · reconciles`) from `buildOverheadAllocation`.
- **`useJobSummaryView`**: effective settings = `prefs.overheadDials ?? appDefault`; the same settings feed the main enrich, the Compare window's enrich and the hygiene, so Jobs · Months · Cut by · Compare agree. New bundle field `view.overhead` (`settings · appDefault · isOverride · appDefaultLoaded · saving · explore(s | null) · saveAppDefault(s)`).
- **Toolbar** (`JobSummaryLedgerToolbar`, new prop `canEditOverheadDials`): beside the Overhead control, when the method is Day-share, a chip naming the constants (`overheadAllocationLabel`: "1 day · no carry" · "30 days · 20% carry · 14-day idle cap"); red with *exploring on this device* while a dev's dials differ from the app default. For devs the chip carries ⚙ and opens **[`OverheadDialsPopover`](../../src/components/jobs/OverheadDialsPopover.tsx)**: smoothing slider (1–60), carry slider (0–100%, steps of 5), idle cap (none · 7 · 14 · 30) and open definition (Working → Billed · first → last work) segments, a live reconciliation strip (pool · by hours · carry · nobody · in flight · ties?), and Recommended / Original day-share / Back to the app default / **Use for everyone** (two-step confirm; writes the org default and clears the exploration). Closes on outside click or Escape. Hygiene chips: "had nobody to charge on N days" (reworded), new "in flight" chip, and a red "does not reconcile — tell a dev" chip that should never show.
- **Tab** (`JobsJobSummaryTab`, prop `canEditOverheadDials` from `Jobs.tsx` = `authRole === 'dev'`): the "Overhead — the math" summary reads *over N field days · M open days* when carry is on; the day table's pool column becomes *Landed that day* under smoothing, gains *By hours* / *Carry* columns when carry is on, and marks carry-only lines *open, not worked* in muted ink; the footnote states the constants in words.
- Pay lockdown unchanged: everything above sits behind `showMoney`; only the dev sees the dials.

## Behavior today

Until a dev saves an app default, `app_settings.overhead_allocation_v1` is absent and every reader charges **1 day · no carry** — the numbers are unchanged from v2.3242. The owner-approved default (30 · 20% · 14) is set from the dials after PR C ships, so the Burn projection and the Days view flip at the same moment.
