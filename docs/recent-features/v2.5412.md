# v2.5412 — Five more server functions pass their own type check again (2026-10-12)

A type-only fix to `drive-contract-scan`, `get-contract-for-signer`, `open-test-report-pdf`, `get-submittal-room` and `resend-webhook`, five of the 24 edge functions a `deno check` sweep of all 151 found failing on 2026-10-12. In each, the type written or inferred for a value was narrower than the value itself. No migration and no screen. Nothing behaves differently.

- **`drive-contract-scan`** (TS2322 ×2):
  - Both folder walks start from `let cur = (f.parents ?? [])[0] ?? null`. Deno checks without `noUncheckedIndexedAccess`, so `[0]` reads as `string`, the `?? null` drops out of the type, and `cur` was `string`.
  - So `cur = m.parent`, a `string | null`, was refused. The loops already stop on the `null` an empty `parents` gives.
  - Both read `let cur: string | null` now. Once `cur` may be null, TypeScript could not infer the second walk's `m` (TS7022), so `m` is typed `FolderMeta`, the type already in scope.
- **`get-contract-for-signer`** (TS2339): the reply sends `id: r.id`, and `r` is the row cast to a type that left `id` out. The select fetches `id`, its first column, so the reply always carried it. The cast's type names `id: string`.
- **`open-test-report-pdf`** (TS2339 ×5):
  - `link` started as `let link: {…} | null = null`, and each read was cast `as typeof link`.
  - `typeof` reads the type narrowed by that `= null`, so `link` was `null`, then `never` past the `!link` check.
  - The row type is named, `PortalLinkRow`, and both casts use it. It was not the `ReturnType<typeof createClient>` client fault v2.5376 fixed elsewhere.
- **`get-submittal-room`** (TS2353):
  - `let personOut = base.person` took its type from `base.person`, which has no `messagesThisHour`, so adding the asker's count for the last hour was refused.
  - It is typed `RoomPerson | null` now, the payload's own person type from `_shared/submittalRoomPayload.ts`, whose `messagesThisHour` is optional.
  - The count reached the page all along, which greys Ask at five an hour.
- **`resend-webhook`** (TS2769):
  - `base64ToBytes` declared a plain `Uint8Array`, which TypeScript 5.7 and later read as `Uint8Array<ArrayBufferLike>`. WebCrypto's `importKey` takes only bytes in a plain `ArrayBuffer`.
  - The function fills a `new Uint8Array(n)` of its own, so it declares `Uint8Array<ArrayBuffer>`. No copy is made, so the signature check does exactly what it did.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3): 11 errors on `main` (2, 1, 5, 1 and 1), 0 here.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
  - Every column the five functions select exists in `src/types/database.ts`.
- **Deploy**: redeploy the five once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
