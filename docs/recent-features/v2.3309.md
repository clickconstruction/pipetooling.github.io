# v2.3309 — Test reports PR 6: the GC picker on the send sheet (2026-09-11)

Client only; no migration, no edge function. The first residual from [`to-dos/test-reports/README.md`](../../to-dos/test-reports/README.md).

## Why

The live send test showed it: the recent pretest jobs (Johnson, Scarbrough, Peterson, Montolongo…) carry the homeowner as `customer_id` and **no `gc_customer_id`**, so the send sheet prefilled the homeowner while the report belongs to Done Right Foundation Repair. Linking the GC on Edit Job every time is a detour; the send sheet is where the office already knows who ordered the test.

## What shipped

- **Kernel [`src/lib/jobs/testReportRecipients.ts`](../../src/lib/jobs/testReportRecipients.ts)** (+9 tests): `prefillTestReportTo` (last send → the GC's email → the customer's), `testReportRecipientLabel` (the GC when its address is a recipient, else the customer), `contactInfoWithEmail` (merge into `customers.contact_info`), `gcPickWrites` (link the picked GC to the job when asked and not already linked; save the typed address on the GC's card only when the card has none and the office said so).
- **[`TestReportSendSheet`](../../src/components/jobs/TestReportSendSheet.tsx)** gains a **GC** row above To: the job's GC by name with *change*, or the job form's own `CustomerSearchCombobox` (customers loaded on first open, archived rows excluded). Picking one fills To with their email and shows **Set <GC> as the GC on this job** (checked); a GC with no email shows **Save <typed address> on <GC>'s customer card** under To (checked). Both writes run before the send through the caller's RLS and fail soft with a toast — the email still goes. The PDF's *Company* line and the activity line use the picked GC.
- Help guide `file-a-test-report.md`: the To bullet describes the pick.

## Verified

Kernel tests; typecheck · lint · theme check. Dev server: on a job with no GC the row offers the search; picking a customer with an email fills To and shows the link checkbox; the send stamps the job's `gc_customer_id` and the activity line names the GC.

## Notes for the next session

No backfill of `gc_customer_id` on the existing pretest jobs — each send links its GC from now on, and the owner can link the older ones from Edit Job if the portal history should show them under Done Right.
