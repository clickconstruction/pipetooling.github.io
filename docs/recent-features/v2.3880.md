# v2.3880 — Lien desk: every strip carries the demand letter (2026-09-27)

Client only; no migration, no edge function. Punch list **#32**, the last piece — the card closes with it (`to-dos/job-deadline-timeline.md` and its mock-up are deleted; the mock-up lives in git history at this commit).

## What shipped

[v2.3877](v2.3877.md) put the demand letter on the strip and gave both desk adapters a `demandLetters` input; only the Lien window passed any. Now every reader does:

- **`src/hooks/useLienDeskData.ts`** — the full (not light) read loads `job_demand_letters` for the desk's jobs, unvoided, chunked like the filings, into `demandLettersByJob`. The field is optional on `LienDeskData`: the light read and the GC run (`useGcOnNoticeData`) carry none, and a failed read draws the strip without the node rather than failing the desk.
- **`LienDeskModal.tsx`, `LienDeskAffidavitPane.tsx`** — each hands its job's letters to `buildLienTimelineFromDesk`. The notice pane and the affidavit pane draw the square node, and *Waiting on* names the letter's debtor while its reply is owed.
- **`src/hooks/useLienTimelineBook.ts`, `src/lib/jobs/lienTimelineBookAssemble.ts`, `lienTimelineBook.ts`** — the Timeline tab's read loads the letters for the book's jobs; `LienBookRaw.demandLetters` (optional) folds to `demandLettersByJob` and each row's timeline takes its own. The mini row draws the node; the row's *Next* words are unchanged (a letter never becomes *Next on the path* — it feeds *Waiting on*, which the mini row does not print).
- **The firm's portal** reads the book through `legal-portal`, which sends no letters: `parseLienBookRaw` reads a missing `demandLetters` as none, so counsel's grid is as it was. The printed grid has no letter column.
- **The guide** *send lien notices from the Lien desk* → *Where a job stands* says all three draw it; the Lien desk map's read list and line counts.

## Not built, by choice

The mock-up offered a *Waiting on* column on the Timeline tab's grid as an option; it was not picked, so the grid keeps its three columns.
