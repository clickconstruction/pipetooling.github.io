# v2.6527 — The login column is required where a login is drawn (punch list #264, PR 1) (2026-11-04)

Card #264, from the dev's question after the users-without-login train (#260) shipped: what keeps it clean. The live walk of v2.6518 had found a reader (the Users tab's three row builders) that never selected `users.login_attached_at`, so a person with no login drew as a login; the sweep (v2.6519) fixed that one by hand and settled on "unstamped means a login", which existed only because the column was optional on every row type. No migration; no edge function change.

## What changed

- **The column is required** (`login_attached_at: string | null`, no longer optional) on `UserRow` (`usePeopleRoster.ts`), `UsersTabRowItem` (`UsersTabRow.tsx`), the Account lens's item (`UsersTabLensCells.tsx`) and `PersonDeskUserRow` (`usePersonDesk.ts`); `RailPersonInput.hasLogin` (`deskRailAttention.ts`) is a required boolean, false for a roster-only row. Every reader the typecheck named now selects or passes it: the Users tab's row builders (`item.source === 'user' ? item.login_attached_at : null`), the desk page's rail rows (its users read carries the column), the test fixtures. `usersTabRows.ts` and `rowNeeds.ts` read `hasLogin` plainly.
- **The picker rule is pinned**: `src/lib/people/fetchActiveUsers.test.ts` — the default keeps a person with no login, `withLogin` reads the column and drops them without a new operator on the query, and a row an older reader did not stamp keeps the older meaning.
- **GLOSSARY** gains *Login attached · no login* with the rule in code.

## Left for PR 2 of the card

`archive-user`'s callers on the id and the lookups by email and name dropped; `create-user`'s attach door lifted into a shared kernel.
