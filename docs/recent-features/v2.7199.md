# v2.7199 — Materials on site: a box's own window, with a Cage tab and a Contents tab (2026-11-13)

The owner's asks of 2026-11-13, looking at Jobs → Materials: click a box to edit its name and its details, quickly, and then a window with tabs to dig in. Tab one is the cage: its location, name, code and history of movement. Tab two is its contents: where each was when added and its history. v2.7179 built **Edit** with the name, the kind and the where line. This turns it into that window.

## What changed

- **A box's name opens the window** on Jobs → Materials (`JobsMaterialsTab.tsx`). The name in a box's heading is a press with a dotted underline. **Edit** beside **Label** stays. Unsorted's name is plain words.
- **The window is two tabs** (`src/components/materials/BoxTabs.tsx`), hosted by the phone's sheet and by `BoxWindow` on the office page.
  - **Cage**: the Edit form, which now also holds **Which place on site** (the job's places as chips, the box's own pressed, a field for a new one). Then **Its code**, the dashed code and the address, with the line that it never changes. Then **Its history**, newest first: added and under which name, each move with its two places, each rename, its retire.
  - **Contents**: each part in the box with its number, as the host page reads its lines. Under a part: the day it first came into this box, who added it, and where the box stood then. A fold opens that part's history in this box.
- **The rules** (pure, with tests):
  - `editBox.ts`: `boxPlaceChange` reads the place draft, a typed place over a picked one, a typed name the job already has as that place. `editBoxPlan` judges the fields and the place together. `savedBoxWords` adds where the box stands now.
  - `boxHistory.ts`: `boxHistory` (the box's own events), `placeAt` (where a box stood at a moment, by its moves), `lineHistory` (every ledger row of a part in a box, a count worded against what the ledger expected then), `lineAdded` and its words.
- **One read** (`boxHistoryIo.ts`): the box's old names from `job_container_names`, the table v2.7072's trigger writes. This is its first reader. A read that fails says why on `OfflineRetryPanel` and reads again by itself when the signal is back.
- **The writes** are the ones the app had: `editContainer` for the fields, `addPlace` and `moveContainer` for the place, as the phone's **Move box** does. Each goes through the outbox.

## Not here

- **A part's typed name** cannot be fixed yet. The ledger takes inserts alone, so a name change needs a function in the database and a record of it. That is its own change with a migration.
- **A count** is still **Correct…** on the line, and a use or a move of a part is still the phone's presses.
- **The site view** (`?site=`) still opens a box by its link to the job's page.
- **A long ledger**: past the store's row cap a history may start part way, and the tab says so.

No migration, no function. Stacked on v2.7179 (#7995), which is in the merge queue.
