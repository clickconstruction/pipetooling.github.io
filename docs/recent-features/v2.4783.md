# v2.4783 — Job form: the address pins itself (2026-10-07)

Client and the `geocode-one` function (**redeploy after merge**; the old function still answers, without a county). PR 1 of 3 of `to-dos/job-address-pin/` (mockup `mockup-on-the-map.html`). The owner (2026-10-07): *right now geocoding occurs when I open the /map page, but I would like it to occur when someone puts in an address in new job and edit job modals. How can I offer this tastefully?* Behind it: 149 property records with no point, which no court map can place.

## What changed

- **[`JobFormAddressPin`](../../src/components/jobs/JobFormAddressPin.tsx)** under the *ON STATEMENTS* line in `JobFormIdentityFields`, in the same voice: *ON THE MAP · placing…* → *Guadalupe County ✓ · pinned from the street map* with *Not right? Pin from Google* (the Map page's own refresh); an older job the cache holds reads *placed ✓ · pinned earlier* at once with no lookup; one it never placed reads *not placed yet · Place it*; a miss reads *could not place it · it needs a street, a city or a ZIP; the night will try once more* with *Try again*. Only the roles `geocode-one` admits (dev, master, assistant-like, estimator) see it; outside an AuthProvider (the form's render smokes) it is silent (`useOptionalAuth`, new).
- **When it runs** ([`addressPinWords.ts`](../../src/lib/jobs/addressPinWords.ts)): the cache is read on open and on every change; a whole-looking address (a city split off after a comma, a ZIP, or a trailing state) pins itself 1.2 s after the last keystroke; a fragment waits for the blur, which the input's existing handler now signals. A taken Google suggestion already pre-warmed the pin (v2.4094); this covers what is typed or pasted.
- **`geocode-one` answers with the county**: Google's `administrative_area_level_2`, else the county the point sits in from the Census geographies lookup (`censusCountyFromPoint`, free, no key), on every ok answer, cache hits included. Additive.
- **Nothing on the job changes.** The pin lives in `address_geocodes` under the address, where the Map page and the court map read it; edit the address and the line resets and runs again.

## Is this the best we can do?

- **No button.** The first draft had *Pin on the map*; a button is a chore someone skips. The only chips are for an answer that looks wrong, an old job never placed, or a miss.
- **Not on every pause.** A fragment never spends a lookup; a whole-looking address waits 1.2 s, a fragment waits for the blur.
- **The county, not a tick.** A tick hides a wrong pin; the county makes the answer checkable in a glance and is what the court map needs.
- **The backlog is the night's**, not the form's (PR 3). The form stops it growing.
