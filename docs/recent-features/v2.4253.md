# v2.4253 — Procurement log: its date boxes read a date with the shared rules (2026-09-30)

The mechanical move [v2.4241](./v2.4241.md) left for later: the procurement log drops its own copies of the date readers and imports the shared kernel. It waited for v2.4243, which edited the same three files. No behavior change.

- [`procurementLog.ts`](../../src/lib/submittals/procurementLog.ts): `LOG_DATE_MIN_YEAR`, `LOG_DATE_MAX_YEAR`, `isPlausibleLogDate`, `LogDateEntry` and `readLogDateEntry` are deleted. Each was line for line the same as `DATE_BOX_MIN_YEAR`, `DATE_BOX_MAX_YEAR`, `isPlausibleDate`, `DateBoxEntry` and `readDateBoxEntry` in [`dateBoxEntry.ts`](../../src/lib/dateBoxEntry.ts).
- [`SubmittalProcurementPanel.tsx`](../../src/components/bids/SubmittalProcurementPanel.tsx) imports from the shared kernel:
  - `saveDate` reads the box with `readDateBoxEntry`;
  - `dateChanged` asks `holdsDateBoxChange(typed, value, stored)`, which is the condition it spelled out before (`typed || … === 'unfinished'`);
  - `dropDate`'s toast is `unfinishedDateMessage(year)`, the same sentence;
  - `dateCell`'s *check the year* test (added by [v2.4243](./v2.4243.md)) is `isPlausibleDate`.
- The panel keeps its own `dateBox()`. Its Expected box compares against the stored date (`storedDate`), not the derived one it shows, so it is not a `FinishedDateInput`.
- [`procurementLog.test.ts`](../../src/lib/submittals/procurementLog.test.ts): the two tests for the deleted readers are gone. Every case in them is in [`dateBoxEntry.test.ts`](../../src/lib/dateBoxEntry.test.ts), which also covers `holdsDateBoxChange` and the message.

Not walked live: nothing a user sees changes, and the panel's render smokes (typed date held, blur and Enter save, a pick saves at once, the dropped-date toast) pass untouched.

Verify: `npx vitest run src/lib/dateBoxEntry src/lib/submittals/procurementLog src/components/bids/SubmittalProcurementPanel`.
