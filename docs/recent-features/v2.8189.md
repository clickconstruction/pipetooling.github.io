# v2.8189 — Document builder: a link keeps its address when the keys behind it change (2026-11-21)

Punch list #404. The review of 2026-11-20 listed it and Taunya asked for it on 2026-11-21. No migration.

## What was wrong

Only the SHA-256 of a link's code is in the database. The function makes the code again from the row's id, its nonce and a secret, to show a dev the same link on another day and to put it in a trade's email. The secret was `DOCUMENT_BUILDER_LINK_SECRET`, or the service role key when that was not set. It was not set.

An open reads the hash alone, so a link would have gone on opening. But after a new service role key, or after the secret was set, the function would have made a different code for every link that existed. The card would have shown an address that opens nothing, and the next email to a trade would have carried it.

## The fix

- **A link that exists is made again by its own hash.** `documentBuilderLinkCodeAgain` tries each secret this side holds and returns the code whose hash is the row's. A link made under the service role key is still found after the secret is set. A link made under the secret is still found after the service role key changes.
- **A new link is made under the link's own secret.** `documentBuilderLinkSecrets` puts it first, with the service role key behind it for links made before.
- **Never a wrong address.** When no secret makes the row's code, `desk.state` answers `code: null`. The card says the link is on, that its address can no longer be shown and that it still opens for anyone who has it, and offers **Make a new link**. A send then carries no sheet link, as it does for a link that is off. It does not make a new one over the address people hold.
- The code's making moved from the edge-only file to the shared kernel (`_shared/documentBuilderLink.ts`), so it is under test. It uses Web Crypto, which both runtimes have.

## On prod

`DOCUMENT_BUILDER_LINK_SECRET` is set and `document-builder-link`, `document-builder-send` and `gc-trade-portal` are deployed after this merges, on Taunya's go of 2026-11-21. Every link on prod had been switched off before, so no live address rides on the old key.

## Tests

- `linkCode.test.ts` (new): the order of the secrets, a code's shape, and a link's address made again across each change of key, with null and never a wrong address when no secret made it.
- `BuilderLinkCard.render.test.tsx`: a link that is on with no address shows the words and no **Copy the link**, and **Make a new link** still works.
