# v2.3264 — People → Overhead: behind every cell of "Who makes up overhead" (2026-09-11)

Client only; no migration. Owner ask: "click on any cell and see a modal with the transactions that add up to that cell." Mock-up built first (Behind the Cell, example rows), reviewed against "is this the best we can do", revised, then built. Stacked on v2.3261 (recorded time).

## The review that shaped it

The first cut proved the number and grouped by week. Asked again on the real data, it still wasn't: Taunya's week read as six punches, four of them on one Tuesday (8:03–8:13, 8:32–1:26, 1:30–1:39, 1:49–1:51), so a 2-minute stray tap weighed the same as an 8-hour day. The built version rolls punches into **one row per person-day** (the day's hours and dollars on the row, every punch inside it in clock order, `OverheadCellDay`), chips **stray punches** under 15 minutes as noise rather than error, and ranks days under Largest first. The review before that added what an auditor actually needs: **outlier emphasis** (sessions over ten hours read as forgotten clock-outs; weekend sessions are tagged), **Largest first** ordering, **Sun–Sat weeks** to match the tab, **purchase rows with their own columns** (Day · Purchase · Section · $ — no empty Hours/Rate), **collapsed person groups** for the Pool row, a **filter** across notes, bids, merchants and sections, and a proportional **bar per week**.

## What shipped

- **Detail lines carry the punch** — [`overheadDailyLabor.ts`](../../src/lib/overheadDailyLabor.ts) `OverheadSessionDetailLine` gains optional `clockedInAt` / `clockedOutAt` / `approved` / `wageUsdPerHour`; `overheadPoolSnapshot.peopleLines.labor` is now the full detail lines (a structural superset of the table's input). `OverheadPeoplePartsInput` gains optional `line` (source, label, transaction id), `bucket`, `cardLabel`; the tab's `overheadPeopleParts` memo fills them.
- **Kernel** [`lib/overheadPeopleCellModel.ts`](../../src/lib/overheadPeopleCellModel.ts) (+6 tests): `buildOverheadPeopleCellModel({ table, person | null, unattributed, column, labor, parts, order, filter, bidLabelById })` → sections (office / bid / parts, all three for Total), groups by Sun–Sat week (a person) or by person ranked by dollars with "no person" last (the Pool row), lines ordered newest or largest, `cellUsd` vs `sumUsd` and `ties`, hours and average rate, counts (pending · no wage · long · no person · shown), the bid ids to label. `overheadPeopleCellCsv` for the clipboard. The filter narrows what is shown, never the sum.
- **Modal** [`components/people/OverheadPeopleCellModal.tsx`](../../src/components/people/OverheadPeopleCellModal.tsx): title (person · column · window), the cell's figure in the column's color with the hours × rate line, column pills (disabled when empty), flag chips linking to People → Hours / Pay config / Banking → Accounting, filter + Newest/Largest toggle, per-group sticky headers with subtotal, day and punch counts, "N to review" and the proportional bar; day rows (day · every punch's in–out or bid label · chips · notes · the day's hours · rate · $) and purchase rows (day · description + source chip · section chip · $); footer with the reconciliation and Copy as CSV. Bid labels fetched once per id set (`bids.bid_number` + `project_name`, fail-soft to "Bid"). Escape and backdrop close.
- **Table** [`OverheadPeopleTable.tsx`](../../src/components/people/OverheadPeopleTable.tsx): every non-zero cell (rows and the Pool row) is a button with an accessible label; the footnote says so.
- Also in this PR: the pool-trend caption that still read "Approved, wage-priced…" now reads recorded time (missed in v2.3261).
