# v2.7331 — The run on a phone: Scan › reads the receipt’s barcode into the Mailed box (2026-11-15)

Client only: no migration, no edge function. PR B of the run's checklist (v2.7328): the phone's camera reads the USPS receipt's barcode and the number lands in that envelope's Mailed box.

## What changed

- `src/lib/jobs/lienRunScan.ts` (+ test): `lienRunScanSupport` (the press shows only on a secure page with `mediaDevices`), `trackingFromScan` (the IMpb on a receipt is `420` + ZIP in front of the 22 digits, with or without GS1 brackets — the number is the tail, grouped in fours; 20 or 22 bare digits are grouped; a courier's lettered code and a QR code's address come back as read), `lienRunScanWords` per outcome, `lienRunScanOutcomeFromError` (NotAllowed → refused, NotFound → no camera), `LIEN_RUN_SCAN_FORMATS`.
- `src/components/jobs/LienRunScanPress.tsx`: **Scan ›** (`run-scan`) opens a full-screen camera over the run (`run-scan-camera`, *Type it instead* closes it). The browser's own `BarcodeDetector` reads where it exists (Chrome, Android); elsewhere `@zxing/browser` is fetched by a dynamic import on the press, so the run's bundle carries none of it. A read calls `onRead` with the grouped number and says *Read … Check it against the slip* under the box; a refusal or no reader says so (`run-scan-words`) and leaves typing as it was.
- `LienDeskRunModal.tsx` hands `besideBox` to the checklist on a phone only (`useIsMobile`), one press per Mailed box, writing through `trackingFor` so a shared envelope takes the number for every notice inside.
- New dependency `@zxing/browser` (with its peer `@zxing/library`), loaded lazily.
- The guide's phone paragraph names the press.

## Verified

- `lienRunScan.test.ts`; `LienRunScanPress.render.test.tsx` (no press without a camera; a refusal's words; a native read lands the number); `LienDeskRunModal.render` (65); lint; the word checks; typecheck; walked at the 375 preset (the press beside each box; the pane has no camera, so the refusal path was what ran live).
