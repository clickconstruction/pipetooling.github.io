# v2.5565 — Training: a place for each course's policy and each person's passes, behind the scenes (2026-10-15)

Punch list #111, PR 2 of six (PR 1 is v2.5564, the lessons and the kernels). The database side of Training: the policy a dev sets and the record a person makes, with the SQL twin of the client's standing rule, so the Dashboard card, the People rail, the Users row and Settings all read one answer. Migration `20261015060000_training_courses.sql` (`docs/migrations/20261015060000_training_courses.md`); push after PR 1 merges and before PR 3 (the course page) merges.

- **`training_courses`**: one row per course the app ships, keyed by the content folder's slug: `enabled` (off by default), `required_roles text[]` (user role words), `good_for_months` (default 12), `due_soon_days` (default 30), `retake_from date` (the *Everyone takes it again…* stamp), `updated_by`. Everyone signed in reads the catalog; only a dev writes it. Seeded `osha-30-refresher`, **off**, required for helpers, subcontractors, primaries, masters and superintendents.
- **`training_lesson_passes`** (`user_id, course_slug, lesson_key`, `passed_at`, `tries`) and **`training_passes`** (`content_version`, `passed_on` by `app_today()`, `passed_at`, `score`, `total`, `answers`): own rows to read and write, the office team (`training_office()`: dev, master, assistant, controller) reads all, nobody updates or deletes a pass through the API.
- **`training_pass_lesson(slug, lesson_key, tries)`** and **`training_finish_course(slug, content_version, score, total, pass, answers)`**: SECURITY INVOKER, so RLS, the read-only training-mode fence and the twin fence all apply to the caller's own row; the finish refuses a score under the bar with *Not a pass*.
- **`training_state_for(user)`**: the SQL twin of `trainingState.ts` (red, amber from `due_soon_days` before the day a pass runs out, green), own rows for anyone and everyone's for the office; **`training_standings(slug)`**: everyone active who must take the course with their colour, worst first, samples, twins and archived accounts left out, office only. The three fence appliers close the migration.
- **SQL bed** `supabase/tests/training/20_scenario.sql` (`npm run test:pg:training`, in `scripts/sql-beds.txt`, the whole schema): the seed, a helper cannot switch a course on and a dev can, red → a lesson pass → a final check under the bar refused → a pass → green with the day it is due, a window of 0 months reads amber, the retake stamp reads red and clears to green, an estimator reads nothing, a helper reads neither another's passes nor standing while the office reads both and the standings list leaves out the sample, the twin and the archived account, a training-mode account and a twin are refused, no sign-in and anon are refused.
- **Docs**: `ACCESS_CONTROL.md` (the three tables and the four functions), `GLOSSARY.md` (*Training · course · pass*), the migration doc.

The migration was dry-run on prod inside a rolled-back transaction before this PR opened, which caught `users.role` being an enum (`user_role`), not text: the two role tests now cast. Docker is not on this Mac, so the bed's first run is CI's.
