# v2.7439 — Lien desk: a job on public property can leave the lien path (2026-11-16)

PR 2 of the public-property train (Taunya's ask of 2026-11-16 on job 883, the second drawing she approved). PR 1 (v2.7436) gave the answer a home on the property record. This PR makes the desk read it. No screen gives the answer yet, so nothing changes on prod until one does. Client only.

## The rule, in one kernel

`src/lib/jobs/lienPublicProperty.ts` (pure, 16 tests) reads `customer_addresses.lien_public_answer`:

- **public**: every job at the address is **off the lien path**. That is derived from the property, never copied onto a job, so one change of the answer brings them all back.
- **private**: the guess from the owner's names is overruled.
- **unanswered**: the desk keeps its guess. A property whose names read as a public body **asks**.

A row read before the migration is pushed carries no answer, so the desk reads exactly as before.

## At the source

`useLienDeskData` already takes ZZ test jobs and in-kind jobs out of every list right after its jobs join, before any queue is built. Off-path jobs now leave at the same place:

- It reads the property record under **every** job on the desk once, whole, in light mode too (it read only the affidavits' before).
- Every job whose property says public leaves the due months, the items, the affidavit and retainage windows and the jobs, so every queue built from them drops it.
- They are handed on as `publicJobs` (the job, its money by the desk's own rule, its bond, the day it went on the attorney's list, and the desk's papers on it), for the bin *Public jobs · bond claim* that comes next.
- `publicAskJobIds` lists the jobs still on the path whose property asks, for the Board's line that comes next.

## The gates read the answer

Everything that held a paper on the name guess now asks the stored answer first:

- the affidavit's owner gate (`withPublicOwner` → `lienPropertyIsPublic`);
- the notice's gate 1 and its draft readiness (`lienOwnerIsPublic(names, answer)`, `draftReadiness`'s new `ownerIsPublic`);
- the job's own Lien window (`LienFilingTabs`).

`resolveLienProperty` carries the answer as `publicAnswer`.

**Put a GC on notice** reads its own months (`useGcOnNoticeData`), so it gets the same rule in its own owner state (`ownerStateFor`): answered public, the job reads *public owner* whatever its owner block holds, and the run already leaves those out; answered private, a name that only sounds public no longer holds it. Unanswered, it guesses from the printed name as before. `useGcOnNoticeData.zz.render.test.tsx` holds all four cases.
