# v2.4918 — GC mode: a trade partner's dates are the office's day, even in the evening (2026-10-08)

Migration `20261008120000_gc_company_record_app_today` (doc: `docs/migrations/20261008120000_gc_company_record_app_today.md`).

The company record (B1, v2.4833) stamped days with the database's `CURRENT_DATE`, which is UTC, so every evening after 7 PM Central it wrote tomorrow's date. It now uses `public.app_today()`, the SQL twin of `todayYmdInAppTz()`:

- in the six date defaults: a form's `sent_on`, an ask's `invited_on`, a quote's `submitted_on`, a call's `contacted_on`, a promise's `made_on` and a move's `moved_on`;
- in the four functions that stamp a day: `gc_vet_company`, `gc_keep_promise`, `gc_keep_promises` and `gc_office_decline`. Each body is otherwise byte for byte.

It was found on the Ask window's live walk: an evening test ask read Oct 8 beside a call logged Oct 7. Rows already written keep their dates. The client is unchanged.

`BOARD_REAL_BUILD.md` → *What the app already has, reused* now names `public.app_today()`, so B5 and B6 stamp days with it from the start.
