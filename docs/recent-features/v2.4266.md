# v2.4266 — Archive from board is always in the Edit Bid footer, and a greyed press says why (2026-09-30)

Grace, 2026-09-30, opening Structura's $15.8M bid as a dev: "I don't see archive, only delete … I would like the archive button shown for all users at all times and grayed out when not able to be clicked such that when a user clicks on it while it is grayed out it tells them the reason it can't be clicked." The button had been rendered only when the whole eligibility check passed, so a sent bid (or one that was not yours) simply had no Archive button and nothing said why. Client only; no migration, no edge function. Mock-up: https://claude.ai/artifact/3xduyWrLeF6kB9pbPZo1wf (the five footer states, the toast each greyed press raises, and the revisions from the "is this the best we can do" pass).

## What shipped

- **One home for the reason** — `archiveFromBoardBlockedReason(bid, userId, role)` in `src/lib/workingBoardArchiveEligibility.ts` returns the sentence a greyed press says, or null when the press may go ahead. Sent first (`Sent Sep 12, 2026. A sent bid is already off the working board. If it is dead, mark it Lost in Outcome.`), then a terminal outcome (`This bid is Won. It left the working board when its outcome was set.`), then ownership (`Only this bid's estimator or account man can archive it. Ask them, or a dev.`). An archived bid has no reason: the button is the way back instead. Ten kernel tests.
- **The footer button is always drawn** (`BidFormModal.tsx`): `archiveFromBoardBlockedReason` replaces the old `showArchiveFromUnsentWorking` boolean. With a reason the button is `aria-disabled` (not `disabled`, so the press still fires and a screen reader hears "dimmed"), at half opacity with a not-allowed cursor, and the reason is its hover title. The press goes to the page as before; `promptArchiveWorkingBoardBid` toasts the kernel's reason before the old generic refusal (kept as a belt).
- **Put back on board** — `archivedFromBoard` + `onRequestUnarchiveFromBoard`: on an archived bid the button flips to the un-archive, a new `unarchiveWorkingBoardBid` on `Bids.tsx` that mirrors `archiveWorkingBoardBid` (same `bidUpdateRefused` guard, reloads, refreshes the open window; toast *Back on the Unsent / Working board.*). The Archived window's own un-archive is unchanged. The archive toast now reads *Archived. Put it back from this window, or from Bid Board → Archived.*
- Three render cases on the footer smoke; the Bid Board guide says where the button is, when it is grey, and that a dead sent bid is marked Lost, not archived.

## The "is this the best we can do" pass — what changed from the first draft

1. Every reason ends with a door (mark it Lost / who can / when it left) instead of restating the grey.
2. An archived bid flips to *Put back on board* rather than a grey button whose toast points at Bid Board → Archived.
3. The reason is also the hover title, so a desktop user reads it before pressing; the phone user presses and gets the toast — same words, one source.
4. `aria-disabled`, not `disabled`, so the press can be told why.
5. The rule itself does not change: who may archive, and which bids qualify, stay as they were — only the silence goes.

## Not run live / left as is

- The Won / Lost / Started reason was walked in the kernel tests only; the live walk covered a sent bid (grey + toast), an unsent bid (confirm → Archived → Put back on board) and the archived → back round trip.
- Names of the estimator and account man are not spoken in the ownership reason (the bid carries ids, not names, in the form); "Ask them, or a dev" stands.
