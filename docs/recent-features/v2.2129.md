# v2.2129 — Roadmap Plan: the "Next up" shortlist — pick, don't sort (2026-08-22)

Owner asked for a "smart sort" on the Roadmap and worried it would fight the arrows and the stage numbers. Proposal (artifact *Pick, Don't Sort*, variant A picked): leave the order alone — numbers are identity + priority, arrows decide eligibility only — and add one small explained panel.

- **Kernel** [`src/lib/roadmapNextUp.ts`](../../src/lib/roadmapNextUp.ts) (`nextUpPicks`, `nextUpReasonLabel`, +8 tests): eligible = open task in an unlocked, incomplete stage. Lexicographic order, no weights: **closes a stage** (≤ `CLOSES_STAGE_LEFT` = 2 tasks left, fewest first — the same threshold as the chip, so the first sort key is the first reason) → **unlocks the most** (open tasks, then stages, transitively behind the stage's arrows) → **your stage order** → task order. Two lanes — *Ready to go* (has an assignee) / *Needs a name* — at most 5 each and at most 2 per stage per lane (`perStageCap`), plus `openReady`/`openNeedsName` counts. Typed reasons per pick in display order: `closes_stage`, `unlocks` (feeds title + counts), `priority` (stage ≤ 3), `first_step` (stage has no completions and this is its first open task), `in_motion` (a completion in the stage in the last 14 days). Raw "tasks left" is deliberately not a sort key beyond the threshold (it would let a small no-consequence stage beat a big stage that unlocks four and leave "unlocks the most" deciding nothing).
- **Panel** [`ChecklistRoadmapNextUpPanel`](../../src/components/checklist/ChecklistRoadmapNextUpPanel.tsx), rendered by `ChecklistRoadmapPlanView` between the header stats and the Now list; hidden while a focus lens is up (the lens is already a worklist); renders nothing when no task is eligible. Rows: task number (first row amber-ringed), title, assignee chips (ready lane), up to two amber reason chips, "Assign →" (needs-a-name lane); tapping a row opens the task card (staffing happens there — no new picker). "why this order?" toggles the rule in a sentence; a dashed footer repeats it in one line. Theme tokens throughout (`--bg-amber-100` / `--border-amber` / `--text-amber-800` from v2.1999).
- Nothing below the panel is re-ordered; Map and Timeline are untouched. No migration.
- Help: new `see-what-to-do-next-on-a-roadmap.md`; `staff-and-discuss-roadmap-tasks.md` points at the Needs-a-name lane.
