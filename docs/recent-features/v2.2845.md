# v2.2845 — Customer portal: bills stack as cards on a phone; PAY ONLINE never starts off-screen (2026-09-05)

Journey map Tier-1 #12 (J21-F2 = J22-F2, customer-portal-visit / customer-pays-online). At a true 375 px viewport the portal ledger pinned `min-width: 560` inside a 343 px scroll container with no scroll affordance: all seven PAY ONLINE buttons in the sample sat at x = 467–576 and every amount-due cell at x = 389–449 — fully off-screen, the page body itself not scrolling sideways. The customer saw date + address columns and no way to pay. Print already exempted the min-width (`min-width:0 !important`), which proved the grid collapses safely.

- **CSS-only, same markup** (`src/pages/CustomerPortal.tsx`): the ledger's grid (`84px 1fr auto auto`), the scroll wrapper's `overflow-x`, row padding/border, and the pay button's padding moved from inline styles into the statement's existing `<style>` block, keyed on data attributes (`data-portal-ledger`, `data-portal-ledger-head`, `data-portal-bill` + `data-last`, `data-bill-age` / `-note` / `-amount` / `-pay` / `-check`). The inline `minWidth: 560` is gone; the stylesheet sets `min-width:560px` on screen ≥ 560 px.
- **`@media screen and (max-width:559px)`**: the scroll wrapper goes `overflow-x:visible`, the ledger `min-width:0`, the column-header row hides, and each bill row becomes a single-column card (`CARD` surface, `HAIR` border): line 1 date · age (the `<br>` hides, a `·` separator is injected), line 2 the "billed $X" note when present (`:empty` hides it), line 3 the amount at 18 px right-aligned, line 4 PAY ONLINE as `display:block` full-width (or the check · ref chip start-aligned). Job band, recap box (`min(320px,100%)`), and the closing Total due row already fit 343 px unchanged.
- **Print untouched**: the query is `screen`-scoped so paper never matches it; the existing `@media print` block still forces `overflow:visible` / `min-width:0 !important` and produces the ruled grid one job per page.
- **Sub portal**: `SubPortal.tsx` has its own `<table>` ledger inside a separate `overflowX:auto` wrapper and shares only `portalTheme.ts` — no shared ledger component, so this change is customer-portal only (the sub-portal table is `width:100%` and not pinned).
- **Telemetry follow-up**: `portal_pay_online_clicked{viewport}` was scoped but not added. The portal is no-login; the only existing public event path is the `public_page_views` insert inside the `customer-portal` edge function (service-role client — the table has a SELECT policy only, no anon INSERT). A click beacon needs either an edge-fn `?event=` branch (that function is being changed by the sibling `journey-phase4-portal-bills` PR) or a new anon-writable path (migration) — neither is cheap or in this PR's lane. Track alongside #37 (view counter).
- **Test**: `CustomerPortal.render.test.tsx` gained a phone-layout smoke — jsdom has no layout, so it asserts the markup branch: no inline `min-width` on the ledger, `data-portal-bill` rows without inline grid columns, the pay/check/amount hooks present, `data-last` on the final row, and the stylesheet carrying the screen-only restack plus the print exemption.
- **Visual verify recipe**: `/portal?t=sample` at 375 px after deploy — no horizontal scroll anywhere, every PAY ONLINE and every amount visible in one vertical read; desktop grid unchanged at ≥ 560 px; print preview unchanged. Also re-check the office "Preview as customer" iframe (it renders the same page and is narrower than 560 px — it now shows the cards).
