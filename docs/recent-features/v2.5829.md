# v2.5829 — Quickfill checklists: a box keeps its ticks when it is reworded or removed (2026-10-24)

Found while walking punch list #156's Mark history window ([v2.5819](v2.5819.md)): Office Arriving's lights and mopping boxes had no ticks before Oct 23, while the station's marks recorded every box done on most days. Their past had been deleted. Proposed as a follow-up card the same afternoon; the owner said *"Do this task here."*

- **The cause**: a checklist's boxes live as JSON `[{ id, label }]` in `app_settings` and their ticks are rows keyed on the box's id. *Edit checklist* had Add, Remove and drag to reorder, but no way to change a box's words, so rewording meant Remove then Add, and a new box gets a fresh `crypto.randomUUID()`. Remove also deleted every tick row for the box (`onRemoveItem` deleted from `quickfill_office_arriving_daily_checks` / `quickfill_assistant_dailys_daily_checks` by `item_id` alone, with no `work_date`). One reword wiped a box's whole history.
- **Remove keeps the rows** (`QuickfillOfficeSection.tsx`, `QuickfillAssistantDailysSection.tsx`): it saves the list without the box and touches no tick row. A removed box's rows are read by nothing: the stations read today's rows of the boxes on the list, and the Mark history band lists the boxes on the list. Unticking a box still deletes that day's row, as before.
- **Rename** (new, beside Remove in *Edit checklist*, dev only): the box's words become a text box with **Save** and **Cancel** (`QuickfillChecklistRenameField`, shared by both sections). Save stays grey until the words change; Enter saves and Escape cancels. The save is the same `app_settings` upsert the list always used, through the new pure `renameChecklistItem` in `lib/quickfill/checklistItems.ts`: the same id, the same place, the new words. Office Leaving's boxes get it too; they keep no tick rows, but a rename there no longer loses the box's done state for the day.
- **Difficult people is left as it was**: its rows already change in place (**Edit**, an `update` by id), and **Delete** is a confirmed end of a follow-up whose daily ticks go with it by the table's cascading foreign key. Keeping those would take a migration for a list of one item.
- **History lost before today stays lost**: nothing audits `app_settings`, and the rows are gone. The Mark history band's first-tick rule ([v2.5817](v2.5817.md)) keeps counting each box from its first tick on record; the comments in `markHistory.ts` and the window, the Glossary's *Quickfill (page)* entry, `docs/QUICKFILL_ARCHITECTURE.md` and the to-do now say so.
- **Tests**: `checklistItems.test.ts` (3); `QuickfillChecklistEdits.render.test.tsx` (6, each section: Remove saves the shorter list and deletes no tick row, Rename saves the same id in the same place with the new words, Escape saves nothing). All six fail against the two sections as they were on main and pass after.
