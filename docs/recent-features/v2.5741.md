# v2.5741 — Settings: retire a robot from the fleet (2026-10-22)

The owner, looking at three twins on Settings → System → Digital twins & samples: "Is it worth us deleting or archiving any of these robots? I want to reduce clutter." The page had no door: archiving went through People → Users, and even then the fleet card kept the row, because a dev's `users` read includes archived rows.

- **Archive** (`src/components/settings/DigitalTwinsPanel.tsx`): a muted text button at the end of each live row's action line, after *Set up on this Mac*. It confirms first (*Archive Twin Estimator 2?* — what goes, what stays, that Restore brings it back; the cancel is the safe answer), revokes the twin's live keys (`twin_credentials.revoked_at`, so no Mac or harness keeps running it), then calls `archive-user` as People → Users does (bans the sign-in, stamps `archived_at`). Runs, shadows and bids stay. Never a hard delete: `delete-user` was removed for its cascade.
- **The fold** (`TwinArchivedFold.tsx`): one muted line under the fleet, *1 archived*, that opens to the rows with when each was archived and a **Restore** (`restore-user`, confirmed). Nothing shows while no twin is archived. The fleet's count and rows are the live twins; seat numbers for the next mint still count archived twins, so an archived seat's email is never reused.
- **Kernel** `src/lib/twins/fleetArchive.ts` (tested, plain words checked): `splitFleet`, `liveKeysOf`, the two confirms, the `archive-user` body, the fold's and rows' words, the toasts. Render smoke `TwinArchivedFold.render.test.tsx`.
- **Docs**: `docs/twins/HANDOFF.md` (day-to-day operation), `GLOSSARY.md` → Digital twin, the guide *run the robots from Claude Desktop* (retire a robot).
