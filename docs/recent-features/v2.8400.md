# v2.8400 — Permits: the nightly pull keeps where each reading started (2026-11-23)

Punch list #405 (`to-dos/permits-market-page/README.md`), the open question the overnight look of 2026-11-23 left after v2.8328. Migration only: [`20261123192240_permit_pulls_issued_reading.sql`](../migrations/20261123192240_permit_pulls_issued_reading.md). The function that reads it is v2.8402, its own PR.

## Why

San Antonio's applications are read twice a night: by filing day, then by issued day. v2.8328 starts the second reading 30 days before the newest issued day held, worked out before either reading writes. Its start is still counted from a day the first reading moves, since the first reading writes issued days too. If the second reading alone failed night after night for over 30 days, its start would walk past the permits issued while it was down, and they would read as waiting for ever.

## What changed

- `permit_pulls.issued_since` (date): the run's second reading's start, on a feed read twice.
- `permit_pulls.issued_whole` (boolean): whether that reading read to its end.
- Both nullable, both added `IF NOT EXISTS` after `SET lock_timeout = '3s'`. No table is created, so the four fence calls are not needed.
