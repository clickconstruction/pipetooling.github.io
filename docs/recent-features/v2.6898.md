# v2.6898 — Add Part says when the part is already in the book (2026-11-10)

Punch list #308, PR 1 of nine. The estimator asked for a tool that reads a supply house's price sheet and never makes a second copy of a part. The parts book knows a part by its name alone, and each house writes the name its own way, so a part the search misses gets made again. This PR is the matcher by itself, on the form where a duplicate is born. No table, no migration and no reader.

## What changed

- **`src/lib/materials/partMatch.ts`** (pure), the matcher every later PR calls:
  - `foldCode`, `modelNumbersIn`, `joinedModelNumbersIn`: a model number read out of a name with its dashes and spaces folded away. A size or a rating is never one (`4INX3IN`, `1-1/2XCL`, `SCH40`, `60A/3P`, `120/277V`, `10KAIC`).
  - `sizesIn`, `sizesAgree`: every size in a name as a number, so `1-1/2`, `1 1/2` and `11/2` are one size. Strict for the words, loose for a model number, where a bare number may leave the sizes out.
  - `wordsOf`, `sameWords`: the same words in any order, one spelling each (`TEE` and `T`, `CHROME PLATED` and `CP`), one slip allowed in a long word. A word more or less is another part.
  - `matchRow(row, book, codes)`: the house's own number, then the model number, then the same name, then the words. A level with two parts returns both as rivals and picks neither. `codes` is empty until PR 2.
  - `alreadyInBook(name, book)`: the form's warning. `sameModelGroups(parts)`: the Duplicates page's group, for PR 9.
- **`src/components/PartFormModal.tsx`**: in add mode the typed name is checked 200 ms behind the keys. A match draws *Already in the book, by its model number* (or *by its name*, or *says the same words*) with the part and **Use that part**, which reads the part on file and hands it to `onSave` exactly as a save would, so Takeoffs drops it into the picker that opened the form. **Mine is different** puts the strip away until the name finds other parts. Robot parts are left out. The check is a help and never a gate: with no book to read the form saves as before.
- **`src/components/bids/BidsTakeoffTab.tsx`** passes the catalog it already holds as `knownParts`. The Parts Book passes nothing, so the form reads the names itself (`id, name, manufacturer, is_robot`) when it opens.
- The guide `add-a-part-and-its-prices-fast` gains *When the part is already in the book*.

## Why the words are matched word for word

The first draft offered a name within 80% of another by letters, as the Duplicates page's near mode does. Run over the real book (read only), it paired 381 parts, and nearly all were different parts a few letters apart: black and galvanized nipples, PVC and PEX, a tee and a wye, male and female adapters. Matching word for word left 40, almost all true copies (`TEE` and `T`, the same words in another order). The same run found 41 groups by model number, nearly all true. Closeness by letters is not used anywhere in the matcher.

## Tests

## Not in this PR

The Duplicates page still uses its own near mode and can only delete; the group by model number and the merge are PR 9. The parts search still matches a substring, so a model number finds its part only when typed as saved.
