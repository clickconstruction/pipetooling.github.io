# v2.5771 — Needs you on Quickfill: every office line the Dashboard shows, with the same buttons (2026-10-23)

Punch list #146, PR 1 of 5 (`to-dos/needs-you-in-quickfill/`). The owner, looking at the Dashboard's Needs you card (30 lines on 2026-10-23): some of these should be workable in Quickfill by an assistant, and are not. The finding: `buildNeedsYouItems` had two hosts that each wired their own hooks, and since v2.2350 the Dashboard host had gained 30 sources the Quickfill host never passed — two carried by Quickfill's own stations, four turned off by a comment, 24 never wired. Nine lines on that day's card were office work an assistant can do and never reached the page the office works from. The fix is structural, so it cannot recur.

- **The gates, one home** ([`needsYouSources.ts`](../../src/lib/needsYouSources.ts)): `NEEDS_YOU_SOURCES` (42 sources), `needsYouSourceEnabled(source, role, host)` with the Dashboard host's role gates of v2.5759 moved in verbatim, `QUICKFILL_CARRIED_BY_STATION` (`jobFollowups` → the Job follow-ups station, `gcReview` → GC weekly review) and `QUICKFILL_HELD_BACK` (`robotAudits`, `d22`, `submittals`, each with its reason). [`needsYouSources.test.ts`](../../src/lib/needsYouSources.test.ts) holds the parity rule: for every office role, a source the Dashboard reads, Quickfill reads, or this file names the station or the reason. The robot-blocked line (`robotBlocked`) got its own gate so it reaches Quickfill while the audits stay back.
- **The hooks, one hook** ([`useNeedsYouInputs.ts`](../../src/hooks/useNeedsYouInputs.ts)): every source's hook called once per host under its gate, the `NeedsYouInputs` built, the items ranked, plus `doorData` (the first row of each pile, for the landings) and `handles` (the windows' queues and refetches, the nudges' snooze and dismiss). The Dashboard's `hideBanners` is the hook's `enabled: false`; Quickfill passes `dispatchAgedEnabled` from whether the page gave it a Dispatch inbox opener.
- **The doors, one table** ([`needsYouDoors.ts`](../../src/lib/needsYouDoors.ts)): `needsYouDoor(item, data, host)` answers for every key `NEEDS_YOU_RANK` knows (an exhaustive `switch`, so a new key with no door is a compile error) with an `href`, a `window` (the five in-place windows), a `test-report` (the modal with the first draft) or a `station` (the Dispatch inbox, and on Quickfill the People Hours station for the clock sessions, the owner's call 1). `needsYouSecondaryDoor` does the same for snooze, dismiss and the Lien desk's two links. [`needsYouDoors.test.ts`](../../src/lib/needsYouDoors.test.ts) walks every key on both hosts. `DASHBOARD_SECTIONS_ARCHITECTURE.md` had asked for exactly this table since the builder's map.
- **The press, one hook** ([`useNeedsYouPress.tsx`](../../src/components/needsYou/useNeedsYouPress.tsx)): takes a door where it goes, mounts the five windows (Match deposits, the team's purchases, the unconditional releases, the waivers to sign, Today's sends) and hands a `station` to the host, which expands it on Quickfill or scrolls to the Teams Inbox card on the Dashboard and navigates to the door's fallback when it cannot.
- **The hosts**: [`DashboardPinnedQuickRow.tsx`](../../src/components/dashboard/DashboardPinnedQuickRow.tsx) lost ~330 lines of hooks and its 170-line `if / else if` chain and kept the Day book's queue snapshot; [`QuickfillNeedsYouSection.tsx`](../../src/components/quickfill/QuickfillNeedsYouSection.tsx) is 70 lines and gained `onOpenPeopleHours`, which [`Quickfill.tsx`](../../src/pages/Quickfill.tsx) wires to `openSectionNow('people-hours-new')` beside the dispatch opener. Quickfill's station now also mounts the waivers-to-sign window (the leader) and Today's sends, and opens a test report in the modal.
- **What changes on screen**: for the office set, Quickfill → Needs you gains `returned-check`, `contract-missing`, `contract-stale`, `job-account-missing`, `test-reports-ready`, `gc-follow-up`, `customer-messages`, `todays-sends`, `robot-blocked`, `statement-round`, `hours-approvals`, `typed-hours`, and the rest of the Dashboard's office lines when they have something (`jobs-stale-open`, `capacity-under`, `work-orders-unpriced`, `legal-firm-activity`, `price-matrix-ready`, `price-requests-late`, `bid-followups`, `paid-claims-stale`, `bulk-hours`, `contract-clauses`, `lien-waivers-to-sign` for the leader). The Dashboard is unchanged line for line. Quickfill reads more on load, as the Dashboard already did.
- **Tests**: the two kernel files above; [`QuickfillNeedsYouSection.officeLines.render.test.tsx`](../../src/components/quickfill/QuickfillNeedsYouSection.officeLines.render.test.tsx) (an assistant draws the contract lines and the clock sessions with the hooks' numbers, the held-back and station-carried flags stay false, Start the sweep navigates, the clock sessions expand the station, an estimator is not asked); the ten existing smokes on both hosts pass unchanged.
- **Guide**: *work the Needs you list on the dashboard* says Quickfill has the same buttons and names the People Hours station.
- **Docs**: `DASHBOARD_SECTIONS_ARCHITECTURE.md` (the Needs You card's hooks and the doors table), `QUICKFILL_ARCHITECTURE.md` (the `needs-you` station), the to-do's status.

## Is this the best we can do?

- The list of nine was the symptom. Adding nine hooks to the Quickfill host would have fixed the day and left the next line to drift. A gate table, one hook and one door table fix the cause, and two tests keep it fixed: the parity test fails the moment a source is added to one host's gate and not the other's without a named reason; the door test fails to compile the moment a key has no door.
- Nothing moved that did not have to: the role gates are the Dashboard's, word for word; the doors are the Dashboard's chain, row for row; the Dashboard's render smokes pass with no edits.
- Not verified live as the sample assistant yet; PR 2's live walk covers both.
