# v2.4498 — AIA G702-G703: more than one line on the continuation sheet (2026-10-04)

The first half of *lines from the bid's schedule of values* (the owner, 2026-10-04, on the four calls: *"I agree with all four, build it"* — mockup https://claude.ai/artifact/3weysQUHxAxfVhv3yB4WJo). This PR makes an application carry lines and the sheet print a row per line; seeding them from the bid, the crew's percents and the scale-to-price offer are the next PR. One migration (`20261004180722_job_pay_applications_lines.sql`, two columns), no edge function.

## What was there

An application had one line, typed into five form fields (`g703_c13_description`, `g703_d13_scheduled_value`, `g703_e13_from_previous`, `g703_f13_this_period`, `g703_g13_materials_stored`), written to row 13 of the G703. Rows 14–46 were never filled.

## The change

- **Kernel** [`aiaPayApplicationLines.ts`](../../src/lib/aiaPayApplicationLines.ts) (new): `PayApplicationLine` (`id`, `label`, `scheduledValue`, `labor`, `stage`, `fromPrevious`, `thisPeriod`, `stored`); `parsePayApplicationLines` (what came back from the database is not trusted to be lines); `linesOfApplication` (the saved list, or the one line the form fields held — never empty) with `legacyLineFromFields` / `legacyFieldsFromLine`; `lineMath` (the sheet's row); `linePercentDone` / `thisPeriodForPercent`; `carryForwardLines` / `carriedWorkByLineId`; `printRowsOf(lines, split)` (a line as one row, or a labor and a material row that add back to it to the cent, stored material on the material row). `AIA_G703_MAX_ROWS` is 34: the sheet numbers items 001–034 on rows 13–46.
- **Fields.** The five line keys leave `AIA_FIELD_DEFS` / `AiaFieldKey`; `buildAiaPrefillLinesFromJob(job)` gives a job its one starting line (the whole contract, the job's value created offered as this period).
- **Math** [`aiaG702G703Preview.ts`](../../src/lib/aiaG702G703Preview.ts): `buildAiaPreview(values, lines, { splitLaborMaterial })` works `math.rows` (a printed row each) and `math.line` (the totals row the G702 reads).
- **Fill** [`fillAiaG702G703Workbook.ts`](../../src/lib/fillAiaG702G703Workbook.ts): `writeLines` writes C–G on every item row (a row with no line as blank and zeros, so the template job's first row never survives), `stampFormulaResults` stamps H–K on all 34 rows and the totals, and more printed rows than the sheet holds throws `AiaTooManyRows` — nothing is written, since a download that dropped lines would ask for the wrong amount.
- **Applications** [`aiaPayApplications.ts`](../../src/lib/aiaPayApplications.ts): `PayApplicationForm` (`values`, `lines`, `splitLaborMaterial`) is what the kernel takes and returns. A save writes `lines` and `split_labor_material`, and for a one-line application also the legacy keys in `fields`. `carryForwardPayApplication` carries every line (work to date → previous work, stored stays); the value-created offer applies to a one-line application only. `carryMismatch` compares each line's previous work by id (a line the earlier one has and this one lacks, and the reverse, are differences) before the G702's three amounts.
- **IO** [`aiaPayApplicationsIo.ts`](../../src/lib/aiaPayApplicationsIo.ts): three column sets, newest first; an unknown column (`42703` on a select, `PGRST204` on a write) falls to the next; a write that would lose lines throws `PayApplicationLinesNotReady`.
- **Window**: **LINES** at the bottom of the form — a card per line (description, scheduled value, from previous application, % done to date, work this period, materials stored), **Add a line**, **Remove**, the rows used of 34, and an amber line when there are too many. The percent box and the dollars box drive each other. The *Labor and material on their own rows* switch shows only when a line carries a split (none does until lines come from a bid).
- **Paper**: the G703 draws a row per printed row; its boxes put the cursor in that line's field.
