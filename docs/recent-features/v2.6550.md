# v2.6550 — End employment and Bring back move the row on the roster behind the desk, and the Wage row reads the wage you typed (2026-11-05)

The owner's sabbatical dry run of 2026-11-05 on the ZZ Test Hand helper, the first use of punch list #256's two windows end to end on prod. Both windows wrote what they said; two things behind them did not follow. The roster and the Archived list under the desk kept the old row until a page reload, so the Archived list still offered **Bring back…** on a person already back, and the Bring back window's Wage row kept reading *No pay setup* after **Save wage** on a person with no pay row, under a green dot.

## What changed

- `src/components/people/PeopleUsersTab.tsx`: the tab reads the desk's `changeKey` (`useOptionalPersonDesk`), which `PersonDeskDrawer` bumps through `markChanged` after every desk write, and on each bump reloads the archived logins and calls `reloadRoster`. `src/pages/People.tsx` makes `reloadRoster` reload the archived roster rows (`loadArchivedPeople`) beside the roster (`loadPeople`), so a roster-only person's End employment moves their row too. The key starts at 0 and the effect skips it, so an opened desk alone reloads nothing.
- `src/lib/people/bringBack.ts`: `withWageChange(facts, wage, backYmd)` folds the typed wage into the facts the checklist reads, making a pay row in the words when there is none and keeping a salaried row salaried; the window (`PersonDeskBringBackModal`) calls it in place of the inline fold that skipped a null pay row.
