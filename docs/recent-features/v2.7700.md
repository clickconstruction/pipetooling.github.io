## Why functions and not policies

The tables' writes are the office's alone. Giving the crew an insert or update policy would let a phone write any day, for anyone, on any trip it could name. A function writes one row, the caller's, for one day, today, after one question: is the caller working this job.

## The gap this closes for the dev seat

`trip_save`'s dry run now names the stamp of the trip it would replace, so a trip changed in the app between `plan_trip` and `apply_trip` refuses the apply. It needs no change to the seat: the seat hashes the whole reply.
