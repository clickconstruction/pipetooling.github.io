# v2.5268 — Messages: a text sent from Quo’s own app lands in the thread too, behind the scenes (2026-10-12)

The Messages build's cut 5, a follow-up to v2.5261 (`src/lib/quo/events.ts`), by helper 3, directed by the GC Review lead. It settles the `message.delivered` question as v2.5266's notes set out. Pure kernels and their tests over made-up deliveries. No screen, no table, no edge function, nothing to deploy.

- **Three more events**: `readQuoEvent` reads `message.delivered`, `message.failed` and `message.undelivered` into a `sent` reading. It carries the message id, the numbers it went to, the Quo user who sent it, the words, the media and the code Quo passed on a failure. Quo's webhooks page calls `message.delivered` a "Text message sent from workspace and successfully delivered", so a text from Quo's own phone app comes back this way.
- **One line a person**: a text keys its line by the message id (`sentKey`). A group text from Quo's app is one line per number, keyed by the id and the number, since `messages.quo_id` is unique. The webhook makes one plan per number (`QuoPlanContext.recipient`).
- **Fill only, our send winning**:
  - With no line under the key, the event writes the whole line (`mergeSent`). That covers a text from Quo's app, named for its sender's seat or "Quo’s app", and also ours when the event beats our write.
  - With a line there, the event only fills the ending and the media.
  - Our send (`sendOver` in `send.ts`) writes who, the words, the time, the job and the opt-out line over whatever the event wrote, and keeps the event's ending and media.
  - The test runs the race both ways, delivered and failed, and gets the same line. I broke each side on purpose and the test caught both.
- **How it ended** (`delivery`): delivered over undelivered over failed, because once a carrier said delivered, the person has it. A failure says so once as a team event, such as "The text to Greg did not go out. Quo gave code 30007."
- **`QuoLine` gains** `optoutLine` and `delivery`. The cut 5 migration adds a `delivery` column beside `quo_id`, `recording_url`, `transcript`, `summary` and `duration_seconds`.
