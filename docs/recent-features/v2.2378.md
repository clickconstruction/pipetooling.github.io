# v2.2378 — Workbench solver zone: press-for-slider margin, coverage chip (2026-08-26)

Estimator feedback (Wendi): the solver zone wasn't "a very productive use of
space" — the coverage bar held a full-width row forever, and the margin
slider's inline track both ate a third of the solver line and stopped at 65%
(ALSATIAN sits at 78%; the thumb couldn't reach the bid's own margin).
Mockups offered two options; she picked Option A (chip + dropdown slider,
price-book row untouched — Option B's table toolbar deferred).

Changes (`BidsPricingTab.tsx`):

- **Margin slider behind a ▾** (`wbMarginSliderOpen` / `wbMarginPopRef`): the
  solver line keeps only the typed % box (behavior unchanged) plus a caret
  button; pressing it drops an absolutely-positioned popover with a long-track
  `range` — **min 20, max 95** (was 20–65) — that still runs the preview solve
  on mouseup/touchend. Click-away and Esc close it (same listener pattern as
  the Solve ▾ menu). The margin cluster shrinks from `flex: 1 1 240px` to
  `flex: 0 0 auto`.
- **Coverage chip** (`wbCoverageOpen`, localStorage
  `bidPricingCoverageOpen_v1`, default collapsed): a pill on the solver line
  after the Margin stat — `29/29 ✓` green when `pricedCount === costed.length`,
  amber with the unpriced-cost tooltip otherwise; hidden when no costed rows.
  The full-width coverage row (count + progress bar + "Show unpriced only")
  renders only while expanded — **or whenever `wbShowUnpricedOnly` is active**,
  so the "show all" escape can never be hidden by a collapsed chip.
- Tour step and help guide updated (slider-on-press wording, coverage-chip
  bullet).

No solver math or data changes — layout and control surfaces only.
