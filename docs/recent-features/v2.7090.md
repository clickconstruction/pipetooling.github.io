# v2.7090 — Pay codes print in PDFs again, and the bill's QR window can copy its image (2026-11-12)

Found while building punch list #333 (the demand letter with its pay code in the amount box): the code was on the page and missing from the PDF.

## The cause

A pay code is drawn as SVG markup for a page (`payQrSvgMarkup`), where the HTML parser supplies the SVG namespace. To become a PNG it is loaded into an `<img>` (`svgMarkupToPngDataUrl`), and there it is read as XML. The markup has no `xmlns`, so the browser refuses it and the function rejects with *svg did not load*. Every caller catches that and carries on without a picture.

So, in Chrome:

- **PDFs drew an empty square** where a code belongs: the pay page behind a § 53.056 notice (`payRow`, v2.3758), the code on a letter mailed through the provider (`qrLink`), and the demand letter's pay codes (v2.4849). The address printed beside the square was right.
- **The bill's QR window** (v2.3757): *Copy image* fell back to copying the address, and *Download PNG* said it could not build the image.
- The page on screen, the print window and the half-sheet were never affected: they draw the SVG itself.

## The fix

- `withSvgNamespace` (`payQr.ts`) puts the namespace on the root when it is missing, and `svgMarkupToPngDataUrl` loads the markup through it. Markup that has it is left alone.
- The four places a code's PNG goes into a PDF store it compressed (`'FAST'`, as the signature ink already is). A code is a few flat colours: uncompressed, a 480 px code is about 690 KB of the file, and compressed the whole sample letter is 30 KB.

Where a code has no picture (a paper bill, a browser that fails) the PDF still draws the empty square, the same size, so no layout moves.

## Checked

- The app's own functions, run in Chrome from the local dev server. Before: `payQrPngDataUrl` rejects, `buildPayPageAssets` returns no PNG. After: both return a PNG.
- A made-up lien paper with a pay row, a paper bill and a mailed letter's code, built to PDF in Chrome and read: both codes drawn with the mark in the middle, the paper bill's square empty, 34 KB.
- Not checked: the live site, a real notice's PDF, any mailed paper, Safari. No code was scanned from paper.

No migration, no edge function.

## Tests

`payQr.test.ts` (+1): the namespace goes on once and nothing else of the markup changes. `lienFilingDocuments.pdf.test.ts`: the code's picture is stored compressed.
