# v2.7640 — Signed contracts: the groundwork for filing each one in its job's Drive folder (2026-11-17)

Punch list #377, PR 1 of six: the rules. The owner settled the card's seven calls on 2026-11-17 and said to build the train. Nothing reads these rules yet, so no screen changes and nothing is filed.

## Why

A signed job contract lives in the app's own storage (`job-contract-documents`) and nowhere in Google Drive or the file index, so Documents → Search → Find a file cannot find it. The card files each signed paper in its job's folder. The filing function, the Contract sweep's Drive pass, the Contract window and Documents → Where files go all have to say the same thing about the same paper, so the rules come first, alone and tested.

## What changed

- **One kernel, `supabase/functions/_shared/jobContractDrive.ts`**, pure, with `src/lib/jobs/jobContractDrive.ts` as the app's door to it, the way `documents/folderName.ts` is the door to `whereFilesGo.ts`. It imports the company's calendar day and the Drive-safe name and nothing else.
- **Which file a record files** (`contractFileSource`). The scan when the record has one, else the signed PDF, else the link the office typed. A link that names a Drive file, a Google Doc included, is read as that file.
- **The name** (`contractDriveName`): the signed day in the company's zone, what the paper is, the job's number and who signed. *2026-11-14 Signed contract · 1042 · Dana Whitfield.pdf*. A warranty, a scan and a GC's own paper are named for what they are. A paper over several jobs says which jobs and ends on the customer. A voided copy takes `VOIDED · ` once.
- **The queue** (`contractDriveDue`). A signed, live paper with no Drive file is due. A hold that clears by itself is taken every run, and one that needs a person's file is taken hourly. A voided paper's copy is marked once, and only when the app made it.
- **Adoption** (`canAdoptLinkedFile`). A linked file is adopted only when the app sees a live file inside the jobs drive.
- **The holds**, eight kinds, each with its words and its door (`CONTRACT_HOLD_WORDS`, `contractHoldDoor`). The job's own folder hold and Drive's own refusal bring their own words.
- **The Contract window's line** (`contractDriveLine`) for each state: filed, adopted, waiting, held, voided.
- **The Where files go card's counts and press** (`contractDriveCounts`, `fileContractsWords`, `fileContractsOutcome`), through `batchWords`.
- **The Drive pass's filter** (`knownContractFileIds`, `withoutKnownContracts`), by Drive id and never by name. A file linked by hand on a record that was later voided may be offered again; the app's own copy of a voided paper may not.

## One change from the card

The card listed six new columns. The rules need the hold's kind apart from its words, since the kind decides the retry and the door, so there will be seven: `drive_file_hold` is the kind and `drive_file_hold_words` the words. The columns arrive with PR 2.
