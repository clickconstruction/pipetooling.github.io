# v2.7612 — Documents: the database can now list every agreement in one read (2026-11-17)

Punch list #376, PR 2 of five: the read. One migration, `20261117200000_agreements_on_file.sql`, its SQL bed, and the client read. No screen calls it yet. The detail of the view is in `docs/migrations/20261117200000_agreements_on_file.md`.

## What is new

- **`agreements_on_file`**: a `security_invoker` view over `job_contracts`, `person_contract_documents` and `step_commitments`, one shape for every kind: a common `state` (`waiting`, `signed`, `ended`), the paper's name, who it is with, the job, the day in the company's calendar, `facts` (the kind's own columns its words are made from, no money) and `find_text` for the find box.
- **`src/lib/documents/agreementsLedgerIo.ts`**: `readAgreements(query)` reads the view newest first, the kind and state chips as `in` filters and each typed word as an `ilike` on `find_text`, a page at a time, and throws with the database's own reason. `countAgreementsWaiting(kind)` is the count on the *Waiting on a signature* chip, null when it cannot be read.
- **The `agreements-on-file` SQL bed**: `scripts/pgtest-agreements-on-file.sh`, `supabase/tests/agreements_on_file/`, a line in `scripts/sql-beds.txt` and `npm run test:pg:agreements-on-file`.
- **`agreementsLedgerIo.test.ts`**: ten tests of the query each read builds, over a fake client.

## Choices worth knowing

- **Row security is the tables' own.** The view runs as its reader, so it opens nothing: the office reads every branch, an estimator work orders alone, a primary and a superintendent nothing. The bed asserts each.
- **Left joins.** A reader who may read a work order but not its job still gets the line, with the job blank. The bed proves it with a sub who is on no crew.
- **One line per filed paper.** A signed paper over several jobs is one row on the first job filed. Rows of a group that are voided stay apart from the live ones, so taking a paper off one job does not hide it on the rest.
- **The day is computed in the database.** `at_day` is the signed, sent or ended day in America/Chicago, so a paper signed at 10:30 PM reads the day it was signed here, and a date-only column (a person's `signed_at`, an offer's expiry) never slips a day.
- **`facts` leaves out what is empty and all money.** The line needs a state, never an amount.
- **The stamp moved once.** `20261117190000` was claimed by another session, so the file is `20261117200000`.
