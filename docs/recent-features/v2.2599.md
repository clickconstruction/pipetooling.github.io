# v2.2599 — Recent Reports for superintendents (2026-09-01)

The Dashboard **Recent Reports** section now renders for the `superintendent` role. The server side needed nothing: `list_reports_with_job_info()` has carried a full superintendent branch since the baseline (reports on projects the caller can access via `can_access_project_row`, jobs anchored to those projects or where they're a team member via `superintendent_report_job_anchor_allowed`, and accessible bids) — the client gate was the only thing hiding the section.

- New predicate `isDashboardRecentReportsRole()` in `src/lib/dashboardRecentReports.ts` (+ tests) replaces the four inline copies of the role list: the `showRecent` derivation in `src/pages/Dashboard.tsx` (also feeds the SectionDock entry) and the three copies inside `DashboardRecentReportsSection.tsx` (loader gate, realtime-channel enable, render gate).
- Superintendents get the same treatment as office roles for auto-expand-on-unread and per-row Job Detail links (they hold Jobs access). `canManageReportEmails` (the email-settings gear) still excludes them, matching primary.
- First step of the superintendent visibility stack (Crew Day section + `crew_day` email stream follow separately).
