# v2.3477 — Price requests: the link box is labeled as the quote link (2026-09-15)

Client only — no migration, no edge function. Owner, from the Edit Bid window: "is this where a quote goes? Says 'link to the request' — it should become 'the link to the quote received from supply house'." Option A of the mock-up (relabel the existing box; the value keeps saving to `bid_rfqs.request_url`) was approved over option B (a second, quote-only box bound to `quote_url`). Live before/after on BP398, nothing saved.

Context: v2.3195 had trimmed this table to house · date · request link and dropped the Quote column after a price was typed into the quote box. This PR changes the *wording* of the remaining link box, not the columns or the field it writes.

## What shipped

- **[`BidPriceRequestsTable`](../../src/components/bids/BidPriceRequestsTable.tsx)**: column header **Request link → Quote link**; the editor's URL input `aria-label` matches; the hint under it reads "the link to the quote received from the supply house — a Drive copy, a PDF". The input is still `type="url"`, still bound to `draft.requestUrl`, still saved through `validateOutsideRequest`.
- **[`bidPriceRequests.ts`](../../src/lib/bids/bidPriceRequests.ts)**: the validator's user-facing error prefix for that box is now `Quote link:` so the inline error names the box the way the header does.

## Docs

- Guide *get supply house prices on a bid* → "Requests you sent yourself": the sentence now says to paste the link to the quote you received; pricing the quote still happens on Pricing.

## Not changed

- App-sent rows still show their **Vendor page** link in the same column. `quote_url` is untouched; the Pricing desk keeps reading it.
