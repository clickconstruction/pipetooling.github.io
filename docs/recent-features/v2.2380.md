# v2.2380 — Workbench round 2: live-drag solving, breakdown jump chips, quieter copy (2026-08-27)

Owner requests batched right after v2.2379 shipped (mockup extended on the
same prototype artifact, approved in advance). All in
`src/components/bids/BidsPricingTab.tsx`:

- **Slider solves live**: the 20–95 popover slider re-runs the margin solve
  on every `change` step (no more solve-on-release; `onMouseUp`/`onTouchEnd`
  handlers removed). `runWorkbenchSolve` gained `opts.marginPct` because the
  same-tick call would otherwise read the stale `wbMarginPct` state. The
  track carries **markup reference ticks** — 2 at 50%, 3 at 66%, 4 at 75%,
  5 at 80% (hover explains: "3× markup = 66% margin").
- **Margin breakdown modal**: type scale down a notch (title 1.125→1rem,
  table 0.875→0.8125rem, margin band 1.375→1.1rem, tighter padding) and a
  row of **jump chips** — `# Counts`, `📐 Takeoffs`, `🛠 Labor` — that close
  the modal and call `onNavigateBidToTab` (prop union widened to include
  `'counts'`; the `Bids.tsx` call site already routes any tab through
  `selectBidAndSyncUrl`).
- **No-cost banner**: renders only while a solve is pending
  (`wbPreview && previewCount + vetoCount > 0`) and reads
  "23/39 have no cost: their $26,156.17 is unaffected" (was the always-on
  "23 of 39 rows have no Takeoffs cost — their $… keeps the prices you set
  and stacks on top of the solve").
- **Copy**: preview line "N drafts — saved only when you Apply" (was
  "N solver prices previewed — … · waits on this device"; the clicked-off
  suffix stays); landing chip "→ bid is $62,191 · 83%" (was "lands at …
  83% blended").

Verified live on the dev server (SAISD bid): ghosts and totals track the
slider mid-drag with no release event; ticks render with hover titles;
banner absent until a solve exists, then shows the new copy; breakdown
chips navigate to `?tab=takeoffs` with the bid selected.
