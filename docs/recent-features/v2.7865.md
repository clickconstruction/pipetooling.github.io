# v2.7865 — Pay: the app's job costs read a salaried person's own week (2026-11-18)

The app half of the cost step of a per-person salaried week. The database half is v2.7840. The owner asked on 2026-11-18. No screen changes.

## Why

A salaried day was costed as 8 hours on a weekday, and the rule was written out by hand in six places in the app. Three of them were copies inside one file. With payroll reading the person's week (v2.7829), each of these would have costed a 6-hour person at 8.

## What ships

Each reader asks the shared rule in `src/lib/salariedEffectiveHours.ts` for the day's hours in the person's week:

| Reader | Where | Where its week comes from |
|---|---|---|
| Labor on a job | `src/utils/teamLabor.ts`, three places, now one `laborDayHours` | `list_people_pay_flags`, which returns the week since v2.7840 |
| Labor on a site | `crewDayHours` in `src/lib/developments/siteLabor.ts` | The same pay map |
| The team board's weekly target | `src/lib/teamBoard.ts` | `list_people_pay_flags`, through `fetchTeamBoardWeek` |
| The Bridge's flat day | `src/lib/bridge/vectorDays.ts` | The pay row, read in `loadBridgeVectors` onto `VectorWage.week` |
| Unallocated field time | `src/lib/peopleHoursUnallocatedRows.ts` | The pay config it is handed |
| The pay-report year calendar | `PeoplePayStubsTab.tsx` | The pay config on the page |

`LaborPayConfig` in `teamLabor.ts` is the one type for a person's pay as the labor readers need it. The edge copies under `gcKernels` are regenerated.

Left as it was on purpose: the view of an old pay report that has no day rows keeps the flat 8, since it must show what was paid.

## What does not change

Every pay row reads 8 hours on the five weekdays, so every reader answers what it answered before. The existing tests pass unchanged, apart from one new line each.

## Tests

One new case per reader, with a week that has a shorter day and a Saturday. Each was broken on purpose: with the reader put back to the default week, its own new test fails, and all pass with the readers restored.

## Order

Needs `list_people_pay_flags` to return the week (`20261118190000` on prod) and the column itself (`20261118160000`). A reader that meets an older function answer reads no week and costs the default, 8 hours on a weekday.
