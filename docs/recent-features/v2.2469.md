# v2.2469 — Remainder-bundle bills compose from uncovered segments (2026-08-28)

Closes the last honest gap from the job-978 arc (v2.2446/2464/2467): billing the elastic
PRIMARY remainder bundle ("auto") directly still listed every job line item prorated — bill the
$1,650 auto on a job whose $1,980 change order was already on its own invoice and the customer
saw "CHANGE ORDER $900 + HVAC $750".

**The rule (one cents-exact equality, both sides).** An invoice with linked fixtures bills
exactly those (v2.1133, unchanged). With no links, an invoice flagged `is_primary_rtb_bundle`
now bills the **still-unlinked billable segments at their real prices — but only when their
per-row cents sum EXACTLY to the target amount**. The equality is the whole safety argument:
the ensure RPC maintains primary = gross − payments − other invoices, so the unlinked-segment
sum equals the primary's amount precisely when nothing else (a payment, an unlinked dollar
carve, riders, `extra_line_items`) has taken an unattributable bite — every case where naming
whole segments would lie breaks the equality and falls back to the historical whole-job
proration. No new data is fetched; the check runs on fixtures + the invoice row alone.

**Where it lives.**
- Edge (authoritative for Stripe): `scopeFixturesToInvoice` in
  `supabase/functions/_shared/stripeInvoiceItemsFromFixtures.ts` gains an optional
  `{isPrimaryRtbBundle, targetAmountCents}` arg; `create-stripe-invoice` and
  `preview-stripe-invoice` add `is_primary_rtb_bundle` to their invoice selects and pass
  `fixtureTargetCents` (amount − extras; the preview's scoping call moved below the extras math
  so both functions match the same target). Per-row cents use the same `max(1, round(qty×unit×100))`
  as `lineExtendedCents`, so a composed set always takes the exact-sum path in
  `buildStripeInvoiceItemsFromFixtures` — no proration, no drift patch.
- Client mirror: `fixturesForInvoiceBill` (`src/lib/invoiceScopedFixtures.ts`, kernel-tested)
  gains an optional invoice context `{is_primary_rtb_bundle, amount}` with byte-identical row
  math; threaded from `SendRecordInvoiceModal`'s `billScopedFixtures` (kind:'invoice' passes the
  payload row; kind:'job' passes the ensured primary) and
  `buildPhysicalInvoiceDetailFromJob` (looks the row up itself) — previews, line-edit refs, and
  physical PDFs stay aligned with what Stripe renders.
- Unchanged: `stripeFixtureMultiLineAvailable` availability checks (whole-list check remains
  correct — a composed subset produces fixture lines, and so does the proration fallback).

**Deploy:** client via Pages on merge; then `supabase functions deploy create-stripe-invoice`
and `preview-stripe-invoice`. Either order is safe mid-window — worst case is the old prorated
lines (edge behind) or a preview that briefly disagrees with a not-yet-deployed function
(client ahead); amounts are identical in all cases.

Help guide `split-a-job-into-stages`: the **auto** bullet now says the bill names the stages it
covers.
