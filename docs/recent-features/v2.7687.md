# v2.7687 — Lien notices: an assistant can put each envelope’s mail number on a notice already recorded (2026-11-17)

On `dev-mcp` (server 0.98.0, 119 write verbs): **`plan_notice_numbers`** → **`apply_notice_numbers`**. The owner, 2026-11-17, with a scan of a notice run's divider pages, each with a certified mail number written in its tracking box: "help me enter these numbers into the lien desk, and if there are not dev verbs to make it easy, add dev verbs."

## What was missing

A recorded § 53.056 or § 53.057 notice keeps one send for each recipient in `job_lien_filings.sends`, and each envelope has its own certified mail label. Three doors write a number, and none reached the case the scan showed:

- The run window takes a number an envelope, when the run is recorded there.
- *Already mailed? Record it…* has one number box. `byHandSends` writes it on every recipient's send, so a notice to the owner and the contractor is recorded with one envelope's number on both.
- *add the number ›* (`LienTrackingOwedEditor`) fills a send whose number is blank. A send that holds the wrong number is not offered.

The seat had `plan_notice_by_hand` (the one box again) and `plan_lien_service` (a filed affidavit's copies, not a notice).

## plan_notice_numbers → apply_notice_numbers

- A notice is `{ job_id, owner?: { tracking }, contractor?: { tracking }, months?: [YYYY-MM], paper?: monthly | retainage, sent_on? }`. One or at most 20 a plan, each with its own `plan_hash`; one an apply.
- The write is the door's own: `sends` on the notice's row, through `withTracking` from the kernel copy, as the dev under RLS. One PATCH held to a live notice (`kind in (notice_53_056, retainage_53_057)`, `voided_at is null`), read back.
- It fills a blank number, replaces a number already there, and with `""` takes one off, so the copy reads *tracking owed* until its own number is set.
- `months` and `paper` tell one notice of a job from another. A row applied from another job's paper (`applied_from`) is never picked: it is not a mailing of its own.
- `sent_on` is a check. A day that is not the record's is refused, and the day is never moved: a notice's day decides whether a month was noticed in time, and the door for a wrong day is to void the record and record the mailing again.
- A certified number is digits alone, 20 or 22 of them: the run window's own rule (`trackingShape`). Spaces and dashes are dropped, as the numbers on record are kept.

## What the plan says

Each copy before and after, the `sends` the row would hold, the desk item the notice marked sent (left as it is), and a line for each thing the eye should check:

- `check_digit`: a USPS number's last digit is computed from the others (from the right, weights 3 and 1, to the next ten). A number read off a label by eye that fails it is named, and the plan stands.
- `same_number`: two envelopes of the notice carry one number.
- `also_holds_this_number`: another live filing already holds a number the call gives, found by a containment read of `sends`.
- `same_paper`: the other jobs of the same packet, each on its own row, which this plan does not change.

## What it does not do

The table's one trigger (`job_lien_filings_to_activity_ins`) fires on an insert alone. The update emails nobody, issues no release and adds no line to the job's Activity. The day mailed, the claim, the months and the desk item stay as they are.

## Left for the app

*Already mailed? Record it…* still has one number box. A box for each envelope there would end the mistake at its source.
