# v2.2251 — Roadmap Add-task modal: typing fix + crew tags (2026-08-24)

Two changes to `src/components/checklist/ChecklistTechTreeAddTaskModal.tsx`,
from the 2026-08-24 design spike.

## Bug fix: every typed letter vanished

The modal's reset effect listed `initialEditAssigneeUserIds` in its dependency
array while the prop's default was an inline `= []` — a new array identity on
every render. Each keystroke re-rendered the modal → "new" dep → the reset
effect re-ran its add-mode branch → `setTitle('')`. The default is now a
module-level `NO_PRESET_ASSIGNEES` constant (with a comment naming the trap).
Reproduced and verified fixed live; the edit-mode props involved are dead code
(the task card modal took over editing in v2.1901) but were kept as-is.

## Crew tags (one-tap staffing from People → Teams)

A chip row between "Assignees (optional)" and the checkbox list, seeded from
the existing `people_teams` / `people_team_members` tables:

- **Tap a crew chip** → all its members get checked, each with a small
  attribution pill; tap again → unchecked. Manually unchecking one member drops
  the chip to a dashed *partial* state (manual edits always win). Tags never
  change what a task stores — they only drive the same checkboxes.
- **＋ New crew** — inline panel (name + the same checkbox list as picker);
  saving writes to People → Teams and comes back active on this task.
- **✎ Edit** flips the row to edit mode (tap a chip to edit); **long-press or
  right-click** a chip jumps straight there. Rename / restaff / **Delete
  crew…** (two-step, names the blast radius). Editing a crew never touches the
  current task's checked boxes.
- Name↔user seam in the new pure kernel `src/lib/checklistCrewTags.ts`
  (+ tests): normalized-name mapping (`people_team_members.person_name` ↔
  `users.name`, same convention as pay config), chip-state math, and a roster
  diff that never removes members without logins (the picker can't represent
  them; chip tooltip counts them).
- Crews load failure (e.g. RLS for a role that can't read `people_teams`)
  hides the row gracefully — assignee checkboxes are unaffected.

Help guide updated: *add a stage and its tasks to a roadmap* (crew-tags
section).
