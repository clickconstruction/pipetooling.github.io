# v2.6004 — dev-mcp: a document onto a matter's Evidence tab (2026-10-27)

The dev seat (`dev-mcp`, server 0.7.0) gains a tenth and eleventh write verb: `plan_matter_document(document)` / `apply_matter_document(document, plan_hash)`. Until now the seat could write a matter's narrative and its planned steps but not file a paper on its Evidence tab, so a session that had just sent a letter had to hand the PDF to the office to upload by hand. The need showed up the day a session sent a demand letter and had three signed scans, two sent emails and a mailing receipt to file.

## What changed

- **Migration** [`20261028010000_dev_legal_document_write.sql`](../migrations/20261028010000_dev_legal_document_write.md): `dev_legal_document_write(p, p_dry_run, p_file)`, the dry-run wrapper modeled on `dev_legal_plan_write`. `p` is the row's words and the file's facts (`matter_id`, `title`, `shows`, `original_name`, `mime`, `size_bytes`, `sha256`, and the Evidence tab's `dated_on`, `state`, `received_on`, `sent_on`, `sent_how`, `sent_to`); the dry run returns the matter, the row as it would be written, the live document count and whether the firm reads it; the write inserts the `legal_matter_documents` row as the caller and refuses it unless the object named in `p_file` is in the `legal-matter-documents` bucket under the matter's folder.
- **Grammar** ([`devMcpWrites.ts`](../../supabase/functions/_shared/devMcpWrites.ts)): the two verbs join `WRITE_VERBS` (eleven verbs over six RPCs); `writeRpcBody` checks the document's shape (a sent paper needs `sent_how` and `sent_to`; days are `YYYY-MM-DD`; `sha256` is 64 hex) and POSTs `{ p, p_dry_run }` like the others.
- **Server** ([`dev-mcp/index.ts`](../../supabase/functions/dev-mcp/index.ts), 0.7.0): `content_base64` is decoded, checked against the Evidence tab's kinds and the 10 MB limit (`_shared/legalMatterDocuments.ts`), and digested before the dry run, so the plan hash commits to the file; at apply the server re-runs the dry run, checks the hash and the one-apply rule, stores the file as the dev under `<matter_id>/<id>-<name>` through the storage API (the office cohort's own policy), then POSTs the RPC with `p_file`; a refused row removes the object. `argsForLog` keeps the base64 out of `dev_mcp_calls`.
- **Tests** ([`devMcpWrites.test.ts`](../../src/lib/devMcp/devMcpWrites.test.ts), +5): the allowlist gains the RPC and checks the migration's gates and bucket check; the grammar's valid and refused shapes; the server's wiring and version.
- **Docs**: `EDGE_FUNCTIONS.md` dev-mcp section; the migration doc.

## Deploy

`supabase db push` (the migration), then `supabase functions deploy dev-mcp`. `tools/list` on `https://mcp.clicktooling.com/dev` shows `serverInfo.version` 0.7.0 and both verbs once it is up.
