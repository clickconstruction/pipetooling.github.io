# v2.3300 — Burn against the bid, PR 3: Job Summary and the Pipeline name the footing (2026-09-11)

Client only (reads `job_budgets` from v2.3297). Rung 3 of [`to-dos/burn-against-the-bid/`](../../to-dos/burn-against-the-bid/README.md).

## What shipped

- [`useJobBudgetFootings`](../../src/hooks/useJobBudgetFootings.ts): one chunked `job_budgets` read for the jobs on Job Summary (and the Pipeline board's open jobs) → job id → `{ usd, source }`. Wired in [`Jobs.tsx`](../../src/pages/Jobs.tsx) into `useJobSummaryView` (`budgetByJobId`) and the Pipeline burn card's rows.
- [`jobSummaryBurn.ts`](../../src/lib/jobs/jobSummaryBurn.ts): `projectJobSummaryBurn` takes `budgetFooting` and reports `footing` (◆ bid · ✎ typed · ≈ assumed); `buildPipelineBurnAlert` carries each hot job's `footing` / `glyph` and an `assumedCount` (+2 tests).
- [`jobSummaryLedgerView.ts`](../../src/lib/jobs/jobSummaryLedgerView.ts): rows gain `budgetFooting`, `budgetGlyph`, `budgetUsd`; the view prefs gain `budgetFilter` (all · bid · typed · assumed, persisted per device); `jobSummaryRowInBudgetFilter`, `countJobSummaryAssumed` (unfinished rows on an assumption — the linking backlog) (+1 test).
- **Job Summary** ([`JobSummaryLedgerToolbar`](../../src/components/jobs/JobSummaryLedgerToolbar.tsx), [`JobsJobSummaryTab`](../../src/components/jobs/JobsJobSummaryTab.tsx)): the **Budget** chip beside Target; the *≈ N open jobs burn against an assumption* chip under the tiles; the Burn cell prefixes ◆ / ✎ when the row has a footing (the assumption stays unmarked so the table reads as before) and its hover names the footing.
- **Pipeline** ([`PipelineMoneyOpportunities`](../../src/components/jobs/PipelineMoneyOpportunities.tsx)): *N jobs burning ahead of progress — $X of margin at risk · M against an assumed budget*; the worst three carry their glyph.
