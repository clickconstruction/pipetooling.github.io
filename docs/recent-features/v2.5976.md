# v2.5976 — Find a job asks the server for your jobs alone (2026-10-27)

Seen while walking each role on 2026-10-27, after punch list #181: the field lookup (T5-01, helpers and subcontractors) sent the office's customer query with every search. The behaviour predates #181.

- **The cause**: `HeaderGlobalSearch`'s data-search effect built `customersPromise` and the bids params before it branched on `fieldLookup`. `Promise.resolve(builder)` starts the request right away, so a `customers?select=…&name=ilike…` read went out and the field branch threw its answer away. As the Sample helper on the dev server, three searches sent three customer reads next to `search_jobs_ledger`. RLS gave the account 0 customers, so it was a wasted request, not a leak.
- **The fix**: the bids params and the customer query now start below the `if (fieldLookup)` return. The field lookup sends `search_jobs_ledger` alone, beside the ZZ test-job ids it uses to drop test jobs (read at most once a minute per user). The office search is unchanged.
- **Test**: `HeaderGlobalSearch.roles.render.test.tsx` +1, a helper search calls `search_jobs_ledger` and never `from('customers')`, and the office search still does. It failed on the old order and passes on the new.

No migration, no edge function.
