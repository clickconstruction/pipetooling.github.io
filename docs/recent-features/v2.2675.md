# v2.2675 — Overhead "who makes it up" people table with window chips (2026-09-03)

Owner ask: a table on People → Overhead of the people that make up overhead, broken down by category, switchable between the last day / week / month, with amount and percentage in every cell.

## Client only — no migration

- Kernel [`lib/overheadPeopleTable.ts`](../../src/lib/overheadPeopleTable.ts) (+5 tests): `buildOverheadPeopleTable({ labor, parts, endYmd, days })` slices a trailing window ending on the company day, merges names case/space-insensitively, sums office labor / bid labor / office parts / total (+ office+bid hours) per person, sorts by total with the synthetic **no-person** parts row last, and returns column totals. `overheadPeopleShare` = share of column (null on a zero column). `OVERHEAD_PEOPLE_WINDOWS` = Today (1) / Last 7 / Last 30 / Last 90 days.
- Data comes from what the 90-day KPI effect already fetches — **zero new queries**: the labor detail lines (`buildOverheadDailyLabor(...).detailByDay`, flattened) and the office-parts detail lines the internal-transfer-excluding loader already returns (`partsDetailByDay` + `bucketByTxId`, previously discarded). The tab maps each parts line to a person at render time: Mercury lines → debit-card nickname via the existing `useMercuryLedgerNicknames` map; supply / tally / no-card Mercury lines → null (no person). Internal-transfer lines are dropped with the same bucket rule the pool sum uses.
- [`components/people/OverheadPeopleTable.tsx`](../../src/components/people/OverheadPeopleTable.tsx): window chip group (`aria-pressed`), table with amount + share-of-column in every cell, hours beside each name, Pool footer with each column's share of the whole, empty state, caption explaining attribution. Placed after the pool-trend card.
- Help guide `understand-overhead-numbers.md` gains "Who makes up the pool".
