# v2.4086 — Bids: the Bid window's state is one piece (2026-09-28)

Client only; no migration, no edge function, no screen change. Punch list **#51** (`to-dos/bids-edit-controller.md`), PR 4a — the first half of moving the Edit Bid controller out of `src/pages/Bids.tsx`.

## What is new

**`src/hooks/useBidWindowState.ts`** (3-case hook test) — the Bid window's own state, which the page declared as eleven `useState`s and one ref: open or not, which face it opens on, the focus a door asked for, the bid it holds, the save in flight, the close guard's state (and the ref an async close reads it through), the key its Bid face re-reads on, and the delete window's three. A state container and nothing else.

## Why a PR of its own

The next PR (4b) moves the Edit Bid handlers, the autosave and the close guard into `useBidEditController`, called where that code stands so no hook or effect changes its order. Those handlers read and write all of this state. It cannot move into the controller: the sent-date hook near the top of the page reads `editingBid`, and a hook called lower down cannot hand state to one called above it. So the state becomes one piece here, called where it was declared, and 4b takes it as one input instead of about fifteen.

## What changed in `src/pages/Bids.tsx`

The eleven declarations become one hook call and a destructure of the same names, so nothing else in the page changes. The bid-form focus effect names its setter in its dependency list — the setter is stable, so the effect runs exactly as before; lint only asked because it now comes from a hook. The page keeps `projectsForPicker`, the party windows' pair and the render-only flags.
