# v2.2962 — Crew Jobs / Bids: `+` links the clock sessions instead of hand-writing the split (2026-09-06)

Owner question on Jobs → Team Labor → **Crew Jobs / Bids**: "Is this driven by clock sessions? If I add an assignment here, does it update the session?" It was driven by approved sessions but the `+` wrote `people_crew_jobs` / `people_crew_bids` directly, leaving the session unlinked and the hand-entered split one approval away from being overwritten by `sync_crew_jobs_from_clock`. Owner's call: keep the button, make it write the session, and **never allow a split unless the person has a clock session**. Client only — no migration, no edge function.

## What shipped

- **Kernel** [`src/lib/crewAssignSessionLinkPlan.ts`](../../src/lib/crewAssignSessionLinkPlan.ts) (+8 tests): `groupCrewDaySessionsByPerson` (trimmed `users.name` key — the same join the sync trigger uses; splits linked from unlinked, sums unlinked hours), `crewAssignCellState` → `no-clock` | `link` | `locked`, `crewLinkPatch` (job clears bid and vice versa), button / toast labels.
- **[`CrewJobsBlock`](../../src/components/CrewJobsBlock.tsx)** (both mounts — Jobs → Team Labor and Quickfill → Crew Jobs / Bids):
  - The day query now returns the sessions themselves (`id, user_id, job_ledger_id, bid_id, clocked_in_at, clocked_out_at`), still approved + closed + not rejected/revoked.
  - **`link`** (≥1 unlinked session): the `+` reads **Link N sessions (H h)**; picking a job or bid runs one `UPDATE clock_sessions SET job_ledger_id / bid_id … WHERE id IN (unlinked)` with `.select('id')`. The existing `clock_sessions_sync_crew_assignments_tr` trigger recomputes the person-day split from durations; the block reloads and toasts. If RLS updates fewer rows than asked, a warning toast says so (see the controller note below).
  - **`locked`** (every session linked): the ⏱ from clock badge and the split, read-only, plus **Split day…**.
  - **`no-clock`**: **No clock session** (hover text explains) and no `+`. A legacy hand-entered row shows its assignments with a **manual · no clock** tag and a **Clear** that empties both crew tables for that person-day (the only remaining direct write; it removes a split, never creates one).
  - **Split day…** (any session state) opens the shared `DashboardMyTimeDayEditorModal` for that user and date (`sessions=[]` → it fetches), so a second job is done by splitting a session; `onSaved` / `onLinkedSessionsUpdated` reload the block.
  - Removed: the percent inputs, the per-chip ×, `saveCrewRow`'s upsert of arbitrary splits, the optimistic local write.
- **RLS, checked first**: `clock_sessions update access` (2026-06-05) passes dev, team leads for their members, the row's own user, pay-approved masters and their adopted assistants (`is_assistant_of_pay_approved_master` walks `master_assistants`). **A controller who is not adopted under a pay-approved master can open the block on Jobs → Team Labor (the tab's edit gate is dev + controller) but the update affects 0 rows** — surfaced by the warning toast, not fixed here (a policy change is a migration; recorded in `to-dos/owner-decisions-pending.md`).
- Guides: new `put-clocked-hours-on-the-right-job`; `quickfill` → Crew Jobs / Bids bullet rewritten.
