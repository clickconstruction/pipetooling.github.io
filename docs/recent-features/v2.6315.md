# v2.6315 — Every edge function links in CI before it can merge (2026-11-01)

v2.6284 (#6719) reached prod with `_shared/jobFolders.ts` importing three names `_shared/driveSettings.ts` did not export, and `job-drive-folders` and `photo-save` answered 503 BOOT_ERROR until v2.6294: Deno refuses a missing named export when a module loads, CI typechecks the app and never the functions, and the Mac the PR was built on has no Deno, so every check passed. v2.6294 proved the break by bundling each function with esbuild; this makes that proof a check that runs on every PR.

- **`scripts/check-edge-bundles.mjs`** (`npm run check:edge-bundles`): esbuild bundles every `supabase/functions/<slug>/index.ts` (`bundle`, `packages: 'external'`, `write: false`, `platform: 'neutral'`), following relative imports and leaving `https:`, `npm:`, `jsr:` and `node:` imports external. A failure names the function, the file and line and esbuild's message, and exits 1; the 173 functions link in about 0.3 s. An optional argument points it at another functions folder, for a scratch copy with a break in it. esbuild is vite's own bundler, so `npm ci` already installs it; nothing was added to `package.json`'s dependencies.
- **The kernel**: `linkFunctions(root, dir, slugs, esbuild)` and `linkReport(results, dir)` in `scripts/lib/edgeBundle.mjs`, which stays dependency-free (esbuild is handed in, so the drift workflow's bare Node still loads the file). `src/lib/edgeBundle.test.ts` builds a two-function fixture in a temp folder and pins: a value import of a name the module does not export fails at the importer's line; a clean function with remote, `npm:` and type-only imports passes with no warning; a type-only import of a missing name passes, as Deno strips it; the report lists each failing function once per distinct message, paths shortened past the folder, and keeps a message with no location.
- **CI** (`.github/workflows/ci.yml`): the step *Every edge function links* runs after Lint on every pull request and merge-queue build. No change detection: the whole check costs less than the checkout, and `check-workflow-parity.mjs` still reads clean.
- **Proved against the incident**: in a copy of `supabase/functions` with the `export` taken off `driveFolderMeta` in `_shared/driveSettings.ts`, the check fails exactly the five whose bundle holds `jobFolders.ts` — `drive-link`, `job-drive-folders`, `job-photos`, `messages-email`, `photo-save` — each at `_shared/jobFolders.ts:17 No matching export in "_shared/driveSettings.ts" for import "driveFolderMeta"`, and the other 168 link.
- **What it does not catch**: a type error (`deno check` at deploy still does), a name read off a dynamic `import()`, and a remote module that will not load, which only the deploy or the dev seat's `check_edge_boot` sees.
