# v2.4259 — Job Parts Tally reads every charge on a card, not just the newest 1,000 (2026-09-30)

Found on 2026-09-30 while reading `/tally?tab=transactions` for punch list #72 (`to-dos/tally-transactions-refresh.md`): the console logged `[row-cap] rpc:list_my_linked_mercury_transactions_for_tally returned exactly 1000 rows with no limit` three times per load on the dev's card. Client only; no migration, no edge function.

## What was wrong

`JobTally.loadTallyTransactions` and both reads in `ClockInOutButton`'s pre-clock-out purchases gate called the RPC un-ranged. PostgREST answers an un-ranged read with its first `max_rows` (1,000) and a 200 (`docs/TROUBLESHOOTING.md` → `[row-cap]`), and the RPC orders newest first, so a card with more than 1,000 charges since its link lost its oldest rows with no error. The client then applied the date floor (`mercuryRowPassesSortingStartDate`) and merged the payroll flags onto the truncated list: the *N unlinked* count, the *Payroll: N · $X* chip and *Show all* read only what survived the cap. The dev's Cash App card crossed 1,000 rows in 2026; any holder's card will as it ages.

## What changed

- **[`src/lib/tally/fetchTallyLinkedMercuryRows.ts`](../../src/lib/tally/fetchTallyLinkedMercuryRows.ts)** — one fetcher for the RPC: `fetchAllRows` over `supabase.rpc(…).range(from, to)` (the RPC's `ORDER BY posted_at DESC, id` keeps pages stable), each page inside the `withSupabaseRetry` the callers had, a failed page throwing rather than returning a partial list. Takes the client so a test can hand in a stub.
- **`JobTally.tsx`** (`loadTallyTransactions`) and **`ClockInOutButton.tsx`** (`handleClockOutClick`, `refreshTallyPreClockOutUnlinked`) call it; nothing else about either path changes. The payroll-flags read stays the whole-table SELECT it was (quirk 1 of the map).
- **Tests** (`fetchTallyLinkedMercuryRows.test.ts`): two pages for 1,400 rows with the oldest row kept, one page for a short list, a failed second page throws.
- `docs/JOB_TALLY_ARCHITECTURE.md` → the Transactions dossier's Supabase line names the fetcher.

## Verify

`npx vitest run src/lib/tally/fetchTallyLinkedMercuryRows src/lib/releaseNotes`. Dev server as the dev: `/tally?tab=transactions` loads with no `[row-cap]` line in the console and the Payroll chip's count rises above the capped figure (401 on 2026-09-30).
