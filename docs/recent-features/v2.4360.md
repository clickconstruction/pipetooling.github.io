# v2.4360 — CI catches a window that closes the window behind it (2026-10-01)

No migration, no edge function, nothing a user sees. Grace asked for the [v2.4352](v2.4352.md) check to run in CI, so a new window drawn inside another window cannot bring back the click that closed both (seventeen fixed in v2.4338 and v2.4352).

## What changed

- **A step in both checks jobs** — [`ci.yml`](../../.github/workflows/ci.yml) (pull requests and the merge queue) and [`deploy.yml`](../../.github/workflows/deploy.yml) (main), as the workflow parity check requires: *Windows drawn inside windows stop their own backdrop click* runs `npm run check:nested-windows`, after the plain-words check. A backdrop that closes without a target check and holds a window that lets the click through fails the job. `--rows` stays a report: its row detection misses `<tr>` rows (v2.4356) and is not a gate.
- **The failure points at the line.** In GitHub Actions each finding is also an `::error` annotation on the line where the inner window is drawn, naming the backdrop behind it and the one-line fix.
- **A finding that is meant can say so.** A `nested-windows: allow — <why>` comment on the line above the inner window or the outer backdrop (or inside its opening tag) lets the finding through; a bare note with no reason does not count. The check reads every return of a component, so a window a component draws only in another mode — an early return on a prop — still counts; this is the way out for that. Notes are listed on every run.
- **Faster and lighter** ([`check-nested-windows.mjs`](../../scripts/check-nested-windows.mjs)): the TypeScript program no longer loads the standard lib or global `@types` — the scan only resolves the app's own symbols. About 6 s instead of 21 s here, and it fits in 1.5 GB of heap where it needed over 2 GB; same findings, checked by diffing both versions' output on the code before v2.4352 (nine windows, fifteen inner ones, the two rows). `npm run check:nested-windows` gives it a 3 GB heap anyway, since a small runner's default heap is near that need.
