# v2.2015 — Partnerships Job review: trade pills on job numbers (2026-08-21)

Owner request (picked from three mockups): show the service type with the job number — "PLUM 789" instead of "#789" — using the app's existing trade-pill vocabulary (`buildServiceTypeTradePill`, the Jobs Stages board convention; Plumbing `#e17235`, Electrical `#EE9310`).

**UI** ([`PartnershipJobReviewTab.tsx`](../../src/components/partnerships/PartnershipJobReviewTab.tsx)): the review queue RPC doesn't carry service types, so after the queue loads the tab resolves them office-side in one query (`jobs_ledger` → embedded `service_types(name)` for the queue's job ids). Rows render the solid trade pill before the plain number (the `#` is dropped when a pill shows); fail-soft — no service type or a failed lookup falls back to the old `#789` form. Client-only; no migration.

**Deliberately not touched** (candidate follow-ups): the Timeline tab's "Job #707 confirmed…" sentence, and the partner-facing "Your jobs" card — the latter gets rows from `get_my_partner_jobs`, so pills there need the RPC payload to carry the service type (migration).
