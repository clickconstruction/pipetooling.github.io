# v2.6401 — How fast a change ships: In line now, the merge queue's line (2026-11-02)

The owner's question on 2026-11-02, after v2.6399 shipped the tab: could the office see the queue itself, so a person can tell what number in line their change is to go live? The office does not know pull request numbers; every pull request's title starts with its version and a plain sentence, so the title is the bridge. The `ship-pace` cron now reads the merge queue's entries and every open pull request's state, the kernel sorts them into a line and three buckets, and the section draws **In line now** under the four tiles. No migration; `ship-pace` redeploys after the merge.

- **The read** (`supabase/functions/ship-pace/index.ts`, `readQueue`): one GraphQL query, `mergeQueue(branch: "main") { entries(first: 100) { totalCount nodes { position enqueuedAt estimatedTimeToMerge pullRequest { number title } } } }` on the first page alone (`@include`), and `pullRequests(states: OPEN, first: 100, after: $after)` with `isDraft`, `mergeable`, `autoMergeRequest { enabledAt }`, `statusCheckRollup { state }` and `mergeQueueEntry { position }`, paged until `hasNextPage` is false or ten pages. GraphQL refusing, erring on the queue or a repository with no queue leaves the whole block null and the count with it, as the count did before. The queue's scope: the owner's fine-grained token (Pull requests, Actions, Contents and Metadata, all Read-only) read the queue's count on 2026-11-02, so that set covers it; GitHub's permission reference names no permission for `mergeQueue`, and the one field report (cli/cli #8352) found a fine-grained token read the queue once Contents was added, so the card's *not read* line points a dev at that permission first. The answer gains `queue: { inLine, armedWaiting, armedHeld, openUnarmed, drafts } | null`.
- **The kernel** (`supabase/functions/_shared/shipPace.ts`, pure, tested from `src/lib/settings/shipPace.test.ts`): `PaceInput.queue` (`{ total, entries, open }`) replaces the bare `queueNow`; `paceQueue` sorts the entries by position with GitHub's estimate rounded to whole minutes (null kept), and sorts every open pull request once into its bucket in this order: a draft is a draft whatever else it is; one in the queue (`mergeQueueEntry`, or its number among the entries when GitHub's field lagged) is in the line and nowhere else; one armed is `armedWaiting`, and `armedHeld` too when its checks are FAILURE or ERROR or it is CONFLICTING, since waiting will not move it; the rest are `openUnarmed`. GitHub clears `autoMergeRequest` once a pull request enters the queue (seen on the live repository: every queued pull request read as unarmed), so armed and queued never overlap. The row's `queue: PaceQueue | null` sits beside `now.queue`, the count; `parseShipPacePicture` reads a row written before this as `queue: null`, never as malformed, so the card says *not read* until the next tick. Words: `ordinalWords` (1st, 2nd, 3rd, 11th, 21st, 112th), `queueSpanWords` (*under a minute*, *25 minutes*, *1 hour*, *2 hours 5 minutes*), `queueLineWords` (*3rd in line, in the queue 25 minutes, about 12 minutes to go*; no estimate drops the tail; under a minute says so; a stamp ahead of our clock reads as *under a minute*, never negative), `queueTitleWords` (drops the leading `v2.NNNN `, cuts at 90 characters on a word with an ellipsis and trims a trailing comma; `SHIP_PACE_QUEUE_TITLE_MAX`), `queueMoreWords` (*and 2 more*), `queueBucketsWords` (*12 more are armed and waiting on their checks. 31 are open and not yet asked to merge.*, with *2 of them are held by a red check or a conflict.* between when any are, *more* dropped when the line is empty, singulars, and *Nothing is armed and waiting on its checks.* / *Every other open change has asked to merge.* for the zeros). `SHIP_PACE_QUEUE_SHOWN` is 10.
- **The section** (`SettingsShipPaceSection.tsx`, `QueueCard`, words in `lib/settings/shipPaceWords.ts`): under the four tiles a card **In line now** with *The order changes go live in, the top one next.*, the first ten entries as a list, each the position, the title after the version and its words, then *and N more* against the queue's total, then the buckets line. An empty queue draws `EmptyState` with `emptyWords({ kind: 'waiting', who: 'the queue' })`: *Nothing waiting on the queue.* A queue not read draws the card's one line *The queue was not read. Ask a dev about the token's scopes.* and no list. The tile **In the merge queue** keeps its count. Three new smoke cases (full, empty, unread) in `SettingsShipPaceSection.render.test.tsx`, nine in all.
- **Guide**: *see how fast a change ships* gains *Find your change in line*: a change is a pull request, its title says what it is, the list is the order they go live in, a change still on its checks is not in line yet, the first ten are listed, and an example panel for the card's *not read* line.
