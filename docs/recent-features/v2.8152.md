# v2.8152 — Document builder: a sent sheet's copy no longer holds the trade's page link (2026-11-20)

Punch list #404. Found on 2026-11-20 while reading `document-builder-send` for step 9, not by the review. No migration. One function changed: `document-builder-send`, which takes a deploy.

## What was wrong

A send of a job's insurance sheet files a copy of its email under Documents → Sent copies. The email is the trade email's frame, with the press **Open your portal** on the trade's own page link, `/t/<token>`. That token opens the trade's page with no login.

A filed copy is cut by its kind (`sentCopyKeptHtml`): a `gc_trade_email` copy keeps `/t/…` and never the token, because four office roles read the filed copies. The sheet's send files its copy as `insurance_sheet_email`, a kind with no rule, so the copy kept the whole link.

## The fix

`document-builder-send` hands the filing the email's HTML already cut by the trade email's rule: `sentCopyKeptHtml('gc_trade_email', email.html)`. The shared file `_shared/sentCopyEmail.ts` is not changed, so no other function is put behind by this. The sheet's own link, `/d/<code>`, stays in the copy: it is the second way in and is made to be handed on.

## What it does not reach

The copy filed by the one send walked on prod on 2026-11-20 went to a `ZZ Test` trade, and was filed before this. Its page link is still in that copy. Nothing rewrites an old copy.

## Deploy

`supabase functions deploy document-builder-send` from `origin/main`, on Taunya's go by the function's name, together with v2.8131 and v2.8142.

## Tests

`sendSentCopy.test.ts`: the email built as the function builds it holds the token. Under the sheet's own kind the copy would keep it. Cut by the trade email's rule it holds `/t/…`, no token, and still the sheet's own link. The function's source is read to hold that every copy it files goes through the rule.
