# v2.3638 — MCP servers, PR 4a: the money kernels move to `_shared` (2026-09-20)

PR 4a of [`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md). `dev-mcp`'s `get_job` and `get_customer` must answer with the numbers the screens show, and those numbers — a job's profit, a customer's lifetime value, open balance and pays-in-N-days — are computed by client kernels, not SQL. An edge function can import from `supabase/functions/_shared/` but not from `src/`, so the kernels move; nothing else does.

## The change

A move, no behaviour change. Six files go to `supabase/functions/_shared/` byte-for-byte (git records an add beside a rewritten stub, since the old path stays — `git blame -C` on the new file reaches the history), their sibling imports become `./x.ts` as the other shared kernels write them, and each old path keeps a three-line `export *` stub, so **no importer changes** (48 of them) and every test stays beside its old path and runs through the stub:

| Kernel | Was |
|---|---|
| `billTruth.ts` — the one kernel behind Ready to Bill / Billed / Owed / Lifetime billed | `src/lib/billing/` |
| `customerProfileStats.ts`, `customersListLcv.ts` | `src/lib/customers/` |
| `jobProfitSummary.ts`, `subLaborCost.ts` | `src/lib/jobs/` |
| `peopleLaborJobItemLineCost.ts` | `src/lib/` |

The tree was already closed: the six import only each other and two kernels that lived in `_shared` before (`paidJobBillGuard`, `portalBillMembership`). None touches `import.meta`, `window` or storage. No edge function imports them yet, so nothing needs deploying.
