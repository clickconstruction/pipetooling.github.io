# v2.3174 — The bid number in a robot's question is a link (2026-09-08)

Client only. No migration or edge-function change.

## Why

Wendi, reading the **Standing rulings** panel on Bids → Audits: "can you make the bid number a link so i can have some context to what it's talking about?" Robots write their questions as prose that names the bid the way the app does — `[audit b474 / footage · sheet P2.01] Your 4in sanitary is 50 ft…` — and until now that `b474` was just text.

## What shipped

- **[`twinQuestionBidRefs.ts`](../../src/lib/bids/twinQuestionBidRefs.ts)** (new kernel, 9 tests) — `splitBidRefs` lifts every `b474` / `B474` / `bp398` (word on its own, digits after the prefix) out of a question into segments; `bidNumbersAcross` collects the distinct numbers the open queue mentions for one lookup; `resolveBidRefId` takes the fetched id first and falls back to the row's own `about_bid_id` when the question names exactly one bid; `bidRefHref` is the board deep link (`/bids?tab=bid-board&bidId=<id>`, the v2.2043 scroll-and-highlight); `trailingBidRef` names the bid a question is *about* when its text never does.
- **[`TwinQuestionText`](../../src/components/bids/TwinQuestionText.tsx)** (new) — renders a question with each resolved reference as a link that opens in a new tab (the answer box stays put). Unresolved references stay plain text. Most live questions say "this bid" and never name it, so a row with `about_bid_id` and no reference in its text gets a trailing **· b474** link after the question.
- **Bids → Audits, Standing rulings** — both the grouped ruling's canonical question and the topicless singles render through it. After the open questions load, two `bids` queries (by `bid_number in (…)` for the numbers mentioned, by `id in (…)` for the rows' `about_bid_id`s) fill both maps.
- **Settings → Digital twins, Twin questions** (dev console) — the same renderer, resolving through `about_bid_id` only.
- Render smoke pins both: a single with `[audit b474 / scope] …` renders `b474` as a link to `/bids?tab=bid-board&bidId=bid-474`; the travel-bands ruling, whose text never names a bid, gets the trailing `b405` link.

## Docs
