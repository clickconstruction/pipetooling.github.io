# v2.3531 — Stages tab decomposition, PR 1: every role gate on the Pipeline board lives in one tested file (2026-09-16)

Client only, behavior-preserving. PR 1 of the train in `to-dos/engineering-hygiene.md` — the Stage-A sweep of [`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`](../JOBS_STAGES_TAB_ARCHITECTURE.md): pure logic out of `JobsStagesTab.tsx` into `lib/*` kernels with tests, before any JSX moves. Nothing changes on screen.

## Why this one first

The playbook's rule is Stage A before Stage B: a region's calculation goes behind unit tests before its JSX moves, so every later PR in the train is a cut-and-paste a reviewer can read. This PR is that pass for the whole tab. The piece that earns its keep long term is the role gates. Before it, the same boolean chain was written out inline **thirteen times** for the office pool, **five** for the Accounts Receivable set (with the one that mirrors a table's RLS carrying a comment and the other four not), **five** for the dev-or-controller money views and **four** for the dev-or-master owner pair — thirty-odd places a new role would have to be threaded through by hand, in one file. `docs/ADDING_A_NEW_ROLE.md` already says "prefer capability functions over per-policy edits" for the database; the board now has the client half of that.
