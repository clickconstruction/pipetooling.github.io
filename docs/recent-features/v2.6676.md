# v2.6676 — Messages: read an email as the sender laid it out, with Rich text · Plain (2026-11-08)

Punch list #259 (`to-dos/email-rich-text.md`), PR 2 of 2, over PR 1's kept HTML part (v2.6675, `messages.body_html_path`). Grace's ask of 2026-11-04 on Glenn Gelwin's invitation: "the option to see it as rich text or in the current format". The plain view's half shipped as v2.6508; this is the switch.

- **The chips** (`MessageWindow.tsx`): an email line whose `bodyHtmlPath` is set draws a group *Read it as* over the words, **Rich text · Plain**, `aria-pressed` on the one chosen; a line with no kept HTML draws no chips and reads as before. The choice is kept on the device (`richMail.ts`'s `readEmailView` / `keepEmailView`, `localStorage` `messages.emailView.v1` in try/catch), Plain until someone presses Rich text. Copy, Print or save as PDF and Share stay the plain words.
- **The read** (`richMailIo.ts`): `loadRichMail(path)` downloads `<line id>/body.html` from the private `message-attachments` bucket under the office's SELECT policy, the one the kept files are opened with; a failure is its `{ kind, message }` (`recoveryFailureFromError`) for `OfflineRetryPanel`, idempotent, so a lost signal reads again by itself and a refusal shows its reason with no Retry.
- **The sanitizer** (`richMail.ts`, pure, and `richMailDom.ts`, DOMPurify `3.4.17` pinned exactly in `package.json`, no `^`): the HTML profile with `RICH_MAIL_FORBID_TAGS` (script, noscript, style, link, meta, base, head, title, frames, object, embed, applet, form and its controls, svg, math, media, canvas, template, slot, dialog, map, area, marquee) and `RICH_MAIL_FORBID_ATTR` (srcset, sizes, ping, background, poster, longdesc, usemap, formaction, action, target, dynsrc, lowsrc, id, class, contenteditable, autofocus, tabindex) out; `RICH_MAIL_URI` in DOMPurify's own shape (the web, mail, a phone, a text, or a value with no scheme, since DOMPurify runs it over `width="600"` too, which a stricter pattern dropped in the first draft); `cleanStyle` takes `url(`, `expression(`, `@import`, `behavior`, `-moz-binding`, `image-set(` and a fixed or sticky position out of every inline style; `isTrackingPixel` removes a picture two pixels or smaller either way, by attribute or by style, or hidden; every other picture loses its `src` while pictures are off and wears `data-picture-off` for the dashed placeholder; on, `richAttr` keeps an `https:`/`http:` or inline `data:image` address and drops a `cid:` one, whose bytes are in Gmail; a link keeps an `http(s):`, `mailto:`, `tel:` or `sms:` address alone and gets `target="_blank" rel="noopener noreferrer"` in `afterSanitizeAttributes`, as `MessageBody` gives the plain view's. One DOMPurify instance per page, made on the first call; the pictures switch and the counts ride on a module-level state set before each synchronous `sanitize`.
- **The view** (`RichMailView.tsx`): *Reading the sender's layout…* while the read runs; then **Show pictures** with *N pictures are off.* while the mail has pictures and they are off, once per opening; the HTML on light paper whatever the theme (`data-theme="light"`, since a mail's own colours assume a white page), `overflow-x: auto` so a 600-pixel table never widens a phone, pictures capped at the paper's width.
- **The guide** *find every message with a person in one place* gains *Read an email as the sender laid it out* (the chips, the new tab, Show pictures and why pictures start off, that older emails have no chips, that Copy, Print and Share stay plain), and *Open a link in an email's words* points at it in place of *the app does not keep that layout yet*.
- **Tests**: `richMail.test.ts` (the device's choice and a storage that throws; the forbidden lists and the config; the URI shape over the web, mail, a phone, plain values and every refused scheme; `cleanStyle` on fetches, `expression`, `@import`, fixed and sticky; `pixelSize` and `isTrackingPixel`; `richAttr` on pictures off and on, `cid:`, `javascript:`, `data:` in a link, a style in a cell); `richMailDom.test.ts` under jsdom on a whole mail document (scripts, forms, frames, styles, handlers, backgrounds, ids and classes gone with the layout kept; every link `_blank noopener noreferrer`, a `javascript:` one words alone; two pixels removed and two pictures off, then on with the `cid:` one still off; an inline `data:image` picture kept; a plain fragment as it is); `MessageWindow.render.test.tsx` (+4: no chips on a line with no kept HTML; Plain by default with nothing read; Rich text reads the path, draws the cleaned HTML with pictures off, Show pictures turns them on, Copy stays plain, Plain goes back and the choice is kept; Rich text remembered and a failed read drawing its reason).
- **Docs**: `docs/MESSAGES_ARCHITECTURE.md` (the thread window's lines), the card's status, next and ver.

**Reads the column PR 1 adds**: `messagesIo.ts`'s `MESSAGE_COLS` now names `body_html_path`, so this PR merges after `20261108020000_messages_body_html_path.sql` is pushed (`npm run check:calls-ahead` labels it otherwise). No migration and no edge function of its own.
