# v2.2584 — AR deposits name their customer (2026-09-01)

Variant A of the owner-picked AR modal plan (mockups: "Who Sent This Check",
approved 2026-09-01; order was restore-filter → A → C, with B/D later). The
modal's matching was amount-only — the payer's name appeared nowhere in the
bill picker's search text, and a deposit whose amount matched several bills
(the live backlog was six $250 DRF checks against five open $250 bills) gave
the assistant no way to pick without the owner's mental map.

- **New kernel `src/lib/jobs/arDepositCustomerMatch.ts`** (13 tests):
  `matchArDepositToPayer` finds the one customer/GC whose open billed lines a
  deposit plausibly pays. Tries counterparty, then internal note, then bank
  memo (check services like DRF put the real customer in the memo). Tokenized
  name matching with legal-suffix stripping, dotted-initial merging, and
  acronym expansion ("DRF" ⊆ "Done Right Foundation"); qualifies only on 2+
  shared tokens or full containment either way; any tie between different
  payers → null (conservative: match leads the UI, never auto-applies).
- **`BankPaymentTarget` carries `customerName` + `gcName`**
  (`jobsStagesBoard.ts`): from `jobs_ledger.customer_name` and the
  `gc_customer` embed. Both join `searchLabel` (skipped when already contained
  in the job name), so typing the payer's name in the picker always finds the
  bill.
- **Modal UI (`BankPaymentsModal`)**: matched deposits lead with a "From
  <payer> — their open bills" chip row (source-aware header: "Note mentions…"
  / "Memo mentions…"); chips are two-line, green-accented "matches this
  deposit" when the remaining equals the deposit (same −1¢/+$26 tolerance as
  the quick picks), amount-matches first then largest, capped at 8. The old
  "Matches deposit amount" row remains as the fallback and lists only bills
  not already shown in the payer section.
- Help guide `match-bank-deposits-to-bills.md` (new). Client-only; no schema
  or RPC changes.
