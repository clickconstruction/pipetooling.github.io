# v2.2456 — Activity: weekly prospecting report (2026-08-28)

Fourth slice of the Prospects-refresh arc. The Activity tab showed only Marked/Updated counts per day; the richer data (answer outcomes, call time, callbacks, conversions) was already in the database.

- **New kernel [`src/lib/prospects/prospectWeekReport.ts`](../../src/lib/prospects/prospectWeekReport.ts)** (+9 tests): `weekRange(nowMs, offsetWeeks)` (Monday-start weeks, browser-local time — matching `prospectTeamActivity.ts`'s local-day convention on the same tab), `buildProspectWeekReport(calls, timers, callbacks, users)` → per-user stats (calls, answered, answerRate, timerSeconds, callbacks, conversions — `converted` comments count as conversions, not calls), a Team rollup, and a per-day/per-user daily breakdown; `formatWeekHours`.
- **[`Prospects.tsx`](../../src/pages/Prospects.tsx)** Activity tab: new week section above the old tables — heading with `‹ previous week` / `next week ›` (offset state), per-user cards with an answer-rate bar, "Team" card when more than one caller, and a Daily detail table (Day | User | Calls | Answered | Time | Callbacks). Loader `loadWeekReport` runs four range queries (`prospect_comments` in didnt_answer/answered/converted, `prospect_timer_events`, `prospect_callbacks`, `users` with the same audience filter as `loadProspectTeamActivity`).
- The 30-day Marked/Updated tables remain below under a "Marked / Updated by day" heading — `loadProspectTeamActivity` is untouched (Quickfill's team chart shares it).
- Conversions attribution comes from v2.2452's tagged `prospect_comments` rows, so weeks before that ship show 0 converted.
