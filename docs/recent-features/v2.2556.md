# v2.2556 — Attendance excuse notes + escalation-banner prefill (2026-08-31)

Late-chip design review follow-ups (options G + the prefill), one PR since
both live on the Writeups ledger surface.

- **Excuse notes (migration `20260901004102_attendance_annotations.sql`)**:
  append-only `attendance_annotations` (subject_user_id, work_date, note,
  author_id; latest note per person-day wins; NO update/delete policies —
  corrections are newer rows, like `person_file_entries`). RLS read+insert for
  the Writeups-tab office set (dev/master/assistant/controller), author must be
  self. The late FACT stays derived; only the context is stored — an
  annotation on a day later corrected to not-late is a harmless orphan.
- **Kernel** (`scheduleLateness.ts`): `latestAnnotationByCell`,
  `fetchAttendanceAnnotationsForRange` (untyped client, fail-soft pre-push),
  `addAttendanceAnnotation`; `computeAttendanceSummaryForUser` gains
  `excusedKeys` + `excusedDays` — excused days leave `lateDays`/median (and
  the 30-day banner count) but stay visible as "Late N× (M excused)".
- **Ledger UI** (`WriteupsContractsSubTab`, new `myRole` prop from People.tsx):
  unexcused late rows get "Add note" (office roles) with an inline composer;
  excused rows dim, show the blue "Excused — note · author" pill, and their
  Status column reads Excused. Board chip deliberately unchanged (the day was
  factually late; dispatch sees facts, HR sees interpretation).
- **Banner prefill** (`WriteupEditorModal` gains `initialSubjectUserId` /
  `initialTemplateId` / `contextNote`): "Start a tardiness write-up →" opens
  create mode with the focused person selected, an active template whose name
  matches /tardi/i preselected (none exists yet — owner creates it in Manage
  templates and it lights up), and a read-only amber "From clock records"
  strip: unexcused-lates count, median, five most recent dates — the author
  writes the write-up; the strip is not saved into it.
- Kernel tests for both; plain "New writeup" clears any prefill.
