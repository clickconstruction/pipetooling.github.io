# v2.4273 — Accounts Receivable: the search finds a cheque that was already applied (2026-09-30)

Punch list **#74** PR 1 of 4 (`to-dos/ar-where-the-cheque-went.md`; the prototype beside it). On 2026-09-30 the office searched Accounts Receivable for a $6,077.51 cheque and got *No bank transactions match this search*. It was not lost: Taunya had applied it the day before, so it had left **To match**, the only list the search read. Client only; no migration, no edge function.

## What changed

- **[`src/lib/jobs/arDepositSearch.ts`](../../src/lib/jobs/arDepositSearch.ts)** (new, +test) — the predicate the modal had inline (`matchesArDepositSearch`: counterparty, note, memo, the amount with commas, the posted day as the caller formats it) and `arSearchFallThrough`: the hits on the list on screen, then the rows only All has, never a row twice, with the heading (*Nothing to match · found in All* / *Also found in All*) and what to say under an empty list (`nowhere` once All was searched, `unsearched` before it landed).
- **Help guide *match bank deposits to the bills they pay*** — rewritten in plain words and off `LEGACY_PLAIN_WORDS_GUIDES` (v2.4233: a touched guide leaves the list); the search's new sentence sits in *The deposit list*.
- **`BankPaymentsModal.tsx`** — the first search typed while To match is showing fetches the All rows once (the same `list_mercury_transactions_for_bank_payments` call the All button makes, `includeHiddenArDeposits: true`), kept in `hiddenCandidates` until `refreshList` clears it. Rows found there render as ordinary `ArDepositRow`s under the heading, with their state from the same `arDepositRowStates` rule (applied, returned, closed out — the sweep never claims them), selectable, and the selection effect keeps a selected All row. On the All list itself nothing changes. A failed fetch leaves the pile's own search as it was.

## Decisions taken

- **The row is the answer.** No card, no sentence: the found row wears its chip and, selected, shows the bills it paid, as any row does. The trail line (where it went, who, when) is PR 2.
- **Fetch on the first keystroke, not on open.** All is the whole history; the pile is what the page is for. The fetch is one call, cached for the visit.
- **Amounts still match the formatted figure.** Typing `6077.51` misses `6,077.51`, as before; the test pins it so a later change is deliberate.
