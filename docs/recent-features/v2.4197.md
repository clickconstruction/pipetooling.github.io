# v2.4197 — The bid room offers the alternate as an add-on (2026-09-30)

Alternates round two, PR 3 (after [v2.4211](v2.4211.md)). The review after round one: the signable link was built from the letter's sections, and round one made those the base — a GC who opened the room saw the base amount, no alternate, and signed the base. Two edge functions to redeploy: `sign-bid-room` and `get-bid-proposal-room` (both bundle the shared payload parser).

## What changed

- **The revision payload carries `add_ons`** ([`bidRoomPayload.ts`](../../src/lib/bids/bidRoomPayload.ts) and its server twin): one per offered with-and-without alternate — `key` (`group:<tag>`), the letter's label as `name`, the group's `tag`, `total_cents`, its fixture rows. Built from the letter's offered alternates (`BidRoomPanel` prop `addOns`, both panel sites in the Cover Letter tab); an older revision parses with `add_ons: []`. `roomGrandTotalCents(option, addOns)`.
- **The customer's page** ([`BidRoom.tsx`](../../src/pages/BidRoom.tsx)): under the options, *Add to the proposal, if you want it* — one card per add-on with a checkbox, ticked to start (the letter offers them), the fixtures it covers and *+ $3,220.00*. The scope table lists the ticked add-ons' rows under the option's, the total and the Approve button follow the ticks, and the signed banner reads *with Alternate 1 — Break room*.
- **The signature** ([`sign-bid-room`](../../supabase/functions/sign-bid-room/index.ts), body `addOnKeys[]`, only keys the published revision carries count): the frozen estimate gets one line per taken add-on and the grand total; the `signed` event carries `add_ons_taken` / `add_on_keys`; the staff notice's total is the grand total; and when the plan marks the bid won, **`bids.accepted_alternate_tags` and `agreed_value`** are written — the same two fields the Won dialog writes (v2.4211), so the office's dialog shows the GC's answer already ticked.

## Decided here

- **Add-ons never replace an option.** An in-lieu-of alternate stays a radio option; a with-and-without alternate is a checkbox beside whichever option the GC picks. Both can be on one page.
- **The room's answer wins by arriving first.** The Won dialog only asks when nothing answered yet; a signed room has.
