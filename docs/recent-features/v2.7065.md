# v2.7065 — Bids: the pricing email shows its cents in smaller type (2026-11-12)

Grace's follow-up to v2.7045, 2026-11-12. That change took the cents off the text an estimator shares with a master. She chose to leave the email's cents, then asked: "In the email, could we make the cents a smaller text than the rest of the number?"

## What changed

The pricing table in **Share with a teammate** prints each money figure through a new `packageMoneyHtml`: the dollars at the cell's 13px, then the point and the two cents digits in a 10px span. It is used for the unit price, the line total and the Total. The count is not money and keeps its size.

```
$6,412.50   →   $6,412<span style="font-size:10px">.50</span>
```

The amount is the same to the cent, and a reader who copies the cell gets `$6,412.50`. The style is inline because mail clients strip `<style>` blocks, and in px because the cell's own size is px.

Two copies changed together, as the file headers ask: `src/lib/buildBidPricingPackageHtml.ts` and the edge function's `supabase/functions/_shared/bidPricingPackage.ts`.

## Where it shows

- **The window's Pricing preview**: on the next deploy of the app.
- **Send via my mail**: the table it copies to the clipboard to paste into the mail. The mail's plain-text body is unchanged, because plain text has one size.
- **Send for me**: only after `send-bid-pricing-package` is redeployed. Until then that email keeps full-size cents while the preview shows small ones.
- **The app's own sample of this email** (`customerSampleEmails.ts`), which draws from the same builder.

## Left alone

The text from **Copy for text** (whole dollars, v2.7045), the Pricing tab, print, CSV, the cover letter and everything the GC receives. `formatPackageCurrency` is unchanged.

## How it was checked

- `buildBidPricingPackageHtml.test.ts`: five new cases. The span holds the point and the cents, the visible amount is unchanged with the tags stripped, the table uses it in exactly three cells a priced row, the plain-text body has no span, and the edge function's copy draws the same money cells as the app's.
- A sample email of made-up rows was drawn through both copies and looked at in Chrome at 640px and 375px: the dollars read first, the cents stay readable, nothing scrolls sideways.
- Walked on the local build against production data with every write refused: the real window on a 40-row bid, light and dark. 81 cents spans, all 10px in 13px cells, every money cell still reading `$x.dd`. The table's inline colours are the same in both themes.

## Is this the best we can do?

For the ask, yes, with one size tried. The cents are smaller only, as asked: same colour, same weight, on the same line. 10px against the cell's 13px read clearly smaller and stayed readable at phone width. No other size, and no grey or raised cents, was tried. The size is one constant, `PACKAGE_CENTS_FONT_PX`, in each copy.

Found while here, not changed:

- **The window's preview says "Sale Price" and the email Send for me sends says "Unit price"** for the same column. The two copies of the builder have drifted on that one word. Which word is right is a person's call.
