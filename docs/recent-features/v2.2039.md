# v2.2039 — Checklist activity panel: ✓ Complete / ✓ Post & complete (2026-08-21)

Implements the "Post and Complete" mockup (owner pick: available to everyone
who can post). The shared activity panel's composer gains a green button —
empty draft → **✓ Complete**, note typed → **✓ Post & complete** (the note
posts first so the thread reads in event order). Retires once the target
occurrence is complete. Notably gives Manage its first way to complete a task.

- **Shared completer** `src/lib/checklistCompleteInstance.ts`: sets
  `completed_at/by` (guarded `.is('completed_at', null)`), then best-effort
  completes-notifications ("&lt;name&gt; completed: &lt;title&gt;" — real name from
  `users`, skips self) and next-`days_after_completion` materialization
  (`ymdAddDays`, fixing the UTC-parse day-drift quirk the inline copies had).
  The v2.1842 trigger writes the `completed` event.
- **`ChecklistItemActivity`** gained `onComplete?: (inst) => Promise<boolean>`:
  the host owns the actual completion so each tab's side effects and
  refreshes stay in charge. On success the panel appends the completed line
  and marks its local instance done (button retires in place).
- **Wiring**: Manage → shared completer + `loadItems()` (row moves to the
  Completed one-offs fold); Review rows → shared completer +
  `loadOutstanding()` (row leaves the outstanding list);
  Today cards + Outstanding section → the tab's own `toggleComplete`
  (keeps its optimistic updates + identical side effects).

Verified live end to end with a throwaway prod task (created → note typed →
✓ Post & complete → DB shows comment then trigger-written completed event,
row moved to the completed fold → task deleted). Help guide
`see-a-tasks-full-history-and-notes.md` documents the button.
