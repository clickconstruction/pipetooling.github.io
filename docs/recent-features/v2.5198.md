## The change

- **The kind `schedule`** on `gc-customer-email` (call 1, in place of a `gc-schedule-send` of its own), in `_shared/gcCustomerEmails.ts`:
  - to the customer's contact (`'contact'`);
  - about a `gc_schedule_sends` row, gated by that row read as the caller, so RLS decides (`'row'`);
  - not framed, since the letter carries its own greeting and sign-off;
  - filed as `field_report_gc_schedule` under Statements;
  - no portal line until their portal shows the schedule (PR 15b);
  - up to 80 lines a request (`gcCustomerEmailMaxLines`), a line a stage and a date to meet, where every other kind keeps 30.
- **The function** reads the row as the caller and refuses `otherProject`, and `alreadySent` once its log is set, except as a test. It sends the row's own subject and lines, never the request's, and writes `email_send_log_id` back with the service role before the copy is filed, as the weekly report does.
- **The letter** (`customerScheduleLetter`), lifted from the prototype now that O2's `lateFinish` is on main, into `schedule/customerScheduleSend.ts`. One fix, made in both copies (call 4): a customer row with no contact's name is greeted *Hello,* and the letter goes to the company alone, where the prototype read *Hello Cibolo,*.
- **The row first, then the send** (call 2): `scheduleLetterIo.ts`'s `sendScheduleLetter` keeps the letter as a `gc_schedule_sends` row (`recordScheduleSend`, `scheduleSendRowOf`, dated the app's day), or goes again on the row kept that day with the same letter and not emailed (`scheduleSendRetryRow`). Then it calls `gc-customer-email` with that row. `ScheduleSend.emailed` reads the row's log.
- **The card** (`GcScheduleLetter.tsx`, the prototype's `ScheduleSendCard` with its words) on the Schedule window of a job being built, for those who may move a bar, under **Milestones**, never in the what-if copy:
  - **Read the letter**;
  - **Print the letter**, which keeps no letter row (call 7) and, like every print, files its copy in Documents with `printAndFile` (kind `field_report_gc_schedule`, the job's `gc_schedules` row as its source), as PR 10 files the chart's. Its name is not the chart's **Print or PDF**, so the window never has two buttons of one name;
  - **Send a test to me**;
  - **Send to {first}**.

  Each send is listed newest first, and a row not emailed reads *not emailed yet*. A refusal is said in `gcCustomerEmailRefusal`'s words, with the card's own *That letter went already.* The letter is built from the read's state, never the money read's, so it reads the same whoever sends it (gc 4's note 1).

## Drift from the plan

Two catches from the wider test sweep, and two smaller changes:

- **Print the letter, not Print or PDF** (call 8): the window already has the chart's **Print or PDF**. Two buttons of one name on one window read as one, and `GcSchedule.whatIf.render.test.tsx` found them. The letter's button is named for what it prints.
- **The print files a copy** (call 7): the plan said a print keeps no row, and it still keeps no letter row. The sent-copies ratchet (`sentCopiesCoverage.test.ts`) holds that every print is a send. So the print files its copy with `printAndFile`, as PR 10 files the chart's, rather than growing `PRINTS_OWED`, which only shrinks.
- **80 lines a request for `schedule`**: the parser's cap was 30 for every kind, and a long job's letter has a line a stage and a date to meet. Every other kind keeps 30.
- **No wiring in `GcProjects.tsx`**: the plan named it for the press. The window's own presses carry it, as Tell the trades' do.
