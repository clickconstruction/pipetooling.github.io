# v2.7241 — The dev seat edits a box and fixes a part's typed name on site (2026-11-13)

The owner's yes of 2026-11-13, after the look at a site whose box names said too much. The app got **Edit** for a box in v2.7179 and **Fix the name** for a typed part in v2.7212. The dev seat could add, move, retire and bring back a box, and write deliveries, presses and counts. It could rename nothing, so a site's names could not be tidied through it: a session could read every name and propose a table of fixes, and a person then had to press each one.

## What changed

- **Four verbs, server 0.86.0** (`supabase/functions/_shared/devMcpWrites.ts`, `dev-mcp/index.ts`), one hundred and seven in all:
  - `plan_container_edit` → `apply_container_edit`: `edit = { job_id, agent_label, container, label?, kind?, where? }`. A live box's name, kind and where line by the Edit window's rules (`src/lib/materials/editBox.ts`). A key left out stays as it is, and `where: ""` clears the line.
  - `plan_part_rename` → `apply_part_rename`: `rename = { job_id, agent_label, from, to }`, or `{ job_id, agent_label, undo: <rename_id> }`. A typed part's name on the whole job, by the `job_part_renames` row **Fix the name** inserts.
- **One new wrapper, `dev_on_site_rename(p, p_dry_run)`** (`20261114050000_dev_on_site_rename.sql`), `SECURITY INVOKER` as `dev_on_site_write` is. It writes what the two screens write, under the dev's own RLS: one update of the box, one insert of a rename row. The triggers those writes already fire keep the name history and set the ledger rows. It is a new function and not two more actions in `dev_on_site_write`, which is 350 lines the four working verbs stand on.
- **The plan for a part rename says what the app's window cannot.** It lists every spelling the rows carry now, every box the line is in, the name an undo would put back, and `merges`. A rename that lands on a name a box already holds makes two lines one. The one line's newest count is the newer of the two, so it does not always read the sum. The plan reads `on_site_typed_names_on_hand` and says which: *The two become one line of 14, not 30: the newer count of the two resets the line.*
- **The two records carry the seat's stamp.** A box's name history and a part rename are written by triggers, which knew the caller's own name alone. `on_site_by_name()` hands back `<agent_label> · MCP as <dev>` inside the wrapper's own transaction (`on_site.by_name`, set and cleared around each write), for a dev alone. `job_containers_keep_names` and `job_part_renames_judge` are re-stated whole with that one name changed. A rename made in the app reads the person's name as before, and `by_user_id` is `auth.uid()` whatever the setting says.
- **A replay is refused by the wrapper**, so both applies are state guarded: the box already reads that way, no typed part carries the old name, every line already reads the new one, or the rename was already undone.

## Correction to what I told the owner

I had said a seat verb for a part rename would need no further migration, because inserting the row is the act. That was wrong. The seat's writes go through a short list of dev-gated functions that take a dry run, never through a table. So the verb needs its wrapper, and this PR carries it.

## Not in this PR

- **The name standard of punch list #351.** The seat renames a box to whatever it is asked. It does not yet hold a name to letters, a number and letters.
- **A box's place.** That stays `plan_container` with `action: 'move'`.
- **No rename on any real site.** The verbs are built and tested. Renaming a site's boxes is the owner's press, or his yes to a plan a session shows him.

## Checked

- **The migration**, applied twice to a throwaway local Postgres 15 over stub tables with the real `on_site_line_on_hand`, `dev_on_site_container`, the name-history trigger and all of `20261113230000`, then walked as a dev on the job, a dev off it, a tech on it and a training dev. An edit of all three fields, dry then real: nothing written by the dry run, the box changed by the real one, its code unchanged, one history row stamped with the robot and the dev, the setting empty after. The replay refused. The refusals: a live name taken, Unsorted, 25 characters, a kind of `pallet`; a retired box's name allowed. A rename in the app by a tech reads the tech's name, and a tech who sets `on_site.by_name` by hand is not believed. A part rename over three spellings in two boxes, with another job's row and a book part left alone. A merge in two boxes, one that reads 14 where the sum is 30 and one that reads the sum of 7, each matching what `on_site_line_on_hand` read after the real run. The undo, which separated the merged lines and put back the rows' own spelling. A second undo, an unknown id, a book part's name, an unknown name and a name of 161 characters, each refused in words. A case-only fix where most rows already read the target.
- **The seat's folder**, 868 tests, with every version and count pin moved: server 0.86.0, one hundred and seven verbs, fifty-one over twenty-one RPCs, 153 tools. `devMcpOnSiteRename.test.ts` is new: 17 tests on the input checks, the plan's commitment, and the migration's shape, with the two re-stated trigger functions held equal to their originals but for the one name.
