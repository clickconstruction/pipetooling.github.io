# v2.3100 — Stage Plan PR 2: the Bill tab sets the stage (2026-09-08)

Second PR of the train in [`to-dos/stage-plan/`](../../to-dos/stage-plan/README.md), on the v2.3083 columns and kernel. Client only — no migration, no edge function. The owner's ask: "the stages order or any time should be set in the billing section of this modal" and "help me make the order / any selector on the second line of each line item."

## ① Line Items — the second line is the stage

- [`JobFormFixturesSection`](../../src/components/jobs/JobFormFixturesSection.tsx) takes `plan` (a `StagePlan`). Every named row gets a **badge** at the left ([`StageKindControls.tsx`](../../src/components/jobs/StageKindControls.tsx): numbered circle — hollow for a stage ahead, dark for the stage the job is on, green check once its draw is paid; an amber diamond for an Any row, filled when done; a dashed circle for a plain line) and a **second line**: the **Order / Any / —** selector (`role=radiogroup`, disabled on an invoiced row) followed by the kernel's `stateParts` toned per part — `Stage 2 · on site Sep 9 – 10 · 50% · draw 2 billed Sep 5`, `◆ done Sep 16 · ready to bill`, `not a stage · bills with the final draw`. One hint line under the grid says the rule; ▲▼ is untouched (the numbers follow it).
- The selector writes `stage_kind` through `updateFixtureRow`; the row saves like every other field (the billing autosave slice now carries `k` / `g`). `FixtureRow.stage_kind` / `shared_with_gc` are optional: `undefined` = never loaded / newly added → saves as the column default (`any`); `null` = a deliberate plain line. [`stagePlanForm.ts`](../../src/lib/jobs/stagePlanForm.ts) holds the readers (`fixtureStageFields` reads the DB row loosely, `formFixtureKind`), `stagePlanFromForm` (form rows → the kernel, array position = sequence), `drawLabelsByInvoiceId`, `upcomingDrawRows`.
- Data: [`useJobStagePlanInputs`](../../src/hooks/useJobStagePlanInputs.ts) loads the job's `job_stage_windows`, the `step_commitments` on them and those orders' `people_labor_jobs` (stage, progress); line items, invoices and payments are the form's own state, so the plan follows every keystroke. `JOBS_LEDGER_FIXTURES_EMBED` selects the two columns; the hydrate spreads them onto the row.

## ② Invoices — draws follow the stages

- [`JobFormSegmentsBar`](../../src/components/jobs/JobFormSegmentsBar.tsx) takes `plan`: blocks run in plan order (Order by number, Any, plain) and take their color from the row's `draw` — paid (green), billed (blue), drafted (light blue: a Ready to Bill invoice exists), ready to bill (amber: nothing drafted, the rule says it may be), waits on its stage (amber, hatched), later (grey). The legend matches; the block tooltip says the draw in words; one rule line under the strip. The dollar-coverage hatching, the Make Invoice track and the per-segment checkbox rows are untouched — the rule guides, it does not lock the manual paths.
- [`JobFormUpcomingDraws`](../../src/components/jobs/JobFormUpcomingDraws.tsx) — **Still to bill**: every uninvoiced row with money, in plan order, with what it waits on (*after it passes inspection*, *passed · waits on stage 1*, *bills when the work is done*, *with the final draw*). A `ready` row is tinted amber and carries **Bill it** → `billStageRow(fixtureId)` in the modal, which selects that one segment and runs the existing segment-invoice path (`createInvoiceFromSelectedSegments` became `createInvoiceFromSegmentIds(selection)`; the button is the only new caller). The invoice list ([`JobFormInvoiceList`](../../src/components/jobs/JobFormInvoiceList.tsx)) prints the draw label under the status chip — *Draw 2 · Top-out*, *◆ Relocate water heater*.
