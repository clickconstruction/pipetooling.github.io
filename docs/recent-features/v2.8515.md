# v2.8515 — Customers: the remove-a-contact window opens on Keep them (2026-11-24)

Seen on the live walk of the #416 small-fault fixes (2026-11-24, `to-dos/document-builder-whats-left.md`): the window v2.8438 put before **Remove** opened with the focus on **Remove ZZ Test Walk Sink**, so Enter removed the contact. Client only: no migration, no edge function.

## The cause

`removeContactConfirm` (`src/lib/customers/removeContactConfirm.ts`) asked with `danger` alone. The shared confirm window puts the focus on its confirm press unless the question says Cancel is the safe answer.

Reproduced before the change: the new render test, run against the old kernel, found the focus on the remove press.

## What changed

- The question now says `cancelIsSafe`. **Keep them** takes the focus and is drawn blue, and **Remove …** stays red, the way the legal firm's **Retire** window and the email count's remove window already read.
- The words, the press that names the person and what each press does are unchanged.

## Tests

- `removeContactConfirm.test.ts`: the question carries the safe answer, with and without a name.
- `CustomerContactsSection.render.test.tsx`: the window opens with the focus on **Keep them**, and nothing is deleted.
- Not seen: the window in a browser after this change. The render test is jsdom's.
