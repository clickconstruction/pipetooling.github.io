# v2.2328 — Title Case policy for job addresses (2026-08-26)

Owner ask following the comma sweep: capitalize the first letter of every
address word — fix the backlog and normalize at entry.

- New kernel `src/lib/addressTitleCase.ts` (+8 tests): `titleCaseAddress`
  title-cases all-lower and ALL-CAPS tokens while passing deliberate mixed
  case through untouched (McQueeney, O'Neil). Conventions: KEEP_UPPER
  abbreviations (TX/FM/RM/CR/US/IH/SH/PO + directionals), glued road numbers
  ("fm1117" → "FM1117", "i35" → "I35"), ordinals ("5TH" → "5th"), suite
  letters ("200b" → "200B"), hyphen parts ("ih-10" → "IH-10"), connective
  words small mid-address ("Ranch to Market Rd"), Mc/apostrophe fix-ups when
  folding case.
- Policy wiring (all four touch points agree):
  - New-job insert (`JobFormModal`) and the Edit Job autosave identity slice
    (`jobFormAutosaveSlices.ts`) store `titleCaseAddress(trimmed)`.
  - The address input normalizes on blur, so the operator sees the stored
    form.
  - The comma nudge (v2.2323) previews and applies in Title Case.
- Backlog: the supervised sweep gained a casing pass driven by this same
  kernel via vite-node (scratchpad tooling, not shipped code) — entry policy
  and data cleanup can never disagree.
