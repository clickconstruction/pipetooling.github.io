# v2.3714 — Day book PR 7: past days say how many approvals were still waiting (2026-09-22)

PR 7 of [`to-dos/day-book`](../../to-dos/day-book/README.md) (punch list #20), built as a query instead of the snapshot the plan drew. One migration, client.

## What the plan said, and what changed

The plan's PR 7 was a `day_book_queue_snapshots` table filled nightly by a cron so history could carry *left* figures and the Month grid could go amber. The second "best we can do" pass asked whether the queue could be **reconstructed** instead. For approvals it can, exactly: a clock session's clock-out, approval, rejection and revocation are all stamped, so "how many were waiting at the end of Tuesday" is one count over timestamps — no table, no cron, no drift between the snapshot and the truth, and true for days before this change.

For the other kinds it cannot: an invoice's "ready to bill" moment is not stamped; the bank-deposit count applies a settings filter for a signed-in caller and the gated RPCs refuse a cron; the contract rule is a client kernel. Those stay live-today-only. A nightly snapshot for them would have to run as a named account (`set_config` of a dev's claims inside the function) — an owner call, now on the to-do rather than built quietly.

## The change

- **[`20260922110000_day_book_queue_history.sql`](../migrations/20260922110000_day_book_queue_history.md)** — `get_day_book_payload` re-created with a `queue` key: `[{ day, kind: 'approvals', n }]` for every day of the range up to today, `n` = sessions clocked out before the day's end and not approved, rejected or revoked by then. And the population follows the roster rule: sample accounts, digital twins and archived users are out (v2.3698's rule; a twin's approvals were nobody's day).
- **Kernel** — `DayBookQueueRow`, `payload.queue?` (absent from an older payload), `dayBookQueueHeldWork(payload)` → the `(chip, day) → true | false | null` the Month grid takes, `dayBookHistoryLeft(payload, line, day)` → *48 still waiting* / *none left waiting* on a past day's Approved line.
- **The tab** — the grid's `queueHeldWork` reads the payload instead of answering null; a past day's Approved line ends with the reconstructed figure; today's figures still come from the live hooks.
- Help guide: the *Reading a month* and *today's rows* paragraphs say which kinds carry history.
