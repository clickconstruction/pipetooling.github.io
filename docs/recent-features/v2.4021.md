# v2.4021 — My Time day editor: what Save writes to the clock has tests — `lib/myTimeDayPersist.ts` (2026-09-28)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 10 (`to-dos/decomposition-queue.md`): step 6 of `docs/MY_TIME_DAY_EDITOR_MODAL_ARCHITECTURE.md`, after [v2.3967](v2.3967.md). The map ranks it the highest-risk move in the file: it writes payroll hours.

## Why

`persistDirtyChangesAsync` is the day editor's save — for each dirty cluster it walks an ordered ladder of nine branches that insert, update or call one of six split / replace RPCs on `clock_sessions`. It could only run inside the mounted editor, which has no test, so five of its nine branches had no test anywhere.

## What shipped

- **[`src/lib/myTimeDayPersist.ts`](../../src/lib/myTimeDayPersist.ts)** — `persistMyTimeDayDirtyClusters(input)`: the ladder's 265-line body moved **word for word** (diffed against main, identical but for indentation), taking `dirty`, the clusters, the split state, `nowTick`, the subject user, the day, the People → Hours seed flag and the RPC trio. It throws `DatabaseError` with the same messages and returns `{ salarySyncMayAdjust }`. `myTimeDayPersistRpcs(editingSelf, fenceOverridden)` picks `own_*` or `leader_*` as before; `MY_TIME_SALARY_SYNC_SAVED_NOTE` is the toast text.
- **The editor** keeps `persistDirtyChangesAsync` as the try / catch around it — `setError` on failure, the salary toast on success — with the same dependency list. 2,687 → 2,414 lines.
- **Tests** — `myTimeDayPersist.test.ts` (64), written by a second session on this branch: every reachable branch over a supabase stand-in that logs each insert, update and RPC call in order; the exact values written; every refusal's message; order across clusters; a refused database write mid-block and mid-day; the RPC choice by identity.
- **The map** marks step 6 done and gains quirks 24–27.
