# v2.5798 — Messages: the sort card asks who the sender is, by name and address or number (2026-10-23)

The owner, 2026-10-23, on an Invitation to Bid's thread on `/messages`: "Instead of Who is this? I think we should make it more clear like 'Who is [Name and email/phone]?'" The sort card's head said *Who is this?* under a header that already said the name and *An address nobody has named*, and the address itself showed nowhere on the screen, since the header's numbers-and-addresses fold is hidden until the sender is named.

- **The kernel** ([`newLane.ts`](../../src/lib/followUp/newLane.ts), `whoHead`, [tested](../../src/lib/followUp/newLane.test.ts)): the name first, then the address or the number after a comma, the owner's pattern. An email with a From line reads *Who is Dale Ferris, dale@ridgeway.example?*; a text whose line says *this is Kevin Alvarez* reads *Who is Kevin Alvarez, 210-555-0188?*; a bare number reads *Who is 512-555-0142?*; a name alone, *Who is Pat Former?*; nothing known falls back to `SORT_HEADS.who`. The name is `senderFacts`' (the line's *this is …*, else the From line's), the rule the guesses already read, so the head and the guesses never disagree. `numberWords` writes a ten-digit number with dashes, since parentheses inside a sentence fail the plain-words rule and the owner wrote it that way; anything else as it came. When the contact has both a number and an address, the channel the line came on goes first.
- **The card** ([`NewLaneCard.tsx`](../../src/components/followUp/NewLaneCard.tsx)): takes the contact's `channels` from [`NewLaneSlot.tsx`](../../src/components/followUp/NewLaneSlot.tsx) and draws the question as its title with `overflowWrap: anywhere`, so at phone width a long address drops to its own line and breaks inside only when it still does not fit. The region keeps the sort's head (*Sort: Who is this?*), *Which of ours?* keeps its own, and the sentence under the head (`whoWhy`) stays as it was: it names nothing the head says.
- **The two other places that say the bare words stay**: the thread header's **Who is this?** button (v2.5541) sits right under the name, and the New row's pill (v2.5793) sits beside it, so a question that carried the name would say it twice on one card. Needs a reply's **Who is this?** act, the same.
- **Tests**: the kernel (an email, a number alone, a name and a number, the line's name over the From line's, both channels, a long address passing plain words, nothing known, `numberWords`), every head in the plain-words sweep; [`NewLaneSlot.render.test.tsx`](../../src/components/followUp/NewLaneSlot.render.test.tsx) with an email sender and a number sender, the wrap style and the unchanged sentence; the thread window's sort-card smoke on the new head.
- **Guide**: *sort new messages before anyone answers them* § Sort one, with the example's chip. **Docs**: `MESSAGES_ARCHITECTURE.md`'s Follow up paragraph, the Glossary's Messages entry, the page map's §22. The guides `find-every-message-with-a-person-in-one-place` and `see-who-is-waiting-on-us-and-what-we-owe-them` quote the header's button, which keeps its words, so they stand.

## Is this the best we can do?

- The question now carries the one fact the office needs to answer it, the address or the number, which the header hid behind the fold until the sender was named.
- The head reads the same name the guesses read, so a card never asks about one person and offers another.
- Checked live as the dev on a ZZ test sender, never a real customer's thread; the real Invitation to Bid row was only looked at.
