## The owner's pick

The to-do offered three: (a) only whole-job report templates count, (b) a report filed before the job last entered Working is out of scope, (c) leave it. The opinion column recommended **b** and the owner took it 2026-09-18 (*"do the pipeline cell item 2"*).

## Why b

J931 Heron Construction ($48,700, Top Out, hand-set 40% from the Aug 7 seed) last entered Working on **2026-08-20**. Its only report answering *How complete is the job?* is the Jun 23 Status Report on a toilet-and-sink visit — **100%** — filed during an earlier run (Working Jun 23 → billed Jun 30 → Working Jul 13 → Ready to bill → Working Aug 20). The Pipeline row already hid it (the seed's 40 wins, v2.3432), but `list_latest_report_completion_pct` still returned the 100 with `manual_at` NULL (a seed is not a hand-set), so Job Summary's % column, Burn and the Ready-to-bill prompt read the job as done. Rule (a) would need every template classified and would still count a whole-job report from a previous run; (b) needs one CTE and is what the status ledger already knows.

## The change

`list_latest_report_completion_pct`: a `current_run` CTE (newest `job_status_events` row with `to_status = 'working'` per job) and one condition on the candidate reports — `created_at >= working_since`, or no Working event at all. Everything else is v2.3372's. The two readers are unchanged: with no row for J931 they fall through to the job's own `pct_complete` (40), which is what the row says.
