# v2.2057 — Checklist scheduling overhaul 3/4: edits regenerate occurrences (2026-08-22)

Fixes B2 from the anatomy investigation: the Edit modal updated the template
and left every occurrence on the old schedule with the old people.

- **`src/lib/checklistEditRegenerate.ts`** (IO applier over the pure
  `planEditRegeneration` kernel from v2.2055): on edit save —
  - one-offs (and never-completed after-completion chains) **move** their open
    occurrence to the new date (same row — notes/events ride along);
  - weeklies **delete future clean occurrences** that no longer fit and
    **create** the ones the new config wants within the 35-day horizon
    (upserts against the unique index); past, completed, and discussed
    occurrences never move; in-flight after-completion chains keep their
    cadence;
  - **roster sync**: every incomplete occurrence's instance assignees are
    re-pointed at the current roster — a reassigned task lands on the new
    person's Today list immediately, including already-overdue one-offs.
- `ChecklistItemEditModal.handleSave` calls the applier after the template
  update; failures surface in the modal error.
