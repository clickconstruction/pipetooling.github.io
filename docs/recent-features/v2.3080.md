## Teacher attribution

A shadow scores against whichever estimator sends the reference. b481 (Galloway Park) scored against Grace's number — practice, not the calibration standard — and the gate math could not tell.

- **`users.calibration_standard`** (boolean, owner-set): the estimator(s) whose sent numbers are the standard. Wendi is set true by the migration; nobody else.
- **`twin_shadow_runs.teacher_user_id` / `teacher_name`**: stamped by `score_shadows` from the reference bid — assigned estimator, else the sender who attested the send, else the creator. Already-scored runs are backfilled the same way.
- **`list_shadow_runs()`** returns `teacher_name` and `teacher_standard`. Before scoring it shows the reference's assigned estimator (who *will* teach); names are not money, so the seal is untouched. The function is dropped and recreated because its return type grew.
- **Gate math** (both the server scoreboard in `score_shadows` and the client kernel `confidenceBoard.ts`): a scored shadow with `teacher_standard === false` is a **practice** run — shown in the ledger with an amber PRACTICE tag, counted on the axis card ("1 practice-teacher run set aside"), never a Gate-B slot and never able to break a streak. Backtests carry no teacher and keep their `gate_eligible` flag. `null` standing (client ahead of the migration) behaves exactly as before.
- **Surfaces**: Scoreboard ledger gains a Teacher column (name + ✓ standard / PRACTICE); the Shadows lens card gets a "teacher: Wendi ✓ standard" line; the `[shadow SCORECARD]` ledger note reads "… vs human $X by Grace (practice teacher — not a gate run)". The ledger also finally renders `status = 'void'` runs as VOID (they were showing as pending).

## Plans readable by robots

A live bid whose plans link the Drive intake service account cannot read is invisible to the shadow program (b480 blocked on exactly this on 2026-09-06, and nothing on the board said so).

- **`bids.plans_robot_readable` / `plans_robot_probed_at` / `plans_robot_probe_note`**: the probe's verdict. NULL = never probed (treated as readable until proven otherwise).
- **plan-fetch `?probe=1`**: a Drive *metadata* GET with the service-account token — no bytes — recorded on the bid. Folder links, non-Drive links, non-PDF files, 403/404 all come back `readable: false` with a plain-words reason. **`?probe=all&limit=N`** sweeps live bids never probed or probed >24h ago (`force=1` re-probes everything; cap 100). Any authorized caller (twin token or staff JWT) may probe — presence-level only; the file name is returned to staff, not twins. A real byte fetch also records its outcome, so a failed pipeline pull marks the bid.
- **twin-mcp**: `get_shadow_queue` and `next_shadow` run a bounded, best-effort sweep first (15 bids, 12 s timeout, the caller's own token forwarded), then exclude `plans_robot_readable = false` bids. The queue lists them under `unreadable` with the reason; coverage reports `unreadable_by_robots`; the dispatcher reports `skipped_unreadable` when it runs dry.
- **Bid Board**: the robot icon on a live bid turns red with a small ✕ when the plans are unreadable; the tooltip carries the reason and the fix (share with the service account, or link the PDF itself). Read through a cast until the types regenerate.
- **Scoreboard**: an amber pill "N plans unreadable by robots · b480, …" beside shadow coverage, with per-bid reasons in the tooltip. Kernel `shadowCoverage.ts` returns `unreadable[]` alongside `covered/live` (an unreadable bid that already has a shadow is covered, not listed).
