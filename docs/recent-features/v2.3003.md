# v2.3003 — Test-gap audit, pass 20: the Forecast stage line-items layer gets its first tests (2026-09-07)

Follow-up to v2.3002. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`projectsForecastStageLineItems.ts` (374 lines) is the data layer under **Projects → Forecast → stage modal → Line Items For Office**, and its URL / amount / date formatters are also reused by the Jobs Sub Labor tab and the job-address links. It loads a step's line items, the "+ Add PO" and "+ Add Supply House Invoice" picker options, saves and deletes lines, fabricates a memo and amount when a PO or invoice is attached, and loads the View PO / View Invoice popovers. Three callers, no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Picker options are the newest hundred (finalized POs by creation, invoices by invoice date); a PO with no items totals zero, and no PO means no second query.
- A saved line trims the memo, parses the amount (unparsable → 0), cuts the date to a calendar day (blank → null), normalises the link (blank → null), and appends after the highest sequence (first line → 1). An edit updates by id and never renumbers.
- Attaching a PO writes `PO: <name> - <n> items, $<total> total` with the PO id stamped; a nameless PO reads "Purchase Order". Attaching an invoice writes `Invoice #<number> - <house> - $<amount>` with the invoice id stamped; an unknown house reads "Unknown".
- Every failure names the action ("Failed to add line item: …", "Failed to load PO items: …", "Failed to load invoice: Not found") so the section can show it as-is.
- `formatLineItemDate` reads the calendar day off the text, so a UTC-midnight timestamp does not shift a day; `normalizeUrl` repairs `http//` and protocol-relative links and adds `https://` to bare hosts.
