# v2.2996 — Team board: the `?teamLaborJob=` deep link jumps to the job's last week with hours (2026-09-07)

Found on the post-deploy walkthrough of the Team train (v2.2974 / v2.2978 / v2.2981 / v2.2986) on clicktooling.com. Client only.

- **Bug**: Edit Job → labor cost panel navigates to `/jobs?tab=combined-labor&teamLaborJob=<id>`. `JobsTeamTab` opens on the current week; a job whose hours were last week (JP878 · Take 5- Seguin on 2026-09-07) has no row there, so the focus effect found nothing, stripped the param, and the user saw an unrelated week. The old Team Labor table listed every job, so this was a regression in the link's usefulness.
- **Fix**: when the focused job has no row on the loaded week, `fetchLatestWorkDateForJob` (newest live closed session's `work_date`) picks its week, the tab jumps there with an info toast ("Showing the week of Sun 8/30 — the last week with clocked hours on this job"), then the existing scroll + highlight runs. A job with no sessions at all behaves as before (param consumed, current week).
- Render test unchanged (19 pass); the jump is guarded by a ref so it runs once per focus.
