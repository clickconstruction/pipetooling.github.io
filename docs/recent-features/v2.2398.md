# v2.2398 — Assign-search add door (Workbench) + entry-target fix (2026-08-27)

Wendi: "need ability to add new from dropdown like on the old page" — screenshot
showed an Exact search with three near-misses and no way to add the right entry.

`BidsPricingTab.tsx`:

- **Both assign dropdowns** (Old "Search or assign…" + Workbench "assign…") now
  render a persistent footer row — `+ Add "<term>" to the book` — whenever the
  search is non-blank, matches or not (near-misses are exactly when a new entry
  is needed). It opens the existing entry form pre-filled with the term via the
  new `openAddEntryFromAssignSearch` helper. The Workbench empty state's "add
  it in the Old view" hint is gone.
- **Targeting fix**: since the drawer rework (`templatesMode = true` constant),
  `savePricingEntry` always wrote to `panelVersionId` — the shared TEMPLATE
  catalog — while the assign dropdowns search `priceBookEntries` (the bid's
  ACTIVE pricing scenario). So the Old page's "Add to Price Book" button filed
  entries where the dropdown would never see them. New
  `entryFormTargetPricing` flag (set by the assign-search opener, cleared on
  close): save inserts into `selectedPricingVersionId` and reloads
  `loadPriceBookEntries`, so the entry appears in the search immediately.
  Drawer "Add entry" is unchanged (still the template catalog).
- Bonus effect verified live: because the grid name-matches book entries to
  count rows, adding an entry named after the row prices that row on the spot.

No schema changes. Verified on BP398 (footer renders with matches present,
form pre-fills, entry count 111→112 in the bid's book, row auto-priced).
Test residue: BP398's WENDI pricing gained a "Toilets · $1,500" entry.
