# v2.4864 — Labor: hours you typed stay when a fixture leaves the counts (2026-10-07)

Punch list #73, PR 0b ([`to-dos/bid-history`](../../to-dos/bid-history/README.md)): the second "stop the losses at the source" fix. Labor rows are keyed by fixture name and belong to the bid; count rows belong to a version. The Labor tab's load sync deleted every labor row no counted name claimed and minted the book's hours for every counted name with no row. So typed hours were lost three ways: a re-import that renamed a fixture (v2.4188 lifted the `[Group] ` prefix off names), **a switch to a version without the fixture** (found while building this PR), and a fixture removed and counted again. Migration `20261008071000_labor_rows_unmatched.sql` ([doc](../migrations/20261008071000_labor_rows_unmatched.md)); no edge function.

## The change

- **The plan** ([`laborSyncPlan.ts`](../../src/lib/bids/laborSyncPlan.ts), pure): a counted name with no row of its own takes, in order, its set-aside row of that exact name (the newest), a live row whose name differs only in case, spacing or a `[Group] ` prefix (renamed in place), a set-aside row matched the same loose way, and only then the book. A loose match never guesses: when two counted names, two live rows or two set-aside rows share a key, none of them is matched by it. A live row nobody claims is **set aside**.
- **The table** `cost_estimate_labor_rows_unmatched`: the labor row's columns plus where it came from and when. It is a separate table, not a flag, because pricing history, job budgets, baselines, the breakdown and the copies all sum `cost_estimate_labor_rows`, and a fixed (task) row counts its hours at any count.
- **The sync** (`useBidPricingEngine.loadCostEstimateLaborRowsAndSync`): renames, sets aside (copy, then delete; the copy goes again if the delete fails), takes back (insert, then delete the set-aside row), then mints and moves counts as before. While the table cannot be read or written (the minutes before the push), an unclaimed row is deleted as before.
- **The tags**: each step carries its own `x-bid-action` (PR 1b): `labor-rename`, `labor-park`, `labor-take-back` (the app's own, `bid_changes_app_actions()` and `BID_APP_ACTIONS`), and `labor-use-parked` for the band's Use for (a press). The table joined the ledger's list (eighteen tables), so the history reads "renamed", "set aside", "taken back" instead of "deleted + minted".
- **The band** ([`BidsLaborUnmatchedBand.tsx`](../../src/components/bids/BidsLaborUnmatchedBand.tsx)): *Hours not on the counts* under the hours grid, one line per set-aside row with its hours and the day; **Use for…** then **Use for <fixture>** writes the hours (and how they read) onto a counted row; **Remove**. Nothing is drawn when nothing is set aside.
- Recently deleted names the table *set-aside labor hours*.
