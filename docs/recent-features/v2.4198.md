# v2.4198 — The Bid Board's "+$ alt" chip follows the price (2026-09-30)

Alternates round two, PR 4 (after [v2.4197](v2.4197.md)). No migration, no edge function. Round one stamped the add-on amounts only on a send, so a priced-but-unsent alternate showed nothing on the board, and repricing after the send left the chip stale until the next *Mark sent*.

## What changed

- **A live stamp in [`BidsCoverLetterTab`](../../src/components/bids/BidsCoverLetterTab.tsx)**: an effect keyed on the bid, its saved wording and `coverLetterPricingRows.byAlternate` (the active version's split, memoized in [`useBidPricingRows`](../../src/hooks/useBidPricingRows.ts)) runs `stampAddAlternateAmounts` and, when the result differs from what is saved, writes `cover_letter_alt_texts` after an 800 ms debounce. Offered flags and wording are untouched (the kernel keeps them); an open wording editor stays open (the write goes around `saveAltTexts`, which closes it).
- **Guarded by hydration**: `altTextsLoadedFor` holds the bid id whose wording is on screen; the stamp never runs against the empty texts of a bid still loading, which would have wiped the saved Offer ticks. A refused write (a read-only seat) clears the flag and stays quiet — the letter on screen is already right.
- **The send path is unchanged** — *Mark sent today* still stamps, now a no-op when the chip is already current.
