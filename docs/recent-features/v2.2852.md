# v2.2852 — Every "% done" says where it came from, every profit number says what it excludes (2026-09-05)

Journey map Phase 4, Tier-1 #5(b)+(c) — follows #5(a) (v2.2840, PR #2581), which gated the paid-invoices → 100 override and made `resolveJobSummaryPercentCompleteWithSource` return a `source`. Findings closed: J6-3 (the % cell had no source), J6-N2 (Job Detail header % is the raw office pct with no label), J2-F1 (the report slider opened on 0 on a 30%-done job), J6-4 / J6-5 (four profit-shaped numbers per job, none labeled; the assistant's chart says "+$35.7k profit" before labor), J8-F4 (Crew P&L "Billing" = gross bill). No migration; no math changed anywhere.

## (b) One "% done" provenance badge

- New pure kernel [`src/lib/jobPercentProvenance.ts`](../../src/lib/jobPercentProvenance.ts): `percentProvenanceLabel(source, { reportedOn })` → **"crew report Aug 27"** (date on the company calendar when known, else "crew report") · **"set by office"** · **"fully collected"** · null for `none`; `percentProvenanceTitle` (hover sentence per source); `latestReportPercent(reports)` (newest report carrying a completion %, with its `created_at`); `recordedPercentProvenance(pctComplete, reports)` — provenance of the RECORDED `jobs_ledger.pct_complete`: reports mirror their % into that column (v2.1833), so when the newest report % equals the recorded value the crew said it, otherwise the office did.
- [`PercentProvenanceChip`](../../src/components/jobs/PercentProvenanceChip.tsx) renders it (theme tokens; `data-pct-source`). Surfaces:
  - **Job Summary row** (`JobsJobSummaryTab.tsx` % cell): from `enriched.pctSource`; the date comes from the lazy `jobSummaryReportsByJobId` cache via `latestReportPercent`, so it appears once the row has been expanded — `list_latest_report_completion_pct` returns no date (follow-up below). The % header tooltip now explains the three badges.
  - **Stages activity header** (`JobActivityView.tsx`, also the full-screen expand modal) and **Job Detail** (`JobThreadNotesPanel.tsx` beside "N% complete"): `recordedPercentProvenance(pctComplete, reports from the activity items)`; the badge only renders when the merged activity (with reports) was supplied.
  - **Report modal** (`NewReportModal.tsx`): on a ledger job it reads `pct_complete` + the last 25 reports (one query each, best-effort) and seeds every untouched `percent_0_100` field with the job's current % — `seedUntouchedPercentFields` — so the slider, Copy as text and the saved report all say the same number; `reportPercentSeedHint` renders "**Currently 30% — move to update · crew report Aug 27**" under the label (→ "Was 30% · …" once moved). `ReportTemplatePercentField` gained a `hint` prop. Untouched ⇒ the report files the seed, `reportPctToPropagate` sees "unchanged" and the job's % does not move (before this, an untouched slider normalized to `'0'` and could propagate 0). A touched 0 still becomes the job's %. Bids/projects/jobs with no % keep the old 0 start.

## (c) Label the profits where they live

- New pure kernel [`src/lib/jobs/profitLabels.ts`](../../src/lib/jobs/profitLabels.ts) — `PROFIT_FIGURE_LABELS` keeps the names the code already had (v2.2692) and adds the exclusions: **Gross** ("revenue − team labor − subs − parts. Before overhead."), **True profit** ("gross − the job's overhead share. The bottom line."), **Margin before team labor** (Job Detail band: "Total Bill − parts − sub labor. Team wages and overhead are not taken out"), **Cash position** (charges chart green line: "payments received − charges to date"). `chartCashLegendLabel(teamLaborIncluded)` / `chartCashTooltipLabel` add "before team labor (wages not included)" when the viewer's chart strips wages. `CREW_PNL_BILLED_LABEL = 'Billed (gross)'` + tooltip.
- Surfaces: Job Summary Gross / True profit headers take label + tooltip from the kernel; `JobDetailProfitSection` cell "Profit" → "Margin before team labor" (tooltip) + one-line footnote; `JobSummaryChargesTimelineChart` legend "Green = profit" → "= cash position (paid − charges)" (or the before-team-labor form), tooltip row "Profit:" → "Cash position:", series name likewise; new `teamLaborIncluded` prop — the tab passes `showTeamLaborAndProfit`, `JobChargesTimelineStandalone` passes `includeTeamLabor`, the view defaults to true. `JobsCrewPnlTab` "Billing" → "Billed (gross)" (main + drill-down headers, tooltip) and the audit footer opens with what the column is.
- **Not in this PR (the larger half of (c)):** one shared earned-revenue kernel for Job Summary, Crew P&L and the board — Crew P&L still credits the gross bill by hours while Job Summary shows earned (contract × %) revenue for in-progress jobs (v2.2686/2688 name this open). The labels make the difference legible; unifying the math is the follow-up.
