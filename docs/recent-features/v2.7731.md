# v2.7731 — Stages: the row context is built once (2026-11-17)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 2 (`to-dos/decomposition-queue.md`): the Stages map's step 13 (`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`).

## What shipped

- **`src/components/jobs/stagesRowContext.ts`** (new, a pure kernel): `stagesRowContext(props, hooks)` builds the forty-key `StagesRowRenderContext` from a list's flat props and what the list takes from its own hooks (the router, the dispatch-task and checklist windows, the customer profile, the hours story, the session notes). It names its keys one by one, so the context holds what the rows read and none of the rest of the bundle.
- **The four lists** call it where each wrote the context out by hand: `JobsStagesTable` and `JobsStagesUnifiedTable` (42 lines each, identical), and the two card lists in `JobsStagesCardList` (38 lines each, identical). The tables' destructures lose the 56 names that only fed the old literal.
- **One difference between the copies is gone, on purpose.** The card lists' copies left out the four property-badge keys (`propertyKindByJobId`, `onPropertyKindSaved`, `propertyLinkByJobId`, `onPropertyLinked`). Their one reader is `renderJobAddressWithMap`, which no card calls, so the cards' context now carries them and draws the same.
- **Sizes**: `JobsStagesTable` 531 → 472 lines, `JobsStagesUnifiedTable` 429 → 366, `JobsStagesCardList` 1,470 → 1,411; the builder is 61.
- **Docs**: the Stages map's substrate paragraph, file table, the two table dossiers, the master summary and step 13.

## Tests (+10)

- `stagesRowContext.test.ts` (6): the forty keys and no other; the windows and the router come from the hooks, never the bundle; every other key from its own name in the props; values handed on as they are; the rest of the bundle left out; a key the list did not get stays, undefined.
