## The sweep

**`scripts/render-smokes-settle.mjs`** (dry run by default, `--write` to apply) walks every `src/**/*.render.test.tsx` and finds the line pair the three flakes shared: a render call (`render(`, `renderWithProviders(`, a file's own `renderX(` / `openX(` helper) followed by a synchronous read or click — `fireEvent.`, a `getBy*` / `getAllBy*` / `queryBy*`, a `.value` / `.disabled` / `.checked` read. A next line that already `await`s (a `waitFor`, a `find*`) is left alone. In a file whose component does async work at mount — it stubs `supabase` or resolves promises from a mock — the script inserts `await settle()` between the two lines, imports `settle` from the harness (extending the existing import or adding one), and makes the enclosing `it()` async. A file with no async mount work is static markup: nothing races there, and it is left as it was. A read that means the **first** paint — a spinner, a pre-load state — opts out with `// first paint` on the line above it, and the script counts it and moves on, so re-runs stay quiet.

The count, as the to-do asked: **263 render smokes · 707 render→sync-read pairs · 85 files left alone (no async mount work) · `await settle()` inserted at 376 places in 84 files**; 0 opt-outs were needed.

## What the sweep found

Two reads in `ChecklistTechTreeTaskCardModal.render.test.tsx` had been passing only because they ran on the first paint: `getByText('Robert')` matched the assignee chip alone; once the activity thread settles, the thread's author line reads Robert too and the query finds two nodes. Both now read `getAllByText('Robert')` — the settled screen, which is what the tests describe ("the loaded activity thread"). Those two lines are the one hand edit in the sweep; a conflict there re-applies them after the script.
