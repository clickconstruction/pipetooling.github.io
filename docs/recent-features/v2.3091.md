# v2.3091 — Calibration standard picker in Settings → Digital twins (2026-09-07)

Client only. No migration or edge-function change.

## Why

v2.3080 introduced `users.calibration_standard` — the estimator(s) whose sent numbers the robot program calibrates to; a shadow scored against anyone else is practice and never a Gate-B slot. The flag was set on Wendi by the migration and had no other door: a new standard, or Wendi stepping back, would have meant another migration. Diane asked for the switch under Settings → Digital twins.

## What shipped

- **Kernel `src/lib/twinTeachers.ts`**: `teacherCandidates(users)` — estimating roles (`estimator`, `dev`, `master_technician`, `assistant`), not a twin, not archived, plus anyone already flagged so a flag can never hide; standards first, then by name. `calibrationStandardSummary` (one line: who the standard is, or a warning that nobody is and Gate B cannot be met) and `calibrationStandardToast`.
- **Card "★ Calibration standard"** in `DigitalTwinsPanel` (dev only, like the rest of the panel), between the twin questions and the run ledger. Each candidate row: name, role, STANDARD/PRACTICE chip, and a "Make standard" / "Make practice" button. The write is a plain `users.update` under the "Owners can update users" policy (dev), with the v2.3058 refused-write guard so a filtered row says "didn't apply" instead of closing quietly. The card hides while the column is not deployed (the select fails soft).
- The flag is read by `score_shadows` and the Scoreboard gate math on their next run — no reload of anything else.

## Tests

`twinTeachers.test.ts` (7): role/twin/archived filtering, flagged users never hidden and sorted first, email fallback sort, the three summary forms, both toast directions.

## Help

`audit-a-robot-bid` gains a short "Who the robots calibrate to" section.
