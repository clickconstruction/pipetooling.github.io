# v2.6544 — Every evidence file on an HR file carries its hash, so a record and a folder are matched by the same number (2026-11-05)

Punch list #269, PR 1b. The owner's case folder keeps SHA256 lists beside its exhibits; the evidence records had no hash, so a file in the app and the same file in the folder could be matched only by name. Migration `20261105230000_evidence_sha256.sql` ([`docs/migrations/`](../migrations/20261105230000_evidence_sha256.md)): push after the merge, then redeploy `dev-mcp`.

## What changed

- `person_file_attachments.sha256` (lower-case hex, held by a CHECK); `PersonEvidenceFile.sha256?` in the kernel and `evidenceHashWords` (*sha256 3a7bd3e2360a…*, '' without one).
- The panel (`personEvidenceIo.ts`) digests each staged file with SubtleCrypto as it is picked and writes the column; before the push it reads and writes without it. The chip's tip ends with the hash.
- `dev_person_evidence_write` (re-made) stores the digest the plan committed to; `get_person_file` carries `sha256` and `linked` on each evidence file.
