# v2.7579 — Materials on site: the box screen asks for a pin when you are standing at the box (2026-11-17)

Punch list #372, *Find a lost box*, step 3 of 5, on the owner's word of 2026-11-17 (*Build all the steps*). The card's own judgment: a path to a box nobody pinned is a line to nowhere, so this step decides whether **Where is it?** (v2.7575) is used. Pinning as a press of its own was live for weeks, and no live box had a pin.

## What ships

[`PinAskStrip.tsx`](../../src/components/materials/PinAskStrip.tsx) over the pure [`pinAsk.ts`](../../src/lib/materials/pinAsk.ts). Under the header of the phone's box screen: *Pin A7 where you stand?*, the line *The next person who looks for it starts from your pin.*, and two presses, **Pin it here** and **Not now**.

It is offered at the four moments a person is known to stand at the box:

- **After Count this box**, when the walk ends.
- **After a photo** of the box is kept, on its way or on the phone.
- **After a signed-in scan of the label.** The page a label's code opens (`BoxCode.tsx`) notes the box for the tab that opens next, in that browser tab alone, and the On site tab reads the note once. A typed code counts too: the label is in the person's hand.
- **When a box is added** and its screen opens.

**Pin it here** takes one reading and pins the box with the phone's margin and the presser's name, held to the rule **I found it** has: a reading the phone is not sure of within about 150 ft is refused in words, and the press becomes **Try again**.

## When it asks

- Only a live cage, box or pile. Never Unsorted, never a retired box.
- Only a box with no pin, or with a pin older than seven days (`PIN_ASK_AFTER_DAYS`). The seven is a guess.
- **Never twice in a day for one box on one device**, whatever the person answers. The memory is one small row in the phone's own storage, emptied each day. A box that wants no pin does not spend the day's ask.

## Walked

On a dev server against the live database, in a headless Chromium at 390 wide, as the dev account, with a made-up location, on a test job's test cage with its pin taken off: **Count this box**, *8 is right*, and the box's screen drew the ask under its header. **Pin it here** pinned the cage, the line under its name read *pinned today*, and the ask went away. The ask after a photo, a scan and a new box was not walked: the tests hold the count's path and the kernel, and the other three call the same one function.
