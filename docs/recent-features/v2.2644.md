# v2.2644 — Price book entry Price field stops reformatting mid-typing (2026-09-02)

Estimator report (Wendi): in the Pricing tab's Price book drawer, adding a new
entry with the book in **Combined price** mode, typing a price fought the
cursor — "needs to be 21.00 but puts it in as 2.01".

Root cause in `src/components/bids/BidsPricingTab.tsx`: the Combined-mode
Price input was controlled by `pricingEntryTotal` while its `onChange` wrote
`pricingEntryRoughIn`; the auto-total effect then re-set `pricingEntryTotal`
to `calculatedTotal.toFixed(2)` on every keystroke. Typing `2` instantly
became `2.00` with the caret displaced, so the next digits landed inside the
forced `.00` (`2` → `2.00` → type `1` before the last zero → `2.010` → the
effect's round-trip → `2.01`).

Fix: the input now owns the raw string the user types
(`pricingEntryCombinedPrice`, seeded on form open/edit/close), matching how
the Stage-price inputs already bind their raw state. `onChange` still derives
Rough In exactly as before (RI absorbs the change so the total matches), and
save still persists from the recomputed `pricingEntryTotal` — only the
mid-typing reformat of the visible field is gone.
