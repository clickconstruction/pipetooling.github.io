# v2.3199 — Crew-day sync: a clock change no longer fails when the roster name differs from the user name (2026-09-09)

Migration `20260909182000_crew_sync_person_id_upsert.sql` (`docs/migrations/`); server-side only, no client change. Found by the first cost batch (v2.3196): its dry run repointed 77 clock sessions off the Diamondback catch-all job and died on the twelfth belonging to one helper with `duplicate key value violates unique constraint "people_crew_jobs_person_id_work_date_uniq"`.

## What was wrong

`sync_crew_jobs_from_clock` rebuilds a person-day's `people_crew_jobs` row from clock sessions and upserts it on the table's primary key `(work_date, person_name)`, using the **clock user's** `users.name`. The roster can know the same person by a different name (`people.name` — "Zack" vs "Zach W"), and rows written under the roster name carry the same `person_id`. Two resolvers then disagreed: the function's `resolve_pay_person_id_from_clock_user(NULL, name)` matches roster names only and returned NULL, so it inserted a row with no person; the table's BEFORE INSERT trigger resolves through `users.name → people.account_user_id`, stamped the real `person_id`, and the partial unique index on `(person_id, work_date)` refused the second row. Net effect: for that person, **any** clock-session change on a day that already had a crew row failed — approvals, edits, job moves — with a database error the user could not act on. Thirty-one such rows existed for one person when found.

## What shipped

- The function now resolves the person the way the insert trigger does (both resolvers, first hit wins), updates the existing `(person_id, work_date)` row in place whatever name it carries, and only falls back to the by-name upsert when no row exists. The "nothing recorded today" branch deletes by `person_id` as well as by name. Body otherwise unchanged from v2.3179.
- Verified in a rolled-back transaction: repointing one of the failing sessions now updates the roster-named row's `job_assignments` and leaves exactly one row for the day.
