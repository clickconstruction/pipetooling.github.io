# v2.5256 — Messages: the rules for a job's files going out (2026-10-12)

Wave 1 of the Messages build, cluster 9's second half (GC Reviews helper 9, directed by the lead session GC Review): the kernels of cut 7, *Files going out* (`to-dos/gc-mode/messages/BUILD_PLAN.md` on `spike/gc-mode`), lifted from the Messages prototype v1.91, v1.92 and v1.148 (`JOB_FILES`, `PORTAL_PAGE`, `PORTAL_LINE`, `attachPicker`, `previewFile`, `addDraftFile`, `linkLines`, the send window's file notes). No screen, no table, no edge function; the Attach picker, the send window and the `drive-link` handler come in wave 2.

- **`src/lib/documents/jobFiles.ts`**: `jobFiles(sources)` is the one list of a job's files from every place they live: the papers the app makes (a statement of work, our contract, a pay application, a change order, the schedule), the plan sets (`gc_plan_sets`, always a Drive link), the job's Drive folder in its Plans and Team only halves, a trade partner's uploads (`gc_trade_files`), the files on our sent copies (`sent_documents.attachments`) and the files that arrived on messages (`message_attachments`, cut 6). Each is a `JobFile` with one key whatever list it came from, its bytes (null until known), its kind from its type, where it lives (`home`), whether it is a plan set, and its portal page. A Drive file reached two ways is one row: Drive says where it lives, the other row how it came. A sent copy's file with the name and size of one already listed is that file and adds no row. The papers first, then the plans, Drive, the trades, what we sent, what came in, each newest first. `PORTAL_PAGES` is the one list of a person's portal pages (`plans`, `sow`, `schedule`, `contract`, `bills`, `changes`, `papers`), with the page's words, a text's line and whose portal has it; helper 8's customer portal maps each to its tab. The trade portal draws no anchors yet, so `/t/<token>#plans` opens the portal at its top until it does. `sizeWords` (*412 KB*, *2.1 MB*, *184 MB*), `fileKindOf`, `portalWords`, `portalHasPage`.
- **`src/lib/documents/outgoing.ts`**: `waysOut(files, channel)` says how each file goes. On an email a file goes as the file up to `EMAIL_FILE_LIMIT_BYTES` (10 MB), a plan set or a file of unknown size as our link, and the files that go as files must fit `EMAIL_MESSAGE_LIMIT_BYTES` (20 MB) together, the largest turned into links first. On a text every file goes as our link, a photo too, since Quo's API sends no picture messages (helper 3's read of its docs, 2026-10-12); the picture is an email's alone. `linkFor` opens the person's portal at the file's page when their portal has that page, else the file's own signed link: a customer gets the file link until their pages land, an architect always. `linkLines` gives a text one line per portal page however many files point at it. `emailFileNote`, `textFileNote`, `chipFacts`, `chipHover` and `sentCopyFoot` are the send window's words; `sentFiles` keeps each file with how it went (`sent_as`) and its link; `landingFor` puts a file from this computer in **Team only → Sent by us** and a photo in the job's photos; `addDraftFile` puts a file on the message once, by its key; `attachPicker` lays out the picker (the step's papers starred, the job's files, this computer, a photo) and `previewFacts` the preview's head line.
- **`src/lib/contracts/assemble.ts`** (from the lead's review of v2.5247): with no job the between line drops its job piece (`betweenLine`), so a statement of work held for its missing job reads *Click Construction and Hillside Excavation*, never a sentence cut off at *for*.
- **Changed from the prototype, and why**: *big* is decided by bytes, per file and for the message together, where the prototype set it by hand and never added the files up; a photo on a text goes as our link, where the prototype sent it as the picture, which Quo cannot; a file of unknown size goes as our link; a portal page counts only when that person's portal has it; a file's kind and page come from where it lives, never from its name; one key per file, so a duplicate is caught by what it is, not by its name; no made-up page counts; the words split to plain words.
