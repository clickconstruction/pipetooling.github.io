# v2.3835 — Robot backtests: the score only unseals after a real lock (2026-09-25)

Hazards 7 and 8 of [`TWIN_MCP_SERVER_ARCHITECTURE.md`](../TWIN_MCP_SERVER_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Both are in `score_backtest`, the STG-6 unseal of [`twin-mcp`](../../supabase/functions/twin-mcp/index.ts). Edge function only, no migration, no client change — **redeploy `twin-mcp` after merge** (`supabase functions deploy twin-mcp`).

## The bugs

- **The LOCK gate matched letters, not the word.** Blindness is structural: `score_backtest` refuses to unseal until the twin bid's ledger carries its blind total as a LOCK note (`[STG-3..5 + LOCK] $NN,NNN …`, per the bid skill). The check was `ilike('notes', '%LOCK%')` — case-insensitive substring — so any ledger note saying *blocked*, *unlock* or *clock* opened the reference before a total was locked.
- **The amend lookup was unscoped.** `twin_run_scores.run_label` is globally UNIQUE, and the idempotent/amend path read the row by label alone. A shell that reused another run's label got **that** run's row back — `reference_value` included — and could patch its `scope_verdict` / `gate_eligible`; its own run was never scored.

## The change

- New shared kernel [`_shared/twinBacktestScoreGate.ts`](../../supabase/functions/_shared/twinBacktestScoreGate.ts): `isBacktestLockNote(notes)` — `LOCK` as its own capital word (`/\bLOCK\b/`); `backtestRunLabelOwner(existing, twinBidNumber)` → `free` / `mine` (a `backtest` row whose `twin_bid_number` is this shell) / `taken`.
- The LOCK gate reads the bid's `LOCK`-containing notes (`like '%LOCK%'`, up to 50) and needs one that passes `isBacktestLockNote`. The refusal text is unchanged — it already names the format.
- A `taken` label is refused: *run_label "…" already belongs to another run — score bNNN under a new run_label.* A shell's own label still reuses / amends as before (v2.2816).
- The verb's tool description says both. `EDGE_FUNCTIONS.md` → twin-mcp (the round-2 / scoring-door paragraph) amended.

## Verified

- `src/lib/twins/twinBacktestScoreGate.test.ts` (6): the pipeline's two lock-note shapes pass; *blocked*, *BLOCKED*, *unlock*, *UNLOCK*, *clock* and the STG-0 shell note do not; empty notes do not; label free / mine / taken (another shell, a shadow row, a null bid number).
- Not exercised against prod (the dev-mcp seat was unavailable): an in-flight shell whose lock note wrote the word in lower case would now be refused and told to add the `[STG-3..5 + LOCK]` note.
