# v2.2594 — Backtest candidates in the Queue lens (2026-09-01)

Owner-approved mockup Variant B (design review artifact 887b4c7a): the dev 🤖
Queue lens gains a third supply line under Requested/Ready — which decided
historical bids are graded well enough to be practice reps, grouped by the
confidence axis whose Gate-B streak they'd feed.

- **Kernel `src/lib/bids/backtestCandidates.ts`** (9 tests): candidates =
  decided bids, grade A/B by field presence (`referenceGrade.ts`), minus bids
  already used as a reference in `twin_run_scores`/`twin_shadow_runs`
  (matched on normalized bid number). Gate-eligible split from flagged (round
  value / weak loss / uncategorized / stale). Groups ordered by demand — open
  gates (closest first), new axes, awaiting-score, blocked (rendered dimmed:
  a rep can't help until the audit answer lands), met — with the unclassified
  bucket last. Demand comes from `buildAxisCards`, the Scoreboard's own gate
  math, so the two lenses can never disagree.
- **Starvation is rendered, not blank**: an axis with demand but no eligible
  references gets a card counting its flagged refs ("the next rep comes from
  repairing history, not from running it") — the reference_quality repair
  loop's front door.
- **Migration `20260901193834_backtest_axis.sql`**: nullable
  `bids.backtest_axis` (dev-assigned via the unclassified rows' "assign
  axis ▾" select). Additive; rides existing RLS.
- **`buildBacktestPrompt`**: the kickoff prompt's backtest sibling —
  `open_backtest`, blind rule; carries bid number + axis only, never the
  value/outcome the dev can see on the row.
- Flagged refs behind a per-axis "Show anyway"; grade chips carry
  full-scorecard vs dollars-only tooltips.

Queue lens stays dev-only; no help-guide change. Deploy order: client first,
`supabase db push` after merge, then `gen-types`.
