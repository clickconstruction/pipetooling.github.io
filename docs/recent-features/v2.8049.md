# v2.8049 — The automatic check of the live site no longer uses Google Maps (2026-11-20)

Asked by Grace on 2026-11-20, after reading the month's Google Maps usage for card #387 (painted maps on Google). The E2E smoke suite signs in to the live site after every deploy and nightly, so every Google map it opened and every address it made the app place was billed as real use. Test-only: no app code, no migration, no edge function.

## Why

- **Map loads.** Google's Maps JavaScript API chart (Google Maps Platform → Metrics, Per Day, Grouped by Domain): on Nov 7 to 11, while the suite failed at sign-in and reached no page, clicktooling.com made 4 to 19 requests a day, workdays included. From Nov 12, when its sign-in was repaired (v2.7003, v2.7016, v2.7258), it made 100 to 460 a day, weekends included, tracking the runners' geocode calls day by day. Most of November's 4,269 billed Dynamic Maps loads were the suite. The smoke test's `pipetooling.com` forwards to clicktooling.com, so Google's domain split cannot tell it from people; the timing does.
- **Geocoding.** Supabase's function logs: 2,391 of November's 3,556 `geocode-address-batch` calls (67%) came from GitHub's runners (Microsoft networks, Windows-style Playwright browsers, about five calls a run, all hours). Each carried one address nobody can place: `useAddressGeocodeCoords` asks again for a miss on every mount and no edge function saves a miss, so every run paid Google again. The suite runs 32 to 78 times a day.

## The rule

[`e2e/fixtures.ts`](../../e2e/fixtures.ts) extends Playwright's `test` with an automatic fixture, `noGoogle`, that every file in `e2e/` runs through, the sign-in included:

- A `context.route` holds each request bound for Google before it leaves the browser (`route.abort('blockedbyclient')`). What counts is [`src/test/smokeNoGoogle.ts`](../../src/test/smokeNoGoogle.ts): Google's map hosts (`maps.googleapis.com`, `maps.gstatic.com`, `places.googleapis.com`, `routes.googleapis.com`; Google's fonts are not maps and stay) and every edge function whose source names `GOOGLE_MAPS_API_KEY`, matched by `/functions/v1/<name>` (a doubled slash too).
- The app does the rest on its own: the Google canvas's load error hands each map to OpenStreetMap (`PinsMapFrame`'s `googleUnavailable` door), and a held geocode, Street View or drive time is a failed call the screens already carry.
- Every Google-bound request is noted as it starts and waited on when the test ends (up to 5 s). One that got any answer, or is still out, fails the test. The wait is the point: an answered request's finished event lands a moment after the test's last line, so a check at teardown that only listened for it missed the leak in the first try.
- The test's report notes what was held, by host or function name and never by query: a Street View or geocode call carries a customer's address in its query, and the report is a public artifact of a public repository.

[`e2e/no-google.spec.ts`](../../e2e/no-google.spec.ts) proves the holding on every run, on a blank page with no live site. [`src/test/smokeNoGoogle.test.ts`](../../src/test/smokeNoGoogle.test.ts) holds the matcher (hosts held, fonts, OpenStreetMap tiles, links and the rest of the app left alone, no query in a label), holds the function list to `supabase/functions/` both ways, and holds every file in `e2e/` to the `./fixtures` import (a type-only import from Playwright is fine).

The app's service worker serves only its own page loads, so every request to Google passes the context's routes; should it ever fetch Google itself, the fixture's comment says to set `serviceWorkers: 'block'`.

## How it was checked

- `src/test/smokeNoGoogle.test.ts`: 17 tests.
- The fixture and `no-google.spec.ts`, transpiled to plain JavaScript with the repo's esbuild (this Mac's Node 20.0 cannot load TypeScript for Playwright 1.61; CI's Node 20.x can) and run on the installed Chrome: both requests held, the report noting *functions/v1/geocode-address-batch × 1, maps.googleapis.com × 1*. A second test whose own route answered a Google request failed with that request named, as expected.
- The app's own `PinsMapFrame`, mounted as the cards mount it with a key set, on a local Vite page with stand-in Supabase values, loaded through the fixture: it opened on Google, the fixture held the Maps script, the app logged *Google Maps unavailable, using OpenStreetMap*, drew on OpenStreetMap, and raised no page error (the smoke specs assert zero page errors on the Jobs and Settings tabs).
- `e2e/` and the new module type-checked with a focused config (the repo's typecheck covers `src` only).
- Not run against the live site from here: its sign-in types the test account's password into the live site, which the runners do.

## What to watch

- Google's Maps chart should fall back toward people's own level, roughly 10 to 40 requests a day, once this deploys and the next runs pass through it.
- Supabase's logs should show no more `geocode-address-batch` calls from Microsoft networks.
- Left out on purpose: saving a geocode miss so no screen asks again for an address nobody can place. That is a change to the app, for its own card if wanted.
