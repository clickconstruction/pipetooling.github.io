# v2.7888 — Trips: how far is far is one setting (2026-11-18)

## Why

The owner's call 1 on the trip record (#379): *150 miles from the shop, one setting; a person can turn trips on for any site*. The 150 was a constant in the code. The second half was already true: a near site's page has a **Trips** line that reads *none yet · add one*.

## What changed

- **The setting.** One row of `app_settings`, `trips_far_miles_v1` (`value_num`): the miles from the shop that make a site a trip from home, 25 to 1,000 whole miles. No row reads 150, so nothing changes until a dev sets it.
- **The Trips look** (`useSiteTrips`) and **the phone's trip question** (`useTripPhone`) read it beside the shop's point. The site's miles stay unknown until both are in, so a site is never called far by the default while the setting is on its way.
- **Settings → Jobs, bills and liens → Trips**, a new card under *The job's record*, for a dev: one number and Save. The Settings search finds it by *trips*, *far site* and *miles from the shop*.
- **The kernel**, `src/lib/trips/tripFarMiles.ts`: what a stored value means, what a typed one means, and the words.

## Decisions

- **A dev sets it.** `app_settings` is a dev's to write by its own policy, so this needs no migration. Every signed-in user reads it, which the phone needs.
- **25 to 1,000.** Below 25 the shop's own town would read as a trip. Past 1,000 no site ever would.
- **A value out of range reads the default**, as a missing row does. The app never treats a bad row as *never far* or *always far*.
- **No switch per site.** A site with a trip shows its look at any distance, and the first trip is one press from the page.

## Docs

The two trip guides say far is 150 miles until it is set otherwise. `docs/GLOSSARY.md` and `docs/ACCESS_CONTROL.md` name the setting and who sets it. `docs/SETTINGS_TABS_ARCHITECTURE.md` counts the cards.
