# v2.7928 — Robots: an assistant can line a bid up for the robots (2026-11-19)

`plan_bid_update` → `apply_bid_update` on `dev-mcp` take three more columns (server 0.109.0, no new verb). The owner, 2026-11-19: "Please build the reference metadata".

## Why

The audit of what an agent can stand up alone listed it as the fifth gap. The seat could make a bid and file its plans, and could not hand it to the robots. Three columns do that, and Edit Bid has no field for any of them.

- `backtest_axis` is written by the Robots Queue's assign axis.
- `holdout` is written by its Hold out and Release holdout presses.
- `robot_requested_at`, with `robot_requested_by`, is written by the robot icon on the Bid Board.

## What `set` takes now

- `backtest_axis`: text, 80 characters at most. `null` sends the bid back to the unclassified group.
- `holdout`: `true` or `false`.
- `robot_requested_at`: `true` asks, `false` withdraws. A time is refused.

## The ask's moment

The app stamps the moment of the press. A plan that carried a time would hash differently at the apply. So the plan's patch carries the marker `now()` (`BID_STAMP_NOW`) and `bidUpdateWritePatch` swaps it for the moment of the write. `robot_requested_by` rides as the dev. An ask already on the bid is a no-op and is not stamped again.

## What the plan warns of

- **An axis nobody uses.** When the plan names an axis, the server reads the axes in use off `twin_run_scores`, `twin_shadow_runs` and `bids`. An axis that matches none starts a group of its own on the Queue, and the plan says so with the list. A match by case alone is named. A refused read leaves the list out and the plan says to check the spelling.
- **A holdout on an open bid.** A holdout is a decided reference kept for the gates.
- **A hold on an asked bid.** The plan runs the queue's own rule (`shadowHold`) over the row as it would read. It says what would still pass the bid over: no plans, left to a person, a due date long past, a link the robot cannot read. Two checks need another table and are not run: another trade's bid, and a robot bid already on it. The plan names `get_shadow_queue` for those.

## History

The four columns are not in `bid_changes_bid_columns()`. The plan says the bid's History does not record them.
