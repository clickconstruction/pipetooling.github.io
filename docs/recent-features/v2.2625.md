# v2.2625 — Division 22 audit modal pages past the 1000-row cap (2026-09-01)

The `spec_section_fixture_name_audit` RPC returns ~3,655 rows, but PostgREST silently caps un-ranged responses at `max_rows` (1000). `SpecSectionAuditModal`'s `load` callback took the single-shot response at face value, so the audit classified only the top 1,000 names by bid count: coverage % was computed against a truncated universe and low-bid names (e.g. GPR-1..12) never appeared as gaps.

- Fix: the RPC read now goes through `fetchAllRows` (`src/lib/supabasePaging.ts`) — `.range(from, to)` pages of 1000 until a short page, each page wrapped in `withSupabaseRetry`. Safe because the RPC's ORDER BY is deterministic (`bid_count DESC, fixture ASC`).
- Same incident class as the Crew P&L v2.976/v2.978 truncations; no schema or RPC changes.
- Expected behavior shift: the modal's total now reads ~3.7k names and the coverage bar drops accordingly — that is the correction, not a regression.
