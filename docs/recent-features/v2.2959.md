# v2.2959 — Add document → Send now reads the quick picker's selection (2026-09-06)

Follow-up to v2.2955, which passed `form_template_id` into the quick-send guard but resolved the picked Book entry from `built.payload.applied_contract_template_document_id`. On the deployed site the refusal persisted: that payload field goes through `resolveAppliedContractTemplateDocIdForSave`, which only keeps ids that appear in `listAppliedContractBookVersionOptions(personName, documentName)` and returns **null** otherwise — so the guard still saw no form.

- **Fix** ([`PeopleContractsTab.tsx`](../../src/components/people/PeopleContractsTab.tsx) `saveContractDocumentAndOpenSend`): the guard resolves the Book entry from `contractAddBookPickedRowId` (what the radio list sets) first, then `contractDocumentFormAppliedTemplateDocId`, then the payload's applied id. `hasContractSigningContent` then sees the entry's `form_template_id`.
- Verified live after deploy: People → Contracts → Claude Test Sub → + Add document → From Contract Book → Direct Deposit Authorization → **Send now** opens the Send for signature dialog (Cancel writes nothing).

Client-only; no migration, no edge deploy.
