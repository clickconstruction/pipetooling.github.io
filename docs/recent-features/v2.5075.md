# v2.5075 — Stages: the GC statement cards read the round through useGcStatementRound (2026-10-09)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 2 (`to-dos/decomposition-queue.md`): the Stages map's step 4 (`docs/JOBS_STAGES_TAB_ARCHITECTURE.md`). It puts the board's round block on the hook the GC Review map's step 8 built (v2.5072).

## What shipped

- **`JobsStagesTab.tsx`**: the board's own copy of the round's reads is gone:
  - four states;
  - the load of the week's certifications, its marks and six weeks of marks;
  - the senders effect.

  In their place is one call, `useGcStatementRound({ open: isRoundOfficeRole && !gcReviewModalOpen, certWeekStart: roundWeekStart, roundGcIds })`, after `roundGcIdsKey`.
  - **The GC ids** go in by their sorted set (`roundGcIdsKey`), as the old senders effect keyed them, so a new array of the same GCs reads nothing.
  - **The board's own memos stay, verbatim:** the temperature map `gcTemperatureById` over the hook's six weeks of marks, and the round cards `gcRoundCards`. They read the old names (`roundCertRows`, `roundMarks`, `roundTempMarks`, `roundSenders`) through the destructure.
  - 4,902 → 4,869 lines. The imports only the old block used are gone.
- **What changes, all off screen:**
  - **When the board reads.** It used to read on every GC Review open and close. Now it reads while GC Review is shut, so each close reads the round again, as before. On open, only the window reads, since it covers the board.
  - **A failed read.** The board used to keep its last good list. Now it empties that list, as GC Review always has. A failed re-read can therefore show more GCs waiting until the next read.
  - **Late answers.** The board's reads used to drop a late answer. The hook's two refreshers do not (the GC Review map's hazard 4). The senders read still does.
  - **No GCs.** With no GCs, the senders read now runs with an empty list, which answers an empty map without a query.
- **Docs**: the Stages map's step 4, cluster I and its seam row; the GC Review map's step 8 and hazard 14; the playbook's Stages row and its `useGcStatementRound` row.
