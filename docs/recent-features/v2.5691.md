# v2.5691 — Reports: Escape closes the report form (2026-10-21)

Found on the overnight live walk of punch list #135 (Leave Report from the job window, v2.5688): the to-do's verify line promised "Escape closes one layer at a time (the form, then the window)", and the window side held — `DetailJobModal` puts `leaveReportOpen` in `detailEscBlocked` so Escape never closes the window underneath — but the form side was never written. `AdditionalReportModal` had no Escape handling at all, so with the form up the key did nothing: the window ignored it by design and the form was not listening. No migration; no edge function.

- **The form** ([`AdditionalReportModal`](../../src/components/AdditionalReportModal.tsx)): a `window` keydown listener while `open`; Escape that nothing above has handled (`defaultPrevented`) is marked handled and runs `handleClose` — reset, then `onClose`, exactly the Close button's path. The handler reads through a ref so the listener is bound once per open. Because the window's listener skips a handled event, the two layers now peel in order; a layer above the form that owns its own Escape is left alone.
- **Tests** ([`DetailJobModalLeaveReport.render.test.tsx`](../../src/components/jobs/DetailJobModalLeaveReport.render.test.tsx)): Escape while the form is up closes the form and leaves the window (its `onClose` never called, the ＋ Report chip back); opened again, the form's own Close takes it down the same way.
- **Walked on prod (read-only)** as the sample assistant on job 978: the chip, the form titled with the job, *How far along is each line?* on the two-line job; Escape now expected to close the form once this deploys.
