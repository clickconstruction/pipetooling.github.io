# v2.2450 — Sign-in stops storing the password in localStorage (2026-08-28)

Flagged in passing during v2.2448: on a successful login, SignIn saved the raw password
to `localStorage.signin_password` and pre-filled the field from it on the next visit —
plaintext credentials readable by any script on the origin (any XSS = harvested password),
and shared-device users inherited the previous person's password in the field.

Owner-approved removal:

- The success branch no longer writes `signin_password`; the `signin_email` pre-fill (a
  convenience, not a credential) stays.
- The mount effect **purges** any `signin_password` an older build left behind, on every
  sign-in page visit — devices clean themselves up as people log in.
- Password convenience is the browser password manager's job — the field already carries
  `autoComplete="current-password"`, so Chrome/Safari offer to save and pre-fill properly
  (encrypted, behind the OS keychain).
- `SignIn.render.test.tsx` +2: a legacy stored password is purged on mount and never
  pre-filled; a successful sign-in (success path stubbed with a `location.reload` shim)
  writes the email but not the password.

User-visible change: the password field starts empty where it used to be magically filled;
the browser's own save-password prompt takes over from here.
