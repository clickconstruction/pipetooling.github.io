# v2.2460 — Estimate Options, Phase 2: the customer chooses (2026-08-28)

Phase 2 of 3 (plan in v2.2457). The customer flow, end to end:

- **`_shared/estimateOptions.ts`** — dependency-free server kernel (normalize + totals +
  `freezeSharedAcceptedOption`), with `estimateOptionsSharedParity.test.ts` keeping it in
  lockstep with the client kernel (the accountingLabelRuleMatch pattern). Options are only
  ever written by the Phase 1 builder, so no legacy line shapes here.
- **`get-estimate-for-customer`** returns `options` (server-normalized — the page renders
  exactly what acceptance validates against).
- **Acceptance page** (`EstimateAccept.tsx`): the stacked-cards picker renders between the
  document header and the line items (recommended pre-selected); picking swaps the document
  and total live; the Approve button and confirm-modal title name the commitment —
  *Approve "Replace 50-gal" — $3,400.00*. The chosen `optionKey` rides the accept POST;
  submitting with no choice is blocked client-side too.
- **`accept-estimate`**: with 2+ options the key is required (`400 option_required`) and
  validated (`400 option_unknown`); the same `sent → customer_accepted` update **freezes**
  the chosen option — lines → `line_items_snapshot`, sum → `total_cents`, key →
  `accepted_option_key`. Downstream readers (accepted document, create-job, Pipeline) need
  no changes — that freeze is the whole design. Staff notify email appends
  `— chose "Replace 50-gal" · $3,400.00`.
- **`send-estimate-to-customer`**: the email appends a "Your options — choose on the page"
  block with **every option's price**, ★ on the recommended (owner decision 5), text + HTML.
- **The Phase 1 send gate is lifted** — multi-option estimates now send.
- **"Preview as customer"** (new tab) carries options through the staff-preview snapshot
  (optional `options` on `StaffAcceptPreviewSnapshotV1`; old snapshots parse unchanged).

Moved to Phase 3 (from the original Phase 2 list): the CX override key for the picker
heading — it's hardcoded "Choose your option" until then.

**Deploy after merge**: `supabase functions deploy get-estimate-for-customer accept-estimate
send-estimate-to-customer` (all three additive — safe in either order relative to the client
deploy; an old client simply never sends `optionKey`, and old emails have no options block).
