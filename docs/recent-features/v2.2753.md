# v2.2753 — BidsAuditsTab render smoke: wait for the notes, not the row (2026-09-04)

Test-only. `src/components/bids/BidsAuditsTab.render.test.tsx` → "read-only roles
(write RLS mirror) see the card without composers or Finish audit" failed once on
GitHub Actions (run 33890871931, PR #2486) with
`Unable to find an element with the text: /Wet tables owner-furnished\?/` while
passing locally on repeat.

**Race.** `BidsAuditsTab`'s `load()` sets the audit rows first, then awaits a
*second* query for `bid_audit_notes`; the auto-expand of the first pending card
is an effect tick after the rows land. The read-only test waited only for the
bid's project name (present in the collapsed row) and then read the question body
synchronously — that body lives inside the expanded card and comes from the
notes query, so under CI load both could still be pending. The sibling test
happened to wait for the expanded card's CountTooling link first, which is why
only the read-only case flaked.

**Fix.** Both tests now `await screen.findByText(/Wet tables owner-furnished\?/)`
before reading anything that depends on the notes. Run 10× locally: 10/10.
No component change.

Precedent for test-only fixes carrying a version: v2.2031 (E2E deep-link spec),
v2.2195 (ChecklistAddModal render flake).
