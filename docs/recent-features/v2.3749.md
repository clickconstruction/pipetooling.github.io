# v2.3749 — The phone dock follows the role: Jobs · Schedule · Quickfill · Inbox · More (2026-09-23)

Punch list #30 (`to-dos/taunya-mobile.md`), **PR 1 of 5** — the shell. Owner's calls, taken 2026-09-23 on the five questions: the assistant's four are Jobs · Schedule · Quickfill · Inbox; Jobs opens the Pipeline, Schedule and Inbox stay the Dispatch Mode pages; the dock stays tied to Dispatch Mode; assistants only (other roles keep the fixed bar); the "suggested for you" line and the sticky tab strip ship in this PR. Client only, no migration.

## What changed

- **Kernel `src/lib/phoneDock.ts`** (16 tests): the page registry (key → label, route, icon, activity keys, `visible(role)`), `roleDockDefault(role)` (assistant-like → `['jobs','schedule','quickfill','inbox']`; `null` for every other role = the fixed bar), `parseStoredDockSlots` / `resolveDockSlots` (a stored choice that no longer parses — a hidden page, a hand-edited value — falls back whole rather than rendering a dead slot), `swapDockSlot` (a page already on the dock trades places), `activeDockKey(pathname, search, slots)` (the most specific match lights; `/jobs?tab=billing` lights nothing), `suggestedDockPages(rows, slots, role)` (the person's own `user_app_activity_page_daily` rows — own rows are readable under RLS — summed per page, a tabbed page claiming its exact key and a plain page the rest of its segment, the dock's own keys excluded), and the per-device store `phone_dock_slots_<userId>` with the same change event pattern as `dispatchModeToggle.ts`.
- **`DispatchModeFooter`** gains `slots` + `onOpenMore`: with them (dispatch variant only) it renders four `DockSlotButton`s and More. Tap opens the page; press-and-hold (`useLongPress`, the Quick Assign pattern — fires on release, `consumeLongPress` swallows the trailing click) opens the sheet in swap mode for that slot. The Inbox badge sits on the Inbox slot, or on More when Inbox was swapped out. Icons come from `PhoneDockGlyph` (one stroke glyph per registry shape) so a swapped-in page arrives with an icon the bar knows.
- **`PhoneDockMoreSheet`**: a bottom sheet (z 1004, above the bar; `aria-modal` so `BodyScrollLockSentinel` freezes the page). Sections: *Suggested for you* (top three, with hours), *Pages* (every page the role can open, "on the dock" marked), *Modes* (the gear's toggles — same gates, same handlers, passed in from Layout), *Settings* (Punch list for dev + master, Help, Settings, Sign out). In swap mode the title reads *Swap ‹slot› for…*, only the pages show, and *Reset to the role's four* appears when the device has its own set.
- **`Layout.tsx`**: `phoneDockActive = dispatchModeActive && isMobile && slots != null`. While it is up the hamburger, the gear button and the header's Customers / People icons hide (More carries them); search and the three task buttons stay. Sign-out is one function (`signOutEverywhere`) shared by the gear and the sheet.
- **`Jobs.tsx`**: at ≤ 640 px the page tab strip is `position: sticky; top: 0` — the app header scrolls away, so the strip is the slim header the second pass drew.
- Help guide `dispatch-mode` (the assistant's bar, hold-to-swap, More), GLOSSARY *Dispatch Mode*, `docs/twins/APP_DIRECTORY.md` header section.

## Verify

Sample assistant on a phone width with Dispatch Mode on → the bar reads Jobs · Schedule · Quickfill · Inbox · More; the header shows no hamburger and no gear. Tap Jobs → `/jobs?tab=stages`, Jobs lit; scroll → the tab strip stays at the top. Hold Schedule → *Swap Schedule for…* → tap Supply houses → the slot reads Supply houses; reload → still there; hold it → Reset → back to the four.
