# v2.2042 — Roadmap Timeline: per-task successive slot bars + expansion waterfall (2026-08-21)

Implements the "Timeline Task Bars" mockup (owner request: "all the stages
inside a group to be their own successive bars"). Two layers on
`ChecklistRoadmapTimelineView` (v2.1979), one geometry:

- **Kernel** `taskSlotRects(barLeft, barWidth, count)` in
  `src/lib/roadmapTimeline.ts` (+3 tests): equal successive slots of the
  existing stage-bar rect, small gap, width floored so a crowded stage in a
  narrow wave stays visible. Pure fractions; the view's `pct()` renders them.
- **Segmented stage bar**: `barFor()` (refactored around a shared `rectFor` +
  `slotStyle`) renders one slot per task in task order — done green **in true
  position** (out-of-order completion finally shows), first not-done task
  amber-ringed ("next up"), rest outlined; locked stages get dashed slots.
  Per-slot `title` tooltip = "N.M title — done/next up/remaining/locked".
  Done stages keep the compact ✓ pill; milestones (◆) unchanged. The old
  in-bar "N of M" count moved to the rail next to the stage title (hidden on
  phones with the title, like before).
- **Expansion waterfall**: the expanded task list swaps its plain `<ul>` for
  stage-row-style lanes — rail (task number, title, assignees; tap opens the
  task card) + lane with wave gridlines, the amber front line, and the task's
  slot bar (also tappable). Slot geometry shared with the parent bar, so the
  cascade overlays it exactly.
- Pace projections, wave layout, and the Map/Plan views are untouched;
  footer legend now says "Each slot ≈ one task".

Verified live on Farm 1: "Cut trail" renders done/next-up/remaining slots
with rail count 1/3; "Drill a well" expands to a 6-row staircase
(0.4% → 7.97% → … equal 7.17% slots).
