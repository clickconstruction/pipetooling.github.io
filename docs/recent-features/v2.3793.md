# v2.3793 — The “signed” email says who and how much (2026-09-23)

The owner, on the staff notice for an accepted estimate: *"a lot of noise and very little signal"* — the subject read `Signed — Estimate for <customer> — $0 (Estimate #N)`: the app's default title repeated the signer, "Estimate" appeared twice, and the amount was wrong.

## The bug

[`accept-estimate`](../../supabase/functions/accept-estimate/index.ts) handed `notifySignedAgreement` the row's `total_cents`, but its select never asked for the column — every accepted-estimate notice since v2.2743 said **$0** (subject and the Amount row). The select now carries `total_cents`, and a chosen option's frozen total (`optionFreeze.total_cents`, the same value the UPDATE writes) wins. Bid-room notices were unaffected (`chosen.total_cents`).

## The subject

[`signedAgreementEmail.ts`](../../supabase/functions/_shared/signedAgreementEmail.ts) (and its byte-identical app twin [`src/lib/signedAgreementEmail.ts`](../../src/lib/signedAgreementEmail.ts)):

- `<who> signed — $4,250[ · <work>]` — *who* is the customer name passed in (the GC for a bid room) or else the signer; the record number moves out of the subject (it stays on the eyebrow and in the links).
- *work* is the title unless it is still the app's default (`isAppDefaultTitle`, an inline twin of `isAppDefaultEstimateTitle` in `src/lib/estimates/estimateTitle.ts`, since the shared file stays dependency-free). The heading and text drop it the same way: "Dana Ruiz accepted the estimate", not "…accepted the estimate for Estimate for Dana Ruiz".
- A hidden preheader carries the job line ("Job J912 was created automatically." / "No job yet — …"), so the inbox preview says what to do next instead of repeating the eyebrow.

## Around it

- [`emailLogStreamLink.ts`](../../src/lib/emailLogStreamLink.ts) — Most recent emails sent matches the new subject (`^… signed — $N`) as well as the old `Signed — ` rows.
- [`emailCatalog.ts`](../../src/lib/emailCatalog.ts) subject example and variant; guide *get notified when a bid or estimate is signed*; `EDGE_FUNCTIONS.md` (accept-estimate, sign-bid-room); `ACCESS_CONTROL.md`.

## Deploy

Edge functions `accept-estimate` and `sign-bid-room` (both import the shared builder) — `supabase functions deploy accept-estimate sign-bid-room`. No migration.
