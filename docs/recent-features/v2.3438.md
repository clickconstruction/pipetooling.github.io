# v2.3438 — Retire the stage window's `offered_to_gc` columns and the calendar's offer props (2026-09-14)

Item 2 of [`to-dos/stage-plan-residuals.md`](../../to-dos/stage-plan-residuals.md). Client + one migration + one edge function. Since Stage Plan PR 5 (v2.3132) the GC portal reads the eye on the line item (`jobs_ledger_fixtures.shared_with_gc`); the per-window *offered to the GC* record from v2.2933 — `job_stage_windows.offered_to_gc`, `offered_to_gc_at`, `bundle_id` and the `job_stage_windows_offered_idx` index — had no reader left. A grep of `src/` and `supabase/functions/` found four mentions, all writes or plumbing: `offerNextStage.ts` mirrored `offered_to_gc` onto the window when it flipped an eye; `JobsSubsWorkView.tsx` selected the two columns and answered a GC ask by `bundle_id` when one was set; `stageWindow.ts` typed them; `submit-portal-request` selected them and looked the ask's window up by id **or** bundle.

## What shipped

- **Client**: the mirror in [`offerNextStage.ts`](../../src/lib/subs/offerNextStage.ts) is gone; [`JobsSubsWorkView.tsx`](../../src/components/jobs/JobsSubsWorkView.tsx) no longer selects the columns and answers an ask on the one window by id; `StageWindowLike` loses the two fields; [`StageCalendarModal`](../../src/components/jobs/StageCalendarModal.tsx) drops its `onOffer` / `onWithdraw` props and the *Offer to …* / *Take it off their portal* buttons (no caller passed them since PR 4 — the render smoke now asserts they never draw). The GC fact on the calendar still reads *not shown yet* / *shown since …* from the eye.
- **Edge function `submit-portal-request`**: the `stage_window` ask selects the window by id only. **Redeploy before the push** (`bash scripts/deploy-functions.sh submit-portal-request`) — the deployed bundle still selects `bundle_id, offered_to_gc` and would 400 once the columns drop.
- **Migration** [`20260914250000_drop_stage_window_offered_columns.sql`](../migrations/20260914250000_drop_stage_window_offered_columns.md): `DROP INDEX IF EXISTS job_stage_windows_offered_idx`, then `DROP COLUMN IF EXISTS` ×3. Idempotent.
- **Types**: the three columns are removed from `src/types/database.ts` by hand (the minimal edit so the client compiles without them); a regen chore PR (`npm run gen-types:linked`) follows the push.

## Deploy order — the client goes first

1. Merge (deploy.yml ships the client) and redeploy `submit-portal-request`.
2. Then `bash scripts/db-push.sh`, then `npm run check:migration-drift`. The old client's Subs → Work read selects `offered_to_gc, bundle_id` and `offerNextStage` writes `offered_to_gc` — against the dropped columns both would fail, so the push waits for the client.

## Verified

`StageCalendarModal` render smoke, the subs kernels, typecheck, lint, the full suite, build, theme check. Grep after the change: no `offered_to_gc` / `bundle_id` / `onOffer` / `onWithdraw` in `src/` or `supabase/functions/` outside the migration.
