# v2.6608 — A dev's agent edits a person's HR summary or narrative a section at a time (2026-11-07)

Migration `20261107013000_dev_person_doc_write.sql` (`docs/migrations/20261107013000_dev_person_doc_write.md`) and dev-mcp server 0.32.0; no client change. Asked for 2026-11-06 while two long documents went onto a person's HR file: the summary and the narrative (`person_files`) render as markdown on People → HR, but the only writers were `hr_agent_write` from psql and `dev_hr_entry_write`'s whole-text rewrite inside an entries call — no preview, no edit of one section, and nothing that told a second writer the text had moved under them. The matter narrative already had the shape (v2.4814: `plan_matter_narrative` over `dev_legal_narrative_write`, whose dry run commits to the text's length and saved time); this copies it to the HR documents and adds section ops, so a 250 KB narrative is changed in a call that carries one section, not the whole text.

## Change

- **`dev_person_doc_write(p, p_dry_run)`** (devs only, definer): `person_id`, `kind` (`summary` | `narrative`) and one of `markdown` (the whole text) or `ops` — `replace_section` (the lines under a heading up to the next heading of the same or a higher level, the heading kept, `''` empties it), `insert_after` (after that section's last line), `append` — against the document's own headings, which **`hr_doc_headings(md)`** reads as the jump list does (fence-aware, backticks and bold stripped). A missing heading is refused with the document's headings; one that appears twice, with the count. The dry run names the person, the size before and after, each change with the words removed and added (capped), the headings after with their line numbers; the plan hash covers the row's `updated_at`, and `expect_updated_at` refuses the call itself when the document was saved since the version read. A text that would not change is refused. The apply upserts the row as the dev (`author_label` the dev's name, `updated_by`, `covered_through` now() unless given); the archive trigger keeps the prior version.
- **`plan_person_doc(doc)` / `apply_person_doc(doc, plan_hash)`** on dev-mcp (0.32.0): the seat's grammar over that RPC; `whoami` counts forty-nine write verbs.
- `src/lib/devMcp/devMcpWrites.test.ts` holds the allowlist, the body shape (the whole text or the ops, `expect_updated_at` carried), the refusals and the migration's guards.
