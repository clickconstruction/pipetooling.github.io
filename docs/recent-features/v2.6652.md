# v2.6652 — The walk kit runs on a nightly schedule, from any checkout (2026-11-07)

Punch list #142's close-out (`docs/WALK_KIT.md`): the card's last `next` was one live run of the fixed driver, then the walk on a schedule. The run on 2026-11-07 found three defects in the way of it, none in the Messages loop itself, fixed here with the schedule. Edge function `dev-login` changed (**redeploy**); no migration.

## Found on the 2026-11-07 run

1. **The driver could not start from a worktree.** `scripts/walk/run.ts` imports the screens' own io modules, and the first of them, `src/lib/supabase.ts`, throws at load when Vite's `import.meta.env` has no `VITE_SUPABASE_URL`. vite-node fills that from the checkout's own `.env` files and the process environment when it starts, and never again; a worktree has no `.env` of its own, so the driver died before its first line, whatever the main checkout's files held. Every earlier run had been from the main checkout.
2. **A lost signal on the first call ended the run, and the report read green.** `walk setup` was the one call outside the retrying wait (v2.6030, found item 2). A transient `fetch failed` on it propagated out of `runWalk`, the finally block printed a report with no step at all, and `finishReport` called that report green: no held step, cleanup kept off.
3. **dev-login refused the tester.** v2.6639, merged earlier the same day, closed the dev sign-in door to everyone but a dev or a digital twin (a link minted as a teammate would have read their Gmail through My email). The walk tester signs in through that door (decision 5 of the card), so `Sign in as the tester` held with the door's 403 and the kit could not press its own sends.

## Change

- **`_shared/devLoginGate.ts`** (`src/lib/devLoginGate.test.ts`): `devLoginMayMint` admits `users.is_walk_tester = true` beside a dev and a twin; the tester has no mailbox and training mode lets it write nothing but the kit's three sends, so a link minted as it reads nobody's Gmail. `dev-login/index.ts` reads the flag with the role. `DEV_LOGIN_NOT_FOR_THEM` names the three.
- **`scripts/walk/start.ts`** is what `npm run walk` runs now: it reads the three keys the driver's way, names a missing one and stops (exit 2), else runs `scripts/walk/run.ts` in a second vite-node with the keys in its environment, the flags passed through and the exit code the driver's own. The env reading moved to **`scripts/walk/env.ts`** (`mainCheckoutRoot`, `readEnvFiles`), which now lays the process environment over the files through **`walkEnv.ts`'s `layerProcessEnv`** (pure, tested): a variable with a value wins, an empty one changes nothing, and the missing-key words name *the environment* among what was read. Proven from this worktree, which has no `.env` and no variable set: `npm run walk -- --cleanup-only` reached the function and answered *nothing to clean*.
- **`walkRun.ts`, `run.ts`**: the setup call goes through the retrying wait (`SETUP_WAIT_MS`, one minute), and a wait that never reaches the function holds the step with what it saw; a call that throws outside a wait is caught, written to the report's new `endedEarly` with `errorWords`, printed as *✗ The run ended early*, and cleanup still runs; `finishReport` is green only when at least one step went and the run reached its end; `main`'s own failure prints `errorWords` (the cause included). Three driver cases in `walkDriver.run.test.ts`.
- **`.github/workflows/walk.yml`**: nightly at 09:00 UTC and on demand, one at a time, non-gating; `npm run walk` with `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` and `VITE_DEV_LOGIN_SECRET` from the repository's secrets (the first two are the deploy's; **the third must be added once** by hand), the report under `tmp/walk/` uploaded on every run. A red run means a leg held on prod and the report says which.
- **Docs**: `docs/WALK_KIT.md` (how to run it from a worktree and from CI, the schedule, § Found on the 2026-11-07 run, *a walk on a schedule* out of Not carried), `docs/EDGE_FUNCTIONS.md` → dev-login, `docs/ACCESS_CONTROL.md` → The walk tester, `docs/README.md`, and the card.
