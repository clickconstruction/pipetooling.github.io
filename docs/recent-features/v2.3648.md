# v2.3648 — MCP servers, PR 3: new twin keys carry `ptt_`, and the Worker turns the wrong key away (2026-09-20)

PR 3 of [`to-dos/mcp-servers.md`](../../to-dos/mcp-servers.md). Dev keys have been `ptd_` + 64 hex since v2.3640; twin keys were bare hex. Both servers look a key up by the sha256 of the **whole presented string**, so a prefix is simply part of a new key: nothing is migrated and every bare key already in a config keeps answering. No migration.

## The change

- **[`_shared/mcpKeyPrefixes.ts`](../../supabase/functions/_shared/mcpKeyPrefixes.ts)** (new, pure): `TWIN_MCP_KEY_PREFIX` / `DEV_MCP_KEY_PREFIX`, `formatTwinMcpKey`, and `wrongDoorRefusal(path, { token, authorization })` — the sentence for a key that names the other audience, or `null`. [`src/lib/mcpKeyPrefixes.ts`](../../src/lib/mcpKeyPrefixes.ts) is the client's re-export; `devMcpKeys.ts` now reads `DEV_MCP_KEY_PREFIX` from it, so each prefix has one home.
- **The two places a twin key is minted** prefix it before hashing: `issueToken` in [`DigitalTwinsPanel.tsx`](../../src/components/settings/DigitalTwinsPanel.tsx) and the `redeem` action of [`twin-setup`](../../supabase/functions/twin-setup/index.ts).
- **[`mcp-router.worker.js`](../../scripts/cloudflare/mcp-router.worker.js)**: at `/twin`, a request whose `x-twin-token` or bearer starts `ptd_` — at `/dev`, one whose `x-dev-token` or bearer starts `ptt_` — answers `401` with one plain sentence **before the fetch**. A bare key, no key, and the audience's own prefix pass through; the function decides those. The Worker still holds no secret and looks no key up. It deploys as a single file, so it carries its own copy of the rule; [`mcpRouterWorker.test.ts`](../../src/lib/mcpRouterWorker.test.ts) runs the Worker itself against a stubbed upstream and pins its sentence to the kernel's.
- Checked again before shipping: nothing validates a twin key's shape (`desktopKickoff.ts`, `TwinSetupDialog`, `twin-setup`, `twin-mcp`, `twin-login`, `scripts/twin/twinenv.py`), and the CountTooling / TakeoffTooling mirrors receive `sha256(rawToken)` — the prefix rides along.
- Docs: `EDGE_FUNCTIONS.md` (the twin-mcp and dev-mcp Endpoint sentences, twin-setup's redeem), `GLOSSARY.md` → twin-mcp, the to-do.

## Deploy

Client by CI · `supabase functions deploy twin-setup` · `npx -y wrangler@3 deploy --config scripts/cloudflare/mcp-router.wrangler.toml`. Any order: a `ptt_` key works the moment it is minted, with or without the Worker's check.

## Verify

Issue a key on Settings → Digital twins → it starts `ptt_` and `get_brief` answers with it; an old bare key still answers; a `ptd_` key at `/twin` gets the Worker's sentence (a `401` text body, not the function's `Auth failed:` tool result); **Set up on this Mac** on a test label redeems a `ptt_` key — revoke the label after.
