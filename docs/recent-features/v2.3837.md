# v2.3837 — Job Parts Tally: a controller's "Mark payroll" sticks (2026-09-25)

The gate split **R1 / R2** of [`JOB_TALLY_ARCHITECTURE.md`](../JOB_TALLY_ARCHITECTURE.md) (the payroll sub-cluster), found by the 2026-09-25 map sweep — step 3 of that map's extraction order. Client only, no migration.

## The bugs

T5-03 (migration `20260906130000`) widened *Mark payroll* from dev to payroll access (`has_payroll_access()`: dev, controller, pay-approved master) — RLS on `mercury_tally_payroll_flags` and the `set_tally_payroll_flag` RPC — and the page's `canMarkPayroll` followed. Two dev-only gates were left behind in [`JobTally.tsx`](../../src/pages/JobTally.tsx):

- **R1 — the flag merge.** `loadTallyTransactions` read the flags table and merged `is_payroll` onto the rows only when `role === 'dev'` (the list RPC does not return it). For a controller the mark succeeded (toast and all), but after the reload `is_payroll` never merged, so `tallyRowIsResolved` was false: the row stayed under *Show unlinked* with its *Mark payroll* button, the *Payroll ✓ / Unmark* banner and the payroll total chip never rendered (so it could not be unmarked either), and the page's *N unlinked* ran above the Dashboard card, whose server count excludes payroll.
- **R2 — Create rule….** The confirm modal always rendered *Create rule…*; its handler closed the confirm and set `payrollRulesModalOpen`, but `TallyPayrollRulesModal` mounts only for a dev — for everyone else the button closed the dialog and opened nothing.

## The change

- R1: the merge runs for `canMarkPayroll` (`canMarkTallyPayroll`, already tested) and the loader's deps carry it instead of `role`, so the transactions reload once payroll access resolves.
- R2: [`TallyMarkPayrollConfirmModal`](../../src/components/tally/TallyMarkPayrollConfirmModal.tsx)'s `onCreateRule` is optional and the button renders only when it is passed; the page passes it only for a dev. Payroll **rules** stay dev-only (`applyPayrollRules`, auto-apply, the chip).
- Guide *mark payroll transactions in the tally*: *Create rule…* is a dev's button.

## Verified

- New `TallyMarkPayrollConfirmModal.render.test.tsx`: with a rules door the button shows and calls it; without one there is no *Create rule…* and *Mark payroll* still confirms.
- Typecheck, lint. R1 is page wiring on the tested `canMarkTallyPayroll` predicate; not checked signed in as a controller (no such session here).
