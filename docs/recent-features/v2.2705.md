# v2.2705 — GC review nudge counts the way the modal does (2026-09-03)

Owner report (screenshot): the Dashboard Needs-you card said "GC review is still due this week · 10 of 10 GCs certified · 0 statements sent" with a badge of **0**, while opening GC Review showed "8 of 11 certified · 0 sent" and RMC- Dudley Mason flagged "Changed since certified · +$2,200". Diagnosed against prod with psql (read-only): three counting differences between the `gc_review_week_status` RPC (v1) and the client's `gcReviewWeekProgress` kernel, plus a badge formula that could never express "certified but not sent".

## Migration (applied with `supabase db push` after merge)

- [`20260903184432_gc_review_week_status_v2.sql`](../migrations/20260903184432_gc_review_week_status_v2.md): `CREATE OR REPLACE` of the RPC — certified = latest attestation this week whose `total` still equals the live outstanding total; outstanding = GCs whose board-mirroring live total is > 0; new `gcs_done` (certified ∩ sent). Dry-run of the body on prod for week 2026-08-31: 10 / 7 / 0 / 0.

## Client

- [`lib/jobs/gcReviewCertification.ts`](../../src/lib/jobs/gcReviewCertification.ts): `gcReviewWeekProgress` skips groups with `subtotal ≤ 0` (a billed job that's fully paid but not yet marked paid — the modal's eleventh group); new `gcReviewGcsToDo(status)` = `outstanding − (gcs_done ?? min(certified, sent))`.
- [`lib/dashboardNeedsYou.ts`](../../src/lib/dashboardNeedsYou.ts) + [`DashboardGcReviewWeeklyBanner.tsx`](../../src/components/DashboardGcReviewWeeklyBanner.tsx): the badge/count use `gcReviewGcsToDo`; the card's detail says "every group is certified; send each statement off…" once certified ≥ outstanding.
- `GcReviewWeekStatus` gains optional `gcs_done`; the v1 payload keeps working (min-fallback), so client and migration are order-safe.

Tests: `dashboardNeedsYou.test.ts` (badge = to-do, the all-certified copy), `gcReviewCertification.test.ts` (paid-up group skipped, `gcReviewGcsToDo`).
