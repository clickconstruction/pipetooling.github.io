# v2.3546 — Pricing tab decomposition, PR 1: four pieces of grid and picker logic become tested kernels (2026-09-16)

Client only, behavior-preserving. PR 1 of the Pricing train in `to-dos/engineering-hygiene.md` — the Stage-A sweep from [`docs/BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md`](../BIDS_PRICING_LABOR_TABS_ARCHITECTURE.md), minus what the Labor refresh train had already done (`bidTotalCostBreakdown`, `costEstimateAutosavePayload`, `laborBookMatch`). Pure logic out of `BidsPricingTab` and `BidsLaborTab` into `lib/bids/*` with tests; the components call the kernels; no JSX moves.

| Kernel | Was | Tests |
|---|---|---|
| [`resolvePricingEntry`](../../src/lib/bids/resolvePricingEntry.ts) — the entry that prices a count row: an assignment for the active pricing wins, else the case-insensitive fixture-name match, nothing without a version | `resolvePricingEntryForCountRow` closing over four pieces of engine state in the Pricing tab | four: no version; assignment beats a name match; another pricing's assignment is ignored; dangling assignment / unknown row / unmatched fixture are null |
| [`filterBidsForPicker`](../../src/lib/bids/filterBidsForPicker.ts) — the bid picker's search over project, address, customer, GC/Builder and the bid number | the same nine lines in `BidsPricingTab` **and** `BidsLaborTab` (twelve more tabs still carry them — the shared picker component is PR 3) | blank query returns all; each field case-insensitively with null fields tolerated |
| [`lastZipInAddress`](../../src/lib/bids/extractZipFromAddress.ts) — the Travel box's ZIP prefill, the **last** five-digit run (map quirk 12) | inline regex in the Labor tab's prefill effect | last not first; six-digit runs ignored; empty for none |
| [`decoratePricingRows`](../../src/lib/bids/decoratePricingRows.ts) — the grid's row join: labor row by fixture, custom price and assignment for the active pricing, takeoff materials, tax, margin flag; then the uncosted-revenue bucket (map quirk 10) | the `.map` inside the grid IIFE, the join the map called the highest-leverage Stage-A item after the totals kernel | the join field by field across two pricings; the uncosted bucket and its sum |

The grid IIFE now reads `const { rows, uncostedRevenueRows, uncostedRevenue } = decoratePricingRows({...})` and the only thing that changed in the call is that `canToggleOmitSubmission` is passed as the boolean it always was (`selectedPricingVersionId != null`; the old per-row helper ignored its argument). `bidNumberMatchesQuery` is no longer imported by either tab.

Numbers: `BidsPricingTab.tsx` 5,720 → 5,665; `BidsLaborTab.tsx` 2,164 → 2,155. Small on purpose — Stage A puts the logic behind tests so the component moves that follow are cut-and-paste.
