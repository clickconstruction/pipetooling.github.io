# v2.4559 — Documents: GC statements and test report emails are kept (2026-10-05)

Step 2 of the Sent copies train ([`docs/SENT_COPIES.md`](../SENT_COPIES.md)), third part, on the helper from [v2.4557](v2.4557.md). No migration. **Four functions to redeploy**: `send-gc-statement-email`, `gc-statement-email-dispatch`, `send-test-report`, `auto-send-test-reports`.

## The change

- **GC statements** — `send-gc-statement-email` and `gc-statement-email-dispatch` file the statement as the GC read it: `gc_statement`, keyed to the GC (`customer_id`), the portal code drawn into the kept page. `gc_statement_emails` recorded that a statement went and its total; the page was rebuilt from an RPC over live data, so last month's statement could not be read again as it was. A statement is not keyed to its jobs (the functions do not hold their ids), so it does not list under a job's *Sent from this job*; step 4's Documents page and customer page are where it will be found.
- **Test reports** — the PDF was already kept (`job-test-reports`, versioned). The email itself was not. `send-test-report` files it after the stamp; the shared `sendTestReportEmailViaResend` takes `file`, and `auto-send-test-reports` passes it. `test_report`, the job, the report as its source. A dev's sample send is not filed.

`EMAILS_OWED` drops four (16 left).
