# v2.5989 — The GC's account page opens a notarized lien waiver (2026-10-27)

The follow-up v2.5985 (#6322) left open. A waiver signed in mode `notary_paper` stores no
`signed_pdf_path`, so `customer-portal` gave the GC's account page no PDF for it: the bill's note and
Your papers listed it as signed with nothing to open (so since Print for a notary, v2.5925). Since
v2.5985 the notarized PDF itself sits at `job_lien_releases.notary_copy_path`, in the same private
`lien-release-documents` bucket.

## What changed

- **`customer-portal`** reads `notary_copy_path` with the jobs' signed releases.
- **[`_shared/portalWaivers.ts`](../../supabase/functions/_shared/portalWaivers.ts)**: `PortalWaiverReleaseRow`
  gains `notary_copy_path`, and `half()` hands over `notary_copy_path || signed_pdf_path`. The notarized
  file wins, as it does on the office's Send it (`sendLienReleaseEmail`) and Download PDF
  (`lienReleaseSignedPdfBlob`), both through `lienReleaseNotaryCopy`, so the page opens the file the
  GC's email carried. Nothing stores `signed_pdf_path` on a notary row today (only the pad and his code
  write `signed.pdf`), so the order matters only if something ever does. The function signs the path
  into a URL good for an hour, as before; `job_lien_releases_notary_copy_path_check` holds the column
  to `notary_paper` rows, so no other waiver changes.
- The bill's note and Your papers (`portalWaiverPapers.ts`) link the payload's `pdfUrl`, so they needed
  no change.
- **Guide** *send a GC our lien waiver*: **Print it for a notary** says the GC's account page opens the
  attached PDF, and that a waiver filed by Drive link alone shows there with no PDF to open.

## Tests

`portalWaivers.test.ts` (+1): a notary waiver holding only `notary_copy_path` hands that path over, and
a row holding both hands over the notarized file. It fails on the old rule.

## Not in this change

A notary waiver filed by its Google Drive link alone (`notary_copy_url`, no file) still shows on the
page without a PDF. The GC's email carries that link.

**Deploy**: `supabase functions deploy customer-portal` after merge. No migration: the column is on prod
since `20261027180000` (v2.5985).
