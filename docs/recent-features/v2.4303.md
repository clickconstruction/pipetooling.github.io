# v2.4303 — Edit Job → Bill: Still to bill leaves out work a bill already covers (2026-10-01)

No migration, no edge function. Found on job 1059 (Seaver Pretest) while reading the Bill tab with Grace: one ◆ line, $250, billed as a plain $250 bill sent Sep 30. The same window said the line was *covered*, *100% Billed*, *$0 Left to bill*, and still listed **◆ Pretest · Later · $250.00** under **Still to bill**. Jobs 1061 and 1063 read the same. Checked first that no other session, branch, open PR or worktree had fixed it.

## Why

A bill made by amount (the break-off slider, a typed amount) links no line item, so the stage plan reads every line as unbilled. `upcomingDrawRows` listed any row without an `invoiceId`. The ② strip already knew better: `dollarCoverageForSegments` hatches the rows that money covers, oldest first, and `createInvoiceFromSegmentIds` already bills a row net of that coverage. Still to bill was the one reader that ignored it.

## What changed

- **Kernel** [`stagePlanForm.ts`](../../src/lib/jobs/stagePlanForm.ts) `upcomingDrawRows(plan, coverage?)` → `UpcomingDrawRow` (the plan row plus `coveredDollars`, `leftDollars`, in cents-rounded dollars). A row covered to the cent leaves the list. A row covered in part stays for what is left. A passed Order stage marked *waits* becomes *ready* when every unbilled stage above it is covered to the cent (a part-covered stage above still holds it). Without `coverage` it reads as before.
- **[`JobFormUpcomingDraws`](../../src/components/jobs/JobFormUpcomingDraws.tsx)** takes `coverage`, prints `leftDollars`, adds *· $X of $Y already billed* on a part-covered row, and skips a covered stage when naming the one a row waits on. [`JobFormModal`](../../src/components/jobs/JobFormModal.tsx) passes `segmentCoverage`. **Bill it** is unchanged; it already billed the row net of coverage, so the amount shown and the amount billed now agree.
- The shared stage plan ([`_shared/stagePlan.ts`](../../supabase/functions/_shared/stagePlan.ts), also read by the customer portal) is untouched.
- Not changed: an Any-time line on a 100%-done job still reads *Later* until its work is marked done. That is to-do #13 item 4, an owner call.
- Guide `split-a-job-into-stages` already says Still to bill lists "every line item with money still to invoice", which is now what it does; left alone (it is on the plain-words legacy list).
