# v2.3610 — Pipeline load speed PR 4: the board you last saw appears at once while the fresh one loads (2026-09-19)

The last PR of the Pipeline load-speed train (`to-dos/pipeline-load-speed/`, retired with this PR — its measurement script moved to [`scripts/browser/measure-pipeline-requests.js`](../../scripts/browser/measure-pipeline-requests.js)). The owner's two answers, 2026-09-19: **a remembered board may be 24 hours old at most**, and **its money reads muted** until the live board lands. The drawing that asked them is in git history at the retiring commit (`to-dos/pipeline-load-speed/before-after-pr4.html`).

## The change

- **The rule** — [`lib/jobs/boardSnapshot.ts`](../../src/lib/jobs/boardSnapshot.ts) (6 tests): `buildBoardSnapshot` (the paid scope and paid rows are never stored), `boardSnapshotIsUsable` (same key — user + customer filter —, every wanted scope covered, younger than `BOARD_SNAPSHOT_MAX_AGE_MS` = 24 h, not from the future), `parseBoardSnapshot` (a stored value off the shape is ignored) and `describeBoardSnapshotAge` (*just now · 4 min ago · 6 h ago · yesterday*).
- **The store** — [`lib/jobs/boardSnapshotStore.ts`](../../src/lib/jobs/boardSnapshotStore.ts): one IndexedDB database (`pipetooling-board`, store `boards`, keyed by the board key). Every call is best-effort: no IndexedDB, a blocked open or a quota error resolves quietly and the board loads as before. `clearBoardSnapshots` runs on sign-out and on an account switch.
- **The cache** ([`JobsListCacheContext.tsx`](../../src/contexts/JobsListCacheContext.tsx)): on a cold load (the key has never completed in this session) `paintRememberedBoard` reads the store *while the live fetch is already running*; if the snapshot is usable and the fetch has not landed, it becomes the rows with `jobsListRefreshing` on and the new `jobsListSnapshotAt` set. Only state is set — the refs that gate scope fetches and the tab TTL stay untouched, so nothing treats the remembered rows as a completed load. When the live board lands it replaces the rows and clears `jobsListSnapshotAt`; the board is then written back (after its enrichment, so the stored rows carry materials, fixtures, schedule date and estimate banner). A failed refresh leaves the remembered rows on screen with a line saying so.
- **The tab** ([`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx)): *Updating jobs…* gains a *board from 6 h ago* chip while `jobsListSnapshotAt` is set, and the tab's root carries `data-board-snapshot`. The section totals, *Capable of Being Billed*, the four answer cards' values ([`PipelineOverview.tsx`](../../src/components/jobs/PipelineOverview.tsx)) and every Progress & payment cell ([`StagesProgressPaymentCell.tsx`](../../src/components/jobs/StagesProgressPaymentCell.tsx)) carry `stagesMoney`; [`index.css`](../../src/index.css) mutes them under the attribute (opacity 0.42, grayscale) and makes the tables' buttons, inputs and selects inert — row buttons carry the row's own data, so nothing can act on a remembered invoice.
- **The guide** — [`read-the-pipeline-money-view.md`](../../src/content/help/read-the-pipeline-money-view.md) gains *The board you last saw comes back first*.

## Measured (dev server, prod data, Ready to Bill + Billed open; SPA click from Reports to Pipeline, so the list is cold; three runs each)

| | blank load (before, and over the 24 h line) | remembered board |
|---|---|---|
| Rows on screen after the click | 788 ms | **245–305 ms** (the remembered rows; the live ones replace them at 1.1–2.3 s) |
| Supabase requests for the visit | 56 | 56 — the remembered paint adds none |
| Money during the wait | (blank) | muted, with the age chip; row buttons inert (`pointer-events: none`, checked by computed style) |

## Not remembered, by design

The paid scope (hundreds of rows the board loads lazily), another account's board (the key carries the user id, and sign-out clears the store), a board from another customer filter (its own key), and anything older than 24 h.
