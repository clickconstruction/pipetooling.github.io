# v2.4287 — Bids: hold a row to mark it, and find it marked on every tab (2026-10-01)

**The ask (Grace, 2026-09-30).** On Bids, with no bid selected on Counts / Takeoffs / Labor / Pricing / Cover Letter / Submittals / RFI / Change Order / Lien Release: long-click a row to highlight it, keep the highlight across those tabs and while searching, and show a light highlight on the Bid Board. Mock-up canvas (five boards, one working): https://claude.ai/artifact/JCpLyfF51VP3Qtw31iHyJx — approved as drawn after a second pass that added the hover circle, the per-account storage, the in-bid button and the dashed finished marks.

**What shipped.**

- **The hold.** `src/lib/bids/bidMarkHold.ts`: a pure state machine (`holdStep`: idle → holding → fired → idle on the click that follows) and the DOM glue (`bidMarkHoldHandlers`) a row spreads. Half a second (`BID_MARK_HOLD_MS`), a move past 8 px cancels (a scroll, not a hold), an early release does nothing, the release after a full hold swallows the click so the bid does not also open, a second finger or a right button never starts one. The state lives in a module map keyed `picker:<id>` / `board:<id>` because the row re-renders when the hold fires. While a hold runs the row carries `data-holding="true"` and a 3 px line fills along its bottom edge (`.bid-mark-hold-fill`). Touch: `-webkit-touch-callout: none` + `user-select: none` on the row and the context menu suppressed on touch, so the iPad's own long-press menu stays quiet.
- **The mark.** `src/lib/bids/bidMarks.ts`: the map (bid id → marked_at), `toggleBidMark`, `bidMarkSinceWords` ("marked today / yesterday / Fri / Sep 12 / Dec 12, 2025"), `isFinishedBidForMark` (the board's stage rule: won, started, lost, archived) and `splitBidMarks`. Theme tokens `--bid-mark` / `--bid-mark-wash` / `--bid-mark-wash-board` (violet, `#7c3aed` light / `#a78bfa` dark) — never amber, red or green, which the rows already use for Pending, due and Won.
- **The store.** `src/lib/bids/bidMarksStore.ts`: one module store (`useBidMarks`) loaded once per sign-in from **`bid_marks`** (migration `20261001001500_bid_marks.sql`, `docs/migrations/`), optimistic upsert / delete, the `onlyMarked` switch in memory. `Bids.tsx` calls `loadBidMarks(user.id)`. Before the table exists the store reads "no marks" and keeps marks for the session.
- **The surfaces.** `BidPickerStandardList`: each row is now a wrap with `BidMarkDot` (a 44 px circle button, hidden until hover, faintly always there on a touch screen, filled when marked) and the main button (the hold, `H` to toggle, "marked Fri" on the rail, dashed bar when finished); the *Marked* filter; a footer with *Clear marks* and *Clear finished marks (n)*. `BidPickerSearchRow`: `MarkedBidsToggle` after *Only my bids*. `BidsBidBoardTab`: the `<tr>` and the phone card take the hold and `data-marked` (`.bid-mark-board-row`: the lighter wash, the bar on the first cell), the tools row gets the same toggle beside the search box, `H` on a focused row. `BidWorkflowTabTitleWithPreview`: `BidMarkButton` (*Mark* / *Marked · today*) after the title on every tab.
- **Docs.** Guides `find-a-bid-on-the-workflow-tabs` (new *Mark a bid to find it again*) and `read-the-bid-board` (the mark on a row); `GLOSSARY.md` (Mark); `ACCESS_CONTROL.md` (`bid_marks`). Types for `bid_marks` hand-added to `database.ts`; regenerate after the push.

**Decided and why.** The word is *Marked*, not *Highlighted*: the board already has the self-highlight on your own name. One color, not several: a legend to learn is a second feature. Marked rows never float to the top of their group: that fights the sort view; the Marked switch does the job. Per account, not per browser: the whole point is finding the bid again from another device. Shared team marks (Wendi marks for Robert) are a different feature with a different word.

**Tests.** `bidMarks.test.ts`, `bidMarkHold.test.ts` (every phase and cancel), `BidPickerStandardList.render.test.tsx` (the circle marks and clears, the wash and the words, the Marked switch, the footer).
