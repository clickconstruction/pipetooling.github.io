# v2.6006 — Print it again on a held waiver records cleanly; the lien push dates an evening signature on its own day (2026-10-28)

Two defects the docs pass of 2026-10-28 (#6357) found reading the fragments against the code, plus one disagreement between two sentences on the same waiver.

## What changed

- **Print it again on a held waiver** ([`LienReleaseModal.tsx`](../../src/components/jobs/LienReleaseModal.tsx), `printForNotary`): the hold's *Print it again* called the first-print handler, whose update was matched on `issued` or `draft`. The held row is `out_for_notary`, so the update found no row: the page printed and a second copy was filed, then the toast said *Printed, but the hold was not recorded — try again* and `notary_printed_at` stayed at the first print. Now `lienReleaseNotaryPrint(row)` ([`lienReleaseLifecycle.ts`](../../src/lib/jobs/lienReleaseLifecycle.ts)) says what a print does to the row: a first print holds it (matched on `issued`/`draft`), a print from the hold is a reprint (matched on `out_for_notary`) that keeps the hold and refreshes its print day. The reprint still files its copy, as the Lien desk's *Print it again* does (a print counts as a send, `docs/SENT_COPIES.md`), and the button's hint says so: *It already printed. Print it again only if the first copy was lost; every copy is filed on the job.* A reprint whose update fails says *Printed again, but the new print day was not recorded.*
- **An evening signature in the lien approval push** ([`notify-lien-approval/index.ts`](../../supabase/functions/notify-lien-approval/index.ts)): the three signed-day lines (the waiver code, the notice code, the pen record) read `signed_at`'s first ten characters, the UTC day, which is tomorrow for anything signed after 7 PM Central (6 PM in winter). They now read `calendarYmdInAppTzFromIso(signed_at)`, new in [`_shared/appTimeZone.ts`](../../supabase/functions/_shared/appTimeZone.ts) as the Edge twin of the web helper (`docs/TIME_AND_ZONES.md`). `check:timezone` does not catch a plain `.slice(0, 10)` (rule 7 is deferred), so the parity test holds the helper and the push test holds the line. **Deploy `notify-lien-approval` after merge.**
- **Step 5's summary on a notarized PDF** (`lienReleaseSignedHow`): it always said *in ink before a notary*, while the audit sentence (v2.5985) and the send email drop *in ink* once the notarized PDF is on the record, since an online notary seals a file. The summary now takes the row's `notary_copy_path` and says *before a notary* for a stored PDF, so the two sentences on one waiver agree.
