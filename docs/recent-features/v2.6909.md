# v2.6909 — A file placed in the body of a mail is a file: the dev seat reads and files it, and a person's entry names it (2026-11-11)

Found 2026-11-10 while checking `read_mail_file_text` (v2.6880), and first written down wrongly as "`read_mail` does not list it". It does. On a supplier's order forwarded from Apple Mail, `read_mail` listed two PDFs and `read_mail_file` answered *That mail carries no file (pictures placed in the body are left out)* for either name.

## Why

Apple Mail writes an attached PDF as `Content-Disposition: inline`. `readGmailMessage` (`src/lib/emailIn/gmailMessage.ts`) marks a part `inline` when its disposition is inline or it carries a Content-ID, which is also how a signature's logo arrives. Three readers treated the flag differently:

- `fileKeep` (`emailIn/emailLine.ts`), the reader that copies a mail's files, and the job tag planner: a file is everything but a picture placed in the body under 30 KB.
- `mailReadReply` (`_shared/devMcpMailSearch.ts`): listed every part, logos included.
- `pickMailFile` (`_shared/devMcpMailFile.ts`) and the person tag planner (`myMail/personTagPlan.ts`): dropped every `inline` part, PDFs included.

## What changed

- **`_shared/devMcpMailSearch.ts`**: `isMailFile(file)` is `fileKeep(file) !== 'skip'`. `mailReadReply` lists the parts it passes, so a logo is no longer listed.
- **`_shared/devMcpMailFile.ts`**: `pickMailFile` picks among the same parts, so what `read_mail` lists can always be picked by `read_mail_file`, `read_mail_file_text` and `plan_mail_file`. The empty refusal now reads *a small picture placed in the body, such as a signature's logo, is left out*.
- **`src/lib/myMail/personTagPlan.ts`** (and its copy under `_shared/gcKernels`, regenerated): a person's entry counts and names a mail's files by the same rule.
- **`supabase/functions/dev-mcp/index.ts`**: server 0.62.0, `read_mail`'s description.
- **Docs**: the mail file row in `docs/dev-mcp/README.md`, `docs/EDGE_FUNCTIONS.md` → dev-mcp, the `mail-search` skill's `read_mail` line.

The flag itself is unchanged, so nothing else that reads a mail moves.

## Tests

`src/lib/devMcp/devMcpMailFile.test.ts` — a PDF placed in the body is picked by name; a large picture placed in the body is a file and a logo is not; `read_mail` lists exactly what can be picked. `src/lib/myMail/personTagPlan.test.ts` — an entry counts and names a placed PDF and leaves the logo out. `src/lib/gc/edgeKernels.test.ts` holds the regenerated copy.
