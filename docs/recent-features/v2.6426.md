# v2.6426 — The dev seat keeps a piece of evidence on a person's HR file (2026-11-02)

The People → Paperwork spike's MCP write, after v2.6392's records and v2.6393's Drive leg: a dev's agent keeps a piece of evidence — the day it is about, a title, a memo and one or more files — on `plan_matter_document`'s pattern, through a dry-run wrapper of its own. Migration `20261103060000_dev_person_evidence_write.sql` (`docs/migrations/20261103060000_dev_person_evidence_write.md`); `dev-mcp` 0.18.0. Builds on v2.6418's lift and v2.6422's read.

- **`dev_person_evidence_write(p, p_dry_run, p_files)`**: dev-gated `SECURITY DEFINER`, closed to `anon`, the pattern of `dev_hr_entry_write` and `dev_legal_document_write`. `p = { person_id, dated_on, title, memo, entry_id?, files: [{ name, mime, size_bytes, sha256 }] }` under the panel's own rules (`evidenceDraftProblem`'s: all four pieces, the day never ahead of `app_today()`, the title under 160, the memo under 4,000, each file 1 byte to 10 MB, at most twenty), refused in words. The dry run returns the person, the dev as `author_label`, the record `after`, `where` it lands (*People › the person › the day · the title*), `evidence_on_person` (the live count, so a record kept since the plan moves the hash) and `people_folder_set`. The write needs `p_files = { evidence_id, files: [{ id, storage_path }] }` and refuses unless every object is in `hr-files` under `<person>/evidence/<record>/<file>-…`; it then inserts the `person_file_evidence` row and one `person_file_attachments` row per file as the caller, the rows `savePersonEvidence` writes. No update or delete.
- **`plan_person_evidence(evidence)` / `apply_person_evidence(evidence, plan_hash)`** (`_shared/devMcpWrites.ts`, `dev-mcp/index.ts`): the same plan → hash → apply grammar as every write. `evidenceBytes` decodes each `content_base64`, holds it to the caps, reads its mime and digest and hands the grammar the facts — never the bytes, which `argsForLog` keeps out of the log. Apply, after the hash and the one-apply rule, stages each file as the dev in `hr-files` under `evidenceStoragePath` (the kernel lifted in v2.6418; `storagePut` and `storageRemove` take the bucket now), writes the rows through the RPC, removes the staged files again if the rows are refused, and then asks `hr-evidence-drive` for the record as the panel does — fail-soft: `drive` says filed, or why not, and `next` says *In Drive* or *Kept, not in Drive yet: …* with the sweep's promise. Refused through `view_as`. The instructions string reads twenty-seven verbs.
