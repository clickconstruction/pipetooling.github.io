# v2.2186 — App-wide modal scroll lock: one sentinel, opt-out by attribute (2026-08-23)

Owner (from the phone, on "Where this task fits"): stop background scroll when a modal is open — across the entire app, then selectively allow it back. Plan reviewed and approved; this is PR 1 of 2.

**What was there:** the right primitive already existed since v2.992 — [`bodyScrollLock.ts`](../../src/lib/bodyScrollLock.ts) (reference-counted, iOS-safe `position: fixed` body with scroll restore + scrollbar compensation, 7 tests) and `useBodyScrollLock()` — but only 5 of ~240 modal files used it, and three more hand-rolled their own (two of them `overflow: hidden`-only, which doesn't hold on iPhone). ~320 files render a fixed `inset: 0` backdrop; 80 of them have no `role="dialog"`.

**What this adds:**
- [`src/lib/blockingOverlay.ts`](../../src/lib/blockingOverlay.ts) (+9 tests): `findBlockingOverlays(doc, win)` — candidates via `[role="dialog"], [aria-modal="true"], [style*="position: fixed"], .respModalOverlay, .roadmap-task-overlay, .dispatch-po-overlay`; each walks to its nearest `position: fixed` layer (stopping before `<body>`/`<html>` — the lock pins the body with `position: fixed`, and treating that as an overlay made the lock self-sustaining in the first live run; regression-tested), which counts when it covers ≥ 90% of the viewport, is visible, and isn't under `data-page-scroll="allow"`.
- [`BodyScrollLockSentinel`](../../src/components/BodyScrollLockSentinel.tsx), mounted once in `Layout`: `MutationObserver` on `body` (childList/subtree/attributes: style, class, hidden, role, aria-modal, data-page-scroll) + `resize`, coalesced to one recompute per animation frame; acquires the refcounted lock while any blocking overlay exists, releases when none. Every existing modal and every future one is covered with zero per-modal code.
- **Opt-out valve:** `data-page-scroll="allow"` on an overlay. **Opt-in for non-overlays:** `useBodyScrollLock(true)` as before.
- Retired the three hand-rolled locks onto the shared hook: `ClockInOutButton` (same recipe, duplicated), `ActiveAccountsModalContext` and the roadmap CSS-fullscreen fallback (overflow-only).
- CSS: `[role="dialog"], .respModalOverlay, .roadmap-task-card { overscroll-behavior: contain }`.
- Docs: `PROJECT_DOCUMENTATION.md` → Common Patterns → "10. Modal scroll lock — automatic, opt-out".

**Considered and rejected:** a 320-file codemod adding the hook per modal (heterogeneous `open` shapes, conflicts with every open PR, and the next modal is unlocked again); CSS `body:has([role=dialog]) { overflow: hidden }` (one line, but the `overflow` variant doesn't stop iOS touch scroll and can't restore position).

**Verified live** (Playwright, iPhone 13 viewport + 1280 desktop, dev-login, Review → Farm 1 → stage 6 → 6.3): sheet opens → `body` is `position: fixed; top: -429px`; task card stacks → still locked; card closes → still locked; sheet closes → body restored and `scrollY` back to 429. Known false-positive-by-design: invisible fixed click-catchers behind dropdowns also lock — correct, and one attribute to exempt if a case feels wrong.

PR 2 (next): `role="dialog"` / `aria-modal` sweep on the 80 bare overlays (script-driven, merges alone).
