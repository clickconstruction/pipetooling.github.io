# v2.3165 — Takeoffs view chooser asks once per device, then remembers (2026-09-08)

Client only — no migration, no edge function. Estimator Wendi, the day after the chooser shipped: "can you make it stop asking me every time I navigate to the page and make one the default please." v2.3082 built the box to ask on every Combined bid open by the owner's design (no "remember", no dismiss) so that which-view-do-people-pick would be a live choice during the retire-Old measurement week. One day of real use said the cost of that is too high for the person doing the takeoffs; this PR keeps the box for its first job — introducing the three views — and makes the first pick the default from then on.

## What shipped

- **[`hasStoredTakeoffView(storage)`](../../src/lib/bids/takeoffView.ts)** (pure, +2 tests): true once `bids_takeoff_view_v1` holds a known view — `old` counts as a pick. Missing or broken storage reads as "never picked", so a device that cannot remember keeps asking rather than silently landing on Old.
- **[`BidsTakeoffTab`](../../src/components/bids/BidsTakeoffTab.tsx)**: the chooser-open effect now also requires `!hasStoredTakeoffView(localStorage)`. A pick of the view already showing (which `switchTakeoffView` early-returns on) writes the stored view explicitly, so picking **Old** on a fresh device is remembered too. Nothing else about the box changed: three cards, keys 1 · 2 · 3, no dismiss without a pick, By Stage bids never see it.
- **The pills beside the bid name** are the way to switch after that — they already wrote the same key, so a pill switch is remembered the same way. Devices that had used the pills before v2.3082 already hold a value and will not see the box at all.
- The chooser's header comment and [`TakeoffViewChooser.tsx`](../../src/components/bids/TakeoffViewChooser.tsx) say "the first time … on a device" now.

## Smokes

- "asks which view to use the first time …" clears the key first and still expects the box; a pick of **Sheet** opens the rail and stores `new2`.
- New: with `old` stored, a Combined bid renders Old with no box (and neither new view); the existing Sheet-mount smoke also asserts no box.

## Docs

- Guides *cost a takeoff one fixture at a time* and *see what Pricing sees on Takeoffs*: "the first time you open a bid on this device … your pick is remembered, so the box does not come back".
- `BIDS_SYSTEM.md` Takeoffs views paragraph, `TAKEOFFS_REFRESH_PLAN.md` status line, and the retire-Old to-do's validation note (the census now reads each device's first pick plus pill switches, not a per-open choice).

## Verify

Clear `bids_takeoff_view_v1` in DevTools → open a Combined bid on Takeoffs → the box → press **1** → Old opens; close the bid, open another Combined bid → no box. Click the **Sheet** pill → the rail; reopen → Sheet, no box.
