# v2.6307 — Documents: the four ledgers read as rows, not as wrapping columns (2026-11-01)

The Documents page design spike of 2026-11-01 (the owner walked every tab; this is the first of its candidates). The owner did not like the Bid proposals tab's job column and how rows wrapped at the pane's width. Client only, no migration and no function; one file, `src/pages/Documents.tsx`.

- **What was wrong, on all four ledgers.** The "Job" column on Bids and Jobs held the site address, which took three or four lines in a column that wide. The customer column repeated an address under the name, a GC's office suite nobody needs on a documents ledger and on Jobs usually the same address as the site column beside it. The service tag sat in a flex row centred against the title, so a wrapped title left the tag floating mid-stack. The two Docs icons stacked and short customer names broke in two, so each row's height came from whichever cell lost. Estimates showed status as plain words while Bids and Jobs showed chips of two sizes. Supply invoices printed `— | <job>` for an unnumbered job, `· 100%` on every single-job invoice, and clipped the address with an ellipsis mid-word.
- **The row grammar.** The title cell owns the row: the service tag inline on the first line (`ledgerServiceTagStyle`, an inline-block at text-bottom so a wrapping title keeps it on line one), the number and name as the link, and the site address as a muted line under it (`ledgerTitleSubLineStyle`). The site column is gone on Bids and Jobs; on Estimates the linked job folds under the title as `Job #972 · <name>`. Customer is the name alone with the address as the cell's `title`. Docs, Status and Total carry fixed widths and `white-space: nowrap`. The header names what the column holds: Bid, Job, Estimate. Status is one chip style (`ledgerStatusChipStyle`, 0.7rem) on all three; Estimates gets `documentsEstimateStatusChip` in the same palette as `bidSearchStatusChip` and `jobPickerStatusChip` (accepted green, sent amber, declined red, draft grey). The Jobs ledger's child rows span five columns now, not six.
- **Supply invoices.** The `— |` prefix is gone, the share (`· N%`) draws only when an invoice is split across more than one job (`showShare`), the address under the job wraps instead of clipping, and the Date cell never breaks.
- **Measured.** Each table measures exactly its wrapper at an 800 px pane (712 px), where before the Bids table ran to 804 px and scrolled sideways; at 1280 px every row is two lines. The Search tab mounts the same four tables, so it reads the same way.
- **Left for another pass.** Under about 700 px a card list would beat any table; the 200-row cap still hides older records from search; the dashed **+** add-link press carries a raw grey hex from before the token rule.
