# v2.2589 — Bill scoping: rows linked to other invoices never re-list (2026-09-01)

User report (taunya, 2026-09-01, job 978 again — the v2.2467 job): "Parting out 2 invoices
and the change order was right. This invoice should only say HVAC to spec". Her $1,072.50
primary remainder bundle previewed as **two** lines — "CHANGE ORDER: Deep cleaning of 2
systems $585.00" + "HVAC to spec $487.50" — even though the change order was already billed
on its own (linked) invoice.

**Mechanism** (numbers penny-exact): job = CO $1,980 (linked to its own invoice) + HVAC
$1,650 (unlinked), $577.50 paid → primary bundle $1,072.50. The v2.2469 exact-sum
composition can't apply ($1,650 ≠ $1,072.50), and the old fallback prorated the target
across the **whole job** — 1980/3630 × 1072.50 = $585.00, 1650/3630 × 1072.50 = $487.50 —
re-listing the already-billed change order.

**Fix**: in both scoping mirrors ([`src/lib/invoiceScopedFixtures.ts`](../../src/lib/invoiceScopedFixtures.ts)
and [`supabase/functions/_shared/stripeInvoiceItemsFromFixtures.ts`](../../supabase/functions/_shared/stripeInvoiceItemsFromFixtures.ts)
`scopeFixturesToInvoice`), when no rows link to THIS invoice the candidate set is now the
**still-unlinked rows only** — a row linked to another invoice is on that bill and never
re-lists. Applies to the primary bundle AND non-primary dollar carves. Jobs with no links at
all are unchanged (the sets are identical). Every row linked elsewhere → empty set → the
builders' existing single-line fallback. Safe against dangling links: `fixtures.invoice_id`
is `ON DELETE SET NULL` (migration `20260729002615`), so voided/deleted invoices release
their rows.

- Taunya's bill now reads one line: "HVAC to spec — $1,072.50".
- New client/edge parity suite in `invoiceScopedFixtures.test.ts` (imports the edge kernel
  directly, the `estimateOptionsSharedParity` pattern) + a regression case with the job-978
  numbers.
- `docs/BILLING_FLOWS.md` fixture-listing rule updated.
- **Deploy note**: redeploy `preview-stripe-invoice` and `create-stripe-invoice` (they
  compile in the `_shared` kernel). Edge-first is safe and immediately fixes Stripe bills
  even under the old client; the client copy only aligns previews/physical PDFs.
