# v2.7872 — Pay: the dev seat's plan names both days the salary sync fills (2026-11-18)

Words only, on `plan_pay_setup` and `apply_pay_setup` (v2.7821). No new verb, no new server number, no migration.

## Why

The first live walk of the pair, on a ZZ Test row, turned Salaried on with a workday from 06:00 and a start date of that day. The plan said *apply syncs today's*. The clock then held two unapproved 8-hour sessions: one for that day and one for the day before, which was before the start date.

The app's own function does that. `sync_salary_clock_sessions_for_user_day(user, day)` syncs the day it is given and the day before. `salary_sync_one_user_clock_sessions` reads the template, time off and the weekend rule. It reads no employment start date and no Salaried flag. The sheet's Salaried tick calls the same function, so the sheet does the same.

Turning Salaried off cleared both sessions: the clear function removes the template, then syncs, and a sync with no template removes the unapproved auto-sessions of both days. The plan said only *today's*.

## What changed

- **The plan's `clock` words** say that apply syncs today and the day before, and that the sync reads no start date.
- **`clock.sync_days`** lists the two days when the sync will run. **`clock.sync_before_start`** names the day before when a template will stand and that day falls before the start date. The words then say a session can appear there, and that payroll's credit still starts on the start date.
- **Salaried off** reads *the unapproved auto-sessions of today and the day before*, in the plan and in the step's words.
- **The sync step's words** after an apply name both days.
- **`fixed_day`** is two sentences now. It had two colons in one.

## Not in this change

The sync itself. Whether a salary session should be made for a day before a person's start date is the app's question, on the sheet as much as here. This change makes the seat say what happens.
