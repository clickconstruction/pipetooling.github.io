# v2.7117 — The Bridge keeps its check on a line when the link is taken off the task (punch list #334, PR 12) (2026-11-12)

PR 12 of the Bridge train (card #334, `to-dos/bridge-pulse/`), the last, on PR 11 (v2.7115). One migration. No edge function.

Since PR 9 a line on *What to do now* can be handed to one person as a task, and the Bridge finds that task again by `?todo=<key>` in its first link. A person who deleted that link lost the check. This gives the tag a home on the card.

## What changed

- **A column** (`20261113110000_checklist_items_source_tag.sql`): `checklist_items.source_tag`, nullable text, with a partial index, back-filled from any link that carries `todo=`.
- **The Add task window writes it** (`ChecklistAddModalContext.tsx`, `ChecklistAddModal.tsx`): a preset may carry `sourceTag`. After the card is made, the window writes the tag onto it. The write is apart from the insert and is allowed to fail, so a card is always made.
- **The Bridge reads by it** (`callTodoIo.ts`, `callTodoState.ts`): `loadTodoCards` asks for the cards whose tag is one of the page's keys, and still asks by link for a card made before the column. `cardKeys` reads a card's own tag first, then the tag in any link. A read by tag that fails leaves the cards to their links.
- **The page** (`Bridge.tsx`) hands the Add task window the line's key, and still tags the first link, so an older client and a card with no column both keep working.

## Safe on either side of the push

The client calls nothing that only the migration creates in a way that can refuse a save: the insert does not name the column, and both the write and the read by tag are allowed to fail. Until the push a new card is found by its link, as before.
