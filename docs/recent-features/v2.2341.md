# v2.2341 — Portal view counting (customer-side measurement) (2026-08-26)

CX-audit measurement plan: the paying customer's tokenized pages were a
measurement blind spot (the page-time/click ledgers only see signed-in
users). Scoping discovery: **estimate-accept views were already recorded** —
`get-estimate-for-customer` has appended `estimate_customer_events`
(`event_type='public_link_view'`, IP/UA, 5s dedupe) on every valid open
since migration `20260406034514` — so this PR adds only the genuinely
missing half: the portal.

- **Migration `20260826160132`**: `public.public_page_views` — surface
  (CHECK pre-allows portal / estimate_terms / contract_accept /
  hazmat_notice; v1 writes only `portal`), `entity_id` (customer id, no FK
  on purpose), `via` (token|slug), `occurred_at`. RLS: **no write policies**
  (service-role only — no anon-writable path, junk traffic can't inflate
  counts); SELECT `is_dev()`. Both read-only sweep calls.
  Details: `docs/migrations/20260826160132_public_page_views.md`.
- **`customer-portal` edge function**: after the link/slug validates and the
  customer resolves, one fire-and-forget insert — measurement can never fail
  the statement. Deployed manually per the edge-function track.
- **`scripts/audit-nav-usage.sql`** gains queries 6–7: weekly portal views
  by via, and the monthly estimate-open history already sitting in
  `estimate_customer_events`.
- Remaining public surfaces (terms, contract signing, hazmat) are
  pre-allowed in the CHECK and wire up as one-line function edits when
  wanted.
