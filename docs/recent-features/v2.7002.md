# v2.7002 — First look: a finished file moves out from under its upload address (2026-11-12)

Punch list #319, what is left of PR 3. The spike left one thing known and open: an upload address is good for two hours and may write its place again, so whoever held a look's link could put other bytes where a finished, checked file sat.

- `first-look`'s `done`, once the file's first bytes pass, moves the object to `<look id>/kept/<file id>.<ext>` (`firstLookKeptPath` in `_shared/firstLook.ts`) and the row keeps that place. The card, the desk and the sweep all read the row, so nothing else changes. A move that fails is logged and the file stays where it was, so a customer's photo is never lost to this.
- `photo-save`'s looks pass ends by clearing the old upload place of each file finished between two and twenty-six hours ago, after its address has run out (`FIRST_LOOK_UPLOAD_ADDRESS_HOURS`). Removing a place that holds nothing is not an error.

The sweep's half of PR 3 (the copy to Drive in pieces, a look with no Send counted as sent) shipped in v2.7001.
