# v2.6303 — Documents tab: Add a file to a job’s Drive folder from the app (2026-11-01)

The owner's ask after punch list #236 put every job's files in one Drive folder and v2.6301 gave the Pipeline a door to them: a file sitting on someone's computer still reached a job's folder only by hand in Drive, or through Messages' Save to Drive once it had been emailed. Now the Documents tab puts it there itself. Client plus one widened edge function action, no migration.

- **The press.** `JobDocumentsAddFile` sits beside each row of the Documents tab's **Job folders** list (`JobWindowDocumentsTab.tsx`, for the roles `canMakeJobDriveFolders` names). It opens this computer's file picker; a chosen file opens a panel under the row with its name and size, where it goes, and a press that names the act and the folder (**Add it to Plans**), never OK. The line afterwards says *<name> is in Plans.* with **Open in Drive** and **Add another**. A file over 10 MB is told so and gets no press; a refusal shows the function's own reason (`formatErrorMessage`) and keeps the file picked.
- **Where it lands** is the row's own, so nobody picks a half: *Job folder* → the job's folder itself (`where: 'top'`), *Plans* → the job's Plans folder by its `job_plans_link`, else Plans made under the folder (`'plans'`), *Pictures* → the job's photo folder, Customer Pictures made as needed by `photoFolderFor` (`'pictures'`). The kernel `src/lib/jobs/jobFolderAddFile.ts` holds the mapping, the cap and the words; `jobFolderAddFileIo.ts` reads the file as base64 and calls `drive-link`.
- **`drive-link` `put`** (`supabase/functions/drive-link/index.ts`, `_shared/driveLink.ts`) takes the three new `where` values beside `sent` and `photos`; `putFolderFor` resolves each. The office gate, the twin refusal, the training-account refusal and the 10 MB cap are the function's own, unchanged. **Redeploy `drive-link` once this merges.**
- A file put this way shows in the folder's listing as *Added in Drive* (the app keeps no row for it yet); a `drive_links`/`uploaded_photos` mark for it is a follow-up.
- Tests: `jobFolderAddFile.test.ts` (the row mapping, the cap at the byte, size words, the labels), `JobDocumentsAddFile.render.test.tsx` (pick → panel → confirm → the io call and the line; too big; a refusal; a row not served), `driveLink.test.ts` (the three `where`s parse, an unknown one is refused). The guide *move between a job's Job, Edit, Bill, and Costs tabs* gains *Add a file to a job's folder*; `docs/EDGE_FUNCTIONS.md`'s drive-link section names the destinations.
