# v2.4649 — Legal: the law firm hears when the office asks, notes or applies a payment (2026-10-05)

Punch list #85, item 17, PR 2 of 2 (lane D). Only three events reached the firm by email: a release, an office answer and a pull-back. An office ask, a note or an applied payment waited until someone at the firm happened to open the portal.

## What changed

- **Migration `20261006170000_legal_firm_notify_events.sql`, in its own PR (#4690)**: the queue takes `ask`, `note`, `applied`, `fee_seen` beside `referred`, `answer`, `pulled`; the office-entry trigger queues each (the answer's payload carries the firm's question); a new trigger queues `fee_seen` when the office acknowledges a firm fee or cost. See `docs/migrations/20261006170000_legal_firm_notify_events.md`.
- **The emails** (`_shared/legalEmails.ts`): `LEGAL_NOW_TRIGGERS`, `legalNowTriggerOf` (an unknown trigger is skipped, never worded as a pull-back), `legalTriggerSendsNow` (`fee_seen` is digest only); `buildLegalNowEmail` words each event (*Click asks your sign-off on Lenox Builders*, *A note from Click on…*, *Payment applied on…*; the answer quotes *You asked:* and *The office:*); the digest labels each kind.
- **`legal-notify-dispatch`** reads the trigger through `legalNowTriggerOf`, passes the new payload fields, and stamps a `fee_seen` row in the now lane without sending.
- The portal's Notifications page and the guide *manage who at the law firm gets emails* list every event; the email catalog's `legal_referral` row lists the variants.
- Docs: EDGE_FUNCTIONS (`legal-notify-dispatch`, `submit-legal-portal` redeploy-only), ACCESS_CONTROL (the migration doc ships with #4690).

**Deploy (order matters)**: merge this PR (client via CI) → `supabase functions deploy legal-notify-dispatch submit-legal-portal` → only then merge #4690, the migration that starts queueing the new events → `supabase db push`. The old dispatcher words any event it does not know as a pull-back, and migrations are pushed within minutes of their merge, so the split turns the deploy order into a merge order.

## Is this the best we can do?

- *Should a seen fee email right away?* A paralegal adding six filing costs would get six emails back. It rides the digest; asks, notes, answers and applied payments go right away, because each asks for or changes something.
- *Should the office's own steps (Move it back, Close the matter) email too?* Closing is the end of the matter and the firm loses the portal page; a later PR can add a `closed` event if the firm asks. Kept out to ship the events item 17 named.
- *One trigger function or several?* The existing insert trigger keeps its name and grows its body, so no second insert trigger competes for the same row.

## Integration pass (review fixes)

- **Honest scope.** Not every office event emails the firm: closing a matter, *Move it back*, the office's undo and a signed-off step send nothing. The title, the release note and the comment on `LEGAL_NOW_TRIGGERS` say what is sent; the four stay on the portal and can join the queue later.
- **One list, never a mislabel.** `buildLegalNowEmail` switches on every trigger by name (`case 'pulled'`, no catch-all), and the dispatcher logs an unknown trigger and stamps it with nobody to send to (`legalNowTriggerOf` → null), so it is never sent as *Referral withdrawn*.
- **Lane E's ledger kept.** The dispatcher keeps item 26's per-person `sent_to` ledger with this PR's `legalNowTriggerOf` / `legalTriggerSendsNow` and the new payload fields (`question`, `reason`, `amount`, `flavor`). `fee_seen` gets an empty list of people to send to now, so its row stamps at once and waits only for the digest.
- **The askId cast is guarded.** The queue trigger casts `meta->>'askId'` only when it is a real uuid, so a malformed value can never fail the office's insert.
- **Deploy order**: split into two PRs on 2026-10-06. This one carries the dispatcher and the words and is safe against today's triggers (an `answer` without its `question` reads *The office answered your question on …*). #4690 carries the migration and is armed only once `legal-notify-dispatch` is live with this code.
