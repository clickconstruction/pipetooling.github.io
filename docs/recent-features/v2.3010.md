# v2.3010 — Test-gap audit, pass 24: bank-category tag writes get their first tests (2026-09-07)

Follow-up to v2.3007. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`banking/categoryTagsData.ts` (203 lines) is the Supabase side of bank-category tags: load, save, membership, the tx → accounting-label lookup the cost-line split uses, merge, delete and reset. Five callers across Banking, People → Review and the jobs allocation hook. Its pure companions (`categoryTags`, `categoryTagMembersDiff`) were tested; the writes were not, and the membership write in particular has a specific order of operations (evict, then insert) that the unique indexes depend on.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Saving a tag trims the name, defaults a blank icon to 🏷, stamps `updated_at` on an edit, and on a create stamps `created_by` with the signed-in user (null when signed out) and returns the new id.
- Bringing a tag's membership to a target set first deletes what left the tag (categories case-insensitively), then for each addition **evicts** the category or label from wherever it lived before inserting it under the tag, so a category or label lives in one tag only. Nothing is sent when the membership already matches, and the write stops at the first failure.
- The tx → label lookup asks nothing for an empty list and otherwise reads in chunks, ordered and ranged.
- Merging moves the members, re-points only the accounting rules whose `bankTag.tagId` named the source (with the target's fresh category snapshot and a new `updated_at`), ignores rules with missing or malformed criteria, then deletes the source, and refuses to merge a tag into itself before touching anything.
- Every failure throws with the server's message.

## What shipped

- **`banking/categoryTagsData.test.ts`** (10) — a recording Supabase stand-in (tables, `rpc`, Auth) with a one-line-per-query trace so the write sequences read as expected literals. Covers the load mapping and orders, both save paths and their failures, the membership sequence (six statements for a two-remove / two-add change), the no-op and stop-on-failure cases, the chunked label lookup, the merge sequence with a five-rule fixture, self-merge refusal and stop-on-failure, delete and the seed RPC. `useCategoryTags` is a React hook and is left to render smokes.
