# v2.7706 — Documents: every bid shows all of its fixture lines (2026-11-17)

Found in passing while checking the Agreements tab (punch list #376) against the live list: the console logged `[row-cap] bids_count_rows returned exactly 1000 rows with no limit` when the Documents page loaded its bids.

## What was wrong

Documents → Bids lists the newest 200 bids and read their count rows in one request with no range: `.in('bid_id', ids)` over `bids_count_rows`. PostgREST answers such a read with the first 1,000 rows and a 200. Once those bids carried more than 1,000 count rows between them, the rest were dropped with no error. A bid lower on the list showed too few fixture lines or none, and the tab's search, which matches fixture names, could not find it by one. The Search tab's Bids section reads through the same loader.

## What changed

- `src/lib/documents/documentsBidCountLines.ts` holds the read and its rule.
  - `loadDocumentsBidCountRows` reads `bids_count_rows` and `bid_versions` through `fetchAllRowsChunkedIn`: 150 bids to a chunk, each chunk paged, under an order that ends on `id` (`sequence_order, id` and `sort_order, id`) so pages cannot shuffle. A bid's rows all come from one chunk, so its own order is unchanged.
  - `documentsBidCountLinesByBid` is the page's version rule, moved out whole: a bid shows its saved version's rows, else its first version's, else the rows with no version.
- `src/pages/Documents.tsx` calls the two, with the read still under the page's retry (`withRetry`). The `bid_versions` read gained the `id` tiebreak and is paged too.

## Tests

`documentsBidCountLines.test.ts`, on the fake client that mimics the 1,000-row cap: 200 bids with 2,400 rows all come back and the last bid keeps its twelve, every request is ranged and chunked, each order ends on `id`, no bids reads nothing, a failed page throws. The version rule has four cases.

## Checked

In a local build on live data, as the dev, with the page's own requests recorded: the Bids tab's load reads close to six thousand count rows for its 200 bids, in two chunks of four and three pages, where the old read stopped at the first thousand. No `[row-cap]` line fires during the load.
