# v2.3025 — Test-gap audit, pass 35: write-up templates get their first tests (2026-09-07)

Follow-up to v2.3024. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`writeupTemplateSchema.ts` (159 lines) is the pure kernel under People's write-ups: the block schema a template stores (prompt, text, textarea, checklist), the blank answer set a new write-up starts from, answer validation against the schema, and the JSON written back. The template manager, the editor modal and the form fields all lean on it. No test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- Parsing trims ids and text, coerces `required` to a boolean, keeps only non-blank checklist options, treats a blank checklist label as none, and names the failing block by index or the duplicate id (after trimming).
- A new write-up starts with empty strings for text blocks and empty lists for checklists; prompts store nothing.
- Validation trims text, drops checklist values that are not among the options, keeps keys the schema does not know, and reports every unmet requirement by label, with a generic line for an unlabeled checklist. With requirements off it still normalises. A non-object answer set reads as empty.
- The JSON written back carries only each block's own fields with `required` explicit, and parsing it again is the identity.
