# v2.7033 — Pipeline: the search box and its chips fit a phone (2026-11-12)

Follows v2.7014, which fixed the 760 px overflow. At 375 px a dev's Pipeline still ran 57 px wider than the screen. The search box shared a line with **Projects** at 265 px, and its pieces never shrink: the clock and `#` chips, the input's 3.5rem floor, the ⋯ and the dev-only *N ZZ test jobs hidden* chip (113 px) need about 336 px. Even on a line of its own, the box was about 9 px too wide.

- **The box takes its own line on a phone.** At 640 px and below, `.stagesSearchBox` (`src/index.css`) is `min-width: min(100%, 20rem)`, no longer `0`. With Projects showing, the 264 px left beside it is less than 20rem, so the box wraps under it at full width. That is a row more for every role that sees Projects, and the search words get room to type. Above 640 px it stays `min-content` (v2.7014).
- **Applied-filter chips shrink.** `stagesActiveFilterChipStyle` in `JobsStagesCommandBar` is `flexShrink: 1` with a `2.75rem` floor. Its words already end in an ellipsis, so a narrow box shortens the chip and the page stays put. The chip's `title` keeps the whole words. Above 640 px the box is never narrower than its chips, so they keep their full width there.

**Measured** (local dev server, dev login, `scrollWidth - clientWidth` on `/jobs?tab=stages`): 320 → 0, 375 → 0 (was 57), 414 → 0, 600 → 0, 700 → 0, 760 → 0, 1400 → 0.

No migration, no edge deploy.
