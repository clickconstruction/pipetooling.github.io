# v2.6339 — Three guides read each section once, and the guide tests refuse a heading written twice (2026-11-01)

The session that fixed the Documents tab's *From the app* chip (v2.6334) saw `job-window-tabs.md` carrying `## Add a file to a job's folder` twice, word for word. The stacked v2.6305 PR (#6751, Find a file) had re-added v2.6303's section when the merge queue squashed the stack. This removes the second copy, checks whether any other guide had the same fault, and makes CI refuse the next one. Guides and a test kernel only: no migration, no edge function, no screen.

- **`job-window-tabs.md`**: lines 46–58 were the same thirteen lines as 32–44 (checked with `diff` against current main, `4eb207540`; neither copy carried a later edit, so the second goes, with its blank line). The anchor the page stamps for the heading is `#add-a-file-to-a-job-s-folder` (the apostrophe becomes a hyphen, as `headingAnchor` always has), and the second copy took `-2`. Nothing in `src/`, `docs/` or `scripts/` linked to either.
- **Two more guides had the same fault**, found by scanning all 473 for a heading whose anchor an earlier heading in the same guide had taken. A second look for a paragraph written twice found nothing the heading scan had not.
  - **`see-every-job-and-bid-on-one-map.md`**: v2.4805 (#4823, Map page refresh PR 4 of 5) added its new *Opening a record from a pin* before the old one instead of replacing it, with *Cluster the piles* repeated between them. The page read both, and ended with an example (*Turn off Estimates and the Lost stage*) that contradicts the chips starting off since v2.4802. The newer *Opening a record from a pin* stays: it is the one that matches `MapPageRail.tsx` (the selected place's card sits in the rail, is the bar on a phone and is also the pin's popup). The second *Cluster the piles* (identical to the first), the older *Opening a record from a pin* and the older example go, 23 lines.
  - **`fill-out-an-aia-g702-g703.md`**: `## When an earlier application changes` was written on two lines in a row. v2.6017 (#6372) added *The final application releases the retainage* above it and brought a copy of the heading along. One line goes.
- **The test.** `repeatedHeadings(body)` in `src/lib/helpGuideAnchors.ts` returns the text of each `##` / `###` line whose anchor an earlier heading in the body already took, so `Sizes` and `SIZES!` count as one and a `###` repeating a `##` counts. `src/lib/helpGuideContent.test.ts` runs it over every real guide and fails with the guide's slug and the headings it wrote twice. `src/lib/helpGuideAnchors.test.ts` holds two cases: the shape a squashed stack leaves (the section again, word for word) is named, and a guide with one of each heading, an `h1`, repeated `h4`s and headings with no letters passes. Run over the three guides as they stood on `origin/main`, it names `Add a file to a job's folder`, `Cluster the piles` with `Opening a record from a pin`, and `When an earlier application changes`. A heading's text is its address (`helpGuideHref`), so two with one text were never meant: the page's `-2` numbering stays for safety and the existing link test still reads it, but no guide may use it.
- **Docs**: `CLAUDE.md`'s *Help guides ship with features* bullet names the refusal in the sentence that already says what `helpGuideContent.test.ts` validates.

The scan found none, and a byte match on blocks needs the `:::` fences taken out first, or the two *Preview & test* examples in `ready-to-bill-pipeline.md` (they share a first line and differ after it) trip it.
