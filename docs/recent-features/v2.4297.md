# v2.4297 — Bids: mark a bid for a teammate, with a note (2026-10-01)

**The ask (Grace, 2026-10-01).** "If I wanted an estimator to highlight a bid for another user, how could I offer this tastefully?" — plan it, ask whether it is the best we can do, mock it up, ask again. Canvas: https://claude.ai/artifact/NM7RnRanRjhAwSH6eK9TMv (row 1 = the first draft, row 2 = the approved design). Builds on v2.4287 (a person's own marks, `bid_marks`), which is unchanged.

**What the two passes changed.** The first draft drew a request like a note to self, hid the note in a hover card (no iPad), added a permanent *Sent* button to nine tabs, and offered no way to finish from inside the bid. The approved design puts the note on the row, opens the card on a tap, answers the sender on their own rows (outlined initials), and puts **Done** under the bid's title. The second pass added **Not for me** (a mark sent to the wrong person) and the rule that a bid marked for you shows under **Only my bids**.

**What shipped.**

- **Database** (`20261001170000_bid_mark_requests.sql`, `docs/migrations/`): `bid_mark_requests` (bid, for, from, note ≤ 280, created / seen / closed, outcome done | not_for_me | taken_back), RLS read for the two people only, writes only through `mark_bid_for()`, `bid_mark_requests_seen()`, `bid_mark_requests_close()`, `bid_mark_request_take_back()`; `user_opens_bids()` and `user_has_push_device()`. Rehearsed on production in a rolled-back transaction as real accounts (18 steps, in the migration doc).
- **Kernel** `src/lib/bids/bidMarkRequests.ts` (+ tests): open requests for me by bid, the sender's newest shown request per bid (open, or finished within three days, never taken back), the sender's words ("for Robert · seen Tue", "Robert is done · Mon", "Robert passed it back · today"), the receiver's line and heading, who to suggest (the bid's estimator and account man first, never me, never twice). `bidMarkDayWords` moved into `bidMarks.ts` and backs "marked Fri" too.
- **Store** `bidMarksStore.ts`: `requests`, `people` (the Bids roster from `Bids.tsx`), `me`; `refreshBidMarkRequests` on load and whenever the tab comes back; optimistic seen / close / take back; `markBidForPerson`, `personHasPushDevice`, `sendBidMarkPush`.
- **UI** `BidMarkControls.tsx`: `BidMarkDot` now has three faces (own mark, filled sender initial with a blue not-seen dot, outlined receiver initial with a green check when done); `BidMarkInitial` + `BidMarkRequestCard` open in a floating layer on the page body (the picker list and the board clip their overflow); `BidMarkForSomeone` (the form); `BidMarkSentStatus`; `BidMarkRequestStrip` under the title (marks seen on mount). `BidWorkflowTabTitleWithPreview` renders For someone…, the status and the strip (a sibling of the heading, `flex: 1 1 100%`; the RFI / Change Order / Lien Release header rows now wrap). `BidPickerStandardList`: the note line, the sender's words, the wash for a bid marked for you, a hold or H finishes it. `BidsBidBoardTab`: the initial before the number on rows and cards, the wash, the hold, the Marked filter. `Bids.tsx`: `isMyBid` counts a bid marked for you (every tab's Only my bids), the roster effect, the visibility refresh. Tokens `--bid-mark-on / -solid / -new / -done`.
- **Push** `supabase/functions/notify-bid-mark` (+ `config.toml`, `EDGE_FUNCTIONS.md`): body is only `request_id`; the caller must be the sender; the function writes its own words; one push per device; `notification_history` `bid_mark`.
- **Also**: `NewReportModal.tsx`'s two `supabase.rpc.bind(supabase)` casts hit TS2589 once `database.ts` grew by six functions; they now cast the client instead of binding the typed overloads.
- **Docs**: guide `find-a-bid-on-the-workflow-tabs` (three new sections), `GLOSSARY.md`, `ACCESS_CONTROL.md`.

**Decided (the defaults Grace accepted).** Anyone who uses Bids may mark for anyone who uses Bids. The phone box starts unticked. Not for me stays. A finished mark stays on the sender's list three days. The not-seen dot is blue so it never reads as Pending amber. Not the bottom-bar Inbox: that is the team's queue for customer requests.

**Deploy order.** Merge → `supabase db push` → `supabase functions deploy notify-bid-mark` → regenerate types.
