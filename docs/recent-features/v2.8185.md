# v2.8185 — The Job window stops looking for the Bill press when it closes (2026-11-21)

A fix found while PR #9208 (punch list #410) was in CI. Taunya said to do it on 2026-11-21. Client only, no migration.

## Why

`JobFormModal` brings **Bill the N picked** into view after lines are picked: it looked for the press every 100 ms, up to 50 times. Nothing stopped that looking when the window closed. In `JobFormModal.billTrips.render.test.tsx` a look could come after the test's page was torn down, throw `document is not defined` as an uncaught exception, and fail the whole Test step. On 2026-11-21 that happened on PR #9208's CI run with 5,595 test files and 56,031 tests passing. The PR did not touch the Job window, so any PR could be hit.

## What changed

- **`landWhenDrawn(find, land, options)`** in `src/lib/landWhenDrawn.ts`: the loop as a kernel. It lands once the thing is there with a height, gives up after its tries, and answers a stop for the screen to call. It also stops by itself when its page is gone. A second stop changes nothing.
- **`JobFormModal`** starts the looking through it, stops the one before when a new one starts, and stops it when the window closes.

## Verified

- `src/lib/landWhenDrawn.test.ts`, 4 tests on fake timers: it lands and looks no more, it gives up, it stops when told, and with the document gone it stops without a throw and leaves no timer.
- `src/components/jobs/JobFormModal.billTrips.render.test.tsx`, one new smoke: with the looking live, the window is closed, and no further look for the press is made. With the stop-on-close line taken out, the smoke fails (12 looks where 5 were made by the close), so it holds the fix.
- The other twelve `JobFormModal` test files, lint, and a typecheck scoped to the changed files.
