# v2.7496 — Bids and plan sets: room for a schedule and a sheet count (2026-11-16)

Punch list #367, PR 3 of the plans-by-date train. One additive migration and no screen: `20261117070000_bid_schedule_and_set_sheets.sql` ([its doc](../migrations/20261117070000_bid_schedule_and_set_sheets.md)).

## What it adds

- A bid can hold a promised schedule: `schedule_start`, `schedule_end` and `schedule_open_ended`. The owner's call of 2026-11-16 is that a person types the start and the end, and nothing is counted from the day the bid was sent. An empty start means no schedule. The flag is for a schedule that runs with no end date.
- A set of drawings can hold its sheet count: `plan_sets.sheet_count`.
- The estimator's read of a development (`list_development_overview`) hands back the schedule on each bid and each job's first work day, so the overview door can draw what the office door draws.

## Why it goes alone

A page that reads a column the database does not have yet fails to load. So the columns merge and are pushed first, and the screens that read them (PR 4, the schedule; PR 5, sheets in hand) follow.

## Verify after the push

`npm run check:migration-drift` is level, the three columns are on `bids` and one on `plan_sets`, and the Development page still loads for an estimator.
