# v2.5517 — Bids: the ground for combining two CountTooling counts on one bid (2026-10-13)

The owner's ask of 2026-10-13: two people count parts of one plan in separate CountTooling projects and combine them on one bid, with an Add instead of Update on the review and both links kept on Edit Bid. Designed on a canvas (today, Combine, Recopy, Edit Bid, the Counts sheet: https://claude.ai/artifact/SbTjnk5bEZ9yPRY3pcLU6L) and approved as drawn. **PR 1 of 3: the migration and the kernels**; the review modal and the Counts tab wire it in PR 2, Edit Bid, the Bid Board and the sheet's From pills in PR 3. One migration, no edge function.

- **Migration `20261014210000_bid_count_sources.sql`** (`docs/migrations/20261014210000_bid_count_sources.md`): `bid_count_sources` (one row per CountTooling project on a bid: link, token, project name, scope, importer, first and last import) and `bids_count_rows.source_shares jsonb` (each project's share of a row's count, `{"<source id>": <count>}`, null = no project). RLS by `can_access_bid_for_pricing`. The SQL bed `count-sources` (`scripts/pgtest-count-sources.sh`, `supabase/tests/count_sources/20_scenario.sql`) covers the writes, the refusals and the three readers. The generated types are hand-added.
- **`parseCountsImportText.ts`**: the copy's `sourceToken` (the `t=<uuid>` of the link, lower-cased; `countSourceTokenOf`) and `projectName` (between `Counts, ` and the first ` · ` of the scope heading).
- **`src/lib/bids/countSources.ts`** (new, pure, tested): `decideCountsImportMode` — no token → replace (today's review); a token the bid knows → recopy; another project already on the bid (a source, or a legacy link with a different token) → combine; else replace; a bid with no sources but a legacy link adopts it as its first source (`adoptLegacy`, `legacyAdoptionPatches` stamps the share-less rows as its). The share arithmetic (`parseSourceShares`, `withShare`, `unclaimedOf`, `isWhollyOf`, `resolveShareKeys` for the `INCOMING_SOURCE_KEY` sentinel the review uses until the source row exists on Apply, `sharesForNewRow`) and `countSourceLabel` (*SpaceX BA · Robert*).
- **`countsImportReview.ts`**: `reviewCountsImport` takes `mode` and `incomingKey`. Combine: every pair is *Both counted* (`changed[].combine`: the sum and the pages joined, `joinPlanPages`), nothing is removed (`untouched`), no rename proposals, Add to it by default with `choices.replaceInstead` for a Replace; the plan counts `combined` and `replaced`. Recopy: a pair moves this project's share and keeps the others' count and pages (`changed[].recopy`), an equal share is Same, a missing shared row leaves only its share (`partialMissing` → an update), a row of its own goes whole, rows with no share of the project are `untouched`. Replace with a key claims the rows for the arriving project; a hand paste (no key) writes no shares. Updates and inserts carry `source_shares` (`CountsImportInsert`); the summary and toast say *Will add to 6, add 4. 30 untouched.* / *Added to 6, added 4 · 30 untouched*.
- **`countsImportUndo.ts`**: a re-inserted row keeps its shares; `deleteSourceId` removes a source the import created. **`CountsImportReviewModal.tsx`**: the choices clone keeps `replaceInstead` (the modal's combine face is PR 2).
- **Tests**: `countSources.test.ts` (new, 8), `countsImportReview.test.ts` (+4: pages, combine, recopy, replace with and without a key), `parseCountsImportText.test.ts` (+2), `countsImportUndo.test.ts` (+1).
