# v2.2661 — Faint-text contrast fix + the visual QA sweep (2026-09-02)

Two pieces born from the same screenshot review that caught v2.2478/v2.2481 (customer
documents inheriting the login shell's white text):

**Token fix** (`src/index.css`): the two faintest text tokens failed WCAG contrast wherever
they carried real text.

- Light `--text-faint` `#9ca3af` → `#767f8d` (was 2.26:1 on the `#f0f2f5` page ground;
  now 3.61:1 there, 4.05:1 on white) — timestamps, "No blocks scheduled", calendar day
  numbers.
- Light `--text-slate-400` `#94a3b8` → `#6b7c91` (was 2.56:1 on white; now 4.27:1) —
  Banking's posted/bank metadata.
- Dark `--text-faint` `#6b7280` → `#8892a3` (was 2.13:1 on raised `#1f2937` cards; now
  4.67:1) — the mirror failure.
- Dark `--text-slate-400` `#64748b` already clears 3:1 on both dark grounds (3.08 on cards,
  3.73 on chrome) and is untouched.

All replacements stay a visible step under `--text-muted` so the hierarchy survives.

**The sweep** (`scripts/visual-qa.mjs`): screenshots every app surface AND audits what it
captured — per-surface WCAG contrast of every visible text node against its effective
background (< 3.0 reported), sideways-scroll detection (house rule: never), broken images,
and console errors during load. Flags: `--theme dark`, `--mobile`, `--only <surface>`,
`--extra name=url` for public/token pages, `--json out.json`. Requires the dev server +
dev-login. Eyes found the last three rendering bugs; this finds the next ones automatically.
