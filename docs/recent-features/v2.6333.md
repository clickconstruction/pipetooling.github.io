# v2.6333 — CI gives the checks 40 minutes, so a slow run no longer cancels a good pull request (2026-11-01)

`ci.yml`'s `checks` job had `timeout-minutes: 30`, set when the job took 15 to 25 minutes. The suite has grown to 3,935 test files, and the job now sits right under the limit.

- **Measured over the last 70 completed `ci.yml` runs on 2026-11-01**: of the 56 that passed, the job took a median of 23.5 minutes and a maximum of 29.8, and the Test step took a median of 18.5 and a maximum of 21.3.
- **What it cost**: #6760's job was cancelled at 30 minutes, 2 seconds after vitest printed `3935 passed (3935)`. #6762's was cancelled with its tests still passing. GitHub reads both as a failed `checks`, so an armed PR waits with no broken test to fix, and a rerun is the only way forward.
- **The change**: `timeout-minutes: 40`, and the comment above it now gives today's numbers. A stalled check still fails rather than holding the queue. The merge queue's own `check_response_timeout_minutes` is 240, so it never fires first.
- **What it does not change**: the suite's length. Shortening the Test step is separate work, and this limit will need another look if the job's median passes 30 minutes.
