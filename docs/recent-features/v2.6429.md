# v2.6429 — The Bridge dial’s marks read on a phone (2026-11-03)

Fix, no migration, no edge function. v2.6421 (#6900) made The Bridge fit a 375 px phone and named what it left: the Dial's mark labels (*today*, *the pile stops growing*, *above here Collect is the link*, *another crew from here*) drawn on top of each other under the slider. Before v2.6421 the slider's column was 0 px wide, so they all sat on one point.

## Cause

`BridgeDial.tsx` hung each label from its point on the track (a percentage) and dropped a label to a second row only when its point was within 16 points of the one before. Points, not pixels: on a 740 px desk track 16 points is 118 px and the labels clear each other; on a 328 px phone track it is 52 px, while *above here Collect is the link* is 138 px wide, so four labels on two rows overlapped in three places.

## Fix

- **A kernel, `src/lib/bridge/dialMarks.ts`**: `markSpan` gives the box a label covers from its point, its width and the track's width (whole to the right of the point near the left end, whole to the left near the right end, centred between — the same anchor rule the component draws with, now in one place as `markAnchor`); `layMarkRows` reads the boxes left to right and gives each the first row where it clears the one before it by 6 px, in the marks' own order; `markRowCount` says how many rows that took. An unmeasured track puts everything on the first row.
- **The component measures**: a layout effect reads the track's and every label's width (`getBoundingClientRect`, which a `translateX` does not change) and a `ResizeObserver` reads again when the track changes width. The read sets state only when a number differs, so the effect settles in one pass; the layout effect runs before paint, so the first row-less pass is never seen. The track's box grows with the rows (`28 + 13 × rows`), never under its old 54 px, so a desk that takes one or two rows draws exactly as before. Each label carries `data-row` for a check to read.

Nothing the page says changed.

## Tests

- `dialMarks.test.ts` (7): the anchor rule, the four marks on a 600 px track (two rows) and on a 328 px track (four rows, in the marks' order `0, 2, 1, 3`), labels that clear each other on one row, the answer in the marks' order whatever their order on the track, the 6 px gap edge to edge, and the unmeasured track.
- `BridgeDial.render.test.tsx` (+2): jsdom lays nothing out, so `getBoundingClientRect` is mocked to answer a track width and 4.6 px a character; at 328 px the labels take more than two rows and the track's height follows, at 740 px two rows and the old 54 px.
