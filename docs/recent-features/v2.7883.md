# v2.7883 — Lien desk: Mail proof complete waits for the mailed day (2026-11-18)

The owner asked for a look at something seen during a live walk of the desk: every filed lien read *Mail proof complete* in **What went out**, while both of its cards read *Mailed, no number yet*.

**What was on record.** Eleven filed liens, filed two days before, each with the clerk's stamped scan, a file on both copies, no mail number and no mailed day. The serve-by watch, *Filed liens: copies to mail* and the dev seat's `read_lien_filings` all counted them as not served, with days left on the clock.

**Why three places disagreed.** `lienMailProof.ts` read a filed lien's copy as mailed when its day was on record, or a number was typed, or a file was attached. Its count was the scan plus one file a copy, and it never read the day or the numbers. The copies window had dropped the file rule that same day (v2.7846), after the office put a file on every envelope ahead of the mailing: a file can be the wrong file, and the day is a legal fact. The reading behind the chip and the cards was not changed with it.

**The fix (`src/lib/jobs/lienMailProof.ts`, pure).**

- A filed lien's copy is mailed once its day is on record, and not before. A copy that keeps a number or a file ahead of the day reads *Not mailed yet*, with the number on the line when there is one, and still shows its file.
- `complete` needs every counted piece on file, an affidavit's mailed day and no copy owing a mail number. The count itself is unchanged: the files as one piece and each posted copy's receipt as one.
- With every counted piece in and something else missing, the chip names it in place of a full count: *Mailed day not recorded*, or *Mail number missing*.
- **Next:** asks in the order the cards do: the scan, the day (*Record the day the copies were mailed.* when a copy keeps something, *Mail the copies. Then add each receipt.* when none does), a mail number, a receipt.
- A notice follows the same rule for a number: a certified copy with no number holds the chip open. No notice on the live desk was in that state.

**The press (`src/lib/jobs/lienMailProofDoor.ts`).** A new lack, `mailed`, for a copy that keeps a number or a file while its lien has no day. Its press reads **Record the mailing ›**, the words of the Lien window's own save. In *Filed liens: copies to mail* it lands on the lien's whole row with the cursor on its **Mailed** box (`tick` on `LienServeLanding`, `lienServeLandingFocus` in `lienServeStage.ts`). In the job's Lien window it lands on the service step.

**A choice made on the way.** The first proposal dropped the mail number once a receipt was on file. The copies window keeps a mailed lien until each envelope has its number and its receipt (`lienServeProofMissing`), so the chip follows that rule and the number is still owed.

**Not changed.** A mailed lien's card still opens the job's Lien window for its number and its receipt, though the copies window lists it under *Mailed* too. The dev seat's `left` still counts a copy's proof as a number or a photo.
