# v2.6856 — Bid photos find their way to Drive (punch list #306, PR 2) (2026-11-10)

Punch list #306's second PR, on the owner's answer of 2026-11-10 to the card's call 3 (*bid's project folder*): a bid's photos live in the bid's project folder under Team only › Photos. This PR is the Drive leg and nothing on screen: a new edge function, the photo sweep's tenth source, and one small migration. PR 3 is the photos icon on the Bid Board and its window.

## What changed

- **The edge function `bid-photos`** (new; `docs/EDGE_FUNCTIONS.md` → bid-photos): `list` (where the bid's photos go, why they are held if they are, and the bid's photos, after adopting any picture the folder holds and the table does not), `make` (the project folder when the bid has none, then Team only › Photos), `thumb` and `full` (a filed photo streamed, since the folder is not public). The gate is a read of the bid through the caller's own client, so `bids`' policies decide. A training account and a twin read and make nothing.
- **`photo-save`'s tenth source** (`sweepBidPhotos`): an added bid photo is copied from the `bid-photos` bucket into the bid's photo folder, named as the person named it or by day and sender, marked with its row's id as a Drive app property, and the bucket copy is deleted. A bid with no project folder gets one under the jobs root by the office's bid pattern, its link written on the bid.
- **A folder in a personal Drive**: the sweep files as the Workspace person in `DRIVE_IMPERSONATE_USER` when that secret is set. Without it the row takes the reason in plain words and the photo stays in the bucket. A row that could not file is left alone for an hour.
- **The migration** `20261110204006_photo_save_bid_photos.sql` (`docs/migrations/20261110204006_photo_save_bid_photos.md`): `bid_photos.tried_at`, the unfiled index remade to leave a removed photo out, and the `photo-save` cron re-scheduled with all ten clauses.
- **The shared rules**: `_shared/bidPhotos.ts` (pure: the asks, the file name, the adoption, the hold's words, the retry hour; tested through `src/lib/bids/bidPhotos.ts`, 22 tests) and `_shared/bidFolder.ts` (the bid folder rule). `drive-intake` names its folder through the same `bidFolderNameFor`, with no change in what it makes. `uploadBytes` takes optional app properties.
- **The bed** `npm run test:pg:bid-photos` now applies both bid photo migrations twice and reads the cron back.

## Decisions

- **The owner's call 3: the bid's project folder.** It is where a text's photo saved onto a bid already lands, and the folder becomes the job's on a win, so nothing moves.
- **Adoption is by Drive id, and the sweep's own files are marked.** A file the sweep uploads carries `bid_photo_id` before its row carries the Drive id, so a window opened in that moment cannot adopt it as a second row.
- **An hour between tries on a held photo.** Every other source retries each five minutes. Most hand-made bid folders are in a personal Drive today (card #240, call 4), so a held bid photo is the common case until they move.
- **A picture a text saved onto the bid is adopted too**, since the owner's rule is *photos in the folder*. PR 8's branch of `uploaded_photos` must leave those out, or Documents → Photos lists them twice.
