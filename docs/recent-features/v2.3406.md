First of three PRs from the owner's ask ("minimum quantity when ordering … if I was to need a 105ft I would have to order 120ft") and the *Sold in Sticks* brief (artifact `0851b7b5`, 2026-09-14): PR 2 rounds and prices, PR 3 lists what to order.

## Why

A takeoff line stores its quantity per fixture and the bid multiplies by the fixture's count, so the real footage of a part is a sum across the bid — that is what a supply house rounds to sticks. The rule has to be authored once (on the kind of pipe), carried to the line when the part is picked (so old bids do not move), and applied per part per bid (PR 2). This PR is the authoring and the carrying.

## What shipped

- **Schema**: `order_increment numeric(12,4)` + `order_increment_unit text` on `part_types` (the rule for the type), `material_parts` (a part's override; NULL = inherit) and `bids_takeoff_rough_part_lines` (the snapshot; NULL = never rounds). Units: `ft_stick` · `ft_coil` · `box` · `bundle`.
- **Kernel [`orderIncrement.ts`](../../src/lib/materials/orderIncrement.ts)** (+4 tests): `parseOrderIncrement`, `effectiveOrderIncrement(part, type)` → the part's own rule else the type's, with `source` for the grey hint; `formatOrderIncrement` (*20 ft sticks* · *box of 10*) and `orderIncrementChip` (*20 ft*); `roundUpToIncrement` (105 → 120, exact multiples stay, float dust does not add a stick) and `packsFor` — PR 2 reads these.
- **Settings → Catalogs → Material Part Types**: the Add / Edit form gains **Sold in** `[20]` `[ft sticks ▾]` with the sentence under it; the list shows the rule as a violet chip beside the part count. `useSettingsCatalogs` carries the two fields through save and open.
- **Add Part / Edit Part** ([`PartFormModal`](../../src/components/PartFormModal.tsx)): the same pair between Part Type and Notes. With a type picked, the box shows the inherited number as a placeholder and the hint reads *From the Copper pipe type…*; a typed number is the part's own (*This part's own rule (the Copper pipe rule is 20 ft sticks)*); blank with no type reads *sold by the each*. Insert and update write both columns (null when blank).
- **The snapshot**: `TakeoffRoughPartLineRow` gains `orderIncrement` / `orderIncrementUnit`; `persistTakeoffRoughPartLine` writes them; the pricing engine reads them back. Every line-creation path snapshots the effective rule — picking a part on a line, Add assembly → expand, Fill from book, Copy from a previous bid — through `orderIncrementsFor(partIds)` (the loaded catalog first, a by-id read for parts not loaded). Bundle lines carry none.
