# v2.5370 — Lien desk: the run shows where it stands, a journey across the top (run train, PR 2) (2026-10-12)

The first screen change of the run train (v2.5369 the kernels; `docs/DOCSMIT_LIEN_RUN_PLAN.md`, *The run, shown not told*). Additive: `LienRunJourney` sits under the run window's title bar, above the old step strip, which stays until Run-3 replaces the table rows with cards.

**What it draws.** `runJourney()` over each envelope's `runEnvelopeStage()`: six nodes (Built, Signed, Sent, In the mail, Recorded, Delivered), a count under each (*2 of 3*), a tick on a node every envelope has passed, the first node not yet passed lit blue as *now* or amber as *blocked* with the blocker's note on it (*2 wait on Robert*, *1 has no address*), and a fill bar between the nodes as far as the done ones reach. On a phone the six wrap to two rows of three and the bar hides (`.lienRunJourney` in `index.css`).

**What it reads.** The modal's `journey` memo: an envelope counts as printed when the packet printed before this sitting (`printedAt`) or every copy inside it printed in this sitting (`printedCopies` through `runCopyKey`, combined notices by part); mailed from the envelope's method and number as `recipientMailed` already says; the leader's name from the run notices' `leader`. Recorded and Delivered have no source inside the window yet (the window closes on record; delivery is the Docsmit train), so they read *0 of N* and the journey never ends inside the window.

Render smoke `LienRunJourney.render.test.tsx`. Looked at on a harness page in the three states (blocked at Signed, now at In the mail, now at Delivered) at desktop and phone widths.
