# v2.4373 — Approval PDF: a bid with versions prices the version you are on (2026-10-01)

Seen live on BP385 Galloway Park (2026-10-01, flagged during the v2.4368 walk): `downloadApprovalPdf` priced page 2 (the Pricing table and *Total Revenue*) and the letter's amount with `bids.selected_price_book_version_id`, the bid-level saved price, against the active version's count rows. That id belongs to whichever version was active when it was saved. BP385's points at its Value Engineered version's price while its active version is Written to Plan, and a price's assignments, custom prices and hides key to its own version's count rows, so nothing matched: *Price book: —*, *Total Revenue: $0.00*, and a letter for *00/100 DOLLARS ($0.00)*. The name came from the Pricing engine's `priceBookVersions` (the Pricing tab's bid, not necessarily this one) and missed too. Page 1's margins priced every price on the bid against the same rows, so another version's read Incomplete.

## What changed
- **The active version's price, picked as the Pricing tab picks it.** The PDF reads the bid's own versions and price scenarios itself (`bid_versions`, `price_book_versions` by `bid_id`) and resolves the price with `deriveActivePricingId`: the version's own ★, else the bid's saved price when it is this version's, else the version's first. A legacy unsplit bid that prices on a shared template still uses its saved template, now named on the page. `ApprovalPdfContext` loses `priceBookVersions` (the engine's list could be another bid's) and gains `coverLetter.altsLayout`.
- **The margins list the Pricing tab's price cards.** Page 1 lists `cardsRowScenarios` for the active version, each priced through `scenarioPricingRows` on its own version's rows (`loadScenarioInputs`, as the cards read them). Pages 1 and 2 price revenue only, so they no longer pass the cost inputs or the hard-coded 8.25 % tax, which never reached a printed figure.
- **The letter page is the Cover Letter tab's letter.** New kernel [`lib/bids/coverLetterDocument.ts`](../../src/lib/bids/coverLetterDocument.ts): `letterSectionPlans` (a split bid's in-letter versions at their ★, a version-less bid's offered prices), `letterRowsFor` (a section's version's rows, else the unsplit rows, else the active ones), `priceLetterSections` (prices only through `scenarioPricingRows`; an offered with-and-without alternate leaves the section, `letterTotalsWithoutOffered`) and `letterDocument` ($0 sections left off, the active version's GC packet, the same-page plan). The tab's bundle effect and its packet and same-page lines now call it, so the tab and the PDF cannot drift apart. The PDF builds the text the tab's Print and Copy build: no packet gives the single letter (the custom amount and the add-on alternates block as before); same page gives the base bids' amount with the bold *Alternates:* block under it; separate pages give one letter per section, each on a fresh page under its bold *Bid: …* or *Alternate: … — in lieu of …* heading. The layout is this device's: `readCoverLetterAltsLayout` reads the studio switch's `localStorage` key, now exported from `coverLetterSamePage.ts`. Each letter spreads its own amount over the payment schedule and the schedule of values.
