# v2.7518 — Print labels: a box gains a place to remember that its label printed (2026-11-16)

Punch list #304. The owner's word of 2026-11-16 on the third call of the Print labels mock-up ([`to-dos/materials-one-story/print-labels-which-job.html`](../../to-dos/materials-one-story/print-labels-which-job.html)): *add a true "not printed yet" mark*. PR 1 of 2, the database. The cards and the labels window that write and read the mark are PR 2.

## Why a stored mark

The app kept no record of which labels were printed. The *Which job?* window of **Print labels** (v2.7482) says *3 added this week* and offers **The 3 new**, which guesses at the question the office is asking: which boxes still need a label. A box added eight days ago with no label reads as done. A box added yesterday and labelled within the hour reads as waiting.

## What ships

Migration `20261117110000_box_label_printed.sql` ([its page](../migrations/20261117110000_box_label_printed.md)): `job_containers.label_printed_at`, a nullable `timestamptz` with no default. NULL means the app has not seen the box's label go out. No function, no grant, no policy: the screens will write it as they write every other change to a box, under `job_containers_update`.

## Order

The push can come any time after this merges. PR 2 must not merge before the push: it names the column in the read of every box.

## Not here

- No screen reads or writes the column.
- A box made before the column reads NULL whether or not it wears a label. PR 2 counts a NULL as *not printed yet* only for a box made after the mark began.
