# v2.8220 — Bids and permits: `bid_site_permits` answers in one order (punch list #307, PR 5's leftover) (2026-11-21)

Punch list #307 ([`to-dos/bid-permits/`](../../to-dos/bid-permits/README.md)), the open line left under PR 5 by v2.6933: *the function orders by day, number and type, which can tie across San Antonio's two feeds*.

## Why

The client reads `bid_site_permits` a page at a time, and each page is a call of its own. The function stops at 5,000 rows by its own `LIMIT`. One permit in both of a city's feeds on one day tied in the function's order, so at the limit one call could keep one twin and the next call the other. A page could then lose a row or bring one twice. No row ties on prod today and the largest ask is under a fifth of the limit, so nothing was lost: this closes the door before a longer read reaches it.

## What changed

- **Migration `20261121234000_bid_site_permits_one_order`** ([its page](../migrations/20261121234000_bid_site_permits_one_order.md)): `CREATE OR REPLACE` of the function on its live body, read from prod line for line first. `p.id` ends the `ORDER BY`. The arguments, the columns, the invoker rights and the grant are as they were.
- **The bed `bid-site-permits`** (`scripts/pgtest-bid-site-permits.sh`, `supabase/tests/bid_site_permits/`, a line in `scripts/sql-beds.txt`, `npm run test:pg:bid-site-permits`): the order, the house numbers asked for, the cut at 5,000 rows with a tie on the last place, the office's own read and anon's refusal, on the whole schema with the file applied twice.
- **`src/lib/research/bidSiteIo.ts`**: comments only. The client still cuts its pages by `id`, which the API sorts by, and `sitePermitOrder` still puts the answer back newest first. That order is now the function's own, so the kernel's comment is true of the database too.

## Not changed

The client keeps its sort. The card said the id *would let the client stop sorting*. It cannot stop while the pages are cut by `id`: the API's own order replaces the function's on a paged read, and it cannot ask for the day issued, else applied for. Cutting pages in the function's order would need the function to take a page itself.
