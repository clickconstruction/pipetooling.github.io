# v2.4073 — Jobs → Stages: the billed-money reads move to their own hook (2026-09-28)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 2 (`to-dos/decomposition-queue.md`): the first half of the Stages map's step 2, the billed-money data seam (cluster H, `docs/JOBS_STAGES_TAB_ARCHITECTURE.md`).

## What shipped

- **`src/hooks/useBilledMoneyData.ts`** — the four billed-money reads, moved out of `JobsStagesTab` verbatim (same RPCs, same parsers, same comments):
  - `get_billed_customer_pay_speeds` → `billedPaySpeeds` + `refreshBilledPaySpeeds` (the Data health drill-down's refresh, v2.2290);
  - `list_job_promised_pay_dates` → `promisedPayDates` + `loadPromisedPayDates`;
  - `list_payment_promise_records` → `promiseRecordsByCustomer` + `loadPromiseRecords`, and the `promiseSlipByCustomer` memo;
  - `list_payment_chase_touches` → `chaseTouches` + `loadChaseTouches`.
  It takes the two gates as inputs (`canSeeBilledExpectedPay` for the first two, `canMarkPromisedPay` for the last two) rather than reading a role, so the other readers of the same RPCs (the Job window's `useJobBilledExpectedPay`, `usePipelineMoneyOpportunities`, `DashboardFinancialsSection`, …) can adopt it later without a Stages dependency. Named for what it reads, not for Stages, for the same reason (the map had called it `useStagesBilledMoneyData`).
- **`JobsStagesTab.tsx`** — calls the hook right after `useBilledLienClocks`, where the first of the four effects stood, so the tab's effect order is unchanged; `canMarkPromisedPay` moves up beside it. The reloader callers (the promise, Data health, chase and money windows) and `billedExpectedPayChipRenderer` read the same names as before. 5,067 → 5,004 lines; 120 → 116 `useState`; 50 → 46 effects.

Still in the tab from step 2: the chase-modal and money-modal scope kicks and the chase memos (`chaseSummary`, `chaseFullQueue`) — they read the tab's cache scope and `gcTemperatureById`.

## Preserved quirk

A promise-record reload that comes back malformed or refused keeps the record already shown (`if (!records) return`), while the pay-speed and chase reloads replace theirs with null. Pinned by a test; not changed here.
