# v2.8459 — View as: the server refuses the seen marks too (2026-11-24)

v2.8246 stopped the client marking things as seen for a person while a dev is in View as, and v2.8251 gave the server a way to tell such a session. This is call 2 of punch list #417, built on a yes given to the building session on 2026-11-24: the four seen marks that are database functions now refuse that session themselves. A migration only: no client change and no function deploy.

## What changed

- **`job_note_tags_seen()`**, **`task_note_tags_seen()`** and **`bid_mark_requests_seen()`** return 0 and mark nothing for a session opened by Imitate or View as.
- **`legal_firm_intake_seen()`** stamps nothing for such a session. Its office check still runs first.
- Each asks `session_opened_by_imitation()` in one line. Nothing else in the four changed.

Migration `20261124084500_imitated_session_holds_seen_marks.sql`; its doc is `docs/migrations/20261124084500_imitated_session_holds_seen_marks.md`.

## Why

Until now only the client held these marks. A browser still on a build from before v2.8246 would clear an answer, a bid request or a firm's answers that the person had not read, just by a dev looking as them. The server now refuses whatever the build.

## What is not held

A press in View as saves as that person by design, so Done and Not for me on a bid request are untouched. The three marks that are table writes (a bid's notes, a plan question's answers, a first look) stay held by the client alone.

## Tests

The `imitated-session` SQL bed gained a second scenario, `supabase/tests/imitated_session/30_seen_marks.sql`: a person's own password session and own emailed link mark all four, a dev's look marks none and answers as if nothing were there, the firm's office check still refuses in words, and Done pressed in the look still saves.

## After the merge

The migration is pushed with `scripts/db-push.sh`. Then one View as on a sample account on the live site: `bid_mark_requests_seen` called by hand must leave a ZZ test request unseen.
