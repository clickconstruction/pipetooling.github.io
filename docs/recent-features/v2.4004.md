## What shipped

**1. The empty-roster sentence.** Four screens said *No people with Show in Hours selected … open People pay config and check Show in Hours*. There is no such tick, and the pay-config window was retired in v2.3702: a person is on the list once they have a pay row, and that is set on the Users tab's Pay lens. The four read one constant now, `EMPTY_HOURS_ROSTER_MESSAGE` in `src/lib/people/hoursGridRoster.ts` — *No one has pay set up yet. Give a person a wage on People → Users → Pay and they appear here.*

- People → Hours, the grid's empty state (`src/pages/People.tsx`)

**2. Lists rebuilt on every render.** `showPeopleForHours` and `hoursDays` were plain expressions, so every memo that listed them as a dependency (`addSessionPeople`, the pending-by-cell map, the live-by-date map, the job highlight) recomputed on every render. Both are memos now. `showPeopleForMatrix` re-sorted every render and rebuilt the day list inside its comparator; it is a memo over `sortPeopleByTotalDesc`, which works each person's total out once.

- **`src/lib/people/hoursGridCost.ts`** (new) — `hoursGridDayCost(cfg, workDate, recordedHours)` (the page's `getCostForPersonDate` calls it), `recordedHoursLookup(rows)` (one pass over the rows; the first row for a person's day wins, as the search it replaces did) and `sortPeopleByTotalDesc`. 7 tests. The order is the one the comparator gave: the same totals, ties in roster order.
- `getEffectiveHours` had one caller, the cost function, and leaves with it.

**3. The dead `#cost-matrix` handler.** The Hours tab listened for that hash, set a section key the tab does not have, and scrolled to an element id nothing renders — the Cost matrix was retired on 2026-07-15. No link in the app points at it. Deleted.
