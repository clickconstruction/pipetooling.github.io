# v2.2416 — bid_gcs: per-GC due / submitted-to / ITB (2026-08-28)

Phase 4 (final) of `docs/PER_GC_BID_PLAN.md`. Sent, last-contact and outcome all DERIVE from
per-GC records (Phases 1–3 + v2.2407) — but due date, submitted-to and ITB links are per-GC
STATE with no ledger to derive from. `bid_gcs` is their home.

- **Migration `20260828050000_bid_gcs.sql`**: one row per (bid, GC) — `customer_id` NULL =
  the bid's own GC, unique via a COALESCE expression index; `due_date`/`due_time`,
  `submitted_to_name/phone/email`, `itb_links jsonb`. RLS mirrors `bid_version_sends`
  (`can_access_bid_for_pricing`); BOTH read-only blocks applied. Rows are created lazily on
  first per-GC edit — no backfill.
- **Derived bid due**: `recompute_bid_due(bid_id)` sets `bids.bid_due_date`/`bid_due_time` to
  the earliest due among packets with NO send (still open), falling back to the earliest due
  overall; bids with no per-GC dues are left untouched (hand-set dates keep working). Fired
  by triggers on `bid_gcs` AND `bid_version_sends` (a send changes which dues are open).
  Board urgency / due chips / lenses keep reading the bid-level columns unchanged.
- **Client**: `BidGcDetailsEditor` under every GC card in Edit Bid (own GC + recipients via
  `GcCard`'s new `details` slot) — collapsed summary line ("due 9/4 2:00 PM · submitted to …
  · 1 ITB link"), expandable editor with the same ITB link list UX as the bid-level one.
  After a save the form re-reads the derived due and syncs its Due fields (the v2.2407
  don't-clobber pattern). The editor hides entirely until the table is deployed
  (Banking quirk-#17 pattern), so client-first deploy is safe.
- Kernel `src/lib/bids/bidGcDetails.ts` (+7 tests): `deriveBidDue` (pure mirror of the SQL
  rule), `gcDetailsSummary`, `normalizeItbLinks`, `formatDueTime`.
- **Deviation from the plan doc**: the bid-level Due/Submitted-to/ITB fields stay as-is
  (they still work, and the derived sync keeps Due honest) instead of being converted into
  own-GC editors — revisit with `bids.submitted_to`/`itb_links` retirement (plan Open Q #2).
