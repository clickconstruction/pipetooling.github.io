# v2.3569 — Pipeline load speed, PR 1: the unused loader stops; the list-driven effects wait (2026-09-17)

PR 1 of four in `to-dos/pipeline-load-speed/README.md` (Grace, 2026-09-16: *"look at the jobs, stages tab, and look at load speed"*). Client only; the screen does not change.

## The change

- **The Mercury card-charge loader runs only where card charges render.** `jobListForCardCharges` in [`Jobs.tsx`](../../src/pages/Jobs.tsx) is the whole `jobs` list on the Parts tab, the summary's ledger jobs on Job Summary, and a stable empty list everywhere else — so `useJobsMercuryAllocations` short-circuits on Pipeline instead of pulling `mercury_transaction_job_allocations` and its transactions, invoice links and drag-sort assignments in 150-id chunks (the 79-request, 4-second tail the to-do measured).
- **The list-driven effects are keyed on ids and held until the list has loaded.** The Stages thread-stats effect keys on the sorted id string instead of the array identity and waits for `jobsListLoading` to clear; the crew-position RPC, the map's geocoder and the Burn budget footings (already id-keyed) now wait the same way, so the same rows re-merged as scopes land do not re-run them.

## Measured (dev server, prod data, `measure.js` in the to-do folder — cold page on Parts, SPA click to Pipeline)

| | before | after |
|---|---|---|
| Supabase requests per visit | 146 | 67 |
| Last response ended | 4.8 s | 3.2 s |
| Card-charge family (allocations · transactions · invoice links · drag-sort · labels) | 79 | 0 |
| Crew position RPC · geocodes · thread stats | 4 · 8 · 2 | 4 · 8 · 2 |

The to-do's estimate was ≈ −90; the cut is −79. The card-charge family is gone in full. The crew, geocode and thread-stats counts did not fall: their extra runs come after `jobsListLoading` clears, as the per-section scope fetches (`fetchScopeIfNeeded`) merge new rows into the list — that is the shape PR 2 (paint first, enrich after) and PR 3 (one enrichment RPC) change, not a hold that PR 1 can add without delaying the first paint.

Checked after the change, by SPA click with an observer: the Parts tab still fires the allocations loader (2 requests) and Job Summary still does (3); Pipeline fires none.
