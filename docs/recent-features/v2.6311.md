# v2.6311 — Photos: every thumbnail loads, a few at a time (2026-11-01)

The Documents page design spike of 2026-11-01, candidate 5: the walk opened Documents → Photos and the first thing on screen was a page of grey tiles. Client only, no migration and no function.

- **The defect.** Every `UploadedPhotoTile` asked `job-photos` for its bytes the moment the page drew: 89 tiles became 154 calls in one burst (strict mode's double mount counted), the functions gateway answered 13 of them 429, and 21 tiles stayed grey with the camera glyph. The console held over a hundred *Failed to load resource: 429* lines.
- **The queue.** `src/lib/photos/photoBytesQueue.ts` (`makeBytesQueue`, pure: the fetch and the sleep come in): a few reads in flight at a time, the rest waiting their turn; a 429 waited out (Retry-After when the answer names it, else 400 ms doubling with a little jitter) and asked again up to the retries; an answer kept so a second tile, a remount or the viewer never ask twice; a refusal (a 404) kept too so a tile does not ask again on every scroll; a 429 that never clears and a lost signal not kept, so the next look asks again. `jobPhotosIo.photoBytes` goes through two of them, thumbnails six in flight and 400 kept, full pictures two in flight and six kept; each caller gets its own object URL over the kept bytes and revokes its own, so the kept Blob outlives any tile. Every consumer benefits (`UploadedPhotoTile`, `UploadedPhotoViewer`, the job window's `JobPhotoThumb` and `JobPhotosViewer`); `resetPhotoBytes(sleep?)` forgets the kept bytes for a test or a sign-out.
- **Lazy tiles.** `UploadedPhotoTile` asks only once it is within 300 px of the screen (`IntersectionObserver`; immediate where it does not exist, so jsdom tests run as before), so a page of a hundred rows asks for the dozen in view and the rest load on scroll.
- **Measured.** After: 11 calls on first paint, all 200, every tile on screen with its picture; 28 after one scroll, all 200.
- **Tests.** `photoBytesQueue.test.ts` (the concurrency cap, Retry-After and backoff, the retries giving up and not keeping, the kept answer and refusal, the cache making room); `jobPhotosIo.test.ts` resets the queue between tests with no wait and adds a 429-then-200 read served once.
