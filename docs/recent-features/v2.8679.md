## A correction to the migration before its first commit

The file as first written counted proposals in `job_paper_gc_proposals`. That is the name of the migration file that made the table. The table is `job_paper_proposals`. A `plpgsql` body is not checked against the schema when it is created, so the file would have pushed clean, twice, and then failed on every call with *relation "public.job_paper_gc_proposals" does not exist*. It was found by reading `20261125023655_job_paper_gc_proposals.sql` and the generated types, and the five places were corrected. The stand-in run below failed on the file as first written at its first call, and passed on the corrected file.
