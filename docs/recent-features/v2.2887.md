# v2.2887 — Hiring → Source success groups by job board, not by pasted URL (2026-09-05)

Journey-map Phase 4, Tier-2 #43 (J25-F3, "the hiring source table lists each pasted Indeed URL as its own source"): candidates imported from Indeed carry the full pasted candidate-view URL (~779 chars, unique `id=` per person) as `team_prospects.source`, and the rollup grouped by exact trimmed/lower-cased string — the walk saw 25+ single-candidate rows, so the table could not answer the one question it exists for ("which source produces hires"). Cards were already right (`via 🔗 employers.indeed.com` hostname chip); the kernel's design assumption ("referral", "walk-in" free text) predated URL sources.

## Kernel — `src/lib/teamProspectSourceSummary.ts`

- `normalizeTeamProspectSource(raw) → { key, label }` replaces the old private trim/collapse/lower-case `normalizeSourceKey` (still exported, now returns the new key). Order of resolution:
  1. **Blank** → `key ''`, label `(no source)` (unchanged sentinel).
  2. **URL or bare domain** (`HOSTLIKE_RE`: optional scheme + dotted host + optional port/path — sentences with a period do not match) → `sourceHost` (lower-case hostname, `www.` stripped) → `SOURCE_ALIASES` host match (`host === domain || host.endsWith('.' + domain)`, so `employers.`, `m.`, `apply.`, `austin.` subdomains all fold) → alias label. Unknown host → `registrableHost` (last two labels, or three under a ccTLD second level like `co.uk`/`com.au`) used as the label.
  3. **Free text** → collapsed lower-case matched against each alias's `text` regex → alias label.
  4. Otherwise the old behavior: key = collapsed lower-case, label = first-seen spelling.
- `SOURCE_ALIASES` (exported, ordered, first match wins): Indeed (`indeed.com/.co.uk/.ca`, `/\bindeed\b/`), ZipRecruiter, Craigslist, Facebook (`facebook.com`, `fb.com`, `fb.me`, `/\b(facebook|fb)\b/`), LinkedIn (`linkedin.com`, `lnkd.in`), Handshake (`joinhandshake.com`), Glassdoor, Monster, CareerBuilder, Snagajob, Nextdoor, Instagram, Referral (`/\b(referr?al|referred|refer)\b/`), Walk-in (`/\bwalk(ed)?[\s-]?ins?\b/`). Keys are the lower-cased label so `"Indeed"` typed by hand and a pasted `employers.indeed.com` URL share `key 'indeed'`.
- `TeamProspectSourceSummaryRow.variants: string[]` — distinct raw spellings/URLs folded into the row (first-seen order), and `describeSourceVariants(variants)` builds the tooltip text (`N variants grouped here:` + up to 5 previews truncated at 60 chars + `…and N more`); `null` for a single spelling.
- `distinctTeamProspectSources` (the Source field's `<datalist>`) returns the grouped labels, so the autocomplete offers `Indeed` once instead of 25 URLs (the 2b proposal-check note).

## Surface — `src/components/prospects/TeamProspectsTab.tsx`

Source success table: the Source cell carries `title={describeSourceVariants(s.variants)}` and, when more than one spelling folded in, a muted `N variants` note after the label (visible on touch devices where tooltips aren't). Columns, sort (hires desc → total desc → A–Z) and the hire-rate formula are unchanged. No writes, no schema change — grouping is display-side; raw `source` values stay as typed.
