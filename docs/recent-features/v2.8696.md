# v2.8696 — The type check says what memory it held, and warns from four fifths of its cap (punch list #434, PR 2) (2026-11-27)

Infra, no screen. No migration, no edge function, no workflow file changed. The heap `tsc` needs grows with the code, about 130 MB a day for the largest of the three programs (v2.8505), and `tsc` dies at its cap with no warning. Every run of `tsc` now ends with one line on its memory, on CI and on a dev machine, and a run near its cap gets a warning. This is the third of the three ways in `to-dos/owner-decisions-pending.md`'s row on the type check's memory.

## The change

- **One line at the end of every `tsc`** that answered, from `scripts/lib/runTsc.mjs`, so `npm run typecheck`'s three parts and the build's `tsc -b` both print it:
  - On CI: `typecheck: tests-rest's tsc took 6:37, ended holding 8,578 MB of its 13,312 MB heap (64%) after a collection of 6.1 s, and held 9,085 MB resident at most.`
  - On a dev machine: `typecheck: app's tsc took 0:17, ended with 3,300 MB of its 16,384 MB heap in use (20%), not collected first, and held 3,553 MB resident at most.`
- **Where the numbers come from.** A hook, `scripts/lib/tscMemoryHook.cjs`, is preloaded into `tsc` with `node --require`. As `tsc` exits it writes one marked line to stderr: the heap in use, the resident size now and the peak resident size. The runner takes that line out of the stream and prints the words in its place. The words and the rules are the kernel `scripts/lib/typecheckMemory.mjs`.
- **Two numbers, because neither is right alone.**
  - *The heap in use after a collection* is what the program needs, and it is the number the card's tables hold. The collection costs seconds, so only CI forces it (`--expose-gc`). `TYPECHECK_COLLECT=1` forces it anywhere and `TYPECHECK_COLLECT=0` never does. The line says how long the collection took.
  - *The peak resident size* is exact everywhere, covers the whole run and not its end alone, and sits a little over the heap.
- **The warning reads the larger of the two.** A run that held four fifths of its cap or more gets a second line, `NEAR ITS HEAP`, with the room left and this card's path. On GitHub Actions it is also a `::warning` annotation, which shows on the run's page and on the pull request's checks.
- **It is a warning, and the check's answer stands.** The exit code is `tsc`'s own. The card's plan said to fail a part within 10% of its cap. That would stop every merge and the deploy about ten days before the heap itself would, with a check that still passes. So it warns, and from 20% instead of 10%: a fifth of a runner's 13,312 MB is about three weeks at 130 MB a day.
- **A heap death is unchanged.** V8 aborts before the hook runs, so the run ends with `NO VERDICT` (v2.8482) and no memory line.
- **The time is in the line because a warm run holds about a third of a cold one.** A cold run is the first after the lockfile, a tsconfig or the eslint config changes, and every deploy's `tsc -b`. The deploy's line is the app program's cold number on every merge.

## One trap found on the way

The hook is CommonJS and loads with `--require`. As a module loaded with `--import`, Node 20.0 sent `tsc`'s own entry file, which has no extension, through the module loader, and `tsc` never started (`ERR_UNKNOWN_FILE_EXTENSION`). A test holds the hook to `--require`.

A second one: Node's `process.resourceUsage().maxRSS` is kilobytes by its docs and bytes on a Mac whose Node carries libuv 1.44. The hook sends the resident size now as well, which is always bytes, and the kernel reads the unit from the two: a peak is never under what is held now.

## Measured

- **The runner on the small config program** (`tsconfig.node.json`), on a dev Mac, Node v20.0.0: 499 MB resident at most; 376 MB of heap in use not collected, 340 MB after a collection of under 0.1 s. Build mode holds its program as it exits too: the same files as `tsc -b` ended holding 340 MB against 342 MB as `tsc -p`. With `TYPECHECK_HEAP_MB=400` the warning and the annotation print and the exit is still 0. With `TYPECHECK_HEAP_MB=60` the run ends `NO VERDICT`, exit 134, with no memory line.
- **CI's own lines** are in the pull request's body, read from its `typecheck, lint and the checks` job. The three parts were not run on a Mac for this change: the machine's typecheck line was taken, and CI's run is the proof.

## Files

- `scripts/lib/typecheckMemory.mjs` (new): when a run collects, the splitter that takes the hook's line out of a stream, the reader of the two units, the words, the warning and the annotation.
- `scripts/lib/tscMemoryHook.cjs` (new): the hook.
- `scripts/lib/runTsc.mjs`: preloads the hook, passes stderr through a line at a time, prints the memory line after the death line. It takes a `label`, the part's name.
- `scripts/typecheck-queued.mjs`, `scripts/tsc-build.mjs`: pass the part's name.
- `src/lib/typecheckMemory.test.ts` (new, 22 tests), with the hook run in a real Node; `src/lib/typecheckHeap.test.ts` and `src/lib/typecheckParts.test.ts` hold the new wiring lines.
- `docs/SESSIONS.md`, `to-dos/type-check-in-parts.md`, `to-dos/owner-decisions-pending.md`.
