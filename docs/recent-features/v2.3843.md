# v2.3843 — Supply houses: a payment's receipt link sits beside the invoice (2026-09-25)

The owner's call (2026-09-25) on the question [v2.3830](v2.3830.md) left open: a typed payment link gets its own field instead of replacing the invoice scan. Migration `20260926025000_supply_invoice_payment_link.sql` ([doc](../migrations/20260926025000_supply_invoice_payment_link.md)) added the column and was pushed before this client.

## Before

`supply_house_invoices.link` is each bill's own paper — the scan the invoice form saves, opened by the detail table's **View**. Supplies → Supply Houses → **Make Payment** (the *Apply Payment* dialog) asked for an optional *Link* with the placeholder *Payment or receipt link…* and wrote it into `link` on every ticked bill, so the receipt replaced the invoice. v2.3830 had already stopped a **blank** box from nulling it.

## The change

- New column `supply_house_invoices.payment_link` (nullable). [`applyPaymentUpdate`](../../src/lib/materials/supplyHouseInvoiceForm.ts) returns `{ is_paid: true }`, plus `payment_link` when a link was typed — never `link`; a blank box also leaves an earlier receipt link alone.
- The dialog's field is labeled *Payment or receipt link (optional)* with *Saved as each bill's Receipt — its invoice scan stays.* under it.
- The detail table's **Link** cell shows **View** (the invoice, `link`) and **Receipt** (`payment_link`) side by side; `—` when neither.
- Types regenerated (`npm run gen-types:linked`) after the push, and the dev-mcp catalog with them (`node scripts/build-dev-mcp-catalog.mjs` — `supabase/functions/dev-mcp/catalog.ts`; redeploy `dev-mcp`).
- New guide *mark supply-house bills paid* (the Make Payment flow and what the two links are); `MATERIALS_TABS_ARCHITECTURE.md` quirk 21 amended.

## Verified

- `supplyHouseInvoiceForm.test.ts`: a blank box carries no link at all; a typed one goes out trimmed as `payment_link` and never as `link`.
- Typecheck, lint, the help-guide content test.
