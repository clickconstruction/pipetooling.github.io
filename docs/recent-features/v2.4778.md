# v2.4778 — Court areas: a record with no county takes the area's (2026-10-07)

One migration (`20261007140000_county_source_map.sql`, push after merge) and the `court-precinct-nightly` function (**redeploy after the push**). Follow-up to [v2.4770](v2.4770.md), found on the first live run.

## Why

The first classification on 2026-10-07, after the import of Bexar, Travis and Hays (14 areas): 475 records read, 132 placed, 193 outside every area (the counties not yet drawn), 4 on a line, 150 with no point in the geocode cache. Of the placed rows, many had no county on file at all, so the firm's page would have read *? · JP Pct 3* — a precinct with no county, which is no court.

## What changed

- `customer_addresses.county_source` admits `map` ([migration page](../migrations/20261007140000_county_source_map.md)).
- The nightly fills a blank county from the area the point fell in — the county's own line for an imported area, what the office named for a drawn one — with `county_source = 'map'`; a county already on the record is never changed. The row is written when the county fills even if the precinct did not change.
- `countySourceLabel('map')` reads *from the office's court map* on the property record.
