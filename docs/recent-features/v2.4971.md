# v2.4971 — Lien desk: the run prints a checklist, a divider before each envelope, and holds what cannot be mailed (2026-10-08)

Client only. Grace, with the October 8 run as it printed (154 pages, 18 envelopes): *when a user goes to do a run it looks like this, I think we should add cover pages before each separate mailer to make it easier for the assistant to not make mistakes and I think the first page could be more direct towards them … checkboxes … where they should record the tracking number.* Page 1 was a paragraph per envelope with the address mid-line and a row of underscores for the number; the envelopes ran into each other with nothing between them; the foot of every page read *7/154*; three envelopes had no mailing address and five carried a $0 claim, and all printed. Board https://claude.ai/artifact/FV9bGjG1ZyYwbPuhDJ6Wsv (three spots, Now vs suggestion), then a sample PDF rendered from the proposal; Grace: *I love it, build it*, with two calls along the way — the divider carries the envelope's face exactly where a label reads it, and the tracking box spans the whole row under the ticks.

## What changed

- **Kernel [`lienRunPaper.ts`](../../src/lib/jobs/lienRunPaper.ts)** (pure; the run's envelopes and each copy's page labels in, HTML out):
  - `runEnvelopeHold(env)` — why an envelope cannot go: no mailing address for a paper method (no email for email, no name for hand delivery), or every notice inside claims $0; both at once in one sentence. `runMailing(envelopes)` splits the run into `mailed` (renumbered 1…N) and `held` (numbered after, each with its reason), and `all` in that order so the sheet, the dividers and the run window agree.
  - `runDocumentWords(labels)` — *7 documents · counsel’s letter, the notice, the pay page, 4 unpaid invoices*, from the labels `runCopyPages` already gives each page. Documents, not pages: a letter can run to a second sheet, and a count the printer contradicts is worse than none.
  - `runSheetHtml` — page 1 (and on): *Today’s mail · 13 envelopes · 181 documents · October 8, 2026*, two sentences to the person at the desk, then one row per envelope: the number large, the name and the address as the envelope reads it (`rollMailingLines`), what is inside, three ticks (*stuffed · slip on · mailed*), and a tracking box the width of the row with *20 digits from the green slip* inside it. Held envelopes follow in red with the reason and no box. The browser paginates; the heading row repeats; a row never splits.
  - `runDividerHtml` — before each envelope: a black band along the top edge, the envelope's face as `runEnvelopeFacesHtml` prints it (return address, the certified line and article number, the addressee where the label sits, *Envelope 3 of 13 · Owner of record* bottom right), the number large, *N documents follow this page · …* and *The next divider is envelope 4* (or *This is the last envelope*), what is inside, the ticks, the box, and *Pull this page out before you seal…* It stays on the desk.
  - `runPageFoot` — on every page that goes out: *Job #878 · copy for the owner of record · Pay codes · 3 of 7*. The run's own count (*envelope 3 of 18*) stays off the paper the recipient reads; the job and the copy are already on the notice's reference strip.
  - `RUN_PAPER_CSS` in the print shell (`runPagesHtml`), letter paper.
- **`runPacketHtml`** is the sheet, then per mailed envelope its divider and its copies with their feet; a held envelope prints nothing. `runCopyHtml` and `runEnvelopeHtml` carry the foot too. `runCoverSheetBlocks`, `envelopeContentsText` and the statute sentence are retired.
- **The run window** (`LienDeskRunModal`): `runMailing` numbers its rows the way the paper does; a held envelope's row reads *Held · <reason>* in red (`run-held-<n>`); *Print the packet · N envelopes* counts the ones that go out; the ? explainer names the sheet, the dividers and how many are held; the envelope faces print only the mailed ones; **printing the packet stamps only the copies that printed** — through the per-copy `notePrinted` (v2.4853), so a notice whose other envelope is held stays half-printed and never reads as in the mail. Put a GC on notice shares the window and the behaviour.
