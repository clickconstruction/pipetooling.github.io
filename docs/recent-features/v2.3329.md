# v2.3329 — Bank transfer card: the check address gets its own box, the wire address says what it is for (2026-09-11)

Client only; owner review of v2.3320: "we want it to look clean and tasteful, but make it clear cheques go to one place and there is another address for wires." One card carried two addresses, and the one under Pay to (the bank's beneficiary address) was the wrong one to mail to.

## What shipped

- [`PortalBankTransferCard`](../../src/components/portal/PortalBankTransferCard.tsx) `Body` is two halves inside `[data-portal-bank-split]` (a two-column grid `minmax(0,1fr) 250px` on wide screens when both halves exist — `data-both` — and one column under 560 px, rules in the statement's style block in `CustomerPortal.tsx`):
  - **By bank transfer — ACH (direct deposit) or wire**: the row grid (Pay to · Address · Routing · Account · Bank), the Address row now tailed *for the wire form — not for mail*, the bank note, the Memo line.
  - **By check — mail it here**: a `NOTE_BAND` box — *Payable to* + the payee, *Mail to* + the mailing address on envelope lines (`mailingAddressLines` in the kernel: street / city-state-zip, +1 test), and *Only this address. Checks mailed anywhere else — the bank address is not a mailbox — may need to be re-issued.*
  - The guard line spans the full width below both. A checks-only record shows the box alone under "Paying by check?"; a transfer-only record shows the left half alone.
- [`BankTransferDetailsPanel`](../../src/components/jobs/BankTransferDetailsPanel.tsx) (Accounts Receivable): the Address row reads *· wire form only, not for mail*.
- Help guide `let-a-customer-pay-by-bank-transfer`: the example block shows the two halves.
- Sample mode (`_shared/customerSampleFixtures.ts`): the sample check address is now a PO Box, so What customers see demonstrates the two-address point — **redeploy `customer-portal`**.
