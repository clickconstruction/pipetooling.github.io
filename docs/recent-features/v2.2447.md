# v2.2447 — Pipeline partial-invoice modal stops counting the elastic auto bundle (2026-08-28)

The scoped follow-up the v2.2446 BILLING_FLOWS note called for: the Jobs Pipeline "Create partial invoice" flow (`JobsStagesTab.tsx` `createInvoiceFromModal` + modal, opened from the mobile cards' ⋯ → Partial invoice) computed its Remaining/clamp/gate from `jobBillingUnallocatedDollars`, which counts the never-sent primary RTB remainder bundle as allocated. Since the bundle is elastic (the ensure RPC resizes it to whatever isn't billed — primary-excluded basis since v2.1134), every Ready-to-Bill job carrying the auto draft read **Remaining $0.00**, clamped typed amounts to $0 ("No remaining balance to bill"), and hid the Partial invoice menu item entirely.

## What changed

- **New primary-excluding sibling** in `src/lib/jobsStagesBoard.ts`: `jobPartialInvoiceRemainingDollars` (+ private `jobPartialInvoiceRemainingCents`) — gross − payments − RTB/billed lines, **excluding** `status='ready_to_bill' AND is_primary_rtb_bundle=true` rows (same rule as the ensure RPC and JobFormModal's `unallocatedBillableDollars` since v2.2446). A billed row with a stale primary flag still counts.
- `clampPartialInvoiceCentsToUnallocated` now clamps to the new basis (it was only ever used by the partial modal).
- Switched call sites: `JobsStagesTab.tsx` Remaining display + full-remainder routing check (full remainder still opens Bill Customer), and the `JobsStagesCardList.tsx` ⋯-menu gate.
- `jobBillingUnallocatedDollars` is **unchanged** and its stale "same basis as ensure RPC" comment now documents what it actually is: the board-merge basis (primary counted), feeding `readyToBillMergedPrimaryInvoiceId`, section exposure sums, and the board "unallocated"/"remaining" footnotes. `promoteJobToBilledIfFullyInvoiced` was audited too — it short-circuits on any RTB invoice before touching the unalloc math, so the two bases are equivalent there.
- Kernel tests in `src/lib/jobsStagesBoard.test.ts` mirror the v2.2446 `jobFormBreakOff.test.ts` cases (auto-bundle-only job 978 numbers, mid-flow resized bundle, stale-flag billed row), and the old clamp cases moved to the new basis.
- Help guide `ready-to-bill-pipeline.md`: the Remaining explanation notes the auto remainder draft doesn't count.

No migration; client-only.
