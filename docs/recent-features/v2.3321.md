# v2.3321 — Cash App reconciliation, PR 1: tables + kernels (2026-09-11)

Owner-approved plan (artifact 44ea272a, Part 2): the owner pays staff through Cash App and records the payment on the pay report by hand, or forgets to. The first-time reconciliation (Mar → Sep 2026) found 187 Cash App payments, $66.4k, with no recorded payment — advances being the biggest hole. This PR is the groundwork; the UI lands in PRs 2–4.

## Migration `20260911203141_cashapp_reconcile.sql`

- **`cashapp_transactions`** — every row of the Cash App activity export, keyed by Cash App's `Transaction ID` (`#D-…`) so re-uploading a bigger export adds only new rows. Stores the exported fields (occurred date/text, type, status, signed amount, fee, net, counterparty, note, account) plus the reconcile decision: `lane` (`review` / `recorded` / `advance` / `expense` / `before_records` / `not_staff` / `ignored`), `person_name`, `match_rule` (`id` / `amount` / `split` / `manual`), and links to the `pay_stub_payments` row it became or the `person_offsets` advance it filed. Indexed by date, lane, person.
- **`cashapp_aliases`** — Cash App counterparty → app person (`counterparty_key` = lower/trim/collapsed-spaces), or `not_staff`; optional `note_contains` / `note_person_name` for proxy accounts (Taunya's account + "tristen" in the note → Tristen).
- **`person_offsets.type`** gains `advance`.
- RLS on both tables: `has_payroll_access()` for all four verbs (the pay_stub_payments gate). Ends with both read-only blocks.

## Kernels `src/lib/cashapp/` (+18 tests)

- `parseCashAppCsv` — the export's exact columns; money `"-$300.00"`; local-day date from the first 10 chars; dedupes by id; `isStaffOutflow` = P2P · COMPLETE · amount < 0.
- `cashAppAliases` — `aliasKey`, `resolveCashAppPerson` (person / proxy via note rule / not_staff / unknown), `unresolvedCounterparties` (the alias step's to-do, biggest money first with sample notes).
- `cashAppLane` — `classifyCashAppNote` (expense keywords → expense; "advance" → advance; else pay) and the lane labels.
- `matchCashAppTransactions` — rules in order, each result naming the rule: (a) Cash App id in a payment memo; (b) same person + amount within 7 days, nearest date; (c) one send = sum of 2–3 recorded payments; (d) else `before_records` when dated before that person's first report (or a company floor), otherwise `unmatched` with its note kind. Proxy accounts try the alternate person. `summarizeCashAppMatches` gives the header numbers.
