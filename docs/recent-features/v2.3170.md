# v2.3170 — Reps are the only home for a supply house's contacts (2026-09-08)

PR 4 of six from [`to-dos/supply-house-directory/`](../../to-dos/supply-house-directory/README.md). Migration `20260908185956_retire_supply_house_contact_columns.sql` — **push after the client deploys** (the old form writes both columns on save).

## Why

`supply_houses.contact_name` / `email` were the single-contact fields from before v2.2648 gave houses a reps table. Since then the same fact lived in two places: the house row and `supply_house_contacts`, with the RFQ compose reading only the latter. The 2026-09-08 read-only probe found every house email already mirrored as a rep, so the to-do's "backfill then retire" PR is a retirement with a guard.

## What shipped

- **[`SupplyHouseForm`](../../src/components/SupplyHouseForm.tsx)** drops **Contact Name** and **Email**; **Phone** becomes **Main phone** ("the counter"). The reps editor at the bottom now shows who added each rep (`showAddedBy`). A new house, which has no id for reps yet, shows *Save the house, then add its reps — who price requests go to.* `SupplyHouseFormData` loses the two fields; [`useSupplyHouseEditor`](../../src/components/materials/useSupplyHouseEditor.tsx) loses their state and never writes them.
- **Readers**: the accounts-payable drawer's **Email:** / **Contact:** lines are gone (the Directory pane above it shows the reps); the two legacy fallback selects (`SupplyHousesTab`, `useMaterialsCatalog`) stop naming the columns; the directory kernel's `DirectoryHouse` type drops them.
- **Migration**: a house whose `contact_name` had no email (so could never become a rep) keeps the name in its notes as `Contact: <name>`; any house email still absent from its reps becomes one (default only if the house had none); then `DROP COLUMN IF EXISTS contact_name, DROP COLUMN IF EXISTS email`. Idempotent.
- `PROJECT_DOCUMENTATION.md` → `supply_houses` lists the surviving columns and the v2.3167 write predicate.

## After the push

`npm run gen-types:linked` and a `chore(types)` PR — the client compiles against the pre-drop types on purpose (it no longer references the two columns), so the regeneration is a follow-up, not a blocker.
