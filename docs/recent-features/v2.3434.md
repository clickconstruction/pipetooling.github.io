# v2.3434 — One eligibility hook for the dispatch and estimator group reads (2026-09-14)

Client only; no migration, no edge function. Refactor from `to-dos/customer-waiting-residuals.md` ("One eligibility hook") — nothing changes for users.

## Why

`CustomerWaitingContext` (v2.3248), `useDispatchInbox` and `useEstimatorInbox` each carried their own copy of "is the signed-in user in the group?": the same `dispatch_group_members` / `estimator_group_members` `maybeSingle`, the same `dev` short-circuit, the same cancel-on-viewer-change effect. Three places to drift when the rule next moves.

## What shipped

- **Kernel** [`inboxGroupEligibility.ts`](../../src/lib/inboxGroupEligibility.ts): `planInboxGroupEligibility({ userId, role, disabled })` → `none` (signed out, or the caller vetoed — the banner's digital-twin fence) · `all` (`dev`) · `lookup` (everyone else, including a role still loading); `INBOX_GROUP_MEMBERS_TABLE` names the two tables; `inboxGroupEligibilityFor` fills only the groups asked about; `membershipRowMeansEligible` (a row → in the group). Tested (`inboxGroupEligibility.test.ts`).
- **Hook** [`useInboxGroupEligibility(groups, { disabled })`](../../src/hooks/useInboxGroupEligibility.ts): reads `useAuth`, runs the plan, fires one `maybeSingle` per requested group in parallel, cancels when the viewer changes. Starts all-false and settles once — no loading flag and no realtime refresh, exactly as the three copies behaved. Module constants `DISPATCH_INBOX_GROUP` / `ESTIMATOR_INBOX_GROUP` / `BOTH_INBOX_GROUPS` keep the array stable.
- **Consumers** — `useDispatchInbox` → `dispatch`; `useEstimatorInbox` → `estimator` (its `role` read is gone with the effect); `CustomerWaitingContext` → both with `disabled: isTwin`. Same tables, same short-circuits, same effect deps (`user id`, `role`, and the twin flag where it applied).
- Not touched: `useSettingsPeopleDirectory.ts` (edits the rosters) and `PersonDeskTeamSection.tsx` (shows another person's membership) read the tables for other reasons.

## Verified

Kernel test, the full unit suite, lint, theme check. Typecheck and `vite build` were green apart from a pre-existing, unrelated gap in this machine's shared `node_modules` (`@vis.gl/react-google-maps` / `@types/google.maps` are in the lockfile but not installed here); CI runs the real gates.
