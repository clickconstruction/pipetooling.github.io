# v2.2731 — "+ version" clone source follows the legacy data template (2026-09-03)

Closes the follow-up noted on v2.2720 — and corrects it. `BidVersionPicker` clones a new version's pricing from `currentPricingId ?? fallbackPricingSourceId`. `currentPricingId` is the engine's resolved pricing, which since v2.2720 already lands on the template holding a legacy bid's rows, so in practice the split was already cloning from the right book (verified: BP405's split modal says "★ stays on 🤖 Robot Default"). The gap was the **fallback** — `defaultPriceBookTemplateId`, the viewer's last pick — which is what the picker would use in the window before the active pricing resolves (or if it ever resolves null). It now prefers the legacy data template too, so the two paths can't disagree.

## Client only — no migration

- [`useBidPricingEngine.ts`](../../src/hooks/useBidPricingEngine.ts) exposes `versionClonePricingSourceId = legacyDataTemplateIdFor(null, priceBookVersions) ?? defaultPriceBookTemplateId`. [`Bids.tsx`](../../src/pages/Bids.tsx) passes it as the picker's `fallbackPricingSourceId` at all four mounts (Counts / Takeoffs / Pricing / Cover Letter). `defaultPriceBookTemplateId` still feeds the drawer's "Your default for new bids" chip.
- Reach: bids that own a copy never hit either path's fallback (their copy is `currentPricingId`); for the 17 twin/shadow bids on `🤖 Robot Default`, and any future bid in that shape, both the active-pricing path and the fallback now name the same book.
