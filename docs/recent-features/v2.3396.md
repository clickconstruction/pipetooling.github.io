# v2.3396 — Pipeline on a map, PR 1: the card, today's view (2026-09-14)

Client only; no migration, no edge function. First PR of the train in [`to-dos/pipeline-on-a-map/`](../../to-dos/pipeline-on-a-map/README.md) (the plan of record); the design brief with mock-ups and the second-pass decisions was published as the artifact *Pipeline on a Map* the same day.

## Why

Owner, 2026-09-12: "right now there is a map at the top of bids that works very productively, what would we need to add one of similar qualities to the top of the Jobs, Pipeline page with one addition, I would like to be able to scroll back in time." This PR is the map; the rail (PR 2) and the As-of rewind (PR 3) follow.

## What shipped

- **Kernel [`jobsMap.ts`](../../src/lib/jobs/jobsMap.ts)** (+8 tests): the board's filtered rows → one map job each (`J1019 · Vasquez pretest`, the section by the # jump's own rule `stagesSectionKeyForJobRow`, Collections as Billed + a ring, the payer under the job's who-pays rule, `owedDollars` from `jobOpenBillingRemainderDollars` on billed / ready-to-bill jobs), pin resolution against the geocode cache, the legend in board order (Paid off by default), status / distance / owed lines, the unmapped line, and the per-device hide / cluster preferences under their own keys. Colors are `jobsLedgerStatusDotColor` — the pins mean what the rows' dots mean.
- **[`JobsMapCard`](../../src/components/jobs/JobsMapCard.tsx)** (+7 render smokes): composed from the shared `PinsMapCanvas` / `PinsMapGoogleCanvas`, `useOfficeAnchor` (25 / 50 mile rings), `useAddressGeocodeCoords`, the Bid Board's home fit and provider rule. Header: the title toggles the card; section chips; Fit all; Cluster; Hide map. Popup / phone bar: number and name, *Bills go to X*, section chip + Collections chip + percent, address and straight-line miles, *$18,400 owed*, then **Open job** (the job window), **Edit** (the Edit tab), **Directions**. The footer counts pins (*112 pinned · Paid 723 off*) and lists unplaced jobs by number as links to their rows.
- **Mount** in [`JobsStagesTab`](../../src/components/jobs/JobsStagesTab.tsx) under the toolbar, above the money story. Pins follow `stagesBoardLists.filtered` (search + every filter). A pin click runs `jumpToNumberMatches` — the section opens, the row flashes and scrolls. **Paid loads on demand** on the board, so the Paid chip reads *…* until its first tap, which asks the paid scope to load (`cacheFetchScopeIfNeeded`).
- Help guide *see the pipeline on a map*.

## Decisions taken (owner can flip)

Shown by default, remembered per device · Waiting / Working / Ready to bill / Billed on, Paid off · one ring only (Collections, red — an amber aging ring on an orange billed pin read as nothing; age goes on the rail in PR 2) · hidden board groups do **not** hide pins (the chips own section visibility; two switches for one thing confused the first pass) · no section tour (Play will mean time in PR 3).

## Not in this PR

The rail (distance buckets with dollars to collect, the ask-for-money list, row hover → pin pulse by event delegation on `data-stages-job-id`) is PR 2; As of is PR 3; crews on the day is PR 4.
