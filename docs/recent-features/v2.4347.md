# v2.4347 — Windows wait for you to let go before closing (2026-10-01)

No migration, no edge function. The second half of Grace's rule from v2.4338 (2026-10-01): a window closes on a click outside it only when the press **and** the release are both outside it.

## Why

94 backdrops in 86 files closed on the press — `onMouseDown={(e) => { if (e.target === e.currentTarget) onClose() }}`. The target check meant a drag that started inside never closed them, but a press outside closed them before the release: a press outside that turned into a drag back in, or a text selection started in the margin beside a box, closed the window. v2.4338's census counted 3 windows closing on the press; it matched only `onMouseDown={onClose}` and missed the target-check form. The codemod found 92 on 2026-10-01; re-run on the newer main before the PR, it found two more — Set a password and Change sign-in email on the Person desk (v2.4343 / v2.4344).

## What changed

- **One codemod** ([`backdrop-click-sweep.mjs`](../../scripts/codemods/backdrop-click-sweep.mjs), TypeScript-parser based, re-runnable — on a rebase conflict re-run it, never hand-resolve its diff) renames each such backdrop's `onMouseDown` to `onClick` and leaves the handler as it is. A site is an element whose `onMouseDown` handler, inline or a same-file function of that name, closes only when `e.target === e.currentTarget` (or `!==` then return). It skips an element that already has an `onClick` (none today), a handler that only records the press (`ResponsiveModalShell`, which already closes on the click), and the Checklist canvas right-click menu (a menu closes on the press).
- **Where**: Bids 20 files, Banking 16, Checklist 9, People 8, Person desk 5, Jobs 4, Estimates 4, Team feedback 3, Contracts 3, Projects 2, My Time 2, Documents 2, pages 2 (People, the submittal room), and one each in Quickfill, Map, Dashboard, Customers, Clock and the app-wide confirm ([`ConfirmDialogContext`](../../src/contexts/ConfirmDialogContext.tsx)).
- **Why the drag case still holds**: v2.4338's guard stops a click on a full-screen fixed layer unless the press and the release were both on it. All 94 are `position: fixed; inset: 0` (92 inline; `BidPreviewModal` through a constant, `ChecklistTechTreeTaskCardModal` through `.roadmap-task-overlay`), and no container in the app makes a fixed layer smaller than the screen (no `transform` / `filter` / `contain` on a window's ancestors — the transforms are all on small markers and tooltips, the one filter on the dark-mode map tiles). Each handler keeps its target check, so a click inside never closes, and a click on a window drawn inside another one's backdrop does not close the outer one.
- My Time quirk 21 amended (all three confirms now close on the click). v2.4338's fragment corrected from "about 30" to 92.
