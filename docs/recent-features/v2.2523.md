# v2.2523 — twin-mcp verbs: open_backtest + add_bid_note (2026-08-30)

Closes the two doors BT-3 had to bridge with dev-seat SQL (see the BT-3 stamps on
b406's ledger):

- **`open_backtest(reference_bid, due_in_days?)`** (twin-mcp): creates the
  `ZZ Twin <PROJECT> (backtest)` bid owned by + assigned to the calling twin,
  copying ONLY logistics fields — the SELECT never touches counts, pricing,
  `bid_value`, or `outcome`, making the blind protocol structural rather than
  disciplinary. Idempotent per reference (re-call returns the existing bid);
  stamps the `[pipeline STG-0]` ledger note.
- **`add_bid_note(bid, note)`** (twin-mcp): one `bids_submission_entries` entry
  on the twin's own/assigned bid — the `[pipeline STG-N]` flight-recorder lane,
  fence-checked like `get_work_state` (estimator or creator only).
- Server version 1.1.0; `docs/EDGE_FUNCTIONS.md` twin-mcp section updated.
- Companion (owner-applied, not in this PR): registering twin-mcp as a native
  Claude Code connector in `.mcp.json` with the per-twin token via
  `${TWIN_ESTIMATOR_1_TOKEN}` env expansion — so twin pipeline sessions need
  neither the service-role Supabase connector nor allowlisted curls.
