# v2.3247 — Customer Waiting, PR 2 of 4: the inbox row, tap-to-call, lower and raise priority (2026-09-10)

Client only; reads the columns and RPCs from migration `20260910220000` (v2.3246). `src/types/database.ts` regenerated after the push.

## Why

PR 1 made portal requests land `priority = 'high'` — but nothing showed it. This PR is the inbox half of the design (mockup https://claude.ai/code/artifact/a4b6cba5-7d7d-42aa-93c2-26c54a391877): the row a dispatcher sees on a phone with a customer waiting, and the two actions that end the wait (call) or the priority (lower).

## What shipped

- **Kernels** — [`requestPriority.ts`](../../src/lib/requestPriority.ts): `isCustomerWaiting` (open + high), `compareCustomerWaitingFirst`, `describeWait` (minutes → hours → days; red at `CUSTOMER_WAITING_RED_MINUTES` = 30), `describeCalled` ("Sam called 2:14 pm", weekday on another day), `LOWER_PRIORITY_REASONS`, `formatPriorityChangeNote`, `portalKindLabel`. [`portalRequestPayload.ts`](../../src/lib/portalRequestPayload.ts) reads `pending_payload` tolerantly (visit / bid / GC stage ask; pre-v2.3246 rows still parse). [`phoneContact.ts`](../../src/lib/phoneContact.ts): one `tel:` / `sms:` / display / E.164 reading — the app had ~35 hand-rolled `tel:` links with five sanitizers; this is the first shared one.
- **Sort + badge** — `compareDispatchInboxRows` gains a first tier: waiting rows (oldest first), then open oldest-first, then closed. The estimator hook applies the same tier ahead of its newest-first habit. `dispatchBadgeCounts` gains `high`; the Dispatch Mode footer badge breathes (`customerWaitingPulse`, reduced-motion off) and its label reads "4 open · 1 customer waiting".
- **Row** — both inbox selects add `priority`, `priority_changed_at`, `last_called_at`, `last_called_by(name)`, `pending_payload`. A waiting row renders [`CustomerWaitingRequestCard`](../../src/components/CustomerWaitingRequestCard.tsx) in place of the title block: the wait as the header (ticks every 30 s via `useIntervalNowMs`), Portal · kind chip, the customer's name + reference, their words in full, *Can be there* / *Asks for*, *Reach them at* (with "from the customer record" when the intake fell back), plans link, one big **Call**, then **Text** · **Lower priority ▾** · **✓ Close** (opens the thread), and a footer that is either *Nobody has called yet.* or *📞 Sam called 2:14 pm — still open until it is lowered or closed*. Everything below the card (From / age chip / messages, the expanded thread) is the row as before.
- **Call** — [`CallPhoneButton`](../../src/components/CallPhoneButton.tsx): coarse pointer → a real `tel:` / `sms:` anchor; desktop → copies the E.164 number and says *Copied* (toast). `onUsed` → the hook's `logDispatchRequestCall` / `logEstimatorRequestCall` → RPC `log_request_call` (stamp + 📞 note), silent on failure.
- **Lower / raise** — [`RequestPrioritySheet`](../../src/components/RequestPrioritySheet.tsx): lowering asks why (Scheduled · Not urgent · Spam or duplicate · Other, default Scheduled) + optional note; raising takes the optional note. Hook `setDispatchRequestPriority` / `setEstimatorRequestPriority` → RPC `set_request_priority` (row stamp + thread note, one transaction; `false` = nothing changed → info toast). **Raise priority** sits in the expanded thread header of any open normal row.
- **Wiring** — `DashboardTeamsInboxCard` (Dashboard + Dispatch Mode → Inbox), `ChecklistReviewInboxes`, Quickfill pass `prioritySavingId` / `onSetPriority` / `onLogCall` to both sections; the props are optional so a host without them renders the card without the actions.
- **Help** — `answer-a-customer-waiting-request.md` (Office; dev / assistant / controller / estimator).
- **Tests** — kernel tests for the three new modules + the sort tier + the badge `high` count; render smoke: a waiting row shows the card, the Call target, Lower priority (opens the sheet, confirm calls `onSetPriority(id, 'normal', 'Scheduled')`), and a normal row shows the title instead.
