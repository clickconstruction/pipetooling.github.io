# v2.4306 — Contracts: the Contract window holds still after you type (2026-10-01)

No migration, no edge function. Grace on the Pipeline board (job 1021, the row's contract chip): after typing in the paper side of the Contract window, the window jumped up and down by a line, over and over.

## What changed

- **The draft autosave re-armed itself.** [`JobContractModal`](../../src/components/jobs/JobContractModal.tsx)'s debounced autosave effect listed `flushDraft` in its deps. `flushDraft` depends on `liveRow`, and every save stores the row it wrote (`setLiveRow(data)`), so each save made a new `flushDraft`, re-ran the effect and armed the next 800 ms save. One edit therefore wrote the draft roughly once a second until the window closed, and the footer's *Saving…* / *Saved as you type.* swap changed its height and re-centred the modal each time. The loop dates from the modal's first version (v2.2681).
- The timer now calls the newest `flushDraft` through a ref (`flushDraftRef`), and `flushDraft` left the deps; the effect still re-arms on every real edit (fields, signer, copies, reminders, template).
- New render test in `JobContractModal.dateHold.render.test.tsx` (*one edit, one save*): one change, six 900 ms ticks, exactly one update — six without the fix.
