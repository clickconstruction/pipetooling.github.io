# v2.2991 — Test-gap audit, pass 14: the Calendar clock-session chips get their first tests (2026-09-07)

Follow-up to v2.2989, which named this kernel next. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`calendarClockSessionDisplay.ts` (132 lines) is everything behind the per-session chips the Calendar grid shows when **Show recorded time** is on: the adapter from the calendar's narrow select row to the full session shape, the active filter (not rejected, not revoked), grouping by work date with the earliest clock-in first, the Central-time range ("8:00 AM – 12:05 PM", or "– open"), the compact duration, the chip cap of three per day cell, and the chip label and tooltip built from the job or bid embed. One caller (`Calendar.tsx`), no test.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- The adapter blanks what the calendar select does not fetch (approvals, locations, the people embeds) rather than inventing values; null notes become an empty string and a null origin becomes undefined.
- Chip label precedence: a job embed wins over a bid embed; with neither, a salary block reads **Scheduled** and anything else **No job**.
- The tooltip uses the bid's customer name when the bid has no address, cuts notes longer than 120 characters at 117 plus an ellipsis, and falls back to **Clock session** when there is nothing at all to say.
- Duration never goes below zero when the clock-in is after "now" (clock skew), and a sub-minute session reads "<1m" while a zero-length one reads "0m".

## What shipped

- **`calendarClockSessionDisplay.test.ts`** (9) — the row adapter; active vs rejected/revoked; day grouping and ordering; the Central-time range in CDT and CST, including a session crossing UTC midnight; duration in seconds (closed, open against now, skew, sub-second) and its compact form; the chip cap; the label across job / custom prefix / click-number fallback / blank name / bid / both / salary / no job; and the tooltip across job + notes, bid with and without address, salary, notes only, nothing, and the 120-character cut. The time assertions normalise the narrow no-break space newer ICU builds put before AM/PM, so they hold on either Node.
