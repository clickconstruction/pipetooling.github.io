# v2.2735 — Wheels on Labor PR 2: Review prices the vehicle deal per field hour (2026-09-03)

Variant C, second half. Stacked on v2.2733 (PR 1: arrangement + Wheels report). No migration.

## Union + kernels

- [`lib/people/teamReviewTypes.ts`](../../src/lib/people/teamReviewTypes.ts): `TeamReviewUnion.vehicleByPersonName: Record<name, TeamReviewVehicle>` (`{ arrangement, rate, truckName, note }`), filled from `loadWheelsSnapshot` (90-day rates, override wins) for people whose arrangement ≠ none.
- **Union loader** ([`PeopleReviewTab.tsx`](../../src/components/people/PeopleReviewTab.tsx) `loadTeamReviewUnion`): card-charge rows whose transaction is in the fuel tag AND attributed (`mercury_transaction_attributions.user_id`) to a person with a deal are dropped before `cardChargesByJobId` / `tagChargesByJobId` are summed — the deal prices that fuel per field hour instead, so it neither counts twice nor lands on co-workers by labor share.
- [`derivePersonTeamSummary.ts`](../../src/lib/people/derivePersonTeamSummary.ts): row gains `vehicleArrangement`, `vehicleRate`, `vehicleTruckName`, `vehicleCost = −(fieldHours × rate)` (0 without a deal or rate). [`formatters.ts`](../../src/components/people/teamSummary/formatters.ts) `enrichTeamSummaryRowsForInline`: `profitAfterOverhead = net + overheadLaborCost + overheadBurden + vehicleCost`.
- [`reviewRanked.ts`](../../src/lib/people/reviewRanked.ts) (+2 tests): `ReviewVerdict.wheels { company, own }` and segments `wheelsCompany` / `wheelsOwn` after Parts burden; `ReviewRankedBar.vehicle`; `wheelsLines(b)` in the drawer — `− 🚚 <truck>` (company) or `− 🚗 Own-vehicle fuel` (own), a $0 line with "no rate yet" when the deal has no rate.
