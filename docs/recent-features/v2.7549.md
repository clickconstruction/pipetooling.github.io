# v2.7549 — Checklist: choose which task to do first (2026-11-16)

Punch list #369, step D1 of the Task Mode train, the first of the three small ones, stacked on C7 (v2.7548). No migration, no call: the pick is kept on the device.

## What changed

- **Do first**, the first row of **⋯ More** on an open task that is not Next already and is not stuck (`taskMoreChoices`). One press, no sheet.
- **That task becomes Next** (`doFirstId` over `nextTaskId`), drawn open with **Mark done**, and a line under the label reads *You picked this to do first.* The task the list would have put there drops back under Then.
- **Stop doing it first** replaces the row on the picked task and gives Next back to the list's own order.
- **A pick that can no longer be Next is passed over.** A task that is finished, stuck, handed on or gone does not hide the real Next.

## Why on the device

The order of Today is the office's: `display_order` on Review. This is how one person reads their own list this morning, not a fact about the task. So it is kept the way Task Mode's own toggle is, in localStorage under one key per account (`doFirst.ts`), and nothing is saved to the task. The mock-up drew it that way: *Lift it into Next on this device.* A pick made on a phone does not show on a tablet.
