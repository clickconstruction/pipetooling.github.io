# v2.2978 — Team board: act on a chip (2026-09-07)

Second PR of the Team train (board v2.2974). Every chip, ledger row and exception on Jobs → Team now carries its fix; each action writes to the clock session or the dispatch plan — never to `people_crew_jobs` — and reloads the week. Client only — no migration, no edge function.

## What shipped

- **Hook** [`useTeamBoardActions`](../../src/components/jobs/team/useTeamBoardActions.tsx) (`renderCellActions`, `renderExceptionActions`, `modals`, `canEdit` = dev / master / controller; RLS still answers with a 0-row toast). Per kind:
  - **not on a job** → **Link to \<block\>** (the day's dispatch block, via `linkClockSessionsToPick` on the cell's unlinked session ids) · **Pick job…** (`AssignFocusModal`, the existing bulk session picker) · **Split day…** (`DashboardMyTimeDayEditorModal`).
  - **planned, no clock** → **Add session** (`ClockSessionEditSplitModal` in `createFor` mode) · **Not coming in** (confirm → `recordNotComingInForUserAsStaff`, the same unpaid-day-off path the clock strip uses) · **Adjust plan** (navigates to `/schedule-dispatch?week=&day=`; dispatch-edit roles only).
  - **clocked, not planned** → **Move to plan** (`insertJobScheduleBlock` from first clock-in to last clock-out — `plannedWindowFromClock`, note "From the clock (Team board)"; dispatch-edit roles) · **Split day…**.
  - **ran long** → **Split day…**; **on plan** → **Open day**.
- **Kernel** (+2 tests): `pickFromTargetKey`, `hoursToHhmmss`, `plannedWindowFromClock`.
- `JobsTeamTab` passes the renderers to the board, the ledger and the drawer, and mounts the three modals (z-index 1200 above the page).
- Guide `read-the-team-board` → "Acting on a chip".

Deliberately not here: **Looks right** (acknowledging a ran-long / not-planned chip so it stops showing) and the ran-long threshold as a setting — both need a table and land in the third PR.
