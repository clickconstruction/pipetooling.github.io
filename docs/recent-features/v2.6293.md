# v2.6293 — The jobs Shared Drive moves into Click Plumbing's own Google Workspace (2026-11-01)

The owner's decision of 2026-11-01, made while picking up punch list #236 (one Drive folder per job, under its customer): the app's file store should live in the Workspace the team works in. The "PipeTooling Jobs" Shared Drive had been created in the douglasmining.com Workspace (the founder's other company, where the service account's GCP project and the Maps key still sit), while the office manager, who files most customer PDFs and service reports by hand, is in clickplumbing.com. Every friction #236 met — Manager needed to move a folder across, the source org's *Distributing content outside* setting, `DIFFERENT_CUSTOMER` refusals — came from the two being in different organizations.

- **The move, done by hand in Drive on 2026-11-01**: a new Shared Drive **PipeTooling Jobs** (`0ANSfYqm0sENHUk9PVA`) in clickplumbing.com, members the owner and the office manager as Manager and `drive-intake@pipetooling-drive.iam.gserviceaccount.com` as Content manager; a **Jobs** folder (`1GuDUKC6emyGB5D62eYT3IGHajKmgV3_a`) at its top; the old drive's eight job folders and probe file moved into it and **Bid plans** moved beside it, as the owner's clickplumbing.com account once raised to Manager on the old drive (Drive's rule: a folder leaves a shared drive only under a Manager; the old org's distributing setting was already *Anyone*). Drive keeps ids through a move, so every `google_drive_link`, pictures and plans link on a job or bid still opens. The old drive is renamed *PipeTooling Jobs (old, Douglas Mining)* and holds an empty Jobs folder.
- **What the app needed**: `ROBOT_PLANS_SHARED_DRIVE.id` in `supabase/functions/_shared/bidPlansFolders.ts` named the old drive by id (the dev seat's `apply_file_plans` files bid plans there), so this PR carries the new id and `dev-mcp` redeploys after the merge; the `DRIVE_JOBS_FOLDER_ID` secret (the root's fallback) was set to the new Jobs folder; the office's own root on Documents → Where files go is repointed to the same folder. The service account, its key and the Maps key are unchanged: a service account is a GCP identity, not a Workspace user, and sits in any org's drive as a member.
- **Why before #236's sweep**: v2.6284's `placeFolder` compares parents inside one Shared Drive and its move helper moves within one, so a folder left in the old drive once the root pointed at the new one would be retried every ten minutes. The content moved first; the sweep deploys after.
- **Left for another day**: the GCP project `pipetooling-drive` (service account, Maps key, billing) into clickplumbing.com's Cloud organization under a `systems@clickplumbing.com` owner, and the bids reader onto `bids@clickplumbing.com` (`GMAIL_IMPERSONATE_USER`; the delegation already exists there, since `gmail-mine` reads people's own boxes under it). `docs/DRIVE_INTAKE_SETUP.md` carries the live ids.
