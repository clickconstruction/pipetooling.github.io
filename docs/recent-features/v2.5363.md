# v2.5363 — Messages: the files that come with an email, and a paper offered for filing (2026-10-12)

The Messages build's cut 6 screens (email in), the last of its four PRs, over the kernels (v2.5349), the migration
(v2.5350, `20261013080000_messages_email_in.sql`) and the `gmail-sync` reader (v2.5354). No migration and no edge
function. Guide `find-every-message-with-a-person-in-one-place`, its new sections *Open a file that came with an email*
and *File a paper that came by email*.

- **The read**: `loadLineFiles` in `messagesIo.ts` reads `message_attachments` with the view, and the paper's answerer
  joins the names it reads. A missing table reads as no files (`42P01`, `PGRST205`), so the client can ship before the
  migration is pushed. `lineFiles.ts` turns the rows into each line's files (`lineFilesFromRows`, `withLineFiles`): our
  copy, too big to keep, not copied, or a link, with a badge, the size in words, the note, where Open goes
  (`fileOpenHref`), the offer (`paperOffer`) and the filed line (`filedWords`).
- **The chips** (`LineFiles.tsx`'s `LineFileChips`, under `ThreadLine.tsx`'s words, the time below them): a badge, the
  name and the size, and a press opens the message window. A picture shows its badge, not the mock-up's thumbnail: a
  thumbnail would fetch the whole picture for each chip.
- **Attachments** in the message window (`MessageFiles`): each file's size and where it is, with **Open** for our copy
  (`/files/messages/<id>`) and for a link (its own address, `http(s)` only). A file left in Gmail has no Open, where the
  mock-up drew *Open in Gmail*: a Gmail link needs the mailbox's account, which stays out of the client.
- **The lasting link** `/files/:source/:id` (`FileOpen.tsx`; `src/lib/files/fileRoute.ts` and `fileOpenIo.ts`, the files
  router cut 7's Drive files are meant to join): outside the layout, and it signs in on its own
  (`POST_LOGIN_REDIRECT_KEY`), so the link comes back to the file. Signed in, it reads the row under the office team's
  policy and goes to our copy through `createSignedUrl(path, 60)` and `location.replace`, or to a link's address. No
  edge function. `fileUrl` writes the link on `APP_ORIGIN` for a record to keep.
- **The paper offer** (`PaperOffers.tsx` in the `underLine` slot; `useThreadSlots` is now `mergeThreadSlots(flow,
  email)`): for a trade partner's kept file that reads as a certificate or a W-9, while nobody has answered it. **File
  this as their certificate** closes the thread and opens the company window at Documents, Insurance, with the file
  (`CompanyAt.file`). There `GcRecordInsurance` starts with the file's lasting link under *From Greg's email:* and the
  file with **Open**. Saved with that same link, the page answers the offer `filed` (`answerPaper`) and reads Messages
  again, so the line says *✓ Filed as their certificate · Rosa, Oct 12*. Filing stays a dev's, as
  `gc_record_company_coi` is (`canUseGcBoardWrites`), so the rest of the office sees **Go to their insurance paper** and
  the window's row read only. **It is not** answers `not_it` for everyone.
- **A W-9 offer** goes to the W-9's row (**Go to their W-9 paper**), which shows where the file came from and that it
  is not filed from here. Filing a W-9 waits for a W-9 save of its own: the office has none today, only the portal's.
- **Smokes**: `PaperOffers.render.test.tsx` and `FileOpen.render.test.tsx` (new), the chips in
  `ThreadWindow.render.test.tsx`, Attachments in `MessageWindow.render.test.tsx`, the company window opened with a file
  in `GcCompanyWindow.render.test.tsx`, and the slots' list in `useThreadWindow.render.test.tsx`. The spine's fixture
  carries the mock-up's four files on Greg's email (`SPINE_ATTACHMENTS`).
