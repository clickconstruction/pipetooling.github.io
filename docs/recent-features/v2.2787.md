# v2.2787 — Sub work orders from sheets, PR 3: the Scope tab in the Contract library (2026-09-04)

Third PR of the Sub Work Orders train. The lists a sheet's Work order box ticks from get a home, and the Contract Book learns the `sub` audience.

- New [`ContractScopeLibraryTab`](../../src/components/contracts/ContractScopeLibraryTab.tsx) as the third tab of `ContractLibraryModal` (Documents · Packets · **Scope**). Left rail: **All trades** + one entry per `service_types` row with counts (empty reads amber, like unused packets). Right: for the picked trade, three sections — Scope items, Exclusions, They confirm at signing — each a list of `sub_scope_items` rows with click-to-edit wording, a default/ask chip (`is_default`), ↑ ↓ reorder (sequence swap), × archive (`archived_at`), and an add row. Every action writes immediately and reloads; RLS decides who may write (dev / master / assistant / controller).
- The **Documents for subs** card lists Contract Book entries with `audience = 'sub'`, their version date, and coverage from the new kernel `generalConditionsCoverage` (active subs on the current version / behind / never signed, each person counted once by their best signed `person_contract_documents` copy). Behind or unsigned → the library's existing **Send to…** quick-send.
- `ContractBookModal`: the Audience select (add + edit) gains **Subs**; sub-audience rows wear a violet *For subs* badge next to the packet badge.
- Help: *manage the contract library and packets* gains the Scope section and the three-tab intro.
- `src/types/database.ts` regenerated from the linked project after the v2.2785 push (sub_scope_items, nullable `step_id`, `signer_acknowledgements`, `can_access_sub_work_order`).
