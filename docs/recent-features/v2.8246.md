# v2.8246 — View as no longer marks things as seen for the person (2026-11-21)

The survey done with v2.8176 listed the saves a page makes with no press that still ran as the imitated person. Taunya asked for the costly ones to be fixed: the "seen" marks, where a dev's look clears something the person has not read, and a third door to the salary sync that v2.8176 held at the clock button. No migration and no function change.

## What changed

Each of these now makes no call while View as is on (`isImpersonationSessionActive()`, read at the call):

- **A tagged note's answers.** `markAnswersSeen` (`noteTagsIo.ts`: `job_note_tags_seen`, `task_note_tags_seen`), set off by the tagged notes list on screen. It answers 0, and the answers keep their *New* mark.
- **A bid request.** `markBidRequestsSeen` (`bidMarksStore.ts`: `bid_mark_requests_seen`), set off by the strip under an open bid's title. The store is not patched either, so the dev sees the request as the receiver still would, unseen.
- **A bid's notes.** `upsertBidNotesReadWatermark` (`user_bid_notes_read_state`), set off by a bid row opened on the Bid Board, the submission tab and the Dashboard's My bids.
- **A plan question's answers.** The `seen_at` update in `usePlanQuestions`, set off by the thread loading. The thread is still read.
- **A law firm's answers.** `legal_firm_intake_seen` in `LegalFirmWindow`, set off by the window opening on new answers. They are still drawn as new.
- **A first look.** The `looked` stamp in `FirstLookCards`, set off by the files drawing. The stamp carries the person's name. Close a look is a press and is untouched.
- **The day editor's salary sync.** `useMyTimeSalaryPrefetch` synced an empty salaried day when the editor opened on it, through the raw sync. It now goes through `syncSalaryClockSessionsUnasked`, the kernel v2.8176 added, which takes the day as a third argument. Held, the editor reads nothing again and shows the empty day; the server's schedule fills it.

Three guards sit in the helper every caller goes through, three at the one effect that makes the call, and the sync in its kernel. A press in View as saves as that person, as it always has: Done on a bid request, Close on a look and a posted note are untouched.

## What it does not do

- It holds only these seven. The rest of the survey still runs in View as: the nav telemetry, the dispatch self-heals, the office schedule fill and the others in the PR body of #9218. None of them costs the person a thing they have not read.
- A dev who opens a bid's notes in View as sees the unread count clear on screen for that visit. The person's row is not written, and a reload shows the count again.
- Nothing on the server refuses these. The guard is in the client, as v2.8176's is.
