# v2.4092 — Write up a change: it tells you when you already sent one for this job today (2026-09-28)

Client only; no migration, no edge function. The second of the three v2.2293 deferrals. A field person who forgets they sent a write-up an hour ago sends a second one and the office prices the same change twice.

## What changed

- **Kernel** `quickEstimateSentTodayForJob(rows, jobId, todayKey, dayKeyOf)` (`src/lib/quickEstimate.ts`) — the newest of this person's sent write-ups whose marker (`field_write_up.job.id`, v2.4076) names the same job and whose `sent_to_dispatch_at` falls on today's company-calendar day; office-made estimates (no marker) never count. `quickEstimateSentTodayNote` words it. 3 tests.
- **Wizard** — on the review screen of the change-order branch, one read of the person's last ten sent write-ups; a hit renders an amber `role="status"` line above **Send to Dispatch**: *You already sent one for this job today — 2:10 pm, #310. Send this one too if it is different work; otherwise the office already has it.* The time is in the company time zone. Send is not blocked.
- Guide *write-up-a-change-order-from-the-field* (Good to know).

## Not in this PR

- Auto-closing the Dispatch request when the office sends the estimate (the last deferral, next).
