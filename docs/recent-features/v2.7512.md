# v2.7512 — Lien desk: Just this one prints every envelope's set, signed, as the run prints it (2026-11-16)

The owner's report of 2026-11-16: an office teammate pressed *Just this one* on an approved, signed notice and got a help sheet and one set of pages. The sheet named two envelopes and told her to photocopy the set for the second. Client only: no migration, no edge function.

## Before

*Just this one ›* (v2.3410) opened the job's Lien window on its § 53.056 tab. That window's print is older than most of what the desk now holds, and never learned any of it:

| | Just this one (the Lien window) | The run's packet |
|---|---|---|
| Sets | one, to photocopy | one per envelope, each page footed with whose copy it is |
| The page in front | the #314 help sheet: *Copy every page behind this sheet*, *signs the notice in each set, in ink* | *Today's mail*, then a divider page before each envelope |
| The notice | built fresh from the job and dated today, not the approved draft | the approved draft's own fields |
| The signature | never printed: `LienFilingTabs` builds the blocks with no signature and the window never reads the desk item | printed with its day (`toFilingSignature`) |
| Counsel's cover letter | never | the owner's set, when the desk's box is ticked |
| The desk row afterwards | still *Approved · to print* | stamped printed, waiting on its mail numbers |

So the paper that went out beside a desk reading *signed by code* was unsigned, and was not the paper the leader signed.

## What changed

- **One notice, one result.** The link opens the run window on that one notice (`openRunOnOne` in `LienDesk.tsx` sets `runOnlyItemId`; `lienRunEntriesFor` in `lienNextUp.ts` takes the item's id and looks in both the ready and the printed pile, since the notice moves piles the moment its packet prints). The packet, the checklist sheet, the dividers, the hold on an unsigned notice, the per-envelope reprint and the record of the mailing are the run's own. Nothing about the print is built a second time.
- **The link says what it prints.** `src/lib/jobs/lienRunOne.ts`, `lienRunOnePlan`: the envelopes that go out in packet order with the documents the desk already knows are inside each, the envelopes the run holds back with the run's own reason (`runEnvelopeHold`), and the words. *Just this one · 2 envelopes ›*; *· 1 envelope, 1 held ›* when the contractor has no mailing address; *· 1 envelope ›* when the owner and the contractor are one name at one address, and the hover says the envelope carries both copies; *· held ›* when nothing can print, with the first reason in the hover. The link is never dead for a hold: the window it opens has the doors that clear one.
- **The desk builds a run's monthly notices in one place** (`monthlyRunNotices`), for the window and for the link's count, so the count cannot disagree with the window.

## What the owner chose (2026-11-16)

Asked with drawings: both envelopes as the run prints them, over a second press in the Lien window or a choice at each press; the run's own sheet in front, over the #314 help sheet rewritten; an unsigned notice held as the run holds it, over a print with a blank line for ink.

## What the single print and the run still do differently

Nothing in the pages. The window is the same window holding one notice.

The Lien window's own § 53.056 tab keeps its *Print* and its help sheet, reached from the job. Its print is still one unsigned set built from the job, and its sheet still says to copy and to sign in ink, which is true of that print. A later change has that tab say so when the desk holds an approved notice for the job.
