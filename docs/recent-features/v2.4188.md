# v2.4188 — Counts: groups and alternates come in from CountTooling (2026-09-29)

The alternates train, PR 2 of 5 (PR 1 was the migration, `20260929230000_bids_alternate_group_tags.sql`, [doc](../migrations/20260929230000_bids_alternate_group_tags.md); CountTooling's side is its PR #290). The owner's ask: a customer's plan set sometimes carries a section they call an *alternate* and want priced with and without. CountTooling counts it as a group and marks the group; this PR is where the group lands on the bid. Mock-up (the five tabs, before / after, the owner's four picks): artifact `WvmELEoMyhjQw54ta13QNv`.

## What changed

- **The import lifts the group** ([`parseCountsImportText.ts`](../../src/lib/bids/parseCountsImportText.ts)): a `[Group] ` prefix on a fixture becomes the row's `group_tag` and is taken off the name. Since the classic table a three-column paste kept the bracket in the fixture ("[Break room] WC"), so those rows matched no book entry and no other version's row (both matchers compare the exact name) and the Group column stayed empty on every import. An explicit four-column group still wins over the prefix.
- **The alternate heading** — CountTooling's `--- Alternate: <name> ---` opens a block whose rows join that group (a row with no bracket takes the heading's name; a blank line or the next framed heading ends it). The names come back as `alternateGroups` and are merged onto **`bids.alternate_group_tags`** (`mergeAlternateTags`), the one list that says which groups are alternates, in every version of the bid. The toast adds *· 1 alternate: Break room (1 ea · 48.5 ft)*.
- **The Count Sheet** ([`BidsCountsTab.tsx`](../../src/components/bids/BidsCountsTab.tsx), kernels in [`countSheet.ts`](../../src/lib/bids/countSheet.ts)): a third view, **By group** (`buildCountSheetGroupGroups`: base groups alphabetical, then *No group*, then the alternates), each group's heading with its totals and an **Alternate** switch (`toggleAlternateTag` → `bids.alternate_group_tags`; the parent re-reads the bid through `onCountSourceLinkSaved`); an **ALT** mark beside the group on every alternate row in any view; an **Alternates** tile on the strip when one holds a row; and under the table the two numbers the customer asked for — *Base · 5 ea · 112.00 ft* and *+ Break room · 1 ea · 48.50 ft* (`countSheetAlternateTotals`; feet and px never summed together).
- **The duplicate guard is scoped** (`findDuplicateFixture(rows, name, excludeId, { alternateTags, groupTag })`): the same fixture in the base bid and in an alternate group are two rows on purpose (WC ×4 in Restroom A, WC ×1 in the Break room alternate), so quick add and a rename only see a duplicate in the same scope. `alternateScopeKey(row, tags)` is the key the name-keyed matchers will compare within in the next PR.

## Decided here

- **One list per bid, not a flag per row.** `clone_count_rows_to_bid_version`, `materialize_bid_version`, `create_bid_version` and `adopt_bid_as_version` already copy `group_tag`; a row flag would have needed every one of them re-created. `duplicate_bid_to_service_type` copies `bids` column by column and was re-created with the column (the migration).
- **Membership is by name**, trimmed and case-insensitive, so *break room* and *Break room* are one group; the first spelling on a row is the label.
- **Quick add stays in the base**: a quick-added row has no group; type one in its Group cell and it joins that group, alternate or not.
