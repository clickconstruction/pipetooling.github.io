# v2.3169 — Phone People board: the v2.3156 audit fixes (2026-09-08)

Client only — no migration, no edge function. A code review of PR #2862 (v2.3156, the People board on a phone) plus the owner's live report ("the board loses itself when the phone rotates") surfaced ten defects; this PR applies them with minimal edits. Files: `HubPeoplePhoneBoard.tsx`, `ScheduleDispatchHub.tsx` (HubPeoplePanel), `ScheduleDispatchHubPage.tsx`, kernels `scheduleDispatch/phonePeopleBoard.ts` and `scheduleDispatchLinkedCopy.ts`, with tests.

## The view choice no longer depends on width alone

- The stored preference is tri-state (`PhonePeopleViewPref = 'board' | 'grid' | null`); `readPhonePeopleView` returns `null` until a pick is made and `resolvePhonePeopleView(pref, narrowViewport)` gives an explicit pick priority at any width, else narrow → board, wide → grid. The page owns the resolution (`phonePeopleView`) and both `phoneBoardActive` derivations (page banners, panel rendering) read it — no `useIsMobile` term. A landscape iPhone (844 px) or a portrait tablet therefore keeps or can choose the board.
- The grid's bottom switch renders whenever the page passes `onPhonePeopleViewChange` (every People tab, not the Quickfill embed), labelled *Back to the phone view* on a narrow viewport and *Show the phone view* otherwise.

## Placement modes match the grid

- **Linked stage 2 wrong day**: `linkedWrongDay` now covers `linked-apply` too, so Copy to techs stage 2 cards off the source day say *Linked copies land on Tue 8* and are not tappable (the legs always write `source.work_date`); the Whole team band hides on those days.
- **Whole team** needs `laneMemberUserIds` (a real swim lane) — never a role heading or *Everyone else*, mirroring the grid's lane-apply gate.
- **Multi-cell + Not coming in**: `cardTargetState` returns a non-tappable busy *Not coming in today* for an unselected tech marked off (a selected one can still be taken off).
- **Move**: the board passes `isSourceCell` and the kernel answers *Where it is now* (non-tappable) instead of a clash with the block in flight; `sourceUserIds` is populated only for `variant === 'linked'`, so a solo copy may land on the same tech another day.
- **Week change**: `shiftWeek` / `goThisWeek` also clear `cardPlacementMode`, `plusMenuBlockId` and `linkedCopyMode` (the board derives its bar from blocks in the loaded week and would otherwise lose the bar and Cancel while the page kept the mode).

## Signals the grid had

- The board receives `latenessByCell`, `hiddenByCell`, `subBadgeByCell`, `noteRequirementForBlock` (the panel's context function) and `onRequestUndoNotComingIn`. The header renders the shared `ScheduleDispatchTimeOffChip` (three-variant palette; tap to undo a Not-coming-in / NCNS marking) or the Late chip, plus a *sub* / *N subs* badge; each block row gets a *✎ no note* marker in the grid's pencil colour under the same rule as the strip count (today/future, `skip` rules quiet); hidden blocks draw a grey *busy · N blocks you can't see* row and make `cardTargetState` read busy (tappable) rather than *Nothing scheduled this day*.
- The grid's `search` / *Hide inactive* state resets when the board activates, so a filter left on in the grid no longer thins the board and its Copy to techs checklist with no control to clear it.

## Copy to techs sheet

- `onCopyBlockToPeople` returns `{ applied } | null`; `null` (busy, or the block vanished — with a toast for the latter) leaves the sheet open. `summarizeLinkedCopyApply` / `…LaneApply` take `{ linked }` and say *solo copy / solo copies* and *(overlap)* when the box was unticked.
