# v2.2060 — Workbench book column + counted fill-matching (2026-08-21)

Owner report ("in the new version of pricing there is no way to type things in and get the price from the price book"; mockup artifact 55b637b4). The Workbench could only hand-type sale prices or run the solver — the price book was reachable only from the Old view.

[`BidsPricingTab.tsx`](../../src/components/bids/BidsPricingTab.tsx): the Workbench table gains a **Book entry** column (derive rows already carried `entry`/`assignment`): assigned rows show a chip (entry name · `total_price`) with × → `removePricingAssignment` (assignment-only delete, so a pre-existing custom price resurfaces); unassigned rows show "assign…" opening a compact search (prefilled with the row's fixture, options show name + price, reuses the Old view's `pricingAssignmentSearches`/`pricingAssignmentDropdownOpen` state, `priceBookEntries` corpus, and `savePricingAssignment` write; wrapped in `data-pricing-assignment-dropdown` for the shared outside-click close). Above the table: "Price book · {name} · N entries" + **Fill N matching from book** — powered by the new pure kernel [`matchCountRowsToBookEntries`](../../src/lib/bids/bookEntryMatching.ts) (trimmed case-insensitive EXACT name matches only, already-assigned rows skipped, names shared by two entries match nothing; 4 tests). The button's label counts live before any write (an improvement over the Old view's "Apply Matching", which only pre-fills search boxes with 3 characters); clicking batch-inserts the assignments and toasts the count. Header alignment/minWidth adjusted for the ninth column.
