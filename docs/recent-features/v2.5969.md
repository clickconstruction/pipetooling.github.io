# v2.5969 — What everyone sees: try a theme on every screen before it ships (2026-10-27)

Punch list #194, PR 5 ([`to-dos/experiences-lens/`](../../to-dos/experiences-lens/README.md); the sealed frame v2.5960, the tab v2.5963, the checks v2.5967). The owner's "if we change themes or styles know how this will look", before a PR exists.

- **The tokens** come from the `virtual:lens-tokens` plugin in `vite.config.ts`. It runs [`parseThemeTokens`](../../src/lib/lens/lensTokens.ts) over `src/index.css` at build time: the light block (`:root, [data-theme='light']`, 111 tokens) and the dark block (`:root[data-theme='dark']`, 109). The draft always starts from the shipped values, and the 240 KB stylesheet never ships as text.
- **The panel** ([`LensThemeDraft.tsx`](../../src/components/settings/LensThemeDraft.tsx)) loads lazily behind the tab's *Theme draft* button.
  - Every token sits in its group, with Light values or Dark values, a color input for plain hexes, a text field for the rest, and a find box.
  - Contrast, as you type, covers eight pairs that must stay readable: body and muted text on a card and the page, a link, the top bar, and the amber, red and green words on their tints. A pair under 4.5:1 turns red.
  - Copy as CSS writes the patch for `index.css`, each line with the value it replaces. Reset clears the draft.
- **The frames**: a draft rides into every frame as one style sheet (`applyDraftStyle`, `style[data-lens-draft]`), each theme's changes `!important` over the shipped values, on load and on every change. Draft and Current flip it.
  - A new draft clears the checks, since a check read the frame as it looked. *Check every screen* then says what the change broke.
  - The draft stays in this device's storage (`lens.themeDraft.v1`) until Reset.
- **Words**: the guide gains *Try a theme before it ships*; the Glossary's *The lens's sealed frame*; the to-do's plan, where the theme draft now comes before the full world.
