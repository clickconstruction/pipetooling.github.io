# v2.7038 — The deploy passes its own check again: the app's build entry is keyed `index` (2026-11-12)

Punch list #319, a fix to PR 4 (v2.7007, #7772). Every deploy of `main` from 19:12 UTC on 2026-11-12 failed at **Verify build output** with *index.html does not reference built assets correctly*, so nothing merged after 18:58 reached the live site.

**Why.** v2.7007 gave the build a second input for the First look page and named the app's own input `main`. Vite names an entry's script after its key, so `dist/index.html` loaded `assets/main-<hash>.js`. `deploy.yml`'s check greps for `assets/index-`, as do the live-site checks in the docs.

**The fix.** The app's input is keyed `index` (`vite.config.ts`), so its script is `assets/index-<hash>.js` again. `showEntry.test.ts` now holds the key and the workflow's grep together.

**Why it got through.** CI does not run `vite build`; only the deploy does. The build was run locally before the merge, as the rule asks, and it passed, because a build passing is not the deploy's check passing. The lesson: before merging a change to `vite.config.ts`, run the build **and** the workflow's own *Verify build output* greps on `dist/`.

No migration and no function.
