# v2.3145 — Dashboard jobs map: Google Maps with an OpenStreetMap fallback (2026-09-08)

Owner's ask (2026-09-07): "maybe we could use Google Maps instead? … if Google Maps doesn't work, we fall back to open street maps." Client only — no migration, no edge function. The office `/map` page stays on Leaflet.

## What shipped

- **[`DashboardJobsMapGoogleCanvas`](../../src/components/dashboard/DashboardJobsMapGoogleCanvas.tsx)** (new, lazy) — the v2.3131 card's canvas drawn with the Maps JavaScript API through `@vis.gl/react-google-maps` (1.10): `APIProvider` + `Map`, one `Marker` per pin with a `SymbolPath.CIRCLE` icon in the Jobs status colors (radius / ring / opacity match the Leaflet canvas), a desktop `InfoWindow` with the same body as the Leaflet popup (label, status chip, address, `stage · last report`, **Open job** / **Directions**), fit-to-all on load and on **Fit all** (`fitBounds` padding 28, capped at zoom 15 on `idle`), zoom control only, `cooperative` gestures on phones. Google's native **`colorScheme`** follows the app's `<html data-theme>` stamp (a `MutationObserver`, so the gear-menu override and the time-of-day flip both apply live) — no tile inversion.
- **Provider choice** in [`DashboardJobsMapCard`](../../src/components/dashboard/DashboardJobsMapCard.tsx): `resolveDashboardMapProvider({ key: googleMapsBrowserKey(), googleFailed })` — Google when `VITE_GOOGLE_MAPS_BROWSER_KEY` is set and nothing has failed; otherwise the existing Leaflet + OpenStreetMap canvas. **Four failure doors all flip to OSM for the rest of the page** (sticky, so a bad key never flickers): the loader's `onError` (script blocked / network); a **10 s** script-load timeout; **`window.gm_authFailure`**, the callback Google documents for a rejected key; and a **paint watchdog** — once the script has loaded, `.gm-style` must appear in the frame within **8 s** (polled every 500 ms). The watchdog is the one that fired in the live test: with a bogus key the script loads, markers are created, the frame holds only Google's static preview image, and neither `onError` nor `gm_authFailure` ever fires — without it the card would have sat empty. A render exception inside the Google canvas is caught by an error boundary and falls back the same way (that door caught a real bug during the build: an inline marker `ref` callback looped React; `useMarkerRef` + an effect fixed it). Each fallback logs one `console.warn` with the reason.
- **Config**: `VITE_GOOGLE_MAPS_BROWSER_KEY` is optional — typed in `vite-env.d.ts`, passed by `deploy.yml`'s build step from the repository secret of the same name (unset → empty → OSM), documented in `README.md` (Optional GitHub Secrets: Maps JavaScript API only, HTTP-referrer restricted to `https://clicktooling.com/*` and `http://localhost:*`) and `PROJECT_DOCUMENTATION.md`. Local dev has no key, so it draws OSM.

Not testable here: the happy path with a real key (none exists yet — see README for the key's restrictions).

## Not changed
