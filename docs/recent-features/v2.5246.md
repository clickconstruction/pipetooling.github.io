# v2.5246 — GC mode: a signed change order reads on the owner’s G702 again (2026-10-12)

A kernel fix in Owner Billing. No migration, no edge function to deploy (the `_shared/gcKernels` mirror is regenerated, but no function calls these helpers).

- **The bug**: `spreadMarkup`, `markupOnTop` and the G702 build in `ownerBilling.ts` told a change-order line from a trade line by `isChangeOrderLineId(id)`, which read `id.startsWith('co-')`. A pay application's change-order line is minted with `id: co.id`, and `gc_change_orders.id` is a uuid on prod (`20261008010000_gc_owner_billing_tables.sql`); only the test fixtures used ids like `co-1`. On a real job a signed change order was spread as a trade: its line took a share of general conditions, contingency and fee on top of a price that already carries our fee, the trades' markup read lower, the G702's line 2 (net change by change orders) read $0, line 1 (original contract sum) carried the change order, and the form's change-order list was empty.
- **The fix**: the lines carry their kind, and the id says nothing. `isChangeOrderLine(line)` reads `line.kind === 'changeOrder'`; `spreadMarkup` and `markupOnTop` accept an optional `kind` on their generic line and read it. `SentPayAppLine` gains `kind` (`sentPayAppLines` carries it from today's lines), so a sent bill spreads the same way. The G702 build (`ownerPayAppForm`) collects the change-order ids from the spread rows, which carry the kind, and uses that set for line 2 and the form's change-order list; `PayAppLine` in `building.ts` is untouched. `isChangeOrderLineId` is gone — nothing outside the kernel called it.
- **Tests**: `ownerBilling.test.ts` gains two cases on Helotes with a signed change order whose id is a uuid: the spread passes it through with `ourShare` 0 and the trades' markup unchanged, and the G702 draft reads it on line 2, takes it out of line 1 and lists it. Both failed before the fix (the line read $8,176 with $2,176 of our share; line 2 read $0). The direct test's spread fixture marks its `co-1` line `kind: 'changeOrder'` and pins `isChangeOrderLine` on a change order, a trade and a line with no kind.
