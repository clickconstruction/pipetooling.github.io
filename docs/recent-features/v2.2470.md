# v2.2470 — The Bid Room, Phase 2: sign & decline (2026-08-28)

The loop closes (plan v2.2468). The GC signs — or says no — right in the room, and the
bid's own bookkeeping follows.

- **Outcome kernel** `_shared/bidRoomOutcome.ts` (+6 parity tests against
  `gcPackets.rollUpOutcome` / `setGcPacketOutcome` semantics): a signature wins the GC's
  packet, auto-loses other SENT unanswered packets (the staff-kernel rule, send evidence =
  `bid_version_sends` rows — deliberately conservative, no `bid_date_sent` guessing), and
  rolls `bids.outcome` up conservatively (a hand-set decision only ever moves to won).
  Decline categories are the real staff loss keys minus the staff-only ones
  (price / other_sub / project_died).
- **`sign-bid-room` edge function** (public, token-validated): only the CURRENT revision
  can be signed or declined — a stale revision gets 409 `stale_revision` and the page
  refreshes itself (the race guard); one response per room (409 `already_answered`).
  **Sign** = the signature-time freeze: mints an `estimates` row born `customer_accepted`
  (`doc_kind='bid_proposal'`, `bid_id`, room's GC as `customer_id`) with the chosen option
  frozen into the legacy fields + `options_snapshot`/`accepted_option_key` (one summary
  line per option — the letter never prices per line; fixture detail lives in the room's
  revisions), acceptor name/IP/UA/consent + optional drawn-signature PNG in the estimates
  signature bucket; then the outcome writes + a `signed` room event + staff notify email
  (room creator + master). **Decline** = packet Lost with the GC's own category/note →
  the Why-we-lost lens; `declined` event; notify.
- **Room page**: typed-name signature (Georgia italic line, consent checkbox, the same
  legal-force wording family as estimates), the Approve button naming the selection —
  *Approve "Base bid" — $249,971.29* — and "Not moving forward? Tell us why" with the
  loss chips + note. Signed/declined banners; the picker locks after an answer.
- **Estimates side (decision 1)**: bid proposals never enter the Pipeline buckets; the
  Ledger gets a "Bid proposals" kind filter and rows wear a violet **Bid ✍** chip; the
  detail page banners "Signed bid-room proposal — Open the bid" (deep link `?bidId=`).

Drawn-signature pad on the room page: the sign function accepts the PNG already; the pad
UI itself is P3 polish — typed-name signing (the standard e-sign path) ships now.

**Deploy after merge**: `supabase functions deploy sign-bid-room`.
