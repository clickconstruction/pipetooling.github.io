# v2.5204 — GC mode: a set of plans always says which sheets it changed, behind the scenes (2026-10-10)

The Board's B2b-vi-a-2, a fix to B2b-vi-a (v2.5199, #5361) found by that lift's spike follow-up (`to-dos/gc-mode/mockups/board-b2b-vi.md` on branch `spike/gc-mode`). No screen, no migration, no deploy.

- **`types.ts`:** `PlanSet.changedSheets` is required again, word for word the prototype's. v2.5199 had made it optional on main, with a comment.
- **Why:** the spike widens each of main's shapes to its own whole one (`src/lib/gcMode/gcMainShapes.ts`: `interface PlanSet extends Spike.PlanSet {}`). The prototype's `changedSheets` is required, so main's optional one could not merge with it. Every main `GcProject` the spike's screens read then failed its typecheck, 38 errors in one cause. Main's own typecheck never sees the widening, so it passed.
- **The lesson:** on a shape the spike widens, a field main lifts keeps the prototype's required or optional as it is. Making it optional on main breaks the spike's widening when the spike's is required. Map a true value instead, or an empty one.
- **What maps it now:**
  - The board (`boardRows.ts`) maps each set's changed sheets from the view, which already has them. Nothing reads them yet, since the board's sets still carry no trades (`touches: []`) until B2b-vi-b.
  - The trade portal (`tradePortalState.ts`, `setsOf`) maps none. Its slice carries no sheet changes and the portal draws none.
- **`lift-same`:** `PlanSet` is the same as the spike's now, so `board-b2b-vi.lift.json`'s `pin.known` keeps two differences, `reachOf` and `staleChange`'s one line (call E3′).
