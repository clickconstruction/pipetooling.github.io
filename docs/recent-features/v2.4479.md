# v2.4479 — Submittals: the Edit window keeps what you typed (2026-10-03)

Finding 4 of the owner's tab review ([`to-dos/submittals/tab-review-before-after.html`](../../to-dos/submittals/tab-review-before-after.html), https://claude.ai/artifact/SJ3skkPrsSDEugjmXe4h2k). Client only: no migration, no edge function.

## What was wrong

Checked live on BP398 before the change: text typed into the Edit window's note, one click on the grey outside, and the window closed with no question; Esc did nothing. The same in *Their answer* and *Choose from the takeoff* (whose backdrop closed on any click). A fixture with eleven parts is a lot to type again. And `saveItem` set no busy flag, so Save stayed live while it saved: two quick presses on a row added by hand would insert it twice.

## What changed

- **One guard**: [`useLeaveGuard({ dirty, onClose, busy, paused })`](../../src/hooks/useLeaveGuard.ts) and `LeaveQuestion` ([`SubmittalLeaveGuard.tsx`](../../src/components/bids/SubmittalLeaveGuard.tsx)). The hook gives a window one way out, `requestClose`. Nothing changed: it closes at once. Something changed: `LeaveQuestion` shows inside the window, above its buttons — *Leave without saving?* with **Leave** and **Keep editing**. Esc asks the same way, and a second Esc is Keep editing. The question is part of the window, not a window over it, so `check:nested-windows` has nothing new to read.
- **The Edit window** ([`SubmittalItemEditDialog`](../../src/components/bids/SubmittalItemEditDialog.tsx)): dirty is the window's twelve pieces of state against what it opened with, so typing and typing back reads as nothing changed. New `busy` prop: Save reads *Saving…*, and Save, Cancel, the backdrop and Esc hold.
- **Their answer** ([`SubmittalAnswerDialog`](../../src/components/bids/SubmittalAnswerDialog.tsx)): dirty is `writes.changed > 0`. Its button reads *Saving…* while busy.
- **Choose from the takeoff** ([`SubmittalTakeoffPicker`](../../src/components/bids/SubmittalTakeoffPicker.tsx)): dirty is any pick, part pick or split switched. Esc is left to the split-rule window while that is open.
- **The tab**: `saveItem` runs one save at a time behind a ref and the tab's busy flag.

## Tests
