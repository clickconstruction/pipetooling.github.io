## Decisions (the owner's rule: the recommended default, named)

- **One RPC with actions, four verb pairs.** The card named two pairs; the surface's own presses are four kinds (a box, a delivery, a line, a count), so an agent that can only deliver and count could not put a delivery away or add the cage it goes in. Four pairs over one `dev_on_site_write` keep the grammar the seat already has (`plan_matter_plan_item`'s `action`) without eleven more RPC names.
- **`SECURITY INVOKER`.** The screens write the tables directly under RLS; there is no office RPC to wrap. A definer wrapper would have had to re-state the gate and would have slipped past the training and twin fences, which are RLS. Running as the caller makes the database the judge, as it is for a press on the phone.
- **The quantity is capped at what the box has**, as the phone's number sheet caps it; more than that is a count. A box with none of the part refuses — deliver it or move it there first.
- **A retire names what is still in the box and goes ahead**, as the phone's Retire does; the plan is where the agent reads it.
- **No `read_only`-style shortcut for the agent:** a twin and a training account are refused, the same as the app refuses them.
