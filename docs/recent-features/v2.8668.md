# v2.8668 — Agreements: find the papers for one site (2026-11-26)

Punch list #439, piece 3 of seven, its part 3d. Client only: no migration, no edge function. It reads the three site columns `agreements_on_file` answers since `20261126110711_agreements_on_file_site.sql` (v2.8659, pushed 2026-11-26). It writes nothing.

## What was there

v2.8660 lets a paper name a site and v2.8665 shows a site's papers on its jobs. On Documents → Agreements, the one list of every paper, a site was on no line and nothing found by it. The find box reads words, and a site's address is not among a line's words.

## What changed

- **Find by site…**, a press beside the find box, for the office and the estimator. It opens **Which site is it for?**, the window v2.8660 made, with the list's own words: *Pick an address. The list then shows the papers that name it.* and **Every site** as its first choice.
- **The ask.** The list is asked for the lines whose paper names one of the site's keys: the picked address's cleaned key and every spelling the answers in **Addresses that look alike** make the same place, forty at most. With the answers refused, the picked spelling alone.
- **Over the list** a line reads *Papers for the site at …* with **Clear the site**. The kind chips, the state chips and the find box still narrow the shorter list. The empty list's **Clear the filters** clears the site too.
- **On a line** a paper that names a site says *for the site at …* after who it is with, whether or not the list is asked for a site.
- **The Search tab** carries no site: it finds by words across every kind.

## How it is built

- `agreementsLedger.ts`: `AgreementsQuery.site` (`AgreementsSiteAsk`, the keys), `agreementsSiteAsked`, `agreementsNarrowed` counts a site, `AGREEMENTS_SELECT` reads the three columns, and the words (`AGREEMENTS_SITE_WORDS`, `agreementsSiteSentence`, `agreementSiteWords`).
- `agreementsLedgerIo.ts`: `applyFilters` adds `.in('site_address_key', keys)`. Every other kind of line answers null there, so it falls out.
- `PaperSitePicker.tsx` takes `lead`, `none` and `closesOnEscape`, so one window serves the send and the list. In Send a paper the caller still owns Escape.
- `DocumentsAgreementsTab.tsx`: the press, the line, `pickSite`, and the site in the read's query.

## Design calls

- **By address only.** A paper that names a development has no address key. The development's page, part 3c, is that door.
- **The chip counts are not narrowed.** *Waiting on a signature · N* counts under the kind chip, as it does while the find box holds words.
- **One window, two sets of words.** A second window for the same pick would be a second place to keep right.
- **The site is not kept in the address bar.** A link to the tab opens every paper, as before.
