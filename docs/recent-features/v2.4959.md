# v2.4959 — GC mode: an answered question says who has the answer (2026-10-08)

A fix to P3-b (v2.4938), found in P3's live check on 2026-10-08. The answer went out and reached the inbox, and `gc_plan_questions.answer_sent_to` held the company. But the answered card still offered **Send it to GC test trade company, delete me** instead of reading *Sent to …*.

- **The cause**: `loadGcProjects` (`src/lib/gc/gcIo.ts`) built each question field by field and left out `answer_sent_to` and `company_id`. So the window never saw who had the answer, and never marked the company that asked from its portal (**asked it**). A second press sent nothing, since the key is the question's.
- **The fix**: the mapping is one pure function, `questionRowOf` in `projectRows.ts`, which carries both columns. `loadGcProjects` maps each row through it.
- **The test**: `gcIo.loadGcProjects.test.ts` reads through `loadGcProjects` itself, against a fake Supabase that answers each table's rows. It fails on the old loader. P3-b's render test had built rows by hand and could not see the loader drop them.
- **Live**: on a dev server against prod, the bidding test project's answered question reads *Sent to GC test trade company, delete me.* and no longer offers to send it.
