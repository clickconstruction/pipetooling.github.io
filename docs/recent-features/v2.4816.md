# v2.4816 — GC mode: the tables for what-if copies, rough schedules and templates (2026-10-07)

PR 4 of the schedule's real build (`to-dos/gc-mode/SCHEDULE_REAL_BUILD.md`; its plan `to-dos/gc-mode/mockups/schedule-pr4.md`, both on branch `spike/gc-mode`): what if and before the job as tables, in `supabase/migrations/20261007235500_gc_schedule_what_if_and_before.sql` (`docs/migrations/20261007235500_gc_schedule_what_if_and_before.md`), after PR 3's (v2.4809).

- Three tables: `gc_schedule_templates` (company-wide, its lines by trade and name, never by id), `gc_rough_schedules` (one per GC project while we bid, keyed to `gc_projects`, with the template's lines copied into `template_lines`), and `gc_schedule_what_ifs` (one person's copy of a schedule, kept whole as the kernel keeps it, with its base and the version it read).
- `gc_schedules.template_id` gets its key (`gc_schedules_template_fkey`, set null), in a `DO` block that runs once.
- A template is append only, by privileges, but its name and the day it is set aside. A what-if copy's policy holds it to its own person.
- Dev only while it is built: one policy a table for `(SELECT public.is_dev())`, `anon` revoked, and the three house sweeps. Nothing reads or writes them yet; the types come in the PR after the push.
