# v2.3833 — Bids: "Edit bid" on the Lien Release tab opens that bid's own details (2026-09-25)

The Lien Release "quirk / likely bug" of [`BIDS_TABS_ARCHITECTURE.md`](../BIDS_TABS_ARCHITECTURE.md), found by the 2026-09-25 map sweep. Client only, no migration.

## The bug

Every Edit door in [`Bids.tsx`](../../src/pages/Bids.tsx) calls `openEditBid(bid)`, which sets the window's initial tab, clears the sent-date attestation flow, runs `bidForm.loadFromBid` (the fields **and** the dirty-prune baseline), seeds `bidDateSent` / `savedBidDateSentRef`, then opens the window. The Lien Release tab's `onEditBid` instead did `setBidFormOpen(true); setEditingBid(bid)` — so the window opened on the right bid with the **previous** form state:

- after another bid's Edit, that bid's fields under this bid's name, diffed against that bid's baseline;
- after New Bid, a reset form whose baseline is `null` — and `pruneUnchangedBidUpdateFields` sends the **whole** payload when there is no baseline, so the first autosave (v2.3130) or Save would write the blank/stale form over the bid.

## The change

- `BidLienReleaseTab`'s `onEditBid` is `openEditBid`, like the other eleven doors.

## Verified

- No kernel to test (it is the door's wiring); `openEditBid` itself is the path every other Edit button runs. Typecheck, lint.
