# v2.2407 — Per-GC sent tracking: Edit Bid panel + derived bid_date_sent (2026-08-27)

Option A from the "Bid Sent Tracking" mockup canvas (owner-approved): with
multi-GC bids, "sent" was recorded twice and the two disagreed — the Cover
Letter's Mark-sent wrote per-GC send rows then stamped `bids.bid_date_sent` =
today and overwrote `bid_value` with THAT GC's letter total (last GC marked
won), while Edit Bid's hand-typed date wrote no send rows at all.

Now the per-GC send records (`bid_version_sends`) are the one truth and the
bid-level date is a derived roll-up = **first send**:

- **Migration `20260827211517`**: row trigger on `bid_version_sends`
  (`sync_bid_date_sent_from_sends`, invoker rights) keeps
  `bids.bid_date_sent = min(sent_on)` — NULL when the last row goes (the bid
  returns to Unsent/Working). Backfill converges bids that have send rows
  (multi-send bids previously showed the LAST send date). Version-less bids
  (no send rows) keep their hand-set dates + the attestation flow untouched.
- **`BidGcSentPanel`** (new, in Edit Bid replacing the date input on bids WITH
  versions): roll-up line ("2 of 3 GCs sent · first …"), one row per GC packet
  (via `groupVersionsByGc`) with Mark sent (today), inline ✎ Date… (backdate /
  correct — updates the packet's latest send rows, or inserts real rows when
  the packet only had the pre-per-GC fallback date), and Un-send (danger
  confirm; deletes the packet's rows). Shared-letter recipients show read-only.
  After each write the panel re-derives first-send, mirrors it onto the bid
  (same value the trigger writes) and into the parent form via
  `onGcRollupDateChanged` so Save can't clobber it; `bid-version-sends-changed`
  refreshes the strip. A `liveBidDateSent` state keeps the fallback honest
  after un-send (the prop is a modal-open snapshot).
- **Cover Letter `markSentToday`**: date patch is now min(existing, today)
  (never moved later by a later GC) and `bid_value` stamps only when marking
  the bid's OWN GC's letter (`selectedKey === 'bid-default'`) — the
  last-GC-wins overwrite is gone. Caption updated per case.
- **Kernel**: `firstSentOn` in `versionSends.ts` (+ tests).

Deploy order: client first, then `supabase db push` (client writes the same
derived value itself, so the window behaves identically). Deferred: a board
"sent 1/2" per-GC count badge (board still shows the single first-sent date).

Verified live on BP398: fallback rendering, date-edit insert + update paths,
un-send → Unsent/Working return (board updated live), re-mark, roll-up line.
