# v2.8597 — Materials on site: a job reads as empty only once its boxes are read (2026-11-25)

Punch list #398, from the simulator's fourth sitting on 2026-11-25, on the live site as the dev. Client only. No migration, no edge function.

**Seen.** On choosing a job with three boxes, a read failed on the sign-in lock. The red line drew, and under it the list read *No containers on this site yet*, with **Add a container**. After a reload, *Loading the boxes…* stood over the same empty words for under a second, then the list drew.

**The cause.** `TallyOnSiteTab.tsx` drew the empty state on `containers.length === 0` alone, and never asked whether the read was in. The same file already had the right test for another use, `emptyJob`, which asks `load.loaded`. The office's twin, a job's On site section in `JobsMaterialsTab.tsx`, had the same shape under its own loading line.

**The mend.** In both, the empty state is drawn only when `load.loaded`. While the boxes are read the loading line stands alone. After a failed read the retry panel stands alone. An empty state offers **Add a container**, and on a job that has boxes that press is the harm.

**What did not change.** A job that is read and has no box reads as before, with the other jobs that hold boxes under it on a phone. A read made again behind a screen that already shows its boxes stays quiet, as the store has it.

**Tests.** The tally's smoke: reading draws the loading line and no empty words, a failed read draws the retry panel and no empty words, a read empty job draws them. A new smoke for the office's section, the same three at a phone's width and at a desk. All nine fail on main.

**Not in this PR.** The failed read offered no **Retry**. That is the other brief of the same sitting, on the sign-in lock.
