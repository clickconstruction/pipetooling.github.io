# v2.3664 — Put a GC on notice: the buttons clear the bottom bar, and read in dark mode (2026-09-21)

Client only; no migration, no edge function. PR 1 of 2 on the *Put a GC on notice* window — the two bugs found while reviewing its layout (mock-up with the before, the first pass, the critique and the after: the Claude artifact *On Notice, Step by Step*); PR 2 is the layout. Both bugs were fixed on the Lien desk and never carried to this modal.

## The causes

- **Footer under the bar.** The overlay was `inset: 0` at z 90 with `maxHeight: 92vh`; the Dispatch / Job mode footer is fixed at z 1000. Measured on prod data at 1440×900: the modal ran to 864px and the bar starts at 840px, so the last 24px of the footer — the bottom of *Approve all 6 and send the run* — was covered. The desk's fix is v2.3522.
- **White on pastel.** `btn()` used `--text-link`, `--text-green-800` and `--text-amber-800` as *fills* under a white label; text tokens lighten in dark mode (`#60a5fa`, `#86efac`, `#fcd34d`). The desk's fix is v2.3656.

## What shipped

- [`GcOnNoticeModal.tsx`](../../src/components/jobs/GcOnNoticeModal.tsx) — the overlay's `bottom` and the modal's `maxHeight` read `--app-bottom-chrome` (v2.2184), and `FILL` (primary `#2563eb`, green `#166534`, amber `#92400e` — the tokens' light values, so light mode is pixel-identical) feeds `btn()`.

## Verified

- Dev server on prod data, dark mode, RMC- Dudley Mason (6 jobs): buttons end at 810px, the bar starts at 840px; computed fills `rgb(146, 64, 14)` and `rgb(22, 101, 52)`.
- `GcOnNoticeModal.render.test.tsx` pins the literal fill and the overlay's `bottom`.
- Typecheck, lint, theme check, tests.
