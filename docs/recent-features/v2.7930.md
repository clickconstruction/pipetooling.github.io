# v2.7930 — Lien desk: the copies packet can be looked at before it prints (2026-11-19)

## Why

The owner, 2026-11-19, asked whether a session can pull the packet that **Filed liens: copies to mail** prints, as a PDF, and show it to him, to talk about it before he prints. It could not in one step. The dev seat reads the filings and the Drive folder but has no verb that builds the print. It was done once by hand: the dev server, `/dev-login`, a temporary line in `LienServeWindow.tsx` to reach the window's plan, `buildLienServeRun` called from the page, and a throwaway local receiver for a 10 MB blob. That took five minutes and a machine with the dev server running.

## What changed

- **`npm run lien:packet`** builds the file in one read-only step, from any checkout. `-- --out <file.pdf>` says where it goes, job numbers hold it to those liens, `--no-letter` leaves the letters out, `--alone <job numbers>` prints a saved copy the window holds as more than one lien, and `--marks` prints a mark for each page. With no `--out` the file goes under the computer's temporary files.
- **It says what is in the file**: each lien with its envelopes and its pages by the file's own page numbers, each lien held with its reason, any lien the print left out, and any number asked for that is not on the list.
- **The pure half** is `src/lib/jobs/lienPacketPreview.ts` (20 tests, made-up names): the flags, the pick by job number, where the file may go, the fence on requests, the report, and the page marks.

## The route, and why

Two routes were weighed.

1. **A repo command that runs the app's own code in Node.** Taken.
2. **A dev seat verb on `dev-mcp`** that builds the packet on the server and hands back a link. Not taken. The letter is drawn by `filingDocPdfBlob` (jsPDF) and the stack by `pdf-lib`, and both would have to be bundled into the edge function unchanged, under a 4.5 MB cap, beside every kernel they pull in. A function has about two seconds of CPU a request, and an eleven-lien run copies 10 MB of scans. The other way to fit it there is a second drawing of the letter or the sheet, and a second drawing is the one thing a preview of legal paper must not be. A verb would also need somewhere to keep a file of customers' names for the link.

Route 1 was checked before anything was built. jsPDF draws the letter in Node as it does in a browser, `pdf-lib` and the Web Crypto digest run as they are, and the app's own Supabase client signs in through `dev-login` the way the pay scripts do.

The one hard part was the rows. Which liens are on the list is decided by the desk's read, a 450-line effect in `useLienDeskData` that also drops the jobs paid in kind, off the lien path, on public property, and the ZZ test jobs. A smaller read of `job_lien_filings` would have been a second answer to "which liens", and pulling the effect out into a function would have re-indented the busiest hook on the desk under several open branches. So the command renders the hook itself, unchanged, in a jsdom page and waits for it. The desk cannot change its read without the preview following.

`import.meta.env` is filled once when vite-node starts and a worktree has no `.env.local`, so `scripts/lien-packet/start.ts` reads the keys from the main checkout and starts the runner with them, as `scripts/walk/start.ts` does.

## What keeps it read-only

- It calls `buildLienServeRun`, the half of the press that opens no tab and keeps nothing. It never calls `printLienServeRun` or `fileSentCopy`.
- Every request passes `lienPacketRequestRefusal` first. A table takes a GET alone. A function of the database is called only when it is one of the desk's `list_…` readers. Of the edge functions it asks `dev-login` for its link and `drive-link` for `read`, and no other.
- A refused request stops the command with no file. So does a row read that did not come back: the desk's read goes on with part of its rows missing, which is right for a screen and wrong for a file somebody will read as the whole list.
- The letterhead read is called with no role, so its one branch that saves a draft cannot be taken.
- `--out` inside this checkout or the main checkout (which holds every worktree) is refused, links followed. The file is written with mode 600.

## How it was checked

On 2026-11-19, against prod, read only. The command wrote an eleven-lien file: 22 envelopes, 68 pages, two of them the mail sheet. The window was then opened in the dev server, `buildLienServeRun` was run in the page on the window's own plan and bytes with `autoPrint: true`, as the press calls it, and `lienPacketPageMarks` was run over both. All 68 marks agreed. A mark is the SHA-256 of the page copied alone into a file with no date on it, so it covers the drawing, the scan behind it and the page's size. The files' own bytes differ by 36: the press's file asks for the print window and the preview's does not.

Afterwards every one of the eleven filings still had no mailing day, and no kept copy of kind `lien_affidavit_copy` was filed that day.

## Not done

- The preview reads as a fresh browser: ZZ test jobs hidden, the letter box ticked. A dev who has ZZ test jobs shown sees those in the window and not in the file.
- A file held to some job numbers has its own mail sheet. It is a part of the press's print, not the whole.
