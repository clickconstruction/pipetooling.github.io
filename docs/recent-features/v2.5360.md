# v2.5360 — Four server functions name every field they read, and pass their type check again (2026-10-12)

A type-only fix to four edge functions that `deno check` refused because their code read a field its own type did not declare. They were found while fixing `_shared/fileSentCopy.ts` (v2.5348). Each field was checked against what really arrives before it was declared, and none is a bug: the caller sends it or the RPC takes it, and the code already checks it. No migration and no screen. Nothing behaves differently.

- **`send-physical-invoice-email`** read `body.additional_emails` (2 errors, TS2339). Bill Customer (`SendRecordInvoiceModal`) has sent it since v2.940 when contact persons are picked for copies. The re-email path (`resendPhysicalInvoiceEmail`) never sends it. The function already checks it: at most 10, each an email, the customer's own address and repeats dropped. The body type declares `additional_emails?: string[]`.
- **`send-rfq-email`** read `plansLink` off the stored `bid_rfqs.scope` in a saved request's preview, the reminder and the resend (3 errors, TS2339). A send has stored it there since v2.2642 (`scope: { lines, text, plansLink }`), but both casts left it out. They use one `StoredScope` type now. A row saved by a copied quote link (`{ lines }`) or an outside request (`{}`) has none, and `cleanPlansLink` reads it as no link, as before.
- **`stripe-webhook`** set `rpcArgs.p_recorded_by` (1 error, TS2339). `mark_invoice_paid_from_stripe` has taken `p_recorded_by uuid default null` since `20261001153000` (v2.4289), its latest definition. The migration ledger on prod matches the repo's 878 files, and `src/types/database.ts` lists the argument. `parseOobPaymentMetadataFromStripe` passes it only when it is a uuid. The arguments' type declares `p_recorded_by?: string`.
- **`test-email`** read `error.message` off an `unknown` in its outer `catch` (1 error, TS18046). It reads `(error as Error).message` now, as `change-user-email`, `invite-user` and `send-sign-in-email` do. What its `try` can throw (a body that is not JSON, a failed `fetch`, a `body` that is not a string) is an `Error`, and the two best-effort helpers it calls catch their own.
- **Checked**:
  - `deno check --no-lock --node-modules-dir=none` (deno 2.9.6, TypeScript 6.0.3) of the four went from 7 errors to 0, on `main` with v2.5348's `fileSentCopy.ts`. On `main` without it, each shows only that file's 2 errors.
  - Each `index.ts`, main's and this one, compiled by TypeScript's `transpileModule` with comments dropped, gives byte-identical JavaScript.
- **Deploy**: redeploy the four once merged. The code that runs does not change, but until then `npm run check:edge-drift` and the Edge function drift workflow name them as behind `main`.
