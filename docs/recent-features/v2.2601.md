# v2.2601 — Send Job Back: stage-billed framing + reason chips (2026-09-01)

Owner request (2026-09-01, screenshot of the Send Job Back confirm): "Oftentimes a job will
be sent to billing and only part of it will need to be billed aka a stage of a job. After
that part is billed, we need to move the job back into working. This modal doesn't well
represent that occasional case." Chosen design: Option A — context-aware form with reason
chips (intent picker and a bill-from-Working affordance were considered; the latter noted
as a possible follow-up).

Mechanically the round trip already worked — RTB → Working never touches billed invoices
and only deletes unsent RTB drafts, where the elastic primary remainder re-mints itself.
The modal just *talked* like every send-back was an incident.

- **New kernel** [`src/lib/jobs/jobSendBackContext.ts`](../../src/lib/jobs/jobSendBackContext.ts):
  `sendBackJobBillingContext(invoices)` classifies the job (billed/paid lines that survive,
  RTB drafts deleted, deliberate non-primary drafts among them) →
  `stageBilledContinues = billedCount > 0 && rtbNonPrimaryDraftCount === 0`;
  `sendBackRequiresVoidAttestation` = a non-primary draft is being deleted. Unit-tested.
- **Modal** ([`JobsStagesTab.tsx`](../../src/components/jobs/JobsStagesTab.tsx), both
  RTB-section call sites pass the context):
  - Stage-billed copy: "The job returns to Working. Its billed line stays billed ($X). The
    unsent remainder draft is removed and comes back automatically…"
  - The "I am going to call the Subcontractor… voiding this bill" checkbox renders — and
    gates the button — ONLY when the send-back deletes a deliberate draft carve (Billed →
    RTB send-backs keep it always; missing context fails safe to required).
  - Reason chips in the stage-billed state: "Stage billed — continuing work" /
    "Rework needed" — one tap fills the required crew-visible reason (both satisfy the
    v2.2065 `sendBackReasonError` minimum).
- Help guide `ready-to-bill-pipeline.md` gains the "Billed a stage and the work continues?"
  paragraph.
- Client-only; no migration, no edge deploy. Possible follow-up (Option C from the design
  discussion): a "bill a stage from Working" affordance so the round trip becomes rare.
