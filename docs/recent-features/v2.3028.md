# v2.3028 — Test-gap audit, pass 38: the Form Studio template repository gets its first tests (2026-09-07)

Follow-up to v2.3027. Tests only; no kernel, client, migration or edge-function change.

## Why this one

`forms/formTemplateRepo.ts` (155 lines) is Form Studio's data layer: list, create, replace the PDF, save, delete, the private-bucket storage calls around them, and publish → the Book entry a form becomes. The schema, fill-state and studio-state kernels beside it were tested; the repository was not.

## What the tests found

Nothing wrong. Contracts now pinned that were only implied:

- A new template's PDF is stored under a fresh id at `<id>/template.pdf` with no overwrite, then the draft row is inserted with the trimmed name and revision, the SHA-256 of the bytes and a page count of at least one; a failed upload stops before the insert, and a failed insert removes the uploaded PDF.
- Replacing the PDF overwrites at the row's path and saves the new hash and page count. Delete removes the row, then the file. The signed URL lives ten minutes unless told otherwise.
- Listing fills a missing or partial schema with the empty defaults so the studio never sees an undefined field.
- Publishing stamps `published_at` once (a republish keeps the first date) and keeps one Book entry per form: an existing entry is moved or renamed in place with its sequence untouched, a new one lands at the end of the chosen packet (0 for an empty packet). A Book insert that returns nothing fails loudly.

## What shipped

- **`forms/formTemplateRepo.test.ts`** (12) — a recording Supabase stand-in for the tables and a spied storage bucket, fake time, the real SHA-256 (the empty-input digest pinned). Covers the list normalisation, the hash, create with its two failure clean-ups and the one-page floor, replace / save / delete, the signed URL and download with their failures, and the three publish paths.
