# v2.3556 — Estimate options, approve more than one — PR 3: the office (2026-09-17)

The last of three (`to-dos/estimate-options-approve-several/`; PR 1 = v2.3554 the kernels, the column and the four functions; PR 2 = v2.3555 the customer page). Client only. This is the PR that lets an estimate carry an add-on, so the whole feature lights up here — Taunya's *"the ability to approve more than 1 option"* (2026-09-17).

## The builder (Estimates → draft editor)

- Each option card in the strip above Line items says how it is offered — *one of the choices* (amber) or *+ add-on* (blue) — and an add-on's total shows with a `+` while the estimate has a choice group.
- Under the name and pitch fields, an **Offered as** switch: *One of the choices* · *An add-on* (`setViewedOptionKind` → the kernel's `setEstimateOptionKind`, which re-seats the star when the rule needs it, and the Page preview restarts from `defaultEstimateSelection`). A copy made with ＋ Option is offered the way its source is.
- **★ Recommended** is disabled on an add-on while a choice exists (*The star marks a choice — add-ons are never pre-selected*); on an all-add-on estimate it moves freely and marks the number the office forecasts. One helper sentence closes the row: *Choices: the customer picks exactly one. Add-ons: they tick any. Make every option an add-on when there is nothing to choose between.*
- The staff **Email** preview passes `kind`, so it renders the same ladder the customer's email carries (choices first, add-ons labelled with a `+`).

## The record

- The accepted view's **Customer acceptance** block reads the new [`estimateAcceptedRecord.ts`](../../src/lib/estimates/estimateAcceptedRecord.ts) (+6 tests): `acceptedEstimateOptionKeys(row)` takes the v2.3554 key list first and falls back to the single key, so every acceptance from before add-ons reads exactly as it did; `describeAcceptedEstimateRecord` prints *Accepted "Replace 50-gal" + 2 add-ons · $5,740.00 (of 4 offered)*, then *Add-on: …* lines, then *Not chosen: …* lines.
- [`JobSignedAgreementModal.tsx`](../../src/components/jobs/JobSignedAgreementModal.tsx)'s Document line says *option "Replace 50-gal" + 2 add-ons frozen at acceptance* from the same helper.
- The Estimates list's row mark grows when add-ons are out with the customer: *· 4 options · 2 add-ons* (`estimateListAddOnCount`, the same cheap keyed-entry scan as the options count).
