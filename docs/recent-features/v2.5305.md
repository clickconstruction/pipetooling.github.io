# v2.5305 — Messages: a flow step can wait on a paper made in the Contract library (2026-10-12)

Messages cut 4, a small kernel PR cut ahead of the flow screens (helper 4) so helper 6's New paper window can import it. TypeScript only: no migration, no screen.

- **`src/lib/flows/facts.ts`** gains the runtime family for a paper made in the New paper window: its id is `doc:<library uuid>` (`DocPaperId`, `isDocPaperId`), and a fact on it is `doc:<uuid>:on_file`, `:current`, `:signed` or `:sent` (`DocFactKind`, `DOC_FACT_KINDS`, `DocFactId`, `docFactId`, `docFactOf`). `docFact(id, name)` reads one like the code list's facts ("The safety plan is signed"), and `stepFactById(id, name?)` finds a step's fact either way; `StepFactId` and `StepPaperId` name the wider sets. A step's `facts` and `papers` keep their types: a runtime id rides in them, cast at the database boundary, so the card, the editor and the board need no change.
- **`src/lib/flows/state.ts`**: `factRead` and `factsWords` read a runtime fact through `stepFactById`.
- The database takes these ids with cut 4's SQL (#5435: `flow_papers_ok`, `flow_facts_ok`); the loader's `docStamps` that stamps them from the library rows comes with the flow screens.
- **Tests**: `docFacts.test.ts` (the ids, the words, a stamp read through `factRead`).
