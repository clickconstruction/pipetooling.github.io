# v2.3222 — The Robot Board mirrors the Bid Board; the robot's envelope opens at send (2026-09-10)

Client only — no migration, no edge function. Grace's direction after the first-look pass (v2.3217): the Robot Board "should not be its own bid board" but "a mirror of the bid board placing these bids in the correct positions and letting us know the perspective of the bids from the robots, such as how far off they were", and the seal procedure should let the estimator "review the robot's interpretation" just before sending, "when the user has the most knowledge about the bid". Before/after mockup and the think-through: https://claude.ai/code/artifact/a2e80fb4-7dec-4cce-8aa0-e203b3f14e70.

**Owner decisions this touches (flag for Robert):** v2.2500 made the Robot Board a lens so ZZ shells stay off the human board — the mirror keeps shells off *every* board and changes what the lens shows, from shells to perspective. The seal doctrine (v2.2544 total, v2.2553 rows) is not loosened: the envelope defines "scored" — the instant the bids row saves with value + sent date, which is when `bids_score_shadow_on_send_trg` (v2.3126) scores the run — as the moment a reveal becomes allowed. Nothing an estimator sees in the envelope can move a score already on the ledger.

## Robot Board → the mirror

- Kernel [`src/lib/bids/robotMirror.ts`](../../src/lib/bids/robotMirror.ts) (+11 tests): `buildRobotMirror({ humanBids, shells, shadowRuns, scores, audits, standardTeacherIds, draftTotals })` → one row per HUMAN bid with at least one robot run, bucketed by the board's own `getSubmissionSectionKey`. Pairing: a shell's `twin_source_bid_id` wins; a shadow run's `reference_bid_number` (`list_shadow_runs`) fills in for pre-v2.2543 shadows; a backtest score's `reference_bid_number` (`twin_run_scores`) covers the seeded BT-6..16 rows that never had a shell. Run statuses: `queued` (a live bid stamped front-of-the-line, no robot yet) · `working` · `audited` (audit filed and priced, no ledger row — the first slate predates `score_backtest`; the draft total stands in, on a SENT bid only) · `sealed` · `scored` · `void`. Newest run leads the row (`sortRunsNewestFirst`); earlier rounds fold behind it. `note` = "no bid value on record" for a sealed run on a sent bid (RBFCU, LIVSTE went out without a value, so the trigger could not score). `uncoveredLive` / `liveEligible` from `shadowCoverage`; `orphanShells` for the shells that pair to nothing (four today: b399, b403, b404, b423).
- Lens [`src/components/bids/BidsRobotMirrorTab.tsx`](../../src/components/bids/BidsRobotMirrorTab.tsx): a four-stat strip (bids with a robot run · live plumbing bids shadowed · audits waiting with the oldest age · axes past Gate B) — the Scoreboard's pills, moved — then the five board sections (Lost collapsed, as on the board). Columns: Bid # (opens the bid) · Project · GC · estimator · sent date · **Robot** (glyph + number or status word, the run label, teacher) · **Ours** · **Δ** (green within ±8%) · doors: `Review now` (a scored/audited run whose audit still waits, sent bids only → the envelope), `Open audit` (lands on that card — new `focusAuditId` prop on `BidsAuditsTab`), `Compare` (the v2.2532 comparison modal), `Robot bid b###` (the shell on its Counts tab). The unsent header carries "N more live bids have no robot yet". Audited-but-unscored shells get their draft priced once (chunked, `computeAuditDraftTotal`, the Audits lens's rule) and only when the human bid is sent. Deep links from the status sheet / comparison modal ring the human row whether they name the human bid or its shell. Reports its row count for the lens label (`Robot Board · 32`).
- The seal in the mirror: a live bid's run shows status only. `list_shadow_runs` NULLs the money until scored and the kernel never reads a shell's draft for an unsent bid.

## The envelope at send

- Kernel [`src/lib/bids/robotEnvelope.ts`](../../src/lib/bids/robotEnvelope.ts) (+9 tests): `envelopeRefusal(bid, viewer, runStatus, offered)` — opens only when the bid is sent WITH a value, the run is `scored`, the viewer is in `ROBOT_AUDIT_ROLES`, and the viewer is the bid's estimator (the teacher the trigger names) or a dev; once per bid per session. `pickEnvelopeRows(diff, cap = 6)` pools missed / added / gaps / rates by dollar distance, missed ahead on a tie. `EnvelopeRun` + `envelopeRunFromShadow`. `robotReviewRevisionNote` / `isRevisionAfterReveal` — a bid-value change on an already-sent bid with a scored run posts `[robot review] Bid value revised after seeing the robot's number: $A → $B (+$D) · robot had $R` to `bids_submission_entries` (the score stays as taken; the revision is on the ledger by name in both directions).
- Modal [`src/components/bids/RobotEnvelopeModal.tsx`](../../src/components/bids/RobotEnvelopeModal.tsx): robot locked · ours · delta KPIs (practice-teacher line when the sender is not a calibration standard), the v2.2935 waterfall, the six biggest differences with the cockpit's one-tap verdicts (`ok` posts at once; `teach` / `record` open the drafted note), the robot's open questions (`twin_questions` with v2.3210 tap choices, `bid_audit_notes` questions with an answer box), then **Full audit** (Audits lens on that card) · **Later** (nothing changes; the audit waits as today) · **Finish audit** (`audit-finish` edge fn, PT-side fallback). Verdicts and answers write through the same inserts the Audits lens uses. Shared loader [`src/lib/bids/loadPricedTakeoffRows.ts`](../../src/lib/bids/loadPricedTakeoffRows.ts).
- Doors in [`Bids.tsx`](../../src/pages/Bids.tsx): `offerRobotEnvelope(bidId)` re-reads the row, finds the bid's scored shadow via `list_shadow_runs`, applies the refusal rules and opens. Called after every send write: the Edit tab autosave when it wrote `bid_date_sent` or `bid_value`, the explicit save, the per-GC panel's roll-up (`onGcRollupDateChanged`), and the Cover Letter's **Mark sent today** / first room-link send (new `onBidSentRecorded` prop on `BidsCoverLetterTab`). `openEnvelopeFromMirror` opens the same modal from a Robot Board row (`mirrorRunReviewable`). Dev door: `/bids?envelope=<bid number>` force-opens the envelope on that bid's scored shadow (support + testing; estimators never see it).
