# v2.6488 — The dev seat reads every movement on a site and reports a full read truthfully, and one refused token no longer stops a whole OCR pass (2026-11-04)

Four confirmed edge-function bugs, fixed in one PR with no function deployed from it. The dev seat's `read_on_site` (v2.6367) paged `job_material_movements` by `at` with an id-dedupe set and stopped when a page added nothing, so a group of 200 or more rows at one stamp — an `apply_delivery` or `apply_count` with 200 lines writes 200 rows at one `now()`; two deliveries with the same explicit `at` do it with 100 each — made every page from that stamp answer the same first 200 rows; the loop broke and every row after the stamp was dropped with `capped` still false, so an agent could read "25 on hand" in a box that held none. `readAllRows` said `capped: true` whenever a full page reached `max`, before asking whether another row existed, so `get_job` wrote `money.stopped_reads` and "these totals undercount" over a read of exactly 5,000 complete rows. `ocr.ts` cached the pass's token promise with `??=`, a rejection included, so one 503 from Google's token endpoint refused every scan the pass reached (up to ten in a sweep) and stamped each for a day. And `drive-link` refused a digital twin's `search` or `search_index` with *A digital twin cannot change Drive.*, words that were not true of the ask.

## What changed

- `supabase/functions/_shared/devMcpComposites.ts`: `readOnSiteMovements` pages `job_material_movements` by `id` through `readAllRows` (the kernel's `byTime` orders the rows, as it already did), and `job_containers` and `job_places` page the same way instead of one read of 200 (`ON_SITE_PAGE` is gone). `readAllRows` reads one row past a full last page that reached `max` and sets `capped` from whether that row exists, so a read of exactly `max` rows is whole and "these totals undercount" is said only when they do.
- `supabase/functions/_shared/ocrKernel.ts` + `ocr.ts`: `mintOnce` holds the pass's cloud-platform token and forgets a mint that fails, so the next scan mints again; `ocrSetup` uses it. The sweep's per-scan stamp and the ten-scan budget are as they were.
- `supabase/functions/_shared/driveLink.ts` + `drive-link/index.ts`: `twinRefusalWords(action)` — a twin asking `search` / `search_index` reads *A digital twin cannot search Drive.*, a `list` / `open` / `list_company` / probe *cannot read Drive*, anything else *cannot change Drive*. The body is parsed before the check so the words fit the ask; a twin is still refused with 403 whatever it sends, and no access is widened.
- `supabase/functions/dev-mcp/index.ts`: `SERVER_VERSION` 0.24.0 → 0.24.1 (the nine test pins in `devMcpWrites.test.ts`, `devMcpPlanSets.test.ts` and `devMcpPersonReport.test.ts` move with it); the header comment's "The file index (v2.6332 / 0.14.0" reads 0.15.0, the server that shipped it (0.14.0 was v2.6317's plan-part verbs, as `docs/dev-mcp/README.md` and the dev-mcp section of `docs/EDGE_FUNCTIONS.md` say); the server instructions' Materials clause now ends before `plan_hours_statement → apply_hours_statement` ("…named by its stencil; plan_hours_statement…"), so an agent no longer reads the hours-statement pair as part of it.
- Tests: `src/lib/devMcp/devMcpComposites.test.ts` — `pagingReader` answers `gte` beside `gt`, so the old `at` paging runs against it and shows what it lost; a 450-row ledger with rows 100–299 at one stamp reads whole through `readOnSiteMovements` (450 rows, three reads) and through `getOnSite` (450 on hand in A2, the newest row first, the boxes and the places one read each); a read of exactly the cap reports `capped: false` through `readAllRows` (two full pages and the look past them) and `get_job` with exactly `ALL_ROWS_MAX` card lines counts them whole with no `stopped_reads`; the 450-over-400 cap case now counts the look-past read. `src/lib/documents/ocrKernel.test.ts` — `mintOnce` rejects once, mints again on the next call and shares that answer; two callers at once share one mint. `src/lib/documents/driveLink.test.ts` — the twin's words per action.
- `docs/EDGE_FUNCTIONS.md`: the dev-mcp server note for 0.24.1 beside v2.6463's.
- **Deploy after the merge**: `dev-mcp`, `drive-link` and `file-index-sweep` (`ocr.ts` is shared by the last two). Nothing was deployed from this PR.
