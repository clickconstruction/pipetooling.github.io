# v2.6359 — The ground under job photos with a description (punch list #244, PR 1) (2026-11-02)

Punch list #244's first PR, on the owner's go of 2026-11-02 (*build it all and let me know when it is live*) with the card's eight calls taken as recommended. The owner's ask: a photos icon beside the Pipeline row's Job folder icon and a window like the report's photo upload where anyone adds a photo to a job with a description that can be found later, and browses the job's photos. This PR is the table, the view's fifth source, the kernel, the io and the shot-tile hook; PR 2 is the sweep; PR 3 the window and the icon; PR 4 the field's doors; PR 5 the offline queue.

## What changed

- **The migration** `20261102171500_job_photo_notes.sql` (`docs/migrations/20261102171500_job_photo_notes.md`): the `job_photo_notes` table, a report photo's shape plus `description` (up to 500 characters), `caption` (what the Drive file is named by) and `added_at` (null while the shot waits on an open window; the press writes it, the sweep files only rows with it, the client discards rows without it); the job's own gate (`can_report_stage_progress`), the words editable by the taker or the office; the private `job-photo-notes` bucket; the `uploaded_photos` view with a fifth branch, `job`, the description as its caption so the search reads every word; the `photo-save` cron with a fifth clause; the three fence calls.
- **The kernel** `src/lib/photos/jobPhotoNotes.ts` (tested): the tile and row shapes, the words, the caption rule (the description's first line cut on a word at 60 characters, else the stage, else *Job photo*), the press's words from `countedLabel` (*Add 2 photos to the job*, dead while a shot is on its way or nothing is ready, never OK), *Use these words for the rest*, the line over the tiles, the words under a tile, the writes the press makes and the toast after it.
- **The io** `src/lib/photos/jobPhotoNotesIo.ts`: the send (the bytes to the bucket, then the row, the bytes taken back when the row refuses), the discard, the press's writes, the viewer's edit of the words, a job's added photos with a signed URL for a shot still in the bucket, and the view's rows for one job.
- **The hook** `src/hooks/useShotTiles.ts` (render-tested): the tile state machine the camera-first report built, written once for a host that takes photos onto a job with no report around them: several files at a desk, one shot a press on a phone with `capture`, the shrink to the office's size, the send through the io the host mounts, Retry and Remove, the words and the stage on each tile, `drop` on a close and `clear` after the press.
- **Documents → Photos** (`lib/photos/uploadedPhotos.ts`): the source chip **Job photos**, the row's source word *Job photo*, and the viewer's door *Open the job*. Until the push the chip lists nothing.

## Decisions

- **A table of its own, not a widened `report_photos`.** The report table's rule is *a row with no report is an unsaved form and is discarded*, and its sweep files saved reports' photos only; widening it means a kind column and every rule branching on it. `added_at` plays the part `report_id` plays there.
- **The shot-tile hook is new beside `useReportPhotos`, not lifted out of it.** The report hook holds the checklist chips, the attach at Save and the kept shots with no signal around the same machine; folding it onto the new hook is a follow-up refactor, so the report form's tests stay as they are in this train.
- **The description is the view's caption** when it is set, so Documents → Photos' server-side search (`caption.ilike`) finds every word of it; the Drive file is named by the shorter `caption` column.
