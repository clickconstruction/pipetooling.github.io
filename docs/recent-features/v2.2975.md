# v2.2975 — Test-gap audit, pass 6: team feedback, its copy defaults and tag-org get their first tests (2026-09-06)

Follow-up to v2.2973, which named team feedback next. Tests only — no kernel, client, migration or edge-function change.

## Why these

`teamFeedback.ts` (315 lines) decides when the clock-out prompt may ask a person for feedback (enabled → snooze → cadence), which cycle a submission files under, and who a person's manager is for the rating — plus the crew-deck reads and writes (v2.2824). It is mostly Supabase calls around two pure rules, so its logic had never been exercised. `tagOrg.ts` (207) builds the tag-org audit signals and falls back to the same manager resolver. `teamFeedbackCopy.ts` holds the shipped Likert prompts and their normaliser.

## How the IO was tested

A recording, chainable Supabase stand-in: every builder method records itself and returns the builder; awaiting it hands the recorded chain to a per-test handler that supplies the `{ data, error }`. The real `withSupabaseRetry` is replaced by a passthrough so a failure path does not sit in backoff. Tests assert both the returned shape and the chain — which table, which `eq` / `ilike` / `in` arguments, which upsert row and conflict target — so a query that silently changes scope fails here.

## What shipped

- **`teamFeedback.test.ts`** (23) — `computeCyclePeriodStart` (cadence buckets anchored at 2024-01-01 noon, the instant before the anchor falls into the previous period, defaults to now); `computeTeamFeedbackEligibilityDetail` (disabled beats everything, no state is eligible, an active snooze wins with its earliest instant the later of snooze and cadence, an expired snooze is ignored, cadence counts from the later of completed and skipped and clears exactly at `cadence_days`); `getTeamFeedbackEligibility` (composes the two, any failure reads as `error`); `resolveManagerUserIdForFeedback` (masters and devs are their own manager, assistant-likes through the first adopting master, superintendents through `master_superintendents`, field roles through the roster person with the same lowercased email among unarchived rows, no email or unknown user → null); the crew reads (`crew_review_teammates` RPC args and `jobs` normalised to an array, this month's rated subjects as a set with the three scoping `eq`s, aggregate numeric coercion with nulls kept, last submission, the state map); and the writes (`submitOpenWords` refuses without a session and otherwise inserts trimmed answers with blanks as null under the computed cycle start; `markCrewDeckCompleted` stamps now and clears the snooze; the dev reset reports `updated` vs `no_row`).
- **`tagOrg.test.ts`** (6) — overrides map and the no-ids short-circuit; override beats the feedback resolver; upsert / delete rows; the signals aggregation (adoption rows deduped, roster hint by lowercased email with one lookup per distinct email, job masters counted and sorted, orphan jobs ignored, users with no rows still get empty signals) and the skipped lookups when there is nothing to look up.
- **`teamFeedbackCopy.test.ts`** (3) — five prompts shipped per set; exactly five trimmed non-empty strings accepted; everything else returns a fresh copy of the defaults.

One first-run expectation was wrong and the kernel right: 979 days after the anchor in 30-day periods is bucket 32, which starts on day 960 — August 18, not 15.
