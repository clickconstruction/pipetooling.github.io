# v2.7265 — Moving a job's materials on site takes its name fixes, sticker runs, Same part? answers and prices too (2026-11-14)

One migration, [`20261114070000_on_site_carry_job_renames_ties_prices_runs.sql`](../migrations/20261114070000_on_site_carry_job_renames_ties_prices_runs.md); no client code and no edge function changed. **`supabase db push` follows the merge.**

## Before

`on_site_carry_job` (v2.6808) moves a job's places, cages and boxes, ledger, box moves and photos to another job, and both the whole-job combine and the dev seat's `plan_materials_move` → `apply_materials_move` run it. It was written before the four tables of 2026-11-13, and a read of the code on 2026-11-14 found that a move or a combine left their rows on the source job:

- a part rename (`job_part_renames`, v2.7212) names the ledger rows that moved, so **Undo** on the new job failed the judge's job match and the name could not be put back;
- a job's own Same part? answers and prices (`on_site_part_ties` v2.7076, `on_site_prices` v2.7159, the rows of a job on no site) were stranded, and a combine deleted them with the source;
- a sticker run printed for the job (`sticker_runs`, v2.7072) kept naming the old job, so its blank stickers were read by the wrong team, or lost its job when a combine deleted it. The map's gap list had named this one.

## What changed

- **The carry** takes the four tables after the photos. Renames and runs take the target job. A job-scoped tie or price goes to the target's scope: the target job when it is on no site, the target's site when it is on one, since the site's screen is the one reader of a job on a site. A pair both scopes answered keeps the newer answer; the older row goes, and the reply says which. A site's own answers and prices stay with the site, since every job on it shares them.
- **The counts** (`on_site_job_counts`) gain the four tables and the job's site's ties and prices.
- **The dev seat's move** refuses a source empty of all nine counts in words that name them, holds the add-up check on every table (the fold into a site included) and writes nothing when it fails, names the four tables in its words and in the note on both jobs only when the job has rows in them, and answers `ties { into, dropped, words }`.
- The combine is not restated: it calls the carry.

## The owner's call

Asked through the main session on 2026-11-14 whether a job-scoped answer landing on a job on a site should fold into the site, stay as the job's (unread) or be dropped: built as the fold, the recommendation, pending his word.
