# v2.3737 — Schedule hub: the sample and twin accounts are off the roster (2026-09-22)

Punch list #30 (*Taunya on a phone*), bug 2. Client only, no migration.

## What was wrong

`/schedule-dispatch?hubTab=day` listed "Sample leader", "Sample assistant", "Sample controller", "Sample primary", "Sample estimator", "Twin Estimator 1", "Twin Estimator 2", "Twin Pricer 1", "Sample subcontractor" and "Sample superintendent" as schedulable people, to a dev and to the sample assistant alike (verified 2026-09-22). The hub's roster loader, `fetchUsersTabRosterForScheduleDispatchHub`, selected `users` by `archived_at IS NULL` and role only — it predates the active-roster kernel (Tier-2 #19) and the sample-account flag (v2.3606), so neither `is_digital_twin` nor `is_sample` was ever applied. The People rosters go through `activeUsersQuery` / `isActiveRosterPerson`, which drop both.

## The change

- **[`scheduleDispatchHub.ts`](../../src/lib/scheduleDispatchHub.ts)** — `fetchUsersTabRosterForScheduleDispatchHub` now runs `activeUsersQuery` (not archived, not a twin, not a sample, dev only for a dev viewer, the People → Users role list) and hands the rows to a new pure kernel, `buildScheduleDispatchHubRoster(rows, includeDevUsers)`, which applies `isActiveRosterPerson` again in memory, keeps one row per id, drops rows with no role and defaults `needs_supervision` to true. `fetchUsersTabUserIdsForScheduleDispatchHub` (no callers) is the same fetch mapped to ids.
- One loader feeds four surfaces, so all four are fixed at once: the Schedule hub (Day / People / Jobs tabs), Dispatch Mode → Schedule, the Quick assign sheet and Quickfill Schedule.
- **[`scheduleDispatchHub.test.ts`](../../src/lib/scheduleDispatchHub.test.ts)** — the kernel: samples and twins dropped for every viewer, archived dropped, dev rows only for a dev viewer, dedupe, empty role dropped, missing flags read as human.

Not touched, noted for a later pass: the Schedule share modal's recipient picker and the Office roster settings' eligible list select `users` by `archived_at` alone too, and so still offer the sample and twin accounts.
