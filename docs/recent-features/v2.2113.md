# v2.2113 — Count Sheet splits counts from line feet (2026-08-22)

Owner report: the Counts tab's Count Sheet strip showed **Total units 1,566.74** for an imported takeoff — a number that adds 12 water closets to 148.5 ft of copper. `bids_count_rows.count` holds both tallies and lengths in one numeric column, and nothing in the schema says which; the unit lives only in the fixture **name**, stamped by CountTooling's "Copy to /Tooling" export (`ft of 2in Copper`, `px of …` for unscaled runs) and echoed by hand entry (`feet of sewer`, `1/2" PEX PER FT`). Prod (read-only probe, 6,530 rows / 233 bids): 1,510 rows on 131 bids are `ft of …` and carry ~96% of the "units".

**Stage 1 (this PR, client-only):**

- **Kernel [`countRowUnit.ts`](../../src/lib/bids/countRowUnit.ts)** (+8 tests) — `CountUnit = 'ea' | 'ft' | 'px' | 'sqft'`; `classifyCountRowUnit(fixture)` reads the name convention with deliberately tight rules (`<unit> of <thing>` or trailing `per ft`; `[Group] ` prefix tolerated) so `FT-1` stays `ea`; `effectiveCountUnit(row)` prefers an explicit `row.unit` (stage 2's column) and falls back to the name — **every surface that totals count rows reads through it**; `sumByUnit` / `formatUnitTotals` ("12 ea · 148.5 ft") / `summarizeRowsByUnit` (the import toast). Known false negatives (`2" HDPE pipe`, `FT SEWER LINE`) are `ea` until a row carries an explicit unit — never loosen the regex.
- **[`countSheet.ts`](../../src/lib/bids/countSheet.ts)** — `countSheetSummary.units` → `byUnit: UnitTotals`; page groups carry `byUnit` instead of `units`; `CountSheetRow.unit?` added.
- **[`BidsCountsTab.tsx`](../../src/components/bids/BidsCountsTab.tsx)** — strip tiles are now **Items · Counts (N ea · k items) · Line feet (N ft · k line types) · [Area sq ft] · [Unscaled px, red] · No plan page · Plan pages cited** (Area/Unscaled render only when > 0); By-plan-page headers read "— 13 items, 12 ea · 148.5 ft"; non-`ea` rows show a muted `ft` (red `px`) tag beside the count; both import paths toast "Imported 35 rows: 29 counts (1,122 ea) · 6 line types (444.74 ft)".
- Help: `count-with-the-count-sheet.md` updated; new guide `import-a-takeoff-from-counttooling.md` (the Import from /Tooling flow had no guide).

**Not changed:** fixture names keep their `ft of ` prefix — the labor/price/takeoff books match count rows by exact name (`fixture_types` like `FEET OF 2" COPPER`), so the prefix is load-bearing. The CountTooling export contract is untouched.

**Next:** stage 2 adds a nullable `bids_count_rows.unit` column (NULL = infer from name) so the importer stamps units, editors can correct a row, and the duplicate-bid function carries it; CountTooling's Copied confirmation mirrors the same split.
