# v2.3907 — Project money: the totals, margin and balance come from one tested place (2026-09-27)

Client only; no migration, no edge function, no screen change. Punch list **#46** row 9 (`to-dos/decomposition-queue.md`): the Workflow map's Stage A (`docs/WORKFLOW_PAGE_ARCHITECTURE.md` → "Recommended extraction order", step 1), which is also step 1 of the Forecast map's order (`docs/PROJECTS_FORECAST_TABS_ARCHITECTURE.md`).

## What shipped

- **`src/lib/workflowMoneyTotals.ts`** — the whole-project roll-up beside `buildWorkflowMoneyFlow`: `sumAmounts(rows)`, `itemsTotalByStep(orderedStepIds, lineItemsByStepId)`, `ledgerTotalForSteps(orderedStepIds, itemsTotalByStepId)`, `workflowMoneyTotals(projectionsTotal, ledgerTotal)` → `{ projectionsTotal, ledgerTotal, marginPct, balance, hasMoney }` (the margin is null when projections are 0 — no division), `formatSignedWholeDollars` (`+$1,235` · `-$400` · `$0`) and `balanceColor` (the ±0.004 dead band).
- **`moneyAmount` pins the one difference between the two old sums.** Workflow added `amount || 0`, the Forecast tab `Number(amount ?? 0)`. They agree on every value the database sends (a JSON number; the columns are `numeric NOT NULL`) — a test runs both old formulas beside the new one. They part only on values it cannot send: NaN (now 0, Workflow's rule) and a numeric string (now its number, the Forecast rule).
- **`src/lib/workflow/unifiedFinancialRows.ts`** — `buildUnifiedFinancialRows(projections, steps, lineItems)`, the Projections & Ledger table's rows, and `panelMoneyTotals(projections, lineItems)` → `{ projectionsTotal, ledgerTotal, left }`. Two rules the page always had are now written down and tested: a projection's stage name is trimmed and a step's name is not (a step saved as "Rough " sits apart from the projections for "Rough"); the panel's Ledger counts every loaded line item, while the rail's total counts only the steps on screen. The panel's ledger sum stays one running total, item by item — summing per step first rounds differently in the last float bit and could flip Left's colour at exactly zero.
- **`src/pages/Workflow.tsx`** — `calculateProjectionsTotal`, `calculateLedgerTotal` and `buildUnifiedRows` are one-line calls; the ledger rail's IIFE reads its totals, margin, balance, `railAmount` and `balanceColor` from the kernel. 4,354 → 4,310 lines.
- **`src/components/projects/ProjectsForecastSpecificTab.tsx`** — the `moneyBalances` memo spreads `workflowMoneyTotals(...)`; the margin chip shows on `marginPct != null` and the balance chip prints `balance`; `formatGutterBalance` is the kernel's `formatSignedWholeDollars` under its old name. The tab's own colours for the strip's end balance (no dead band) are untouched.
- **Tests** — `workflowMoneyTotals.test.ts` (22), `workflow/unifiedFinancialRows.test.ts` (21), `parseWorkflowLineItemPaste.test.ts` (14 — the bulk line-item paste had none; two quirks pinned as they are: an amount with text after the number reads its leading number, `12abc` → 12, and accounting parentheses are refused).
- Both maps say the step is done and name what is next; the playbook's inventory rows and its Workflow ↔ Forecast seam row say the same. The queue card (`to-dos/decomposition-queue.md`) is left for the one docs PR that closes the parallel batch.
