# v2.7986 — Papers: Send for signature keeps who signs (2026-11-19)

Punch list #403, PR 2 of seven: the send keeps the signer. One edge function, one window and one small read. No migration: the columns are PR 1's (v2.7977), and they must be on prod before this function is deployed.

## What is new

- **Signer name** and **Title (optional)**, two boxes above **Signer email** in the Send for signature window (`ContractSendWindow.tsx`). People → Contracts and Documents → Agreements open the same window.
- **Signer name opens filled in.** It is the person the paper is filed under. The office changes it when someone else signs for them, such as the owner of a sub's business that is on the roster by its business name.
- **The paper keeps the signer.** `send-contract-for-signature` writes `signer_name`, `signer_title` and `signer_email` on the paper's own row, in the same update that activates the link. A send keeps both or neither.
- **Sending again opens on the signer the paper kept.** The name and the title come back. The address still opens on the roster's, as before, and on the address the paper last went to when the roster has none.
- One line under the boxes says so: *The name and the address are kept on the paper.*

## What did not change

- **The email.** Its words, its subject, its sender and its sent copy are as they were. `contractSigningSend.pin.test.ts` still holds the person path to main's bytes.
- **The trade company branch** of the function, which mails a company's `contracts` people.
- **Who may send.** The window and the function refuse whom they refused.

## The function's rule

`signerRowPatch` in `supabase/functions/_shared/paperSigner.ts`, dependency-free, read by the app and the function alike:

- **An emailed send** keeps the address the link went to. It keeps the name as posted, else the name the row already holds, else the person the paper is filed under. It never takes a stored name (`gc-company:<id>`, `party:<id>`) for a signer.
- **The title** is written only when the request names one. A window from before this release sends none, so it never wipes a title. A title sent empty clears it.
- **A link made to hand over** (`mode: 'link'`, **Copy the signing link**) emails nobody, so it keeps no address. It only names a signer the paper never had.
- A word is trimmed, its inner spaces made single, and clamped to 200 characters. The table's check from PR 1 refuses an empty word, so nothing empty is ever written.

## One copy of the words

PR 1's kernel `paperParty.ts` held its own `paperWord`, `signerEmailWord` and the stored name's prefix. They now live in `_shared/paperSigner.ts`, where the function needs them, and the kernel reads them from there. Its tests are unchanged and pass.

## The read

`readKeptSigner` (`personPaperSendIo.ts`) reads the three columns of one saved paper. `readPersonPaperSendFacts`, which Documents → Agreements calls before it opens the window, hands them on. People → Contracts holds its own rows and passes none, so the window reads them itself for a saved paper. A read that fails leaves the boxes as they opened: it is a help, never a gate. What the office has typed is never written over.

The three columns are not in the generated types until the types PR that follows PR 1's push, so the column list is a plain string in that one read.
