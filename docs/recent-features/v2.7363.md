# v2.7363 — Tasks: a task card can show a painted map that has no place (2026-11-15)

Punch list #345, *A map on a task*, step 9 of the card's train, built first. Taunya asked for it on 2026-11-15: "I want to add paint a map to checklist items, I want someone to be able to assign a task with a map." She said yes to the design the same day (*Yes, build it*), every call at the card's pick.

Step 9 goes before step 7 on purpose. Step 7 lets a giver put a map on a task with no place. If it landed first, a task could carry a map the person given it could not see. So the card learns to show the map first, and nothing sets one yet.

## What changed

- **Under the title,** a task with a map and no place wears the paint's stroke, the map's name, its length and its places: *The trench · about 830 ft · 3 places*.
- **Opened,** the card draws the whole line from above with its numbered places. The picture frames the line, so a long drive and a short trench both fit.
- **Three presses:** **Open the map**, **Directions to the start** and **How far am I?**. A press on the picture opens the map too.
- **How far am I?** measures to the line's start: *The start is 250 ft north-east of you.* The answer stays on the phone, as a place's does.
- **A photo of the spot** sits beside the picture, as it sits beside a place's.
- The same on the Today tab's cards and on Outstanding rows.

A task with a place is untouched: its map is the way in to that place, as v2.7342 built it.

## How it is built

- `taskMap.ts`, pure (+13 tests): `taskMapIdFromRow` (a row with a place carries no map by itself), `taskMapLineWords`, `taskMapFrame` (the middle of the map's box and the closest zoom that holds it), `taskMapStart` and `taskMapHowFarWords`.
- `loadTaskWheresForItems` in `taskPlaceIo.ts`: the reads that find the tasks' places already bring `painted_map_id`, so the map costs no read of its own. A task made from a roadmap takes its roadmap task's map when it has none itself, as it takes its place. `loadTaskPlacesForItems` is now the `places` half of it.
- `useTaskPlaces` gains `mapFor(taskId)`.
- `useTaskMapWhole` reads the one map for the card with `loadPaintedMap`, and reads again when a painted map changes, so a place added from **Open the map** shows on the card.
- `TaskMapBlock.tsx`: `TaskMapLine` and `TaskMapBlock`. `canOpen` is false where the map's window would open under the window the block sits in, which the roadmap PR will use.

## Is this the best we can do

- **One read a card.** Each card with a map reads its map when it draws, for the name and the length under the title. Few tasks will carry a map, and a list of ten of them is ten small reads. If that grows, one read for the screen is the fix.
- **A map that is gone draws nothing.** No empty line and no error: the task is still the task. A map thrown away already clears the task's pointer in the database.
- **The picture is not a control.** It does not drag or zoom inside a list. The map's own window does.
