# v2.7578 — Tag a teammate from History and from a Roadmap task (2026-11-17)

Punch list #375, PR 5 of six, the last: the two other boxes that write a task note. Client only: no migration, no edge function.

## What changed

- **History's box** (`ChecklistHistoryLedger`). One day is open at a time, so one `useNoteTagBox` serves the open day's box with that day row's names. A note that tags someone posts through `task_note_post_tagged`. A note that tags nobody is inserted as before, and now asks for its new row's id. **Reopen** uses the same box, so its reason takes the same path: a name tagged in it is tagged.
- **The Roadmap task card's box** (`ChecklistTechTreeTaskCardModal`). The same hook, with the day row the card is bridged to. A tagged post that fails says why at the box, since the card is drawn in places with no toast. The plain post in `useTechTreeTaskMutations.postInstanceComment`, which the one-tap *On it* and *Problem* use too, now hands the note's id to the notice.
- **Both threads draw the chip and who a note waits on** through `TaggedNoteBody`. They show one day row, so `useTaskNoteTags` takes a day row in place of a task.
- **The notice.** Both boxes call `notify-note-tag` for a typed note, so an answer typed there reaches the asker's phone. v2.7577 left these two out.
