# v2.8477 — Maps: an address the map cannot place is asked once, not on every open (2026-11-24)

Punch list #408, step 2 of the train of three in [`to-dos/remember-unplaced-addresses.md`](../../to-dos/remember-unplaced-addresses.md). The functions and the readers use the table step 1 made (v2.8473).

## Why

An address no service could place was kept nowhere, so each open of a map sent it to `geocode-address-batch` again, and the function asked OpenStreetMap, Google and the Census again. The card's read of 2026-11-20 counted five such addresses and 80 to 250 calls a day.

## What changed

- **One rule, one file**: [`supabase/functions/_shared/geocodeMissMemory.ts`](../../supabase/functions/_shared/geocodeMissMemory.ts). The edge functions and the screens import the same kernel.
  - `GEOCODE_MISS_STANDS_DAYS = 30` is the one place the number lives. It is the owner's second call, built to the plan's pick.
  - `isSettledGeocodeMiss` is true only when OpenStreetMap, Google and the Census each answered and none found the address.
- **`geocode-address-batch`** reads the misses for the batch before it asks.
  - A miss that still stands is answered in `failures` with `remembered: true` and `checked_at`, and no service is asked.
  - `retry: true` in the body asks past the memory.
  - A miss is written when all three services said *not found*. A service that was down, refused the key or was over its limit keeps nothing. Google with no key set keeps nothing either.
  - The 1.1 second wait is owed only after a request to OpenStreetMap in the same call.
- **`geocode-one`** does the same for one address. The Google refresh reads no memory and keeps no miss.
- **The readers** read the misses for the addresses with no saved point, and send only an address that is in neither.
  - `useAddressGeocodeCoords`: the Dashboard, Pipeline and Bid Board maps, the travel hints, *Needs you*, the Legal desk, *On site*.
  - `useMapPageData`: the Map page. A remembered miss still shows in the address sheet with its reason, and nothing is sent for it.
  - Quickfill's travel hints, which call the function directly.
  - The read is one small request, made only when an address has no saved point.
- **The job form**: *Place it* and *Try again* send `retry: true`. The look-up the line starts by itself takes the remembered answer.

## Both orders of deploy work

- **The new client with the old function**: `retry` is ignored and the old function asks every time, as it always did. No miss is written, so the client finds none and sends as before.
- **The old client with the new function**: it sends no `retry` and ignores the two new fields. A remembered miss comes back as the same failure it read before.
- The function's read and write of a miss are best effort. Neither fails a call.

## What differed from the card

- The card's function deleted the miss on a hit. Step 1's trigger does that, so the functions hold no delete.
- The card read the misses *with* the saved points. The readers read them after, for the addresses with no point alone, so an open with every address placed makes no extra request.
- `isRlsRefusal` in the batch function now also reads the training-mode statement trigger's own words as a refusal.
