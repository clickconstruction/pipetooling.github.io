# v2.3663 — Quick time add, PR 3: the approver's view — the chip, the sentence, the weekly total (2026-09-21)

PR 3 of [`to-dos/quick-time-add`](../../to-dos/quick-time-add/README.md), and the first client code to **read** `clock_sessions.quick_add_minutes` — so it ships after the migration push (2026-09-21, ledger 625 / 625) and the types PR. No migration.

## Why it was not just a chip

The pending-week list shows a session's **job label in place of its note** whenever a job exists (`jobLabel ?? notes`). Every quick add is pinned to the Office job (PR 1), so an approver would have read "Office" on each one and found the sentence only in a tooltip — the opposite of the design, whose whole control on self-reported time is *the chip, the sentence, and one weekly number*. So on a quick add the row shows the sentence.

## The change

- **[`QuickAddChip`](../../src/components/clock/QuickAddChip.tsx)** — one shared mark (violet: the hours surfaces already use green / amber / red for status).
- **[`UpcomingWeekSessionsModal`](../../src/components/people/UpcomingWeekSessionsModal.tsx)** (a person's pay week, where hours are approved) — selects the mark; a quick add's row shows the chip and its sentence; the header gains the weekly line from `weeklyQuickAddLine` — *1 h 05 m across 8 entries this week — time added after a call or an email, not clocked.* (live rows only; the query already excludes rejected and revoked).
- **[`PeopleHoursPendingCellPopover`](../../src/components/people/PeopleHoursPendingCellPopover.tsx)** (People → Hours, a pending cell) — the same chip and sentence.
- `CLOCK_SESSION_LIST_SELECT` and `ClockSessionRow` carry `quick_add_minutes`, so every list built on them (People → Hours, My Team, the pending fetch, Quickfill hours, Job Summary) has the field for the next surface that wants it.
- Guide: `approve-my-teams-hours.md` → *The quick add chip*. Test: a render test of the pay-week view with one punch and one quick add.
