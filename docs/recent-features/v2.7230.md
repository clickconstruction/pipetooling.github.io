# v2.7230 — The Bridge no longer says a wait such as 7 to 7 weeks when Build is the slowest step (punch list #334) (2026-11-13)

A follow-up to the Bridge train (card #334, `to-dos/bridge-pulse/`). An edge function changed (`bridge-weekly-sheet`, through a kernel copied to it), so it is redeployed after the merge. No migration.

## Why

The dry run of the Monday email on 2026-11-13 read *7 to 7 weeks to build what is already sold* under the slowest step. The page said the same. Build's wait is a range when some jobs have no percent: the low end counts the jobs with a percent, the high end adds half of the rest. Both ends are rounded, and that day they rounded to one number. Bill's sentence has guarded against this since it gained its range. Build's did not.

## What changed

- **Build's range has Bill's guard** (`stageFlow.ts`): the sentence is a range only when the two rounded ends differ. Otherwise it is the one figure to a decimal, as with no guess at all: *7.2 weeks to build what is already sold*.
- **The copy the edge functions carry is regenerated** (`npm run gen:edge-kernels`). The kernel index did not change, so the functions that read only the index are not touched.

## Tests

- `stageFlow.test.ts`: a guess too small to move the rounded figure gives one figure, and a larger one gives *7 to 8 weeks*.
