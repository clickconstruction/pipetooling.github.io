# v2.5424 — Messages: every person at a customer reads the customer's language, behind the scenes (2026-10-12)

Residential R8 · 16, PR 2 of 2: the reads. PR 1 (v2.5422, #5585) added `customers.language`. This gives it to every
contact of the customer and picks a quick reply's words by it (`to-dos/gc-mode/messages/RESIDENTIAL_BUILD_PLAN.md` →
R8; card 16 of `customer-messages-integrations-mockups.html` v0.2 on branch spike/gc-mode). Built on R0's loaders
(#5570). No migration and no screen.

- `Contact.lang?: 'en' | 'es'` (`contacts/kernel.ts`), filled by `contacts/load.ts` from the customer's row for the
  customer and each person at one. A row that says nothing, or a value the check would refuse, leaves it unset, which
  is English. Nothing guesses from a name. The loader reads `language` as an optional extra on the customer row until
  the types regenerate after PR 1's push. The fetchers select it only after that push.
- `messages/customerLang.ts`:
  - `customerLang(contact, gate)` is `tradeMailLang`'s rule for a customer: Spanish only once the gate
    (`PORTAL_SPANISH_ON`, a parameter so a test can open it) is on, English until then.
  - `lineFor(line, contact, gate)` is a quick reply's Spanish for a Spanish customer behind the gate, else its English.
    A line with no Spanish, or only spaces, goes in English. It is `wordsFor`'s pick (R3, #5558); the input is typed
    here until #5558 lands, then this calls it.
  - `languageWords(contact)` is the customer card's field: *Reads Spanish* or *Reads English*, as the record keeps it.

The strip, the phone and the morning run pass `customerLang(contact)` in the PRs that draw them. The customer form's
**Language** field is the screens PR, at the save sites PR 1's migration note names. The Glossary clause waits until the
Messages line is quiet.
