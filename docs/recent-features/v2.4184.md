# v2.4184 — The Contract window's highlighted buttons carry their whole border (2026-09-29)

No migration, no edge function. One line in `src/components/jobs/JobContractModal.tsx`, plus its comment.

## What was going on

- `btnPrimary` was `btn` with `borderColor` laid over `btn`'s `border` shorthand. Harmless while the rail's labelled button rows (`Group`) were declared inside the render body: a new component type every commit, so every button remounted per render and React never diffed one button's style against its last.
- v2.4175 hoists `Group` to module scope (the right fix for that remount — see its fragment). Once the buttons persist, one flipping between `btn` and `btnPrimary` in place (Edit & re-send arming, File the signed copy) has a longhand removed beside its shorthand, and React warns: *Removing a style property during rerender (borderColor) when a conflicting property is set (border)*. The modal's tests showed it once, only with the hoist in place; zero times without.
- This PR began as the same hoist, found in parallel; v2.4175 was already in the merge queue with it, so this one keeps only the follow-through.

## What shipped

- `btnPrimary` sets `border: '1px solid var(--text-link)'` as the full shorthand. Same pixels; no warning with the hoist in place.
- The rail's wording and behaviour are untouched.

## To see it

Nothing visible on purpose. Open a sent agreement's Contract window, tap Edit & re-send once (it arms), tap Never mind — the button's border goes primary and back with a clean console.
