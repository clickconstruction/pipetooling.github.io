# v2.8437 — Document builder: a row says how many times a send went (2026-11-24)

A small fault the #416 walk found and left (`to-dos/document-builder-whats-left.md`, *Faults seen and not fixed*): **Send it again** on the day of the first send changed nothing on the row. It still read *Sent* with the same day, and how many times it went was not shown. Client only: no migration, no edge function.

## The cause

`document-builder-send` keeps one row a party. A second send moves `sent_at` to now and adds one to `times_sent`. The client read `times_sent` into `SendRecord.timesSent`, and `sendChips` (`src/lib/documentBuilder/send.ts`) drew only the day and the name. On the day of the first send the day does not move, so the row read the same before and after the press.

Reproduced on made-up rows before the change: the chips of a send with `timesSent` 1 and with `timesSent` 2 on the same day were equal.

## What changed

- `sentWords` in `send.ts` writes the row's first chip. A send that went once reads *Sent Nov 23 to Dana Whitlock*, as before. A send that went more than once reads *Sent 2 times, last Nov 23 to Dana Whitlock*. The day is the last send's, which is the only day the row keeps.
- **Tell them it changed** counts as a send too, since the function adds one for it the same way.
- The list reads its rows again after each press, as it did, so the chip changes as soon as the send lands.
- Not changed: the days of the earlier sends are not kept on the row and are not shown. Each send's email is still under Sent copies on Documents.
- Help: *use the document builder* and *set the insurance a job's subs must carry* show the chip.

## Tests

- `send.test.ts`: once reads as before; twice on the same day and three times on a later day say the count and the last day; the chips carry the words; the words pass the plain-words rules.
- `BuilderGcSendCard.render.test.tsx`: a row that reads *Sent Nov 23 to Dana Whitlock* reads *Sent 2 times, last Nov 23 to Dana Whitlock* after **Send it again** lands and the rows are read again.
- Not seen: a second send on the live site. The function's write was read in its source (`times_sent: live.times_sent + 1`, for a sheet and for a builder) and no send was made.
