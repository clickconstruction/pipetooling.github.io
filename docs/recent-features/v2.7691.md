# v2.7691 — Lien papers: a sent paper shows what went out, with every file and receipt one press away (2026-11-17)

The second of three changes from the owner's yes to the mail proof mock-ups of 2026-11-17 (the first is v2.7688). His question was whether a copy of the mail is easy to view once it is uploaded. It was not: the scan showed as one link named *Saved copy · Drive* in the job's Lien window and one column header of the notice pane, a second mailed file had no link anywhere, a receipt showed in the Lien window alone, and the stop's window hid the link whenever it could redraw the page. Client only: no migration, no edge function.

## What a person sees

- **What went out**, a block on a recorded paper: the files that went in the envelope, each a link by its own name, then each envelope with how it went, its number and its receipt.
- A chip counts the proof: *Mail proof: 2 of 3 on file*, or *Mail proof complete*. The files count as one piece and each posted copy's receipt as one. A copy sent by email, handed over or carried by a mail provider owes none.
- A blue **Next:** line names the one thing missing: *Add what was mailed.*, *Add the original contractor's receipt.*, or on a filed affidavit not yet served, *Mail the copies. Then add each receipt.*
- Each posted copy carries the receipt press of v2.7688, so a receipt is added, replaced or taken off after the mailing is recorded. A notice has **Add another** for one more mailed file.
- On a computer the labels sit in a column. On a phone each part is a card and every press is a thumb tall.

## Where it shows

- **The desk's Sent row** (By paper, Lien notices, Sent): under the facts, through the footer's new `proof` slot.
- **The Lien window, *Filings on this job***: under each row. It replaces the row's saved copy link and its *receipt ›* links. The row keeps *change the saved copy* and the door to a served affidavit's mail numbers.
- **The stop's window**: read-only, in the stop's rail, whether or not the page is redrawn beside it.

## Where it lives

- `src/lib/jobs/lienMailProof.ts` (new, pure): `lienMailProof` reads one filing. The files are the notice's own `job_lien_desk_items.mailed_copies`, which the item keeps after its mailing is recorded and which is reached by `sent_filing_id`, then the filing's saved copy when it is not one of them, so a link the office typed still shows.
- `src/lib/jobs/lienMailProofIo.ts` (new): `readJobMailedCopies` for the Lien window, which holds no desk items, and `addRecordedMailedCopy`, which adds a file to the notice's list and makes it the saved copy on a paper that has none.
- `LienMailProofBlock.tsx` (new) draws it. `LienFilingMailProof.tsx` (new) adds the writes and shows what was just written until the host's read comes back.
- `LienDeskSentFooter.tsx` takes `proof`; `LienDesk.tsx` hands it. `LienFilingTabs.tsx` reads the job's mailed copies and draws the block under each row. `LienStopPaperWindow.tsx` draws `record.proof`, which the three `stopPaperFor` builders fill.

## Not changed

No file is taken off a recorded paper from the block, and the affidavit's stamped scan is still changed from its own press. The job's Documents tab and counsel's packet still read the one saved copy link.
