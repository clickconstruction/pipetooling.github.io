# v2.2452 — Prospects: Converted status — won companies leave the calling queue (2026-08-28)

First slice of the Prospects-refresh arc (approved mockup: before/after artifact, 2026-08-28). Root problem: conversion never touched the prospect row, so companies already converted to customers stayed in the Follow Up queue collecting "Due N days" badges (268-deep queue with converted rows still cycling).

- **New `prospect_fit_status` value `'converted'`** — plain text column, no constraint, so **no migration**. Attribution rides an existing table: every conversion inserts a `prospect_comments` row with `interaction_type: 'converted'` (`created_by`/`created_at` = who/when), which the future Activity week report can count.
- **[`Prospects.tsx`](../../src/pages/Prospects.tsx)** changes:
  - `handleConvertSubmit` (Convert tab): after the customer + contacts + bids inserts succeed, marks the source prospect converted + inserts the tagged comment ("Converted to customer <name>"), patches both caches. A failure to mark logs and never blocks the `/customers/:id` navigation (the customer already exists).
  - New `handleConverted` outcome handler + **Converted ✓** button in the Follow Up action row (beside Can't reach; purple `#ede9fe`/`#6d28d9` — saturated action colors stay literal). Mirrors `handleCantReach`: status update, `saveTimerEvent('converted')` (union type widened), lock release, tagged comment, cache patches, advance-to-next.
  - `loadFollowUpProspects` client filter now also excludes `'converted'`.
  - Prospect List: third sentinel section **Converted** (`CONVERTED_KEY = -3`, default closed, same Edit / Send back / Not a fit / Delete actions); the five scattered `(warmth === CANT_REACH_KEY || warmth === NO_LONGER_FIT_KEY)` checks collapsed into `isSentinelKey(k) => k < 0`.
  - `formatInteractionType` / `formatTimerButtonName` learn `'converted'`.
- Convert's prospect dropdown still lists converted prospects — the type-ahead picker slice (next in the arc) excludes them.
- No help-guide update: Follow Up has no guide yet (known gap since v2.2301); the workstation-rework slice of this arc will add it.
