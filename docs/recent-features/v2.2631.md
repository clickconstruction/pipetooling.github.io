# v2.2631 — RFQ Phase 2: the quote link lane (2026-09-01)

Phase 2 of `docs/SUPPLY_HOUSE_RFQ_PLAN.md` — vendors type prices into a
public page instead of texting them back.

- **Prepare screen** (`PrepareFixtureCopyModal`, new `quoteLink` prop):
  a footer strip — pick the supply house (required; the RFQ is addressed),
  optional needed-by — and **Copy with quote link** mints a `bid_rfqs` row
  (scope = the current selection snapshot `{lines:[{fixture,count,unit}]}`,
  `token` = dash-less uuid, status `sent`) and appends
  `Price it here: https://clicktooling.com/q/<token>` to the same paste.
  `onRfqMinted` bumps the caller's chip nonce.
- **Edge functions** (deployed; `docs/EDGE_FUNCTIONS.md` + config.toml
  `verify_jwt = false`, Bid Room pattern): `get-rfq-quote-page` (scope
  lines + bid label `bid_number · project_name` — NOT `bids.name`, which
  doesn't exist; closed on rfq `closed` or bid outcome `lost`) and
  `submit-rfq-quote` (scope-validated lines → `bid_quotes` source `link`
  + lines, RFQ → `quoted`, price-memory upsert deduped by fixture_key).
- **Public route `/q/:token`** (`SupplyHouseQuotePage`, registered beside
  `/bid-room`): mobile-first, light-pinned; per-line $ + can't-supply +
  note, quote-level rep/valid-until/freight; **localStorage draft per
  token** (survives reload, cleared on submit); partial quotes fine;
  closed and 404 states; sticky Send with answered-count.
- **Signals** (`BidsPricingTab`): amber "RFQ sent" chip while a link is
  out with no quotes; the Quotes chip turns green once an RFQ is quoted.
- Also: PlugInQuotesModal's memory upsert now dedupes by fixture_key
  (two lines on one fixture would have errored the batch).
- Live-tested end to end: mint on BP339 (whose lost outcome proved the
  closed page), full vendor lane on twin bid B429 — draft persisted
  through a reload, submit wrote quote/lines/memory/status, junk-fixture
  submit rejected, compare + green chip verified.
