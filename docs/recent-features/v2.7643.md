# v2.7643 — Signed contracts: the app can now file one in its job's Drive folder (2026-11-17)

Punch list #377, PR 2 of six: the ground. The migration, and the function that files a paper. No cron and no screen yet, so nothing files by itself and nothing on a page changes.

## What changed

- **Migration `20261117213000_job_contracts_drive_file.sql`.** Seven nullable columns on `job_contracts`: the Drive file that is the paper's copy, when it was filed, whether the app filed it or adopted the office's own, why it is not in Drive (a kind, and the words a person reads), when it was last tried, and when a voided copy was renamed. Three checks and two partial indexes. No new table, so no fence calls. `signed_document_url` is not touched.
- **A new edge function, `job-contract-drive`.** `{ contract_id }` files one paper now. `{ sweep: { limit? } }` runs the queue with the cron's secret or as the office. The four office roles that read `job_contracts` may call it, never a training account or a twin. See `docs/EDGE_FUNCTIONS.md`.
- **One paper's path, `_shared/jobContractDriveFiler.ts`.** It talks to a Drive and a store it is handed, so its tests run the whole path with neither. The function hands it the real ones.
- **Where it lands.** The job's own folder, made through the tree's rule when the job has none, then **Team only › Contracts**, found or made on first use. The name comes from PR 1's rules.
- **Filed once.** The file carries the contract's id as the app's own mark (`appProperties.pt_job_contract`). A run that uploaded the file and died before it wrote the row finds the file by that mark.
- **Adopted, not copied.** A record with no stored file whose typed link names a file inside the jobs Shared Drive is recorded as that file. Nothing in Drive changes.
- **Never into an open folder.** Before an upload the function reads who can open the Contracts folder, its own sharing and what it inherits. If anyone with the link can, the paper is held.
- **Handed to the index in the same call**, through the pass every indexer runs. If that fails the filing still stands, and the index sweep picks the file up.
- **A voided paper's filed copy** is renamed to start with `VOIDED · ` and kept. A copy Drive no longer holds is marked done. An adopted file is never renamed.
- **Whatever stops it is written on the row**, in words, and tried again an hour on. Drive's own refusal becomes a hold with Drive's words, so nothing throws past the filing.

## Two changes from the card

- **Every hold is retried hourly.** The card said a hold that could clear by itself would be retried every run. That would have Drive read a held job's folder every ten minutes for as long as it stayed held. An hour is enough, and **Try again** on the Contract window will not wait.
- **A file past 25 MB is held as too big** instead of being sent in pieces. The door is to put it in the job's folder in Drive and paste its link, which the app then adopts.
