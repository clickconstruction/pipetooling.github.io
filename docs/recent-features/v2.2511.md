# v2.2511 — Notes ledger loop: pins + drawer in CT, answers back to the twin (2026-08-30)

The estimator-twin takeoffs were burying CountTooling sheets under paragraph-sized
plan-space notes (fontSize 14pt in PDF points ≈ a 35-plan-foot billboard each). This
release replaces that with a ledgered loop across both apps:

**CountTooling** (branches `feat/notes-ledger` UI + `feat/notes-rfi-loop` functions):
- `features/notes-ledger.js`: notes render as numbered canvas pins (red = `RFI:`,
  gray = note, hollow = resolved) via canvas-draw's live-only `env.notePin` seam —
  exports/prints keep full text. Display mode per device (`auto` pins RFIs,
  `detail`-bearing, and ≥100-char notes / `text` / `pins`).
- Header button (badge = open RFI count) opens the Notes drawer: all notes grouped
  by page, filters all/RFI/open, click-to-jump (page switch + centered pan + hover
  chip), resolved checkbox, inline RFI answer editor (answer ⇒ resolved). Both are
  undo-snapshotted project data. Playwright spec `notes-ledger.spec.js` (5 tests).
- `import-takeoff` accepts an optional per-note `detail` (≤4000 chars); notes
  contract documented in CT `TAKEOFF_IMPORT.md`. `manage-user` gains `twin_rfis`
  (email + project_id → full note ledger with kind/resolved/answer). Both deployed.

**PipeTooling**:
- `twin-mcp` `get_work_state.ct_takeoff` now includes `notes_ledger` — the newest CT
  project's notes with `open_rfis` / `answered_rfis` counts, fetched over the CT
  bridge via `twin_rfis`. Deployed.
- `docs/twins/COUNTTOOLING_BID_GUIDE.md` notes contract: on-sheet text ≤ ~100 chars,
  provenance in `detail`, read answers before re-asking. Briefs regenerated.

E2E-verified live: import with `detail` → pins + drawer render in CT (screenshots) →
`twin_rfis` → `get_work_state.notes_ledger` returns the RFI with its detail and
`open_rfis: 1`. Scratch test project deleted after.
