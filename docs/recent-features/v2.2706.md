# v2.2706 — Person Desk PR 2: Pay & schedule, End employment, Start employment (2026-09-03)

Second Person Desk PR (train: v2.2701 spine + drawer). The eight-stop onboarding and offboarding tours become one screen each. No migration; no new permissions; one new write (an append-only HR-file line, dev-only).

## Client only

- **Pay & schedule section** [`components/personDesk/sections/PersonDeskPaySection.tsx`](../../src/components/personDesk/sections/PersonDeskPaySection.tsx) (pay roles; hidden otherwise): wage + office rate inline edit; **Salaried** checkbox — turning it on runs `syncSalaryClockSessionsForUserDay(today)`, turning it off shows the Employment tab's red confirm (history safe, hours × wage, today's auto-sessions removed, template + overrides cleared) then calls `pay_staff_clear_salary_schedule_by_person_name`, exactly the side effects `usePayConfig` performs; **also record hours** when salaried; employment start → end on the roster row (gap message when none); upcoming **time off** (list, add with paid/unpaid for salaried, remove; today-in-range re-syncs the salary day); **Workday schedule…** opens `SalaryWorkScheduleSettings` in a modal; **Money** shows the newest pay report (paid / unpaid chip) and open offsets (`pay_stub_id` null) with **Ledger** (dev), **Payroll**, and **Add offset** (`PersonOffsetFormModal` seeded with the pay name). Writes go through the same name-keyed `people_pay_config` upsert Payroll uses.
- **Lifecycle kernel** [`lib/people/lifecycleChecklist.ts`](../../src/lib/people/lifecycleChecklist.ts) (+8 tests): `buildEndEmploymentChecklist(facts)` → items for on-the-clock, pending sessions, final pay report (covered when the newest `pay_stubs.period_end ≥` the end date), sub balance (junction-first sheets through `subLaborJobBalance`), portal on, each vehicle held, each housing occupancy, each team-lead link, open work orders, missing compliance docs; `buildStartEmploymentChecklist(facts)` → start date, pay, team lead, packet, vehicle (optional), housing (optional). Each item carries a state (`open` / `done` / `skipped` / `left_open`), its one `LifecycleAction`, and whether *Leave open* is allowed (never for a live portal, a running clock, pending sessions, or a leader link). `applyChecklistResolutions`, `checklistSummary` (`canFinish` = zero open), `endEmploymentHrLine`.
- **Facts loader** [`lib/people/personDeskFacts.ts`](../../src/lib/people/personDeskFacts.ts): `loadPayConfigFacts`, `loadEndEmploymentFacts`, `loadStartEmploymentFacts` — the tabs' own queries under caller RLS; an unreadable table degrades to "unknown", never to a false all-clear.
- **Flow modal** [`components/personDesk/PersonDeskLifecycleModal.tsx`](../../src/components/personDesk/PersonDeskLifecycleModal.tsx) (z 1100 over the drawer): rows with the state dot, detail, action button (Force clock out; Open approvals → the pinned queue at z 1120; Turn off portal → `revoke_sub_portal_link`; To motor pool → `handOffWrites` with `toUserId` null; End occupancy; Remove leader; Save date / Save wage / Assign for Start), **Leave open…** with a required reason, **Undo**. Footer: end date, **Archive account after** (only when `canArchiveAccount`), **Note to HR file** (dev + roster row). Finish (End): confirm → `people.end_date` → optional `person_file_entries` insert (`source: 'milestone'`, the kernel's line) → optional `archive-user` edge function. Finish (Start): `people.start_date`. The button reads "End employment · N open" until every row is green, grey, or left open on purpose.
- **Header** gains a ⋯ menu (pay roles) with **Start employment…** / **End employment…**; the drawer owns the `flow` state and mounts the modal.
- Verified live as dev: Isiah's Pay section (no wage on file → the Edit path; not salaried; dates present; no time off; no pay report), End employment listing his running session, 23 pending sessions and no leader, Start employment listing the open items. No writes were made to prod during verification.
