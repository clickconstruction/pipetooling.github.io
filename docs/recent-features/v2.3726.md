# v2.3726 — Day book PR 5: the schedule keeps a ledger (2026-09-22)

PR 5 of [`to-dos/day-book`](../../to-dos/day-book/README.md) (punch list #20). One migration (a table, three triggers, the RPC), client.

## What was missing

`job_schedule_blocks` carries only `created_by`. A block moved to another day, handed to another tech or removed left no trace of who did it, so the line the owner asked for first — *"updated the schedule for 3 or 6 team members"* — could not be read from anything.

## The change

- **[`20260922120000_schedule_block_events.sql`](../migrations/20260922120000_schedule_block_events.md)** — `schedule_block_events` (`block_id`, `job_id`, `bid_id`, `assignee_user_id`, `work_date`, `change` ∈ added · moved · reassigned · removed, `old` / `new` window + assignee, `actor_user_id`, `occurred_at`); RLS select for dev, payroll access or your own rows, no client insert; index on `(actor_user_id, occurred_at)`. `job_schedule_blocks_to_ledger()` — SECURITY DEFINER, on insert, on update of `work_date` / `time_start` / `time_end` / `assignee_user_id` (an assignee change is *reassigned*, a window change *moved*, anything else no row), on delete. `get_day_book_payload` re-created on PR 7's body with the ledger in its union and unattributed rows on the day header. Ends with both read-only-block calls (new table).
- **Kernel** — the `schedule` kind; the Schedule chip names it; one line per person-day: *Updated the schedule · J102 J258 · 2 people · 3 blocks (1 removed) · Thu–Fri* — people = distinct assignees, blocks = distinct `block_id` (a move and a reassign of one block is one block), the span = the weekdays the blocks fall on; `summary.scheduleBlocks`.
- **The tab** — the Schedule chip is live; a *Schedule · N blocks changed* tile; the Month grid gains a Schedule row (its coverage sentence reads *updated on N of M working days*).
- Docs: `PROJECT_DOCUMENTATION.md` (the table), `SCHEDULE_DISPATCH_ARCHITECTURE.md` (the ledger section), `ACCESS_CONTROL.md` (the policy), the help guide.
