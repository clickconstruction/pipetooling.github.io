Punch list #184, the last piece (`to-dos/consistency-sweeps/README.md`): two gaps the earlier sweeps named and left, and the to-do closed as built. Stacked on #6325 (v2.5962 · 5964 · 5965 · 5966).

## A lost signal on an edge function call (sweep D)

- `supabase.functions.invoke` wraps the browser's fetch rejection in a `FunctionsFetchError` (*Failed to send a request to the Edge Function*) and keeps the rejection as `context`. `isFetchLayerTypeError` (`src/lib/networkErrorMessage.ts`) knew only the bare `TypeError`, so `errorKindOf` classed the wrapper `unknown` and every edge call on a dead signal showed the wrapper's words with no Retry ([v2.5962](v2.5962.md) → *Is this the best we can do?*). It now counts the wrapper when its `context` is a fetch-layer `TypeError`, and the four chokepoints read it from there: `errorKindOf` gives `network`, `formatErrorMessage` and `formatPostgrestOrUnknownError` give the offline copy, `isRetryableError` gives true. Decided by class: the wrapper's name alone is not enough, and one around an `AbortError` (a timeout, a closed window) stays `unknown`, since the request may have landed.
- 159 files call `functions.invoke`. Each that words its failure with the formatter now reads the offline copy on a dead signal. The three that check the wrapper by name and keep their own fallback (`lib/models/modelKeysIo.ts`, `lib/quo/connectionIo.ts`, `pages/DevLogin.tsx`) are unchanged.
- The Dashboard's billing pipeline, stage 1, **Field: Waiting for Approval**: the Stripe invoice under a row (`dashboard/DashboardFieldCollectPaymentQueue.tsx`, `FieldQueueLineItemsSection`, now exported for its test). v2.5962 left it because the class was missing. Its failure is now `{ kind, message }` from `recoveryFailureFromError`, drawn by `OfflineRetryPanel` (`surface: 'field-collect-invoice'`, idempotent, so it reads again by itself when the signal returns), with *Saved total* on its own line under it. A refusal the function words itself (`{ error }` in the body) is `server` and shows as it is, with no Retry.

## The bid picker's second press (sweep C, from the live check)

Read live against the to-do's mock-up on the v2.5935 build: Bids → Pricing with *Only my bids* ticked, a search for *Ridgway* read *No bids match ‘Ridgway’. Clear the search* and nothing else. The mock-up's After also offers *or widen it: Show every bid*, because *Only my bids* narrows the search too and the match may be someone else's bid. `EmptyStateWords` gains `orNext`, a second press `EmptyState` draws after *or*, and `bidPickerEmptyWords` (`src/lib/bids/bidPickerEmptyWords.ts`) adds Show every bid to the search case while only my bids is on: *No bids match ‘Ridgway’. Clear the search or Show every bid*. One kernel, so the nine Bids tabs that feed `BidPickerStandardList` change at once.

The same read held everywhere else it could: Estimates' search reads *No estimates match ‘…’. Clear the search*, and the press brings the list back. The Checklist review inbox runs oldest first with *6 days waiting* and *5 days waiting* red, *4 days waiting* amber and the rest gray, `CHECKLIST_REVIEW_AGE` exactly. The empty Estimator inbox reads *Nothing waiting on an estimator.* The signing code's confirm passes *Remove the code* and *Keep it*; the owner has no code set, so it was read in the code, not pressed. Left as it is on purpose: the mock-up's headers add *· oldest 12 days* to the two inboxes' counts. The Dispatch inbox, the precedent both follow, has none, and the first row's chip already shows the oldest wait, so one inbox gaining it would break the match the sweep is for.
