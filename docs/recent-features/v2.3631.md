# v2.3631 — Contracts: email the agreement as a PDF to sign by hand (2026-09-19)

PR 3 of [`to-dos/contract-paper-lane/README.md`](../../to-dos/contract-paper-lane/README.md) — the middle way, and the first PR of the train that sends anything to a customer. One edge function (+ one shared module); no migration (`sent_channel` shipped in v2.3629).

## The send — `share-job-contract`, mode `send_to_sign`

It lives on `share-job-contract` rather than `send-job-contract` (the to-do left it to the builder) because that function already holds pdf-lib, the issuer, the unsigned-PDF assembly (`draft_pdf`, v2.3527) and the attachment send; the new mode runs through the same block, so the attached page is byte-for-byte what Download PDF gives. It needs a `contract_id`, reads the row through the caller's RLS, and refuses a voided or signed row, empty terms, or no valid recipient — the same gates as the link send.

**Order matters.** `send-job-contract` stamps the row and then emails, reporting `emailed: false` when the email fails. For an attachment to a customer that is the wrong way round: a row must never say *sent* for a page that did not go. So the email goes first (a failure is a 502 and nothing is written), then the row is stamped `sent` / `sent_channel = 'pdf_email'`, and a `sent` event is logged with `channel: 'pdf_email'` (the Day book counts it). A stamp that fails after the email returns `{ ok, emailed: true, warning }`.

**The link is the second door.** The send mints the durable token exactly as a link send does. The email leads with the PDF and how to send it back, and offers *Rather sign on a screen?* underneath; and `remind-job-contracts` — which skips token-less rows — keeps working, which is the to-do's "reminders as today". Wording: `buildJobContractPaperEmail` in `_shared/jobContractEmail.ts` (no big button; paper is the ask), re-exported through `src/lib/jobContractEmail.ts`.

## The screens

- **Sweep pane**: **Email the PDF to sign** beside Download PDF, enabled on Ready rows. A confirm names the address first. It goes through `quickSendJobContract` with `channel: 'pdf_email'` (same draft reuse and pane flush as Send), the row leaves the list, and the toast says to file the signed copy when it comes back.
- **Contract window**: a `pdf_email` row keeps the link strip (there is a link) but reads *📎 PDF emailed to sign by hand …* and leads with **File the signed copy**.
- **Chip**: `PDF emailed · awaiting signature` (with `×n` on a resend).
- **Filing**: `isAwaitingPaperCopy` — handed **or** PDF-emailed — is now the rule `fileSignedJobContract` and both filing doors use to convert the sent row in place; the token is cleared with the conversion. A plain link send still never converts.

## Coverage

The email builder (subject, the ask before the link, no button, sign-off), `isAwaitingPaperCopy`, the chip, and a sweep render test (nothing is sent before the confirm; after it the send carries `channel: 'pdf_email'`). The function has no harness and Deno is not installed locally; it was read against `draft_pdf`'s variables and is boot-probed after deploy. **Not run live** — it emails a customer; the to-do's recipe wants a throwaway job whose customer email is ours.
