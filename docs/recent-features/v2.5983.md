# v2.5983 — The Monday sheet names the same jobs on the page and in the email (2026-10-27)

Found by the weekly send's live check (v2.5883): the dry run's sheet matched the page's line for line except one move, *Price jobs … and 2 more*, which named the same five unpriced jobs but a different first three. The jobs read in `loadEarnedJobs` (`src/lib/bridge/loadBridgeData.ts`) has no ORDER BY, so Postgres returns the rows in whatever order its plan gives. A dev's read through RLS and `bridge-weekly-sheet`'s read as the service role came back in different orders, and the earned-revenue kernel keeps the order it is given.

- **Job-number order** (`byJobLabel`): the loader sorts its jobs by their label, which leads with the job's number, compared as a number (`localeCompare` with `numeric: true`, so 999 comes before 1017), then by id. Every reader of `loadEarnedJobs` now sees one order: the Bridge data, Vectors by the day and the weekly send. The unpriced jobs and the half-done jobs follow it.
- **Test**: `loadEarnedJobs.test.ts` feeds the same rows in two orders and gets one; without the sort it fails.
- **The copy of the kernels**: `loadBridgeData.ts` is in it, so it is regenerated. After the merge, `bridge-weekly-sheet` and the functions that import the copy's index (`customer-portal`, `drive-link`, `gc-trade-portal`, `photo-save`) are redeployed, as `check:edge-drift` names them.
