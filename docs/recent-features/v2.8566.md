## What changed

- `src/lib/jobs/arCaseReopen.ts`, the rule, pure. `arCaseReopenDrawn(role)` is true for a dev alone. `arCaseJobs(row)` reads every job a case names: the jobs its payments are on, the last job it was on, a payment typed by hand, Stripe's bill. `arCaseReopenProblem(row)` refuses, in a sentence, an open case, a case that names no job, a case that names a job that is not a ZZ test job, and a case closed for any reason but *settled another way* or *not coming*. `arClosedTestCases(all)` is the list: the closed cases on test jobs, newest closed first, and a count of the rest.
- `src/lib/jobs/arCaseReopenIo.ts`. `reopenArTestCase(id)` reads `list_ar_return_cases` again with the closed ones, runs the rule on the case as it stands now, then calls the function of the case's own table, once. The function's own refusal is passed on in its words.
- `src/components/jobs/ar/ArClosedTestCases.tsx`, drawn at the top of the list in `BankPaymentsModal.tsx` from the cases the page already reads (`useArReturnCases` hands back `allCases`). One folded line, *Closed test cases · N*, with **Show**. Each case reads who paid, the amount, its job, how and when it was closed, and **Reopen…**. The confirm's button reads **Reopen the case**. Then the page reads again and the case is under **Came back**.
- The guide *match bank deposits to bills* and the glossary say so.

## Why the rule holds the reasons itself

`reopen_ar_stripe_case` and `reopen_ar_unbanked_check_case` reopen only a case closed as *settled another way* or *not coming*. `reopen_ar_return_case` reopens any closed case and clears its replacement, so a case closed because a new check replaced it would come open with its replacement forgotten. The rule refuses every other reason before the call, for all three.

## Who sees it, and what widening would take

A dev, on a case whose every job is a ZZ test job. The list reads the role the window is handed, which is the signed-in person's, so View as a sample account draws nothing.

The `fixing` thread asked whether this should be for the office on any case, as the functions already allow. That is not answered, so it is built narrow. Widening it needs no database change. It would be the two gates taken off, in `arCaseReopenDrawn` and the test-job lines of `arCaseReopenProblem` and `arClosedTestCases`, a list the office can read in full, and the guide's line reworded. The rule on reasons stays either way.
