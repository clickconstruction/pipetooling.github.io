# v2.6438 — The reply-box render tests stub their papers read (2026-11-03)

Test-only; no app code, migration or edge function changed. The sibling of v2.6436 (PR #6917), which guards the hook: that PR keeps a read that lands after the box is gone from reaching React, and this one keeps the read from going out at all.

## What was happening

Every `ReplyBox*.render.test.tsx` but `ReplyBox.papers.render.test.tsx` rendered the box without a `papersIo`, so `usePapers` (v2.5641) read the customer's bills and estimates through `supabasePapersIo()` and the real client: CI's dummy `https://example.supabase.co` on a build, and prod's URL with the anon key from `.env.local` on a Mac. Neither answered anything (no session, so the read's own catch gave no papers), but the request went out from fourteen files, and its answer was what landed after PR #6892's teardown.

## The change

Each of the fourteen files holds one `noPapers: PapersIo = { load: () => Promise.resolve([]) }` and passes it at every `<ReplyBox` (fifteen render sites; `ReplyBox.textsOn.render.test.tsx` has two). A box with no papers draws as it did when the real read answered nothing, so no assertion moved. `JobCustomerBox.render.test.tsx`, which renders the box through its parent, already mocks the client module and is untouched.

## Verified

The reply folder (18 files, 120 tests), `npm run typecheck`, `npm run lint`, the release-note drift test.

## Deploy

Nothing: tests only.
