# v2.6556 — A machine’s check photos file into the machine’s own Drive folder, under a Fleet folder the office sets (2026-11-06)

Punch list #270 PR 2. The owner's rule from the spike (2026-11-05): a machine's photos go "to a folder for that vehicle or piece of equipment", the way job photos go to the job's. The `photo-save` sweep already files five sources into a job's folder; a machine's photos are a sixth, with one difference: the folder is the machine's. Edge function and settings only; the phone that takes the photos ships in a later PR.

## What changed

- `supabase/functions/_shared/whereFilesGo.ts`, `driveSettings.ts`: a seventh Drive setting, `drive_fleet_root_folder_id` (`DRIVE_FLEET_FOLDER_ID_KEY`, `DriveSettings.fleetFolderId`, `NO_FLEET_FOLDER_WORDS`), read with the others; `src/lib/appSettingsKeys.ts` and the gcKernels mirror carry the key for the page that will set it.
- `supabase/functions/_shared/machineWords.ts`: `machineFolderName`, pure: *E-12 · Kubota KX040*, or *Rental · Sunbelt 48812-3 · Bobcat E35* for a rented one. `src/lib/machines/machineFolder.test.ts` holds it.
- `supabase/functions/_shared/driveMachineFolder.ts`: `machineFolderOrWhy` reads the machine, answers its own folder's id from `vehicles.google_drive_link`, else finds or makes one under the Fleet folder and writes the link where it was empty, or answers the reason while no Fleet folder is set.
- `supabase/functions/photo-save/index.ts`: `sweepMachinePhotos`, the sixth pass after the job photos, over `machine_check_photos` rows with a `storage_path` and no `filed_at`: the bucket copy into the machine's folder under the row's `file_name` with *(2)* when taken, the row keeping `drive_file_id` and `filed_at`, the bucket copy deleted, a failure's reason on the row; `machines` in the answer.
- `docs/EDGE_FUNCTIONS.md`: the sixth-source bullet and the status.

## Deploy
