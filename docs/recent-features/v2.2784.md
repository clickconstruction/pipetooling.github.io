# v2.2784 — Takeoffs hardening: what must not die with Old (2026-09-04)

Owner ask after PR 7: "long term we are going to get away from the old Takeoffs — make it durable so when it is time to remove the old nothing breaks." Audit + fixes; the audit itself is recorded in `docs/TAKEOFFS_REFRESH_PLAN.md` → "Retirement readiness".

## Client only — no migration, no edge functions

- **Materials-model toggle is shared** ([`BidsTakeoffTab.tsx`](../../src/components/bids/BidsTakeoffTab.tsx)): the By Stage / Combined switch (with its `openMaterialsModelSwitch` confirm) moved out of the Old branch to just above the view switch — it is the only door that flips a bid's model and would have vanished with Old. Old renders byte-for-byte as before (the toggle sits where it always did); New 1 / New 2 now show it above the strip.
- **Row jumps reach the new views**: a Pricing → Takeoffs jump (`rowJump`) while New 1 / New 2 is up sets a `focusRequest` (row id + nonce); [`TakeoffFocusView`](../../src/components/bids/TakeoffFocusView.tsx) focuses that fixture, [`TakeoffCostRailView`](../../src/components/bids/TakeoffCostRailView.tsx) drops its filter, and the existing `usePendingRowFlash` poll then finds the row and flashes it. Before this, a jump into New 1 could time out with the "couldn't find that row" toast.
- **Dead code**: `TakeoffNewViewPlaceholder` removed (both views are built).
- **Render smokes** ([`BidsTakeoffTab.render.test.tsx`](../../src/components/bids/BidsTakeoffTab.render.test.tsx)): New 1 mounts (focus view + coverage strip, no Old button), New 2 mounts (rail's "What Pricing sees"), and the By Stage notice renders on an `exact` bid — pinned so the retirement PR cannot take a new view down unnoticed.
- **Plan doc**: "Retirement readiness" — what is already shared, what still dies with Old (the By Stage editor, Old's own book row, its empty state), an Old-feature → New 1 / New 2 parity table, and the retirement PR recipe.
