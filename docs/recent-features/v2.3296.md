# v2.3296 — Test reports PR 1: the kernel and the PDF, no table yet (2026-09-11)

Client + one shared edge kernel; no migration, no edge function deployed. First of the train in [`to-dos/test-reports/README.md`](../../to-dos/test-reports/README.md) (owner picks 2026-09-11: dial A office sends · Malachi certifies · pay link in the same email · show them in the portal).

## Why

The plumbingtooling.com report app's real output is one email — the test report PDF attached, the job's Stripe pay link pasted in, sent by hand to the GC. Internalizing it starts with the paper: everything the external app hard-coded (four test types, the system / method / pressure defaults, the pass / fail conclusions, the certification per type, the gas conversions, the certifier's license block) becomes one dependency-free kernel the browser, the edge functions and the tests all read.

## What shipped

- **Kernel [`supabase/functions/_shared/testReport.ts`](../../supabase/functions/_shared/testReport.ts)** (app door `src/lib/jobs/testReport.ts`, +20 tests): `TestReportData` / `TestReportJobInfo` / `TestReportSettings` with `DEFAULT_TEST_REPORT_SETTINGS` seeded from the external app's literals and `parseTestReportSettings` for storage; `formatTestType` / `testReportTitle` / `testReportShortLabel` / `testReportServiceDescription` ("Preleveling Hydrostatic Test at 112 Seidel St", the Stripe memo); `splitTestReportAddress`; `gasPressureFromPsi` / `gasPressureToPsi` (PSI base ×27.68 / ×16 / ×703) and `gasFixturesTotalBtu` / `formatBtu`; `resolveTestReportText` (system-aware defaults, per-report overrides, the certification body + signature block); **`buildTestReportBlocks`** — the paper as a block model (letterhead · customer/location columns · sections · key-value rows · verdict · paragraphs · certification), empty sections simply absent as the external app did; `testReportSendBlockers` (date, system, verdict, findings, pressure-or-fixture, email, optional pay link); `inferTestReportDraft` (type from the job name — "Johnson Pretest", "Montolongo Post Test", "…Hydrostatic Test PRE" — and PASS / FAIL from the tech's wording, "no leaks" never read as a fail; null on ordinary jobs) for PR 4's trigger.
- **PDF [`src/lib/jobsDocuments/testReportPdf.ts`](../../src/lib/jobsDocuments/testReportPdf.ts)** (+4 tests on the recording jsPDF double): the block model walked with a paging cursor on Letter — company wordmark + tagline, right-aligned title with the date and job, two columns, copper section rules, the verdict word in green / red on the same baseline as its explanation, the certification's signature lines; a long FAIL paginates. `testReportPdfToBase64` for the send function.
- **Samples [`src/lib/jobs/testReportSample.ts`](../../src/lib/jobs/testReportSample.ts)** and a **Test report (sample)** row on Settings → What customers see: four buttons open the PDF built from the invented Johnson job. Nothing in the database.
- Wording note: the external app's FAIL conclusion read "The consistency in water levels … indicates leaks"; the seeded default says "The change in water levels …". Every one of these strings is a setting (PR 2 gives them a Settings card), so the owner can restore the old wording verbatim.
