# v2.8508 — Lien: the release waits for the money and takes the county's stamp (2026-11-24)

Piece 2 of punch list #435 (`to-dos/lien-payoff/README.md`), built the same day as piece 1 (v2.8504) on the owner's word. It is the other half of Payoffs: piece 1 says which step a filed lien is on, and this makes steps 2 and 3 safe and able to finish.

## What changed on the Lien window's Release of record tab

| Before | Now |
|---|---|
| It saved and printed with no payment recorded. | **Money holds the release.** A line says what the money says: green *Paid Nov 20 by cash.*, amber while a check clears, red *$1,455.50 is still open on this job's bills. Record the payment first.* While red, **Print for notarization**, **Download PDF** and **Save release record** are dead. |
| No way to release a lien settled for less. | **Release it anyway…** opens a box for the reason. A typed reason lifts the hold and is saved on the release (`fields.releasedUnpaidReason`). |
| The payment date was today. | It starts on the day of the last payment. |
| It took the job's first filed affidavit. | It is on one filed lien. A job with two asks **Which lien**, and opens on the first whose release the county has not recorded. |
| Pressing save twice made two releases. | A lien takes one release. Once saved, the tab draws no save press and prints the release as it was saved. |
| Nowhere to put what the clerk hands back, and *Released* read the day the row was saved. | **The county's stamp**: *Recorded on* and *Instrument number*, each a value changed where it sits, each Keep one write. The day is the release row's `filed_at`. The number is `fields.releaseInstrument`. |

## No migration

The link to the affidavit (`fields.releasesFilingId`), the release's own instrument number and the reason live in the `fields` a release already saves, and the county's day is the row's own `filed_at`, which nothing set before. The row's `recording_number` keeps the affidavit's number, as every older row and reader has it. The card proposed two new columns. With a release owed that day, the fields were the faster and no less exact home. A later piece may lift the link into a column with a foreign key.

## The rule

[`lienReleaseOfRecord.ts`](../../src/lib/jobs/lienReleaseOfRecord.ts), pure, 12 tests: `releaseTargets`, `pickReleaseTarget`, `releaseMoneyGate`, `releasePaymentDay`, `releaseSaveFields`, `releaseStampDayCheck` (no day still to come, none before the lien was filed), `releaseStampPatch`, `releaseRecordedSentence`. It reads `lienPayoff.ts` for which release belongs to which affidavit, so the tab and the desk's Payoffs agree.

Payoffs' third press now reads **Record the county's stamp ›**. It read *Open the release ›* in v2.8504 alone, when the tab could not yet take the stamp.

A check still clearing only warns. Whether a release waits for a check to clear is the owner's call, the card's first, not yet made.

## What it does not do yet

- The stamped copy is a Drive link on the release's line under *Filings on this job*. The scan press there is still for affidavits only.
- The job's lien timeline still reads *Released* from the moment a release is saved. Only Payoffs and this tab tell a saved release from a recorded one.
- The release is not signed in the app, and its notary block is the affidavit's sworn one. Which certificate a release takes is counsel's question on the card.
- One check over several bills is piece 3.
