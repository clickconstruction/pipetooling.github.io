# v2.5911 — An empty state names the next press: EmptyState, emptyWords, the four list props, and check:empty-words (2026-10-26)

Punch list #184, sweep C, PR 1 of the consistency sweeps (`to-dos/consistency-sweeps/README.md` → *C. Empty states*). The rule, now in `CLAUDE.md` → Working conventions and the Glossary's *Empty state*: an empty list says what fills it and offers the press, or, where empty is the good state, says so and names where to look next. A bare *No bills* or *Nothing here* fails. This PR ships the piece; the words of the ~500 legacy sentences are not rewritten here.

## The kernel: `src/lib/emptyWords.ts`

`emptyWords(input)` writes the sentence for four kinds, each in plain words (the test asserts `plainWordsFailures` is empty for every kind):

- **make** `{ noun, control }` → *No bids yet.* · `New Bid` · *adds the first.*
- **filter** `{ noun, query }` → *No bids match ‘Ridgeway’.* · `Clear the search` (curly quotes); with no search text, *No purchase orders match the filters.* · `Clear the filters`
- **waiting** `{ who }` → *Nothing waiting on dispatch.* (no press: empty is the good state)
- **data** `{ noun, page }` → *No sessions yet.* · `Clock in` · *starts the first.*

`emptyWordsWithPress(words, { onPress } | { to })` lifts the result into the shape the component takes. `EmptyNext` and `EmptyStateWords` are the types.

## The component: `src/components/EmptyState.tsx`

One `<p data-empty-state>` in the Prospects shape: centered, muted, `main`, then the press as a link-styled `<button type="button">` or a react-router `<Link>` (font-weight 600, `var(--text-link)`), then `tail`. `compact` tightens the padding for a list inside a window. `main` alone is the "fine" kind for a sub-list whose next step is the row above it.

## The check: `npm run check:empty-words`

`src/lib/emptyStateCheck.ts` (`bareEmptySentences`) parses a `.tsx` with the TypeScript compiler, loaded through `createRequire` as the codemods do, since the compiler's CommonJS bundle has no named ESM exports; it lives under `src/lib` with its unit test, and the lint, the bundler (nothing in the app imports it) and the typecheck all take it. It reads every JSX text child and every string literal that is a direct JSX child or a branch of a conditional child, matching `/^(No|Nothing|None|Nobody)\b[^.?!]{0,80}[.!]?$/`, outside an `<EmptyState>`; a single word (a Yes / No control), an `<option>` and a table cell with no `colSpan` (a cell fallback such as *No house*) are left alone. `scripts/check-empty-words.ts` is `check-pronoun-openers.ts`'s shape: the same base ref, every changed `src/**/*.tsx` that is not a test, a finding on a line the change wrote fails (exit 1, `::error` on its line) with the sentence *An empty state names the next press: draw it with <EmptyState main=… next=…> (src/components/EmptyState.tsx), or with main alone when it is a sub-list inside a window.*; findings on unchanged lines are only counted, and `-- --all` lists them. `deploy.yml` runs it right after `check:pronouns`. On this PR's diff it finds nothing on the lines written and counts the legacy sentences in the touched files.

The rest, the 33 make presses and the ~300 waiting and data sentences, go by surface in the order people meet them (the Dashboard cards, the Checklist tabs, Estimates, Documents, the Jobs tabs, the Bids tabs, People, Materials, Settings), each PR with its own list and cut when its surface is quiet.

## Is this the best we can do?

The kernel writes the words only where they are the same everywhere; every other sentence stays a person's, which is why the legacy sites are counted, not blocked, and why the check reads only the lines a PR adds. The make press from a Bids tab is a Link to the page's deep link rather than a prop threaded through nine tabs: it already exists, it opens the same window, and it costs the tabs nothing. The one thing a later PR could improve is the "fine" kind: a sub-list's `main` alone is honest today, but a day row that could open the session it is missing from would be better.
