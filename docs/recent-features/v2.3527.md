# v2.3527 — Signing it on paper, PR 1: the unsigned agreement as a PDF (2026-09-16)

Client + one edge function (`share-job-contract`, plus `sign-job-contract` redeployed because both import the shared PDF builder). No migration. PR 1 of `to-dos/contract-paper-lane/`; item 7 of the owner's ready-to-build train.

## Why

Prod says the e-signing link is the one outcome that has never worked — 0 contracts ever signed through it, 3 of 3 finished ones signed on paper — and the app could take signed paper in but could not produce the page to sign. The renderer it had (`_shared/jobContractPdf.ts`) required a signature and stamped every copy *SIGNED ELECTRONICALLY*.

## What shipped

- **The unsigned variant** — `buildJobContractPdf` takes `signature: null`: the same document above the block, then two pen rules (a long one for the signature, a short one for the date), *Sign* and *Date* under them, and one line, *Sign and date here, then return a copy to us.* No frame, no tag, no audit line — nothing on the page may read as an electronic signature. The wording is the exported `UNSIGNED_BLOCK` constant so the guide and the page agree. Two twin tests: it renders and parses; it is a different document from the signed one.
- **`share-job-contract` `mode: 'draft_pdf'`** — the unsigned agreement as bytes (`{ ok, filename, pdf_base64 }`), from a contract row in any status or from `job_id` + the pane's own draft fields. Bytes only: no storage write, no row, no link, no token (the to-do's gotcha). Rows and the job are read as the caller (RLS).
- **Download PDF** in the Contract sweep pane (beside *Open the full editor*) and in the full editor (beside *Preview as customer*), through [`src/lib/jobs/contractDraftPdf.ts`](../../src/lib/jobs/contractDraftPdf.ts). The pane renders from what it shows right now — its edited scope and amount, the chosen terms, the draft row's terms when one exists — and writes nothing; the toast says what to do with the signed copy. If the function build on the server predates this mode, the error says the download is not live yet rather than the old build's *Add at least one valid email*.
- Help guide *get a job contract signed* → *Send a contract* gains the door; `docs/EDGE_FUNCTIONS.md` documents the mode.

Not in this PR, by the plan: the hand-off stamp (PR 2, a migration), emailing the PDF (PR 3), terms as two levers (PR 4), the three-way *How this one gets signed* block (PR 5), Edit & re-send (PR 6).

## Deploy

`supabase functions deploy share-job-contract` and `supabase functions deploy sign-job-contract` (shared-module importer) — done before the client merged, since the new mode is additive and the old build answers it with a wrong error.

## Verified

- Twin tests (`jobContractPdf` 5), the client helper (4), `helpGuideContent`, release-notes drift, typecheck, lint.
- Live on prod data: Contract sweep (filter *All*) → a job with no contract row → **Download PDF** produced a 3.8 KB `%PDF-1.7` file from the deployed function (the browser's object URL was intercepted to read it), and the contract table read 6 rows before and after — nothing written. J363, the to-do's example, was no longer in the sweep's list. The pen rules and the absence of the electronic-signature tag are pinned by the twin test over the same builder the function runs.
