## The change

- **`users.is_sample`** ([`docs/migrations/20260919044528_users_is_sample.md`](../migrations/20260919044528_users_is_sample.md)): one real account per imitable role, dev-set only (the privileged-columns guard gains the rule and the trigger fires on it). No RLS change — a sample's rows are ordinary rows.
- **Hidden like a twin**: `isActiveRosterPerson` / `activeUsersQuery` drop `is_sample` rows (kernel test); the People roster's own `users` read and every recipient read in the email dispatch functions (`_shared/jobWatchers`, schedule-day, schedule-share, crew-day, weekly-money, weekly-movement, money-waiting, payment-forecast, statement-round, recurring-job-report, paid-job, send-report, billed-report, send-rfq, send-bid-pricing-package) filter `is_sample = false`.
- **Kernel** [`lib/viewAs.ts`](../../src/lib/viewAs.ts) (tests): `IMITABLE_ROLES` (every role but dev), `sampleEmailForRole` (`sample-<role>@samples.pipetooling.local`), `sampleNameForRole`, `sampleAccountsByRole`, `missingSampleRoles`, a throwaway password.
- **Settings → Active accounts → Sample accounts**: the samples sit under their own heading at the foot of the list (dev only), with *Create the missing samples* — one `create-user` call per role without a live sample (`is_sample: true`); their switches are set with the same controls as anyone's.
- **Imitate lands on the page you were on** (`loginAsUser`: `redirectTo` defaults to `location.href`; the Users tab's two doors and the person desk pass it) and **Exit returns there**: the stash carries `returnTo`; `impersonationReturnPath` (tests: same origin only, never a sign-in page, the dashboard otherwise) drives both Exit controls (Layout's header button, Settings' *Back to my account*).

Not in this PR: the gear-menu *View as…* door with the roles list and the person search, and the guide — PR 2.
