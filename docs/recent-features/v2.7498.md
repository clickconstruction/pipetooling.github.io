# v2.7498 — Developer docs: the three shared docs hold one sentence a line (2026-11-16)

A mechanical sweep, merged alone. No app code, no migration, no edge function.

## Before

`docs/GLOSSARY.md`, `docs/ACCESS_CONTROL.md` and `docs/LIEN_DESK_ARCHITECTURE.md` are amended by every PR on their surfaces, and "Amend, don't add" sends each of those PRs to the same entry. Each entry was one physical line: 66 glossary lines ran past 3,000 characters and the longest to 28,784; the access control doc had 12 such lines and the Lien desk map 9. Git merges by line, so two PRs that amended different sentences of one entry conflicted. On 2026-11-16 ten open PRs edited the glossary at once and eleven the Lien desk map, and the merge queue dropped #8358 three times, #8372 twice and #8381 once on these files alone, at about 35 minutes of checks a round.

The conflict read on `origin/main` against #8381: one glossary line of 5,045 characters on main and 4,467 on the branch, eleven sentences against ten. Main had changed three of them and the branch had added one.

## What changed

- **`scripts/lib/docSentenceLines.mjs`** (new, plain JS, no dependencies): the rule. A prose line breaks after each sentence end (`.`, `!`, `?`) and after each semicolon. A bullet's later lines sit under its words and a quote's under its `>`. It is split only, never join, so a line of one sentence is left as written, a hand-made break is kept and a second run changes nothing. Left whole: code fences, indented code, table rows (a GFM row is one line by definition), headings, raw HTML and the YAML block at the top. No break lands inside a code span, a link or an HTML tag, after an abbreviation or an initial, or before words that would open a list, a heading, a quote or a table.
- **`scripts/codemods/doc-sentence-lines.mjs`** (new): the sweep and its check. No flag rewrites the three docs, `--dry` lists, `--check` exits 1 when a line holds two sentences or runs past its cap (`CAPS`: 2,400 characters for a sentence, 4,000 for a table row, each just over the longest the sweep left), `--prove <rev>` renders each doc at `<rev>` and on disk with `marked` and exits 1 unless the two pages are the same HTML once white space outside `<pre>` is folded, and `--resolve` is for a branch cut before the sweep: in a merge or rebase stopped on these docs it splits the base and both sides, merges the three again, stages each doc that comes out clean and splits what the branch added.
- **`npm run check:doc-lines`** and its step in `ci.yml`. The step sits with the other checks, ahead of the docs-only split, so it runs on a docs-only PR too.
- **The three docs**, reflowed by the script: the glossary from about 2,500 lines to about 7,300, the access control doc from about 1,900 to about 3,900, the Lien desk map from about 500 to about 1,300. Lines past 3,000 characters: 66, 12 and 9 before; 0, 0 and 3 after, the three being table rows.
- **`CLAUDE.md`**, "Amend, don't add": in these three docs the amendment goes on its own line.
- **`src/lib/docSentenceLines.test.ts`**: where a line breaks, what is left whole, the second run, and a page that draws the same before and after.

## The proof that the pages are the same

Three renderers, each fed the doc at the commit before the sweep and after it, compared as HTML with runs of white space folded to one space outside `<pre>`:

- `marked` (the app's own renderer): the three pages are the same, about 1.1 million, 0.6 million and 0.3 million characters of HTML. This is `--prove`, and it is re-run on every rebase.
- `pandoc -f gfm`: the same.
- GitHub's Markdown API (`POST /markdown`, `mode=markdown`), one section at a time: every section the sweep touched renders the same.

A control (one break put before a `- ` inside a paragraph) is caught by `--prove` as a different page.

## What it does to conflicts, measured

Every pair among `origin/main` and the 17 open PR branches that touch these docs was merged file by file, as written and again with all three sides reflowed: 198 merges where both sides changed the doc, 15 conflicts as written, 6 once reflowed. The six that remain are of two kinds the split cannot clear: two PRs that each add a new dated note at the same spot (three, in the Lien desk map), and one PR that rewrites a sentence while another adds a sentence right beside it (three, in the glossary).

## What it costs the PRs open now

The sweep rewrites the lines every open PR on these docs amends, so each of them conflicts with it once. On 2026-11-16, 16 of the 39 open PRs touch the three docs (12 the glossary, 4 the access control doc, 11 the Lien desk map), 11 of them armed. Each was merged with the sweep in a scratch clone and `--resolve` run: 15 came out clean, pass the check, and draw the same three pages as a plain merge with main. #8389 was left one place for a hand, where it and main each add a dated note at the same spot (it merged first, and the sweep was re-run over it).

For a branch cut before the sweep: `git merge origin/main`, then `node scripts/codemods/doc-sentence-lines.mjs --resolve`, then commit, push and re-arm.

## What stays long

- Table rows: 16 in the access control doc and 15 in the Lien desk map are over 1,000 characters (the longest 3,901). A row cannot be broken. Two PRs that amend one row still conflict; the cure is to move a row's detail into a paragraph under the table, which changes the page and is the owner's call.
- Sentences: 11 in the glossary and 4 in the access control doc are still over 1,000 characters (the longest 2,232), each one sentence chained with commas. The cap stops them growing.

## Why not `merge=union`

A `.gitattributes` line `merge=union` keeps both sides of a conflict. GitHub does not apply it to pull requests (community discussion 9288, an open request), and on these docs it would be wrong anyway: run locally on #8361 against #8365 it kept the whole 4,322-character entry twice, once from each PR.

## On a rebase of the sweep itself

Check out main's three docs, re-run `node scripts/codemods/doc-sentence-lines.mjs`, then `--prove origin/main`. Never hand-resolve its diff.
