# v2.8005 — Document builder: a builder's contents are kept in the database (2026-11-19)

Punch list #404, step 2 of ten, the second half: the client. The table came in v2.7988 and is pushed. No migration and no function here.

## What changed

- The tab reads `document_builders` (`readDocumentBuilders`). A builder's row says where it stands: *Not loaded yet*, *Draft, not published*, or *Published, revision 2*, with *Changes not published* once the draft moves on, and *Read by* a name and a day or *Not read by an attorney*.
- **Load the first draft** is the press on a builder with no row. It writes the placeholder words from the client's file into the database, as a draft on revision 0. The migration wrote no words, so this is where a builder's first words come from. After it the press is **Open**.
- The Sub NDA's flow now runs on the draft the database holds, read through `readPaperDef`. Step 1 ran it on the file itself.
- A draft that does not read as a paper is never half drawn. The page says the builder cannot be shown and lists what is wrong, one line each.
- A read that fails draws the retry panel, which reads again by itself when the signal returns.

## The rules, each a kernel with its tests

| File | What it decides |
|---|---|
| `src/lib/documentBuilder/definition.ts` | What the database holds, as a `PaperDef`, or every gap it has in words. Then the rules a definition keeps: a level, no two on one id, every topic has every level and no other, each says what it means and has a breach line, a topic that can be left out says what Off means, and every line passes the plain-words rules. |
| `src/lib/documentBuilder/standing.ts` | A row as a record. Where a builder stands. That it is read only while the mark names the published revision. Whether the draft has moved on from the published copy. The chips. |
| `src/lib/documentBuilder/firstDrafts.ts` | The first draft for each builder in the registry. |
| `src/lib/documentBuilder/documentBuildersIo.ts` | The read, and the write of a first draft. |

The paper's own names (its title, the job, the company) are names and not lines, so the plain-words check leaves them alone.

## What it does not do yet

- Nobody types on a builder's words, publishes or marks a revision as read. Those are step 3 for the insurance sheet and step 7 for the Sub NDA. The chips already read them, so they need no change then.
- The types file does not know the table yet, so `documentBuildersIo.ts` casts the client once. The types PR takes the cast away.
