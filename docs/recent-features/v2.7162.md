# v2.7162 — Materials on site: a job reads by its number, not a dash (2026-11-13)

Found by the review of Materials → On site (2026-11-13), on the live desk: all three jobs that hold a box read `— · <name>`, while the printed material location report named the same jobs `JP224` and `JP1091`.

## What was wrong

The on-site screens built a job's label from `hcp_number` alone. A job made in the app has no HCP number; its number is `click_number`, and the app's rule is `effectiveJobLedgerNumber` (the HCP number when there is one, else the app's own). So the desk's rows, the job page's head, the phone's job press, the search across jobs, Print labels' *Which job?* and the manifest's head all printed a dash for the number. The report was right because the Development page builds its labels with the app's rule.

## The change

- `src/lib/materials/onSiteJobWords.ts`: `onSiteJobNumber` and `onSiteJobWords` (`224 · Phase 2 draws`), over `effectiveJobLedgerNumber`.
- `JobsMaterialsTab.tsx` (`jobLabel`), `TallyOnSiteTab.tsx` (the job press, the label and manifest windows) and `useOnSiteDeskJobs.ts` (`onSiteJobLabel`) read it.
- The four reads that feed these labels select `click_number` beside `hcp_number`: the Materials page's job list, the desk's extra jobs, the desk hook, and the list Jobs → Materials hands in.

The label keeps the surface's own shape, a bare number with no `JP` prefix, as a job with an HCP number already read here. No migration, no edge function.

## Tests

`onSiteJobWords.test.ts` (4). The on-site render tests pass unchanged.

## Not changed

The Tally's own job pill on its other two tabs (`JobTally.tsx`) reads the HCP number alone in the same way. It is outside this surface and is on the review's list.
