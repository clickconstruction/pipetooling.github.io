# v2.3253 — Discount line items PR 2: the row in ① Line Items (2026-09-10)

Client only — no migration (PR 1, v2.3252, added the columns; this PR selects and writes them, so it merges only after that migration is pushed). Design: https://claude.ai/code/artifact/7109f02d-bf06-4fff-a5f2-2f3c0bfdff0a (Mockup B).

## What shipped

**The row.** {{button:green|− Add discount}} sits beside **+ Add line item** under ① Line Items (the lone empty placeholder row is reused). A discount row keeps the grid's rhythm — a dashed **−** badge in the stage column, the name field, the amount cell, the trash — with:

- **One smart field** (`JobFormDiscountRow.tsx`): `10%` is a percent, `500` is dollars (`parseDiscountEntry`); the prefix chip shows the mode and taps to swap; the dashed **twin** beside it shows the other form (*−$3,774.50* under a percent, *1.32%* under dollars) and taps to swap too. Commits on every keystroke like the price field, so the Job Total moves as you type.
- **Reason chips** while the name is empty — Negotiated · Referral · Repeat customer · Goodwill · Price match — fill the name (*Referral thank-you*) and stamp `discount_reason`.
- **The second line** replaces the stage selector (a discount is never a stage): *10% off all 3 work lines · follows each draw · not on riders*. On a multi-line job the basis is a link that opens an inline checklist; unticking rows narrows the basis and the readout names what is left.
- **The customer's line** under it: *On the customer's bill: Negotiated discount (10%) −$1,509.80 with Rough In, −$1,509.80 with Top Out, −$754.90 with Trim Set* — the same strings PR 3 prints.
- **The cap**: a dollar amount above the work shows *Can't exceed $37,745.00 — the work it applies to. Kept at $37,745.00.* and the stored amount is held there.
- **The lock**: once any basis row is on a bill the row wears *On a bill · locked*, the inputs disable, and the line says to delete / send back that bill — or use **Add discount** on a sent invoice (the write-down).
- **Phone**: the amount group drops under the name like the ×/$ groups do.
- **Footer**: *$37,745.00 work − $3,774.50 discount* above **Job Total: $33,970.50**; the helper sentence gains *A discount is never a stage: it follows the work it applies to onto every draw.* The Stripe preview dialog lists the discount as *Negotiated discount (10%)  −$3,774.50*.

**The shell.** `setFixtures` is now a wrapper that runs `syncDiscountRows` on every write, so the Job Total, the segments, the plan and the save engine all read rows whose derived price, cap and count are already true. Hydration goes through `fixtureRowsFromDb` (`jobFormFixtureHydrate.ts`): `discount_basis_positions` → basis ids by `sequence_order`, and **a legacy negative work row — a change order's credit line applied to a job — reads as a fixed dollar discount**, so the next autosave keeps it instead of nulling the price (the bug found in the review). The estimate-import path runs the same normalization.

**The math everything else reads.** `jobSegmentsCoverage.ts` sizes every segment by its dollars NET of discount shares and never draws a discount (the strip sums to the Job Total; selection totals, positions, links and the exact-amount match all read net). `stagePlanFixturesFromForm` drops discount rows and hands the plan each work row's net amount, so *draw 1 · $13,588.20* is what **Bill it** bills. `fixtureInsertRows` writes a discount row signed, capped, count 1, `stage_kind` null, unshared, with `line_kind`, `discount_pct`, `discount_basis_positions`, `discount_reason`; the billing slice JSON carries the four fields so autosave sees them change. `JOBS_LEDGER_FIXTURES_EMBED` selects the columns; the Job tab and the Billing tab cell print a discount's signed amount instead of *× 1 @*.

**Help**: new guide *give a customer a discount*; a bullet in *split a job into stages*. Glossary: *Discount Line Item*. Architecture map §7 notes the wrapper.

**Tests**: 8 render smokes for the row (percent / dollars entry, twin swap, chips, cap, basis checklist, lock, hidden button), hydrate (6), segments net (3), plan (1), save engine (2).
