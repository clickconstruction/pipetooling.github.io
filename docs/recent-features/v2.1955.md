# v2.1955 — Partner statements: pick which charges attach (2026-08-21)

Owner request: `generate_partner_statement` attached every pending offset unconditionally — with months-old charges queued (Bryan carries five back to April), closing a week meant all of them landed at once.

**DB** (migration `20260821170000_statement_offset_selection.sql`): the generator grows `p_offset_ids uuid[] DEFAULT NULL` — NULL keeps attach-everything; an array attaches only those ids (still person-scoped, `occurred_date <= week end`, and the can't-deduct-below-zero cap is unchanged, so oversized charges keep auto-staying pending). The old 3-arg signature is **dropped, not overloaded** (PostgREST named-arg ambiguity); the selection is recorded in the `statement_generated` event patch. Body otherwise verbatim from the live 20260820180000 definition.

**Client** ([`PartnershipStatementsTab.tsx`](../../src/components/partnerships/PartnershipStatementsTab.tsx)): the close card gains a "Charges to put on this statement" checkbox list (all checked by default, "attaching X of N" counter, signed amounts via `pendingOffsetSignedAmount`); unchecked charges stay pending. Applies to both the last-week close and the older-gap-week chips. Fail-soft ordering: with everything checked the client omits `p_offset_ids`, so full-attach generation keeps working against a pre-migration server; only a partial selection requires the new signature. Type entry hand-added to `src/types/database.ts` (matches next regen).
