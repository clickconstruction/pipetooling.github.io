# v2.3711 — Day book PR 1b: a bill sent through Stripe counts for the person who sent it (2026-09-22)

PR 1b of [`to-dos/day-book`](../../to-dos/day-book/README.md) (punch list #20). One migration, two edge functions redeployed (`send-stripe-invoice`, `send-physical-invoice-email`), no client change.

## What was wrong

The Day book's census ([`census-2026-09.md`](../../to-dos/day-book/census-2026-09.md)) found 94 % of `invoice_sent` activity rows with no actor. `send-stripe-invoice` persists the send with the service-role client, so the activity trigger's `auth.uid()` is NULL and the send is nobody's outcome. The tab worked around it by reading *Marked billed* as the office's billing act and listing the Stripe sends on the day header as *and N more by the system*. A person who sent six bills through Stripe and marked none as billed had an empty Billed line.

## The change

- **[`20260922100000_invoice_sent_by.sql`](../migrations/20260922100000_invoice_sent_by.md)** — `jobs_ledger_invoices.sent_by_user_id` (nullable, FK to `users`), and the invoice activity trigger stamps `coalesce(auth.uid(), new.sent_by_user_id)` on the `invoice_sent` event. Every other branch of the trigger is unchanged.
- **`send-stripe-invoice`** — the post-send persist writes `sent_by_user_id` from the caller it already resolved off the Authorization header (`persistSendAfterStripeEmail` takes `sentByUserId`).
- **`send-physical-invoice-email`** — the first-send update writes it too. That write already runs as the user, so the event was attributed; the column makes the sender a fact on the row either way.
- `src/types/database.ts` is not touched: the column reaches the client types with the regen after the push (the convention since the `stripe_credit_note_id` push — a hand-added required column breaks every fixture that builds a whole row).

The Day book RPC needs no change: an attributed `invoice_sent` already joins the *Billed* line (deduped against *Marked billed* on the same invoice), and the system count on the day header shrinks by the same rows.

## Verified

- `npm run typecheck`; `deno check` on both functions; `releaseNotes` test.
- After the push and the two deploys: a Stripe send from the app writes `sent_by_user_id` and its `invoice_sent` event carries the actor (checked on the next real send; not staged on prod — a send emails a customer).
