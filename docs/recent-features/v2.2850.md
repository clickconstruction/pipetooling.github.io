# v2.2850 — Opening Follow Up or a portal globe no longer writes anything: the calling lock is taken on intent and expires; the portal link is created on "Create their link" (2026-09-05)

Journey-map Tier-1 #14(b) — the two customer members of the "opening is a write" family (J34-F5/N3, J21-F7; `_DRIFT-2` row #14 UNCHANGED). Will's decision 17 (2026-09-05): **write only after an explicit user commit.** No migration, no edge function — pure client change.

## Before / after

| surface | before | after |
|---|---|---|
| **Prospects → Follow Up** (`Prospects.tsx`) | the per-prospect effect upserted a `prospect_calling_locks` row **on view** (`onConflict: 'prospect_id'` — viewing stole a colleague's live lock); `locked_at` had **no reader** and there was no purge, so a closed tab hid that prospect from every caller indefinitely (live 2026-09-05: 0 rows, so nothing was stuck at the time, but the mechanism was) | the effect is **release-only**. `takeCallingLock(trigger)` runs once per prospect per tab on the first sign of intent — `dial` (📞 button), `composer` (comment box focus), `outcome` (Didn't Answer / Answered), `callback` (Set callback). It reads the existing row, runs the kernel, upserts only on `take` / `stale-take`, and on `held-by-other` shows **"<name> is calling this one"** on the card and writes nothing. The queue read filters `.gte('locked_at', now − 30 min)`, so stale rows never hide a prospect. Cleanup deletes only the row this tab wrote. Terminal outcomes (Can't reach / Not a fit / Converted) keep their own delete and take no lock (the prospect leaves the queue anyway). v2.2689's insert-then-delete retag write is untouched. |
| **Customer portal globe** (`CustomerPortalGlobeButton.tsx`) | `loadState()` fell through to `mint('all', false)` for a never-minted customer — a live capability link with no confirm and no toast | `loadState()` runs the `portalGlobeInitialState` kernel: `active` → hero as today; `off` → off panel as today; **`unminted` → a dashed "No portal link yet." panel with {{button:blue|Create their link}}**; `legacy-active` (only pre-merge scoped rows, one live) → the continuation mint, unchanged. `createLink()` is the one mint site: RPC, hero, toast **"Portal link created."**, telemetry. |
| **Sub portal globe** (`SubPortalGlobeButton.tsx`, v2.2667 clone) | same fallthrough `mint(false)` on open | same treatment — `unminted` panel + Create their link + toast; the adapter has no legacy audiences so `legacy-active` cannot occur. |

## Kernels (tested)

- [`src/lib/prospects/callingLock.ts`](../../src/lib/prospects/callingLock.ts): `CALLING_LOCK_TTL_MS = 30 min`; `callingLockDecision({ existing, now, me, ttlMs }) → 'take' | 'held-by-other' | 'stale-take'` (no row or my row → take; other's row younger than TTL → held-by-other; older, null or unparseable `locked_at` → stale-take); `isCallingLockLive`, `callingLockCutoffIso` (the `.gte()` bound); `CallingLockTrigger`. Tests: `callingLock.test.ts` (TTL edge exactly-at vs one-ms-inside, custom TTL, garbage timestamps).
- [`src/lib/portal/portalLinkState.ts`](../../src/lib/portal/portalLinkState.ts): `portalGlobeInitialState(rows, id) → 'unminted' | 'active' | 'off' | 'legacy-active'` (the fourth value is the pre-existing legacy continuation, kept so a customer who already holds a live scoped link is not told they have no link). Tests appended to `portalLinkState.test.ts`, including the sub-portal adapter shape (rows without `customer_id`).
- Render smoke `CustomerPortalGlobeButton.render.test.tsx` case 1 rewritten: open → "No portal link yet." and **zero RPCs**; click Create → exactly one `mint_customer_portal_link` call → hero/gear assertions as before. The legacy-continuation and off-state cases are unchanged and still pass.

## Telemetry (`ui_nav_clicks` via `recordNavClick`)

- `prospect_lock_taken` with target `#dial` / `#composer` / `#outcome` / `#callback`, suffixed `-stale` when the row taken over was a colleague's expired one.
- `portal_link_minted` with target `#customer-globe` / `#sub-globe`. Together with the row's `from_path` this is the `record_minted_on_open{surface}` counter #14 asked for — for these two surfaces it should now read zero on open.
