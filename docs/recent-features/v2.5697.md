# v2.5697 — Estimates: What went names only the texts that carried this estimate’s link (2026-10-20)

PR 6 of punch list #139 (`to-dos/press-always-answers/README.md`), from the live walk: opening #164 (Evan's accepted $1,200 estimate of Oct 16) showed *Texted the link to (210) 870-4770 · Tue, Oct 20 at 1:33 PM* — #166's text. v2.5683's tie was a body match (`/estimate/accept`) from ten minutes before `sent_at` with no upper bound, so an older estimate claimed any later estimate-link text to the same customer. No migration; no edge function change.

- **The exact tie** (`src/lib/estimates/acceptLinkTie.ts`, pure): a text's body carries the accept link's `t=<token>`; the estimate row keeps `public_token_hash`, the SHA-256 hex of that token as `send-estimate-to-customer` mints it. `acceptTokensIn` reads the tokens, `sha256Hex` hashes one with Web Crypto as the edge does, `textsCarryingLink` keeps the texts whose token hashes to the estimate's — none without a hash. `messages.estimate_id` was not reused on purpose: it means a customer's message that became a line on an estimate (R8), and stamping outbound texts with it would read as that.
- **The read** (`whatWentIo.ts`): the same candidates (now with `body`), then the tie; the card (`EstimateWhatWent.tsx`) takes `tokenHash` from the row. A resend re-mints the hash, so the card shows the texts carrying the estimate's live link — after Send the link again, the fresh text, not the one whose link died.
- **Tests**: `acceptLinkTie.test.ts` (the tokens read and decoded in order, the published SHA-256 vector, the tie keeping only the matching text, case-insensitive, none without a hash); the card's smoke passes the hash.
