# v2.4075 — Cover Letter: the schedule of values can split each stage into labor and material (2026-09-28)

The owner's ask (2026-09-28): GCs sometimes want the schedule of values broken into labor and material, and the estimator needs to be able to add and annotate that. Options mock-up https://claude.ai/artifact/1NTszEBtqr82VL3HdV89ya, then the revised "one schedule, two shapes" mock-up https://claude.ai/artifact/2tLGjhg8hy8eFC4JeGmApB; the owner took every recommended option: a sub's work counts as labor, the ratio uses the takeoff × the factor, and "total only" defaults off. This PR is the **By stage** shape (Option 2); the **My lines** shape (Option 3) follows on the same storage.

## The kernel — `sovLaborMaterial.ts`

- `laborCostByStage({ hoursByStage, laborRate, subByStage })`: hours × rate + the subcontractor rows' dollars per stage.
- `splitStageValues(letter, { costs, ruleLaborPct, overrides })`: each `scheduleOfValuesLetter` row divides by `L / (L + M)` in whole cents; material is the value less labor, so a line always adds up. No cost on either side → the company rule (`source: 'rule'`); a typed labor figure wins, clamped to the value (`source: 'typed'`, `derivedLabor` kept for the reset); the note rides along. `sovSplitTotals`, `sovSplitLineText`, `parseSovLaborSharePct` (0–100, else 45). 6 tests, pinned to the mock-up's bid.
- `buildScheduleOfValuesSectionLines(letter, { split, totalOnly })` in `scheduleOfValues.ts`: `Rough In — $35,596.80 (labor $12,143.83 · material $23,452.97)`, a note indented five spaces under its line, a Total with both figures; `totalOnly` → `See the attached schedule — $86,400.00`.
- `buildScheduleOfValuesHtml` takes `split`: with the contract column, three more columns (Labor with `(typed)` / `(rule)` marks, Material, Notes) and a footer sentence saying where the figures came from, "for progress billing only".

## The reads — `sovLaborMaterialIo.ts`

`loadSovLaborCostsForBid` (the bid's `cost_estimates` row → its `labor_rate`, its `cost_estimate_labor_rows` through `laborRowRough` / `Top` / `Trim`, its `cost_estimate_subcontractor_rows`), `loadSovLaborShareDefault` (`app_settings` `bid_sov_labor_share_pct_v1`), `loadSovStageOverrides`, and `loadSovSplitInputsForBid` = all three. The Cover Letter tab and the Approval PDF read through the same door.

## The letter, the PDF, the tab, Settings

- `CoverLetterScheduleOfValues` gains `split` and `totalOnly`; `scheduleOfValuesSectionFor(sov)` builds the lines once for both builders. The Approval PDF reads the two new flags in the same fresh `bids` read and loads the split inputs when the switch is on.
- `BidsCoverLetterTab.tsx`: two checkboxes under the schedule's label (`bids.sov_split_labor_material`, `bids.sov_letter_total_only`, the optimistic + `bidUpdateRefused` path); with the split on, the editor is a table (`data-testid="cover-letter-sov-split"`) — a labor box per stage (commit on blur / Enter; blank or the derived figure = back to the bid's costs; amber when typed, with *reset*), material and value read-only, a *from the bid* / *company rule* / *typed* word, and a note box that prints under the line. Writes are one upsert per stage into `bid_sov_stage_overrides`. The hint says the hours, the rate, whether subs counted and the factor; **Print the full schedule** passes the split.
- Settings → Bid Cover Letter Defaults: a *labor share, %* field beside the factor (`APP_SETTINGS_KEY_BID_SOV_LABOR_SHARE_PCT_V1`).
