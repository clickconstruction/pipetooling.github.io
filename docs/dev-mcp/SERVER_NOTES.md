A new server version adds its note at the end of this file, not to `index.ts`. The verbs' own reference is [`README.md`](./README.md), and the function's is [`EDGE_FUNCTIONS.md`](../EDGE_FUNCTIONS.md) → dev-mcp.

A person's HR file whole (v2.6422 / 0.17.0, numbered behind v2.6367's 0.16.0): get_person_file reads it as the People → HR tab draws it — the tab's own kernel (_shared/personTimeline.ts) over the tab's sources and keys (_shared/devMcpPersonFile.ts), as the reader under RLS, fail-soft per source; the HR sources are dev-only, so a view_as of the office sees the papers. A piece of evidence on that file (v2.6426 / 0.18.0): plan_person_evidence → apply_person_evidence, the record and its files (content_base64, each a name, mime, size and sha256 before the dry run) through dev_person_evidence_write; apply stages the files in the hr-files bucket as the dev before the rows and asks hr-evidence-drive after them, fail-soft. A waiting field report (v2.6430 / 0.21.0): plan_person_report → apply_person_report file it onto the person's file as the entry it becomes, or dismiss it with a reason, through the HR queue's own file_person_report / dismiss_person_report — no wrapper: the dry run is this server's read of the report, hashed with the ask (_shared/devMcpPersonReport.ts). get_job by the one card rule (v2.6468 / 0.23.0, behind its paged reads' 0.22.0): the card charges and the profit count as the Job window's profit band counts them, from the window's own lookups, and the man-hours read asks the server for the one job — an RPC result filter, checked as read_rows' filters are (buildRpcQuery).

A teammate's account, from the seat (v2.6792 / 0.50.0, punch list #260's seat door; numbered behind v2.6790's 0.49.0, which merged first): plan_account → apply_account makes a person as the Hire form does or renames one, changes their role or address; plan_login → apply_login attaches a login to a row with none and sends the sign-in email (or sets a password, or removes the login); plan_password_reset → apply_password_reset sends the app's own Forgot password email or sets a dictated password; get_login_state reads where getting them online stands. Every write is the edge function or RPC the desk itself calls, as the dev (invokeAsDev / restPost), so the functions' own dev gates hold; the dry run is this server's read of the users row, the roster row and the auth account's stamps (devMcpAccount.ts) — the FOURTH thing the service role is used for, timestamps by id and nothing else, since no other door reads auth.users. A password never comes back and never reaches the log (argsWithoutPasswords).

0.57.0 (v2.6808, punch list #209, numbered behind v2.6804's 0.51.0, v2.6806's 0.52.0, v2.6793's 0.53.0, v2.6822's 0.54.0, v2.6794's 0.55.0 and v2.6795's 0.56.0, which merged first): plan_materials_move → apply_materials_move — everything a job holds on site moved to another job, for a count recorded under the wrong job. A mailed file's words (v2.6880 / 0.60.0, punch list #296): read_mail_file_text hands back the words of a file off a mail instead of its base64 — a PDF's text layer, a text file, an .eml decoded — read by the file index's own reader (fileText.ts → textFromBytes, the index's limits for one file in a request) and paged by character, at most MAIL_FILE_TEXT_MAX_CHARS a reply (devMcpMailFile.ts → mailFileTextReply). Every call parses the file again, since the function keeps nothing between calls: 40 written pages measured about 120 ms locally, about 350 ms on the platform, inside the reader's 800 ms for one file. A scan answers in words that name read_mail_file. Read-only and logged.
